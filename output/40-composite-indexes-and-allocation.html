Chapter 40

Composite Indexes And Allocation

Orientation

A shop changes the price of a product. The product page shows the new price, and the sorted category page still shows the old one. Nothing crashed, and every structure holds data that was true a moment ago. The service is wrong because one record lives in two places and an update reached only one of them.

This chapter teaches classes in which one logical record appears in several indexes at once: a lookup by id, a ranking, a set of free resources, a count group or a price order. Each lesson asks which copy is the source of truth, which indexes follow it, and which step repairs them together.

Prerequisites

You should know hash maps, tree sets and tree maps, priority queues, doubly linked lists and the basic cache designs of the earlier design chapter. A secondary index is a structure that holds the same facts as the main record in another order. A stale entry is an index entry that no longer matches the record. A call is one public method of a class, and the workload is the mix of calls the class must serve. Every exercise lists the indexes that each call changes before it shows code.

What Each Lesson Protects

Each lesson names a fact that every call must leave true.

  • Multi-Index Records keeps the main record and every secondary index describing the same live entities.
  • Dynamic Rankings keeps the order total, so no two entries tie and an update removes the exact old key.
  • Resource Allocation keeps free and taken resources as two sets with no overlap.
  • Frequency Buckets keeps every key in the one bucket that matches its count.
  • Validated Priority keeps the heap as a list of candidates that the record can reject.
  • Transaction Lifecycles keeps each call all-or-nothing across every index.
  • Look Up By ID And By Order joins the record map with sorted views that have several exits.
  • Pick The Best Free Resource joins free resources with candidates whose priority comes from neighbors.

Reading Order

Every lesson opens with a class that passes small tests and fails under a real workload. You predict the failure before the explanation. Two traces follow the state call by call, then Java code and the limits of the idea. Four exercises climb from a basic build to a variation, an edge case and a recognition problem. A false friend is a design that looks like the pattern and breaks one of its conditions. The solutions check each class against a slow, obviously correct version on random calls. The two closing lessons add a section that names what each earlier lesson contributes.

What You Can Do After This Chapter

You can list every index that a public call must touch before writing the call. You can choose between exact removal from a sorted set and a version check on a heap. You can split a call into a plan that only reads and a commit that cannot fail. The lock-free and cache designs belong to other chapters.

Problem

One Update That Reaches Only One View

An online store keeps one record per product. Support staff look a product up by its id, and the category page lists the cheapest products first. A developer stores the records in a hash map for the id lookups and keeps a second sorted collection for the category page. One night a price drops from 40 to 25. The hash map shows 25, but the category page still lists the product at 40, and a second copy appears at 25 after the next refresh.

Both views are correct about something. Each one is wrong about the other. The bug sits in the update, which touched one structure and forgot the other.

This lesson asks how to store one record in several structures so that every public call leaves all of them telling the same story.

Simple approach

Two Collections That Update Separately

The direct design keeps a map from each index to its number. A separate list of pairs answers the ordered question of which index is smallest for a number. The class below stores the pairs in a list and scans it.

final class NaiveContainers {
    private final java.util.Map<Integer, Integer> numberAt = new java.util.HashMap<>();
    private final java.util.List<int[]> pairs = new java.util.ArrayList<>(); // {index, number}

    void change(int index, int number) {
        numberAt.put(index, number);
        pairs.add(new int[] {index, number});      // forgets the old pair for this index
    }

    int find(int number) {
        int best = -1;
        for (int[] p : pairs) {
            if (p[1] == number && (best == -1 || p[0] < best)) best = p[0];
        }
        return best;
    }
}

After change(1, 10) and then change(1, 20), the call find(10) still returns 1, although index 1 now holds 20.

Predict first: The class passes a test that changes each index only once. What breaks when an index is changed twice, and how much work does each find call do after n changes?

The list keeps the first pair for the index, so find reports an index for a number that the index no longer holds. Each find scans every pair ever added, so it costs O(n) and the list also grows with every change instead of with the number of live indexes.

Bottleneck

Stale Pairs And Full Scans

Two separate costs hide in the naive class. The first is correctness. The map answers "what does index 1 hold now?" correctly, while the list still holds the history of every earlier value. A call that reads the list sees values that no longer exist.

The second cost is time. A find call scans the whole list, which costs O(n) for n changes made so far, and the list never shrinks.

Fixing only the speed does not help. A sorted set per number answers find in O(log n), yet it still returns a dead entry when the old pair stays inside it. The sorted set needs the exact old pair removed at the moment the record changes. That removal needs the old value, and only the map can supply it.

Key idea

Keeping Every View Equal To The Record

The map from index to number is the source of truth. It holds exactly one current value per index, and no other structure may disagree with it.

Views Built From The Record

A secondary index is any other structure that answers a question faster than a scan of the map. Here the secondary index maps each number to a sorted set of the indexes that hold it. A secondary index stores no new facts. It stores the same facts in another order.

Repairing After Every Change

Each public call finishes with a repair step. The step reads the old value from the source of truth. It removes the old entry from each secondary index and writes the new value. It then inserts the new entry into each secondary index. The removal must come first. A sorted set locates an entry by its fields, so the entry must still hold the old fields when the removal runs.

The invariant has two parts. Every live record appears in every secondary index exactly once. No secondary index holds an entry for a record that no longer exists or no longer has those fields.

State

What Each Piece Of State Means

Three pieces of state carry the lesson, and each changes at a known moment.

  • numberAt maps each index to its current number and changes in every change call.
  • indexesOf maps each number to a sorted set of indexes and changes in step with numberAt.
  • old is the number that numberAt held before the call, or absent for a new index, and it exists only inside the call.

The call removes an empty set from indexesOf. A find call then treats a missing key as the answer -1.

Walkthrough

Following Calls Through Both Maps

Changing An Index Twice

The first trace uses five calls. The pointer call points at the call that just ran. Each step shows both maps after that call, with the map from index to number first.

The third call is the one that the naive class gets wrong. It reads the old number 10 from the source of truth, removes index 1 from the set for 10, and only then inserts index 1 into the set for 20. The set for 10 keeps index 2, so find still answers 2.

Writing The Same Value Again

The second trace changes index 3 to 5 twice, then to 7. The repeated call finds that the old number equals the new number, so it leaves both maps alone.

The set for 5 empties after the move to 7, so the repair step deletes the key. The last find returns -1 because the key is gone.

Code

The Repair Step In Java

The class below keeps one map as the source of truth and one map of sorted sets as the secondary index.

final class NumberContainers {
    private final java.util.Map<Integer, Integer> numberAt = new java.util.HashMap<>();
    private final java.util.Map<Integer, java.util.TreeSet<Integer>> indexesOf = new java.util.HashMap<>();

    void change(int index, int number) {
        Integer old = numberAt.put(index, number);          // source of truth first; returns the old value
        if (old != null && old == number) return;           // same value: both maps already agree
        if (old != null) {
            java.util.TreeSet<Integer> set = indexesOf.get(old);
            set.remove(index);                               // remove the exact old entry
            if (set.isEmpty()) indexesOf.remove(old);        // drop empty sets so memory follows live data
        }
        indexesOf.computeIfAbsent(number, k -> new java.util.TreeSet<>()).add(index);
    }

    int find(int number) {
        java.util.TreeSet<Integer> set = indexesOf.get(number);
        return set == null ? -1 : set.first();               // smallest index in O(log n)
    }
}

A change call costs O(log n), because one hash lookup and at most two tree operations run. A find call costs O(log n) as well, and the first element of a tree set needs no scan. The space is O(n), one entry per index in each map.

When to use it

When Several Indexes Share One Record

Spotting The Pattern

Look for one entity that callers reach by an id and also through an order, such as smallest index, cheapest price or best rating. If a call changes a field that an index sorts by, the call must repair that index. The invariant is that the source of truth and every secondary index describe the same live records.

Fields That Order A Tree

Java tree sets and tree maps find entries by comparing fields. Mutating a field of an object that already sits inside a tree set leaves the object in the wrong place, and later removals miss it. Store immutable entries, or remove the entry before the field changes. Compare fields with Integer.compare and never by subtraction, because subtraction overflows.

A False Friend And A Boundary

A cache that stores each value twice under two keys looks like a multi-index record. It is a false friend when the two copies never need to agree after a change. A second false friend is a derived value that costs almost nothing to recompute on every read. Such a value needs no index. Skip this design when a single sorted structure already contains the id, because then the id lookup is one of the views and nothing needs repair.

Number Container System

LeetCode 2349

Problem Specification. Design a class NumberContainers with an unbounded array of slots indexed by non-negative integers, where every slot starts empty. The call change(index, number) stores number in slot index and replaces any earlier value. The call find(number) returns the smallest index whose slot holds number, or -1 if no slot holds it.

Input Constraints. The limits are:

  • Calls number at most 10^5 in total.
  • Index and number satisfy 1 <= value <= 10^9.
  • Return is a single int.
  • Mutation happens only in change.

Example 1. Input calls find(10), change(2,10), change(1,10), find(10), output -1 for the first find and 1 for the second.

Example 2. Input calls change(1,10), change(1,20), find(10), find(20), output -1 for find(10) and 1 for find(20).

Prerequisites. Hash maps and tree sets from earlier chapters.

What This Exercise Changes. The class stores both maps and removes the old pair on every change.

Hint

Which structure holds the current number for an index, and which structure answers the smallest-index question?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps a hash map from index to number as the source of truth. A second hash map from number to a tree set of indexes is the secondary index.

A change call reads the old number with put, which returns the previous value. When the old number equals the new one, both structures already agree and the call stops. Otherwise it removes the index from the old number's set, deletes that set if it is empty, and inserts the index into the new number's set. A find call returns the first element of the set for the number.

The invariant is that index i appears in the set of number v exactly when the map holds v for i. Removal happens before insertion, so the index never sits in two sets at once.

Complexity.

  • Time is O(log n) for both calls. One hash lookup and at most three tree operations touch a set of at most n indexes.
  • Space is O(n), because each index appears once in the map and once in one set.
import java.util.*;

public final class NumberContainerSolution {
    static final class NumberContainers {
        private final Map<Integer, Integer> numberAt = new HashMap<>();             // index -> number, source of truth
        private final Map<Integer, TreeSet<Integer>> indexesOf = new HashMap<>();   // number -> sorted indexes

        /**
         * Stores number at index and repairs the secondary index.
         * Time: O(log n), because it does a constant number of hash and tree operations.
         * Space: O(1) extra, because only one entry moves.
         * Invariant: each index sits in exactly the set of its current number.
         */
        void change(int index, int number) {
            // put returns the old value, which names the set that must lose the index.
            Integer old = numberAt.put(index, number);
            // Equal values need no repair, and skipping avoids removing then re-adding.
            if (old != null && old == number) return;
            if (old != null) {
                // Remove the exact old entry before the new one enters.
                TreeSet<Integer> set = indexesOf.get(old);
                set.remove(index);
                // Drop empty sets so find sees a missing key, not an empty set.
                if (set.isEmpty()) indexesOf.remove(old);
            }
            // Create the set on demand and insert the index in sorted position.
            indexesOf.computeIfAbsent(number, k -> new TreeSet<>()).add(index);
        }

        /**
         * Returns the smallest index holding number, or -1.
         * Time: O(log n) for the hash lookup and tree first element.
         * Space: O(1).
         * Invariant: the first element of a set is its minimum.
         */
        int find(int number) {
            // A missing key means no index holds the number.
            TreeSet<Integer> set = indexesOf.get(number);
            return set == null ? -1 : set.first();
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        NumberContainers a = new NumberContainers();
        if (a.find(10) != -1) throw new AssertionError("e1 empty");
        a.change(2, 10); a.change(1, 10);
        if (a.find(10) != 1) throw new AssertionError("e1 smallest");
        NumberContainers b = new NumberContainers();
        b.change(1, 10); b.change(1, 20);
        if (b.find(10) != -1 || b.find(20) != 1) throw new AssertionError("e2");
        // Random calls checked against a scan of an array that holds the current numbers.
        Random rnd = new Random(2349);
        for (int round = 0; round < 300; round++) {
            NumberContainers s = new NumberContainers();
            int[] ref = new int[12];                       // 0 means empty
            for (int op = 0; op < 150; op++) {
                if (rnd.nextBoolean()) {
                    int i = 1 + rnd.nextInt(11), v = 1 + rnd.nextInt(4);
                    ref[i] = v; s.change(i, v);
                } else {
                    int v = 1 + rnd.nextInt(4), want = -1;
                    for (int i = 1; i < 12 && want == -1; i++) if (ref[i] == v) want = i;
                    if (s.find(v) != want) throw new AssertionError("random find");
                }
            }
        }
    }
}verified

Food Rating System

LeetCode 2353

Problem Specification. Design a class FoodRatings built from arrays foods, cuisines and ratings of equal length, where foods[i] belongs to cuisine cuisines[i] and starts with rating ratings[i]. The call changeRating(food, newRating) sets the rating of one food. The call highestRated(cuisine) returns the food of that cuisine with the highest rating. Among equal ratings, return the name that is smallest in lexicographic order.

Input Constraints. The limits are:

  • Foods are distinct lowercase strings, and the arrays hold 1 to 2 * 10^4 entries.
  • Ratings satisfy 1 <= rating <= 10^8.
  • Calls number at most 2 * 10^4, and every queried cuisine exists.
  • Return is the food name.

Example 1. Input foods a, b, c in cuisine x with ratings 5, 9, 9 and the call highestRated(x), output b, because b beats c by name.

Example 2. Input the call changeRating(b, 1) and then highestRated(x) on the same data, output c.

Prerequisites. The number container exercise above.

What This Exercise Changes. Ratings now change, so the entry in each cuisine set must leave before its rating changes.

Hint

What must the tree set compare, and what must hold true about the entry at the moment of removal?

Algorithmic Solution (attempt the problem first)

Approach. A record holds a food's cuisine and current rating. A map from food name to record is the source of truth. A map from cuisine to a tree set of entries is the secondary index, where an entry is an immutable pair of name and rating.

The set orders entries by higher rating first and then by smaller name, using Integer.compare on the ratings. A rating change removes the entry built from the stored rating, writes the new rating into the record, and inserts the new entry. The highest-rated food is the first entry of its cuisine's set.

The invariant is that every food has exactly one entry in its cuisine set, and the entry holds the same rating as the record. The removal runs first, because the set finds an entry through its rating.

Complexity.

  • Time is O(log n) for a change call and for a query. Each runs hash lookups and tree operations on at most n entries. The constructor adds O(n log n).
  • Space is O(n), because each food owns one record and one entry.
import java.util.*;

public final class FoodRatingSolution {
    static final class FoodRatings {
        private record Entry(String name, int rating) {}                    // immutable, so tree order cannot drift
        private final Map<String, int[]> ratingOf = new HashMap<>();        // food -> {rating}
        private final Map<String, String> cuisineOf = new HashMap<>();      // food -> cuisine
        private final Map<String, TreeSet<Entry>> byCuisine = new HashMap<>();
        private static final Comparator<Entry> ORDER = (x, y) -> {
            int c = Integer.compare(y.rating(), x.rating());                // higher rating first
            return c != 0 ? c : x.name().compareTo(y.name());               // then smaller name
        };

        /**
         * Builds both maps from the starting arrays.
         * Time: O(n log n), because each food enters a tree set.
         * Space: O(n).
         * Invariant: each food appears once in its cuisine set with its record's rating.
         */
        FoodRatings(String[] foods, String[] cuisines, int[] ratings) {
            for (int i = 0; i < foods.length; i++) {
                // Record first, then the matching entry in the cuisine index.
                ratingOf.put(foods[i], new int[] {ratings[i]});
                cuisineOf.put(foods[i], cuisines[i]);
                byCuisine.computeIfAbsent(cuisines[i], k -> new TreeSet<>(ORDER)).add(new Entry(foods[i], ratings[i]));
            }
        }

        /**
         * Sets the rating of a food.
         * Time: O(log n).
         * Space: O(1).
         * Invariant: the old entry leaves before the rating changes.
         */
        void changeRating(String food, int newRating) {
            int[] cell = ratingOf.get(food);
            TreeSet<Entry> set = byCuisine.get(cuisineOf.get(food));
            // Remove using the stored rating, because the set locates entries by rating.
            set.remove(new Entry(food, cell[0]));
            cell[0] = newRating;
            // Insert the entry that carries the new rating.
            set.add(new Entry(food, newRating));
        }

        /**
         * Returns the best food of a cuisine.
         * Time: O(log n).
         * Space: O(1).
         * Invariant: the first entry has the highest rating, then the smallest name.
         */
        String highestRated(String cuisine) {
            return byCuisine.get(cuisine).first().name();
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        FoodRatings f = new FoodRatings(new String[] {"a", "b", "c"}, new String[] {"x", "x", "x"}, new int[] {5, 9, 9});
        if (!f.highestRated("x").equals("b")) throw new AssertionError("e1");
        f.changeRating("b", 1);
        if (!f.highestRated("x").equals("c")) throw new AssertionError("e2");
        // Random updates checked against a scan of all foods in the cuisine.
        Random rnd = new Random(2353);
        for (int round = 0; round < 300; round++) {
            int n = 2 + rnd.nextInt(8);
            String[] foods = new String[n], cuis = new String[n];
            int[] rat = new int[n];
            for (int i = 0; i < n; i++) { foods[i] = "f" + (char) ('a' + i); cuis[i] = "c" + rnd.nextInt(2); rat[i] = 1 + rnd.nextInt(4); }
            FoodRatings s = new FoodRatings(foods, cuis, rat.clone());
            for (int op = 0; op < 80; op++) {
                if (rnd.nextBoolean()) {
                    int i = rnd.nextInt(n), v = 1 + rnd.nextInt(4);
                    rat[i] = v; s.changeRating(foods[i], v);
                } else {
                    String c = cuis[rnd.nextInt(n)];
                    int best = -1;
                    for (int i = 0; i < n; i++)
                        if (cuis[i].equals(c) && (best == -1 || rat[i] > rat[best] || (rat[i] == rat[best] && foods[i].compareTo(foods[best]) < 0))) best = i;
                    if (!s.highestRated(c).equals(foods[best])) throw new AssertionError("random best");
                }
            }
        }
    }
}verified
Edge Cases

Update To Same Value

Author exercise

Problem Specification. Design a class Roster of players. The call setTeam(player, team) assigns a player to a team and returns true if the stored team changed, or false if the player already belongs to that team. The call size(team) returns the number of players on a team, kept as a counter. The call members(team) returns the players on a team in increasing order.

Input Constraints. The limits are:

  • Players and teams are integers from 1 to 10^5.
  • Calls number at most 10^5.
  • Counter must equal the length of members(team) after every call.
  • Return of setTeam is a boolean.

Example 1. Input calls setTeam(7,1), setTeam(7,1), size(1), output true, false and 1.

Example 2. Input calls setTeam(7,1), setTeam(7,2), size(1), size(2), output true, true, 0 and 1.

Prerequisites. The two exercises above.

What This Exercise Changes. An update that does not change the value must change nothing else either.

Hint

What happens to the counter when the code raises it before comparing the old team with the new team?

Algorithmic Solution (attempt the problem first)

Approach. A map from player to team is the source of truth. A map from team to a tree set of players is the secondary index, and a counter per team is a third derived view.

The call reads the old team first. When the old team equals the new team, the call returns false before it touches any counter or set. Otherwise it removes the player from the old team's set, lowers the old counter, inserts the player into the new team's set, raises the new counter and returns true.

The invariant is that each counter equals the size of its set. An update that skips the early return raises the counter without adding a new set element, because adding an existing element to a set changes nothing. The counter then exceeds the true size.

Complexity.

  • Time per call is O(log n), which comes from two hash lookups and at most two tree operations.
  • Space is O(n), because each player appears once in the map and once in one set.
import java.util.*;

public final class SameValueSolution {
    static final class Roster {
        private final Map<Integer, Integer> teamOf = new HashMap<>();            // player -> team, source of truth
        private final Map<Integer, TreeSet<Integer>> members = new HashMap<>();  // team -> sorted players
        private final Map<Integer, Integer> counter = new HashMap<>();           // team -> number of players

        /**
         * Assigns a player and reports whether the stored team changed.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: counter(team) equals members(team).size() after every call.
         */
        boolean setTeam(int player, int team) {
            Integer old = teamOf.get(player);
            // Same team: no index entry moves, so no counter may move either.
            if (old != null && old == team) return false;
            if (old != null) {
                // Leave the old team in both the set and the counter.
                members.get(old).remove(player);
                counter.merge(old, -1, Integer::sum);
            }
            // Enter the new team in the source of truth, the set and the counter.
            teamOf.put(player, team);
            members.computeIfAbsent(team, k -> new TreeSet<>()).add(player);
            counter.merge(team, 1, Integer::sum);
            return true;
        }

        /** Returns the counter; O(1) time and space, equal to the set size by the invariant. */
        int size(int team) { return counter.getOrDefault(team, 0); }

        /** Returns the players of a team in order; O(k) time for k players, O(k) space for the copy. */
        List<Integer> members(int team) { return new ArrayList<>(members.getOrDefault(team, new TreeSet<>())); }
    }

    public static void main(String[] args) {
        // Example 1: a repeated assignment returns false and keeps the count at 1.
        Roster r = new Roster();
        if (!r.setTeam(7, 1) || r.setTeam(7, 1) || r.size(1) != 1) throw new AssertionError("e1");
        // Example 2: a real move changes both counters.
        Roster q = new Roster();
        if (!q.setTeam(7, 1) || !q.setTeam(7, 2) || q.size(1) != 0 || q.size(2) != 1) throw new AssertionError("e2");
        // Random calls checked against a plain array of teams.
        Random rnd = new Random(40);
        for (int round = 0; round < 300; round++) {
            Roster s = new Roster();
            int[] team = new int[8];                                // 0 means unassigned
            for (int op = 0; op < 120; op++) {
                int p = 1 + rnd.nextInt(7), t = 1 + rnd.nextInt(3);
                boolean want = team[p] != t;
                team[p] = t;
                if (s.setTeam(p, t) != want) throw new AssertionError("return value");
                for (int x = 1; x <= 3; x++) {
                    List<Integer> ref = new ArrayList<>();
                    for (int i = 1; i < 8; i++) if (team[i] == x) ref.add(i);
                    if (!s.members(x).equals(ref) || s.size(x) != ref.size()) throw new AssertionError("counter or members");
                }
            }
        }
    }
}verified

Movie Rental System

LeetCode 1912

Problem Specification. A chain has n shops, and each shop owns at most one copy of each movie at a fixed price. Design a class MovieRental built from entries {shop, movie, price}. The call search(movie) returns up to 5 shops that hold an unrented copy, ordered by price and then shop number. The call rent(shop, movie) marks that copy rented. The call drop(shop, movie) marks it unrented. The call report() returns up to 5 rented copies as {shop, movie}, ordered by price, then shop, then movie.

Input Constraints. The limits are:

  • Shops satisfy 1 <= n <= 3 * 10^5.
  • Entries number at most 10^5, each {shop, movie} pair appears once.
  • Calls number at most 10^5, and rent and drop use existing and valid copies.
  • Price is an int from 1 to 10^4.

Example 1. Input entries {0,1,5}, {0,2,6}, {1,1,4} and the call search(1), output shops 1 and 0.

Example 2. Input the call rent(1,1) on the same entries, then search(1) and report(), output shop 0 and the pair {1,1}.

Prerequisites. All three exercises above.

What This Exercise Changes. One call moves a copy between two views, so it removes from one index and inserts into the other.

Hint

Which two questions need an order, and which record move touches both of them?

Algorithmic Solution (attempt the problem first)

Approach. A record is an immutable entry of price, shop and movie. One tree set holds all rented entries. A map from movie to a tree set holds the unrented entries of that movie. A map from the pair of shop and movie to the entry is the source of truth for the price.

All sets use one order: price first, then shop, then movie, compared with Integer.compare. A rent call removes the entry from its movie's unrented set and inserts it into the rented set. A drop call moves the entry back. A search reads the first five entries of one movie's set. A report reads the first five entries of the rented set.

The invariant is that every entry sits in exactly one of its movie's unrented set and the rented set. Each call removes before it inserts, so no entry is ever in both.

Complexity.

  • Time is O(log n) for rent and drop, and O(log n) for search and report. Each of those reads at most five entries from the start of a tree set.
  • Space is O(n), because each copy owns one entry and one map slot.
import java.util.*;

public final class MovieRentalSolution {
    static final class MovieRental {
        private record Copy(int price, int shop, int movie) {}
        private static final Comparator<Copy> ORDER = (a, b) -> {
            int c = Integer.compare(a.price(), b.price());
            if (c != 0) return c;
            c = Integer.compare(a.shop(), b.shop());
            return c != 0 ? c : Integer.compare(a.movie(), b.movie());
        };
        private final Map<Long, Copy> copyAt = new HashMap<>();               // pair key -> copy, source of truth
        private final Map<Integer, TreeSet<Copy>> unrented = new HashMap<>();  // movie -> unrented copies
        private final TreeSet<Copy> rented = new TreeSet<>(ORDER);

        private static long key(int shop, int movie) { return ((long) shop << 32) | movie; }

        /**
         * Builds the views with every copy unrented.
         * Time: O(n log n).
         * Space: O(n).
         * Invariant: each copy sits in its movie's unrented set.
         */
        MovieRental(int[][] entries) {
            for (int[] e : entries) {
                Copy c = new Copy(e[2], e[0], e[1]);
                copyAt.put(key(e[0], e[1]), c);
                unrented.computeIfAbsent(e[1], k -> new TreeSet<>(ORDER)).add(c);
            }
        }

        /** Returns up to 5 cheapest shops with an unrented copy; O(log n + 5) time, O(1) extra space. */
        List<Integer> search(int movie) {
            List<Integer> out = new ArrayList<>();
            // Walk the sorted set and stop after five entries.
            for (Copy c : unrented.getOrDefault(movie, new TreeSet<>(ORDER))) {
                if (out.size() == 5) break;
                out.add(c.shop());
            }
            return out;
        }

        /** Moves a copy from its unrented set to the rented set; O(log n) time, O(1) space; invariant: one view at a time. */
        void rent(int shop, int movie) {
            Copy c = copyAt.get(key(shop, movie));
            unrented.get(movie).remove(c);   // leave the old view first
            rented.add(c);                   // then enter the new view
        }

        /** Moves a copy back to its unrented set; O(log n) time, O(1) space; invariant: one view at a time. */
        void drop(int shop, int movie) {
            Copy c = copyAt.get(key(shop, movie));
            rented.remove(c);
            unrented.get(movie).add(c);
        }

        /** Returns up to 5 cheapest rented copies as {shop, movie}; O(log n + 5) time, O(1) extra space. */
        List<int[]> report() {
            List<int[]> out = new ArrayList<>();
            for (Copy c : rented) {
                if (out.size() == 5) break;
                out.add(new int[] {c.shop(), c.movie()});
            }
            return out;
        }
    }

    public static void main(String[] args) {
        // Examples from the problem text.
        MovieRental m = new MovieRental(new int[][] {{0, 1, 5}, {0, 2, 6}, {1, 1, 4}});
        if (!m.search(1).equals(List.of(1, 0))) throw new AssertionError("e1");
        m.rent(1, 1);
        List<int[]> rep = m.report();
        if (!m.search(1).equals(List.of(0)) || rep.size() != 1 || rep.get(0)[0] != 1 || rep.get(0)[1] != 1) throw new AssertionError("e2");
        // Random calls checked against a scan over a boolean array of rented flags.
        Random rnd = new Random(1912);
        for (int round = 0; round < 200; round++) {
            int shops = 4, movies = 3;
            List<int[]> list = new ArrayList<>();
            for (int s = 0; s < shops; s++) for (int v = 0; v < movies; v++) if (rnd.nextInt(3) > 0) list.add(new int[] {s, v, 1 + rnd.nextInt(5)});
            int[][] entries = list.toArray(new int[0][]);
            MovieRental sut = new MovieRental(entries);
            boolean[] out = new boolean[entries.length];
            for (int op = 0; op < 100; op++) {

                int t = rnd.nextInt(3);
                if (t == 0 && !out[k]) { out[k] = true; sut.rent(entries[k][0], entries[k][1]); }

                    for (int i = 0; i < entries.length; i++) if (entries[i][1] == mv && !out[i]) cand.add(entries[i]);
                    cand.sort((x, y) -> x[2] != y[2] ? Integer.compare(x[2], y[2]) : Integer.compare(x[0], y[0]));

                }

Problem

A Scoreboard That Sorts On Every Refresh

A game server keeps a score for each of 200,000 players. Matches end every few milliseconds, and each match adds points to a handful of players. The lobby screen shows the top 10 players and refreshes after every match. A developer stores the scores in a hash map. Each refresh copies all entries into a list, sorts the list and reads the first ten.

The refresh costs a full sort even though the screen needs only ten rows. The server spends most of its time ordering players that the screen never shows.

The same question appears in task queues, auction pages and search results. Scores change, and callers ask for the best few entries. This lesson asks how to keep the ranking sorted between calls, and what must hold true about the order so that a changed score never leaves a stale row behind.

Simple approach

Sorting All Scores For Each Query

The direct design keeps a hash map from player id to score. A top query copies the map entries, sorts them by score, and adds up the first k values.

final class NaiveBoard {
    private final java.util.Map<Integer, Long> score = new java.util.HashMap<>();

    void addScore(int player, long points) {
        score.merge(player, points, Long::sum);          // one hash operation per update
    }

    long top(int k) {
        java.util.List<Long> all = new java.util.ArrayList<>(score.values());
        all.sort(java.util.Collections.reverseOrder());   // sorts every player on every query
        long sum = 0;
        for (int i = 0; i < k; i++) sum += all.get(i);
        return sum;
    }
}

An update costs O(1). A top query costs O(n log n) for n players, whatever the value of k.

Predict first: Players 1, 2 and 3 hold 50, 30 and 40 points. A caller asks for top(2) one million times between updates. How much sorting work is repeated, and what does a sorted structure save?

Every call sorts all three scores again and returns 90, so the same ordering is rebuilt one million times. A structure that stays sorted between updates reads two entries per query. The sort cost moves into the update, which touches one player.

Bottleneck

Re-Sorting Unchanged Data

A top query reads k entries, yet it pays for sorting all n. The sort repeats work whenever two queries arrive without an update between them, and even one update changes only one position in the order.

A tree set that stays sorted fixes the repeated work. An update then costs O(log n) and a top query costs O(k + log n). The tree set brings two new risks.

The first risk is a comparator that sees two players as equal. A tree set treats entries that compare equal as the same entry, so a second player with the same score silently disappears. The second risk is a score change. The old entry sits in the tree under its old score. A removal that uses the new score does not find it, and the old row stays in the ranking.

Key idea

A Strict Order And An Exact Removal

The ranking is a total order on entries. A total order compares any two different entries as unequal. A score alone is not a total order, because two players can share a score. Adding the player id as the last comparison field makes every pair of entries comparable and distinct.

Naming The Tie Rule

The tie policy says which of two entries with equal scores ranks first. It is part of the problem, not an implementation detail. A problem that says "smaller name first" states a tie policy. The comparator must follow that statement field by field, and it must end with the id so the order stays total.

Removing The Right Entry

An update has to delete the exact old key, which is the entry built from the old score and the same id. The class reads the old score from its map, removes the entry that carries that score, writes the new score and inserts the new entry. Entries are immutable, so no field changes while an entry sits inside the tree.

The invariant is that the tree holds one entry per live player, and each entry carries that player's current score.

State

What The Class Stores

Two structures and one record type carry the state.

  • scoreOf maps each player id to the current total and changes in every addScore and reset call.
  • board is a tree set of entries ordered by higher score first and then by smaller id, and it changes in step with scoreOf.
  • Entry is an immutable pair of score and id, and a new object replaces it on every change.

The top query reads from board and never writes to either structure.

Walkthrough

Following Updates And Queries

Scores That Add Up

The first trace follows six calls. Here the pointer call names the latest call, and each step lists the board from best to worst as score:id.

The third call is the one that moves a player. Player 1 holds 30, so the class removes the entry 30:1 and then inserts 45:1. Player 1 now outranks player 2.

Players With The Same Score

The second trace starts three players with equal scores. The id decides the order, and an update then separates one of them.

The three entries sit in the board together, because the id makes them compare unequal. A comparator on score alone would keep only the first of the three.

Code

The Board In Java

The class stores entries in a tree set and sums the first k entries of an iterator.

final class Leaderboard {
    private record Entry(long score, int id) {}
    private final java.util.Map<Integer, Long> scoreOf = new java.util.HashMap<>();
    private final java.util.TreeSet<Entry> board = new java.util.TreeSet<>((a, b) -> {
        int c = Long.compare(b.score(), a.score());          // higher score first; compare never subtracts
        return c != 0 ? c : Integer.compare(a.id(), b.id()); // id breaks ties, so the order is total
    });

    void addScore(int id, long points) {
        Long old = scoreOf.get(id);
        if (old != null) board.remove(new Entry(old, id));    // exact old key first
        long now = (old == null ? 0 : old) + points;
        scoreOf.put(id, now);
        board.add(new Entry(now, id));                        // then the new key
    }

    long top(int k) {
        long sum = 0;
        for (Entry e : board) {                               // iterator walks in rank order
            if (k-- == 0) break;
            sum += e.score();
        }
        return sum;
    }
}

An update costs O(log n), because it does one removal and one insertion. A top query costs O(k), because the iterator starts at the first entry. The space is O(n).

When to use it

Choosing A Sorted Set For Rankings

Checking The Comparator

Before you write the set, say the order aloud, one field at a time. The last field must be unique, and the comparison of every field must use Integer.compare or Long.compare. The invariant is that no two live entries compare equal, and every entry matches current state.

Rank Queries By Position

A top-k sum or a name list needs only the first k entries, so an iterator is enough. A query for the rank of one player is different. A tree set cannot report a position without a scan. That question needs a Fenwick tree or an order-statistic structure.

False Friends

A tree map keyed by score alone looks like a ranking, but it is a false friend, because it holds one player per score. A priority queue looks like a ranking too. It exposes only the best entry, and removing an arbitrary entry costs O(n). Skip the sorted set when only the single best entry matters and scores never decrease, because one variable is enough there.

Approach. A hash map from player id to total is the source of truth. A tree set of immutable entries is the ranking. The comparator puts the higher total first and breaks ties by the smaller id, so no two entries compare equal.

import java.util.*;

public final class LeaderboardSolution {
    static final class Leaderboard {
        private record Entry(long score, int id) {}
        private final Map<Integer, Long> totalOf = new HashMap<>();   // id -> total, source of truth
        private final TreeSet<Entry> board = new TreeSet<>((a, b) -> {
            int c = Long.compare(b.score(), a.score());                // higher total first
            return c != 0 ? c : Integer.compare(a.id(), b.id());       // smaller id first among equals
        });

        /**
         * Replaces a player's total and repairs the ranking.
         * Time: O(log n), because it does one removal and one insertion.
         * Space: O(1) extra.
         * Invariant: board holds exactly one entry per player with the stored total.
         */
        private void set(int id, long total) {
            Long old = totalOf.get(id);
            // Remove the exact old key; a new player has none.
            if (old != null) board.remove(new Entry(old, id));
            totalOf.put(id, total);
            board.add(new Entry(total, id));
        }

        void addScore(int id, int score) {
            // Add to the stored total, or start from zero for a new player.
            set(id, totalOf.getOrDefault(id, 0L) + score);
        }

        /** Sums the first K entries in rank order; O(K) time, O(1) space; invariant: iteration order equals rank order. */
        long top(int k) {
            long sum = 0;
            for (Entry e : board) {
                if (k-- == 0) break;
                sum += e.score();
            }
            return sum;
        }

        void reset(int id) { set(id, 0); }
    }

Sequentially Ordinal Rank Tracker

LeetCode 2102

Problem Specification. Design a class RankTracker. The call add(name, score) inserts a location with a unique name. The call get() returns the name of the location at rank i, where i is the number of get calls so far including this one. Rank 1 is the highest score, and equal scores rank by the smaller name first.

Input Constraints. The limits are:

  • Names are distinct lowercase strings of length 1 to 10.
  • Scores satisfy 1 <= score <= 10^5.
  • Calls number at most 10^5, and every get has at least i locations.
  • Return of get is a name.

Example 1. Input calls add(a,3), add(b,5), get(), add(c,4), get(), output b and then c.

Example 2. Input calls add(x,1), add(y,1), get(), get(), output x and then y.

Prerequisites. The leaderboard exercise above.

What This Exercise Changes. The query position grows with each call, so one half only gains entries and the other half hands over its best.

Hint

Split the entries into the ones already returned and the rest. What must hold between the two halves?

Algorithmic Solution (attempt the problem first)

Approach. Two tree sets share one comparator, which ranks the higher score first and the smaller name second. The set returned holds the entries at ranks 1 up to i - 1, where i - 1 is the number of earlier get calls. The set pending holds every other entry.

A get call moves the first entry of pending into returned and returns its name. That entry is the one at rank i, because returned holds exactly the better entries. An add call must keep every entry of returned better than every entry of pending. When the new entry beats the last entry of returned, the call inserts it into returned and moves the last entry of returned to pending. Otherwise the call inserts it into pending.

The invariant is that returned holds the best i - 1 entries overall, and its size changes only in a get call.

Complexity.

  • Time per call is O(log n). Each call performs at most three tree operations.
  • Space is O(n), because each entry sits in exactly one of the two sets.
import java.util.*;

public final class RankTrackerSolution {
    static final class RankTracker {
        private record Place(int score, String name) {}
        private static final Comparator<Place> BETTER_FIRST = (a, b) -> {
            int c = Integer.compare(b.score(), a.score());
            return c != 0 ? c : a.name().compareTo(b.name());
        };
        private final TreeSet<Place> returned = new TreeSet<>(BETTER_FIRST);   // ranks 1 .. gets
        private final TreeSet<Place> pending = new TreeSet<>(BETTER_FIRST);    // all lower ranks

        /**
         * Inserts a place while keeping every returned place better than every pending place.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: returned holds the best |returned| places overall.
         */
        void add(String name, int score) {
            Place p = new Place(score, name);
            // A place that beats the weakest returned place takes its slot, and that place moves down.
            if (!returned.isEmpty() && BETTER_FIRST.compare(p, returned.last()) < 0) {
                returned.add(p);
                pending.add(returned.pollLast());
            } else {
                pending.add(p);
            }
        }

        /** Returns the place at the next rank; O(log n) time, O(1) extra space; invariant: the size of returned grows by one. */
        String get() {
            Place best = pending.pollFirst();   // best place not yet returned
            returned.add(best);
            return best.name();
        }
    }

    public static void main(String[] args) {
        // Examples from the problem text.
        RankTracker a = new RankTracker();
        a.add("a", 3); a.add("b", 5);
        if (!a.get().equals("b")) throw new AssertionError("e1 first");
        a.add("c", 4);
        if (!a.get().equals("c")) throw new AssertionError("e1 second");
        RankTracker b = new RankTracker();
        b.add("x", 1); b.add("y", 1);
        if (!b.get().equals("x") || !b.get().equals("y")) throw new AssertionError("e2");
        // Random calls checked by sorting all places and taking the i-th.
        Random rnd = new Random(2102);
        for (int round = 0; round < 300; round++) {
            RankTracker s = new RankTracker();
            List<int[]> all = new ArrayList<>();                  // {score, name number}
            int gets = 0, next = 0;
            for (int op = 0; op < 60; op++) {
                if (all.size() > gets && rnd.nextInt(3) == 0) {
                    gets++;
                    List<int[]> sorted = new ArrayList<>(all);
                    sorted.sort((x, y) -> x[0] != y[0] ? Integer.compare(y[0], x[0]) : Integer.compare(x[1], y[1]));
                    String want = "n" + (char) ('a' + sorted.get(gets - 1)[1] / 26) + (char) ('a' + sorted.get(gets - 1)[1] % 26);
                    if (!s.get().equals(want)) throw new AssertionError("rank " + gets);
                } else {
                    int score = 1 + rnd.nextInt(4);
                    String nm = "n" + (char) ('a' + next / 26) + (char) ('a' + next % 26);
                    all.add(new int[] {score, next++});
                    s.add(nm, score);
                }
            }
        }
    }

Equal Scores And Renames

  • Names are lowercase strings of length 1 to 8, and two players may share a name.

Example 2. Input calls add(1,zed,5), add(2,amy,5), rename(1,abe), topNames(2), output abe, amy.

Prerequisites. The two exercises above.

What This Exercise Changes. Equal names and scores must stay distinct entries, so the id joins the comparator.

Hint

What does a comparator that stops after the name do with two players called sam?

Algorithmic Solution (attempt the problem first)

Approach. A map from id to a record of name and score is the source of truth. A tree set of immutable entries holds the ranking. The comparator compares the higher score first, then the smaller name, then the smaller id, so two players with equal names and scores stay distinct.

A rename call removes the entry built from the stored name and score, stores the new name and inserts the new entry. A top call collects the names of the first k entries.

The invariant is that the set holds one entry per id, and the entry carries the stored name. A comparator that stops at the name would treat two players called sam with equal scores as one entry, and the second add would vanish.

Complexity.

  • Time is O(log n) per add and rename, and O(k) per query, because the iterator starts at the first entry.
  • Space is O(n), because each id owns one record and one entry.
import java.util.*;

public final class EqualRenamesSolution {
    static final class NameBoard {
        private record Row(int score, String name, int id) {}
        private final Map<Integer, Row> rowOf = new HashMap<>();     // id -> current row, source of truth
        private final TreeSet<Row> ranking = new TreeSet<>((a, b) -> {
            int c = Integer.compare(b.score(), a.score());
            if (c != 0) return c;
            c = a.name().compareTo(b.name());
            return c != 0 ? c : Integer.compare(a.id(), b.id());     // id keeps the order total
        });

        /** Registers a player; O(log n) time, O(1) extra space; invariant: one row per id in both structures. */
        void add(int id, String name, int score) {
            Row r = new Row(score, name, id);
            rowOf.put(id, r);
            ranking.add(r);
        }

        /**
         * Changes a name and repairs the ranking.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the removed row equals the stored row field by field.
         */
        void rename(int id, String newName) {
            Row old = rowOf.get(id);
            // The removal needs the old name, because the comparator reads it.
            ranking.remove(old);
            Row now = new Row(old.score(), newName, id);
            rowOf.put(id, now);
            ranking.add(now);
        }

        /** Returns the names of the first k rows; O(k) time, O(k) space for the result. */
        List<String> topNames(int k) {
            List<String> out = new ArrayList<>();
            for (Row r : ranking) {
                if (out.size() == k) break;
                out.add(r.name());
            }
            return out;
        }
    }

    public static void main(String[] args) {
        // Example 1: two players called sam with the same score both appear.
        NameBoard a = new NameBoard();
        a.add(1, "sam", 10); a.add(2, "sam", 10);
        if (!a.topNames(2).equals(List.of("sam", "sam"))) throw new AssertionError("e1");
        // Example 2: a rename moves a player ahead of an equal score.

Design Task Manager

Problem Specification. The contract below belongs to this chapter and can differ from the LeetCode text in detail. Design a class TaskManager built from tasks {userId, taskId, priority}. Input Constraints. The limits are:

  • Tasks number at most 10^5 at any time, and each taskId is unique among live tasks.
  • Priority satisfies 0 <= priority <= 10^9.
  • Calls number at most 2 * 10^5, and edit and rmv name live tasks.
  • Return of execTop is an int.

Example 1. Input tasks {1,101,5}, {2,102,9}, {3,103,9} and two execTop() calls, output 3 and then 2.

Example 2. Input tasks {1,101,5}, {2,102,9} and the calls edit(101,12), execTop(), rmv(102), execTop(), output 1 and then -1.

What This Exercise Changes. Execution removes the best entry, so it also removes the record from the map.

Hint

Which fields form the comparator, and which structure reads the old priority?

Algorithmic Solution (attempt the problem first)

Approach. A map from task id to an immutable task is the source of truth. A tree set of the same tasks is the ranking. The comparator puts the higher priority first and the larger task id second, which matches the required tie rule and keeps the order total.

An edit call removes the task built from the stored fields, stores a copy with the new priority and inserts it. A remove call deletes the task from the set and the map. An execute call takes the first task of the set, deletes it from the map as well, and returns its user id.

The invariant is that the map and the set hold the same tasks. Execute updates both structures, so a task never stays in one after it leaves the other.

Complexity.

  • Time per call is O(log n). A call costs one hash operation plus two tree operations at most.
  • Space is O(n), because each live task owns one map slot and one tree entry.
import java.util.*;

public final class TaskManagerSolution {
    static final class TaskManager {
        private record Task(int priority, int taskId, int userId) {}
        private final Map<Integer, Task> byId = new HashMap<>();       // taskId -> task, source of truth
        private final TreeSet<Task> ranking = new TreeSet<>((a, b) -> {
            int c = Integer.compare(b.priority(), a.priority());        // higher priority first
            return c != 0 ? c : Integer.compare(b.taskId(), a.taskId()); // larger task id first on ties
        });

        /** Adds a task; O(log n) time, O(1) space; invariant: the task enters both structures. */
        void add(int userId, int taskId, int priority) {
            Task t = new Task(priority, taskId, userId);
            byId.put(taskId, t);
            ranking.add(t);
        }

        /** Changes a priority; O(log n) time, O(1) space; invariant: the old entry leaves before the new one enters. */
        void edit(int taskId, int newPriority) {
            Task old = byId.get(taskId);
            ranking.remove(old);
            Task now = new Task(newPriority, taskId, old.userId());
            byId.put(taskId, now);
            ranking.add(now);
        }

        /** Deletes a task; O(log n) time, O(1) space; invariant: the task leaves both structures. */
        void rmv(int taskId) {
            ranking.remove(byId.remove(taskId));
        }

        /**
         * Removes and reports the best task.
         * Time: O(log n).
         * Space: O(1).
         * Invariant: the executed task leaves the map and the set together.
         */
        int execTop() {
            // pollFirst removes the best entry from the set in one step.
            Task best = ranking.pollFirst();
            if (best == null) return -1;
            byId.remove(best.taskId());
            return best.userId();
        }
    }

    public static void main(String[] args) {
        // Example 1: ties go to the larger task id.
        TaskManager a = new TaskManager();
        a.add(1, 101, 5); a.add(2, 102, 9); a.add(3, 103, 9);
        if (a.execTop() != 3 || a.execTop() != 2) throw new AssertionError("e1");
        // Example 2: edit then remove.
        TaskManager b = new TaskManager();
        b.add(1, 101, 5); b.add(2, 102, 9); b.edit(101, 12);
        if (b.execTop() != 1) throw new AssertionError("e2 first");
        b.rmv(102);
        if (b.execTop() != -1) throw new AssertionError("e2 last");
        // Random calls checked against a scan of a plain map.
        Random rnd = new Random(3408);
        for (int round = 0; round < 300; round++) {
            TaskManager s = new TaskManager();
            Map<Integer, int[]> ref = new HashMap<>();              // taskId -> {user, priority}
            int next = 0;
            for (int op = 0; op < 100; op++) {
                int t = rnd.nextInt(4);
                if (t == 0) { int u = rnd.nextInt(5), p = rnd.nextInt(4); ref.put(next, new int[] {u, p}); s.add(u, next++, p); }
                else if (t == 1 && !ref.isEmpty()) { int id = new ArrayList<>(ref.keySet()).get(rnd.nextInt(ref.size())); int p = rnd.nextInt(4); ref.get(id)[1] = p; s.edit(id, p); }
                else if (t == 2 && !ref.isEmpty()) { int id = new ArrayList<>(ref.keySet()).get(rnd.nextInt(ref.size())); ref.remove(id); s.rmv(id); }
                else if (t == 3) {
                    int best = -1;
                    for (int id : ref.keySet())
                        if (best == -1 || ref.get(id)[1] > ref.get(best)[1] || (ref.get(id)[1] == ref.get(best)[1] && id > best)) best = id;
                    int want = best == -1 ? -1 : ref.get(best)[0];
                    if (best != -1) ref.remove(best);
                    if (s.execTop() != want) throw new AssertionError("execTop");
                }
            }
        }

Problem

Two Customers Hold The Same Seat

A ticket service sells numbered seats for a small theater. A customer asks for any seat, and the service must hand out the lowest-numbered seat that nobody holds. Customers also cancel, and the service must hand a cancelled seat out again. One evening two customers receive seat 12, because the service handled one cancellation twice. Each customer arrives at the door with a valid ticket for the same chair.

The failure is a bookkeeping error, not a slow query. The service lost track of which seats customers hold. The same problem appears in port allocators, ID generators, meeting-room booking and license pools. Each caller asks for the best free item under some rule, and each caller can return an item later.

This lesson asks how to store free and held items so that the best free item comes out quickly. It also asks how to stop a repeated return of one item from creating a second copy.

Simple approach

Scanning Flags For The First Free Seat

The direct design keeps an array of flags. A reserve call scans from seat 1 for the first flag that says free. A cancel call sets the flag back.

final class NaiveSeats {
    private final boolean[] held;                       // held[s] is true while seat s belongs to a customer

    NaiveSeats(int n) { held = new boolean[n + 1]; }

    int reserve() {
        for (int s = 1; s < held.length; s++) {
            if (!held[s]) { held[s] = true; return s; }
        }
        return -1;
    }

    void unreserve(int s) { held[s] = false; }
}

The class is correct. A cancel call is idempotent, because setting a flag to false twice leaves the same state.

Predict first: A theater has 100,000 seats and the first 99,999 are held. How many flags does one reserve call read, and what changes if the class keeps released seats in a min-heap instead of scanning?

The scan reads 99,999 flags before it finds the last free seat, so each call costs O(n). A min-heap of released seats reads one entry, but releasing seat 12 twice pushes it twice, and two later reserve calls both return seat 12.

Bottleneck

Scans And Duplicates In The Free List

The array pays O(n) for every reserve when the low seats are all held, and the cost repeats for every call. A heap or sorted list of free seats removes the scan. It also removes the flag that told the class whether a customer holds a seat. Without that fact, a repeated release adds the seat to the free structure a second time.

A fast structure without a held record gives duplicates. A held record without a fast structure gives scans. The two facts about each seat have to live together and stay consistent.

Each seat has one status at any moment. A call that changes the status must change every structure that stores it. A call that does not change the status must change nothing.

Key idea

Every Resource Sits In Exactly One Set

Split the resources into two groups. The free set holds every resource that no caller owns, in sorted order, so the best free resource is the first element. The taken set records every resource that a caller owns, in a form that answers membership in O(1).

A Partition Of The Resources

The two sets form a partition of all resources. Every resource belongs to one set, and no resource belongs to both. The sum of the two sizes equals the total number of resources. This statement is the invariant, and every call must keep it true.

Moving One Resource At A Time

A reserve call removes the first element of the free set and marks it taken. A release call first checks the taken record. If the resource is not taken, the call stops, because a second release would put the resource into the free set twice. Otherwise the call unmarks the resource and inserts it into the free set. Each call moves at most one resource, and it removes the resource from its old set before it inserts it into the new one.

State

What Each Structure Records

Two structures and one rule carry the state.

  • free is a sorted set of the seat numbers that no customer holds, and its first element is the answer to a reserve call.
  • taken is a boolean array indexed by seat number, and it is true exactly for the seats that a customer holds.
  • Release rule says that a seat leaves taken and enters free only when taken is true for that seat.

The counts satisfy free.size() + (number of true flags) = n after every call.

Walkthrough

Following Seats And Gaps

Reserving And Releasing Seats

The first trace uses four seats. The pointer call sits on the call that just finished. Each step lists the free set and the taken seats.

The fourth call returns seat 1 and not seat 3. The release in the third call put seat 1 back into the free set, and the first element of that set is the smallest free seat.

Choosing A Seat By Distance

The second trace changes the rule. A room has seats 0 to 9, and each seat call picks the seat farthest from every occupied seat, with the smallest number winning ties.

This room needs a different structure. The useful structure is the sorted set of occupied seats. Each pair of neighbors defines a gap, and the middle of the gap is a candidate seat.

Code

A Seat Manager In Java

The class keeps the free set as a tree set and the taken record as a boolean array.

final class SeatManager {
    private final java.util.TreeSet<Integer> free = new java.util.TreeSet<>();
    private final boolean[] taken;

    SeatManager(int n) {
        taken = new boolean[n + 1];
        for (int s = 1; s <= n; s++) free.add(s);          // every seat starts free
    }

    int reserve() {
        if (free.isEmpty()) return -1;
        int s = free.pollFirst();                          // leave the free set first
        taken[s] = true;                                   // then enter the taken record
        return s;
    }

    boolean release(int s) {
        if (s < 1 || s >= taken.length || !taken[s]) return false;  // a second release stops here
        taken[s] = false;
        free.add(s);
        return true;
    }
}

A reserve call costs O(log n) and a release call costs O(log n). The constructor costs O(n log n). The space is O(n) for the set and the array.

When to use it

Allocators With A Sorted Free Set

Recognizing The Pattern

Look for calls that take the best available resource under a stated rule and return it later. State the rule first, such as smallest number, nearest to a target or farthest from the others. The invariant is that every resource sits in exactly one of the two sets, and every call moves at most one resource.

Sorted Set Or Counter

A resource pool that grows without bound and never receives repeated returns needs less. A counter for the next unused number plus a heap of returned numbers is enough, and the lesson Availability Priority later in this chapter shows it. A fixed pool of at most about 10^5 resources fits the sorted set above.

False Friends And Limits

A queue of free seats looks like an allocator, but it is a false friend when the rule asks for the smallest number and not the oldest release. A free list that skips the taken record is a false friend as well, because repeated releases create copies. Skip the pre-filled set when n reaches 10^9. The set would need a billion entries. The allocator has to derive free seats from the few seats that customers hold.

Exam Room

LeetCode 855

Problem Specification. A room has n seats numbered 0 to n - 1 in a row. Design a class ExamRoom. The call seat() seats a student at the free seat that maximizes the distance to the nearest occupied seat, and returns that seat. Equal distances go to the smallest seat number, and the first student sits at seat 0. The call leave(p) frees seat p.

Input Constraints. The limits are:

  • Seats satisfy 1 <= n <= 10^9.
  • Calls number at most 10^4.
  • Seat is called only while a free seat exists.
  • Leave names an occupied seat.

Example 1. Input n = 10 and four seat() calls, output 0, 9, 4 and 2.

Example 2. Input the same calls, then leave(4) and seat(), output 5.

Prerequisites. The seat manager exercise above.

What This Exercise Changes. The best seat depends on the gaps between occupied seats, so the sorted set holds occupied seats and a scan of neighbors picks the seat.

Hint

Which seats can ever be optimal: the two ends of the row, or the middle of a gap between neighbors?

Algorithmic Solution (attempt the problem first)

Approach. A tree set holds the occupied seats in order. The first student takes seat 0. For later students, the class lists every candidate seat. The candidates are seat 0 when it is free, the middle of each gap between two neighbors, and seat n - 1 when it is free.

The distance of seat 0 is the first occupied seat. The distance of the last seat is n - 1 minus the last occupied seat. A gap between neighbors a and b offers the seat a + (b - a) / 2 at distance (b - a) / 2. A distance of 0 offers nothing. The scan visits candidates from the lowest seat upward and replaces the best only for a strictly larger distance, so ties keep the smallest seat. A leave call removes the seat from the set.

The invariant is that the set holds exactly the occupied seats, and each candidate is a free seat whose nearest occupied seat is as far away as the candidate's distance.

Complexity.

  • Time is O(k) for a seat call and O(log k) for a leave call, with k occupied seats. The seat call visits each neighboring pair once.
  • Space is O(k), because the set holds the occupied seats.
import java.util.*;

public final class ExamRoomSolution {
    static final class ExamRoom {
        private final int n;
        private final TreeSet<Integer> occupied = new TreeSet<>();

        ExamRoom(int n) { this.n = n; }

        /**
         * Seats a student at the best free seat.
         * Time: O(k) for k occupied seats, because the scan visits each gap once.
         * Space: O(1) extra.
         * Invariant: bestDist is the largest distance among the candidates visited so far.
         */
        int seat() {
            if (occupied.isEmpty()) { occupied.add(0); return 0; }
            int bestSeat = 0, bestDist = occupied.first();              // seat 0, distance to the first student
            int prev = occupied.first();
            // Visit each pair of neighbors in increasing seat order.
            for (int cur : occupied.tailSet(prev, false)) {
                int d = (cur - prev) / 2;
                // Strictly greater keeps the smaller seat on ties.
                if (d > bestDist) { bestDist = d; bestSeat = prev + d; }
                prev = cur;
            }
            // The last seat competes with the right end of the row.
            if (n - 1 - prev > bestDist) bestSeat = n - 1;
            occupied.add(bestSeat);
            return bestSeat;
        }

        /** Frees seat p; O(log k) time, O(1) space; invariant: occupied loses exactly p. */
        void leave(int p) { occupied.remove(p); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        ExamRoom r = new ExamRoom(10);
        int[] first = {r.seat(), r.seat(), r.seat(), r.seat()};
        if (first[0] != 0 || first[1] != 9 || first[2] != 4 || first[3] != 2) throw new AssertionError("e1");
        r.leave(4);
        if (r.seat() != 5) throw new AssertionError("e2");
        // Random calls checked against a scan of every free seat.
        Random rnd = new Random(855);
        for (int round = 0; round < 300; round++) {
            int n = 2 + rnd.nextInt(14);
            ExamRoom s = new ExamRoom(n);
            boolean[] occ = new boolean[n];
            int count = 0;
            for (int op = 0; op < 60; op++) {
                if (count < n && (count == 0 || rnd.nextInt(3) > 0)) {
                    int want = 0, wantD = -1;
                    for (int c = 0; c < n; c++) {
                        if (occ[c]) continue;
                        int d = count == 0 ? n : Integer.MAX_VALUE;
                        for (int q = 0; q < n; q++) if (occ[q]) d = Math.min(d, Math.abs(q - c));
                        if (d > wantD) { wantD = d; want = c; }
                    }
                    occ[want] = true; count++;
                    if (s.seat() != want) throw new AssertionError("seat");
                } else {
                    int p = rnd.nextInt(n);
                    while (!occ[p]) p = (p + 1) % n;
                    occ[p] = false; count--;
                    s.leave(p);
                }
            }
        }
    }

Problem Specification. Design a class SeatBook for seats 1 to n. The call reserve() returns the smallest free seat and marks it held, or returns -1 when every seat is held. Input Constraints. The limits are:

  • Seats satisfy 1 <= n <= 10^5.
  • Calls number at most 10^5, and release accepts any integer.
  • Seat numbers passed to release fit in an int.
  • Available equals n minus the number of held seats after every call.

Example 2. Input n = 3 and calls release(0), release(3), available(), output false, false and 3.

What This Exercise Changes. A rejected release must leave both structures untouched, so the check comes before any change.

Hint

Which record answers whether a customer holds seat 3, without touching the free set?

Algorithmic Solution (attempt the problem first)

Approach. The free set is a tree set of seat numbers, and the taken record is a boolean array. A reserve call polls the first free seat, marks it taken and returns it, or returns -1 when the set is empty. A release call returns false when the number is outside 1 to n or when the taken flag is false. Otherwise it clears the flag, inserts the seat into the free set and returns true. The count of free seats is the size of the set.

The invariant is that a seat is in the free set exactly when its taken flag is false. The release check reads the flag before it touches the set, so a rejected call changes neither structure.

Complexity.

  • Time is O(log n) per call. The tree set polls and inserts in logarithmic time, and the flag check adds O(1).
  • Space is O(n), because the set and the array each hold up to n entries.
import java.util.*;

public final class DuplicateReleaseSolution {
    static final class SeatBook {
        private final TreeSet<Integer> free = new TreeSet<>();
        private final boolean[] taken;                              // taken[s] is true while s is held

        /** Starts with every seat free; O(n log n) time, O(n) space; invariant: free and taken partition 1..n. */
        SeatBook(int n) {
            taken = new boolean[n + 1];
            for (int s = 1; s <= n; s++) free.add(s);
        }

        /** Holds the smallest free seat or returns -1; O(log n) time, O(1) space; invariant: the seat moves from free to taken. */
        int reserve() {
            if (free.isEmpty()) return -1;
            int s = free.pollFirst();
            taken[s] = true;
            return s;
        }

        /**
         * Frees a held seat and rejects everything else.
         * Time: O(log n).
         * Space: O(1).
         * Invariant: the check reads taken first, so a rejected call changes nothing.
         */
        boolean release(int seat) {
            // Out-of-range numbers and free seats are rejected before any write.
            if (seat < 1 || seat >= taken.length || !taken[seat]) return false;
            taken[seat] = false;
            free.add(seat);
            return true;
        }

        /** Returns the number of free seats; O(1) time and space; invariant: it equals the size of free. */
        int available() { return free.size(); }
    }

    public static void main(String[] args) {
        // Example 1: the second release of seat 2 is rejected, and seat 2 comes back once.
        SeatBook a = new SeatBook(2);
        if (a.reserve() != 1 || a.reserve() != 2 || !a.release(2) || a.release(2) || a.reserve() != 2) throw new AssertionError("e1");
        // Example 2: out-of-range releases change nothing.
        SeatBook b = new SeatBook(3);
        if (b.release(0) || b.release(3) || b.available() != 3) throw new AssertionError("e2");
        if (b.release(Integer.MIN_VALUE) || b.release(Integer.MAX_VALUE)) throw new AssertionError("extreme ints");
        // Random calls including invalid releases, checked against a boolean array.
        Random rnd = new Random(41);
        for (int round = 0; round < 300; round++) {
            int n = 1 + rnd.nextInt(8);
            SeatBook s = new SeatBook(n);
            boolean[] held = new boolean[n + 2];
            for (int op = 0; op < 80; op++) {
                if (rnd.nextBoolean()) {
                    int want = -1;
                    for (int i = 1; i <= n && want == -1; i++) if (!held[i]) want = i;
                    if (want != -1) held[want] = true;
                    if (s.reserve() != want) throw new AssertionError("reserve");
                } else {
                    int seat = rnd.nextInt(n + 3) - 1;
                    boolean want = seat >= 1 && seat <= n && held[seat];
                    if (want) held[seat] = false;
                    if (s.release(seat) != want) throw new AssertionError("release");

                int free = 0;
                for (int i = 1; i <= n; i++) if (!held[i]) free++;
                if (s.available() != free) throw new AssertionError("available");
            }
        }

Booking Concert Tickets In Groups

LeetCode 2286

Problem Specification. A hall has n rows of m seats, numbered from 0 in each row. Seats in a row fill from the left, so row r with u held seats has seats 0 to u - 1 held. Design a class Hall. The call gather(k, maxRow) finds the smallest row r <= maxRow with at least k free seats, holds k seats there from the leftmost free seat, and returns [r, firstSeat]. It returns an empty array if no such row exists. The call scatter(k, maxRow) holds k seats in rows 0 to maxRow, filling the lowest rows first, and returns true. It returns false and changes nothing if those rows hold fewer than k free seats in total.

Input Constraints. The limits are:

  • Rows satisfy 1 <= n <= 5 * 10^4, and m satisfies 1 <= m <= 10^9.
  • k satisfies 1 <= k <= m, and maxRow satisfies 0 <= maxRow < n.
  • Calls number at most 5 * 10^4.
  • Totals of free seats can reach 5 * 10^13, so use long.

Example 1. Input n = 2, m = 5 and calls gather(4,0), gather(2,0), output [0,0] and an empty array.

Example 2. Input n = 2, m = 5 and calls scatter(5,1), gather(5,1), output true and [1,0].

Prerequisites. All three exercises above, and the segment tree from the range-query chapter.

What This Exercise Changes. One call needs a local fit in one row and the other needs total capacity over many rows, so each node stores both a maximum and a sum.

Hint

A gather call needs the leftmost row with a large enough maximum, and a scatter call needs a sum over a prefix of rows. What does one tree node store?

Algorithmic Solution (attempt the problem first)

Approach. Row r has free[r] free seats, and its held seats are the leftmost ones. A segment tree over the rows stores, for each node, the maximum and the sum of free over its rows.

A gather call descends from the root toward the leftmost row whose free count is at least k. At each node it goes left when the left child's maximum is at least k, and right otherwise. If that row is beyond maxRow, or no row qualifies, the call returns an empty array. Otherwise the first seat is m - free[r], and the call lowers free[r] by k with a point update. A scatter call sums the free seats of rows 0 to maxRow. It returns false when the sum is below k. Otherwise it takes seats from the first non-full row, then the next, until k seats are placed. The pointer to the first non-full row only moves forward, because rows only fill in this exercise.

The invariant is that every node holds the maximum and sum of its rows' free values, and each point update repairs the nodes on the path to the root.

Complexity.

  • Time is O(log n) per gather call and O((rows touched + 1) log n) per scatter call. Each touched row needs one point update, and scatter calls touch at most n rows in total.
  • Space is O(n), because the tree has about 4n nodes.
import java.util.*;

public final class ConcertTicketsSolution {
    static final class Hall {
        private final int n;
        private final long m;
        private final long[] free;                               // free[r] = free seats in row r
        private final long[] mx, sm;                             // segment tree: maximum and sum of free
        private int firstOpen = 0;                               // first row that may still have free seats

        /**
         * Builds the tree with every row empty.
         * Time: O(n).
         * Space: O(n).
         * Invariant: each node covers a row range and holds the max and sum of free there.
         */
        Hall(int n, int m) {
            this.n = n; this.m = m;
            free = new long[n];
            Arrays.fill(free, m);
            mx = new long[4 * n]; sm = new long[4 * n];
            build(1, 0, n - 1);
        }

        private void build(int node, int l, int r) {
            if (l == r) { mx[node] = sm[node] = m; return; }
            int mid = (l + r) / 2;
            build(2 * node, l, mid); build(2 * node + 1, mid + 1, r);
            pull(node);
        }

        // Recomputes one node from its two children in O(1).
        private void pull(int node) {
            mx[node] = Math.max(mx[2 * node], mx[2 * node + 1]);
            sm[node] = sm[2 * node] + sm[2 * node + 1];
        }

        private void set(int node, int l, int r, int pos, long v) {
            if (l == r) { mx[node] = sm[node] = v; return; }
            int mid = (l + r) / 2;
            if (pos <= mid) set(2 * node, l, mid, pos, v); else set(2 * node + 1, mid + 1, r, pos, v);
            pull(node);
        }

        // Sums free over rows [0, hi] in O(log n).
        private long sum(int node, int l, int r, int hi) {
            if (l > hi) return 0;
            if (r <= hi) return sm[node];
            int mid = (l + r) / 2;
            return sum(2 * node, l, mid, hi) + sum(2 * node + 1, mid + 1, r, hi);
        }

        /** Returns {row, firstSeat} or an empty array; O(log n) time, O(1) space; invariant: the row is the leftmost with at least k free. */
        int[] gather(int k, int maxRow) {
            if (mx[1] < k) return new int[0];
            // Descend to the leftmost row whose free count is at least k.
            int node = 1, l = 0, r = n - 1;
            while (l < r) {
                int mid = (l + r) / 2;
                if (mx[2 * node] >= k) { node = 2 * node; r = mid; } else { node = 2 * node + 1; l = mid + 1; }
            }
            if (l > maxRow) return new int[0];
            int seat = (int) (m - free[l]);
            free[l] -= k;
            set(1, 0, n - 1, l, free[l]);
            return new int[] {l, seat};
        }

        /** Holds k seats in the lowest rows up to maxRow or changes nothing; O((rows + 1) log n) time, O(1) space; invariant: the prefix sum check precedes every write. */
        boolean scatter(int k, int maxRow) {
            if (sum(1, 0, n - 1, maxRow) < k) return false;
            long need = k;
            while (need > 0) {
                // Skip rows that are already full; the pointer never moves backward.
                while (free[firstOpen] == 0) firstOpen++;
                long take = Math.min(free[firstOpen], need);
                free[firstOpen] -= take;
                set(1, 0, n - 1, firstOpen, free[firstOpen]);
                need -= take;
            }
            return true;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Hall h = new Hall(2, 5);
        int[] g = h.gather(4, 0);
        if (g.length != 2 || g[0] != 0 || g[1] != 0 || h.gather(2, 0).length != 0) throw new AssertionError("e1");
        Hall h2 = new Hall(2, 5);
        int[] g2;
        if (!h2.scatter(5, 1) || (g2 = h2.gather(5, 1)).length != 2 || g2[0] != 1 || g2[1] != 0) throw new AssertionError("e2");
        // Random calls checked against a plain array of free counts.
        Random rnd = new Random(2286);
        for (int round = 0; round < 300; round++) {
            int n = 1 + rnd.nextInt(6), m = 1 + rnd.nextInt(6);
            Hall s = new Hall(n, m);
            int[] free = new int[n];
            Arrays.fill(free, m);
            for (int op = 0; op < 40; op++) {
                int k = 1 + rnd.nextInt(m), maxRow = rnd.nextInt(n);
                if (rnd.nextBoolean()) {
                    int row = -1;
                    for (int r = 0; r < n && row == -1; r++) if (free[r] >= k) row = r;
                    int[] got = s.gather(k, maxRow);
                    if (row == -1 || row > maxRow) { if (got.length != 0) throw new AssertionError("gather none"); }
                    else {
                        if (got.length != 2 || got[0] != row || got[1] != m - free[row]) throw new AssertionError("gather row");
                        free[row] -= k;
                    }
                } else {
                    int total = 0;
                    for (int r = 0; r <= maxRow; r++) total += free[r];
                    boolean want = total >= k;
                    if (want) { int need = k; for (int r = 0; r <= maxRow && need > 0; r++) { int t = Math.min(free[r], need); free[r] -= t; need -= t; } }
                    if (s.scatter(k, maxRow) != want) throw new AssertionError("scatter");
                }
            }
        }
    }

Problem

Reporting The Most Frequent Word Live

A log analyzer reads search queries as they arrive. A dashboard next to the stream shows the most frequent query and the least frequent query seen so far, and it refreshes after every line. The analyzer keeps a hash map from query text to its count, so each line costs one update. Each refresh scans the whole map to find the largest count. With a million distinct queries, the scan takes longer than the gap between two lines.

The map holds the right counts. It cannot answer "which count is largest" without looking at every count. The same shape appears in rate limiters that report the busiest client, in autocomplete ranking and in cache eviction by use count.

This lesson asks how to arrange the keys so that a count change and a most-frequent query both finish quickly, even when a count goes down.

Simple approach

Scanning All Counts For The Largest

The direct design keeps one hash map from key to count. An increment adds 1 to the count. The most-frequent query scans every entry and keeps the largest.

final class NaiveCounts {
    private final java.util.Map<String, Integer> count = new java.util.HashMap<>();

    void inc(String key) { count.merge(key, 1, Integer::sum); }

    String mostCommon() {
        String best = "";
        int bestCount = 0;
        for (java.util.Map.Entry<String, Integer> e : count.entrySet()) {
            if (e.getValue() > bestCount) { bestCount = e.getValue(); best = e.getKey(); }
        }
        return best;                                  // scans every entry on every query
    }
}

An increment costs O(1), and a query costs O(n) for n distinct keys.

Predict first: A million distinct keys have counts between 1 and 5, and one query asks for the largest count after every increment. How many entries does the scan read per query, and how many different counts exist?

The scan reads a million entries per query. Only five different counts exist. The answer depends on five numbers, while the work depends on a million keys.

Bottleneck

Many Keys Share Few Counts

The scan costs O(n) per query, because keys with the same count are interchangeable for a max or min question and the scan still reads each one. A count changes by 1 per call. The key that moves leaves one group of equal counts and joins the group of the next count.

The number of distinct counts is small compared with the number of keys, since counts above c need at least c increments each. A structure that groups keys by count can answer a max query by looking at the group with the largest count, and the group changes only at its neighbors.

The grouping brings a new job. When a key moves from count 2 to count 3, the group for count 2 may become empty. An empty group must disappear, or the max and min queries read a group that holds no key.

Key idea

Keys Grouped By Exact Count

A frequency bucket holds every key whose count equals one number. Every live key sits in exactly one bucket, and the bucket's number equals the key's count.

One Step To A Neighbor

An increment moves a key by an adjacent move. The key leaves the bucket for count c and enters the bucket for count c + 1. A decrement moves it from c to c - 1. No other key changes, and the move touches only two buckets. When the target bucket does not exist yet, the call creates it. When the old bucket becomes empty, the call removes it.

Keeping The Buckets In Count Order

The bucket order is the sorted order of the bucket numbers. If the buckets form a list in this order, the first bucket holds the minimum count and the last bucket holds the maximum count. A new bucket always appears next to the bucket of the key that moved, because counts differ by 1. So the call splices the new bucket into the list in O(1) without a search.

The invariant has three parts. Every key is in exactly one bucket. The bucket number equals the key's count. No bucket is empty.

State

What The Class Keeps

The counter keeps three structures.

  • count maps each key to its current count and changes in every inc call.
  • bucket maps each count to the sorted set of keys that have it, and it changes in step with count.
  • top is the largest count that has a bucket, and it changes only when an increment passes it.

The call deletes an empty bucket from bucket, so the map holds only counts that some key has.

Walkthrough

Following Keys Between Buckets

Moving Keys Up By One

The first trace feeds six increments to the counter. In each step the pointer call marks the call just run, and the buckets appear from the smallest count to the largest.

The fifth call moves b from count 2 to count 3. Bucket 2 held only b, so it empties and the call removes it. The list then holds buckets 1 and 3, which are not neighbors in count, and the order of the list still matches the order of the counts.

Moving Keys Down By One

The second trace adds decrements. The bucket list must stay free of empty buckets in both directions.

The last call removes x from the counter, because its count reaches 0. Bucket 1 empties, and the list holds the remaining buckets only.

Code

An Increment-Only Counter In Java

The class stores buckets in a map from count to sorted keys, and it tracks the largest count.

final class BucketCounter {
    private final java.util.Map<String, Integer> count = new java.util.HashMap<>();
    private final java.util.Map<Integer, java.util.TreeSet<String>> bucket = new java.util.HashMap<>();
    private int top = 0;

    void inc(String key) {
        int c = count.getOrDefault(key, 0);
        if (c > 0) {                                           // leave the old bucket first
            java.util.TreeSet<String> old = bucket.get(c);
            old.remove(key);
            if (old.isEmpty()) bucket.remove(c);               // an empty bucket must disappear
        }
        count.put(key, c + 1);
        bucket.computeIfAbsent(c + 1, k -> new java.util.TreeSet<>()).add(key);
        top = Math.max(top, c + 1);                            // counts only grow, so top never needs a search
    }

    String mostCommon() {
        return top == 0 ? "" : bucket.get(top).first();
    }
}

An increment costs O(log n) because of the tree set, and a query costs O(log n). Replacing the tree set with a hash set gives O(1) for both and returns any key of the top bucket. The space is O(n).

When to use it

When Counts Form The Query

Recognizing Count Queries

The cue is an update that moves one count by a small step, together with a query for the minimum, the maximum or the most frequent item. State the step size first. The invariant is that each key sits in one bucket that matches its count, and no bucket stays empty.

Increments Only Or Both Directions

With increments only, the largest count never drops, so one integer tracks it. With decrements, the largest bucket can empty. Then the next maximum is the previous bucket in the list, and the list must store links in both directions. A heap of counts cannot delete the old count of a key cheaply, so it is not a substitute.

False Friends

A sorted map from count to key looks like the same design. It is a false friend when several keys share a count, because the map keeps only one of them. A priority queue holds the largest count at its root, but it gives no way to move a key by one step without a search. Skip buckets when counts jump by large amounts, because a jump creates many new buckets and a sorted structure costs the same.

Prerequisites. Hash maps and tree sets.

What This Exercise Changes. A key moves between adjacent buckets, so the call removes the old bucket once it empties and before the query reads the top.

Hint

Which two buckets does one increment touch, and which integer tracks the top?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from key to count is the source of truth. A second hash map from count to a sorted set of keys holds the buckets. An increment reads the old count and removes the key from that bucket, deleting the bucket when it empties. It then writes the new count and inserts the key into the next bucket. A single integer holds the largest count, because counts only grow.

The most common key is the first key of the top bucket, which is the smallest key of that bucket. A keysAt call copies the bucket for the count.

The invariant is that each key sits in the bucket numbered by its count, and no bucket is empty. The removal precedes the insertion, so a key never sits in two buckets.

Complexity.

  • Time is O(log n) per call, because each call does a few hash lookups and one or two tree operations on a bucket.
  • Space is O(n), because each key owns one count and one slot in a bucket.
import java.util.*;

public final class KeyBucketsSolution {
    static final class KeyBuckets {
        private final Map<String, Integer> countOf = new HashMap<>();          // key -> count, source of truth
        private final Map<Integer, TreeSet<String>> bucket = new HashMap<>();   // count -> sorted keys
        private int top = 0;                                                    // largest count with a bucket

        /**
         * Raises one count by 1 and moves the key to the next bucket.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the key leaves bucket c before it enters bucket c + 1.
         */
        void inc(String key) {
            int c = countOf.getOrDefault(key, 0);
            if (c > 0) {
                // Leave the old bucket and delete it when it empties.
                TreeSet<String> old = bucket.get(c);
                old.remove(key);
                if (old.isEmpty()) bucket.remove(c);
            }
            countOf.put(key, c + 1);
            bucket.computeIfAbsent(c + 1, k -> new TreeSet<>()).add(key);
            // Counts only grow, so the top never needs a search.
            top = Math.max(top, c + 1);
        }

        /** Returns the smallest key of the top bucket or an empty string; O(log n) time, O(1) space. */
        String mostCommon() { return top == 0 ? "" : bucket.get(top).first(); }

        /** Returns the keys with count c in order; O(k) time and space for k keys. */
        List<String> keysAt(int c) { return new ArrayList<>(bucket.getOrDefault(c, new TreeSet<>())); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.

        b.inc("y"); b.inc("x");
        if (!b.mostCommon().equals("x") || !b.keysAt(1).equals(List.of("x", "y"))) throw new AssertionError("e2");
        if (!new KeyBuckets().mostCommon().isEmpty()) throw new AssertionError("empty");
        // Random increments checked against a plain count map.
        Random rnd = new Random(4001);
        for (int round = 0; round < 300; round++) {
            KeyBuckets s = new KeyBuckets();
            Map<String, Integer> ref = new TreeMap<>();
            for (int op = 0; op < 60; op++) {
                String k = "k" + rnd.nextInt(6);
                ref.merge(k, 1, Integer::sum);
                s.inc(k);
                int best = 0; String bestKey = "";
                for (Map.Entry<String, Integer> e : ref.entrySet()) if (e.getValue() > best) { best = e.getValue(); bestKey = e.getKey(); }
                if (!s.mostCommon().equals(bestKey)) throw new AssertionError("mostCommon");

                List<String> want = new ArrayList<>();
                for (Map.Entry<String, Integer> e : ref.entrySet()) if (e.getValue() == c) want.add(e.getKey());
                if (!s.keysAt(c).equals(want)) throw new AssertionError("keysAt");
            }
        }
    }

Variation

All O`one Data Structure

LeetCode 432

Problem Specification. Design a class AllOne. The call inc(key) raises the count of a key by 1, starting from 0. The call dec(key) lowers the count by 1 and removes the key when the count reaches 0. The call getMaxKey() returns any key with the largest count, and getMinKey() returns any key with the smallest count. Both return an empty string when no key exists. Every call must run in O(1) time on average.

Input Constraints. The limits are:

  • Keys are lowercase strings of length 1 to 10.
  • Calls number at most 5 * 10^4.
  • Dec is called only for keys that exist.
  • Return of getMaxKey and getMinKey is any key that meets the rule.

Example 1. Input calls inc(a), inc(b), inc(b), getMaxKey(), getMinKey(), output b and a.

Example 2. Input calls inc(a), dec(a), getMaxKey(), output an empty string.

Prerequisites. The key buckets exercise above.

What This Exercise Changes. A decrement can empty the minimum bucket, so the min pointer moves to a neighbor and needs no search.

Hint

Why must the buckets form a linked list in count order, and which neighbor does a decrement read?

Algorithmic Solution (attempt the problem first)

Approach. The buckets form a doubly linked list in increasing count order, between a head sentinel with count 0 and a tail sentinel. Each node holds its count and a hash set of keys. A hash map from key to node is the source of truth for the key's count.

An increment starts at the key's node, or at the head for a new key. It looks at the next node. If that node has count one higher, the key joins it. Otherwise the call splices a new node right after the current one. A decrement looks at the previous node and does the mirror step, and a key whose count reaches 0 leaves the map. The call unlinks the old node when its set empties. The maximum key comes from the node before the tail, and the minimum key from the node after the head.

The invariant is that the list is sorted by count with no empty node, and each key's node has the key's count. Each call reads one neighbor, so the work is constant on average.

Complexity.

  • Time is O(1) on average per call, because each call reads one neighbor, changes a constant number of links and makes hash operations.
  • Space is O(n), because each key sits in one set and the list has at most n nodes.
import java.util.*;

public final class AllOneSolution {
    static final class AllOne {
        private static final class Node {
            final int count;
            final Set<String> keys = new HashSet<>();
            Node prev, next;
            Node(int count) { this.count = count; }
        }
        private final Node head = new Node(0), tail = new Node(0);              // sentinels
        private final Map<String, Node> nodeOf = new HashMap<>();                // key -> its node

        AllOne() { head.next = tail; tail.prev = head; }

        // Splices a new node after a in O(1).
        private Node insertAfter(Node a, int count) {
            Node n = new Node(count);
            n.prev = a; n.next = a.next;
            a.next.prev = n; a.next = n;
            return n;
        }

        // Removes a node from the list in O(1).
        private void unlink(Node n) { n.prev.next = n.next; n.next.prev = n.prev; }

        /**
         * Raises a count by 1.
         * Time: O(1) on average.
         * Space: O(1) extra.
         * Invariant: the target node sits directly after the old node and holds count + 1.
         */
        void inc(String key) {
            Node cur = nodeOf.get(key);
            Node from = cur == null ? head : cur;                  // the head stands for count 0
            Node target = from.next;
            // The neighbor may skip the needed count, so create the bucket when it does.
            if (target == tail || target.count != from.count + 1) target = insertAfter(from, from.count + 1);
            target.keys.add(key);
            nodeOf.put(key, target);
            // The old bucket may be empty now, so remove it.
            if (cur != null) { cur.keys.remove(key); if (cur.keys.isEmpty()) unlink(cur); }
        }

        /**
         * Lowers a count by 1 and drops the key at 0.
         * Time: O(1) on average.
         * Space: O(1) extra.
         * Invariant: the target node sits directly before the old node and holds count - 1.
         */
        void dec(String key) {
            Node cur = nodeOf.get(key);
            if (cur.count == 1) nodeOf.remove(key);
            else {
                Node target = cur.prev;
                if (target == head || target.count != cur.count - 1) target = insertAfter(cur.prev, cur.count - 1);
                target.keys.add(key);
                nodeOf.put(key, target);
            }
            cur.keys.remove(key);
            if (cur.keys.isEmpty()) unlink(cur);
        }

        /** Returns any key with the largest count; O(1) time and space. */
        String getMaxKey() { return tail.prev == head ? "" : tail.prev.keys.iterator().next(); }

        /** Returns any key with the smallest count; O(1) time and space. */
        String getMinKey() { return head.next == tail ? "" : head.next.keys.iterator().next(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        AllOne a = new AllOne();
        a.inc("a"); a.inc("b"); a.inc("b");
        if (!a.getMaxKey().equals("b") || !a.getMinKey().equals("a")) throw new AssertionError("e1");
        AllOne b = new AllOne();
        b.inc("a"); b.dec("a");
        if (!b.getMaxKey().isEmpty() || !b.getMinKey().isEmpty()) throw new AssertionError("e2");
        // Random calls checked against a plain count map; any key with the right count is accepted.
        Random rnd = new Random(432);
        for (int round = 0; round < 300; round++) {
            AllOne s = new AllOne();
            Map<String, Integer> ref = new HashMap<>();
            for (int op = 0; op < 80; op++) {
                String k = "k" + rnd.nextInt(5);
                if (ref.containsKey(k) && rnd.nextInt(3) == 0) {
                    s.dec(k);
                    if (ref.get(k) == 1) ref.remove(k); else ref.merge(k, -1, Integer::sum);
                } else { s.inc(k); ref.merge(k, 1, Integer::sum); }
                int hi = 0, lo = Integer.MAX_VALUE;
                for (int v : ref.values()) { hi = Math.max(hi, v); lo = Math.min(lo, v); }
                String mx = s.getMaxKey(), mn = s.getMinKey();
                if (ref.isEmpty()) { if (!mx.isEmpty() || !mn.isEmpty()) throw new AssertionError("empty"); }

Empty Bucket Removal

Author exercise

Problem Specification. Design a class CountLedger with the calls inc(key), dec(key) and getMaxKey() of the previous exercise, and a call bucketCount() that returns the number of distinct positive counts held by live keys. The call getMaxKey() returns the smallest key among those with the largest count, or an empty string when no key exists. The structure must keep no empty bucket after any call.

Input Constraints. The limits are:

  • Keys are lowercase strings of length 1 to 10.
  • Calls number at most 10^5, and dec names a live key.
  • Dec removes the key when its count reaches 0.
  • bucketCount returns an int and equals 0 when no key exists.

Example 1. Input calls inc(a), inc(b), inc(b), bucketCount(), dec(a), bucketCount(), output 2 and then 1.

Example 2. Input calls inc(x), inc(y), inc(x), inc(y), bucketCount(), dec(y), bucketCount(), output 1 and then 2.

Prerequisites. The two exercises above.

What This Exercise Changes. The check for an empty bucket moves into every call that removes a key from a bucket.

Hint

What does the structure hold for count 3 right after the last key with count 3 moves down?

Algorithmic Solution (attempt the problem first)

Approach. This solution stores the buckets in a tree map from count to a sorted set of keys, so the order of buckets comes from the tree and not from links. A hash map from key to count is the source of truth. One helper moves a key from a count to a new count. It removes the key from the old bucket, deletes that tree map entry when the set is empty, and inserts the key into the new bucket. A move to count 0 only removes.

The number of buckets is the size of the tree map. The largest count is the last key of the tree map, and its smallest key is the first element of that bucket.

The invariant is that every tree map entry holds at least one key, so bucketCount() equals the number of distinct counts held by live keys. The helper is the only code that changes a bucket, so the check for an empty bucket cannot be skipped.

Complexity.

  • Time is O(log n) per call, because the tree map and the tree sets cost logarithmic time per operation.
  • Space is O(n), since every key holds one count and sits in exactly one bucket set.
import java.util.*;

public final class EmptyBucketSolution {
    static final class CountLedger {
        private final Map<String, Integer> countOf = new HashMap<>();
        private final TreeMap<Integer, TreeSet<String>> buckets = new TreeMap<>();

        /**
         * Moves a key between buckets and deletes any bucket that empties.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: no entry of buckets is empty when the helper returns.
         */
        private void move(String key, int from, int to) {
            if (from > 0) {
                TreeSet<String> old = buckets.get(from);
                old.remove(key);
                // Delete the bucket in the same step that empties it.
                if (old.isEmpty()) buckets.remove(from);
            }
            if (to > 0) {
                countOf.put(key, to);
                buckets.computeIfAbsent(to, k -> new TreeSet<>()).add(key);
            } else {
                countOf.remove(key);
            }
        }

        /** Raises a count by 1; O(log n) time, O(1) space; invariant: delegated to move. */
        void inc(String key) {
            int c = countOf.getOrDefault(key, 0);
            move(key, c, c + 1);
        }

        /** Lowers a count by 1 and drops the key at 0; O(log n) time, O(1) space; invariant: delegated to move. */
        void dec(String key) {
            int c = countOf.get(key);
            move(key, c, c - 1);
        }

        /** Returns the smallest key with the largest count; O(log n) time, O(1) space. */
        String getMaxKey() { return buckets.isEmpty() ? "" : buckets.lastEntry().getValue().first(); }

        /** Returns the number of distinct positive counts; O(1) time and space. */
        int bucketCount() { return buckets.size(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        CountLedger a = new CountLedger();
        a.inc("a"); a.inc("b"); a.inc("b");
        if (a.bucketCount() != 2) throw new AssertionError("e1 before");
        a.dec("a");
        if (a.bucketCount() != 1) throw new AssertionError("e1 after");
        CountLedger b = new CountLedger();
        b.inc("x"); b.inc("y"); b.inc("x"); b.inc("y");
        if (b.bucketCount() != 1) throw new AssertionError("e2 before");
        b.dec("y");
        if (b.bucketCount() != 2) throw new AssertionError("e2 after");
        if (new CountLedger().bucketCount() != 0 || !new CountLedger().getMaxKey().isEmpty()) throw new AssertionError("empty");
        // Random calls checked against a recount of distinct values.
        Random rnd = new Random(4003);
        for (int round = 0; round < 300; round++) {
            CountLedger s = new CountLedger();
            Map<String, Integer> ref = new TreeMap<>();
            for (int op = 0; op < 80; op++) {
                String k = "k" + rnd.nextInt(5);
                if (ref.containsKey(k) && rnd.nextInt(3) == 0) {
                    s.dec(k);
                    if (ref.get(k) == 1) ref.remove(k); else ref.merge(k, -1, Integer::sum);
                } else { s.inc(k); ref.merge(k, 1, Integer::sum); }
                if (s.bucketCount() != new HashSet<>(ref.values()).size()) throw new AssertionError("bucketCount");
                int hi = 0; String hiKey = "";
                for (Map.Entry<String, Integer> e : ref.entrySet()) if (e.getValue() > hi) { hi = e.getValue(); hiKey = e.getKey(); }
                if (!s.getMaxKey().equals(hiKey)) throw new AssertionError("getMaxKey");
            }
        }
    }

Maximum Frequency Stack

LeetCode 895

Problem Specification. Design a class FreqStack. The call push(val) pushes an integer. The call pop() removes and returns the value with the highest number of occurrences currently in the stack. When several values tie, it removes the occurrence of the value whose latest remaining occurrence is closest to the top.

Input Constraints. The limits are:

  • Values satisfy 0 <= val <= 10^9.
  • Calls number at most 2 * 10^4.
  • Pop is called only on a non-empty stack.
  • Return of pop is an int.

Example 1. Input pushes of 5, 7, 5, 7, 4, 5 and then four pop() calls, output 5, 7, 5, 4.

Example 2. Input pushes of 1, 1, 2 and then two pop() calls, output 1 and then 2.

Prerequisites. All three exercises above.

What This Exercise Changes. Ties break by recency, so each bucket stores values in push order and a pop reads the top of the highest bucket.

Hint

Keep one stack for each frequency. Which stack does a push join, and which stack does a pop read?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from value to count is the source of truth. A second hash map from frequency to a stack of values holds the buckets. A push raises the count of the value to f and pushes the value onto the stack for f. The value therefore appears once in every stack from 1 up to its count, in push order. An integer tracks the highest frequency that has a non-empty stack.

A pop takes the top of the stack for the highest frequency, lowers that value's count by 1 and lowers the highest frequency when the stack becomes empty. The top of the highest stack is the value whose latest push reached that frequency, which is the value closest to the top among the tied values.

The invariant is that the stack for frequency f holds one entry for each value with a count of at least f, in the order in which those values reached f.

Complexity.

  • Time is O(1) per call, because each call does a constant number of hash and deque operations.
  • Space is O(n), because a value with count f owns f entries, and the entries add up to the number of pushes.
import java.util.*;

public final class FreqStackSolution {
    static final class FreqStack {
        private final Map<Integer, Integer> countOf = new HashMap<>();            // value -> occurrences
        private final Map<Integer, Deque<Integer>> stackAt = new HashMap<>();      // frequency -> values in push order
        private int top = 0;                                                       // highest non-empty frequency

        /**
         * Pushes a value into the stack for its new frequency.
         * Time: O(1).
         * Space: O(1) extra.
         * Invariant: the value appears in stacks 1 through its count.
         */
        void push(int val) {
            int f = countOf.merge(val, 1, Integer::sum);
            stackAt.computeIfAbsent(f, k -> new ArrayDeque<>()).push(val);
            top = Math.max(top, f);
        }

        /**
         * Removes the most frequent value, preferring the latest push on ties.
         * Time: O(1).
         * Space: O(1) extra.
         * Invariant: top names the highest non-empty stack after the call.
         */
        int pop() {
            Deque<Integer> st = stackAt.get(top);
            int val = st.pop();
            // The highest stack may empty, so move top down by one.
            if (st.isEmpty()) top--;
            // Lower the count or drop the value at zero.
            if (countOf.get(val) == 1) countOf.remove(val); else countOf.merge(val, -1, Integer::sum);
            return val;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        FreqStack a = new FreqStack();
        for (int v : new int[] {5, 7, 5, 7, 4, 5}) a.push(v);
        int[] want = {5, 7, 5, 4};
        for (int w : want) if (a.pop() != w) throw new AssertionError("e1");
        FreqStack b = new FreqStack();
        b.push(1); b.push(1); b.push(2);
        if (b.pop() != 1 || b.pop() != 2) throw new AssertionError("e2");
        // Random calls checked against a list scan: highest count, then latest last occurrence.
        Random rnd = new Random(895);
        for (int round = 0; round < 300; round++) {
            FreqStack s = new FreqStack();
            List<Integer> ref = new ArrayList<>();
            for (int op = 0; op < 80; op++) {
                if (ref.isEmpty() || rnd.nextInt(5) < 3) { int v = rnd.nextInt(4); ref.add(v); s.push(v); }
                else {
                    int bestVal = -1, bestCount = 0, bestLast = -1;
                    for (int v = 0; v < 4; v++) {
                        int cnt = Collections.frequency(ref, v), last = ref.lastIndexOf(v);
                        if (cnt > bestCount || (cnt == bestCount && cnt > 0 && last > bestLast)) { bestVal = v; bestCount = cnt; bestLast = last; }
                    }
                    ref.remove(bestLast);
                    if (s.pop() != bestVal) throw new AssertionError("pop");
                }
            }
        }
    }

Problem

Raising The Priority Of A Queued Job

A job scheduler keeps waiting jobs in a priority queue and always starts the job with the highest priority. Users can raise or lower the priority of a job that is still waiting. During a busy hour, the scheduler holds 100,000 waiting jobs and receives thousands of priority changes per second. The developer implements a change as "remove the job from the queue, then add it back with the new priority". Throughput collapses, and a profile shows that almost all the time goes into the removal step.

A priority queue answers "who is first?" very well. It answers "where is this job?" badly. The same pattern appears in task managers, auction pages, timers that can be rescheduled and shortest-path searches whose distances improve.

This lesson asks how to change priorities without ever searching the queue, and how to make sure that an outdated queue entry never decides an answer.

Simple approach

Remove And Re-Add On Every Change

The direct design uses java.util.PriorityQueue and a change call that removes the old object before it adds the new one.

final class NaiveScheduler {
    record Job(int priority, int id) {}
    private final java.util.PriorityQueue<Job> queue = new java.util.PriorityQueue<>(
            (a, b) -> a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(a.id(), b.id()));
    private final java.util.Map<Integer, Job> jobOf = new java.util.HashMap<>();

    void set(int id, int priority) {
        Job old = jobOf.get(id);
        if (old != null) queue.remove(old);                  // linear search through the heap array
        Job now = new Job(priority, id);
        jobOf.put(id, now);
        queue.add(now);
    }

    int poll() {
        Job top = queue.poll();
        if (top == null) return -1;
        jobOf.remove(top.id());
        return top.id();
    }
}

The class gives correct answers. A set call costs O(n) when the job already exists, and a poll costs O(log n).

Predict first: A heap holds 100,000 jobs, and the scheduler changes the priority of one job. How many entries can the removal step compare before it finds the job, and what could the scheduler do instead of removing it?

The heap array has no order that helps a search, so the removal can compare all 100,000 entries. The scheduler could leave the old entry in the heap and add a second entry with the new priority. It then has to recognize and ignore the old entry when that entry reaches the top.

Bottleneck

The Search Inside The Heap

A heap keeps only one promise: the top entry is the best. The other entries sit in an order that supports sift operations and nothing else. PriorityQueue.remove(Object) therefore scans the array, which costs O(n) per priority change.

Skipping the removal looks cheap. The scheduler adds the new entry and leaves the old one in place, so a change costs O(log n). The old entry now competes for the top. Suppose a job had priority 5 and later received priority 1. The old entry with priority 5 reaches the top, the scheduler starts the job early, and the answer is wrong.

The queue needs a way to tell an old entry from a current one in O(1) time, using information that lives outside the heap.

Key idea

Trust The Record, Not The Queue

The map from job id to its current priority is the authoritative record. The heap is only a list of candidates. A candidate describes what the record said at the time of the call that created it.

Telling Candidates Apart

Each call that creates a candidate also tags it with a version, which is a counter value that grows with every call. The record stores the version of the newest candidate for each job. A candidate is current only when its version equals the stored version. Comparing priorities is not enough, because a job can be cancelled and added again with the same priority, and the old candidate would look correct while it is not.

Discarding At The Top

A candidate that fails the check is a stale entry. The class never searches for stale entries. It drops one only when it reaches the top, at the moment the answer depends on it. The top is checked in a loop: poll a candidate, compare its version with the record, and keep it only if the versions match. Each stale entry is dropped once, so the total drop work is bounded by the number of entries ever added.

The invariant is that every live job has exactly one current candidate in the heap, and a candidate leaves the loop only if it matches the record.

State

Record Fields And Heap Fields

The scheduler keeps a record map, a heap and a counter.

  • current maps each live job id to its priority and its newest version, and a set call overwrites that entry.
  • heap holds entries of priority, id and version, and a set call adds one entry without removing any.
  • clock is the counter that hands out the next version, and it only grows.

A cancel call removes the job from current and leaves its heap entries in place. Those entries fail the version check later, because the job is missing from the record.

Code

A Job Queue With Version Checks

The class stores the record in a map and the candidates in a heap.

final class JobQueue {
    private record Entry(int priority, int id, int version) {}
    private final java.util.PriorityQueue<Entry> heap = new java.util.PriorityQueue<>((a, b) ->
            a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(a.id(), b.id()));
    private final java.util.Map<Integer, int[]> current = new java.util.HashMap<>();   // id -> {priority, version}
    private int clock = 0;

    void set(int id, int priority) {
        int v = ++clock;
        current.put(id, new int[] {priority, v});            // the record changes first
        heap.add(new Entry(priority, id, v));                // the old entry stays in the heap
    }

    void cancel(int id) { current.remove(id); }

    int poll() {
        while (!heap.isEmpty()) {
            Entry e = heap.poll();
            int[] cur = current.get(e.id());
            if (cur != null && cur[1] == e.version()) {      // only the newest entry of a live job passes
                current.remove(e.id());
                return e.id();
            }
        }
        return -1;
    }
}

A set call costs O(log n). A poll call costs O(log n) per entry it drops and per entry it returns. Each entry is dropped at most once, so the cost of dropping is O(log n) amortized per set call. The space is O(total set calls) until the heap is rebuilt.

When to use it

When Stale Entries Are Cheaper Than Removal

Checking The Conditions

Use versioned candidates when callers change or cancel items far more often than they ask for the best item, and when the heap offers no handle to an arbitrary entry. The invariant is that the record decides, and a heap entry is exposed only if it still matches the record.

Memory And Rebuilding

Stale entries accumulate in the heap between polls. If the workload makes millions of changes and few polls, the heap grows far beyond the number of live jobs. A rebuild fixes this. When the heap size exceeds about twice the live count, copy the current entries into a new heap and drop the rest.

False Friends

A sorted set with an exact removal is a false friend of this design when the entries are small and immutable. It supports removal in O(log n), and it needs no versions, so it is the simpler choice. A second false friend is a priority change that only ever raises a priority in a minimum heap, as in shortest paths, where a duplicate entry is harmless and a plain distance check is enough. Skip versions when the heap must also answer "what is the k-th best" for large k, because stale entries distort that answer.

Problem Specification. Design a class JobBoard. The call set(id, priority) adds a job with a new id or changes the priority of an existing job. The call cancel(id) deletes a live job. Hint

Which value tells a heap entry that a newer entry for the same job exists?

Algorithmic Solution (attempt the problem first)

Approach. The record is a hash map from job id to the newest heap entry of that job. A set call builds a new immutable entry, stores it in the record and adds it to the heap. The older entry of the same job stays in the heap. A cancel call removes the job from the record.

A poll call pops entries until one is current. An entry is current when the record holds that very object for its id. The object itself acts as the version, because every set call creates a new object, so no two calls ever share one. The size is the size of the record.

The invariant is that every live job has exactly one current entry in the heap, and a popped entry is returned only if the record still points to it.

Complexity.

  • Time is O(log n) per set call, and a poll call costs O(log n) for each entry it pops. Each entry is popped once, so the cost is O(log n) amortized per call.
  • Space is O(m), where m is the number of set calls since the heap was last emptied, because stale entries stay until they reach the top.
import java.util.*;

public final class VersionedHeapSolution {
    static final class JobBoard {
        private record Entry(int priority, int id) {}                       // a fresh object per set call
        private final PriorityQueue<Entry> heap = new PriorityQueue<>((a, b) ->
                a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(a.id(), b.id()));
        private final Map<Integer, Entry> newest = new HashMap<>();         // id -> its current entry, source of truth

        /**
         * Adds a job or changes its priority.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: newest.get(id) is the only current entry of the job.
         */
        void set(int id, int priority) {
            Entry e = new Entry(priority, id);
            newest.put(id, e);
            heap.add(e);
        }

        /** Deletes a live job; O(1) time and space; invariant: its heap entries stop matching the record. */
        void cancel(int id) { newest.remove(id); }

        /**
         * Removes and returns the best live job.
         * Time: O(log n) per popped entry.
         * Space: O(1) extra.
         * Invariant: a popped entry is returned only if the record holds the same object.
         */
        int poll() {
            while (!heap.isEmpty()) {
                Entry e = heap.poll();
                // Identity comparison tells the newest entry from every older one, even with equal fields.
                if (newest.get(e.id()) == e) { newest.remove(e.id()); return e.id(); }
            }
            return -1;
        }

        /** Returns the number of live jobs; O(1) time and space. */
        int size() { return newest.size(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        JobBoard a = new JobBoard();
        a.set(1, 5); a.set(2, 9); a.set(1, 12);
        if (a.poll() != 1 || a.poll() != 2 || a.poll() != -1) throw new AssertionError("e1");
        JobBoard b = new JobBoard();
        b.set(4, 3); b.cancel(4);
        if (b.size() != 0 || b.poll() != -1) throw new AssertionError("e2");
        // Random calls checked against a scan of a plain map.
        Random rnd = new Random(5001);
        for (int round = 0; round < 300; round++) {
            JobBoard s = new JobBoard();
            Map<Integer, Integer> ref = new HashMap<>();
            for (int op = 0; op < 100; op++) {
                int t = rnd.nextInt(4);
                if (t == 0) { int id = rnd.nextInt(6), p = rnd.nextInt(4); ref.put(id, p); s.set(id, p); }
                else if (t == 1 && !ref.isEmpty()) { int id = new ArrayList<>(ref.keySet()).get(rnd.nextInt(ref.size())); ref.remove(id); s.cancel(id); }
                else if (t == 2) {
                    int best = -1;
                    for (int id : ref.keySet()) if (best == -1 || ref.get(id) > ref.get(best) || (ref.get(id).equals(ref.get(best)) && id < best)) best = id;
                    if (best != -1) ref.remove(best);
                    if (s.poll() != best) throw new AssertionError("poll");
                } else if (s.size() != ref.size()) throw new AssertionError("size");
            }
        }
    }

Design Movie Rental System

LeetCode 1912

Problem Specification. Shops of a rental chain own at most one copy per movie, each with a fixed price. Write a class RentalReport built from entries {shop, movie, price}, with all copies unrented. The call rent(shop, movie) marks a copy rented. The call drop(shop, movie) marks it unrented. The call report() lists the 5 cheapest rented copies as {shop, movie}, or all of them when fewer exist, with ties broken by shop and then movie. A copy may be rented, dropped and rented again.

Input Constraints. The limits are:

  • Entries number at most 10^5, each {shop, movie} pair appears once, and prices are int values from 1 to 10^4.
  • Calls number at most 10^5.
  • Rent names an unrented copy, and drop names a rented copy.
  • Report must not list a copy twice.

Example 1. Input entries {0,1,5}, {0,2,6}, {1,1,4} and calls rent(0,1), rent(1,1), report(), output {1,1} and {0,1}.

Example 2. Input the same entries and calls rent(1,1), drop(1,1), rent(1,1), rent(0,2), report(), output {1,1} and {0,2}.

Prerequisites. The versioned heap exercise above.

What This Exercise Changes. The report reads five entries and puts the valid ones back, so a version check runs on every popped entry.

Hint

What does the heap hold for a copy that was rented twice, and how does the report avoid listing it twice?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from the copy key to its rent version holds exactly the rented copies, and it is the source of truth. Every rent call increments a counter, stores the new version in the map and adds a heap entry that carries the same version. A drop call removes the copy from the map.

A report call pops entries from the heap and keeps those whose version equals the stored version, until it has five or the heap is empty. Popped stale entries are discarded for good. The call then pushes the kept entries back, so the report does not change the state. A copy rented, dropped and rented again has two entries, and only the newer one matches, so the copy appears once.

The invariant is that each rented copy has exactly one current entry in the heap, and every popped entry that fails the check is dropped.

Complexity.

  • Time is O(log n) per rent call and O((s + 5) log n) per report call, where s counts the stale entries it drops. Each stale entry is dropped once, so the drops add O(log n) amortized per earlier rent call.
  • Space is O(m), where m is the number of rent calls, because stale entries stay until a report reaches them.
import java.util.*;

public final class RentalReportSolution {
    static final class RentalReport {
        private record Item(int price, int shop, int movie, int version) {}
        private final Map<Long, Integer> price = new HashMap<>();             // pair key -> fixed price
        private final Map<Long, Integer> rentedVersion = new HashMap<>();     // rented pair key -> newest version
        private final PriorityQueue<Item> heap = new PriorityQueue<>((a, b) -> {
            int c = Integer.compare(a.price(), b.price());
            if (c != 0) return c;
            c = Integer.compare(a.shop(), b.shop());
            return c != 0 ? c : Integer.compare(a.movie(), b.movie());
        });
        private int clock = 0;

        private static long key(int shop, int movie) { return ((long) shop << 32) | movie; }

        RentalReport(int[][] entries) {
            for (int[] e : entries) price.put(key(e[0], e[1]), e[2]);
        }

        /** Marks a copy rented and adds one candidate; O(log n) time, O(1) space; invariant: the record holds the newest version. */
        void rent(int shop, int movie) {
            int v = ++clock;
            rentedVersion.put(key(shop, movie), v);
            heap.add(new Item(price.get(key(shop, movie)), shop, movie, v));
        }

        /** Marks a copy unrented; O(1) time and space; invariant: its candidates stop matching the record. */

                // Keep only the newest candidate of a rented copy; drop the rest for good.
                if (v != null && v == it.version()) kept.add(it);
            }
            List<int[]> out = new ArrayList<>();
            for (Item it : kept) { out.add(new int[] {it.shop(), it.movie()}); heap.add(it); }
            return out;
        }
    }

Repeated Corrections

Author exercise

Problem Specification. Design a class Desk with the calls set(id, priority), cancel(id), poll() and size() of the versioned heap exercise, and a call peek(). The call peek() returns the id that poll() would return, but removes nothing. Calling peek() any number of times must not change any later answer. Equal priorities go to the smaller id.

Input Constraints. The limits are:

  • Ids are integers from 1 to 10^5, and priorities satisfy 0 <= priority <= 10^9.
  • Calls number at most 2 * 10^5, and one id may receive thousands of set calls.
  • Cancel names a live job.
  • Return of peek and poll is -1 when no job is live.

Example 1. Input calls set(1,5), set(1,9), set(1,5), peek(), poll(), peek(), output 1, 1 and -1.

Example 2. Input calls set(2,4), set(3,4), cancel(2), set(2,4), peek(), poll(), poll(), output 2, 2 and 3.

Prerequisites. The two exercises above.

What This Exercise Changes. A read-only call may drop stale entries but never a live entry, and repeated corrections must not change any answer.

Hint

May a peek call discard a stale entry, and may it discard a live one?

Algorithmic Solution (attempt the problem first)

Approach. The record maps each live id to its priority and newest version, and the heap holds candidates stamped with versions. A set call adds a candidate. A peek call drops stale candidates from the top until the top matches the record, and it leaves that live candidate in place. A poll call runs the same loop and then removes the live top.

Because peek removes only entries that fail the version check, it never changes an answer. Thousands of corrections to one id would still grow the heap. Every mutating call therefore compares the heap size with twice the live count plus 16. When the heap is larger, the call rebuilds the heap from the record, which holds exactly one candidate per live job.

The invariant is that the record decides every answer, and after every call the heap holds at most 2 * live + 16 entries.

Complexity.

  • Time is O(log n) amortized per call. A rebuild costs O(n) and runs only after the heap has grown by at least live + 16 entries, which pays for it.
  • Space is O(live) after every call, because the rebuild rule bounds the heap.
import java.util.*;

public final class RepeatedCorrectionsSolution {
    static final class Desk {
        private record Entry(int priority, int id, int version) {}
        private final PriorityQueue<Entry> heap = new PriorityQueue<>((a, b) ->
                a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(a.id(), b.id()));
        private final Map<Integer, int[]> record = new HashMap<>();           // id -> {priority, version}
        private int clock = 0;

        // Rebuilds the heap from the record when stale entries dominate; O(n) time, O(n) space.
        private void compact() {
            if (heap.size() <= 2 * record.size() + 16) return;
            heap.clear();
            for (Map.Entry<Integer, int[]> e : record.entrySet()) heap.add(new Entry(e.getValue()[0], e.getKey(), e.getValue()[1]));
        }

        /** Adds a job or changes its priority; O(log n) amortized time, O(1) extra space; invariant: the record holds the newest version. */
        void set(int id, int priority) {
            record.put(id, new int[] {priority, ++clock});
            heap.add(new Entry(priority, id, clock));
            compact();
        }

        /** Deletes a live job; O(1) amortized time, O(1) space; invariant: its entries stop matching the record. */
        void cancel(int id) { record.remove(id); compact(); }

        // Drops stale entries from the top until the top matches the record or the heap is empty.
        private Entry liveTop() {
            while (!heap.isEmpty()) {
                Entry e = heap.peek();
                int[] r = record.get(e.id());
                if (r != null && r[1] == e.version()) return e;
                heap.poll();
            }
            return null;
        }

        /** Returns the best live id without removing it; O(log n) amortized time, O(1) space; invariant: only stale entries leave the heap. */
        int peek() {
            Entry e = liveTop();
            return e == null ? -1 : e.id();
        }

        /** Removes and returns the best live id; O(log n) amortized time, O(1) space; invariant: the record and the heap lose the same job. */
        int poll() {
            Entry e = liveTop();
            if (e == null) return -1;
            heap.poll();
            record.remove(e.id());
            compact();
            return e.id();
        }

        int size() { return record.size(); }
        int heapSize() { return heap.size(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Desk a = new Desk();
        a.set(1, 5); a.set(1, 9); a.set(1, 5);
        if (a.peek() != 1 || a.poll() != 1 || a.peek() != -1) throw new AssertionError("e1");
        Desk b = new Desk();
        b.set(2, 4); b.set(3, 4); b.cancel(2); b.set(2, 4);
        if (b.peek() != 2 || b.poll() != 2 || b.poll() != 3) throw new AssertionError("e2");
        // Heavy corrections of one id keep the heap bounded and the answers unchanged.
        Desk c = new Desk();
        for (int i = 0; i < 10_000; i++) c.set(7, i % 3);
        if (c.heapSize() > 2 * c.size() + 16 || c.peek() != 7 || c.peek() != 7) throw new AssertionError("heavy corrections");
        // Random calls with many peeks, checked against a scan of a plain map.
        Random rnd = new Random(5003);
        for (int round = 0; round < 300; round++) {
            Desk s = new Desk();
            Map<Integer, Integer> ref = new HashMap<>();
            for (int op = 0; op < 150; op++) {
                int t = rnd.nextInt(5);
                if (t <= 1) { int id = rnd.nextInt(5), p = rnd.nextInt(3); ref.put(id, p); s.set(id, p); }
                else if (t == 2 && !ref.isEmpty()) { int id = new ArrayList<>(ref.keySet()).get(rnd.nextInt(ref.size())); ref.remove(id); s.cancel(id); }
                else {
                    int best = -1;
                    for (int id : ref.keySet()) if (best == -1 || ref.get(id) > ref.get(best) || (ref.get(id).equals(ref.get(best)) && id < best)) best = id;
                    if (s.peek() != best || s.peek() != best) throw new AssertionError("peek");
                    if (t == 4) { if (best != -1) ref.remove(best); if (s.poll() != best) throw new AssertionError("poll"); }
                }
                if (s.size() != ref.size() || s.heapSize() > 2 * s.size() + 16) throw new AssertionError("size or bound");
            }
        }
    }

Design Auction System

LeetCode 3815

Problem Specification. The contract here is the chapter's own and can differ in detail from LeetCode. Design a class Auction. The call addBid(userId, itemId, amount) records a bid, and a new bid by the same user on the same item replaces that user's earlier bid. The call removeBid(userId, itemId) withdraws the user's current bid on the item. The call getHighestBidder(itemId) returns the user with the highest current bid on the item, breaking ties by the larger user id, or -1 if the item has no bid.

Input Constraints. The limits are:

  • Users and items are integers from 1 to 10^5.
  • Amounts satisfy 1 <= amount <= 10^9.
  • Calls number at most 2 * 10^5, and removeBid names a user with a current bid on that item.
  • Return of getHighestBidder is an int.

Example 1. Input calls addBid(1,10,50), addBid(2,10,70), addBid(1,10,80), getHighestBidder(10), output 1.

Example 2. Input calls addBid(1,10,50), addBid(2,10,50), getHighestBidder(10), removeBid(2,10), getHighestBidder(10), output 2 and then 1.

Prerequisites. All three exercises above.

What This Exercise Changes. The record is keyed by user and item, and each item owns its own heap of candidates.

Hint

Which key identifies one bid in the record, and how many heaps does the system need?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from the pair of user and item to the current bid and its version is the source of truth. Each item owns a heap of bid candidates, ordered by higher amount first and then by larger user id. Each add call increments a counter, stores the amount and version in the map and adds a candidate to the item's heap. A remove call deletes the pair from the map.

A highest-bidder query looks at the top of the item's heap. If the pair is missing from the map, or its stored version differs from the candidate's version, the candidate is stale and the query pops it. The query stops at the first current candidate and leaves it in place. A user who bids twice has two candidates, and only the newer one matches.

The invariant is that every current bid has exactly one current candidate in its item's heap, and the query exposes a candidate only after the version check.

Complexity.

  • Time is O(log n) per add call and O(log n) amortized per query, because each stale candidate is popped once.
  • Space is O(b), where b is the number of add calls, because stale candidates stay until a query reaches them.
import java.util.*;

public final class AuctionSolution {
    static final class Auction {
        private record Bid(int amount, int user, int version) {}
        private final Map<Long, int[]> current = new HashMap<>();                       // (user,item) -> {amount, version}
        private final Map<Integer, PriorityQueue<Bid>> heapOf = new HashMap<>();          // item -> candidates
        private int clock = 0;

        private static long key(int user, int item) { return ((long) user << 32) | item; }

        /**
         * Records a bid and replaces the user's earlier bid on the item.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the stored version belongs to the newest candidate.
         */
        void addBid(int user, int item, int amount) {
            int v = ++clock;
            current.put(key(user, item), new int[] {amount, v});
            heapOf.computeIfAbsent(item, k -> new PriorityQueue<>((a, b) ->
                    a.amount() != b.amount() ? Integer.compare(b.amount(), a.amount()) : Integer.compare(b.user(), a.user()))).add(new Bid(amount, user, v));
        }

        /** Withdraws a bid; O(1) time and space; invariant: the candidates of the pair stop matching the record. */
        void removeBid(int user, int item) { current.remove(key(user, item)); }

        /**
         * Returns the leading bidder or -1.
         * Time: O(log n) amortized.
         * Space: O(1) extra.
         * Invariant: only stale candidates leave the heap.
         */
        int getHighestBidder(int item) {
            PriorityQueue<Bid> heap = heapOf.get(item);
            if (heap == null) return -1;
            while (!heap.isEmpty()) {
                Bid b = heap.peek();
                int[] cur = current.get(key(b.user(), item));
                // A candidate is current only when the record holds its version.
                if (cur != null && cur[1] == b.version()) return b.user();
                heap.poll();
            }
            return -1;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Auction a = new Auction();
        a.addBid(1, 10, 50); a.addBid(2, 10, 70); a.addBid(1, 10, 80);
        if (a.getHighestBidder(10) != 1) throw new AssertionError("e1");
        Auction b = new Auction();
        b.addBid(1, 10, 50); b.addBid(2, 10, 50);
        if (b.getHighestBidder(10) != 2) throw new AssertionError("e2 tie");
        b.removeBid(2, 10);
        if (b.getHighestBidder(10) != 1 || b.getHighestBidder(99) != -1) throw new AssertionError("e2 after");
        // Random calls checked against a scan of all current bids.
        Random rnd = new Random(3815);
        for (int round = 0; round < 300; round++) {
            Auction s = new Auction();
            Map<Long, Integer> ref = new HashMap<>();
            for (int op = 0; op < 120; op++) {
                int u = rnd.nextInt(4), item = rnd.nextInt(3), t = rnd.nextInt(3);
                long k = ((long) u << 32) | item;
                if (t == 0) { int amt = 1 + rnd.nextInt(4); ref.put(k, amt); s.addBid(u, item, amt); }
                else if (t == 1 && ref.containsKey(k)) { ref.remove(k); s.removeBid(u, item); }
                else {
                    int best = -1, bestAmt = 0;
                    for (int x = 0; x < 4; x++) {
                        Integer amt = ref.get(((long) x << 32) | item);
                        if (amt != null && (amt > bestAmt || (amt == bestAmt && x > best))) { best = x; bestAmt = amt; }
                    }
                    if (s.getHighestBidder(item) != best) throw new AssertionError("highest");
                }
            }
        }
    }

Problem

A Withdrawal That Fails After Taking Cash

A cash machine holds five kinds of banknotes. A customer asks for 130, and the machine can reach only 120 with the notes it has. The code takes notes from the inventory one denomination at a time, and it stops with an error when the amount does not come out exact. The error screen appears, and the customer leaves with no cash. The inventory now holds fewer notes than before, because the code had already removed them.

Every later customer sees a machine that holds less cash than its ledger says. Nobody can find the missing notes, because each failed request leaves a small unexplained change behind.

This lesson asks how to run a call that changes several counters and indexes so that a failure leaves everything as it was. The same idea covers calls that move one record through a lifecycle.

Simple approach

Changing The Inventory While Deciding

The direct design walks through the denominations from the largest to the smallest. It subtracts notes from the inventory as it goes and checks at the end whether the remaining amount is zero.

final class NaiveAtm {
    private static final int[] VALUE = {20, 50, 100, 200, 500};
    private final long[] notes = new long[5];

    void deposit(int[] add) { for (int i = 0; i < 5; i++) notes[i] += add[i]; }

    int[] withdraw(int amount) {
        int[] used = new int[5];
        for (int i = 4; i >= 0; i--) {
            int take = (int) Math.min(notes[i], amount / VALUE[i]);
            notes[i] -= take;                      // writes before the answer is known
            used[i] = take;
            amount -= take * VALUE[i];
        }
        return amount == 0 ? used : new int[] {-1};   // the failure path keeps the writes
    }
}

The success path is correct. The failure path returns {-1} and leaves the changed inventory.

Predict first: The machine holds one 50 note and two 20 notes, and a customer asks for 130. What does the inventory look like after the failed call, and what should it look like?

The loop takes one 50 note and two 20 notes for a total of 90, finds 40 still missing and returns the failure value. The inventory now holds no 50 and no 20 notes. It should still hold one 50 note and two 20 notes, because a failed call must change nothing.

Bottleneck

Writes That Happen Before The Verdict

The cost here is correctness, not time. The loop does O(1) work for five denominations, and the damage comes from the order of its steps. The code writes the first result before it knows whether the call succeeds.

A failure can arrive at any point after the first write. The more steps a call has, the more half-finished states exist. A call that touches a map, a sorted index and a counter has at least three places where it can stop in the middle. Each place leaves a different mix of old and new data.

Repairing a half-finished state after the fact is hard. The code would have to remember every earlier write and undo it in reverse order. A simpler path is to avoid the writes until the verdict is known.

Key idea

Decide First, Then Change Everything

Split every public call into two phases. The first phase computes a plan, which is a description of every change the call would make. It reads state and writes nothing outside local variables. If the plan is impossible, the call returns the failure value and nothing has changed.

The Commit Step

The second phase is the commit. It applies every change in the plan, and it cannot fail. All checks that could fail belong to the first phase. Because the commit has no failure path, no reader ever sees half of it.

When A Failure Cannot Be Avoided

Sometimes a later step can only be checked by running it. Then the call has to undo its earlier writes. A rollback restores each changed value in reverse order, using the old values the call saved. A rollback is a fallback. A plan that checks everything first is shorter and has less code to get wrong.

The invariant is that every public call either applies its whole plan or changes nothing, so every counter and every index describes the same state after each call.

State

State Touched By One Call

A call of this kind touches four kinds of state, and each kind has a stated moment of change.

  • Record is the authoritative state of the entity, such as the note counts or an order's current state, and it changes only in the commit.
  • Index is any derived view, such as a sorted set of orders per state, and it changes in the same commit as the record.
  • Plan is a local copy of the changes, such as the notes to hand out, and it exists only during the call.
  • Verdict is the boolean or failure code that the first phase produces before any commit.

Code

The Machine With Plan Then Commit

The class computes the plan in a local array and commits it only when the remaining amount is zero.

final class SafeAtm {
    private static final int[] VALUE = {20, 50, 100, 200, 500};
    private final long[] notes = new long[5];

    void deposit(int[] add) { for (int i = 0; i < 5; i++) notes[i] += add[i]; }

    int[] withdraw(int amount) {
        int[] plan = new int[5];
        int left = amount;
        for (int i = 4; i >= 0; i--) {                       // phase one reads notes and writes only plan
            plan[i] = (int) Math.min(notes[i], left / VALUE[i]);
            left -= plan[i] * VALUE[i];
        }
        if (left != 0) return new int[] {-1};                // failure: nothing was written
        for (int i = 0; i < 5; i++) notes[i] -= plan[i];     // phase two cannot fail
        return plan;
    }
}

A call costs O(1) for a fixed number of denominations. The space is O(1) beyond the five counters.

When to use it

Calls That Move Several Pieces Of State

Recognizing The Pattern

The cue is one public call that changes more than one value, or that moves an entity from one state to the next. Write down every value and index the call changes. The invariant is that each call applies its whole plan or none of it.

Lifecycle Rules

A lifecycle is a graph of legal moves, such as created to paid to shipped. Store the legal moves as data and check the current state against them in the first phase. A move that the graph does not allow returns false and leaves every index untouched.

False Friends

A try-catch block around the writes looks like a safe design. It is a false friend when the catch block cannot restore the old values, because the exception arrives after some writes. Locks and synchronized methods protect against other threads, and they do not make a call all-or-nothing against its own failure. Skip the two phases when the call changes exactly one value, because a single write cannot be left half done.

Design ATM Machine

Problem Specification. Design a class Atm that stores counts of banknotes of values 20, 50, 100, 200 and 500, all starting at 0. The call deposit(counts) adds the five counts in that order. The call withdraw(amount) hands out the amount by taking as many notes as possible of the largest value, then the next largest, and so on, with no later correction. Input Constraints. The limits are:

  • Counts are integers from 0 to 10^9 per call, and totals fit in a long.
  • Amount satisfies 1 <= amount <= 10^9.
  • Calls number at most 5000.
  • Return is an array of length 5, or [-1].

Example 1. Input calls deposit([3,2,0,1,0]), withdraw(270), output [1,1,0,1,0].

Example 2. Input the same deposit and withdraw, then withdraw(130), withdraw(90), output [-1] and then [2,1,0,0,0].

Prerequisites. Arrays and greedy choice.

What This Exercise Changes. The result is known only after all five denominations are checked, so the stock changes after the last check.

Hint

Which array holds the notes you would take, and when may the stock array change?

Algorithmic Solution (attempt the problem first)

Approach. The stock is an array of five long counters. A withdraw call builds a plan in a local array. For each value from 500 down to 20, it takes the smaller of the stocked count and the number of whole notes that fit in the remaining amount, then lowers the remaining amount. If the remaining amount is not zero, the call returns [-1] without writing the stock. Otherwise it subtracts the plan from the stock and returns the plan.

The invariant is that the stock changes only in the final loop, which runs after every check has passed. A failed call therefore leaves the stock as it was.

Complexity.

  • Time is O(1) per call, because the loops run over five denominations.
  • Space is O(1), because the stock and the plan hold five numbers each.
import java.util.*;

public final class AtmSolution {
    static final class Atm {
        private static final int[] VALUE = {20, 50, 100, 200, 500};
        private final long[] stock = new long[5];

        /** Adds banknotes to the stock; O(1) time and space; invariant: every counter stays non-negative. */
        void deposit(int[] counts) {
            for (int i = 0; i < 5; i++) stock[i] += counts[i];
        }

        /**
         * Hands out an amount by the largest-first rule, or changes nothing.
         * Time: O(1).
         * Space: O(1).
         * Invariant: stock changes only after the plan reaches the amount exactly.
         */
        int[] withdraw(int amount) {
            int[] plan = new int[5];
            long left = amount;
            // Phase one reads the stock and writes only the plan.
            for (int i = 4; i >= 0; i--) {
                plan[i] = (int) Math.min(stock[i], left / VALUE[i]);
                left -= (long) plan[i] * VALUE[i];
            }
            // An unpaid remainder means the rule cannot reach the amount.
            if (left != 0) return new int[] {-1};
            // Phase two cannot fail, because each plan count is at most the stock.
            for (int i = 0; i < 5; i++) stock[i] -= plan[i];
            return plan;
        }

        long[] snapshot() { return stock.clone(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Atm a = new Atm();
        a.deposit(new int[] {3, 2, 0, 1, 0});
        if (!Arrays.equals(a.withdraw(270), new int[] {1, 1, 0, 1, 0})) throw new AssertionError("e1");
        if (!Arrays.equals(a.withdraw(130), new int[] {-1})) throw new AssertionError("e2 failure");
        if (!Arrays.equals(a.snapshot(), new long[] {2, 1, 0, 0, 0})) throw new AssertionError("failure changed the stock");
        if (!Arrays.equals(a.withdraw(90), new int[] {2, 1, 0, 0, 0})) throw new AssertionError("e2 success");

Design Order Management System

LeetCode 3822

Problem Specification. The rules below are this chapter's own wording and may differ in detail from LeetCode. Design a class Orders. The call create(orderId, customerId) adds an order in state CREATED and returns true, or returns false if the id exists. The call pay(orderId) moves CREATED to PAID. The call ship(orderId) moves PAID to SHIPPED. The call deliver(orderId) moves SHIPPED to DELIVERED. The call cancel(orderId) moves CREATED or PAID to CANCELLED. Each move returns true when legal and false otherwise, and an illegal move changes nothing. The call listByState(state) returns the order ids in that state in increasing order. The call countByCustomer(customerId, state) returns how many of that customer's orders are in that state.

Input Constraints. The limits are:

  • Ids are integers from 1 to 10^5, and customers are integers from 1 to 10^4.
  • States are the strings CREATED, PAID, SHIPPED, DELIVERED and CANCELLED.
  • Calls number at most 10^5, and a move may name an unknown order, which is illegal.
  • Return of listByState is a list, and countByCustomer returns an int.

Example 1. Input calls create(1,7), create(2,7), pay(1), ship(1), cancel(1), listByState(SHIPPED), output true, true, true, true, false and the list 1.

Example 2. Input calls create(3,8), cancel(3), pay(3), countByCustomer(8,CANCELLED), output true, true, false and 1.

Prerequisites. The ATM exercise above and tree sets.

What This Exercise Changes. Each move changes the record and two indexes, so a helper moves all three in one step after the legality check.

Hint

Which two indexes change when an order moves from one state to the next?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from order id to an immutable record of customer and state is the source of truth. Two derived views depend on it: a tree set of ids for each state, and a counter for each pair of customer and state. A table lists the legal source states for each move.

A move call first reads the record and checks that the current state is a legal source. If it is not, the call returns false and writes nothing. Otherwise one helper removes the id from the old state's set, lowers the old counter, stores the new record, adds the id to the new set and raises the new counter.

The invariant is that every order sits in exactly one state set, and each counter equals the number of the customer's orders in that state. Only the helper writes these three structures.

Complexity.

  • Time is O(log n) per call, because a move does one hash lookup and two tree operations. A list call costs O(k) for k results.
  • Space is O(n), because each order owns one record, one set slot and a share of a counter.
import java.util.*;

public final class OrderManagementSolution {
    static final class Orders {
        private enum State { CREATED, PAID, SHIPPED, DELIVERED, CANCELLED }
        private record Order(int customer, State state) {}
        private final Map<Integer, Order> orderOf = new HashMap<>();                              // id -> record, source of truth
        private final EnumMap<State, TreeSet<Integer>> byState = new EnumMap<>(State.class);
        private final Map<Long, Integer> counter = new HashMap<>();                               // (customer, state) -> count

        Orders() { for (State s : State.values()) byState.put(s, new TreeSet<>()); }

        private static long key(int customer, State s) { return ((long) customer << 8) | s.ordinal(); }

        /**
         * Moves one order between states and repairs every view.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the id leaves the old set before it enters the new one.
         */
        private void move(int id, Order old, State to) {
            byState.get(old.state()).remove(id);
            counter.merge(key(old.customer(), old.state()), -1, Integer::sum);
            orderOf.put(id, new Order(old.customer(), to));
            byState.get(to).add(id);
            counter.merge(key(old.customer(), to), 1, Integer::sum);
        }

        // Checks legality first and calls move only for a legal source state; O(log n) time, O(1) space.
        private boolean transition(int id, State to, State... allowedFrom) {
            Order o = orderOf.get(id);
            if (o == null) return false;
            boolean legal = false;
            for (State s : allowedFrom) if (o.state() == s) legal = true;
            if (!legal) return false;
            move(id, o, to);
            return true;
        }

        boolean create(int id, int customer) {
            if (orderOf.containsKey(id)) return false;
            orderOf.put(id, new Order(customer, State.CREATED));
            byState.get(State.CREATED).add(id);
            counter.merge(key(customer, State.CREATED), 1, Integer::sum);
            return true;
        }

        boolean pay(int id) { return transition(id, State.PAID, State.CREATED); }
        boolean ship(int id) { return transition(id, State.SHIPPED, State.PAID); }
        boolean deliver(int id) { return transition(id, State.DELIVERED, State.SHIPPED); }
        boolean cancel(int id) { return transition(id, State.CANCELLED, State.CREATED, State.PAID); }

        /** Lists the ids in one state in order; O(k) time and space for k results. */
        List<Integer> listByState(String state) { return new ArrayList<>(byState.get(State.valueOf(state))); }

        /** Counts one customer's orders in a state; O(1) time and space. */
        int countByCustomer(int customer, String state) { return counter.getOrDefault(key(customer, State.valueOf(state)), 0); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Orders a = new Orders();
        boolean[] r = {a.create(1, 7), a.create(2, 7), a.pay(1), a.ship(1), a.cancel(1)};
        if (!r[0] || !r[1] || !r[2] || !r[3] || r[4] || !a.listByState("SHIPPED").equals(List.of(1))) throw new AssertionError("e1");
        Orders b = new Orders();
        if (!b.create(3, 8) || !b.cancel(3) || b.pay(3) || b.countByCustomer(8, "CANCELLED") != 1) throw new AssertionError("e2");
        // Random calls checked against a plain map of states.
        Random rnd = new Random(3822);
        String[] names = {"CREATED", "PAID", "SHIPPED", "DELIVERED", "CANCELLED"};
        for (int round = 0; round < 300; round++) {
            Orders s = new Orders();
            Map<Integer, String> st = new HashMap<>();
            Map<Integer, Integer> cust = new HashMap<>();
            for (int op = 0; op < 100; op++) {
                int id = rnd.nextInt(6), t = rnd.nextInt(6);
                if (t == 0) {
                    int c = rnd.nextInt(3);
                    boolean want = !st.containsKey(id);
                    if (want) { st.put(id, "CREATED"); cust.put(id, c); }
                    if (s.create(id, c) != want) throw new AssertionError("create");
                } else {
                    String from1 = t == 1 ? "CREATED" : t == 2 ? "PAID" : t == 3 ? "SHIPPED" : "CREATED";
                    String from2 = t >= 4 ? "PAID" : from1;
                    String to = t == 1 ? "PAID" : t == 2 ? "SHIPPED" : t == 3 ? "DELIVERED" : "CANCELLED";

Author exercise

Problem Specification. Design a class Warehouse built from arrays items and quantities that give the starting stock of each item. The call checkout(customer, items, quantities) reserves several lines for a customer at once. It returns true and applies every line when the stock covers the total demand of each item. The same item may appear in several lines, and its demands add up. Otherwise it returns false and changes nothing. The call stock(item) returns the stock. The call held(customer, item) returns the quantity that the customer holds. The call holders(item) returns the customers who hold the item in increasing order.

Input Constraints. The limits are:

  • Items are lowercase strings, and customers are integers from 1 to 10^4.
  • Quantities are integers from 1 to 10^6 per line, and totals fit in a long.
  • Lines number from 1 to 100 per checkout, and calls number at most 10^4.
  • Holders lists a customer only while the customer holds at least one unit of the item.

Example 1. Input stock a 3 and b 2, then checkout(1,[a,b],[2,1]), checkout(2,[a,a],[1,1]), stock(a), holders(a), output true, false, 1 and the list 1.

Example 2. Input the same calls, then checkout(2,[b,a],[1,1]), holders(a), output true and the list 1, 2.

Prerequisites. The two exercises above.

What This Exercise Changes. Lines add up per item before any check, so the plan holds one total per item and the commit writes all three structures.

Hint

Which total must each item's stock cover when two lines name the same item?

Algorithmic Solution (attempt the problem first)

Approach. Three structures hold the state: a map from item to stock, a map from customer to held quantities, and a map from item to the sorted set of customers who hold it. A checkout call first adds the quantities of every line into a local map of totals per item. It then checks each total against the stock and returns false if any total is too large. No structure has been written at that point.

When every check passes, the commit loops over the totals once. For each item it lowers the stock, raises the customer's held quantity and inserts the customer into the item's holder set. A check line by line would accept two lines of 1 unit against a stock of 1, so the plan must hold totals per item.

The invariant is that the stock plus all held quantities of an item stays equal to the starting stock, and an item's holder set holds exactly the customers with a positive held quantity.

Complexity.

  • Time is O(L log n) per checkout call, where L is the number of lines, because the plan and the commit each visit every item once and the set insertion costs O(log n).
  • Space is O(n + h), where h is the number of pairs of customer and item that hold stock, because the plan adds O(L) temporary entries.
import java.util.*;

public final class FailedRollbackSolution {
    static final class Warehouse {
        private final Map<String, Long> stock = new HashMap<>();
        private final Map<Integer, Map<String, Long>> held = new HashMap<>();       // customer -> item -> quantity
        private final Map<String, TreeSet<Integer>> holdersOf = new HashMap<>();     // item -> customers with a positive quantity

        Warehouse(String[] items, int[] quantities) {
            for (int i = 0; i < items.length; i++) stock.merge(items[i], (long) quantities[i], Long::sum);
        }

        /**
         * Reserves all lines or none.
         * Time: O(L log n) for L lines.
         * Space: O(L) for the plan.
         * Invariant: no structure changes before every total passes its check.
         */
        boolean checkout(int customer, String[] items, int[] quantities) {
            // The plan sums the demand per item, because two lines can name one item.
            Map<String, Long> plan = new HashMap<>();
            for (int i = 0; i < items.length; i++) plan.merge(items[i], (long) quantities[i], Long::sum);
            for (Map.Entry<String, Long> e : plan.entrySet()) {
                // One failed check ends the call before any write.
                if (stock.getOrDefault(e.getKey(), 0L) < e.getValue()) return false;
            }
            // The commit cannot fail, because every total already fits.
            for (Map.Entry<String, Long> e : plan.entrySet()) {
                stock.merge(e.getKey(), -e.getValue(), Long::sum);
                held.computeIfAbsent(customer, k -> new HashMap<>()).merge(e.getKey(), e.getValue(), Long::sum);
                holdersOf.computeIfAbsent(e.getKey(), k -> new TreeSet<>()).add(customer);
            }
            return true;
        }

        long stock(String item) { return stock.getOrDefault(item, 0L); }

        long held(int customer, String item) { return held.getOrDefault(customer, Map.of()).getOrDefault(item, 0L); }

        List<Integer> holders(String item) { return new ArrayList<>(holdersOf.getOrDefault(item, new TreeSet<>())); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Warehouse w = new Warehouse(new String[] {"a", "b"}, new int[] {3, 2});
        if (!w.checkout(1, new String[] {"a", "b"}, new int[] {2, 1})) throw new AssertionError("e1 first");
        if (w.checkout(2, new String[] {"a", "a"}, new int[] {1, 1})) throw new AssertionError("e1 duplicate lines");
        if (w.stock("a") != 1 || !w.holders("a").equals(List.of(1)) || w.held(2, "a") != 0) throw new AssertionError("failed call changed state");
        if (!w.checkout(2, new String[] {"b", "a"}, new int[] {1, 1}) || !w.holders("a").equals(List.of(1, 2))) throw new AssertionError("e2");
        // Random calls checked against a simulation on copies.
        Random rnd = new Random(42);
        String[] names = {"a", "b", "c"};
        for (int round = 0; round < 300; round++) {
            int[] start = {rnd.nextInt(6), rnd.nextInt(6), rnd.nextInt(6)};
            Warehouse s = new Warehouse(names, start);
            long[] stk = {start[0], start[1], start[2]};
            long[][] hold = new long[4][3];
            for (int op = 0; op < 40; op++) {
                int c = 1 + rnd.nextInt(3), lines = 1 + rnd.nextInt(4);
                String[] it = new String[lines];
                int[] q = new int[lines];
                long[] need = new long[3];
                for (int i = 0; i < lines; i++) { int k = rnd.nextInt(3); it[i] = names[k]; q[i] = 1 + rnd.nextInt(3); need[k] += q[i]; }
                boolean want = true;
                for (int k = 0; k < 3; k++) if (need[k] > stk[k]) want = false;
                if (want) for (int k = 0; k < 3; k++) { stk[k] -= need[k]; hold[c][k] += need[k]; }
                if (s.checkout(c, it, q) != want) throw new AssertionError("verdict");
                for (int k = 0; k < 3; k++) {
                    if (s.stock(names[k]) != stk[k]) throw new AssertionError("stock");
                    List<Integer> hs = new ArrayList<>();
                    for (int x = 1; x <= 3; x++) { if (s.held(x, names[k]) != hold[x][k]) throw new AssertionError("held"); if (hold[x][k] > 0) hs.add(x); }
                    if (!s.holders(names[k]).equals(hs)) throw new AssertionError("holders");
                }
            }
        }
    }

Design Event Manager

LeetCode 3885

Problem Specification. This contract is written for the chapter, so the LeetCode statement may differ in detail. Design a class Events. The call create(eventId, time) adds an event in state SCHEDULED and returns true, or returns false if the id exists. The call reschedule(eventId, newTime) changes the time of a SCHEDULED event and returns true, or returns false for any other state. The call cancel(eventId) moves a SCHEDULED event to CANCELLED and returns true, or returns false otherwise. The call runNext() takes the SCHEDULED event with the earliest time, breaking ties by the smaller id, marks it DONE and returns its id, or returns -1 if none exists. The call count(state) returns the number of events in that state.

Input Constraints. The limits are:

  • Ids are integers from 1 to 10^5, and times satisfy 0 <= time <= 10^9.
  • States are the strings SCHEDULED, CANCELLED and DONE.
  • Calls number at most 2 * 10^5.
  • Return types are boolean, int or int as named above.

Example 1. Input calls create(1,50), create(2,30), create(3,30), runNext(), reschedule(3,60), runNext(), output 2 for the first runNext, true for reschedule, then 1.

Example 2. Input calls create(5,10), cancel(5), reschedule(5,20), runNext(), count(CANCELLED), output true for cancel, false for reschedule, then -1 and 1.

Prerequisites. All three exercises above.

What This Exercise Changes. Only scheduled events live in the time index, so every move out of that state removes the event from the index.

Hint

Which of the three views holds only scheduled events, and which call removes an event from it?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from event id to an immutable record of time and state is the source of truth. Two derived views follow it: a tree set of scheduled events ordered by time and then id, and a counter for each state. Only SCHEDULED events appear in the tree set.

Reschedule and cancel first read the record and return false unless the state is SCHEDULED. Reschedule then removes the event with the old time from the tree set, stores the new record and inserts the event with the new time. Cancel removes the event from the tree set and moves one unit between the counters. A run call polls the first event of the tree set, stores the record in state DONE and moves one unit between the counters.

The invariant is that the tree set holds exactly the scheduled events with their current times, and each counter equals the number of records in that state.

Complexity.

  • Time is O(log n) per call, because each call does one hash lookup and at most two tree operations.
  • Space is O(n), because each event owns one record and at most one tree entry.
import java.util.*;

public final class EventManagerSolution {
    static final class Events {
        private enum State { SCHEDULED, CANCELLED, DONE }
        private record Event(int time, int id) {}
        private record Rec(int time, State state) {}
        private final Map<Integer, Rec> recOf = new HashMap<>();                        // id -> record, source of truth
        private final TreeSet<Event> scheduled = new TreeSet<>((a, b) ->
                a.time() != b.time() ? Integer.compare(a.time(), b.time()) : Integer.compare(a.id(), b.id()));
        private final int[] counts = new int[3];                                        // number of events per state

        /** Adds a scheduled event; O(log n) time, O(1) space; invariant: the record, the tree and the counter agree. */
        boolean create(int id, int time) {
            if (recOf.containsKey(id)) return false;
            recOf.put(id, new Rec(time, State.SCHEDULED));
            scheduled.add(new Event(time, id));
            counts[State.SCHEDULED.ordinal()]++;
            return true;
        }

        /** Moves a scheduled event to a new time; O(log n) time, O(1) space; invariant: the old tree entry leaves first. */
        boolean reschedule(int id, int newTime) {
            Rec r = recOf.get(id);
            if (r == null || r.state() != State.SCHEDULED) return false;
            scheduled.remove(new Event(r.time(), id));
            recOf.put(id, new Rec(newTime, State.SCHEDULED));
            scheduled.add(new Event(newTime, id));
            return true;
        }

        /** Cancels a scheduled event; O(log n) time, O(1) space; invariant: only scheduled events sit in the tree. */
        boolean cancel(int id) {
            Rec r = recOf.get(id);
            if (r == null || r.state() != State.SCHEDULED) return false;
            scheduled.remove(new Event(r.time(), id));
            recOf.put(id, new Rec(r.time(), State.CANCELLED));
            counts[State.SCHEDULED.ordinal()]--;
            counts[State.CANCELLED.ordinal()]++;
            return true;
        }

        /** Runs the earliest scheduled event or returns -1; O(log n) time, O(1) space; invariant: the polled event leaves the tree. */
        int runNext() {
            Event e = scheduled.pollFirst();
            if (e == null) return -1;
            recOf.put(e.id(), new Rec(e.time(), State.DONE));
            counts[State.SCHEDULED.ordinal()]--;
            counts[State.DONE.ordinal()]++;
            return e.id();
        }

        /** Returns the number of events in a state; O(1) time and space. */
        int count(String state) { return counts[State.valueOf(state).ordinal()]; }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        Events a = new Events();
        a.create(1, 50); a.create(2, 30); a.create(3, 30);
        if (a.runNext() != 2 || !a.reschedule(3, 60) || a.runNext() != 1) throw new AssertionError("e1");
        Events b = new Events();
        b.create(5, 10);
        if (!b.cancel(5) || b.reschedule(5, 20) || b.runNext() != -1 || b.count("CANCELLED") != 1) throw new AssertionError("e2");
        // Random calls checked against a scan of a plain map.
        Random rnd = new Random(3885);
        String[] names = {"SCHEDULED", "CANCELLED", "DONE"};
        for (int round = 0; round < 300; round++) {
            Events s = new Events();
            Map<Integer, int[]> ref = new HashMap<>();                                   // id -> {time, state}
            for (int op = 0; op < 100; op++) {
                int id = rnd.nextInt(6), t = rnd.nextInt(4);
                if (t == 0) {
                    int time = rnd.nextInt(4);
                    boolean want = !ref.containsKey(id);
                    if (want) ref.put(id, new int[] {time, 0});
                    if (s.create(id, time) != want) throw new AssertionError("create");
                } else if (t == 1) {
                    int time = rnd.nextInt(4);
                    boolean want = ref.containsKey(id) && ref.get(id)[1] == 0;
                    if (want) ref.get(id)[0] = time;
                    if (s.reschedule(id, time) != want) throw new AssertionError("reschedule");
                } else if (t == 2) {
                    boolean want = ref.containsKey(id) && ref.get(id)[1] == 0;
                    if (want) ref.get(id)[1] = 1;
                    if (s.cancel(id) != want) throw new AssertionError("cancel");
                } else {
                    int best = -1;
                    for (int i : ref.keySet()) if (ref.get(i)[1] == 0 && (best == -1 || ref.get(i)[0] < ref.get(best)[0] || (ref.get(i)[0] == ref.get(best)[0] && i < best))) best = i;
                    if (best != -1) ref.get(best)[1] = 2;
                    if (s.runNext() != best) throw new AssertionError("runNext");
                }
                for (int k = 0; k < 3; k++) {
                    int n = 0;
                    for (int[] v : ref.values()) if (v[1] == k) n++;
                    if (s.count(names[k]) != n) throw new AssertionError("count");
                }
            }
        }
    }

            a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(b.id(), a.id());
    private final java.util.TreeSet<Task> global = new java.util.TreeSet<>(order);
    private final java.util.Map<Integer, java.util.TreeSet<Task>> perUser = new java.util.HashMap<>();

    void add(int user, int id, int priority) {
        Task t = new Task(priority, id, user);
        global.add(t);
        perUser.computeIfAbsent(user, k -> new java.util.TreeSet<>(order)).add(t);
    }

    int execUser(int user) {
        java.util.TreeSet<Task> mine = perUser.get(user);
        if (mine == null || mine.isEmpty()) return -1;
        return mine.pollFirst().id();            // the global set still holds this task
    }

    int execGlobal() {
        Task t = global.pollFirst();
        return t == null ? -1 : t.id();          // the user's set still holds this task
    }
}

After add(1, 7, 5) and execUser(1), the call execGlobal() returns 7 again.

Predict first: A task has been run through the user's page. Which of the two calls can run it a second time, and which of the two calls can keep a task alive after the global call ran it?

Both can. The global call finds the task because the user path never touched the global set. The user call finds the task because the global path never touched the user's set. Each exit fixes one set and leaves the other with a task that no longer exists.

Bottleneck

Every Exit Must Repair Every Set

The cost of the naive design is correctness, and it grows with the number of exits. A class with two sorted sets and three ways to remove a task has six repair decisions to make. A missed one produces a task that runs twice or a task that never runs.

Repairing by search does not help. A scan of the user's set for the task that the global set returned costs O(n), and a scan in the other direction costs the same. The class already knows the task, so it can build the exact old key and remove it in O(log n).

The design needs one place that removes a task from all three structures, and every public call has to pass through that place.

Key idea

One Removal Path For Every Exit

The class keeps three structures. The map from task id to task is the record that decides. The global index is a sorted set of all tasks. The owner index is a map from user to a sorted set of that user's tasks.

The Single Place That Writes

A removal helper takes one task, removes it from the record, from the global index and from the owner index, and deletes an owner set that becomes empty. A matching insert helper does the reverse. No public call touches a structure directly. Add calls insert, edit calls remove and insert, a remove call removes, and both execute calls pick a task from one index and then call the helper.

Why The Order Of Steps Matters

An execute call reads the task from one index first and removes it second. The removal uses the full task object, because both sorted sets find entries by their fields. An edit builds the new task as a copy and runs remove-then-insert in the helper, so the old fields leave every set before the new fields enter.

The invariant is that the record, the global index and the owner index hold the same tasks, with the same fields, after every call.

State

Three Views And Two Helpers

The class stores one record and two indexes, and two helpers write them.

  • byId maps each task id to its immutable task and is the record that decides.
  • global is a tree set of all tasks, ordered by higher priority and then by larger id.
  • perUser maps each user to a tree set of that user's tasks, with the same order.
  • insert and drop are the only methods that write the three structures.

An owner set that becomes empty is removed from perUser, so a query for an unknown user and for a user with no tasks gives the same answer.

The Task Desk In Java

The class routes every change through two helpers.

final class TaskDesk {
    private record Task(int priority, int id, int user) {}
    private static final java.util.Comparator<Task> ORDER = (a, b) ->
            a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(b.id(), a.id());
    private final java.util.Map<Integer, Task> byId = new java.util.HashMap<>();
    private final java.util.TreeSet<Task> global = new java.util.TreeSet<>(ORDER);
    private final java.util.Map<Integer, java.util.TreeSet<Task>> perUser = new java.util.HashMap<>();

    private void insert(Task t) {
        byId.put(t.id(), t);
        global.add(t);
        perUser.computeIfAbsent(t.user(), k -> new java.util.TreeSet<>(ORDER)).add(t);
    }

    private void drop(Task t) {
        byId.remove(t.id());
        global.remove(t);                                   // the exact object removes the exact entry
        java.util.TreeSet<Task> mine = perUser.get(t.user());
        mine.remove(t);
        if (mine.isEmpty()) perUser.remove(t.user());
    }

    int execGlobal() {
        if (global.isEmpty()) return -1;
        Task t = global.first();
        drop(t);
        return t.id();
    }
}

Every call costs O(log n), because the helpers do a constant number of hash and tree operations. The space is O(n), because each task sits in three structures.

When to use it

Several Exits From One Record

Counting The Doors

List every public call that creates, changes or removes a record. Mark which indexes each call must touch. If two calls remove the same record, they must share a helper. The invariant is that the record and every index hold the same tasks after each call.

Order Fields And Copies

A sorted set compares the fields of its entries, so an edit must remove the old entry before the new fields exist anywhere in the set. Store immutable entries and build a new entry per edit. The comparator must end with a unique field, so removing an entry cannot remove a different one.

False Friends And Limits

A lazy heap with version checks looks like a way to avoid the helper. It is a false friend when two heaps exist for the same records, because a version number in one heap says nothing about the other heap. Skip the owner index when no call asks about one user, because the second index then costs memory and gives nothing back.

Hint

Which method of a tree set answers "smallest element at least x"?

Algorithmic Solution (attempt the problem first)

Approach. A hash map from index to number is the record that decides. A hash map from number to a tree set of indexes is the ordered view. One helper, store, takes an index and a new number, or none for a clear. It removes the index from the set of the old number, deletes an empty set and inserts the index into the set of the new number when there is one. Both change and clear call that helper.

  • Time is O(log n) per call. Each call runs hash lookups and at most two tree operations.
  • Space is O(n), since a filled slot appears once in each map.
import java.util.*;

public final class NumberContainerFloorSolution {
    static final class FloorContainers {
        private final Map<Integer, Integer> numberAt = new HashMap<>();
        private final Map<Integer, TreeSet<Integer>> indexesOf = new HashMap<>();

        /**
         * The only method that writes the two maps.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the index leaves the old set before it enters the new one.
         */
        private void store(int index, Integer number) {
            Integer old = number == null ? numberAt.remove(index) : numberAt.put(index, number);
            // An unchanged value needs no repair.
            if (old != null && old.equals(number)) return;
            if (old != null) {
                TreeSet<Integer> set = indexesOf.get(old);
                set.remove(index);
                if (set.isEmpty()) indexesOf.remove(old);
            }
            if (number != null) indexesOf.computeIfAbsent(number, k -> new TreeSet<>()).add(index);
        }

        void change(int index, int number) { store(index, number); }

        void clear(int index) { store(index, null); }

        /** Returns the smallest index at least floor that holds number, or -1; O(log n) time, O(1) space. */
        int find(int number, int floor) {
            TreeSet<Integer> set = indexesOf.get(number);
            if (set == null) return -1;
            Integer hit = set.ceiling(floor);
            return hit == null ? -1 : hit;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        FloorContainers a = new FloorContainers();
        a.change(1, 10); a.change(5, 10); a.change(9, 10);
        if (a.find(10, 2) != 5) throw new AssertionError("e1 first");
        a.clear(5);
        if (a.find(10, 2) != 9) throw new AssertionError("e1 second");
        FloorContainers b = new FloorContainers();
        if (b.find(10, 10) != -1 || b.find(7, 0) != -1) throw new AssertionError("e2");
        // Random calls checked against a scan of an array.
        Random rnd = new Random(9101);
        for (int round = 0; round < 300; round++) {
            FloorContainers s = new FloorContainers();
            int[] ref = new int[10];
            for (int op = 0; op < 100; op++) {
                int t = rnd.nextInt(3), i = rnd.nextInt(10);
                if (t == 0) { int v = 1 + rnd.nextInt(3); ref[i] = v; s.change(i, v); }
                else if (t == 1) { ref[i] = 0; s.clear(i); }
                else {
                    int v = 1 + rnd.nextInt(3), f = rnd.nextInt(11), want = -1;
                    for (int x = f; x < 10 && want == -1; x++) if (ref[x] == v) want = x;
                    if (s.find(v, f) != want) throw new AssertionError("find");
                }
            }
        }
    }

Hint

Which two structures must forget a retired food?

Algorithmic Solution (attempt the problem first)

Approach. A map from food name to an immutable record of cuisine and rating is the record that decides. A map from cuisine to a tree set of immutable entries is the ordered view. The entries order by higher rating and then smaller name. A rating change and a retire call both go through one helper that removes the entry built from the stored record. A rating change then stores a new record and inserts a new entry, and a retire call stops after the removal.

A top-two query iterates the first two entries of the cuisine's set.

The invariant is that each food on the menu has exactly one entry in its cuisine's set, and the entry carries the stored rating. A retired food has no record and no entry.

Complexity.

  • Time is O(log n) per update and O(1 + log n) per query, because the iterator starts at the first entry and reads two entries.
  • Space is O(n), since every food on the menu keeps one record and one set entry.
import java.util.*;

public final class FoodRetireSolution {
    static final class FoodMenu {
        private record Item(String cuisine, int rating) {}
        private record Entry(String name, int rating) {}
        private static final Comparator<Entry> ORDER = (a, b) -> {
            int c = Integer.compare(b.rating(), a.rating());
            return c != 0 ? c : a.name().compareTo(b.name());
        };
        private final Map<String, Item> itemOf = new HashMap<>();
        private final Map<String, TreeSet<Entry>> byCuisine = new HashMap<>();

        FoodMenu(String[] foods, String[] cuisines, int[] ratings) {
            for (int i = 0; i < foods.length; i++) put(foods[i], new Item(cuisines[i], ratings[i]));
        }

        // Inserts a record and its entry; O(log n) time, O(1) space.
        private void put(String food, Item item) {
            itemOf.put(food, item);
            byCuisine.computeIfAbsent(item.cuisine(), k -> new TreeSet<>(ORDER)).add(new Entry(food, item.rating()));
        }

        // Removes a record and its exact entry; O(log n) time, O(1) space; invariant: no entry outlives its record.
        private Item take(String food) {
            Item item = itemOf.remove(food);
            byCuisine.get(item.cuisine()).remove(new Entry(food, item.rating()));
            return item;
        }

        /** Sets a rating by removing the old pair and inserting the new one; O(log n) time, O(1) space. */
        void changeRating(String food, int rating) {
            Item old = take(food);
            put(food, new Item(old.cuisine(), rating));
        }

        /** Deletes a food from the menu; O(log n) time, O(1) space; invariant: take is the only removal path. */
        void retire(String food) { take(food); }

        /** Returns up to two best names of a cuisine; O(log n) time, O(1) space. */
        List<String> topTwo(String cuisine) {
            List<String> out = new ArrayList<>();
            for (Entry e : byCuisine.getOrDefault(cuisine, new TreeSet<>(ORDER))) {
                if (out.size() == 2) break;
                out.add(e.name());
            }
            return out;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        String[] foods = {"a", "b", "c", "d"}, cuis = {"x", "x", "x", "y"};
        int[] rat = {5, 9, 9, 4};
        FoodMenu m = new FoodMenu(foods, cuis, rat);
        if (!m.topTwo("x").equals(List.of("b", "c"))) throw new AssertionError("e1 first");
        m.retire("b");
        if (!m.topTwo("x").equals(List.of("c", "a"))) throw new AssertionError("e1 second");
        m.changeRating("a", 9);
        if (!m.topTwo("x").equals(List.of("a", "c"))) throw new AssertionError("e2");
        // Random calls checked against a sort of the live foods.
        Random rnd = new Random(9102);
        for (int round = 0; round < 300; round++) {
            int n = 2 + rnd.nextInt(7);
            String[] f = new String[n], c = new String[n];
            int[] r = new int[n];
            boolean[] live = new boolean[n];
            for (int i = 0; i < n; i++) { f[i] = "f" + i; c[i] = "c" + rnd.nextInt(2); r[i] = 1 + rnd.nextInt(3); live[i] = true; }
            FoodMenu s = new FoodMenu(f, c, r.clone());
            for (int op = 0; op < 60; op++) {
                int i = rnd.nextInt(n), t = rnd.nextInt(3);
                if (t == 0 && live[i]) { r[i] = 1 + rnd.nextInt(3); s.changeRating(f[i], r[i]); }
                else if (t == 1 && live[i]) { live[i] = false; s.retire(f[i]); }
                else if (t == 2) {
                    String cu = "c" + rnd.nextInt(2);
                    List<Integer> ids = new ArrayList<>();
                    for (int k = 0; k < n; k++) if (live[k] && c[k].equals(cu)) ids.add(k);
                    ids.sort((x, y) -> r[x] != r[y] ? Integer.compare(r[y], r[x]) : f[x].compareTo(f[y]));
                    List<String> want = new ArrayList<>();
                    for (int k = 0; k < Math.min(2, ids.size()); k++) want.add(f[ids.get(k)]);
                    if (!s.topTwo(cu).equals(want)) throw new AssertionError("topTwo");
                }
            }
        }
    }

Problem Specification. Each shop of a chain owns at most one copy of a movie, sold at a fixed price. Write a class MovieDesk built from entries {shop, movie, price}, all unrented. The call rent(shop, movie) returns true and marks the copy rented if the copy exists and is unrented, and returns false otherwise. The call search(movie) returns up to 3 shops with an unrented copy, ordered by price and then shop. The call rentedCount() returns the number of rented copies.

Input Constraints. The limits are:

  • Entries number at most 10^5, with one copy per pair of shop and movie.
  • Prices are integers from 1 to 10^4, and shops and movies are integers from 0 to 10^5.
  • Calls number at most 10^5, and rent and drop may name a pair that has no copy.
  • Rejected calls change nothing.

Example 1. Input entries {0,1,5}, {1,1,4}, {2,1,4} and the calls search(1), rent(1,1), rent(1,1), search(1), output shops 1, 2, 0, then true, false and shops 2, 0.

What This Exercise Changes. Each copy carries a state, and one move helper changes the state and both views.

Hint

What does a state field on each copy replace, and which check runs before a move?

Algorithmic Solution (attempt the problem first)

Approach. Each copy is an object with its price, shop, movie and a mutable state flag. A hash map from the pair of shop and movie to the copy is the record that decides. Two views exist: an array of two sets indexed by state, where the unrented view is a map from movie to a tree set, and the rented view is one tree set. A move helper checks that the copy exists and holds the expected state before it writes anything. It then removes the copy from the view of its old state, flips the flag and inserts the copy into the view of its new state.

The flag changes after the removal and before the insertion, and the sets order only by price, shop and movie, never by the flag, so a flag change cannot disturb a set. A rejected call returns false before any write.

The invariant is that a copy with state unrented sits in exactly its movie's unrented set, and a copy with state rented sits in the rented set.

Complexity.

  • Time is O(log n) per rent and drop, and O(log n + 3) per search.
  • Space is O(n), because each copy sits in one map slot and one set.
import java.util.*;

public final class MovieDeskSolution {
    static final class MovieDesk {
        private static final class Copy {
            final int price, shop, movie;
            boolean rented;
            Copy(int price, int shop, int movie) { this.price = price; this.shop = shop; this.movie = movie; }
        }
        private static final Comparator<Copy> ORDER = (a, b) -> {
            int c = Integer.compare(a.price, b.price);
            if (c != 0) return c;
            c = Integer.compare(a.shop, b.shop);
            return c != 0 ? c : Integer.compare(a.movie, b.movie);
        };
        private final Map<Long, Copy> copyAt = new HashMap<>();
        private final Map<Integer, TreeSet<Copy>> unrented = new HashMap<>();
        private final TreeSet<Copy> rented = new TreeSet<>(ORDER);

        private static long key(int shop, int movie) { return ((long) shop << 32) | movie; }

        MovieDesk(int[][] entries) {
            for (int[] e : entries) {
                Copy c = new Copy(e[2], e[0], e[1]);
                copyAt.put(key(e[0], e[1]), c);
                unrented.computeIfAbsent(e[1], k -> new TreeSet<>(ORDER)).add(c);
            }
        }

        /**
         * Moves a copy from one state to the other, or rejects the call.
         * Time: O(log n).
         * Space: O(1) extra.
         * Invariant: the checks run before the first write.
         */
        private boolean move(int shop, int movie, boolean fromRented) {
            Copy c = copyAt.get(key(shop, movie));
            if (c == null || c.rented != fromRented) return false;
            if (fromRented) rented.remove(c); else unrented.get(movie).remove(c);
            c.rented = !fromRented;
            if (c.rented) rented.add(c); else unrented.get(movie).add(c);
            return true;
        }

        boolean rent(int shop, int movie) { return move(shop, movie, false); }

        boolean drop(int shop, int movie) { return move(shop, movie, true); }

        /** Returns up to 3 cheapest shops with an unrented copy; O(log n) time, O(1) extra space. */
        List<Integer> search(int movie) {
            List<Integer> out = new ArrayList<>();
            for (Copy c : unrented.getOrDefault(movie, new TreeSet<>(ORDER))) {
                if (out.size() == 3) break;
                out.add(c.shop);
            }
            return out;
        }

        /** Returns the number of rented copies; O(1) time and space. */
        int rentedCount() { return rented.size(); }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        int[][] entries = {{0, 1, 5}, {1, 1, 4}, {2, 1, 4}};
        MovieDesk a = new MovieDesk(entries);
        if (!a.search(1).equals(List.of(1, 2, 0))) throw new AssertionError("e1 search");
        if (!a.rent(1, 1) || a.rent(1, 1) || !a.search(1).equals(List.of(2, 0))) throw new AssertionError("e1 rent");
        MovieDesk b = new MovieDesk(entries);
        if (b.drop(0, 1) || b.rent(9, 9) || !b.rent(0, 1) || b.rentedCount() != 1) throw new AssertionError("e2");
        // Random calls checked against boolean flags and a sort.
        Random rnd = new Random(9103);
        for (int round = 0; round < 200; round++) {
            List<int[]> list = new ArrayList<>();
            for (int s = 0; s < 4; s++) for (int v = 0; v < 3; v++) if (rnd.nextInt(3) > 0) list.add(new int[] {s, v, 1 + rnd.nextInt(4)});
            int[][] es = list.toArray(new int[0][]);
            MovieDesk sut = new MovieDesk(es);
            boolean[] out = new boolean[es.length];
            for (int op = 0; op < 100; op++) {
                int s = rnd.nextInt(5), v = rnd.nextInt(4), t = rnd.nextInt(3), idx = -1;
                for (int i = 0; i < es.length; i++) if (es[i][0] == s && es[i][1] == v) idx = i;
                if (t == 0) { boolean want = idx >= 0 && !out[idx]; if (want) out[idx] = true; if (sut.rent(s, v) != want) throw new AssertionError("rent"); }
                else if (t == 1) { boolean want = idx >= 0 && out[idx]; if (want) out[idx] = false; if (sut.drop(s, v) != want) throw new AssertionError("drop"); }
                else {
                    List<int[]> cand = new ArrayList<>();
                    for (int i = 0; i < es.length; i++) if (es[i][1] == v && !out[i]) cand.add(es[i]);
                    cand.sort((x, y) -> x[2] != y[2] ? Integer.compare(x[2], y[2]) : Integer.compare(x[0], y[0]));
                    List<Integer> want = new ArrayList<>();
                    for (int i = 0; i < Math.min(3, cand.size()); i++) want.add(cand.get(i)[0]);
                    int cnt = 0;
                    for (boolean o : out) if (o) cnt++;
                    if (!sut.search(v).equals(want) || sut.rentedCount() != cnt) throw new AssertionError("search or count");
                }
            }
        }

Algorithmic Solution (attempt the problem first)

Approach. A hash map from task id to an immutable task is the record that decides. Two private helpers write every structure. The insert helper writes the record and both indexes. The drop helper removes the task from the record and both indexes, and deletes an owner set that becomes empty.

An add call inserts. An edit call drops the stored task and inserts a copy with the new priority. A remove call drops the stored task. Each execute call reads the first task of its index and then drops it, so the other index loses the task in the same call.

The invariant says all three structures hold the same tasks with equal fields after every call. No public method writes a structure except through the helpers.

Complexity.

  • Time is O(log n) per call, from a constant number of hash and tree operations.
  • Space is O(n), because a task appears in the record and in two sets.
import java.util.*;

public final class TaskDeskSolution {
    static final class TaskDesk {
        private record Task(int priority, int id, int user) {}
        private static final Comparator<Task> ORDER = (a, b) ->
                a.priority() != b.priority() ? Integer.compare(b.priority(), a.priority()) : Integer.compare(b.id(), a.id());
        private final Map<Integer, Task> byId = new HashMap<>();
        private final TreeSet<Task> global = new TreeSet<>(ORDER);
        private final Map<Integer, TreeSet<Task>> perUser = new HashMap<>();

        // Writes the record and both indexes; O(log n) time, O(1) space.
        private void insert(Task t) {
            byId.put(t.id(), t);
            global.add(t);
            perUser.computeIfAbsent(t.user(), k -> new TreeSet<>(ORDER)).add(t);
        }

        // Removes the exact task from the record and both indexes; O(log n) time, O(1) space; invariant: the only removal path.
        private void drop(Task t) {
            byId.remove(t.id());
            global.remove(t);
            TreeSet<Task> mine = perUser.get(t.user());
            mine.remove(t);
            // An empty owner set is deleted so unknown users and idle users look alike.
            if (mine.isEmpty()) perUser.remove(t.user());
        }

        void add(int user, int id, int priority) { insert(new Task(priority, id, user)); }

        void edit(int id, int priority) {
            Task old = byId.get(id);
            drop(old);
            insert(new Task(priority, id, old.user()));
        }

        void rmv(int id) { drop(byId.get(id)); }

        /** Runs the best task overall; O(log n) time, O(1) space; invariant: the task leaves every structure. */
        int execGlobal() {
            if (global.isEmpty()) return -1;
            Task t = global.first();
            drop(t);
            return t.id();
        }

        /** Runs the best task of one user; O(log n) time, O(1) space; invariant: the task leaves every structure. */
        int execUser(int user) {
            TreeSet<Task> mine = perUser.get(user);
            if (mine == null) return -1;
            Task t = mine.first();
            drop(t);
            return t.id();
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.

        a.add(1, 101, 5); a.add(1, 102, 7); a.add(2, 103, 7);
        if (a.execUser(1) != 102 || a.execGlobal() != 103 || a.execGlobal() != 101) throw new AssertionError("e1");
        TaskDesk b = new TaskDesk();
        if (b.execUser(3) != -1) throw new AssertionError("e2 empty");
        b.add(3, 200, 1);
        if (b.execGlobal() != 200 || b.execUser(3) != -1) throw new AssertionError("e2 after");
        // Random calls checked against a scan of a plain map.
        Random rnd = new Random(9104);
        for (int round = 0; round < 300; round++) {
            TaskDesk s = new TaskDesk();
            Map<Integer, int[]> ref = new HashMap<>();
            int next = 0;
            for (int op = 0; op < 120; op++) {
                int t = rnd.nextInt(5);
                List<Integer> ids = new ArrayList<>(ref.keySet());
                if (t == 0) { int u = 1 + rnd.nextInt(3), p = rnd.nextInt(4); ref.put(next, new int[] {u, p}); s.add(u, next++, p); }
                else if (t == 1 && !ids.isEmpty()) { int id = ids.get(rnd.nextInt(ids.size())), p = rnd.nextInt(4); ref.get(id)[1] = p; s.edit(id, p); }
                else if (t == 2 && !ids.isEmpty()) { int id = ids.get(rnd.nextInt(ids.size())); ref.remove(id); s.rmv(id); }
                else {
                    int user = t == 3 ? 0 : 1 + rnd.nextInt(3), best = -1;
                    for (int id : ids) {
                        if (user != 0 && ref.get(id)[0] != user) continue;
                        if (best == -1 || ref.get(id)[1] > ref.get(best)[1] || (ref.get(id)[1] == ref.get(best)[1] && id > best)) best = id;
                    }
                    if (best != -1) ref.remove(best);
                    int got = user == 0 ? s.execGlobal() : s.execUser(user);
                    if (got != best) throw new AssertionError("exec");
                }
            }
        }

Problem

Too Many Seats To List

An online exam service assigns seats in a long virtual row of one billion positions. Each arriving student must sit as far as possible from every student already seated. Students also leave, and their seats open up again. A developer lists all free seats in a set at start-up, and the service runs out of memory before the first student sits down.

A second developer keeps only the occupied seats and scans every pair of neighbors to find the widest gap. That works for 100 students. With 100,000 students in the room, each new arrival scans 100,000 pairs, and the service handles about ten arrivals per second.

Both designs answer the same question. The first stores too much, and the second recomputes too much. This lesson asks how to store only what exists, how to find the best option without a scan, and how to make sure that an option computed earlier still describes the room now.

What Each Technique Adds

What The Earlier Lessons Contribute

Free And Held Items In One Partition

The lesson Resource Allocation supplied the rule that every resource is free or held and never both, and that a release call checks the held side first. This lesson keeps that rule for seats whose numbers are too large to list.

Candidates That Are Checked Later

The lesson Validated Priority supplied the heap of candidates, the record that decides, and the habit of checking a candidate when it reaches the top instead of searching for it earlier. This lesson reuses the habit with a harder check.

Where The Record Lives

The lesson Multi-Index Records supplied the method of reading the old state before writing the new state. Here the old state includes the two neighbors of a seat.

The Choice This Lesson Adds

The new work is the source of priority. In the earlier lessons a candidate carried its own priority, such as a rating or a number. A gap between two seated students derives its priority from two other records, so a candidate is valid only if both of those records still describe the same pair.

Simple approach

Listing Every Free Seat

The direct design stores every free seat in a sorted set and picks the seat that is farthest from the nearest occupied seat.

final class NaiveRoom {
    private final java.util.TreeSet<Integer> free = new java.util.TreeSet<>();
    private final java.util.TreeSet<Integer> seated = new java.util.TreeSet<>();

    NaiveRoom(int n) { for (int s = 0; s < n; s++) free.add(s); }   // n entries up front

    int seat() {
        int best = -1, bestDist = -1;
        for (int s : free) {                                       // checks every free seat
            Integer lo = seated.floor(s), hi = seated.ceiling(s);
            int d = Math.min(lo == null ? Integer.MAX_VALUE : s - lo, hi == null ? Integer.MAX_VALUE : hi - s);
            if (d > bestDist) { bestDist = d; best = s; }
        }
        free.remove(best);
        seated.add(best);
        return best;
    }
}

The class gives right answers for a small room. Its memory and its time both grow with the number of seats, not with the number of students.

Predict first: The room has one billion seats. About how much memory does the free set need before the first student arrives, and how many seats does one seat call check when 100 students are seated?

A tree set entry takes roughly 40 bytes, so one billion entries need about 40 gigabytes before any student arrives. With 100 students seated, one call still checks all 999,999,900 free seats, so no useful call finishes.

Bottleneck

Cost That Tracks Seats Not Students

Let n be the number of seats and k the number of seated students. The free set costs O(n) memory, and a seat call costs O(n log k). Both depend on the size of the room.

Only k seats are interesting. The best new seat is either seat 0, seat n - 1, or the middle of a gap between two neighbors. A room with k students has at most k + 1 gaps, so the choice has at most k + 1 candidates.

Keeping candidates in a heap cuts the cost to O(log k) per call. The heap holds each gap computed at some earlier time. A gap changes whenever a student sits inside it or leaves one end of it. A heap entry for the old gap does not change, and it looks as good as before.

Key idea

Candidates That Check Their Own Neighbors

Store the room as the occupied seats only. A next-unused counter covers the case where seats have no structure beyond their numbers. It names the smallest seat that has never been handed out, so a room of a billion seats needs one integer. Released seats go into a min-heap, and the smallest free seat is the smaller of the heap top and the counter.

Gaps As Candidates

For a room where distance matters, each pair of neighbors defines a gap candidate. The candidate holds the two neighbors, and its priority is computed from them. A gap between neighbors a and b offers the seat in the middle at distance (b - a) / 2. The two ends of the row offer seat 0 and seat n - 1.

The Neighbor Check

A candidate in the heap is current only if its two seats are still neighbors. The neighbor check asks whether both seats are occupied and no occupied seat lies between them. A linked structure over the occupied seats answers that in O(1): the successor of the left seat must be the right seat. When the check fails, the call drops the candidate and looks at the next one.

The invariant is that every current gap has a candidate in the heap, and a candidate leaves the loop only if both neighbors still match.

State

Counters, Links And Heaps

Two small designs share one idea. The first holds three pieces of state, and the second holds four.

  • next is the next-unused counter, and it only grows.
  • released is a min-heap of seats that were handed out and returned, and a release call adds to it.
  • nextOf and prevOf map each occupied seat to its neighbors, and a seat or leave call rewires them.
  • heap holds gap candidates ordered by larger distance and then smaller seat, and every call that creates a gap adds one.

A candidate holds only its two end seats, and the sentinel values -1 and n stand for the two ends of the row.

Code

A Counter With A Heap In Java

The class below covers a room of any size, because it stores only what was handed out.

final class SeatCounter {
    private int next = 1;                                          // smallest seat never handed out
    private final java.util.PriorityQueue<Integer> released = new java.util.PriorityQueue<>();

    int reserve() {
        if (!released.isEmpty()) return released.poll();           // a returned seat is always below next
        return next++;
    }

    void unreserve(int seat) { released.add(seat); }
}

A call costs O(log k) for k returned seats, and the space is O(k). The code assumes that callers return only seats that they hold, and the first exercise adds the check that removes the assumption.

When to use it

Free Resources Under A Derived Priority

Checking The Pattern

Look for a request for the best free resource where the number of resources is far larger than the number of callers. List what the priority depends on. If it depends only on the resource itself, a counter and a heap are enough. If it depends on neighbors, store candidates for the neighbor pairs and check both ends when a candidate reaches the top. The invariant is that every current option has a candidate and no stale candidate is ever returned.

What Else Can Go Stale

An end of the row is a special case. The gap before the first seat and the gap after the last seat have only one real neighbor, so the check uses the first and last occupied seat instead of a successor. A seat that leaves and returns to the same place makes an old candidate current again, and that is correct, because the room matches the candidate once more.

False Friends

A sorted set of free seats is a false friend when the room is huge, because it stores seats that no caller will ever name. A queue of released seats is a false friend when the rule asks for the smallest seat. Skip candidates when the number of callers is small, because a scan of k neighbors costs less than the code for the checks.

Hint

Which collection answers whether a seat is held, and which two sources give the smallest free seat?

Algorithmic Solution (attempt the problem first)

Approach. The class stores three things: the next seat that was never handed out, a min-heap of returned seats, and a hash set of held seats. A reserve call takes the smaller of the heap top and the counter. Every returned seat is below the counter, so a non-empty heap always wins. The call adds the seat to the held set.

An unreserve call returns false unless the held set contains the seat. Otherwise it removes the seat from the held set and adds it to the heap, and it returns true. A seat that was never handed out is not in the held set, so the call rejects it. A second release of the same seat is rejected as well, because the first release removed it from the held set.

The invariant is that every seat from 1 up to the counter minus 1 is either in the held set or in the heap, exactly once.

Complexity.

  • Time is O(log k) per call for k returned seats, because heap operations cost logarithmic time and the set operations cost O(1).
  • Space is O(k + h) for h held seats, and it does not depend on n.
import java.util.*;

public final class SeatCounterSolution {
    static final class SeatCounter {
        private int next = 1;                                         // smallest seat never handed out
        private final PriorityQueue<Integer> released = new PriorityQueue<>();
        private final Set<Integer> held = new HashSet<>();

        /**
         * Holds the smallest free seat.
         * Time: O(log k).
         * Space: O(1) extra.
         * Invariant: seats below next are in held or released, exactly once.
         */
        int reserve() {
            // A returned seat is always smaller than the counter, so it wins when present.
            int seat = released.isEmpty() ? next++ : released.poll();
            held.add(seat);
            return seat;
        }

        /** Frees a held seat or rejects the call; O(log k) time, O(1) space; invariant: only held seats enter the heap. */
        boolean unreserve(int seat) {
            // Removing from the held set both checks and records the release in one step.
            if (!held.remove(seat)) return false;
            released.add(seat);
            return true;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text, with a billion seats and no listing.
        SeatCounter a = new SeatCounter();
        if (a.reserve() != 1 || a.reserve() != 2 || !a.unreserve(1) || a.unreserve(1) || a.reserve() != 1 || a.reserve() != 3) throw new AssertionError("e1");

        if (b.unreserve(5) || b.reserve() != 1) throw new AssertionError("e2");
        // Random calls including invalid releases, checked against a boolean array.
        Random rnd = new Random(9201);
        for (int round = 0; round < 300; round++) {
            SeatCounter s = new SeatCounter();
            boolean[] held = new boolean[200];
            for (int op = 0; op < 100; op++) {

                    if (want) held[seat] = false;
                    if (s.unreserve(seat) != want) throw new AssertionError("unreserve");
                }
            }
        }
    }

Exam Room With A Gap Heap

LeetCode 855

Problem Specification. A row has n seats numbered 0 to n - 1. Design a class GapRoom. The call seat() seats a student at the free seat that maximizes the distance to the nearest seated student and returns it. Equal distances go to the smaller seat, and the first student sits at seat 0. The call leave(p) frees seat p.

Input Constraints. The limits are:

  • Seats satisfy 2 <= n <= 10^9.
  • Calls number at most 10^5, so a scan of all seated students per call is too slow.
  • Seat is called only while a free seat exists, and leave names a seated student.
  • Return of seat is an int.

Example 1. Input n = 8 and four seat() calls, output 0, 7, 3 and 5.

Example 2. Input the same calls, then leave(3) and seat(), output 2.

Prerequisites. The first exercise above and the validated priority lesson.

What This Exercise Changes. Candidate gaps replace the scan, and each pop checks that the two end seats are still neighbors.

Hint

What must be true of the two seats in a gap entry when it reaches the top of the heap?

Algorithmic Solution (attempt the problem first)

Approach. The occupied seats form a doubly linked list stored in two hash maps, nextOf and prevOf, plus the first and last occupied seat. A candidate is a pair of two seats where -1 stands for the left end and n for the right end. Its seat is 0 for the left end, n - 1 for the right end, and left + (right - left) / 2 otherwise. Its distance is right for the left end, n - 1 - left for the right end, and (right - left) / 2 otherwise. The heap orders candidates by larger distance and then smaller seat. A candidate with distance 0 is never added.

A seat call pops candidates until one is current. A candidate with two real seats is current when the successor of its left seat is its right seat. A left-end candidate is current when its right seat is the first occupied seat, and a right-end candidate is current when its left seat is the last occupied seat. The call seats the student at the candidate's seat, rewires the links and adds the two halves of the old gap. A leave call unlinks the seat and adds the merged gap of its two neighbors.

The invariant is that every gap between neighbors has a candidate in the heap, and a popped candidate is used only if its two ends are still neighbors.

Complexity.

  • Time is O(log k) amortized per call, because every candidate is added at most once per call and popped at most once.
  • Space is O(k + c), where c is the number of calls that left stale candidates behind.
import java.util.*;

public final class ExamRoomHeapSolution {
    static final class GapRoom {
        private record Gap(int left, int right) {}                      // -1 and n stand for the two ends
        private final int n;
        private final Map<Integer, Integer> nextOf = new HashMap<>();   // occupied seat -> next occupied seat, or n
        private final Map<Integer, Integer> prevOf = new HashMap<>();   // occupied seat -> previous occupied seat, or -1
        private int first = -1, last = -1;                              // first and last occupied seats, -1 when empty
        private final PriorityQueue<Gap> heap;

        GapRoom(int n) {
            this.n = n;
            heap = new PriorityQueue<>((a, b) -> {
                int c = Integer.compare(dist(b), dist(a));
                return c != 0 ? c : Integer.compare(pick(a), pick(b));
            });
        }

        private int pick(Gap g) { return g.left() == -1 ? 0 : g.right() == n ? n - 1 : g.left() + (g.right() - g.left()) / 2; }

        private int dist(Gap g) { return g.left() == -1 ? g.right() : g.right() == n ? n - 1 - g.left() : (g.right() - g.left()) / 2; }

        private void offer(Gap g) { if (dist(g) > 0) heap.add(g); }

        // True when the two ends are still neighbors; O(1) time and space.
        private boolean current(Gap g) {
            if (g.left() == -1) return first == g.right();
            if (g.right() == n) return last == g.left();
            Integer succ = nextOf.get(g.left());
            return succ != null && succ == g.right();
        }

        /**
         * Seats a student at the best free seat.
         * Time: O(log k) amortized.
         * Space: O(1) extra.
         * Invariant: only a candidate whose ends are neighbors is used.
         */
        int seat() {
            if (first == -1) {
                first = last = 0;
                nextOf.put(0, n); prevOf.put(0, -1);
                offer(new Gap(0, n));
                return 0;
            }
            Gap g = heap.poll();
            // Drop candidates whose two ends stopped being neighbors.
            while (!current(g)) g = heap.poll();
            int p = pick(g), l = g.left(), r = g.right();
            nextOf.put(p, r); prevOf.put(p, l);
            if (l == -1) first = p; else nextOf.put(l, p);
            if (r == n) last = p; else prevOf.put(r, p);
            offer(new Gap(l, p));
            offer(new Gap(p, r));
            return p;
        }

        /** Frees seat p and offers the merged gap; O(log k) time, O(1) extra space; invariant: the links skip p. */
        void leave(int p) {
            int l = prevOf.remove(p), r = nextOf.remove(p);
            if (l != -1) nextOf.put(l, r); else first = r == n ? -1 : r;
            if (r != n) prevOf.put(r, l); else last = l;
            if (first != -1) offer(new Gap(l, r));
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        GapRoom r = new GapRoom(8);
        int[] got = {r.seat(), r.seat(), r.seat(), r.seat()};
        if (got[0] != 0 || got[1] != 7 || got[2] != 3 || got[3] != 5) throw new AssertionError("e1");
        r.leave(3);
        if (r.seat() != 2) throw new AssertionError("e2");
        // A huge row works because only seated students are stored.
        GapRoom big = new GapRoom(1_000_000_000);
        if (big.seat() != 0 || big.seat() != 999_999_999 || big.seat() != 499_999_999) throw new AssertionError("big row");
        // Random calls checked against a scan of every free seat.
        Random rnd = new Random(855);
        for (int round = 0; round < 400; round++) {
            int n = 2 + rnd.nextInt(14);
            GapRoom s = new GapRoom(n);
            boolean[] occ = new boolean[n];
            int count = 0;
            for (int op = 0; op < 80; op++) {
                if (count < n && (count == 0 || rnd.nextInt(3) > 0)) {
                    int want = 0, wantD = -1;
                    for (int c = 0; c < n; c++) {
                        if (occ[c]) continue;
                        int d = count == 0 ? n : Integer.MAX_VALUE;
                        for (int q = 0; q < n; q++) if (occ[q]) d = Math.min(d, Math.abs(q - c));
                        if (d > wantD) { wantD = d; want = c; }
                    }
                    occ[want] = true; count++;
                    if (s.seat() != want) throw new AssertionError("seat");
                } else {
                    int p = rnd.nextInt(n);
                    while (!occ[p]) p = (p + 1) % n;
                    occ[p] = false; count--;
                    s.leave(p);
                }
            }
        }
    }

Edge Cases

Stale Gap Candidate

Author exercise

Problem Specification. Design a class GapBook of occupied positions on a line. The call occupy(seat) marks a free position occupied. The call vacate(seat) marks an occupied position free. The call widestGap() returns [left, right] for the pair of consecutive occupied positions with the largest difference right - left, breaking ties by the smaller left. It returns an empty array when fewer than two positions are occupied.

Input Constraints. The limits are:

  • Positions are integers from 0 to 10^9.
  • Calls number at most 10^5, and occupy and vacate name positions in the right state.
  • Consecutive means no occupied position lies strictly between the two.
  • Return of widestGap is an array of length 2 or length 0.

Example 1. Input calls occupy(2), occupy(10), occupy(6), widestGap(), vacate(6), widestGap(), output [2,6] and then [2,10].

Example 2. Input calls occupy(1), widestGap(), occupy(9), occupy(4), widestGap(), vacate(9), widestGap(), output an empty array, [4,9] and then [1,4].

Prerequisites. The two exercises above.

What This Exercise Changes. A candidate needs both ends occupied and no occupied position between them, and checking one end accepts wrong answers.

Hint

Is it enough to check that the left position is still occupied? What can happen between the two positions?

Algorithmic Solution (attempt the problem first)

Approach. A tree set holds the occupied positions. A heap holds candidate pairs ordered by larger difference and then smaller left position. An occupy call finds the lower and higher neighbors of the new position before it inserts the position. It then adds a candidate for each existing neighbor pair that touches the new position. A vacate call finds the same two neighbors after the removal and adds the merged pair when both neighbors exist.

A widest-gap call looks at the heap top. A candidate is current only when both positions are occupied and the occupied position directly above the left one is the right one. A candidate that fails the test is popped and dropped. The first current candidate is returned and stays in the heap.

Checking only the left position is not enough. If position 9 is vacated, the pair (4, 9) keeps its left end occupied and fails only on the right end. If a new position is occupied between 4 and 9, both ends stay occupied and the pair fails only on the adjacency test.

The invariant is that every pair of consecutive occupied positions has a candidate in the heap, and a candidate is returned only after the three-part test passes.

Complexity.

  • Time is O(log k) amortized per call, because each candidate is added once and dropped at most once.
  • Space is O(k + c) for k occupied positions and c candidates that went stale.
import java.util.*;

public final class StaleGapSolution {
    static final class GapBook {
        private record Gap(int left, int right) {}
        private final TreeSet<Integer> occupied = new TreeSet<>();
        private final PriorityQueue<Gap> heap = new PriorityQueue<>((a, b) -> {
            int c = Integer.compare(b.right() - b.left(), a.right() - a.left());
            return c != 0 ? c : Integer.compare(a.left(), b.left());
        });

        /** Marks a free position occupied and offers the two new gaps; O(log k) time, O(1) space; invariant: both new pairs enter the heap. */
        void occupy(int seat) {
            Integer lo = occupied.lower(seat), hi = occupied.higher(seat);
            occupied.add(seat);
            if (lo != null) heap.add(new Gap(lo, seat));
            if (hi != null) heap.add(new Gap(seat, hi));
        }

        /** Frees an occupied position and offers the merged gap; O(log k) time, O(1) space; invariant: the merged pair enters the heap. */
        void vacate(int seat) {
            occupied.remove(seat);
            Integer lo = occupied.lower(seat), hi = occupied.higher(seat);
            if (lo != null && hi != null) heap.add(new Gap(lo, hi));
        }

        // The three-part test: both ends occupied and no occupied position between them; O(log k) time.
        private boolean current(Gap g) {
            if (!occupied.contains(g.left()) || !occupied.contains(g.right())) return false;
            Integer above = occupied.higher(g.left());
            return above != null && above == g.right();
        }

        /**
         * Returns the widest pair of consecutive occupied positions.
         * Time: O(log k) amortized.
         * Space: O(1) extra.
         * Invariant: only candidates that fail the test leave the heap.
         */
        int[] widestGap() {
            while (!heap.isEmpty()) {
                Gap g = heap.peek();
                if (current(g)) return new int[] {g.left(), g.right()};
                heap.poll();
            }
            return new int[0];
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        GapBook a = new GapBook();
        a.occupy(2); a.occupy(10); a.occupy(6);
        if (!Arrays.equals(a.widestGap(), new int[] {2, 6})) throw new AssertionError("e1 first");
        a.vacate(6);
        if (!Arrays.equals(a.widestGap(), new int[] {2, 10})) throw new AssertionError("e1 second");
        GapBook b = new GapBook();
        b.occupy(1);
        if (b.widestGap().length != 0) throw new AssertionError("e2 empty");
        b.occupy(9); b.occupy(4);
        if (!Arrays.equals(b.widestGap(), new int[] {4, 9})) throw new AssertionError("e2 middle");
        b.vacate(9);
        if (!Arrays.equals(b.widestGap(), new int[] {1, 4})) throw new AssertionError("e2 vacate");
        // Random calls checked against a scan of the sorted occupied positions.
        Random rnd = new Random(9203);
        for (int round = 0; round < 400; round++) {
            GapBook s = new GapBook();
            boolean[] occ = new boolean[15];
            for (int op = 0; op < 100; op++) {
                int p = rnd.nextInt(15);
                if (occ[p]) { occ[p] = false; s.vacate(p); } else { occ[p] = true; s.occupy(p); }
                int[] want = new int[0];
                int prev = -1;
                for (int x = 0; x < 15; x++) {
                    if (!occ[x]) continue;
                    if (prev != -1 && (want.length == 0 || x - prev > want[1] - want[0])) want = new int[] {prev, x};
                    prev = x;
                }
                if (!Arrays.equals(s.widestGap(), want) || !Arrays.equals(s.widestGap(), want)) throw new AssertionError("widestGap");
            }
        }
    }

Booking Hall With Cancellations

LeetCode 2286

Problem Specification. A hall has n rows of m seats. Seats in a row are booked from the left, so a row with b bookings has its first b seats booked. Design a class CancelHall. The call gather(k, maxRow) books k seats in the smallest row r <= maxRow that has k free seats, and returns [r, firstSeat], or an empty array if no such row exists. The call scatter(k, maxRow) books k seats over rows 0 to maxRow, lowest rows first, and returns true, or returns false and changes nothing if the free seats there total fewer than k. The call cancel(row, k) frees the last k booked seats of the row and returns true, or returns false if the row holds fewer than k bookings.

Input Constraints. The limits are:

  • Rows satisfy 1 <= n <= 5 * 10^4, and m satisfies 1 <= m <= 10^9.
  • k satisfies 1 <= k <= m, and maxRow and row satisfy 0 <= value < n.
  • Calls number at most 5 * 10^4.
  • Totals of free seats need a long.

Example 1. Input n = 3, m = 4 and calls scatter(5,2), cancel(0,2), gather(2,0), output true, true and [0,2].

Example 2. Input the same hall and calls scatter(5,2), cancel(2,1), gather(4,2), output true, false and [2,0].

Prerequisites. All three exercises above and the segment tree from the range-query chapter.

What This Exercise Changes. Cancellation makes the first open row move backward, so each call finds it by a tree descent and not by a pointer.

Hint

After a cancellation, which row is the first one with free seats, and can a pointer that only moves forward still find it?

Algorithmic Solution (attempt the problem first)

Approach. Each row stores its free seat count, and the booked seats are the leftmost ones. An iterative segment tree over the rows keeps the maximum and the sum of the free counts, padded with empty rows up to a power of two.

A gather call descends from the root to the leftmost row whose free count is at least k. It returns an empty array when that row is past maxRow. Otherwise the first seat is m minus the free count, and a point update lowers the count by k. A scatter call checks the sum of rows 0 to maxRow against k. It then repeats the same descent with a demand of 1 to find the lowest row that still has a free seat, takes as many seats as that row offers, and updates it. A cancel call checks that the row holds at least k bookings, raises the free count and updates the tree.

The descent replaces the forward-moving pointer of the version without cancellations, because a cancel call can reopen a row below the pointer.

The invariant is that each tree node holds the maximum and the sum of the free counts of its rows after every call.

Complexity.

  • Time is O(log n) per gather and cancel call, and O((rows touched + 1) log n) per scatter call.
  • Space is O(n), because the tree holds about 2n numbers.
import java.util.*;

public final class HallCancelSolution {
    static final class CancelHall {
        private final int n, size;
        private final long m;
        private final long[] free, mx, sm;

        /** Builds the tree with every row empty; O(n) time, O(n) space; invariant: each node summarizes its rows. */
        CancelHall(int n, int m) {
            this.n = n; this.m = m;
            int sz = 1;
            while (sz < n) sz <<= 1;
            size = sz;
            free = new long[n];
            mx = new long[2 * sz]; sm = new long[2 * sz];
            for (int r = 0; r < n; r++) { free[r] = m; mx[sz + r] = sm[sz + r] = m; }
            for (int i = sz - 1; i >= 1; i--) pull(i);
        }

        private void pull(int i) {
            mx[i] = Math.max(mx[2 * i], mx[2 * i + 1]);
            sm[i] = sm[2 * i] + sm[2 * i + 1];
        }

        // Writes one row and repairs its ancestors in O(log n).
        private void setRow(int r, long value) {
            free[r] = value;
            int i = size + r;
            mx[i] = sm[i] = value;
            for (i >>= 1; i >= 1; i >>= 1) pull(i);
        }

        // Sums rows [0, hi] with a bottom-up walk in O(log n).
        private long prefix(int hi) {
            long total = 0;
            for (int l = size, r = size + hi + 1; l < r; l >>= 1, r >>= 1) {
                if ((l & 1) == 1) total += sm[l++];
                if ((r & 1) == 1) total += sm[--r];
            }
            return total;
        }

        // Returns the leftmost row with at least k free seats, or -1, in O(log n).
        private int leftmost(long k) {
            if (mx[1] < k) return -1;
            int i = 1;
            while (i < size) i = mx[2 * i] >= k ? 2 * i : 2 * i + 1;
            return i - size;
        }

        /** Books k seats in the first row with room; O(log n) time, O(1) space; invariant: the row is the leftmost with k free. */
        int[] gather(int k, int maxRow) {
            int r = leftmost(k);
            if (r == -1 || r > maxRow) return new int[0];
            int seat = (int) (m - free[r]);
            setRow(r, free[r] - k);
            return new int[] {r, seat};
        }

        /** Books k seats over the lowest rows or changes nothing; O((rows + 1) log n) time, O(1) space; invariant: the sum check precedes every write. */
        boolean scatter(int k, int maxRow) {
            if (prefix(maxRow) < k) return false;
            long need = k;
            while (need > 0) {
                int r = leftmost(1);
                long take = Math.min(free[r], need);
                setRow(r, free[r] - take);
                need -= take;
            }
            return true;
        }

        /** Frees the last k bookings of a row; O(log n) time, O(1) space; invariant: free stays between 0 and m. */
        boolean cancel(int row, int k) {
            if (m - free[row] < k) return false;
            setRow(row, free[row] + k);
            return true;
        }
    }

    public static void main(String[] args) {
        // Example 1 and Example 2 from the problem text.
        CancelHall a = new CancelHall(3, 4);
        int[] g;
        if (!a.scatter(5, 2) || !a.cancel(0, 2) || (g = a.gather(2, 0)).length != 2 || g[0] != 0 || g[1] != 2) throw new AssertionError("e1");
        CancelHall b = new CancelHall(3, 4);
        if (!b.scatter(5, 2) || b.cancel(2, 1) || (g = b.gather(4, 2)).length != 2 || g[0] != 2 || g[1] != 0) throw new AssertionError("e2");
        // Random calls checked against a plain array of free counts.
        Random rnd = new Random(9204);
        for (int round = 0; round < 400; round++) {
            int n = 1 + rnd.nextInt(6), m = 1 + rnd.nextInt(6);
            CancelHall s = new CancelHall(n, m);
            int[] free = new int[n];
            Arrays.fill(free, m);
            for (int op = 0; op < 60; op++) {
                int t = rnd.nextInt(3), k = 1 + rnd.nextInt(m), maxRow = rnd.nextInt(n);
                if (t == 0) {
                    int row = -1;
                    for (int r = 0; r < n && row == -1; r++) if (free[r] >= k) row = r;
                    int[] got = s.gather(k, maxRow);
                    if (row == -1 || row > maxRow) { if (got.length != 0) throw new AssertionError("gather none"); }
                    else { if (got.length != 2 || got[0] != row || got[1] != m - free[row]) throw new AssertionError("gather row"); free[row] -= k; }
                } else if (t == 1) {
                    int total = 0;
                    for (int r = 0; r <= maxRow; r++) total += free[r];
                    boolean want = total >= k;
                    if (want) { int need = k; for (int r = 0; need > 0; r++) { int take = Math.min(free[r], need); free[r] -= take; need -= take; } }
                    if (s.scatter(k, maxRow) != want) throw new AssertionError("scatter");
                } else {
                    int row = rnd.nextInt(n);
                    boolean want = m - free[row] >= k;
                    if (want) free[row] += k;
                    if (s.cancel(row, k) != want) throw new AssertionError("cancel");
                }
            }
        }
    }
