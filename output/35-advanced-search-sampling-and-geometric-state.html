Chapter 35

Advanced Search And Random Sampling

Orientation

A coupon tool must pick the best subset of 40 items for a budget, and a loop over every subset never finishes. A promotion engine must choose one winner at random, and its winners cluster at the start of the list. A map app must find a route fast, and its shortcut sometimes returns a slower road. Each problem has a correct method that is neither the first idea nor an exotic one. This chapter teaches six such methods for search that must split its work, and for random choices that must stay fair.

Prerequisites

You should know binary search, sorting, heaps, shortest paths with a priority queue, and the Fenwick tree from the range-query chapter. A uniform choice gives every allowed outcome the same chance. A distribution states the chance of each outcome. An expected cost is the average cost over the random draws for a fixed input. Every lesson passes the source of randomness into the method as a parameter, so tests can script each draw and check each probability by counting.

What Each Lesson Protects

Each lesson names one fact that stays true for the whole run.

  • Meet In Middle keeps a one-to-one map between full choices and pairs of half choices.
  • A Star Search keeps the priority of every queued entry at or below the cost of the best route.
  • Reservoir Sampling keeps every item seen so far equally likely to be held.
  • Weighted Selection keeps one owner for every ticket from 1 to the total weight.
  • Rejection Sampling keeps every draw uniform over the larger region and the test independent of the draw.
  • Randomized Partitioning keeps the wanted rank inside the active range after every round.
  • Randomized Sampling State keeps the chance of each eligible item equal to its weight over the eligible total.
  • A-Star Heuristics keeps the guess below the true remaining cost and handles a negative reduced weight by reopening.

Reading Order

Every lesson opens with a program that passes short tests and fails on larger inputs or on a statistical check. You predict the failure before the reasoning appears. Two traces follow the variables step by step, then Java code and the limits of the idea. The four exercises climb from a basic build to a variation, an edge case and a recognition problem. A false friend is a method that looks like the pattern but breaks its precondition. Solutions check each class against an oracle, a slow but obviously correct version, and count outcomes over every possible draw sequence where the sizes are small.

What You Can Do After This Chapter

You can tell from a limit of 40 that two half enumerations are the intended method. You can attach a guess to a shortest-path search and test it before trusting it. You can write the chance of one item as a fraction before you code a random pick, and you can name the denominator. Randomized state that changes between calls, such as shuffles, belongs to the streaming chapter that precedes this one.

Problem

Forty Items And One Budget

A shopping app lets a customer pick any of 40 add-on items so that the total price lands as close as possible to a gift-card balance. A test with 12 items answers instantly. The same code on 40 items runs for the whole afternoon and the test never finishes. Each item is either in the order or out of it, so 40 items allow about 1.1 trillion different orders. No loop can look at that many totals in a normal request.

The problem is not unusual. Subset-sum questions with 30 to 44 items show up in interview rounds and in budget tools. The numbers are too large for one pass over all choices and too small to justify heavy machinery. This lesson asks one question. Can the work shrink from "all choices of 40 items" to something a laptop finishes in under a second, without losing the exact answer?

Simple approach

Try Every Subset Directly

The direct method treats each subset as a bit pattern. A counter mask runs from 0 to 2^n - 1, and bit k of the counter says whether item k is in the order. For every pattern the method adds up the chosen items and compares the total with the target. The code keeps the total in a long, because 40 prices near a billion overflow an int.

final class NaiveClosest {
    static long closest(int[] a, long target) {
        int n = a.length;
        long best = Long.MAX_VALUE;
        for (long mask = 0; mask < (1L << n); mask++) {
            long sum = 0;
            for (int k = 0; k < n; k++) {
                if ((mask >> k & 1) == 1) sum += a[k];   // item k is in this subset
            }
            best = Math.min(best, Math.abs(sum - target));
        }
        return best;
    }
}

The method is correct and easy to check. For n = 20 it makes about a million patterns and finishes at once. A different attempt would try dynamic programming over the total, as in the knapsack lessons, but prices up to a billion make the table of totals far too large.

Predict first: Suppose the machine checks one pattern per nanosecond and ignores the inner loop. About how long does the loop take for n = 40? Now cut the 40 items into two groups of 20 and write down every subset total of each group separately. How many totals do you write down in all?

The loop needs 2^40, about 1.1 x 10^12, checks. At one per nanosecond that is roughly 1100 seconds, and the inner loop of 40 steps makes it far worse. Two groups of 20 produce 2^20, about one million, totals each, so about two million totals in all. Two million is a number that fits in memory and in a fraction of a second.

Bottleneck

Recomputing Totals For Every Pair

Repeated Work In The Loop

The loop costs O(2^n * n) time and O(1) extra space. The 2^n factor is the real problem. Look at what happens inside it. Take two patterns that agree on the first 20 items and differ only on the last 20. The loop adds up the same first 20 items for both patterns, then adds different last items. Across all patterns, the same 2^20 partial totals of the first group are rebuilt 2^20 times each.

The patterns also have a structure that the loop ignores. Choosing a subset of 40 items is the same as choosing a subset of the first 20 and, independently, a subset of the last 20. The final total is the sum of two numbers, one from each side, and the choices on the two sides never interact. The loop pairs every first-group choice with every last-group choice one at a time, and that pairing is where the 2^40 comes from.

Looking Up Instead Of Pairing

Pairing is not necessary. If the loop fixes one first-group total s and wants the total closest to target, it needs one value from the last group that is closest to target - s. Finding the closest value to a given number in a list is a search question, and a sorted list answers it quickly. So the requirement is a way to write each group's totals once and look up the best partner for each.

Key idea

Split In Two And Search

Two Halves With One Rule

The method cuts the array at mid = n / 2 into two halves: positions 0 to mid - 1, and positions mid to n - 1. Every subset of the array has a unique split: the part inside the first half and the part inside the second half. No position belongs to both halves, so no subset is split in two ways, and the two parts together give the whole subset back. The map from subsets of the array to pairs (first-half subset, second-half subset) is one to one and covers every pair.

The consequence is a total that adds up in two pieces. If the first-half part has sum s and the second-half part has sum t, the subset sum is s + t. The method lists all 2^mid sums of the first half and all 2^(n - mid) sums of the second half. Each list builds by doubling. It starts as [0], and for each element x it appends a copy of the list shifted by x.

Looking Up The Complement

Fix one first-half sum s. The best partner is the second-half sum t that makes s + t closest to target. That means t should be closest to the complement target - s. The method sorts the second-half sums once. For each s a binary search finds the first sum at or above the complement, and the sum just before it. The closer of those two neighbours is the best partner for s. Taking the smallest distance over all s gives the answer.

What The Cost Becomes

Building both lists costs O(2^(n/2)) time. Sorting one list costs O(2^(n/2) * n). Each of the 2^(n/2) lookups costs O(n). The total is O(2^(n/2) * n) time and O(2^(n/2)) space. For n = 40 that is about a million entries per list instead of a trillion patterns.

The invariant is this: the pairs (first-half sum, second-half sum) stand for every subset exactly once, and for each first-half sum the lookup returns the best second-half sum.

State

Lists, Midpoint And Best Distance

The code keeps six names, and each one is set in a known place.

  • mid is n / 2. It is the first position of the second half.
  • left is the array of all first-half sums, with 2^mid entries.
  • right is the sorted array of all second-half sums, with 2^(n - mid) entries.
  • target is the goal total, stored as a long.
  • need is the complement target - s for the current first-half sum s. It changes once per loop step.
  • best is the smallest distance found so far. It starts at Long.MAX_VALUE and only decreases.

The lists contain the empty sum 0, because each half may contribute no item. Equal sums stay in the lists as separate entries, because two different subsets can produce the same total.

Walkthrough

Tracing The Two Steps

Building Half Sums By Doubling

The first trace builds the sums of the half 3 5 2. The pointer i marks the element being added. At the start the list holds only the empty sum 0. Adding 3 copies the list shifted by 3 and gives 0 3. Adding 5 doubles the list again and gives 0 3 5 8. Adding 2 doubles it a third time and gives eight sums, 0 3 5 8 2 5 7 10. Two different subsets, {5} and {3, 2}, both have the sum 5, and the list keeps both copies. Sorting at the end gives 0 2 3 5 5 7 8 10.

Searching For The Complement

The second trace searches the sorted second-half list 0 4 7 11 15 for the complement 8. The pointers lo, mid and hi bound the search. The search looks for the first entry at or above 8. It ends at index 3, where the value is 11. The entry before it, 7, is also a candidate. The distances are 3 for 11 and 1 for 7, so the best partner is 7 and the subset total misses the target by 1.

Code

Closest Sum With Two Lists

Building And Searching

The method halfSums builds the sums of positions from to to - 1 by doubling. The method closest sorts the second list and runs a lower-bound binary search for each first-half sum.

final class MeetInMiddle {
    static long[] halfSums(int[] a, int from, int to) {
        long[] s = new long[1 << (to - from)];
        int size = 1;                                   // the empty subset gives sum 0
        for (int k = from; k < to; k++) {
            for (int j = 0; j < size; j++) s[size + j] = s[j] + a[k];   // copy shifted by a[k]
            size *= 2;                                  // the list doubles with each element
        }
        return s;
    }

    static long closest(int[] a, long target) {
        int mid = a.length / 2;
        long[] left = halfSums(a, 0, mid);
        long[] right = halfSums(a, mid, a.length);
        java.util.Arrays.sort(right);                   // binary search needs sorted order
        long best = Long.MAX_VALUE;
        for (long s : left) {
            long need = target - s;                     // the complement of this first-half sum
            int lo = 0, hi = right.length;              // find the first index with right[idx] >= need
            while (lo < hi) {
                int m = (lo + hi) >>> 1;
                if (right[m] < need) lo = m + 1; else hi = m;
            }
            if (lo < right.length) best = Math.min(best, Math.abs(right[lo] - need));
            if (lo > 0) best = Math.min(best, Math.abs(need - right[lo - 1]));
        }
        return best;
    }
}

Cost

  • halfSums costs O(2^k) time and space for k elements.
  • closest costs O(2^(n/2) * n) time and O(2^(n/2)) space.
  • Memory for n = 40 is two arrays of about a million long values, near 16 MB.
When to use it

When Splitting In Half Applies

Recognizing The Pattern

Use this method when the statement lets each item be taken or left, when n is between about 30 and 44, and when the objective is a sum of per-item contributions. The limits are the cue. A limit of n <= 20 allows plain enumeration and a limit near 100 or more points to a different tool. The invariant to protect is that each full choice maps to exactly one pair of half choices.

False Friends

A knapsack table is a false friend when values are small. It runs in O(n * W) time, and it beats this method when the total W is a few thousand. A greedy choice of the largest item that still fits is another false friend, because subset sum has no greedy rule that stays exact. Two pointers over a sorted array look like pairing, but they pair two elements, not two subsets.

When The Method Does Not Apply

If the objective does not split into a sum, as in a product with sign changes or a cost that depends on neighbouring picks across the middle, the halves interact and the pair lookup is wrong. If n is 60 or more, 2^30 entries per list no longer fit in memory, so the method is a no-go.

Half Subset Sums

Author exercise

Problem Specification. Write long[] subsetSums(int[] a). The method returns every subset sum of a in increasing order. There is one entry for each subset of positions, so the result has 2^a.length entries. The empty subset contributes the sum 0.

Input Constraints. The limits are:

  • Length of a is from 0 to 20.
  • Values are int values from -10^9 to 10^9, possibly equal or negative.
  • Result is a new array that is sorted in non-decreasing order.
  • Sums use long arithmetic.

Example 1. Input a = [3, 3], output [0, 3, 3, 6].

Example 2. Input a = [4, -2, 5], output [-2, 0, 2, 3, 4, 5, 7, 9].

Prerequisites. The doubling construction from this lesson.

What This Exercise Changes. Basic case: build the sums for one array, with no target and no search.

Hint

How long is the result after each element, and what does the new half of the array hold?

Algorithmic Solution (attempt the problem first)

Approach. The result array starts with one entry, the empty sum 0. For each element x the method copies the current entries into the next block of the same array, adding x to each copy. The entry count doubles with every element, so after k elements the array holds 2^k sums, one per subset of the first k positions. The method adds in long, so values near 10^9 cannot wrap. A final sort puts the sums in order. The invariant is that after each element the filled prefix of the array holds exactly one sum per subset of the elements seen so far.

The program compares the method with a mask-based enumeration on random arrays that include negative values and repeats. It also checks that two ints near 2^31 overflow in int arithmetic and not in long, which is why the sums are long.

Complexity.

  • Time is O(2^n * n) with the sort, because the doubling writes 2^n entries and the sort compares them in n * 2^n steps.
  • Space is O(2^n) for the result array.
import java.util.Arrays;
import java.util.Random;

public final class HalfSubsetSumsBuild {
    /**
     * Returns all subset sums of a in non-decreasing order.
     * Time: O(2^n * n). Space: O(2^n).
     * Invariant: after element k the first 2^k entries hold one sum per subset of a[0..k-1].
     */
    static long[] subsetSums(int[] a) {
        long[] s = new long[1 << a.length];
        int size = 1; // the empty subset gives the sum 0
        for (int k = 0; k < a.length; k++) {
            // copy every sum into the next block and add a[k], so each old subset gains a twin that takes a[k]
            for (int j = 0; j < size; j++) s[size + j] = s[j] + a[k];
            size *= 2; // the count of subsets doubles with each element
        }
        Arrays.sort(s); // sorted order is the output contract
        return s;
    }

    static long[] oracle(int[] a) {
        long[] r = new long[1 << a.length];
        for (int mask = 0; mask < r.length; mask++) {
            long sum = 0;
            for (int k = 0; k < a.length; k++) if ((mask >> k & 1) == 1) sum += a[k];
            r[mask] = sum;
        }
        Arrays.sort(r);
        return r;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (!Arrays.equals(subsetSums(new int[]{3, 3}), new long[]{0, 3, 3, 6})) throw new AssertionError("ex1");
        if (!Arrays.equals(subsetSums(new int[]{4, -2, 5}), new long[]{-2, 0, 2, 3, 4, 5, 7, 9})) throw new AssertionError("ex2");
        // the empty array has exactly one subset
        if (!Arrays.equals(subsetSums(new int[0]), new long[]{0})) throw new AssertionError("empty");
        // int addition wraps near 2^31, long addition does not
        int wrapped = 2_000_000_000 + 2_000_000_000;
        if (wrapped >= 0 || (long) 2_000_000_000 + 2_000_000_000 != 4_000_000_000L) throw new AssertionError("overflow claim");
        // random arrays with negatives and repeats agree with the mask oracle
        Random rnd = new Random(35);
        for (int t = 0; t < 400; t++) {
            int[] a = new int[rnd.nextInt(11)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(7) - 3;
            if (!Arrays.equals(subsetSums(a), oracle(a))) throw new AssertionError("random " + Arrays.toString(a));
        }
        System.out.println("ok");
    }
}verified
Variation

Closest Pair Of Half Sums

Author exercise

Problem Specification. Write long closestPair(int[] left, int[] right, long target). Pick one subset of left and one subset of right, either possibly empty. Let total be the sum of the two subsets together. Return the smallest value of |total - target| over all such picks.

Input Constraints. The limits are:

  • Lengths of both arrays are from 0 to 20.
  • Values are int values from -10^9 to 10^9.
  • Target is a long from -10^15 to 10^15.
  • Mutation is not allowed on the inputs.

Example 1. Input left = [5, 10], right = [3, 6], target = 14, output 0, because 5 and 3 + 6 give 14.

Example 2. Input left = [7, 2], right = [4, -9], target = 20, output 7, because the best total is 13.

Prerequisites. The Half Subset Sums exercise above. This exercise adds a second array and a target.

What This Exercise Changes. The split of the array is given by the input, and the objective is a distance to a target.

Hint

Which of the two lists needs to be sorted, and how many neighbours of the complement must be checked?

Algorithmic Solution (attempt the problem first)

Approach. The method lists every sum of left and every sum of right. It sorts the second list. For each sum s of the first list it computes the complement target - s and runs a lower-bound binary search for the first entry at or above the complement. The entry found and the entry before it are the only two candidates, because every other entry is farther from the complement. The method keeps the smallest distance seen. An empty array contributes the single sum 0, so empty picks are covered. The invariant is that after each first-list sum the variable best equals the minimum distance over all pairs that use a first-list sum seen so far.

The program checks the method against a double loop over both lists on random inputs, including targets far outside the reachable range and empty arrays.

Complexity.

  • Time is O(2^a * a + 2^b * b + 2^a * b) for arrays of lengths a and b, which is the build plus one binary search per first-list sum.
  • Space is O(2^a + 2^b) for the two lists.
import java.util.Arrays;
import java.util.Random;

public final class ClosestPairHalfSumsVary {
    static long[] sums(int[] a) {
        long[] s = new long[1 << a.length];
        int size = 1;
        for (int k = 0; k < a.length; k++) {
            for (int j = 0; j < size; j++) s[size + j] = s[j] + a[k];
            size *= 2;
        }
        return s;
    }

    /**
     * Smallest |sumLeft + sumRight - target| over all pairs of subsets.
     * Time: O(2^a * a + 2^b * b + 2^a * b). Space: O(2^a + 2^b).
     * Invariant: best is the minimum distance over the first-list sums handled so far.
     */
    static long closestPair(int[] left, int[] right, long target) {
        long[] ls = sums(left);
        long[] rs = sums(right);
        Arrays.sort(rs); // the lookup needs sorted order
        long best = Long.MAX_VALUE;
        for (long s : ls) {
            long need = target - s; // complement of the first-list sum
            int lo = 0, hi = rs.length;
            while (lo < hi) { // lower bound: first index with rs[idx] >= need
                int m = (lo + hi) >>> 1;
                if (rs[m] < need) lo = m + 1; else hi = m;
            }
            if (lo < rs.length) best = Math.min(best, Math.abs(rs[lo] - need)); // nearest from above
            if (lo > 0) best = Math.min(best, Math.abs(need - rs[lo - 1]));     // nearest from below
        }
        return best;
    }

    static long oracle(int[] left, int[] right, long target) {
        long best = Long.MAX_VALUE;
        for (long x : sums(left)) for (long y : sums(right)) best = Math.min(best, Math.abs(x + y - target));
        return best;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (closestPair(new int[]{5, 10}, new int[]{3, 6}, 14) != 0) throw new AssertionError("ex1");
        if (closestPair(new int[]{7, 2}, new int[]{4, -9}, 20) != 7) throw new AssertionError("ex2");
        // both arrays empty: the only total is 0
        if (closestPair(new int[0], new int[0], -5) != 5) throw new AssertionError("both empty");
        // random inputs, including targets far from every reachable total
        Random rnd = new Random(36);
        for (int t = 0; t < 500; t++) {
            int[] l = new int[rnd.nextInt(7)], r = new int[rnd.nextInt(7)];
            for (int i = 0; i < l.length; i++) l[i] = rnd.nextInt(41) - 20;
            for (int i = 0; i < r.length; i++) r[i] = rnd.nextInt(41) - 20;
            long target = rnd.nextInt(400) - 200;
            if (closestPair(l, r, target) != oracle(l, r, target)) throw new AssertionError("random");
        }
        System.out.println("ok");
    }
}verified
Edge Cases

Duplicates And Long Sums

Author exercise

Problem Specification. Write long countSubsets(int[] a, long target). The method counts the subsets of positions of a whose sum equals target. Two subsets are different when their position sets are different, even if their values are equal. The empty subset counts when target is 0.

Input Constraints. The limits are:

  • Length of a is from 0 to 40.
  • Values are int values from -10^9 to 10^9, and they may repeat or equal 0.
  • Target is a long.
  • Result fits in a long.

Example 1. Input a = [1, 1, 1], target = 2, output 3.

Example 2. Input a = [1000000000, 1000000000, 1000000000, 1000000000], target = 3000000000, output 4.

Prerequisites. The Closest Pair Of Half Sums exercise above. This exercise changes the goal from a distance to an exact count and keeps every equal sum.

What This Exercise Changes. The lookup returns how many partners match exactly, not which partner is nearest, and the code must keep multiplicity.

Hint

When the lookup finds one equal sum, how many equal sums sit next to it in the sorted list?

Algorithmic Solution (attempt the problem first)

Approach. The method counts pairs of half subsets whose sums add to target. It builds the sums of the first half and the sorted sums of the second half. For each first-half sum it needs the number of second-half entries equal to the complement. Two lower-bound searches give that number: the first index at or above the complement and the first index above it. Their difference is the count of equal entries. Adding the counts over all first-half sums gives the answer. Equal sums stay in the lists as separate entries, so two subsets with the same values count twice. The invariant is that total holds the number of matching subsets whose first-half part has a sum already handled.

The program compares the method with a mask enumeration on arrays full of zeros, repeats and negatives, and runs the large-value example that overflows int arithmetic.

Complexity.

  • Time is O(2^(n/2) * n), because the build and sort dominate and each lookup is two binary searches.
  • Space is O(2^(n/2)) for the two lists.
import java.util.Arrays;
import java.util.Random;

public final class DuplicatesLongSumsBoundary {
    static long[] sums(int[] a, int from, int to) {
        long[] s = new long[1 << (to - from)];
        int size = 1;
        for (int k = from; k < to; k++) {
            for (int j = 0; j < size; j++) s[size + j] = s[j] + a[k];
            size *= 2;
        }
        return s;
    }

    /** First index in sorted r whose value is at least v. */
    static int lowerBound(long[] r, long v) {
        int lo = 0, hi = r.length;
        while (lo < hi) {
            int m = (lo + hi) >>> 1;
            if (r[m] < v) lo = m + 1; else hi = m;
        }
        return lo;
    }

    /**
     * Counts subsets of positions with sum equal to target.
     * Time: O(2^(n/2) * n). Space: O(2^(n/2)).
     * Invariant: total counts matching subsets whose first-half part was already handled.
     */
    static long countSubsets(int[] a, long target) {
        int mid = a.length / 2;
        long[] left = sums(a, 0, mid);
        long[] right = sums(a, mid, a.length);
        Arrays.sort(right); // equal sums become neighbours
        long total = 0;
        for (long s : left) {
            long need = target - s; // the second-half sum that completes the target
            // the run of entries equal to need starts at lowerBound(need) and ends before lowerBound(need + 1)
            total += lowerBound(right, need + 1) - lowerBound(right, need);
        }
        return total;
    }

    static long oracle(int[] a, long target) {
        long c = 0;
        for (int mask = 0; mask < (1 << a.length); mask++) {
            long sum = 0;
            for (int k = 0; k < a.length; k++) if ((mask >> k & 1) == 1) sum += a[k];
            if (sum == target) c++;
        }
        return c;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (countSubsets(new int[]{1, 1, 1}, 2) != 3) throw new AssertionError("ex1");
        if (countSubsets(new int[]{1_000_000_000, 1_000_000_000, 1_000_000_000, 1_000_000_000}, 3_000_000_000L) != 4) throw new AssertionError("ex2");
        // zeros double the count of every sum, and the empty array has one subset with sum 0
        if (countSubsets(new int[]{0, 0}, 0) != 4) throw new AssertionError("zeros");
        if (countSubsets(new int[0], 0) != 1) throw new AssertionError("empty");
        // random arrays with many repeats and negatives
        Random rnd = new Random(37);
        for (int t = 0; t < 500; t++) {
            int[] a = new int[rnd.nextInt(13)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(5) - 2;
            long target = rnd.nextInt(7) - 3;
            if (countSubsets(a, target) != oracle(a, target)) throw new AssertionError("random " + Arrays.toString(a));
        }
        System.out.println("ok");
    }
}verified
Pattern Recognition

Closest Subsequence Sum

LeetCode 1755

Problem Specification. Given an integer array nums and an integer goal, choose a subsequence of nums, which is any set of positions kept in their original order and possibly empty. Return the minimum possible value of |sum - goal|, where sum is the sum of the chosen elements.

Input Constraints. The limits are:

  • Length of nums is from 1 to 40.
  • Values are integers from -10^7 to 10^7.
  • Goal is an integer from -10^9 to 10^9.

Example 1. Input nums = [4, -3, 8, 1], goal = 10, output 0.

Algorithmic Solution (attempt the problem first)

Approach. A limit of 40 on the length rules out the 2^40 enumeration and rules in two enumerations of 2^20. The order of a subsequence never changes its sum, so the problem is the closest-subset-sum question and position order does not matter. The method splits nums in the middle, lists both half sums, sorts the second list and looks up the complement of every first-half sum by binary search. The answer is the smallest distance. The invariant is that the pair of half sums stands for each subsequence exactly once.

The program compares the method with a mask enumeration on random arrays of length up to 14 with negative values. It also confirms that 40 values of 10^7 stay inside int but that 40 values near 10^9 would not, which is why the lesson sums in long.

Complexity.

  • Time is O(2^(n/2) * n).
  • Space is O(2^(n/2)).
import java.util.Arrays;
import java.util.Random;

public final class ClosestSubsequenceSumRecognize {
    static long[] sums(int[] a, int from, int to) {
        long[] s = new long[1 << (to - from)];
        int size = 1;
        for (int k = from; k < to; k++) {
            for (int j = 0; j < size; j++) s[size + j] = s[j] + a[k];
            size *= 2;
        }
        return s;
    }

    /**
     * Minimum |sum - goal| over all subsequences of nums.
     * Time: O(2^(n/2) * n). Space: O(2^(n/2)).
     * Invariant: each subsequence maps to exactly one pair (first-half sum, second-half sum).
     */
    static int minAbsDifference(int[] nums, int goal) {
        int mid = nums.length / 2;
        long[] left = sums(nums, 0, mid);
        long[] right = sums(nums, mid, nums.length);
        Arrays.sort(right); // required by the lower-bound search
        long best = Long.MAX_VALUE;
        for (long s : left) {
            long need = (long) goal - s; // complement
            int lo = 0, hi = right.length;
            while (lo < hi) {
                int m = (lo + hi) >>> 1;
                if (right[m] < need) lo = m + 1; else hi = m;
            }
            if (lo < right.length) best = Math.min(best, Math.abs(right[lo] - need));
            if (lo > 0) best = Math.min(best, Math.abs(need - right[lo - 1]));
        }
        return (int) best; // the answer is at most |goal| + 40 * 10^7, which fits in int
    }

    static int oracle(int[] a, int goal) {
        long best = Long.MAX_VALUE;
        for (int mask = 0; mask < (1 << a.length); mask++) {
            long sum = 0;
            for (int k = 0; k < a.length; k++) if ((mask >> k & 1) == 1) sum += a[k];
            best = Math.min(best, Math.abs(sum - goal));
        }
        return (int) best;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (minAbsDifference(new int[]{4, -3, 8, 1}, 10) != 0) throw new AssertionError("ex1");
        if (minAbsDifference(new int[]{3, 8}, -20) != 20) throw new AssertionError("ex2");
        // 40 values of 10^7 fit in int, while 40 values of 10^9 would not
        long small = 40L * 10_000_000, big = 40L * 1_000_000_000;
        if (small > Integer.MAX_VALUE || big <= Integer.MAX_VALUE) throw new AssertionError("range claim");
        // random arrays with negative values and goals on both sides
        Random rnd = new Random(38);
        for (int t = 0; t < 500; t++) {
            int[] a = new int[1 + rnd.nextInt(14)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(61) - 30;
            int goal = rnd.nextInt(301) - 150;
            if (minAbsDifference(a, goal) != oracle(a, goal)) throw new AssertionError("random " + Arrays.toString(a));
        }
        System.out.println("ok");
    }

Problem

A Route Planner That Searches Everywhere

A warehouse robot must drive from a dock to a shelf ten cells away on the same row. The planner uses Dijkstra's algorithm on the floor grid. It finds the right path, but a log of the run shows it visited 111 cells, and most of them lie behind the robot or far to the side. On a floor of a million cells, the same planner visits hundreds of thousands of cells for a trip of thirty steps. The robot waits, and the battery drains while the search wanders.

The planner is correct and wasteful. It has no idea where the shelf is, so it grows a circle of explored cells in every direction. A person with a map would walk toward the shelf first. This lesson asks how to add a sense of direction to the search, and how to do it without ever returning a longer route than Dijkstra's algorithm would.

Simple approach

Expand By Cost From The Start

The direct planner is Dijkstra's algorithm on a grid. Each cell has an entering cost, and 0 marks a wall. A priority queue holds entries (g, row, col), where g is the cost of the best known route from the start. The planner pops the cheapest entry, skips it if a cheaper route to that cell is already known, and pushes the four neighbours with updated costs. It stops when the goal cell pops.

final class GridDijkstra {
    static int shortest(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) java.util.Arrays.fill(row, Integer.MAX_VALUE);
        java.util.PriorityQueue<int[]> pq = new java.util.PriorityQueue<>((x, y) -> x[0] - y[0]);
        best[sr][sc] = 0;
        pq.add(new int[]{0, sr, sc});
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (cur[0] > best[cur[1]][cur[2]]) continue;       // a cheaper route was found later
            if (cur[1] == gr && cur[2] == gc) return cur[0];   // the goal pops with its best cost
            for (int d = 0; d < 4; d++) {
                int nr = cur[1] + dr[d], nc = cur[2] + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                int g = cur[0] + cost[nr][nc];
                if (g < best[nr][nc]) { best[nr][nc] = g; pq.add(new int[]{g, nr, nc}); }
            }
        }
        return -1;                                              // the goal is unreachable
    }
}

The planner is exact, and tests with small floors pass. A tempting repair is to stop the search early at some cost limit, but a limit that is too tight loses valid routes.

Predict first: The floor is open, every enter cost is 1, the start is at column 0, and the goal is 10 cells to the right on the same row. Roughly how many cells does the loop pop before it returns? If the planner could add to each entry a guess of how far the goal still is, which cells would never be popped?

Every cell within cost 9 of the start pops first, which is a diamond of 181 cells, and some cells at cost 10 pop before the goal. The run on a floor of 21 by 21 cells pops 111 cells because the start sits at the edge of the diamond on some sides. Cells that sit above or below the row do not lie on any cheapest route, yet they pop because their cost from the start is small. A guess of the remaining distance would push those entries behind the entries on the row.

Bottleneck

Cost So Far Ignores The Goal

Why The Queue Ignores The Goal

The loop costs O(V log V) time and O(V) space for V cells that can pop. In the open case above, V is the number of cells within the goal's cost from the start, and it grows with the square of the distance. The priority g measures only the past. A cell above the row and a cell on the row have the same g when they are the same number of steps from the start, so the queue treats them the same. The goal is on the row, and only one of them leads there.

What Extra Information Helps

The missing piece is information about the future. For every cell, the planner can cheaply compute a number h that tells how much cost might remain, for example the count of rows and columns between the cell and the goal. Combining g and h into one priority would reorder the queue so that cells headed toward the goal pop first.

Why A Careless Guess Fails

A careless guess breaks the exact answer. If h claims the remaining cost is larger than it truly is, a cheap route can hide behind a cell that the queue ranks too low. The search then pops the goal through a worse route. The repair must say precisely which guesses are allowed.

Key idea

Rank By Cost So Far Plus Guess

The Priority Is g Plus h

A* search keeps Dijkstra's loop and changes one line. The queue orders entries by f = g + h, where g is the cost of the best known route from the start to the cell and h is the heuristic, a guess of the remaining cost from the cell to the goal. With h equal to 0 for every cell, f equals g and the loop is exactly Dijkstra's algorithm.

A Guess That Never Overestimates

A heuristic is admissible when h(v) is at most the true cheapest remaining cost from v to the goal, for every cell v. The Manhattan distance, which is the row difference plus the column difference, is admissible on a grid where every move costs at least 1, because a route needs at least that many moves. The proof that A* then returns an optimal route runs as follows. Suppose the goal pops with cost G, and suppose a cheaper route of cost C < G exists. Some cell n on that route is already in the queue with its best g. Its priority g(n) + h(n) is at most C, by admissibility, so it is less than G. The queue would pop n before the goal, which contradicts the goal popping first with G.

Closing Cells And Rejecting Old Entries

A heuristic is consistent when h(u) <= w(u, v) + h(v) for every move from u to v with entering cost w(u, v). Manhattan distance is consistent on this grid. With a consistent heuristic the priorities along any route never decrease, so the first time a cell pops, its g is final and the planner never reopens it. An admissible heuristic that is not consistent keeps the answer exact only if cells can be reopened.

The queue may hold several entries for one cell, because each improvement of g pushes a new entry. An old entry whose g is larger than the best known value is a stale entry. The planner skips it when it pops. The invariant of the search is that the entry popped with the smallest f never has a larger f than the cost of the optimal route, so the first goal pop is optimal.

State

Cost, Guess And Best Known

The search keeps five pieces of state.

  • best is a matrix with the cheapest known cost from the start to each cell. It starts at a huge value and only decreases.
  • h is the heuristic value of a cell. Here it equals |row - gr| + |col - gc|, the Manhattan distance to the goal cell.
  • f is g + h for an entry. The queue orders entries by f, then by row, then by column, so ties are deterministic.
  • prev is a matrix that stores the cell from which best was reached. It rebuilds the route after the goal pops.
  • expanded is the count of non-stale pops. It measures how much of the floor the search touched.

The entry cost matrix uses 0 for a wall and values from 1 to 9 for open cells. Every move costs at least 1, so each step lowers the Manhattan distance by at most 1 and that distance stays admissible.

A Star On A Cost Grid

The Search

The method keeps the loop of the naive planner. The queue entries hold f, g, row and column, and the comparator breaks f ties by row and then column.

final class AStarGrid {
    static int shortest(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) java.util.Arrays.fill(row, Integer.MAX_VALUE);
        java.util.PriorityQueue<int[]> pq = new java.util.PriorityQueue<>(
            (x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                    : x[2] != y[2] ? Integer.compare(x[2], y[2]) : Integer.compare(x[3], y[3]));
        best[sr][sc] = 0;
        pq.add(new int[]{Math.abs(sr - gr) + Math.abs(sc - gc), 0, sr, sc});
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int r = cur[2], c = cur[3];
            if (cur[1] > best[r][c]) continue;                // stale entry: a cheaper route was recorded
            if (r == gr && c == gc) return cur[1];            // first goal pop is optimal
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                int g = cur[1] + cost[nr][nc];                 // cost so far of the neighbour
                if (g < best[nr][nc]) {
                    best[nr][nc] = g;
                    int h = Math.abs(nr - gr) + Math.abs(nc - gc);   // admissible guess
                    pq.add(new int[]{g + h, g, nr, nc});
                }
            }
        }
        return -1;
    }
}

Cost

  • Time is O(V log V) in the worst case, the same bound as Dijkstra, with V the count of cells.
  • Space is O(V) for best and the queue.
  • Expansions shrink in most inputs against Dijkstra's, because every cell with g + h above the optimal cost stays in the queue.
When to use it

When A Star Applies

Recognizing The Pattern

Use A* when a shortest-path search has one goal state, the graph is large, and a cheap lower bound on the remaining cost is available. Grid routing, puzzle solving and map navigation have this shape. Before coding, state the heuristic and check two things: it never exceeds the true remaining cost, and it satisfies h(u) <= w + h(v) on every move. The invariant to keep is that f = g + h never exceeds the cost of the optimal route for the entry that pops.

False Friends

Greedy best-first search ranks by h alone. It looks like A* and runs faster on many inputs, but it can return a long route because it ignores g. Dijkstra's algorithm with an early stop at the goal is another false friend, since it ranks by g alone and gains no direction. Breadth-first search is exact only when all moves cost the same.

When The Method Does Not Apply

If the search needs distances to every cell, as in a map of reachable areas, the heuristic toward one goal helps nothing, and Dijkstra's algorithm is the right tool. If no lower bound better than 0 exists, A* equals Dijkstra and adds only a constant factor. If edge costs can be negative, neither algorithm is valid.

Problem Specification. Write int[] zeroHeuristic(int[][] cost, int sr, int sc, int gr, int gc). The grid cost has entries 0 for a wall and 1 to 9 for an open cell with that entering cost. A move goes to one of four neighbours and pays the entering cost of the target cell. Run the search with h = 0 for every cell. The queue pops the smallest f, then the smallest row, then the smallest column. Return {c, e}. Here c is the cheapest cost from the start to the goal, or -1 if unreachable. The value e is the number of non-stale pops, counting the goal pop, before the method returns.

Input Constraints. The limits are:

  • Grid has 1 to 50 rows and 1 to 50 columns.
  • Cells the start and the goal are open cells.
  • Costs are integers from 0 to 9.
  • Unreachable goals return {-1, e} after the queue is empty.

Example 1. Input cost = [[1,1,1],[1,0,1],[1,1,1]], start (0,0), goal (2,2), output {4, 8}.

Example 2. Input cost = [[1,0,1]], start (0,0), goal (0,2), output {-1, 1}.

Prerequisites. The priority f = g + h and the stale-entry skip from this lesson.

What This Exercise Changes. Basic case: the heuristic is fixed at 0, so the loop is Dijkstra's algorithm with a counter.

Hint

What does f equal when h is 0, and which pops count as stale?

Algorithmic Solution (attempt the problem first)

Approach. With h = 0 the priority f equals g, so the loop is Dijkstra's algorithm. The queue holds entries (f, row, col, g) ordered by f, then row, then column. Each pop first compares the entry's g with best for the cell. A larger g means a cheaper route was recorded after the entry was pushed, so the entry is stale and the loop skips it without counting. Every other pop counts as one expansion. When the goal pops, its g is final, because every entry still in the queue has f at least as large and no entering cost is negative. The method then returns the cost and the count. If the queue empties, the goal is unreachable and the method returns -1 with the count so far. The invariant is that a cell pops non-stale at most once, and its g equals the cheapest cost from the start.

The program checks the cost against a Bellman-Ford style relaxation oracle. It checks the expansion count against a second implementation that keeps entries in a TreeSet, so the order of pops comes from a different structure.

Complexity.

  • Time is O(V log V) for V cells, because each cell enters the queue a bounded number of times and every queue operation costs O(log V).
  • Space is O(V) for best and the queue.
import java.util.Arrays;
import java.util.PriorityQueue;
import java.util.Random;
import java.util.TreeSet;

public final class ZeroHeuristicBuild {
    /**
     * Dijkstra on a cost grid, reported as {cost, nonStalePops}.
     * Time: O(V log V). Space: O(V).
     * Invariant: a non-stale pop carries the final cost of its cell.
     */
    static int[] zeroHeuristic(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE); // no route is known yet
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> {
            if (x[0] != y[0]) return Integer.compare(x[0], y[0]); // smallest f first
            if (x[1] != y[1]) return Integer.compare(x[1], y[1]); // then smallest row
            return Integer.compare(x[2], y[2]);                   // then smallest column
        });
        best[sr][sc] = 0;
        pq.add(new int[]{0, sr, sc, 0});
        int expanded = 0;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) { // each pop either skips a stale entry or finalizes one cell
            int[] cur = pq.poll();
            int r = cur[1], c = cur[2], g = cur[3];
            if (g > best[r][c]) continue;          // stale entry: not counted
            expanded++;                            // one finalized cell
            if (r == gr && c == gc) return new int[]{g, expanded}; // first goal pop is optimal
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue; // wall or outside
                int ng = g + cost[nr][nc];         // cost so far of the neighbour
                if (ng < best[nr][nc]) { best[nr][nc] = ng; pq.add(new int[]{ng, nr, nc, ng}); } // h = 0, so f = g
            }
        }
        return new int[]{-1, expanded};
    }

    static int bellman(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        long[][] dist = new long[R][C];
        for (long[] row : dist) Arrays.fill(row, Long.MAX_VALUE / 4);
        dist[sr][sc] = 0;
        boolean changed = true;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (changed) { // repeated relaxation reaches every shortest distance
            changed = false;
            for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) {
                if (cost[r][c] == 0) continue;
                for (int d = 0; d < 4; d++) {
                    int pr = r + dr[d], pc = c + dc[d];
                    if (pr < 0 || pc < 0 || pr >= R || pc >= C || cost[pr][pc] == 0) continue;
                    if (dist[pr][pc] + cost[r][c] < dist[r][c]) { dist[r][c] = dist[pr][pc] + cost[r][c]; changed = true; }
                }
            }
        }
        return dist[gr][gc] >= Long.MAX_VALUE / 4 ? -1 : (int) dist[gr][gc];
    }

    static int[] treeVersion(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        TreeSet<long[]> set = new TreeSet<>((x, y) -> {
            for (int i = 0; i < 4; i++) if (x[i] != y[i]) return Long.compare(x[i], y[i]);
            return 0;
        });
        best[sr][sc] = 0;
        set.add(new long[]{0, sr, sc, 0});
        int expanded = 0;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!set.isEmpty()) {
            long[] cur = set.pollFirst();
            int r = (int) cur[1], c = (int) cur[2], g = (int) cur[3];
            if (g > best[r][c]) continue;
            expanded++;
            if (r == gr && c == gc) return new int[]{g, expanded};
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                if (g + cost[nr][nc] < best[nr][nc]) { best[nr][nc] = g + cost[nr][nc]; set.add(new long[]{best[nr][nc], nr, nc, best[nr][nc]}); }
            }
        }
        return new int[]{-1, expanded};
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (!Arrays.equals(zeroHeuristic(new int[][]{{1,1,1},{1,0,1},{1,1,1}}, 0, 0, 2, 2), new int[]{4, 8})) throw new AssertionError("ex1");
        if (!Arrays.equals(zeroHeuristic(new int[][]{{1,0,1}}, 0, 0, 0, 2), new int[]{-1, 1})) throw new AssertionError("ex2");
        // random grids: cost against relaxation, expansions against the TreeSet version
        Random rnd = new Random(41);
        for (int t = 0; t < 400; t++) {
            int R = 1 + rnd.nextInt(5), C = 1 + rnd.nextInt(5);
            int[][] g = new int[R][C];
            for (int[] row : g) for (int c = 0; c < C; c++) row[c] = rnd.nextInt(4) == 0 ? 0 : 1 + rnd.nextInt(4);
            g[0][0] = 1; g[R - 1][C - 1] = 1;
            int[] got = zeroHeuristic(g, 0, 0, R - 1, C - 1);
            if (got[0] != bellman(g, 0, 0, R - 1, C - 1)) throw new AssertionError("cost");
            if (!Arrays.equals(got, treeVersion(g, 0, 0, R - 1, C - 1))) throw new AssertionError("expansions");
        }
        System.out.println("ok");
    }

Hint

Why does a cheaper entering cost than 1 never occur, and why does that keep h admissible?

Algorithmic Solution (attempt the problem first)

Approach. The change from the previous exercise is the priority. A pushed entry carries f = g + h, where h is the row difference plus the column difference to the goal. Every open cell costs at least 1 to enter, so a route to the goal needs at least h more cost, and h never overestimates. Moving from u to v changes h by at most 1 and costs at least 1, so h(u) <= w + h(v) holds, and h is consistent. A consistent heuristic makes f non-decreasing along pops, so the first pop of a cell carries its final cost and the first goal pop is optimal. The stale-entry skip and the count stay as before. The invariant is that every popped entry has f no larger than the optimal cost until the goal pops.

The program checks the cost against Bellman-Ford relaxation on random grids and checks the count against a TreeSet implementation. It also confirms the examples show fewer expansions than h = 0 and that the two heuristics give equal costs.

  • Time is O(V log V) in the worst case, the bound of Dijkstra, and it is smaller in practice because cells with a large f stay in the queue.
  • Space is O(V) for best and the queue.
import java.util.Arrays;
import java.util.PriorityQueue;
import java.util.Random;
import java.util.TreeSet;

public final class ManhattanGridVary {
    /**
     * A star with Manhattan distance, reported as {cost, nonStalePops}; weight 0 turns the guess off.
     * Time: O(V log V). Space: O(V).
     * Invariant: popped entries have f no larger than the optimal cost until the goal pops.
     */
    static int[] search(int[][] cost, int sr, int sc, int gr, int gc, int weight) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                : x[1] != y[1] ? Integer.compare(x[1], y[1]) : Integer.compare(x[2], y[2]));
        best[sr][sc] = 0;
        pq.add(new int[]{weight * (Math.abs(sr - gr) + Math.abs(sc - gc)), sr, sc, 0});
        int expanded = 0;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int r = cur[1], c = cur[2], g = cur[3];
            if (g > best[r][c]) continue;            // stale entry
            expanded++;                              // finalized cell
            if (r == gr && c == gc) return new int[]{g, expanded}; // goal pop
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                int ng = g + cost[nr][nc];
                if (ng < best[nr][nc]) {
                    best[nr][nc] = ng;
                    int h = Math.abs(nr - gr) + Math.abs(nc - gc); // Manhattan distance to the goal
                    pq.add(new int[]{ng + weight * h, nr, nc, ng}); // f = g + h
                }
            }
        }
        return new int[]{-1, expanded};
    }

    static int[] manhattan(int[][] cost, int sr, int sc, int gr, int gc) { return search(cost, sr, sc, gr, gc, 1); }

        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        TreeSet<long[]> set = new TreeSet<>((x, y) -> {
            for (int i = 0; i < 4; i++) if (x[i] != y[i]) return Long.compare(x[i], y[i]);
            return 0;
        });
        best[sr][sc] = 0;
        set.add(new long[]{Math.abs(sr - gr) + Math.abs(sc - gc), sr, sc, 0});
        int expanded = 0;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!set.isEmpty()) {
            long[] cur = set.pollFirst();
            int r = (int) cur[1], c = (int) cur[2], g = (int) cur[3];
            if (g > best[r][c]) continue;
            expanded++;

            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;

                if (ng < best[nr][nc]) { best[nr][nc] = ng; set.add(new long[]{ng + Math.abs(nr - gr) + Math.abs(nc - gc), nr, nc, ng}); }
            }
        }
        return new int[]{-1, expanded};
    }

Overestimating Heuristic

Author exercise

Problem Specification. Write int inflated(int[][] cost, int sr, int sc, int gr, int gc, int w). Use the same grid, moves and tie rules, but set h = w * (|row - gr| + |col - gc|) for an integer w >= 1. Skip stale entries as before, never reopen a cell that has been expanded, and return the cost g of the first goal pop, or -1 if the queue empties. The result can be larger than the cheapest cost.

Input Constraints. The limits are:

  • Grid has 1 to 12 rows and 1 to 12 columns.
  • Costs are integers from 0 to 9, and the start and the goal are open.
  • Weight w is from 1 to 10.
  • Closed cells are never reopened, even if a cheaper route to them appears later.

Example 1. Input cost = [[1,1,1,2],[0,1,0,1],[0,1,1,1]], start (0,0), goal (2,3), w = 1, output 5.

Example 2. The same input with w = 4 outputs 6, which is larger than the cheapest cost.

Prerequisites. The Manhattan Grid Heuristic exercise above. This exercise changes the guess from admissible to inflated.

What This Exercise Changes. The guess is allowed to exceed the true remaining cost, and the exercise shows the answer stops being optimal.

Hint

Which cell gets popped first when the guess dominates the cost so far, and what does that cell commit to?

Algorithmic Solution (attempt the problem first)

Approach. The method multiplies the Manhattan distance by w. For w = 1 the guess is admissible and consistent, so the first goal pop is optimal. For w above 1 the guess can exceed the true remaining cost. In the second example the guess at the top row route is large relative to the cost so far, so the planner follows the cell with the smallest h and pops the goal through the route that enters the cost-2 cell. The goal pops with g = 6 while a route of cost 5 exists through the middle column. The queue never ranks the cheaper route first, because the entry on that route has a larger f. Closed cells are never reopened here, which matches the problem text, so a later cheaper route to a closed cell cannot repair the result. The invariant that failed is "every queue entry has f at most the optimal cost".

The program runs both examples, compares every weight against a TreeSet implementation on random grids, and checks two facts. The result for w = 1 always equals the true cost, and the result for every w is never below the true cost. A search over random grids confirms that inflated weights do overshoot on some inputs.

Complexity.

  • Time is O(V log V), because the loop is the same as before.
  • Space is O(V).
import java.util.Arrays;
import java.util.PriorityQueue;
import java.util.Random;
import java.util.TreeSet;

public final class OverestimatingHeuristicBoundary {
    /**
     * First goal pop of the weighted search, or -1.
     * Time: O(V log V). Space: O(V).
     * Invariant for w = 1 only: every queued entry has f at most the optimal cost.
     */
    static int inflated(int[][] cost, int sr, int sc, int gr, int gc, int w) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        boolean[][] closed = new boolean[R][C];
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                : x[1] != y[1] ? Integer.compare(x[1], y[1]) : Integer.compare(x[2], y[2]));
        best[sr][sc] = 0;
        pq.add(new int[]{w * (Math.abs(sr - gr) + Math.abs(sc - gc)), sr, sc, 0});
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int r = cur[1], c = cur[2], g = cur[3];
            if (g > best[r][c] || closed[r][c]) continue; // stale or already expanded
            closed[r][c] = true;                          // closed cells are never reopened
            if (r == gr && c == gc) return g;             // with w > 1 this g can exceed the optimum
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0 || closed[nr][nc]) continue;
                int ng = g + cost[nr][nc];
                if (ng < best[nr][nc]) {
                    best[nr][nc] = ng;
                    pq.add(new int[]{ng + w * (Math.abs(nr - gr) + Math.abs(nc - gc)), nr, nc, ng});
                }
            }
        }
        return -1;
    }

    static int viaTree(int[][] cost, int sr, int sc, int gr, int gc, int w) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        boolean[][] closed = new boolean[R][C];
        TreeSet<long[]> set = new TreeSet<>((x, y) -> {
            for (int i = 0; i < 4; i++) if (x[i] != y[i]) return Long.compare(x[i], y[i]);
            return 0;
        });
        best[sr][sc] = 0;
        set.add(new long[]{(long) w * (Math.abs(sr - gr) + Math.abs(sc - gc)), sr, sc, 0});
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!set.isEmpty()) {
            long[] cur = set.pollFirst();
            int r = (int) cur[1], c = (int) cur[2], g = (int) cur[3];
            if (g > best[r][c] || closed[r][c]) continue;
            closed[r][c] = true;
            if (r == gr && c == gc) return g;
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0 || closed[nr][nc]) continue;
                if (g + cost[nr][nc] < best[nr][nc]) {
                    best[nr][nc] = g + cost[nr][nc];
                    set.add(new long[]{best[nr][nc] + (long) w * (Math.abs(nr - gr) + Math.abs(nc - gc)), nr, nc, best[nr][nc]});
                }
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        int[][] ex = {{1,1,1,2},{0,1,0,1},{0,1,1,1}};
        // the two examples from the problem text
        if (inflated(ex, 0, 0, 2, 3, 1) != 5) throw new AssertionError("ex1");
        if (inflated(ex, 0, 0, 2, 3, 4) != 6) throw new AssertionError("ex2");
        // random grids: w = 1 is optimal, every weight is at least the optimum, and the TreeSet version agrees
        Random rnd = new Random(43);
        int overshoots = 0;
        for (int t = 0; t < 600; t++) {
            int R = 1 + rnd.nextInt(5), C = 1 + rnd.nextInt(5);
            int[][] g = new int[R][C];
            for (int[] row : g) for (int c = 0; c < C; c++) row[c] = rnd.nextInt(4) == 0 ? 0 : 1 + rnd.nextInt(5);
            g[0][0] = 1; g[R - 1][C - 1] = 1;
            int opt = inflated(g, 0, 0, R - 1, C - 1, 1);
            for (int w = 1; w <= 6; w++) {
                int got = inflated(g, 0, 0, R - 1, C - 1, w);
                if (got != viaTree(g, 0, 0, R - 1, C - 1, w)) throw new AssertionError("oracle");
                if ((got == -1) != (opt == -1) || (opt != -1 && got < opt)) throw new AssertionError("below optimum");
                if (got > opt) overshoots++;
            }
        }
        if (overshoots == 0) throw new AssertionError("no overshoot found");
        System.out.println("ok");
    }

A-Star Grid Path

Author exercise

Problem Specification. Write List<int[]> route(int[][] cost, int sr, int sc, int gr, int gc). Use the Manhattan heuristic, the tie rule and the move rules from the previous exercises. Store for each cell the predecessor that gave its best known cost, and replace it only when a strictly cheaper cost appears. Neighbours are tried in the order up, down, left, right. Return the cells of the route from the start to the goal inclusive, or an empty list if the goal is unreachable.

Input Constraints. The limits are:

  • Grid has 1 to 100 rows and 1 to 100 columns.
  • Costs are integers from 0 to 9, with 0 for a wall.
  • Start and goal are open cells and may be the same cell.
  • Route consecutive cells are neighbours, and its cost is the entering cost of every cell except the start.

Example 1. Input cost = [[1,1,1,2],[0,1,0,1],[0,1,1,1]], start (0,0), goal (2,3), output [(0,0),(0,1),(1,1),(2,1),(2,2),(2,3)].

Example 2. Input cost = [[7]], start (0,0), goal (0,0), output [(0,0)].

Prerequisites. The Overestimating Heuristic exercise above. This exercise returns the route, not only its cost.

What This Exercise Changes. The state grows by one matrix of predecessors, and the stale-entry rule must keep that matrix in step with best.

Hint

State the heuristic and check admissibility before coding. Then ask what must be recorded when a stale entry pops.

Algorithmic Solution (attempt the problem first)

Approach. The heuristic is the Manhattan distance, which is admissible because every move costs at least 1 and consistent because one move changes the distance by at most 1. The method keeps best and a predecessor matrix. When a neighbour gets a strictly cheaper cost, the method stores the current cell as its predecessor and pushes a new entry. The strict comparison fixes the choice among equal routes, since the first cheapest predecessor found stays. A stale entry carries a g above best, so the method skips it before it touches any neighbour. That skip protects the predecessor matrix, because a stale expansion could push entries based on an outdated cost. When the goal pops, the method follows predecessors back to the start and reverses the list. The invariant is that prev[v] is the cell that produced best[v].

The program checks that the returned route starts and ends at the right cells, that consecutive cells are neighbours, that the route cost equals the Bellman-Ford optimum, and that the example route matches. It also checks the single-cell case and unreachable goals.

Complexity.

  • Time is O(V log V) for the search plus O(V) to rebuild the route.
  • Space is O(V) for best, the predecessor matrix and the queue.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Random;

public final class GridPathRecognize {
    /**
     * Cheapest route from start to goal as a list of cells, or an empty list.
     * Time: O(V log V). Space: O(V).
     * Invariant: prev[v] is the cell that produced best[v], and best only decreases.
     */
    static List<int[]> route(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        int[][] prev = new int[R][C];
        for (int i = 0; i < R; i++) { Arrays.fill(best[i], Integer.MAX_VALUE); Arrays.fill(prev[i], -1); }
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                : x[1] != y[1] ? Integer.compare(x[1], y[1]) : Integer.compare(x[2], y[2]));
        best[sr][sc] = 0;
        pq.add(new int[]{Math.abs(sr - gr) + Math.abs(sc - gc), sr, sc, 0});
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1}; // up, down, left, right
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int r = cur[1], c = cur[2], g = cur[3];
            if (g > best[r][c]) continue; // stale entry: its predecessor choice is outdated
            if (r == gr && c == gc) {
                List<int[]> path = new ArrayList<>();
                for (int at = r * C + c; at != -1; at = prev[at / C][at % C]) path.add(new int[]{at / C, at % C}); // walk predecessors
                Collections.reverse(path); // start first
                return path;
            }
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                int ng = g + cost[nr][nc];
                if (ng < best[nr][nc]) { // strictly cheaper only, so equal routes keep the first predecessor
                    best[nr][nc] = ng;
                    prev[nr][nc] = r * C + c;
                    pq.add(new int[]{ng + Math.abs(nr - gr) + Math.abs(nc - gc), nr, nc, ng});
                }
            }
        }
        return new ArrayList<>();
    }

    static int optimum(int[][] cost, int sr, int sc, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        long INF = Long.MAX_VALUE / 4;
        long[][] dist = new long[R][C];
        for (long[] row : dist) Arrays.fill(row, INF);
        dist[sr][sc] = 0;
        boolean changed = true;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (changed) {
            changed = false;
            for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) if (cost[r][c] != 0)
                for (int d = 0; d < 4; d++) {
                    int pr = r + dr[d], pc = c + dc[d];
                    if (pr < 0 || pc < 0 || pr >= R || pc >= C || cost[pr][pc] == 0 || dist[pr][pc] >= INF) continue;
                    if (dist[pr][pc] + cost[r][c] < dist[r][c]) { dist[r][c] = dist[pr][pc] + cost[r][c]; changed = true; }
                }
        }
        return dist[gr][gc] >= INF ? -1 : (int) dist[gr][gc];
    }

    public static void main(String[] args) {
        int[][] ex = {{1,1,1,2},{0,1,0,1},{0,1,1,1}};
        // the two examples from the problem text
        int[][] want = {{0,0},{0,1},{1,1},{2,1},{2,2},{2,3}};
        List<int[]> got = route(ex, 0, 0, 2, 3);
        if (got.size() != want.length) throw new AssertionError("ex1 length");
        for (int i = 0; i < want.length; i++) if (!Arrays.equals(got.get(i), want[i])) throw new AssertionError("ex1 cell " + i);
        List<int[]> single = route(new int[][]{{7}}, 0, 0, 0, 0);
        if (single.size() != 1 || single.get(0)[0] != 0 || single.get(0)[1] != 0) throw new AssertionError("ex2");
        // an unreachable goal gives an empty list
        if (!route(new int[][]{{1,0,1}}, 0, 0, 0, 2).isEmpty()) throw new AssertionError("unreachable");
        // random grids: valid neighbour steps and optimal route cost
        Random rnd = new Random(44);
        for (int t = 0; t < 500; t++) {
            int R = 1 + rnd.nextInt(6), C = 1 + rnd.nextInt(6);
            int[][] g = new int[R][C];
            for (int[] row : g) for (int c = 0; c < C; c++) row[c] = rnd.nextInt(4) == 0 ? 0 : 1 + rnd.nextInt(6);
            g[0][0] = 1; g[R - 1][C - 1] = 1;
            List<int[]> p = route(g, 0, 0, R - 1, C - 1);
            int opt = optimum(g, 0, 0, R - 1, C - 1);
            if (opt == -1) { if (!p.isEmpty()) throw new AssertionError("should be empty"); continue; }
            if (p.get(0)[0] != 0 || p.get(0)[1] != 0 || p.get(p.size() - 1)[0] != R - 1 || p.get(p.size() - 1)[1] != C - 1) throw new AssertionError("ends");
            int total = 0;
            for (int i = 1; i < p.size(); i++) {
                int[] a = p.get(i - 1), b = p.get(i);
                if (Math.abs(a[0] - b[0]) + Math.abs(a[1] - b[1]) != 1 || g[b[0]][b[1]] == 0) throw new AssertionError("step");

            }
            if (total != opt) throw new AssertionError("route cost " + total + " vs " + opt);
        }
        System.out.println("ok");
    }

Problem

One Random Line From A Pipe

A support dashboard shows one random request from today's traffic so engineers can spot odd cases. The traffic arrives as a log stream, one line at a time, and nobody knows in advance how many lines arrive. By the evening the stream holds a billion lines of about 100 bytes each. A first version collects every line into a list and then picks a random position. It works on a developer laptop. On the real stream it needs about 100 GB of memory and the program dies before the dashboard refreshes.

Two facts make the task hard. The program sees each line once and cannot go back, and it cannot hold the stream. Yet the line on display must be fair. A line from the first minute and a line from the last minute must have exactly the same chance of being chosen. The question of this lesson is whether a program can keep one line, or a handful, while still being fair at every moment the stream stops.

Simple approach

Store Everything, Then Pick

The direct design appends each item to a list and picks a random position when asked. A source of randomness is passed in as a LongUnaryOperator called pick, so tests can script it. A call pick.applyAsLong(b) returns an integer from 0 to b - 1.

final class StoreAllSampler {
    private final java.util.ArrayList<Integer> all = new java.util.ArrayList<>();
    private final java.util.function.LongUnaryOperator pick;

    StoreAllSampler(java.util.function.LongUnaryOperator pick) { this.pick = pick; }

    void add(int value) { all.add(value); }              // every item stays in memory

    int sample() {
        if (all.isEmpty()) throw new java.util.NoSuchElementException();
        return all.get((int) pick.applyAsLong(all.size()));   // fair, because every position is equally likely
    }
}

The class is fair and short. Its cost grows with the stream. A second idea keeps only one item and flips a coin for each new item: with probability one half the new item replaces the held one. That uses constant memory, so it deserves a test.

Predict first: The coin rule runs on a stream of 4 items. Each new item replaces the held item with probability 1/2. What is the probability that the first item is the one held at the end? What is that probability for the last item? Is the rule fair?

The first item stays only if the three later coins all come up "keep", which has probability (1/2)^3 = 1/8. The last item is held if its own coin says "replace", which has probability 1/2. The probabilities for the four items are 1/8, 1/8, 1/4 and 1/2. They are not equal, so the rule is not fair.

Bottleneck

Memory Grows, Coins Skew

Memory Grows With The Stream

The store-all design takes O(n) space for a stream of n items, and n has no upper limit. The sampling step costs O(1) time, so the bottleneck is memory alone. For a billion lines the list does not fit, and a stream that never ends has no moment at which it is allowed to be picked from.

Why The Fixed Coin Skews

The coin rule shows what a repair has to fix. A fair rule treats every item that has arrived the same way, and a fixed coin cannot. The first item is exposed to many coins, one for each later item. The last item faces only its own. The more items have arrived, the less likely each newer item should be to replace the held one, because there are more earlier items that also deserve their fair share.

What A Fix Needs

A fix therefore needs a replacement chance that depends on how many items have arrived. The chance for the third item must differ from the chance for the thousandth. The program needs a counter, one held item, and a rule that makes every item equally likely whenever the stream stops. Memory of one item and one counter is O(1) and does not depend on n.

Key idea

Replace With Chance One Over t

The Rule For One Item

The reservoir is the small array that holds the current sample. For a sample of one item, the reservoir has one slot. The first item always enters. When item number t arrives, with t counting from 1, the program makes a replacement draw: it asks for an integer from 0 to t - 1. It replaces the held item with the new one only when the result is 0. The chance of replacement is 1 / t, so item 2 replaces with chance one half, item 3 with chance one third, and item 1000 with chance one in a thousand.

Why The Chances Come Out Equal

The inclusion probability of an item is the chance that it sits in the reservoir when the stream stops. The claim is that after t items every one of them has inclusion probability 1 / t. The proof is by induction. After one item the claim holds, since the only item is held. Suppose it holds after t - 1 items. Item t is held after its own draw with probability 1 / t. An older item was held with probability 1 / (t - 1), and it stays when the new draw says "keep", which has probability (t - 1) / t. The product is (1 / (t - 1)) * ((t - 1) / t) = 1 / t. All t items now have the same inclusion probability.

A Reservoir Of k Items

For a sample of k items, the first k items fill the reservoir. When item t arrives with t > k, the replacement draw asks for an integer j from 0 to t - 1. If j < k, the new item overwrites slot j, and otherwise it is dropped. The new item enters with probability k / t. A specific held item is overwritten with probability (k / t) * (1 / k) = 1 / t. An older item with inclusion probability k / (t - 1) therefore keeps k / (t - 1) * (1 - 1 / t) = k / t. Every item has inclusion probability k / t after t items.

The invariant is that after every arrival, each item seen so far has inclusion probability k / t, and the reservoir stores at most k items.

State

Counter, Slot And Draw Bound

The code for one item keeps three names, and the code for k items adds one.

  • seen is the count t of items that have arrived, stored as a long because a stream can pass two billion items.
  • held is the item currently in the reservoir. It changes only when the replacement draw returns 0.
  • pick is the injected source of randomness. A call with bound b returns an integer from 0 to b - 1.
  • reservoir is the array of at most k held items, used for the larger sample. Its slot j changes only when the draw j is below k.

The counter increases before the draw, so the draw bound is the new count. The first item makes no draw in the code, since its replacement chance is 1.

Walkthrough

Tracing Two Streams

A Sample Of One

The first trace feeds the stream A B C D E to the one-item rule with scripted draws. The pointer t marks the item that arrives. Item A enters without a draw. Item B draws from bound 2 and gets 1, so A stays. Item C draws from bound 3 and gets 0, so C replaces A. Item D draws from bound 4 and gets 2, so C stays. Item E draws from bound 5 and gets 0, so E replaces C. The final sample is E. The note of each step names the bound, the draw and the chance of replacement.

A Sample Of Two

The second trace uses a reservoir of two slots on the stream P Q R S T U. The first two items fill slots 0 and 1. Item R draws from bound 3 and gets 2, which is not below 2, so R is dropped. Item S draws from bound 4 and gets 1, so S overwrites slot 1. Item T draws from bound 5 and gets 0, so T overwrites slot 0. Item U draws from bound 6 and gets 4, so U is dropped. The reservoir ends as T S.

Code

One Pass With Constant Memory

The Two Samplers

The first method keeps one item and a counter. The second method keeps an array of k slots. Both read the input once and never store more than k items.

final class Reservoir {
    static int sampleOne(int[] stream, java.util.function.LongUnaryOperator pick) {
        if (stream.length == 0) throw new java.util.NoSuchElementException();
        int held = stream[0];                                  // item 1 always enters
        long seen = 1;
        for (int i = 1; i < stream.length; i++) {
            seen++;                                            // seen is now t
            if (pick.applyAsLong(seen) == 0) held = stream[i]; // replace with chance 1/t
        }
        return held;
    }

    static int[] sampleK(int[] stream, int k, java.util.function.LongUnaryOperator pick) {
        int[] reservoir = new int[Math.min(k, stream.length)];
        long seen = 0;
        for (int x : stream) {
            seen++;
            if (seen <= k) { reservoir[(int) seen - 1] = x; continue; }  // the first k items fill the slots
            long j = pick.applyAsLong(seen);                   // 0 to t - 1
            if (j < k) reservoir[(int) j] = x;                 // enters with chance k/t, into a uniform slot
        }
        return reservoir;
    }
}

Cost

  • sampleOne costs O(n) time for one pass and O(1) space.
  • sampleK costs O(n) time and O(k) space.
  • Randomness is one draw per item after the first k.
When to use it

When One Pass Sampling Applies

Recognizing The Pattern

Use this method when items arrive one at a time, the total is unknown or too large to store, and each item must have the same chance of selection. The words "uniformly at random", "stream" and "do not store" are the cue. Before coding, decide the sample size k and what counts as an item, because the counter must count only eligible items. The invariant to protect is that after t eligible items, each has inclusion probability k / t.

False Friends

Picking a random position from a list is a false friend when the list already exists in memory, because direct indexing is simpler and costs O(1) after the length is known. Shuffling the stream is a second false friend: it needs the whole stream. The coin rule with a fixed probability is a third, since its chances skew toward recent items. When the stream length is known at the start, drawing k distinct positions without replacement does the same job.

When The Method Does Not Apply

If items carry different weights, the chance 1 / t is wrong and the next lessons give the right rule. If the sample must be re-drawn many times from the same data, storing the data and sampling by index is faster per query. If the source of randomness is not uniform, the proof above no longer holds.

import java.util.NoSuchElementException;
import java.util.function.LongUnaryOperator;

public final class SampleOneBuild {
    /**
     * Returns the held item after one pass.
     * Time: O(n). Space: O(1).
     * Invariant: after t items each of them is held with chance 1/t.
     */
    static int sampleOne(int[] stream, LongUnaryOperator pick) {
        if (stream.length == 0) throw new NoSuchElementException(); // nothing to sample
        int held = stream[0]; // item 1 enters with chance 1
        long t = 1;
        for (int i = 1; i < stream.length; i++) {
            t++; // t is the number of items that have arrived
            long d = pick.applyAsLong(t); // replacement draw with bound t
            if (d < 0 || d >= t) throw new IllegalStateException("draw out of range");
            if (d == 0) held = stream[i]; // replace with chance 1/t
        }
        return held;
    }

    /** Feeds a fixed list of draws and checks every bound on the way. */
    static final class Script implements LongUnaryOperator {
        final long[] draws; int next = 0;
        Script(long... draws) { this.draws = draws; }
        public long applyAsLong(long bound) {
            long expected = next + 2; // the first draw has bound 2
            if (bound != expected) throw new AssertionError("bound " + bound + " expected " + expected);
            return draws[next++];
        }
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (sampleOne(new int[]{5, 8, 3, 9}, new Script(1, 0, 2)) != 3) throw new AssertionError("ex1");
        if (sampleOne(new int[]{7}, new Script()) != 7) throw new AssertionError("ex2");
        // an empty stream throws
        boolean threw = false;
        try { sampleOne(new int[0], new Script()); } catch (NoSuchElementException e) { threw = true; }
        if (!threw) throw new AssertionError("empty");
        // exact fairness: enumerate every draw sequence and count how often each position is held
        for (int n = 1; n <= 6; n++) {
            int[] stream = new int[n];
            for (int i = 0; i < n; i++) stream[i] = i; // distinct values identify positions
            long[] counts = new long[n];
            long[] draws = new long[Math.max(0, n - 1)];
            while (true) {
                counts[sampleOne(stream, new Script(draws.clone()))]++;
                int pos = 0; // odometer: draw k has bound k + 2
                while (pos < draws.length && ++draws[pos] == pos + 2) draws[pos++] = 0;
                if (pos == draws.length) break;
            }
            long fact = 1;
            for (int i = 2; i < n; i++) fact *= i; // (n - 1)!
            for (long c : counts) if (c != fact) throw new AssertionError("unfair at n=" + n);
        }
        System.out.println("ok");
    }

import java.util.function.LongUnaryOperator;

public final class LinkedListRandomNodeVary {
    static final class ListNode {
        int val; ListNode next;
        ListNode(int val, ListNode next) { this.val = val; this.next = next; }
    }

    /**
     * Returns the value of a uniformly chosen node.
     * Time: O(n). Space: O(1).
     * Invariant: held is the value of a node chosen uniformly among the t nodes read so far.
     */
    static int randomNode(ListNode head, LongUnaryOperator pick) {
        int held = head.val; // the first node is the sample so far
        long t = 1;
        for (ListNode cur = head.next; cur != null; cur = cur.next) {
            t++; // one more node has been read
            if (pick.applyAsLong(t) == 0) held = cur.val; // chance 1/t to take this node
        }
        return held;
    }

    static ListNode build(int... vals) {
        ListNode head = null;
        for (int i = vals.length - 1; i >= 0; i--) head = new ListNode(vals[i], head);
        return head;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] d1 = {0, 0};
        int[] at1 = {0};
        if (randomNode(build(1, 2, 3), b -> d1[at1[0]++]) != 3) throw new AssertionError("ex1");
        if (randomNode(build(4, 5), b -> 1) != 4) throw new AssertionError("ex2");
        // exact fairness: every node is returned in exactly (n - 1)! of the n! draw sequences
        for (int n = 1; n <= 6; n++) {
            int[] vals = new int[n];
            for (int i = 0; i < n; i++) vals[i] = 100 + i;
            ListNode head = build(vals);
            long[] counts = new long[n];
            long[] draws = new long[Math.max(0, n - 1)];
            while (true) {
                final long[] copy = draws.clone();
                final int[] at = {0};
                counts[randomNode(head, b -> copy[at[0]++]) - 100]++;
                int pos = 0;
                while (pos < draws.length && ++draws[pos] == pos + 2) draws[pos++] = 0; // odometer with bound pos + 2
                if (pos == draws.length) break;
            }
            long fact = 1;
            for (int i = 2; i < n; i++) fact *= i;
            for (long c : counts) if (c != fact) throw new AssertionError("unfair at n=" + n);
            // the walk must leave the list unchanged
            ListNode cur = head;
            for (int i = 0; i < n; i++, cur = cur.next) if (cur.val != 100 + i) throw new AssertionError("list changed");
        }
        System.out.println("ok");
    }

First K Items And Short Stream

Author exercise

Problem Specification. Write int[] sampleK(int[] stream, int k, LongUnaryOperator pick). The first min(k, n) items fill slots 0 onward in arrival order. For each item t with t > k, the method calls pick.applyAsLong(t) once. If the result j is below k, the method stores the new item in slot j. The method returns the slots as an array whose length is min(k, n).

Input Constraints. The limits are:

  • Length n of stream is from 0 to 10^5.
  • Sample size k is from 1 to 10^5, and k may exceed n.
  • Draws happen only for items with t > k, with the bound t.
  • Result is a new array, and an empty stream returns an empty array.

Example 1. Input stream = [10, 20, 30, 40, 50], k = 2, scripted draws 0, 3, 1 for the bounds 3, 4 and 5, output [30, 50].

Example 2. Input stream = [9, 8], k = 5, no draws, output [9, 8].

Prerequisites. The Linked List Random Node exercise above. This exercise grows the sample from one item to k items.

What This Exercise Changes. The reservoir holds k items, and the code must handle the fill phase and a stream shorter than k.

Hint

What should the result contain when the stream ends before the reservoir is full?

Algorithmic Solution (attempt the problem first)

Approach. The result array has length min(k, n), which covers a stream shorter than k without a special case. The first min(k, n) items go into slots 0 onward in arrival order. For each later item number t the method draws j from bound t. When j < k the item overwrites slot j. The new item is kept with chance k / t. A specific held item is overwritten with chance (k / t) * (1 / k) = 1 / t, so an item held with chance k / (t - 1) keeps k / t. The invariant is that after t items every item seen is in the reservoir with chance k / t (or with chance 1 when t <= k).

The program enumerates every sequence of draws for stream lengths up to 6 and every k up to 7. For each case, every position must appear in the final reservoir in exactly k * n! / (k! * n) sequences when n >= k, and in every sequence when n < k. It also checks the two examples and the empty stream.

Complexity.

  • Time is O(n) for one pass.
  • Space is O(k) for the reservoir, and O(1) beyond it.
import java.util.Arrays;
import java.util.function.LongUnaryOperator;

public final class FirstKShortStreamBoundary {
    /**
     * Returns the reservoir after one pass.
     * Time: O(n). Space: O(min(k, n)).
     * Invariant: after t items each item is in the reservoir with chance min(1, k/t).
     */
    static int[] sampleK(int[] stream, int k, LongUnaryOperator pick) {
        int[] slots = new int[Math.min(k, stream.length)]; // a short stream gives a short result
        for (int i = 0; i < stream.length; i++) {
            long t = i + 1L; // number of items that have arrived
            if (t <= k) { slots[i] = stream[i]; continue; } // fill phase: no draw
            long j = pick.applyAsLong(t); // 0 to t - 1
            if (j < k) slots[(int) j] = stream[i]; // enters with chance k/t into slot j
        }
        return slots;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] d = {0, 3, 1};
        int[] at = {0};
        if (!Arrays.equals(sampleK(new int[]{10, 20, 30, 40, 50}, 2, b -> d[at[0]++]), new int[]{30, 50})) throw new AssertionError("ex1");
        if (!Arrays.equals(sampleK(new int[]{9, 8}, 5, b -> { throw new AssertionError("no draw"); }), new int[]{9, 8})) throw new AssertionError("ex2");
        // an empty stream gives an empty array
        if (sampleK(new int[0], 3, b -> 0).length != 0) throw new AssertionError("empty");
        // exact fairness over every draw sequence: counts per position are equal
        for (int n = 1; n <= 6; n++) for (int kk = 1; kk <= 7; kk++) {
            final int k = kk; // effectively final copy for the lambda
            int[] stream = new int[n];
            for (int i = 0; i < n; i++) stream[i] = i;
            int draws = Math.max(0, n - k); // draws exist for items k + 1 .. n
            long[] seq = new long[draws];
            long[] counts = new long[n];
            long total = 0;
            while (true) {
                final long[] copy = seq.clone();
                final int[] cursor = {0};
                int[] res = sampleK(stream, k, b -> {
                    long expectedBound = k + 1 + cursor[0];
                    if (b != expectedBound) throw new AssertionError("bound");
                    return copy[cursor[0]++];
                });
                for (int v : res) counts[v]++;
                total++;
                int pos = 0; // odometer: draw index p has bound k + 1 + p
                while (pos < draws && ++seq[pos] == k + 1 + pos) seq[pos++] = 0;
                if (pos == draws) break;
            }
            // each position must be present in k/n of the sequences (all of them when n <= k)
            long expected = n <= k ? total : total * k / n;
            if (n > k && (total * k) % n != 0) throw new AssertionError("not divisible");
            for (long c : counts) if (c != expected) throw new AssertionError("unfair n=" + n + " k=" + k);
        }
        System.out.println("ok");
    }

Hint

What count should the replacement chance use when only some positions are eligible?

Algorithmic Solution (attempt the problem first)

Approach. Only positions with nums[i] == target count as items, so the counter m counts matches. The first match is taken without a draw. For the m-th match, the method calls pick with bound m and replaces the stored index when the result is 0. A draw bound based on the array position would give early matches too little weight, because the position grows even when no match arrives. The method stores one index and one counter, so it needs no list of indices. The proof is the reservoir proof applied to the subsequence of matches. The invariant is that after m matches, each of them is the stored index with chance 1 / m.

  • Space is O(1), because the method stores one index and one counter.
import java.util.ArrayList;
import java.util.List;
import java.util.function.LongUnaryOperator;

public final class RandomPickIndexRecognize {
    /**
     * Returns a uniformly chosen index among the positions equal to target.
     * Time: O(n). Space: O(1).
     * Invariant: after m matches the stored index is each of them with chance 1/m.
     */
    static int pickIndex(int[] nums, int target, LongUnaryOperator pick) {
        int chosen = -1;
        long m = 0; // count of matches so far
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != target) continue; // only matches are items
            m++;
            if (m == 1 || pick.applyAsLong(m) == 0) chosen = i; // first match enters, later ones with chance 1/m
        }
        return chosen;
    }

    /** The biased variant that uses the array position as the bound. */
    static int biased(int[] nums, int target, LongUnaryOperator pick) {
        int chosen = -1;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != target) continue;
            if (chosen == -1 || pick.applyAsLong(i + 1) == 0) chosen = i;
        }
        return chosen;
    }

    interface Picker { int run(int[] nums, int target, LongUnaryOperator p); }

    /** Counts results over all draw sequences, where the sequence length is the number of draws used. */
    static long[] histogram(Picker f, int[] nums, int target, long[] bounds) {
        long[] counts = new long[nums.length];
        long[] seq = new long[bounds.length];
        while (true) {
            final long[] copy = seq.clone();
            final int[] at = {0};
            counts[f.run(nums, target, b -> copy[at[0]++])]++;
            int pos = 0;
            while (pos < seq.length && ++seq[pos] == bounds[pos]) seq[pos++] = 0;
            if (pos == seq.length) break;
        }
        return counts;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] d = {1, 0};
        int[] at = {0};
        if (pickIndex(new int[]{1, 2, 3, 3, 3}, 3, b -> d[at[0]++]) != 4) throw new AssertionError("ex1");
        if (pickIndex(new int[]{5, 5}, 5, b -> 0) != 1) throw new AssertionError("ex2");
        // exact fairness on arrays with gaps between matches
        int[][] cases = {{3, 1, 3, 2, 3}, {2, 3, 3, 1, 3, 3, 0}, {4, 4, 4, 4}, {1, 7, 2}};
        for (int[] nums : cases) {
            int target = nums[0] == 4 ? 4 : (nums.length == 3 ? 7 : 3);
            List<Integer> matches = new ArrayList<>();
            for (int i = 0; i < nums.length; i++) if (nums[i] == target) matches.add(i);
            long[] bounds = new long[matches.size() - 1];
            for (int i = 0; i < bounds.length; i++) bounds[i] = i + 2; // the m-th match draws from bound m
            long[] counts = histogram(RandomPickIndexRecognize::pickIndex, nums, target, bounds);
            long expected = -1;
            for (int i : matches) { if (expected == -1) expected = counts[i]; if (counts[i] != expected) throw new AssertionError("unfair " + i); }
        }
        // the position-based bound is not fair on {3,1,3,2,3}: matches at 0, 2, 4 draw from bounds 3 and 5
        long[] bad = histogram(RandomPickIndexRecognize::biased, new int[]{3, 1, 3, 2, 3}, 3, new long[]{3, 5});
        if (bad[0] == bad[2] && bad[2] == bad[4]) throw new AssertionError("biased variant looks fair");
        System.out.println("ok");
    }

Problem

Servers With Unequal Capacity

A load balancer sends each incoming request to one of three servers. Server 0 has weight 1, server 1 has weight 3 and server 2 has weight 6, so over many requests server 2 should receive 60 percent of the traffic. A test with these weights passes. In production the weights are capacities measured in requests per hour, and a single weight reaches a billion. The balancer builds a table with one row per unit of weight, and the program runs out of memory while it fills the table.

The task is to choose index i with probability proportional to w[i], using memory that grows with the number of servers and not with the sum of their weights. Each pick must also be fast, because the balancer chooses for every request. The question of this lesson is how a single random number can be mapped to the right server without a table of billions of rows.

Simple approach

One Table Row Per Unit Of Weight

The direct design writes each index into a list w[i] times and picks a random position in the list. A server with weight 6 appears six times, so it is six times as likely as a server with weight 1. The source of randomness is a LongUnaryOperator named pick, where pick.applyAsLong(b) returns an integer from 0 to b - 1.

final class ExpandedPicker {
    private final int[] table;
    private final java.util.function.LongUnaryOperator pick;

    ExpandedPicker(int[] w, java.util.function.LongUnaryOperator pick) {
        int total = 0;
        for (int x : w) total += x;
        table = new int[total];
        int at = 0;
        for (int i = 0; i < w.length; i++)
            for (int c = 0; c < w[i]; c++) table[at++] = i;   // index i appears w[i] times
        this.pick = pick;
    }

    int pickIndex() { return table[(int) pick.applyAsLong(table.length)]; }
}

The class is exact and a pick costs O(1). Its memory is the sum of all weights. A different attempt scans the weights for each pick, which saves memory and spends time.

Predict first: The weights are 2, 5 and 3, so the table has 10 rows numbered 1 to 10 from left to right, with index 0 in rows 1 and 2. Which index does row 7 hold, and which index does row 8 hold? Then suppose there are 10^5 servers and each weight is 10^9. How many rows does the table need?

Rows 1 and 2 hold index 0, rows 3 to 7 hold index 1, and rows 8 to 10 hold index 2. So row 7 holds index 1 and row 8 holds index 2. The boundary falls between rows 7 and 8. With 10^5 weights of 10^9 the table needs 10^14 rows, far more than any machine can store.

Bottleneck

Memory Follows The Weights

The table costs O(W) space for total weight W, and it costs O(W) time to build. The weights are numbers, and a number such as 10^9 needs a few bytes. The table stores it as a billion separate rows. The cost depends on how big the weights are, not on how many servers there are.

The table is also redundant. The rows for one server are consecutive and identical. All the table says about server 1 in the predict example is that its rows start at row 3 and end at row 7. Two numbers per server carry the same information. A pick only needs to know which of these row ranges holds the random row number.

A scan over the weights avoids the table. It adds weights one at a time until the running sum reaches the random number, and the index where it reaches is the answer. That costs O(1) space but O(n) time per pick, and the balancer picks for every request. A faster design keeps the running sums once and finds the right range without re-adding. The structure has to be small, built once, and searchable.

Key idea

Cumulative Sums Mark The Ranges

Each Index Owns A Range Of Tickets

Number the rows of the imaginary table from 1 to W, and call each number a ticket. Index i holds the tickets from P[i-1] + 1 to P[i], where P[i] is the prefix total w[0] + w[1] + ... + w[i] and P[-1] is 0. The range of index i has exactly w[i] tickets. The ranges do not overlap, and together they cover every ticket from 1 to W. The index that holds a ticket is its owner.

A uniform random ticket from 1 to W is owned by index i with probability w[i] / W. This is the required probability, and no table is built. The program stores only the n prefix totals.

Finding The Owner By Binary Search

The prefix totals are non-decreasing, because weights are not negative. The owner of ticket x is the first index i with P[i] >= x. That index satisfies P[i-1] < x <= P[i], so x lies in the range of i. A binary search for the first prefix total that is at least x finds it in O(log n) steps. At the exact boundary x = P[i], the ticket belongs to index i and not to i + 1, because the comparison is "at least".

An index with weight 0 has P[i] = P[i-1]. The search stops at the first index with the value, so it stops before the zero-weight index and that index owns no ticket.

The Cost

Building the prefix totals costs O(n) time and O(n) space. Each pick draws one ticket and searches in O(log n) time. The invariant is that the prefix totals are non-decreasing, the last one is W, and every ticket from 1 to W has exactly one owner.

State

Totals, Tickets And Search Range

The picker keeps four names.

  • prefix is a long array where prefix[i] is the sum of weights 0 to i. It is built once.
  • total is prefix[n - 1], the number of tickets. It is a long, because a sum of 10^5 weights of 10^9 reaches 10^14.
  • ticket is the random number from 1 to total drawn for one pick. It equals pick.applyAsLong(total) + 1.
  • lo and hi bound the binary search. The answer always lies in [lo, hi], and the search ends when lo == hi.

The draw returns 0 to total - 1, so adding 1 makes the ticket start at 1. A ticket of 0 would belong to no range.

Walkthrough

Tracing Two Picks

A Ticket Inside A Range

The first trace uses weights 3 1 4 2, so the prefix totals are 3 4 8 10 and the number of tickets is 10. The ticket is 5. Three pointers track the search: lo and hi mark its ends and mid marks the probe. The search starts with lo at 0 and hi at 3. The middle prefix total, 4 at index 1, is below 5, so lo moves to 2. The next middle value, 8 at index 2, is at least 5, so hi moves to 2. The search ends at index 2. Index 2 owns tickets 5 to 8, so ticket 5 is the first ticket of its range.

A Ticket On The Boundary

The second trace uses the same prefix totals with ticket 4. This ticket equals P[1], the last ticket of index 1. The first middle value is 4, which is at least 4, so hi moves to 1. The next middle value is 3 at index 0, which is below 4, so lo moves to 1. The search ends at index 1. The comparison "at least" gives the boundary ticket to the earlier index.

Code

Picker With Prefix Totals

The Class

The constructor builds the prefix totals as a long array. Each pick draws a ticket and runs a lower-bound search.

final class WeightedPicker {
    private final long[] prefix;
    private final java.util.function.LongUnaryOperator pick;

    WeightedPicker(int[] w, java.util.function.LongUnaryOperator pick) {
        prefix = new long[w.length];
        long run = 0;
        for (int i = 0; i < w.length; i++) { run += w[i]; prefix[i] = run; }   // long arithmetic
        this.pick = pick;
    }

    int pickIndex() {
        long total = prefix[prefix.length - 1];
        long ticket = pick.applyAsLong(total) + 1;           // 1 to total
        int lo = 0, hi = prefix.length - 1;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (prefix[mid] >= ticket) hi = mid; else lo = mid + 1;   // first prefix total >= ticket
        }
        return lo;
    }
}

Cost

  • Constructor costs O(n) time and O(n) space.
  • pickIndex costs O(log n) time and O(1) extra space.
  • Weights may be as large as the int range, because every sum is in a long.
When to use it

When Cumulative Ranges Apply

Recognizing The Pattern

Use this method when each item has a non-negative weight, the chance of an item is its weight divided by the total, and the weights are fixed between picks. Before coding, decide the width of the sums and the policy for zero weights and for a total of zero. The invariant to keep is that the prefix totals are non-decreasing and every ticket has exactly one owner.

False Friends

Reservoir sampling looks related, since both pick at random, but it chooses among items that arrive one at a time with equal chance. A random pick from a sorted array by value is a second false friend: it uses binary search too, but the array holds values, not cumulative weights. A pick by rejection, which draws an index and a number below the maximum weight and keeps the pair when the number is below the weight, is exact but its speed depends on how uneven the weights are.

When The Method Does Not Apply

If weights change between picks, rebuilding the prefix totals costs O(n) per update, and a Fenwick tree is the right structure. If the weights are floating-point numbers, a ticket of exact integer width is not available and the boundaries need a tolerance. If every weight is 0, no item has a chance, and the caller must handle that case.

Mutable Weight Discussion

Author exercise

Problem Specification. Design the class LivePicker with a constructor that receives int[] w and a LongUnaryOperator pick. The method update(int i, int newWeight) sets w[i] to newWeight. The method pickIndex() returns an index with chance proportional to the current weights, using the ticket rule of the previous exercises. Both methods must run in O(log n) time. Static prefix totals cost O(n) per update, so the design keeps a Fenwick tree and finds the owner by descending the tree.

Input Constraints. The limits are:

  • Length of w is from 1 to 10^5.
  • Weights are int values from 0 to 10^9, and the total is positive before every pick.
  • Calls number at most 10^5 per object.
  • Update index i is valid, and the total after an update may be 0 until the next update.

Example 1. Input w = [3, 1, 2] with scripted draw 3, output 1. After update(1, 5) and the scripted draw 3, output 1, and with the scripted draw 8, output 2.

Example 2. Input w = [4] with scripted draw 3, output 0. After update(0, 0) a pick throws IllegalStateException.

Prerequisites. The Large Total And Zero Weight Policy exercise above and the Fenwick tree from the range-query chapter.

What This Exercise Changes. The weights change between picks, so the state becomes a Fenwick tree and the search becomes a descent on it.

Hint

Which update would a prefix array pay for, and what does a Fenwick tree touch instead?

Algorithmic Solution (attempt the problem first)

Approach. Static prefix totals break when a weight changes, because one update shifts every later prefix total and repairing them costs O(n). A Fenwick tree stores partial sums so that a point update touches O(log n) cells and a prefix query reads O(log n) cells. The picker stores the current weights and a Fenwick tree. An update adds the difference newWeight - old along the update path. For a pick, the method draws the ticket and finds the owner by descent: starting from position 0, it tries the largest power-of-two step; if the tree cell at the next position holds less than the remaining ticket, it moves there and subtracts the cell. After the last step, the position is the count of indexes whose prefix is below the ticket, and that count is the owner's zero-based index. A pick with a total of 0 throws IllegalStateException. The invariant is that the tree always equals the Fenwick representation of the current weights, and the descent keeps the remaining ticket positive.

The program applies random updates and picks, and it compares each pick with a scan over a plain weight array. It also runs every draw after the updates and checks that each index appears exactly as often as its weight.

Complexity.

  • Time is O(n) for the constructor with the linear-time build, and O(log n) per update and per pick.
  • Space is O(n) for the tree and the weight copy.
import java.util.Random;
import java.util.function.LongUnaryOperator;

public final class MutableWeightsRecognize {
    static final class LivePicker {
        private final int n;
        private final long[] tree; // 1-based Fenwick tree
        private final int[] w;
        private final LongUnaryOperator pick;
        private long total;

        LivePicker(int[] weights, LongUnaryOperator pick) {
            n = weights.length;
            w = weights.clone();
            tree = new long[n + 1];
            for (int i = 1; i <= n; i++) {
                tree[i] += w[i - 1]; // add the weight of position i
                int parent = i + (i & -i);
                if (parent <= n) tree[parent] += tree[i]; // push the partial sum to its parent
                total += w[i - 1];
            }
            this.pick = pick;
        }

        /** Sets w[i]. Time: O(log n). Space: O(1). */
        void update(int i, int newWeight) {
            long delta = (long) newWeight - w[i]; // change to propagate
            w[i] = newWeight;
            total += delta;
            for (int p = i + 1; p <= n; p += p & -p) tree[p] += delta; // touch O(log n) cells
        }

        /**
         * Returns an index chosen proportionally to the current weights.
         * Time: O(log n). Space: O(1).
         * Invariant: remaining ticket stays positive and pos counts indexes whose prefix is below the ticket.
         */
        int pickIndex() {
            if (total == 0) throw new IllegalStateException("zero total");
            long ticket = pick.applyAsLong(total) + 1; // 1 to total
            int pos = 0;
            for (int step = Integer.highestOneBit(n); step > 0; step >>= 1) { // descend from the largest power of two
                if (pos + step <= n && tree[pos + step] < ticket) { pos += step; ticket -= tree[pos]; }
            }
            return pos; // zero-based index of the owner
        }
    }

    static int scan(int[] w, long ticket) {
        long run = 0;
        for (int i = 0; i < w.length; i++) { run += w[i]; if (run >= ticket) return i; }
        throw new AssertionError("ticket above total");
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] draw = {3};
        LivePicker p = new LivePicker(new int[]{3, 1, 2}, b -> draw[0]);
        if (p.pickIndex() != 1) throw new AssertionError("ex1 before");
        p.update(1, 5);
        if (p.pickIndex() != 1) throw new AssertionError("ex1 after, draw 3");
        draw[0] = 8;
        if (p.pickIndex() != 2) throw new AssertionError("ex1 after, draw 8");
        long[] draw2 = {3};
        LivePicker single = new LivePicker(new int[]{4}, b -> draw2[0]);
        if (single.pickIndex() != 0) throw new AssertionError("ex2");
        single.update(0, 0);
        boolean threw = false;
        try { single.pickIndex(); } catch (IllegalStateException e) { threw = true; }
        if (!threw) throw new AssertionError("zero total");
        // random updates: every possible draw agrees with a scan over the plain weights
        Random rnd = new Random(54);
        for (int t = 0; t < 200; t++) {
            int n = 1 + rnd.nextInt(9);
            int[] w = new int[n];
            for (int i = 0; i < n; i++) w[i] = rnd.nextInt(5);
            long[] d = {0};
            LivePicker lp = new LivePicker(w, b -> d[0]);
            for (int op = 0; op < 12; op++) {
                int i = rnd.nextInt(n), v = rnd.nextInt(6);
                lp.update(i, v);
                w[i] = v;
                long total = 0;
                for (int x : w) total += x;
                if (total == 0) continue;
                long[] counts = new long[n];
                for (long dr = 0; dr < total; dr++) {
                    d[0] = dr;
                    int got = lp.pickIndex();
                    if (got != scan(w, dr + 1)) throw new AssertionError("scan mismatch");
                    counts[got]++;
                }
                for (int j = 0; j < n; j++) if (counts[j] != w[j]) throw new AssertionError("unfair after update");
            }
        }
        System.out.println("ok");
    }

Simple approach

Random Distance And Random Angle

The direct design copies how a circle is described. It draws a distance d uniformly from 0 to the radius and an angle a uniformly from 0 to 2 * pi, then converts to coordinates. The source of randomness is a DoubleSupplier named rand, whose method getAsDouble() returns a number from 0 (included) to 1 (excluded).

final class PolarPicker {
    private final java.util.function.DoubleSupplier rand;

    PolarPicker(java.util.function.DoubleSupplier rand) { this.rand = rand; }

    double[] pointInUnitCircle() {
        double d = rand.getAsDouble();                   // distance from the center, 0 to 1
        double a = 2 * Math.PI * rand.getAsDouble();     // angle, 0 to 2 pi
        return new double[]{d * Math.cos(a), d * Math.sin(a)};
    }
}

The code is short and always returns a point inside the circle. It passes a visual check on a few points, which is why the bug survives review. The designers' plot is the real test.

Predict first: Consider the inner disc with half the radius. What fraction of the circle's area does it cover? What fraction of the drops from PolarPicker land in that inner disc?

The inner disc has radius 1/2, so its area is pi * (1/2)^2 = pi / 4, which is one quarter of the area pi of the full circle. PolarPicker draws the distance uniformly, so half of the drops (distance below 1/2) land in the inner disc. That is twice the fair share. The method puts too many points near the center.

Bottleneck

Equal Distances Are Not Equal Areas

Why The Polar Method Fails

The polar method costs O(1) time and O(1) space, and it is wrong. Its error is in what the uniform distance means. A ring between distance d and d + e has area about 2 * pi * d * e, which grows with d. A uniform distance gives every ring of the same width the same number of points. The ring near the wall has far more area than the ring near the center, so its points are spread thin, and the center is crowded. Fair points need a distance whose chance of falling in a ring is proportional to the ring's area.

An Exact Repair For One Shape

There is an exact repair for the circle. Taking the square root of the uniform number gives a distance with the right chance for every ring. The repair works only because the area of a disc has a formula that can be inverted. For an arena shaped like a ring with a hole, a triangle, or a region given by a test function, no such formula is available. The method has to stay simple, exact, and independent of the shape.

A Method Without A Formula

A tool that needs no formula for the shape would be valuable. The only shape-specific operation it may use is a yes-or-no test: is this point inside the region? The tool needs a source of points that is uniform over some simpler region, where uniform points are easy to produce.

Key idea

Draw From A Square And Reject

A Simple Region Around The Shape

The bounding square of the unit circle is the square with corners at (-1, -1) and (1, 1). Uniform points in it are easy to produce, since the x-coordinate and the y-coordinate are independent. The program sets x = 2u - 1 and y = 2v - 1 for two numbers u and v from the generator. Every patch of the square receives points in proportion to its area.

Keep Only The Points That Pass The Test

The method draws a point from the square and tests x^2 + y^2 <= 1. If the point passes, the method returns it. If not, the method discards it and draws a new one. Why is the returned point uniform over the circle? Take any patch A inside the circle. A draw lands in A with probability area(A) / 4, and a draw is kept with probability pi / 4. The chance that the returned point lies in A is (area(A) / 4) / (pi / 4) = area(A) / pi, which is the patch's share of the circle's area. Rejection removes the part of the square outside the circle and leaves the density in the circle unchanged.

How Many Draws It Takes

The acceptance probability p is the area of the circle divided by the area of the bounding square, here pi / 4, about 0.785. The trials are independent, so the number of trials until the first acceptance follows a geometric law. The expected trials are 1 / p, about 1.27 draws of a pair. The chance that more than m trials are needed is (1 - p)^m, which shrinks fast.

The invariant is that every draw is uniform over the bounding square, the test depends only on the point, and the point returned is therefore uniform over the shape.

State

Draws, Coordinates And Trials

The loop keeps five names.

  • u and v come from rand, and each lies from 0 (included) to 1 (excluded).
  • x and y are 2u - 1 and 2v - 1, so they lie from -1 (included) to 1 (excluded).
  • r2 is x * x + y * y, the squared distance from the center. Comparing squares avoids a square root.
  • trials counts the pairs drawn so far. It starts at 0 and grows by one per pair.
  • accepted is true when r2 <= 1. The loop ends when it becomes true.

The squared distance is compared to 1, which is the squared radius. The comparison uses <=, so a point exactly on the edge counts as inside.

Code

Circle Sampler With A Loop

The Loop

The method draws pairs until one passes the test. It counts the pairs in a local variable so a test can read the trial count.

final class CirclePicker {
    private final java.util.function.DoubleSupplier rand;
    int lastTrials;                                       // trials used by the last call

    CirclePicker(java.util.function.DoubleSupplier rand) { this.rand = rand; }

    double[] pointInUnitCircle() {
        int trials = 0;
        while (true) {
            trials++;
            double x = 2 * rand.getAsDouble() - 1;        // uniform in [-1, 1)
            double y = 2 * rand.getAsDouble() - 1;
            if (x * x + y * y <= 1) {                     // test against the squared radius
                lastTrials = trials;
                return new double[]{x, y};
            }
        }
    }
}

Cost

  • Time is O(1) expected per point, with 4 / pi pairs on average.
  • Worst case has no fixed bound, because a long run of rejections is possible, though its chance falls geometrically.
  • Space is O(1).
When to use it

When Rejection Applies

Recognizing The Pattern

Use this method in three conditions. Uniform points are easy in a larger region. A yes-or-no test decides whether a point lies in the shape. The shape fills a good share of the larger region. The words "uniformly at random in a circle, triangle or range" are the cue. Before coding, compute the acceptance probability and decide whether boundary points count as inside. The invariant to keep is that every draw is uniform over the larger region and the test sees only the drawn point.

False Friends

The polar method with a uniform distance is a false friend: it looks uniform and is not. Clamping a rejected point to the circle edge is a second false friend, because every rejected point would pile onto the boundary. Reusing leftover randomness from rejected draws needs care and a proof, which is why the simple version discards them.

When The Method Does Not Apply

If the shape fills a tiny share of its bounding region, the acceptance probability is small and the expected trials 1 / p grow. A thin ring inside a large square is an example, and an inverse formula or a mapped sampler is faster. If the loop must finish within a fixed number of draws, rejection has no guarantee, and a capped version needs a stated fallback.

import java.util.function.DoubleSupplier;

public final class PointUnitCircleBuild {
    /**
     * Returns a uniform point in the closed unit disc.
     * Time: O(1) expected. Space: O(1).
     * Invariant: every draw is uniform in the square [-1, 1)^2 and the test depends on the point only.
     */
    static double[] pointInUnitCircle(DoubleSupplier rand) {
        while (true) { // each pass is one independent trial
            double x = 2 * rand.getAsDouble() - 1; // uniform in [-1, 1)
            double y = 2 * rand.getAsDouble() - 1;
            if (x * x + y * y <= 1) return new double[]{x, y}; // inside: accept, edge included
        }

Approach. The method draws at most maxTrials pairs. For each pair it forms x and y and accepts only if x * x + y * y < 1, so a point on the edge is rejected. import java.util.Random;
import java.util.function.DoubleSupplier;

public final class BoundaryExpectedTrialsBoundary {
    static int lastTrials; // trials used by the last call, kept for the statistics below

    /**
     * Returns the first point in the open unit disc within maxTrials trials, or null.
     * Time: O(maxTrials). Space: O(1).
     * Invariant: trial k runs only when the first k - 1 trials were rejected.
     */
    static double[] boundedPoint(DoubleSupplier rand, int maxTrials) {
        for (int t = 1; t <= maxTrials; t++) { // the cap bounds the worst case
            lastTrials = t;
            double x = 2 * rand.getAsDouble() - 1;
            double y = 2 * rand.getAsDouble() - 1;
            if (x * x + y * y < 1) return new double[]{x, y}; // strict: the edge is rejected
        }
        return null; // every trial was rejected
    }

    static DoubleSupplier script(double... v) {
        int[] at = {0};
        return () -> v[at[0]++];
    }

        if (Math.abs(fails / (double) n - expected) > 0.003) throw new AssertionError("failure rate");

import java.util.Random;
import java.util.function.IntSupplier;

     * Time: O(1) expected. Space: O(1).
     * Invariant: every accepted index is uniform over 1..40.
     */

        while (true) {
            int a = rand7.getAsInt(), b = rand7.getAsInt(); // two rolls
            calls += 2;

            if (idx <= 40) return 1 + (idx - 1) % 10; // 40 indexes form ten groups of four

Problem

The Median Query That Got Slow

A monitoring job reports the 95th percentile of response times for each hour. It copies the hour's measurements into an array and selects the right value with quickselect, which avoids sorting the whole array. The job runs in milliseconds on live data. One night an engineer replays the logs after a backup step that sorts them by time of arrival, and the same job takes minutes on the same number of values. The code did not change, only the order of the input.

A method whose speed depends on how the input is ordered is risky, because an attacker or an unlucky export can choose the order. The question of this lesson is how to select the k-th smallest value so that no input order can make the method slow, while the answer stays exactly correct.

Simple approach

Always Split On The Last Element

Quickselect finds the k-th smallest value without sorting everything. It picks one value as the pivot, rearranges the array so that smaller values sit before the pivot and larger or equal values after it, and then continues in the one side that contains the wanted position. The direct version always takes the last element of the active range as its pivot.

final class LastPivotSelect {
    static int kthSmallest(int[] a, int k) {
        int lo = 0, hi = a.length - 1, target = k - 1;       // 0-based rank
        while (true) {
            int pv = a[hi], store = lo;                      // the last element is the pivot
            for (int j = lo; j < hi; j++)
                if (a[j] < pv) { int t = a[store]; a[store] = a[j]; a[j] = t; store++; }
            int t = a[store]; a[store] = a[hi]; a[hi] = t;   // the pivot lands at its final index
            if (store == target) return a[store];
            if (target < store) hi = store - 1; else lo = store + 1;
        }
    }
}

On shuffled data the method is fast, and tests with random arrays pass. The sorted replay is a different story.

Predict first: The array is 1 2 3 4 5 6 7 8, already sorted, and the call asks for the smallest value (k = 1). How many element comparisons `a[j] < pv` does the method make in total? How many would it make for 100000 sorted values?

The pivot is always the largest value of the active range, so every round compares the other elements to it, leaves them all on the left, and removes only the pivot. The rounds compare 7, 6, 5, 4, 3, 2 and 1 elements, which is 28 comparisons for 8 values. For n values the total is n(n - 1) / 2. For 100000 values that is about 5 * 10^9 comparisons, which takes many seconds or minutes.

Bottleneck

One Bad Pivot Removes One Value

Cost Depends On The Pivot

The method costs O(n) time per round and the number of rounds depends on the pivot. A pivot that splits the range into two nearly equal parts cuts the work in half each round, so the total is about n + n/2 + n/4 + ..., which is O(n). A pivot that is the largest or smallest value removes one element per round, so the total is n + (n - 1) + ..., which is O(n^2). The worst case needs O(n^2) time and O(1) space.

Fixed Rules Can Be Defeated

The pivot rule decides which case occurs, and a fixed rule can be defeated. The last element is the maximum on a sorted ascending array. The first element fails on a sorted descending array. A middle element fails on a specially built array that places extreme values at the middle of every active range. Any rule that reads positions in a fixed way has some input that makes every split unbalanced.

Equal Values Break The Split

A second weakness hides in the partition itself. When many values are equal, the test a[j] < pv leaves all of the equal values on one side. An array of 10^5 equal values gives the same removal of one element per round, even with a good pivot. The repair has to handle both the choice of the pivot and the equal values.

Key idea

Choose The Pivot By Chance

A Random Pivot Defeats Any Order

A random pivot is a position drawn uniformly from the active range [lo, hi], endpoints included. The draw uses pick.applyAsInt(hi - lo + 1) and adds lo. The input order no longer matters, because the choice does not look at positions in a fixed way. Call a pivot good when its rank lies in the middle half of the active range. A uniform draw is good with probability one half, whatever the input is. A good pivot leaves at most three quarters of the range for the next round. The expected number of rounds until a good pivot appears is 2, so the work shrinks by a constant factor every two rounds on average.

Expected Time

The expected time is the average over the random draws, with the input fixed. A round on a range of length m costs O(m). With a good pivot every other round on average, the expected total is at most a geometric sum with ratio 3/4 and a constant factor, which is O(n). A bad run is possible, but its probability falls quickly. The worst case stays O(n^2), and the guarantee is about the average over draws, never about a single run.

Equal Values Need Three Regions

A three-way partition splits the active range into three parts: values below the pivot value, values equal to it, and values above it. Three indices keep the boundaries: lt for the first equal position, gt for the last equal position, and i for the next position to examine. If the wanted rank lies in the equal band, the pivot value is the answer, and the method returns without further work. Otherwise the method keeps only the below part or the above part, which excludes the whole equal band. An array of equal values then finishes in one round.

The invariant is that the wanted rank always lies inside the active range, and every value outside the active range is correctly placed relative to it.

State

Range, Pivot And Three Bands

The loop keeps eight names.

  • lo and hi are the ends of the active range, inclusive. Both change only when a side is dropped.
  • target is the 0-based rank of the wanted value in sorted order. It equals k - 1 for the k-th smallest.
  • p is the pivot position, drawn as lo + pick.applyAsInt(hi - lo + 1).
  • pv is the pivot value a[p], read before any swap.
  • lt is the first position of the equal band. Positions lo to lt - 1 hold values below pv.
  • gt is the last position of the equal band. Positions gt + 1 to hi hold values above pv.
  • i is the next position to examine. Positions lt to i - 1 hold values equal to pv.
  • rounds counts the loop passes, which a test can read.

The scan ends when i passes gt. At that moment the three bands cover the whole active range.

Code

Quickselect With Random Pivots

The Loop

The method keeps the loop shape of the naive version and replaces the pivot rule and the partition. It rearranges the array in place.

final class RandomizedSelect {
    static int kthSmallest(int[] a, int k, java.util.function.IntUnaryOperator pick) {
        int lo = 0, hi = a.length - 1, target = k - 1;
        while (true) {
            int p = lo + pick.applyAsInt(hi - lo + 1);       // uniform position in [lo, hi]
            int pv = a[p];
            int lt = lo, i = lo, gt = hi;                    // below: [lo, lt), equal: [lt, i), unknown: [i, gt], above: (gt, hi]
            while (i <= gt) {
                if (a[i] < pv) { int t = a[lt]; a[lt] = a[i]; a[i] = t; lt++; i++; }
                else if (a[i] > pv) { int t = a[i]; a[i] = a[gt]; a[gt] = t; gt--; }
                else i++;
            }
            if (target < lt) hi = lt - 1;                    // keep the below band
            else if (target > gt) lo = gt + 1;               // keep the above band
            else return pv;                                  // the rank is in the equal band
        }
    }
}

Cost

  • Time is O(n) expected for any input order, and O(n^2) in the worst case.
  • Space is O(1), because the method works in place and keeps a few indices.
  • Mutation rearranges the input array, so a caller who needs the original order passes a copy.
When to use it

When Random Pivots Apply

Recognizing The Pattern

Use this method when the task needs the k-th smallest value, a median or a percentile. Check two conditions: only one rank is wanted, and the input order is not under your control. Before coding, decide whether equal values are common and whether the input array may be rearranged. The invariant to keep is that the wanted rank lies in the active range after every round.

False Friends

Sorting is a false friend when only one rank is needed, since it costs O(n log n) where selection costs O(n) on average. A heap of size k is a second false friend: it gives O(n log k) time and is better when k is small or the data arrive as a stream. A median of three fixed positions looks like a defence, but an adversarial order still defeats it.

When The Method Does Not Apply

If a hard worst-case bound is required, as in a real-time controller, the expected bound is not enough, and a deterministic median-of-medians selection or a heap is the right choice. If the input must keep its order, the method needs a copy. If the randomness source is predictable, an adversary can learn the pivots and rebuild the bad case.

How many positions does an inclusive range from lo to hi contain?

Algorithmic Solution (attempt the problem first)

Approach. An inclusive range from lo to hi holds hi - lo + 1 positions, so the draw bound is that count and not hi - lo. The bound hi - lo would make the last position unreachable. The method checks lo <= hi first, calls pick once, validates that the offset is within 0 to hi - lo, and returns lo + d. Under the constraint hi <= 10^9, the count fits in an int. import java.util.Random;
import java.util.function.IntUnaryOperator;

public final class UniformPivotIndexBuild {
    /**
     * Returns a pivot position drawn from the inclusive range [lo, hi].
     * Time: O(1). Space: O(1).
     * Invariant: the result lies in [lo, hi].
     */
    static int pivotIndex(int lo, int hi, IntUnaryOperator pick) {
        if (lo > hi) throw new IllegalArgumentException("empty range"); // checked before any draw
        int d = pick.applyAsInt(hi - lo + 1); // the range holds hi - lo + 1 positions
        if (d < 0 || d > hi - lo) throw new IllegalStateException("draw out of range");
        return lo + d; // offset from the left end
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        int[] bound = {0};
        if (pivotIndex(3, 7, b -> { bound[0] = b; return 4; }) != 7 || bound[0] != 5) throw new AssertionError("ex1");
        if (pivotIndex(5, 5, b -> { bound[0] = b; return 0; }) != 5 || bound[0] != 1) throw new AssertionError("ex2");
        // empty range: no draw happens
        boolean threw = false;
        try { pivotIndex(4, 3, b -> { throw new AssertionError("pick must not run"); }); } catch (IllegalArgumentException e) { threw = true; }
        if (!threw) throw new AssertionError("empty range");
        // out-of-range draws are rejected
        threw = false;
        try { pivotIndex(2, 4, b -> 3); } catch (IllegalStateException e) { threw = true; }
        if (!threw) throw new AssertionError("bad draw");
        // every position of a random range is reachable exactly once
        Random rnd = new Random(71);
        for (int t = 0; t < 200; t++) {
            int lo = rnd.nextInt(50), hi = lo + rnd.nextInt(20);
            boolean[] seen = new boolean[hi - lo + 1];
            for (int d = 0; d <= hi - lo; d++) {
                final int dd = d;
                int p = pivotIndex(lo, hi, b -> dd);
                if (p < lo || p > hi || seen[p - lo]) throw new AssertionError("range or duplicate");
                seen[p - lo] = true;
            }
        }
        System.out.println("ok");
    }

Randomized Quickselect

Author exercise

Problem Specification. Write int kthSmallest(int[] a, int k, IntUnaryOperator pick). Each round draws a pivot position with the previous exercise, swaps the pivot to the end of the active range, and partitions with the rule a[j] < pv so that smaller values come first. The pivot ends at its final index s. If s equals k - 1, the method returns the pivot. Otherwise it continues in the part of the range that contains k - 1. The method may rearrange a.

Input Constraints. The limits are:

  • Length of a is from 1 to 10^5.
  • Rank k is from 1 to the length.
  • Values are int values that may repeat.
  • Draws use the bound hi - lo + 1 once per round.

Example 1. Input a = [7, 2, 9, 4, 1], k = 2, scripted draws 0, 1, output 2.

Example 2. Input a = [9, 4, 7, 4, 1, 8], k = 3, scripted draws 0, 1, 1, output 4.

Prerequisites. The Uniform Pivot Index exercise above. This exercise adds the partition and keeps one side.

What This Exercise Changes. The method keeps only the side that holds the wanted rank, and the input order no longer decides the pivot.

Hint

After the partition, which side can be dropped when the wanted rank is below the pivot's final index?

Algorithmic Solution (attempt the problem first)

Approach. Each round draws the pivot position, swaps the pivot to the end of the active range and scans the rest of the range once. A value below the pivot goes to the next free slot at the front, and the pivot then swaps into the slot after the last smaller value. That slot, store, is the pivot's final index in sorted order. If store equals the wanted index k - 1, the loop returns. If the wanted index is smaller, the range shrinks to the part before store, and otherwise to the part after it. The part that is dropped never contains the wanted index, so the answer stays inside the active range. The invariant is that every value left of lo is no larger than every value in the range, and every value right of hi is no smaller.

The program compares the method with a sort on random arrays that include repeats. It also checks the lesson's claim about the last-element rule: on a sorted array the last-pivot version makes exactly n(n - 1) / 2 comparisons. The random version makes far fewer on the same input.

Complexity.

  • Time is O(n) expected for any input order and O(n^2) in the worst case.
  • Space is O(1), because the method works in place.
import java.util.Arrays;
import java.util.Random;
import java.util.function.IntUnaryOperator;

public final class RandomizedQuickselectVary {
    static long compares; // number of element comparisons in the last run

    /**
     * Returns the k-th smallest value, rearranging a.
     * Time: O(n) expected. Space: O(1).
     * Invariant: the wanted index stays inside [lo, hi].
     */
    static int kthSmallest(int[] a, int k, IntUnaryOperator pick) {
        int lo = 0, hi = a.length - 1, target = k - 1;
        while (true) {
            int p = lo + pick.applyAsInt(hi - lo + 1); // pivot position, inclusive range
            int pv = a[p];
            a[p] = a[hi]; a[hi] = pv; // park the pivot at the end of the range
            int store = lo;
            for (int j = lo; j < hi; j++) {
                compares++;
                if (a[j] < pv) { int t = a[store]; a[store] = a[j]; a[j] = t; store++; } // smaller values go to the front
            }
            int t = a[store]; a[store] = a[hi]; a[hi] = t; // the pivot reaches its final index
            if (store == target) return a[store];
            if (target < store) hi = store - 1; else lo = store + 1; // keep the side with the target
        }
    }

    static int lastPivot(int[] a, int k) {
        return kthSmallest(a, k, bound -> bound - 1); // offset bound - 1 is always the last position
    }

    static IntUnaryOperator script(int... d) {
        int[] at = {0};
        return b -> d[at[0]++];
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (kthSmallest(new int[]{7, 2, 9, 4, 1}, 2, script(0, 1)) != 2) throw new AssertionError("ex1");
        if (kthSmallest(new int[]{9, 4, 7, 4, 1, 8}, 3, script(0, 1, 1)) != 4) throw new AssertionError("ex2");
        // random arrays with repeats agree with a sort
        Random rnd = new Random(72);
        for (int t = 0; t < 500; t++) {
            int[] a = new int[1 + rnd.nextInt(30)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(12);
            int k = 1 + rnd.nextInt(a.length);
            int[] sorted = a.clone();
            Arrays.sort(sorted);
            if (kthSmallest(a.clone(), k, bound -> rnd.nextInt(bound)) != sorted[k - 1]) throw new AssertionError("random");
        }
        // sorted input: the last-element rule makes n(n-1)/2 comparisons for k = 1, the random rule far fewer
        for (int n : new int[]{8, 100, 2000}) {
            int[] sorted = new int[n];
            for (int i = 0; i < n; i++) sorted[i] = i;
            compares = 0;
            if (lastPivot(sorted.clone(), 1) != 0) throw new AssertionError("last pivot answer");
            if (compares != (long) n * (n - 1) / 2) throw new AssertionError("quadratic count " + compares);
            compares = 0;
            kthSmallest(sorted.clone(), 1, bound -> rnd.nextInt(bound));
            if (n == 2000 && compares > 20L * n) throw new AssertionError("random rule too slow: " + compares);
        }
        System.out.println("ok");
    }

What This Exercise Changes. Equal values form their own band, and the method drops the whole band at once.

Hint

Where does the equal band sit after one pass, and what happens if the rank is inside it?

Algorithmic Solution (attempt the problem first)

Approach. The method keeps three indices over the active range. Positions from lo to lt - 1 hold values below the pivot value, positions from lt to i - 1 hold values equal to it, and positions from gt + 1 to hi hold values above it. The scan examines position i. A smaller value swaps with the first equal position and both lt and i advance. A larger value swaps with the last unexamined position and only gt moves, so i stays to examine the swapped-in value. An equal value advances i. When i passes gt, the three bands cover the range. If the wanted index lies inside [lt, gt], the pivot value is the answer. Otherwise the range shrinks to the below band or the above band, and the equal band leaves at once. An array of equal values forms a single equal band, so the first round returns. The invariant is that the three bands plus the unexamined part always cover [lo, hi] without overlap.

  • Time is O(n) expected, and an array of equal values costs O(n) in one round.
  • Space is O(1).
import java.util.Arrays;
import java.util.Random;
import java.util.function.IntUnaryOperator;

public final class EqualValuesBoundary {
    /**
     * Returns {value, rounds} for the k-th smallest value with a three-way partition.
     * Time: O(n) expected. Space: O(1).
     * Invariant: [lo, lt) is below pv, [lt, i) equals pv, (gt, hi] is above pv.
     */
    static int[] kthSmallestThreeWay(int[] a, int k, IntUnaryOperator pick) {
        int lo = 0, hi = a.length - 1, target = k - 1, rounds = 0;
        while (true) {
            rounds++;
            int pv = a[lo + pick.applyAsInt(hi - lo + 1)];
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) { // each pass examines one position
                if (a[i] < pv) { int t = a[lt]; a[lt] = a[i]; a[i] = t; lt++; i++; } // grow the below band
                else if (a[i] > pv) { int t = a[i]; a[i] = a[gt]; a[gt] = t; gt--; } // the swapped-in value is still unexamined
                else i++; // grow the equal band
            }
            if (target < lt) hi = lt - 1; // continue in the below band
            else if (target > gt) lo = gt + 1; // continue in the above band
            else return new int[]{pv, rounds}; // the target is in the equal band
        }
    }

    static long twoWayCompares(int[] a, int k) {
        long compares = 0;
        int lo = 0, hi = a.length - 1, target = k - 1;
        while (true) {
            int pv = a[hi], store = lo; // last-element pivot with the two-way rule
            for (int j = lo; j < hi; j++) { compares++; if (a[j] < pv) { int t = a[store]; a[store] = a[j]; a[j] = t; store++; } }
            int t = a[store]; a[store] = a[hi]; a[hi] = t;
            if (store == target) return compares;
            if (target < store) hi = store - 1; else lo = store + 1;
        }
    }

    static IntUnaryOperator script(int... d) {
        int[] at = {0};
        return b -> d[at[0]++];
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        int[] r1 = kthSmallestThreeWay(new int[]{3, 1, 3, 2, 3}, 4, script(1, 0));
        if (r1[0] != 3 || r1[1] != 2) throw new AssertionError("ex1");
        int[] r2 = kthSmallestThreeWay(new int[]{4, 4, 4, 4, 4}, 3, script(0));
        if (r2[0] != 4 || r2[1] != 1) throw new AssertionError("ex2");
        // random arrays with many repeats agree with a sort
        Random rnd = new Random(73);
        for (int t = 0; t < 500; t++) {
            int[] a = new int[1 + rnd.nextInt(30)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(4);
            int k = 1 + rnd.nextInt(a.length);
            int[] sorted = a.clone();
            Arrays.sort(sorted);
            if (kthSmallestThreeWay(a, k, bound -> rnd.nextInt(bound))[0] != sorted[k - 1]) throw new AssertionError("random");
        }
        // 100000 equal values need one round
        int[] same = new int[100_000];
        Arrays.fill(same, 9);
        if (kthSmallestThreeWay(same, 50_000, bound -> rnd.nextInt(bound))[1] != 1) throw new AssertionError("one round");
        // the two-way rule makes n(n-1)/2 comparisons on equal values
        int[] equal = new int[1000];
        Arrays.fill(equal, 5);
        if (twoWayCompares(equal, 1000) != 1000L * 999 / 2) throw new AssertionError("two-way growth");
        System.out.println("ok");
    }

Problem

A Fair Pick From A Moving Pool

A game server awards one random reward to a player. Only some rewards qualify: the player's level must be high enough, the reward must not already be owned, and the season must be active. Each qualifying reward has a drop weight. The first implementation counts all rewards in the catalog, picks a random number below that count, and walks the catalog to the chosen position. When the position falls on a reward that does not qualify, the code gives the next qualifying reward instead. Players with few qualifying rewards notice that one reward appears far more often than the others.

The error is the wrong total. A fair pick is fair among the items that qualify, with chances proportional to their weights, and the code computed its chances against the whole catalog. The lessons before this one taught three separate tools for fair random choice. This lesson asks how to combine them when a data structure decides which items qualify, and how to prove that the final chances are right.

Combining The Three

The new work is the combination. The data structure, whether an array window, a linked list or a geometric test, decides which items are eligible. The probability rule must then use the total weight of the eligible items as its denominator. The lesson shows how each of the three tools keeps that denominator correct, and which of them applies when eligibility is discovered during a single pass.

Simple approach

Count Everything, Then Skip

The direct design counts the whole catalog, draws a position below that count, and repairs a bad landing by moving forward to the next qualifying item. Each item is a record with a name, a weight and a flag that says whether it qualifies. Tests script the random draws through a LongUnaryOperator parameter. A call with bound b returns an integer below b.

final class SkipPicker {
    record Item(String name, long weight, boolean qualifies) {}

    static String pick(java.util.List<Item> catalog, java.util.function.LongUnaryOperator pick) {
        int start = (int) pick.applyAsLong(catalog.size());          // position among all items
        for (int step = 0; step < catalog.size(); step++) {
            Item it = catalog.get((start + step) % catalog.size());  // move forward until an item qualifies
            if (it.qualifies()) return it.name();
        }
        return null;                                                  // nothing qualifies
    }
}

The code never returns an item that does not qualify, and it ignores the weights entirely. A repair that multiplies the position by the weight would not fix the problem, because the skipping step is what distorts the chances.

Predict first: The catalog has five items in this order: A qualifies, B does not, C does not, D qualifies, E does not. The draw is uniform over the five positions and an item that does not qualify passes the pick to the next qualifying item. What is the chance of A and what is the chance of D? Is that fair among the two qualifying items?

Position 0 gives A. Positions 1, 2 and 3 give D, since B and C are skipped forward to D. Position 4 skips E and wraps around to A. So A gets positions 0 and 4, which is 2/5, and D gets positions 1, 2 and 3, which is 3/5. Two qualifying items should each get 1/2, so the pick is unfair.

Bottleneck

Skipping Moves Chance To Neighbours

The pick costs O(n) time and O(1) extra space. The cost is acceptable, and the fairness is not. A skipped item passes its whole share of probability to the next qualifying item after it. An item that follows a long run of non-qualifying items collects the shares of all of them. The chance of a qualifying item therefore depends on the length of the gap before it in the catalog, and the gap has nothing to do with the item's weight.

The root cause is the denominator. A fair pick over k qualifying items with equal weights needs every item to get chance 1 / k. A uniform draw over n catalog positions gives each position 1 / n. The two numbers k and n differ, and no rule that moves probability between neighbours can repair them evenly.

A correct design has two requirements. It must count only eligible items, and the count must be the denominator of every chance. It must also be able to learn eligibility during the pass, because for a linked list or a stream the program cannot count the qualifying items before it starts.

Key idea

The Denominator Is The Eligible Total

One Rule For Three Tools

The eligible set is the set of items that qualify at the moment of the pick, as decided by the data structure: a window of an array, the nodes of a list, or the points of a shape. The weight of the eligible set is the sum of the weights of its members. The denominator of the pick is that sum. The probability invariant says that every eligible item e has chance weight(e) / denominator, and no ineligible item has any chance.

Each earlier tool keeps the invariant in its own way. The reservoir keeps a running denominator, which is the total weight of the eligible items seen so far. The ticket method computes the denominator once, as the last prefix total. Rejection never computes it, and it lets the uniform draw over the larger region and the membership test produce chances that are proportional to the area of the eligible part.

A Weighted Reservoir

The reservoir rule extends to integer weights without a table. Let W be the total weight of the eligible items read so far, including the current item e with weight w. The method draws an integer from 0 to W - 1 and replaces the held item with e when the draw is below w. The chance of replacement is w / W. The proof is by induction. After the first eligible item the invariant holds, since it is the only one. Suppose item j is held with chance w_j / W_before. After item e arrives, j stays with chance (W_before / W) * (w_j / W_before) = w_j / W. Item e is held with chance w / W. Every eligible item has chance proportional to its weight.

Choosing The Tool

The reservoir fits when eligibility is found while reading and the total is unknown. The ticket method fits when the items sit in memory, the weights are fixed, and many picks follow. Rejection fits when membership is a cheap test and the shape fills a large share of a simple region. The invariant is checked the same way for all three: write down the chance of one eligible item, divided by the eligible total.

State

Eligible Total, Draw And Held Item

The weighted reservoir keeps five names.

  • held is the name or index of the item currently in the sample.
  • total is the sum of the weights of all eligible items read so far. It is a long, because a long stream of large weights overflows an int.
  • w is the weight of the item being read. Only eligible items change total.
  • draw is the result of pick.applyAsLong(total), an integer from 0 to total - 1.
  • eligible is the flag from the data structure. An ineligible item neither changes total nor makes a draw.

The first eligible item always becomes held. Its draw would always be below its own weight, so the code skips the draw and keeps the count of calls equal to the number of eligible items after the first.

Walkthrough

Tracing A Pool And A Ring

A Weighted Pass Over A Stream

The first trace reads five records in order, each written as a name and a weight. The records A:3, C:1, D:4 and E:2 are eligible, and B:2 is not. The pointer t marks the record being read. Record A becomes the held item and sets total to 3. Record B does not qualify, so nothing changes. Record C brings total to 4 and draws from bound 4, getting 3, which is not below its weight 1, so A stays. Record D brings total to 8 and draws from bound 8, getting 2, which is below 4, so D replaces A. Record E brings total to 10 and draws from bound 10, getting 7, which is not below 2, so D stays. The final sample is D.

Rejection On A Ring

The second trace samples a point in a ring with inner radius 1 and outer radius 2. The square around the outer circle gives unit coordinates from -1 to 1. A point is accepted when its squared distance from the center is between 0.25 and 1, because the inner radius is half the outer radius. The pointer trial marks the trial. The first pair of draws lies inside the hole and is rejected. The second pair lies outside the outer circle and is rejected. The third pair lies in the ring and is accepted, and the result is scaled by the outer radius.

Code

One Pass With Weights And Eligibility

The Weighted Reservoir

The method reads records once. A record carries a flag from the data structure, and the method ignores records that do not qualify. The first eligible record is kept without a draw.

final class WeightedReservoir {
    record Item(String name, long weight, boolean qualifies) {}

    static String pick(java.util.List<Item> items, java.util.function.LongUnaryOperator pick) {
        String held = null;
        long total = 0;                                       // weight of the eligible items read so far
        for (Item it : items) {
            if (!it.qualifies() || it.weight() == 0) continue;   // ineligible items change nothing
            total += it.weight();
            if (held == null) { held = it.name(); continue; }    // the first eligible item needs no draw
            if (pick.applyAsLong(total) < it.weight()) held = it.name();   // replace with chance w / total
        }
        return held;                                          // null when nothing qualifies
    }
}

Cost

  • Time is O(n) for one pass with one draw per eligible item after the first.
  • Space is O(1), because the method keeps the held name and the total.
  • Rejection costs O(1) expected per sample when the eligible region fills a good share of the simple region.
When to use it

When The Eligible Total Matters

Recognizing The Pattern

Use this combination when a statement asks for a random pick among items that satisfy a condition. A data structure decides the condition, for example a window, a list traversal, a set or a geometric test. Before coding, name the eligible set, name its total weight and write the chance of one eligible item as a fraction. The invariant to protect is that every eligible item has chance weight / denominator and nothing else has any chance.

False Friends

Skipping to the next qualifying item is a false friend, as the predict question showed. Picking a position among all items and retrying until it qualifies is exact but is rejection in disguise, and its speed depends on the share of qualifying items. A shuffle of the whole catalog followed by a scan is exact and costs more than needed. Picking uniformly among qualifying items and then adjusting by weight does not give proportional chances.

When The Method Does Not Apply

If the weights change between picks, a Fenwick tree keeps the totals current. If the eligible set is empty, the pick has no valid answer, and the contract must say what the method returns. If the weights are real numbers, integer tickets are unavailable, and the boundary comparisons need a stated tolerance.

Hint

Which count is the denominator when matches outside the window do not exist for this call?

Algorithmic Solution (attempt the problem first)

Approach. The eligible positions are those inside [from, to] whose value equals target. The method scans only that window and keeps a counter m of eligible positions seen so far. The first eligible position is stored without a draw. For the m-th one, the method draws from bound m and stores the position when the result is 0, so its chance is 1 / m. By the induction from the Reservoir Sampling lesson, every eligible position has chance 1 / m after m eligible positions. Positions outside the window and positions with other values never change m, so the denominator counts eligible positions only. When m stays 0, the method returns -1 and makes no draw. The invariant is that after m eligible positions, each of them is held with chance 1 / m.

The program enumerates all draw sequences for several windows and checks that every eligible position is returned equally often. It checks the examples, an empty window result and that no draw happens when nothing matches.

Complexity.

  • Time is O(window length).
  • Space is O(1).
import java.util.ArrayList;
import java.util.List;
import java.util.function.LongUnaryOperator;

public final class RandomPickWindowBuild {
    /**
     * Returns an eligible position chosen uniformly, or -1.
     * Time: O(to - from + 1). Space: O(1).
     * Invariant: after m eligible positions each is held with chance 1/m.
     */
    static int pickInWindow(int[] nums, int target, int from, int to, LongUnaryOperator pick) {
        int held = -1;
        long m = 0; // count of eligible positions
        for (int i = from; i <= to; i++) {
            if (nums[i] != target) continue; // not eligible
            m++;
            if (m == 1 || pick.applyAsLong(m) == 0) held = i; // the first enters, later ones with chance 1/m
        }
        return held;
    }

    static int run(int[] nums, int target, int from, int to, long[] draws) {
        int[] at = {0};
        return pickInWindow(nums, target, from, to, b -> draws[at[0]++]);
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        if (run(new int[]{2, 7, 2, 2, 9, 2}, 2, 1, 5, new long[]{0, 2}) != 3) throw new AssertionError("ex1");
        if (pickInWindow(new int[]{4, 5}, 9, 0, 1, b -> { throw new AssertionError("no draw expected"); }) != -1) throw new AssertionError("ex2");
        // exact fairness over all draw sequences for several windows
        int[][] arrays = {{2, 7, 2, 2, 9, 2}, {1, 1, 1, 1, 1}, {5, 2, 5, 2, 5, 2, 5}};
        int[][] windows = {{0, 5}, {1, 5}, {2, 3}, {0, 4}, {1, 6}};
        for (int[] nums : arrays) for (int[] win : windows) {
            if (win[1] >= nums.length) continue;
            int target = nums[0];
            List<Integer> eligible = new ArrayList<>();
            for (int i = win[0]; i <= win[1]; i++) if (nums[i] == target) eligible.add(i);
            if (eligible.isEmpty()) continue;
            int draws = eligible.size() - 1;
            long[] seq = new long[draws];
            long[] counts = new long[nums.length];
            while (true) {
                counts[run(nums, target, win[0], win[1], seq.clone())]++;
                int pos = 0; // odometer: draw p has bound p + 2
                while (pos < draws && ++seq[pos] == pos + 2) seq[pos++] = 0;
                if (pos == draws) break;
            }
            long expected = counts[eligible.get(0)];
            for (int i : eligible) if (counts[i] != expected) throw new AssertionError("unfair");
            for (int i = 0; i < nums.length; i++) if (!eligible.contains(i) && counts[i] != 0) throw new AssertionError("ineligible chosen");
        }
        System.out.println("ok");
    }

Hint

What is the chance that a node with count c replaces the held value when the running total is T?

Algorithmic Solution (attempt the problem first)

Approach. A node with count c stands for c copies, so the denominator is the sum of counts read so far. The first node is held without a draw. For a later node, the method adds its count to total, draws from bound total, and replaces the held value when the draw is below the node's count. That replacement has chance c / total. Suppose node j is held with chance c_j / T_before. It survives the new node with chance T_before / T, so it is held with chance c_j / T. The new node is held with chance c / T. By induction, after the whole list, a node is held with chance c / T_final, which is the share of the expanded sequence that it occupies. The invariant is that after each node the held value has chance proportional to the node's count among the nodes read.

The program enumerates every draw sequence for lists with 1 to 4 nodes and counts how often each node is returned. It compares count[j] * T with c_j * (number of sequences), which is the exact proportion. It also checks the examples and that the list is unchanged.

Complexity.

  • Time is O(n) for one walk.
  • Space is O(1).
import java.util.function.LongUnaryOperator;

public final class WeightedListNodeVary {
    static final class RunNode {
        final int val; final long count; RunNode next;
        RunNode(int val, long count, RunNode next) { this.val = val; this.count = count; this.next = next; }
    }

    /**
     * Returns a value so that each element of the expanded sequence is equally likely.
     * Time: O(n). Space: O(1).
     * Invariant: after each node the held value has chance proportional to its node's count.
     */
    static int weightedNode(RunNode head, LongUnaryOperator pick) {
        int held = head.val; // the first node needs no draw
        long total = head.count;
        for (RunNode cur = head.next; cur != null; cur = cur.next) {
            total += cur.count; // the denominator grows by the weight of this node
            if (pick.applyAsLong(total) < cur.count) held = cur.val; // chance count / total
        }
        return held;
    }

    static RunNode build(int[] vals, long[] counts) {
        RunNode head = null;
        for (int i = vals.length - 1; i >= 0; i--) head = new RunNode(vals[i], counts[i], head);
        return head;
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] d = {0, 4};
        int[] at = {0};
        if (weightedNode(build(new int[]{5, 8, 3}, new long[]{2, 1, 3}), b -> d[at[0]++]) != 8) throw new AssertionError("ex1");
        if (weightedNode(build(new int[]{7}, new long[]{4}), b -> { throw new AssertionError("no draw"); }) != 7) throw new AssertionError("ex2");
        // exact proportions over every draw sequence
        long[][] countCases = {{1}, {2, 3}, {1, 1, 1}, {2, 1, 3}, {3, 1, 2, 2}};
        for (long[] counts : countCases) {
            int n = counts.length;
            int[] vals = new int[n];
            for (int i = 0; i < n; i++) vals[i] = 10 + i;
            RunNode head = build(vals, counts);
            long[] bounds = new long[Math.max(0, n - 1)];
            long run = counts[0], seqCount = 1;
            for (int i = 1; i < n; i++) { run += counts[i]; bounds[i - 1] = run; seqCount *= run; } // bound for node i is the prefix sum
            long totalWeight = run;
            long[] seq = new long[bounds.length];
            long[] hits = new long[n];
            while (true) {
                final long[] copy = seq.clone();
                final int[] cursor = {0};
                hits[weightedNode(head, b -> copy[cursor[0]++]) - 10]++;
                int pos = 0;
                while (pos < seq.length && ++seq[pos] == bounds[pos]) seq[pos++] = 0;
                if (pos == seq.length) break;
            }
            for (int i = 0; i < n; i++) if (hits[i] * totalWeight != counts[i] * seqCount) throw new AssertionError("proportion " + i);
            RunNode cur = head;
            for (int i = 0; i < n; i++, cur = cur.next) if (cur.val != 10 + i || cur.count != counts[i]) throw new AssertionError("list changed");
        }
        System.out.println("ok");
    }

Hint

Which search finds the first prefix total that is strictly above a zero-based ticket?

Algorithmic Solution (attempt the problem first)

Approach. The constructor builds prefix totals with Math.addExact, which throws ArithmeticException instead of wrapping when a sum exceeds Long.MAX_VALUE. Invalid inputs fail early with IllegalArgumentException, because an input with no items, a negative weight or a total of zero has no valid ticket. A zero-based ticket t lies from 0 to total - 1, and index i owns the tickets from P[i-1] to P[i] - 1, where P[-1] is 0. The owner of t is therefore the first index whose prefix total is strictly greater than t. The binary search keeps hi at an index whose prefix is above the ticket and lo at the earliest candidate. A zero-weight index repeats a prefix total, so the search stops at the first index with that value and skips the repeat. The invariant here is the same window rule: whichever branch runs, the owner still lies in [lo, hi].

The program checks every ticket for small weight arrays against a table of owners. It runs the large examples, and it checks the overflow cases and that two weights of 4 * 10^18 add without overflow while Long.MAX_VALUE + 1 does overflow.

Complexity.

  • Time is O(n) for the constructor and O(log n) per pick.
  • Space is O(n).
import java.util.ArrayList;
import java.util.List;
import java.util.Random;
import java.util.function.LongUnaryOperator;

public final class WideTicketPickerBoundary {
    static final class WidePicker {
        private final long[] prefix;
        private final LongUnaryOperator pick;

        WidePicker(long[] w, LongUnaryOperator pick) {
            if (w.length == 0) throw new IllegalArgumentException("empty");
            prefix = new long[w.length];
            long run = 0;
            for (int i = 0; i < w.length; i++) {
                if (w[i] < 0) throw new IllegalArgumentException("negative");
                run = Math.addExact(run, w[i]); // throws ArithmeticException on overflow
                prefix[i] = run;
            }
            if (run == 0) throw new IllegalArgumentException("zero total");
            this.pick = pick;
        }

        /**
         * Returns the index that owns a zero-based ticket.
         * Time: O(log n). Space: O(1).
         * Invariant: the owner of the ticket lies in [lo, hi].
         */
        int pickIndex() {
            long ticket = pick.applyAsLong(prefix[prefix.length - 1]); // 0 to total - 1
            int lo = 0, hi = prefix.length - 1;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (prefix[mid] > ticket) hi = mid; // strictly above: mid may own the ticket
                else lo = mid + 1; // the range of mid ended at or below the ticket
            }
            return lo;
        }
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        long[] d = {2, 3};
        int[] at = {0};
        WidePicker p = new WidePicker(new long[]{3, 0, 2}, b -> d[at[0]++]);
        if (p.pickIndex() != 0 || p.pickIndex() != 2) throw new AssertionError("ex1");
        boolean overflow = false;
        try { new WidePicker(new long[]{Long.MAX_VALUE, 1}, b -> 0); } catch (ArithmeticException e) { overflow = true; }
        if (!overflow) throw new AssertionError("overflow not detected");

Generate Random Point In A Circle

LeetCode 478

Problem Specification. Write double[] ringPoint(double inner, double outer, DoubleSupplier rand). The eligible region is the set of points whose distance from the origin is at least inner and at most outer. Each trial draws u and then v from rand, forms ux = 2u - 1 and uy = 2v - 1, and accepts the pair when (inner / outer)^2 <= ux^2 + uy^2 <= 1. The method returns {outer * ux, outer * uy} for the first accepted pair.

Input Constraints. The limits are:

  • Radii satisfy 0 <= inner < outer <= 10^8.
  • Draws are doubles from 0 (included) to 1 (excluded).
  • Test runs in unit coordinates before scaling, and both edges are inside.
  • Acceptance probability is (pi - pi * (inner / outer)^2) / 4.

Example 1. Input inner = 1, outer = 2, draws 0.5, 0.5, 0.9, 0.5, output [1.6, 0.0].

Example 2. Input inner = 0, outer = 3, draws 0.5, 0.5, output [0.0, 0.0].

Prerequisites. The Boundary exercise above and the Rejection Sampling lesson. This exercise removes an inner disc from the eligible region.

What This Exercise Changes. The eligible region is a ring, so the membership test has a lower bound as well as an upper bound.

Hint

What fraction of the unit square is accepted when the inner disc has half the outer radius?

Algorithmic Solution (attempt the problem first)

Approach. The ring is the circle of radius outer minus the disc of radius inner. The method works in unit coordinates, where the outer circle has radius 1 and the hole has radius rho = inner / outer. Each trial draws a uniform point in the square from -1 to 1, and the test rho^2 <= ux^2 + uy^2 <= 1 accepts points of the ring only. The accepted point is uniform over the ring, since every patch of the ring is accepted with the same chance 1 / 4 per unit of area and the rejected region carries no weight. The method scales the accepted point by outer. The acceptance probability is the area of the ring divided by the area of the square, which is pi * (1 - rho^2) / 4. For rho = 0.5 this is about 0.589, so the expected number of trials is about 1.70. The invariant is that every draw is uniform over the square and only the ring passes the test.

The program checks the examples. It then runs 200000 seeded samples for inner = 1, outer = 2 and checks three facts: every point lies in the ring, the mean number of trials is near 4 / (pi * 0.75). The fraction of points within distance 1.5 equals the ratio of areas (1.5^2 - 1) / (2^2 - 1).

Complexity.

  • Time is O(1) expected, with 4 / (pi * (1 - rho^2)) trials.
  • Space is O(1).
import java.util.Random;
import java.util.function.DoubleSupplier;

public final class RandomPointRingRecognize {
    static long trials; // trials used since the counter was reset

    /**
     * Returns a uniform point in the ring inner <= r <= outer.
     * Time: O(1) expected. Space: O(1).
     * Invariant: each draw is uniform over the unit square and only the ring passes the test.
     */
    static double[] ringPoint(double inner, double outer, DoubleSupplier rand) {
        double rho2 = (inner / outer) * (inner / outer); // squared radius of the hole in unit coordinates
        while (true) {
            trials++;
            double ux = 2 * rand.getAsDouble() - 1;
            double uy = 2 * rand.getAsDouble() - 1;
            double r2 = ux * ux + uy * uy;
            if (rho2 <= r2 && r2 <= 1) return new double[]{outer * ux, outer * uy}; // inside the ring: scale and return
        }
    }

    static DoubleSupplier script(double... v) {
        int[] at = {0};
        return () -> v[at[0]++];
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        double[] a = ringPoint(1, 2, script(0.5, 0.5, 0.9, 0.5));
        if (a[0] != 1.6 || a[1] != 0.0) throw new AssertionError("ex1 " + a[0] + " " + a[1]);
        double[] b = ringPoint(0, 3, script(0.5, 0.5));
        if (b[0] != 0.0 || b[1] != 0.0) throw new AssertionError("ex2");
        // statistics for inner = 1, outer = 2
        Random rnd = new Random(82);
        DoubleSupplier src = rnd::nextDouble;
        int n = 200_000, within = 0;
        trials = 0;
        for (int i = 0; i < n; i++) {
            double[] p = ringPoint(1, 2, src);
            double r = Math.hypot(p[0], p[1]);
            if (r < 1 - 1e-12 || r > 2 + 1e-12) throw new AssertionError("outside the ring");
            if (r <= 1.5) within++;
        }
        double meanTrials = trials / (double) n;
        if (Math.abs(meanTrials - 4 / (Math.PI * 0.75)) > 0.02) throw new AssertionError("mean trials " + meanTrials);
        double areaShare = (1.5 * 1.5 - 1) / (4 - 1); // share of the ring inside radius 1.5
        if (Math.abs(within / (double) n - areaShare) > 0.01) throw new AssertionError("area share");
        System.out.println("ok");
    }

Problem

A Faster Route Planner That Lies

A navigation team speeds up its route planner by adding a guess of the remaining drive time to every road junction. The guess is the straight-line distance multiplied by a "typical detour factor" of 1.5. Benchmarks improve, and most routes look right. Then support receives a ticket: for one commuter pair the app suggests a 31 minute route while a 24 minute route exists. The team cannot tell whether the guess, the graph or the search is wrong, because no test checks the guess itself.

The search of the previous lesson is exact only when the guess obeys a rule, and a rule that nobody checks is a rule that breaks in production. This lesson asks how to test a guess against a graph before trusting it, and what the search must do when the guess satisfies the weaker of the two rules.

What Each Technique Adds

What The Earlier Lessons Contribute

Chapter 24 supplied shortest paths on weighted directed graphs. Its Dijkstra loop keeps a queue of entries ordered by cost so far, skips entries whose cost is larger than the best known cost, and finalizes a vertex when it pops. It also supplied the proof that this works because no edge weight is negative.

The lesson A Star Search supplied the priority f = g + h and the two properties of a guess h. It also supplied the proof that the first goal pop is optimal when the guess never overestimates. It worked on a grid, where Manhattan distance is the guess and no test of the guess was needed, because the grid made the guess obviously valid.

The new work is the combination on general graphs. The guess becomes an array of numbers supplied by a caller, and the program has to check it against the graph. The lesson derives a test for each of the two properties and shows that a consistent guess turns the search into Dijkstra's algorithm on adjusted edge weights, which reuses the chapter 24 proof. It then shows what changes when the guess is valid but not consistent.

Simple approach

Dijkstra With A Guess Bolted On

The direct design takes the Dijkstra loop and adds the guess to the priority of every pushed entry. The graph has n vertices and directed edges {u, v, w} with w >= 0. The array h holds one guess per vertex. The loop skips stale entries and returns the cost at the first pop of the goal.

final class GuessedSearch {
    static int search(int n, int[][] edges, int start, int goal, int[] h) {
        java.util.List<int[]>[] adj = new java.util.List[n];
        for (int i = 0; i < n; i++) adj[i] = new java.util.ArrayList<>();
        for (int[] e : edges) adj[e[0]].add(new int[]{e[1], e[2]});
        int[] best = new int[n];
        java.util.Arrays.fill(best, Integer.MAX_VALUE);
        java.util.PriorityQueue<int[]> pq = new java.util.PriorityQueue<>((x, y) -> x[0] - y[0]);
        best[start] = 0;
        pq.add(new int[]{h[start], start, 0});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (cur[2] > best[cur[1]]) continue;               // stale entry
            if (cur[1] == goal) return cur[2];                 // first pop of the goal
            for (int[] nb : adj[cur[1]]) {
                int g = cur[2] + nb[1];
                if (g < best[nb[0]]) { best[nb[0]] = g; pq.add(new int[]{g + h[nb[0]], nb[0], g}); }
            }
        }
        return -1;
    }
}

With h set to all zeros the code is Dijkstra's algorithm. With a guess array it is faster on many inputs, and nothing in the code checks the guess.

Predict first: The graph has three vertices S (0), A (1) and G (2), with edges S to G of weight 10, S to A of weight 1 and A to G of weight 1. The guess is 0 for S, 20 for A and 0 for G. What cost does the search return for the start S and the goal G? What is the cheapest cost?

The start entry has priority 0 and pops first. It pushes G with cost 10 and priority 10, and A with cost 1 and priority 21. The entry for G has the smaller priority, so G pops next and the search returns 10. The cheapest route goes through A and costs 2. The guess of 20 at A is far above the real remaining cost 1, so the search never looks at A.

Bottleneck

Nothing Checks The Guess

Cost Is Not The Problem

The search costs O(E log V) time and O(V + E) space, the same as Dijkstra's algorithm. The cost is not the problem. The problem is that the answer depends on the guess, and the guess is an input that is never validated. The predict example shows a single wrong number turning the exact answer 2 into 10.

Two Questions A Program Can Answer

Two questions need an answer that a program can compute. First, how far is each vertex from the goal in truth? If the program knows that distance, it can compare it with the guess and report a violation. Second, a valid guess can still be loose in one particular way: it can drop by more than the edge weight when the search moves from one vertex to the next. The first lesson's proof assumed the guess never overestimates, but its stronger rule, which lets a vertex be finalized at its first pop, needs more.

Why A Manual Check Fails

A graph with many vertices also makes a manual check impossible. A planner with a million junctions has a million guesses. The test has to be a loop over the vertices and the edges, with a clear yes or no and a measure of how far the worst violation reaches.

Key idea

Test The Guess, Then Pick The Loop

Computing The True Remaining Cost

The true remaining cost of a vertex v, written h*(v), is the length of the cheapest path from v to the goal. One Dijkstra run on the reversed graph, started at the goal, computes h* for every vertex at once in O((V + E) log V) time. A guess is admissible when h(v) <= h*(v) for every vertex that can reach the goal. The test is a single comparison per vertex, and the largest value of h(v) - h*(v) measures how badly the guess overestimates.

Reduced Weights

The reduced weight of an edge (u, v) with weight w is w + h(v) - h(u). The guess is consistent when every reduced weight is at least 0. The priority of the search is f(v) = g(v) + h(v). Along any path from the start to v, the reduced weights add up to g(v) + h(v) - h(start), because the intermediate guesses cancel in pairs. So the search orders vertices by the cost to reach them under the reduced weights, plus the constant h(start). If every reduced weight is non-negative, the search is Dijkstra's algorithm on the reduced graph. The chapter 24 proof applies, and each vertex is finalized at its first pop. Every start-to-goal path changes length by the same amount, h(goal) - h(start), so the cheapest path is the same in both graphs.

When Reduced Weights Go Negative

A guess can be admissible and still have a negative reduced weight on some edge. The search can then pop a vertex with a cost that a later pop improves. To stay exact, the search must reopen the vertex: when an entry with a smaller cost than the recorded cost arrives for a vertex that was already expanded, it expands the vertex again and updates its neighbours. The stale-entry skip still discards entries whose cost is larger than the recorded cost. Reopening costs extra expansions, and the optimality proof from the previous lesson still holds for an admissible guess.

The invariant is twofold. The recorded cost of a vertex never increases, and the first goal pop is optimal as long as the guess is admissible and cheaper entries are never discarded.

State

Guess, Remaining Cost And Excess

The checker and the search keep the following names.

  • best is the array of cheapest known costs from the start. It only decreases.
  • h is the guess array supplied by the caller, one number per vertex.
  • hstar is the true remaining cost per vertex, computed by Dijkstra on reversed edges from the goal.
  • excess is the largest value of h[v] - hstar[v], or 0 if no guess exceeds its true remaining cost.
  • gap is the reduced weight w + h[v] - h[u] of one edge. A negative gap marks an inconsistent edge.
  • reopened counts pops of a vertex that had already been expanded.

Every vertex must be able to reach the goal for the checks to be defined. A vertex that cannot reach the goal has no finite true remaining cost.

Code

Check The Guess And Search

The Checker

The method trueRemaining runs Dijkstra on the reversed edges from the goal. The method check compares the guess with it and tests every edge.

final class GuessChecker {
    static int[] trueRemaining(int n, int[][] edges, int goal) {
        java.util.List<int[]>[] rev = new java.util.List[n];
        for (int i = 0; i < n; i++) rev[i] = new java.util.ArrayList<>();
        for (int[] e : edges) rev[e[1]].add(new int[]{e[0], e[2]});     // reversed edge
        int[] d = new int[n];
        java.util.Arrays.fill(d, Integer.MAX_VALUE);
        java.util.PriorityQueue<int[]> pq = new java.util.PriorityQueue<>((x, y) -> x[0] - y[0]);
        d[goal] = 0;
        pq.add(new int[]{0, goal});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (cur[0] > d[cur[1]]) continue;                           // stale entry
            for (int[] nb : rev[cur[1]])
                if (cur[0] + nb[1] < d[nb[0]]) { d[nb[0]] = cur[0] + nb[1]; pq.add(new int[]{d[nb[0]], nb[0]}); }
        }
        return d;
    }

    static int[] check(int n, int[][] edges, int goal, int[] h) {
        int[] hs = trueRemaining(n, edges, goal);
        int excess = 0, admissible = 1, consistent = 1;
        for (int v = 0; v < n; v++) {
            excess = Math.max(excess, h[v] - hs[v]);                    // how far the guess overshoots
            if (h[v] > hs[v]) admissible = 0;
        }
        for (int[] e : edges)
            if (e[2] + h[e[1]] - h[e[0]] < 0) consistent = 0;           // negative reduced weight
        return new int[]{admissible, consistent, excess};
    }
}

Cost

  • trueRemaining costs O((V + E) log V) time and O(V + E) space.
  • check adds O(V + E) time for the comparisons.
  • Search with reopening costs O(E log V) per expansion round, and the number of reopenings is zero when the guess is consistent.
When to use it

When To Test A Guess

Recognizing The Pattern

Use this combination when a shortest-path search has one goal and edge weights are non-negative. The guess toward the goal comes from outside the graph, for example from coordinates, from a table or from a learned model. Before shipping the guess, compute the true remaining cost on test graphs and run the edge test. The invariant to protect is that the guess never exceeds the true remaining cost, and that a negative reduced weight triggers reopening.

False Friends

Scaling the guess by a constant above 1 looks like a safe speed-up and is a false friend, since it makes the guess exceed the true remaining cost whenever the path is not a straight line. A guess that is exact on a few test routes is a second false friend: the check must hold at every vertex. Passing the admissibility test does not prove consistency, and the two tests answer different questions.

When The Method Does Not Apply

If edge weights can be negative, neither Dijkstra's algorithm nor A* is valid. If the goal changes for every query, computing the true remaining cost once per goal costs as much as the search, so the checker belongs to test time and not to query time. If the graph is a tree with a unique path, no guess helps.

Zero-Heuristic Search

Author exercise

Problem Specification. Write int[] finalizeOrder(int n, int[][] edges, int start, int goal). Run the search with h = 0 for every vertex on the directed graph with vertices 0 to n - 1 and edges {u, v, w}. The queue pops the smallest cost, then the smallest vertex id. Return the vertices in the order in which non-stale pops finalize them, ending with the goal. If the goal is unreachable, return every reachable vertex in that order.

Input Constraints. The limits are:

  • Vertices number from 1 to 1000, and edges from 0 to 5000.
  • Weights are integers from 0 to 1000.
  • Ties go to the smaller vertex id.
  • Start and goal are valid vertex ids and may be equal.

Example 1. Input n = 6, edges = [[0,1,2],[0,2,1],[1,3,1],[2,3,4],[2,4,1],[4,3,1],[3,5,2]], start = 0, goal = 5, output [0, 2, 1, 4, 3, 5].

Example 2. Input n = 3, edges = [[0,1,1]], start = 0, goal = 2, output [0, 1].

Prerequisites. The Dijkstra loop of chapter 24 and the priority f = g + h from the A Star Search lesson.

What This Exercise Changes. Basic case: the zero guess makes the loop Dijkstra's algorithm, and the result is the order of finalization.

Hint

Which entries pop with equal cost, and which vertex id goes first?

Algorithmic Solution (attempt the problem first)

Approach. With a zero guess, the priority f equals the cost so far g, so the search is Dijkstra's algorithm. The queue entry holds the cost and the vertex id, and the comparator orders by cost and then by id. A pop is stale when its cost is larger than the recorded cost, and the method skips it. Every other pop finalizes its vertex, so the method appends the vertex to the result. If the vertex is the goal, the method returns the result. Because weights are non-negative, an entry with the smallest cost cannot be improved later, so a non-stale pop carries the final cost. When the queue empties first, the goal is unreachable and the result lists the reachable vertices. The invariant is that finalized vertices have final costs and appear in non-decreasing cost order.

The program compares the order with an array-based Dijkstra that scans for the unfinalized vertex with the smallest pair (cost, id), a different structure from the queue. It uses random graphs with zero weights and unreachable goals.

Complexity.

  • Time is O((V + E) log V), because each edge can push one entry.
  • Space is O(V + E) for the adjacency lists and the queue.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Random;

public final class ZeroHeuristicOrderBuild {
    /**
     * Returns the vertices in finalization order, ending with the goal when it is reachable.
     * Time: O((V + E) log V). Space: O(V + E).
     * Invariant: finalized vertices carry final costs and appear in non-decreasing cost order.
     */
    static int[] finalizeOrder(int n, int[][] edges, int start, int goal) {
        List<int[]>[] adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (int[] e : edges) adj[e[0]].add(new int[]{e[1], e[2]});
        long[] best = new long[n];
        Arrays.fill(best, Long.MAX_VALUE);
        PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Long.compare(x[0], y[0]) : Long.compare(x[1], y[1]));
        best[start] = 0;
        pq.add(new long[]{0, start});
        List<Integer> order = new ArrayList<>();
        while (!pq.isEmpty()) {
            long[] cur = pq.poll();
            int u = (int) cur[1];
            if (cur[0] > best[u]) continue; // stale entry
            order.add(u); // non-stale pop finalizes u
            if (u == goal) break;
            for (int[] nb : adj[u]) {
                long g = cur[0] + nb[1];
                if (g < best[nb[0]]) { best[nb[0]] = g; pq.add(new long[]{g, nb[0]}); }
            }
        }
        return order.stream().mapToInt(Integer::intValue).toArray();
    }

    static int[] oracle(int n, int[][] edges, int start, int goal) {
        long[] dist = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        boolean[] done = new boolean[n];
        dist[start] = 0;
        List<Integer> order = new ArrayList<>();
        while (true) {
            int u = -1;
            for (int v = 0; v < n; v++) if (!done[v] && dist[v] != Long.MAX_VALUE && (u == -1 || dist[v] < dist[u])) u = v; // smallest (cost, id)
            if (u == -1) break;
            done[u] = true;
            order.add(u);
            if (u == goal) break;
            for (int[] e : edges) if (e[0] == u && dist[u] + e[2] < dist[e[1]]) dist[e[1]] = dist[u] + e[2];
        }
        return order.stream().mapToInt(Integer::intValue).toArray();
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        int[][] e1 = {{0,1,2},{0,2,1},{1,3,1},{2,3,4},{2,4,1},{4,3,1},{3,5,2}};
        if (!Arrays.equals(finalizeOrder(6, e1, 0, 5), new int[]{0, 2, 1, 4, 3, 5})) throw new AssertionError("ex1");
        if (!Arrays.equals(finalizeOrder(3, new int[][]{{0,1,1}}, 0, 2), new int[]{0, 1})) throw new AssertionError("ex2");
        // random graphs with zero weights and unreachable goals
        Random rnd = new Random(91);
        for (int t = 0; t < 500; t++) {
            int n = 1 + rnd.nextInt(7), m = rnd.nextInt(14);
            int[][] edges = new int[m][];
            for (int i = 0; i < m; i++) edges[i] = new int[]{rnd.nextInt(n), rnd.nextInt(n), rnd.nextInt(5)};
            int s = rnd.nextInt(n), g = rnd.nextInt(n);
            if (!Arrays.equals(finalizeOrder(n, edges, s, g), oracle(n, edges, s, g))) throw new AssertionError("random " + Arrays.deepToString(edges));
        }
        System.out.println("ok");
    }

Hint

Why does the Manhattan bound on every edge keep the guess from exceeding the true remaining cost?

Algorithmic Solution (attempt the problem first)

Approach. The guess of a vertex is the Manhattan distance from its position to the goal's position. Every edge weight is at least the Manhattan distance between its endpoints, so the guess cannot exceed the true remaining cost: by the triangle inequality for the Manhattan metric, any path from v to the goal has length at least the direct distance. The reduced weight w + h(v) - h(u) is at least d(u, v) + h(v) - h(u). The triangle inequality h(u) <= d(u, v) + h(v) makes that non-negative, so the guess is also consistent. The search orders entries by the pair (g + h, vertex id), skips stale entries, counts every other pop and returns at the goal. Consistency means each vertex is finalized at its first pop, so the pop count is the number of finalized vertices. The invariant is that every popped entry has priority at most the cheapest cost until the goal pops.

The program builds random graphs with coordinates and weights above the Manhattan bound. It compares the result with an array-based version of the same rule, with an unguided Dijkstra for the cost. It confirms that the guided search never finalizes more vertices than the unguided search by more than ties allow.

Complexity.

  • Time is O((V + E) log V) in the worst case.
  • Space is O(V + E).
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Random;

public final class ManhattanGraphSearchVary {
    /**
     * Returns {cost, pops} for the guided search, or {-1, pops}.
     * Time: O((V + E) log V). Space: O(V + E).
     * Invariant: every popped entry has priority at most the cheapest cost until the goal pops.
     */
    static int[] manhattanSearch(int n, int[][] pos, int[][] edges, int start, int goal) {
        List<int[]>[] adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (int[] e : edges) adj[e[0]].add(new int[]{e[1], e[2]});
        int[] h = new int[n];
        for (int v = 0; v < n; v++) h[v] = Math.abs(pos[v][0] - pos[goal][0]) + Math.abs(pos[v][1] - pos[goal][1]); // Manhattan guess
        long[] best = new long[n];
        Arrays.fill(best, Long.MAX_VALUE);
        PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Long.compare(x[0], y[0]) : Long.compare(x[1], y[1]));
        best[start] = 0;
        pq.add(new long[]{h[start], start, 0});
        int pops = 0;
        while (!pq.isEmpty()) {
            long[] cur = pq.poll();
            int u = (int) cur[1];
            if (cur[2] > best[u]) continue; // stale entry
            pops++; // a finalized vertex
            if (u == goal) return new int[]{(int) cur[2], pops};
            for (int[] nb : adj[u]) {
                long g = cur[2] + nb[1];
                if (g < best[nb[0]]) { best[nb[0]] = g; pq.add(new long[]{g + h[nb[0]], nb[0], g}); }
            }
        }
        return new int[]{-1, pops};
    }

    static int[] oracle(int n, int[][] pos, int[][] edges, int start, int goal, boolean guided) {
        long[] dist = new long[n];
        Arrays.fill(dist, Long.MAX_VALUE);
        boolean[] done = new boolean[n];
        dist[start] = 0;
        int pops = 0;
        while (true) {
            int u = -1;
            long bestF = 0;
            for (int v = 0; v < n; v++) {
                if (done[v] || dist[v] == Long.MAX_VALUE) continue;
                long f = dist[v] + (guided ? Math.abs(pos[v][0] - pos[goal][0]) + Math.abs(pos[v][1] - pos[goal][1]) : 0);
                if (u == -1 || f < bestF) { u = v; bestF = f; } // smallest (priority, id)
            }
            if (u == -1) return new int[]{-1, pops};
            done[u] = true;
            pops++;
            if (u == goal) return new int[]{(int) dist[u], pops};
            for (int[] e : edges) if (e[0] == u && dist[u] + e[2] < dist[e[1]]) dist[e[1]] = dist[u] + e[2];
        }
    }

    public static void main(String[] args) {
        // the two examples from the problem text
        int[][] pos1 = {{0,0},{4,1},{3,3},{2,2},{1,3},{0,1},{4,0}};
        int[][] e1 = {{2,4,3},{0,5,2},{0,3,6},{3,5,4},{2,6,5},{5,6,7},{3,4,4},{5,4,3},{4,2,2},{6,1,1},{3,6,4}};
        if (!Arrays.equals(manhattanSearch(7, pos1, e1, 0, 6), new int[]{9, 3})) throw new AssertionError("ex1");
        int[][] pos2 = {{0,0},{1,0},{0,2},{2,1},{1,3},{3,3}};
        int[][] e2 = {{0,1,1},{0,2,2},{1,3,2},{2,4,2},{3,5,3},{4,5,3},{2,3,4},{1,4,5}};
        if (!Arrays.equals(manhattanSearch(6, pos2, e2, 0, 5), new int[]{6, 6})) throw new AssertionError("ex2");
        // random graphs with weights at least the Manhattan distance
        Random rnd = new Random(92);
        for (int t = 0; t < 500; t++) {
            int n = 1 + rnd.nextInt(7);
            int[][] pos = new int[n][];
            for (int i = 0; i < n; i++) pos[i] = new int[]{rnd.nextInt(5), rnd.nextInt(5)};
            int m = rnd.nextInt(14);
            int[][] edges = new int[m][];
            for (int i = 0; i < m; i++) {
                int u = rnd.nextInt(n), v = rnd.nextInt(n);
                int d = Math.abs(pos[u][0] - pos[v][0]) + Math.abs(pos[u][1] - pos[v][1]);
                edges[i] = new int[]{u, v, d + rnd.nextInt(3)}; // weight at least the Manhattan distance
            }
            int s = rnd.nextInt(n), g = rnd.nextInt(n);
            int[] got = manhattanSearch(n, pos, edges, s, g);
            if (!Arrays.equals(got, oracle(n, pos, edges, s, g, true))) throw new AssertionError("guided oracle");
            if (got[0] != oracle(n, pos, edges, s, g, false)[0]) throw new AssertionError("cost differs from Dijkstra");
        }
        System.out.println("ok");
    }

Inadmissible Counterexample

Author exercise

Problem Specification. Write int[] checkGuess(int n, int[][] edges, int goal, int[] h). Compute the true remaining cost of every vertex by Dijkstra on the reversed edges from goal. Return {admissible, consistent, excess}. The value admissible is 1 when h[v] <= hstar[v] for every vertex, else 0. The value consistent is 1 when w + h[v] - h[u] >= 0 for every edge {u, v, w}, else 0. The value excess is the largest h[v] - hstar[v], or 0 if no vertex exceeds it.

Input Constraints. The limits are:

  • Vertices number from 1 to 1000, and edges from 0 to 5000.
  • Weights are integers from 0 to 1000.
  • Reachability holds: every vertex can reach the goal.
  • Guesses are integers from 0 to 10^6.

Example 1. Input the graph of the first Build example with goal = 5 and h = [5, 3, 4, 2, 3, 0], output {1, 1, 0}.

Example 2. Input the same graph with h = [7, 3, 4, 2, 3, 0], output {0, 0, 2}. Input the same graph with h = [0, 0, 4, 0, 0, 0], output {1, 0, 0}.

Prerequisites. The Manhattan Grid Search exercise above. This exercise tests a guess instead of using it.

What This Exercise Changes. The guess becomes the object under test, and the answer separates admissibility from consistency.

Hint

Which graph does the Dijkstra run use to measure distances to the goal?

Algorithmic Solution (attempt the problem first)

Approach. The method reverses every edge and runs Dijkstra from the goal. The resulting distance of a vertex is the true remaining cost hstar[v], the length of the cheapest path from v to the goal in the original graph. Admissibility holds when no guess is above its true remaining cost, so the method scans the vertices and records the largest overshoot h[v] - hstar[v], with 0 as the floor. Consistency holds when every edge has a non-negative reduced weight w + h[v] - h[u], so a second scan over the edges decides it. The two properties are independent. The guess [0, 0, 4, 0, 0, 0] is admissible because each value is at most the true remaining cost. It is inconsistent because the edge from vertex 2 to vertex 4 has reduced weight 1 + 0 - 4 = -3. The guess with 7 at the start overestimates by 2, which breaks admissibility whether or not one particular search happens to return a wrong cost. The invariant is that hstar holds exact shortest distances to the goal, so the comparisons are against the truth.

The program checks the three examples, then compares the result with a Floyd-Warshall oracle on random graphs in which every vertex reaches the goal. It also runs the unchecked search from the lesson with the overestimating guess on the lesson's three-vertex graph and confirms it returns 10 where 2 is optimal.

Complexity.

  • Time is O((V + E) log V) for the reverse Dijkstra and O(V + E) for the scans.
  • Space is O(V + E).
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.PriorityQueue;
import java.util.Random;

public final class CheckGuessBoundary {
    /**
     * Returns {admissible, consistent, excess}.
     * Time: O((V + E) log V). Space: O(V + E).
     * Invariant: hstar[v] is the exact cheapest cost from v to the goal.
     */
    static int[] checkGuess(int n, int[][] edges, int goal, int[] h) {
        List<int[]>[] rev = new List[n];
        for (int i = 0; i < n; i++) rev[i] = new ArrayList<>();
        for (int[] e : edges) rev[e[1]].add(new int[]{e[0], e[2]}); // reversed edge
        long[] hs = new long[n];
        Arrays.fill(hs, Long.MAX_VALUE);
        PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));
        hs[goal] = 0;
        pq.add(new long[]{0, goal});
        while (!pq.isEmpty()) {
            long[] cur = pq.poll();
            if (cur[0] > hs[(int) cur[1]]) continue; // stale entry
            for (int[] nb : rev[(int) cur[1]])
                if (cur[0] + nb[1] < hs[nb[0]]) { hs[nb[0]] = cur[0] + nb[1]; pq.add(new long[]{hs[nb[0]], nb[0]}); }
        }
        int admissible = 1, consistent = 1;
        long excess = 0;
        for (int v = 0; v < n; v++) {
            excess = Math.max(excess, h[v] - hs[v]); // overshoot against the true remaining cost
            if (h[v] > hs[v]) admissible = 0;
        }
        for (int[] e : edges) if (e[2] + h[e[1]] - h[e[0]] < 0) consistent = 0; // negative reduced weight
        return new int[]{admissible, consistent, (int) excess};
    }

    static int unchecked(int n, int[][] edges, int start, int goal, int[] h) {
        List<int[]>[] adj = new List[n];
        for (int i = 0; i < n; i++) adj[i] = new ArrayList<>();
        for (int[] e : edges) adj[e[0]].add(new int[]{e[1], e[2]});
        int[] best = new int[n];
        Arrays.fill(best, Integer.MAX_VALUE);
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[0] - y[0]);
        best[start] = 0;
        pq.add(new int[]{h[start], start, 0});
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            if (cur[2] > best[cur[1]]) continue;
            if (cur[1] == goal) return cur[2];
            for (int[] nb : adj[cur[1]]) {
                int g = cur[2] + nb[1];
                if (g < best[nb[0]]) { best[nb[0]] = g; pq.add(new int[]{g + h[nb[0]], nb[0], g}); }
            }
        }
        return -1;
    }

    public static void main(String[] args) {
        // the examples from the problem text
        int[][] e1 = {{0,1,2},{0,2,1},{1,3,1},{2,3,4},{2,4,1},{4,3,1},{3,5,2}};
        if (!Arrays.equals(checkGuess(6, e1, 5, new int[]{5, 3, 4, 2, 3, 0}), new int[]{1, 1, 0})) throw new AssertionError("ex1");
        if (!Arrays.equals(checkGuess(6, e1, 5, new int[]{7, 3, 4, 2, 3, 0}), new int[]{0, 0, 2})) throw new AssertionError("ex2a");
        if (!Arrays.equals(checkGuess(6, e1, 5, new int[]{0, 0, 4, 0, 0, 0}), new int[]{1, 0, 0})) throw new AssertionError("ex2b");
        // the lesson's three-vertex graph: the overestimate 20 makes the search return 10 where 2 is optimal
        int[][] tri = {{0, 2, 10}, {0, 1, 1}, {1, 2, 1}};
        if (unchecked(3, tri, 0, 2, new int[]{0, 20, 0}) != 10 || unchecked(3, tri, 0, 2, new int[]{0, 0, 0}) != 2) throw new AssertionError("lesson claim");
        if (checkGuess(3, tri, 2, new int[]{0, 20, 0})[0] != 0) throw new AssertionError("should be inadmissible");
        // random graphs in which every vertex reaches the goal, checked against Floyd-Warshall
        Random rnd = new Random(93);
        for (int t = 0; t < 500; t++) {
            int n = 2 + rnd.nextInt(6), goal = rnd.nextInt(n);
            List<int[]> list = new ArrayList<>();
            for (int v = 0; v < n; v++) if (v != goal) list.add(new int[]{v, goal, 1 + rnd.nextInt(9)}); // guarantees reachability
            for (int i = rnd.nextInt(10); i > 0; i--) list.add(new int[]{rnd.nextInt(n), rnd.nextInt(n), rnd.nextInt(6)});
            int[][] edges = list.toArray(new int[0][]);
            int[] h = new int[n];
            for (int v = 0; v < n; v++) h[v] = rnd.nextInt(12);
            long INF = 1_000_000;
            long[][] d = new long[n][n];
            for (long[] row : d) Arrays.fill(row, INF);
            for (int v = 0; v < n; v++) d[v][v] = 0;
            for (int[] e : edges) d[e[0]][e[1]] = Math.min(d[e[0]][e[1]], e[2]);
            for (int k = 0; k < n; k++) for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) d[i][j] = Math.min(d[i][j], d[i][k] + d[k][j]);
            int adm = 1, cons = 1, ex = 0;
            for (int v = 0; v < n; v++) { if (h[v] > d[v][goal]) adm = 0; ex = (int) Math.max(ex, h[v] - d[v][goal]); }
            for (int[] e : edges) if (e[2] + h[e[1]] - h[e[0]] < 0) cons = 0;
            if (!Arrays.equals(checkGuess(n, edges, goal, h), new int[]{adm, cons, ex})) throw new AssertionError("random");
        }
        System.out.println("ok");
    }

A-Star Grid Path

Author exercise

Problem Specification. Write int[] searchWithReopen(int[][] cost, int sr, int sc, int gr, int gc, int[][] h). The matrix cost has 0 for a wall and 1 to 9 for the entering cost of an open cell. The matrix h holds an admissible guess per cell. Run the search with the priority g + h. A pop is stale when its g is larger than the recorded cost. A non-stale pop of a cell that was already expanded is a reopening. The queue pops the smallest priority, then the smallest row, then the smallest column. Return {cost, reopened}, where cost is the cheapest cost or -1 and reopened is the number of reopenings before the goal pops.

Input Constraints. The limits are:

  • Grid has 1 to 30 rows and 1 to 30 columns.
  • Costs are integers from 0 to 9, and the start and the goal are open.
  • Guess values are integers from 0 up to the true remaining cost.
  • Moves go to the four neighbours and pay the entering cost.

Example 1. Input cost = [[2,2,9,1],[1,1,2,1]], start (0,0), goal (1,3), h = [[0,1,2,0],[3,0,1,0]], output {5, 1}.

Example 2. Input the same grid with h equal to zero everywhere, output {5, 0}.

Prerequisites. The Inadmissible Counterexample exercise above and the stale-entry rule from the A Star Search lesson. This exercise uses a guess that is admissible but not consistent.

What This Exercise Changes. The guess is admissible only, so cells can be expanded more than once, and the answer counts the extra expansions.

Hint

What must the search do with a cheaper entry for a cell that it has already expanded?

Algorithmic Solution (attempt the problem first)

Approach. The guess is admissible, so the first goal pop is optimal as long as no cheaper entry is thrown away. The method therefore keeps no closed set. It records the cheapest cost per cell. A pop is stale when its cost is larger than the record, and the method skips it. A non-stale pop of a cell that was expanded before happens when an entry with a smaller cost arrived after the first expansion. The method counts it as a reopening and expands the cell again. Neighbour updates use a strict comparison, so only cheaper costs create entries. The guess in the example is inconsistent, because the cell at row 1, column 0 has guess 3 while its neighbour at row 1, column 1 has guess 0 and the step costs 1, giving the reduced weight 1 + 0 - 3 = -2. The cell at row 1, column 1 is therefore expanded through the top route first and reached more cheaply through row 1, column 0 later. The invariant is that the recorded cost of a cell never increases and the goal pop carries the cheapest cost.

The program verifies that the example guess is admissible by computing true remaining costs, runs the examples, and compares the cost with a Bellman-Ford relaxation on random grids with random admissible guesses. It also checks that a variant that never reopens returns 6 on the first example, so the reopening is what keeps the answer at 5.

Complexity.

  • Time is O(R * C * log(R * C)) per expansion round, and the number of reopenings can exceed 0 only when the guess is inconsistent.
  • Space is O(R * C).
import java.util.Arrays;
import java.util.PriorityQueue;
import java.util.Random;

public final class ReopenGridRecognize {
    /**
     * Returns {cost, reopened} for an admissible guess, with reopening allowed.
     * Time: O(R*C log(R*C)) per round of expansions. Space: O(R*C).
     * Invariant: best never increases, and the first goal pop carries the cheapest cost.
     */
    static int[] searchWithReopen(int[][] cost, int sr, int sc, int gr, int gc, int[][] h, boolean allowReopen) {
        int R = cost.length, C = cost[0].length;
        int[][] best = new int[R][C];
        for (int[] row : best) Arrays.fill(row, Integer.MAX_VALUE);
        boolean[][] expanded = new boolean[R][C];
        PriorityQueue<int[]> pq = new PriorityQueue<>((x, y) -> x[0] != y[0] ? Integer.compare(x[0], y[0])
                : x[1] != y[1] ? Integer.compare(x[1], y[1]) : Integer.compare(x[2], y[2]));
        best[sr][sc] = 0;
        pq.add(new int[]{h[sr][sc], sr, sc, 0});
        int reopened = 0;
        int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
        while (!pq.isEmpty()) {
            int[] cur = pq.poll();
            int r = cur[1], c = cur[2], g = cur[3];
            if (g > best[r][c]) continue; // stale entry
            if (expanded[r][c]) { if (!allowReopen) continue; reopened++; } // a cheaper cost reached an expanded cell
            expanded[r][c] = true;
            if (r == gr && c == gc) return new int[]{g, reopened};
            for (int d = 0; d < 4; d++) {
                int nr = r + dr[d], nc = c + dc[d];
                if (nr < 0 || nc < 0 || nr >= R || nc >= C || cost[nr][nc] == 0) continue;
                int ng = g + cost[nr][nc];
                if (ng < best[nr][nc]) {
                    if (expanded[nr][nc] && !allowReopen) continue; // the closed-set variant ignores the improvement
                    best[nr][nc] = ng;
                    pq.add(new int[]{ng + h[nr][nc], nr, nc, ng});
                }
            }
        }
        return new int[]{-1, reopened};
    }

    static int[][] trueRemaining(int[][] cost, int gr, int gc) {
        int R = cost.length, C = cost[0].length;
        int[][] zero = new int[R][C];
        int[][] res = new int[R][C];
        for (int r = 0; r < R; r++) for (int c = 0; c < C; c++) {
            int d = r == gr && c == gc ? 0 : cost[r][c] == 0 ? -1 : searchWithReopen(cost, r, c, gr, gc, zero, true)[0];
            res[r][c] = d == -1 ? Integer.MAX_VALUE : d; // no route to the goal means no finite remaining cost
        }
        return res;
    }

    public static void main(String[] args) {
        int[][] cost = {{2, 2, 9, 1}, {1, 1, 2, 1}};
        int[][] h = {{0, 1, 2, 0}, {3, 0, 1, 0}};
        // the example guess is admissible
        int[][] hs = trueRemaining(cost, 1, 3);
        for (int r = 0; r < 2; r++) for (int c = 0; c < 4; c++) if (h[r][c] > hs[r][c]) throw new AssertionError("not admissible");
        // the two examples from the problem text
        if (!Arrays.equals(searchWithReopen(cost, 0, 0, 1, 3, h, true), new int[]{5, 1})) throw new AssertionError("ex1");
        if (!Arrays.equals(searchWithReopen(cost, 0, 0, 1, 3, new int[2][4], true), new int[]{5, 0})) throw new AssertionError("ex2");
        // without reopening the same guess returns 6
        if (searchWithReopen(cost, 0, 0, 1, 3, h, false)[0] != 6) throw new AssertionError("closed set should be wrong");
        // random grids with random admissible guesses: the cost equals the true shortest cost
        Random rnd = new Random(94);
        int reopenSeen = 0;
        for (int t = 0; t < 600; t++) {
            int R = 1 + rnd.nextInt(4), C = 1 + rnd.nextInt(4);
            int[][] g = new int[R][C];
            for (int[] row : g) for (int c = 0; c < C; c++) row[c] = rnd.nextInt(5) == 0 ? 0 : 1 + rnd.nextInt(8);
            g[0][0] = 1; g[R - 1][C - 1] = 1;
            int[][] tr = trueRemaining(g, R - 1, C - 1);
            int[][] guess = new int[R][C];
            for (int r = 0; r < R; r++) for (int c = 0; c < C; c++)
                guess[r][c] = tr[r][c] == Integer.MAX_VALUE ? 0 : rnd.nextInt(tr[r][c] + 1); // admissible by construction
            int[] got = searchWithReopen(g, 0, 0, R - 1, C - 1, guess, true);
            if (got[0] != tr[0][0] && !(g[0][0] == 1 && tr[0][0] == Integer.MAX_VALUE && got[0] == -1)) throw new AssertionError("cost " + got[0] + " vs " + tr[0][0]);
            reopenSeen += got[1];
        }
        if (reopenSeen == 0) throw new AssertionError("no reopening exercised");
        System.out.println("ok");
    }
