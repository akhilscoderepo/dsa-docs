Chapter 31

Range Query Structures And Sweep Processing

Orientation

A leaderboard service updates one player's score and then reports the total score of ranks 1,000 to 5,000. Recomputing the total with a loop costs thousands of additions per request, and a stored prefix-sum array costs a full rebuild per update. A calendar service must report the most overlapping meetings at any minute while bookings arrive in any order. Both services need a structure that answers range questions while the data changes, or a pass that visits only the moments when something changes.

Prerequisites

You should know prefix sums from the earlier chapter on prefix sums and difference arrays, sorting with comparators, binary search on a sorted array, and the heap from the chapter on priority queues. A half-open range [a, b) includes a and excludes b, and later lessons use it for intervals. You should read i & -i as the lowest set bit of i. Lesson 01 explains that expression again where it first matters. Recursive functions on a range, as in the tree chapters, appear from lesson 02 onward.

The Five Lessons

Each lesson answers one question about how to avoid repeating work on a range of values or on a series of changes.

  • Fenwick Trees store block sums in one array, so a prefix query and a point update each take O(log n) steps.
  • Segment Trees store the aggregate of an exact interval in every node, so they handle operators such as minimum, which has no inverse operation and therefore does not fit a Fenwick tree.
  • Lazy Propagation delays a range update inside a node until a later query needs the children.
  • Coordinate Compression replaces huge or negative values by dense ranks that keep the order.
  • Sweep Events sorts the moments at which state changes and updates the state once per moment.

The Two Closing Lessons

Each closing lesson adds a part that names what the earlier lessons contribute.

  • Sweep And Ordered State keeps an ordered structure of active values while events arrive in coordinate order. Its exercises cover a capacity check, a skyline, an equal-coordinate rule and a booking counter.
  • Compress Values Then Count Ranks turns sparse keys into ranks and counts them with a Fenwick tree. Its exercises cover the ranking step, a sparse mutable sum, extreme values and an insertion cost.

How To Work Through Each Lesson

A lesson opens with a realistic scenario that exposes a failure. A short direct program follows, and it is too slow or returns a wrong answer. You predict its cost before the explanation appears. The later parts name the stored quantity and list the variables, then follow two traces, show the code and state where the idea stops fitting. Range conventions differ by lesson: the Fenwick tree takes zero-based positions and stores them one-based, the segment tree uses inclusive ranges, and lazy propagation uses half-open ranges. Four exercises close each lesson, and each exercise has a hint and a solution that you can open after your own attempt.

What You Can Do After This Chapter

You can choose between a Fenwick tree, a segment tree and a sorted event list from the update and query types in a problem statement. You can state what each stored number covers, and you can use long sums and one-based or zero-based indexes without off-by-one errors. You can also replace a sparse value range by ranks before counting.

Problem

Why Running Totals Slow Down After Edits

A dashboard shows the number of requests per minute for the last 200,000 minutes. Operators ask for the total between two minutes many times a second. Late events also arrive, and each one changes the count of a single minute that already passed.

A prefix-sum array answers each total with one subtraction, so the questions are cheap. The trouble starts when a count changes. Every prefix sum after the changed minute is now wrong, and the array must be repaired. The program needs both operations to stay fast at the same time, and the prefix-sum array makes only one of them fast. This lesson asks how a program can keep both point changes and range totals cheap.

Simple approach

Rebuilding The Prefix Array After Each Change

The direct approach keeps the prefix-sum array and rebuilds the affected part after every change. The method below changes one count and repairs every prefix sum from that position onward.

static void update(long[] prefix, int pos, long delta) {
    for (int i = pos + 1; i < prefix.length; i++) {
        prefix[i] += delta;            // every prefix that contains position pos shifts by delta
    }
}

static long rangeSum(long[] prefix, int left, int right) {
    return prefix[right + 1] - prefix[left];   // two reads answer any total
}

Here prefix[k] holds the sum of the first k counts, and prefix[0] is 0. The range query is a single subtraction. The update touches every entry after pos, which is up to n entries. A change near the start of the data repairs almost the whole array.

Bottleneck

Updates Cost O(n) Each

Predict first: A prefix-sum array holds 200,000 counts. A program runs 200,000 operations, and half of them change a count at a random position. About how many array writes do the changes cost in total?

About ten billion writes. Each change rewrites on average half of the 200,000 entries, which is 100,000 writes, and there are 100,000 changes. The total grows as the number of changes times the array length.

Count The Writes

One update writes up to n entries, so it costs O(n). With q updates mixed into the workload, the total cost is O(n * q). For n = q = 200,000 the product is 4 * 10^10 in the worst case, and a typical run still writes ten billion entries. Ten billion writes take several seconds, which is over a typical limit of one or two seconds.

Compare The Two Extremes

Dropping the prefix array and summing the range on demand has the opposite profile. An update becomes one write, but each query reads up to n counts, so a query costs O(n). One extreme makes queries cheap and updates expensive. The other extreme does the reverse. Both extremes cost O(n * q) for a workload that mixes the two operations evenly. The structure we need must store partial sums in a way that lets one update repair only a few of them and lets one query combine only a few of them.

Key idea

Store Partial Sums By Low Bit

Define The Low Bit

The low bit of a positive integer i is the value of its lowest set bit in binary, and Java computes it as i & -i. The number 6 is 110 in binary, and its low bit is 2. The number 8 is 1000, and its low bit is 8. Java stores negative numbers in two's complement, where -i equals the bitwise complement of i plus one. That operation flips every bit above the lowest set bit and keeps the lowest set bit and the zeros below it. The bitwise AND of i and -i therefore keeps only the lowest set bit.

Give Every Index A Block Length

A Fenwick tree is an array tree of sums, indexed from 1. Entry tree[i] stores the sum of the i & -i counts that end at position i. The entry tree[6] stores positions 5 and 6, because the low bit of 6 is 2. The entry tree[8] stores positions 1 to 8, and tree[7] stores only position 7. Each entry covers a block length equal to its low bit, so odd indexes cover one count and indexes that are powers of two cover everything before them.

Query By Clearing The Low Bit

The sum of the first k counts splits into blocks. Start at i = k, add tree[i], and replace i by i - (i & -i). That step removes the lowest set bit of i, and the removed block ends exactly where the next block must begin. Repeat until i reaches 0. The loop runs once per set bit of k, which is at most log2(n) + 1 times.

Update By Adding The Low Bit

A change at position p affects every block that contains p. Start at i = p, add the delta to tree[i], and replace i by i + (i & -i). This step moves to the next larger block that contains p. The indexes visited form the update path. Each step raises the lowest set bit, so the path leaves the array after at most log2(n) + 1 steps. Both operations cost O(log n), and the invariant that makes them correct is that tree[i] always equals the sum of the i & -i counts ending at i.

State

Quantities To Track In The Array

Track these items while reading or changing the array.

  • tree is a long[] of length n + 1, and slot 0 stays unused.
  • i is the internal one-based index that the loops move.
  • i & -i is the low bit, which is both the block length and the step size.
  • pos is the zero-based position that the caller uses.
  • delta is the signed amount that a change adds to one count.

The caller passes a zero-based pos, and the class converts it to the internal index pos + 1 before any loop starts. The method prefix(k) returns the sum of the first k counts, which are internal positions 1 to k. The range sum of external positions left to right is prefix(right + 1) - prefix(left).

Walkthrough

Follow One Update And One Query

Take eight counts 3, 1, 4, 1, 5, 9, 2, 6. The array tree for them is 0, 3, 4, 4, 9, 5, 14, 2, 31, where the leading 0 is the unused slot.

Add Ten To The Third Count

In this trace, every index and position inside tree counts from 1. The call add(2, 10) targets the zero-based position 2, which is the third count, so it converts position 2 to internal index 3. The entry tree[3] covers one count, so it changes first. Index 3 plus its low bit 1 gives 4. The entry tree[4] covers positions 1 to 4, which contain position 3, so it changes next. Index 4 plus its low bit 4 gives 8, and tree[8] covers all eight positions, so it changes last. Index 8 plus 8 is 16, which is past the array, so the loop stops.

Sum The First Six Positions

The call prefix(6) runs on the updated array. It starts at index 6, where tree[6] covers positions 5 and 6. Removing the low bit 2 leaves index 4. The entry tree[4] covers positions 1 to 4 and now includes the added ten. Removing the low bit 4 leaves index 0, and the loop stops after two reads.

The hardest step is the first jump in the update, from index 3 to index 4. Index 3 is odd, so its block holds one count, and the next block that contains it is the larger block ending at 4. The two traces use different jumps, and each visits only three or fewer entries out of eight.

Code

Implement Add And Prefix

final class Fenwick {
    final long[] tree;                       // internal one-based storage, slot 0 unused

    Fenwick(int n) {
        tree = new long[n + 1];              // n counts need n + 1 slots
    }

    void add(int pos, long delta) {
        for (int i = pos + 1; i < tree.length; i += i & -i) {
            tree[i] += delta;                // each visited block contains the changed position
        }
    }

    long prefix(int k) {
        long sum = 0;
        for (int i = k; i > 0; i -= i & -i) {
            sum += tree[i];                  // each visited block ends where the next one begins
        }
        return sum;
    }

    long range(int left, int right) {
        return prefix(right + 1) - prefix(left);   // counts left..right as a difference of prefixes
    }
}

The class has no separate build method, because a new tree holds all zeros and a loop of add calls loads the starting counts. That load costs O(n log n). The update loop ends because i grows and passes tree.length. The query loop ends because i shrinks to 0. The sums use long, so large counts do not overflow an int.

When to use it

When A Fenwick Tree Applies

Recognize The Pattern

Use this structure when point changes and prefix or range sums must both stay O(log n). The data must be a sequence of numbers where a sum of a range equals a difference of two prefix sums. That rule holds for sums, counts and bitwise exclusive-or, and it fails for minimum and maximum, which cannot be subtracted.

Before coding, check the invariant that tree[i] equals the sum of the i & -i counts that end at i. Every change must keep it true, and every query must rely only on it.

Watch For The Nearest False Friend

A prefix-sum array is a false friend here. It looks like the right tool because it answers range sums, but it only works when the data never changes. If the data is fixed, prefer the prefix-sum array, because its query reads two entries and it needs no loop. If the program needs range minimum on fixed data, a different structure fits better, and a later lesson covers the segment tree for operations that cannot be subtracted.

Avoid The Java Index Trap

The loops need a one-based index. With index 0 the expression 0 & -0 is 0, so the update loop never moves and runs forever. The class therefore converts every external zero-based position to pos + 1 once, at the boundary. Keep the sums in long, and let the query for an empty prefix return 0 without reading tree[0].

Prefix Query

Author exercise

Problem Specification. A Fenwick tree for n counts is stored in an array tree of length n + 1. Slot 0 is unused, and tree[i] is the sum of the i & -i counts that end at position i. Given tree and an integer k, return the sum of the first k counts.

Input Constraints. The limits are:

  • n is an int with 0 <= n <= 10^5.
  • k is an int with 0 <= k <= n.
  • Counts are long values with absolute value at most 10^9.
  • Return is a long, and k = 0 returns 0.
  • Mutation of tree is not allowed.

Example 1. Input tree = [0, 3, 4, 4, 9, 5, 14, 2, 31] and k = 5, output 14, from tree[5] + tree[4].

Example 2. Input the same tree and k = 0, output 0, since no block is read.

Prerequisites. The low bit and the block lengths from this lesson.

What This Exercise Changes. Baseline case: reads partial sums by clearing the low bit.

Hint

Which blocks end at 5 and then at the index you reach by clearing the low bit?

Algorithmic Solution (attempt the problem first)

Approach. The query adds the blocks that together cover positions 1 to k.

Entry tree[k] covers the k & -k counts that end at k. Subtracting that low bit from k leaves the index where the next block ends, so the blocks do not overlap and leave no gap. The loop repeats until the index reaches 0, and the invariant is that sum equals the total of the counts above the current index, up to k. For k = 5 the loop reads tree[5] and tree[4], which gives 5 + 9 = 14. For k = 0 the loop body never runs.

Complexity.

  • Time is O(log k), because every step clears the lowest set bit of the index and k has at most 17 set bits for k <= 10^5.
  • Space is O(1), since the loop carries one index and one sum.
import java.util.Random;

public final class FenwickPrefix {
    /**
     * Returns the sum of the first k counts stored in a one-based Fenwick array.
     * Time: O(log k), one step per set bit of k.
     * Space: O(1), one index and one running sum.
     * Invariant: sum holds the counts at positions i+1 to k, and i is the end of the next unread block.
     */
    static long prefix(long[] tree, int k) {
        // The running sum starts empty, so k = 0 returns 0 without reading tree.
        long sum = 0;
        // Each step clears the lowest set bit, so the loop runs once per set bit of k.
        for (int i = k; i > 0; i -= i & -i) {
            // The block ending at i covers i & -i counts, which no earlier block covered.
            sum += tree[i];
        }
        // The blocks read together cover positions 1 to k exactly.
        return sum;
    }

    /** Builds the tree from the definition: tree[i] sums the i & -i counts ending at i. */
    static long[] buildByDefinition(long[] a) {
        // One slot per count plus the unused slot 0.
        long[] tree = new long[a.length + 1];
        // Visit each internal index once.
        for (int i = 1; i <= a.length; i++) {
            // The block starts at i - (i & -i) + 1 in one-based terms.
            for (int p = i - (i & -i); p < i; p++) {
                // Position p + 1 in one-based terms is a[p] in zero-based terms.
                tree[i] += a[p];
            }
        }
        // The finished array is the input to prefix.
        return tree;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2 on the lesson tree.
        long[] tree = {0, 3, 4, 4, 9, 5, 14, 2, 31};
        if (prefix(tree, 5) != 14) throw new AssertionError("example 1");
        if (prefix(tree, 0) != 0) throw new AssertionError("example 2");
        // Checks that the definition builder reproduces the lesson tree.
        long[] built = buildByDefinition(new long[]{3, 1, 4, 1, 5, 9, 2, 6});
        if (!java.util.Arrays.equals(built, tree)) throw new AssertionError("definition builder");
        // Checks every prefix against a brute-force sum on random arrays with a fixed seed.
        Random rnd = new Random(31);
        for (int round = 0; round < 300; round++) {
            int n = rnd.nextInt(40);
            long[] a = new long[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(2001) - 1000;
            long[] t = buildByDefinition(a);
            long expected = 0;
            for (int k = 0; k <= n; k++) {
                if (k > 0) expected += a[k - 1];
                if (prefix(t, k) != expected) throw new AssertionError("round " + round + " k " + k);
            }
        }
    }
}verified
Variation

Point Update

Author exercise

Problem Specification. Start with n counts that are all 0 and an empty Fenwick tree. Process a list of assignments. Each assignment (pos, value) sets the count at zero-based position pos to value, replacing the old count. Return the array tree after all assignments.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 10^5.
  • pos is an int with 0 <= pos < n.
  • value is a long with absolute value at most 10^9.
  • Assignments number at most 10^5, and a position can repeat.
  • Return is a long[] of length n + 1 with slot 0 equal to 0.

Example 1. Input n = 6 and assignments (2, 5), (0, 3), (2, 1), (5, 4), output [0, 3, 3, 1, 4, 0, 4].

Example 2. Input n = 5 and assignments (4, 9), (4, 2), (1, 6), output [0, 0, 6, 0, 6, 2].

Prerequisites. The prefix query exercise above.

What This Exercise Changes. The operation changes from adding a delta to replacing a value, so the program must remember the current count.

Hint

The tree adds a delta and does not store assignments. What delta turns the old count into the new one?

Algorithmic Solution (attempt the problem first)

Approach. An assignment becomes a delta, and the delta travels along the update path.

The tree only supports adding, so the program keeps a plain array values with the current count of each position. The delta for an assignment is the new value minus values[pos]. After the delta is added along the path, the program stores the new value, which keeps values equal to the true counts. The path starts at pos + 1 and adds the low bit each step, so each visited block contains the changed position and every other block stays correct. A repeated position works because the second assignment subtracts the first value through its delta.

Complexity.

  • Time is O(m log n) for m assignments, because each assignment walks at most log2(n) + 1 blocks.
  • Space is O(n), for the values array and the tree array.
import java.util.Arrays;
import java.util.Random;

public final class FenwickAssign {
    /**
     * Applies assignments (pos, value) to an all-zero Fenwick array and returns the array.
     * Time: O(m log n), one update path of at most log2(n) + 1 blocks per assignment.
     * Space: O(n), for the current counts and the tree.
     * Invariant: values[p] is the true count at p, and tree[i] sums the i & -i counts ending at i.
     */
    static long[] assign(int n, int[][] ops) {
        // Slot 0 stays unused, so the tree has n + 1 slots.
        long[] tree = new long[n + 1];
        // The current counts let each assignment compute its delta.
        long[] values = new long[n];
        // One iteration per assignment.
        for (int[] op : ops) {
            int pos = op[0];
            // The delta turns the old count into the new one.
            long delta = op[1] - values[pos];
            // The path starts at the internal index and moves to the next larger block each step.
            for (int i = pos + 1; i <= n; i += i & -i) {
                // Each visited block contains position pos, so it shifts by the delta.
                tree[i] += delta;
            }
            // Remember the new count so a later assignment computes the right delta.
            values[pos] = op[1];
        }
        // The finished tree is returned to the caller.
        return tree;
    }

    /** Builds the tree directly from final counts using the block definition. */
    static long[] byDefinition(long[] a) {
        // One slot per count plus the unused slot 0.
        long[] tree = new long[a.length + 1];
        // Visit each internal index once.
        for (int i = 1; i <= a.length; i++) {
            // Sum the i & -i counts that end at i.
            for (int p = i - (i & -i); p < i; p++) tree[i] += a[p];
        }
        return tree;
    }

    public static void main(String[] args) {
        // Checks Example 1.
        long[] e1 = assign(6, new int[][]{{2, 5}, {0, 3}, {2, 1}, {5, 4}});
        if (!Arrays.equals(e1, new long[]{0, 3, 3, 1, 4, 0, 4})) throw new AssertionError("example 1 " + Arrays.toString(e1));
        // Checks Example 2, where a position repeats.
        long[] e2 = assign(5, new int[][]{{4, 9}, {4, 2}, {1, 6}});
        if (!Arrays.equals(e2, new long[]{0, 0, 6, 0, 6, 2})) throw new AssertionError("example 2 " + Arrays.toString(e2));
        // Checks random assignment lists against the tree built from the final counts.
        Random rnd = new Random(32);
        for (int round = 0; round < 300; round++) {
            int n = 1 + rnd.nextInt(30);
            int m = rnd.nextInt(40);
            int[][] ops = new int[m][2];
            long[] expected = new long[n];
            for (int j = 0; j < m; j++) {
                ops[j][0] = rnd.nextInt(n);
                ops[j][1] = rnd.nextInt(2001) - 1000;
                expected[ops[j][0]] = ops[j][1];
            }
            if (!Arrays.equals(assign(n, ops), byDefinition(expected))) throw new AssertionError("round " + round);
        }
    }
}verified
Edge Cases

Index Conversion

Author exercise

Problem Specification. Given an array a of n counts and a list of queries (left, right) with zero-based inclusive bounds, return the sum of a[left..right] for each query. Answer them with a Fenwick tree built from a, and convert between external and internal indexes at the boundary.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 10^5.
  • Bounds satisfy 0 <= left <= right < n.
  • Counts are long values with absolute value at most 10^9, and may be negative or 0.
  • Queries number at most 10^5.
  • Return is a long[] with one sum per query.

Example 1. Input a = [4, -2, 7, 0, 5, -3] and queries (0, 0), (0, 5), (2, 4), (5, 5), output 4, 11, 12, -3.

Example 2. Input the same a and the query (0, 2), output 9, which needs the empty prefix prefix(0).

Prerequisites. The two exercises above.

What This Exercise Changes. The boundary queries start at the first position and end at the last, where a wrong index conversion fails.

Hint

Which internal prefixes does the query (left, right) need, and what does the prefix for left = 0 return?

Algorithmic Solution (attempt the problem first)

Approach. Each external position converts to an internal index once, at the boundary.

The class stores positions one-based, so add(pos, delta) starts its loop at pos + 1. The method prefix(k) returns the sum of the first k counts, which are external positions 0 to k - 1. The inclusive range left..right is therefore prefix(right + 1) - prefix(left). When left is 0, prefix(0) returns 0 because the loop never runs, so no read of index -1 occurs. When right is n - 1, the call prefix(n) reads the last valid slot. An internal index of 0 would never advance, because 0 & -0 equals 0, and the program asserts that fact.

Complexity.

  • Time is O((n + q) log n), because the build performs n updates and each of the q queries performs two prefixes.
  • Space is O(n), for the tree array.
import java.util.Arrays;
import java.util.Random;

public final class FenwickRanges {
    /**
     * Fenwick tree over zero-based external positions with one-based internal storage.
     * Time: O(log n) per add and per prefix.
     * Space: O(n).
     * Invariant: tree[i] sums the i & -i counts ending at internal index i.
     */
    static final class Fenwick {
        // Internal one-based storage, with slot 0 unused.
        final long[] tree;

        Fenwick(int n) {
            // The extra slot keeps internal indexes 1..n valid.
            tree = new long[n + 1];
        }

        void add(int pos, long delta) {
            // Convert once: external position pos is internal index pos + 1.
            for (int i = pos + 1; i < tree.length; i += i & -i) {
                // Every visited block contains the changed position.
                tree[i] += delta;
            }
        }

        long prefix(int k) {
            // An empty prefix returns 0 because the loop does not run.
            long sum = 0;
            // Each step removes the lowest set bit of the index.
            for (int i = k; i > 0; i -= i & -i) {
                sum += tree[i];
            }
            return sum;
        }
    }

    /** Answers inclusive zero-based range queries; Time O((n + q) log n); Space O(n). */
    static long[] answer(long[] a, int[][] queries) {
        // Load the counts one add at a time.
        Fenwick f = new Fenwick(a.length);
        for (int p = 0; p < a.length; p++) f.add(p, a[p]);
        long[] out = new long[queries.length];
        // One answer per query.
        for (int j = 0; j < queries.length; j++) {
            // The inclusive range is a difference of two prefixes over the half-open range left..right + 1.
            out[j] = f.prefix(queries[j][1] + 1) - f.prefix(queries[j][0]);
        }
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        long[] a = {4, -2, 7, 0, 5, -3};
        long[] r = answer(a, new int[][]{{0, 0}, {0, 5}, {2, 4}, {5, 5}});
        if (!Arrays.equals(r, new long[]{4, 11, 12, -3})) throw new AssertionError("example 1 " + Arrays.toString(r));
        if (answer(a, new int[][]{{0, 2}})[0] != 9) throw new AssertionError("example 2");
        // Checks the Java fact behind the index trap: the low bit of 0 is 0, so a zero index never advances.
        int zero = 0;
        if ((zero & -zero) != 0) throw new AssertionError("low bit of zero");
        // Checks the empty prefix and the full prefix.
        Fenwick f = new Fenwick(a.length);
        for (int p = 0; p < a.length; p++) f.add(p, a[p]);
        if (f.prefix(0) != 0) throw new AssertionError("empty prefix");
        if (f.prefix(a.length) != 11) throw new AssertionError("full prefix");
        // Checks random arrays and all ranges against a brute-force loop.
        Random rnd = new Random(33);
        for (int round = 0; round < 200; round++) {
            int n = 1 + rnd.nextInt(30);
            long[] b = new long[n];
            for (int i = 0; i < n; i++) b[i] = rnd.nextInt(2001) - 1000;
            for (int l = 0; l < n; l++) {
                for (int rr = l; rr < n; rr++) {
                    long expected = 0;
                    for (int i = l; i <= rr; i++) expected += b[i];
                    if (answer(b, new int[][]{{l, rr}})[0] != expected) throw new AssertionError("round " + round + " " + l + " " + rr);
                }
            }
        }
    }
}verified
Pattern Recognition

Mutable Range Sum

LeetCode 307

Problem Specification. Design a class built from an integer array nums. The call update(index, val) assigns val to position index. The call sumRange(left, right) returns the total of positions left to right, both included. Indexes are zero-based.

Input Constraints. The limits are:

  • Length of nums is an int with 1 <= n <= 3 * 10^4.
  • Values are int values with absolute value at most 100.
  • Calls to either method number at most 3 * 10^4.
  • Bounds satisfy 0 <= left <= right < n and 0 <= index < n.
  • Return of sumRange is an int.

Algorithmic Solution (attempt the problem first)

Approach. A Fenwick tree plus a copy of the values supports both calls.

The constructor loads each value with an add. The method update computes the delta as the new value minus the stored one, adds it along the update path and stores the new value. The method sumRange returns a difference of two prefixes. The tree holds long sums internally, and the answer fits in an int under the stated limits, so the cast is safe. The invariant is that values[i] equals the current nums[i] and tree[i] sums the i & -i counts ending at internal index i.

Complexity.

  • Time is O(n log n) for construction and O(log n) for each call, because each call walks at most log2(n) + 1 blocks.
  • Space is O(n), for the values and tree arrays.
import java.util.Random;

public final class MutableRangeSum {
    /**
     * Supports point assignment and inclusive range sums on an int array.
     * Time: O(log n) per call after an O(n log n) build.
     * Space: O(n).
     * Invariant: values mirrors the array, and tree[i] sums the i & -i counts ending at i.
     */
    static final class NumArray {
        // Internal one-based sums, with slot 0 unused.
        private final long[] tree;
        // The current values let update compute its delta.
        private final int[] values;

        NumArray(int[] nums) {
            // Copy the input so later calls do not depend on the caller's array.
            values = nums.clone();
            tree = new long[nums.length + 1];
            // Load each value as an add on an all-zero tree.
            for (int p = 0; p < nums.length; p++) add(p, nums[p]);
        }

        private void add(int pos, long delta) {
            // The update path visits every block that contains pos.
            for (int i = pos + 1; i < tree.length; i += i & -i) tree[i] += delta;
        }

        private long prefix(int k) {
            long sum = 0;
            // Clearing the low bit moves to the next unread block.
            for (int i = k; i > 0; i -= i & -i) sum += tree[i];
            return sum;
        }

        void update(int index, int val) {
            // The delta replaces the old value with the new one.
            add(index, (long) val - values[index]);
            // Keep the mirror equal to the true array.
            values[index] = val;
        }

        int sumRange(int left, int right) {
            // Two prefixes bound the inclusive range; the result fits in an int by the constraints.
            return (int) (prefix(right + 1) - prefix(left));
        }
    }

    public static void main(String[] args) {
        // Checks Example 1: a query, an update, then the same query.
        NumArray na = new NumArray(new int[]{6, -1, 4, 3, 8});
        if (na.sumRange(1, 3) != 6) throw new AssertionError("before update");
        na.update(2, 10);
        if (na.sumRange(1, 3) != 12) throw new AssertionError("after update");
        // Checks Example 2 on the updated array.
        if (na.sumRange(0, 4) != 26) throw new AssertionError("full range");
        if (na.sumRange(4, 4) != 8) throw new AssertionError("single position");
        // Checks random operation sequences against a plain array with a fixed seed.
        Random rnd = new Random(34);
        for (int round = 0; round < 200; round++) {
            int n = 1 + rnd.nextInt(30);
            int[] b = new int[n];
            for (int i = 0; i < n; i++) b[i] = rnd.nextInt(201) - 100;
            NumArray s = new NumArray(b);
            for (int op = 0; op < 60; op++) {
                if (rnd.nextBoolean()) {
                    int idx = rnd.nextInt(n);
                    int v = rnd.nextInt(201) - 100;
                    b[idx] = v;
                    s.update(idx, v);
                } else {
                    int l = rnd.nextInt(n);
                    int r = l + rnd.nextInt(n - l);
                    int expected = 0;
                    for (int i = l; i <= r; i++) expected += b[i];
                    if (s.sumRange(l, r) != expected) throw new AssertionError("round " + round + " op " + op);
                }
            }
        }
    }

Problem

Why Minimum Queries Break Prefix Sums

A monitoring service keeps one response time per request in an array. Operators ask for the lowest response time between request l and request r. Between questions, a late measurement overwrites one stored value, and the next question must see it.

The Fenwick tree from the previous lesson answers a range sum as the difference of two prefix sums. That subtraction works because addition has an inverse. Minimum has no inverse. Knowing the lowest value of the first seven requests and of the first four requests does not reveal the lowest value of requests at positions 4 to 6, counting from 0. A structure for range minimum with updates needs a different design.

Simple approach

Scanning The Range On Every Query

The direct approach keeps the plain array. An update overwrites one cell, and a query scans every cell from l to r.

static long rangeMin(long[] a, int l, int r) {
    long best = Long.MAX_VALUE;        // larger than every stored value
    for (int i = l; i <= r; i++) {
        best = Math.min(best, a[i]);   // one comparison per scanned cell
    }
    return best;
}

static void overwrite(long[] a, int pos, long value) {
    a[pos] = value;                    // the update itself costs one write
}

Each update is cheap and each query is correct. The query cost grows with the length of the range, so a query over the whole array reads every cell.

Bottleneck

Every Query Pays For The Full Range

Predict first: The array holds 100,000 response times, and 100,000 queries each ask about a range of about 50,000 requests. Roughly how many cell reads happen, and what would a stored summary have to provide to avoid them?

About five billion cell reads, because each query reads half the array. To avoid them, the structure must keep minima of many ranges in advance, so a query combines a few stored minima and never reads the cells one by one.

Count The Cell Reads

A query over k cells costs O(k), so q queries over ranges of length up to n cost O(n * q) in total. With n = q = 100,000, the worst case is 10^10 reads. The update costs O(1), so the scan is balanced in the wrong place. All the cost sits in the queries, and queries are the common operation.

Rule Out Prefix Subtraction

Storing the minimum of every prefix does not help. When one value changes, many prefix minima change with it, so an update becomes O(n). Subtracting two prefix minima also fails. In the array [5, 2, 7, 1, 4, 3, 6, 8], the first seven cells and the first four cells both have minimum 1. The range from position 4 to 6 has minimum 3. The structure needs stored answers for ranges that are not prefixes.

Key idea

Store One Aggregate Per Node Range

Split The Array Into Halves

A segment tree is a binary tree in which each node owns one node range of positions. The root owns positions 0 to n - 1. A node that owns positions lo to hi splits at mid, which is (lo + hi) / 2. Its left child owns lo to mid, and its right child owns mid + 1 to hi. A leaf owns one position. Every node stores the aggregate of its node range, which is the minimum or the sum of the values at those positions.

The aggregate of a parent comes from its children alone. For a minimum, the parent stores the smaller of the two child values. For a sum, it stores their total. This works for any operator that is associative, meaning the grouping of three values does not change the result. Subtraction is never needed.

Answer A Query From Few Nodes

A query for positions l to r starts at the root and compares the node range with the query. Three cases cover everything. If the two ranges do not overlap, the node contributes the identity element, a value that leaves any result unchanged. That value is Long.MAX_VALUE for a minimum and 0 for a sum. If the node range lies fully inside the query, the node returns its stored aggregate without looking at its children. If the ranges partly overlap, the query recurses into both children and combines their answers.

At each depth, at most two nodes partly overlap the query. Every other visited node is a no-overlap or full-cover stop. A query therefore visits O(log n) nodes, since the tree has about log n levels.

Update By Recomputing Ancestors

A point assignment walks from the root to the leaf that owns the position. It writes the new value into the leaf. On the way back up, each ancestor recomputes its aggregate from its two children. Only the nodes on that one path change, so an update touches O(log n) nodes.

The invariant is that every node always stores the aggregate of exactly its node range. Build, query and update each preserve it, and the query depends on it.

State

Quantities To Track In The Tree

Track these items for each recursive call.

  • node is the index of the current tree node, with node 1 as the root and children 2 * node and 2 * node + 1.
  • lo and hi bound the node range of the current node, both inclusive.
  • mid splits the node range into the left half lo to mid and the right half mid + 1 to hi.
  • l and r bound the query range, both inclusive.
  • tree[node] holds the aggregate of the node range.

Query Stops At Full Cover

The query asks for the sum of positions 2 to 6. The root partly overlaps the query, so it recurses. Node 4 owns positions 0 and 1, which lie outside the query, so it returns the identity 0. The hardest step is node 7, which owns positions 6 and 7. It overlaps only in position 6, so it recurses again and picks up leaf 14 while leaf 15 returns the identity.

The answer combines three stored values from nodes 5, 6 and 14. Five array cells were covered, but only three stored values were added.

final class SegmentTree {
    private final int n;
    private final long[] tree;

    SegmentTree(long[] values) {
        n = values.length;
        tree = new long[4 * n];                        // enough room for every node index
        build(values, 1, 0, n - 1);
    }

    private void build(long[] v, int node, int lo, int hi) {
        if (lo == hi) { tree[node] = v[lo]; return; }  // a leaf stores one value
        int mid = (lo + hi) / 2;
        build(v, 2 * node, lo, mid);
        build(v, 2 * node + 1, mid + 1, hi);
        tree[node] = tree[2 * node] + tree[2 * node + 1];  // parent combines its children
    }

    void assign(int pos, long value) { assign(1, 0, n - 1, pos, value); }

    private void assign(int node, int lo, int hi, int pos, long value) {
        if (lo == hi) { tree[node] = value; return; }  // reached the leaf of pos
        int mid = (lo + hi) / 2;
        if (pos <= mid) assign(2 * node, lo, mid, pos, value);
        else assign(2 * node + 1, mid + 1, hi, pos, value);
        tree[node] = tree[2 * node] + tree[2 * node + 1];  // recompute on the way back up
    }

    long query(int l, int r) { return query(1, 0, n - 1, l, r); }

    private long query(int node, int lo, int hi, int l, int r) {
        if (r < lo || hi < l) return 0;                // no overlap: identity of addition
        if (l <= lo && hi <= r) return tree[node];     // full cover: stored aggregate
        int mid = (lo + hi) / 2;
        return query(2 * node, lo, mid, l, r)
             + query(2 * node + 1, mid + 1, hi, l, r); // partial overlap: combine both halves
    }
}

The class uses sums, so the identity is 0 and the combine is +. A minimum tree changes exactly two things. The identity becomes Long.MAX_VALUE, and Math.min replaces each +. The three query cases and the recompute on the way back up stay the same.

Build visits each of the O(n) nodes once. Assign and query each visit O(log n) nodes.

When to use it

When A Segment Tree Fits

Recognize The Pattern

Reach for a segment tree when an array receives point updates and range queries mix in any order. The operator must be associative, so the aggregate of a node range comes from its two children. It does not need an inverse. Range minimum, range maximum, range greatest common divisor and range sum all qualify.

The invariant is that each node stores the aggregate of exactly its node range, and every update restores it along one path. When a problem needs that guarantee and cannot subtract prefixes, the tree fits.

Choose Between A Fenwick Tree And This Tree

A Fenwick tree is shorter and faster by a constant factor, but it needs a sum-like operator with an inverse and answers prefixes. A segment tree answers any range directly for any associative operator. A static array with no updates is a false friend for this tree, because a prefix-sum array answers it with less machinery, and a sparse table, which precomputes the minimum of every range whose length is a power of two, answers range minimum on fixed data. A plain Fenwick tree is a false friend in the other direction, since it cannot hold a minimum under point assignment.

Avoid The Java Hazards

The tree array needs 4 * n entries for a recursive layout with arbitrary n, and a smaller array fails with ArrayIndexOutOfBoundsException on some sizes. Sums need long, because 100,000 values near 10^9 overflow int. The identity of a minimum must be Long.MAX_VALUE, and adding to it overflows, so combine minima only with Math.min. Recursion depth stays near log n, so the call stack is safe.

Prerequisites. The node range, the children split and the combine step from this lesson.

What This Exercise Changes. Baseline case: one recursive split and one combine over a whole array.

Hint

Algorithmic Solution (attempt the problem first)

Approach. The recursion writes each node only after both children return.

A call receives a node number and the node range lo to hi. A leaf stores the array value at lo. Any other node splits at mid = (lo + hi) / 2, recurses into children 2k and 2k + 1, and then stores the total of their two stored values. The invariant is that a finished node holds the exact sum of its node range, so a parent can trust both children when it adds them.

For [5, 2, 7, 1], the leaves 4 to 7 store 5, 2, 7 and 1. Node 2 stores 7, node 3 stores 8, and node 1 stores 15. The tree array has room for 4 * n entries, and a node-existence flag selects only the created nodes, in increasing node number, for the result.

Complexity.

  • Time is O(n), because the recursion creates 2n - 1 nodes and each does constant work.
  • Space is O(n) for the tree array and O(log n) for the recursion stack.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class BuildRangeSums {
    /**
     * Builds the sum tree and returns the stored sums of created nodes in node order.
     * Time: O(n), because each of the 2n - 1 nodes is written once.
     * Space: O(n) for the arrays plus O(log n) recursion depth.
     * Invariant: after build(node, lo, hi) returns, tree[node] equals the sum of nums[lo..hi].
     */
    static long[] build(int[] nums) {
        // The 4n size keeps every node index of an uneven split inside the array.
        long[] tree = new long[4 * nums.length];
        // The flag array records which node numbers were created, because some numbers stay unused.
        boolean[] made = new boolean[4 * nums.length];
        // Start at the root, which owns every position.
        fill(nums, tree, made, 1, 0, nums.length - 1);
        // Count the created nodes so the result array has the exact length.
        int count = 0;
        // One pass over all node numbers collects the created ones in increasing order.
        for (boolean m : made) {
            // Only created nodes belong to the result.
            if (m) count++;
        }
        // The result array receives the stored sums.
        long[] out = new long[count];
        // The cursor tracks the next free result slot.
        int w = 0;
        // Walk node numbers in increasing order, which is the order the problem asks for.
        for (int k = 0; k < tree.length; k++) {
            // Skip numbers that no node uses.
            if (made[k]) out[w++] = tree[k];
        }
        // Return the sums of all created nodes.
        return out;
    }

    private static void fill(int[] a, long[] tree, boolean[] made, int node, int lo, int hi) {
        // Mark the node as created, because later code must skip unused numbers.
        made[node] = true;
        // A leaf owns one position, so it stores that value and needs no children.
        if (lo == hi) { tree[node] = a[lo]; return; }
        // Splitting at the midpoint gives the left half lo..mid and the right half mid+1..hi.
        int mid = (lo + hi) / 2;
        // Finish the left child first, so its sum exists when the parent adds.
        fill(a, tree, made, 2 * node, lo, mid);
        // Finish the right child, which completes the inputs of the parent.
        fill(a, tree, made, 2 * node + 1, mid + 1, hi);
        // The parent stores the sum of its two finished children.
        tree[node] = tree[2 * node] + tree[2 * node + 1];
    }

    /** Oracle: lists node ranges by an explicit work list and sums each range directly. */
    static long[] oracle(int[] nums) {
        // The list maps position k to the node range of node k, or null when unused.
        List<int[]> ranges = new ArrayList<>();
        // Reserve enough entries, all unused at first.
        for (int k = 0; k < 4 * nums.length; k++) ranges.add(null);
        // The root owns every position.
        ranges.set(1, new int[]{0, nums.length - 1});
        // Scan node numbers upward, so each parent is placed before its children.
        for (int k = 1; k < ranges.size() / 2; k++) {
            // Skip numbers that no node uses.
            if (ranges.get(k) == null) continue;
            int lo = ranges.get(k)[0], hi = ranges.get(k)[1];
            // A node with more than one position gets two children.
            if (lo < hi) {
                int mid = (lo + hi) / 2;
                ranges.set(2 * k, new int[]{lo, mid});
                ranges.set(2 * k + 1, new int[]{mid + 1, hi});
            }
        }
        // Collect direct range sums for the created nodes in node order.
        List<Long> sums = new ArrayList<>();
        for (int[] rg : ranges) {
            // Skip unused numbers.
            if (rg == null) continue;
            long s = 0;
            // Sum the range directly with no tree.
            for (int i = rg[0]; i <= rg[1]; i++) s += nums[i];
            sums.add(s);
        }
        // Convert the list to the array form.
        long[] out = new long[sums.size()];
        for (int i = 0; i < out.length; i++) out[i] = sums.get(i);
        // Return the oracle answer.
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2 from the problem.
        if (!java.util.Arrays.equals(build(new int[]{5, 2, 7, 1}), new long[]{15, 7, 8, 5, 2, 7, 1})) throw new AssertionError("example 1");
        if (!java.util.Arrays.equals(build(new int[]{4, -1, 6}), new long[]{9, 3, 6, 4, -1})) throw new AssertionError("example 2");
        // Checks the smallest input of one value.
        if (!java.util.Arrays.equals(build(new int[]{9}), new long[]{9})) throw new AssertionError("single value");
        // Checks 500 random arrays against the oracle, with a fixed seed.
        Random rnd = new Random(31002);
        for (int t = 0; t < 500; t++) {
            int[] a = new int[1 + rnd.nextInt(40)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(2_000_001) - 1_000_000;
            int[] copy = a.clone();
            if (!java.util.Arrays.equals(build(a), oracle(a))) throw new AssertionError("random " + t);
            // The input array must stay unchanged.
            if (!java.util.Arrays.equals(a, copy)) throw new AssertionError("input mutated");
        }
    }

Point Assignment

Author exercise

Problem Specification. Use the sum tree from the first exercise. Process a list of assignments (pos, value) in order. Each assignment overwrites nums[pos] with value and recomputes every affected ancestor. For each assignment, return the number of nodes whose stored sum is rewritten, including the leaf, and the root sum afterwards.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 1000.
  • Assignments number at most 1000, and each pos satisfies 0 <= pos < n.
  • Values are int values with absolute value at most 10^6.
  • Result is a long[][] with one pair {rewritten, rootSum} per assignment.

Example 1. Input [5, 2, 7, 1] with assignments (2, 0) and (0, 10), output {3, 8} and {3, 13}.

Example 2. Input [1, 1, 1, 1, 1] with assignments (4, 6) and (0, 0), output {3, 10} and {4, 9}, because the tree for five values is uneven. The path to position 4 is shorter.

Prerequisites. The first exercise above.

What This Exercise Changes. Only the leaf changes, so the exercise recomputes aggregates along one root-to-leaf path and nowhere else.

Hint

Which nodes own the assigned position? Do the other nodes change?

Algorithmic Solution (attempt the problem first)

Approach. An assignment changes one leaf, so only its ancestors can hold a stale sum.

The recursion descends toward the leaf that owns pos. It chooses the left child when pos <= mid and the right child otherwise. At the leaf it writes the new value. On the way back, each node on the path recomputes its sum from its two children, and the code counts each rewrite. Nodes off the path keep their node ranges and values, so they are never read for rewriting.

The invariant is that after the call returns, every node holds the sum of its node range under the new array. For five values, the path to position 4 has 3 nodes and the path to position 0 has 4, because the split of five positions is uneven.

Complexity.

  • Time is O(log n) per assignment, because the path has one node per level.
  • Space is O(n) for the tree and O(log n) for the recursion stack.
import java.util.Random;

public final class PointAssignment {
    private final long[] tree;
    private final int n;
    private int rewritten;

    /**
     * Builds the sum tree for the given array.
     * Time: O(n). Space: O(n).
     * Invariant: tree[node] equals the sum of the node range of node.
     */
    PointAssignment(int[] nums) {
        // Remember the length so every call starts from the root range.
        n = nums.length;
        // The 4n size covers every node number of an uneven split.
        tree = new long[4 * n];
        // Build from the root over positions 0..n-1.
        build(nums, 1, 0, n - 1);
    }

    private void build(int[] a, int node, int lo, int hi) {
        // A leaf stores one array value.
        if (lo == hi) { tree[node] = a[lo]; return; }
        // The midpoint splits the node range into two halves.
        int mid = (lo + hi) / 2;
        build(a, 2 * node, lo, mid);
        build(a, 2 * node + 1, mid + 1, hi);
        // The parent combines the finished children.
        tree[node] = tree[2 * node] + tree[2 * node + 1];
    }

    /**
     * Assigns one value and returns {rewritten nodes, root sum}.
     * Time: O(log n), because one node per level changes.
     * Space: O(log n) for the recursion stack.
     * Invariant: only nodes whose node range contains pos are rewritten.
     */
    long[] assign(int pos, int value) {
        // Reset the counter so each assignment reports its own rewrites.
        rewritten = 0;
        // Descend from the root toward the owner leaf of pos.
        walk(1, 0, n - 1, pos, value);
        // Return the count of rewrites and the new total of the whole array.
        return new long[]{rewritten, tree[1]};
    }

    private void walk(int node, int lo, int hi, int pos, int value) {
        // The leaf of pos receives the new value; this is one rewrite.
        if (lo == hi) { tree[node] = value; rewritten++; return; }
        int mid = (lo + hi) / 2;
        // Only the half that owns pos can contain the leaf, so the other half is skipped.
        if (pos <= mid) walk(2 * node, lo, mid, pos, value);
        else walk(2 * node + 1, mid + 1, hi, pos, value);
        // On the way back, the ancestor recomputes from its children; this is one rewrite.
        tree[node] = tree[2 * node] + tree[2 * node + 1];
        rewritten++;
    }

    public static void main(String[] args) {
        // Checks Example 1: two assignments on four values.
        PointAssignment p = new PointAssignment(new int[]{5, 2, 7, 1});
        if (!java.util.Arrays.equals(p.assign(2, 0), new long[]{3, 8})) throw new AssertionError("example 1a");
        if (!java.util.Arrays.equals(p.assign(0, 10), new long[]{3, 13})) throw new AssertionError("example 1b");
        // Checks Example 2: the unbalanced tree of five values has paths of length 3 and 4.
        PointAssignment q = new PointAssignment(new int[]{1, 1, 1, 1, 1});
        if (!java.util.Arrays.equals(q.assign(4, 6), new long[]{3, 10})) throw new AssertionError("example 2a");
        if (!java.util.Arrays.equals(q.assign(0, 0), new long[]{4, 9})) throw new AssertionError("example 2b");
        // Checks random sequences against a direct array and a depth count, with a fixed seed.
        Random rnd = new Random(31102);
        for (int t = 0; t < 300; t++) {
            int n = 1 + rnd.nextInt(30);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(2001) - 1000;
            PointAssignment s = new PointAssignment(a);
            for (int step = 0; step < 20; step++) {
                int pos = rnd.nextInt(n), val = rnd.nextInt(2001) - 1000;
                a[pos] = val;
                long total = 0;
                for (int v : a) total += v;
                long[] got = s.assign(pos, val);
                // The oracle counts the nodes on the path by walking the ranges directly.
                int lo = 0, hi = n - 1, len = 1;
                while (lo < hi) {
                    int mid = (lo + hi) / 2;
                    if (pos <= mid) hi = mid; else lo = mid + 1;
                    len++;
                }

No Overlap And Full Cover

Author exercise

Problem Specification. Given n and a query range l to r, run the query on the tree for n positions, using the node numbering from the first exercise. Return two lists of node numbers, each in the order the recursion reaches them. The first list holds the nodes that return their stored sum because their node range lies fully inside the query. The second list holds the nodes that return the identity 0 because their node range does not overlap the query.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 1000.
  • Query satisfies 0 <= l <= r < n, and both ends are inclusive.
  • Recursion stops at a node as soon as it is a full cover or a no-overlap node.
  • Result is two int lists, first the full-cover nodes, then the no-overlap nodes.

Example 1. Input n = 8, query 2 to 6, output full cover [5, 6, 14] and no overlap [4, 15].

Example 2. Input n = 5, query 1 to 1, output full cover [9] and no overlap [8, 5, 3], so three nodes off the path return the identity.

Prerequisites. The three query cases from this lesson.

What This Exercise Changes. The question moves from the sum to the stopping rule, so each node returns the identity or its stored value and never recurses further.

Hint

Which test comes first, no overlap or full cover? Which nodes does a partly overlapping node still visit?

Algorithmic Solution (attempt the problem first)

Approach. The check for no overlap runs first, then the check for full cover, then the split.

A node whose node range has hi < l or lo > r shares no position with the query, so it returns the identity and the code records its number. A node whose node range lies inside l..r returns its stored value, and the code records it as a full cover. Any other node overlaps in part, so it recurses into both children and records nothing itself.

Both stopping checks must run before the split, or the recursion would descend to every leaf. A non-empty node range cannot be both disjoint and inside the query, so the two stops never conflict. For n = 5 and the query 1 to 1, nodes 8, 5 and 3 return the identity and node 9 is the only full cover.

Complexity.

  • Time is O(log n) for the recursion, because at most two partial nodes exist per level and each has two children.
  • Space is O(log n) for the stack plus the two output lists, which hold O(log n) nodes.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class NoOverlapFullCover {
    /**
     * Runs the query recursion and records full-cover and no-overlap node numbers.
     * Time: O(log n), because at most two nodes per level overlap in part.
     * Space: O(log n) for the stack and the recorded lists.
     * Invariant: a recorded node is a child of a node that overlaps the query in part.
     */
    static List<List<Integer>> classify(int n, int l, int r) {
        // Two lists collect the node numbers by outcome, in recursion order.
        List<Integer> full = new ArrayList<>(), none = new ArrayList<>();
        // Start at the root, which owns positions 0..n-1.
        visit(1, 0, n - 1, l, r, full, none);
        // Return the full-cover list first, then the no-overlap list.
        return List.of(full, none);
    }

    private static void visit(int node, int lo, int hi, int l, int r, List<Integer> full, List<Integer> none) {
        // No overlap comes first: the node range lies left or right of the query.
        if (r < lo || hi < l) { none.add(node); return; }
        // Full cover: every position of the node range is inside the query.
        if (l <= lo && hi <= r) { full.add(node); return; }
        // Partial overlap: split the node range and ask both children.
        int mid = (lo + hi) / 2;
        visit(2 * node, lo, mid, l, r, full, none);
        visit(2 * node + 1, mid + 1, hi, l, r, full, none);
    }

    /** Oracle: lists every node in pre-order, then filters by the definition with the parent's range. */
    static List<List<Integer>> oracle(int n, int l, int r) {
        // Collect all nodes with their ranges and parent numbers in pre-order.
        List<int[]> all = new ArrayList<>();
        collect(1, 0, n - 1, all);
        List<Integer> full = new ArrayList<>(), none = new ArrayList<>();
        for (int[] e : all) {
            // The root has no parent and the query is never empty, so it is never recorded alone.
            if (e[0] == 1) continue;
            // Look up the parent's range from the same list.
            int[] par = null;
            for (int[] f : all) if (f[0] == e[0] / 2) par = f;
            boolean parentInside = l <= par[1] && par[2] <= r;
            boolean parentOutside = r < par[1] || par[2] < l;
            // A recorded node needs a parent that overlaps in part.
            if (parentInside || parentOutside) continue;
            if (l <= e[1] && e[2] <= r) full.add(e[0]);
            else if (r < e[1] || e[2] < l) none.add(e[0]);
        }
        // The root itself is a full cover when the query spans every position.
        if (l == 0 && r == n - 1) full.add(1);
        return List.of(full, none);
    }

    private static void collect(int node, int lo, int hi, List<int[]> out) {
        // Record node number, lo and hi in pre-order.
        out.add(new int[]{node, lo, hi});
        // Leaves have no children.
        if (lo == hi) return;
        int mid = (lo + hi) / 2;
        collect(2 * node, lo, mid, out);
        collect(2 * node + 1, mid + 1, hi, out);
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        if (!classify(8, 2, 6).equals(List.of(List.of(5, 6, 14), List.of(4, 15)))) throw new AssertionError("example 1");
        if (!classify(5, 1, 1).equals(List.of(List.of(9), List.of(8, 5, 3)))) throw new AssertionError("example 2");
        // Checks a query that spans the whole array: the root is the only stop.
        if (!classify(5, 0, 4).equals(List.of(List.of(1), List.of()))) throw new AssertionError("whole array");
        // Checks every query for sizes 1 to 25 against the oracle.
        for (int n = 1; n <= 25; n++) {
            for (int l = 0; l < n; l++) {
                for (int r = l; r < n; r++) {
                    if (!classify(n, l, r).equals(oracle(n, l, r))) throw new AssertionError("n=" + n + " l=" + l + " r=" + r);
                }
            }
        }
        // Checks random larger sizes with a fixed seed.
        Random rnd = new Random(31202);
        for (int t = 0; t < 200; t++) {
            int n = 26 + rnd.nextInt(300);
            int l = rnd.nextInt(n), r = l + rnd.nextInt(n - l);
            if (!classify(n, l, r).equals(oracle(n, l, r))) throw new AssertionError("large " + t);
        }
    }

Mutable Range Sum

LeetCode 307

Problem Specification. Design a class NumArray built from an integer array nums. The method update(index, val) sets nums[index] to val. The method sumRange(left, right) returns the sum of nums[left] through nums[right], both inclusive. Support calls in any order, and let each call see all earlier updates.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 30000.
  • Values are int values with absolute value at most 100.
  • Calls number at most 30000, in any order.
  • Indexes satisfy 0 <= left <= right < n and 0 <= index < n.

Example 1. Input [3, -2, 5, 1, 4], then sumRange(1, 3), update(2, 9), sumRange(1, 3), sumRange(0, 4), output 4, 8, 15.

Example 2. Input [7], then sumRange(0, 0), update(0, -3), sumRange(0, 0), output 7, -3.

Prerequisites. All three exercises above.

What This Exercise Changes. The array now changes between queries, so a fixed prefix-sum array fails and the tree repairs one path per update.

Hint

Which operator combines two node ranges? Does a sum need a tree, or would prefix sums be enough here?

Algorithmic Solution (attempt the problem first)

Approach. The recognition is that updates between queries rule out a fixed prefix-sum array, and sums need no inverse in a tree.

This solution stores the tree in a bottom-up layout. The leaf count size is the smallest power of two that is at least n. Leaf i lives at size + i, and node k has children 2k and 2k + 1, so node 1 is the root. An update writes the leaf and then halves the node number, recomputing each ancestor. A query over the half-open range [left, right + 1) moves two cursors up the tree. A cursor that is a right child contributes its node and steps inward, and a cursor that is a left child just moves to its parent.

The invariant is that every node stores the sum of the leaves below it. Padding leaves hold 0, which is the identity of addition, so they never change a sum.

Complexity.

  • Time is O(n) to build and O(log n) per update and per query, because each walks one level per step.
  • Space is O(n), because the array has 2 * size entries and size is under 2n.
import java.util.Random;

public final class NumArray {
    private final int size;
    private final long[] tree;

    /**
     * Builds the tree from the array.
     * Time: O(n). Space: O(n).
     * Invariant: tree[k] = tree[2k] + tree[2k+1] for every inner node k.
     */
    NumArray(int[] nums) {
        // Find the smallest power of two that holds every position.
        int s = 1;
        while (s < nums.length) s *= 2;
        size = s;
        // Leaves occupy size..2*size-1; padding leaves stay 0, the identity of addition.
        tree = new long[2 * size];
        // Copy the values into their leaves.
        for (int i = 0; i < nums.length; i++) tree[size + i] = nums[i];
        // Fill the inner nodes from the last to the first, so children come before parents.
        for (int k = size - 1; k >= 1; k--) tree[k] = tree[2 * k] + tree[2 * k + 1];
    }

    /**
     * Sets nums[index] to val.
     * Time: O(log n), one node per level. Space: O(1).
     * Invariant: after the loop, every ancestor of the leaf equals the sum of its children.
     */
    void update(int index, int val) {
        // Start at the leaf and write the new value.
        int k = size + index;
        tree[k] = val;
        // Move to the parent until the root is rewritten; this costs one step per level.
        for (k /= 2; k >= 1; k /= 2) {
            // Each ancestor recomputes from its two children.
            tree[k] = tree[2 * k] + tree[2 * k + 1];
        }
    }

    /**
     * Returns the sum of nums[left..right], both inclusive.
     * Time: O(log n), because each cursor climbs at most one level per step. Space: O(1).
     * Invariant: total plus the sum of leaves in [lo, hi) equals the answer.
     */
    long sumRange(int left, int right) {
        long total = 0;
        // Cursors cover the half-open leaf range [lo, hi).
        int lo = left + size, hi = right + 1 + size;
        // The loop ends when the cursors meet, which takes O(log n) steps.
        while (lo < hi) {
            // A right-child cursor is not covered by its parent's left side, so it adds itself.
            if ((lo & 1) == 1) total += tree[lo++];
            // A right-end cursor that is odd points past a right child, so the node before it is added.
            if ((hi & 1) == 1) total += tree[--hi];
            // Both cursors move to their parents, one level up.
            lo /= 2;
            hi /= 2;
        }
        // Return the accumulated sum.
        return total;
    }

    public static void main(String[] args) {
        // Checks Example 1: the three results 4, 8 and 15.
        NumArray a = new NumArray(new int[]{3, -2, 5, 1, 4});
        if (a.sumRange(1, 3) != 4) throw new AssertionError("example 1a");
        a.update(2, 9);
        if (a.sumRange(1, 3) != 8) throw new AssertionError("example 1b");
        if (a.sumRange(0, 4) != 15) throw new AssertionError("example 1c");
        // Checks Example 2: a single value, updated.
        NumArray b = new NumArray(new int[]{7});
        if (b.sumRange(0, 0) != 7) throw new AssertionError("example 2a");
        b.update(0, -3);
        if (b.sumRange(0, 0) != -3) throw new AssertionError("example 2b");
        // Checks random mixed calls against a direct array, with a fixed seed.
        Random rnd = new Random(31302);
        for (int t = 0; t < 300; t++) {
            int n = 1 + rnd.nextInt(40);
            int[] ref = new int[n];
            for (int i = 0; i < n; i++) ref[i] = rnd.nextInt(201) - 100;
            NumArray s = new NumArray(ref.clone());
            for (int step = 0; step < 60; step++) {
                if (rnd.nextBoolean()) {
                    int idx = rnd.nextInt(n), v = rnd.nextInt(201) - 100;
                    ref[idx] = v;
                    s.update(idx, v);
                } else {
                    int l = rnd.nextInt(n), r = l + rnd.nextInt(n - l);
                    long want = 0;
                    for (int i = l; i <= r; i++) want += ref[i];
                    if (s.sumRange(l, r) != want) throw new AssertionError("random " + t + " step " + step);
                }
            }
        }
    }

Problem

Why Range Updates Slow The Tree

A pricing service stores one price per product in a segment tree. Every night a promotion subtracts the same amount from 40,000 consecutive products. All day long, a dashboard asks for the total price of other consecutive ranges.

The segment tree from the previous lesson answers a range sum in O(log n). It also changes one position in O(log n). The nightly promotion is not a single position, though. It is a range update, where one call changes every position between two indexes by the same amount. The tree has no operation for that. The service needs one call that changes 40,000 prices and still leaves every later sum query correct and fast.

Simple approach

Update Every Position One At A Time

This lesson writes ranges as half-open [lo, hi), which includes lo and excludes hi, where the previous lesson used inclusive ranges. The direct approach reuses the point update. For each position in the range, it descends from the root to that leaf, adds the amount and recomputes the sums on the way back up.

// tree[k] holds the sum of positions [lo, hi) for node k; node 1 is the root.
static void pointAdd(long[] tree, int k, int lo, int hi, int pos, long delta) {
    tree[k] += delta;                          // every node on the path to pos gains delta
    if (hi - lo == 1) return;                  // a leaf has no children to visit
    int mid = (lo + hi) >>> 1;
    if (pos < mid) pointAdd(tree, 2 * k, lo, mid, pos, delta);
    else pointAdd(tree, 2 * k + 1, mid, hi, pos, delta);
}

static void rangeAddByPoints(long[] tree, int n, int l, int r, long delta) {
    for (int pos = l; pos < r; pos++) {        // one full descent per changed position
        pointAdd(tree, 1, 0, n, pos, delta);
    }
}

Each descent visits one node per level. A range of k positions therefore costs k descents. The sums stay correct after every call, but the cost grows with the length of the range.

Bottleneck

One Descent Per Position Costs Too Much

Predict first: A segment tree covers 131,072 positions. One update adds 1 to every position. Roughly how many nodes does the one-position-at-a-time update visit?

About 2.4 million node visits for a single update. Each of the 131,072 descents visits 18 nodes. A method that stops at the root, which already covers the whole range, needs far fewer visits.

Count The Visits

The tree with 131,072 leaves has 18 levels. One descent visits 18 nodes, so the full-range update makes 131,072 times 18 visits, which is about 2.36 million. A workload of 100,000 such updates costs about 2.4 times 10^11 visits. The range update costs O(k log n) for a range of length k, which is O(n log n) in the worst case. A sum query still costs only O(log n), so the updates dominate everything.

See Why Skipped Children Are Wrong

A range query already avoids visiting every leaf. It stops at nodes whose range lies entirely inside the query range and reads their stored sums. A range update can stop at the same nodes. A node that covers positions lo to hi and lies inside the update range gains delta * (hi - lo) in its own sum, and the update stops there. At most about 2 log n nodes qualify, so the visit count drops to O(log n).

That shortcut leaves a problem. The children of a covered node still hold their old sums. A later query that descends below that node reads those old numbers and returns a wrong total. The structure must remember the skipped work and apply it when a query or update needs the children.

Key idea

Remember The Update On The Node

Store The Update As A Lazy Tag

The fix keeps a second number at each node, called the lazy tag. The tag stores the amount that every position under the node has gained but that the node's children do not know about yet. A covered node updates its own sum immediately and adds delta to its tag. It leaves the children alone.

The invariant is that a lazy tag records an update already applied to the node's sum but not yet pushed to the children. A node's stored sum is correct exactly when no ancestor holds a pending tag. A query or update that enters a node therefore clears the tags above it first.

Push Down Before You Descend

Any operation that must look inside a node first performs a push down. The push down moves the node's tag to both children in one step. Each child adds tag * childLength to its sum and adds tag to its own tag. The node then sets its tag to 0, so the update is passed along exactly once.

After the push down, both children hold correct sums, and the descent can continue safely. Updates and queries both push before they recurse. A fully covered node never needs a push, because it uses only its own sum. This is why every operation still visits only O(log n) nodes.

Combine Tags In The Right Order

Addition tags combine by adding the amounts, because adding 3 and then 4 equals adding 7 in either order. A different kind of update shows why the combination rule needs care. Suppose an update sets every position to a value v, and a node already holds a pending tag. The tag composition rule decides the result. A new assignment replaces whatever tag exists, because the old values no longer matter. A new addition applied after an assignment of v changes the assignment to v + delta. Reversing the order gives a different answer, so the order of composition is part of the data structure's contract. For example, a node of length 4 with sum 10 receives add 3 and then set 5. The tag becomes set 5, and the sum becomes 20. In the opposite order, set 5 and then add 3 give the tag set 8 and the sum 32.

State

Quantities Stored At Each Node

The lazy tree keeps two arrays indexed by node number, with node 1 as the root.

  • sum[k] holds the total of the positions under node k, including every tag already applied at k.
  • add[k] holds the pending amount per position that node k has not passed to its children. This pending amount is the lazy tag.
  • lo and hi describe the half-open range [lo, hi) of positions that node k covers. The range includes lo and excludes hi, so its length hi - lo scales an amount into a change of the sum.

This lesson uses half-open ranges where the previous lesson used inclusive ones, because the length hi - lo then needs no + 1. Both arrays hold long values, because a delta times a length easily exceeds the int range. Each array needs 4 * n slots to hold every node safely.

Walkthrough

Add To A Range, Then Query It

The array is 3, 1, 4, 1, 5, 9, 2, 6. The tree has node 1 as the root over [0, 8). The pointers lo and hi mark the range of the node being visited.

Add 5 To Positions 2 Through 6

The update covers [2, 7). The root and the nodes over [0, 4) and [4, 8) overlap it only in part, so each descends. Node 5 covers [2, 4) and lies fully inside. Its sum grows from 5 to 15, and its tag becomes 5. Node 6 covers [4, 6) and does the same, and its sum grows from 14 to 24.

The range [6, 8) is again partial. Its left child covers only position 6, and that single leaf gains 5. After the recursion returns, each ancestor recomputes its sum from its children. The root ends with 56, which is the old total 31 plus 5 times 5 positions.

The hardest step is the stop at node 5. Positions 2 and 3 now hold 9 and 6 in truth, but the leaves under node 5 still hold 4 and 1.

Query The Sum Of Positions 3 To 5

The query covers [3, 6). The descent reaches node 5 over [2, 4), and this node overlaps the query in part, so it must look at its children. Node 5 holds the tag 5, so it pushes first. Its left child, covering position 2, becomes 9. Its right child, covering position 3, becomes 6.

The query takes the 6 from position 3. Node 6 covers [4, 6) and lies fully inside, so it contributes its stored sum 24 without any push. The total is 30, which equals 6 plus 10 plus 14 in the updated array.

Code

Implement The Lazy Sum Tree

final class LazySumTree {
    private final int n;
    private final long[] sum;   // sum[k]: total of node k's range, with its own tag applied
    private final long[] add;   // add[k]: amount per position not yet passed to the children

    LazySumTree(int[] a) {
        n = a.length;
        sum = new long[4 * n];
        add = new long[4 * n];
        build(1, 0, n, a);
    }

    private void build(int k, int lo, int hi, int[] a) {
        if (hi - lo == 1) { sum[k] = a[lo]; return; }
        int mid = (lo + hi) >>> 1;
        build(2 * k, lo, mid, a);
        build(2 * k + 1, mid, hi, a);
        sum[k] = sum[2 * k] + sum[2 * k + 1];
    }

    private void applyTag(int k, int lo, int hi, long delta) {
        sum[k] += delta * (hi - lo);      // the sum changes by the amount times the length
        add[k] += delta;                  // the children learn about it only at push time
    }

    private void pushDown(int k, int lo, int hi) {
        if (add[k] == 0) return;          // nothing is pending, so the children are current
        int mid = (lo + hi) >>> 1;
        applyTag(2 * k, lo, mid, add[k]);
        applyTag(2 * k + 1, mid, hi, add[k]);
        add[k] = 0;                       // the pending amount is passed along exactly once
    }

    void rangeAdd(int l, int r, long delta) { rangeAdd(1, 0, n, l, r, delta); }

    private void rangeAdd(int k, int lo, int hi, int l, int r, long delta) {
        if (r <= lo || hi <= l) return;                        // no overlap
        if (l <= lo && hi <= r) { applyTag(k, lo, hi, delta); return; }  // full cover
        pushDown(k, lo, hi);                                   // partial overlap: children must be current
        int mid = (lo + hi) >>> 1;
        rangeAdd(2 * k, lo, mid, l, r, delta);
        rangeAdd(2 * k + 1, mid, hi, l, r, delta);
        sum[k] = sum[2 * k] + sum[2 * k + 1];                  // recompute from the updated children
    }

    long rangeSum(int l, int r) { return rangeSum(1, 0, n, l, r); }

    private long rangeSum(int k, int lo, int hi, int l, int r) {
        if (r <= lo || hi <= l) return 0;
        if (l <= lo && hi <= r) return sum[k];
        pushDown(k, lo, hi);
        int mid = (lo + hi) >>> 1;
        return rangeSum(2 * k, lo, mid, l, r) + rangeSum(2 * k + 1, mid, hi, l, r);
    }
}

The two public methods take half-open ranges [l, r) with zero-based positions. Both operations share the same three cases: no overlap, full cover and partial overlap. Only the partial case descends, and it pushes first. Both methods run in O(log n) time on a tree built in O(n).

When to use it

When Lazy Propagation Applies

Recognize The Pattern

Use lazy propagation when updates affect whole ranges and queries ask for range aggregates, with both mixed in any order. Immediate descent to every leaf would cost too much. The recognition cue is a range update and a range query on the same array.

The state invariant is that each tag is already part of its node's sum and is not yet part of its children's sums. Every operation that descends below a node must push that node's tag first. Forgetting one push breaks the invariant silently, and the first symptom is a wrong sum much later.

Reject The False Friends

A difference array supports range addition in O(1), but it answers a range sum only after a rebuild. It is a false friend when updates and queries interleave. A plain segment tree is another false friend, because it handles point updates only.

Lazy tags also require that an update can be applied to a node's aggregate from the node's length alone. Addition to a sum has that property. Adding to a maximum needs no length at all. Some aggregates have no such formula and cannot use a tag.

Watch The Java Hazards

Multiply a delta by the range length in long. An int product of 10^9 and 10^5 overflows silently. Size the arrays at 4 * n, because a tree over a length that is not a power of two can need nodes beyond 2 * n. Keep the half-open convention in every comparison. A mix of inclusive and half-open bounds produces off-by-one errors that tests with small ranges often miss.

Range Add One Node

Input Constraints. The limits are:

  • Deltas are long values with absolute value at most 10^9, and the list has at most 10^3 entries.

Example 1. Input len = 4, S = 10, deltas 3, -1, 2. Output sum 26 and tag 4.

Example 2. Input len = 100000, S = 0, deltas 10^9, 10^9, 10^9. Output sum 300000000000000 and tag 3000000000, so both values exceed the int range.

Prerequisites. The sum and add arrays from this lesson.

What This Exercise Changes. Baseline case: one node absorbs an update by length and stores the remainder as a pending amount.

Hint

Does the sum change by the delta or by the delta times the length? Which type holds the tag?

Algorithmic Solution (attempt the problem first)

Approach. The node keeps its sum and its pending tag as two long values. Applying a delta multiplies it by the node length, adds that product to the sum and adds the delta itself to the tag.

The invariant is that the sum always equals the starting sum plus the tag times the length. The tag stays in per-position units, so a later push down can hand it to a child of any length. The product uses long arithmetic, because a delta of 10^9 times a length of 10^5 exceeds the int range. An empty list leaves both values unchanged.

Complexity.

  • Time is O(m) for m deltas, because each delta costs one multiplication and two additions.
  • Space is O(1), because the node stores only the sum and the tag.
import java.util.Random;

public final class RangeAddOneNode {
    /**
     * Applies whole-node deltas and returns {sum, tag}.
     * Time: O(m) for m deltas. Space: O(1) beyond the two-element result.
     * Invariant: sum equals startSum + tag * len after every delta.
     */
    static long[] apply(int len, long startSum, long[] deltas) {
        // The sum starts at the stored value and the pending tag starts empty.
        long sum = startSum, tag = 0;
        // One iteration per delta, which is the only source of cost.
        for (long d : deltas) {
            // The delta reaches every one of the len positions, so the sum moves by d * len in long arithmetic.
            sum += d * len;
            // The tag keeps the per-position amount for the children, so it does not scale by len.
            tag += d;
        }
        // Return both values so the caller can compare them with the expected result.
        return new long[]{sum, tag};
    }

    /** Oracle: materializes the positions and adds each delta to every one of them. */

        // Spread the starting sum over positions: the first holds the remainder, the others hold 0.
        long[] pos = new long[len];

        long tag = 0;

        for (long d : deltas) {
            for (int i = 0; i < len; i++) pos[i] += d;
            tag += d;
        }
        // Sum the positions to obtain the true node total.
        long s = 0;
        for (long x : pos) s += x;
        return new long[]{s, tag};
    }

Push Before Descent

Author exercise

Problem Specification. A parent node has a left child covering a positions and a right child covering b positions. Each of the three nodes has a stored sum and a pending tag, and the parent's sum already includes the parent's tag. Perform one push down from the parent. Each child adds tag * childLength to its sum and adds tag to its own tag, and the parent's tag becomes 0. Return the parent tag, then the sum and tag of the left child, then the sum and tag of the right child. A second push down must change nothing.

Input Constraints. The limits are:

  • a and b are int values with 1 <= a, b <= 10^5.
  • Sums and tags are long values with absolute value at most 10^12.
  • Parent tag may be 0, positive or negative.
  • Return value is the five numbers in the order stated above.

Example 1. Input a = 2, b = 3, parent tag 4, left sum 10 and tag 1, right sum 30 and tag 0. Output parent tag 0, left sum 18 and tag 5, right sum 42 and tag 4.

Example 2. Input a = 1, b = 4, parent tag -3, left sum 5 and tag 0, right sum -2 and tag 2. Output parent tag 0, left sum 2 and tag -3, right sum -14 and tag -1.

Prerequisites. The previous exercise.

What This Exercise Changes. The tag moves from the parent to two children, and the code must hand it over exactly once.

Hint

Does the push scale the tag by the length of the parent or by the length of each child? What happens on a second call?

Algorithmic Solution (attempt the problem first)

Approach. The push scales the parent tag by each child's own length and not by the parent's length. Each child gains tag * childLength in its sum and tag in its own tag. The parent tag then becomes 0.

The invariant is that the parent's sum equals the sum of its children's sums after the push, and it is equal to the parent's sum before the push when the children were consistent with the parent tag. Because the parent tag is cleared, a second push finds nothing to move and changes nothing. Skipping the clearing step would apply the same amount twice.

Complexity.

  • Time is O(1), because the push touches exactly three nodes and does a fixed number of operations.
  • Space is O(1), because the result holds five numbers.
import java.util.Random;

public final class PushBeforeDescent {
    /**
     * Pushes the parent tag to both children and returns {parentTag, leftSum, leftTag, rightSum, rightTag}.
     * Time: O(1). Space: O(1).
     * Invariant: afterwards the parent tag is 0, so a repeated push moves nothing.
     */
    static long[] push(int a, int b, long parentTag, long leftSum, long leftTag, long rightSum, long rightTag) {
        // A zero tag means the children are already current, so there is nothing to move.
        if (parentTag != 0) {
            // The left child covers a positions, so its sum grows by tag times a.
            leftSum += parentTag * a;
            // The left child keeps the amount as its own pending tag for its children.
            leftTag += parentTag;
            // The right child covers b positions, so its sum grows by tag times b.
            rightSum += parentTag * b;
            // The right child also records the amount as pending.
            rightTag += parentTag;
            // Clearing the parent tag makes the transfer happen exactly once.
            parentTag = 0;
        }
        // Return the five values in the order the problem states.
        return new long[]{parentTag, leftSum, leftTag, rightSum, rightTag};
    }

    public static void main(String[] args) {
        // Checks Example 1 against the stated output.
        if (!java.util.Arrays.equals(push(2, 3, 4, 10, 1, 30, 0), new long[]{0, 18, 5, 42, 4})) throw new AssertionError("example 1");
        // Checks Example 2 with a negative parent tag and a nonzero right tag.
        if (!java.util.Arrays.equals(push(1, 4, -3, 5, 0, -2, 2), new long[]{0, 2, -3, -14, -1})) throw new AssertionError("example 2");
        // Compares with a model that rebuilds each child sum from its explicit positions, using a fixed seed.
        Random rnd = new Random(31_03_02);
        for (int t = 0; t < 500; t++) {
            int a = 1 + rnd.nextInt(5), b = 1 + rnd.nextInt(5);
            long pt = rnd.nextInt(21) - 10;
            long ls = rnd.nextInt(101) - 50, lt = rnd.nextInt(11) - 5;
            long rs = rnd.nextInt(101) - 50, rt = rnd.nextInt(11) - 5;
            long[] got = push(a, b, pt, ls, lt, rs, rt);
            // Model: every position under the left child gains pt, so the sum gains pt once per position.
            long modelLeft = ls;
            for (int i = 0; i < a; i++) modelLeft += pt;
            long modelRight = rs;
            for (int i = 0; i < b; i++) modelRight += pt;
            if (got[0] != 0 || got[1] != modelLeft || got[3] != modelRight || got[2] != lt + pt || got[4] != rt + pt) throw new AssertionError("mismatch at trial " + t);
            // A second push must change nothing, which proves the transfer happens once.
            long[] again = push(a, b, got[0], got[1], got[2], got[3], got[4]);
            if (!java.util.Arrays.equals(got, again)) throw new AssertionError("second push changed state at trial " + t);
        }
    }

Assignment Versus Addition Tags

Author exercise

Problem Specification. A node covers len positions with current sum S and no tag. A tag is empty, an addition of d or an assignment of v. Apply a list of whole-node operations in order, each either add d or set v. Compose each new operation with the existing tag: a set v replaces any tag, an add d on an empty or addition tag adds the amounts, and an add d on an assignment of v gives an assignment of v + d. Then push the final tag to a child of length c whose stored sum is sc. Return the node's final sum, the final tag and the child's new sum.

Input Constraints. The limits are:

  • len and c are int values with 1 <= c <= len <= 10^5.
  • S and sc are long values with absolute value at most 10^12.
  • Operations number at most 10^3, with amounts of absolute value at most 10^9.
  • Tag output is none, add d or set v.

Example 1. Input len = 4, S = 10, operations add 3, set 5, add 2, child c = 2, sc = 6. Output sum 28, tag set 7 and child sum 14.

Example 2. Input the same sizes with operations add 2, set 5, and then with set 5, add 2. The first order outputs tag set 5, node sum 20 and child sum 10. The second order outputs tag set 7, node sum 28 and child sum 14.

Prerequisites. The two exercises above.

What This Exercise Changes. The tag has two kinds, and the order in which they compose changes the answer.

Hint

Does the old sum of the child matter after an assignment? Which operation wins when both are pending?

Algorithmic Solution (attempt the problem first)

Approach. The tag is a pair of a kind and a number, and each new operation composes with the current tag by a fixed rule. An assignment replaces the tag. An addition on an empty or addition tag adds the amounts. An addition on an assignment of v gives an assignment of v + d.

The invariant is that the tag applied to the untouched positions gives the same result as running all operations in order. Once the final tag is an assignment, the old child sum is irrelevant, and the child sum becomes v * c. For an addition tag, the child sum becomes sc + d * c. Swapping the order of an addition and an assignment changes the tag, which the second example shows.

Complexity.

  • Time is O(m) for m operations, because composing an operation with the tag costs O(1).
  • Space is O(1), because the tag is one kind and one number.
import java.util.Random;

public final class TagComposition {
    /** Operation kinds: 0 is add, 1 is set. Tag kinds: 0 is none, 1 is add, 2 is set. */
    /**
     * Composes the operations and returns {nodeSum, tagKind, tagValue, childSum}.
     * Time: O(m) for m operations. Space: O(1).
     * Invariant: the tag alone reproduces the effect of all operations applied so far.
     */
    static long[] run(int len, long sum, int[] kinds, long[] vals, int c, long childSum) {
        // Start with an empty tag, which changes nothing.
        int tagKind = 0;
        long tagVal = 0;
        // Compose one operation at a time, in the given order.
        for (int i = 0; i < kinds.length; i++) {
            // A set operation ignores every earlier tag, because it overwrites all old values.
            if (kinds[i] == 1) {
                tagKind = 2;
                tagVal = vals[i];
            } else if (tagKind == 0) {
                // An add on an empty tag starts an addition tag.
                tagKind = 1;
                tagVal = vals[i];
            } else {
                // An add on an add tag sums the amounts, and an add on a set tag shifts the assigned value.
                tagVal += vals[i];
            }
        }
        // Apply the final tag to the node sum and push it to the child.
        if (tagKind == 1) {
            // Addition changes both sums by the amount times the node length.
            sum += tagVal * len;
            childSum += tagVal * c;
        } else if (tagKind == 2) {
            // Assignment makes the old sums irrelevant, so both are recomputed from the value alone.
            sum = tagVal * len;
            childSum = tagVal * c;
        }
        // Return all four values so the harness can compare the whole state.
        return new long[]{sum, tagKind, tagVal, childSum};
    }

    public static void main(String[] args) {
        // Checks Example 1: add 3, set 5, add 2 gives set 7.
        if (!java.util.Arrays.equals(run(4, 10, new int[]{0, 1, 0}, new long[]{3, 5, 2}, 2, 6), new long[]{28, 2, 7, 14})) throw new AssertionError("example 1");
        // Checks Example 2: swapping add and set changes the tag from set 5 to set 7.
        if (!java.util.Arrays.equals(run(4, 10, new int[]{0, 1}, new long[]{2, 5}, 2, 6), new long[]{20, 2, 5, 10})) throw new AssertionError("add then set");
        if (!java.util.Arrays.equals(run(4, 10, new int[]{1, 0}, new long[]{5, 2}, 2, 6), new long[]{28, 2, 7, 14})) throw new AssertionError("set then add");
        // Compares with an element-by-element simulation using a fixed seed.
        Random rnd = new Random(31_03_03);
        for (int t = 0; t < 500; t++) {
            int len = 1 + rnd.nextInt(6), c = 1 + rnd.nextInt(len);
            long[] pos = new long[len];
            for (int i = 0; i < len; i++) pos[i] = rnd.nextInt(21) - 10;
            long s = 0, cs = 0;
            for (int i = 0; i < len; i++) { s += pos[i]; if (i < c) cs += pos[i]; }
            int m = rnd.nextInt(6);
            int[] kinds = new int[m];
            long[] vals = new long[m];
            for (int i = 0; i < m; i++) {
                kinds[i] = rnd.nextInt(2);
                vals[i] = rnd.nextInt(21) - 10;
                // Simulate the operation on every position directly.
                for (int j = 0; j < len; j++) pos[j] = kinds[i] == 1 ? vals[i] : pos[j] + vals[i];
            }
            long ns = 0, ncs = 0;
            for (int j = 0; j < len; j++) { ns += pos[j]; if (j < c) ncs += pos[j]; }
            long[] got = run(len, s, kinds, vals, c, cs);
            if (got[0] != ns || got[3] != ncs) throw new AssertionError("mismatch at trial " + t);
        }
    }

Range Add Range Sum

Author exercise

Problem Specification. Given an integer array a of length n, process a list of operations in order. Operation (1, l, r, d) adds d to every a[i] with l <= i < r. Operation (2, l, r) asks for the sum of a[i] with l <= i < r. Return the answers to the sum operations in the order they appear.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 10^5, and a[i] is an int with absolute value at most 10^9.
  • Operations number at most 10^5, and each range satisfies 0 <= l < r <= n.
  • Added value d is an int with absolute value at most 10^4.
  • Answers are long values.

Example 1. Input a = [3, 1, 4, 1, 5] and operations: sum [0, 5), add 10 on [1, 4), sum [0, 3), add -2 on [0, 5), sum [2, 5), sum [3, 4). Output 14, 28, 24, 9.

Example 2. Input a = [7] and operations: add -10000 on [0, 1), sum [0, 1), add 10000 on [0, 1), sum [0, 1). Output -9993, 7.

Prerequisites. All three exercises above.

What This Exercise Changes. The earlier pieces combine into one structure that supports both operations in O(log n).

Hint

Which operation needs the children to be current? What do you do with a node that lies entirely inside the range?

Algorithmic Solution (attempt the problem first)

Approach. A tree of sums with a pending amount per node answers both operations in logarithmic time. A range add stops at every node whose range lies inside the update and records the amount there. A range sum stops at every node inside the query and reads its stored sum.

The invariant is that every stored total already includes the tags at its own node, while the children may lag behind by that tag. Any operation that must enter a node with a nonzero pending amount first hands the amount to both children, scaled by their lengths, and clears it. After an update returns from its children, the node recomputes its total from them. Half-open ranges and long totals keep the boundaries and the large values safe.

Complexity.

  • Time is O(n + q log n) for q operations, because building costs O(n) and each operation visits O(log n) nodes.
  • Space is O(n), because the two arrays hold 4n entries each.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class RangeAddRangeSum {
    private final int n;
    private final long[] total;    // total[k]: sum of node k's range with its own pending amount applied
    private final long[] pending;  // pending[k]: per-position amount the children have not received

    RangeAddRangeSum(int[] a) {
        // Remember the length and allocate four slots per position, which covers any tree shape.
        n = a.length;
        total = new long[4 * n];
        pending = new long[4 * n];
        // Build bottom-up values once, which costs O(n).
        init(1, 0, n, a);
    }

    private void init(int k, int lo, int hi, int[] a) {
        // A leaf stores its element directly.
        if (hi - lo == 1) { total[k] = a[lo]; return; }
        // Split the half-open range in the middle and build both halves.
        int mid = (lo + hi) / 2;
        init(2 * k, lo, mid, a);
        init(2 * k + 1, mid, hi, a);
        // An internal total is the sum of its two children.
        total[k] = total[2 * k] + total[2 * k + 1];
    }

    private void absorb(int k, int len, long d) {
        // The node total moves by the amount times the node length.
        total[k] += d * len;
        // The amount waits in pending for the children.
        pending[k] += d;
    }

    private void release(int k, int lo, int hi) {
        // Skip the work when nothing waits, so the children are already current.
        if (pending[k] == 0) return;
        int mid = (lo + hi) / 2;
        // Each child receives the amount scaled by its own length.
        absorb(2 * k, mid - lo, pending[k]);
        absorb(2 * k + 1, hi - mid, pending[k]);
        // Clearing the amount guarantees the transfer happens once.
        pending[k] = 0;
    }

    void add(int k, int lo, int hi, int l, int r, long d) {
        // A node outside the range changes nothing.
        if (r <= lo || hi <= l) return;
        // A node inside the range absorbs the amount and stops the descent.
        if (l <= lo && hi <= r) { absorb(k, hi - lo, d); return; }
        // A partial overlap needs current children before the recursion.
        release(k, lo, hi);
        int mid = (lo + hi) / 2;
        add(2 * k, lo, mid, l, r, d);
        add(2 * k + 1, mid, hi, l, r, d);
        // The node total must reflect the changed children.
        total[k] = total[2 * k] + total[2 * k + 1];
    }

    long sum(int k, int lo, int hi, int l, int r) {
        // A node outside the range contributes nothing.
        if (r <= lo || hi <= l) return 0;
        // A node inside the range contributes its stored total.
        if (l <= lo && hi <= r) return total[k];
        // A partial overlap releases its amount before reading the children.
        release(k, lo, hi);
        int mid = (lo + hi) / 2;
        return sum(2 * k, lo, mid, l, r) + sum(2 * k + 1, mid, hi, l, r);
    }

    /**
     * Processes the operations and returns the answers of the sum operations.
     * Time: O(n + q log n). Space: O(n).
     * Invariant: total[k] includes pending[k]; children lag by exactly pending[k].
     */
    static List<Long> solve(int[] a, int[][] ops) {
        // Build the structure once from the starting array.
        RangeAddRangeSum t = new RangeAddRangeSum(a);
        List<Long> out = new ArrayList<>();
        // Process the operations in order, each costing O(log n).
        for (int[] op : ops) {
            if (op[0] == 1) t.add(1, 0, t.n, op[1], op[2], op[3]);
            else out.add(t.sum(1, 0, t.n, op[1], op[2]));
        }
        return out;
    }

    /** Oracle: applies each operation directly to the array. */
    static List<Long> brute(int[] a, int[][] ops) {
        // Work on long copies so that sums cannot overflow.
        long[] b = new long[a.length];
        for (int i = 0; i < a.length; i++) b[i] = a[i];
        List<Long> out = new ArrayList<>();
        for (int[] op : ops) {
            long s = 0;
            for (int i = op[1]; i < op[2]; i++) {
                if (op[0] == 1) b[i] += op[3]; else s += b[i];
            }
            if (op[0] == 2) out.add(s);
        }
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 against the stated output.
        int[][] ops1 = {{2, 0, 5, 0}, {1, 1, 4, 10}, {2, 0, 3, 0}, {1, 0, 5, -2}, {2, 2, 5, 0}, {2, 3, 4, 0}};
        if (!solve(new int[]{3, 1, 4, 1, 5}, ops1).equals(List.of(14L, 28L, 24L, 9L))) throw new AssertionError("example 1");
        // Checks Example 2: a single element with extreme deltas.
        int[][] ops2 = {{1, 0, 1, -10_000}, {2, 0, 1, 0}, {1, 0, 1, 10_000}, {2, 0, 1, 0}};
        if (!solve(new int[]{7}, ops2).equals(List.of(-9_993L, 7L))) throw new AssertionError("example 2");
        // Compares with the brute force on random arrays and operation lists using a fixed seed.
        Random rnd = new Random(31_03_04);
        for (int t = 0; t < 400; t++) {
            int n = 1 + rnd.nextInt(12);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(41) - 20;
            int[][] ops = new int[1 + rnd.nextInt(15)][];
            for (int i = 0; i < ops.length; i++) {
                int l = rnd.nextInt(n), r = l + 1 + rnd.nextInt(n - l);
                ops[i] = rnd.nextBoolean() ? new int[]{1, l, r, rnd.nextInt(41) - 20} : new int[]{2, l, r, 0};
            }
            if (!solve(a, ops).equals(brute(a, ops))) throw new AssertionError("mismatch at trial " + t);
        }
    }

Problem

Why Huge Values Break Array Indexing

A service logs the response time of each request in microseconds. Values reach one billion, yet a log batch holds only a few thousand requests. For every new request, the service must report how many earlier requests were faster. A counting array indexed by the value would need one billion slots, which is about 4 GB of int counters, to track a few thousand entries. Negative values or long values make the array impossible to build at all.

The question is how to keep a counting structure small when the values are huge or sparse. The answer depends on one observation. A count of "values below x" depends only on the order of the values and on which ones are equal. The actual magnitudes never enter the answer.

Simple approach

Using The Value As The Index

The direct approach allocates an array large enough to be indexed by the value itself, then counts by scanning it.

static int countBelow(int[] seenValues, int x) {
    int[] present = new int[1_000_000_001];   // one slot per possible value
    for (int v : seenValues) present[v]++;     // the value is used as the index
    int below = 0;
    for (int v = 0; v < x; v++) below += present[v];
    return below;
}

For values up to one billion, this method allocates about 4 GB on every call. It also scans up to a billion slots to answer one query. Values such as -5 throw ArrayIndexOutOfBoundsException.

Bottleneck

Memory And Scan Follow The Value Range

Predict first: A batch has 5,000 requests with response times up to 10^9. You want counts of earlier requests below each value. How many counting slots do you actually need?

Only 5,000 slots at most, one for each distinct value. The counts depend on the order of the values and not on their size, so the other billion slots never hold anything.

Measure The Wasted Space

The array in the naive method has V + 1 slots, where V is the largest value. Space is O(V) and a single query scans O(V) slots. With V = 10^9, a batch of n = 5,000 values uses a number of slots 200,000 times larger than n. Almost every slot stays at zero.

Spot What The Answer Needs

Take the values 7, 40 and 1,000,000. The count of values below 40 is 1. It stays 1 if the values become 2, 3 and 4 and the question asks about 3. Only two facts about the data affect any count: which value is smaller than which, and which values are equal. Memory should therefore depend on the number of distinct values, which is at most n, and not on V.

Key idea

Replace Each Value By Its Rank

Build The Table Of Distinct Values

Coordinate compression replaces each value by a small integer that keeps the order of the original values. Copy the values, sort the copy and remove duplicates. The result is a rank table, a sorted array with no repeated value. Position p in the table holds the (p + 1)-th smallest distinct value.

Look Up The Dense Rank

The dense rank of a value is its position in the rank table plus one, so ranks run from 1 to m with no gaps, where m is the number of distinct values. A binary search in the table finds the rank in O(log m) time. Equal values share one rank, and a smaller value always gets a smaller rank.

The mapping preserves exactly what counting needs. For two values a and b, a < b holds exactly when rank(a) < rank(b), and a == b holds exactly when the ranks are equal. A structure indexed by rank therefore returns the same counts as one indexed by value, using only m slots.

The invariant of this method is that the table is sorted and free of duplicates. Binary search is only correct under that condition, and the dense ranks are only gap-free under it.

State

Quantities To Track While Compressing

These items describe the state of one compression.

  • values holds the original input, which stays unchanged.
  • table holds the sorted distinct values, with m entries.
  • rank is the 1-based position of a value in table, found by binary search.
  • m is the number of distinct values, and the largest rank.

Once ranks feed a Fenwick tree, the tree has m positions. A value of rank r is stored at external position r - 1. A call to prefix(r - 1) then counts the values with rank below r, and prefix(r) counts values with rank up to r.

Walkthrough

Compress Seven Values Step By Step

The input is 900, -5, 1000000000, 900, 42, -5 and 7. Sorting removes the duplicates 900 and -5 and leaves five distinct values.

Rank Each Value With The Table

The table is -5, 7, 42, 900 and 1000000000, so m = 5. The first 900 searches the table and lands at position 3, so its rank is 4. The value -5 lands at position 0, which gives rank 1, and one billion lands at the last position, which gives rank 5.

The second 900 lands at position 3 again, so it receives rank 4 once more. The repeated -5 also receives its earlier rank 1. This repeat is the hardest step, because equal values must return equal ranks. The table holds each value once, so every search for that value ends at the same position.

Count Both Sides With A Fenwick Tree

The second trace puts the values 8, 2, 5, 5, 9, 1, 5 one at a time into an initially empty sorted container. Inserting a value costs the smaller of two counts: the inserted values strictly below it and the inserted values strictly above it. Each value is compressed to its rank, and a Fenwick tree over the ranks answers both counts.

The table is 1, 2, 5, 8 and 9. The third value, 5, arrives after 8 and 2, so one value lies below it and one lies above it. The fourth value, 5, finds the earlier 5 in neither count, because the counts are strict. That strict comparison is the step to watch, since prefix(r) would include the equal value and prefix(r - 1) does not.

Build The Table And Look Up Ranks

static long[] buildTable(long[] values) {
    long[] copy = values.clone();              // keep the input unchanged
    Arrays.sort(copy);                         // sorting costs O(n log n)
    int m = 0;
    for (int i = 0; i < copy.length; i++) {
        if (i == 0 || copy[i] != copy[i - 1]) copy[m++] = copy[i];   // keep first of each run
    }
    return Arrays.copyOf(copy, m);             // the table holds m distinct values
}

static int rank(long[] table, long value) {
    int pos = Arrays.binarySearch(table, value);   // O(log m) lookup
    return pos < 0 ? 0 : pos + 1;                  // 0 means the value is absent
}

The first method sorts a copy and writes each first-of-run value forward, which removes duplicates in one pass. The comparison uses != on long values, so no subtraction occurs and no overflow can happen. The second method turns a table position into a 1-based rank and reports 0 for an absent value. Together they cost O(n log n) to build and O(log m) per lookup.

When to use it

When To Compress Coordinates

Recognize The Pattern

Compress when the values are sparse, huge or negative, and the question depends only on order and equality. Typical cases are counting smaller earlier values with a Fenwick tree, counting inversions (pairs where an earlier value is larger than a later one), and sweeping over interval endpoints. The invariant to protect is that the table is sorted without duplicates, and that every query value either appears in the table or is handled as absent.

Avoid The False Friend

Compression is not a way to shrink values that take part in arithmetic. If the answer sums, subtracts or multiplies the values themselves, ranks lose the information. A false friend of compression is the sorted position of each element, where equal values receive different positions. That variant breaks every equality test, so counts that treat ties as equal go wrong.

Watch The Java Hazards

Comparing with subtraction such as (int) (a - b) overflows for values near the ends of the long range. Use Long.compare or Arrays.sort on a primitive array. Do not use a value as an array index unless its range is small and non-negative. Compression is also an offline technique, since the table needs all values before the first query.

Hint

After sorting and removing duplicates, which search finds the position of a query?

Algorithmic Solution (attempt the problem first)

Approach. The method sorts a copy of values and keeps the first element of each run of equal values. The result is the rank table. Each query then runs a binary search on the table.

The invariant is that the table is strictly increasing. Under that condition, a found position p identifies the unique matching entry, and p + 1 is its rank. A query that is missing from the table yields a negative search result, which the method maps to 0.

Complexity.

  • Time is O(n log n + q log m), because sorting costs O(n log n) and each of the q queries searches m distinct entries.
  • Space is O(n) for the copy that is sorted plus O(q) for the answer array.
import java.util.Arrays;
import java.util.Random;

public final class CompressDistinct {
    /**
     * Returns the 1-based position of each query in the sorted distinct values, or 0 if absent.
     * Time: O(n log n + q log m). Space: O(n + q).
     * Invariant: table is strictly increasing, so binary search finds at most one match.
     */
    static int[] positions(int[] values, int[] queries) {
        // Copy first so that the caller's array stays unmodified.
        int[] copy = values.clone();
        // Sorting puts equal values next to each other and costs O(n log n).
        Arrays.sort(copy);
        // m counts the distinct values written so far.
        int m = 0;
        // One pass over the sorted copy, so this loop is O(n).
        for (int i = 0; i < copy.length; i++) {
            // Keep a value only when it starts a new run of equal values.
            if (i == 0 || copy[i] != copy[i - 1]) copy[m++] = copy[i];
        }
        // The table is the first m entries of the copy.
        int[] table = Arrays.copyOf(copy, m);
        // One answer per query.
        int[] out = new int[queries.length];
        // Each iteration does one O(log m) binary search.
        for (int k = 0; k < queries.length; k++) {
            // A negative result means the query is absent from the table.
            int pos = Arrays.binarySearch(table, queries[k]);
            // Convert a 0-based table position into a 1-based rank.
            out[k] = pos < 0 ? 0 : pos + 1;
        }
        // The answers are in query order.
        return out;
    }

    /** Oracle: counts distinct smaller values directly and checks membership by scanning. Time O(n q). */
    static int[] brute(int[] values, int[] queries) {
        int[] out = new int[queries.length];
        for (int k = 0; k < queries.length; k++) {
            boolean present = false;
            for (int v : values) if (v == queries[k]) present = true;
            if (!present) continue;
            // The rank is 1 plus the number of distinct values below the query.
            int distinctBelow = 0;
            for (int cand : Arrays.stream(values).distinct().toArray()) if (cand < queries[k]) distinctBelow++;
            out[k] = distinctBelow + 1;
        }
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1: duplicates collapse and an absent query returns 0.
        if (!Arrays.equals(positions(new int[]{40, 7, 40, 1000000, 7}, new int[]{7, 1000000, 5}), new int[]{1, 3, 0})) throw new AssertionError("example 1");
        // Checks Example 2: all-equal input has one distinct value.
        if (!Arrays.equals(positions(new int[]{3, 3, 3, 3}, new int[]{3, 4}), new int[]{1, 0})) throw new AssertionError("example 2");
        // Checks empty input: every query is absent, and no query gives an empty answer.
        if (!Arrays.equals(positions(new int[0], new int[]{1}), new int[]{0})) throw new AssertionError("empty values");
        if (positions(new int[]{1}, new int[0]).length != 0) throw new AssertionError("empty queries");
        // Checks the input stays unmodified.
        int[] keep = {5, 1, 5};
        positions(keep, new int[]{1});
        if (!Arrays.equals(keep, new int[]{5, 1, 5})) throw new AssertionError("input mutated");
        // Compares with the oracle on random inputs from a fixed seed.
        Random rnd = new Random(31041);
        for (int t = 0; t < 500; t++) {
            int n = rnd.nextInt(12), q = rnd.nextInt(8);
            int[] v = new int[n], qs = new int[q];
            for (int i = 0; i < n; i++) v[i] = rnd.nextInt(15) - 5;
            for (int i = 0; i < q; i++) qs[i] = rnd.nextInt(15) - 5;
            if (!Arrays.equals(positions(v, qs), brute(v, qs))) throw new AssertionError("random case " + t);
        }
    }

Which value does a rank count: every earlier element, or every distinct smaller value?

Algorithmic Solution (attempt the problem first)

Approach. The method builds the rank table as in the previous solution and then ranks every element by binary search. The table holds each value once, so every copy of a value reaches the same table position.

The invariant is that ranks[i] - 1 equals the number of distinct values smaller than values[i]. Binary search on a strictly increasing table returns exactly that count as the match position. Ranking by sorted index would instead give equal values different numbers, so the method avoids that approach.

Complexity.

  • Time is O(n log n), since sorting costs O(n log n) and each of the n lookups costs O(log m).
  • Space is O(n), because the sorted copy and the rank array each hold up to n entries.
import java.util.Arrays;
import java.util.Random;
import java.util.TreeSet;

public final class EqualRanks {
    /**
     * Returns the dense rank of every element, with equal values sharing one rank.
     * Time: O(n log n). Space: O(n).
     * Invariant: ranks[i] - 1 is the number of distinct values below values[i].
     */
    static int[] denseRanks(int[] values) {
        // Sort a copy so that duplicates become adjacent.
        int[] copy = values.clone();
        Arrays.sort(copy);
        // m counts the distinct values written so far.
        int m = 0;
        // One pass removes duplicates in place, costing O(n).
        for (int i = 0; i < copy.length; i++) {
            // Keep only the first value of each run.
            if (i == 0 || copy[i] != copy[i - 1]) copy[m++] = copy[i];
        }
        // The binary search below only needs the first m entries.
        int[] table = Arrays.copyOf(copy, m);
        // One rank per input element.
        int[] ranks = new int[values.length];
        // Each iteration costs O(log m).
        for (int i = 0; i < values.length; i++) {
            // The value is always present, so the result is never negative.
            ranks[i] = Arrays.binarySearch(table, values[i]) + 1;
        }
        // Ranks are in input order.
        return ranks;
    }

    /** Oracle: a TreeSet's headSet size counts distinct smaller values. Time O(n log n). */
    static int[] brute(int[] values) {
        TreeSet<Integer> set = new TreeSet<>();
        for (int v : values) set.add(v);
        int[] out = new int[values.length];
        for (int i = 0; i < values.length; i++) out[i] = set.headSet(values[i]).size() + 1;
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1: repeated values share ranks.
        if (!Arrays.equals(denseRanks(new int[]{100, 5, 100, 70, 5}), new int[]{3, 1, 3, 2, 1})) throw new AssertionError("example 1");
        // Checks Example 2: all equal values give rank 1.
        if (!Arrays.equals(denseRanks(new int[]{8, 8, 8}), new int[]{1, 1, 1})) throw new AssertionError("example 2");
        // Checks the empty input.
        if (denseRanks(new int[0]).length != 0) throw new AssertionError("empty");
        // Compares with the oracle on random inputs from a fixed seed.
        Random rnd = new Random(31042);
        for (int t = 0; t < 500; t++) {
            int n = rnd.nextInt(14);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = rnd.nextInt(10) - 4;
            if (!Arrays.equals(denseRanks(v), brute(v))) throw new AssertionError("random case " + t);
        }
    }

Create Sorted Array Cost

Problem Specification. An initially empty container receives the elements of instructions in order. Inserting an element costs the smaller of two counts: the elements already in the container that are strictly less than it, and those that are strictly greater. Return the total cost of all insertions modulo 1,000,000,007.

Input Constraints. The limits are:

  • instructions has 1 <= length <= 10^5 entries.
  • Each element is an int with 1 <= element <= 10^9.
  • Equal elements count in neither the less count nor the greater count.
  • Result is returned modulo 1,000,000,007 as a long.

Example 1. Input 4, 9, 4, 1, 7, 7. Output 2. The costs are 0, 0, 0, 0, 1, 1.

Example 2. Input 3, 3, 3, 3. Output 0, since no element is strictly less or greater than another.

Prerequisites. The three exercises above and the Fenwick tree lesson.

What This Exercise Changes. Ranks now index a Fenwick tree that changes as elements arrive, and the counts must be strict.

Hint

Which two prefix queries on the Fenwick tree give the less count and the greater count?

Algorithmic Solution (attempt the problem first)

Approach. The method compresses the values to dense ranks and keeps a Fenwick tree of counts, one position per rank.

Before inserting an element of rank r, the less count is prefix(r - 1), the number of inserted elements with a smaller rank. The count of inserted elements with rank up to r is prefix(r), so the greater count is the number inserted so far minus prefix(r). Equal elements fall in prefix(r) and not in prefix(r - 1), so they enter neither count. The cost is the smaller count. Then add(r - 1, 1) records the element, and the running total is kept modulo 1,000,000,007.

The invariant is that after k insertions, prefix(p) equals the number of inserted elements whose rank is at most p.

Complexity.

  • Time is O(n log n), because compression costs O(n log n) and each insertion does two prefix queries and one update of O(log m).
  • Space is O(n) for the table, the ranks and the tree.
import java.util.Arrays;
import java.util.Random;

public final class SortedArrayCost {
    /** Fenwick tree over positions; external positions are 0-based, the internal array is 1-based. */
    static final class Fenwick {
        final long[] tree;

        Fenwick(int size) {
            // Slot 0 stays unused so that the lowest-set-bit step terminates.
            tree = new long[size + 1];
        }

        /** Adds delta at 0-based position pos. Time: O(log n). Space: O(1). */
        void add(int pos, long delta) {
            // Convert to the 1-based internal index, then climb by the lowest set bit.
            for (int i = pos + 1; i < tree.length; i += i & -i) tree[i] += delta;
        }

        /** Returns the sum of the first pos positions (internal indices 1..pos). Time: O(log n). */
        long prefix(int pos) {
            long sum = 0;
            // Descend by clearing the lowest set bit; at most log n steps.
            for (int i = pos; i > 0; i -= i & -i) sum += tree[i];
            return sum;
        }
    }

    static final long MOD = 1_000_000_007L;

    /**
     * Returns the total insertion cost modulo 1,000,000,007.
     * Time: O(n log n). Space: O(n).
     * Invariant: after k insertions, prefix(p) counts inserted elements with rank at most p.
     */
    static long totalCost(int[] instructions) {
        // Build the rank table: sorted distinct values.
        int[] copy = instructions.clone();
        Arrays.sort(copy);
        int m = 0;
        // Deduplicate in one O(n) pass.
        for (int i = 0; i < copy.length; i++) {
            if (i == 0 || copy[i] != copy[i - 1]) copy[m++] = copy[i];
        }
        int[] table = Arrays.copyOf(copy, m);
        // The tree has one position per distinct value, not per possible value.
        Fenwick fen = new Fenwick(m);
        // Total is a long and is reduced modulo MOD after every addition.
        long total = 0;
        // One iteration per instruction, each costing O(log m).
        for (int k = 0; k < instructions.length; k++) {
            // The 1-based dense rank of the current value.
            int r = Arrays.binarySearch(table, instructions[k]) + 1;
            // Inserted elements strictly below: ranks 1..r-1.
            long less = fen.prefix(r - 1);
            // Inserted elements strictly above: all k inserted so far, minus ranks 1..r.
            long greater = k - fen.prefix(r);
            // The cost is the cheaper side, and equal elements count on neither side.
            total = (total + Math.min(less, greater)) % MOD;
            // Record this element at external position r - 1.
            fen.add(r - 1, 1);
        }
        // Return the reduced total.
        return total;
    }

    /** Oracle: counts both sides by scanning all earlier elements. Time O(n^2). */
    static long brute(int[] ins) {
        long total = 0;
        for (int i = 0; i < ins.length; i++) {
            long less = 0, greater = 0;
            for (int j = 0; j < i; j++) {
                if (ins[j] < ins[i]) less++;
                if (ins[j] > ins[i]) greater++;
            }
            total = (total + Math.min(less, greater)) % MOD;
        }
        return total;
    }

    public static void main(String[] args) {
        // Checks Example 1: costs 0, 0, 0, 0, 1, 1.
        if (totalCost(new int[]{4, 9, 4, 1, 7, 7}) != 2) throw new AssertionError("example 1");
        // Checks Example 2: equal elements are strictly neither less nor greater.
        if (totalCost(new int[]{3, 3, 3, 3}) != 0) throw new AssertionError("example 2");
        // Checks a single element and the trace input.
        if (totalCost(new int[]{1000000000}) != 0) throw new AssertionError("single");
        if (totalCost(new int[]{8, 2, 5, 5, 9, 1, 5}) != 4) throw new AssertionError("trace input");
        // Compares with the oracle on random inputs from a fixed seed, with sparse large values.
        Random rnd = new Random(31044);
        for (int t = 0; t < 500; t++) {
            int n = 1 + rnd.nextInt(30);
            int[] v = new int[n];
            int span = rnd.nextBoolean() ? 6 : 1_000_000_000;
            for (int i = 0; i < n; i++) v[i] = 1 + rnd.nextInt(span);
            if (totalCost(v) != brute(v)) throw new AssertionError("random case " + t);
        }
    }

Problem

Why Per-Position Checks Fail On Long Ranges

A shuttle service accepts trips. Each trip carries some passengers from a pickup marker to a drop-off marker on a road, and the bus has a fixed number of seats. Before accepting a batch, the service must answer one question: does the number of passengers on board ever exceed the seat count?

Markers can be as large as one billion, and a trip can span almost all of them. A check that visits every marker inside every trip does work proportional to the road length. That cost is far beyond a time limit, even when only a handful of trips exist.

The same failure appears when a calendar looks for double-booked rooms and when a map renderer draws building outlines. The load changes at a few known coordinates and stays constant everywhere between them. The question this lesson answers is how to look only at the coordinates where something changes.

Simple approach

Add Each Trip To Every Position

The direct approach keeps one load counter per marker. For each trip, it adds the passenger count to every marker from the pickup up to, but not including, the drop-off. It stops as soon as one counter exceeds the capacity.

static boolean carPoolingNaive(int[][] trips, int capacity, int maxMarker) {
    int[] load = new int[maxMarker + 1];       // one counter for every marker on the road
    for (int[] trip : trips) {
        for (int x = trip[1]; x < trip[2]; x++) {
            load[x] += trip[0];                // the trip occupies seats at x
            if (load[x] > capacity) return false;
        }
    }
    return true;
}

The method is correct, and it works well when the road has a few hundred markers. The answer depends only on the trips, but the cost depends on how long each trip is.

Bottleneck

Cost Follows Trip Length, Not Trip Count

Predict first: There are 1,000 trips, and each one runs from marker 0 to marker 1,000,000,000. About how many counter updates does the direct approach perform, and how many coordinates actually change the load?

About 10^12 updates, because each trip updates one billion counters. Only 2 distinct coordinates change the load, 0 and 1,000,000,000, although they hold 2,000 events, namely 1,000 pickups and 1,000 drop-offs. Everywhere else the load stays the same as at the previous coordinate.

Count The Work

With n trips and a longest trip of length L, the loop performs O(n * L) updates. The counter array also needs O(maxMarker) memory, which is a gigabyte-scale allocation for a billion markers. Both costs track the size of the coordinate range and ignore the size of the input.

Find The Wasted Work

Between two neighboring pickup or drop-off coordinates, no trip starts or ends. Every position in that gap has the same load, so the inner loop recomputes one number millions of times. The load at a position equals the load at the previous change coordinate plus the changes that happen exactly there. Only the change coordinates, at most 2n of them, carry information, so the work should be O(n log n) for sorting them and not O(n * L).

Key idea

Process Changes In Coordinate Order

Turn Each Trip Into Two Events

An event is a pair of a coordinate and a signed change in the active state. A trip of p passengers from a to b yields the event {a, +p} and the event {b, -p}. The drop-off is the exclusive end of the half-open range [a, b), so the seats free up at b.

Sort Then Move Along The Line

A sweep line visits the events in ascending coordinate order and keeps the active state up to date. For car pooling, the state is one number, the current load. Add each delta to the load, and the load after an event is the load on the span up to the next event coordinate. Checking the load against the capacity at each step covers every position with at most 2n steps.

Fix A Tie Policy For Equal Coordinates

Several events can share one coordinate, for example a drop-off and a pickup at the same marker. The tie policy is the rule for those events. For half-open ranges, the policy applies every delta at the coordinate and only then reads the state. Ordering the deltas with decreases first and reading after each one gives the same maximum. For closed ranges, a range that ends at the coordinate still counts there, so the policy orders increases first and reads the state before the decreases apply. Without a stated policy, the load can show a peak that no position ever had.

The invariant is this. With the half-open tie policy, after the events at a coordinate are applied, the active state describes exactly the positions from this coordinate up to the next one. Every sweep line algorithm preserves that sentence, and only the kind of state changes. A counter handles a load, and a structure that reports a maximum handles heights.

  • events holds the pairs {coordinate, delta}, two per trip, sorted by coordinate and then by delta.
  • load is the sum of all deltas applied so far, which equals the passengers on board.
  • capacity is the fixed seat limit that load must never exceed.
  • e is the event being applied, and it is the pointer in the first trace.

In the skyline trace, maxHeight is the code variable top, which is the top of heap after the discards. The trace value pendingRemovals is the number of ended heights still waiting in pending.

Follow The Load Across Sorted Events

Trips With A Shared Stop

Take capacity 4 and three trips: 2 passengers from 1 to 5, 1 passenger from 3 to 6, and 3 passengers from 5 to 8. The sorted events are {1,+2}, {3,+1}, {5,-2}, {5,+3}, {6,-1} and {8,-3}.

The first two events raise the load to 2 and then 3. The two events at coordinate 5 form the tie. The drop-off of 2 runs first, so the load falls to 1, and the pickup of 3 then raises it to 4. The load equals the capacity and does not exceed it.

The remaining events lower the load to 3 and then to 0, so every trip fits. The hardest step is coordinate 5. If the pickup ran first, the load would reach 6 for a moment that no position ever has, and the answer would be wrong.

Buildings With Shared Edges

A skyline problem gives buildings [left, right) with a height. The outline lists a key point (x, height) wherever the greatest active height changes, and the last key point has height 0. The state of this sweep is the maximum of the active heights, so it must forget a height when its building ends. A max-heap gives the maximum, but removing an arbitrary value costs O(n). Lazy deletion avoids that: an ended height is only counted as a pending removal and leaves the heap when it reaches the top. Take buildings [2,6) of height 3, [4,6) of height 5 and [6,9) of height 2.

At coordinate 2 the maximum rises from 0 to 3, so the outline gets a key point (2,3). At coordinate 4 it rises to 5, giving (4,5). At coordinate 6 two buildings end and one starts, and all three events are applied before the maximum is read. The maximum becomes 2, giving (6,2). At coordinate 9 the last building ends and the outline returns to height 0.

The ended heights 5 and 3 are not deleted from the heap at once. They are recorded as pending removals and discarded when they reach the top, which the trace shows at coordinate 6.

static boolean carPooling(int[][] trips, int capacity) {
    int[][] events = new int[trips.length * 2][];
    int k = 0;
    for (int[] t : trips) {
        events[k++] = new int[]{t[1], t[0]};      // pickup adds passengers
        events[k++] = new int[]{t[2], -t[0]};     // drop-off removes them at the exclusive end
    }
    // Integer.compare states the order directly and cannot overflow.
    Arrays.sort(events, (p, q) -> p[0] != q[0] ? Integer.compare(p[0], q[0]) : Integer.compare(p[1], q[1]));
    long load = 0;
    for (int[] e : events) {
        load += e[1];                              // apply one delta under the decreases-first policy
        if (load > capacity) return false;
    }
    return true;
}

static List<int[]> skyline(int[][] buildings) {
    int[][] events = new int[buildings.length * 2][];
    int k = 0;
    for (int[] b : buildings) {
        events[k++] = new int[]{b[0], b[2]};      // positive height means the building starts
        events[k++] = new int[]{b[1], -b[2]};     // negative height means the building ends
    }
    Arrays.sort(events, (p, q) -> Integer.compare(p[0], q[0]));
    PriorityQueue<Integer> heap = new PriorityQueue<>(Comparator.reverseOrder());
    Map<Integer, Integer> pending = new HashMap<>();   // heights ended but still inside the heap
    heap.add(0);                                       // ground level is always active
    List<int[]> outline = new ArrayList<>();
    int previous = 0, i = 0;
    while (i < events.length) {
        int x = events[i][0];
        while (i < events.length && events[i][0] == x) {   // apply every event at this coordinate first
            int h = events[i++][1];
            if (h > 0) heap.add(h);
            else pending.merge(-h, 1, Integer::sum);
        }
        while (pending.getOrDefault(heap.peek(), 0) > 0)   // discard ended heights that reached the top
            pending.merge(heap.poll(), -1, Integer::sum);
        int top = heap.peek();
        if (top != previous) { outline.add(new int[]{x, top}); previous = top; }
    }
    return outline;
}

The first method reads the state after each delta, so its tie policy is the sort order. The second method applies a whole group of equal coordinates before it reads the state, so its tie policy is grouping. The PriorityQueue removes its top in O(log n) time, but removing an arbitrary value needs a linear search. Lazy deletion avoids that search. It counts each ended height in pending and removes a heap value only when that value is at the top and its count is positive. Each height enters and leaves the heap once, so the total heap work is O(n log n).

When to use it

When A Sweep Line Applies

Recognize The Pattern

Use a sweep line when the state changes only at known coordinates or times. The question must also concern the state between those coordinates, such as a maximum load, a covered length or an outline. Typical cases are overlapping intervals, meeting room counts, capacity limits and skyline outlines.

The invariant to carry through the code is that the state always describes the span from the current coordinate to the next one. State it before choosing the structure. A counter is enough when only a total matters. A heap with lazy deletion, or a TreeMap of height counts, is needed when the maximum matters.

Avoid The False Friend

A difference array looks like a close relative, because both add a delta at the start and subtract it at the end. That false friend works only when coordinates are small and dense, because it allocates one cell per coordinate. It fails for markers near a billion. Coordinate compression, from the previous lesson, shrinks the coordinates and makes an array usable again, while the sweep line needs no array at all.

Watch The Java Hazards

Sorting with a comparator such as p[0] - q[0] overflows when coordinates have opposite signs and large magnitude, so use Integer.compare. The coordinates here stay between 0 and 10^9, where subtraction would still fit, but negative inputs make the habit necessary. A tie policy that disagrees with the range convention gives wrong answers on touching intervals, and no test with distinct coordinates reveals it. Test every sweep with two events at one coordinate.

Problem Specification. A vehicle has capacity seats. A list of trips is given, where trip i is [passengers, from, to]. The passengers occupy seats on the half-open range [from, to), so they leave at to before any passenger who boards at to. Return true if the number of occupied seats never exceeds capacity at any position, and false otherwise.

Input Constraints. The limits are:

  • Trips number between 1 and 10^4.
  • Passengers per trip are an int between 1 and 100.
  • Positions satisfy 0 <= from < to <= 10^9.
  • Capacity is an int between 1 and 10^5.
  • Input arrays are read only, and the return value is a boolean.

Example 1. Input trips [[2,1,5],[3,3,7]] and capacity 4, output false, because positions 3 and 4 carry 2 + 3 = 5 passengers.

Example 2. Input trips [[2,1,5],[3,5,7]] and capacity 3, output true, because the 2 passengers leave at 5 as the 3 passengers board.

Prerequisites. The events, load and tie policy from this lesson.

What This Exercise Changes. Baseline case: replaces the per-position load array with two signed events per trip.

Hint

What are the two events of a trip, and which one runs first when two share a coordinate?

Algorithmic Solution (attempt the problem first)

Approach. Each trip becomes two events, and a sorted pass keeps the load.

A trip adds its passengers at from and removes them at to. Sorting the pairs by coordinate and then by delta places a drop-off before a pickup at the same coordinate, which matches the half-open range. The pass adds each delta to a running load and returns false as soon as the load exceeds the capacity.

The invariant is that the load after each event equals the passengers on board from that coordinate to the next one. The load can only reach a new maximum right after a pickup, so checking after every event covers every position. The size of the coordinates never enters the cost.

Complexity.

  • Time is O(n log n), because sorting the 2n events dominates the single linear pass over them.
  • Space is O(n), because the event array holds two entries for each trip.
import java.util.Arrays;
import java.util.Random;

public final class CarPoolingSweep {
    /**
     * Reports whether the seat count is never exceeded.
     * Time: O(n log n) for sorting 2n events. Space: O(n) for the event array.
     * Invariant: load equals the passengers on board between the last applied coordinate and the next one.
     */
    static boolean carPooling(int[][] trips, int capacity) {
        // Two events per trip, so the array has 2n entries and costs O(n) memory.
        int[][] events = new int[trips.length * 2][];
        // k is the next free slot in the event array.
        int k = 0;
        // One iteration per trip creates its pickup and drop-off events in O(n) total.
        for (int[] t : trips) {
            // The pickup adds passengers at the first occupied position.
            events[k++] = new int[]{t[1], t[0]};
            // The drop-off removes them at the exclusive end of the range.
            events[k++] = new int[]{t[2], -t[0]};
        }
        // Sort by coordinate, then by delta, so a decrease runs before an increase at one coordinate; this is the O(n log n) step.
        Arrays.sort(events, (p, q) -> p[0] != q[0] ? Integer.compare(p[0], q[0]) : Integer.compare(p[1], q[1]));
        // The load is a long so that large inputs cannot overflow the sum.
        long load = 0;
        // One pass over the sorted events costs O(n).
        for (int[] e : events) {
            // Apply one delta; the load now describes the span up to the next coordinate.
            load += e[1];
            // A load above capacity at any span makes the whole batch infeasible.
            if (load > capacity) return false;
        }
        // Every span stayed within capacity.
        return true;
    }

    /** Reference answer that adds each trip to every position; usable only for small coordinates. */
    static boolean brute(int[][] trips, int capacity) {
        // One counter per position from 0 to 20 is enough for the test coordinates.
        int[] load = new int[21];
        // Add each trip to every position it occupies.
        for (int[] t : trips) {
            for (int x = t[1]; x < t[2]; x++) {
                load[x] += t[0];
                if (load[x] > capacity) return false;
            }
        }
        return true;
    }

    public static void main(String[] args) {
        // Checks Example 1: the overlap at positions 3 and 4 carries 5 passengers.
        if (carPooling(new int[][]{{2, 1, 5}, {3, 3, 7}}, 4)) throw new AssertionError("example 1");
        // Checks Example 2: the drop-off at 5 runs before the pickup at 5.
        if (!carPooling(new int[][]{{2, 1, 5}, {3, 5, 7}}, 3)) throw new AssertionError("example 2");
        // Checks a trip near one billion, which the position array could not store.
        if (!carPooling(new int[][]{{5, 0, 1_000_000_000}, {5, 1_000_000_000 - 1, 1_000_000_000}}, 10)) throw new AssertionError("large coordinates");
        // Compares the sweep with the brute force on random small inputs with a fixed seed.
        Random rnd = new Random(3105);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(6);
            int[][] trips = new int[n][];
            for (int i = 0; i < n; i++) {
                int a = rnd.nextInt(10);
                int b = a + 1 + rnd.nextInt(10 - a);
                trips[i] = new int[]{1 + rnd.nextInt(4), a, b};
            }
            int cap = 1 + rnd.nextInt(9);
            if (carPooling(trips, cap) != brute(trips, cap)) throw new AssertionError("random case " + iter);
        }
    }

Group Equal Coordinates

Author exercise

Problem Specification. Given half-open intervals [start, end), return the maximal covered spans in ascending order. A span [a, b) is maximal when every position in it lies inside at least one interval and no position just before a or at b does. Intervals that touch at a coordinate belong to one span.

Input Constraints. The limits are:

  • Intervals number between 0 and 10^5.
  • Coordinates are int values with -10^9 <= start < end <= 10^9.
  • Output is a list of [a, b] pairs, empty when there are no intervals.
  • Input may be unsorted and may contain duplicates.

Example 1. Input [[1,3],[3,5],[7,9]], output [[1,5],[7,9]], because [1,3) and [3,5) touch at 3 and form one span.

Example 2. Input [[4,6],[1,2],[3,4]], output [[1,2],[3,6]], because position 2 is uncovered and separates the first two spans.

Prerequisites. The Car Pooling exercise above.

What This Exercise Changes. The state is a count that is read once per distinct coordinate, so all deltas at a coordinate are applied before the read.

Hint

What is the coverage count after all events at one coordinate have run, and when does it change between zero and positive?

Algorithmic Solution (attempt the problem first)

Approach. A coverage count is read once per distinct coordinate, after all deltas there are applied.

Each interval adds one event at start and subtracts one at end. After sorting, the pass walks groups of equal coordinates. It applies every delta in a group and only then compares the count before and after the group. A change from zero to positive opens a span at this coordinate, and a change from positive to zero closes it.

Reading the count after each single delta would split [1,3) and [3,5), because the count would touch zero between the drop-off and the pickup. Grouping removes that false gap. The invariant is that the count describes the positions from the current coordinate to the next distinct one.

Complexity.

  • Time is O(n log n), because sorting 2n events dominates the linear grouped pass.
  • Space is O(n), because the events and the output spans take linear memory.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Random;

public final class MergeSpansSweep {
    /**
     * Returns the maximal covered spans of half-open intervals.
     * Time: O(n log n) for sorting. Space: O(n) for events and output.
     * Invariant: count equals the number of intervals covering the positions from the current coordinate onward.
     */
    static List<int[]> spans(int[][] intervals) {
        // Two events per interval, so memory is O(n).
        int[][] events = new int[intervals.length * 2][];
        int k = 0;
        // One iteration per interval creates its start and end events.
        for (int[] iv : intervals) {
            // The start raises coverage at the first covered position.
            events[k++] = new int[]{iv[0], 1};
            // The end lowers coverage at the first uncovered position.
            events[k++] = new int[]{iv[1], -1};
        }
        // Only the coordinate matters for the order, because groups are applied together.
        Arrays.sort(events, (p, q) -> Integer.compare(p[0], q[0]));
        List<int[]> out = new ArrayList<>();
        // count is the current coverage and open is the start of the span being tracked.
        int count = 0, open = 0, i = 0;
        // The outer loop visits each group of equal coordinates once, so the pass costs O(n).
        while (i < events.length) {
            // The group coordinate is read before any delta changes the count.
            int x = events[i][0];
            // Remember coverage before the group to detect a transition.
            int before = count;
            // Apply every delta that shares this coordinate before reading the count.
            while (i < events.length && events[i][0] == x) count += events[i++][1];
            // Coverage rising from zero opens a span at this coordinate.
            if (before == 0 && count > 0) open = x;
            // Coverage falling to zero closes the span at this coordinate.
            else if (before > 0 && count == 0) out.add(new int[]{open, x});
        }
        // The list holds the maximal spans in ascending order.
        return out;
    }

    /** Reference answer that marks every covered integer position and joins adjacent ones. */
    static List<int[]> brute(int[][] intervals) {
        // Positions range from -5 to 9 in the tests; the offset of 5 maps them to indexes.
        boolean[] cov = new boolean[16];
        for (int[] iv : intervals) for (int x = iv[0]; x < iv[1]; x++) cov[x + 5] = true;
        List<int[]> out = new ArrayList<>();
        // Scan once and join consecutive covered positions into one span.
        for (int x = 0; x < 16; x++) {
            if (!cov[x]) continue;
            int y = x;
            while (y < 16 && cov[y]) y++;
            out.add(new int[]{x - 5, y - 5});
            x = y;
        }
        return out;
    }

    static boolean same(List<int[]> a, List<int[]> b) {
        // Two span lists agree when they have the same length and equal pairs.
        if (a.size() != b.size()) return false;
        for (int i = 0; i < a.size(); i++) if (!Arrays.equals(a.get(i), b.get(i))) return false;
        return true;
    }

    public static void main(String[] args) {
        // Checks Example 1: touching intervals merge and the gap keeps spans apart.
        if (!same(spans(new int[][]{{1, 3}, {3, 5}, {7, 9}}), List.of(new int[]{1, 5}, new int[]{7, 9}))) throw new AssertionError("example 1");
        // Checks Example 2: unsorted input with one uncovered position.
        if (!same(spans(new int[][]{{4, 6}, {1, 2}, {3, 4}}), List.of(new int[]{1, 2}, new int[]{3, 6}))) throw new AssertionError("example 2");
        // Checks the empty input.
        if (!spans(new int[0][]).isEmpty()) throw new AssertionError("empty");
        // Compares with the brute force on random inputs with a fixed seed.
        Random rnd = new Random(3105);
        for (int iter = 0; iter < 3000; iter++) {
            int n = rnd.nextInt(7);
            int[][] iv = new int[n][];
            for (int i = 0; i < n; i++) {
                int a = -5 + rnd.nextInt(13);
                iv[i] = new int[]{a, a + 1 + rnd.nextInt(10 - a)};
            }
            if (!same(spans(iv), brute(iv))) throw new AssertionError("random case " + iter);
        }
    }

Start-End Tie

Author exercise

Problem Specification. Given intervals [start, end] with integer endpoints and a flag closed, return the largest number of intervals that are active at the same integer position. If closed is true, an interval contains both endpoints. If closed is false, it contains start and excludes end.

Input Constraints. The limits are:

  • Intervals number between 1 and 10^5.
  • Endpoints are int values with -10^9 <= start < end <= 10^9.
  • Flag closed selects the endpoint convention for every interval.
  • Return value is an int.

Example 1. Input [[1,3],[3,5]], output 2 when closed is true and 1 when closed is false, because position 3 belongs to both intervals only in the closed case.

Example 2. Input [[1,4],[2,6],[4,8]], output 3 when closed is true and 2 when closed is false, because the first interval contains position 4 only in the closed case.

Prerequisites. The two exercises above.

What This Exercise Changes. Only the endpoint convention changes, and it reverses the order of increases and decreases at equal coordinates.

Hint

At one coordinate, should the interval that starts or the interval that ends run first for each convention?

Algorithmic Solution (attempt the problem first)

Approach. The endpoint convention decides which event runs first at an equal coordinate.

Every interval produces a +1 event at start and a -1 event at end. For half-open intervals, an interval ending at x no longer contains x, so the decrease must run before the increase. For closed intervals, the interval still contains x, so the increase must run first. The sort key is the coordinate, then the delta ascending for half-open and descending for closed.

The pass keeps the running count and the largest value it reaches after any event. With the correct order, each value after an event is the true number of active intervals at some integer position. The wrong order creates a peak that no position has, or hides one that a position has.

Complexity.

  • Time is O(n log n), since sorting the 2n events costs more than the linear scan.
  • Space is O(n), because the event array holds two entries for each interval.
import java.util.Arrays;
import java.util.Random;

public final class MaxActiveTie {
    /**
     * Returns the largest number of intervals active at one integer position.
     * Time: O(n log n) for sorting. Space: O(n) for events.
     * Invariant: current equals the intervals active at the coordinate of the last applied event under the chosen convention.
     */
    static int maxActive(int[][] intervals, boolean closed) {
        // Two events per interval, so memory is O(n).
        int[][] events = new int[intervals.length * 2][];
        int k = 0;
        // One iteration per interval creates its two events.
        for (int[] iv : intervals) {
            events[k++] = new int[]{iv[0], 1};
            events[k++] = new int[]{iv[1], -1};
        }
        // The tie policy: closed ranges put increases first, half-open ranges put decreases first.
        Arrays.sort(events, (p, q) -> p[0] != q[0] ? Integer.compare(p[0], q[0])
                : closed ? Integer.compare(q[1], p[1]) : Integer.compare(p[1], q[1]));
        // current is the running count and best is the largest count seen after any event.
        int current = 0, best = 0;
        // One linear pass over the sorted events.
        for (int[] e : events) {
            // Apply one delta under the tie policy.
            current += e[1];
            // The maximum can only change right after an increase, and taking it every time is still correct.
            best = Math.max(best, current);
        }
        // The best count is the answer for the chosen convention.
        return best;
    }

    /** Reference answer that counts the active intervals at every integer position. */
    static int brute(int[][] intervals, boolean closed) {
        int best = 0;
        // Positions in the tests lie between 0 and 12.
        for (int x = 0; x <= 12; x++) {
            int c = 0;
            // Count intervals that contain x under the convention.
            for (int[] iv : intervals) if (iv[0] <= x && (closed ? x <= iv[1] : x < iv[1])) c++;
            best = Math.max(best, c);
        }
        return best;
    }

    public static void main(String[] args) {
        // Checks Example 1 under both conventions.
        int[][] a = {{1, 3}, {3, 5}};
        if (maxActive(a, true) != 2 || maxActive(a, false) != 1) throw new AssertionError("example 1");
        // Checks Example 2 under both conventions.
        int[][] b = {{1, 4}, {2, 6}, {4, 8}};
        if (maxActive(b, true) != 3 || maxActive(b, false) != 2) throw new AssertionError("example 2");
        // Checks the Java claim that comparing by subtraction overflows for large coordinates of opposite sign.
        int big = 1_500_000_000;
        if (!(big - (-big) < 0)) throw new AssertionError("subtraction overflows");
        // Checks that the sweep still orders such coordinates correctly through Integer.compare.
        if (maxActive(new int[][]{{-big, big}, {-big, 0}}, false) != 2) throw new AssertionError("large coordinates");
        // Compares with the brute force on random inputs with a fixed seed.
        Random rnd = new Random(3105);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(6);
            int[][] iv = new int[n][];
            for (int i = 0; i < n; i++) {
                int s = rnd.nextInt(10);
                iv[i] = new int[]{s, s + 1 + rnd.nextInt(12 - s)};
            }
            for (boolean closed : new boolean[]{true, false})
                if (maxActive(iv, closed) != brute(iv, closed)) throw new AssertionError("random case " + iter + " closed=" + closed);
        }
    }

The Skyline Problem

LeetCode 218

Problem Specification. Each building is [left, right, height] and covers the half-open range [left, right). Return the outline as a list of key points [x, height] in ascending x. A key point is the left end of a horizontal segment, and it appears only where the maximum height changes. The last key point has height 0.

Input Constraints. The limits are:

  • Buildings number between 0 and 10^4.
  • Coordinates satisfy 0 <= left < right <= 10^9.
  • Heights are int values between 1 and 10^9.
  • Output has no two consecutive key points with the same height.

Example 1. Input [[2,6,3],[4,6,5],[6,9,2]], output [[2,3],[4,5],[6,2],[9,0]], because the shared edge at 6 changes the maximum from 5 to 2.

Example 2. Input [[0,3,4],[2,5,4]], output [[0,4],[5,0]], because the two buildings of height 4 overlap and produce no key point at 3.

Prerequisites. All three exercises above.

What This Exercise Changes. The state is the maximum of a changing set and not a counter, so removing an ended height needs lazy deletion.

Hint

Which structure reports the largest active height, and how can it forget a building that has ended?

Algorithmic Solution (attempt the problem first)

Approach. A max-heap holds the active heights, and lazy deletion removes ended ones.

Each building gives a start event with its positive height and an end event with its negative height. The pass applies all events at one coordinate and then reads the maximum height. A key point is emitted only when that maximum differs from the previous one. The invariant is that the heap top, after cleanup, is the largest height over the positions from this coordinate to the next.

A PriorityQueue cannot cheaply remove an arbitrary height. The code instead counts each ended height in a map and leaves it in the heap. Before reading the top, the code pops the top while its pending count is positive. The count handles duplicate heights, so two buildings of equal height end independently. Ground height 0 stays in the heap, so the heap is never empty.

Complexity.

  • Time is O(n log n), because sorting and the heap operations each handle at most 2n values at O(log n) apiece.
  • Space is O(n), because the heap, the pending map and the events hold at most one entry per building end.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Comparator;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.PriorityQueue;
import java.util.Random;

public final class SkylineSweep {
    /**
     * Returns the key points of the outline of half-open buildings.
     * Time: O(n log n) for sorting and heap work. Space: O(n) for events, heap and pending counts.
     * Invariant: after cleanup, the heap top is the maximum height active from the current coordinate to the next.
     */
    static List<int[]> skyline(int[][] buildings) {
        // Two events per building, so memory is O(n).
        int[][] events = new int[buildings.length * 2][];
        int k = 0;
        // One iteration per building creates its start and end events.
        for (int[] b : buildings) {
            // A positive height marks the start of a building.
            events[k++] = new int[]{b[0], b[2]};
            // A negative height marks its end at the exclusive right edge.
            events[k++] = new int[]{b[1], -b[2]};
        }
        // Only the coordinate matters, because all events at one coordinate are applied together.
        Arrays.sort(events, (p, q) -> Integer.compare(p[0], q[0]));
        // The max-heap yields the largest active height at its top.
        PriorityQueue<Integer> heap = new PriorityQueue<>(Comparator.reverseOrder());
        // pending counts ended heights that still sit inside the heap.
        Map<Integer, Integer> pending = new HashMap<>();
        // Ground level stays in the heap, so peek never returns null.
        heap.add(0);
        List<int[]> outline = new ArrayList<>();
        // previous is the last emitted height and i is the next unapplied event.
        int previous = 0, i = 0;
        // Each pass of this loop handles one distinct coordinate, so the loop touches each event once.
        while (i < events.length) {
            // The group coordinate is fixed before the inner loop moves i.
            int x = events[i][0];
            // Apply every event at this coordinate before reading the maximum.
            while (i < events.length && events[i][0] == x) {
                int h = events[i++][1];
                // A start pushes its height in O(log n).
                if (h > 0) heap.add(h);
                // An end only increments a counter in O(1), which is the lazy deletion.
                else pending.merge(-h, 1, Integer::sum);
            }
            // Discard ended heights that reached the top; each height is popped at most once overall.
            while (pending.getOrDefault(heap.peek(), 0) > 0)
                pending.merge(heap.poll(), -1, Integer::sum);
            // The cleaned top is the current maximum height.
            int top = heap.peek();
            // Emit a key point only where the maximum changes.
            if (top != previous) {
                outline.add(new int[]{x, top});
                previous = top;
            }
        }
        // The last key point has height 0 once every building has ended.
        return outline;
    }

    /** Reference answer that finds the height at every integer position in 0..10. */
    static List<int[]> brute(int[][] buildings) {
        List<int[]> out = new ArrayList<>();
        int prev = 0;
        // Positions in the tests lie between 0 and 10.
        for (int x = 0; x <= 10; x++) {
            int h = 0;
            // The height at x is the maximum over buildings that contain x.
            for (int[] b : buildings) if (b[0] <= x && x < b[1]) h = Math.max(h, b[2]);
            // A key point appears where the height differs from the previous position.
            if (h != prev) { out.add(new int[]{x, h}); prev = h; }
        }
        return out;
    }

    static boolean same(List<int[]> a, List<int[]> b) {
        // Two outlines agree when they have equal length and equal pairs.
        if (a.size() != b.size()) return false;
        for (int i = 0; i < a.size(); i++) if (!Arrays.equals(a.get(i), b.get(i))) return false;
        return true;
    }

        // Checks Example 1: the shared edge at 6 drops the maximum from 5 to 2.
        if (!same(skyline(new int[][]{{2, 6, 3}, {4, 6, 5}, {6, 9, 2}}),
                List.of(new int[]{2, 3}, new int[]{4, 5}, new int[]{6, 2}, new int[]{9, 0}))) throw new AssertionError("example 1");

        // Checks the empty input.

        }

Problem

Finding The First Moment Of Overload

A licence server allows at most 4 simultaneous sessions. Its log holds one record per session with a user count, a start time and an end time. The times are integers up to one billion. An operator asks for the first time at which the licence limit is exceeded.

Checking every possible time is impossible, because one billion times is too many. Checking only the start times is possible, but each check must add up every session that is active at that time. A log with 100,000 sessions makes that repeated addition slow.

A second report asks for the tallest stack of overlapping jobs, and a third asks how many bookings overlap at the busiest moment. Each report has the same shape. The answer depends only on the instants at which something starts or ends.

Formally, the input is a list of half-open intervals [start, end) with weights. The task is to report a maximum, or the first point where a sum passes a limit. This lesson asks how to read the instants in sorted order and keep just enough state to answer without rescanning.

What Each Technique Adds

What Earlier Lessons Contribute

Event Sweeps Supply The Order

The sweep-events lesson turned each interval into two events, a coordinate paired with a change. It sorted the events by coordinate and applied them one after another. The state between two neighbouring coordinates is constant, so one evaluation per coordinate is enough. This lesson reuses that order and adds a data structure to hold the state.

Compression Supplies Only The Needed Coordinates

The compression lesson replaced sparse values with dense ranks, because only the relative order of the coordinates matters. A sweep has the same property. Only coordinates where an event occurs can change the answer, so a billion possible times shrink to at most 2n relevant ones. An ordered map keeps those coordinates sorted without a separate rank table.

Tree Structures Answer Interleaved Queries

The Fenwick and segment tree lessons answered range questions while values changed at fixed positions. They are the right tool when queries ask about arbitrary ranges between updates. A sweep asks one fixed question at each coordinate in order. A sorted map then suffices, and the applicability part names the case where a tree is needed instead.

The Ordered Map

A TreeMap is the Java sorted map. It keeps its keys in increasing order and inserts, finds and removes a key in O(log n) time. It also offers firstKey, lastKey and iteration in key order. The combination of sorted events and a sorted map is the whole subject of this lesson.

Simple approach

Adding Up Every Session At Every Start

The direct approach collects all coordinates, sorts them and recomputes the load at each one by testing every trip. The routine below returns the first coordinate where the load passes the capacity.

static int firstOverloadByScan(int[][] trips, int capacity) {
    int[] stops = new int[trips.length];
    for (int i = 0; i < trips.length; i++) stops[i] = trips[i][1];
    java.util.Arrays.sort(stops);
    for (int x : stops) {
        long load = 0;
        for (int[] t : trips) if (t[1] <= x && x < t[2]) load += t[0];
        if (load > capacity) return x;
    }
    return -1;
}

The routine is correct. The load can only rise at a start, so checking each start is enough. The inner loop reads all n trips for each of n starts. That is the cost to reduce.

Bottleneck

Rescanning Trips Costs Too Much

Predict first: A log holds 100,000 sessions. The routine above tests every session at each of the 100,000 start times. About how many interval tests does it run?

About 10^10 tests, which is O(n^2). Each start re-reads every session, although moving from one start to the next changes the active set by only a few sessions.

Count The Repeated Work

The scan performs n tests for each of n starts, so it runs in O(n^2) time. For n = 100,000 that is 10^10 tests, far beyond a one-second limit. The work is repeated, because two neighbouring starts share almost the same active sessions. The scan throws that sharing away and recomputes the load from nothing.

Count The Cost Of Removal

Reading the maximum of an active set is also hard. Take the skyline task, where each building has a height and the answer at each coordinate is the greatest active height. A single variable maxHeight works while heights only arrive. When the tallest building ends, the variable cannot say which height is next. An unsorted list of active heights fixes that but costs O(n) to search and O(n) to delete from. The target is O(log n) per event, which gives O(n log n) for the whole sweep.

Key idea

Keep Net Changes In A Sorted Map

Store Net Changes In A Delta Map

Keep a delta map, which is a TreeMap from coordinate to the net change in weight at that coordinate. A trip adds its passengers at its start key and subtracts them at its end key. Adding to an existing key merges the two changes into one value. Reading the map in key order and keeping a running sum gives the load on every span, with no sorting step of its own.

Store Active Values In An Active Multiset

Some answers need the extreme of the currently active values and not their sum. For that, keep an active multiset, which is a TreeMap from value to the number of active items with that value. Java has no multiset class, so the count plays that role. Inserting a height increments its count. Removing one decrements the count and deletes the key at zero. lastKey then returns the greatest active height in O(log n) time, even after the tallest building ends.

Fix A Tie Policy

Events at one coordinate need a tie policy, which is the rule for the order in which they are applied and when the state is read. For half-open intervals [start, end), all changes at coordinate x apply before the state is read, so an ending interval and a starting interval at x never overlap. For closed intervals [start, end], an interval that ends at x still counts at x, so the starts at x apply first and the state is read before the ends apply. A delta map merges all changes at one key, so it fits only the half-open rule. A closed integer interval fits it after the end moves to end + 1. The tie policy follows from the interval contract and is chosen before any code.

Under the half-open rule the invariant is the same for both structures. After all events at coordinate x are applied, the state describes exactly the span from x up to the next event coordinate.

State

Quantities To Track During The Sweep

Track these seven quantities across the sweeps in this lesson.

  • delta map holds the net change in weight at each event coordinate, in sorted order.
  • load is the running sum of the deltas applied so far, kept as a long.
  • active multiset maps each active height to the number of active buildings with it.
  • height is the greatest key of the active multiset after a coordinate, or 0 when it is empty.
  • best height is the greatest height seen so far.
  • best x is the coordinate where the best height first appeared.
  • end x is the first later coordinate whose height is lower than the best height, and it stays -1 while the stretch is open.

In the code, the delta map is the variable change, and the active multiset is the variable active. In the second trace, bestH, bestX and endX are best height, best x and end x. The names differ only because the code and trace use short identifiers.

Walkthrough

Two Sweeps Step By Step

Overload Check With Merged Changes

Take capacity 4 and four trips written as passengers, from, to: (2, 1, 4), (1, 2, 6), (2, 4, 8) and (3, 6, 9). The delta map holds +2 at 1, +1 at 2, 0 at 4, +2 at 6, -2 at 8 and -3 at 9.

The value at key 4 is zero, because the first trip ends there and the third trip starts there. That merge is the half-open tie policy at work. The load stays 3 across coordinate 4, and no false drop or spike appears.

The sweep adds +2 to reach 2, adds +1 to reach 3, keeps 3 at key 4 and adds +2 to reach 5 at key 6. Since 5 exceeds 4, the sweep returns coordinate 6 and stops.

Tallest Stretch With Touching Buildings

Take four buildings written as left, right, height: (1, 6, 3), (4, 9, 5), (6, 8, 2) and (8, 11, 5). The event coordinates are 1, 4, 6, 8, 9 and 11.

At coordinate 4 the height 5 appears for the first time, so best height is 5 and best x is 4. At coordinate 6 the height 3 ends and the height 2 starts, and the greatest key stays 5. At coordinate 8 the height 2 ends and a second height 5 starts, so the count for key 5 becomes 2.

At coordinate 9 the first height 5 ends. The count for key 5 drops from 2 to 1, so the key stays and the height is still 5. Without counts, the key would vanish and the sweep would report a false drop. At coordinate 11 the last building ends, the map is empty, and the stretch closes with end x equal to 11.

Code

Two Sweep Methods With TreeMap

static long peakLoad(int[][] trips) {
    java.util.TreeMap<Integer, Long> change = new java.util.TreeMap<>();
    for (int[] t : trips) {
        change.merge(t[1], (long) t[0], Long::sum);
        change.merge(t[2], -(long) t[0], Long::sum);
    }
    long load = 0, peak = 0;
    for (long delta : change.values()) {
        load += delta;
        peak = Math.max(peak, load);
    }
    return peak;
}

static int firstOverload(int[][] trips, int capacity) {
    java.util.TreeMap<Integer, Long> change = new java.util.TreeMap<>();
    for (int[] t : trips) {
        change.merge(t[1], (long) t[0], Long::sum);
        change.merge(t[2], -(long) t[0], Long::sum);
    }
    long load = 0;
    for (var entry : change.entrySet()) {
        load += entry.getValue();                  // the merged change is applied as one step
        if (load > capacity) return entry.getKey();   // the load holds until the next key
    }
    return -1;
}

static void addHeight(java.util.TreeMap<Integer, Integer> active, int h) {
    active.merge(h, 1, Integer::sum);
}

static void removeHeight(java.util.TreeMap<Integer, Integer> active, int h) {
    if (active.merge(h, -1, Integer::sum) == 0) active.remove(h);
}

static int greatestHeight(java.util.TreeMap<Integer, Integer> active) {
    return active.isEmpty() ? 0 : active.lastKey();
}

static int[] tallestStretch(int[][] buildings) {
    java.util.TreeMap<Integer, java.util.List<int[]>> at = new java.util.TreeMap<>();
    for (int[] b : buildings) {
        at.computeIfAbsent(b[0], k -> new java.util.ArrayList<>()).add(new int[]{b[2], 1});
        at.computeIfAbsent(b[1], k -> new java.util.ArrayList<>()).add(new int[]{b[2], -1});
    }
    java.util.TreeMap<Integer, Integer> active = new java.util.TreeMap<>();
    int bestH = 0, bestX = -1, endX = -1;
    for (var group : at.entrySet()) {
        for (int[] ev : group.getValue()) {          // apply the whole group before reading
            if (ev[1] == 1) addHeight(active, ev[0]); else removeHeight(active, ev[0]);
        }
        int height = greatestHeight(active);
        if (height > bestH) { bestH = height; bestX = group.getKey(); endX = -1; }   // a new best opens a stretch
        else if (height < bestH && endX == -1) endX = group.getKey();           // the first lower height closes it
    }
    return new int[]{bestH, bestX, endX};
}

The method peakLoad needs only the values of the delta map, because the keys matter for order and not for arithmetic. The method firstOverload also reads the keys, because it returns the coordinate where the load first passes the capacity. The three helpers wrap the multiset operations, and removeHeight is the single place where a key disappears, when its count reaches zero. The method tallestStretch applies every event at one coordinate before it reads greatestHeight. Each map operation costs O(log n), so a sweep over 2n events costs O(n log n) in total.

When to use it

When To Sweep With Ordered State

Recognize The Pattern

Reach for this combination when each item is an interval with a weight or a value. The question asks for a maximum, a total or a first violation over all points. The answer then changes only at interval boundaries. Car loads, overlapping bookings and skylines share that cue.

The invariant is that the state after each coordinate describes the span up to the next coordinate. If the question instead asks about an arbitrary query range between updates, the answer depends on the query and a Fenwick or segment tree is the better fit.

Choose The Tie Policy From The Contract

Read whether the end coordinate belongs to the interval. Half-open ends apply with starts at one coordinate before the state is read. Closed ends need starts first and the state read before the ends apply. A skipped decision here produces off-by-one answers that pass most random tests and fail on touching intervals.

Avoid The False Friend

A single running maximum is a false friend of the active multiset. It looks like enough state, but it cannot recover the next value when the current maximum leaves. A PriorityQueue is a related trap, because its remove(Object) call costs O(n) in Java. A TreeMap of counts removes in O(log n).

One Java hazard remains. Sums of weights can pass int range, so use long.

First Overloaded Stop

LeetCode 1094

Problem Specification. A vehicle has capacity seats. Each trip is [passengers, from, to]. The riders of a trip occupy seats at every integer coordinate x with from <= x < to. The load at x is the sum of passengers over all trips that occupy x. Return the smallest integer coordinate whose load is greater than capacity. Return -1 if no coordinate has such a load.

Input Constraints. The limits are:

  • Trips number between 1 and 100,000, and the order is arbitrary.
  • passengers is an int from 1 to 100.
  • Coordinates satisfy 0 <= from < to <= 1,000,000,000.
  • capacity is an int from 1 to 1,000,000,000.
  • Input is not modified.

Example 1. Input capacity 4 and trips [[2,1,5],[3,3,7],[4,5,9]], output 3, because the load at coordinate 3 is 2 + 3 = 5.

Example 2. Input capacity 3 and trips [[3,1,4],[3,4,7]], output -1, because the first trip frees its seats at coordinate 4 before the second trip fills them.

Prerequisites. The delta map and the half-open tie policy from this lesson.

What This Exercise Changes. The original asks whether the capacity is ever exceeded. This version returns the first coordinate where it is exceeded.

Hint

Where can the load change? What happens to a drop-off and a pickup at the same coordinate?

Algorithmic Solution (attempt the problem first)

Approach. The solution stores one net change per coordinate in a sorted map and reads the map in key order.

Each trip adds +passengers at from and -passengers at to. The map merges every change at one coordinate into a single value, so equal coordinates are already grouped. The sweep then adds the values in increasing key order. After adding the value for key x, the running load equals the load on the span that starts at x. The first key whose running load exceeds the capacity is the answer, because the load cannot change between two keys. A trip that ends at x and a trip that starts at x cancel inside one merged value, which implements the half-open rule. The sum uses long, so the totals stay safe even when the limits grow.

Complexity.

  • Time is O(n log n), because the map performs 2n merges at O(log n) each and the sweep visits at most 2n keys.
  • Space is O(n), because the map holds at most one entry per distinct coordinate, which is at most 2n.
import java.util.Map;
import java.util.Random;
import java.util.TreeMap;

public final class FirstOverloadStop {
    /**
     * Returns the smallest coordinate whose load exceeds the capacity, or -1.
     * Time: O(n log n), because each of the 2n merges costs O(log n) and the sweep reads 2n keys.
     * Space: O(n), because the map keeps one net change per distinct coordinate.
     * Invariant: after key x is applied, load equals the passengers seated on the span starting at x.
     */
    static int firstOverload(int[][] trips, int capacity) {
        // The map keeps coordinates sorted and merges equal coordinates into one net change.
        TreeMap<Integer, Long> change = new TreeMap<>();
        // One pass over the trips costs O(n) iterations.
        for (int[] t : trips) {
            // Boarding raises the load at the start coordinate; merge costs O(log n).
            change.merge(t[1], (long) t[0], Long::sum);
            // Leaving lowers the load at the end coordinate, so the seat is free from that coordinate on.
            change.merge(t[2], -(long) t[0], Long::sum);
        }
        // The running load is a long so that large passenger counts cannot overflow it.
        long load = 0;
        // Entries arrive in increasing coordinate order, which is the sweep order.
        for (Map.Entry<Integer, Long> e : change.entrySet()) {
            // Apply the whole merged change for this coordinate before looking at the load.
            load += e.getValue();
            // The load is constant until the next key, so the first key above capacity is the first bad coordinate.
            if (load > capacity) return e.getKey();
        }
        // No span exceeded the capacity.
        return -1;
    }

    /** Brute-force oracle that evaluates every integer coordinate in range. */
    static int oracle(int[][] trips, int capacity) {
        // Scan each integer coordinate from 0 to the largest end.
        for (int x = 0; x <= 60; x++) {
            // Recompute the load at x from scratch.
            long load = 0;
            // A trip occupies x when from <= x < to.
            for (int[] t : trips) if (t[1] <= x && x < t[2]) load += t[0];
            // The first exceeding coordinate is the answer.
            if (load > capacity) return x;
        }
        // Nothing exceeded the capacity.
        return -1;
    }

    public static void main(String[] args) {
        // Checks Example 1: the load reaches 5 at coordinate 3.
        if (firstOverload(new int[][]{{2, 1, 5}, {3, 3, 7}, {4, 5, 9}}, 4) != 3) throw new AssertionError("example 1");
        // Checks Example 2: a trip that ends at 4 frees its seats for the trip that starts at 4.
        if (firstOverload(new int[][]{{3, 1, 4}, {3, 4, 7}}, 3) != -1) throw new AssertionError("example 2");
        // Checks the lesson trace input: the net change at coordinate 4 is zero and the overload starts at 6.
        if (firstOverload(new int[][]{{2, 1, 4}, {1, 2, 6}, {2, 4, 8}, {3, 6, 9}}, 4) != 6) throw new AssertionError("trace input");
        // Checks 2000 random inputs against the oracle with a fixed seed.
        Random rnd = new Random(9101L);
        for (int iter = 0; iter < 2000; iter++) {
            // Build a random trip list with 1 to 6 trips on small coordinates.
            int n = 1 + rnd.nextInt(6);
            int[][] trips = new int[n][];
            for (int i = 0; i < n; i++) {
                int from = rnd.nextInt(40), to = from + 1 + rnd.nextInt(15);
                trips[i] = new int[]{1 + rnd.nextInt(5), from, to};
            }
            int cap = 1 + rnd.nextInt(10);
            if (firstOverload(trips, cap) != oracle(trips, cap)) throw new AssertionError("random mismatch at " + iter);
        }
    }

LeetCode 218

Problem Specification. Each building is [left, right, height] and covers every integer coordinate x with left <= x < right. Hint

Algorithmic Solution (attempt the problem first)

Approach. The sweep keeps the heights of active buildings in a sorted map from height to count.

Events are grouped by coordinate. At each coordinate the sweep first applies every start and every end, and only then reads the greatest key of the map. That tie policy matters for two touching buildings, because the end of one and the start of the next must not produce a false drop. Removal decrements the count and deletes the key when the count reaches zero, so equal heights are not lost when only one of them ends.

After each coordinate the current height is the greatest key, or 0 when the map is empty. A height above the best so far starts a new best stretch at that coordinate and marks it open. The first later coordinate whose height is below the best closes the stretch. Because all heights are positive and the last end empties the map, the stretch always closes.

Complexity.

  • Time is O(n log n), because sorting the coordinates and the map updates cost O(log n) per event over 2n events.
  • Space is O(n), because the event table and the height map hold at most 2n and n entries.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;
import java.util.TreeMap;

public final class SkylineTallest {
    /**
     * Returns {greatest height, leftmost coordinate with it, first coordinate where it ends}.
     * Time: O(n log n), because there are 2n events and each map update costs O(log n).
     * Space: O(n), because events and active heights are stored.
     * Invariant: after all events at x are applied, the greatest key is the skyline height on [x, next event).
     */
    static int[] tallest(int[][] buildings) {
        // Events are grouped by coordinate; each value lists {height, +1 for start or -1 for end}.
        TreeMap<Integer, List<int[]>> events = new TreeMap<>();
        // One pass over the buildings costs O(n) iterations.
        for (int[] b : buildings) {
            // The start event adds the height to the active set at the left coordinate.
            events.computeIfAbsent(b[0], k -> new ArrayList<>()).add(new int[]{b[2], 1});
            // The end event removes it at the right coordinate, so the building covers [left, right).
            events.computeIfAbsent(b[1], k -> new ArrayList<>()).add(new int[]{b[2], -1});
        }
        // Active heights map to the number of active buildings with that height.
        TreeMap<Integer, Integer> active = new TreeMap<>();
        // The best stretch starts empty; endX stays -1 while the stretch is open.
        int bestH = 0, bestX = -1, endX = -1;
        // A flag that says the best stretch has not yet closed.
        boolean open = false;
        // Visit coordinates in increasing order, which is the sweep order.
        for (var entry : events.entrySet()) {
            // Apply every event at this coordinate before reading the height, so ties cannot create a false drop.
            for (int[] ev : entry.getValue()) {
                if (ev[1] == 1) {
                    // A start increments the count for its height.
                    active.merge(ev[0], 1, Integer::sum);
                } else {
                    // An end decrements the count; the key goes away only when the count reaches zero.
                    int left = active.get(ev[0]) - 1;
                    if (left == 0) active.remove(ev[0]); else active.put(ev[0], left);
                }
            }
            // The skyline height is the greatest active height, or 0 when nothing is active.
            int h = active.isEmpty() ? 0 : active.lastKey();
            // A strictly greater height starts a new best stretch at this coordinate.
            if (h > bestH) { bestH = h; bestX = entry.getKey(); endX = -1; open = true; }
            // The first lower height after the best stretch began closes it.
            else if (open && h < bestH) { endX = entry.getKey(); open = false; }
        }
        // Return the three values the contract asks for.
        return new int[]{bestH, bestX, endX};
    }

    /** Brute-force oracle that computes the height at every integer coordinate. */
    static int[] oracle(int[][] buildings) {
        // Heights for coordinates 0..59 are enough for the random inputs.
        int[] h = new int[60];
        // Each coordinate takes the maximum height of the buildings covering it.
        for (int x = 0; x < 60; x++) for (int[] b : buildings) if (b[0] <= x && x < b[1]) h[x] = Math.max(h[x], b[2]);
        // Find the greatest height.
        int m = 0;
        for (int v : h) m = Math.max(m, v);
        // The leftmost coordinate with that height starts the stretch.
        int s = 0;
        while (h[s] != m) s++;
        // The stretch ends at the first later coordinate below the greatest height.
        int e = s;
        while (h[e] == m) e++;
        // Return the same triple as the sweep.
        return new int[]{m, s, e};
    }

        // Checks Example 1: height 9 starts at coordinate 2 and ends at 8.
        int[][] ex1 = {{1, 5, 7}, {2, 4, 9}, {3, 8, 9}, {6, 10, 4}};

Edge Cases

Equal-Coordinate Events

Author exercise

Problem Specification. Given integer intervals [start, end] and a flag closed, return the largest number of intervals that contain one common integer coordinate, and the smallest coordinate where that number occurs. When closed is true, an interval contains every x with start <= x <= end. When closed is false, it contains every x with start <= x < end, so an interval with start == end contains nothing.

Input Constraints. The limits are:

  • Intervals number between 1 and 100,000, and the order is arbitrary.
  • Coordinates satisfy 0 <= start <= end <= 1,000,000,000.
  • closed is a boolean that applies to every interval.
  • Result is an int[] of the form {count, coordinate}, and {0, -1} is possible when closed is false and all intervals are empty.

Example 1. Input [[1,3],[3,5]], output {1, 1} when closed is false and {2, 3} when closed is true.

Example 2. Input [[2,6],[6,9],[4,6],[6,6]], output {2, 4} when closed is false and {4, 6} when closed is true.

Prerequisites. The tie policy from this lesson.

What This Exercise Changes. The interval contract changes between the two calls, and the result also names the first coordinate of the maximum, so the event order at equal coordinates must change with it and the load must be read at the right moment.

Hint

At one coordinate, should a start or an end come first? When does the running load first reach its maximum?

Algorithmic Solution (attempt the problem first)

Approach. The solution turns each interval into two events and sorts them with a tie rule that depends on the interval kind.

For half-open intervals, an end at coordinate x must come before a start at x, because the ended interval no longer contains x. For closed intervals, a start at x must come before an end at x, because the ending interval still contains x. The comparator sorts by coordinate first and by the delta sign second, with the sign order reversed between the two kinds. The sweep adds each delta and records the largest running load after every event, together with the coordinate of the first event that reaches it. An empty half-open interval, where start == end, contains no coordinate, so the solution skips it.

The invariant is that the running load after any prefix of events never exceeds the true overlap at the coordinate being processed, and it equals the true overlap after the last event at that coordinate. The tie rule makes the first part hold.

Complexity.

  • Time is O(n log n), because sorting 2n events dominates and the sweep is linear.
  • Space is O(n), because the event table holds 2n pairs.
import java.util.Arrays;
import java.util.Random;

public final class EqualCoordinateEvents {
    /**
     * Returns {largest number of intervals that contain one common integer coordinate, smallest such coordinate}, or {0, -1}.
     * Time: O(n log n), because sorting 2n events dominates the linear sweep.
     * Space: O(n), because the event table holds two entries per interval.
     * Invariant: with the tie rule applied, the running load equals the overlap after each event.
     */
    static int[] maxOverlap(int[][] intervals, boolean closed) {
        // Events are {coordinate, delta}; two per interval.
        int[][] ev = new int[intervals.length * 2][];
        // Count of events actually created, because empty half-open intervals add none.
        int m = 0;
        // One pass over the intervals costs O(n) iterations.
        for (int[] iv : intervals) {
            // An empty half-open interval contains no coordinate, so it creates no events.
            if (!closed && iv[0] == iv[1]) continue;
            // The start raises the load by one.
            ev[m++] = new int[]{iv[0], 1};
            // The end lowers the load by one.
            ev[m++] = new int[]{iv[1], -1};
        }
        // Sort by coordinate, then by delta sign according to the interval kind; this is the O(n log n) step.
        Arrays.sort(ev, 0, m, (a, b) -> {
            // Different coordinates sort by coordinate alone.
            if (a[0] != b[0]) return Integer.compare(a[0], b[0]);
            // Closed intervals put starts (+1) first; half-open intervals put ends (-1) first.
            return closed ? Integer.compare(b[1], a[1]) : Integer.compare(a[1], b[1]);
        });
        // The running load and the best load seen so far.
        int load = 0, best = 0, where = -1;
        // Apply events in sorted order, which is the sweep order.
        for (int i = 0; i < m; i++) {
            // Each event changes the load by its delta.
            load += ev[i][1];
            // A strictly larger load marks the first coordinate that reaches the new best.
            if (load > best) { best = load; where = ev[i][0]; }
        }
        // Return the largest overlap and where it first occurs.
        return new int[]{best, where};
    }

    /** Brute-force oracle that counts containing intervals at every integer coordinate. */
    static int[] oracle(int[][] intervals, boolean closed) {
        // The best count over all coordinates.
        int best = 0, where = -1;
        // Coordinates 0..59 cover the random inputs.
        for (int x = 0; x < 60; x++) {
            // Count the intervals that contain x under the chosen kind.
            int c = 0;
            for (int[] iv : intervals) if (closed ? (iv[0] <= x && x <= iv[1]) : (iv[0] <= x && x < iv[1])) c++;
            if (c > best) { best = c; where = x; }
        }
        // Return the best count and its first coordinate.
        return new int[]{best, where};
    }

    public static void main(String[] args) {
        // Checks Example 1: touching intervals overlap only when the ends are included.
        int[][] touching = {{1, 3}, {3, 5}};
        if (!Arrays.equals(maxOverlap(touching, false), new int[]{1, 1})) throw new AssertionError("half-open touching");
        if (!Arrays.equals(maxOverlap(touching, true), new int[]{2, 3})) throw new AssertionError("closed touching");
        // Checks Example 2: the zero-length interval counts only when the ends are included.
        int[][] mixed = {{2, 6}, {6, 9}, {4, 6}, {6, 6}};
        if (!Arrays.equals(maxOverlap(mixed, false), new int[]{2, 4})) throw new AssertionError("half-open mixed");
        if (!Arrays.equals(maxOverlap(mixed, true), new int[]{4, 6})) throw new AssertionError("closed mixed");
        // Checks 3000 random inputs for both kinds against the oracle with a fixed seed.
        Random rnd = new Random(9103L);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(7);
            int[][] iv = new int[n][];
            for (int i = 0; i < n; i++) {
                int s = rnd.nextInt(30);
                iv[i] = new int[]{s, s + rnd.nextInt(10)};
            }
            if (!Arrays.equals(maxOverlap(iv, false), oracle(iv, false))) throw new AssertionError("half-open mismatch at " + iter);
            if (!Arrays.equals(maxOverlap(iv, true), oracle(iv, true))) throw new AssertionError("closed mismatch at " + iter);
        }
    }

Busiest Moment After Each Booking

LeetCode 732

Problem Specification. Design a class with a method int[] book(int start, int end). Each call adds the booking [start, end). It returns [k, x], where k is the largest number of bookings so far that cover one integer coordinate, and x is the smallest coordinate covered by k bookings.

Input Constraints. The limits are:

  • Calls number at most 400.
  • Coordinates satisfy 0 <= start < end <= 1,000,000,000.
  • Bookings stay stored, and none is ever removed.
  • Touching bookings, where one end equals another start, do not overlap.

Example 1. Input the calls book(4,8), book(8,12), book(6,10), book(1,5), output [1,4], [1,4], [2,6], [2,4].

Example 2. Input the calls book(3,9), book(9,14), book(1,3), output [1,3], [1,3], [1,1], because touching bookings never overlap.

Prerequisites. The delta map and all three exercises above.

What This Exercise Changes. The original returns only the maximum. This version also returns the leftmost coordinate that reaches it.

Hint

What does a booking add to the map? How is the leftmost coordinate of the maximum kept during the pass?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps one sorted map of net changes and rescans it after every booking.

A booking [start, end) adds +1 at start and -1 at end. Equal coordinates merge into one value, so a booking that ends where another begins does not overlap it. After the update, a sweep over the map adds the values in key order. The running sum equals the number of bookings active on the span that starts at each key. The sweep keeps the largest sum and the first key where that sum is reached. A strict comparison keeps the leftmost key.

The rescan visits every key, so each booking costs time linear in the number of bookings so far. A segment tree with lazy updates would lower that cost, but it needs the compressed coordinate set in advance.

Complexity.

  • Time is O(n) per booking and O(n^2) for n bookings, because each booking performs two O(log n) merges and one pass over up to 2n keys.
  • Space is O(n), because the map holds one entry per distinct boundary.
import java.util.Arrays;
import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.Random;
import java.util.TreeMap;

public final class CalendarBusiest {
    /** Net change in the number of active bookings, keyed by coordinate. */
    private final TreeMap<Integer, Integer> change = new TreeMap<>();

    /**
     * Adds the booking [start, end) and returns {largest overlap, leftmost coordinate reaching it}.
     * Time: O(n) per call, because two merges cost O(log n) and the rescan visits up to 2n keys.
     * Space: O(1) extra per call, because only counters are kept besides the map.
     * Invariant: the prefix sum of the map up to key x equals the bookings active on [x, next key).
     */
    int[] book(int start, int end) {
        // The booking becomes active at start.
        change.merge(start, 1, Integer::sum);
        // The booking stops being active at end, so the interval is half-open.
        change.merge(end, -1, Integer::sum);
        // Running overlap, the best overlap and the coordinate where the best first appears.
        int run = 0, best = 0, at = start;
        // Visit keys in increasing order; the cost is linear in the number of keys.
        for (Map.Entry<Integer, Integer> e : change.entrySet()) {
            // Add the merged change for this coordinate.
            run += e.getValue();
            // A strictly greater overlap records the key, so ties keep the leftmost key.
            if (run > best) { best = run; at = e.getKey(); }
        }
        // Return the pair the contract asks for.
        return new int[]{best, at};
    }

    /** Brute-force oracle that rescans every integer coordinate over a list of bookings. */
    static int[] oracleAfter(List<int[]> bookings) {
        // Best overlap and the leftmost coordinate that reaches it.
        int best = 0, at = 0;
        // Coordinates 0..59 cover the random inputs.
        for (int x = 0; x < 60; x++) {
            // Count bookings containing x.
            int c = 0;
            for (int[] b : bookings) if (b[0] <= x && x < b[1]) c++;
            // Strict comparison keeps the leftmost coordinate.
            if (c > best) { best = c; at = x; }
        }
        // Return the pair.
        return new int[]{best, at};
    }

    public static void main(String[] args) {
        // Checks Example 1: results after each of four bookings.
        CalendarBusiest c1 = new CalendarBusiest();
        int[][] in1 = {{4, 8}, {8, 12}, {6, 10}, {1, 5}};
        int[][] out1 = {{1, 4}, {1, 4}, {2, 6}, {2, 4}};
        for (int i = 0; i < in1.length; i++) {
            if (!Arrays.equals(c1.book(in1[i][0], in1[i][1]), out1[i])) throw new AssertionError("example 1 step " + i);
        }
        // Checks Example 2: a booking that touches another at coordinate 9 or 3 adds no overlap.
        CalendarBusiest c2 = new CalendarBusiest();
        int[][] in2 = {{3, 9}, {9, 14}, {1, 3}};
        int[][] out2 = {{1, 3}, {1, 3}, {1, 1}};
        for (int i = 0; i < in2.length; i++) {
            if (!Arrays.equals(c2.book(in2[i][0], in2[i][1]), out2[i])) throw new AssertionError("example 2 step " + i);
        }
        // Checks 1000 random booking sequences against the oracle with a fixed seed.
        Random rnd = new Random(9104L);
        for (int iter = 0; iter < 1000; iter++) {
            CalendarBusiest cal = new CalendarBusiest();
            List<int[]> seen = new ArrayList<>();
            for (int k = 0; k < 8; k++) {
                int s = rnd.nextInt(40);
                int[] b = {s, s + 1 + rnd.nextInt(15)};
                seen.add(b);
                if (!Arrays.equals(cal.book(b[0], b[1]), oracleAfter(seen))) throw new AssertionError("random mismatch at " + iter + "," + k);
            }
        }
    }

Problem

A Counter Too Large For Memory

A monitoring service receives sensor readings one at a time. Each reading is a signed 32-bit integer, and readings such as -2,000,000,000 and 1,500,000,000 occur. For every new reading, the service must report how many earlier readings were strictly smaller. A stream of 100,000 readings arrives, and many readings repeat.

The first idea is a counter array with one slot per possible value. A slot for every 32-bit integer needs about 4.3 billion cells. A long[] of that size takes about 34 gigabytes, and a stream of 100,000 readings uses at most 100,000 of those cells. The memory request fails long before the first reading is processed.

Formally, the input is an int[] values. For each position i, the output is the number of positions j < i with values[j] < values[i]. The answer must use equality correctly, because a repeated reading is not smaller than itself.

This lesson asks how to answer that question for sparse values in O(n log n) time while the memory stays proportional to the number of readings.

What Each Technique Adds

What Two Earlier Skills Add

Compression Adds A Small Key Space

Coordinate compression sorts the distinct values and replaces each value with its position in that sorted list, starting at 1. The replacement keeps order and equality. If a < b holds for two readings, the same holds for their positions, and equal readings share one position. The key space shrinks from billions of possible values to at most n positions.

The Fenwick Tree Adds Cheap Prefix Sums

The Fenwick tree from the first lesson of this chapter stores one long per position in a one-based array. It supports add(pos, delta) and prefix(pos), which returns the sum of positions 1 through pos. Both operations take O(log m) time for m positions. The code in this lesson uses the internal one-based form, so add takes the rank itself. The first lesson's add took a zero-based position and added 1 before the loop.

The two skills fit because each covers the weakness of the other. Compression gives small positions that a tree array can hold, and the tree answers how many stored items lie at or below a position. Neither skill alone solves the sensor problem.

Simple approach

Scanning Every Earlier Reading

The direct method compares each reading with all readings before it. It needs no extra memory and is correct for any input.

static int[] smallerBeforeScan(int[] values) {
    int n = values.length;
    int[] out = new int[n];
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < i; j++) {
            if (values[j] < values[i]) out[i]++;
        }
    }
    return out;
}

The method is easy to trust, and it also makes a good test oracle for faster code. The inner loop reads every earlier position once. For a stream of 100,000 readings, the total is about 5 billion comparisons.

Bottleneck

The Scan Repeats Work On Every Reading

Predict first: A stream has 100,000 readings. The scan compares each reading with every earlier one. About how many comparisons does it make in total, and can a counter array indexed by value avoid them?

About 5 billion comparisons, because the inner loop runs 0, 1, 2 and so on up to 99,999 times, and that sum is n(n - 1) / 2. A counter array indexed by value avoids the comparisons but needs a cell for every possible 32-bit value, which is about 4.3 billion cells and far too much memory.

Count The Comparisons

The scan costs O(n^2) time. At roughly one billion simple comparisons per second, 5 billion comparisons take several seconds, and a stream ten times longer takes minutes. The scan also learns nothing that later readings can reuse. When reading 70,000 arrives, the scan examines readings 0 to 69,999 again, although it examined nearly all of them for reading 69,999.

Find The Two Opposing Costs

A counter array indexed by value answers a query by summing the cells below the reading. That sum still costs time proportional to the number of cells, and the array needs a cell per possible value. The scan needs O(1) extra memory but O(n^2) time. The value-indexed array needs O(V) memory for the largest value V, and a query still costs O(V) time. Both costs are too high. The goal is a structure whose memory depends on the number of readings and whose query cost depends on the logarithm of that number.

Key idea

Rank Values Then Count With A Tree

The two weaknesses have separate fixes. Order is the only property the question uses, so exact values can be replaced. A tree that adds up stored counts by position can then answer the query.

Replace Values With A Dense Rank

Sort the distinct values of the input into a list keys in increasing order. The dense rank of a value is its index in keys plus 1, so ranks run from 1 to m, where m is the number of distinct values. Equal values share one rank, and no rank is skipped. For [30, -5, 30, 1000000, -5, 7], the keys are [-5, 7, 30, 1000000], and the ranks are 3, 1, 3, 4, 1, 2.

The rank lookup finds a value's rank with binary search on keys. It costs O(log m) time per reading and needs no hash table. When the value is absent, Arrays.binarySearch returns -p - 1, where p is the number of keys smaller than the value, so the same call also counts the keys below any bound. Sorting costs O(n log n) time once, and the array keys uses O(m) memory. The lookup uses the sorted array, so the order of the values stays intact.

Count Stored Readings With A Prefix Query

Create a Fenwick tree over positions 1 to m. When a reading arrives, add 1 at the position of its rank. The tree then holds, for each rank, how many readings with that rank have been seen. The prefix count is the sum of positions 1 through rank - 1, and it equals the number of earlier readings with a strictly smaller rank. Because compression preserves order, those are exactly the earlier readings with a strictly smaller value.

The query happens before the add. Reading the prefix first keeps the current reading out of its own count. The query is prefix(rank - 1) for strictly smaller readings and prefix(rank) for smaller or equal readings. A reading of rank 1 asks for prefix(0), which is 0 and needs no special case.

The invariant is that after i readings are processed, the tree holds one count for each earlier reading at the position of its rank. Every query therefore describes only the readings before it.

State

Quantities For The Rank Counter

The code below uses these quantities for the stream [30, -5, 30, 1000000, -5, 7].

  • keys is the sorted array of distinct values, here [-5, 7, 30, 1000000], with m = 4.
  • rank is the position of the current reading in keys plus 1, between 1 and m.
  • tree is the Fenwick array of m + 1 longs, where index 0 stays unused.
  • smaller is prefix(rank - 1), the number of earlier readings with a strictly smaller value.
  • total is the running sum of smaller over all processed readings.

In the code, the Fenwick object is named seen, and smaller is stored directly in out[i]. The running total appears only in the trace, as a check on the sum of the answers. In the trace, the variable counts shows how many readings of each rank have been added, listed from rank 1 to rank m. The array tree holds sums of blocks of those counts, so a trace shows counts because it is easier to read.

Walkthrough

Process Two Streams Of Readings

A Stream With Repeated Values

The first stream is [30, -5, 30, 1000000, -5, 7]. The keys are [-5, 7, 30, 1000000]. The pointer i marks the reading in progress, and each step shows the answer for that reading, taken before the reading is added.

The first reading, 30, has rank 3 and finds an empty tree, so its answer is 0. The second reading, -5, has rank 1, so its query covers no ranks and returns 0. The third reading, 30, has rank 3 again, and prefix(2) finds only the -5, so the answer is 1. The earlier 30 is not counted, because an equal value is not smaller.

The reading 1000000 has rank 4, and prefix(3) counts the two 30s and the -5, so the answer is 3. The next -5 answers 0, and the final 7 has rank 2, so it counts only the two readings of -5 and answers 2.

A Stream With Extreme Values

The second stream is [9, 2000000000, -3, 9, 2000000000, 0, -3]. The keys are [-3, 0, 9, 2000000000]. The value 2,000,000,000 is far above the others, and compression gives it rank 4, the same as any other largest value.

The hardest step is the fifth reading. The value 2,000,000,000 appears for the second time. Its rank is 4, and prefix(3) counts the readings 9, -3 and 9, so the answer is 3. The earlier 2,000,000,000 does not count. The last step repeats the lowest value -3 and answers 0, because no earlier reading is smaller.

Code

Rank Values And Query The Tree

The class below holds the tree, the compression step and the counting loop.

final class RankCounter {
    static final class Fenwick {
        final long[] tree;
        Fenwick(int size) { tree = new long[size + 1]; }
        void add(int pos, long delta) {
            for (int i = pos; i < tree.length; i += i & -i) tree[i] += delta;
        }
        long prefix(int pos) {
            long sum = 0;
            for (int i = pos; i > 0; i -= i & -i) sum += tree[i];
            return sum;
        }
    }

    static int[] distinctSorted(int[] values) {
        int[] sorted = values.clone();
        java.util.Arrays.sort(sorted);
        int m = 0;
        for (int v : sorted) {
            if (m == 0 || sorted[m - 1] != v) sorted[m++] = v;
        }
        return java.util.Arrays.copyOf(sorted, m);
    }

    static int[] smallerBefore(int[] values) {
        int[] keys = distinctSorted(values);
        Fenwick seen = new Fenwick(keys.length);
        int[] out = new int[values.length];
        for (int i = 0; i < values.length; i++) {
            int rank = java.util.Arrays.binarySearch(keys, values[i]) + 1;
            out[i] = (int) seen.prefix(rank - 1);
            seen.add(rank, 1);
        }
        return out;
    }
}

The code runs in O(n log n) time. Sorting takes O(n log n), and each reading costs one binary search plus one prefix query and one add, each O(log m). Memory is O(n) for the copy, the keys and the tree. The binary search always finds a hit, because every reading is in keys. An empty input gives an empty keys, a tree of size 0 and an empty result. The tree stores long values, because the sums in later exercises can pass the int range.

When to use it

When Ranks And A Tree Fit

Recognize The Cue

Use this pair when the question compares values by order, the values are sparse or huge, and the data changes between queries. Typical signals are counting earlier smaller items, counting inversions, and keeping a running count of values in a range while items arrive. Plain compression is enough when nothing changes. The tree is needed when the answer must follow each addition.

Check The Invariant

The invariant is that the tree holds one count per processed reading at the position of its rank. Test it with an empty input, one value, all-equal values, strictly ascending and descending input, and the extreme values Integer.MIN_VALUE and Integer.MAX_VALUE. Compare the result against the scan on random small inputs.

Watch For The False Friend

The first false friend is a plain HashMap from value to count. A hash map answers how often one exact value occurred, and it cannot answer how many values lie below it without scanning. The second false friend is the comparison a - b inside a custom sort. It overflows for extreme values and breaks the order that the ranks rely on. Use Integer.compare or sort primitives directly.

Know When Not To Use It

Skip compression when the values already form a small dense range, since a direct array is simpler. Skip it when the query values are not known when the structure is built and cannot be ranked in advance. In that case an ordered tree structure supports insertion directly. Also stay with the scan for very small inputs, where the logarithmic factors cost more than they save.

Author exercise

Problem Specification. An int[] values and an int[] queries are given. Let keys be the distinct entries of values in increasing order. The rank of a value is its 1-based position in keys. For each query, return how many entries of keys are strictly smaller than the query, whether or not the query occurs in values. Return the answers in query order.

  • values has length from 0 to 100,000, and the array may be empty.
  • queries has length from 1 to 100,000.
  • Entries are int values between -10^9 and 10^9, and equal entries count once.

  • Mutation of the input arrays is not allowed.

Example 1. Input values = [900, -40, 900, 12, 7000000], queries = [12, 900, 13, -40, 7000000], output [1, 2, 2, 0, 3].

Example 2. Input values = [], queries = [5], output [0], since no value is stored and no key is smaller.

Prerequisites. The sorted distinct keys and the rank lookup from this lesson.

What This Exercise Changes. The task asks for the count of smaller keys and not the rank, so an absent query must still get an answer. The lookup must turn a missing value into its insertion point.

Hint

How do you remove duplicates after sorting? What does Arrays.binarySearch return for a value that is absent?

Algorithmic Solution (attempt the problem first)

Approach. Sorting and removing duplicates produces the array keys, whose index is the number of smaller keys.

A query is answered by binary search on keys. A found index p is exactly the number of smaller keys. A missing value gives the negative result -p - 1 from Arrays.binarySearch, where p is the insertion point, which is again the number of smaller keys. The invariant is that keys is strictly increasing, so binary search is valid and equal values land on one index.

Complexity.

  • Time is O((n + q) log n) for n values and q queries, with the O(n log n) sort paid once and one O(log n) search per query.
  • Space is O(n) for the sorted copy and O(q) for the answers, because the input arrays stay unchanged.
import java.util.*;

public final class CompressSparse {
    /**
     * Returns, for each query, the number of distinct values strictly smaller than it.
     * Time: O((n + q) log n). Space: O(n + q).
     * Invariant: keys[0..m-1] is strictly increasing, so binary search finds each value at most once.
     */
    static int[] ranksOf(int[] values, int[] queries) {
        // Copy the input so that the caller's array stays unchanged.
        int[] sorted = values.clone();
        // Sorting costs O(n log n) and places equal values next to each other.
        Arrays.sort(sorted);
        // m counts the distinct values written to the front of the sorted copy.
        int m = 0;
        // One pass removes duplicates, so this loop costs O(n).
        for (int v : sorted) {
            // Keep a value only when it differs from the last kept value.
            if (m == 0 || sorted[m - 1] != v) sorted[m++] = v;
        }
        // Trim to the distinct values, which are the keys.
        int[] keys = Arrays.copyOf(sorted, m);
        // One answer per query.
        int[] out = new int[queries.length];
        // Each iteration performs one O(log m) binary search.
        for (int i = 0; i < queries.length; i++) {
            // A present value gives its index; an absent value gives -(insertion point) - 1.
            int p = Arrays.binarySearch(keys, 0, m, queries[i]);
            // Both cases give the number of keys below the query.
            out[i] = p >= 0 ? p : -p - 1;
        }
        // Return the answers in query order.
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1: duplicates count once and an absent query still gets its insertion point.
        if (!Arrays.equals(ranksOf(new int[]{900, -40, 900, 12, 7000000}, new int[]{12, 900, 13, -40, 7000000}), new int[]{1, 2, 2, 0, 3}))
            throw new AssertionError("example 1");
        // Checks Example 2: an empty value array makes every query absent.
        if (!Arrays.equals(ranksOf(new int[]{}, new int[]{5}), new int[]{0})) throw new AssertionError("example 2");
        // Checks the Java behaviour that an absent value yields -(insertion point) - 1.
        if (Arrays.binarySearch(new int[]{1, 3}, 2) != -2) throw new AssertionError("absent value must be negative");
        // Checks the input arrays stay unchanged.
        int[] vals = {5, 1, 5};
        ranksOf(vals, new int[]{1});
        if (!Arrays.equals(vals, new int[]{5, 1, 5})) throw new AssertionError("input mutated");
        // Compares with a TreeSet oracle on random inputs with a fixed seed.
        Random rnd = new Random(9201);
        for (int iter = 0; iter < 2000; iter++) {
            int n = rnd.nextInt(10);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = rnd.nextInt(15) - 7;
            int[] q = new int[1 + rnd.nextInt(8)];
            for (int i = 0; i < q.length; i++) q[i] = rnd.nextInt(19) - 9;
            TreeSet<Integer> set = new TreeSet<>();
            for (int x : v) set.add(x);
            int[] expect = new int[q.length];
            for (int i = 0; i < q.length; i++) expect[i] = set.headSet(q[i]).size();
            if (!Arrays.equals(ranksOf(v, q), expect)) throw new AssertionError("random " + iter);
        }
    }

Range Sum With Sparse Keys

LeetCode 307

Problem Specification. This is a variant of LeetCode 307 in which positions are arbitrary keys. Every key starts with value 0. An operation {0, key, value} sets the value stored at key to value, replacing any earlier value. An operation {1, lo, hi} asks for the sum of the values stored at keys k with lo <= k <= hi. The bounds lo and hi need not be keys that were ever set. Return the answers of the sum operations in order.

Input Constraints. The limits are:

  • Operations number from 1 to 100,000, and all are known before processing starts.
  • Keys and bounds are long values between -10^12 and 10^12, with lo <= hi.
  • Values are long values between -10^9 and 10^9.
  • Result is a long[] with one entry per sum operation.
  • Mutation of the operation array is not allowed.

Example 1. Input ops = [[0,100,5],[0,-3,7],[1,-10,100],[0,100,2],[1,0,99],[1,100,100],[0,1000000000000,-4],[1,-3,1000000000000]], output [12, 0, 2, 5].

Example 2. Input ops = [[0,5,3],[0,5,3],[1,5,5]], output [3], because setting the same key twice does not add the value twice.

Prerequisites. The exercise above and the Fenwick tree from this lesson.

What This Exercise Changes. Updates replace a value and do not add to it, so the tree needs the difference from the stored value. Range ends can fall between keys, so each end needs a count of keys at or below it.

Hint

Which keys can ever hold a value? What delta must the tree receive when a key is overwritten? How do you turn a bound that is not a key into a rank?

Algorithmic Solution (attempt the problem first)

Approach. All operations are known first, so the keys of the set operations are collected, sorted and deduplicated into keys.

The tree has one position per key. A set operation finds the rank of its key, computes value - current[rank] and adds that difference. Adding the difference makes the tree entry equal the new value, and a repeated set adds 0. A sum operation needs the number of keys below lo and the number of keys at or below hi. Those two counts come from binary searches and are valid positions even when the bounds are not keys. The answer is prefix(atMostHi) - prefix(below lo).

The invariant is that the tree position of each key holds its current value, and keys never set hold 0.

Complexity.

  • Time is O(q log q) for q operations, because sorting the keys costs O(q log q) and each operation costs O(log q) for the searches and the tree.
  • Space is O(q) for the keys, the current values, the tree and the answers.
import java.util.*;

public final class SparseKeySum {
    /** Fenwick tree over positions 1..size, storing long sums. */
    static final class Fenwick {
        final long[] tree;

        Fenwick(int size) {
            // Index 0 stays unused because the structure is 1-based.
            tree = new long[size + 1];
        }

        /**
         * Adds delta at pos. Time: O(log size). Space: O(1).
         * Invariant: tree[i] holds the sum of the block of positions that ends at i.
         */
        void add(int pos, long delta) {
            // Each step moves to the next block that covers pos, so the loop runs O(log size) times.
            for (int i = pos; i < tree.length; i += i & -i) tree[i] += delta;
        }

        /**
         * Returns the sum of positions 1..pos. Time: O(log size). Space: O(1).
         * Invariant: the blocks visited are disjoint and together cover 1..pos.
         */
        long prefix(int pos) {
            // The running sum is a long so that large values cannot overflow.
            long sum = 0;
            // Clearing the lowest set bit jumps to the next disjoint block.
            for (int i = pos; i > 0; i -= i & -i) sum += tree[i];
            return sum;
        }
    }

    /** Returns the number of keys that are less than or equal to bound. */
    static int countAtMost(long[] keys, long bound) {
        // Binary search for the first key greater than bound.
        int lo = 0, hi = keys.length;
        // Each iteration halves the candidate range, so the loop costs O(log m).
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            // A key at or below the bound lies left of the answer.
            if (keys[mid] <= bound) lo = mid + 1; else hi = mid;
        }
        // The index of the first larger key equals the count of keys at or below the bound.
        return lo;
    }

    /**
     * Processes set and sum operations with a Fenwick tree over the sorted distinct keys.
     * Time: O(q log q). Space: O(q).
     * Invariant: the tree position of each key holds that key's current value.
     */
    static long[] run(long[][] ops) {
        // Collect the keys of set operations, which are the only keys that can hold a value.
        long[] all = new long[ops.length];
        int c = 0;
        for (long[] op : ops) if (op[0] == 0) all[c++] = op[1];
        // Sort so that equal keys are adjacent and ranks follow key order.
        long[] sorted = Arrays.copyOf(all, c);
        Arrays.sort(sorted);
        // Remove duplicates in place; m is the number of distinct keys.
        int m = 0;
        for (long k : sorted) if (m == 0 || sorted[m - 1] != k) sorted[m++] = k;
        long[] keys = Arrays.copyOf(sorted, m);
        // The tree and the stored values start at 0, matching keys that were never set.
        Fenwick tree = new Fenwick(m);
        long[] current = new long[m + 1];
        // Answers are appended in the order of the sum operations.
        List<Long> answers = new ArrayList<>();
        // One iteration per operation, each costing O(log q).
        for (long[] op : ops) {
            if (op[0] == 0) {
                // Rank of the key is its index in keys plus 1.
                int rank = Arrays.binarySearch(keys, op[1]) + 1;
                // The tree receives only the change, so a repeated set adds 0.
                tree.add(rank, op[2] - current[rank]);
                // Remember the stored value for the next overwrite.
                current[rank] = op[2];
            } else {
                // Keys at or below hi minus keys below lo are exactly the keys inside [lo, hi].
                int upper = countAtMost(keys, op[2]);
                int lower = countAtMost(keys, op[1] - 1);
                answers.add(tree.prefix(upper) - tree.prefix(lower));
            }
        }
        // Convert the answers to an array in order.
        long[] out = new long[answers.size()];
        for (int i = 0; i < out.length; i++) out[i] = answers.get(i);
        return out;
    }

    /** Brute-force oracle that keeps the values in a map and scans it for each sum. */
    static long[] oracle(long[][] ops) {
        Map<Long, Long> map = new HashMap<>();
        List<Long> answers = new ArrayList<>();
        for (long[] op : ops) {
            if (op[0] == 0) map.put(op[1], op[2]);
            else {
                long s = 0;
                for (Map.Entry<Long, Long> e : map.entrySet()) if (e.getKey() >= op[1] && e.getKey() <= op[2]) s += e.getValue();
                answers.add(s);
            }
        }
        long[] out = new long[answers.size()];
        for (int i = 0; i < out.length; i++) out[i] = answers.get(i);
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 with negative, small and huge keys.
        long[][] ex1 = {{0, 100, 5}, {0, -3, 7}, {1, -10, 100}, {0, 100, 2}, {1, 0, 99}, {1, 100, 100}, {0, 1000000000000L, -4}, {1, -3, 1000000000000L}};
        if (!Arrays.equals(run(ex1), new long[]{12, 0, 2, 5})) throw new AssertionError("example 1");
        // Checks Example 2: setting the same key twice does not double the value.
        if (!Arrays.equals(run(new long[][]{{0, 5, 3}, {0, 5, 3}, {1, 5, 5}}), new long[]{3})) throw new AssertionError("example 2");
        // Checks a sum over a range that holds no key and a sum before any key is set.
        if (!Arrays.equals(run(new long[][]{{1, 0, 0}, {0, 9, 1}, {1, 10, 20}}), new long[]{0, 0})) throw new AssertionError("empty ranges");
        // Compares with the oracle on random operation lists with a fixed seed.
        Random rnd = new Random(9202);
        for (int iter = 0; iter < 2000; iter++) {
            int n = 1 + rnd.nextInt(14);
            long[][] ops = new long[n][];
            for (int i = 0; i < n; i++) {
                if (rnd.nextBoolean()) {
                    long key = rnd.nextInt(8) == 0 ? (rnd.nextBoolean() ? 1000000000000L : -1000000000000L) : rnd.nextInt(13) - 6;
                    ops[i] = new long[]{0, key, rnd.nextInt(21) - 10};
                } else {
                    long a = rnd.nextInt(17) - 8, b = rnd.nextInt(17) - 8;
                    ops[i] = new long[]{1, Math.min(a, b), Math.max(a, b)};
                    if (rnd.nextInt(6) == 0) ops[i][2] = 1000000000000L;
                }
            }
            if (!Arrays.equals(run(ops), oracle(ops))) throw new AssertionError("random " + iter);
        }
    }

Edge Cases

Negative And Extreme Coordinates

Author exercise

Problem Specification. An int[] values is given. Compute the 1-based rank of every entry among the distinct entries in increasing order. Also compute the largest difference between two neighbouring distinct values, as a long. If fewer than two distinct values exist, that difference is 0. Return a long[] of length n + 1. Entry i for i < n is the rank of values[i], and the last entry is the largest difference.

Input Constraints. The limits are:

  • Length n is from 1 to 100,000.
  • Entries are any int values, including Integer.MIN_VALUE and Integer.MAX_VALUE.
  • Ties share one rank, and ranks have no gaps.
  • Difference is computed as a long, because the true value can exceed Integer.MAX_VALUE.
  • Mutation of the input array is not allowed.

Example 1. Input values = [2147483647, -2147483648, 0, -2147483648], output [3, 1, 2, 1, 2147483648].

Example 2. Input values = [7, 7, 7], output [1, 1, 1, 0], since one distinct value has no neighbour.

Prerequisites. The two exercises above and the overflow warning in the applicability stage.

What This Exercise Changes. The comparison must be safe and the neighbour difference must widen to long before it subtracts. A value is never used as an array index.

Hint

What does a - b return in int arithmetic when the true result is above Integer.MAX_VALUE? Which conversion prevents the overflow?

Algorithmic Solution (attempt the problem first)

Approach. The method sorts a copy with the primitive sort, which orders int values correctly at both extremes.

It removes duplicates to get keys, then finds each rank by binary search. The largest neighbour difference widens one operand to long before the subtraction, so the result is exact. The expression a - b in int arithmetic wraps for extreme values, which is why the code never subtracts in int. The invariant is that keys is strictly increasing, so every rank is unique to one value and no raw value serves as an array index.

Complexity.

  • Time grows as O(n log n), since the sort of the copy outweighs the later searches, which cost O(log n) each.
  • Space is O(n) for the sorted copy and the result.
import java.util.*;

public final class ExtremeCoordinates {
    /**
     * Returns the rank of each entry followed by the largest gap between neighbouring distinct values.
     * Time: O(n log n). Space: O(n).
     * Invariant: keys is strictly increasing, so each value has one rank.
     */
    static long[] ranksAndGap(int[] values) {
        int n = values.length;
        // Sort a copy with the primitive sort, which compares int values without subtraction.
        int[] sorted = values.clone();
        Arrays.sort(sorted);
        // Keep one copy of each value; m counts the distinct values.
        int m = 0;
        for (int v : sorted) if (m == 0 || sorted[m - 1] != v) sorted[m++] = v;
        // The result holds n ranks and then the gap.
        long[] out = new long[n + 1];
        // Each rank is one binary search plus 1.
        for (int i = 0; i < n; i++) out[i] = Arrays.binarySearch(sorted, 0, m, values[i]) + 1;
        // Scan the neighbours of the distinct values to find the largest gap.
        long gap = 0;
        for (int i = 1; i < m; i++) {
            // Widening one operand to long keeps the subtraction exact.
            gap = Math.max(gap, (long) sorted[i] - sorted[i - 1]);
        }
        // The last entry carries the gap, which is 0 when fewer than two distinct values exist.
        out[n] = gap;
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 with both extreme values and a duplicate.
        if (!Arrays.equals(ranksAndGap(new int[]{2147483647, -2147483648, 0, -2147483648}), new long[]{3, 1, 2, 1, 2147483648L}))
            throw new AssertionError("example 1");
        // Checks Example 2: one distinct value has no neighbour.
        if (!Arrays.equals(ranksAndGap(new int[]{7, 7, 7}), new long[]{1, 1, 1, 0})) throw new AssertionError("example 2");
        // Checks the Java behaviour behind the hint: int subtraction wraps at the extremes.
        if (Integer.MAX_VALUE - Integer.MIN_VALUE != -1) throw new AssertionError("int subtraction must wrap");
        if ((long) Integer.MAX_VALUE - Integer.MIN_VALUE != 4294967295L) throw new AssertionError("long subtraction is exact");
        // Compares with a TreeSet and BigInteger oracle on random inputs with a fixed seed.
        Random rnd = new Random(9203);
        int[] pool = {Integer.MIN_VALUE, Integer.MAX_VALUE, 0, -1, 1, 1000000000, -1000000000, 5};
        for (int iter = 0; iter < 2000; iter++) {
            int n = 1 + rnd.nextInt(9);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = pool[rnd.nextInt(pool.length)];
            TreeSet<Integer> set = new TreeSet<>();
            for (int x : v) set.add(x);
            long[] expect = new long[n + 1];
            for (int i = 0; i < n; i++) expect[i] = set.headSet(v[i]).size() + 1;
            java.math.BigInteger best = java.math.BigInteger.ZERO;
            Integer prev = null;
            for (int x : set) {
                if (prev != null) best = best.max(java.math.BigInteger.valueOf(x).subtract(java.math.BigInteger.valueOf(prev)));
                prev = x;
            }
            expect[n] = best.longValueExact();
            if (!Arrays.equals(ranksAndGap(v), expect)) throw new AssertionError("random " + iter);
        }
    }

Pattern Recognition

Insertion Cost By Smaller Count

LeetCode 1649

Problem Specification. This is a variant of LeetCode 1649 with a one-sided cost. The entries of instructions are inserted one at a time into an initially empty sorted container. The cost of inserting an entry equals the number of entries already in the container that are strictly smaller than it. Entries that are equal or larger add nothing. Return the total cost modulo 1,000,000,007.

Input Constraints. The limits are:

  • Length is from 1 to 100,000.
  • Entries are int values between -10^9 and 10^9.
  • Ties are not smaller, so equal entries add 0.
  • Result is an int in the range 0 to 1,000,000,006.
  • Mutation of the input array is not allowed.

Example 1. Input instructions = [8, -2, 8, 5, -2, 1000000000, 5], output 9.

Example 2. Input instructions = [1, 2, 3, ..., 100000] in ascending order, output 999949972, because the true total 4,999,950,000 is reduced by the modulus.

Prerequisites. All three exercises above and the counting loop from this lesson.

What This Exercise Changes. The cost uses only the count of strictly smaller entries, with no minimum against the larger side. The total passes the modulus, so it needs long accumulation.

Hint

Which prefix query counts strictly smaller entries? Why must the total be a long before the reduction?

Algorithmic Solution (attempt the problem first)

Approach. The cost of an insertion is the number of stored entries strictly below it, which is a prefix count over ranks.

The ranks come from the sorted distinct entries. For each entry, the code reads prefix(rank - 1) before it adds 1 at rank. Reading first keeps the entry out of its own count, and rank - 1 excludes equal entries. The costs are summed in a long, because the total can reach about 5 billion, and the remainder is taken at the end. The invariant is that the tree holds one count per inserted entry at its rank.

Complexity.

  • Time grows as O(n log n), since each entry needs one search, one query and one update of O(log n) each, after the initial sort.
  • Space is O(n) for the keys and the tree.
import java.util.*;

public final class SmallerInsertionCost {
    static final long MOD = 1_000_000_007L;

    /**
     * Returns the total of strictly-smaller counts, modulo 1,000,000,007.
     * Time: O(n log n). Space: O(n).
     * Invariant: before entry i is added, the tree holds one count per earlier entry at its rank.
     */
    static int totalCost(int[] instructions) {
        // Sort a copy and drop duplicates to get the dense ranks.
        int[] sorted = instructions.clone();
        Arrays.sort(sorted);
        int m = 0;
        for (int v : sorted) if (m == 0 || sorted[m - 1] != v) sorted[m++] = v;
        // The Fenwick array has m + 1 slots because index 0 is unused.
        long[] tree = new long[m + 1];
        // The total is a long, since it can exceed the int range before the reduction.
        long total = 0;
        // One iteration per inserted entry.
        for (int x : instructions) {
            // The rank is the index in the distinct values plus 1.
            int rank = Arrays.binarySearch(sorted, 0, m, x) + 1;
            // Query first: positions 1..rank-1 hold only strictly smaller earlier entries.
            long smaller = 0;
            for (int i = rank - 1; i > 0; i -= i & -i) smaller += tree[i];
            total += smaller;
            // Add the entry after the query so it never counts itself.
            for (int i = rank; i <= m; i += i & -i) tree[i]++;
        }
        // Reduce once at the end; the long total holds the exact sum.
        return (int) (total % MOD);
    }

    /** Brute-force oracle that mirrors the problem statement with a list. */
    static int oracle(int[] a) {
        long total = 0;
        for (int i = 0; i < a.length; i++)
            for (int j = 0; j < i; j++) if (a[j] < a[i]) total++;
        return (int) (total % MOD);
    }

    public static void main(String[] args) {
        // Checks Example 1 with duplicates, a negative entry and a large entry.
        if (totalCost(new int[]{8, -2, 8, 5, -2, 1000000000, 5}) != 9) throw new AssertionError("example 1");
        // Checks Example 2: the true total passes the modulus, so the reduction matters.
        int[] asc = new int[100000];
        for (int i = 0; i < asc.length; i++) asc[i] = i + 1;
        if (totalCost(asc) != 999949972) throw new AssertionError("example 2");
        if (4999950000L <= MOD) throw new AssertionError("the exact total exceeds the modulus");
        // Checks equal entries add nothing.
        if (totalCost(new int[]{3, 3, 3}) != 0) throw new AssertionError("equal entries");
        // Compares with the oracle on random inputs with a fixed seed.
        Random rnd = new Random(9204);
        for (int iter = 0; iter < 2000; iter++) {
            int n = 1 + rnd.nextInt(30);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(12) - 6;
            if (totalCost(a) != oracle(a)) throw new AssertionError("random " + iter);
        }
    }
