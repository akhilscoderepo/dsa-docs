Chapter 32

Selection And Ordered Data

Orientation

A monitoring service stores a million response times and must report the median every minute. Sorting the whole list each time wastes work, because only one position of the sorted order is needed. A pricing service also asks for the nearest cheaper offer to a given price while offers come and go. Both services need an answer about order without paying for a full sort.

Prerequisites

You should know arrays and swapping two cells, sorting with comparators, recursion on an index range, and the merge step of merge sort. You should know that a TreeMap keeps keys sorted. The lessons explain the exact methods when they first matter.

The Four Lessons

Each lesson answers one question about order.

  • Quickselect finds the value of one sorted position by partitioning and then following only the side that holds the target position.
  • Partition Invariants shows which index ranges a partition loop guarantees at every step, including the three-way form for repeated values.
  • Ordered Maps And Sets uses TreeMap and TreeSet to find the nearest key below or above a value in O(log n) time while keys change.
  • Merge Counting counts pairs of positions that violate an order while merge sort combines two sorted halves.

The Closing Lesson

Partition And Selection joins the first three skills. A partition places one value at its final position, and selection uses that proof to skip a whole side. Its four exercises select a rank with its position range, select the closest points with ties, count smaller values to the right within a distance, and count pairs with a scaled threshold.

How To Work Through Each Lesson

A lesson opens with a realistic failure and a direct program that is too slow or wrong. You predict its cost before the explanation appears. Later parts name the stored quantity, list the variables, follow two traces, show the code and say when the idea stops fitting. Four exercises close each lesson, and each has a hint and a solution you can open after your own attempt.

What You Can Do After This Chapter

You can decide when one rank is enough and a full sort is not needed. You can write a partition loop whose index boundaries you can state before the first swap. You can pick a sorted collection for nearest-key questions and count order violations in O(n log n) time.

Problem

Why Sorting Everything Wastes Time

A monitoring service collects ten million request latencies each hour. The on-call engineer wants the median latency, which is the value that would sit in the middle if the list were in order. The service needs only that one value. It does not need the other nine million nine hundred ninety-nine thousand nine hundred ninety-nine in any order.

The obvious route sorts the whole list and reads the middle slot. That works, but it orders every value when the answer depends on a single position. The same waste appears when a program needs the 90th percentile, the third highest score, or the ten nearest stores. Can a program find the value at one chosen position without ordering the rest? The answer follows below.

Simple approach

Sort The Array And Read One Slot

The direct approach sorts a copy of the array and returns the element at the wanted position. The method below takes a zero-based position k, where k = 0 asks for the smallest value.

static int selectBySorting(int[] a, int k) {
    int[] copy = a.clone();       // keep the caller's array unchanged
    java.util.Arrays.sort(copy);  // orders every element, even those far from position k
    return copy[k];               // the wanted value now sits at index k
}

The code is short and correct for every input. It also does far more ordering than the question needs, because the order among the values that lie far from position k never affects the answer.

Bottleneck

Sorting Costs More Than One Answer Needs

Predict first: A program needs the median of 10,000,000 values. A comparison sort does about n times log2(n) comparisons. About how many comparisons per value does the sort spend, and what is the least a correct method could spend per value?

About 23 comparisons per value, because log2 of ten million is about 23. A correct method must look at every value at least once, so the least it can spend is about one comparison per value. Sorting spends over twenty times that minimum.

Count The Comparisons

A comparison sort on n values costs O(n log n). For n = 10^7 that is about 2.3 * 10^8 comparisons. Any method that answers correctly must read every value at least once, because one unread value could be the answer. The lower bound for selection is therefore O(n), and the sort exceeds it by a factor of log n.

Name The Missing Idea

The sort throws away its progress after each answer, so repeating the query on the same array repeats the full cost. The extra factor comes from ordering values that cannot affect the answer. A faster method must split the values so that one whole group can be ignored. It must also prove that the ignored group does not hold position k.

Key idea

Split Around One Value

Place A Pivot At Its Final Rank

Choose one element of the array and call it the pivot. A partition step rearranges the array so that every element smaller than the pivot comes before it and every element not smaller comes after it. After the step, the pivot sits at index p. That index is the final rank of the pivot, which means the index it would have in the sorted array. The pivot is already in its sorted place, and nothing needs to move it again.

The final rank follows from counting. Exactly p elements are smaller than the pivot, so exactly p elements must come before it in sorted order. The order inside the left group and inside the right group is still unknown, and that is fine.

Keep Only The Side That Holds The Target

Quickselect uses the final rank to discard work. Suppose the target index is k. If p equals k, the pivot is the answer. If k is less than p, the values that belong at index k are all in the left group, so the right group can never matter. If k is greater than p, the values that belong at index k are all in the right group, so the left group can never matter.

The method keeps two bounds, lo and hi, and repeats the partition on a[lo..hi] only. It passes the bounds and never copies a subarray. Each round shrinks the range to one side of the pivot.

State The Invariant And The Cost

The invariant is that a[lo..hi] always holds exactly the values whose sorted positions are lo to hi, and the target index k lies inside lo..hi. A partition keeps it true, because the pivot's final rank splits the range at a proven boundary. A partition of a range of length m costs O(m). If each round removes about half of the range, the work is n + n/2 + n/4 + ..., which sums to O(n) on average. A bad pivot that removes one element per round costs O(n^2) in the worst case.

State

Quantities To Track In The Loop

Track these items during one run.

  • a is the int[] that the method rearranges in place.
  • k is the zero-based target index, where k = 0 is the smallest value.
  • lo and hi are the inclusive bounds of the range that still holds index k.
  • pivot is the value that the current partition places at its final rank.
  • p is the index where the partition leaves the pivot.
  • store is the index of the first element that is not smaller than the pivot, found while scanning.

The method partitions in place, so it reorders the caller's array. A caller who needs the original order passes a clone. The scan inside a partition uses store to mark the boundary between the smaller group and the rest. The boundary is defined before any swap happens, so every swap moves one smaller element across it.

Walkthrough

Follow Two Searches Round By Round

Each step below shows the bounds lo and hi and the index p where the pivot lands after that round. The cells show the starting array, and each note spells out the array after the round. The pointer p rests at -1 before the first partition.

Find The Third Smallest Value

Take the array 7, 2, 9, 4, 1, 8, 3 and the target index k = 2. The range is the whole array, so lo = 0 and hi = 6. The pivot is the middle element 4. The partition moves 2, 1 and 3 in front of it, and 4 lands at index 3. Index 2 is less than 3, so the method keeps the left side and sets hi = 2. The next partition works on 2, 3, 1 with the middle element 3 as the pivot. The value 3 lands at index 2, which equals k, so the answer is 3.

Find The Sixth Smallest Value

The array 3, 2, 3, 1, 2, 4, 5, 5, 6 has nine elements, and the target index is k = 5. The first pivot is the middle element 2, and it lands at index 1. Index 5 is greater than 1, so the method keeps the right side and sets lo = 2. The second pivot is the middle element 4 of the range lo..hi, and it lands exactly at index 5, so the search ends. This is also the fourth largest value, because 9 - 5 = 4.

The hardest step is the choice of side. The method compares k with p only, and it never compares values from the discarded side. The first trace discards the right side, and the second trace discards the left side.

Code

Implement Partition And Select

final class Quick {
    static int select(int[] a, int k) {
        int lo = 0, hi = a.length - 1;           // the range that still holds index k
        while (lo < hi) {
            int p = partition(a, lo, hi);        // pivot reaches its final rank p
            if (p == k) return a[p];             // the pivot is the answer
            if (k < p) hi = p - 1;               // the target is in the left group
            else lo = p + 1;                     // the target is in the right group
        }
        return a[lo];                            // one element is left, and it holds index k
    }

    static int partition(int[] a, int lo, int hi) {
        int mid = lo + (hi - lo) / 2;            // the form lo + (hi - lo) / 2 cannot overflow
        swap(a, mid, hi);                        // park the pivot at hi so the scan can skip it
        int pivot = a[hi];
        int store = lo;                          // a[lo..store-1] holds the smaller values
        for (int i = lo; i < hi; i++) {
            if (a[i] < pivot) {
                swap(a, i, store);               // move the smaller value across the boundary
                store++;
            }
        }
        swap(a, store, hi);                      // the pivot lands at its final rank
        return store;
    }

    static void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }
}

The loop ends because every round either returns or shrinks hi - lo by at least one. The method reads and writes only inside lo..hi, so no subarray is copied and the extra memory is O(1). The middle element serves as the pivot in this lesson so that the traces repeat exactly. A program that must resist crafted input picks a random index between lo and hi instead.

When to use it

When One Rank Is Enough

Recognize The Pattern

Use this method when the question asks for a single rank, or for the k smallest values in any order. Median, percentile, kth largest and the k nearest items all fit. The invariant to check before coding is that a[lo..hi] holds exactly the values that belong at sorted positions lo to hi. Every partition must keep that statement true, and the loop must rely on nothing else.

The method also changes the array. If the caller needs the original order, copy once before the loop. That single copy costs O(n) and is not a copy per round.

Watch For The Nearest False Friend

A full sort is the false friend, and so is a heap of size k. Sorting gives the answer, but it pays the extra log n factor. A heap of size k costs O(n log k) and never changes the input, which makes it the better fit when values arrive one at a time or when the input must stay intact. Quickselect fits when the whole array sits in memory and in-place changes are allowed.

Avoid The Java Hazards

Write lo + (hi - lo) / 2 and never (lo + hi) / 2, because the sum of two large int values overflows to a negative number. Pass lo and hi to the recursive or looping step, because Arrays.copyOfRange allocates a new array each round and the copies cost O(n) every time. When the key is computed, as in a squared distance, use long for the key, since the product of two int values can overflow. Finally, do not compare values with a - b, because the difference overflows for values of opposite signs.

Basic

Select Kth Smallest

Author exercise

Problem Specification. Given an integer array a and a zero-based rank r, return the value that would sit at index r if a were sorted in non-decreasing order. The method may reorder a.

Input Constraints. The limits are:

  • n is the length of a, an int with 1 <= n <= 10^5.
  • Values are int values with absolute value at most 10^9.
  • r is an int with 0 <= r < n.
  • Ties may repeat, and equal values count separately.
  • Return is an int.

Example 1. Input a = [9, 4, 7, 1, 8, 2] and r = 2, output 4, since the sorted array is [1, 2, 4, 7, 8, 9].

Example 2. Input a = [5] and r = 0, output 5, since one element is its own rank.

Prerequisites. The partition step and the loop from this lesson.

What This Exercise Changes. Baseline case: partition and continue into the one side that holds the target index.

Hint

After a partition places the pivot at index p, which side contains index r?

Algorithmic Solution (attempt the problem first)

Approach. The method keeps the bounds lo and hi of the range that still holds index r. Each round partitions a[lo..hi] around its middle element and gets the pivot's final rank p.

The pivot's final rank is exact, because the partition leaves exactly p - lo smaller values in front of it and the range holds the values that belong at positions lo to hi. If p equals r, the pivot is the answer. If r is smaller, only the left group can hold index r, so hi becomes p - 1. Otherwise lo becomes p + 1. The invariant is that r stays inside lo..hi and the range holds exactly the values of sorted positions lo to hi. The method passes bounds and never copies a subarray. The test also shows that the form (lo + hi) / 2 overflows, which is why the code uses lo + (hi - lo) / 2.

Complexity.

  • Time is expected O(n), because each partition scans the current range once and the range shrinks geometrically for typical pivots. A bad pivot sequence costs O(n^2).
  • Space is O(1), because the method swaps inside the input and keeps three integers.
import java.util.Arrays;
import java.util.Random;

public final class SelectKth {
    /**
     * Returns the value at sorted index k, reordering a in place.
     * Time: expected O(n), worst case O(n^2).
     * Space: O(1) extra.
     * Invariant: k lies in lo..hi and a[lo..hi] holds the values of sorted positions lo..hi.
     */
    static int select(int[] a, int k) {
        // The range starts as the whole array, which trivially holds index k.
        int lo = 0, hi = a.length - 1;
        // One element left means the range holds only index k.
        while (lo < hi) {
            // The partition fixes the pivot at its final rank p.
            int p = partition(a, lo, hi);
            // A pivot at index k is the answer.
            if (p == k) return a[p];
            // The target lies left of the pivot, so the right group is discarded.
            if (k < p) hi = p - 1;
            // The target lies right of the pivot, so the left group is discarded.
            else lo = p + 1;
        }
        // The last remaining element sits at index k.
        return a[lo];
    }

    /** Places the middle element at its final rank inside lo..hi and returns that rank. */
    static int partition(int[] a, int lo, int hi) {
        // The overflow-safe midpoint stays inside lo..hi.
        int mid = lo + (hi - lo) / 2;
        // Park the pivot at hi so the scan can ignore it.
        swap(a, mid, hi);
        int pivot = a[hi];
        // The boundary store is defined before any swap: a[lo..store-1] is below the pivot.
        int store = lo;
        // One scan costs O(hi - lo).
        for (int i = lo; i < hi; i++) {
            // Only values below the pivot cross the boundary.
            if (a[i] < pivot) {
                swap(a, i, store);
                store++;
            }
        }
        // The pivot moves to the boundary, which is its final rank.
        swap(a, store, hi);
        return store;
    }

    static void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        if (select(new int[]{9, 4, 7, 1, 8, 2}, 2) != 4) throw new AssertionError("example 1");
        if (select(new int[]{5}, 0) != 5) throw new AssertionError("example 2");
        // Checks the claim that (lo + hi) / 2 overflows while lo + (hi - lo) / 2 does not.
        int lo = 2_000_000_000, hi = 2_100_000_000;
        if ((lo + hi) / 2 >= 0) throw new AssertionError("naive midpoint should overflow");
        if (lo + (hi - lo) / 2 != 2_050_000_000) throw new AssertionError("safe midpoint");
        // Checks every rank against a sorted copy on random arrays, including many ties.
        Random rnd = new Random(32);
        for (int round = 0; round < 500; round++) {
            int n = 1 + rnd.nextInt(30);
            int bound = 1 + rnd.nextInt(12);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(2 * bound + 1) - bound;
            int[] sorted = a.clone();
            Arrays.sort(sorted);
            for (int r = 0; r < n; r++) {
                if (select(a.clone(), r) != sorted[r]) throw new AssertionError("rank " + r + " of " + Arrays.toString(a));
            }
            // Checks the partition postcondition: the pivot sits at the count of smaller values.
            int[] b = a.clone();
            int p = partition(b, 0, n - 1);
            int smaller = 0;
            for (int v : a) if (v < b[p]) smaller++;
            if (p != smaller) throw new AssertionError("final rank");
            for (int i = 0; i < p; i++) if (b[i] >= b[p]) throw new AssertionError("left side");
            for (int i = p + 1; i < n; i++) if (b[i] < b[p]) throw new AssertionError("right side");
        }
    }
}verified
Variation

Kth Largest Element

LeetCode 215

Problem Specification. Given an integer array nums and an integer k, return the k-th largest element in the sorted order, where k = 1 asks for the maximum. Equal values count separately.

Input Constraints. The limits are:

  • n is the length of nums, an int with 1 <= n <= 10^5.
  • Values are int values with absolute value at most 10^9.
  • k is an int with 1 <= k <= n.
  • Return is an int.

Example 1. Input nums = [3, 2, 1, 5, 6, 4] and k = 2, output 5, since the sorted array is [1, 2, 3, 4, 5, 6].

Example 2. Input nums = [4, 4, 1, 9, 9, 2, 7] and k = 3, output 7, since the sorted array is [1, 2, 4, 4, 7, 9, 9].

Prerequisites. The exercise above.

What This Exercise Changes. The question counts from the large end, so the target index becomes n - k.

Hint

Which zero-based index in ascending order holds the k-th largest value?

Algorithmic Solution (attempt the problem first)

Approach. The k-th largest value is the value at ascending index n - k, because k - 1 values are larger than it and n - k values come before it. The method converts k to that index once and then runs the same bounded partition loop.

The invariant stays the same: the range lo..hi holds the values of sorted positions lo to hi and contains the target index n - k. Equal values count separately, so a repeated value occupies several ranks. The test also asserts two Java facts that the lesson states. The call Arrays.copyOfRange returns an independent array, so writes to it never reach the original. The subtraction a - b overflows for values of opposite signs.

Complexity.

  • Time is expected O(n), because each round scans only the surviving range.
  • Space is O(1), because the partition swaps inside the input array.
import java.util.Arrays;
import java.util.Random;

public final class KthLargest {
    /**
     * Returns the k-th largest element, where k = 1 is the maximum.
     * Time: expected O(n), worst case O(n^2).
     * Space: O(1) extra.
     * Invariant: n - k lies in lo..hi and a[lo..hi] holds the values of those sorted positions.
     */
    static int findKthLargest(int[] nums, int k) {
        // The k-th largest has n - k elements before it in ascending order.
        int target = nums.length - k;
        int lo = 0, hi = nums.length - 1;
        // Each round discards one side of the pivot.
        while (lo < hi) {
            int p = partition(nums, lo, hi);
            // The pivot at the target index is the answer.
            if (p == target) return nums[p];
            // Keep the side that contains the target.
            if (target < p) hi = p - 1;
            else lo = p + 1;
        }
        // One element left holds the target index.
        return nums[lo];
    }

    /** Places the middle element at its final rank in lo..hi and returns the rank. */
    static int partition(int[] a, int lo, int hi) {
        // Overflow-safe midpoint.
        int mid = lo + (hi - lo) / 2;
        int t = a[mid]; a[mid] = a[hi]; a[hi] = t;
        int pivot = a[hi];
        // Boundary of the smaller group, defined before the scan swaps anything.
        int store = lo;
        for (int i = lo; i < hi; i++) {
            if (a[i] < pivot) {
                int u = a[i]; a[i] = a[store]; a[store] = u;
                store++;
            }
        }
        // The pivot lands at the boundary.
        t = a[store]; a[store] = a[hi]; a[hi] = t;
        return store;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        if (findKthLargest(new int[]{3, 2, 1, 5, 6, 4}, 2) != 5) throw new AssertionError("example 1");
        if (findKthLargest(new int[]{4, 4, 1, 9, 9, 2, 7}, 3) != 7) throw new AssertionError("example 2");
        // Checks that copyOfRange gives an independent array, so a subarray copy is real extra work.
        int[] src = {1, 2, 3, 4};
        int[] copy = Arrays.copyOfRange(src, 1, 3);
        copy[0] = 99;
        if (src[1] != 2) throw new AssertionError("copy must be independent");
        // Checks that a - b overflows for values of opposite signs.
        int big = Integer.MAX_VALUE, neg = -1;
        if (big - neg >= 0) throw new AssertionError("difference should overflow");
        if (Integer.compare(big, neg) <= 0) throw new AssertionError("compare must stay correct");
        // Checks every k against a descending sort on random arrays with extreme values.
        Random rnd = new Random(215);
        for (int round = 0; round < 500; round++) {
            int n = 1 + rnd.nextInt(25);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) {
                int pick = rnd.nextInt(6);
                a[i] = pick == 0 ? Integer.MAX_VALUE : pick == 1 ? Integer.MIN_VALUE : rnd.nextInt(9) - 4;
            }
            int[] sorted = a.clone();
            Arrays.sort(sorted);
            for (int k = 1; k <= n; k++) {
                if (findKthLargest(a.clone(), k) != sorted[n - k]) throw new AssertionError("k=" + k + " " + Arrays.toString(a));
            }
        }
    }
}verified
Edge Cases

Duplicates And Extreme K

Author exercise

Problem Specification. Given an integer array a and a zero-based rank r, return the value at index r of the sorted array. The array can hold long runs of one value, and r can be 0 or n - 1. The method must run in expected O(n) time even when all values are equal.

Input Constraints. The limits are:

  • n is an int with 1 <= n <= 10^5.
  • Values are int values, and all of them may be equal.
  • r is an int with 0 <= r < n.
  • Mutation of a is allowed.
  • Return is an int.

Example 1. Input a = [6, 6, 6, 6, 6] and r = 3, output 6, since every rank holds 6.

Example 2. Input a = [2, 9, 2, 2, 5, 2, 9] and r = 4, output 5, since the sorted array is [2, 2, 2, 2, 5, 9, 9].

Prerequisites. The two exercises above.

What This Exercise Changes. The partition now splits three ways, so a whole run of values equal to the pivot is settled in one round.

Hint

If a partition keeps only strictly smaller values on the left, how many elements does it remove when all values are equal?

Algorithmic Solution (attempt the problem first)

Approach. A partition that keeps only strictly smaller values on the left and puts every other value on the right removes just the pivot from an array of equal values. Each round then shrinks the range by one, and the total cost is O(n^2). The fix is a three-way partition.

The three-way partition splits a[lo..hi] into three groups with boundaries lt and gt. Values below the pivot occupy lo..lt-1, values equal to it occupy lt..gt, and values above it occupy gt+1..hi. The scan index i separates the settled groups from the unread values i..gt. The method defines lt, i and gt before it swaps anything. After the scan, every index in lt..gt has the final value of the pivot, so a target inside that block is answered at once. Otherwise the range keeps the left or the right group. The invariant is that the range holds the values of sorted positions lo..hi and contains the target. With all equal values, one round settles the whole range, and the test counts the rounds to confirm it. Extreme ranks 0 and n - 1 need no special case.

Complexity.

  • Time is expected O(n), because each round scans the range once and an equal run leaves the range in one step.
  • Space is O(1), because the method swaps inside the input and keeps five integers.
import java.util.Arrays;
import java.util.Random;

public final class DuplicatesSelect {
    static int rounds;   // counts partition rounds so the test can check the equal-values claim

    /**
     * Returns the value at sorted index r using a three-way partition.
     * Time: expected O(n), and one round when all values are equal.
     * Space: O(1) extra.
     * Invariant: r lies in lo..hi and a[lo..hi] holds the values of sorted positions lo..hi.
     */
    static int select(int[] a, int r) {
        int lo = 0, hi = a.length - 1;
        // The range always contains r, so the loop stops when the equal block covers r.
        while (lo <= hi) {
            rounds++;
            // Overflow-safe middle value as the pivot.
            int pivot = a[lo + (hi - lo) / 2];
            // Boundaries are defined before any swap: a[lo..lt-1] < pivot, a[gt+1..hi] > pivot.
            int lt = lo, i = lo, gt = hi;
            // Scan the unread values i..gt exactly once.
            while (i <= gt) {
                if (a[i] < pivot) {
                    swap(a, lt++, i++);       // smaller value joins the left group
                } else if (a[i] > pivot) {
                    swap(a, i, gt--);         // larger value joins the right group; i stays to re-read the swapped value
                } else {
                    i++;                      // equal value stays in the middle block
                }
            }
            // A target inside lt..gt already holds the pivot value.
            if (r < lt) hi = lt - 1;
            else if (r > gt) lo = gt + 1;
            else return pivot;
        }
        // Unreachable, because the range always contains r.
        throw new AssertionError("range lost the target");
    }

    static void swap(int[] a, int i, int j) {
        int t = a[i]; a[i] = a[j]; a[j] = t;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        if (select(new int[]{6, 6, 6, 6, 6}, 3) != 6) throw new AssertionError("example 1");
        if (select(new int[]{2, 9, 2, 2, 5, 2, 9}, 4) != 5) throw new AssertionError("example 2");
        // Checks that an array of equal values needs a single round, even for large n.
        int[] same = new int[100_000];
        Arrays.fill(same, 7);
        rounds = 0;
        if (select(same, 99_999) != 7) throw new AssertionError("all equal");
        if (rounds != 1) throw new AssertionError("rounds " + rounds);
        // Checks all ranks against a sorted copy on random arrays with few distinct values.
        Random rnd = new Random(322);
        for (int round = 0; round < 500; round++) {
            int n = 1 + rnd.nextInt(30);
            int distinct = 1 + rnd.nextInt(4);
            int[] a = new int[n];

K Closest Points To Origin

LeetCode 973

Problem Specification. Given an array points where each entry is [x, y], and an integer k, return the k points with the smallest Euclidean distance from the origin. The answer may be in any order.

Input Constraints. The limits are:

  • n is the number of points, an int with 1 <= k <= n <= 10^5.
  • Coordinates are int values with absolute value at most 10^9.
  • Ties at the cutoff do not occur, so the set of k points is unique.
  • Return is a list of k points in any order.

Example 1. Input points = [[3, 3], [5, -1], [-2, 4]] and k = 2, output [[3, 3], [-2, 4]] in any order, since the squared distances are 18, 26 and 20.

Example 2. Input points = [[1000000000, 1000000000], [1, 1], [-1, 2]] and k = 2, output [[1, 1], [-1, 2]] in any order, since the first squared distance is 2 * 10^18.

Prerequisites. All three exercises above.

What This Exercise Changes. The partition compares a derived key, the squared distance, and the key needs long.

Hint

Which key replaces the value in the comparison, and which type holds that key without overflow?

Algorithmic Solution (attempt the problem first)

Approach. The k closest points are the points with the k smallest squared distances, and the square root is not needed because it preserves order. The method selects index k - 1 by quickselect on the squared distance, and then the first k entries of the array are the answer.

A squared distance x*x + y*y reaches 2 * 10^18 for coordinates of 10^9, which exceeds the int range but fits in long. The key function therefore widens each coordinate to long before multiplying. The invariant is the same as before: after the partition loop for target index k - 1, every entry in 0..k-1 has a key not larger than every entry in k..n-1. The method swaps whole point references and passes bounds, so it copies no coordinates during the search.

Complexity.

  • Time is expected O(n), because each round scans the surviving range and computes two long products per point.
  • Space is O(1) extra beyond the returned array of k references.
import java.util.Arrays;
import java.util.Random;

public final class KClosest {
    /** Returns the squared distance to the origin as a long, so the sum cannot overflow. */
    static long key(int[] pt) {
        // Widening before the multiplication prevents int overflow.
        return (long) pt[0] * pt[0] + (long) pt[1] * pt[1];
    }

    /**
     * Returns the k points with the smallest squared distance, in any order.
     * Time: expected O(n).
     * Space: O(k) for the result, O(1) extra otherwise.
     * Invariant: k - 1 lies in lo..hi and points[lo..hi] holds the keys of sorted positions lo..hi.
     */
    static int[][] kClosest(int[][] points, int k) {
        int target = k - 1;
        int lo = 0, hi = points.length - 1;
        // Each round discards the side that cannot hold the cutoff index.
        while (lo < hi) {
            int p = partition(points, lo, hi);
            if (p == target) break;
            if (target < p) hi = p - 1;
            else lo = p + 1;
        }
        // Entries 0..k-1 now hold the k smallest keys.
        return Arrays.copyOfRange(points, 0, k);
    }

    /** Places the middle point at its final rank by key and returns that rank. */
    static int partition(int[][] a, int lo, int hi) {
        int mid = lo + (hi - lo) / 2;
        swap(a, mid, hi);
        long pivot = key(a[hi]);
        // Boundary of the smaller group, defined before the scan swaps anything.
        int store = lo;
        for (int i = lo; i < hi; i++) {
            if (key(a[i]) < pivot) {
                swap(a, i, store);
                store++;
            }
        }
        swap(a, store, hi);
        return store;
    }

    static void swap(int[][] a, int i, int j) {
        int[] t = a[i]; a[i] = a[j]; a[j] = t;
    }

    static long[] sortedKeys(int[][] pts) {
        long[] keys = new long[pts.length];
        for (int i = 0; i < pts.length; i++) keys[i] = key(pts[i]);
        Arrays.sort(keys);
        return keys;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        int[][] r1 = kClosest(new int[][]{{3, 3}, {5, -1}, {-2, 4}}, 2);
        if (!Arrays.equals(sortedKeys(r1), new long[]{18, 20})) throw new AssertionError("example 1");
        int[][] r2 = kClosest(new int[][]{{1_000_000_000, 1_000_000_000}, {1, 1}, {-1, 2}}, 2);
        if (!Arrays.equals(sortedKeys(r2), new long[]{2, 5})) throw new AssertionError("example 2");
        // Checks that int arithmetic would overflow while the long key is exact.
        int x = 1_000_000_000;
        if ((long) (x * x) == (long) x * x) throw new AssertionError("int product should overflow");
        if (key(new int[]{x, x}) != 2_000_000_000_000_000_000L) throw new AssertionError("long key");
        // Checks the selected keys against a full sort on random points, including ties and large values.
        Random rnd = new Random(973);
        for (int round = 0; round < 500; round++) {
            int n = 1 + rnd.nextInt(25);
            int[][] pts = new int[n][2];
            for (int i = 0; i < n; i++) {
                boolean large = rnd.nextInt(5) == 0;
                pts[i][0] = large ? (rnd.nextInt(3) - 1) * 1_000_000_000 : rnd.nextInt(11) - 5;
                pts[i][1] = large ? (rnd.nextInt(3) - 1) * 1_000_000_000 : rnd.nextInt(11) - 5;
            }
            int k = 1 + rnd.nextInt(n);
            long[] expected = Arrays.copyOf(sortedKeys(pts), k);
            int[][] got = kClosest(pts.clone(), k);
            if (got.length != k) throw new AssertionError("length");
            if (!Arrays.equals(sortedKeys(got), expected)) throw new AssertionError("keys differ, k=" + k);
        }
    }

Problem

Why Splitting Values In Place Is Hard

A billing service holds one million order amounts in an array. A report needs the orders below a price limit first, then the orders exactly at the limit, then the orders above it. The amounts inside each group may stay in any order. The service has little spare memory, so it must rearrange the array it already has.

Sorting would produce this layout, but sorting does far more work than the report needs. A hand-written loop is faster, and it is also easy to get wrong. A swap in the wrong place loses an order, a pointer that never moves hangs the program, and a pointer that moves too far skips a value. The question for this lesson is how a program splits an array into three groups in place and knows at every moment which part of the array is already correct.

Simple approach

Copying Values Into Three Lists

The direct approach reads the array once and appends each value to one of three new lists. It then writes the lists back into the array one after another.

static void splitByCopy(int[] a, int limit) {
    java.util.List<Integer> below = new java.util.ArrayList<>();
    java.util.List<Integer> equal = new java.util.ArrayList<>();
    java.util.List<Integer> above = new java.util.ArrayList<>();
    for (int v : a) {
        if (v < limit) below.add(v);          // goes to the first group
        else if (v == limit) equal.add(v);    // goes to the middle group
        else above.add(v);                    // goes to the last group
    }
    int k = 0;
    for (int v : below) a[k++] = v;           // write the groups back in order
    for (int v : equal) a[k++] = v;
    for (int v : above) a[k++] = v;
}

The method is correct and easy to read. It reads the array twice and holds a second copy of every value in the three lists.

Bottleneck

Extra Memory And Repeated Copies

Predict first: A recursive routine splits an array of n values, then splits each part again, and copies the parts into new arrays at every level. If each level copies all n values, about how many values does it copy over 20 levels?

About 20 times n. Every level copies every value once, so the copy cost grows with the number of levels times n, and it adds nothing to the answer.

Count The Extra Work

The copy method needs O(n) extra memory, because the three lists together hold n values plus the list overhead. Boxing each int into an Integer adds an object per value. A routine that splits and then splits again copies O(n) values at each level, so a recursion with L levels spends O(n * L) on copies alone. Sorting instead costs O(n log n) comparisons, and it also orders values inside each group, which the report never asked for.

Name What Is Missing

The copying method knows which group each value belongs to only after it has moved the value to a new place. An in-place method must do the opposite. It must keep one array and promise, at every step, which index ranges hold finished groups and which range has not been looked at. That promise is called a loop invariant, and the rest of this lesson builds it.

Key idea

Keep Finished Groups As Index Ranges

Split The Array Into Regions

A partition rearranges the values of a[lo..hi] around a pivot value, so that smaller values come first and larger values come last. The array stays in one piece. Each index range of the array has a fixed meaning, and a pointer marks where one range ends and the next begins. The values inside a finished range may still be in any order.

Build The Lomuto Partition

The Lomuto partition uses the last element as the pivot and two pointers. The pointer j scans from lo to hi - 1. The pointer i marks the first slot after the values that are strictly below the pivot. The invariant has four regions. The range a[lo..i-1] holds values below the pivot. The range a[i..j-1] holds values at least as large as the pivot. The range a[j..hi-1] is the unresolved region, which means values the scan has not examined yet. The slot a[hi] holds the pivot.

When a[j] is below the pivot, the loop swaps a[i] and a[j] and then increases i. The swap moves the small value into the first slot of the large range, and it moves the large value that was there to position j. When a[j] is not below the pivot, the loop does nothing, because the value already sits in the large range. In both cases j advances, so the unresolved region shrinks by one slot. After the scan the unresolved region is empty, and one final swap of a[i] with a[hi] puts the pivot between the two groups. The pivot index i is now its final position in sorted order.

Build The Three-Way Partition

The Lomuto partition lumps equal values with the large ones. A three-way partition keeps them in their own range. It uses three pointers lt, i and gt. The range a[lo..lt-1] holds values below the pivot value, a[lt..i-1] holds values equal to it, and a[gt+1..hi] holds values above it. The unresolved region is a[i..gt].

Each step looks at a[i]. A smaller value swaps with a[lt], and both lt and i advance, because the value that arrives at i came from the equal range and is already known to be equal. A larger value swaps with a[gt], and only gt moves, because the value that arrives at i is new and unexamined, so i must stay. An equal value needs only i to advance. The loop ends when i passes gt, which means the unresolved region is empty.

State

Pointers And Regions To Track

Track these items while the partition runs.

  • lo and hi are the inclusive bounds of the part of the array being partitioned.
  • pivot is the value that the regions compare against.
  • i in the Lomuto partition is the first slot after the strictly smaller values.
  • j is the scan pointer, and everything at an index below j is resolved.
  • lt, i and gt in the three-way partition mark the ends of the smaller, equal and larger regions.

The bounds lo and hi are inclusive, and the caller passes them in, so a recursive call never copies a subarray. Every region is described by an index range, and a region is empty when its start is greater than its end. The pivot slot a[hi] in the Lomuto partition lies outside the scan range until the final swap. The count of unresolved slots is hi - j in the Lomuto partition and gt - i + 1 in the three-way partition.

Walkthrough

Follow Two Partitions Step By Step

Each step below lists the whole array in the variable arr, so the reader can check every region against the pointers.

Lomuto On Seven Values

The array is 7, 2, 9, 4, 1, 8, 5 and the pivot is the last value, 5. The pointer j scans the first six slots. The values 7, 9 and 8 are not below 5, so they stay in the large range and only j moves. The values 2, 4 and 1 are below 5, so each swaps with the slot at i, and i moves right after each swap. After the scan, i is 3, and the last swap exchanges the slot 3 with the pivot slot 6.

The hard step is the swap of 4 at j = 3. At that moment i is 1 and a[1] holds 7, a large value. The swap moves 7 to position 3, which is still inside the large range, so the invariant holds. The final array has 2, 4, 1 before the pivot and 9, 8, 7 after it, and the pivot sits at index 3.

Three-Way On Eight Values

The array is 4, 7, 1, 4, 9, 2, 4, 0 and the pivot value is 4. The pointer lt starts at 0, i at 0, and gt at 7. A value of 7 or 9 swaps with a[gt] and i stays, and a value of 1, 2 or 0 swaps with a[lt] and both advance. The loop ends when i is greater than gt.

The hardest step is the first large value, 7. It swaps with the last slot, which holds 0, and i does not move. The next step then examines the 0 that just arrived. It is below the pivot, so it swaps into the front. If i had moved after the first swap, the program would have skipped that 0 and left it inside the equal range.

Code

Implement Both Partitions With Bounds

final class Partition {
    static void swap(int[] a, int x, int y) {
        int t = a[x];
        a[x] = a[y];
        a[y] = t;
    }

    // Lomuto: pivot is a[hi]; returns the final index of the pivot.
    static int lomuto(int[] a, int lo, int hi) {
        int pivot = a[hi];                 // fix the pivot value before any swap
        int i = lo;                        // a[lo..i-1] holds values below the pivot
        for (int j = lo; j < hi; j++) {    // a[j..hi-1] is the unresolved region
            if (a[j] < pivot) {
                swap(a, i, j);             // move the small value to the end of the small range
                i++;
            }
        }
        swap(a, i, hi);                    // place the pivot between the two ranges
        return i;
    }

    // Three-way: returns {lt, gt} so that a[lt..gt] equals the pivot value.
    static int[] threeWay(int[] a, int lo, int hi, int pivot) {
        int lt = lo, i = lo, gt = hi;      // the unresolved region is a[i..gt]
        while (i <= gt) {
            if (a[i] < pivot) {
                swap(a, lt++, i++);        // the value from a[lt] is equal, so i moves too
            } else if (a[i] > pivot) {
                swap(a, i, gt--);          // the value from a[gt] is unexamined, so i stays
            } else {
                i++;                       // an equal value is already in place
            }
        }
        return new int[]{lt, gt};
    }
}

Both methods take the bounds lo and hi and never copy a subarray. The pivot value is read into a local variable before any swap, so no swap can change it. A swap of a slot with itself is harmless, because the value is written back unchanged. Each loop does constant work per slot, so both methods cost O(hi - lo + 1) time and O(1) extra space.

When to use it

When A Partition Applies

Recognize The Pattern

Use a partition when values must be divided around a pivot in place and the order inside each group does not matter. The invariant to write down before coding is the list of index ranges and what each one holds. Every loop step must keep that list true, and the loop must end when the unresolved region is empty. Pick the Lomuto partition when you need one final pivot position, as in a selection step. Pick the three-way partition when many values can equal the pivot, because the equal range is finished work that later steps skip.

Watch For The Nearest False Friend

Sorting is a false friend. It also leaves the pivot in place, but it orders every group and costs O(n log n). A partition costs O(n) and gives only the grouping. If the problem asks for sorted output, partition alone is not enough. A second false friend is the Lomuto partition on many equal values. Equal values count as large there, so an array of identical values leaves the pivot at index lo and an unresolved right part of size n - 1. A recursion on that input does O(n) work per level for n levels.

Avoid The Java Index Traps

Define lo, hi and the pivot before the first swap. Pass the bounds to a recursive call instead of calling Arrays.copyOfRange, because a copy changes the copy and leaves the original array unchanged. Compute a middle index as lo + (hi - lo) / 2, because (lo + hi) / 2 overflows int for large indexes. In the three-way loop, keep i in place after a swap with gt.

Rearrange a[lo..hi] in place so that every value below the pivot comes first, the pivot comes next, and every other value comes last. Use the scan described in this lesson.   • Bounds satisfy 0 <= lo <= hi < n.
  • Values are int values and may repeat.
  • Mutation is limited to a[lo..hi], and other slots stay unchanged.

Example 2. Input a = [5, 1, 5, 5, 2], lo = 1, hi = 3. Output 2, and a stays [5, 1, 5, 5, 2], since slots 0 and 4 are outside the bounds.

Prerequisites. The Lomuto regions from this lesson.

What This Exercise Changes. Baseline case: keeps a prefix of strictly smaller values.

Hint

What does the slot i hold when the scan meets a value that is not below the pivot?

Algorithmic Solution (attempt the problem first)

Approach. The scan keeps four regions inside a[lo..hi], and each step shrinks the unresolved one.

The pivot value is read from a[hi] before any swap. The pointer i starts at lo, so the range of smaller values is empty. For each j from lo to hi - 1, a value below the pivot swaps with a[i] and i moves right. The invariant is that a[lo..i-1] is below the pivot, a[i..j-1] is at least the pivot, and a[j..hi-1] is unresolved. A value that is not below the pivot needs no move, because it already lies in the second range. When i equals j the swap is a slot with itself, which leaves the array unchanged. The final swap puts the pivot at i. Slots outside lo..hi are never read or written.

Complexity.

  • Time is O(hi - lo + 1), since the scan visits each slot of the range once and does constant work per slot.
  • Space is O(1), because the method keeps two indexes and the pivot value.
import java.util.Arrays;
import java.util.Random;

public final class LomutoPartition {
    /**
     * Partitions a[lo..hi] around a[hi] and returns the final pivot index.
     * Time: O(hi - lo + 1), one visit per slot.
     * Space: O(1), two indexes and the pivot value.
     * Invariant: a[lo..i-1] below pivot, a[i..j-1] at least pivot, a[j..hi-1] unresolved.
     */
    static int lomuto(int[] a, int lo, int hi) {
        // Read the pivot before any swap can change a[hi].
        int pivot = a[hi];
        // The small range starts empty at lo.
        int i = lo;
        // The scan visits each unresolved slot once.
        for (int j = lo; j < hi; j++) {
            // Only a strictly smaller value joins the small range.
            if (a[j] < pivot) {
                // The swap keeps the large range contiguous.
                int t = a[i]; a[i] = a[j]; a[j] = t;
                // The small range grows by one slot.
                i++;
            }
        }
        // The pivot lands between the two ranges.
        int t = a[i]; a[i] = a[hi]; a[hi] = t;
        // This index is the pivot's final sorted position within the range.
        return i;
    }

    public static void main(String[] args) {
        // Checks Example 1.
        int[] e1 = {6, 3, 9, 2, 7, 4};
        if (lomuto(e1, 0, 5) != 2 || !Arrays.equals(e1, new int[]{3, 2, 4, 6, 7, 9})) throw new AssertionError("example 1");
        // Checks Example 2, where the bounds leave the outer slots alone.
        int[] e2 = {5, 1, 5, 5, 2};
        if (lomuto(e2, 1, 3) != 2 || !Arrays.equals(e2, new int[]{5, 1, 5, 5, 2})) throw new AssertionError("example 2");
        // Checks a single-slot range, where the pivot index is lo.
        int[] one = {9};
        if (lomuto(one, 0, 0) != 0) throw new AssertionError("single slot");
        // Checks the claim that equal values count as large: all equal puts the pivot at lo.
        int[] same = {4, 4, 4, 4};
        if (lomuto(same, 0, 3) != 0) throw new AssertionError("all equal pivot index");
        // Checks the postcondition on random inputs against a counting oracle.
        Random rnd = new Random(32);
        for (int round = 0; round < 2000; round++) {
            int n = 1 + rnd.nextInt(12);
            int[] a = new int[n];
            for (int x = 0; x < n; x++) a[x] = rnd.nextInt(6);
            int lo = rnd.nextInt(n), hi = lo + rnd.nextInt(n - lo);
            int[] before = a.clone();
            int pivot = a[hi];
            int less = 0;
            for (int x = lo; x <= hi; x++) if (before[x] < pivot) less++;
            int idx = lomuto(a, lo, hi);
            if (idx != lo + less) throw new AssertionError("index round " + round);
            if (a[idx] != pivot) throw new AssertionError("pivot round " + round);
            for (int x = lo; x < idx; x++) if (a[x] >= pivot) throw new AssertionError("left round " + round);
            for (int x = idx + 1; x <= hi; x++) if (a[x] < pivot) throw new AssertionError("right round " + round);
            for (int x = 0; x < n; x++) if ((x < lo || x > hi) && a[x] != before[x]) throw new AssertionError("outside round " + round);
            int[] s1 = Arrays.copyOfRange(a, lo, hi + 1), s2 = Arrays.copyOfRange(before, lo, hi + 1);
            Arrays.sort(s1); Arrays.sort(s2);
            if (!Arrays.equals(s1, s2)) throw new AssertionError("multiset round " + round);
        }
    }

Three-Way Partition

Author exercise

Problem Specification. Given an int array a and an int value p, rearrange a in place into three consecutive ranges. The first range holds values below p, the second holds values equal to p, and the third holds values above p. Return {lt, gt}, where the second range is a[lt..gt]. The value p need not occur in a.

Input Constraints. The limits are:

  • Length of a is an int with 0 <= n <= 10^5.
  • Values and p are int values.
  • Return is an int[] of length 2, and gt = lt - 1 when no value equals p.
  • Order inside each range is not specified.

Example 1. Input a = [4, 7, 1, 4, 9, 2, 4, 0] and p = 4. Output [3, 5], since three values are below 4 and three are equal to it.

Example 2. Input a = [8, 9, 6] and p = 5. Output [0, -1], because no value is below or equal to 5.

Prerequisites. The Lomuto exercise above.

What This Exercise Changes. The output changes from one pivot index to a range of equal values, so the program needs a third pointer.

Hint

After a swap with the end of the unresolved region, has the value now at i been compared?

Algorithmic Solution (attempt the problem first)

Approach. Three pointers split the array into below, equal, unresolved and above ranges.

The pointers start at lt = 0, i = 0 and gt = n - 1, so only the unresolved range a[i..gt] is non-empty. The invariant is that a[0..lt-1] is below p, a[lt..i-1] equals p, a[i..gt] is unresolved and a[gt+1..n-1] is above p. A smaller value swaps with a[lt]. The value that arrives at i came from the equal range, so both lt and i advance. A larger value swaps with a[gt]. The value that arrives at i has not been compared, so i stays and only gt moves. An equal value advances i. The loop ends when i > gt, and the pair {lt, gt} bounds the equal range. If no value equals p, the result is gt = lt - 1.

Complexity.

  • Time is O(n), because each step either advances i or lowers gt, so the unresolved range loses one slot per step.
  • Space is O(1), because the method keeps three indexes.
import java.util.Arrays;
import java.util.Random;

public final class ThreeWayPartition {
    /**
     * Rearranges a into below, equal and above ranges around p and returns {lt, gt}.
     * Time: O(n), the unresolved range loses one slot per step.
     * Space: O(1), three indexes.
     * Invariant: a[0..lt-1] < p, a[lt..i-1] == p, a[i..gt] unresolved, a[gt+1..n-1] > p.
     */
    static int[] threeWay(int[] a, int p) {
        // All slots start unresolved.
        int lt = 0, i = 0, gt = a.length - 1;
        // The loop runs while the unresolved range is non-empty.
        while (i <= gt) {
            if (a[i] < p) {
                // The value at lt is equal, so it moves to i and both pointers advance.
                int t = a[lt]; a[lt] = a[i]; a[i] = t;
                lt++; i++;
            } else if (a[i] > p) {
                // The arrival from gt is unexamined, so i stays.
                int t = a[i]; a[i] = a[gt]; a[gt] = t;
                gt--;
            } else {
                // An equal value is already in the equal range.
                i++;
            }
        }
        // The two bounds describe the equal range.
        return new int[]{lt, gt};
    }

    /** A faulty variant that advances i after the swap with gt, used to show why i must stay. */
    static void faulty(int[] a, int p) {
        int lt = 0, i = 0, gt = a.length - 1;
        while (i <= gt) {
            if (a[i] < p) { int t = a[lt]; a[lt] = a[i]; a[i] = t; lt++; i++; }
            else if (a[i] > p) { int t = a[i]; a[i] = a[gt]; a[gt] = t; gt--; i++; }
            else i++;
        }
    }

    static boolean valid(int[] a, int p, int lt, int gt) {
        for (int x = 0; x < a.length; x++) {
            if (x < lt && a[x] >= p) return false;
            if (x >= lt && x <= gt && a[x] != p) return false;
            if (x > gt && a[x] <= p) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        // Checks Example 1.
        int[] e1 = {4, 7, 1, 4, 9, 2, 4, 0};

Edge Cases

All Equal Values

Author exercise

Problem Specification. Given an int array a, inclusive bounds lo and hi, and an index k with lo <= k <= hi, take the pivot value a[hi]. Partition a[lo..hi] into values below, equal to, and above the pivot, in place. If the position k lies in the equal range, return {-1, -1}. Otherwise return the bounds of the smaller or larger range that contains k.

Input Constraints. The limits are:

  • Length of a is an int with 1 <= n <= 10^5.
  • Bounds satisfy 0 <= lo <= hi < n.
  • Values are int values, and all of them may be equal.
  • Mutation is limited to a[lo..hi].

Example 1. Input a = [3, 8, 3, 1, 3, 9, 3], lo = 0, hi = 6, k = 5. Output [5, 6], because the equal range is a[1..4] and k lies above it.

Example 2. Input a = [5, 5, 5, 5, 5], lo = 0, hi = 4, k = 2. Output [-1, -1], because the whole range is equal and one pass finishes the search.

Prerequisites. The two exercises above.

What This Exercise Changes. The input is all one value, so a two-way split would leave n - 1 values to examine, while a three-way split leaves none.

Hint

When every value equals the pivot, which pointer moves on each step, and where does the loop stop?

Algorithmic Solution (attempt the problem first)

Approach. One three-way pass either finds that rank k is in the equal range or names the side that holds it.

The pivot value is read from a[hi] first. The three pointers start at lt = lo, i = lo and gt = hi, and the loop follows the same invariant as the three-way partition, restricted to a[lo..hi]. When every value equals the pivot, each step only advances i, lt stays at lo and gt stays at hi. The loop therefore ends after hi - lo + 1 steps, and the equal range is the whole range. Then k lies in lt..gt, so the method returns {-1, -1}. If k < lt the answer lies below, so the method returns {lo, lt - 1}. If k > gt it returns {gt + 1, hi}. A two-way split on the same input would leave n - 1 values still to examine.

Complexity.

  • Time is O(hi - lo + 1), because each step shrinks the unresolved range by one slot.
  • Space is O(1), since the method keeps three indexes and the pivot.
import java.util.Arrays;
import java.util.Random;

public final class AllEqualValues {
    /**
     * One three-way pass over a[lo..hi] that returns the range still holding position k.
     * Time: O(hi - lo + 1), one slot resolved per step.
     * Space: O(1), three indexes and the pivot.
     * Invariant: a[lo..lt-1] < pivot, a[lt..i-1] == pivot, a[i..gt] unresolved, a[gt+1..hi] > pivot.
     */
    static int[] step(int[] a, int lo, int hi, int k) {
        // Read the pivot before any swap.
        int pivot = a[hi];
        // The bounds are fixed, so the pointers start at them.
        int lt = lo, i = lo, gt = hi;
        // The loop ends when the unresolved range is empty.
        while (i <= gt) {
            if (a[i] < pivot) {
                int t = a[lt]; a[lt] = a[i]; a[i] = t;
                lt++; i++;
            } else if (a[i] > pivot) {
                int t = a[i]; a[i] = a[gt]; a[gt] = t;
                gt--;
            } else {
                i++;
            }
        }
        // Position k in the equal range is already final.
        if (k >= lt && k <= gt) return new int[]{-1, -1};
        // A smaller k keeps only the range below the equal block.
        if (k < lt) return new int[]{lo, lt - 1};
        // A larger k keeps only the range above the equal block.
        return new int[]{gt + 1, hi};
    }

    /** Counting oracle for the same contract. */
    static int[] oracle(int[] a, int lo, int hi, int k) {
        int p = a[hi], less = 0, eq = 0;
        for (int x = lo; x <= hi; x++) { if (a[x] < p) less++; else if (a[x] == p) eq++; }
        int lt = lo + less, gt = lt + eq - 1;
        if (k >= lt && k <= gt) return new int[]{-1, -1};
        if (k < lt) return new int[]{lo, lt - 1};
        return new int[]{gt + 1, hi};
    }

    public static void main(String[] args) {
        // Checks Example 1.
        int[] e1 = {3, 8, 3, 1, 3, 9, 3};
        if (!Arrays.equals(step(e1, 0, 6, 5), new int[]{5, 6})) throw new AssertionError("example 1");
        // Checks Example 2, where all values are equal.
        int[] e2 = {5, 5, 5, 5, 5};
        if (!Arrays.equals(step(e2, 0, 4, 2), new int[]{-1, -1})) throw new AssertionError("example 2");
        // Checks that the all-equal array is not changed by the pass.
        if (!Arrays.equals(e2, new int[]{5, 5, 5, 5, 5})) throw new AssertionError("all equal unchanged");
        // Checks the lower side of Example 1.
        int[] e3 = {3, 8, 3, 1, 3, 9, 3};
        if (!Arrays.equals(step(e3, 0, 6, 0), new int[]{0, 0})) throw new AssertionError("lower side");
        // Checks random sub-ranges against the counting oracle.
        Random rnd = new Random(34);
        for (int round = 0; round < 3000; round++) {
            int n = 1 + rnd.nextInt(12);
            int[] a = new int[n];
            int spread = 1 + rnd.nextInt(4);
            for (int x = 0; x < n; x++) a[x] = rnd.nextInt(spread);
            int lo = rnd.nextInt(n), hi = lo + rnd.nextInt(n - lo), k = lo + rnd.nextInt(hi - lo + 1);
            int[] expected = oracle(a, lo, hi, k);
            int[] got = step(a, lo, hi, k);
            if (!Arrays.equals(expected, got)) throw new AssertionError("round " + round);
        }
    }

Kth Largest Element In An Array

LeetCode 215

Problem Specification. Given an int array nums and an integer k, return the k-th largest value in sorted order, counting repeated values separately. The input array must not be modified. Use partition with index bounds and discard the ranges that cannot contain the answer.

Input Constraints. The limits are:

  • Length of nums is an int with 1 <= n <= 10^5.
  • k is an int with 1 <= k <= n.
  • Values are int values and may repeat.
  • Mutation of nums is not allowed, so one working copy is allowed.

Example 1. Input nums = [4, 9, 2, 9, 7, 1] and k = 3. Output 7, since the sorted order from the top is 9, 9, 7.

Example 2. Input nums = [5, 5, 5, 5] and k = 4. Output 5, and the equal range ends the search at once.

Prerequisites. All three exercises above.

What This Exercise Changes. The contract keeps the caller's array unchanged and counts duplicates separately, so the program partitions a working copy and relies on the equal range.

Hint

Which index in ascending order holds the k-th largest, and which three-way range can the search drop?

Algorithmic Solution (attempt the problem first)

Approach. The k-th largest value sits at ascending index n - k, and a three-way partition on a working copy narrows the bounds until that index falls in an equal range.

The method copies nums once, so the caller's array stays unchanged. It sets lo = 0, hi = n - 1 and target = n - k. Each round computes the middle index as lo + (hi - lo) / 2, which cannot overflow, and reads that value as the pivot. The three-way partition then splits copy[lo..hi] into below, equal and above ranges. If target is below the equal range, the search continues in the below range with hi = lt - 1. If target is above it, the search continues with lo = gt + 1. Otherwise the pivot is the answer. The invariant is that the element of ascending rank target always lies in copy[lo..hi]. Duplicates are counted separately, because the equal range occupies all its ranks. The bounds are passed as indexes, so no round copies a subarray.

Complexity.

  • Time is O(n) on average, since each round discards the equal range and one side, and O(n^2) in the worst case with a fixed middle pivot.
  • Space is O(n), for the single working copy, and O(1) beyond it.
import java.util.Arrays;
import java.util.Random;

public final class KthLargestUnchanged {
    /**
     * Returns the k-th largest value of nums without modifying nums.
     * Time: O(n) on average, O(n^2) worst case with a fixed middle pivot.
     * Space: O(n) for the working copy, O(1) beyond it.
     * Invariant: the value of ascending rank target lies in copy[lo..hi].
     */
    static int kthLargest(int[] nums, int k) {
        // One copy protects the caller's array.
        int[] copy = nums.clone();
        // The k-th largest has ascending index n - k.
        int target = copy.length - k;
        // The search range starts as the whole copy.
        int lo = 0, hi = copy.length - 1;
        // Each round removes at least the pivot's equal range.
        while (lo <= hi) {
            // This midpoint form cannot overflow.
            int pivot = copy[lo + (hi - lo) / 2];
            // The three pointers describe the regions of copy[lo..hi].
            int lt = lo, i = lo, gt = hi;
            // The loop resolves one slot per step.
            while (i <= gt) {
                if (copy[i] < pivot) {
                    int t = copy[lt]; copy[lt] = copy[i]; copy[i] = t;
                    lt++; i++;
                } else if (copy[i] > pivot) {
                    int t = copy[i]; copy[i] = copy[gt]; copy[gt] = t;
                    gt--;
                } else {
                    i++;
                }
            }
            // The target rank is below the equal range, so drop it and everything above.
            if (target < lt) hi = lt - 1;
            // The target rank is above the equal range, so drop it and everything below.
            else if (target > gt) lo = gt + 1;
            // The target rank lies in the equal range, so the pivot is the answer.
            else return pivot;
        }
        // The invariant guarantees a return above for valid k.
        throw new IllegalArgumentException("k out of range");
    }

    public static void main(String[] args) {
        // Checks Example 1, where duplicates count separately.
        int[] e1 = {4, 9, 2, 9, 7, 1};
        int[] e1copy = e1.clone();
        if (kthLargest(e1, 3) != 7) throw new AssertionError("example 1");
        if (kthLargest(e1, 2) != 9) throw new AssertionError("duplicate count");
        // Checks that the input array is unchanged.
        if (!Arrays.equals(e1, e1copy)) throw new AssertionError("input changed");
        // Checks Example 2, where all values are equal.
        if (kthLargest(new int[]{5, 5, 5, 5}, 4) != 5) throw new AssertionError("example 2");
        // Checks that a copy of a subarray does not change the source, which is why bounds are passed instead.
        int[] src = {3, 1, 2};
        int[] part = Arrays.copyOfRange(src, 0, 3);
        part[0] = 99;
        if (src[0] != 3) throw new AssertionError("copy independent");
        // Checks that the sum of two large indexes overflows int while the safe midpoint does not.
        int lo = 1_500_000_000, hi = 2_000_000_000;
        if ((lo + hi) / 2 >= 0) throw new AssertionError("overflow expected");
        if (lo + (hi - lo) / 2 != 1_750_000_000) throw new AssertionError("safe midpoint");
        // Checks random arrays against sorting.
        Random rnd = new Random(35);
        for (int round = 0; round < 3000; round++) {
            int n = 1 + rnd.nextInt(15);
            int[] a = new int[n];
            for (int x = 0; x < n; x++) a[x] = rnd.nextInt(9) - 4;
            int k = 1 + rnd.nextInt(n);
            int[] sorted = a.clone();
            Arrays.sort(sorted);
            if (kthLargest(a, k) != sorted[n - k]) throw new AssertionError("round " + round);
        }
    }

Problem

Why Nearest Lookups Slow Down

A booking service stores the start time of every reservation. A new request asks for a start time, and the service must find the reservation that begins just before it and the one that begins just after it. Those two neighbors decide whether the request overlaps. Requests arrive all day, and each accepted request adds a new start time to the data.

A hash set answers "is this exact time stored?" in constant time, but it cannot answer "which stored time is the closest one below this value?". A hash set keeps no order, so that question forces a scan of every entry. A plain sorted array answers the nearest question quickly, yet it struggles when new entries keep arriving. The question for this lesson is how a program keeps keys in order, finds their neighbors quickly and still accepts new keys.

Simple approach

Keeping A Sorted List By Hand

The direct approach stores the start times in a sorted ArrayList. A binary search finds where a new value belongs, and the list inserts it at that position. The same search also finds the neighbors of any query value.

static void insert(java.util.ArrayList<Integer> sorted, int x) {
    int at = java.util.Collections.binarySearch(sorted, x);   // index of x, or -(insertion point) - 1
    if (at < 0) {
        at = -at - 1;                                         // convert to the insertion point
    }
    sorted.add(at, x);                                        // shifts every later element one slot right
}

static Integer lowerNeighbor(java.util.ArrayList<Integer> sorted, int q) {
    int at = java.util.Collections.binarySearch(sorted, q);
    int point = at >= 0 ? at : -at - 1;                       // first index whose value is >= q
    return point == 0 ? null : sorted.get(point - 1);         // the entry just before that index
}

The search costs O(log n) comparisons, so each neighbor query is fast. The insertion is different. The call sorted.add(at, x) moves every element after at one slot to the right, which is up to n moves.

Bottleneck

Insertions Cost O(n) Each

Predict first: A sorted list starts empty. A program inserts 100,000 distinct values in random order, one at a time. About how many element moves do all the insertions cost together?

About 2.5 billion moves. The list holds k elements before the k-th insertion, and a random position shifts about half of them. Summing k / 2 for k up to 100,000 gives about n squared divided by 4.

Count The Moves

One insertion into a list of size k moves about k / 2 elements on average, so it costs O(k). Over n insertions the total is O(n^2). For n = 100,000 that is about 2.5 * 10^9 element moves, which takes seconds. Removing a value has the same cost, because every later element shifts one slot left.

Compare The Other Extreme

An unsorted list makes each insertion O(1), because the new value goes at the end. But a neighbor query then scans all entries and costs O(n). One layout makes queries cheap and updates expensive, and the other does the reverse. The structure we need must keep keys in order, find a neighbor in O(log n) and also add or remove a key in O(log n). That requires storing the keys as linked nodes that never shift, arranged so that every search path stays short.

Key idea

Keep Keys In A Balanced Search Tree

Store Keys In A Balanced Tree

A binary search tree stores one key per node. Every key in the left subtree of a node is smaller than the node's key, and every key in the right subtree is larger. A search starts at the root and moves left or right, so it follows one path from the root downward. A balanced tree keeps its height at O(log n) by restructuring itself after each insertion or removal. Java's TreeMap is a balanced tree of this kind, a red-black tree, and TreeSet is a thin wrapper around a TreeMap. Because nodes link to each other, an insertion adds one node and relinks a few pointers, and no element moves.

Answer Neighbor Queries By Descending

The method floor(x) returns the greatest key that is less than or equal to x, and ceiling(x) returns the smallest key that is greater than or equal to x. Their strict versions are lower(x) and higher(x). All four run the same descent. At each node the search compares x with the node key. When the node key qualifies as an answer, the search remembers it as the best candidate and moves toward the side that could hold a better one. When the node key does not qualify, the search moves toward the side that holds qualifying keys. The descent ends at a missing child, and the remembered candidate is the answer, or null when no key ever qualified. The path has the height of the tree, so each query costs O(log n).

Let The Comparator Decide Equality

A comparator is the rule that orders two keys and returns a negative number, zero or a positive number. A TreeMap never calls equals or hashCode. It treats two keys as the same key exactly when the comparator returns 0 for them. The invariant is that the tree stays ordered under one fixed comparator, and every search and insertion relies on it. If the comparator gives inconsistent answers, or if a stored key changes in a way that alters its comparison result, the invariant breaks and later searches walk the wrong way.

State

Quantities To Track In The Tree

Track these items while using an ordered map or set.

  • map is a TreeMap<K, V> that stores each key once under its comparator.
  • x is the query value that a navigation call compares with the stored keys.
  • best is the remembered candidate while the descent runs.
  • node is the tree node that the descent currently compares with x.
  • result is the key that a call returns, or null when no key qualifies.

The four navigation calls differ only in which comparison results qualify a node. The call floor accepts a key when it is at most x, and lower accepts it only when it is smaller than x. The call ceiling accepts a key at least x, and higher accepts it only when it is larger. The methods firstKey and lastKey give the minimum and maximum keys. They throw NoSuchElementException on an empty map, while firstEntry and lastEntry return null instead.

Walkthrough

Follow Two Descents

The trace draws the keys in sorted order and picks the node to compare with a midpoint rule, so the picture shows a balanced tree. Java's TreeMap reaches the same shape of path with rotations, and its comparisons follow the same rule. Each step shows the node being compared and the best candidate so far. The pointer value -1 means that no node is selected or no candidate exists.

Find The Ceiling Of 14

The keys are 3, 8, 12, 17, 21, 25, 30, and the call is ceiling(14). The root is the middle key 17. Since 17 is at least 14, it qualifies, so the search remembers 17 and goes left for a smaller qualifying key. The left subtree holds 3, 8, 12, and its root is 8. Since 8 is below 14, it does not qualify, so the search goes right. The next node is 12, which is also below 14, so the search goes right again and finds no child. The remembered candidate 17 is the answer.

Find The Floor Of 25

The keys are 2, 7, 11, 16, 22, 27, 31, 40, 44, and the call is floor(25). The root is 22, which is at most 25, so it qualifies and the search goes right for a larger qualifying key. The right subtree holds 27, 31, 40, 44, and its first compared key is 31, which is above 25, so the search goes left. The next key is 27, which is also above 25, and it has no left child. The answer is the remembered 22.

The first trace changes the candidate once, at the root, and then moves left past keys that do not qualify. The second trace keeps the root as its candidate while the later nodes fail. Each descent compares only three keys, although the maps hold seven and nine.

Code

Use Navigation Calls For Neighbors

final class OrderedCounts {
    private final java.util.TreeMap<Integer, Integer> counts = new java.util.TreeMap<>();

    void add(int key) {
        counts.merge(key, 1, Integer::sum);          // one tree search; creates the entry or raises its count
    }

    boolean removeOne(int key) {
        Integer c = counts.get(key);                 // one tree search for the exact key
        if (c == null) return false;                 // absent key: nothing to remove
        if (c == 1) counts.remove(key);              // a zero count must delete the entry, or the key stays visible
        else counts.put(key, c - 1);
        return true;
    }

    Integer nearestAtMost(int x) {
        return counts.floorKey(x);                   // greatest key <= x, or null when none exists
    }

    Integer nearestAbove(int x) {
        return counts.higherKey(x);                  // smallest key > x, or null when none exists
    }

    java.util.Map<Integer, Integer> keysBetween(int lo, int hi) {
        return counts.subMap(lo, true, hi, true);    // a live view of keys lo..hi, not a copy
    }
}

Every call above runs one descent and costs O(log n). The method keysBetween also costs O(log n) to create, because it only records two bounds. Iterating the view then costs O(log n + m) for m keys in range. A view is live, which means it reads the original map each time. A later change to the map shows through the view, and a put through the view with a key outside its bounds throws IllegalArgumentException. The descendingMap and headMap calls follow the same rule.

When to use it

When An Ordered Map Applies

Recognize The Pattern

Use TreeMap or TreeSet when a program needs the predecessor or successor of a value, the minimum or maximum, or iteration in key order, while keys are added and removed. Typical cases are interval booking, the closest value to a target, and counts that must print in sorted order. Each insert, removal and lookup costs O(log n), and the invariant to protect is that every stored key keeps a stable position under the comparator.

Watch For The Nearest False Friend

A HashMap is a false friend. It looks like the right tool because it also stores keys and values, and its operations cost O(1) on average, but it has no order and no neighbor query. A PriorityQueue is a second false friend. It gives the minimum quickly, yet it cannot find the key just below a given value and cannot remove an arbitrary key cheaply. If the data never changes after loading, a sorted array with binary search is simpler and faster in practice.

Avoid The Java Comparator Traps

The comparator replaces equals. A case-insensitive comparator makes "Apple" and "apple" the same key, so the second add is ignored, even though "Apple".equals("apple") is false. The class BigDecimal shows the reverse case. new BigDecimal("1.0") and new BigDecimal("1.00") are not equal under equals, but compareTo returns 0, so a TreeSet keeps one of them and a HashSet keeps both. A comparator should be consistent with equals unless the program wants that merging.

Never change a stored key in a way that alters its order. The tree does not notice the change, so it stays arranged by the old order. A later search for the key can end at the wrong node and report it missing. Also remember that null is a normal result of floor and its relatives, while put(null, v) on a natural-order TreeMap throws NullPointerException.

Floor And Ceiling

Author exercise

Problem Specification. Given a set of distinct integer keys and a list of query integers, return for each query q two values. The first value is the greatest key that is less than or equal to q. The second value is the smallest key that is greater than or equal to q. If no such key exists, that value is -1.

Input Constraints. The limits are:

  • Keys number between 0 and 10^5, are distinct, and satisfy 0 <= key <= 10^9.
  • Queries number at most 10^5 and satisfy 0 <= q <= 10^9.
  • Return is an int[][] with one pair per query.
  • Mutation of the inputs is not allowed.

Example 1. Input keys 10, 20, 30, 40 and queries 25, 20, 5, 45, output (20, 30), (20, 20), (-1, 10), (40, -1).

Example 2. Input keys 7 and queries 7, 8, output (7, 7), (7, -1).

Prerequisites. The navigation calls and the null result from this lesson.

What This Exercise Changes. Baseline case: one pair of nearest keys per query.

Hint

Which two navigation calls match the two bounds, and what do they return when nothing qualifies?

Algorithmic Solution (attempt the problem first)

Approach. The program loads the keys into a TreeSet and answers each query with two navigation calls.

The call floor(q) returns the greatest key at most q, and ceiling(q) returns the smallest key at least q. Each call descends one root-to-leaf path and remembers the last key that qualified. The invariant is that the remembered key is the best qualifying key among all nodes passed so far, and the subtree not entered cannot hold a better one. Both calls return null when no key qualifies, and the program maps null to -1 before it writes the pair. For keys 10, 20, 30, 40 and query 5, floor finds nothing and ceiling returns 10. The harness also checks the strict calls lower and higher, the empty-set behavior of first, and the live behavior of headSet.

Complexity.

  • Time is O((n + q) log n), because each of the n insertions and 2q navigation calls follows one path of height O(log n).
  • Space is O(n), for the nodes of the tree.
import java.util.NoSuchElementException;
import java.util.Random;
import java.util.TreeSet;

public final class FloorCeilingCheck {
    /**
     * Returns one (floor, ceiling) pair per query, with -1 for a missing neighbor.
     * Time: O((n + q) log n), one tree path per insertion and per navigation call.
     * Space: O(n), one node per key.
     * Invariant: the remembered candidate is the best qualifying key on the path walked so far.
     */
    static int[][] nearest(int[] keys, int[] queries) {
        // The tree keeps keys ordered under natural integer order.
        TreeSet<Integer> set = new TreeSet<>();
        // Each insertion descends one path and relinks a few nodes.
        for (int k : keys) set.add(k);
        // One output pair per query.
        int[][] out = new int[queries.length][2];
        // Each query costs two descents.
        for (int i = 0; i < queries.length; i++) {
            // floor returns the greatest key <= q, or null when none exists.
            Integer f = set.floor(queries[i]);
            // ceiling returns the smallest key >= q, or null when none exists.
            Integer c = set.ceiling(queries[i]);
            // The null result is mapped to the sentinel -1 required by the problem.
            out[i][0] = f == null ? -1 : f;
            out[i][1] = c == null ? -1 : c;
        }
        // The pairs follow the query order.
        return out;
    }

    /** Linear-scan oracle with the same contract. */
    static int[][] brute(int[] keys, int[] queries) {
        // One pair per query.
        int[][] out = new int[queries.length][2];
        // Scan all keys for every query.
        for (int i = 0; i < queries.length; i++) {
            int f = -1, c = -1;
            for (int k : keys) {

                if (k >= queries[i] && (c == -1 || k < c)) c = k;
            }
            out[i][0] = f;
            out[i][1] = c;
        }
        return out;
    }

Ordered Frequency Map

Author exercise

Problem Specification. Start with an empty multiset of integers. Process a list of operations. The operation (1, x) adds one copy of x. The operation (2, x) removes one copy of x, and it does nothing when x is absent. Return the final contents as pairs (value, count) in increasing order of value, listing only values with a positive count.

Input Constraints. The limits are:

  • Operations number at most 10^5.
  • Values are int values with -10^9 <= x <= 10^9.
  • Type is 1 for add and 2 for remove.
  • Return is an int[][] of pairs, and empty contents return an empty array.

Example 1. Input (1,5), (1,3), (1,5), (1,9), (2,3), (2,5), output (5, 1), (9, 1).

Example 2. Input (1,4), (2,7), (1,4), (2,4), (2,4), (2,4), output the empty array.

Prerequisites. The floor and ceiling exercise above.

What This Exercise Changes. The map now stores a count per key, and a removal must delete the key at count 0.

Hint

What must happen to an entry when its count drops to 0, so that the ordered output stays correct?

Algorithmic Solution (attempt the problem first)

Approach. A TreeMap from value to count keeps the values in order while the counts change.

An add operation calls merge, which creates the entry or raises its count with one search. A remove operation looks up the count. When the count is 1, the program deletes the entry, and otherwise it stores the count minus one. The invariant is that every key in the map has a count of at least 1. Deleting at count 0 is necessary, because a key that stays with count 0 would still appear in iteration and in firstKey. The harness shows that effect with a put(k, 0). Iterating the map yields the pairs in increasing key order with no extra sort.

Complexity.

  • Time is O(m log d) for m operations and d distinct values, since each operation does one or two tree searches, and the final iteration costs O(d).
  • Space is O(d), one entry per distinct value with a positive count.
import java.util.Arrays;
import java.util.HashMap;
import java.util.Map;
import java.util.NoSuchElementException;
import java.util.Random;
import java.util.TreeMap;

public final class FrequencyMapCheck {
    /**
     * Applies add and remove operations and returns (value, count) pairs in increasing value order.
     * Time: O(m log d) for m operations and d distinct values, plus O(d) to read the result.
     * Space: O(d), one entry per value with a positive count.
     * Invariant: every key stored in the map has a count of at least 1.
     */
    static int[][] apply(int[][] ops) {
        // The tree orders values and holds one count per value.
        TreeMap<Integer, Integer> counts = new TreeMap<>();
        // One iteration per operation.
        for (int[] op : ops) {
            if (op[0] == 1) {
                // Add: create the entry with 1 or raise the count, using one search.
                counts.merge(op[1], 1, Integer::sum);
            } else {
                // Remove: read the current count with one search.
                Integer c = counts.get(op[1]);
                // An absent value is ignored.
                if (c == null) continue;
                // A count of 1 would become 0, so the entry is deleted to keep the invariant.
                if (c == 1) counts.remove(op[1]);
                // Otherwise the count drops by one.
                else counts.put(op[1], c - 1);
            }
        }
        // Iteration in key order produces the pairs without sorting.
        int[][] out = new int[counts.size()][2];
        int i = 0;
        for (Map.Entry<Integer, Integer> e : counts.entrySet()) {
            // Each entry becomes one (value, count) pair.
            out[i][0] = e.getKey();
            out[i][1] = e.getValue();
            i++;
        }
        return out;
    }

    /** Oracle that counts in a hash map and sorts the distinct values at the end. */
    static int[][] brute(int[][] ops) {
        // The hash map has no order, so ordering happens at the end.
        HashMap<Integer, Integer> m = new HashMap<>();
        for (int[] op : ops) {
            int cur = m.getOrDefault(op[1], 0);
            // Add raises the count, and remove lowers it only when it is positive.
            if (op[0] == 1) m.put(op[1], cur + 1);
            else if (cur > 0) m.put(op[1], cur - 1);
        }
        // Keep only positive counts and sort the values.
        int[] vals = m.entrySet().stream().filter(e -> e.getValue() > 0).mapToInt(Map.Entry::getKey).sorted().toArray();
        int[][] out = new int[vals.length][2];
        for (int i = 0; i < vals.length; i++) {
            out[i][0] = vals[i];
            out[i][1] = m.get(vals[i]);
        }
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        int[][] e1 = apply(new int[][]{{1, 5}, {1, 3}, {1, 5}, {1, 9}, {2, 3}, {2, 5}});
        if (!Arrays.deepEquals(e1, new int[][]{{5, 1}, {9, 1}})) throw new AssertionError("example 1");
        int[][] e2 = apply(new int[][]{{1, 4}, {2, 7}, {1, 4}, {2, 4}, {2, 4}, {2, 4}});
        if (e2.length != 0) throw new AssertionError("example 2");
        // Checks the Java claims: a zero-count entry stays visible, firstKey throws, firstEntry returns null.
        TreeMap<Integer, Integer> t = new TreeMap<>();
        t.put(3, 0);
        if (t.firstKey() != 3) throw new AssertionError("zero count stays");
        t.remove(3);
        boolean threw = false;
        try { t.firstKey(); } catch (NoSuchElementException ex) { threw = true; }
        if (!threw || t.firstEntry() != null) throw new AssertionError("empty map");
        // Checks that subMap is a live view of the map.
        t.put(1, 1); t.put(5, 1); t.put(9, 1);
        Map<Integer, Integer> view = t.subMap(2, true, 9, true);
        t.put(7, 4);
        if (view.size() != 3 || view.get(7) != 4) throw new AssertionError("live subMap");
        // Checks random operation lists against the hash-map oracle.
        Random rnd = new Random(3204);
        for (int round = 0; round < 400; round++) {
            int m = rnd.nextInt(30);
            int[][] ops = new int[m][2];
            for (int i = 0; i < m; i++) {
                ops[i][0] = 1 + rnd.nextInt(2);
                ops[i][1] = rnd.nextInt(7) - 3;
            }
            if (!Arrays.deepEquals(apply(ops), brute(ops))) throw new AssertionError("round " + round);
        }
    }

Author exercise

Problem Specification. Words are compared by letters only, ignoring the case of ASCII letters. Two words are the same key when they differ only in case. Insert the given words in order into an ordered set, and keep the first spelling of each key. For each query word, return the stored word with the greatest key that is strictly smaller than the query under the same comparison, or the text none if no stored key is smaller.

Input Constraints. The limits are:

  • Words number between 0 and 10^4, with length 1 to 10, ASCII letters only.
  • Queries number at most 10^4, with the same length and alphabet.
  • Order compares words letter by letter after converting every letter to lower case.
  • Return is a String[] with one answer per query.

Example 1. Input words Pear, apple, APPLE, banana and queries BANANA, Apple, zebra, output apple, none, Pear.

Example 2. Input words b, B, a and queries B, A, c, output a, none, b.

Prerequisites. The two exercises above.

What This Exercise Changes. Key identity comes from the comparator and not from equals, and a missing neighbor must map to a text result.

Hint

Which comparator makes two spellings one key, and which call returns the strictly smaller neighbor?

Algorithmic Solution (attempt the problem first)

Approach. A TreeSet built with a case-insensitive comparator treats two spellings as one key.

The comparator String.CASE_INSENSITIVE_ORDER returns 0 for words that differ only in case. The set therefore ignores a second insertion of the same key, and the first spelling stays. For a query, lower(query) returns the greatest stored word whose key is strictly smaller, and the comparator also decides what smaller means. When no stored key is smaller, lower returns null, and the program writes none. The invariant is that the set stays ordered under one comparator that is never changed, and that no stored element is mutated. The harness asserts that add returns false for the repeated key, that equals still says the spellings differ, that BigDecimal values 1.0 and 1.00 merge in a TreeSet but not in a HashSet, and that mutating a stored key hides it from contains.

Complexity.

  • Time is O((n + q) log n) comparisons, and each comparison costs O(L) for words of length L, which is at most 10 here.
  • Space is O(n), for the nodes of the stored keys.
import java.math.BigDecimal;
import java.util.HashSet;
import java.util.Random;
import java.util.TreeSet;

public final class ComparatorEqualityCheck {
    /**
     * Returns, per query, the stored word with the greatest key strictly below the query key, or "none".
     * Time: O((n + q) L log n) for words of length L.
     * Space: O(n), one node per distinct key.
     * Invariant: the tree is ordered under one fixed comparator and no stored element changes.
     */
    static String[] lowerWords(String[] words, String[] queries) {
        // Keys that differ only in case compare as equal under this comparator.
        TreeSet<String> set = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);
        // add ignores a word whose key is already present, so the first spelling stays.
        for (String w : words) set.add(w);
        // One answer per query.
        String[] out = new String[queries.length];
        for (int i = 0; i < queries.length; i++) {
            // lower returns the greatest strictly smaller element, or null when none exists.
            String r = set.lower(queries[i]);
            // The null result becomes the required text.
            out[i] = r == null ? "none" : r;
        }
        return out;
    }

    /** Oracle that keeps first spellings in a list and scans for the best smaller key. */
    static String[] brute(String[] words, String[] queries) {
        java.util.ArrayList<String> kept = new java.util.ArrayList<>();
        // Keep a word only when no kept word has the same lower-case text.
        for (String w : words) {
            boolean seen = false;
            for (String k : kept) if (k.toLowerCase().equals(w.toLowerCase())) seen = true;
            if (!seen) kept.add(w);
        }
        String[] out = new String[queries.length];
        for (int i = 0; i < queries.length; i++) {
            String best = null;
            for (String k : kept) {
                // A candidate must be strictly smaller than the query in lower-case order.
                if (k.toLowerCase().compareTo(queries[i].toLowerCase()) < 0
                        && (best == null || k.toLowerCase().compareTo(best.toLowerCase()) > 0)) best = k;
            }
            out[i] = best == null ? "none" : best;
        }
        return out;
    }

    public static void main(String[] args) {
        // Checks Example 1 and Example 2.
        String[] e1 = lowerWords(new String[]{"Pear", "apple", "APPLE", "banana"}, new String[]{"BANANA", "Apple", "zebra"});
        if (!java.util.Arrays.equals(e1, new String[]{"apple", "none", "Pear"})) throw new AssertionError("example 1");
        String[] e2 = lowerWords(new String[]{"b", "B", "a"}, new String[]{"B", "A", "c"});
        if (!java.util.Arrays.equals(e2, new String[]{"a", "none", "b"})) throw new AssertionError("example 2");
        // Checks that the comparator, and not equals, decides key identity.
        TreeSet<String> ci = new TreeSet<>(String.CASE_INSENSITIVE_ORDER);
        ci.add("apple");
        if (ci.add("APPLE") || ci.size() != 1 || !ci.contains("Apple")) throw new AssertionError("comparator identity");
        if ("Apple".equals("apple")) throw new AssertionError("equals differs");
        // Checks a comparator that is not consistent with equals: BigDecimal 1.0 and 1.00.
        BigDecimal a = new BigDecimal("1.0"), b = new BigDecimal("1.00");
        if (a.equals(b) || a.compareTo(b) != 0) throw new AssertionError("bigdecimal contract");
        TreeSet<BigDecimal> tree = new TreeSet<>(java.util.List.of(a, b));
        HashSet<BigDecimal> hash = new HashSet<>(java.util.List.of(a, b));
        if (tree.size() != 1 || hash.size() != 2) throw new AssertionError("merge versus keep both");
        // Checks the key mutation hazard: changing a stored key hides it from searches.
        int[] x = {5}, y = {10}, z = {15};
        TreeSet<int[]> byFirst = new TreeSet<>((p, q) -> Integer.compare(p[0], q[0]));
        byFirst.add(x); byFirst.add(y); byFirst.add(z);
        x[0] = 50;
        if (byFirst.contains(new int[]{50}) || byFirst.contains(new int[]{5}) || byFirst.size() != 3) throw new AssertionError("mutation hazard");
        // Checks that a natural-order TreeMap rejects a null key.
        boolean threw = false;
        try { new java.util.TreeMap<String, Integer>().put(null, 1); } catch (NullPointerException ex) { threw = true; }
        if (!threw) throw new AssertionError("null key");
        // Checks random inputs against the oracle.
        Random rnd = new Random(3205);
        String letters = "abcABC";
        for (int round = 0; round < 400; round++) {
            String[] ws = new String[rnd.nextInt(10)];
            String[] qs = new String[8];
            for (int i = 0; i < ws.length; i++) ws[i] = word(rnd, letters);
            for (int i = 0; i < qs.length; i++) qs[i] = word(rnd, letters);

Problem Specification. Design a calendar class. The call book(start, end) represents the half-open time range from start up to but not including end. If the range shares at least one time with an accepted booking, return false and store nothing. Otherwise store it and return true.

Input Constraints. The limits are:

  • Times are int values with 0 <= start < end <= 10^9.
  • Calls number at most 1000.
  • Touching ranges, where one end equals another start, do not overlap.
  • Return is a boolean for each call.

Example 1. Input the calls book(10, 20), book(15, 25), book(20, 30), output true, false, true.

Example 2. Input the calls book(5, 10), book(0, 5), book(0, 6), book(10, 11), output true, true, false, true.

Prerequisites. All three exercises above.

What This Exercise Changes. The query is an overlap test against stored neighbors, and the stored data changes after every accepted call.

Hint

Among accepted starts, which two neighbors of the new start are the only ones that can overlap it?

Algorithmic Solution (attempt the problem first)

Approach. Accepted bookings never overlap, so only the two neighbors of a new start can conflict with it.

The program stores each accepted booking in a TreeMap from start to end. For a new range, floorEntry(start) gives the booking with the greatest start at most the new start. That booking overlaps when its end is greater than the new start. The call ceilingKey(start) gives the booking with the smallest start at least the new start, and that booking overlaps when its start is below the new end. Any other stored booking lies entirely before the floor booking or after the ceiling booking, because the stored ranges are disjoint and sorted by start. The invariant is that the stored ranges stay pairwise disjoint. A booking with the same start as the new one is found by floorEntry, and its end exceeds the start, so the call is rejected.

Complexity.

  • Time is O(log n) per call, since one insertion and two navigation calls follow tree paths.
  • Space is O(n), one entry per accepted booking.
import java.util.ArrayList;
import java.util.Map;
import java.util.Random;
import java.util.TreeMap;

public final class CalendarCheck {
    private final TreeMap<Integer, Integer> booked = new TreeMap<>();

    /**
     * Books [start, end) when it shares no time with an accepted booking.
     * Time: O(log n), three tree paths.
     * Space: O(1) extra per call, plus one stored entry when accepted.
     * Invariant: the stored ranges are pairwise disjoint, so only the two nearest starts can conflict.
     */
    boolean book(int start, int end) {
        // The booking with the greatest start at most the new start.
        Map.Entry<Integer, Integer> before = booked.floorEntry(start);
        // It conflicts when it still runs after the new start.
        if (before != null && before.getValue() > start) return false;
        // The booking with the smallest start at least the new start.
        Integer after = booked.ceilingKey(start);
        // It conflicts when it begins before the new range ends.
        if (after != null && after < end) return false;
        // No neighbor conflicts, so the range is stored and the invariant holds.
        booked.put(start, end);
        return true;
    }

    /** Oracle that compares the new range with every accepted range. */
    static final class Brute {
        final ArrayList<int[]> list = new ArrayList<>();

        boolean book(int start, int end) {
            // Two half-open ranges overlap when each starts before the other ends.
            for (int[] r : list) if (start < r[1] && r[0] < end) return false;
            list.add(new int[]{start, end});
            return true;
        }
    }

        // Checks Example 1.
        CalendarCheck c1 = new CalendarCheck();
        if (!c1.book(10, 20) || c1.book(15, 25) || !c1.book(20, 30)) throw new AssertionError("example 1");

        if (!c2.book(5, 10) || !c2.book(0, 5) || c2.book(0, 6) || !c2.book(10, 11)) throw new AssertionError("example 2");

        if (m.floorEntry(3) != null || m.ceilingKey(3) != null) throw new AssertionError("empty map neighbors");
        m.put(5, 9);
        if (m.floorEntry(5).getValue() != 9 || m.ceilingKey(5) != 5) throw new AssertionError("equal start");
        // Checks random call sequences against the oracle.
        Random rnd = new Random(3206);
        for (int round = 0; round < 400; round++) {
            CalendarCheck fast = new CalendarCheck();
            Brute slow = new Brute();

                if (fast.book(s, e) != slow.book(s, e)) throw new AssertionError("round " + round + " call " + call);
            }
        }

Problem

Why Comparing Every Pair Is Too Slow

A search engine ranks 100,000 results for a query. An older ranking of the same results exists, and the team wants one number that says how much the two rankings disagree. The number is the count of result pairs that appear in opposite order in the two rankings. A low count means the new ranking changed little. A high count means it reshuffled the list.

The same question appears in many programs. A fraud check counts how many transactions arrive out of timestamp order. A sync tool counts how many edits were applied out of sequence. In each case the program holds an array and must count the pairs of positions i < j where the earlier value is larger than the later value. An array of 100,000 values holds almost five billion such pairs to examine. This lesson answers how to get the total without visiting each pair.

Simple approach

Checking Every Pair With Two Loops

The direct approach fixes each earlier position and compares it with every later position. The method below counts one pair for each position pair where the earlier value is larger.

static long countPairsSlowly(int[] a) {
    long count = 0;                              // a long holds counts above two billion
    for (int i = 0; i < a.length; i++) {
        for (int j = i + 1; j < a.length; j++) {
            if (a[i] > a[j]) {
                count++;                         // one pair out of order
            }
        }
    }
    return count;
}

The outer loop picks the earlier position and the inner loop visits every later position. The method is correct on every input and needs no extra memory. The only question is the number of comparisons.

Bottleneck

Pair Checks Cost O(n^2)

Predict first: An array has 100,000 values. How many comparisons does the double loop make, and is that count larger than the biggest `int`?

It makes 4,999,950,000 comparisons, which is n * (n - 1) / 2. The biggest int is 2,147,483,647, so the count is more than twice as large. The answer itself can reach the same size, so the counter must be a long.

Count The Comparisons

The pair (i, j) is checked once for each i < j. That gives n * (n - 1) / 2 comparisons, so the cost is O(n^2). For n = 100,000 the loops make about five billion comparisons. A typical machine runs a few hundred million simple comparisons per second, so the run takes ten seconds or more. A limit of one or two seconds fails.

Find The Wasted Work

The loops treat every pair as unrelated to the others. Suppose the program already knows that a[5] is larger than a[9] and that a[9] is larger than a[12]. Then a[5] is larger than a[12], and the third comparison adds no information. Sorted order carries exactly this kind of knowledge. If a group of values is sorted, one comparison against that group can settle many pairs at once. The structure we need must put values in sorted order while the program still counts the pairs that sorting would otherwise erase.

Key idea

Count Between Halves Before Merging

Define The Count

An inversion is a pair of positions i < j with a[i] > a[j]. The goal is to count all inversions of the array. Merge sort splits the array into a left half and a right half, sorts each half recursively, and merges the two sorted halves. Every inversion falls into exactly one of three groups. Both positions are in the left half, both are in the right half, or one is in each half.

Split The Pairs

A pair with one position in each half is a cross pair. The recursion already counts the other two groups, because each half is a smaller copy of the same problem. Only the cross pairs remain. For a cross pair the left position is always smaller than the right position, so the pair is an inversion exactly when the left value is larger than the right value. The order of values inside each half does not matter for this test. That fact lets the program sort both halves first, and it still counts the same cross pairs.

Count A Whole Suffix At Once

Take two sorted halves. Compare the current left value a[i] with the current right value a[j]. If a[i] <= a[j], the value a[i] is not larger than a[j] or any later right value, so it forms no cross pair with the unread right values. The left pointer moves forward. If a[i] > a[j], then a[i] and every later left value are also larger than a[j], because the left half is sorted. That is mid - i cross pairs found with one comparison. The right pointer moves forward. This is the counting pass, and it is the ordinary merge loop with one addition per right value taken.

Keep The Counts Correct

Each cross pair is counted exactly once, at the moment its right value is taken by the pointer j. The invariant is that the count so far equals the number of cross pairs whose right value lies before the pointer j. The merge then writes the halves into one sorted run, so the parent level sees a sorted half. The recursion has O(log n) levels, and each level does O(n) work in total. The whole count costs O(n log n).

State

Quantities To Track While Merging

Track these items for one call on the range from lo up to but not including hi.

  • lo is the first index of the range, included.
  • hi is the end of the range, excluded, so the range holds hi - lo values.
  • mid is the start of the right half, and the left half is lo up to mid.
  • i is the left pointer, which moves from lo toward mid.
  • j is the right pointer, which moves from mid toward hi.
  • count is a long with the number of inversions found in the range.
  • buffer is a shared int[] of the full length that holds the merged values before they are copied back.

The range is half open so that hi - lo is its length and an empty range needs no special case. The method passes only these bounds and one shared buffer. It never copies a subarray to pass the state into a recursive call. The unread left values at the moment of a count are the indexes i up to mid, and their number is mid - i.

Walkthrough

Follow Two Merges

Both traces show the counting pass on two sorted halves. The array cells are the left half followed by the right half. The pointer i walks the left half and the pointer j walks the right half.

Count With Distinct Values

The left half is 3, 6, 9 and the right half is 1, 7, 8. At the start, a[i] = 3 is larger than a[j] = 1, and all three left values are larger than 1. The count jumps by 3 with a single comparison. After that the left values 3 and 6 are not larger than 7, so i moves past them. The value 9 is larger than 7 and larger than 8, and each time only one left value is unread, so the count grows by 1 twice. The final count is 5.

Count With Equal Values

The left half is 2, 4, 4, 8 and the right half is 4, 4, 6. The equal values 4 are the hard step. The test is a[i] <= a[j], so an equal left value moves on without counting. The pointer i passes 2 and both left 4s, and none of them is a cross pair with the right 4s, because equal values are not inversions. Only 8 is larger than the right values 4, 4 and 6, and one unread left value remains each time. The final count is 3.

The first trace shows a count larger than 1 from one comparison, which is the saving over the double loop. The second trace shows that the sign of the comparison decides which ties count.

Code

Implement Counting During The Merge

final class MergeCount {
    static long countInversions(int[] a) {
        int[] work = a.clone();                       // the caller's array stays unchanged
        return sortAndCount(work, 0, work.length, new int[work.length]);
    }

    private static long sortAndCount(int[] a, int lo, int hi, int[] buffer) {
        if (hi - lo < 2) {
            return 0;                                 // zero or one value has no pair
        }
        int mid = lo + (hi - lo) / 2;                 // right half starts here
        long count = sortAndCount(a, lo, mid, buffer)
                   + sortAndCount(a, mid, hi, buffer); // pairs inside each half
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            if (j == hi || (i < mid && a[i] <= a[j])) {
                buffer[k++] = a[i++];                 // equal values stay on the left, so ties never count
            } else {
                count += mid - i;                     // all unread left values exceed a[j]
                buffer[k++] = a[j++];
            }
        }
        System.arraycopy(buffer, lo, a, lo, hi - lo); // the range is sorted for the parent
        return count;
    }
}

The recursion passes index bounds and one shared buffer, so no call copies a subarray. The only copy is the single clone at the start, which keeps the caller's array unchanged. When the left half is used up, the else branch adds mid - i, which is 0. The count is a long, because the total can reach about five billion.

When to use it

When Merge Counting Applies

Recognize The Pattern

Use merge counting when the task counts pairs of positions i < j whose values satisfy an order relation, such as a[i] > a[j], and the program only needs the total or one count per position. The relation must be monotone over sorted values: if a left value satisfies it for some right value, every larger left value does too. That property lets one pointer count a whole suffix of the sorted left half.

The invariant to check is that both halves are sorted before the cross pairs are counted, and that the count so far covers exactly the right values already passed. When a condition is more complex than a comparison, such as a[i] > 2 * a[j], the pointer needs its own counting pass before the merge, because the merge order and the counting order differ.

Watch For The Nearest False Friend

Plain sorting is a false friend. Sorting the array gives the right order, but it destroys the original positions, and an inversion depends on those positions. Sorting first and counting afterward answers a different question. A second false friend is a stack or heap pass that works for the next larger value. It finds one neighbor for each position and does not count all larger values.

Avoid The Java Traps

Keep the count in a long, because an array of 100,000 reversed values holds almost five billion inversions. Choose <= or < on purpose, since the choice decides whether equal values count as inversions. Compute the midpoint as lo + (hi - lo) / 2 so the sum of two large bounds cannot overflow. Pass index bounds and one shared buffer, and do not copy subarrays at each level.

Count Inversions

Author exercise

Problem Specification. Given an integer array a, return the number of pairs of positions (i, j) with i < j and a[i] > a[j].

Input Constraints. The limits are:

  • Return is a long, and an empty array or a single value returns 0.

Example 1. Input a = [2, 4, 1, 3, 5], output 3, from the pairs (2, 1), (4, 1) and (4, 3).

Example 2. Input a strictly decreasing array of 100,000 values, output 4,999,950,000, which does not fit in an int.

Prerequisites. The counting pass and the merge from this lesson.

What This Exercise Changes. Baseline case: the merge gains one addition when it takes a right value.

Hint

After both halves are sorted, how many left values are larger than the right value you take?

Algorithmic Solution (attempt the problem first)

Approach. Split the range, count inside each half by recursion, then count the pairs between the halves while merging.

Both halves are sorted when the merge starts. When the merge takes a right value a[j] while the left value a[i] is larger, the sorted left half guarantees that all mid - i unread left values are larger too. The merge adds that number at once. A left value that is less than or equal to the right value moves first, so equal values are never counted. The invariant is that count equals the number of pairs in the range whose right value is already written. The program works on a clone, so the caller's array stays unchanged. The midpoint uses lo + (hi - lo) / 2, because (lo + hi) / 2 overflows an int for bounds near two billion.

Complexity.

  • Time is O(n log n), because the recursion has about log2(n) levels and each level merges n values in total.
  • Space is O(n), for the clone, the shared buffer and the recursion stack of depth O(log n).
import java.util.Arrays;
import java.util.Random;

public final class InversionCount {
    /**
     * Counts pairs i < j with a[i] > a[j] without changing the input.
     * Time: O(n log n), about log2(n) levels of linear merges.
     * Space: O(n), one clone and one shared buffer.
     * Invariant: after a call on [lo, hi), the range is sorted and the return value counts its inversions.
     */
    static long count(int[] input) {
        // The clone keeps the caller's array unchanged.
        int[] work = input.clone();
        // One buffer is shared by every call, so no level allocates.
        return sortCount(work, 0, work.length, new int[work.length]);
    }

    private static long sortCount(int[] a, int lo, int hi, int[] buf) {
        // A range of zero or one value holds no pair.
        if (hi - lo < 2) return 0;
        // The offset form cannot overflow when lo and hi are large.
        int mid = lo + (hi - lo) / 2;
        // Pairs inside each half come from the recursion.
        long total = sortCount(a, lo, mid, buf) + sortCount(a, mid, hi, buf);
        int i = lo, j = mid, k = lo;
        // The loop runs once per value in the range, so each level costs O(n).
        while (i < mid || j < hi) {
            // A tie takes the left value first, so equal values do not count.
            if (j == hi || (i < mid && a[i] <= a[j])) {
                buf[k++] = a[i++];
            } else {
                // Every unread left value is larger than a[j] because the left half is sorted.
                total += mid - i;
                buf[k++] = a[j++];
            }
        }
        // Copy the merged range back so the parent sees sorted halves.
        System.arraycopy(buf, lo, a, lo, hi - lo);
        return total;
    }

    /** Counts inversions with the double loop. */
    static long brute(int[] a) {
        long c = 0;
        for (int i = 0; i < a.length; i++)
            for (int j = i + 1; j < a.length; j++)
                if (a[i] > a[j]) c++;
        return c;
    }

    public static void main(String[] args) {
        // Checks Example 1 and the empty and single-value cases.
        if (count(new int[]{2, 4, 1, 3, 5}) != 3) throw new AssertionError("example 1");
        if (count(new int[]{}) != 0 || count(new int[]{9}) != 0) throw new AssertionError("tiny");
        // Checks Example 2: the total exceeds the int range, so the counter must be a long.
        int n = 100_000;
        int[] down = new int[n];
        for (int i = 0; i < n; i++) down[i] = n - i;
        long big = count(down);
        if (big != 4_999_950_000L) throw new AssertionError("example 2");
        if (big <= Integer.MAX_VALUE) throw new AssertionError("long needed");
        if ((int) big == big) throw new AssertionError("an int cast would lose the value");
        // Checks the claim that (lo + hi) / 2 overflows while the offset form does not.
        int lo = 1_500_000_000, hi = 2_000_000_000;
        if ((lo + hi) / 2 >= 0) throw new AssertionError("sum should overflow");
        if (lo + (hi - lo) / 2 != 1_750_000_000) throw new AssertionError("offset midpoint");
        // Checks against the brute force on random arrays, with many ties and with a wide range.
        Random rnd = new Random(3204);
        for (int round = 0; round < 600; round++) {
            int len = rnd.nextInt(60);
            int bound = round % 2 == 0 ? 6 : Integer.MAX_VALUE;
            int[] a = new int[len];
            for (int i = 0; i < len; i++) a[i] = rnd.nextInt(bound) - (bound / 2);
            int[] copy = a.clone();
            if (count(a) != brute(a)) throw new AssertionError("round " + round);
            // The input array is unchanged by the call.
            if (!Arrays.equals(a, copy)) throw new AssertionError("mutated " + round);
        }
    }

Count of Smaller Numbers After Self

LeetCode 315

Problem Specification. Given an integer array a, return an array result of the same length. The entry result[j] is the number of positions i < j with a[i] > a[j].

Input Constraints. The limits are:

  • Length n is an int with 0 <= n <= 10^5.
  • Values are int values over the full int range, and may repeat.
  • Return is an int[] of length n, indexed by original position.
  • Mutation of a is not allowed.

Example 1. Input a = [5, 2, 6, 1], output [0, 1, 0, 3].

Example 2. Input a = [4, 4, 4], output [0, 0, 0], since equal values are not larger.

Prerequisites. Count Inversions above.

What This Exercise Changes. The output changes from one total to one count per original position, so the merge must carry indexes.

Hint

The merge reorders values, so which array can still tell you the original position of the value you take?

Algorithmic Solution (attempt the problem first)

Approach. Sort an array of positions instead of values, and add to the entry of the right value when it is taken.

The array order holds original positions, and the merge compares a[order[i]] with a[order[j]]. Merging moves positions around, but the array a and the meaning of each position never change. When the right position order[j] is taken while the left value is larger, all mid - i unread left positions hold larger values that sit before it in the original array. The merge adds mid - i to result[order[j]]. Each right position is taken once per level, and its earlier larger values are split across levels without overlap, so the additions over all levels sum to the full count. A left value that is less than or equal to the right value goes first, so equal values do not count. The sums are at most n - 1, so an int is enough here.

Complexity.

  • Time is O(n log n), because each level merges n positions and does one addition per right position.
  • Space is O(n), for the position array, the shared buffer and the result.
import java.util.Arrays;
import java.util.Random;

public final class GreaterBefore {
    /**
     * Returns, for each position j, the number of positions i < j with a[i] > a[j].
     * Time: O(n log n), one merge pass per level over the position array.
     * Space: O(n), for order, the buffer and the result.
     * Invariant: after a call on [lo, hi), order[lo..hi) lists those positions by ascending value,
     * and result holds the larger values found among positions of the same range.
     */
    static int[] countBefore(int[] a) {
        int n = a.length;
        // The position array starts as the identity order.
        int[] order = new int[n];
        for (int i = 0; i < n; i++) order[i] = i;
        int[] result = new int[n];
        sort(a, order, 0, n, new int[n], result);
        return result;
    }

    private static void sort(int[] a, int[] order, int lo, int hi, int[] buf, int[] result) {
        // A range of zero or one position needs no work.
        if (hi - lo < 2) return;
        int mid = lo + (hi - lo) / 2;
        sort(a, order, lo, mid, buf, result);
        sort(a, order, mid, hi, buf, result);
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            // Compare values through the positions; ties go left so equal values are not counted.
            if (j == hi || (i < mid && a[order[i]] <= a[order[j]])) {
                buf[k++] = order[i++];
            } else {
                // The right value gains one per unread left position, all with larger values.
                result[order[j]] += mid - i;
                buf[k++] = order[j++];
            }
        }
        // Copy the merged positions back for the parent level.
        System.arraycopy(buf, lo, order, lo, hi - lo);
    }

    /** Counts earlier larger values with the double loop. */
    static int[] brute(int[] a) {
        int[] r = new int[a.length];
        for (int j = 0; j < a.length; j++)
            for (int i = 0; i < j; i++)
                if (a[i] > a[j]) r[j]++;
        return r;
    }

    public static void main(String[] args) {
        // Checks both examples.
        if (!Arrays.equals(countBefore(new int[]{5, 2, 6, 1}), new int[]{0, 1, 0, 3})) throw new AssertionError("example 1");
        if (!Arrays.equals(countBefore(new int[]{4, 4, 4}), new int[]{0, 0, 0})) throw new AssertionError("example 2");
        if (countBefore(new int[]{}).length != 0) throw new AssertionError("empty");
        // Checks the claim that the call leaves the input unchanged and that the sums fit in an int.
        int n = 50_000;
        int[] down = new int[n];
        for (int i = 0; i < n; i++) down[i] = n - i;
        int[] copy = down.clone();
        int[] r = countBefore(down);
        if (!Arrays.equals(down, copy)) throw new AssertionError("mutated");
        if (r[n - 1] != n - 1) throw new AssertionError("last entry");
        // Checks the per-position results against the brute force, with ties and with a wide value range.
        Random rnd = new Random(3205);
        for (int round = 0; round < 600; round++) {
            int len = rnd.nextInt(60);
            int bound = round % 2 == 0 ? 6 : Integer.MAX_VALUE;
            int[] a = new int[len];
            for (int i = 0; i < len; i++) a[i] = rnd.nextInt(bound) - (bound / 2);
            if (!Arrays.equals(countBefore(a), brute(a))) throw new AssertionError("round " + round);
        }
    }

Equal Values

Author exercise

Problem Specification. Count the position pairs (i, j) of an integer array a that satisfy i < j and a[i] >= a[j]. Equal values count as pairs. Return that count.

Input Constraints. The limits are:

  • Length n is an int with 0 <= n <= 10^5.
  • Values are int values over the full int range, and many may be equal.
  • Return is a long.
  • Mutation of a is not allowed.

Example 1. Input a = [1, 2, 2, 1], output 4, from the pairs at positions (0, 3), (1, 2), (1, 3) and (2, 3).

Example 2. Input a = [7, 7, 7, 7], output 6, since every pair counts. The strict version of the count returns 0 here.

Prerequisites. Both exercises above.

What This Exercise Changes. The relation changes from strictly larger to larger or equal, so the tie rule in the merge flips.

Hint

On a tie, which pointer must move so that the left value is counted against the equal right value?

Algorithmic Solution (attempt the problem first)

Approach. Flip the tie rule so that an equal left value is counted against the right value.

The relation is now a[i] >= a[j]. The merge takes a left value first only when it is strictly smaller than the right value. On a tie the right value is taken and the program adds mid - i. That is correct because the left half is sorted, so the equal left value and every later left value are at least as large as a[j]. The invariant is that the unread left values are all at least a[j] whenever the right value is taken. Keeping the strict rule from the earlier exercise would count only strictly larger left values and would return 0 for four equal values, so the two contracts need different tie rules.

Complexity.

  • Time is O(n log n), since the tie rule changes one comparison and not the number of merge steps.
  • Space is O(n), because the clone, the shared buffer and the call stack are the only extra storage.
import java.util.Random;

public final class EqualPairs {
    /**
     * Counts pairs i < j with a[i] >= a[j].
     * Time: O(n log n), the same merge shape as the strict count.
     * Space: O(n), one clone and one buffer.
     * Invariant: when a right value is taken, every unread left value is at least that right value.
     */
    static long countAtLeast(int[] input) {
        int[] work = input.clone();
        return run(work, 0, work.length, new int[work.length], false);
    }

    /** Counts strict pairs; the flag chooses the tie rule so the two contracts can be compared. */
    static long countStrict(int[] input) {
        int[] work = input.clone();
        return run(work, 0, work.length, new int[work.length], true);
    }

    private static long run(int[] a, int lo, int hi, int[] buf, boolean strict) {
        if (hi - lo < 2) return 0;
        int mid = lo + (hi - lo) / 2;
        long total = run(a, lo, mid, buf, strict) + run(a, mid, hi, buf, strict);
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            // Strict: a tie moves left. Non-strict: a tie moves right, which counts the left value.
            boolean leftFirst = j == hi || (i < mid && (strict ? a[i] <= a[j] : a[i] < a[j]));
            if (leftFirst) {
                buf[k++] = a[i++];
            } else {
                // All unread left values satisfy the relation with a[j].
                total += mid - i;
                buf[k++] = a[j++];
            }
        }
        System.arraycopy(buf, lo, a, lo, hi - lo);
        return total;
    }

    /** Counts pairs with the double loop. */
    static long brute(int[] a, boolean strict) {
        long c = 0;
        for (int i = 0; i < a.length; i++)
            for (int j = i + 1; j < a.length; j++)
                if (strict ? a[i] > a[j] : a[i] >= a[j]) c++;
        return c;
    }

    public static void main(String[] args) {
        // Checks both examples, and the claim that the strict rule returns 0 on equal values.
        if (countAtLeast(new int[]{1, 2, 2, 1}) != 4) throw new AssertionError("example 1");
        if (countAtLeast(new int[]{7, 7, 7, 7}) != 6) throw new AssertionError("example 2");
        if (countStrict(new int[]{7, 7, 7, 7}) != 0) throw new AssertionError("strict on ties");
        if (countAtLeast(new int[]{}) != 0 || countAtLeast(new int[]{3}) != 0) throw new AssertionError("tiny");
        // Checks a large all-equal array: n(n-1)/2 pairs need a long.
        int n = 100_000;
        int[] same = new int[n];
        if (countAtLeast(same) != 4_999_950_000L) throw new AssertionError("all equal");
        // Checks both tie rules against the brute force on random arrays with heavy repetition.
        Random rnd = new Random(3206);
        for (int round = 0; round < 600; round++) {
            int len = rnd.nextInt(60);
            int bound = round % 3 == 0 ? 3 : 8;
            int[] a = new int[len];
            for (int i = 0; i < len; i++) a[i] = rnd.nextInt(bound);
            if (countAtLeast(a) != brute(a, false)) throw new AssertionError("non-strict " + round);
            if (countStrict(a) != brute(a, true)) throw new AssertionError("strict " + round);
        }
    }

Reverse Pairs

LeetCode 493

Problem Specification. Given an integer array a and a non-negative integer d, return the number of pairs of positions (i, j) with i < j and a[i] - a[j] > d.

Input Constraints. The limits are:

  • Length n is an int with 0 <= n <= 10^5.
  • Values are int values over the full int range.
  • Threshold d is a long with 0 <= d <= 4 * 10^9.
  • Return is a long.
  • Mutation of a is not allowed.

Example 1. Input a = [7, 1, 5, 2] and d = 3, output 2, from the pairs (7, 1) and (7, 2).

Example 2. Input a = [2000000000, -2000000000] and d = 3999999999, output 1. The difference is 4,000,000,000, which does not fit in an int.

Prerequisites. All three exercises above.

What This Exercise Changes. The condition becomes a difference test, so the program counts in a separate pass with long arithmetic and then merges.

Hint

The test no longer matches the merge order. Which loop can move one pointer forward over the left half before the merge starts?

Algorithmic Solution (attempt the problem first)

Approach. Count the cross pairs in a separate pass over the two sorted halves, then merge.

The condition a[i] - a[j] > d is the same as a[i] > a[j] + d. The right half is sorted, so a[j] + d grows as j grows. The count of left values above that threshold can only shrink, so one left pointer p moves forward and never back. For each right value, the pointer skips the left values with a[p] - a[j] <= d, and the remaining mid - p left values all satisfy the relation. The counting pass finishes before the merge, because the merge order compares plain values and the counting order compares shifted values. The difference of two int values can reach about four billion, so the subtraction is done in long. The invariant is that, for the right value being processed, the left values before p do not satisfy the relation and those from p on all do.

Complexity.

  • Time is O(n log n), because each level makes one linear counting pass and one linear merge.
  • Space is O(n), for the clone, the shared buffer and the recursion stack.
import java.util.Random;

public final class LargeDrop {
    /**
     * Counts pairs i < j with a[i] - a[j] > d, using long arithmetic.
     * Time: O(n log n), a counting pass and a merge per level.
     * Space: O(n), one clone and one buffer.
     * Invariant: for the current right value, left values before p fail the test and the rest pass.
     */
    static long countDrops(int[] input, long d) {
        int[] work = input.clone();
        return run(work, 0, work.length, new int[work.length], d);
    }

    private static long run(int[] a, int lo, int hi, int[] buf, long d) {
        if (hi - lo < 2) return 0;
        int mid = lo + (hi - lo) / 2;
        long total = run(a, lo, mid, buf, d) + run(a, mid, hi, buf, d);
        // Counting pass: p only moves forward because a[j] + d grows with j.
        int p = lo;
        for (int j = mid; j < hi; j++) {
            // The cast to long happens before the subtraction, so the difference cannot overflow.
            while (p < mid && (long) a[p] - a[j] <= d) p++;
            // Every left value from p on has a difference above d.
            total += mid - p;
        }
        // Merge pass: an ordinary merge of two sorted halves.
        int i = lo, j = mid, k = lo;
        while (i < mid || j < hi) {
            if (j == hi || (i < mid && a[i] <= a[j])) buf[k++] = a[i++];
            else buf[k++] = a[j++];
        }
        System.arraycopy(buf, lo, a, lo, hi - lo);
        return total;
    }

    /** Counts pairs with the double loop in long arithmetic. */
    static long brute(int[] a, long d) {
        long c = 0;
        for (int i = 0; i < a.length; i++)
            for (int j = i + 1; j < a.length; j++)
                if ((long) a[i] - a[j] > d) c++;
        return c;
    }

    public static void main(String[] args) {
        // Checks Example 1 and the empty input.
        if (countDrops(new int[]{7, 1, 5, 2}, 3) != 2) throw new AssertionError("example 1");
        if (countDrops(new int[]{}, 0) != 0) throw new AssertionError("empty");
        // Checks Example 2, and the claim that the difference overflows an int.
        int bad = 2_000_000_000 - (-2_000_000_000);
        if (bad >= 0) throw new AssertionError("int difference should wrap to a negative value");
        if (countDrops(new int[]{2_000_000_000, -2_000_000_000}, 3_999_999_999L) != 1) throw new AssertionError("example 2");
        if (countDrops(new int[]{2_000_000_000, -2_000_000_000}, 4_000_000_000L) != 0) throw new AssertionError("threshold equal");
        // Checks d = 0 against the plain inversion count and a large decreasing array for the long total.
        int n = 100_000;
        int[] down = new int[n];
        for (int i = 0; i < n; i++) down[i] = n - i;
        if (countDrops(down, 0) != 4_999_950_000L) throw new AssertionError("d = 0");
        // Checks random arrays with small and with extreme values against the brute force.
        Random rnd = new Random(3207);
        for (int round = 0; round < 600; round++) {
            int len = rnd.nextInt(60);
            boolean wide = round % 2 == 1;
            int[] a = new int[len];
            for (int i = 0; i < len; i++) a[i] = wide ? rnd.nextInt() : rnd.nextInt(21) - 10;
            long d = wide ? (long) (rnd.nextDouble() * 4e9) : rnd.nextInt(8);
            if (countDrops(a, d) != brute(a, d)) throw new AssertionError("round " + round);
        }
    }

Problem

A Percentile Report On A Million Samples

A web service records the response time of every request in an int[] of 1,000,000 entries, measured in milliseconds. The on-call engineer wants the 95th-percentile time, and the alert must also name how many requests were strictly slower than that time. Many requests share the same time, so the count of ties matters as much as the value.

Sorting the whole array answers the question, but it also orders 950,000 entries that nobody asked about. The report needs one value at one rank plus two counts, and the full order is wasted work.

Formally, the input is an int[] a and a zero-based rank r with 0 <= r < n. The output is the value v that sits at index r when a is sorted in increasing order, the number below of entries strictly smaller than v, and the number equal of entries equal to v.

This lesson asks how to find v, below and equal in expected O(n) time, and how to tell this problem apart from questions that look similar but need the order between pairs of entries.

What Each Technique Adds

What Three Earlier Skills Add

Quickselect Adds Discarding One Side

Quickselect partitions the array around a pivot. The pivot lands at its final sorted index, so a target rank on one side lets the search drop the other side completely. Only the side that holds the target is searched again.

Partition Invariants Add An Equal Region

The three-way partition from the previous lesson splits a range into entries smaller than the pivot, entries equal to the pivot and entries larger than the pivot. Duplicates stay together in the middle region, so one pass reports how many entries tie with the pivot. That count is the extra output this lesson needs.

Merge Counting Adds A Contrast

Merge counting counts, during a merge sort, the pairs that take one entry from each half. It answers questions about two entries at once. This lesson uses it only at the end, to show which questions selection cannot answer.

Simple approach

Sort Everything And Read One Index

The direct method sorts a copy of the array, reads index r, and then scans once to count the smaller and equal entries. It is correct for every input and works as a test oracle for faster code.

static int[] selectBySorting(int[] a, int r) {
    int[] sorted = a.clone();
    java.util.Arrays.sort(sorted);
    int v = sorted[r];
    int below = 0, equal = 0;
    for (int x : sorted) {
        if (x < v) below++;
        else if (x == v) equal++;
    }
    return new int[]{v, below, equal};
}

The sort dominates the work. For 1,000,000 entries it performs about 20 million comparisons, and the counting scan adds one more pass.

Bottleneck

The Sort Orders Entries Nobody Needs

Predict first: After the sort, the code reads only sorted[r] and then counts entries. Which part of the sorted order did the answer actually use, and is there a cheaper way to learn it?

The answer used only one position and the knowledge of which entries lie before and after it. The order inside the smaller entries and inside the larger entries was never read. A single partition around any value already tells how many entries are smaller, equal and larger, so a rank inside the middle region is answered without sorting the sides.

Count The Wasted Work

Sorting costs O(n log n) time. For n = 1,000,000 that is about 20 comparisons per entry. The answer uses one position, so the log n factor pays for order that the output never shows. A single pass over the array costs O(n), and the goal is to reach the answer with a few such passes.

Find What One Pass Can Decide

One pass can compare every entry with a chosen pivot and count three groups. If r falls inside the group of smaller entries, the answer lies in that group. If r falls in the group of larger entries, the answer lies there. In both cases the other two groups are never examined again. The open question is how to move entries so the next pass sees only the group that holds r.

Key idea

Partition Then Keep One Side

A three-way partition solves both parts. It rearranges the current range in place and gives exact counts.

Use The Pivot Rank To Discard

Pick a pivot value p and partition the range lo..hi into three blocks, in this order: entries smaller than p, the equal block of entries equal to p, and entries larger than p. Let lt be the first index of the equal block and gt its last index. Every entry left of lt is smaller than p, so the pivot rank of the block is the index range lt..gt, and those indices hold p in the final sorted order.

Compare r with that range. If r < lt, the answer is in the smaller block, so the search continues on lo..lt - 1. If r > gt, the answer is in the larger block, so it continues on gt + 1..hi. If lt <= r <= gt, the answer is p, and the search stops.

Read The Counts From The Last Partition

The two counts need no extra scan. Every entry discarded on the left is strictly smaller than every entry in the current range, and every entry discarded on the right is strictly larger. All entries equal to the answer therefore lie inside the last equal block. The last values of lt and gt give below = lt and equal = gt - lt + 1.

The invariant is that the answer index r always lies inside the current range, and everything outside the range keeps its position relative to the answer. Each round removes at least the equal block, so the loop ends.

Separate Selection From Pair Questions

Selection knows how each entry compares with one pivot. It does not know how two entries compare with each other. A question such as "for every index, how many later entries are smaller" needs the relation of each pair. Counting a cross pair, a pair with one entry in each half of a split array, is the job of merge counting. The applicability stage returns to this difference.

State

Quantities For The Selection Loop

The code and the traces use the following quantities.

  • a is the working copy of the input, rearranged by every round.
  • r is the zero-based target rank in the sorted order.
  • lo and hi are the first and last index of the current range.
  • pivot is the value at the middle index of the range, a[lo + (hi - lo) / 2].
  • lt and gt are the first and last index of the equal block after a round.
  • below and equal are the final outputs and equal lt and gt - lt + 1 after the last round.

Walkthrough

Select A Rank From Two Arrays

An Array With Many Ties

The first array is [7, 2, 9, 2, 5, 7, 7, 1, 8] with r = 6. The sorted order is [1, 2, 2, 5, 7, 7, 7, 8, 9], so the answer is 7 with 4 smaller entries and 3 equal entries.

Round 1 uses the middle entry 5 as pivot and moves the three smaller entries to the front. The equal block holds the single 5 at index 3, and r = 6 lies to its right, so the search keeps the larger side, indices 4 to 8. Round 2 uses pivot 9, which ends alone at index 8. Now r lies to its left, so the search keeps indices 4 to 7. Round 3 uses pivot 7, and the equal block holds all three 7s at indices 4 to 6. Rank 6 falls inside it, so the loop stops. The counts come from lt and gt: below = 4 and equal = 3.

An Array With A Target Near The Front

The second array is [4, 4, 4, 3, 10, -6, 4, 8] with r = 1. The sorted order is [-6, 3, 4, 4, 4, 4, 8, 10], so the answer is 3 with one smaller entry and one equal entry.

The middle entry of the whole array is 3, so the first round uses pivot 3. One entry, -6, is smaller, and the equal block holds only the 3 at index 1. Rank 1 falls inside that block, so the loop stops after one round. The four 4s and the other larger entries are never examined again. This array shows that a pivot equal to the answer ends the search at once.

Code

Select With A Three-Way Partition

The method below returns {value, below, equal} and leaves the input array unchanged.

final class Selector {
    static int[] select(int[] input, int r) {
        int[] a = input.clone();
        int lo = 0, hi = a.length - 1;
        while (true) {
            int pivot = a[lo + (hi - lo) / 2];
            int lt = lo, i = lo, gt = hi;
            while (i <= gt) {
                if (a[i] < pivot) swap(a, lt++, i++);
                else if (a[i] > pivot) swap(a, i, gt--);
                else i++;
            }
            if (r < lt) hi = lt - 1;
            else if (r > gt) lo = gt + 1;
            else return new int[]{pivot, lt, gt - lt + 1};
        }
    }

    static void swap(int[] a, int x, int y) {
        int t = a[x]; a[x] = a[y]; a[y] = t;
    }
}

Each round costs O(hi - lo + 1), and the range shrinks by at least one entry. A pivot near the middle value halves the range, so the expected total is O(n). A fixed middle-index pivot has an input that shrinks the range by one entry per round and costs O(n^2) time, so production code picks the pivot index at random. The method uses O(n) memory for the copy. When every entry is equal, the first round ends the loop, because the equal block covers the whole range.

When to use it

When Selection Fits And When It Fails

Recognize The Cue

Use selection when the output depends on one rank, or on a group at a rank, and not on the full order. Typical signals are a median, a percentile, the k-th largest value, and the k closest items with a tie rule. The equal block also supports a tie rule, because it states how many entries tie at the boundary.

Check The Invariant

The invariant is that the target rank stays inside the current range and the discarded entries sit on the correct side of every later value. Test an array of one entry, all-equal entries, ascending and descending input, r = 0, r = n - 1, and Integer.MIN_VALUE with Integer.MAX_VALUE. Compare the output with sorting on random small arrays.

Watch For The False Friend

The false friend is a per-index question that looks like a rank question. "How many later entries are smaller than this one" mentions order and smaller entries, but the answer differs for every index and depends on positions. A pivot partition destroys the original positions of the entries. Partition cannot answer it. Merge counting keeps the position information while it sorts. A second false friend is the pair condition nums[i] > 2 * nums[j], which compares two entries with each other. No single pivot decides it, so selection does not apply. A related slip is the product 2 * nums[j] in int, which overflows near the type limits and needs long.

Know When Not To Use It

Skip selection when the full sorted order is needed, when many different ranks of the same array are queried, or when the array changes between queries. In those cases sort once, or use an ordered structure. For a small fixed k on a stream, a heap is simpler.

Kth Largest Element In An Array With Position Range

LeetCode 215

Problem Specification. This is a variant of LeetCode 215 that also reports positions. An int[] nums and an integer k are given. Let s be nums sorted in non-increasing order. Return an int[] of three entries. The first entry is s[k - 1]. The second and third entries are the smallest and the largest zero-based index t with s[t] == s[k - 1].

Input Constraints. The limits are:

  • Length n is from 1 to 100,000.
  • k satisfies 1 <= k <= n.
  • Entries are any int values, including the extreme values, and may repeat.
  • Mutation of the input array is not allowed.

Example 1. Input nums = [4, 9, 4, 1, 4, 9, 6], k = 5, output [4, 3, 5].

Example 2. Input nums = [5, 5, 5, 5], k = 3, output [5, 0, 3], since all entries tie.

Prerequisites. The three-way partition and the loop that keeps one side, from this lesson.

What This Exercise Changes. The partition puts larger entries first, and the output is a position range and not a single value. The counts of larger and equal entries replace the index of the last pivot.

Hint

How many entries are larger than the answer? How many tie with it? Which of the two numbers gives the first index of the range?

Algorithmic Solution (attempt the problem first)

Approach. The search partitions the current range into larger entries, equal entries and smaller entries, in that order, so the sorted-descending index of each block is known from counts alone.

The variable before counts the entries already discarded on the larger side. If the target index k - 1 is below before + big, the larger block holds it and the search keeps that block. If it is at or past before + big + same, the smaller block holds it, and before grows by big + same. Otherwise the pivot is the answer, the first index of the range is before + big, and the last is that value plus same - 1. The invariant is that every discarded entry on the larger side is greater than every entry in the range, so before is exactly the number of entries above the range.

Complexity.

  • Time is expected O(n), because a random pivot shrinks the range by a constant factor in expectation and each round scans the range once.
  • Space is O(n) for the working copy, because the input must stay unchanged.
import java.util.*;

public final class KthRange {
    /**
     * Returns {value, firstIndex, lastIndex} of the k-th largest entry in non-increasing order.
     * Time: expected O(n). Space: O(n) for the copy.
     * Invariant: before counts the discarded entries that are larger than everything in a[lo..hi].
     */
    static int[] kthRange(int[] nums, int k, Random rnd) {
        // Copy so the caller's array stays unchanged.
        int[] a = nums.clone();
        // The range starts as the whole array and nothing is discarded yet.
        int lo = 0, hi = a.length - 1, before = 0;
        // Each round removes at least the equal block, so the loop ends.
        while (true) {
            // A random pivot index avoids a fixed worst-case input.
            int pivot = a[lo + rnd.nextInt(hi - lo + 1)];
            // gt..: larger entries go to the front of the range, smaller ones to the back.
            int big = lo, i = lo, small = hi;
            // One scan of the range costs O(hi - lo + 1).
            while (i <= small) {
                // A larger entry swaps into the front block.
                if (a[i] > pivot) { int t = a[big]; a[big] = a[i]; a[i] = t; big++; i++; }
                // A smaller entry swaps into the back block, and the swapped-in entry is unread.
                else if (a[i] < pivot) { int t = a[small]; a[small] = a[i]; a[i] = t; small--; }
                // An equal entry stays in the middle.
                else i++;
            }
            // Descending index of the first and last equal entry in the whole array.
            int first = before + (big - lo), last = before + (small - lo);
            // The target lies in the larger block: keep only that block.
            if (k - 1 < first) hi = big - 1;
            // The target lies in the smaller block: discard the larger and equal blocks.
            else if (k - 1 > last) { before = last + 1; lo = small + 1; }
            // The target lies in the equal block: the pivot is the answer.
            else return new int[]{pivot, first, last};
        }
    }

    public static void main(String[] args) {
        // Checks Example 1 with ties in the answer.
        if (!Arrays.equals(kthRange(new int[]{4, 9, 4, 1, 4, 9, 6}, 5, new Random(1)), new int[]{4, 3, 5})) throw new AssertionError("example 1");
        // Checks Example 2 where all entries tie.
        if (!Arrays.equals(kthRange(new int[]{5, 5, 5, 5}, 3, new Random(1)), new int[]{5, 0, 3})) throw new AssertionError("example 2");
        // Checks the extreme value and that the input is not mutated.
        int[] in = {Integer.MIN_VALUE, Integer.MAX_VALUE, 0};
        if (!Arrays.equals(kthRange(in, 3, new Random(1)), new int[]{Integer.MIN_VALUE, 2, 2})) throw new AssertionError("extreme");
        if (!Arrays.equals(in, new int[]{Integer.MIN_VALUE, Integer.MAX_VALUE, 0})) throw new AssertionError("mutated");
        // Compares with a sort-based oracle on random inputs.
        Random rnd = new Random(3201);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(12);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = rnd.nextInt(6) - 3;
            int k = 1 + rnd.nextInt(n);
            Integer[] s = new Integer[n];
            for (int i = 0; i < n; i++) s[i] = v[i];
            Arrays.sort(s, Collections.reverseOrder());
            int val = s[k - 1], f = -1, l = -1;
            for (int i = 0; i < n; i++) if (s[i] == val) { if (f < 0) f = i; l = i; }
            if (!Arrays.equals(kthRange(v, k, rnd), new int[]{val, f, l})) throw new AssertionError("random " + iter);
        }
    }

LeetCode 973

Problem Specification. This is a variant of LeetCode 973 that reports a tie boundary. An array points of pairs {x, y} and an integer k are given. The squared distance of a point to the origin is x * x + y * y. Let d be the k-th smallest squared distance, counting repeated distances. Input Constraints. The limits are:

  • Count of points is from 1 to 100,000.
  • k satisfies 1 <= k <= the count of points.
  • Coordinates are int values between -10^9 and 10^9.
  • Distances need long arithmetic, and the points may repeat.
  • Mutation of the input is not allowed.

Example 1. Input points = [[3, 4], [-3, -4], [0, 5], [1, 1], [5, 0]], k = 3, output [25, 1, 4].

Example 2. Input points = [[1000000000, 1000000000], [0, 0]], k = 2, output [2000000000000000000, 1, 1].

Prerequisites. The exercise above and the equal block from this lesson.

What This Exercise Changes. The selection key is derived from each point and is a long. The output reports the boundary of a tie group, so the points themselves are never returned.

Hint

Which array do you partition, the points or a derived array? What happens to x * x when x is an int?

Algorithmic Solution (attempt the problem first)

Approach. The code builds a long[] of squared distances and applies quickselect with a two-way partition to that array. Selecting on the derived array leaves the points unchanged, and one final pass over the distances counts the entries below and equal to the selected value.

The conversion (long) x * x widens before multiplying. Without the cast, x * x is computed in int and wraps for x above 46,340. The invariant of the partition is that after each round the pivot index holds the value that belongs there, so the target index lies in exactly one side or equals the pivot index.

Complexity.

  • Time is expected O(n), with one pass to build the distances, expected linear selection and one counting pass.
  • Space is O(n) for the distance array.
import java.util.*;

public final class ClosestTies {
    /**
     * Returns {d, countBelow, countEqual} for the k-th smallest squared distance.
     * Time: expected O(n). Space: O(n).
     * Invariant: after each partition the pivot sits at its final index inside lo..hi.
     */
    static long[] boundary(int[][] points, int k, Random rnd) {
        int n = points.length;
        // Widen before multiplying so the product cannot wrap.
        long[] d = new long[n];
        for (int i = 0; i < n; i++) d[i] = (long) points[i][0] * points[i][0] + (long) points[i][1] * points[i][1];
        // Zero-based target rank in increasing order.
        int target = k - 1, lo = 0, hi = n - 1;
        // The loop ends when the pivot index equals the target.
        while (lo < hi) {
            // Move a random pivot to the end of the range for a Lomuto partition.
            int p = lo + rnd.nextInt(hi - lo + 1);
            long pv = d[p]; d[p] = d[hi]; d[hi] = pv;
            // store marks the end of the block of entries smaller than the pivot.
            int store = lo;
            for (int i = lo; i < hi; i++) {
                // A smaller entry joins the front block.
                if (d[i] < pv) { long t = d[store]; d[store] = d[i]; d[i] = t; store++; }
            }
            // Place the pivot at its final index.
            d[hi] = d[store]; d[store] = pv;
            // Keep the side that holds the target, or stop when the pivot index is the target.
            if (target < store) hi = store - 1;
            else if (target > store) lo = store + 1;
            else lo = hi = store;
        }
        long val = d[target];
        // One counting pass reads the tie boundary.
        long below = 0, equal = 0;
        for (long x : d) { if (x < val) below++; else if (x == val) equal++; }
        return new long[]{val, below, equal};
    }

    public static void main(String[] args) {
        // Checks Example 1 with four tied points.
        if (!Arrays.equals(boundary(new int[][]{{3, 4}, {-3, -4}, {0, 5}, {1, 1}, {5, 0}}, 3, new Random(1)), new long[]{25, 1, 4})) throw new AssertionError("example 1");
        // Checks Example 2 where the squared distance exceeds the int range.
        if (!Arrays.equals(boundary(new int[][]{{1000000000, 1000000000}, {0, 0}}, 2, new Random(1)), new long[]{2000000000000000000L, 1, 1})) throw new AssertionError("example 2");
        // Checks the Java behaviour that int multiplication wraps while the widened product does not.
        int x = 100000;
        if (x * x == (long) x * x) throw new AssertionError("int product should wrap");
        // Checks that the input points are unchanged.
        int[][] pts = {{2, 1}, {0, 0}};
        boundary(pts, 1, new Random(1));
        if (pts[0][0] != 2 || pts[1][0] != 0) throw new AssertionError("mutated");
        // Compares with a sort-based oracle on random inputs.
        Random rnd = new Random(3202);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(10);
            int[][] p = new int[n][2];
            long[] s = new long[n];
            for (int i = 0; i < n; i++) {
                p[i][0] = rnd.nextInt(7) - 3; p[i][1] = rnd.nextInt(7) - 3;
                s[i] = (long) p[i][0] * p[i][0] + (long) p[i][1] * p[i][1];
            }
            int k = 1 + rnd.nextInt(n);
            long[] sorted = s.clone();
            Arrays.sort(sorted);
            long v = sorted[k - 1], b = 0, e = 0;
            for (long y : s) { if (y < v) b++; else if (y == v) e++; }
            if (!Arrays.equals(boundary(p, k, rnd), new long[]{v, b, e})) throw new AssertionError("random " + iter);
        }
    }

Count Of Smaller Numbers After Self Within A Distance

LeetCode 315

Problem Specification. This is a variant of LeetCode 315 with a value window. An int[] nums and a long d are given. For every index i, count the indices j > i with 0 < nums[i] - nums[j] <= d. Return an int[] with one count per index.

Input Constraints. The limits are:

  • Length is from 1 to 100,000.
  • Entries are any int values, including the extreme values.
  • d is a long between 0 and 4,294,967,295.
  • Differences are computed in long, and d = 0 gives all zeros.
  • Mutation of the input array is not allowed.

Example 1. Input nums = [8, 5, 7, 3, 5, 2], d = 3, output [3, 2, 1, 1, 1, 0].

Example 2. Input nums = [2147483647, -2147483648], d = 4294967295, output [1, 0].

Prerequisites. The false friend in the applicability stage and merge counting from the earlier lesson.

What This Exercise Changes. The count is restricted to a window of values below each entry, so the merge needs two moving positions in the sorted right half instead of one. The result is stored per original index.

Hint

Why does selection fail here? When both halves are sorted by value, how do the two window ends move as the left entry grows?

Algorithmic Solution (attempt the problem first)

Approach. Selection cannot answer this because the result differs for every index, so the solution sorts an array of indices by value with merge sort and counts during each merge.

When two halves are sorted by value, every index in the left half precedes every index in the right half. For a left entry x, the matching right entries are those with value in [x - d, x). Two positions walk the sorted right half: hiPos stops at the first right value that is not below x, and loPos stops at the first right value that is not below x - d. The count hiPos - loPos is added to the answer of the left entry's original index. Both positions only move forward, because the left values ascend. The bound x - d is computed in long. The invariant is that, when a merge starts, each half is sorted by value and each half has already counted all pairs inside itself.

Complexity.

  • Time is O(n log n), since the recursion has log n levels and each merge makes linear moves.
  • Space is O(n) for the index array, the temporary array and the answers.
import java.util.*;

public final class WindowSmaller {
    /**
     * Counts, for each i, the later entries j with 0 < nums[i] - nums[j] <= d.
     * Time: O(n log n). Space: O(n).
     * Invariant: before a merge, both halves of idx are sorted by value and count their internal pairs.
     */
    static int[] count(int[] nums, long d) {
        int n = nums.length;
        int[] out = new int[n];
        // idx holds original positions and gets sorted by value.
        int[] idx = new int[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        sort(nums, d, idx, new int[n], 0, n, out);
        return out;
    }

    private static void sort(int[] v, long d, int[] idx, int[] tmp, int lo, int hi, int[] out) {
        // A range of one entry has no pair.
        if (hi - lo < 2) return;
        int mid = (lo + hi) >>> 1;
        // Sort and count inside each half first.
        sort(v, d, idx, tmp, lo, mid, out);
        sort(v, d, idx, tmp, mid, hi, out);
        // Positions in the sorted right half; both only move forward.
        int hiPos = mid, loPos = mid;
        for (int a = lo; a < mid; a++) {
            long x = v[idx[a]];
            // Advance to the first right value that is not below x.
            while (hiPos < hi && v[idx[hiPos]] < x) hiPos++;
            // Advance to the first right value that is not below x - d.
            while (loPos < hi && v[idx[loPos]] < x - d) loPos++;
            // Right values in [x - d, x) are the smaller entries within the window.
            out[idx[a]] += hiPos - loPos;
        }
        // Standard merge by value restores the sorted order for the parent call.
        int l = lo, r = mid, t = lo;
        while (l < mid && r < hi) tmp[t++] = v[idx[l]] <= v[idx[r]] ? idx[l++] : idx[r++];
        while (l < mid) tmp[t++] = idx[l++];
        while (r < hi) tmp[t++] = idx[r++];
        System.arraycopy(tmp, lo, idx, lo, hi - lo);
    }

    public static void main(String[] args) {
        // Checks Example 1.
        if (!Arrays.equals(count(new int[]{8, 5, 7, 3, 5, 2}, 3), new int[]{3, 2, 1, 1, 1, 0})) throw new AssertionError("example 1");
        // Checks Example 2 where the difference exceeds the int range.
        if (!Arrays.equals(count(new int[]{Integer.MAX_VALUE, Integer.MIN_VALUE}, 4294967295L), new int[]{1, 0})) throw new AssertionError("example 2");
        // Checks the Java behaviour that the int difference wraps to a negative value.
        if (Integer.MAX_VALUE - Integer.MIN_VALUE >= 0) throw new AssertionError("int difference should wrap");
        // Checks d = 0 and that the input is unchanged.
        int[] in = {4, 1, 4};

Reverse Pairs With A Triple Threshold

LeetCode 493

Problem Specification. This is a variant of LeetCode 493 with factor 3. An int[] nums is given. Return the number of index pairs (i, j) with i < j and nums[i] >= 3 * nums[j], where the product is computed without overflow.

Input Constraints. The limits are:

  • Length is from 1 to 100,000.
  • Entries are any int values, including the extreme values.
  • Result is a long, since it can exceed the int range.
  • Products are computed in long.
  • Mutation of the input array is not allowed.

Example 1. Input nums = [9, 2, 6, -1, 3, -4], output 10.

Example 2. Input nums = [0, 0, 0], output 3, since 0 >= 0 holds for each of the three pairs.

Prerequisites. All three exercises above.

What This Exercise Changes. The factor is 3 and the comparison is non-strict, so the pointer in the sorted left half stops at the first entry that reaches the threshold. Equal values now count.

Hint

Does any single pivot decide a pair? Which counting method keeps the order of the positions while it sorts?

Algorithmic Solution (attempt the problem first)

Approach. A pair condition between two entries is a cross-pair question, so the solution uses merge counting on values and not selection.

After both halves are sorted ascending, each right entry y is checked against the left half. The left entries with value at least 3 * y form a suffix of the sorted left half, and the pointer p marks where the suffix starts. As y ascends, 3 * y ascends, so p only moves forward. The count added for y is mid - p. The product uses 3L * y so it cannot overflow. The count is counted before the halves merge, so only pairs with the left entry earlier in the array are counted. The invariant is that both halves are sorted and have counted their internal pairs.

Complexity.

  • Time is O(n log n), from log n levels of linear merges.
  • Space is O(n) for the temporary array and the copy.
import java.util.*;

public final class TriplePairs {
    /**
     * Counts pairs i < j with nums[i] >= 3 * nums[j].
     * Time: O(n log n). Space: O(n).
     * Invariant: before counting a merge, both halves are sorted ascending and count their own pairs.
     */
    static long count(int[] nums) {
        int[] a = nums.clone();
        return sort(a, new int[a.length], 0, a.length);
    }

    private static long sort(int[] a, int[] tmp, int lo, int hi) {
        // A range of one entry has no pair.
        if (hi - lo < 2) return 0;
        int mid = (lo + hi) >>> 1;
        // Pairs inside each half.
        long total = sort(a, tmp, lo, mid) + sort(a, tmp, mid, hi);
        // p is the first left index whose value reaches the threshold.
        int p = lo;
        for (int r = mid; r < hi; r++) {
            // The threshold ascends with r, so p never moves back.
            while (p < mid && a[p] < 3L * a[r]) p++;
            // Every left entry from p to mid - 1 forms a counted pair.
            total += mid - p;
        }
        // Merge by value so the parent call sees sorted halves.
        int l = lo, r = mid, t = lo;
        while (l < mid && r < hi) tmp[t++] = a[l] <= a[r] ? a[l++] : a[r++];
        while (l < mid) tmp[t++] = a[l++];
        while (r < hi) tmp[t++] = a[r++];
        System.arraycopy(tmp, lo, a, lo, hi - lo);
        return total;
    }

    public static void main(String[] args) {
        // Checks Example 1.
        if (count(new int[]{9, 2, 6, -1, 3, -4}) != 10) throw new AssertionError("example 1");
        // Checks Example 2 where the non-strict comparison counts equal values.
        if (count(new int[]{0, 0, 0}) != 3) throw new AssertionError("example 2");
        // Checks the extreme pair, where the int product 3 * MIN_VALUE would wrap.
        if (count(new int[]{Integer.MAX_VALUE, Integer.MIN_VALUE}) != 1) throw new AssertionError("extreme");
        if (3 * Integer.MIN_VALUE == 3L * Integer.MIN_VALUE) throw new AssertionError("int product should wrap");
        // Checks that the input is unchanged.
        int[] in = {5, 1, 0};
        count(in);
        if (!Arrays.equals(in, new int[]{5, 1, 0})) throw new AssertionError("mutated");
        // Compares with a double loop on random inputs.
        Random rnd = new Random(3204);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(12);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = rnd.nextInt(13) - 6;
            long expect = 0;
            for (int i = 0; i < n; i++)
                for (int j = i + 1; j < n; j++)
                    if (v[i] >= 3L * v[j]) expect++;
            if (count(v) != expect) throw new AssertionError("random " + iter);
        }
    }
