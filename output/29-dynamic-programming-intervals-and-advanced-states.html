Chapter 29

Dynamic Programming With Ranges And Masks

Orientation

A greedy loop pops balloons in the order of their sizes and reports fewer coins than the best plan earns. A cleaner rejects a two-person assignment because it tries the cheapest worker for each task and runs out of workers. A counter loops through ten million numbers to count the ones without a zero digit and times out. Each program fails because one position, one set or one bound is not part of the state. This chapter adds that missing piece to a table entry: a range of positions, the children of a tree node, a set of used items, or the digits seen so far.

Prerequisites

You should know the three previous dynamic programming chapters. They explained how to state in one sentence what a table entry means, how to seed the base entry, and how to read only entries that are already final. The previous chapter ended with a table indexed by the two ends of one string, and the first lessons here reuse it. The code uses arrays of int, long and String, and it assumes import java.util.*; in samples.

The Seven Lessons

Each lesson fixes one question about what an entry remembers.

  • Interval DP stores the best value for every contiguous range and combines two shorter ranges around one split.
  • Palindrome Partitions builds a table that says whether each substring reads the same in both directions, then uses it to count the fewest pieces of a prefix.
  • Tree DP returns several values from each subtree, one for each choice the parent can make, and passes distances from the parent in a second pass.
  • Bitmask Assignment packs a set of used items into one int and explains the bit operations it needs.
  • Submask Aggregation visits every subset of a mask, and it sums over all subsets with one pass per bit.
  • Digit DP counts numbers up to a bound by tracking the position and two flags.
  • Optimization Proofs shows how to shrink a table or a scan without losing any entry the recurrence reads.

The Closing Lesson

  • DP With Advanced State compares the three index choices (range, prefix, mask) on one problem and then solves four exercises that each need two of them.

How To Work Through Each Lesson

A lesson opens with a small program that returns a wrong or slow answer on a realistic input. It shows a first version and asks you to predict its output. Later parts name the rule, list the variables, follow two traces, show the code and say when the rule stops fitting. Four exercises close each lesson, and they climb through Build, Vary, Boundary and Recognize. Read a hint only after a real attempt.

What You Can Do After This Chapter

You can read a problem and name the state that its entries need: a range, a mask, a pair of flags or a subtree summary. You can size the table before allocating it. You can fill the table in an order that finishes every needed entry first, and you can state which entries an optimization may drop.

What Later Chapters Reuse

The bit operations from the bitmask lessons return in the bits and number theory chapter, which treats them in depth. Chapters on trees and graphs reuse the subtree summary. Specialized speedups for recurrences, such as Knuth, divide and conquer, and convex hull optimizations, need their own proofs and have no lesson here.

Problem

Joining Chunks That Must Stay In Order

A build tool receives four chunk files of 9, 7, 8 and 8 megabytes. It must join them into one file, and the chunks must stay in their given order. Each join of two neighbouring pieces copies every byte of both, so a join of 9 and 7 megabytes costs 16 megabytes of copying. The tool wants the plan with the least total copying.

A developer adds a simple rule: always join the two neighbours with the smallest combined size. On these chunks the rule copies 70 megabytes. Another plan copies only 64 megabytes, and the rule never finds it.

Formally, the input is an array a of non-negative sizes. A merge replaces two neighbouring pieces with one piece whose size is their sum, and it costs that sum. Repeat merges until one piece remains. Return the smallest total cost. An array with zero or one piece costs 0, and the input array does not change.

This lesson asks how to choose merges when each choice changes which pieces stay neighbours.

Simple approach

Joining The Cheapest Neighbours First

The simple rule looks at every neighbouring pair, merges the pair with the smallest sum, and repeats. The list shrinks by one piece per round.

static int cheapestFirst(int[] a) {
    List<Integer> pieces = new ArrayList<>();
    for (int x : a) pieces.add(x);
    int total = 0;
    while (pieces.size() > 1) {
        int at = 0;
        for (int i = 1; i + 1 < pieces.size(); i++) {
            if (pieces.get(i) + pieces.get(i + 1) < pieces.get(at) + pieces.get(at + 1)) at = i;
        }
        int sum = pieces.get(at) + pieces.get(at + 1);
        total += sum;
        pieces.set(at, sum);
        pieces.remove(at + 1);
    }
    return total;
}

Each round scans the list once and removes one piece, so the rule runs in O(n^2) time with O(n) memory. It is fast, but each merge is final. A cheap early merge can create a large piece that every later merge must copy again.

Predict first: Run cheapestFirst on a = [9, 7, 8, 8]. What does it return, and what is the true minimum?

It returns 70. It merges 7 and 8 for 15, then 15 and 8 for 23, then 9 and 23 for 32, and 15 + 23 + 32 is 70. The piece of 15 is copied again in two later merges. Merging 9 with 7 and 8 with 8 costs 16 + 16 + 32, which is 64.

Bottleneck

Every Merge Plan Shares Smaller Plans

Predict first: A recursive search tries every way to finish merging 10 pieces and stores nothing. How many calls does it make, and how many different groups of neighbouring pieces exist among those calls?

It makes 3^9 = 19683 calls. Only 55 different groups of neighbouring pieces exist, because a group is fixed by its first and last piece. The search solves each of the 55 groups about 358 times on average.

The correct method looks at the last merge of the whole array. That merge joins a left part and a right part, and each part is a run of neighbouring pieces. The search tries every cut position, solves both parts, and keeps the cheapest total. For n pieces the call count T(n) satisfies T(n) = 1 + 2 * (T(1) + ... + T(n - 1)), which gives T(n) = 3^(n - 1). This is O(3^n) time. For n = 30 it exceeds 10^13 calls.

The cost comes from repetition. A run of pieces from index l to index r appears inside many different cuts, and every appearance re-solves it from nothing. The answer for that run does not depend on how the pieces outside it were merged. Only n * (n + 1) / 2 different runs exist. If each run is solved once and stored, the work drops to O(n^3), because each of the O(n^2) runs tries at most n cuts. The next section shows what to store and in which order to fill it.

Key idea

Solve Every Run By Length

Treat each run of neighbouring pieces as its own small problem, and solve the short runs before the long ones. A run of length 2 needs only runs of length 1, a run of length 3 needs runs of length 1 and 2, and so on.

One Entry For Each Interval

An interval [l, r] is the pieces a[l] through a[r], inclusive. The interval table holds dp[l][r], the least cost to merge exactly that interval into one piece. The answer is dp[0][n - 1].

The Last Merge Fixes A Split Point

Every plan for [l, r] ends with one merge of a left piece and a right piece. The left piece is the merged result of [l, k] and the right piece is the merged result of [k + 1, r] for some split point k with l <= k < r. The final merge always costs the interval sum, a[l] + ... + a[r], whatever k is. The two parts are independent, so the best plan for each part can be chosen separately. Therefore dp[l][r] is the minimum over k of dp[l][k] + dp[k + 1][r], plus the interval sum.

One Piece Needs No Merge

An interval with one piece, l == r, is the base interval. It is already a single piece, so dp[l][l] = 0. The interval sum comes from prefix sums in constant time. The invariant is that dp[l][r] describes exactly the interval [l, r], and the recurrence reads only dp[l][k] and dp[k + 1][r], which are strictly shorter intervals. Filling the table by increasing length makes every read final.

State

The Table And Its Three Indexes

The input array stays unchanged, and these working values describe the computation.

  • prefix is an int[n + 1]; prefix[i] is the sum of the first i sizes, so the interval sum is prefix[r + 1] - prefix[l].
  • dp is an int[n][n]; entry dp[l][r] is the least merge cost of the interval from l to r, and only entries with l <= r are used.
  • len is the number of pieces in the interval, from 2 to n.
  • l and r are the first and last index of the interval, with r = l + len - 1.
  • k is the split point; the left part ends at k and the right part starts at k + 1.

Java fills a new int array with zeros, so every base interval already holds 0. The loop over len must be the outer loop. If l were the outer loop, dp[k + 1][r] would be read before it is final.

Code

Filling The Table By Length

The method returns the least total cost. It builds prefix sums first and then fills the table with the shortest intervals first.

static int mergeCost(int[] a) {
    int n = a.length;
    if (n < 2) return 0;
    int[] prefix = new int[n + 1];
    for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + a[i];
    int[][] dp = new int[n][n];
    for (int len = 2; len <= n; len++) {
        for (int l = 0; l + len <= n; l++) {
            int r = l + len - 1;
            int best = Integer.MAX_VALUE;
            for (int k = l; k < r; k++) {
                best = Math.min(best, dp[l][k] + dp[k + 1][r]);
            }
            dp[l][r] = best + prefix[r + 1] - prefix[l];
        }
    }
    return dp[0][n - 1];
}

Time grows as O(n^3), because there are O(n^2) intervals and each tries up to n split points. The table needs O(n^2) memory. An empty array and a single piece return 0 before any table exists. The exercises below change the cost of one merge, the shape of the table and the meaning of the split.

When to use it

Recognizing Problems Built On Intervals

Reading The Cue

Use this method when the pieces form a line, the final operation joins two contiguous parts, and the cost of the final operation depends only on the interval. Phrases such as "adjacent", "in order" and "the last one removed or merged" point here. The state is a pair of indexes, and each entry reads shorter intervals of the same line.

Checking The Invariant

The invariant says that dp[l][r] describes exactly the interval from l to r and reads only completed shorter intervals. Test a single piece, which must return 0. Test two pieces, which must return their sum. Test sizes that are all 0, which must return 0. Test a case where the cheapest first rule fails, such as the opening chunks, which must return 64.

Avoiding The False Friend

The first false friend is the cheapest first rule, which passes any test where the locally cheap merge is also globally cheap. The second is a table filled with l as the outer loop, which reads entries that are not final yet. The third is a table that adds the interval sum only at the top level, which undercounts the copies of inner pieces. The method does not apply when any two pieces may merge, not only neighbours, because an interval no longer captures the remaining problem. It also does not fit n above a few thousand, since O(n^3) time becomes too slow.

Basic

Best Split Of A Short Interval

Author exercise

Problem Specification. An array a of non-negative sizes and two indexes l and r are given. Return the least total cost to merge the pieces a[l] through a[r] into one piece. A merge of two neighbouring pieces costs their sum.

Input Constraints. The limits are:

  • Length satisfies 1 <= a.length <= 200.
  • Sizes satisfy 0 <= a[i] <= 1000.
  • Indexes satisfy 0 <= l <= r < a.length.
  • Mutation is not allowed, and the result is an int.

Example 1. Input a = [9, 7, 8, 8], l = 1, r = 3, output 38.

Example 2. Input a = [4, 1, 3, 5], l = 0, r = 2, output 12.

Prerequisites. The interval table from this lesson.

What This Exercise Changes. The table covers only the interval from l to r. The pieces outside it never enter any sum.

Hint

For a given split point, which two shorter intervals does the entry read, and what is added on top?

Algorithmic Solution (attempt the problem first)

Approach. The method builds prefix sums over the whole array, so the sum of any interval comes from two reads. It then fills dp[x][y] only for l <= x <= y <= r, by increasing interval length. A one-piece interval keeps the value 0 that Java writes into a new array. A longer interval takes the minimum of dp[x][k] + dp[k + 1][y] over every split point k, and adds the interval sum.

The invariant is that dp[x][y] describes exactly the pieces x through y, and it reads only intervals that are strictly shorter and lie inside [l, r]. Pieces outside the range never enter a read, so they never change the answer.

Complexity.

  • Time is O(L^3) for L = r - l + 1, because there are O(L^2) intervals and each tries up to L split points.
  • Space is O(n + L^2) for the prefix sums and the table, and the input array stays unchanged.
import java.util.*;

public final class IntervalShortSplit {
    /**
     * Returns the least cost to merge a[l..r] into one piece.
     * Time: O(L^3) with L = r - l + 1. Space: O(n + L^2).
     * Invariant: dp[x][y] reads only shorter intervals, which are final.
     */
    static int rangeMergeCost(int[] a, int l, int r) {
        // prefix[i] is the sum of the first i sizes, so an interval sum costs two reads.
        int[] prefix = new int[a.length + 1];
        // One pass builds all prefix sums in O(n).
        for (int i = 0; i < a.length; i++) prefix[i + 1] = prefix[i] + a[i];
        // The table is indexed by absolute positions; Java fills it with zeros, which is right for one-piece intervals.
        int[][] dp = new int[a.length][a.length];
        // The outer loop runs over interval length, so shorter intervals are final first.
        for (int len = 2; len <= r - l + 1; len++) {
            // The first index slides so that the interval stays inside [l, r].
            for (int x = l; x + len - 1 <= r; x++) {
                int y = x + len - 1;
                // best starts above any real cost, so the first split replaces it.
                int best = Integer.MAX_VALUE;
                // Each split point joins a left interval and a right interval.
                for (int k = x; k < y; k++) {
                    // The two parts are independent, so their best costs add.
                    best = Math.min(best, dp[x][k] + dp[k + 1][y]);
                }
                // The last merge always copies the whole interval once.
                dp[x][y] = best + prefix[y + 1] - prefix[x];
            }
        }
        // The entry for the full range holds the answer.
        return dp[l][r];
    }

    /** Oracle: tries every pair of neighbours to merge next, with no table. */
    static int oracle(List<Integer> pieces) {
        if (pieces.size() < 2) return 0;
        int best = Integer.MAX_VALUE;
        for (int i = 0; i + 1 < pieces.size(); i++) {
            List<Integer> next = new ArrayList<>(pieces);
            int sum = next.get(i) + next.get(i + 1);
            next.set(i, sum);
            next.remove(i + 1);
            best = Math.min(best, sum + oracle(next));
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (rangeMergeCost(new int[]{9, 7, 8, 8}, 1, 3) != 38) throw new AssertionError("ex1");
        if (rangeMergeCost(new int[]{4, 1, 3, 5}, 0, 2) != 12) throw new AssertionError("ex2");
        // The lesson array over its full range gives 64.
        if (rangeMergeCost(new int[]{9, 7, 8, 8}, 0, 3) != 64) throw new AssertionError("lesson");
        // A one-piece range costs 0, and a two-piece range costs the sum.
        if (rangeMergeCost(new int[]{5, 6, 7}, 1, 1) != 0) throw new AssertionError("single");
        if (rangeMergeCost(new int[]{5, 6, 7}, 1, 2) != 13) throw new AssertionError("pair");
        // A new Java int array holds zeros, which the base intervals rely on.
        int[][] fresh = new int[3][3];
        if (fresh[1][1] != 0 || fresh[0][2] != 0) throw new AssertionError("zero fill");
        // The input array is not changed by the call.
        int[] keep = {2, 9, 4, 4};
        int[] copy = keep.clone();
        rangeMergeCost(keep, 0, 3);
        if (!Arrays.equals(keep, copy)) throw new AssertionError("mutated");
        // Random subranges against the oracle that tries every neighbour pair.
        Random rnd = new Random(2901);
        for (int t = 0; t < 1500; t++) {
            int n = 1 + rnd.nextInt(7);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(10);
            int l = rnd.nextInt(n);
            int r = l + rnd.nextInt(n - l);
            List<Integer> sub = new ArrayList<>();
            for (int i = l; i <= r; i++) sub.add(a[i]);
            if (rangeMergeCost(a, l, r) != oracle(sub)) throw new AssertionError("random " + t);
        }
    }
}verified

Matrix Chain Cost

Author exercise

Problem Specification. An array dims of length n + 1 is given. Matrix i has dims[i] rows and dims[i + 1] columns, for 0 <= i < n. Multiplying a matrix of shape p x q by one of shape q x s costs p * q * s scalar multiplications. Return the least total cost to multiply all n matrices in order. Only the grouping may change.

Input Constraints. The limits are:

  • Length satisfies 1 <= dims.length <= 150, so n is at most 149.
  • Dimensions satisfy 1 <= dims[i] <= 100.
  • Result fits in an int, and n = 1 returns 0.
  • Mutation is not allowed.

Example 1. Input dims = [10, 30, 5, 60], output 4500.

Example 2. Input dims = [3, 8, 2, 9, 4], output 144.

Prerequisites. The exercise above.

What This Exercise Changes. The cost of the last merge is dims[l] * dims[k + 1] * dims[r + 1] and depends on the split point, so it moves inside the minimum.

Hint

When the matrices from l to r split after k, what shape does each side have, and what does the last multiplication cost?

Algorithmic Solution (attempt the problem first)

Approach. Matrix i has shape dims[i] x dims[i + 1]. For the matrices l through r, split after k means the left product has shape dims[l] x dims[k + 1] and the right product has shape dims[k + 1] x dims[r + 1]. The last multiplication therefore costs dims[l] * dims[k + 1] * dims[r + 1]. The entry dp[l][r] is the minimum over k of the two part costs plus that product.

The last multiplication cost depends on k, so it moves inside the minimum, unlike the interval sum in the lesson. The invariant is unchanged: dp[l][r] reads only shorter intervals. A single matrix needs no multiplication, so its entry is 0.

Complexity.

  • Time is O(n^3), because O(n^2) intervals each try up to n split points at constant cost.
  • Space is O(n^2) for the table, and dims stays unchanged.
import java.util.*;

public final class IntervalMatrixChain {
    /**
     * Returns the least scalar multiplications for the chain described by dims.
     * Time: O(n^3). Space: O(n^2).
     * Invariant: dp[l][r] reads only shorter intervals, which are final.
     */
    static int chainCost(int[] dims) {
        // n matrices need n + 1 dimensions.
        int n = dims.length - 1;
        // Zero or one matrix needs no multiplication.
        if (n < 2) return 0;
        // dp[l][r] is the least cost for matrices l through r; Java zeroes the single-matrix entries.
        int[][] dp = new int[n][n];
        // Interval length runs outward so shorter chains are final first.
        for (int len = 2; len <= n; len++) {
            // The first matrix slides across the valid starts, which costs n - len + 1 steps.
            for (int l = 0; l + len <= n; l++) {
                int r = l + len - 1;
                int best = Integer.MAX_VALUE;
                // The split point k decides the shapes of both products.
                for (int k = l; k < r; k++) {
                    // The last multiplication costs rows of the left, the shared size and columns of the right.
                    int cost = dp[l][k] + dp[k + 1][r] + dims[l] * dims[k + 1] * dims[r + 1];
                    // Keep the cheapest split.
                    best = Math.min(best, cost);
                }
                dp[l][r] = best;
            }
        }
        // The whole chain is the interval from 0 to n - 1.
        return dp[0][n - 1];
    }

    /** Oracle: multiplies any adjacent pair next, using shape lists and no table. */
    static int oracle(List<Integer> d) {
        if (d.size() < 3) return 0;
        int best = Integer.MAX_VALUE;
        for (int i = 1; i + 1 < d.size(); i++) {
            // Multiplying the matrices around dimension i removes that dimension.
            int cost = d.get(i - 1) * d.get(i) * d.get(i + 1);
            List<Integer> next = new ArrayList<>(d);
            next.remove(i);
            best = Math.min(best, cost + oracle(next));
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (chainCost(new int[]{10, 30, 5, 60}) != 4500) throw new AssertionError("ex1");
        if (chainCost(new int[]{3, 8, 2, 9, 4}) != 144) throw new AssertionError("ex2");
        // One matrix and one dimension pair give 0, and two matrices give one product.
        if (chainCost(new int[]{7, 2}) != 0) throw new AssertionError("single");
        if (chainCost(new int[]{4, 5, 6}) != 120) throw new AssertionError("pair");
        // A single dimension is legal input and describes no matrix.
        if (chainCost(new int[]{6}) != 0) throw new AssertionError("none");
        // The input array is not changed by the call.
        int[] keep = {5, 2, 8, 3};
        int[] copy = keep.clone();
        chainCost(keep);
        if (!Arrays.equals(keep, copy)) throw new AssertionError("mutated");
        // Random chains against the oracle that tries every adjacent product.
        Random rnd = new Random(2902);
        for (int t = 0; t < 1500; t++) {
            int len = 1 + rnd.nextInt(8);
            int[] d = new int[len];
            List<Integer> list = new ArrayList<>();
            for (int i = 0; i < len; i++) {
                d[i] = 1 + rnd.nextInt(9);
                list.add(d[i]);
            }
            if (chainCost(d) != oracle(list)) throw new AssertionError("random " + t);
        }
    }
}verified
Edge Cases

Empty And Singleton Intervals

Author exercise

Problem Specification. An array a of non-negative sizes is given, and it may be empty. Return the least total cost to merge all pieces into one piece, where a merge of two neighbouring pieces costs their sum. An array of zero or one piece needs no merge and costs 0.

Input Constraints. The limits are:

  • Length satisfies 0 <= a.length <= 300.
  • Sizes satisfy 0 <= a[i] <= 100.
  • Result is an int.
  • Mutation is not allowed.

Example 1. Input a = [], output 0.

Example 2. Input a = [3, 1, 2], output 9.

Prerequisites. The two exercises above.

What This Exercise Changes. The answer must exist for length 0 and length 1, where the table has no interval to fill. The method returns the neutral value 0 directly.

Hint

Which intervals hold 0 before any split is tried, and what would dp[0][n - 1] mean for an empty array?

Algorithmic Solution (attempt the problem first)

Approach. An interval of length 0 or 1 has no merge to perform, so the method returns 0 for a.length < 2 before it allocates any table. This also protects the final read dp[0][n - 1], which would use index -1 for an empty array. For longer arrays the method uses the standard table, with prefix sums of length n + 1 and entries filled by increasing interval length.

The invariant is that every base entry is 0 when a longer interval reads it, and no read touches an entry of equal or greater length. The neutral value is correct because adding a one-piece interval to a split contributes no copying.

Complexity.

  • Time is O(n^3) for n pieces, and O(1) when n is 0 or 1.
  • Space is O(n^2) for the table, and the input array stays unchanged.
import java.util.*;

public final class IntervalEmptySingleton {
    /**
     * Returns the least merge cost of the whole array, and 0 for fewer than two pieces.
     * Time: O(n^3), or O(1) below two pieces. Space: O(n^2).
     * Invariant: base entries are 0 before any longer interval reads them.
     */
    static int wholeCost(int[] a) {
        int n = a.length;
        // With no merge to make, the neutral cost is 0 and the table is never built.
        if (n < 2) return 0;
        // prefix has n + 1 entries, so prefix[0] = 0 covers an interval that starts at index 0.
        int[] prefix = new int[n + 1];
        for (int i = 0; i < n; i++) prefix[i + 1] = prefix[i] + a[i];
        // Java zeroes the diagonal, which holds the one-piece intervals.
        int[][] dp = new int[n][n];
        // Length 2 is the first length that needs a merge.
        for (int len = 2; len <= n; len++) {
            for (int l = 0; l + len <= n; l++) {
                int r = l + len - 1;
                int best = Integer.MAX_VALUE;
                // Every split point reads two shorter intervals.
                for (int k = l; k < r; k++) best = Math.min(best, dp[l][k] + dp[k + 1][r]);
                // Add the interval sum for the last merge.
                dp[l][r] = best + prefix[r + 1] - prefix[l];
            }
        }
        // The corner interval is the whole array.
        return dp[0][n - 1];
    }

    /** Oracle: tries every neighbour pair as the next merge. */
    static int oracle(List<Integer> pieces) {
        if (pieces.size() < 2) return 0;
        int best = Integer.MAX_VALUE;
        for (int i = 0; i + 1 < pieces.size(); i++) {
            List<Integer> next = new ArrayList<>(pieces);
            int sum = next.get(i) + next.get(i + 1);
            next.set(i, sum);
            next.remove(i + 1);
            best = Math.min(best, sum + oracle(next));
        }
        return best;
    }

Burst Balloons

LeetCode 312

Problem Specification. An array nums of n balloon values is given. Bursting balloon i earns left * nums[i] * right, where left and right are the values of its nearest unburst neighbours. A missing neighbour counts as 1. Return the largest total coins from bursting all balloons in the best order.

Input Constraints. The limits are:

  • Length satisfies 0 <= nums.length <= 300.
  • Values satisfy 0 <= nums[i] <= 100.
  • Result fits in an int.
  • Mutation is not allowed.

Example 1. Input nums = [2, 4, 3], output 33.

Example 2. Input nums = [5, 1, 6, 2], output 105.

Prerequisites. All three exercises above.

What This Exercise Changes. The split is the last balloon removed from an open interval, not the last merge. Its neighbours are the fixed boundary values, so the two sides stay independent.

Hint

Choose the balloon that bursts last inside an interval. Which neighbours does it see at that moment?

Algorithmic Solution (attempt the problem first)

Approach. Choosing the first balloon to burst fails, because its removal changes the neighbours of the others and the two sides depend on each other. Choosing the last balloon removed in an open interval fixes this. The method pads the values with a 1 on each side, so v[0] = 1 and v[n + 1] = 1. The entry dp[l][r] is the most coins from bursting every balloon strictly between positions l and r.

If balloon k bursts last in that open interval, its neighbours at that moment are v[l] and v[r], because everything else between them is gone. The two sides (l, k) and (k, r) then never affect each other. So dp[l][r] is the maximum over k of dp[l][k] + dp[k][r] + v[l] * v[k] * v[r]. An open interval with no balloon inside, where r = l + 1, is worth 0.

The invariant is that dp[l][r] reads only open intervals that are strictly shorter. The answer is dp[0][n + 1].

Complexity.

  • Time is O(n^3), because O(n^2) open intervals each try up to n last balloons.
  • Space is O(n^2) for the table and O(n) for the padded array, and nums stays unchanged.
import java.util.*;

public final class IntervalBurstBalloons {
    /**
     * Returns the most coins from bursting every balloon.
     * Time: O(n^3). Space: O(n^2).
     * Invariant: dp[l][r] covers the balloons strictly between l and r and reads shorter gaps.
     */
    static int maxCoins(int[] nums) {
        int n = nums.length;
        // The padded array has a boundary value 1 at both ends, so a missing neighbour counts as 1.
        int[] v = new int[n + 2];
        v[0] = 1;
        v[n + 1] = 1;
        // Copy the values into the middle so the input array stays unchanged.
        for (int i = 0; i < n; i++) v[i + 1] = nums[i];
        // Java zeroes the table, which is right for an empty gap with r = l + 1.
        int[][] dp = new int[n + 2][n + 2];
        // gap is r - l, and gap 2 is the first gap with a balloon inside.
        for (int gap = 2; gap <= n + 1; gap++) {
            // l slides so that r stays within the padded array.
            for (int l = 0; l + gap <= n + 1; l++) {
                int r = l + gap;
                int best = 0;
                // k is the balloon that bursts last inside the open gap.
                for (int k = l + 1; k < r; k++) {
                    // At that moment its neighbours are the gap boundaries v[l] and v[r].
                    int coins = dp[l][k] + dp[k][r] + v[l] * v[k] * v[r];
                    // Keep the largest total.
                    if (coins > best) best = coins;
                }
                dp[l][r] = best;
            }
        }
        // The widest gap holds every real balloon.
        return dp[0][n + 1];
    }

    /** Oracle: tries every burst order by removing one balloon at a time. */
    static int oracle(List<Integer> balloons) {
        int best = 0;
        for (int i = 0; i < balloons.size(); i++) {
            int left = i == 0 ? 1 : balloons.get(i - 1);
            int right = i + 1 == balloons.size() ? 1 : balloons.get(i + 1);
            List<Integer> next = new ArrayList<>(balloons);
            int value = next.remove(i);
            best = Math.max(best, left * value * right + oracle(next));
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (maxCoins(new int[]{2, 4, 3}) != 33) throw new AssertionError("ex1");
        if (maxCoins(new int[]{5, 1, 6, 2}) != 105) throw new AssertionError("ex2");
        // The empty array earns 0, and one balloon earns its own value.
        if (maxCoins(new int[]{}) != 0) throw new AssertionError("empty");
        if (maxCoins(new int[]{9}) != 9) throw new AssertionError("single");
        // Zero values are legal and earn nothing when they are the product.
        if (maxCoins(new int[]{0, 0}) != 0) throw new AssertionError("zeros");
        // The input array is not changed by the call.
        int[] keep = {3, 1, 5, 8};
        int[] copy = keep.clone();
        maxCoins(keep);
        if (!Arrays.equals(keep, copy)) throw new AssertionError("mutated");
        // Random arrays against the oracle that tries every burst order.
        Random rnd = new Random(2904);
        for (int t = 0; t < 1500; t++) {
            int n = rnd.nextInt(8);
            int[] a = new int[n];
            List<Integer> list = new ArrayList<>();
            for (int i = 0; i < n; i++) {
                a[i] = rnd.nextInt(10);
                list.add(a[i]);
            }
            if (maxCoins(a) != oracle(list)) throw new AssertionError("random " + t);
        }
    }

Problem

Splitting A String Into Mirror Segments

A text-analysis tool reports how a string decomposes into segments that read the same forward and backward. The product rule says to report the fewest segments. For the input aaba, the best report has 2 segments, a and aba. The tool needs one cut between them.

A developer writes a quick rule. It repeatedly removes the longest segment at the front that reads the same in both directions. On aaba it removes aa, then b, then a. The rule reports 3 segments, one more than the best answer, because aa hides the longer segment aba that starts one character later.

Formally, the input is a string s. A palindrome is a string equal to its own reverse. A partition splits s into consecutive pieces, and every piece must be a palindrome. A cut is a boundary between two neighbouring pieces, so a partition with p pieces uses p - 1 cuts. The task is to return the fewest cuts over all partitions. The string never changes.

This lesson asks how to find that count when the choice at the front of the string changes what remains possible.

Simple approach

Trying Every Set Of Cuts

The safe idea is to try every way to place cuts. A string of length n has n - 1 gaps between characters, and each gap either holds a cut or does not. The method below reads each subset of gaps from the bits of a number, checks every resulting piece, and keeps the smallest valid count.

static int bruteCuts(String s) {
    int n = s.length();
    if (n == 0) return 0;
    int best = n - 1;
    for (int mask = 0; mask < (1 << (n - 1)); mask++) {
        int start = 0;
        int cuts = 0;
        boolean valid = true;
        for (int k = 0; k < n && valid; k++) {
            boolean pieceEnds = k == n - 1 || ((mask >> k) & 1) == 1;
            if (!pieceEnds) continue;
            int lo = start;
            int hi = k;
            while (lo < hi && s.charAt(lo) == s.charAt(hi)) { lo++; hi--; }
            if (lo < hi) valid = false;
            start = k + 1;
            if (k < n - 1) cuts++;
        }
        if (valid) best = Math.min(best, cuts);
    }
    return best;
}

There are 2^(n - 1) masks, and each one costs O(n) time to check its pieces. The total is O(2^n * n) time with O(1) extra memory. The method always returns the right answer, but the time doubles with every added character.

Predict first: A string has 30 characters. How many different sets of cuts does the method above examine?

It examines 2^29, which is 536,870,912 sets. Each set also needs a scan of the whole string, so the work reaches about 1.6 * 10^10 character comparisons.

Bottleneck

The Same Work Repeats Many Times

The method is slow because it repeats two kinds of work. Both repeats come from decisions that do not depend on each other.

Checking The Same Substring Again

Take the substring s[2..5]. Every mask that places cuts exactly before index 2 and after index 5 re-reads those four characters and decides again whether they form a palindrome. That count grows as 2^(n - 5) for a fixed substring. A string of length n has only n * (n + 1) / 2 substrings, so the same few answers are recomputed an enormous number of times. Checking each substring once costs O(n) per substring and O(n^3) in total, and a better order brings that down to O(n^2).

Solving The Same Remaining Text Again

Two different sets of cuts can agree on the first end characters of the string. Both then face the same question about the remaining text, and the method answers it from scratch each time. The number of distinct prefixes is only n + 1. If the best piece count for each prefix is stored, each prefix needs one pass over its possible starting points, which costs O(n) per prefix and O(n^2) in total.

The next section removes both repeats. It stores palindrome answers in a table and stores best piece counts for prefixes in an array.

Key idea

Store Palindromes, Then Count Pieces

Two small tables replace the search over cuts. The first table answers "is this substring a palindrome" in constant time. The second table uses the first one to count pieces for every prefix.

One Entry For Each Substring

The palindrome table is a boolean array pal[i][j] for 0 <= i <= j < n. Entry pal[i][j] is true exactly when s[i..j] is a palindrome. A single character is always a palindrome, so every entry with i == j is true.

Equal Ends Depend On The Inner Interval

A substring with i < j is a palindrome when its two end characters are equal and the characters between them also form a palindrome. The characters between them are the inner interval s[i + 1..j - 1]. If the two ends are equal and the inner interval is empty, as for aa, the substring is a palindrome. If the inner interval holds one or more characters, the entry equals pal[i + 1][j - 1]. That entry has a larger i and a smaller j, so the loop must visit i from the end of the string down to 0 and j from i upward. Then the inner interval is final before the outer entry reads it.

Count Pieces For Each Prefix

Let pieces[end] be the fewest pieces in a partition of the first end characters. The empty prefix needs 0 pieces, so pieces[0] = 0. Consider any partition of the prefix and look at its last piece, which is s[start..end - 1] for some start from 0 to end - 1. The last piece must be a palindrome, and the characters before it form a partition of the shorter prefix of length start. The best choice is therefore pieces[start] + 1, minimized over every start with pal[start][end - 1] true.

Convert Pieces To Cuts

The answer for the whole string is pieces[n] - 1, because p pieces use p - 1 cuts. The invariant is that pieces[start] is final before pieces[end] reads it, since start < end, and that every entry of pal read here is final after the first loop. An empty string has no pieces and no cuts, so the method returns 0 for it in place of the value -1.

State

Two Tables And Their Indexes

The string comes in unchanged, and these working values describe both tables.

  • pal is a boolean[n][n]; entry pal[i][j] is true when s[i..j], both ends included, is a palindrome.
  • pieces is an int[n + 1]; entry pieces[end] is the fewest palindromic pieces that cover the first end characters.
  • i and j are the first and last index of a substring while the palindrome table is filled.
  • start is the first index of the last piece, so the piece is s[start..end - 1].
  • end is the prefix length, from 1 to n, and end - 1 is the index of the last character of the prefix.

Java fills a new boolean array with false, so entries that the loop never sets stay false. The loop sets pal[i][j] only for i <= j. The second loop reads pal[start][end - 1] with start <= end - 1, which stays inside the filled part.

Walkthrough

Two Runs Of The Method

Filling The Palindrome Table

The first run uses s = "aaba" from the opening. The table has 4 rows and 4 columns, and the cells below list them row by row, so cell 0 to 3 is row 0, cell 4 to 7 is row 1, and so on. The pointer cell marks the entry in progress, and only the entries with i <= j are visited. The variable ends says whether the two end characters match, inner shows the entry for the inner interval, and pal is the value written.

Row 3 and row 2 hold single characters and the pair ba. Row 1 is the useful one. The pair aa has equal ends and an empty inner interval, so it is true. The substring aba has equal ends, and its inner interval is the single character b, which is true, so aba is true. Row 0 then finds that aaba has equal ends, but its inner interval ab is false, so the whole string is not a palindrome. The table holds 6 true entries.

Counting Pieces For Each Prefix

The second run reads the table from the first run and fills pieces for the same string. Two pointers mark the characters. The pointer start marks the first character of the candidate last piece, and the pointer end marks the last character of the prefix. Each step tests one candidate piece. A palindromic piece proposes pieces[start] + 1, and the array keeps the smaller value.

Prefix length 2 shows the choice. The piece aa starts at 0 and gives 1 piece. The piece a starts at 1 and would give 2, so the array keeps 1. Prefix length 4 tests aaba, aba, ba and a. The piece aba starts at 1, where pieces[1] is 1, so it gives 2. The piece a gives 3, which loses. The final value is 2 pieces, so the method returns 1 cut.

Code

Table First, Then Prefix Counts

The method returns the fewest cuts. The first pair of loops fills pal from the last row upward. The second pair fills pieces from short prefixes to long ones.

static int minCuts(String s) {
    int n = s.length();
    if (n == 0) return 0;
    boolean[][] pal = new boolean[n][n];
    for (int i = n - 1; i >= 0; i--) {
        for (int j = i; j < n; j++) {
            boolean innerOk = j - i < 2 || pal[i + 1][j - 1];
            pal[i][j] = s.charAt(i) == s.charAt(j) && innerOk;
        }
    }
    int[] pieces = new int[n + 1];
    for (int end = 1; end <= n; end++) {
        pieces[end] = Integer.MAX_VALUE;
        for (int start = 0; start < end; start++) {
            if (pal[start][end - 1] && pieces[start] + 1 < pieces[end]) {
                pieces[end] = pieces[start] + 1;
            }
        }
    }
    return pieces[n] - 1;
}

Both parts take O(n^2) time, and the two tables need O(n^2) memory. The sentinel Integer.MAX_VALUE is safe, because start = end - 1 always finds a one-character palindrome and pieces[start] is already finite. For an empty string the early return gives 0 in place of -1. The exercises below change the rule for a valid piece, the value stored per prefix and the memory used.

When to use it

Recognizing Cost Tied To Valid Substrings

Reading The Cue

Use this method when a string splits into consecutive pieces, a yes-or-no rule judges each piece by its own characters, and the goal counts or minimizes the pieces. Phrases such as "every piece must be" and "fewest cuts" point here. The rule must depend only on the piece and not on its neighbours.

Checking The Invariant

The invariant says that pal is final before the prefix loop starts, and that pieces[start] is final before pieces[end] reads it. Test a single character, which needs 0 cuts. Test a whole-string palindrome, which also needs 0 cuts. Test a string with no repeated neighbours, such as abcd, which needs n - 1 cuts. Test the empty string, which must return 0.

Avoiding The False Friend

The first false friend is the longest-prefix rule from the opening, which passes any input where the longest palindrome at the front is also part of a best partition. The second false friend is a longest palindromic substring search, which finds one piece and says nothing about how the rest splits. The third is a table fill that visits i upward, so pal[i + 1][j - 1] is still false when read. The method does not apply when the validity of a piece depends on the pieces next to it, because pieces[start] then no longer summarizes the earlier text.

Algorithmic Solution (attempt the problem first)

Approach. The table pal has one row and one column for each index of s. Entry pal[i][j] is true when the substring from i to j is a palindrome. A substring of one or two characters needs only equal end characters. A longer substring needs equal end characters and a true entry for the inner interval, pal[i + 1][j - 1]. The method visits i from the last index down to 0 and j from i upward, so the inner entry is final when the outer entry reads it. The method counts the true entries as it sets them.

The invariant is that every entry read by (i, j) belongs to a row below i or to the same row and was set earlier. An empty string has no rows, so the count stays 0.

Complexity.

  • Time is O(n^2), because the loops visit n * (n + 1) / 2 entries and each costs constant work.

import java.util.*;

public final class PpPalindromeTable {
    /**
     * Counts the index pairs (i, j) whose substring is a palindrome.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: pal[i + 1][j - 1] is final before pal[i][j] reads it.
     */
    static int countPalindromes(String s) {
        // n is the string length, and the table has n rows and n columns.
        int n = s.length();
        boolean[][] pal = new boolean[n][n];
        int count = 0;
        // Rows run from the last index upward, so the row below is complete.
        for (int i = n - 1; i >= 0; i--) {
            // Columns start at i, because a substring needs i <= j.
            for (int j = i; j < n; j++) {
                // A substring of length 1 or 2 has an empty inner interval.
                boolean innerOk = j - i < 2 || pal[i + 1][j - 1];
                // Equal end characters and a valid inner interval make a palindrome.
                pal[i][j] = s.charAt(i) == s.charAt(j) && innerOk;
                // Each true entry adds one to the count.
                if (pal[i][j]) count++;
            }
        }
        // The count covers every pair with i <= j.
        return count;
    }

    /** Oracle: reverses every substring and compares it with the original. */
    static int oracle(String s) {
        int count = 0;
        for (int i = 0; i < s.length(); i++) {
            for (int j = i; j < s.length(); j++) {
                String t = s.substring(i, j + 1);
                if (new StringBuilder(t).reverse().toString().equals(t)) count++;
            }
        }
        return count;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (countPalindromes("aaba") != 6) throw new AssertionError("ex1");
        if (countPalindromes("abcba") != 7) throw new AssertionError("ex2");
        // The empty string, one character, equal characters and distinct characters.
        if (countPalindromes("") != 0) throw new AssertionError("empty");
        if (countPalindromes("a") != 1) throw new AssertionError("single");
        if (countPalindromes("aaaa") != 10) throw new AssertionError("equal");
        if (countPalindromes("abcd") != 4) throw new AssertionError("distinct");
        // A new boolean array holds false, and substring excludes its end index.
        boolean[][] fresh = new boolean[2][2];
        if (fresh[0][1]) throw new AssertionError("false fill");
        if (!"abc".substring(0, 2).equals("ab")) throw new AssertionError("substring");
        // Strings are immutable, so the input keeps its content.
        String s = "abba";
        countPalindromes(s);
        if (!s.equals("abba")) throw new AssertionError("mutated");
        // Random strings against the reversal oracle.
        Random rnd = new Random(2921);
        for (int t = 0; t < 2000; t++) {
            String w = word(rnd, rnd.nextInt(12), 3);
            if (countPalindromes(w) != oracle(w)) throw new AssertionError("random " + t);
        }
    }

    static String word(Random rnd, int len, int alphabet) {
        StringBuilder s = new StringBuilder();
        for (int k = 0; k < len; k++) s.append((char) ('a' + rnd.nextInt(alphabet)));
        return s.toString();
    }

Minimum Valid Prefix Pieces

Author exercise

Problem Specification. A string s and an integer k are given. A piece is valid when it is a palindrome and has at least k characters. Split s into consecutive valid pieces and return the smallest number of pieces. Return -1 if no such split exists.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 500.
  • Minimum piece length satisfies 1 <= k <= s.length().
  • Characters are lowercase English letters.
  • Result is an int, and -1 marks an impossible split.

Example 1. Input s = "aabbcc", k = 2, output 3.

Example 2. Input s = "racecarbob", k = 3, output 2.

Prerequisites. The exercise above.

What This Exercise Changes. The validity rule gains a length limit, so some prefixes have no split. The array needs an explicit value for unreachable prefixes, and the transition must skip them.

Hint

For each prefix, try every earlier cut. Which cuts are allowed, and what value marks a prefix that no split reaches?

Algorithmic Solution (attempt the problem first)

Approach. The method fills the palindrome table first. It then defines pieces[end] as the fewest valid pieces that cover the first end characters, with pieces[0] = 0. For each end, it tries every start below end. A start is allowed when the piece s[start..end - 1] is a palindrome, has at least k characters, and pieces[start] is reachable. Unreachable prefixes hold a large sentinel, and the transition skips them. A reachable value plus 1 never overflows, because the method adds 1 only to reachable values.

The invariant is that pieces[start] is final before pieces[end] reads it, and the sentinel marks exactly the prefixes with no valid split. The method returns -1 when pieces[n] is still the sentinel.

Complexity.

  • Time is O(n^2), because the table fill and the prefix loops each visit O(n^2) pairs.
  • Space is O(n^2) for the table plus O(n) for pieces.
import java.util.*;

public final class PpValidPrefixPieces {
    /**
     * Returns the fewest palindromic pieces of length at least k, or -1 if no split exists.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: pieces[start] is final before pieces[end] reads it.
     */
    static int minPieces(String s, int k) {
        int n = s.length();
        boolean[][] pal = new boolean[n][n];
        // Rows run upward so the inner interval is final when read.
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                pal[i][j] = s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1]);
            }
        }
        // The sentinel marks a prefix that no valid split reaches.
        final int unreachable = Integer.MAX_VALUE;
        int[] pieces = new int[n + 1];
        Arrays.fill(pieces, unreachable);
        // The empty prefix needs 0 pieces.
        pieces[0] = 0;
        // end is the prefix length, so each pass finishes one entry.
        for (int end = 1; end <= n; end++) {
            // start is the first index of the last piece.
            for (int start = 0; start < end; start++) {
                // The piece must be long enough, a palindrome, and attached to a reachable prefix.
                if (end - start >= k && pal[start][end - 1] && pieces[start] != unreachable) {
                    pieces[end] = Math.min(pieces[end], pieces[start] + 1);
                }
            }
        }
        // An untouched sentinel means no split exists.
        return pieces[n] == unreachable ? -1 : pieces[n];
    }

    /** Oracle: tries every set of cut positions and checks each piece directly. */
    static int oracle(String s, int k) {
        int n = s.length();
        int best = -1;
        for (int mask = 0; mask < (1 << (n - 1)); mask++) {
            int start = 0;
            int count = 0;
            boolean valid = true;
            for (int p = 0; p < n && valid; p++) {
                if (p == n - 1 || ((mask >> p) & 1) == 1) {
                    String t = s.substring(start, p + 1);
                    if (t.length() < k || !new StringBuilder(t).reverse().toString().equals(t)) valid = false;
                    count++;
                    start = p + 1;
                }
            }
            if (valid && (best == -1 || count < best)) best = count;
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minPieces("aabbcc", 2) != 3) throw new AssertionError("ex1");
        if (minPieces("racecarbob", 3) != 2) throw new AssertionError("ex2");
        // A limit that no split can meet, and a limit of 1 that reduces to the plain count.
        if (minPieces("aabbcc", 3) != -1) throw new AssertionError("impossible");

Empty Prefix And Whole Palindrome

Author exercise

Problem Specification. A string s is given. Return an int array r of length s.length() + 1. Entry r[e] is the fewest cuts in a palindrome partition of the first e characters of s.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 500, and the string may be empty.
  • Characters are lowercase English letters.
  • Entry zero equals 0, because the empty prefix needs no cuts.
  • Mutation is not allowed, because strings are immutable.

Example 1. Input s = "", output [0].

Example 2. Input s = "abcba", output [0, 0, 1, 2, 1, 0].

Prerequisites. The two exercises above.

What This Exercise Changes. The method reports every prefix, not only the whole string. The empty prefix and every palindromic prefix must give 0, so the subtraction needs a guard.

Hint

Piece counts and cut counts differ by one. Which prefix would give -1 if the method subtracted blindly?

Algorithmic Solution (attempt the problem first)

Approach. The method fills the palindrome table, then fills pieces[end] for every prefix length, with pieces[0] = 0. The cut count of a prefix is pieces[end] - 1, except for the empty prefix, where the subtraction would give -1. The method therefore writes 0 into r[0] directly and writes pieces[end] - 1 for each end from 1. A palindromic prefix has pieces[end] = 1, which gives 0 cuts.

The invariant is that r[end] reads only a finished pieces[end], and that the guard covers exactly the one prefix with zero pieces. An empty string returns the array [0].

Complexity.

  • Time is O(n^2), because the table fill and the prefix loops each visit O(n^2) pairs.
  • Space is O(n^2) for the table, and the result has n + 1 entries.
import java.util.*;

public final class PpEmptyPrefix {
    /**
     * Returns the fewest palindrome cuts for every prefix length from 0 to n.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: r[end] is read from a finished pieces[end], and r[0] is fixed at 0.
     */
    static int[] cutsPerPrefix(String s) {
        int n = s.length();
        boolean[][] pal = new boolean[n][n];
        // Rows run upward so the inner interval is final when read.
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                pal[i][j] = s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1]);
            }
        }
        int[] pieces = new int[n + 1];
        int[] r = new int[n + 1];
        // The empty prefix keeps pieces 0 and cuts 0, so no subtraction runs for it.
        for (int end = 1; end <= n; end++) {
            pieces[end] = Integer.MAX_VALUE;
            // Each start gives a candidate last piece.
            for (int start = 0; start < end; start++) {
                if (pal[start][end - 1] && pieces[start] + 1 < pieces[end]) pieces[end] = pieces[start] + 1;
            }
            // p pieces use p - 1 cuts, which is valid because end >= 1 gives pieces[end] >= 1.
            r[end] = pieces[end] - 1;
        }
        return r;
    }

    /** Oracle: for each prefix, tries every set of cut positions with direct palindrome checks. */
    static int[] oracle(String s) {
        int[] r = new int[s.length() + 1];
        for (int e = 1; e <= s.length(); e++) {
            String p = s.substring(0, e);
            int best = e - 1;
            for (int mask = 0; mask < (1 << (e - 1)); mask++) {
                int start = 0;
                int cuts = 0;
                boolean valid = true;
                for (int q = 0; q < e && valid; q++) {
                    if (q == e - 1 || ((mask >> q) & 1) == 1) {
                        String t = p.substring(start, q + 1);
                        if (!new StringBuilder(t).reverse().toString().equals(t)) valid = false;
                        if (q < e - 1) cuts++;
                        start = q + 1;
                    }
                }
                if (valid) best = Math.min(best, cuts);
            }
            r[e] = best;
        }
        return r;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(cutsPerPrefix(""), new int[] {0})) throw new AssertionError("ex1");
        if (!Arrays.equals(cutsPerPrefix("abcba"), new int[] {0, 0, 1, 2, 1, 0})) throw new AssertionError("ex2");
        // A whole palindrome ends with 0, and distinct characters grow by one per prefix.
        if (cutsPerPrefix("aaaa")[4] != 0) throw new AssertionError("whole");
        if (!Arrays.equals(cutsPerPrefix("abcd"), new int[] {0, 0, 1, 2, 3})) throw new AssertionError("distinct");
        // A new int array holds zeros, so entry 0 of a one-character result is 0 and entry 1 is 0.
        int[] z = new int[3];
        if (z[2] != 0) throw new AssertionError("zero fill");
        if (cutsPerPrefix("a")[0] != 0) throw new AssertionError("entry zero");
        // Random strings against the cut-set oracle.
        Random rnd = new Random(2923);
        for (int t = 0; t < 1500; t++) {
            String w = word(rnd, rnd.nextInt(11), 3);
            if (!Arrays.equals(cutsPerPrefix(w), oracle(w))) throw new AssertionError("random " + t + " " + w);
        }
    }

    static String word(Random rnd, int len, int alphabet) {
        StringBuilder s = new StringBuilder();
        for (int k = 0; k < len; k++) s.append((char) ('a' + rnd.nextInt(alphabet)));
        return s.toString();
    }

Problem Specification. A string s is given. Split s into substrings so that each substring is a palindrome. Return the smallest number of cuts that makes this possible.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 2000.
  • Characters are lowercase English letters.
  • Result is an int, and 0 means s is already a palindrome.
  • Mutation is not allowed, because strings are immutable.

Example 1. Input s = "abbab", output 1.

Example 2. Input s = "cabbad", output 2.

Prerequisites. All three exercises above.

What This Exercise Changes. The length limit of 2000 makes a full boolean table expensive. The solution keeps only an array of cut counts and finds palindromes by growing them from each center.

Hint

The cost of a piece depends on whether it is a palindrome. Can a second loop produce the validity answers while the cut counts fill?

Algorithmic Solution (attempt the problem first)

Approach. The method keeps only cuts, where cuts[e] is the fewest cuts for the first e characters, with cuts[0] = -1 so that a prefix that is one whole palindrome costs -1 + 1 = 0. Each entry starts at its worst case, e - 1. Instead of a boolean table, the method grows a palindrome from every center. For an odd center c it starts at l = r = c, and for an even center it starts at l = c, r = c + 1. Each palindrome s[l..r] offers cuts[l] + 1 to cuts[r + 1], and the method keeps the smaller value.

The invariant is that cuts[l] is final when a palindrome starting at l reads it. Every palindrome that ends at index l - 1 has a center left of c, so the earlier centers already updated cuts[l]. The answer is cuts[n].

Complexity.

  • Time is O(n^2), because each of the 2n - 1 centers grows over at most n characters.
  • Space is O(n) for the cuts array, with no boolean table.
import java.util.*;

public final class PpMinCuts {
    /**
     * Returns the fewest cuts that split s into palindromes.
     * Time: O(n^2). Space: O(n).
     * Invariant: cuts[l] is final before a palindrome that starts at l uses it.
     */
    static int minCut(String s) {
        int n = s.length();
        int[] cuts = new int[n + 1];
        // Prefix length e needs at most e - 1 cuts, and the empty prefix holds -1.
        for (int e = 0; e <= n; e++) cuts[e] = e - 1;
        // Centers run from left to right, so earlier centers finish first.
        for (int c = 0; c < n; c++) {
            // Odd length: the palindrome grows around the single character c.
            for (int l = c, r = c; l >= 0 && r < n && s.charAt(l) == s.charAt(r); l--, r++) {
                // The palindrome s[l..r] ends the prefix of length r + 1 after the prefix of length l.
                cuts[r + 1] = Math.min(cuts[r + 1], cuts[l] + 1);
            }
            // Even length: the palindrome grows around the gap between c and c + 1.
            for (int l = c, r = c + 1; l >= 0 && r < n && s.charAt(l) == s.charAt(r); l--, r++) {
                cuts[r + 1] = Math.min(cuts[r + 1], cuts[l] + 1);
            }
        }
        // The last entry covers the whole string.
        return cuts[n];
    }

    /** Oracle: tries every set of cut positions and checks each piece directly. */
    static int oracle(String s) {
        int n = s.length();
        int best = n - 1;
        for (int mask = 0; mask < (1 << (n - 1)); mask++) {
            int start = 0;
            int cuts = 0;
            boolean valid = true;
            for (int q = 0; q < n && valid; q++) {
                if (q == n - 1 || ((mask >> q) & 1) == 1) {
                    String t = s.substring(start, q + 1);
                    if (!new StringBuilder(t).reverse().toString().equals(t)) valid = false;
                    if (q < n - 1) cuts++;
                    start = q + 1;
                }
            }
            if (valid) best = Math.min(best, cuts);
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minCut("abbab") != 1) throw new AssertionError("ex1");
        if (minCut("cabbad") != 2) throw new AssertionError("ex2");
        // One character, a whole palindrome, distinct characters and the lesson string.
        if (minCut("a") != 0) throw new AssertionError("single");
        if (minCut("abcba") != 0) throw new AssertionError("whole");
        if (minCut("abcd") != 3) throw new AssertionError("distinct");
        if (minCut("aaba") != 1) throw new AssertionError("lesson");
        // A long string of equal characters finishes without a cut and without a table.
        if (minCut("a".repeat(2000)) != 0) throw new AssertionError("long");
        // Random strings against the cut-set oracle.
        Random rnd = new Random(2924);
        for (int t = 0; t < 2000; t++) {
            String w = word(rnd, 1 + rnd.nextInt(12), 3);
            if (minCut(w) != oracle(w)) throw new AssertionError("random " + t + " " + w);
        }
    }

    static String word(Random rnd, int len, int alphabet) {
        StringBuilder s = new StringBuilder();
        for (int k = 0; k < len; k++) s.append((char) ('a' + rnd.nextInt(alphabet)));
        return s.toString();
    }

Problem

Choosing People In A Reporting Tree

A company wants to pick people for a review panel. Each person has a score, and nobody may sit on the panel together with their direct manager. The goal is the highest total score.

A manager scores 5 and has two reports who score 4 each. A quick rule picks the highest score first, so it picks the manager and blocks both reports. The total is 5. The better panel holds the two reports and totals 8. One early pick ruined the result.

Formally, the input is a tree: a set of nodes joined by edges with one root and no cycles. Every node except the root has one parent, and the nodes directly below a node are its children. A node with no children is a leaf. A subtree of a node is that node together with everything below it. Each node carries an integer weight. The task is to choose a set of nodes so that no chosen node has a chosen parent, and to return the largest total weight.

This lesson asks how a parent can decide well when the answer for each child depends on whether the parent is chosen.

Simple approach

Trying Both Choices At Every Node

The direct method makes the decision at the root and recurses. If the root is chosen, its children are blocked, so the method adds the root weight to the best results of the grandchildren. If the root is not chosen, the method adds the best results of the two children. It returns the larger sum.

static int best(Node node) {
    if (node == null) return 0;
    int withNode = node.val;
    if (node.left != null) withNode += best(node.left.left) + best(node.left.right);
    if (node.right != null) withNode += best(node.right.left) + best(node.right.right);
    int withoutNode = best(node.left) + best(node.right);
    return Math.max(withNode, withoutNode);
}

Here Node has an int val and two fields left and right, each a Node or null. The method is correct, because it tries both choices at every node. It also solves the same subtree again and again. The grandchild subtrees are visited once through withNode and once more through the children.

Bottleneck

The Same Subtree Is Solved Twice

Predict first: A chain has 30 nodes, and each node has exactly one child. Roughly how many calls does best make, counting calls on null?

It makes 7,049,153 calls. Each node spawns calls for its child and its grandchild, so the count follows the Fibonacci pattern and grows by a factor near 1.6 for every added node.

The call count c(n) for a chain of n nodes satisfies c(n) = 1 + c(n - 1) + c(n - 2) plus a few calls on null. That recurrence is exponential, so the method runs in O(1.6^n) time on a chain. In any tree, a grandchild subtree is solved once through withNode and once through its parent in withoutNode. The repeats compound with every added level of depth. The recursion also uses O(h) stack space for a tree of height h.

The repeated work has a clear cause. The method asks each subtree one question per call: what is your best total? Yet the parent needs two different answers from a child, one for a chosen parent and one for a free parent. Each call computes only one of them, so the other is recomputed later in a separate call. If each subtree answered both questions once and returned both answers, the parent could read everything from two numbers per child. Total work then falls to O(n), one visit per node. The next section defines these two numbers.

Key idea

Return Two Numbers From Each Subtree

A parent cares about only one fact of each child subtree: whether the child itself is chosen. So every subtree reports its best total for each of the two cases, and the parent combines those totals.

Two Answers For Each Node

For a node v, the take value is the largest total weight in the subtree of v when v itself is chosen. The skip value is the largest total weight in the subtree of v when v is not chosen. Both values count only nodes inside that subtree. The best total for the whole subtree is the larger of the two.

How A Parent Combines Children

If v is chosen, both children must be left out. The take value is the weight of v plus the skip value of each child. If v is not chosen, each child is free to go either way. The skip value is the larger of take and skip for the left child plus the larger of take and skip for the right child. Each child contributes independently, because the only link between two sibling subtrees runs through their shared parent.

The Neutral Pair For A Missing Child

A missing child is an empty subtree with no nodes and no weight. Its neutral pair is take 0 and skip 0. Plugging the neutral pair into both formulas adds nothing, so a leaf gets take equal to its weight and skip equal to 0 with no special case. A node with one child uses the neutral pair for the other side in the same way.

Why Post-Order Works

The invariant is that the pair returned for a subtree is final and summarizes that subtree completely for both choices of its root. A parent reads two finished pairs and never needs to look inside them again. The method therefore visits the children first and the parent last. The answer for the whole tree is the larger value of the root pair.

State

The Pair Each Call Returns

A call receives one node and returns two integers. The working values are these.

  • node is the subtree root in the current call.
  • left and right are the pairs returned for the two children, each holding a take value and a skip value.
  • take is the weight of node plus the skip values of left and right.
  • skip is the larger entry of left plus the larger entry of right.

The method returns the pair as an int[2], with the take value at index 0 and the skip value at index 1. For a null node it returns {0, 0}, the neutral pair. A tree with n nodes produces n pairs, one per call, plus the neutral pairs for missing children.

Walkthrough

Two Runs Over Small Trees

A Tree With Two Levels Of Children

Trace cells need an array, so the tree is stored in heap layout. The root sits at cell 0, and the children of the node at cell k sit at cells 2k + 1 and 2k + 2. The value -1 marks a missing node. The first tree is [6, 2, 5, 4, 1, -1, 3]. Node 6 has children 2 and 5. Node 2 has leaves 4 and 1, and node 5 has only a right child 3.

The pointer node marks the cell being finished, and the order is post-order, so children finish first. The variables left and right hold the pairs of the two children as (take, skip), and take and skip are the pair just computed. The leaves 4, 1 and 3 get a take value equal to their weight and a skip value of 0. Node 2 chooses itself for 2 or leaves itself out for 4 + 1 = 5, so its pair is (2, 5). Node 5 gets (5, 3). The root combines them: take is 6 + 5 + 3 = 14, and skip is 5 + 5 = 10. The answer is 14.

A Skip Beats A Take

The second tree is [2, 1, 3, -1, 4]. Node 1 has only a right child, which is the leaf 4. Node 1 gets (1, 4), because choosing the leaf 4 beats choosing node 1. At the root, taking 2 gives 2 + 4 + 0 = 6, and skipping it gives the larger entry of node 1, which is 4, plus the 3 of node 2, so 7. The skip value wins and the answer is 7.

Code

Computing The Pair In One Pass

The method below returns the best total weight. A helper does the post-order recursion and returns the pair for each subtree.

final class TreeDp {
    static final class Node {
        int val;
        Node left, right;
        Node(int val) { this.val = val; }
    }

    static int bestTotal(Node root) {
        int[] pair = pairOf(root);
        return Math.max(pair[0], pair[1]);
    }

    static int[] pairOf(Node node) {
        if (node == null) return new int[] {0, 0};
        int[] left = pairOf(node.left);
        int[] right = pairOf(node.right);
        int take = node.val + left[1] + right[1];
        int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
        return new int[] {take, skip};
    }
}

Each node triggers one call, and each call does a constant amount of work, so time is O(n). The stack grows to the height of the tree, which is O(h) memory. A chain of a million nodes would overflow the default stack, and a parent array processed from the last index down avoids recursion entirely. An empty tree returns 0, because both entries of the neutral pair are 0.

When to use it

Recognizing Subtree Summaries

Reading The Cue

Use this method when a decision at a node changes what its children may do, and the children's subtrees do not interact except through that node. Phrases such as "no two adjacent", "a parent and child may not both" and "answer for every node as the root" point here. The state is a node together with a small number of modes of that node, and each mode has its own best value.

Checking The Invariant

The invariant says that every returned pair describes its own subtree completely, for each mode the parent can ask about. Test a single node, which must return its weight when the weight is positive. Test a chain of three nodes with weights 4, 5, 4, where the middle node loses to the two ends. Test a node with only a left child and a node with only a right child. Compare the result with a subset check on trees of about a dozen nodes.

Avoiding The False Friend

The first false friend is the greedy pick of the heaviest node, which fails on the opening example. The second is the sum of every other level, which assumes the best panel uses whole levels. A tree where the top level is heavy but the next level has one very large node breaks it. The third is a single returned number, which cannot tell the parent whether the child is chosen. The method does not apply when nodes have several parents or when the graph has a cycle, because a subtree no longer isolates its own choices. It also does not apply when the rule links nodes farther apart than parent and child, unless the pair grows to hold the extra modes.

Take Or Skip Node

Author exercise

Problem Specification. A rooted tree has nodes 0 to n - 1, with root 0. An array parent gives the parent of each node, where parent[0] = -1 and parent[i] < i for i >= 1. An array w gives the weight of each node. A set of nodes is valid if no chosen node has a chosen parent. Return an array of two integers. The first is the largest total weight of a valid set that contains node 0. The second is the largest total weight of a valid set that does not contain node 0.

Input Constraints. The limits are:

  • Size satisfies 1 <= n <= 100000.
  • Weights satisfy 0 <= w[i] <= 1000.
  • Result is an int[2], and the sums fit in int.
  • Mutation is not allowed for the input arrays.

Example 1. Input parent = [-1, 0, 0, 1, 1], w = [2, 7, 4, 6, 1], output [9, 11].

Example 2. Input parent = [-1, 0, 1, 2], w = [5, 1, 1, 5], output [10, 6].

Prerequisites. The pair of take and skip values from this lesson.

What This Exercise Changes. The method returns both values for the root in place of one maximum. The loop runs from the last node down to node 1 and pushes each finished pair into its parent.

Hint

Every parent has a smaller index than its children. In which order can the loop visit the nodes so that each node is finished before its parent?

Algorithmic Solution (attempt the problem first)

Approach. Two arrays take and skip hold one pair for each node. Entry take[v] is the largest valid total in the subtree of v when v is chosen, and skip[v] is the same total when v is left out. Every node starts with take[v] = w[v] and skip[v] = 0, which is the pair of a leaf. The loop then visits nodes from n - 1 down to 1. Because parent[i] < i, every child has a larger index than its parent, so each node is finished before the loop reaches its parent. A finished child adds skip[v] to take[p], since a chosen parent blocks the child. It adds max(take[v], skip[v]) to skip[p], since a free parent lets the child choose.

The invariant is that when the loop reaches node v, all of its children have already pushed their contributions, so take[v] and skip[v] are final. The method never recurses, so a chain of 100000 nodes needs no stack depth.

Complexity.

  • Time is O(n), because the loop visits each node once and does constant work for it.
  • Space is O(n) for the two arrays, and the input arrays stay unchanged.
import java.util.*;

public final class DpTakeOrSkipNode {
    /**
     * Returns {best with node 0 chosen, best with node 0 left out}.
     * Time: O(n). Space: O(n).
     * Invariant: take[v] and skip[v] are final once every child of v has been visited.
     */
    static int[] rootPair(int[] parent, int[] w) {
        // n nodes, so each of the two arrays has n entries.
        int n = w.length;
        int[] take = new int[n];
        int[] skip = new int[n];
        // Every node starts as a leaf: chosen total is its weight, left-out total is 0.
        for (int v = 0; v < n; v++) take[v] = w[v];
        // Visit from the last index down, so children come before their parent.
        for (int v = n - 1; v >= 1; v--) {
            int p = parent[v];
            // A chosen parent blocks this child, so only the child's skip total counts.
            take[p] += skip[v];
            // A free parent lets the child pick its better case.
            skip[p] += Math.max(take[v], skip[v]);
        }
        // The root pair summarizes the whole tree.
        return new int[] {take[0], skip[0]};
    }

    /** Oracle: tries every subset of nodes and keeps the valid ones. */
    static int[] oracle(int[] parent, int[] w) {
        int n = w.length;
        int withRoot = Integer.MIN_VALUE;
        int withoutRoot = Integer.MIN_VALUE;
        for (int mask = 0; mask < (1 << n); mask++) {
            boolean ok = true;
            int sum = 0;
            for (int v = 0; v < n && ok; v++) {
                if ((mask >> v & 1) == 0) continue;
                sum += w[v];
                if (v > 0 && (mask >> parent[v] & 1) == 1) ok = false;
            }
            if (!ok) continue;
            if ((mask & 1) == 1) withRoot = Math.max(withRoot, sum);
            else withoutRoot = Math.max(withoutRoot, sum);
        }
        return new int[] {withRoot, withoutRoot};
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(rootPair(new int[] {-1, 0, 0, 1, 1}, new int[] {2, 7, 4, 6, 1}), new int[] {9, 11})) throw new AssertionError("ex1");
        if (!Arrays.equals(rootPair(new int[] {-1, 0, 1, 2}, new int[] {5, 1, 1, 5}), new int[] {10, 6})) throw new AssertionError("ex2");
        // A single node: choosing it gives its weight, leaving it out gives 0.
        if (!Arrays.equals(rootPair(new int[] {-1}, new int[] {7}), new int[] {7, 0})) throw new AssertionError("single");
        // A new int array holds zeros, which is the skip total of a leaf.
        int[] fresh = new int[3];
        if (fresh[0] != 0 || fresh[1] != 0 || fresh[2] != 0) throw new AssertionError("zero fill");
        // A chain of 100000 nodes runs without recursion and takes every other node.
        int big = 100000;
        int[] chainParent = new int[big];
        int[] chainWeight = new int[big];
        chainParent[0] = -1;
        for (int i = 1; i < big; i++) chainParent[i] = i - 1;
        Arrays.fill(chainWeight, 1);
        int[] chain = rootPair(chainParent, chainWeight);
        if (chain[0] != 50000 || chain[1] != 50000) throw new AssertionError("chain");
        // The input arrays are not modified.
        int[] par = {-1, 0, 0};
        int[] wt = {10, 6, 7};
        rootPair(par, wt);
        if (!Arrays.equals(par, new int[] {-1, 0, 0}) || !Arrays.equals(wt, new int[] {10, 6, 7})) throw new AssertionError("mutated");
        // Random trees against the subset oracle.
        Random rnd = new Random(2931);
        for (int t = 0; t < 2000; t++) {
            int n = 1 + rnd.nextInt(11);
            int[] p = new int[n];
            int[] w = new int[n];
            p[0] = -1;

            for (int i = 0; i < n; i++) w[i] = rnd.nextInt(10);

House Robber III

LeetCode 337

Problem Specification. A binary tree is given by its root. Each node holds a non-negative integer amount. Choose a set of nodes so that no chosen node is the parent of another chosen node. Return the largest total amount of a valid set.

Input Constraints. The limits are:

  • Size satisfies 1 <= nodes <= 1000, and the height is at most 1000.
  • Values satisfy 0 <= val <= 10000.
  • Result is an int.
  • Mutation is not allowed, so the tree stays unchanged.

Example 1. Input root [5, 4, 3, 2, 1] in level order, output 8.

Example 2. Input root [4, 1, null, 2, null, 3] in level order, output 7.

Prerequisites. The exercise above.

What This Exercise Changes. The tree is binary with explicit child links in place of a parent array, so the method recurses over the links. Choosing a node forces both children into their skip states.

Hint

When a node is chosen, what must the skip value of each child supply, and what may the parent read when the node is left out?

Algorithmic Solution (attempt the problem first)

Approach. A recursive helper returns an int[2] for each node, with the take total at index 0 and the skip total at index 1. A null node returns {0, 0}. For a real node, the helper first gets the pairs of its two children. The take total adds the node amount to both child skip totals, because a chosen node blocks its children. The skip total adds the better case of the left child to the better case of the right child. The main method returns the larger entry of the root pair.

The invariant is that each returned pair is final and describes only the subtree of that node. A parent never revisits a child. The recursion depth equals the tree height, which the constraints cap at 1000. The solution also contains the direct recursion from the lesson, to count its calls.

Complexity.

  • Time is O(n) for n nodes, because each node is visited once and combines two pairs in constant time.
  • Space is O(h) for the call stack on a tree of height h, plus a constant-size pair per active call.
import java.util.*;

public final class DpHouseRobberThree {
    static final class Node {
        int val;
        Node left, right;
        Node(int val) { this.val = val; }
    }

    /**
     * Returns the largest total of nodes where no chosen node is the parent of another.
     * Time: O(n). Space: O(h).
     * Invariant: the pair of a subtree is final before its parent reads it.
     */
    static int rob(Node root) {
        // The root pair covers the whole tree, and the better entry is the answer.
        int[] pair = pairOf(root);
        return Math.max(pair[0], pair[1]);
    }

    /** Returns {take, skip} for the subtree of node. Time: O(size). Space: O(height). */
    static int[] pairOf(Node node) {
        // A missing subtree adds nothing in either case.
        if (node == null) return new int[] {0, 0};
        // Children finish first, so their pairs are final.
        int[] left = pairOf(node.left);
        int[] right = pairOf(node.right);
        // Choosing node forces both children into their skip totals.
        int take = node.val + left[1] + right[1];
        // Leaving node out lets each child pick its better case.
        int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
        return new int[] {take, skip};
    }

    static long calls = 0;

    /** The direct recursion from the lesson, with a call counter. */
    static int direct(Node node) {
        calls++;
        if (node == null) return 0;
        int withNode = node.val;
        if (node.left != null) withNode += direct(node.left.left) + direct(node.left.right);
        if (node.right != null) withNode += direct(node.right.left) + direct(node.right.right);
        int withoutNode = direct(node.left) + direct(node.right);
        return Math.max(withNode, withoutNode);
    }

    /** Builds a tree from a level-order list where null marks a missing child. */
    static Node fromLevels(Integer[] a) {
        if (a.length == 0 || a[0] == null) return null;
        Node root = new Node(a[0]);
        ArrayDeque<Node> queue = new ArrayDeque<>();
        queue.add(root);
        int i = 1;
        while (!queue.isEmpty() && i < a.length) {
            Node cur = queue.poll();
            if (i < a.length && a[i] != null) { cur.left = new Node(a[i]); queue.add(cur.left); }
            i++;
            if (i < a.length && a[i] != null) { cur.right = new Node(a[i]); queue.add(cur.right); }
            i++;
        }
        return root;
    }

    /** Oracle: lists every node, then tries all subsets and rejects parent-child pairs. */
    static int oracle(Node root) {
        List<Node> nodes = new ArrayList<>();
        Map<Node, Node> parentOf = new IdentityHashMap<>();
        ArrayDeque<Node> stack = new ArrayDeque<>();
        if (root != null) stack.push(root);
        while (!stack.isEmpty()) {
            Node cur = stack.pop();
            nodes.add(cur);
            if (cur.left != null) { parentOf.put(cur.left, cur); stack.push(cur.left); }
            if (cur.right != null) { parentOf.put(cur.right, cur); stack.push(cur.right); }
        }
        int n = nodes.size();
        int best = 0;
        for (int mask = 0; mask < (1 << n); mask++) {
            Set<Node> chosen = Collections.newSetFromMap(new IdentityHashMap<>());
            int sum = 0;
            for (int k = 0; k < n; k++) if ((mask >> k & 1) == 1) { chosen.add(nodes.get(k)); sum += nodes.get(k).val; }
            boolean ok = true;
            for (Node c : chosen) if (chosen.contains(parentOf.get(c))) ok = false;
            if (ok) best = Math.max(best, sum);
        }
        return best;
    }

    static Node randomTree(Random rnd, int n, int lo, int hi) {
        if (n == 0) return null;
        Node root = new Node(lo + rnd.nextInt(hi - lo + 1));
        List<Node> open = new ArrayList<>();
        open.add(root);
        for (int made = 1; made < n; ) {
            Node p = open.get(rnd.nextInt(open.size()));
            Node c = new Node(lo + rnd.nextInt(hi - lo + 1));
            if (rnd.nextBoolean()) { if (p.left == null) p.left = c; else if (p.right == null) p.right = c; else continue; }
            else { if (p.right == null) p.right = c; else if (p.left == null) p.left = c; else continue; }
            open.add(c);
            made++;
        }
        return root;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (rob(fromLevels(new Integer[] {5, 4, 3, 2, 1})) != 8) throw new AssertionError("ex1");
        if (rob(fromLevels(new Integer[] {4, 1, null, 2, null, 3})) != 7) throw new AssertionError("ex2");
        // The opening example of the lesson: a manager of weight 5 with two reports of weight 4.
        if (rob(fromLevels(new Integer[] {5, 4, 4})) != 8) throw new AssertionError("opening");
        // The two traced trees of the lesson, written in level order.
        if (rob(fromLevels(new Integer[] {6, 2, 5, 4, 1, null, 3})) != 14) throw new AssertionError("trace1");
        if (rob(fromLevels(new Integer[] {2, 1, 3, null, 4})) != 7) throw new AssertionError("trace2");
        // The direct recursion makes 7049153 calls on a chain of 30 nodes, and the pair method visits each node once.
        Node chain = null;
        for (int i = 0; i < 30; i++) { Node c = new Node(1); c.left = chain; chain = c; }
        calls = 0;
        int directAnswer = direct(chain);
        if (calls != 7049153L) throw new AssertionError("calls " + calls);
        if (directAnswer != rob(chain) || directAnswer != 15) throw new AssertionError("chain answer");

        Node deep = null;
        for (int i = 0; i < 1000000; i++) { Node c = new Node(1); c.left = deep; deep = c; }
        boolean overflow = false;
        try { rob(deep); } catch (StackOverflowError e) { overflow = true; }
        if (!overflow) throw new AssertionError("expected stack overflow");

        Node t = fromLevels(new Integer[] {3, 1, 2});
        rob(t);
        if (t.val != 3 || t.left.val != 1 || t.right.val != 2) throw new AssertionError("mutated");

        Random rnd = new Random(2932);
        for (int k = 0; k < 1500; k++) {
            Node tree = randomTree(rnd, 1 + rnd.nextInt(11), 0, 9);
            if (rob(tree) != oracle(tree)) throw new AssertionError("random " + k);
        }
    }

Null And Negative Values

Author exercise

Problem Specification. A binary tree is given by its root, which may be null. Each node holds an integer, possibly negative. Choose any set of nodes, possibly empty, so that no chosen node is the parent of another chosen node. Return the largest total of a valid set. The empty set has total 0.

Input Constraints. The limits are:

  • Size satisfies 0 <= nodes <= 1000, and the height is at most 1000.
  • Values satisfy -10000 <= val <= 10000.
  • Result is an int, and an empty tree returns 0.
  • Mutation is not allowed, so the tree stays unchanged.

Example 1. Input root [-3, -2, -4] in level order, output 0.

Example 2. Input root [5, -10, 5, -1, 7] in level order, output 12.

Prerequisites. The two exercises above.

What This Exercise Changes. Negative weights can push a take value below 0. The skip value of every subtree still allows the empty set, so the answer never falls below 0.

Hint

What pair should a missing child return, and does the skip value of a subtree ever fall below 0 when the empty set is allowed?

Algorithmic Solution (attempt the problem first)

Approach. The helper returns {take, skip} for each subtree and returns {0, 0} for a null node. The take total adds the node value to the skip totals of both children. The skip total adds the better case of each child. A negative value can make a take total negative, but the skip total of any subtree is at least 0, because a leaf has skip 0 and each combination adds non-negative terms. The skip total therefore always allows the empty choice, and the answer, which is the larger entry of the root pair, is at least 0. An empty tree returns 0 at once.

The invariant is that the pair of a subtree is final and that skip is never negative. A different neutral value breaks it. If a missing child returned Integer.MIN_VALUE as its take total, a parent that adds two of them overflows to 0 and gives a wrong answer, which is why the neutral pair uses 0.

Complexity.

  • Time is O(n) for n nodes, because each node is visited once and combines two pairs in constant time.
  • Space is O(h) for the call stack on a tree of height h.
import java.util.*;

public final class DpNullAndNegative {
    static final class Node {
        int val;
        Node left, right;
        Node(int val) { this.val = val; }
    }

    /**
     * Returns the largest total of a valid set of nodes, where the empty set counts as 0.
     * Time: O(n). Space: O(h).
     * Invariant: each skip total is at least 0, because the empty set is allowed.
     */
    static int bestSet(Node root) {
        // A null root has the neutral pair, so the answer is 0.
        int[] pair = pairOf(root);
        return Math.max(pair[0], pair[1]);
    }

    /** Returns {take, skip} for the subtree of node. Time: O(size). Space: O(height). */

        // A missing subtree has no nodes, so both totals are 0.
        if (node == null) return new int[] {0, 0};
        int[] left = pairOf(node.left);
        int[] right = pairOf(node.right);
        // A chosen node blocks both children, so their skip totals add to its value.
        int take = node.val + left[1] + right[1];
        // A free node lets each child pick its better case, which can be the empty choice.
        int skip = Math.max(left[0], left[1]) + Math.max(right[0], right[1]);
        return new int[] {take, skip};
    }

            i++;
            if (i < a.length && a[i] != null) { cur.right = new Node(a[i]); queue.add(cur.right); }
            i++;
        }
        return root;
    }

        List<Node> nodes = new ArrayList<>();
        Map<Node, Node> parentOf = new IdentityHashMap<>();
        ArrayDeque<Node> stack = new ArrayDeque<>();

        while (!stack.isEmpty()) {
            Node cur = stack.pop();
            nodes.add(cur);
            if (cur.left != null) { parentOf.put(cur.left, cur); stack.push(cur.left); }
            if (cur.right != null) { parentOf.put(cur.right, cur); stack.push(cur.right); }
        }
        int n = nodes.size();
        int best = 0;
        for (int mask = 0; mask < (1 << n); mask++) {
            Set<Node> chosen = Collections.newSetFromMap(new IdentityHashMap<>());
            int sum = 0;
            for (int k = 0; k < n; k++) if ((mask >> k & 1) == 1) { chosen.add(nodes.get(k)); sum += nodes.get(k).val; }
            boolean ok = true;
            for (Node c : chosen) if (chosen.contains(parentOf.get(c))) ok = false;
            if (ok) best = Math.max(best, sum);
        }

    }

            if (p.left == null) p.left = c;

        }

    }

Rerooted Distance Sums

Author exercise

Problem Specification. An undirected tree has nodes 0 to n - 1 and n - 1 edges. The distance between two nodes is the number of edges on the path between them. For every node v, return the sum of the distances from v to all nodes of the tree. Return the sums as an array indexed by node.

Input Constraints. The limits are:

  • Size satisfies 1 <= n <= 10000.
  • Edges are given as pairs {a, b} and form one connected tree.
  • Result is an int[n], and each sum fits in int.
  • Mutation is not allowed for the edge list.

Example 1. Input n = 4, edges = [[0, 1], [0, 2], [2, 3]], output [4, 6, 4, 6].

Example 2. Input n = 5, edges = [[0, 1], [1, 2], [2, 3], [3, 4]], output [10, 7, 6, 7, 10].

Prerequisites. All three exercises above.

What This Exercise Changes. Every node must be the root once, so a second pass from the root down hands each child a parent contribution. Each subtree returns a count and a distance sum, which is a pair in place of the take and skip values.

Hint

One pass from the leaves up gives, for each node, its subtree size and the distance sum inside that subtree. How does the answer change when the root moves from a parent to one child?

Algorithmic Solution (attempt the problem first)

Approach. The method roots the tree at node 0 and finds a breadth-first order, which lists every parent before its children. The first pass walks that order backward. For each node v it computes size[v], the number of nodes in its subtree, and down[v], the sum of distances from v to the nodes in its subtree. A child c adds size[c] to its parent's down because every node in the child subtree is one edge farther from the parent, and it adds down[c]. The value down[0] is already the full answer for node 0.

The second pass walks the order forward and carries the answer from each parent to its children. Moving the root from p to a child c makes the size[c] nodes in the child subtree one edge closer, and it makes the other n - size[c] nodes one edge farther. So ans[c] = ans[p] - size[c] + (n - size[c]). The invariant is that when the second pass reaches c, ans[p] is final and size[c] is final from the first pass. Both passes use arrays, so no recursion is needed.

Complexity.

  • Time is O(n), because the breadth-first order and the two passes each touch every node and edge once.
  • Space is O(n) for the adjacency lists, the order and the three arrays.
import java.util.*;

public final class DpRerootedDistanceSums {
    /**
     * Returns, for every node, the sum of its distances to all nodes.
     * Time: O(n). Space: O(n).
     * Invariant: when the downward pass reaches a node, its parent answer is final.
     */
    static int[] distanceSums(int n, int[][] edges) {
        // Adjacency lists give every neighbor of a node in one array slice.
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }
        // Breadth-first order from node 0 lists every parent before its children.
        int[] order = new int[n];
        int[] parent = new int[n];
        Arrays.fill(parent, -1);
        boolean[] seen = new boolean[n];
        int head = 0, tail = 0;
        order[tail++] = 0;
        seen[0] = true;
        while (head < tail) {
            int v = order[head++];
            for (int c : adj.get(v)) {
                if (seen[c]) continue;
                seen[c] = true;
                parent[c] = v;
                order[tail++] = c;
            }
        }
        // First pass: size[v] counts the subtree nodes and down[v] sums their distances to v.
        int[] size = new int[n];
        int[] down = new int[n];
        Arrays.fill(size, 1);
        for (int k = n - 1; k >= 1; k--) {
            int c = order[k];
            int p = parent[c];
            // Every node in the child subtree is one edge farther from the parent.
            size[p] += size[c];
            down[p] += down[c] + size[c];
        }
        // Second pass: move the root from each parent to each child in order.
        int[] ans = new int[n];
        ans[0] = down[0];
        for (int k = 1; k < n; k++) {
            int c = order[k];
            // size[c] nodes get one edge closer and the other n - size[c] nodes get one edge farther.
            ans[c] = ans[parent[c]] - size[c] + (n - size[c]);
        }
        return ans;
    }

    /** Oracle: runs a breadth-first search from every node and adds the distances. */
    static int[] oracle(int n, int[][] edges) {
        List<List<Integer>> adj = new ArrayList<>();
        for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
        for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }
        int[] out = new int[n];
        for (int s = 0; s < n; s++) {
            int[] d = new int[n];
            Arrays.fill(d, -1);
            d[s] = 0;
            ArrayDeque<Integer> q = new ArrayDeque<>();
            q.add(s);
            while (!q.isEmpty()) {
                int v = q.poll();
                for (int c : adj.get(v)) if (d[c] < 0) { d[c] = d[v] + 1; q.add(c); }
            }
            for (int x : d) out[s] += x;
        }
        return out;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(distanceSums(4, new int[][] {{0, 1}, {0, 2}, {2, 3}}), new int[] {4, 6, 4, 6})) throw new AssertionError("ex1");
        if (!Arrays.equals(distanceSums(5, new int[][] {{0, 1}, {1, 2}, {2, 3}, {3, 4}}), new int[] {10, 7, 6, 7, 10})) throw new AssertionError("ex2");
        // One node has sum 0, and two nodes have sum 1 each.
        if (!Arrays.equals(distanceSums(1, new int[][] {}), new int[] {0})) throw new AssertionError("single");
        if (!Arrays.equals(distanceSums(2, new int[][] {{1, 0}}), new int[] {1, 1})) throw new AssertionError("pair");
        // The largest allowed chain keeps every sum inside int: the end sum is 10000 * 9999 / 2.
        int n = 10000;
        int[][] chain = new int[n - 1][];
        for (int i = 0; i < n - 1; i++) chain[i] = new int[] {i, i + 1};
        int[] big = distanceSums(n, chain);
        if (big[0] != 49995000 || big[n - 1] != 49995000) throw new AssertionError("big chain");
        // The edge list is not modified.
        int[][] edges = {{0, 1}, {1, 2}};
        distanceSums(3, edges);
        if (!Arrays.deepEquals(edges, new int[][] {{0, 1}, {1, 2}})) throw new AssertionError("mutated");
        // Random trees, with random labels, against the search from every node.
        Random rnd = new Random(2934);
        for (int t = 0; t < 2000; t++) {
            int m = 1 + rnd.nextInt(12);
            int[] label = new int[m];
            for (int i = 0; i < m; i++) label[i] = i;
            for (int i = m - 1; i > 0; i--) { int j = rnd.nextInt(i + 1); int tmp = label[i]; label[i] = label[j]; label[j] = tmp; }
            int[][] es = new int[m - 1][];
            for (int i = 1; i < m; i++) es[i - 1] = new int[] {label[i], label[rnd.nextInt(i)]};
            if (!Arrays.equals(distanceSums(m, es), oracle(m, es))) throw new AssertionError("random " + t);
        }
    }

Problem

Giving Each Worker One Job

A batch system has three workers and three jobs. Each worker takes one job, and each job goes to one worker. The table cost[w][j] gives the minutes that worker w needs for job j. For [[3,3,9],[2,8,9],[7,6,5]], the cheapest plan costs 10. Worker 0 takes job 1, worker 1 takes job 0 and worker 2 takes job 2.

A developer writes a quick rule. It handles the workers in order, and each worker takes the cheapest job that is still free, using the lowest job number on a tie. Worker 0 takes job 0 for 3 minutes. Worker 1 then has only jobs 1 and 2 left and pays 8. Worker 2 pays 5 for job 2. The rule reports 16, which is 6 minutes worse than the best plan.

Formally, the input is a square matrix cost with n rows and n columns. Row w is a worker and column j is a job. An assignment gives every worker a different job. Its cost is the sum of the chosen entries. The goal is to return the smallest cost over all assignments.

This lesson asks how to search the assignments quickly when one early pick changes which jobs stay free.

Simple approach

Trying Every Order Of Jobs

The safe idea is to try every assignment. The method gives worker 0 each job, then gives worker 1 each job that is still free, and so on. A boolean[] named taken records which jobs are in use.

static int tryAll(int[][] cost, int worker, boolean[] taken) {
    int n = cost.length;
    if (worker == n) {
        return 0;
    }
    int best = Integer.MAX_VALUE;
    for (int j = 0; j < n; j++) {
        if (!taken[j]) {
            taken[j] = true;
            int rest = tryAll(cost, worker + 1, taken);
            taken[j] = false;
            best = Math.min(best, cost[worker][j] + rest);
        }
    }
    return best;
}

The first call passes worker = 0 and an all-false array. The method finds the true minimum, because it looks at every assignment. Worker 0 has n choices, worker 1 has n - 1 choices, and so on, so the recursion visits n! complete assignments. The time is O(n!), and the recursion depth gives O(n) memory.

Bottleneck

Repeated Work Across Different Orders

Predict first: A search tries every assignment for 15 workers. How many complete assignments is that? And how many different sets of jobs can the first few workers hold, counting every size from 0 to 15?

There are 15! = 1,307,674,368,000 complete assignments. There are only 2^15 = 32,768 different sets of jobs, because each job is either in the set or out of it.

The search is correct but its cost explodes. For n = 12 it visits 479,001,600 assignments, and each one costs O(n) to add up unless the sum is kept along the path. For n = 15 the count passes 10^12. No input of that size finishes.

The cause is repeated work. Take workers 0 and 1 and jobs 3 and 5. Worker 0 on job 3 with worker 1 on job 5 leaves the same problem as worker 0 on job 5 with worker 1 on job 3. Both leave workers 2 onward facing the same free jobs. The search solves that remaining problem once for each order of the two picks.

Only the set of used jobs matters for the future, not the order that produced it. A set drawn from n jobs has 2^n possibilities, which is far below n!. If each set is solved once and stored, the work drops to O(n * 2^n). The next section shows how to store a set in one integer and how one answer follows from smaller ones.

Key idea

Store The Used Jobs In One Integer

An integer has 32 bits, and each bit can say yes or no for one job. That makes a whole set of jobs a single number, which can index an array.

Bits Hold A Set Of Jobs

A job mask is an int whose bit j is 1 exactly when job j is in the set. Bit 0 is the lowest bit. The set {0, 2} is the number 101 in binary, which is 5.

Five operations cover everything the lesson needs. 1 << j is an integer with only bit j set. mask | (1 << j) adds job j. mask & ~(1 << j) removes it. (mask >> j) & 1 tests it and gives 0 or 1. mask ^ (1 << j) flips it, which removes a job that is known to be present.

Counting Bits Gives The Worker

The popcount of a mask is the number of 1 bits, and Java computes it with Integer.bitCount(mask). Suppose workers receive jobs in order, worker 0 first. After the first k workers finish, the job mask holds exactly k jobs. The popcount therefore names the next worker without an extra index.

The full mask is (1 << n) - 1, which has bits 0 to n - 1 all set. It is the largest mask for n jobs. The array that stores one answer per mask has 1 << n entries, indexes 0 to the full mask.

Each Entry Removes One Job

Let dp[mask] be the smallest cost of giving the first popcount(mask) workers different jobs, using exactly the jobs in mask. For a nonempty mask, the last of those workers is worker w = popcount(mask) - 1. That worker holds one job j from the mask. The other workers hold the jobs of mask ^ (1 << j).

The entry is the smallest value of dp[mask ^ (1 << j)] + cost[w][j] over every j in the mask. The base entry is dp[0] = 0, because no worker needs a job. The answer is dp[full mask]. The invariant is that mask ^ (1 << j) is a smaller number than mask, so a loop that counts up from 1 finishes every entry before another entry reads it.

State

The Array And Its Bit Operations

One matrix comes in, and these working values describe the computation.

  • cost is the int[n][n] input; cost[w][j] is the price of giving job j to worker w.
  • dp is an int[1 << n]; entry dp[mask] is the cheapest way to cover the jobs in mask with the first popcount(mask) workers.
  • mask runs from 1 to (1 << n) - 1, one value per set of jobs.
  • w is Integer.bitCount(mask) - 1, the worker who takes the last job of the set.
  • j is a job whose bit is 1 in mask; the loop tries each one.

Java fills a new int array with zeros, so dp[0] is already the base value 0. The loop sets best to Integer.MAX_VALUE before it compares. Each cost stays small enough that adding it to a stored answer never overflows an int.

Walkthrough

Two Runs Over The Masks

Beating The Cheapest Free Job Rule

The first run uses the matrix from the opening, [[3,3,9],[2,8,9],[7,6,5]]. The array has 8 cells, one per mask from 0 to 7, and the pointer mask marks the entry in progress. The variable mask prints the bits with job 0 on the right, worker is the index of the worker who takes the last job, and dp is the value written.

The three masks with one job cost the first row of the matrix, which is 3, 3 and 9. Mask 011 holds jobs 0 and 1. Worker 1 takes one of them, and the cheaper option leaves job 1 to worker 0 and gives job 0 to worker 1, for 5. The final mask 111 has three options. Worker 2 on job 2 adds 5 to the 5 stored for 011, which gives 10. The other two options give 19 and 17. The answer is 10, as the opening claimed.

A Larger Matrix With Sixteen Masks

The second run uses a 4 by 4 matrix, so the array has 16 cells. The single-job masks again copy the first row. Each two-job mask compares two options and keeps the smaller. Each three-job mask compares three, and the final mask compares four. The sequence shows that every entry is written once, in increasing order, and that each option reads an entry with fewer bits that is already final. The answer at mask 1111 is 13.

Code

Filling The Array By Mask

The method returns the smallest total cost of a complete assignment. It visits masks in increasing order and reads only smaller masks.

static int minAssignment(int[][] cost) {
    int n = cost.length;
    int full = (1 << n) - 1;
    int[] dp = new int[1 << n];
    for (int mask = 1; mask <= full; mask++) {
        int w = Integer.bitCount(mask) - 1;
        int best = Integer.MAX_VALUE;
        for (int j = 0; j < n; j++) {
            if ((mask >> j & 1) == 1) {
                best = Math.min(best, dp[mask ^ (1 << j)] + cost[w][j]);
            }
        }
        dp[mask] = best;
    }
    return dp[full];
}

Time is O(n * 2^n), because there are 2^n masks and each tries up to n jobs. Memory is O(2^n). For n = 0 the loop runs zero times and the method returns dp[0], which is 0. For n = 20 the array holds about a million entries, and for n = 30 it would hold over a billion, which is too large. The exercises below build the bit operations first.

When to use it

Recognizing Small Sets In The State

Reading The Cue

Use this method when each item can be used once and the future depends on which items are left. Phrases such as "each exactly once", "different columns" and "split into groups" point here, together with a limit near 20 on the item count. The state is a set of used items, and a count often tells the next position.

Checking The Invariant

The invariant says that bit j of the mask records whether item j is used, and that each entry is final before a larger mask reads it. Test a one-by-one matrix, which must return its single entry. Test a matrix where every entry is equal, which must return n times that value. Test a matrix whose cheapest picks collide on one column, because that case defeats the quick rule from the opening.

Avoiding The False Friend

The first false friend is the cheapest-free-job rule, which passes whenever the cheapest picks happen not to collide. The second is a set stored as a sorted list or a string key in a hash map, which has the same states but pays far more per lookup. The third is reading the worker from a loop counter, which breaks when the order of workers is not fixed by the popcount. The method does not apply when n reaches 30 or more, because 2^n entries no longer fit in memory, or when item order matters and not just the set, because a mask forgets order.

Problem Specification. An integer n and two arrays add and remove are given. Start with an empty set stored in an int where bit i stands for item i. First add every item of add, in order. Then remove every item of remove, in order. Return the final integer.

Input Constraints. The limits are:

  • Item count satisfies 0 <= n <= 30.
  • Items satisfy 0 <= item < n in both arrays.
  • Length of each array is at most 100, and either array may be empty.
  • Repeats are allowed, and removing an absent item changes nothing.

Example 1. Input n = 5, add = [0, 2, 4], remove = [2], output 17.

Example 2. Input n = 4, add = [1, 1, 3], remove = [0], output 10.

Prerequisites. The bit operations from this lesson.

What This Exercise Changes. The method stores the whole set in one int instead of a boolean[], so each update is a single bit operation.

Hint

Which operator sets a bit without touching the others, and which one clears a bit that may already be 0?

Algorithmic Solution (attempt the problem first)

Approach. The integer mask starts at 0, which is the empty set. Adding item i ORs the mask with 1 << i, which sets bit i and leaves every other bit alone. Removing item i ANDs the mask with the complement of 1 << i, which clears bit i and also works when the bit is already 0. All additions run before all removals, in the order the arrays give.

The invariant is that after each update, bit i is 1 exactly when item i has been added more recently than it was removed. Because n <= 30, every shift stays below bit 31, so the sign bit is never set and the result is nonnegative.

Complexity.

  • Time is O(a + r), where a and r are the array lengths, because each update is one bit operation.
  • Space is O(1), because the whole set lives in one int.
import java.util.*;

public final class Dp29SetTestClear {
    /**
     * Returns the integer set after all additions and then all removals.
     * Time: O(a + r). Space: O(1).
     * Invariant: bit i is 1 exactly when item i is currently in the set.
     */
    static int apply(int n, int[] add, int[] remove) {
        // Zero is the empty set because no bit is set.
        int mask = 0;
        // Each addition sets one bit and keeps the others.
        for (int item : add) {
            mask |= 1 << item;
        }
        // Each removal clears one bit, and clearing a bit that is 0 changes nothing.
        for (int item : remove) {
            mask &= ~(1 << item);
        }
        // The integer is the complete answer.
        return mask;
    }

    /** Oracle: keeps the set in a boolean array and rebuilds the integer from it. */
    static int oracle(int n, int[] add, int[] remove) {
        boolean[] in = new boolean[n];
        for (int item : add) in[item] = true;
        for (int item : remove) in[item] = false;
        int value = 0;
        for (int i = 0; i < n; i++) if (in[i]) value += 1 << i;
        return value;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (apply(5, new int[]{0, 2, 4}, new int[]{2}) != 17) throw new AssertionError("ex1");
        if (apply(4, new int[]{1, 1, 3}, new int[]{0}) != 10) throw new AssertionError("ex2");
        // Empty arrays leave the empty set, and removing an absent item changes nothing.
        if (apply(3, new int[]{}, new int[]{}) != 0) throw new AssertionError("empty");
        if (apply(3, new int[]{}, new int[]{1}) != 0) throw new AssertionError("absent");
        // The operators behave as the approach claims on small values.
        if ((1 << 3) != 8) throw new AssertionError("shift");
        if ((5 | (1 << 1)) != 7) throw new AssertionError("or");
        if ((7 & ~(1 << 1)) != 5) throw new AssertionError("andnot");
        if (((5 >> 2) & 1) != 1 || ((5 >> 1) & 1) != 0) throw new AssertionError("test");
        // With n = 30 the highest item is bit 29, so the result stays positive.
        if (apply(30, new int[]{29}, new int[]{}) <= 0) throw new AssertionError("sign");
        // Random inputs against the boolean array oracle.
        Random rnd = new Random(2901);
        for (int t = 0; t < 3000; t++) {
            int n = rnd.nextInt(31);
            if (n == 0) continue;
            int[] add = pick(rnd, n);
            int[] remove = pick(rnd, n);
            if (apply(n, add, remove) != oracle(n, add, remove)) throw new AssertionError("random " + t);
        }
    }

    static int[] pick(Random rnd, int n) {
        int[] a = new int[rnd.nextInt(12)];
        for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(n);
        return a;
    }

Example 2. Input cost = [[5, 9, 1, 6]], output 1.

Prerequisites. The exercise above and the table from this lesson.

What This Exercise Changes. The mask has m bits and only n workers, so the answer is the smallest entry among masks with exactly n bits set, not the entry for the full mask.

Hint

The mask now ranges over columns, so which masks can be a final answer, and which popcount do they share?

Algorithmic Solution (attempt the problem first)

Approach. The mask ranges over the m columns. Entry dp[mask] is the smallest cost of giving the first popcount(mask) rows different columns, using exactly the columns in mask. A mask with more than n bits is skipped, because only n rows exist. For a nonempty mask, row popcount(mask) - 1 takes one column j of the mask, and the rest come from dp[mask ^ (1 << j)].

The invariant is that mask ^ (1 << j) is smaller than mask, so every entry is final when read. The answer is the smallest dp[mask] over the masks with exactly n bits, since the unused columns are free to stay out of the mask.

Complexity.

  • Time is O(m * 2^m), because each of the 2^m masks tries at most m columns.
  • Space is O(2^m) for the array of entries.
import java.util.*;

public final class Dp29MinAssignmentCost {
    /**
     * Returns the smallest total cost of giving every row a different column.
     * Time: O(m * 2^m). Space: O(2^m).
     * Invariant: dp[mask] is final once the loop passes mask, and bit j means column j is used.
     */
    static int minCost(int[][] cost) {
        int n = cost.length;
        int m = cost[0].length;
        // One entry per set of columns; a very large value marks an unreachable set.
        int[] dp = new int[1 << m];
        Arrays.fill(dp, Integer.MAX_VALUE);
        // Zero columns used costs nothing.
        dp[0] = 0;
        int answer = Integer.MAX_VALUE;
        // Counting up guarantees that every smaller mask is final first.
        for (int mask = 1; mask < (1 << m); mask++) {
            // The popcount is the number of rows already served.
            int served = Integer.bitCount(mask);
            // A mask with more bits than rows cannot be reached.
            if (served > n) continue;
            int w = served - 1;
            int best = Integer.MAX_VALUE;
            // Try each column of the mask as the one that row w takes.
            for (int j = 0; j < m; j++) {
                if ((mask >> j & 1) == 1) {
                    best = Math.min(best, dp[mask ^ (1 << j)] + cost[w][j]);
                }
            }
            dp[mask] = best;
            // Only masks with exactly n bits are complete assignments.
            if (served == n) answer = Math.min(answer, best);
        }
        return answer;
    }

    /** Oracle: recursive search over all injective column choices. */
    static int oracle(int[][] cost, int row, boolean[] used) {
        if (row == cost.length) return 0;
        int best = Integer.MAX_VALUE;
        for (int j = 0; j < used.length; j++) {
            if (!used[j]) {
                used[j] = true;
                best = Math.min(best, cost[row][j] + oracle(cost, row + 1, used));
                used[j] = false;
            }
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minCost(new int[][]{{4, 2, 8}, {4, 3, 7}}) != 6) throw new AssertionError("ex1");
        if (minCost(new int[][]{{5, 9, 1, 6}}) != 1) throw new AssertionError("ex2");
        // The square case matches the lesson example 10.
        if (minCost(new int[][]{{3, 3, 9}, {2, 8, 9}, {7, 6, 5}}) != 10) throw new AssertionError("square");
        // Integer.bitCount counts the 1 bits.
        if (Integer.bitCount(0b10110) != 3) throw new AssertionError("bitCount");
        // Random matrices against the recursive oracle.
        Random rnd = new Random(2902);
        for (int t = 0; t < 1500; t++) {
            int n = 1 + rnd.nextInt(4);
            int m = n + rnd.nextInt(3);
            int[][] c = new int[n][m];
            for (int[] row : c) for (int j = 0; j < m; j++) row[j] = rnd.nextInt(20);
            if (minCost(c) != oracle(c, 0, new boolean[m])) throw new AssertionError("random " + t);
        }
    }

Full Mask And State Count

Author exercise

Problem Specification. An integer n is given. Return a long[] of three values. The first is the full mask (1 << n) - 1. The second is the number of masks from 0 to the full mask. The third is the memory in bytes of an int[] that holds one entry for each of those masks, counting 4 bytes per entry and ignoring the array header.

Input Constraints. The limits are:

  • Item count satisfies 0 <= n <= 30.
  • Result is a long[] of length 3, because the byte count exceeds the int range for large n.
  • Mutation is not applicable, because the method has no array input.

Example 1. Input n = 3, output [7, 8, 32].

Example 2. Input n = 0, output [0, 1, 4].

Prerequisites. The two exercises above.

What This Exercise Changes. The loop bound is the full mask and not 1 << n minus one by hand, so n = 0 gives a single state and n = 30 needs long arithmetic for the byte count.

Hint

Which type must hold the shift, and what does 1 << 31 produce in an int?

Algorithmic Solution (attempt the problem first)

Approach. The full mask for n items has bits 0 to n - 1 set, so it equals (1 << n) - 1. The masks from 0 to the full mask number 1 << n, which is full + 1. Each state needs 4 bytes in an int[], so the byte count is the state count times 4. For n = 30 the state count is 1,073,741,824 and the byte count is 4,294,967,296, which exceeds Integer.MAX_VALUE. The method therefore computes every value as a long, with 1L << n.

The invariant is that the three returned values satisfy states = full + 1 and bytes = 4 * states. For n = 0 the full mask is 0 and the single state is the empty set.

Complexity.

  • Time is O(1), because the method does three arithmetic operations.
  • Space is O(1), because it returns three numbers.
import java.util.*;

public final class Dp29FullMaskCount {
    /**
     * Returns {full mask, state count, bytes of an int table with one entry per state}.
     * Time: O(1). Space: O(1).
     * Invariant: states = full + 1 and bytes = 4 * states, all in long arithmetic.
     */
    static long[] budget(int n) {
        // A long shift avoids the int overflow that begins at bit 31.
        long states = 1L << n;
        // The full mask has bits 0 to n - 1 set, which is one less than the state count.
        long full = states - 1;
        // Each int entry takes 4 bytes.
        long bytes = 4 * states;
        return new long[]{full, states, bytes};
    }

    /** Oracle: counts masks by looping, and builds the full mask by setting bits one at a time. */
    static long[] oracle(int n) {
        long count = 0;
        for (int mask = 0; mask < (1 << n); mask++) count++;
        long full = 0;
        for (int i = 0; i < n; i++) full |= 1L << i;
        return new long[]{full, count, 4 * count};
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(budget(3), new long[]{7, 8, 32})) throw new AssertionError("ex1");
        if (!Arrays.equals(budget(0), new long[]{0, 1, 4})) throw new AssertionError("ex2");
        // The largest allowed n needs a byte count above the int range.
        long[] big = budget(30);
        if (big[2] != 4294967296L || big[2] <= Integer.MAX_VALUE) throw new AssertionError("big");
        // An int shift of 31 reaches the sign bit, and an int shift of 32 wraps to a shift of 0.
        if ((1 << 31) >= 0) throw new AssertionError("int 31");
        if ((1 << 32) != 1) throw new AssertionError("int 32");
        if ((1L << 31) != 2147483648L) throw new AssertionError("long 31");
        // The int full mask for n = 30 is still positive.
        if (((1 << 30) - 1) != 1073741823) throw new AssertionError("full 30");
        // Small n against the counting oracle.
        for (int n = 0; n <= 20; n++) {
            if (!Arrays.equals(budget(n), oracle(n))) throw new AssertionError("n " + n);
        }
    }

Partition To K Equal Sum Subsets

LeetCode 698

Problem Specification. An integer array nums and an integer k are given. Return true if the numbers can be split into k nonempty groups with the same sum, using every number exactly once. Return false otherwise.

Input Constraints. The limits are:

  • Length satisfies 1 <= k <= nums.length <= 16.
  • Values satisfy 1 <= nums[i] <= 10000.
  • Result is a boolean.
  • Mutation of nums is not required.

Example 1. Input nums = [2, 2, 2, 3, 3], k = 2, output true.

Example 2. Input nums = [5, 5, 5, 5, 2, 2], k = 3, output false.

Prerequisites. All three exercises above.

What This Exercise Changes. The state has two parts, the set of placed numbers and the fill of the group in progress, and the fill is stored as the remainder of the mask's sum divided by t.

Hint

If the target sum is t, how full is the current group after the numbers in a mask are placed, and can that be stored as one number per mask?

Algorithmic Solution (attempt the problem first)

Approach. Let total be the sum of nums. If total is not divisible by k, the answer is false. Otherwise the target is t = total / k, and a number larger than t makes the answer false. Entry fill[mask] stores the fill of the group in progress after the numbers in mask are placed, as sum(mask) % t, or -1 when the placement is impossible. The set of placed numbers is the mask, and the fill is the second state part.

From a reachable mask, the method tries each unplaced number j. It is allowed when fill[mask] + nums[j] <= t. The new fill is (fill[mask] + nums[j]) % t, which becomes 0 when a group closes exactly. The invariant is that every reachable mask has placed numbers whose sum is groups * t + fill, with all closed groups equal to t. The answer is true when fill[full] is 0, which means the last group also closed.

Complexity.

  • Time is O(n * 2^n), because each of the 2^n masks tries at most n numbers.
  • Space is O(2^n) for the fill array.
import java.util.*;

public final class Dp29PartitionKSubsets {
    /**
     * Returns true when nums splits into k groups with equal sums.
     * Time: O(n * 2^n). Space: O(2^n).
     * Invariant: fill[mask] is the sum of the open group, or -1 when mask cannot be placed.
     */
    static boolean canPartition(int[] nums, int k) {
        int n = nums.length;
        int total = 0;
        for (int x : nums) total += x;
        // A total that k cannot divide rules out equal groups.
        if (total % k != 0) return false;
        int t = total / k;
        // One entry per set of placed numbers; -1 marks an impossible set.
        int[] fill = new int[1 << n];
        Arrays.fill(fill, -1);
        fill[0] = 0;
        // Counting up visits every set after all of its subsets.
        for (int mask = 0; mask < (1 << n); mask++) {
            // Unreachable sets cannot extend.
            if (fill[mask] < 0) continue;
            // Try each unplaced number as the next one in the open group.
            for (int j = 0; j < n; j++) {
                if ((mask >> j & 1) == 0 && fill[mask] + nums[j] <= t) {
                    // The remainder is 0 exactly when the open group reaches t and closes.
                    fill[mask | (1 << j)] = (fill[mask] + nums[j]) % t;
                }
            }
        }
        // All numbers placed and no open group left means every group has sum t.
        return fill[(1 << n) - 1] == 0;
    }

    /** Oracle: assigns each number to one of k groups in every possible way and compares the sums. */
    static boolean oracle(int[] nums, int k) {
        int n = nums.length;
        int combos = 1;
        for (int i = 0; i < n; i++) combos *= k;
        for (int code = 0; code < combos; code++) {
            int[] sums = new int[k];
            boolean[] used = new boolean[k];
            int c = code;
            for (int i = 0; i < n; i++) {
                sums[c % k] += nums[i];
                used[c % k] = true;
                c /= k;
            }
            boolean ok = true;
            for (int g = 0; g < k; g++) if (!used[g] || sums[g] != sums[0]) ok = false;
            if (ok) return true;
        }
        return false;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!canPartition(new int[]{2, 2, 2, 3, 3}, 2)) throw new AssertionError("ex1");
        if (canPartition(new int[]{5, 5, 5, 5, 2, 2}, 3)) throw new AssertionError("ex2");
        // One group always works, and an indivisible total never does.
        if (!canPartition(new int[]{4}, 1)) throw new AssertionError("single");
        if (canPartition(new int[]{1, 2, 3, 4}, 3)) throw new AssertionError("indivisible");
        // The remainder operator returns 0 when a group closes exactly.
        if ((4 + 2) % 6 != 0 || (4 + 1) % 6 != 5) throw new AssertionError("remainder");
        // Random inputs against the assignment oracle.
        Random rnd = new Random(2903);
        for (int t = 0; t < 1500; t++) {
            int n = 1 + rnd.nextInt(7);
            int k = 1 + rnd.nextInt(Math.min(3, n));
            int[] nums = new int[n];
            for (int i = 0; i < n; i++) nums[i] = 1 + rnd.nextInt(5);
            if (canPartition(nums, k) != oracle(nums, k)) throw new AssertionError("random " + t);
        }
    }

Problem

Trying Every Flag Combination

A configuration service stores the enabled feature flags of one customer as the bits of an int. The customer has flags 0, 2 and 3 enabled, so the mask is 1101 in binary, which is 13. A test planner must run the product once for every nonempty combination of those three flags. There are 7 combinations: 13, 12, 9, 8, 5, 4 and 1.

A developer writes the obvious scan. It counts s from 1 up to the mask and keeps s when s & mask == s, which means every set bit of s is also set in the mask. For the mask 13 the scan makes 13 steps to find 7 combinations, and nobody notices the waste.

The waste appears when the enabled flags sit at high positions. A customer with only flags 0 and 29 enabled has 3 combinations, but the scan counts up to more than half a billion. The same pattern appears in every problem that splits a set of up to 20 items into two groups.

Formally, the input is one non-negative int called mask. A subset of the mask is an int whose set bits all lie among the set bits of the mask. The task is to visit every nonempty subset exactly once. This lesson asks how to reach each one in constant work, so the cost depends on the number of enabled flags and not on their positions.

Simple approach

Counting Up And Filtering

The simple method tries every integer from 1 to mask and keeps those that pass the filter. It never looks at which bits the mask contains.

static int countByScan(int mask) {
    int found = 0;
    for (int s = 1; s <= mask; s++) {
        if ((s & mask) == s) {
            found++;
        }
    }
    return found;
}

The loop makes mask iterations, so the cost is O(mask) time with O(1) memory. A mask is as large as its highest set bit, so the cost grows with the position of the top flag and not with the number of flags. The method is correct. It is slow only because most of the integers it tries fail the filter.

Bottleneck

The Scan Ignores The Mask Bits

The scan spends one iteration per integer, and a mask with k set bits has only 2^k subsets. The ratio of wasted work to useful work is about mask / 2^k. A mask of 30 bits with 2 set bits wastes about 2^30 iterations to reach 3 results.

The cost grows when a dynamic program needs the subsets of every mask. Such a program loops over all masks from 0 to 2^n - 1 and runs the scan inside each one. The total is the sum of the mask values, which is about 2^n * 2^n / 2, so the cost is O(4^n). For n = 20 that is more than 10^12 steps, which no judge accepts.

Most of those steps are wasted. A mask with k set bits has only 2^k subsets, and the sum of 2^k over all masks is 3^n. Each of the n items is in the subset, in the rest of the mask, or outside the mask, which gives 3 choices per item. For n = 20 the number is 3486784401, about 300 times smaller than 4^20. The next section shows how to step directly from one subset to the next, so the work matches the number of subsets.

Key idea

Step Down To The Next Subset

Name the subsets, then find one operation that moves from a subset to the next smaller one. With that operation, a loop visits only real subsets.

A Submask Is A Subset Of Bits

A submask of mask is an integer sub with sub & mask == sub. Every submask is at most mask, and the mask itself is its largest submask. If the mask has k set bits, it has exactly 2^k submasks, including 0, because each set bit is either kept or dropped.

The Descending Step

The descending step computes (sub - 1) & mask from a submask sub. Subtracting 1 clears the lowest set bit of sub, call its position p, and sets every bit below p. The AND with mask then removes the bits that are not in the mask. The result is sub with bit p replaced by all the mask bits below p.

This value is the next smaller submask. Any submask that is smaller than sub either differs from sub at a bit above p, which makes it smaller than the result, or agrees with sub above p and uses only mask bits below p, which makes it at most the result. Starting from mask, the loop therefore meets each submask once, in strictly decreasing order, and it reaches 0 last.

Stop At Zero On Purpose

The value 0 is a submask, but the standard loop treats it as the end. In Java, 0 - 1 is -1, whose bits are all set, so (0 - 1) & mask equals mask. A loop that continues after 0 returns to the start and never ends. The condition sub > 0 ends the loop and skips the empty submask. A loop that must include 0 handles it with its own check before it computes the next value.

Split A Mask Into Two Parts

A submask sub also names a split. The pair sub and mask ^ sub divides the set bits of mask into two disjoint parts. A dynamic program that combines dp[sub] with dp[mask ^ sub] reads only values with a smaller mask number, so it fills dp in increasing mask order. Each mask costs 2^k steps, and the total over all masks is O(3^n).

Sum Over Subsets With Bit Layers

Some problems need, for every mask, the sum of a[sub] over all of its submasks. Enumerating them costs O(3^n). A bit layer reduces this to O(n * 2^n). Layer b visits every mask that has bit b set and adds the value of the mask with bit b cleared. After layer b, f[mask] holds the sum over the submasks that differ from mask only in bits 0 to b. After all n layers, every submask has been counted exactly once.

State

Masks, Submasks And Tables

These values appear in the loops and tables of this lesson.

  • mask is the int whose set bits form the full set.
  • sub is the current submask of mask, and sub & mask == sub holds at every step.
  • rest is mask ^ sub, the part of the mask that sub leaves out.
  • dp is an int[1 << n]; entry dp[mask] is the best answer for the items named by mask.
  • f is a long[1 << n] that holds a at the start and the sum over submasks at the end.
  • bit is the index of the current bit layer, from 0 to n - 1.

Java stores an int in 32 bits, and 1 << b has only bit b set. A mask for n items therefore uses bits 0 to n - 1, and the arrays have 1 << n entries. A sum over up to 2^n values can exceed the int range, so f uses long.

Code

Three Loops Over Submasks

The first method returns all nonempty submasks of a mask in decreasing order. The second method fills the grouping table from the trace. The third method sums over all submasks with one pass per bit.

static int[] listSubmasks(int mask) {
    int[] out = new int[(1 << Integer.bitCount(mask)) - 1];
    int w = 0;
    for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
        out[w++] = sub;
    }
    return out;
}

static int minGroups(int[] weight, int cap) {
    int n = weight.length;
    int[] total = new int[1 << n];
    int[] dp = new int[1 << n];
    for (int mask = 1; mask < (1 << n); mask++) {
        int low = Integer.numberOfTrailingZeros(mask);
        total[mask] = total[mask & (mask - 1)] + weight[low];
        dp[mask] = total[mask] <= cap ? 1 : Integer.MAX_VALUE;
        for (int sub = (mask - 1) & mask; sub > 0; sub = (sub - 1) & mask) {
            dp[mask] = Math.min(dp[mask], dp[sub] + dp[mask ^ sub]);
        }
    }
    return dp[(1 << n) - 1];
}

static long[] sumOverSubmasks(long[] a, int n) {
    long[] f = a.clone();
    for (int bit = 0; bit < n; bit++) {
        for (int mask = 0; mask < (1 << n); mask++) {
            if ((mask >> bit & 1) == 1) {
                f[mask] += f[mask ^ (1 << bit)];
            }
        }
    }
    return f;
}

The first method runs in O(2^k) time for a mask with k set bits. The second runs in O(3^n) time and O(2^n) memory, and it assumes every weight is at most cap. The third runs in O(n * 2^n) time. In the second method, mask & (mask - 1) clears the lowest set bit, which lets each total reuse a smaller one. The inner loop starts at (mask - 1) & mask, which skips mask itself, and it stops at 0, which skips the empty part.

When to use it

Recognizing Subset Splits

Reading The Cue

Use this method when a transition or a query ranges over every subset of a mask. Phrases such as "split the set into two groups", "for every subset of the chosen items" and "sum over all subsets" point here. The bit count n must stay small, usually at most 20, because 3^n is the cost of full enumeration.

Checking The Invariant

The invariant of the descending step is that every submask below the current one is still ahead, and none has been skipped or repeated. Check it on a mask with one bit, which must report that bit only. Check it on a mask with spread bits, such as 100001, which must report 3 values. Check that a mask of 0 reports nothing. For the table, the invariant is that both dp[sub] and dp[mask ^ sub] are final when dp[mask] reads them, because both have smaller mask numbers.

Avoiding The False Friend

The first false friend is the counting scan from the opening, which gives correct output at a cost that depends on the highest bit. The second is a loop written sub >= 0, which never ends, because -1 & mask equals mask. The third is a split that visits both sub and mask ^ sub as separate cases and counts every pair twice. When the pair is unordered, the loop can fix the lowest bit of mask inside sub.

The method does not apply when n is above about 22, because 3^n is too large, or when the groups are not drawn from one shared set of items. In those cases a different state or a greedy argument is needed.

Hint

Which value comes after sub, and where does the loop stop?

Algorithmic Solution (attempt the problem first)

Approach. The loop starts at mask, which is its own largest submask. After each report it replaces sub by (sub - 1) & mask. Subtracting 1 clears the lowest set bit and sets the bits below it, and the AND keeps only the bits that belong to the mask. The result is the next smaller submask.

The invariant is that every submask smaller than the current sub is still ahead, and every larger one has been reported once. The loop condition sub > 0 stops at the empty submask, which the problem excludes. The output length is known in advance as 2^k - 1, with k = Integer.bitCount(mask).

  • Time is O(2^k) for k set bits, because each iteration reports one submask with constant work.

import java.util.*;

public final class Dp29EnumerateSubmasks {
    /**
     * Returns all nonempty submasks of mask in decreasing order.
     * Time: O(2^k) for k set bits. Space: O(2^k) for the result.
     * Invariant: every submask below sub is still ahead and none is repeated.
     */
    static int[] submasks(int mask) {
        // The count of nonempty submasks is 2^k - 1, so the array has the exact size.
        int[] out = new int[(1 << Integer.bitCount(mask)) - 1];
        int w = 0;
        // The loop starts at the largest submask and stops before the empty one.
        for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
            // Each iteration reports one submask, which costs constant time.
            out[w++] = sub;
        }
        return out;
    }

    /** Oracle: scans every integer up to mask and keeps those with all bits inside the mask. */
    static int[] oracle(int mask) {
        List<Integer> all = new ArrayList<>();
        for (int s = mask; s >= 1; s--) if ((s & mask) == s) all.add(s);
        int[] r = new int[all.size()];
        for (int i = 0; i < r.length; i++) r[i] = all.get(i);
        return r;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(submasks(13), new int[]{13, 12, 9, 8, 5, 4, 1})) throw new AssertionError("ex1");
        if (!Arrays.equals(submasks(6), new int[]{6, 4, 2})) throw new AssertionError("ex2");
        // A zero mask has no nonempty submask.
        if (submasks(0).length != 0) throw new AssertionError("zero");

        int iterations = 0;
        int mask = (1 << 20) | 1;
        for (int s = 1; s <= mask; s++) iterations++;

        // Subtracting 1 from 12 gives 1011, and the AND with 1101 gives 1001, which is 9.
        if (((12 - 1) & 13) != 9) throw new AssertionError("step");

        Random rnd = new Random(2905);
        for (int t = 0; t < 2000; t++) {
            int m = rnd.nextInt(1 << 12);
            if (!Arrays.equals(submasks(m), oracle(m))) throw new AssertionError("random " + m);
        }
    }

Partition A Mask

Author exercise

Problem Specification. An array weight of n positive integers and an integer cap are given. Split the items into groups so that the weights in each group sum to at most cap. Return the smallest possible number of groups.

Input Constraints. The limits are:

  • Items satisfy 1 <= n <= 12.
  • Weights satisfy 1 <= weight[i] <= cap.
  • Capacity satisfies 1 <= cap <= 10^6.
  • Result is an int, and the array stays unchanged.

Example 1. Input weight = [4, 3, 3, 2], cap = 6, output 2.

Example 2. Input weight = [5, 5, 5], cap = 9, output 3.

Prerequisites. The exercise above.

What This Exercise Changes. The loop now combines two stored answers for each split in place of listing the parts, so each mask uses its proper submasks.

Hint

Which two table entries does a split of a mask into sub and mask ^ sub read?

Algorithmic Solution (attempt the problem first)

Approach. Entry dp[mask] is the smallest number of groups for the items named by mask. If the total weight of mask is at most cap, one group holds all of them, so the entry is 1. Otherwise some group in an optimal answer contains a proper part of the mask, and the rest forms the other part. The entry is the minimum of dp[sub] + dp[mask ^ sub] over every proper nonempty sub.

The invariant is that sub and mask ^ sub are both smaller than mask as numbers, so their entries are final when mask is processed in increasing order. The total weight of each mask comes from the mask without its lowest bit, which costs constant time per mask. Every weight is at most cap, so each single item fits and every entry is finite.

Complexity.

  • Time is O(3^n), because the proper submasks of all masks together number at most 3^n.
  • Space is O(2^n) for the two tables, and the input array stays unchanged.
import java.util.*;

public final class Dp29PartitionMask {
    /**
     * Returns the smallest number of groups whose weight sums stay within cap.
     * Time: O(3^n). Space: O(2^n).
     * Invariant: dp[sub] and dp[mask ^ sub] are final before dp[mask] reads them.
     */
    static int groups(int[] weight, int cap) {
        // n items give 2^n masks, one table entry for each.
        int n = weight.length;
        int[] sum = new int[1 << n];
        int[] dp = new int[1 << n];
        // Masks grow from 1, so every smaller mask is final when read.
        for (int mask = 1; mask < (1 << n); mask++) {
            // The mask without its lowest bit is smaller, so its sum is already known.
            int lowest = Integer.numberOfTrailingZeros(mask);
            sum[mask] = sum[mask & (mask - 1)] + weight[lowest];
            // A mask that fits the capacity needs one group; otherwise start from a large value.
            dp[mask] = sum[mask] <= cap ? 1 : Integer.MAX_VALUE / 2;
            // The proper submasks start below mask and stop before 0.
            for (int sub = (mask - 1) & mask; sub > 0; sub = (sub - 1) & mask) {
                // Combine the answer for sub with the answer for the remaining items.
                dp[mask] = Math.min(dp[mask], dp[sub] + dp[mask ^ sub]);
            }
        }
        // The full mask names every item.
        return dp[(1 << n) - 1];
    }

    /** Oracle: places each item into an existing group or a new group, trying every choice. */
    static int oracle(int[] w, int cap, int i, List<Integer> loads) {
        if (i == w.length) return loads.size();
        int best = Integer.MAX_VALUE;
        for (int g = 0; g < loads.size(); g++) {
            if (loads.get(g) + w[i] <= cap) {
                loads.set(g, loads.get(g) + w[i]);
                best = Math.min(best, oracle(w, cap, i + 1, loads));
                loads.set(g, loads.get(g) - w[i]);
            }
        }
        loads.add(w[i]);
        best = Math.min(best, oracle(w, cap, i + 1, loads));
        loads.remove(loads.size() - 1);
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (groups(new int[]{4, 3, 3, 2}, 6) != 2) throw new AssertionError("ex1");
        if (groups(new int[]{5, 5, 5}, 9) != 3) throw new AssertionError("ex2");
        // One item needs one group, and mask & (mask - 1) clears the lowest set bit.
        if (groups(new int[]{7}, 7) != 1) throw new AssertionError("single");
        if ((12 & 11) != 8 || Integer.numberOfTrailingZeros(12) != 2) throw new AssertionError("bit facts");
        // Random instances against the assignment oracle.
        Random rnd = new Random(2906);
        for (int t = 0; t < 1500; t++) {
            int n = 1 + rnd.nextInt(8);
            int cap = 1 + rnd.nextInt(12);
            int[] w = new int[n];
            for (int i = 0; i < n; i++) w[i] = 1 + rnd.nextInt(cap);
            int[] copy = w.clone();
            if (groups(w, cap) != oracle(w, cap, 0, new ArrayList<>())) throw new AssertionError("random " + t);
            if (!Arrays.equals(copy, w)) throw new AssertionError("mutation");
        }
    }

Include Empty Submask Deliberately

Author exercise

Problem Specification. An integer mask is given. Return all submasks of mask, including 0, in decreasing order.

Input Constraints. The limits are:

  • Value satisfies 0 <= mask < 2^20, and mask may be 0.
  • Result is an int[] of length 2^k, where k is the number of set bits, and its last entry is 0.
  • Order is strictly decreasing.
  • Termination is required for every allowed mask, including 0.

Example 1. Input mask = 5, output [5, 4, 1, 0].

Example 2. Input mask = 0, output [0].

Prerequisites. The two exercises above.

What This Exercise Changes. The loop reports the empty submask, so it must test for 0 before it computes the next value.

Hint

What does (0 - 1) & mask equal in Java, and where must the check for 0 sit?

Algorithmic Solution (attempt the problem first)

Approach. The standard loop ends at 0 because sub > 0 fails there. This exercise needs 0 in the output, so the loop reports sub first and then checks for 0. Java computes 0 - 1 as -1, whose bits are all set, so (0 - 1) & mask equals mask. A loop that moves on from 0 returns to the start and never ends. The explicit break prevents that.

The invariant is that every submask larger than the current one has been reported, and the current one is reported before the stop test. Mask 0 reports [0] and stops at once. The result has 2^k entries.

Complexity.

  • Time is O(2^k) for k set bits, because each submask costs constant work, including the final 0.
  • Space is O(2^k) for the result array.
import java.util.*;

public final class Dp29IncludeEmpty {
    /**
     * Returns every submask of mask including 0, in decreasing order.
     * Time: O(2^k) for k set bits. Space: O(2^k).
     * Invariant: the current submask is reported before the stop test, so 0 appears last.
     */
    static int[] withEmpty(int mask) {
        // There are 2^k submasks including the empty one.
        int[] out = new int[1 << Integer.bitCount(mask)];
        int w = 0;
        int sub = mask;
        // The loop is open-ended on purpose, and the break below is the only exit.
        while (true) {
            // Report first, so that sub = 0 is also reported.
            out[w++] = sub;
            // Stop at 0, because the next step from 0 would return to mask.
            if (sub == 0) break;
            // Move to the next smaller submask.
            sub = (sub - 1) & mask;
        }
        return out;
    }

    /** Oracle: scans every integer from mask down to 0 and keeps the submasks. */
    static int[] oracle(int mask) {
        List<Integer> all = new ArrayList<>();
        for (int s = mask; s >= 0; s--) if ((s & mask) == s) all.add(s);
        int[] r = new int[all.size()];
        for (int i = 0; i < r.length; i++) r[i] = all.get(i);
        return r;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(withEmpty(5), new int[]{5, 4, 1, 0})) throw new AssertionError("ex1");
        if (!Arrays.equals(withEmpty(0), new int[]{0})) throw new AssertionError("ex2");
        // In Java, 0 - 1 is -1, and -1 & mask equals mask, so a loop that continues after 0 repeats.
        for (int mask : new int[]{1, 5, 13, 1000}) {
            if (((0 - 1) & mask) != mask) throw new AssertionError("wrap " + mask);
        }
        // The condition sub >= 0 on an int never fails, because the value returns to mask.
        int sub = 5, steps = 0;
        while (sub >= 0 && steps < 10) { sub = (sub - 1) & 5; steps++; }
        if (steps != 10) throw new AssertionError("no end");
        // Random masks against the scan oracle.
        Random rnd = new Random(2907);
        for (int t = 0; t < 2000; t++) {
            int m = rnd.nextInt(1 << 12);
            if (!Arrays.equals(withEmpty(m), oracle(m))) throw new AssertionError("random " + m);
        }
    }

SOS Subset Sums

Author exercise

Problem Specification. An integer n and an array a of length 2^n are given. Return an array f of length 2^n where f[mask] is the sum of a[sub] over all submasks sub of mask, including 0 and mask.

Input Constraints. The limits are:

  • Size satisfies 0 <= n <= 16.
  • Values satisfy 0 <= a[i] <= 10^6.
  • Result is a long[], because a sum can exceed the int range.
  • Mutation is not allowed, so the input array stays unchanged.

Example 1. Input n = 2, a = [1, 2, 3, 4], output [1, 3, 4, 10].

Example 2. Input n = 3, a = [3, 1, 4, 1, 5, 9, 2, 6], output [3, 4, 7, 9, 8, 18, 14, 31].

Prerequisites. All three exercises above.

What This Exercise Changes. The query covers every mask at once, so the method adds one bit layer at a time in place of listing submasks for each mask.

Hint

Add the values one bit at a time, so that after layer b the sums cover only changes in bits 0 to b.

Algorithmic Solution (attempt the problem first)

Approach. The array f starts as a copy of a. The method then processes the bits one at a time. In layer bit, every mask that has that bit set adds the current value of the mask with that bit cleared. After layer bit, f[mask] holds the sum of a[sub] over submasks that differ from mask only in bits 0 to bit.

The invariant is the sentence above, and it holds by induction on the layer. A submask that has the bit cleared is reached through the added entry, and a submask that keeps the bit is already in the old value. The layer reads an entry with the bit cleared, which the layer never changes, so the in-place update is safe. After the last layer every submask is counted once. Sums use long, since 2^16 values of 10^6 exceed the int range.

Complexity.

  • Time is O(n * 2^n), because each of the n layers visits 2^n masks with constant work.
  • Space is O(2^n) for the result, and the input array stays unchanged.
import java.util.*;

public final class Dp29SosSubsetSums {
    /**
     * Returns f where f[mask] is the sum of a[sub] over all submasks of mask.
     * Time: O(n * 2^n). Space: O(2^n).
     * Invariant: after layer b, f[mask] sums the submasks that differ from mask only in bits 0..b.
     */
    static long[] sums(int n, int[] a) {
        // The copy keeps the input unchanged and widens each value to long.
        long[] f = new long[1 << n];
        for (int i = 0; i < f.length; i++) f[i] = a[i];
        // Each layer handles one bit, so n layers run.
        for (int b = 0; b < n; b++) {
            // Every mask is visited once per layer, which costs 2^n.
            for (int mask = 0; mask < (1 << n); mask++) {
                // Only masks with bit b set receive a contribution.
                if ((mask & (1 << b)) != 0) {
                    // The partner has bit b cleared, so this layer does not change it.
                    f[mask] += f[mask ^ (1 << b)];
                }
            }
        }
        return f;
    }

    /** Oracle: enumerates the submasks of each mask, including 0. */
    static long[] oracle(int n, int[] a) {
        long[] f = new long[1 << n];
        for (int mask = 0; mask < (1 << n); mask++) {
            long s = 0;
            for (int sub = mask; ; sub = (sub - 1) & mask) {
                s += a[sub];
                if (sub == 0) break;
            }
            f[mask] = s;
        }
        return f;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(sums(2, new int[]{1, 2, 3, 4}), new long[]{1, 3, 4, 10})) throw new AssertionError("ex1");
        if (!Arrays.equals(sums(3, new int[]{3, 1, 4, 1, 5, 9, 2, 6}), new long[]{3, 4, 7, 9, 8, 18, 14, 31})) throw new AssertionError("ex2");
        // With n = 0 the table has one entry, which is a[0].
        if (!Arrays.equals(sums(0, new int[]{7}), new long[]{7})) throw new AssertionError("n zero");
        // The largest allowed sum exceeds the int range, so long is required.
        long big = (1L << 16) * 1_000_000L;
        if (big <= Integer.MAX_VALUE) throw new AssertionError("range");
        // Random arrays against the enumeration oracle, with a check that the input is unchanged.
        Random rnd = new Random(2908);
        for (int t = 0; t < 500; t++) {
            int n = rnd.nextInt(8);
            int[] a = new int[1 << n];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(1_000_001);
            int[] copy = a.clone();
            if (!Arrays.equals(sums(n, a), oracle(n, a))) throw new AssertionError("random " + t);
            if (!Arrays.equals(copy, a)) throw new AssertionError("mutation");
        }
        // The full table at n = 16 with maximal values stays exact.
        int[] full = new int[1 << 16];
        Arrays.fill(full, 1_000_000);

Problem

Counting Codes Below A Limit

A registration system issues numeric codes. Staff dislike the digit 0 because it looks like the letter O on printed labels, so the system must never use a code that contains a 0. A manager asks how many valid codes exist among the integers from 1 to 3047. The answer must come back instantly, and the same question will soon arrive with limits near 10^18.

A first script checks every integer one at a time. It works for 3047 and stalls for 10^18, because the loop body would run a billion billion times.

Formally, the input is a non-negative integer n. The task is to count the integers x with 1 <= x <= n whose decimal representation has no digit 0. The decimal representation of x has no leading zeros, so the integer 105 contains a 0 and the integer 15 does not. The input is read and never changed.

This lesson asks how to count such integers by looking at the digits of n once, and not at the integers themselves.

Simple approach

Testing Every Integer In The Range

The direct method loops over every integer from 1 to n. It converts each integer to text and rejects it when the text contains the character '0'.

static long countByLoop(long n) {
    long total = 0;
    for (long x = 1; x <= n; x++) {
        if (Long.toString(x).indexOf('0') < 0) {
            total++;
        }
    }
    return total;
}

For n = 3047 the loop makes 3047 checks and finds 2277 valid codes. Each check costs O(d) time, where d is the number of digits of x, so the whole method runs in O(n * d) time and uses O(d) memory for the text.

Predict first: Suppose one check takes one nanosecond and n is 10^18. About how long does countByLoop run?

About 10^9 seconds, which is roughly 30 years. The cost grows with the value of n, and not with the number of digits of n. Doubling the number of digits squares the work.

Bottleneck

Cost Grows With The Value Of n

The failure has one cause. The loop count equals the size of the range, and the size of the range is exponential in the number of digits. A number with 18 digits can reach 10^18, so the loop needs O(10^d) steps for d digits. The answer itself only depends on a short string of d digits.

A smarter method builds valid numbers digit by digit. It chooses a first digit, then a second, and so on, and it stops when a prefix already exceeds n. That method still visits one path for every valid number below the limit. Valid numbers with no digit 0 number about 9^d, so the visits still run in O(9^d) time. For d = 18 that is more than 10^17 paths.

The paths repeat their work. Take the prefixes 12 and 21. Each has two digits, each contains no 0, and each is already below the first two digits of a large n. The remaining digits can be chosen the same way after both prefixes, so the count of completions is identical. The next section defines the facts a prefix needs to remember, so equal prefixes share one answer and the work becomes O(d) steps.

Key idea

Remember Only Two Facts About A Prefix

A prefix of a number matters for the future in only two ways. It decides which next digits keep the number at or below n. It also decides whether the zero rule applies yet. Everything else about the prefix, such as which exact digits it holds, does not change the count of completions.

The Tight Flag Limits The Next Digit

Write n as digits n[0], n[1], up to n[d - 1], and process positions from left to right. A prefix is tight when it equals the first p digits of n. The tight flag is 1 for such a prefix and 0 otherwise. A tight prefix may place only digits from 0 up to n[p] at position p. A prefix that already sits below n may place any digit from 0 to 9.

After a digit is placed, the flag stays 1 only when the prefix was tight and the new digit equals n[p]. If the digit is smaller, the number is already below n, and the flag becomes 0 for good.

The Started Flag Handles Leading Zeros

To compare numbers of different lengths, the method writes every number with exactly d digits and pads short numbers with zeros on the left. Those padding zeros are not part of the number, so the zero rule must ignore them. The started flag is 1 once a nonzero digit has been placed. While the flag is 0, a digit 0 is padding and stays allowed. Once the flag is 1, a digit 0 is a real digit and the zero rule forbids it.

One Cell For Each Combination

The two flags give four combinations. Let ways[t][s] count the prefixes of the current length with tight flag t and started flag s. This ways table is the whole state, and it has 4 entries. At each position, every entry spreads its count to the entries of the next position, one transition for each allowed digit.

The invariant is that after p positions, ways[t][s] equals the number of distinct digit prefixes of length p that satisfy the zero rule, are not above the first p digits of n, and have those exact flags. The final answer adds ways[0][1] and ways[1][1], because the all-padding prefix stands for the integer 0, which the range excludes.

State

The Digits And The Four Counts

The input is a number, and these working values describe the pass over its digits.

  • digits is an int[] that holds the decimal digits of n, with digits[0] as the leading digit.
  • p is the position being processed, from 0 to d - 1.
  • ways is a long[2][2]; entry ways[t][s] counts the prefixes with tight flag t and started flag s.
  • next is a fresh long[2][2] for position p + 1, filled from ways.
  • limit is digits[p] when t is 1 and 9 when t is 0, the largest digit the prefix may place.

Java fills a new long array with zeros, so next starts empty without extra code. The counts are long because the answer for a number with 18 digits is near 9^18, which exceeds the int range. In the trace below, t1s0 is the name used for ways[1][0], and the other three names follow the same pattern.

Code

Spreading Counts Across Four Entries

The method returns how many integers from 1 to n have no digit 0. It reads the digits of n once and keeps only the four counts.

static long countZeroFree(long n) {
    int[] digits = Long.toString(n).chars().map(c -> c - '0').toArray();
    long[][] ways = new long[2][2];
    ways[1][0] = 1;
    for (int p = 0; p < digits.length; p++) {
        long[][] next = new long[2][2];
        for (int t = 0; t < 2; t++) {
            for (int s = 0; s < 2; s++) {
                if (ways[t][s] == 0) continue;
                int limit = t == 1 ? digits[p] : 9;
                for (int dig = 0; dig <= limit; dig++) {
                    if (s == 1 && dig == 0) continue;
                    int nt = (t == 1 && dig == limit) ? 1 : 0;
                    int ns = (s == 1 || dig != 0) ? 1 : 0;
                    next[nt][ns] += ways[t][s];
                }
            }
        }
        ways = next;
    }
    return ways[0][1] + ways[1][1];
}

The loops run d positions, four entries and at most ten digits, so the time is O(d * 4 * 10), which is O(d). The memory is O(d) for the digit array plus constant space for the two small tables. For n = 0 the digit array holds the single digit 0, the started count stays 0, and the method returns 0. The exercises below remove the flags one at a time and then add them back.

When to use it

Recognizing Counts Under A Bound

Reading The Cue

Use this method when a question asks how many integers up to a bound satisfy a rule on their digits. Phrases such as "at most n", "no digit equal to", "digit sum" and "digits taken from a set" point here. The state is the position plus a tight flag plus a started flag, and a rule may add one more small fact, such as a running digit sum or the previous digit.

Checking The Invariant

The invariant says that each state summarizes every prefix with the same flags and the same extra fact, and that no prefix is counted twice or lost. Test a bound with one digit, such as 7. Test a bound that is a power of ten, such as 1000, where every tight prefix dies early. Test the bound 0, which must return 0. Compare the method against the loop on every bound up to a few thousand.

Avoiding The False Friend

The first false friend is a table that counts only numbers with exactly d digits, which misses every shorter number because the started flag is gone. The second is a table that never lets the tight flag expire, which counts numbers above the bound. The third is a rule that treats padding zeros as real digits, which rejects every number shorter than n. The method does not apply when the rule compares digits far apart with no small summary, because the extra fact then grows too large to store as a state.

Count Fixed-Length Digit Strings

Input Constraints. The limits are:

  • Result is a long.
  • Mutation is not allowed, because strings are immutable.

Example 1. Input len = 4, allowed = "024", output 81.

Example 2. Input len = 3, allowed = "1357", output 64.

Prerequisites. The ways table from this lesson, without the two flags.

What This Exercise Changes. The table has no tight or started state, so every position offers the same choices.

Hint

If ways[p] counts the valid strings of length p, how many choices does position p have?

Algorithmic Solution (attempt the problem first)

Approach. Let ways[p] be the number of valid strings of length p. The empty string is valid, so ways[0] is 1. Each position accepts every character of allowed, whatever came before, so ways[p + 1] equals ways[p] times the size of allowed. No flag is needed here, because no position depends on an earlier choice.

The invariant is that ways[p] counts distinct strings of length p over allowed, and each string of length p + 1 is one string of length p followed by one allowed character. The answer is ways[len].

Complexity.

  • Time is O(len), because the loop makes one multiplication for each position.
  • Space is O(len) for the array, and a single running product would reduce it to O(1).
import java.util.*;

public final class Dp29FixedLengthStrings {
    /**
     * Counts strings of length len whose characters all come from allowed.
     * Time: O(len). Space: O(len).
     * Invariant: ways[p] counts the distinct valid strings of length p.
     */
    static long count(int len, String allowed) {
        // One slot per length from 0 to len; Java fills the new array with zeros.
        long[] ways = new long[len + 1];
        // The empty string is the single valid string of length 0.
        ways[0] = 1;
        // Each loop pass extends every string of length p by one allowed character.
        for (int p = 0; p < len; p++) {
            // Every position offers allowed.length() choices, so the count multiplies by that size.
            ways[p + 1] = ways[p] * allowed.length();
        }
        // The last slot holds the strings of the requested length.
        return ways[len];
    }

    /** Oracle: builds every string over the allowed characters and counts them. */
    static long oracle(int len, String allowed) {
        List<String> cur = new ArrayList<>();
        cur.add("");
        for (int p = 0; p < len; p++) {
            List<String> nxt = new ArrayList<>();
            for (String s : cur) for (char c : allowed.toCharArray()) nxt.add(s + c);
            cur = nxt;
        }
        return cur.size();
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (count(4, "024") != 81) throw new AssertionError("ex1");
        if (count(3, "1357") != 64) throw new AssertionError("ex2");
        // Length 0 gives one empty string, and the largest case stays inside a long.
        if (count(0, "5") != 1) throw new AssertionError("len 0");
        if (count(15, "0123456789") != 1_000_000_000_000_000L) throw new AssertionError("max");
        // Java behavior: a new long array holds zeros, and an int times a long widens to long.
        long[] fresh = new long[3];
        if (fresh[2] != 0L) throw new AssertionError("zero fill");
        if (((long) 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10 * 10) != 1_000_000_000_000_000L) throw new AssertionError("widen");
        // Random inputs against the oracle.
        Random rnd = new Random(2906);
        for (int t = 0; t < 300; t++) {
            int len = rnd.nextInt(6);
            StringBuilder sb = new StringBuilder();
            for (char c = '0'; c <= '9'; c++) if (rnd.nextInt(4) == 0) sb.append(c);
            if (sb.length() == 0) sb.append('7');
            if (count(len, sb.toString()) != oracle(len, sb.toString())) throw new AssertionError("random " + t);
        }
    }

Add Tight State

Author exercise

Problem Specification. A non-negative integer n and a string allowed of distinct digit characters are given. Write n with d digits, where d is the length of its decimal representation. Count the digit strings of exactly d characters, with leading zeros allowed, that read as a value at most n and use only characters from allowed.

Input Constraints. The limits are:

  • Bound satisfies 0 <= n <= 10^15.
  • Allowed set has between 1 and 10 distinct characters, each from '0' to '9'.
  • Result is a long.
  • Mutation is not allowed, because the inputs are values.

Example 1. Input n = 3047, allowed = "0123", output 208.

Example 2. Input n = 58, allowed = "2468", output 8.

Prerequisites. The exercise above.

What This Exercise Changes. The prefix now carries a tight flag, so the digit limit depends on the history and not only on the position.

Hint

Which digits may a prefix place when it still equals the leading digits of n, and which when it is already smaller?

Algorithmic Solution (attempt the problem first)

Approach. The method writes n as d digits and walks the positions from left to right. It keeps tight, the count of prefixes equal to the leading digits of n, and loose, the count of prefixes already smaller. A tight prefix may place an allowed digit from 0 up to the digit of n at that position. A loose prefix may place any allowed digit.

When a tight prefix places the digit of n itself, it stays tight. Every smaller allowed digit moves it to the loose count. The invariant is that after p positions, tight is 1 if the first p digits of n all belong to allowed and 0 otherwise, and loose counts every allowed prefix that is smaller. The answer is tight + loose, because a tight string equals n and still counts.

Complexity.

  • Time is O(d * 10), because each position tries at most ten digits for two counts.
  • Space is O(d) for the digit array, plus constant space for the two counts.
import java.util.*;

public final class Dp29AddTightState {
    /**
     * Counts d-digit strings, leading zeros allowed, with value at most n and characters from allowed.
     * Time: O(d * 10). Space: O(d).
     * Invariant: tight is 1 only while the prefix equals the leading digits of n.
     */
    static long count(long n, String allowed) {
        // Mark each allowed digit once so each test costs O(1).
        boolean[] ok = new boolean[10];
        for (char c : allowed.toCharArray()) ok[c - '0'] = true;
        // Digits of n from the leading digit down to the last digit.
        String text = Long.toString(n);
        long tight = 1;
        long loose = 0;
        // Each pass handles one position of the d positions.
        for (int p = 0; p < text.length(); p++) {
            int limit = text.charAt(p) - '0';
            // Loose prefixes keep their count for every allowed digit, any of ten digits.
            long nextLoose = 0;
            int allowedCount = 0;
            for (int dig = 0; dig <= 9; dig++) if (ok[dig]) allowedCount++;
            nextLoose += loose * allowedCount;
            // A tight prefix places digits up to the limit, and smaller digits turn loose.
            long nextTight = 0;
            if (tight == 1) {
                for (int dig = 0; dig < limit; dig++) if (ok[dig]) nextLoose++;
                // The limit digit keeps the prefix tight only when it is allowed.
                if (ok[limit]) nextTight = 1;
            }
            tight = nextTight;
            loose = nextLoose;
        }
        // A tight string equals n, so it counts with the smaller strings.
        return tight + loose;
    }

    /** Oracle: pads every value from 0 to n to d digits and tests each character. */
    static long oracle(long n, String allowed) {
        int d = Long.toString(n).length();
        long total = 0;
        for (long x = 0; x <= n; x++) {
            StringBuilder s = new StringBuilder(Long.toString(x));
            while (s.length() < d) s.insert(0, '0');
            boolean good = true;
            for (int i = 0; i < s.length(); i++) if (allowed.indexOf(s.charAt(i)) < 0) good = false;
            if (good) total++;
        }
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (count(3047, "0123") != 208) throw new AssertionError("ex1");
        if (count(58, "2468") != 8) throw new AssertionError("ex2");
        // Bound 0 has one digit; the string "0" counts only when 0 is allowed.
        if (count(0, "0") != 1) throw new AssertionError("zero allowed");
        if (count(0, "5") != 0) throw new AssertionError("zero not allowed");
        // Java behavior: subtracting '0' from a digit character gives its int value.
        if ("7".charAt(0) - '0' != 7) throw new AssertionError("digit value");
        // Random bounds against the oracle.
        Random rnd = new Random(2907);
        for (int t = 0; t < 400; t++) {
            long n = rnd.nextInt(3000);
            StringBuilder sb = new StringBuilder();
            for (char c = '0'; c <= '9'; c++) if (rnd.nextInt(2) == 0) sb.append(c);
            if (sb.length() == 0) sb.append('3');
            if (count(n, sb.toString()) != oracle(n, sb.toString())) throw new AssertionError("random " + t);
        }
    }

Leading Zero And Number Zero

Author exercise

Problem Specification. A non-negative integer n and an integer k are given. Count the integers x with 0 <= x <= n whose decimal representation contains exactly k digits equal to 0. The representation has no leading zeros, and the integer 0 is written as the single digit 0.

Input Constraints. The limits are:

  • Bound satisfies 0 <= n <= 10^15.
  • Zero count satisfies 0 <= k <= 16.
  • Result is a long.
  • Mutation is not allowed, because the inputs are values.

Example 1. Input n = 100, k = 2, output 1.

Example 2. Input n = 0, k = 1, output 1.

Prerequisites. The two exercises above.

What This Exercise Changes. The started flag decides which zeros count, and the integer 0 is the one case where the number never starts but still owns one zero digit.

Hint

Which padding zeros must stay out of the count, and which digit of the integer 0 must stay in?

Algorithmic Solution (attempt the problem first)

Approach. The state is the position, the tight flag, the started flag and the number of real zero digits placed so far. A map from zero count to ways would also work, and a long[2][2][k + 2] array is simpler. Zeros placed before the first nonzero digit are padding, so they leave the zero count at its value. Zeros placed after the number started add 1. Counts above k are dropped, since zero counts never decrease.

The integer 0 never starts, so the final tally of a state that is not started needs a rule. That state stands for the single integer 0, whose one digit is a zero. The method adds its count to the answer only when k equals 1. The invariant is that the zero count of a state equals the number of zero digits in the number's real representation so far.

Complexity.

  • Time is O(d * 4 * k * 10), because each position, flag pair and zero count tries ten digits.
  • Space is O(k) for the two layers of counts, plus O(d) for the digits.
import java.util.*;

public final class Dp29LeadingZeroAndZero {
    /**
     * Counts integers x in [0, n] whose decimal form has exactly k zero digits.
     * Time: O(d * k * 10). Space: O(d + k).
     * Invariant: zeros counts only digits placed after the number has started.
     */
    static long count(long n, int k) {
        // Digits of n from the leading digit down.
        String text = Long.toString(n);
        // cur[t][s][z] counts prefixes with tight flag t, started flag s and z real zeros.
        long[][][] cur = new long[2][2][k + 2];
        // The empty prefix is tight and not started, with no zeros.
        cur[1][0][0] = 1;
        // Each pass handles one position of the digits of n.
        for (int p = 0; p < text.length(); p++) {
            long[][][] nxt = new long[2][2][k + 2];
            int d = text.charAt(p) - '0';
            for (int t = 0; t < 2; t++) {
                for (int s = 0; s < 2; s++) {
                    for (int z = 0; z <= k; z++) {
                        long c = cur[t][s][z];
                        if (c == 0) continue;
                        // A tight prefix is capped by the digit of n; a loose one accepts 0 to 9.
                        int limit = t == 1 ? d : 9;
                        for (int dig = 0; dig <= limit; dig++) {
                            int nt = (t == 1 && dig == limit) ? 1 : 0;
                            int ns = (s == 1 || dig != 0) ? 1 : 0;
                            // A zero counts only after the number has started.
                            int nz = z + ((s == 1 && dig == 0) ? 1 : 0);
                            if (nz > k) continue;
                            nxt[nt][ns][nz] += c;
                        }
                    }
                }
            }
            cur = nxt;
        }
        // Started prefixes are real integers from 1 to n, so those with k zeros count.
        long total = cur[0][1][k] + cur[1][1][k];
        // The unstarted prefix is the integer 0, which has exactly one zero digit.
        if (k == 1) total += cur[0][0][0] + cur[1][0][0];
        return total;
    }

    /** Oracle: writes every integer from 0 to n and counts the character '0'. */
    static long oracle(long n, int k) {
        long total = 0;
        for (long x = 0; x <= n; x++) {
            String s = Long.toString(x);
            int zeros = 0;
            for (int i = 0; i < s.length(); i++) if (s.charAt(i) == '0') zeros++;
            if (zeros == k) total++;
        }
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (count(100, 2) != 1) throw new AssertionError("ex1");
        if (count(0, 1) != 1) throw new AssertionError("ex2");
        // The integer 0 has one zero digit and none for k = 0; a one-digit bound has no zeros.
        if (count(0, 0) != 0) throw new AssertionError("zero k0");
        if (count(9, 0) != 9) throw new AssertionError("nine");
        // Java behavior: Long.toString writes 0 as the single character "0" and adds no leading zeros.
        if (!Long.toString(0).equals("0")) throw new AssertionError("toString zero");
        if (!Long.toString(105).equals("105")) throw new AssertionError("toString 105");
        // Random bounds and zero counts against the oracle.
        Random rnd = new Random(2908);
        for (int t = 0; t < 500; t++) {
            long n = rnd.nextInt(4000);
            int k = rnd.nextInt(4);
            if (count(n, k) != oracle(n, k)) throw new AssertionError("random " + t);
        }
    }

Numbers At Most N Given Digit Set

LeetCode 902

Problem Specification. A set digits of distinct characters from '1' to '9' and an integer n are given. Count the positive integers x with x <= n whose decimal representation uses only characters from digits. A character may appear many times in one integer.

Input Constraints. The limits are:

  • Set size satisfies 1 <= digits.length() <= 9, with distinct characters from '1' to '9'.
  • Bound satisfies 1 <= n <= 10^9.
  • Result is a long.
  • Mutation is not allowed, because the inputs are values.

Example 1. Input digits = "249", n = 500, output 30.

Example 2. Input digits = "1357", n = 1000, output 84.

Prerequisites. All three exercises above.

What This Exercise Changes. The rule now forbids digits outside a set and not one digit, and the set has no 0, so a started number can never place a padding zero by mistake.

Hint

Which numbers are shorter than n, and which flag lets the table count them without a separate case?

Algorithmic Solution (attempt the problem first)

Approach. The method counts positive integers at most n with every digit in the set, and it uses the same two flags as the lesson. At each position a prefix places a digit from the set that does not pass the limit. Because the set has no 0, a started number never places a padding zero. Padding zeros may still appear while the number has not started, and they leave the started flag at 0.

The state tracks tight and started flags, and the invariant is the one from the lesson: each count covers every distinct prefix with those flags. The answer adds the two started counts, which excludes the empty number. The alternative of adding the count of every shorter length separately gives the same total, and the started flag removes that special case.

Complexity.

  • Time is O(d * 9), because each position tries at most nine set digits for four states.
  • Space is O(d) for the digit array, plus constant space for the counts.
import java.util.*;

public final class Dp29DigitSetAtMostN {
    /**
     * Counts positive integers at most n whose digits all come from the given set.
     * Time: O(d * 9). Space: O(d).
     * Invariant: ways[t][s] counts distinct prefixes with tight flag t and started flag s.
     */
    static long count(String digits, long n) {
        // Mark each digit of the set so the membership test costs O(1).
        boolean[] inSet = new boolean[10];
        for (char c : digits.toCharArray()) inSet[c - '0'] = true;
        String text = Long.toString(n);
        long[][] ways = new long[2][2];
        // The empty prefix is tight and not started.
        ways[1][0] = 1;
        // Each pass fixes one position of the digits of n.
        for (int p = 0; p < text.length(); p++) {
            long[][] next = new long[2][2];
            int d = text.charAt(p) - '0';
            for (int t = 0; t < 2; t++) {
                for (int s = 0; s < 2; s++) {
                    long c = ways[t][s];
                    if (c == 0) continue;
                    // A tight prefix may not pass the digit of n.
                    int limit = t == 1 ? d : 9;
                    // Digit 0 is padding for an unstarted prefix; any other digit must belong to the set.
                    for (int dig = 0; dig <= limit; dig++) {
                        if (dig == 0 ? s == 1 : !inSet[dig]) continue;
                        int nt = (t == 1 && dig == limit) ? 1 : 0;
                        int ns = dig == 0 ? 0 : 1;
                        next[nt][ns] += c;
                    }
                }
            }
            ways = next;
        }
        // Started prefixes are the positive integers that fit the set and the bound.
        return ways[0][1] + ways[1][1];
    }

    /** Oracle: tests every integer from 1 to n against the set. */
    static long oracle(String digits, long n) {
        long total = 0;
        for (long x = 1; x <= n; x++) {
            String s = Long.toString(x);
            boolean good = true;
            for (int i = 0; i < s.length(); i++) if (digits.indexOf(s.charAt(i)) < 0) good = false;
            if (good) total++;
        }
        return total;
    }

Problem

A Scheduler That Runs Out Of Memory

A batch system runs a pipeline of 100,000 stages on a row of 10,000 servers. Stage r costs cost[r][j] on server j. A stage may not run on a server with a smaller number than the server of the stage before it, because data only flows toward higher server numbers. The scheduler must pick one server per stage and minimize the total cost.

A correct recurrence exists. The first test run still fails, because the table of best totals holds 10^9 entries. At 4 bytes each, that is 4 GB. Even with enough memory, the table fill takes about 5 * 10^12 steps, which is far beyond a practical run.

Formally, the input is an int[][] cost with R rows and C columns. A plan is a sequence of columns c_0 <= c_1 <= ... <= c_(R-1), one per row. Its cost is the sum of cost[r][c_r]. The task is to return the smallest plan cost. The input stays unchanged.

This lesson asks how to shrink a correct recurrence in time and memory without changing a single answer.

Simple approach

Enumerating Plans And Filling A Full Table

The direct method tries every plan. At row r it tries every column from the previous column onward.

static long tryAll(int[][] cost, int r, int from) {
    if (r == cost.length) return 0;
    long best = Long.MAX_VALUE;
    for (int j = from; j < cost[0].length; j++) {
        best = Math.min(best, cost[r][j] + tryAll(cost, r + 1, j));
    }
    return best;
}

Call tryAll(cost, 0, 0). The call tree has one leaf for each plan. For R rows and C columns, the number of plans is the binomial coefficient of R + C - 1 over R, which is exponential in R.

A table removes the repeated calls. Entry dp[r][j] holds the cheapest plan that covers rows 0 to r and ends in column j. Each entry scans the whole previous row up to column j.

static long fullTable(int[][] cost) {
    int rows = cost.length;
    int cols = cost[0].length;
    long[][] dp = new long[rows][cols];
    for (int j = 0; j < cols; j++) dp[0][j] = cost[0][j];
    for (int r = 1; r < rows; r++) {
        for (int j = 0; j < cols; j++) {
            long best = Long.MAX_VALUE;
            for (int k = 0; k <= j; k++) best = Math.min(best, dp[r - 1][k]);
            dp[r][j] = cost[r][j] + best;
        }
    }
    long answer = Long.MAX_VALUE;
    for (int j = 0; j < cols; j++) answer = Math.min(answer, dp[rows - 1][j]);
    return answer;
}

The table is correct. It costs O(R * C^2) time and O(R * C) memory.

Bottleneck

Repeated Scans And Rows Nobody Rereads

Predict first: In fullTable, which rows of dp does the code read while it computes row 40? And how many entries of row 39 does the entry for column 700 scan?

It reads only row 39, and it never reads rows 0 to 38 again. The entry for column 700 scans 701 entries of row 39, and the entry for column 701 scans the same 701 entries plus one more.

The prediction shows two separate wastes. The first is memory. Rows 0 to 38 sit in the table, yet no later statement reads them. For R = 100,000 and C = 10,000 the table holds 10^9 entries, and only 2 * 10^4 of them matter at any moment.

The second waste is time. The inner loop over k computes a minimum over columns 0 to j. The next entry computes a minimum over columns 0 to j + 1. Those two ranges share all but one column, so the work for column j + 1 repeats the work for column j. Across a row, the scans cost 1 + 2 + ... + C, which is O(C^2). Across all rows, the total is O(R * C^2), which is 5 * 10^12 steps for the opening input.

Both wastes have a cheap cure, but each cure carries a risk. Dropping rows is safe only if nothing later reads them. Replacing a scan with a stored value is safe only if the stored value equals the scan result for every column. Writing new values over old ones is safe only if every old value is read before it disappears. The next section turns these three risks into proofs.

Key idea

Prove What Each Entry Reads

An optimization is correct when it keeps every value the original recurrence reads and every candidate it compares. The proof lists those reads first and then shows that the cheaper code makes the same reads.

List The Dependency Set

The dependency set of an entry is the set of table cells its formula reads. For dp[r][j] the set is dp[r - 1][0] to dp[r - 1][j]. Every member has row r - 1. No cell from row r - 2 or earlier appears. Therefore, once row r is complete, rows before r - 1 can be discarded. Two arrays of length C replace the table, and the memory drops from O(R * C) to O(C).

Keep A Running Minimum

The scan computes min(dp[r - 1][0..j]). Call this value m_j. The next scan computes m_(j+1), whose candidate set is the candidate set of m_j plus the single cell dp[r - 1][j + 1]. So m_(j+1) = min(m_j, dp[r - 1][j + 1]). A running minimum is a variable that holds m_j while the loop moves from column to column. It starts as infinity, and one comparison per column updates it. The candidate set is identical to the scan, so every answer is identical, and the row costs O(C) in place of O(C^2).

Choose The Update Direction

The two arrays can shrink to one. The new value dp[r][j] may overwrite the old value dp[r - 1][j] only if no later statement still needs the old value. The running minimum already consumed the old value at column j, and later columns need only the running minimum, not the cell. Walking left to right, read the old cell, fold it into the running minimum, and then write the new value. The update direction is this order of visiting cells. It is part of the proof. Walking right to left would overwrite old cells that columns on the left still need.

The same question decides other single-array tables. A recurrence that reads the old value at a smaller index must visit indexes from high to low. A recurrence that must read the new value at a smaller index must visit them from low to high. The invariant for the plan table is that before column j is processed, the array holds new values for columns below j and old values for columns from j on, and the running minimum equals the minimum of the old values below j.

State

One Array And One Running Value

The method takes the cost table unchanged and keeps these working values.

  • dp is a long[C] array that holds the best totals of the most recent finished row; before row 0 it holds zeros.
  • r is the row being processed, from 0 to R - 1.
  • j is the column being processed, from 0 to C - 1.
  • old is the value dp[j] had before this row touched it, which is the total for column j after row r - 1.
  • run is the running minimum of the old values in columns 0 to j; it restarts at infinity for each row.

The zeros before row 0 stand for an empty plan with total 0, and they let row 0 use the same formula as every other row. Sums use long, because the total over 100,000 rows can pass the int limit of about 2.1 * 10^9 when costs reach 10^5.

Walkthrough

Two Runs Of The Single Array

Three Servers And Three Stages

The first run uses cost = [[3,1,4],[2,5,1],[4,2,3]]. The cells below list the cost table row by row, so cells 0 to 2 are row 0, cells 3 to 5 are row 1, and cells 6 to 8 are row 2. The pointer cell marks the entry in progress. The variable old is the value read from dp before the write, run is the running minimum after folding old in, and dp is the value written.

Row 0 sees only zeros, so it copies its costs: 3, 1 and 4. Row 1 starts with old = 3, and it writes 2 + 3 = 5 at column 0. At column 1 the running minimum becomes 1, and the entry writes 5 + 1 = 6. At column 2 the running minimum stays 1, and the entry writes 1 + 1 = 2. Row 2 repeats the pattern over the values 5, 6 and 2. It ends with 9, 7 and 5, and the smallest is 5.

Four Servers And Three Stages

The second run uses cost = [[5,2,6,3],[4,7,1,5],[6,3,2,1]]. The running minimum drops at different columns in each row, and it always covers old values only. Row 0 writes 5, 2, 6 and 3. In row 1 the running minimum falls to 2 at column 1, so column 2 writes 1 + 2 = 3. Row 2 then sees the old values 9, 9, 3 and 7. Its running minimum falls to 3 at column 2, so columns 2 and 3 write 5 and 4. The smallest final value is 4.

Code

Rolling The Table Into One Array

The method returns the smallest plan cost. It keeps one array and one running value for each row.

static long cheapestPlan(int[][] cost) {
    int cols = cost[0].length;
    long[] dp = new long[cols];
    for (int[] row : cost) {
        long run = Long.MAX_VALUE;
        for (int j = 0; j < cols; j++) {
            long old = dp[j];
            run = Math.min(run, old);
            dp[j] = row[j] + run;
        }
    }
    long answer = Long.MAX_VALUE;
    for (long v : dp) answer = Math.min(answer, v);
    return answer;
}

Time drops to O(R * C), and memory drops to O(C). For the opening input, that is 10^9 steps and 10,000 stored values. The read of old comes before the write to dp[j], and this order is the whole proof of the single array. If R or C is 0, the input is outside the contract. The exercises below practice each proof step on its own.

When to use it

Checking An Optimization Before Using It

Reading The Cue

Look for a recurrence that is already correct but too large or too slow. Two cues matter. A table whose entries read only the previous row can shrink to one or two rows. A scan over a range that grows by one cell per column can become a maintained aggregate. Write the original recurrence first, list its dependency set, and name the structure that replaces the scan.

Checking The Invariant

The invariant is that the optimized code reads every cell and considers every candidate the original reads and considers. Test it by running both versions on random small inputs and comparing every answer. Include a single row, a single column, equal costs everywhere and costs that make the best plan stay in one column.

Avoiding The False Friend

The false friend is a scan whose range slides in place of growing. If the previous column must lie within a fixed distance of j, the range drops a cell on the left as it gains one on the right. A minimum cannot forget a dropped cell, so the running minimum gives wrong answers. A second false friend is the in-place loop in the wrong direction. It compiles, runs fast and returns plausible numbers, but it lets one item or one stage reuse a value that the recurrence forbids.

Knowing The Limits

This method does not apply when later rows read rows older than the previous one, unless the code keeps that many rows. Faster recurrence-specific techniques such as Knuth optimization, divide-and-conquer optimization and the convex hull trick need their own proofs of structure. They are out of scope here, and a later chapter owns them.

Roll One Dimension

Author exercise

Problem Specification. An int[][] cost with R rows and C columns is given. A falling path picks one column per row, and each column differs from the previous pick by at most 1. Return the smallest sum of the picked costs. Use only arrays of length C for the table.

Input Constraints. The limits are:

  • Size satisfies 1 <= R <= 200 and 1 <= C <= 200.
  • Values satisfy 0 <= cost[r][j] <= 10000.
  • Result is a long.
  • Mutation is not allowed, so the method leaves cost unchanged.

Example 1. Input cost = [[3,1,4],[2,5,1],[4,2,3]], output 4.

Example 2. Input cost = [[7,2],[1,9]], output 3.

Prerequisites. The dependency set and the single array from this lesson.

What This Exercise Changes. The table keeps two rows in place of all rows. A new row can overwrite the row before the previous one, because nothing reads it.

Hint

List which cells the entry (r, j) reads. If every one has row r - 1, which earlier rows can go?

Algorithmic Solution (attempt the problem first)

Approach. The full table has entry dp[r][j] equal to cost[r][j] plus the smaller of dp[r - 1][j - 1], dp[r - 1][j] and dp[r - 1][j + 1], where a neighbour outside the row does not exist. Every cell in that dependency set has row r - 1. Row r - 2 and earlier rows are never read once row r - 1 exists, so two arrays suffice.

The method keeps prev for the finished row and cur for the row in progress. After each row, the two references swap, so the old prev becomes the next cur and gets overwritten. The invariant is that prev holds the exact table row r - 1 whenever row r starts. Row 0 copies its costs, because it has no previous row.

Complexity.

  • Time is O(R * C), because each entry costs at most three reads and one write.
  • Space is O(C) for the two arrays, in place of O(R * C) for the table.
import java.util.*;

public final class Dp29RollOneDimension {
    /**
     * Returns the smallest falling path sum using two arrays of length C.
     * Time: O(R * C). Space: O(C).
     * Invariant: prev equals table row r - 1 when row r starts.
     */
    static long fallingPath(int[][] cost) {
        // cols is the width of every row, and each array holds one table row.
        int cols = cost[0].length;
        long[] prev = new long[cols];
        long[] cur = new long[cols];
        // Row 0 has no previous row, so it copies its own costs.
        for (int j = 0; j < cols; j++) prev[j] = cost[0][j];
        // Each later row reads only prev, which costs R - 1 passes of C entries.
        for (int r = 1; r < cost.length; r++) {
            for (int j = 0; j < cols; j++) {
                // Start with the cell straight above, then widen to the two diagonal cells if they exist.
                long best = prev[j];
                if (j > 0) best = Math.min(best, prev[j - 1]);
                if (j + 1 < cols) best = Math.min(best, prev[j + 1]);
                // The new entry adds its own cost to the best allowed predecessor.
                cur[j] = cost[r][j] + best;
            }
            // Swapping references reuses the old array without copying C values.
            long[] tmp = prev;
            prev = cur;
            cur = tmp;
        }
        // The answer is the smallest entry of the last finished row.
        long answer = Long.MAX_VALUE;
        for (long v : prev) answer = Math.min(answer, v);
        return answer;
    }

    /** Oracle: tries every falling path by recursion. */
    static long oracle(int[][] cost, int r, int col) {
        if (r == cost.length) return 0;
        long best = Long.MAX_VALUE;
        for (int j = Math.max(0, col - 1); j <= Math.min(cost[0].length - 1, col + 1); j++) {
            best = Math.min(best, cost[r][j] + oracle(cost, r + 1, j));
        }
        return best;
    }

    static long oracleAll(int[][] cost) {
        long best = Long.MAX_VALUE;
        for (int j = 0; j < cost[0].length; j++) best = Math.min(best, cost[0][j] + oracle(cost, 1, j));
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (fallingPath(new int[][]{{3, 1, 4}, {2, 5, 1}, {4, 2, 3}}) != 4) throw new AssertionError("ex1");
        if (fallingPath(new int[][]{{7, 2}, {1, 9}}) != 3) throw new AssertionError("ex2");
        // A single row returns its smallest cost, and a single column returns the column sum.
        if (fallingPath(new int[][]{{4, 9, 2}}) != 2) throw new AssertionError("one row");
        if (fallingPath(new int[][]{{4}, {9}, {2}}) != 15) throw new AssertionError("one col");
        // Java gives a new long array zeros, and swapping two references leaves both arrays intact.
        long[] a = new long[2];
        long[] b = {5, 6};
        if (a[0] != 0 || a[1] != 0) throw new AssertionError("zero fill");
        long[] t = a;
        a = b;
        b = t;
        if (a[0] != 5 || b.length != 2) throw new AssertionError("swap");
        // The input must stay unchanged after the call.
        int[][] input = {{3, 1, 4}, {2, 5, 1}};
        fallingPath(input);
        if (!Arrays.deepEquals(input, new int[][]{{3, 1, 4}, {2, 5, 1}})) throw new AssertionError("mutated");
        // Random tables against the exhaustive path search.
        Random rnd = new Random(2907);
        for (int trial = 0; trial < 2000; trial++) {
            int rows = 1 + rnd.nextInt(5);
            int cols = 1 + rnd.nextInt(5);
            int[][] cost = new int[rows][cols];
            for (int[] row : cost) for (int j = 0; j < cols; j++) row[j] = rnd.nextInt(20);
            if (fallingPath(cost) != oracleAll(cost)) throw new AssertionError("random " + trial);
        }
    }

Variation

Prefix-Minimum Transition

Author exercise

Problem Specification. A matrix int[][] cost has R rows and C columns. Pick one column per row so that each picked column is strictly greater than the previous pick. Return the smallest sum of picked costs, or -1 if no such plan exists.

Input Constraints. The limits are:

  • Size satisfies 1 <= R <= 200 and 1 <= C <= 200.
  • Values satisfy 0 <= cost[r][j] <= 10000.
  • Result is a long, or -1 when R > C.
  • Mutation is not allowed, so the method leaves cost unchanged.

Example 1. Input cost = [[3,1,4],[2,5,1]], output 2.

Example 2. Input cost = [[1],[1]], output -1.

Prerequisites. The exercise above and the running minimum.

What This Exercise Changes. The range ends one column earlier, so the running minimum folds in the old cell after the new value is written. Column 0 has an empty range and must stay unreachable.

Hint

The set of allowed previous columns for column j is columns 0 to j - 1. What is that set for column 0, and which old cell joins the minimum next?

Algorithmic Solution (attempt the problem first)

Approach. Entry dp[r][j] equals cost[r][j] plus the smallest dp[r - 1][k] with k < j. The candidate range for column j + 1 is the range for column j plus the single old cell dp[r - 1][j]. So one variable run carries the minimum from column to column.

The loop visits columns left to right and updates one array in place. At column j it reads old = dp[j], writes the new value from run, and only then folds old into run. This order keeps old out of its own range, which is the strict inequality. Column 0 sees an empty range, so its value becomes unreachable. A large sentinel marks unreachable entries, and the final answer maps a sentinel to -1.

The invariant is that before column j, the array holds new values for columns below j and old values from j on, and run is the minimum of the old values below j.

Complexity.

  • Time is O(R * C), because each entry costs one comparison and two array accesses.
  • Space is O(C) for the single array.
import java.util.*;

public final class Dp29PrefixMinimumTransition {
    static final long INF = Long.MAX_VALUE / 4;

    /**
     * Returns the smallest cost of a plan with strictly increasing columns, or -1 if none exists.
     * Time: O(R * C). Space: O(C).
     * Invariant: before column j, dp holds new values below j, old values from j, and run is the old minimum below j.
     */
    static long strictPlan(int[][] cost) {
        // cols is the row width, and dp starts as row 0 because the first pick has no predecessor.
        int cols = cost[0].length;
        long[] dp = new long[cols];
        for (int j = 0; j < cols; j++) dp[j] = cost[0][j];
        // Each later row rewrites dp once, so the loops cost R - 1 passes of C steps.
        for (int r = 1; r < cost.length; r++) {
            long run = INF;
            for (int j = 0; j < cols; j++) {
                // Save the old value before the write destroys it.
                long old = dp[j];
                // An empty or unreachable range makes this entry unreachable.
                dp[j] = run >= INF ? INF : cost[r][j] + run;
                // Fold the old value in after the write, so the range stays strictly below the next column.
                run = Math.min(run, old);
            }
        }
        // The smallest final entry is the answer, and the sentinel means no plan exists.
        long answer = INF;
        for (long v : dp) answer = Math.min(answer, v);
        return answer >= INF ? -1 : answer;
    }

    /** Oracle: tries every strictly increasing column sequence. */
    static long oracle(int[][] cost, int r, int minCol) {
        if (r == cost.length) return 0;
        long best = INF;
        for (int j = minCol; j < cost[0].length; j++) {
            long rest = oracle(cost, r + 1, j + 1);
            if (rest < INF) best = Math.min(best, cost[r][j] + rest);
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (strictPlan(new int[][]{{3, 1, 4}, {2, 5, 1}}) != 2) throw new AssertionError("ex1");
        if (strictPlan(new int[][]{{1}, {1}}) != -1) throw new AssertionError("ex2");
        // More rows than columns has no plan, and equal counts force the diagonal.
        if (strictPlan(new int[][]{{1, 1}, {1, 1}, {1, 1}}) != -1) throw new AssertionError("too many rows");
        if (strictPlan(new int[][]{{1, 9}, {9, 2}}) != 3) throw new AssertionError("diagonal");
        // The sentinel stays far from overflow when a cost is added to it once.
        if (INF + 10000 < INF) throw new AssertionError("sentinel overflow");
        // The input must stay unchanged after the call.
        int[][] input = {{3, 1, 4}, {2, 5, 1}};
        strictPlan(input);
        if (!Arrays.deepEquals(input, new int[][]{{3, 1, 4}, {2, 5, 1}})) throw new AssertionError("mutated");
        // Random tables against the exhaustive search.
        Random rnd = new Random(2908);
        for (int trial = 0; trial < 3000; trial++) {
            int rows = 1 + rnd.nextInt(5);
            int cols = 1 + rnd.nextInt(6);
            int[][] cost = new int[rows][cols];
            for (int[] row : cost) for (int j = 0; j < cols; j++) row[j] = rnd.nextInt(20);
            long expected = oracle(cost, 0, 0);
            if (expected >= INF) expected = -1;
            if (strictPlan(cost) != expected) throw new AssertionError("random " + trial);
        }
    }
}verified
Edge Cases

In-Place Direction Counterexample

Author exercise

Problem Specification. An int[] weights and an integer target are given. The single-array table ways[s] counts item subsets with sum s. A correct loop visits s from target down to each weight. A flawed loop visits s from each weight up to target. Return the flawed count minus the correct count for ways[target].

Input Constraints. The limits are:

  • Length satisfies 0 <= weights.length <= 20, and the array may be empty.
  • Values satisfy 1 <= weights[i] <= 20 and 0 <= target <= 60.
  • Result is a long.
  • Mutation is not allowed, so the method leaves weights unchanged.

Example 1. Input weights = [2], target = 4, output 1.

Example 2. Input weights = [], target = 0, output 0.

Prerequisites. The two exercises above.

What This Exercise Changes. The loop direction flips, so each item can be used any number of times. The value of target is unchanged, but the meaning of the table entry is not.

Hint

In the upward loop, ways[s - w] may already include the current item. Which count does that produce for weights = [2]?

Algorithmic Solution (attempt the problem first)

Approach. The array ways[s] counts subsets of the items processed so far with sum s. For one item of weight w, the new ways[s] equals the old ways[s] plus the old ways[s - w]. The formula needs the old value at the smaller index s - w.

Visiting s from target down to w keeps that promise, because the write at s happens before any smaller index is rewritten. Visiting s upward breaks it. By the time the loop reaches s, the cell s - w already includes the current item, so the item is counted again. The flawed loop therefore counts multisets, where an item may repeat. The method runs both loops and returns the flawed count minus the correct count.

The invariant for the downward loop is that every index below the current s still holds its value from before the current item. For the upward loop the invariant fails by design.

Complexity.

  • Time is O(n * target), because each of the two loops makes n passes over at most target indexes.
  • Space is O(target) for each array.
import java.util.*;

public final class Dp29DirectionCounterexample {
    /**
     * Returns flawed count minus correct count for ways[target].
     * Time: O(n * target). Space: O(target).
     * Invariant of the downward loop: indexes below s still hold values from before the current item.
     */
    static long gap(int[] weights, int target) {
        // Both arrays start with the empty subset at sum 0, and Java zero fills the rest.
        long[] correct = new long[target + 1];
        long[] flawed = new long[target + 1];
        correct[0] = 1;
        flawed[0] = 1;
        // Each item costs one pass over the table in each direction.
        for (int w : weights) {
            // Downward: the cell at s - w is still old when s is written.
            for (int s = target; s >= w; s--) correct[s] += correct[s - w];
            // Upward: the cell at s - w was already updated, so the item repeats.
            for (int s = w; s <= target; s++) flawed[s] += flawed[s - w];
        }
        // The gap is zero exactly when no repeated use changes the count at the target.
        return flawed[target] - correct[target];
    }

    /** Oracle for the correct count: tries every subset by bitmask. */
    static long subsets(int[] weights, int target) {
        long count = 0;
        for (int mask = 0; mask < (1 << weights.length); mask++) {
            int sum = 0;
            for (int i = 0; i < weights.length; i++) if ((mask >> i & 1) == 1) sum += weights[i];
            if (sum == target) count++;
        }
        return count;
    }

    /** Oracle for the flawed count: counts multiplicity choices item by item. */
    static long multisets(int[] weights, int i, int left) {
        if (i == weights.length) return left == 0 ? 1 : 0;
        long total = 0;
        for (int use = 0; use * weights[i] <= left; use++) total += multisets(weights, i + 1, left - use * weights[i]);
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (gap(new int[]{2}, 4) != 1) throw new AssertionError("ex1");
        if (gap(new int[0], 0) != 0) throw new AssertionError("ex2");
        // Target 0 counts only the empty subset in both loops, and a heavy item never fits.
        if (gap(new int[]{3, 5}, 0) != 0) throw new AssertionError("target zero");
        if (gap(new int[]{9}, 4) != 0) throw new AssertionError("too heavy");
        // A weight of 1 and target 3 lets the flawed loop count one multiset that the subset count cannot.
        if (gap(new int[]{1}, 3) != 1) throw new AssertionError("repeat");
        // Java adds to a long array cell in place, so the compound assignment reads the current cell value.
        long[] cell = {2, 0};
        cell[1] += cell[0];
        cell[0] += cell[1];
        if (cell[1] != 2 || cell[0] != 4) throw new AssertionError("compound");
        // Random inputs against both oracles.
        Random rnd = new Random(2909);
        for (int trial = 0; trial < 1500; trial++) {
            int n = rnd.nextInt(8);
            int[] weights = new int[n];
            for (int i = 0; i < n; i++) weights[i] = 1 + rnd.nextInt(6);
            int target = rnd.nextInt(25);
            long expected = multisets(weights, 0, target) - subsets(weights, target);
            if (gap(weights, target) != expected) throw new AssertionError("random " + trial);

Optimization Audit

Author exercise

Problem Specification. An int[][] cost and an integer w are given. Pick one column per row so that each picked column c_r satisfies c_(r-1) <= c_r <= c_(r-1) + w. Return the smallest sum of picked costs.

Input Constraints. The limits are:

  • Size satisfies 1 <= R <= 100 and 1 <= C <= 100.
  • Values satisfy 0 <= cost[r][j] <= 10000.
  • Window satisfies 0 <= w <= 100.
  • Result is a long, and the method leaves cost unchanged.

Example 1. Input cost = [[3,1,4],[2,5,1],[4,2,3]], w = 100, output 5.

Example 2. Input cost = [[3,1,4],[2,5,1],[4,2,3]], w = 0, output 8.

Prerequisites. All three exercises above.

What This Exercise Changes. The previous column range now has an upper limit, so a running minimum is valid only when the limit never cuts a cell. Otherwise the code scans the range.

Hint

Compare the range of previous columns for column j with the range the lesson used. For which values of w do the two ranges match?

Algorithmic Solution (attempt the problem first)

Approach. The original recurrence is dp[r][j] = cost[r][j] + min dp[r - 1][k] over k with j - w <= k <= j and k >= 0. The dependency set lies in row r - 1, so two rows suffice for any w.

The lesson replaced the scan with a running minimum because its range was columns 0 to j, which grows by one cell per column. That range matches the original recurrence here only when the lower bound j - w never exceeds 0, which means w >= C - 1. For smaller w, the range drops its left cell as it gains the right one. A minimum cannot forget a cell, so the replacement would include columns the recurrence forbids and would return too small a value. The method therefore uses the running minimum in place when w >= C - 1 and otherwise scans the window of the previous row in a second array.

The invariant is that every candidate the original recurrence compares is compared, and no other candidate is.

Complexity.

  • Time is O(R * C) when w >= C - 1, and O(R * C * min(w + 1, C)) otherwise, because each entry scans its window.
  • Space is O(C) in both cases.
import java.util.*;

public final class Dp29OptimizationAudit {
    /**
     * Returns the smallest plan cost when each column lies in [previous, previous + w].
     * Time: O(R * C) if w >= C - 1, otherwise O(R * C * (w + 1)). Space: O(C).
     * Invariant: each entry compares exactly the previous-row cells inside its window.
     */
    static long windowPlan(int[][] cost, int w) {
        // cols is the row width, and dp holds the finished row, starting from zeros for the empty plan.
        int cols = cost[0].length;
        long[] dp = new long[cols];
        if (w >= cols - 1) {
            // The window covers every column below j, so one running minimum equals the scan.
            for (int[] row : cost) {
                long run = Long.MAX_VALUE;
                for (int j = 0; j < cols; j++) {
                    // Read the old cell, fold it in, then overwrite it.
                    long old = dp[j];
                    run = Math.min(run, old);
                    dp[j] = row[j] + run;
                }
            }
        } else {
            // A narrow window needs old values, so a second array holds the new row.
            long[] next = new long[cols];
            for (int[] row : cost) {
                for (int j = 0; j < cols; j++) {
                    // Scan only the window, which costs at most w + 1 reads.
                    long best = Long.MAX_VALUE;
                    for (int k = Math.max(0, j - w); k <= j; k++) best = Math.min(best, dp[k]);
                    next[j] = row[j] + best;
                }
                // Swap the references so the finished row becomes the source of the next pass.
                long[] tmp = dp;
                dp = next;
                next = tmp;
            }
        }
        // The smallest entry of the last row is the answer.
        long answer = Long.MAX_VALUE;
        for (long v : dp) answer = Math.min(answer, v);
        return answer;
    }

    /** The unsafe replacement: a running minimum used for every window width. */
    static long forcedPrefix(int[][] cost) {
        long[] dp = new long[cost[0].length];
        for (int[] row : cost) {
            long run = Long.MAX_VALUE;
            for (int j = 0; j < dp.length; j++) {
                long old = dp[j];
                run = Math.min(run, old);
                dp[j] = row[j] + run;
            }
        }
        long answer = Long.MAX_VALUE;
        for (long v : dp) answer = Math.min(answer, v);
        return answer;
    }

    /** Oracle: tries every plan by recursion. */
    static long oracle(int[][] cost, int r, int prev, int w) {
        if (r == cost.length) return 0;
        long best = Long.MAX_VALUE;
        for (int j = prev; j <= Math.min(cost[0].length - 1, prev + w); j++) {
            best = Math.min(best, cost[r][j] + oracle(cost, r + 1, j, w));
        }
        return best;
    }

    public static void main(String[] args) {
        int[][] sample = {{3, 1, 4}, {2, 5, 1}, {4, 2, 3}};
        // The two examples of the exercise.
        if (windowPlan(sample, 100) != 5) throw new AssertionError("ex1");
        if (windowPlan(sample, 0) != 8) throw new AssertionError("ex2");
        // The forced running minimum returns 5 for w = 0, which is smaller than the true 8.
        if (forcedPrefix(sample) != 5) throw new AssertionError("forced value");
        if (forcedPrefix(sample) == windowPlan(sample, 0)) throw new AssertionError("false friend hidden");
        // A window of C - 1 is the first width where the two methods must agree.
        if (windowPlan(sample, 2) != forcedPrefix(sample)) throw new AssertionError("boundary width");
        // The input must stay unchanged after the call.
        int[][] input = {{3, 1, 4}, {2, 5, 1}};
        windowPlan(input, 1);
        if (!Arrays.deepEquals(input, new int[][]{{3, 1, 4}, {2, 5, 1}})) throw new AssertionError("mutated");
        // Random tables against the exhaustive search for every width.
        Random rnd = new Random(2910);
        for (int trial = 0; trial < 3000; trial++) {
            int rows = 1 + rnd.nextInt(5);
            int cols = 1 + rnd.nextInt(6);
            int w = rnd.nextInt(cols + 2);
            int[][] cost = new int[rows][cols];
            for (int[] row : cost) for (int j = 0; j < cols; j++) row[j] = rnd.nextInt(20);
            long expected = Long.MAX_VALUE;
            for (int j = 0; j < cols; j++) expected = Math.min(expected, cost[0][j] + oracle(cost, 1, j, w));
            if (windowPlan(cost, w) != expected) throw new AssertionError("random " + trial);
        }
    }

Problem

A Scoring Rule That Defeats Greedy

A list editor deletes entries one at a time. Each deletion earns points equal to the product of the two entries that sit next to the deleted one at that moment. Entries beyond either end count as 1. For the list 4, 9, 3, 1, a developer picks the best-scoring deletion at every step. The program earns 21 points. Another order earns 28.

The greedy program is not buggy in any line. It fails because the best deletion now changes which entries are neighbours later. Deleting the 9 first earns 12 points, but it removes the large neighbour that the other three deletions could have used.

Formally, the input is an int[] values. One move deletes an entry and adds the product of its current left and right neighbours to the score. The task is to delete every entry and return the largest possible total.

This lesson asks how to choose the table index so that one stored answer stays valid no matter what happens elsewhere in the list.

What Each Technique Adds

What Four Earlier Skills Add

Interval Tables Add Independent Pieces

The interval lesson showed that dp[left][right] can own a contiguous range and read only shorter ranges that are already final. Choosing the last operation inside a range splits it into two parts that no longer affect each other. This lesson reuses that split.

Palindrome Tables Add Cheap Validity Checks

The palindrome lesson filled a yes or no table over all substrings and then ran a prefix loop that picks the last piece. The table answers validity in O(1) time. The prefix loop then needs only the lengths of the prefixes, not their contents.

Bit Masks Add Sets Of Used Items

The bitmask lesson stored which items are already taken in one integer. Bit i is 1 when item i is used. The integer is a complete description of a subset, so it works as a table index when the item count is small.

Range Tables Add Many Queries

Chapter 28 filled a table over pairs of positions so that every range answer was ready after one pass. Here the same idea lets one table answer many range questions. Together, the four skills give the recurrence a choice of index: a range, a prefix, a set, or a table that serves all ranges at once.

Simple approach

Deleting The Best Entry Each Time

The quick idea scores every remaining entry, deletes the highest-scoring one and repeats. The routine below keeps the list in an ArrayList with the outside value 1 at both ends.

static int greedyDeletes(int[] values) {
    java.util.List<Integer> cur = new java.util.ArrayList<>();
    cur.add(1);
    for (int v : values) cur.add(v);
    cur.add(1);
    int total = 0;
    while (cur.size() > 2) {
        int bestAt = 1;
        for (int i = 1; i < cur.size() - 1; i++) {
            if (cur.get(i - 1) * cur.get(i + 1) > cur.get(bestAt - 1) * cur.get(bestAt + 1)) bestAt = i;
        }
        total += cur.get(bestAt - 1) * cur.get(bestAt + 1);
        cur.remove(bestAt);
    }
    return total;
}

The routine runs in O(n^2) time for n entries, because each of the n rounds scans the list, and uses O(n) memory. Each round makes a final choice using only the score available at that moment.

Predict first: Run greedyDeletes on the values [4, 9, 3, 1]. What does it return, and which order of deletions earns more?

It returns 21. It deletes the 9 first for 12 points, then the 3 for 4, then the 1 for 4, then the 4 for 1. Deleting 4, 3 and 1 first, with the 9 still in place, earns 9 each, and the 9 then earns 1, for a total of 28.

Bottleneck

A Deletion Changes Every Later Neighbour

Greedy fails because a deletion rewrites the neighbours of two other entries. Any table indexed by a prefix of the original list breaks for the same reason. After the entries 3 and 5 of a prefix are gone, the next entry sees a different left neighbour than its position suggests, and the prefix length does not record that.

The correct method tries every order. A list of n entries has n! orders, and each order costs O(n) to score, so the total is O(n! * n). For n = 12 the count of orders is about 479 million, and for n = 20 it exceeds 10^18.

The orders share work. Whatever happens to the entries on one side of a chosen survivor does not change the neighbours on the other side. Many orders therefore repeat the same sub-order on a range of the list. The number of distinct ranges is only O(n^2), and a range with fixed ends needs one answer. The next section names the index that makes this sharing exact.

Key idea

Pick The Index That Fixes The Outside

A stored answer is reusable only when everything outside it is fixed. The index is the smallest description that fixes that outside. Each earlier skill supplies one kind of index.

Interval State For Last Deletions

Let a be the list with the outside value 1 added at both ends. Define dp[l][r] as the best score from deleting every entry strictly between positions l and r, while positions l and r stay in place. This is an interval state: the two ends fix the neighbours for the whole sub-problem.

Consider the entry k deleted last inside the range. At that moment its neighbours are exactly a[l] and a[r], so it earns a[l] * a[r]. Before it, the entries between l and k and the entries between k and r were deleted with k still standing. The two parts do not touch, so dp[l][r] is the best k of a[l] * a[r] + dp[l][k] + dp[k][r].

Prefix State For Cuts

The prefix state stores best[j] for the first j items and tries every earlier cut i. It works when the last piece is judged on its own, as with a palindrome whose validity comes from a second table. It fails for deletions, because a prefix has no way to say what stands next to it.

Mask State For Sets

The mask state stores a subset of items in an integer. It works when the next decision depends on which items remain, and not on their order. A group fill that equals the sum of the used items modulo the target is a function of the mask alone, so the mask can replace a list of bucket loads.

The Rule Behind All Three

Choose the index from the question "what must stay fixed for the answer to remain true". The invariant is that every entry read is complete and describes exactly its own index.

State

The Table For Deletion Intervals

The list values stays unchanged, and these working values describe the table for the running example.

  • a is an int[n + 2] with a[0] = 1, a[n + 1] = 1 and the original entries in between.
  • dp is an int[n + 2][n + 2]; entry dp[l][r] is the best score for deleting every entry strictly between l and r.
  • gap is r - l, from 2 up to n + 1; a gap of 1 means no entry lies between, and the entry stays 0.
  • last is the position k that the best choice deletes last inside (l, r).
  • pair is a[l] * a[r], the score for deleting last at the very end.

Ranges of a smaller gap come first, so dp[l][k] and dp[k][r] are final when (l, r) reads them. Java fills the new array with zeros, so the gap-1 entries need no extra code.

Code

Filling Intervals By Gap Size

The method returns the largest score for deleting every entry. It copies the input into an array with the outside value 1 added at both ends and fills intervals in order of increasing gap.

static int bestDeletionScore(int[] values) {
    int n = values.length;
    int[] a = new int[n + 2];
    a[0] = 1;
    a[n + 1] = 1;
    for (int i = 0; i < n; i++) a[i + 1] = values[i];
    int[][] dp = new int[n + 2][n + 2];
    for (int gap = 2; gap <= n + 1; gap++) {
        for (int l = 0; l + gap <= n + 1; l++) {
            int r = l + gap;
            for (int k = l + 1; k < r; k++) {
                int total = a[l] * a[r] + dp[l][k] + dp[k][r];
                if (total > dp[l][r]) dp[l][r] = total;
            }
        }
    }
    return dp[0][n + 1];
}

Time grows as O(n^3), because O(n^2) intervals each try up to n choices. Memory is O(n^2) for the table. An empty array gives n = 0, the gap loop starts at 2 and never runs, and the method returns 0. The product of two ends can reach large values, so a very large input needs long instead of int.

When to use it

Matching The Index To The Problem

Reading The Cue

Ask what must stay fixed when two choices lead to the same remaining work. If the last operation inside a contiguous range splits it into independent parts, use a range index. If the last piece of a prefix is judged alone, use a prefix index with a validity table. If the future depends on a small set of used items and not on their order, use a mask. If many range questions are asked on one text, fill the whole range table once.

Checking The Invariant

The invariant says that each entry is final before any entry reads it and that it describes exactly its own index. Test the empty input, a single item, two equal items and a case where the greedy choice and the best choice differ. Compare against a brute-force search on inputs small enough to enumerate. A table that returns a value above the brute force has read an entry that was not yet final.

Spotting The False Friend

The false friend is a prefix table used for a problem where choices change the neighbours of other items. It passes tests where the best order happens to run left to right. The second false friend is the greedy rule above, which passes whenever the best immediate choice is also globally best. A third false friend is a mask over bucket loads: it stores a bucket order that the problem does not care about.

Knowing When Not To Use It

Do not use a mask when the item count exceeds about 20, because 2^n entries no longer fit in memory. Do not use an O(n^3) interval table when n is in the thousands. Both cases call for a different formulation.

Palindromic Subsequence In Query Ranges

LeetCode 516

Problem Specification. A string s and a list of queries are given. Each query is a pair (l, r) of indexes with l <= r. For every query, return the length of the longest palindromic subsequence of the substring s[l..r]. A palindromic subsequence keeps characters in order, may skip characters and reads the same in both directions. Return the answers in query order.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 300.
  • Queries number at most 2000, and 0 <= l <= r < s.length().
  • Characters are lowercase English letters.
  • Result is an int[] with one entry per query.
  • Mutation is not allowed, because strings are immutable.

Example 1. Input s = "xabcbayz", queries = [[0,7],[1,5],[2,2],[6,7]], output [5, 5, 1, 1].

Example 2. Input s = "cbbdcb", queries = [[0,5],[1,4]], output [4, 2].

Prerequisites. The interval table from this lesson and the range table from chapter 28.

What This Exercise Changes. One table answers every query after it is filled once. The table keeps all ranges, because a query may ask for any of them.

Hint

What does a range with equal end characters read, and what does a range with different end characters read? What value does an empty inner range have?

Algorithmic Solution (attempt the problem first)

Approach. The table dp[l][r] holds the longest palindromic subsequence length of s[l..r]. A single character gives 1. When the two end characters match, both join the subsequence and the inner range l + 1 .. r - 1 supplies the rest, so the entry is the inner value plus 2. When they differ, at least one end is unused, so the entry is the larger of the range without the left end and the range without the right end. If the inner range is empty, its entry is a cell that was never written and still holds 0.

Rows run from the last start index down to 0 and columns run upward from l, so each entry reads only shorter ranges that are already final. Every query then reads one cell. The invariant is that dp[l][r] describes exactly the substring s[l..r] and nothing else.

Complexity.

  • Time is O(n^2 + q) for n characters and q queries, because the table has about n^2 / 2 entries with constant work each and a query is one read.
  • Space is O(n^2) for the table, plus O(q) for the answers.
import java.util.*;

public final class Dp29RangePalindromeQueries {
    /**
     * Answers each query with the longest palindromic subsequence length of s[l..r].
     * Time: O(n^2 + q). Space: O(n^2 + q).
     * Invariant: dp[l][r] is final and describes exactly s[l..r] when a longer range reads it.
     */
    static int[] answer(String s, int[][] queries) {
        // n is the number of characters.
        int n = s.length();
        // Row n and the cells below the diagonal stay 0, which covers empty inner ranges.
        int[][] dp = new int[n + 1][n];
        // Start indexes run from the right so that dp[l + 1][...] is final first.
        for (int l = n - 1; l >= 0; l--) {
            // A single character is a palindrome of length 1.
            dp[l][l] = 1;
            // Ends move apart one position at a time, and each range reads shorter ranges only.
            for (int r = l + 1; r < n; r++) {
                if (s.charAt(l) == s.charAt(r)) {
                    // Equal ends join the subsequence around the inner range.
                    dp[l][r] = dp[l + 1][r - 1] + 2;
                } else {
                    // Different ends mean one end is unused, so keep the larger shorter range.
                    dp[l][r] = Math.max(dp[l + 1][r], dp[l][r - 1]);
                }
            }
        }
        // Each query is one table read.
        int[] out = new int[queries.length];
        for (int q = 0; q < queries.length; q++) out[q] = dp[queries[q][0]][queries[q][1]];
        return out;
    }

    /** Oracle: tries every subset of the characters in the range and keeps the longest palindrome. */
    static int oracle(String s, int l, int r) {
        int len = r - l + 1;
        int best = 0;
        for (int mask = 1; mask < (1 << len); mask++) {
            StringBuilder t = new StringBuilder();
            for (int k = 0; k < len; k++) if ((mask >> k & 1) == 1) t.append(s.charAt(l + k));
            if (t.toString().contentEquals(new StringBuilder(t).reverse()) && t.length() > best) best = t.length();
        }
        return best;
    }

    public static void main(String[] args) {
        // Both examples of the exercise.
        if (!Arrays.equals(answer("xabcbayz", new int[][]{{0, 7}, {1, 5}, {2, 2}, {6, 7}}), new int[]{5, 5, 1, 1})) throw new AssertionError("ex1");
        if (!Arrays.equals(answer("cbbdcb", new int[][]{{0, 5}, {1, 4}}), new int[]{4, 2})) throw new AssertionError("ex2");
        // A one-character string, equal pair and unequal pair at the edges.
        if (answer("a", new int[][]{{0, 0}})[0] != 1) throw new AssertionError("single");
        if (answer("aa", new int[][]{{0, 1}})[0] != 2) throw new AssertionError("pair");
        if (answer("ab", new int[][]{{0, 1}})[0] != 1) throw new AssertionError("different pair");
        // A new int array holds zeros, so the empty inner range of an equal pair reads 0.
        int[][] fresh = new int[3][2];
        if (fresh[2][1] != 0) throw new AssertionError("zero fill");
        // Strings are immutable, so the call leaves the input equal to its copy.
        String keep = new String("abcba");
        answer(keep, new int[][]{{0, 4}});
        if (!keep.equals("abcba")) throw new AssertionError("immutable");
        // Random strings and random ranges against the subset oracle.
        Random rnd = new Random(2901);
        for (int t = 0; t < 400; t++) {
            int n = 1 + rnd.nextInt(10);
            StringBuilder b = new StringBuilder();
            for (int i = 0; i < n; i++) b.append((char) ('a' + rnd.nextInt(3)));
            String s = b.toString();
            int[][] qs = new int[5][2];
            for (int[] q : qs) {
                q[0] = rnd.nextInt(n);
                q[1] = q[0] + rnd.nextInt(n - q[0]);
            }
            int[] got = answer(s, qs);
            for (int i = 0; i < qs.length; i++) {
                if (got[i] != oracle(s, qs[i][0], qs[i][1])) throw new AssertionError("random " + t);
            }
        }
    }

Palindrome Cuts With Minimum Piece Length

LeetCode 132

Problem Specification. A string s and an integer minLen are given. A cut splits s between two neighbouring characters. Choose cuts so that every piece is a palindrome with at least minLen characters. Return the smallest number of cuts, or -1 if no choice of cuts works.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 1000.
  • Minimum length satisfies 1 <= minLen <= s.length().
  • Characters are lowercase English letters.
  • Result is an int, with -1 when impossible.
  • Mutation is not allowed, because strings are immutable.

Example 1. Input s = "aaacbcaa", minLen = 2, output 2. With minLen = 1 the same string needs only 1 cut.

Example 2. Input s = "abacabb", minLen = 2, output -1.

Prerequisites. The exercise above and the palindrome table lesson.

What This Exercise Changes. A prefix may be unreachable. The prefix table needs a marker for that state, and the length floor removes some cuts that a palindrome table alone would accept.

Hint

Which earlier prefixes may end just before the last piece, and what must be true about the last piece itself? What marks a prefix that has no valid split?

Algorithmic Solution (attempt the problem first)

Approach. The first table pal[i][j] is true when s[i..j] is a palindrome. Equal end characters make the range a palindrome when the inner range is empty, has one character or is itself a palindrome. The second table pieces[j] is the fewest pieces that cover the first j characters, with a large marker for a prefix that cannot be covered. The empty prefix needs 0 pieces. For each j, the loop tries each start i of the last piece and accepts it when pal[i][j - 1] is true and the piece length j - i is at least minLen and pieces[i] is reachable.

The answer is pieces[n] - 1, which counts cuts and not pieces, or -1 when the marker remains. The invariant is that pieces[j] is final when a longer prefix reads it, and the palindrome table is complete before the prefix loop starts.

Complexity.

  • Time is O(n^2), because the palindrome table and the prefix loop each visit about n^2 / 2 pairs with constant work.
  • Space is O(n^2) for the palindrome table and O(n) for the prefix array.
import java.util.*;

public final class Dp29CutsMinPieceLength {
    /**
     * Returns the fewest cuts so every piece is a palindrome of at least minLen characters, or -1.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: pieces[j] is final before any longer prefix reads it.
     */
    static int minCuts(String s, int minLen) {
        // n is the number of characters.
        int n = s.length();
        // pal[i][j] is true when s[i..j] is a palindrome.
        boolean[][] pal = new boolean[n][n];
        // Start indexes run from the right so that the inner range is final first.
        for (int i = n - 1; i >= 0; i--) {
            for (int j = i; j < n; j++) {
                // Equal ends make a palindrome when the inner range is short or already a palindrome.
                pal[i][j] = s.charAt(i) == s.charAt(j) && (j - i < 2 || pal[i + 1][j - 1]);
            }
        }
        // INF marks a prefix that has no valid cover.
        final int INF = Integer.MAX_VALUE / 2;
        int[] pieces = new int[n + 1];
        // The empty prefix needs 0 pieces.
        Arrays.fill(pieces, INF);
        pieces[0] = 0;
        // j is the prefix length, and the last piece is s[i..j - 1].
        for (int j = 1; j <= n; j++) {
            for (int i = 0; i < j; i++) {
                // The piece must be long enough, a palindrome, and attach to a reachable prefix.
                if (j - i >= minLen && pal[i][j - 1] && pieces[i] < INF) {
                    pieces[j] = Math.min(pieces[j], pieces[i] + 1);
                }
            }
        }
        // A cover of p pieces uses p - 1 cuts.
        return pieces[n] >= INF ? -1 : pieces[n] - 1;
    }

    /** Oracle: tries every subset of the n - 1 gaps as cuts. */
    static int oracle(String s, int minLen) {
        int n = s.length();
        int best = -1;
        for (int mask = 0; mask < (1 << (n - 1)); mask++) {
            int start = 0;
            boolean ok = true;
            int cuts = Integer.bitCount(mask);
            for (int i = 0; i < n && ok; i++) {
                // A piece ends at index i when a cut follows it or the string ends.
                if (i == n - 1 || (mask >> i & 1) == 1) {
                    String piece = s.substring(start, i + 1);
                    ok = piece.length() >= minLen && piece.contentEquals(new StringBuilder(piece).reverse());
                    start = i + 1;
                }
            }
            if (ok && (best < 0 || cuts < best)) best = cuts;
        }
        return best;
    }

    public static void main(String[] args) {
        // The examples of the exercise, including the impossible case.
        if (minCuts("aaacbcaa", 2) != 2) throw new AssertionError("ex1");
        if (minCuts("aaacbcaa", 1) != 1) throw new AssertionError("ex1 floor 1");
        if (minCuts("abacabb", 2) != -1) throw new AssertionError("ex2");
        // A whole palindrome needs 0 cuts, and a single character fails a floor of 2.
        if (minCuts("racecar", 1) != 0) throw new AssertionError("whole");
        if (minCuts("a", 1) != 0) throw new AssertionError("single");
        if (minCuts("a", 1 + 1) != -1) throw new AssertionError("single floor");
        // Integer.MAX_VALUE / 2 plus 1 does not overflow, so INF can be extended safely.
        if (Integer.MAX_VALUE / 2 + 1 < 0) throw new AssertionError("overflow");
        // Random strings and floors against the cut-subset oracle.
        Random rnd = new Random(2902);
        for (int t = 0; t < 1500; t++) {
            int n = 1 + rnd.nextInt(10);
            StringBuilder b = new StringBuilder();
            for (int i = 0; i < n; i++) b.append((char) ('a' + rnd.nextInt(2)));
            String s = b.toString();
            int floor = 1 + rnd.nextInt(n);
            if (minCuts(s, floor) != oracle(s, floor)) throw new AssertionError("random " + t + " " + s + " " + floor);
        }
    }

Burst Balloons With Given Outer Values

LeetCode 312

Problem Specification. An array nums and two integers leftEdge and rightEdge are given. Bursting the balloon at index i earns left * nums[i] * right, where left and right are the nearest balloons that have not burst yet. If no balloon remains on a side, that side uses leftEdge or rightEdge. Burst every balloon in some order. Return the largest total.

Input Constraints. The limits are:

  • Length satisfies 0 <= nums.length <= 300, and the array may be empty.
  • Values satisfy 0 <= nums[i] <= 100.
  • Edges satisfy 0 <= leftEdge, rightEdge <= 100.
  • Result is an int, and 0 is returned for an empty array.
  • Mutation is not allowed; the method copies the array before it adds the edges.

Example 1. Input nums = [2,4,3], leftEdge = 5, rightEdge = 2, output 130.

Example 2. Input nums = [2,4,3], leftEdge = 0, rightEdge = 0, output 24.

Prerequisites. The two exercises above and the interval table from this lesson.

What This Exercise Changes. The two outside values are inputs, not fixed to 1. A value of 0 at an edge makes some choices worth nothing, so the table cannot rely on ones as defaults.

Hint

If a balloon is the last one burst inside an interval, which two values are its neighbours, and where do the edges enter the table?

Algorithmic Solution (attempt the problem first)

Approach. The method copies nums into an array a of length n + 2 with leftEdge at index 0 and rightEdge at index n + 1. Entry dp[l][r] is the best total for bursting every balloon strictly between l and r while positions l and r stay. The balloon k burst last inside the range has neighbours a[l] and a[r], so it earns a[l] * a[k] * a[r]. Before that, the balloons between l and k and between k and r were burst independently, which gives dp[l][k] + dp[k][r].

Ranges with a larger gap read only ranges with a smaller gap, so the loops run by increasing gap. Ranges with gap 1 hold no balloon and stay 0. With an empty array the gap loop does not run, and the answer is 0. The edges are separate from the values, so an edge of 0 makes every product at that side 0 without any special case.

Complexity.

  • Time is O(n^3), because O(n^2) ranges try up to n last balloons each.
  • Space is O(n^2) for the table.
import java.util.*;

public final class Dp29BurstOuterValues {
    /**
     * Returns the largest total from bursting every balloon, with the given outside values.
     * Time: O(n^3). Space: O(n^2).
     * Invariant: dp[l][r] is final before any wider range reads it.
     */
    static int maxCoins(int[] nums, int leftEdge, int rightEdge) {
        // n is the number of balloons, and the copy leaves the input unchanged.
        int n = nums.length;
        int[] a = new int[n + 2];
        // The two edge cells hold the outside values.
        a[0] = leftEdge;
        a[n + 1] = rightEdge;
        for (int i = 0; i < n; i++) a[i + 1] = nums[i];
        int[][] dp = new int[n + 2][n + 2];
        // The gap r - l grows, so both parts of a split are final when read.
        for (int gap = 2; gap <= n + 1; gap++) {
            for (int l = 0; l + gap <= n + 1; l++) {
                int r = l + gap;
                // k is the balloon burst last inside (l, r), so its neighbours are a[l] and a[r].
                for (int k = l + 1; k < r; k++) {
                    int total = a[l] * a[k] * a[r] + dp[l][k] + dp[k][r];
                    if (total > dp[l][r]) dp[l][r] = total;
                }
            }
        }
        // The widest range spans both edges.
        return dp[0][n + 1];
    }

    /** Oracle: tries every burst order with recursion on the remaining balloons. */
    static int oracle(List<Integer> rest, int left, int right) {
        if (rest.isEmpty()) return 0;
        int best = 0;
        for (int i = 0; i < rest.size(); i++) {
            int l = i == 0 ? left : rest.get(i - 1);
            int r = i == rest.size() - 1 ? right : rest.get(i + 1);
            List<Integer> next = new ArrayList<>(rest);
            next.remove(i);
            best = Math.max(best, l * rest.get(i) * r + oracle(next, left, right));
        }
        return best;
    }

    public static void main(String[] args) {
        // The examples of the exercise.
        if (maxCoins(new int[]{2, 4, 3}, 5, 2) != 130) throw new AssertionError("ex1");
        if (maxCoins(new int[]{2, 4, 3}, 0, 0) != 24) throw new AssertionError("ex2");
        // The empty array gives 0, and one balloon earns edge * value * edge.
        if (maxCoins(new int[]{}, 5, 5) != 0) throw new AssertionError("empty");
        if (maxCoins(new int[]{7}, 3, 4) != 84) throw new AssertionError("single");
        // The input array stays unchanged.
        int[] keep = {2, 4, 3};
        maxCoins(keep, 1, 1);
        if (!Arrays.equals(keep, new int[]{2, 4, 3})) throw new AssertionError("input changed");
        // The largest allowed total stays inside int range: 300 balloons of 100 with edges of 100.
        long bound = 300L * 100 * 100 * 100;
        if (bound > Integer.MAX_VALUE) throw new AssertionError("overflow bound");
        // Random arrays and edges against the order oracle.
        Random rnd = new Random(2903);
        for (int t = 0; t < 600; t++) {
            int n = rnd.nextInt(7);
            int[] v = new int[n];
            List<Integer> list = new ArrayList<>();
            for (int i = 0; i < n; i++) {
                v[i] = rnd.nextInt(6);
                list.add(v[i]);
            }
            int le = rnd.nextInt(6);
            int re = rnd.nextInt(6);
            if (maxCoins(v, le, re) != oracle(list, le, re)) throw new AssertionError("random " + t);
        }
    }

Largest Number Of Equal Sum Groups

LeetCode 698

Problem Specification. An array nums of positive integers is given. Split all entries into k non-empty groups so that every group has the same sum. Every entry belongs to exactly one group. Return the largest k for which such a split exists.

Input Constraints. The limits are:

  • Length satisfies 1 <= nums.length <= 16.
  • Values satisfy 1 <= nums[i] <= 10000.
  • Result is an int, and k = 1 always works.
  • Mutation is not allowed.

Example 1. Input nums = [1,2,3,4,5,6], output 3.

Example 2. Input nums = [7,7,2,2,3,3], output 2.

Prerequisites. All three exercises above and the bitmask lesson.

What This Exercise Changes. The method tries each possible k and runs a mask search for each. The fill of the open group follows from the mask alone, so the search does not track which group is which.

Hint

For a fixed group count, what sum must each group have? Does the fill of the group in progress depend on the order the used items were added, or only on which items are used?

Algorithmic Solution (attempt the problem first)

Approach. For a fixed group count k, the total must divide by k, and the share target = total / k must be at least the largest entry. The search then walks over subsets. Entry fill[mask] is the sum of the used items modulo target when the used items can be arranged into complete groups plus one open group, and -1 otherwise. The empty set has fill 0. From a reachable mask, adding an unused item is allowed when the open group stays at or below target. The new fill is the sum modulo target, so a closed group wraps to 0.

The fill of the open group depends only on the sum of the mask, so the search never records which group holds which item. That removes the symmetric work of trying equal groups in different orders. The set of all items works when fill[full] == 0. The method tries k from the item count down to 2, returns the first that works, and returns 1 otherwise. The invariant is that fill[mask] is final before a larger mask reads it, because adding a bit always raises the mask value.

Complexity.

  • Time is O(d * 2^n * n) for n items and d divisors of the total that reach the search, because each mask tries each unused item.
  • Space is O(2^n) for the fill array, reused for each divisor.
import java.util.*;

public final class Dp29EqualSumGroups {
    /**
     * Returns the largest k so nums splits into k non-empty groups of equal sum.
     * Time: O(d * 2^n * n). Space: O(2^n).
     * Invariant: fill[mask] depends on the mask alone and is final before a larger mask reads it.
     */
    static int largestGroupCount(int[] nums) {
        // n is the item count and total is the sum of all items.
        int n = nums.length;
        int total = 0;
        int max = 0;
        for (int v : nums) {
            total += v;
            max = Math.max(max, v);
        }
        // fill is reused across divisors; its size is 2^n.
        int[] fill = new int[1 << n];
        // Try the largest group count first, so the first success is the answer.
        for (int k = n; k >= 2; k--) {
            // The total must divide into k shares, and no item may exceed a share.
            if (total % k != 0 || total / k < max) continue;
            int target = total / k;
            Arrays.fill(fill, -1);
            fill[0] = 0;
            // Masks grow with each added bit, so a mask is final before any superset reads it.
            for (int mask = 0; mask < (1 << n); mask++) {
                if (fill[mask] < 0) continue;
                for (int i = 0; i < n; i++) {
                    // Skip items already used.
                    if ((mask >> i & 1) == 1) continue;
                    // The open group must stay within the target.
                    if (fill[mask] + nums[i] > target) continue;
                    // The modulo wraps a completed group to 0.
                    fill[mask | 1 << i] = (fill[mask] + nums[i]) % target;
                }
            }
            // A reachable full mask with fill 0 means every group closed exactly.
            if (fill[(1 << n) - 1] == 0) return k;
        }
        // One group holding every item always works.
        return 1;
    }

    /** Oracle: assigns every item to a group index with plain recursion for each k. */
    static boolean oracleSplit(int[] nums, int idx, int[] load, int target) {
        if (idx == nums.length) {
            for (int x : load) if (x != target) return false;
            return true;
        }
        for (int g = 0; g < load.length; g++) {
            load[g] += nums[idx];
            boolean ok = oracleSplit(nums, idx + 1, load, target);
            load[g] -= nums[idx];
            if (ok) return true;
        }
        return false;
    }

    static int oracle(int[] nums) {
        int total = Arrays.stream(nums).sum();
        for (int k = nums.length; k >= 1; k--) {
            if (total % k == 0 && oracleSplit(nums, 0, new int[k], total / k)) return k;
        }
        return 1;
    }

    public static void main(String[] args) {
        // The examples of the exercise.
        if (largestGroupCount(new int[]{1, 2, 3, 4, 5, 6}) != 3) throw new AssertionError("ex1");
        if (largestGroupCount(new int[]{7, 7, 2, 2, 3, 3}) != 2) throw new AssertionError("ex2");
        // One item, equal items and a total with no usable divisor.
        if (largestGroupCount(new int[]{5}) != 1) throw new AssertionError("single");
        if (largestGroupCount(new int[]{3, 3, 3, 3}) != 4) throw new AssertionError("equal");
        if (largestGroupCount(new int[]{1, 2, 4}) != 1) throw new AssertionError("prime total");
        // Operator precedence: 1 << n is evaluated before the bitwise or in mask | 1 << i.
        if ((5 | 1 << 1) != 7) throw new AssertionError("precedence");
        // Random arrays against the assignment oracle.
        Random rnd = new Random(2904);
        for (int t = 0; t < 400; t++) {
            int n = 1 + rnd.nextInt(7);
            int[] v = new int[n];
            for (int i = 0; i < n; i++) v[i] = 1 + rnd.nextInt(5);
            int[] copy = v.clone();
            if (largestGroupCount(v) != oracle(copy)) throw new AssertionError("random " + t + " " + Arrays.toString(v));
            if (!Arrays.equals(v, copy)) throw new AssertionError("input changed");
        }
    }
