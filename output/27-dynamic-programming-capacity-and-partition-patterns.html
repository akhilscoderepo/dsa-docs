Chapter 27

Dynamic Programming Capacity And Partition Patterns

Orientation

A game shop pays out loyalty points in tokens and its change routine hands out four tokens where two would do. A backup tool copies a file onto a disk twice because its table lets the file be chosen again. A cashier screen lists nine ways to pay five units when only four exist. Each program has a table with a sound meaning and one wrong choice in its loops. This chapter adds a capacity to the table state and shows how the direction of a loop and the owner of the outer loop decide what the table counts.

Prerequisites

You should know the foundations chapter before this one. That chapter explained how to say in one sentence what a table entry means, how to seed the base entry, and how to read only entries that are already final. This chapter uses arrays of int and long, and it assumes import java.util.*; in code samples.

The Seven Lessons

Each lesson fixes one decision about a table that is indexed by a total or a capacity.

  • Unbounded Coin Change finds the fewest items for an exact total when every item can repeat. The table walks the totals upward, so a finished entry may already contain the same item.
  • Unbounded Knapsack keeps a value for each capacity when items repeat and leftover capacity is allowed. Each entry compares skipping an item with taking one more copy.
  • Zero-One Knapsack lets each item appear once. A one-dimensional table works only when the capacities are visited downward.
  • Partition State records which sums a subset can reach. A subset is any choice of positions, and the question is whether one reaches half of the total.
  • Target Sum turns a plus or minus choice for each number into a count of subsets. The derived goal is (total + target) / 2.
  • Combination Counts counts unordered ways to reach a total. A combination is a choice of how many times each item is used.
  • Permutation Counts counts ordered ways to reach a total. A sequence is a list in which the order of the items matters.

The Combination Lesson

  • DP And Capacity joins the two loop decisions and the combine rule into one procedure, and it shows what each wrong setting returns.

How To Work Through Each Lesson

A lesson opens with a small program that returns a wrong or slow answer on a realistic input. It shows a first version and asks you to predict its output. Later parts name the rule, list the variables, follow two traces, show the code and say when the rule stops fitting. Four exercises close each lesson, and they climb through Build, Vary, Boundary and Recognize. Read a hint only after a real attempt.

You can read a statement and decide whether items repeat, whether order counts and what the table entry must hold. You can choose the loop direction and the loop owner from those answers, and you can say which neighboring question a wrong choice answers. You can reduce signed sums to a subset count, and you can use long counts when the numbers grow.

Problem

Paying Out Loyalty Points In Tokens

A rewards service pays out loyalty points as tokens worth 1, 3 and 4 points. A customer redeems 6 points, and the service wants to hand out as few tokens as possible. A payout routine that always hands out the largest token that still fits pays 4, then 1, then 1, which is three tokens. Two tokens of value 3 pay the same amount.

Formally, the input is an array coins of distinct positive integers and a nonnegative integer amount. Every denomination may be used any number of times. The task is to return the smallest number of tokens whose values add up to exactly amount, or -1 when no combination reaches it. The method never changes the array.

This lesson asks how to find the smallest token count without testing every combination of tokens.

Simple approach

Paying With The Largest Token First

The quick idea is greedy. Sort the denominations, then repeatedly hand out as many tokens of the largest denomination as fit, and continue with the next smaller denomination for the rest.

static int greedyCoins(int[] coins, int amount) {
    int[] sorted = coins.clone();
    Arrays.sort(sorted);
    int left = amount;
    int count = 0;
    for (int i = sorted.length - 1; i >= 0; i--) {
        count += left / sorted[i];
        left %= sorted[i];
    }
    return left == 0 ? count : -1;
}

The method sorts a copy and then makes one pass, so it runs in O(k log k) time for k denominations. It is fast and it pays correctly for many token sets. The open question is whether the largest token always belongs to a cheapest payout.

Predict first: Run greedyCoins with the tokens [1, 3, 4] and the amount 6. What does it return, and what is the true smallest count?

It returns 3, because it pays 4, then 1, then 1. The true smallest count is 2, from the tokens 3 and 3. Taking the biggest token first can leave a remainder that needs many small tokens.

Bottleneck

Many Orders Reach The Same Remainder

The greedy method commits to a token before it knows what the remainder costs. A cheaper payout can start with a smaller token, so no ordering of the denominations repairs the method for every token set.

A correct but slow method tries every denomination as the next token and recurses on the remainder. With k denominations and a smallest denomination m, the recursion has depth up to amount / m and branches k ways at each level. The call count grows like O(k^(amount/m)). For tokens 1, 2 and 5 and the amount 100, that is more than 3^100 calls.

Most of those calls repeat. Paying 1 then 2 and paying 2 then 1 both leave the same remainder, and the remaining cost depends only on that remainder. There are only amount + 1 distinct remainders. A method that stores one answer per remainder does k steps of work per remainder, which is O(amount * k) time in total. The next section defines that table.

Key idea

Build The Table From Small Amounts Up

Imagine the cheapest payout for some amount. Look at one token in it and ask what the rest of the payout must be. The rest pays a smaller amount, and it must itself be cheapest for that smaller amount.

One Entry For Each Amount

Let dp[a] be the smallest number of tokens that add up to exactly a. The final answer is dp[amount]. The entry dp[0] is 0, because paying nothing needs no tokens. An amount that no combination reaches is unreachable, and its entry holds the marker amount + 1. That marker is larger than any real answer, because every token is worth at least 1 point and so a payout never needs more than amount tokens.

The Last Coin Splits Every Payout

Pick any payout for amount a and let c be the last coin in it, meaning any one token removed from the payout. The remaining tokens pay a - c exactly, and they form a cheapest payout for a - c, because a cheaper one would also improve the payout for a. So dp[a] equals 1 plus the smallest dp[a - c] over all denominations c with c <= a. A denomination larger than a cannot be the last coin. When every candidate entry holds the marker, dp[a] keeps the marker too.

Fill In Increasing Amounts

The loop visits increasing amounts from 1 to amount. When it reaches a, every entry below a is final. The entry dp[a - c] may already count the same denomination c once or several times. The loop therefore allows every denomination to appear again in any payout, which is exactly what the problem permits. The invariant is that dp[a] is correct for every amount the loop has passed, and the order of the amounts is what grants repeated use.

State

The Table And The Candidate Coin

The method reads coins and amount and changes nothing. It keeps these working values.

  • dp is an int[] of length amount + 1; entry a is the smallest token count that adds up to a.
  • a is the amount that the outer loop fills, from 1 to amount.
  • coin is the denomination that the inner loop tries as the last coin.
  • marker is the value amount + 1, which stands for an unreachable amount.

The marker is not Integer.MAX_VALUE. Adding 1 to that value overflows to a negative number and makes the unreachable entry look like the best one. With the marker amount + 1, the sum dp[a - coin] + 1 never exceeds amount + 2, so it fits in an int.

Walkthrough

Two Runs Over Small Amounts

A Smaller Token Beats The Largest

The first run uses the tokens 1, 3 and 4 and the amount 6. Each cell is an amount from 0 to 6, and the pointer a marks the amount that the loop fills. The variable dp is the filled entry and coin is the denomination that gave it. The first step, with the pointer at -1, shows the base entry.

At amount 3, the token 3 pays it alone. At amount 5, the last coin 1 leaves amount 4, which costs one token, so the payout costs two. At amount 6, the last coin 3 leaves amount 3, which costs one token. That gives 2 tokens, and the largest-token-first payout of 3 tokens is beaten.

Unreachable Amounts Stay Marked

The second run uses the tokens 5 and 7 and the amount 14. The marker is 15, so a dp value of 15 means that no combination reaches the amount. Amounts 1 to 4, 6, 8, 9, 11 and 13 keep the marker. Amount 14 becomes 2, because the last coin 7 leaves amount 7, which one token of 7 pays. The payout uses the denomination 7 twice, and the table allows that because dp[7] is final when amount 14 is filled.

Code

Two Loops Over Amounts And Coins

The method returns the smallest token count, or -1 when the amount is unreachable. It fills the table once, from small amounts to large ones.

static int minCoins(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++) {
        for (int coin : coins) {
            if (coin <= a && dp[a - coin] + 1 < dp[a]) dp[a] = dp[a - coin] + 1;
        }
    }
    return dp[amount] > amount ? -1 : dp[amount];
}

The test coin <= a keeps the index a - coin inside the table. The final comparison turns the marker into -1. The method runs in O(amount * k) time and uses O(amount) memory. For amount equal to 0 the loops do not run, and the method returns dp[0], which is 0.

When to use it

Recognizing Repeatable Items With A Count Goal

Reading The Cue

Use this method when a positive-valued item can be used any number of times, the items must add up to an exact target, and the goal is the smallest number of items. Wording such as "any number of each kind" and "fewest" points here. The table indexes the target value, and each entry depends on entries with smaller targets.

Checking The Invariant

An invariant is a statement that stays true before and after each loop step. Here it says that dp[a] is the fewest tokens for amount a for every amount the loop has passed. Test amount 0, which must return 0 even with no denominations. Test an amount below every denomination, which must return -1. Test one denomination that does not divide the amount.

Avoiding The False Friend

A false friend is a method that passes simple samples yet returns a wrong result on other inputs. The greedy payout is the false friend here, and it is correct only for token sets with a special structure. A second false friend is a table that holds Integer.MAX_VALUE as the marker and then adds 1 to it. A third is a loop over amounts that runs downward, which makes each denomination appear at most once and answers a different question.

Exercises

Exercises

Basic

One Denomination

Author exercise

Problem Specification. A single positive integer coin is the only denomination, and it may be used any number of times. Return the smallest number of tokens that add up to exactly amount, or -1 when no number of tokens does.

Input Constraints. The limits are:

  • Coin satisfies 1 <= coin <= 1000.
  • Amount satisfies 0 <= amount <= 10000, and amount 0 needs 0 tokens.
  • Result is an int, and -1 marks an unreachable amount.

Example 1. Input coin = 4, amount = 12, output 3.

Example 2. Input coin = 4, amount = 10, output -1.

Prerequisites. The table of fewest tokens per amount from this lesson.

What This Exercise Changes. The inner loop over denominations has one candidate, so the minimum is a single read. Amounts that are not multiples of the coin keep the marker.

Hint

With one denomination, which single earlier entry can the entry for amount a read, and what does it hold when that entry is unreachable?

Algorithmic Solution (attempt the problem first)

Approach. The table entry dp[a] holds the smallest token count for amount a, and the marker amount + 1 stands for an unreachable amount. With one denomination the last coin is always coin, so the entry reads only dp[a - coin] when that index exists. The base entry dp[0] is 0. The invariant is that every entry the loop has passed is exact, and an entry keeps the marker exactly when a is not a multiple of coin.

The loop runs in increasing order of a. When it reaches a multiple of the coin, the entry one coin earlier is already final, so the count grows by one per coin. The closed form amount / coin agrees with the table, and the test below checks that.

Complexity.

  • Time is O(amount), because each amount does one comparison and one table read.
  • Space is O(amount) for the table, and the inputs are not changed.
import java.util.*;

public final class CapCoinOneDenomination {
    /**
     * Returns the fewest tokens of one denomination that add up to amount, or -1.
     * Time: O(amount). Space: O(amount).
     * Invariant: dp[a] is exact for every amount the loop has passed.
     */
    static int oneDenomination(int coin, int amount) {
        // The marker amount + 1 is larger than any real token count.
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);
        // Paying nothing needs no tokens.
        dp[0] = 0;
        // Increasing amounts make each earlier entry final before it is read.
        for (int a = 1; a <= amount; a++) {
            // The only possible last coin is the single denomination.
            if (coin <= a && dp[a - coin] + 1 < dp[a]) dp[a] = dp[a - coin] + 1;
        }
        // The marker becomes -1 at the return.
        return dp[amount] > amount ? -1 : dp[amount];
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (oneDenomination(4, 12) != 3) throw new AssertionError("ex1");
        if (oneDenomination(4, 10) != -1) throw new AssertionError("ex2");
        // Amount 0 needs no tokens, and a coin above the amount cannot be used.
        if (oneDenomination(5, 0) != 0) throw new AssertionError("zero");
        if (oneDenomination(5, 3) != -1) throw new AssertionError("too big");
        // Every pair is checked against the closed form.
        for (int coin = 1; coin <= 30; coin++) {
            for (int amount = 0; amount <= 200; amount++) {
                int expected = amount % coin == 0 ? amount / coin : -1;
                if (oneDenomination(coin, amount) != expected) throw new AssertionError(coin + " " + amount);
            }
        }
    }
}verified
Variation

Coin Change

LeetCode 322

Problem Specification. An array coins holds distinct positive denominations, and each may be used any number of times. Return the smallest number of coins that add up to exactly amount, or -1 when no combination does.

Input Constraints. The limits are:

  • Length satisfies 1 <= coins.length <= 12.
  • Denomination satisfies 1 <= coins[i] <= 10000, and values are distinct.
  • Amount satisfies 0 <= amount <= 10000.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input coins = [3,7,10], amount = 14, output 2.

Example 2. Input coins = [5,9], amount = 8, output -1.

Prerequisites. The exercise above.

What This Exercise Changes. Every denomination that fits is tried as the last coin, and the entry keeps the smallest result. One denomination is no longer enough to decide the entry.

Hint

For one amount, which denominations can be the last coin, and which entry does each of them read?

Algorithmic Solution (attempt the problem first)

Approach. The table keeps the same meaning, and the entry for amount a now takes the smallest value of dp[a - coin] + 1 over every denomination with coin <= a. Each such denomination is a candidate for the last coin. The base entry is dp[0] = 0, and the marker amount + 1 is larger than any real count because each coin is worth at least 1.

The invariant is that dp[a] is the fewest coins for a for every amount the loop has passed. Increasing order of a is what lets a denomination appear more than once, since dp[a - coin] may already use it. A downward loop would answer a different question. The greedy method of the lesson fails on [1,3,4] with amount 6, and the test checks that the table does not.

Complexity.

  • Time is O(amount * k) for k denominations, because each amount tries each denomination once.
  • Space is O(amount) for the table, and the input array stays unchanged.
import java.util.*;

public final class CapCoinFewestCoins {
    /**
     * Returns the fewest coins that add up to amount, or -1 when no combination does.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: dp[a] is the fewest coins for a, for every amount the loop has passed.
     */
    static int minCoins(int[] coins, int amount) {
        // The marker amount + 1 stands for an unreachable amount.
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);
        // Paying nothing needs no coins.
        dp[0] = 0;
        // Increasing amounts allow the same denomination to appear again.
        for (int a = 1; a <= amount; a++) {
            // Each denomination that fits is a candidate for the last coin.
            for (int coin : coins) {
                // The candidate wins when the smaller amount plus one coin is cheaper.
                if (coin <= a && dp[a - coin] + 1 < dp[a]) dp[a] = dp[a - coin] + 1;
            }
        }
        // The marker becomes -1 at the return.
        return dp[amount] > amount ? -1 : dp[amount];
    }

    /** The greedy method of the lesson, kept to show that it fails. */
    static int greedy(int[] coins, int amount) {
        int[] sorted = coins.clone();
        Arrays.sort(sorted);
        int left = amount, count = 0;
        for (int i = sorted.length - 1; i >= 0; i--) {
            count += left / sorted[i];
            left %= sorted[i];
        }
        return left == 0 ? count : -1;
    }

    /** Oracle: breadth-first search over remaining amounts, one level per coin. */
    static int oracle(int[] coins, int amount) {
        int[] dist = new int[amount + 1];
        Arrays.fill(dist, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        dist[0] = 0;
        queue.add(0);
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int coin : coins) {
                int next = cur + coin;
                if (next <= amount && dist[next] == -1) {
                    dist[next] = dist[cur] + 1;
                    queue.add(next);
                }
            }
        }
        return dist[amount];
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minCoins(new int[] {3, 7, 10}, 14) != 2) throw new AssertionError("ex1");
        if (minCoins(new int[] {5, 9}, 8) != -1) throw new AssertionError("ex2");
        // The greedy method returns 3 for the lesson input, while the table returns 2.
        if (greedy(new int[] {1, 3, 4}, 6) != 3) throw new AssertionError("greedy value");
        if (minCoins(new int[] {1, 3, 4}, 6) != 2) throw new AssertionError("table value");
        // The input array stays unchanged.
        int[] coins = {4, 1, 3};
        int[] copy = coins.clone();
        minCoins(coins, 11);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs against the breadth-first oracle.
        Random rnd = new Random(2701);
        for (int t = 0; t < 3000; t++) {
            int k = 1 + rnd.nextInt(5);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(12));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(60);
            if (minCoins(c, amount) != oracle(c, amount)) throw new AssertionError("random " + t);
        }
    }
}verified
Edge Cases

Amount Zero And Impossible Target

Author exercise

Problem Specification. An array coins of distinct positive denominations, a nonnegative amount and an integer failure are given. Return the smallest number of coins that add up to exactly amount, or return failure when no combination does.

Input Constraints. The limits are:

  • Length satisfies 0 <= coins.length <= 12, and the array may be empty.
  • Amount satisfies 0 <= amount <= 10000, and amount 0 returns 0 even with no coins.
  • Failure satisfies -1000 <= failure <= 1000, and it may equal a valid count such as 0 or 2.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input coins = [], amount = 0, failure = -7, output 0.

Example 2. Input coins = [6,10], amount = 9, failure = 2, output 2.

Prerequisites. The two exercises above.

What This Exercise Changes. The table keeps its own marker amount + 1 and the method converts it to failure only at the return. A caller value such as 0 or 2 cannot be confused with a real count inside the table.

Hint

The table needs a marker that is never a real answer. Why must the marker not be the same value as failure?

Algorithmic Solution (attempt the problem first)

Approach. The table is the same as before, and the work is in the two edges. Amount 0 is answered by dp[0] = 0, which is set before any loop, so the answer is 0 even when coins is empty and the inner loop has nothing to try. An impossible amount keeps the table marker amount + 1. The method converts the marker to the caller's failure only in the final statement.

The invariant is that the table never stores failure. A caller value such as 0 or 2 is a legal count, and storing it inside the table would make a failed entry look like a payout. Keeping a separate marker avoids that, and the test uses a failure equal to a real count.

Complexity.

  • Time is O(amount * k), and it is O(amount) when coins is empty because the inner loop does nothing.
  • Space is O(amount) for the table, and the input array stays unchanged.
import java.util.*;

public final class CapCoinZeroAndImpossible {
    /**
     * Returns the fewest coins for amount, or failure when no combination reaches it.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: the table holds only real counts and the marker amount + 1.
     */
    static int coinsOrFailure(int[] coins, int amount, int failure) {
        // The marker stays inside the table and never equals the caller's failure value.
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);
        // Amount 0 is answered before any loop runs, so an empty coin array still returns 0.
        dp[0] = 0;
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) {
                // Only a coin that fits can be the last coin.
                if (coin <= a && dp[a - coin] + 1 < dp[a]) dp[a] = dp[a - coin] + 1;
            }
        }
        // Only the final statement maps the marker to the caller's value.
        return dp[amount] > amount ? failure : dp[amount];
    }

    /** Oracle: exhaustive recursion on the remaining amount, fine for small amounts. */
    static int oracle(int[] coins, int amount) {
        if (amount == 0) return 0;
        int best = Integer.MAX_VALUE;
        for (int coin : coins) {
            if (coin <= amount) {
                int sub = oracle(coins, amount - coin);
                if (sub != Integer.MAX_VALUE) best = Math.min(best, sub + 1);
            }
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (coinsOrFailure(new int[] {}, 0, -7) != 0) throw new AssertionError("ex1");
        if (coinsOrFailure(new int[] {6, 10}, 9, 2) != 2) throw new AssertionError("ex2");
        // A failure equal to a real count is still returned only for impossible amounts.
        if (coinsOrFailure(new int[] {3}, 6, 2) != 2) throw new AssertionError("real two");
        if (coinsOrFailure(new int[] {3}, 7, 2) != 2) throw new AssertionError("failure two");
        if (coinsOrFailure(new int[] {}, 5, 0) != 0) throw new AssertionError("failure zero");
        // Java fact: the sentinel Integer.MAX_VALUE overflows when 1 is added.
        if (Integer.MAX_VALUE + 1 >= 0) throw new AssertionError("overflow");
        // Random inputs against the recursive oracle, including empty coin arrays.
        Random rnd = new Random(2702);
        for (int t = 0; t < 2000; t++) {
            int k = rnd.nextInt(4);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(9));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(25);
            int failure = rnd.nextInt(7) - 3;
            int want = oracle(c, amount);
            if (want == Integer.MAX_VALUE) want = failure;
            if (coinsOrFailure(c, amount, failure) != want) throw new AssertionError("random " + t);
        }
    }
}verified
Pattern Recognition

Reconstruct One Minimum Set

Author exercise

Problem Specification. An array coins holds distinct positive denominations, each usable any number of times. Return an int[] of coins that add up to exactly amount and whose length is the smallest possible, listed from largest to smallest. Return null when no combination reaches amount. Any smallest set is accepted.

Input Constraints. The limits are:

  • Length satisfies 1 <= coins.length <= 12.
  • Denomination satisfies 1 <= coins[i] <= 1000, and values are distinct.
  • Amount satisfies 0 <= amount <= 5000, and amount 0 returns an empty array.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input coins = [1,3,4], amount = 6, output [3,3].

Example 2. Input coins = [2,5], amount = 3, output null.

Prerequisites. All three exercises above.

What This Exercise Changes. Each improvement also stores the last coin in a parallel array choice. The method then follows amount - choice[amount] until it reaches 0.

Hint

The table only stores counts. What second value, saved when an entry improves, lets the method walk back from amount to 0?

Algorithmic Solution (attempt the problem first)

Approach. The count table is unchanged, and a parallel array choice records the last coin each time an entry improves. When the method finishes, choice[amount] names one last coin of a smallest payout, and amount - choice[amount] is the remaining amount, whose own entry also holds a recorded coin. Following that chain down to 0 lists the coins.

The invariant is that choice[a] is a coin for which dp[a - choice[a]] + 1 == dp[a], so every step of the walk removes exactly one coin from a smallest payout. The walk collects coins in the order of the chain, and the method sorts them from largest to smallest to match the stated output. An amount of 0 gives an empty array and an unreachable amount gives null.

Complexity.

  • Time is O(amount * k) for the table and O(amount) for the walk, which is O(amount * k) in total.
  • Space is O(amount) for the two arrays, and the output has at most amount entries.
import java.util.*;

public final class CapCoinReconstruct {
    /**
     * Returns one smallest set of coins that adds up to amount, largest first, or null.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: dp[a] - 1 == dp[a - choice[a]] for every reachable a above 0.
     */
    static int[] oneMinimumSet(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        int[] choice = new int[amount + 1];
        Arrays.fill(dp, amount + 1);
        // Paying nothing needs no coins and records no last coin.
        dp[0] = 0;
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) {
                // An improvement also stores the coin that caused it.
                if (coin <= a && dp[a - coin] + 1 < dp[a]) {
                    dp[a] = dp[a - coin] + 1;
                    choice[a] = coin;
                }
            }
        }
        // An unreachable amount has no payout to list.
        if (dp[amount] > amount) return null;
        int[] out = new int[dp[amount]];
        // The walk removes one recorded last coin per step until the amount reaches 0.
        int rest = amount;
        for (int i = 0; rest > 0; i++) {
            out[i] = choice[rest];
            rest -= choice[rest];
        }
        // Largest first, as the output contract states.
        Arrays.sort(out);
        for (int i = 0, j = out.length - 1; i < j; i++, j--) {
            int tmp = out[i];
            out[i] = out[j];
            out[j] = tmp;
        }
        return out;
    }

    /** Oracle: breadth-first search for the smallest count. */
    static int oracleCount(int[] coins, int amount) {
        int[] dist = new int[amount + 1];
        Arrays.fill(dist, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        dist[0] = 0;
        queue.add(0);
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int coin : coins) {
                int next = cur + coin;
                if (next <= amount && dist[next] == -1) {
                    dist[next] = dist[cur] + 1;
                    queue.add(next);
                }
            }
        }
        return dist[amount];
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(oneMinimumSet(new int[] {1, 3, 4}, 6), new int[] {3, 3})) throw new AssertionError("ex1");
        if (oneMinimumSet(new int[] {2, 5}, 3) != null) throw new AssertionError("ex2");
        // Amount 0 returns an empty array.
        if (oneMinimumSet(new int[] {2, 5}, 0).length != 0) throw new AssertionError("zero");
        // The input array stays unchanged.
        int[] coins = {5, 2, 4};
        int[] copy = coins.clone();
        oneMinimumSet(coins, 13);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs: the set must use given coins, sum to the amount, be sorted downward and have the oracle's length.
        Random rnd = new Random(2703);
        for (int t = 0; t < 3000; t++) {
            int k = 1 + rnd.nextInt(5);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(12));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(60);
            int[] got = oneMinimumSet(c, amount);
            int want = oracleCount(c, amount);
            if (want == -1) {
                if (got != null) throw new AssertionError("expected null " + t);
                continue;
            }
            if (got == null || got.length != want) throw new AssertionError("length " + t);
            int sum = 0;
            for (int i = 0; i < got.length; i++) {
                sum += got[i];
                if (i > 0 && got[i] > got[i - 1]) throw new AssertionError("order " + t);
                boolean known = false;
                for (int coin : c) if (coin == got[i]) known = true;
                if (!known) throw new AssertionError("unknown coin " + t);
            }
            if (sum != amount) throw new AssertionError("sum " + t);
        }
    }

Problem

Filling A Compute Window With Repeatable Jobs

A batch scheduler has a 6-hour compute window. It offers two job types that can each run any number of times. Job A needs 4 hours and pays 5 points. Job B needs 3 hours and pays 3 points. A planner that ranks jobs by points per hour picks job A first, since 1.25 beats 1.0. Only 2 hours remain after that, so the plan earns 5 points. Running job B twice fills the window and earns 6 points.

Formally, the input is two arrays weight and value of equal length, plus a nonnegative integer capacity. Item i uses weight[i] units of capacity and pays value[i]. An item may be chosen any number of times. The task is to return the largest total value of a selection whose total weight is at most capacity. The empty selection is legal and the method never changes the arrays.

This lesson asks how to find the best total value without testing every combination of repeats.

Simple approach

Ranking Items By Value Per Unit

The quick idea is greedy. Rank the items by value divided by weight. Use as many copies of the top item as fit, then move to the next item and use the capacity that is left.

static int greedyPack(int[] weight, int[] value, int capacity) {
    Integer[] order = new Integer[weight.length];
    for (int i = 0; i < order.length; i++) order[i] = i;
    Arrays.sort(order, (x, y) -> Long.compare((long) value[y] * weight[x], (long) value[x] * weight[y]));
    int left = capacity;
    int total = 0;
    for (int i : order) {
        total += (left / weight[i]) * value[i];
        left %= weight[i];
    }
    return total;
}

The comparator multiplies instead of dividing, so it ranks items without fractions. The method sorts the items and makes one pass, so it runs in O(k log k) time for k items. It is fast and it packs correctly on many inputs. The open question is whether the best ratio always belongs to the best selection.

Predict first: Run greedyPack with weights [4, 3], values [5, 3] and capacity 6. What does it return, and what is the true best total?

It returns 5, because it takes one copy of the first item and cannot fit another. The true best total is 6, from two copies of the second item. A good ratio can leave unused capacity that a worse ratio would fill.

Bottleneck

Leftover Capacity Hides The Real Cost

The greedy method judges an item by its ratio, but the real cost of a choice is the capacity it leaves behind. Whether a leftover of 2 units is wasted depends on the other items, so no fixed ranking works for every input.

A correct but slow method decides how many copies of each item to take. Item i allows up to capacity / weight[i] copies. With k items, the number of count vectors is the product of those limits, which is O(capacity^k) for weights near 1. For capacity 100 and five items of weight 2, that is already more than 10^8 vectors.

Most vectors repeat a subproblem. Taking one copy of item A and then two of item B leaves the same remaining capacity as taking two of B and then one of A. The best future value depends only on the remaining capacity, and there are only capacity + 1 values for it. A table with one entry per capacity does k steps of work for each entry, which is O(capacity * k) time. The next section defines that table.

Key idea

Skip The Item Or Take It Again

Process the item kinds one at a time. After the first i kinds, ask for the best value of every capacity when only those kinds are allowed. Each new kind either helps or does not.

One Entry For Each Capacity

Let dp[c] be the largest total value of a selection with total weight at most c, using only the kinds processed so far. Before any kind is processed, every entry is 0, because the empty selection is legal. The final answer is dp[capacity]. The words "at most" matter here. The table needs no marker for an unreachable capacity, because leaving capacity unused is always allowed.

The Skip Case

To skip item i at capacity c means the best selection contains no copy of item i. Its value is the entry that the table already holds for c, which describes the earlier kinds only. This entry belongs to the previous row, meaning the table state before item i started.

The Take Case

To take item i at capacity c means the selection contains at least one copy. Remove one copy. What remains has weight at most c - weight[i] and may still contain copies of item i. So the remaining value is the entry for capacity c - weight[i] in the current row, meaning the table after item i has already updated that smaller capacity. The take value is that entry plus value[i].

Increasing Capacity Reads The Current Row

The loop visits capacities from weight[i] up to capacity. When it reaches c, the entry at c - weight[i] has already been rewritten for item i, so it may include earlier copies. This is why repeats are allowed. The new entry is the larger of skip and take. The invariant is that after item i finishes, dp[c] is the best value for every capacity when kinds 0 through i are allowed.

State

The Capacity Table And Two Candidates

The inputs weight, value and capacity stay unchanged, and the method keeps five working values.

  • dp is an int[] of length capacity + 1; entry c is the best value with weight at most c.
  • i is the item kind that the outer loop processes.
  • c is the capacity that the inner loop updates, from weight[i] to capacity.
  • skip is dp[c] before the update, which describes only earlier kinds.
  • take is dp[c - weight[i]] + value[i], which reads the current row.

The entries below weight[i] stay as they are, because item i does not fit there. Each value is a total that must fit in an int. When values reach 10^9, the totals need a long array.

Walkthrough

Two Runs Over Small Capacities

Taking The Smaller Item Twice

The first run uses the job example. Item 0 has weight 4 and value 5, and item 1 has weight 3 and value 3. Each cell is a capacity from 0 to 6, and the pointer c marks the capacity that the loop updates. The variable item names the kind in progress, skip and take are the two candidates, and dp is the entry after the update. The first step, with the pointer at -1, shows the empty table.

Item 0 fills capacities 4, 5 and 6 with the value 5, because only one copy fits. Item 1 then starts. At capacity 3 it takes 3. At capacity 6 it reads the current-row entry for capacity 3, which already holds 3, so taking gives 6 and beats the skip value 5.

One Item Used Several Times

The second run uses item 0 with weight 3 and value 4, and item 1 with weight 5 and value 7, for capacity 9. Item 0 reads its own updates. At capacity 6 it reads capacity 3 and gets 8, and at capacity 9 it reads capacity 6 and gets 12. Item 1 then helps only where it beats the stored entries. At capacity 8 it reads capacity 3 and gets 11, which beats 8. At capacity 9 it reads capacity 4 and gets 11, which loses to the stored 12.

Code

An Item Loop Around A Capacity Loop

The method returns the best total value. It processes one item kind at a time and updates the table in increasing order of capacity.

static int unboundedPack(int[] weight, int[] value, int capacity) {
    int[] dp = new int[capacity + 1];
    for (int i = 0; i < weight.length; i++) {
        for (int c = weight[i]; c <= capacity; c++) {
            int take = dp[c - weight[i]] + value[i];
            if (take > dp[c]) dp[c] = take;
        }
    }
    return dp[capacity];
}

The inner loop starts at weight[i], so the index c - weight[i] is never negative. The array starts at 0 because Java zero-fills new arrays, which matches the empty selection. The cost is O(capacity * k) time and O(capacity) memory for k kinds. An item heavier than the capacity never enters the inner loop.

When to use it

Recognizing Repeatable Items With A Weight Limit

Reading The Cue

Use this method when items have a weight and a value, the total weight has a limit, and each item can be chosen again and again. The goal is the largest total value, and leftover capacity is allowed. The table indexes the capacity, and each entry reads a smaller capacity in the same row.

Checking The Invariant

An invariant is a condition that holds at the start of every loop iteration. Here it says that after item i finishes, dp[c] is the best value using kinds 0 through i for each c. Test capacity 0, which must return 0. Test an item that does not fit at all, which must leave the table alone. Test two items with equal ratios, where either may be chosen.

Avoiding The False Friend

A false friend is a method that looks right on small samples but fails on other inputs. The ratio greedy of the naive section is one. A second is the inner loop run from high capacity down to low, which lets each kind enter at most once and answers the one-use question of the next lesson. A third is a table that demands an exact weight, which returns the wrong value when the best selection leaves capacity unused.

With one item, which earlier capacity does each entry read, and what does an entry hold when the item does not fit?

Algorithmic Solution (attempt the problem first)

Approach. The entry dp[c] holds the best value with total weight at most c, and every entry starts at 0 for the empty selection. With one item, the loop runs capacities from weight to capacity. Each entry compares the stored value with the value one copy below, which is dp[c - weight] + value. The current-row read is what chains the copies, because dp[c - weight] already holds the copies chosen below it.

The invariant is that dp[c] equals (c / weight) * value after the loop reaches c. The method returns dp[capacity], which must equal the closed form (capacity / weight) * value, and the test checks that.

Complexity.

  • Space is O(capacity) for the table, and the inputs are not changed.
import java.util.*;

public final class CapUknOneItem {
    /**
     * Returns the best value of copies of one item within capacity.
     * Time: O(capacity). Space: O(capacity).
     * Invariant: after the loop passes c, dp[c] is (c / weight) * value.
     */
    static int oneItem(int weight, int value, int capacity) {
        // Java zero-fills the table, which matches the empty selection at every capacity.
        int[] dp = new int[capacity + 1];
        // Increasing capacity lets the entry read copies already counted below it.
        for (int c = weight; c <= capacity; c++) {
            // Taking one more copy reads the current row at the smaller capacity.
            int take = dp[c - weight] + value;
            // The entry keeps the larger of the stored value and the take value.
            if (take > dp[c]) dp[c] = take;
        }
        // The full capacity covers every smaller selection.
        return dp[capacity];
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (oneItem(4, 7, 13) != 21) throw new AssertionError("ex1");
        if (oneItem(5, 9, 4) != 0) throw new AssertionError("ex2");
        // Capacity 0 returns 0.
        if (oneItem(3, 8, 0) != 0) throw new AssertionError("zero");
        // Every small input is checked against the closed form.
        for (int w = 1; w <= 20; w++) {
            for (int v = 0; v <= 10; v++) {
                for (int cap = 0; cap <= 100; cap++) {
                    if (oneItem(w, v, cap) != (cap / w) * v) throw new AssertionError(w + " " + v + " " + cap);
                }
            }
        }
    }

import java.util.*;

public final class CapUknMaxValue {
    /**
     * Returns the best total value of repeatable items within capacity.
     * Time: O(capacity * k). Space: O(capacity).
     * Invariant: after kind i finishes, dp[c] is the best value using kinds 0..i.
     */
    static int unboundedPack(int[] weight, int[] value, int capacity) {
        // Every entry starts at 0 for the empty selection.
        int[] dp = new int[capacity + 1];
        // One pass per item kind costs k passes over the table.
        for (int i = 0; i < weight.length; i++) {
            // Upward order makes dp[c - weight[i]] hold the current row.
            for (int c = weight[i]; c <= capacity; c++) {
                // The take value adds one copy to the best value of the smaller capacity.
                int take = dp[c - weight[i]] + value[i];
                // The skip value is the entry already stored, so the larger one stays.
                if (take > dp[c]) dp[c] = take;
            }
        }
        // The full capacity covers every smaller selection.
        return dp[capacity];
    }

    /** The ratio greedy of the lesson, kept to show that it fails. */
    static int greedy(int[] weight, int[] value, int capacity) {
        Integer[] order = new Integer[weight.length];
        for (int i = 0; i < order.length; i++) order[i] = i;
        Arrays.sort(order, (x, y) -> Long.compare((long) value[y] * weight[x], (long) value[x] * weight[y]));
        int left = capacity, total = 0;
        for (int i : order) {
            total += (left / weight[i]) * value[i];
            left %= weight[i];
        }
        return total;
    }

    /** Oracle: tries every vector of copy counts. */
    static int oracle(int[] weight, int[] value, int i, int left) {
        if (i == weight.length) return 0;
        int best = 0;
        for (int copies = 0; copies * weight[i] <= left; copies++) {
            best = Math.max(best, copies * value[i] + oracle(weight, value, i + 1, left - copies * weight[i]));
        }
        return best;
    }

        if (unboundedPack(new int[] {4, 3}, new int[] {5, 3}, 6) != 6) throw new AssertionError("ex1");

        if (greedy(new int[] {4, 3}, new int[] {5, 3}, 6) != 5) throw new AssertionError("greedy value");

Zero Capacity

Problem Specification. Arrays weight and value describe item kinds that may be chosen any number of times, and weights may be 0. If some item has weight 0 and positive value, the total value has no upper bound and the method returns -1. Otherwise it returns the largest total value of a selection with total weight at most capacity.

  • Capacity satisfies 0 <= capacity <= 10000, and an empty item list returns 0.

Example 2. Input weight = [0,5], value = [2,6], capacity = 7, output -1.

Prerequisites. The two exercises above.

What This Exercise Changes. The method checks for a zero-weight item with positive value before the loops. A zero-weight item with value 0 is skipped, because it never changes the table.

Hint

What happens to the inner loop when the weight is 0, and why would a repeat then add value forever?

Algorithmic Solution (attempt the problem first)

Approach. A zero-weight item with positive value breaks the table. The inner loop would start at capacity 0 and read dp[c - 0], which is the entry being written, so the update would add the value once and stop, while the true best total grows without limit. The method therefore scans the items first. If any item has weight 0 and value above 0, it returns -1 before any loop runs.

After that scan, a zero-weight item has value 0 and never changes an entry, so the loops skip it. Capacity 0 returns 0 because every other item has positive weight. The invariant of the main loop is unchanged: after item i finishes, dp[c] is the best value for every c using kinds 0 through i.

Complexity.

  • Time is O(k + capacity * k), which is O(capacity * k) for the table and O(k) for the scan.
  • Space is O(capacity) for the table, and both arrays stay unchanged.
import java.util.*;

public final class CapUknZeroCapacity {
    /**
     * Returns the best value of repeatable items within capacity, or -1 when the value is unbounded.
     * Time: O(capacity * k). Space: O(capacity).
     * Invariant: after kind i finishes, dp[c] is the best value using kinds 0..i.
     */
    static int packOrUnbounded(int[] weight, int[] value, int capacity) {
        // A free item with positive value can repeat forever, so no finite best exists.
        for (int i = 0; i < weight.length; i++) {
            if (weight[i] == 0 && value[i] > 0) return -1;
        }
        int[] dp = new int[capacity + 1];
        for (int i = 0; i < weight.length; i++) {
            // A zero-weight item now has value 0, so it can never change an entry.
            if (weight[i] == 0) continue;
            for (int c = weight[i]; c <= capacity; c++) {
                // The take value reads the current row at the smaller capacity.
                int take = dp[c - weight[i]] + value[i];
                if (take > dp[c]) dp[c] = take;
            }
        }
        // Capacity 0 returns dp[0], which is 0.
        return dp[capacity];
    }

    /** Oracle: tries every vector of copy counts over the positive-weight items. */
    static int oracle(int[] weight, int[] value, int i, int left) {
        if (i == weight.length) return 0;
        if (weight[i] == 0) return oracle(weight, value, i + 1, left);
        int best = 0;
        for (int copies = 0; copies * weight[i] <= left; copies++) {
            best = Math.max(best, copies * value[i] + oracle(weight, value, i + 1, left - copies * weight[i]));
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (packOrUnbounded(new int[] {0, 5}, new int[] {0, 6}, 0) != 0) throw new AssertionError("ex1");
        if (packOrUnbounded(new int[] {0, 5}, new int[] {2, 6}, 7) != -1) throw new AssertionError("ex2");
        // An empty item list returns 0.
        if (packOrUnbounded(new int[] {}, new int[] {}, 9) != 0) throw new AssertionError("empty");
        // A zero-weight item with value 0 is ignored.
        if (packOrUnbounded(new int[] {0, 3}, new int[] {0, 4}, 7) != 8) throw new AssertionError("free zero");
        // Random inputs against the exhaustive oracle.
        Random rnd = new Random(2705);
        for (int t = 0; t < 2000; t++) {
            int k = rnd.nextInt(4);
            int[] ww = new int[k];
            int[] vv = new int[k];
            boolean unbounded = false;
            for (int i = 0; i < k; i++) {
                ww[i] = rnd.nextInt(7);
                vv[i] = rnd.nextInt(12);
                if (ww[i] == 0 && vv[i] > 0) unbounded = true;
            }
            int cap = rnd.nextInt(25);
            int want = unbounded ? -1 : oracle(ww, vv, 0, cap);
            if (packOrUnbounded(ww, vv, cap) != want) throw new AssertionError("random " + t);
        }
    }

Perfect Squares

LeetCode 279

Problem Specification. A positive integer n is given. A perfect square is 1, 4, 9, 16 and so on. Return the smallest number of perfect squares, with repeats allowed, whose sum is exactly n.

Input Constraints. The limits are:

  • Value satisfies 1 <= n <= 10000.
  • Result is an int at least 1.
  • Terms may repeat, and every term is a perfect square.

Example 1. Input n = 12, output 3.

Example 2. Input n = 28, output 4.

Prerequisites. All three exercises above and the previous lesson.

What This Exercise Changes. The items are the squares up to n, every use costs 1, and the sum must be exact. The method minimizes the count and uses the marker n + 1 for unreachable entries.

Hint

Which numbers play the role of the item weights, and what does each use cost?

Algorithmic Solution (attempt the problem first)

Approach. Each perfect square up to n is an item whose weight is the square and whose use costs 1. The sum must be exactly n, and the goal is the fewest items, which is the coin change table with the squares as denominations. The entry dp[a] is the fewest squares that add up to a, with dp[0] = 0 and the marker n + 1 for amounts not yet reached. Every a from 1 to n is reachable, because 1 is a square.

The invariant is that dp[a] is exact for every amount the loop has passed. The loop over amounts runs upward, so a square may repeat. The inner loop tries each square s * s <= a as the last term.

Complexity.

  • Time is O(n * sqrt(n)), because each amount tries at most sqrt(n) squares.
  • Space is O(n) for the table.
import java.util.*;

public final class CapUknPerfectSquares {
    /**
     * Returns the fewest perfect squares that sum to n.
     * Time: O(n * sqrt(n)). Space: O(n).
     * Invariant: dp[a] is the fewest squares for a, for every amount the loop has passed.
     */
    static int fewestSquares(int n) {
        // The marker n + 1 is larger than any real count, because 1 is a square.
        int[] dp = new int[n + 1];
        Arrays.fill(dp, n + 1);
        // Zero squares add up to 0.
        dp[0] = 0;
        // Upward amounts let a square appear more than once.
        for (int a = 1; a <= n; a++) {
            // Each square that fits is a candidate for the last term.
            for (int s = 1; s * s <= a; s++) {
                // The candidate wins when the smaller amount plus one square is cheaper.
                if (dp[a - s * s] + 1 < dp[a]) dp[a] = dp[a - s * s] + 1;
            }
        }
        // Every amount is reachable, so no marker conversion is needed.
        return dp[n];
    }

    /** Oracle: breadth-first search by number of squares. */
    static int oracle(int n) {
        int[] dist = new int[n + 1];
        Arrays.fill(dist, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        dist[0] = 0;
        queue.add(0);
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int s = 1; cur + s * s <= n; s++) {
                if (dist[cur + s * s] == -1) {
                    dist[cur + s * s] = dist[cur] + 1;
                    queue.add(cur + s * s);
                }
            }
        }
        return dist[n];
    }

Problem

Choosing Files For A Small Backup Disk

A backup tool has a 6 MB disk and three files to copy. File A is 4 MB with importance 5. File B is 3 MB with importance 3. File C is 3 MB with importance 3. Each file exists once, so the tool can copy it at most once. Copying A leaves only 2 MB, which fits nothing else, so the importance total is 5. Copying B and C fills the disk and totals 6.

A developer reuses the repeatable-item table from the previous lesson for this job. The code is short and runs fast, but it reports a total of 8 for a single 3 MB file of importance 4 on a 6 MB disk. That answer pretends the file can be copied twice.

Formally, the input is arrays weight and value of equal length and a nonnegative integer capacity. Item i weighs weight[i] and is worth value[i]. A selection is a set of distinct indexes, so each item appears at most once. The task is to return the largest total value of a selection with total weight at most capacity. The method never changes the arrays.

This lesson asks how a table can count each item once.

Simple approach

Reusing The Repeatable-Item Table

The quick idea is to run the loop from the previous lesson unchanged. It processes the items one at a time and updates capacities from small to large.

static int reuseTable(int[] weight, int[] value, int capacity) {
    int[] dp = new int[capacity + 1];
    for (int i = 0; i < weight.length; i++) {
        for (int c = weight[i]; c <= capacity; c++) {
            dp[c] = Math.max(dp[c], dp[c - weight[i]] + value[i]);
        }
    }
    return dp[capacity];
}

The method runs in O(capacity * k) time for k items and uses O(capacity) memory. Its structure is the right one for a capacity table. The open question is whether the inner loop treats an item that it has already placed as available again.

Predict first: Run reuseTable with weights [3], values [4] and capacity 6. What does it return, and what is the true best total?

It returns 8. When the loop reaches capacity 6, it reads the entry for capacity 3, which already holds the item, and adds the item again. The true best total is 4, because the single item can be used once.

Bottleneck

The Table Remembers Values Not Items

An entry of the table stores a value, and it forgets which items produced that value. When the loop reads dp[c - weight[i]] after item i already updated that entry, it cannot tell that the stored value contains item i. The update then adds the same item twice.

A correct but slow method lists every subset of items and sums its weight. A set of k items has 2^k subsets, and summing one subset costs O(k), so the work is O(2^k * k). For k = 40 that is more than 10^13 operations.

The table needs a way to keep the reads for item i separate from the writes for item i. If the reads come only from the table that describes items before i, no entry can contain item i when it is read. There are k + 1 such tables of capacity + 1 entries each, so O(k * capacity) memory is enough, and each entry needs two reads. The next section builds that layout and then shrinks it to one array.

Key idea

Read From The Rows Before The Item

Process the items in input order and keep the answers for every capacity after each item. The answers after item i must be computed only from the answers before item i.

One Row For Each Item Prefix

An item prefix of length i is the first i items. Let dp[i][c] be the largest total value of a selection that uses only items from the prefix of length i and has weight at most c. Row 0 is all zeros, because the empty prefix allows only the empty selection. The final answer is dp[k][capacity].

Both Cases Read The Previous Row

Item i - 1 is the last item of the prefix of length i. A best selection either leaves it out or contains it once. If it leaves the item out, the value is dp[i - 1][c], which is the entry in the previous row at the same capacity. If it contains the item, the other items come from the prefix of length i - 1 with weight at most c - weight[i - 1], so the value is dp[i - 1][c - weight[i - 1]] + value[i - 1]. Both reads come from the previous row, so no entry can contain the item twice. The entry is the larger of the two cases.

One Array In Descending Order

Row i needs only row i - 1, so one array can hold the current row while it overwrites the previous one. The overwrite is safe only if an entry is still unchanged when a later entry reads it. The take case reads a capacity smaller than c. Visiting the capacities in descending order, from capacity down to weight[i], means every smaller capacity has not yet been rewritten when entry c reads it. That smaller entry therefore still holds the previous row. The invariant is that at the start of each step, entries at or below the current c describe the previous row and entries above it describe the new row.

State

The Array And The Downward Index

The method leaves its three inputs alone and keeps these working values.

  • dp is an int[] of length capacity + 1; during item i, entries at or below the current index hold the previous row.
  • i is the item that the outer loop processes.
  • c is the capacity that the inner loop rewrites, from capacity down to weight[i].
  • skip is dp[c] before the rewrite, which is the previous-row value at capacity c.
  • take is dp[c - weight[i]] + value[i], which reads the previous row at the smaller capacity.

Entries below weight[i] are not touched, because item i does not fit there. The index c - weight[i] is never negative inside the loop, since c starts no lower than weight[i].

Walkthrough

Two Runs Over A Small Disk

Each File Counted Once

The first run uses the three files from the opening, with weights 4, 3 and 3, values 5, 3 and 3, and capacity 6. Each cell is a capacity from 0 to 6. The pointer c marks the entry that the loop rewrites, moving downward inside each item. The variable item names the file in progress, skip and take are the two candidates, and dp is the entry after the rewrite.

File A rewrites capacities 6, 5 and 4 with the value 5. File B starts at capacity 6 and reads capacity 3, which is still 0, so the take value is 3 and the skip value 5 wins. File C then reads capacity 3, which now holds 3 from file B, so taking gives 6 at capacity 6. The two 3 MB files fill the disk once each.

What The Upward Loop Does Instead

The second run applies the upward loop of the naive section to one file with weight 3 and value 4 and capacity 6. The correct answer is 4. At capacity 3 the take value is 4. At capacity 6 the loop reads capacity 3, which was rewritten a moment earlier and already holds the file, so the take value is 8. The trace shows the entry reaching 8, and that value counts the same file twice. The descending order of the correct loop reads capacity 3 before rewriting it, so it returns 4.

Code

The Compressed Array Loop

The method returns the best total value. It processes one item at a time and rewrites the array from the largest capacity down.

static int oneUsePack(int[] weight, int[] value, int capacity) {
    int[] dp = new int[capacity + 1];
    for (int i = 0; i < weight.length; i++) {
        for (int c = capacity; c >= weight[i]; c--) {
            int take = dp[c - weight[i]] + value[i];
            if (take > dp[c]) dp[c] = take;
        }
    }
    return dp[capacity];
}

Only the direction of the inner loop differs from the repeatable version. The cost is O(capacity * k) time and O(capacity) memory for k items. An item heavier than capacity never enters the inner loop, because c >= weight[i] fails at once. The first exercise below builds the two-dimensional table from the insight.

When to use it

Recognizing Items That Can Be Chosen Once

Reading The Cue

Use this method when each item is either chosen or left out, the total weight has a limit, and the goal is a total value or a yes-or-no question about reachable totals. Words such as "each element at most once" and "a subset of the items" point here. The table indexes capacity, and every entry for an item depends on entries that describe the items before it.

Checking The Invariant

The invariant says that entries at or below the current index still hold the previous row, so a take never reads the item that it is adding. Try a single item with weight at most half the capacity, because it exposes a loop that runs upward. Test an item exactly as heavy as the capacity, which must be taken once. Test an item heavier than the capacity, which must change nothing.

Avoiding The False Friend

The first false friend is the upward loop, which passes any test where no item fits twice. The second is the ratio greedy, which fails on the disk example. The third is a two-array version that forgets to copy the finished row before the next item starts, which silently drops the earlier items.

One-Use Items

Problem Specification. Each item in arrays weight and value can be chosen at most once. Fill a table with one row per item prefix and one column per capacity. Return the largest total value of a selection with total weight at most capacity.

Prerequisites. The item-prefix table and the previous-row reads from this lesson.

What This Exercise Changes. Both cases read row i - 1, and the method writes row i into a separate array row. The row index replaces the loop direction as the guard against reuse.

Hint

For prefix i and capacity c, which two entries of the previous row give the skip case and the take case?

Algorithmic Solution (attempt the problem first)

Approach. The table has one row for each item prefix. Entry dp[i][c] is the largest total value of a selection that uses only the first i items and weighs at most c. Row 0 is all zeros for the empty selection. For row i, the skip case copies dp[i - 1][c]. The take case applies only when weight[i - 1] <= c, and it adds value[i - 1] to dp[i - 1][c - weight[i - 1]].

Both cases read row i - 1 and write row i, so an entry never contains the item that it is adding. The invariant is that every row is final before the next row starts. The answer is the last row at capacity.

Complexity.

  • Time is O(k * capacity), because each of the k rows fills capacity + 1 entries with two reads.
  • Space is O(k * capacity) for the table, and both input arrays stay unchanged.
import java.util.*;

public final class CapZokOneUseItems {
    /**
     * Returns the largest value of a one-use selection within capacity, using a full table.
     * Time: O(k * capacity). Space: O(k * capacity).
     * Invariant: row i is final before row i + 1 starts, and each row reads only the row before it.
     */
    static int tableBest(int[] weight, int[] value, int capacity) {
        int k = weight.length;
        // Row 0 is all zeros, because the empty prefix allows only the empty selection.
        int[][] dp = new int[k + 1][capacity + 1];
        // One row per item prefix costs k rows.
        for (int i = 1; i <= k; i++) {
            for (int c = 0; c <= capacity; c++) {
                // Skip case: the item stays out, so the previous row decides.
                dp[i][c] = dp[i - 1][c];
                // Take case: the item fits, so the rest comes from the previous row at the smaller capacity.
                if (weight[i - 1] <= c) {
                    dp[i][c] = Math.max(dp[i][c], dp[i - 1][c - weight[i - 1]] + value[i - 1]);
                }
            }
        }
        // The last row at the full capacity covers every selection.
        return dp[k][capacity];
    }

    /** Oracle: tests every subset of the items. */
    static int oracle(int[] weight, int[] value, int capacity) {
        int n = weight.length;
        int best = 0;
        for (int mask = 0; mask < (1 << n); mask++) {
            int w = 0, v = 0;
            for (int i = 0; i < n; i++) {
                if ((mask >> i & 1) == 1) {
                    w += weight[i];
                    v += value[i];
                }
            }
            if (w <= capacity) best = Math.max(best, v);
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (tableBest(new int[] {1, 3, 4, 5}, new int[] {1, 4, 5, 7}, 7) != 9) throw new AssertionError("ex1");
        if (tableBest(new int[] {6, 7}, new int[] {3, 4}, 5) != 0) throw new AssertionError("ex2");
        // An empty item list and capacity 0 both return 0.
        if (tableBest(new int[] {}, new int[] {}, 9) != 0) throw new AssertionError("empty");
        if (tableBest(new int[] {2}, new int[] {5}, 0) != 0) throw new AssertionError("zero capacity");
        // A single item is used once, not twice.
        if (tableBest(new int[] {3}, new int[] {4}, 6) != 4) throw new AssertionError("single");
        // Both arrays stay unchanged.
        int[] w = {1, 3};
        int[] v = {2, 5};
        tableBest(w, v, 4);
        if (!Arrays.equals(w, new int[] {1, 3}) || !Arrays.equals(v, new int[] {2, 5})) throw new AssertionError("mutated");
        // Random inputs against the subset oracle.
        Random rnd = new Random(2706);
        for (int t = 0; t < 2000; t++) {
            int k = rnd.nextInt(9);
            int[] ww = new int[k];
            int[] vv = new int[k];
            for (int i = 0; i < k; i++) {
                ww[i] = 1 + rnd.nextInt(8);
                vv[i] = rnd.nextInt(15);
            }
            int cap = rnd.nextInt(30);
            if (tableBest(ww, vv, cap) != oracle(ww, vv, cap)) throw new AssertionError("random " + t);
        }
    }

Algorithmic Solution (attempt the problem first)

Approach. One array dp of length capacity + 1 holds the current row as it overwrites the previous row. For item i, the loop visits capacities from capacity down to weight[i]. import java.util.*;

public final class CapZokDescendingCompression {
    /**
     * Returns the best one-use value for every capacity from 0 to capacity.
     * Time: O(k * capacity). Space: O(capacity).
     * Invariant: entries at or below the current index hold the previous row.
     */
    static int[] bestRow(int[] weight, int[] value, int capacity) {
        // Every entry starts at 0 for the empty selection.
        int[] dp = new int[capacity + 1];
        for (int i = 0; i < weight.length; i++) {
            // Descending order keeps the smaller capacities unchanged until they are read.
            for (int c = capacity; c >= weight[i]; c--) {
                // The take value reads the previous row at the smaller capacity.
                int take = dp[c - weight[i]] + value[i];
                // The skip value is the entry before the rewrite.
                if (take > dp[c]) dp[c] = take;
            }
        }
        // The whole array is the final row.
        return dp;
    }

    /** Oracle: a full table with a separate row for each item prefix. */
    static int[] fullTable(int[] weight, int[] value, int capacity) {
        int k = weight.length;
        int[][] dp = new int[k + 1][capacity + 1];
        for (int i = 1; i <= k; i++) {
            for (int c = 0; c <= capacity; c++) {
                dp[i][c] = dp[i - 1][c];
                if (weight[i - 1] <= c) dp[i][c] = Math.max(dp[i][c], dp[i - 1][c - weight[i - 1]] + value[i - 1]);
            }
        }
        return dp[k];
    }

        if (bestRow(new int[] {2}, new int[] {5}, 0).length != 1) throw new AssertionError("length");

        int[] w = {2, 3};
        int[] v = {3, 4};
        bestRow(w, v, 9);
        if (!Arrays.equals(w, new int[] {2, 3}) || !Arrays.equals(v, new int[] {3, 4})) throw new AssertionError("mutated");

            int cap = rnd.nextInt(30);

Ascending-Loop Counterexample

Author exercise

Problem Specification. Items come as arrays weight and value, each usable once. Compute the correct one-use table, and also the table that an upward capacity loop would produce. Return the smallest capacity c in 0..capacity where the two tables differ, or -1 if they agree everywhere.

Input Constraints. The limits are:

  • Length satisfies 0 <= weight.length <= 12, and both arrays have equal length.
  • Weight satisfies 1 <= weight[i] <= 50.
  • Value satisfies 0 <= value[i] <= 1000, and an item with value 0 never causes a difference.
  • Capacity satisfies 0 <= capacity <= 200.
  • Mutation is not allowed, because both arrays stay unchanged.

Example 1. Input weight = [3], value = [4], capacity = 6, output 6.

Example 2. Input weight = [4], value = [5], capacity = 7, output -1.

Prerequisites. The two exercises above and the previous lesson.

What This Exercise Changes. The method runs both loop directions on separate arrays and compares them entry by entry. The first capacity with a different entry is the answer.

Hint

A repeated item first appears at a capacity of at least twice its weight. Which capacities need to be compared at all?

Algorithmic Solution (attempt the problem first)

Approach. The method builds two arrays with the same recurrence and different loop directions. The descending array is the correct one-use table. The ascending array lets entry c read dp[c - weight[i]] after item i has already rewritten it, so it can count item i several times. The method compares the arrays from capacity 0 upward and returns the first index where they differ, or -1 if they never differ.

A difference needs a repeated item, and the second copy of item i fits only when c >= 2 * weight[i]. So no index below the smallest such bound can differ, and an item with value 0 never raises an entry. The invariant for the descending array is the usual one: entries at or below the current index hold the previous row.

Complexity.

  • Time is O(k * capacity) for the two tables and O(capacity) for the comparison.
  • Space is O(capacity) for the two arrays, and both input arrays stay unchanged.
import java.util.*;

public final class CapZokAscendingCounterexample {
    /**
     * Returns the smallest capacity where the upward loop disagrees with the one-use table, or -1.
     * Time: O(k * capacity). Space: O(capacity).
     * Invariant: the descending array holds the correct one-use answers.
     */
    static int firstDifference(int[] weight, int[] value, int capacity) {
        int[] right = new int[capacity + 1];
        int[] wrong = new int[capacity + 1];
        for (int i = 0; i < weight.length; i++) {
            // The correct loop runs downward so that every read sees the previous row.
            for (int c = capacity; c >= weight[i]; c--) right[c] = Math.max(right[c], right[c - weight[i]] + value[i]);
            // The upward loop reads entries that the same item already rewrote.
            for (int c = weight[i]; c <= capacity; c++) wrong[c] = Math.max(wrong[c], wrong[c - weight[i]] + value[i]);
        }
        // The first mismatch from capacity 0 upward is the answer.
        for (int c = 0; c <= capacity; c++) if (right[c] != wrong[c]) return c;
        return -1;
    }

    /** Oracle: subset enumeration for the correct table, repeat enumeration for the upward table. */
    static int oracleDifference(int[] weight, int[] value, int capacity) {
        int n = weight.length;
        for (int c = 0; c <= capacity; c++) {
            int right = 0;
            for (int mask = 0; mask < (1 << n); mask++) {
                int w = 0, v = 0;
                for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) { w += weight[i]; v += value[i]; }
                if (w <= c) right = Math.max(right, v);
            }
            // The upward loop equals the best value when each item may repeat only if it was processed in order.
            int wrong = upwardOracle(weight, value, 0, c);
            if (right != wrong) return c;
        }
        return -1;
    }

    /** Value of the upward loop: each item repeats freely in item order, which is the repeatable table. */
    static int upwardOracle(int[] weight, int[] value, int i, int left) {
        if (i == weight.length) return 0;
        int best = 0;
        for (int copies = 0; copies * weight[i] <= left; copies++) {
            best = Math.max(best, copies * value[i] + upwardOracle(weight, value, i + 1, left - copies * weight[i]));
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (firstDifference(new int[] {3}, new int[] {4}, 6) != 6) throw new AssertionError("ex1");
        if (firstDifference(new int[] {4}, new int[] {5}, 7) != -1) throw new AssertionError("ex2");
        // An item with value 0 never causes a difference, and an empty list agrees everywhere.
        if (firstDifference(new int[] {2}, new int[] {0}, 50) != -1) throw new AssertionError("zero value");
        if (firstDifference(new int[] {}, new int[] {}, 9) != -1) throw new AssertionError("empty");
        // Both input arrays stay unchanged.
        int[] w = {2, 5};
        int[] v = {3, 1};
        firstDifference(w, v, 9);
        if (!Arrays.equals(w, new int[] {2, 5}) || !Arrays.equals(v, new int[] {3, 1})) throw new AssertionError("mutated");
        // Random inputs against the enumeration oracle.
        Random rnd = new Random(2708);
        for (int t = 0; t < 1500; t++) {
            int k = rnd.nextInt(5);
            int[] ww = new int[k];
            int[] vv = new int[k];
            for (int i = 0; i < k; i++) {
                ww[i] = 1 + rnd.nextInt(6);
                vv[i] = rnd.nextInt(10);
            }
            int cap = rnd.nextInt(20);
            if (firstDifference(ww, vv, cap) != oracleDifference(ww, vv, cap)) throw new AssertionError("random " + t);
        }
    }

Partition Equal Subset Sum

Problem Specification. An array nums of positive integers is given. Decide whether the elements can be split into two groups with equal sums, where each element belongs to exactly one group. Return true if such a split exists and false otherwise.

Input Constraints. The limits are:

  • Length satisfies 1 <= nums.length <= 200.
  • Value satisfies 1 <= nums[i] <= 100.
  • Result is a boolean.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input nums = [3,3,6,2,4], output true.

Example 2. Input nums = [2,2,3,5], output false.

Prerequisites. All three exercises above.

What This Exercise Changes. The items are the elements, each weighs its own value, and the question asks whether the sum total / 2 is reachable exactly. The table holds booleans in place of best values.

Hint

If the two groups have equal sums, what must one group sum to, and which sums can a one-use loop reach?

Algorithmic Solution (attempt the problem first)

Approach. If the two groups have equal sums, each sums to half of the total, so the total must be even. The question becomes whether some subset of nums sums to total / 2, and then the rest sums to the same value. Each element weighs its own value and is used at most once, so the table is the one-use table with booleans: reach[s] is true when some subset of the elements processed so far sums to exactly s.

For each element x, the loop visits sums from half down to x and sets reach[s] when reach[s - x] is true. The descending order keeps reach[s - x] at the previous row, so no element is counted twice. The invariant is that reach[s] describes subsets of the processed elements. The answer is reach[half].

Complexity.

  • Time is O(n * total), because each element updates up to total / 2 entries.
  • Space is O(total) for the boolean array, and the input array stays unchanged.
import java.util.*;

public final class CapZokEqualPartition {
    /**
     * Returns whether nums splits into two groups with equal sums.
     * Time: O(n * total). Space: O(total).
     * Invariant: reach[s] is true when a subset of the processed elements sums to s.
     */
    static boolean canSplit(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        // An odd total cannot be halved into integers.
        if (total % 2 != 0) return false;
        int half = total / 2;
        boolean[] reach = new boolean[half + 1];
        // The empty subset sums to 0.
        reach[0] = true;
        for (int x : nums) {
            // Descending sums keep reach[s - x] at the previous row.
            for (int s = half; s >= x; s--) {
                // A sum becomes reachable when the sum x below it was reachable before this element.
                if (reach[s - x]) reach[s] = true;
            }
        }
        // One group sums to half exactly when half is reachable.
        return reach[half];
    }

    /** Oracle: tests every subset. */
    static boolean oracle(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            if (sum * 2 == total) return true;
        }
        return false;
    }

        if (!canSplit(new int[] {3, 3, 6, 2, 4})) throw new AssertionError("ex1");

Problem

Splitting Files Across Two Servers

A deployment script copies five data files of 3, 3, 2, 2 and 2 GB to two servers. Both servers must receive the same number of gigabytes, or a later merge step refuses to start. The script walks the files in order and sends each one to the server with the smaller load. The loads grow as 3 and 0, then 3 and 3, then 5 and 3, then 5 and 5, and the last file makes them 7 and 5. The merge fails, yet a correct split exists. Sending 3 and 3 to one server and 2, 2 and 2 to the other gives 6 and 6.

Formally, the input is an array nums of positive integers. A split assigns every index to one of two groups. The task is to decide whether a split exists in which both groups have the same sum. The method never changes the array.

This lesson asks how to answer that question without testing every assignment of files.

Simple approach

Sending Each File To The Lighter Server

The quick idea keeps two running loads. Each file goes to the server whose load is currently smaller, and the method reports success when the two loads end equal.

static boolean lighterFirst(int[] nums) {
    long a = 0;
    long b = 0;
    for (int x : nums) {
        if (a <= b) a += x;
        else b += x;
    }
    return a == b;
}

A single scan of the array gives O(n) time and O(1) memory. It balances many inputs correctly, and it never reads a file twice. The open question is whether a balanced split exists whenever this rule fails to find one.

Predict first: Run lighterFirst on the file sizes [3, 3, 2, 2, 2]. What does it return, and does an equal split exist?

It returns false, because the final loads are 7 and 5. An equal split exists: 3 and 3 form one group with sum 6, and 2, 2 and 2 form the other group with sum 6. The rule fixes each file's server before it sees the files that come later.

Bottleneck

Early Choices Block Later Matches

The running-load rule commits to a server for each file in turn. Whether a file belongs in the first group depends on the files after it, which the rule has not examined. Choosing by input order, by size or by a random shuffle fails on some input.

A correct but slow method tests every assignment. Each of n files has two possible groups, so there are 2^n assignments, and summing one assignment costs O(n). The work is O(2^n * n), and for n = 50 that exceeds 10^16 operations.

Many assignments end with the same sum for the first group, and only that sum matters for the rest of the decision. Two different sets of files with the same total leave identical choices for the remaining files. The number of distinct sums that can matter is at most total / 2 + 1. A table that records which sums are possible does O(1) work per element and sum, which is O(n * total) time. The next section defines that table.

Key idea

Track Which Sums Are Possible

An equal split asks for one group with a known sum. Once that sum is known, the task becomes a question about subsets, and a table can answer it.

Equal Groups Need Half The Total

If both groups have the same sum, each equals total / 2, where total is the sum of all elements. An odd total has no integer half, so the answer is false at once. This quick check uses parity, which means whether a number is even or odd. For an even total, call total / 2 the target. A split exists exactly when some subset of the elements sums to the target, because the elements outside that subset then sum to the target as well.

A Reachable Sum Stands For Many Subsets

A reachable sum s is a value for which some subset of the processed elements adds up to s. Let reach[s] be true for those values. Different subsets often give the same s, and the rest of the decision depends only on s, not on which subset produced it. So one boolean replaces all subsets with that sum. Before any element, only reach[0] is true, because the empty subset sums to 0.

Descending Updates Use Each Element Once

Adding an element x makes the sum s reachable when s - x was reachable before x was added. The update reach[s] = reach[s] or reach[s - x] must read the state from before x. The loop therefore visits sums from the target down to x, the same descending order as the one-use knapsack. The invariant is that after each element, reach[s] is true exactly for sums of subsets of the processed elements. The answer is reach[target].

State

The Sum Flags And The Target

The method leaves nums unchanged. It keeps these working values.

  • total is a long that holds the sum of all elements, so a large input cannot overflow.
  • target is total / 2, and it exists only when total is even.
  • reach is a boolean[] of length target + 1; entry s says whether a subset sums to s.
  • x is the element that the outer loop adds.
  • s is the sum that the inner loop updates, from target down to x.

Only sums up to the target matter, because a subset above the target cannot be completed to an equal split. The array has target + 1 entries, so its memory grows with the target and not with the number of elements.

Flags Up To A Limit

The first method returns the flag array for every sum up to a limit. The second uses it to answer the equal-split question.

static boolean[] reachableSums(int[] nums, int limit) {
    boolean[] reach = new boolean[limit + 1];
    reach[0] = true;
    for (int x : nums) {
        for (int s = limit; s >= x; s--) {
            if (reach[s - x]) reach[s] = true;
        }
    }
    return reach;
}

static boolean equalSplit(int[] nums) {
    long total = 0;
    for (int x : nums) total += x;
    if (total % 2 != 0) return false;
    int target = (int) (total / 2);
    return reachableSums(nums, target)[target];
}

The array costs O(target) memory and the loops cost O(n * target) time. The cast to int is safe only when the target fits in an int, and an input with a very large target needs a different method. Elements larger than the limit never enter the inner loop.

When to use it

Recognizing Questions About Subset Sums

Reading The Cue

Use this method when the input splits into groups with a required sum, or when the question asks which totals a subset can produce. Phrases such as "two groups with equal sum", "difference as small as possible" and "can some of the numbers add up to" point here. The table indexes the sum, and a boolean per sum is enough when the question asks only whether a sum can occur.

Checking The Invariant

The invariant says that after each element, reach[s] is true exactly for the sums of subsets of the processed elements. Test an odd total, which must stop before any table is built. Test an element equal to the target, which makes the answer true after one step. Test an element larger than the target, which must leave the table alone.

Avoiding The False Friend

The balancing rule of the naive section is one false friend. Another is sorting the elements and alternating groups, which fails on [3, 3, 2, 2, 2] as well. A third is a table that is large enough for the total and not the target, which wastes half the memory, and a fourth is an int total that overflows for big elements and produces a negative target.

Hint

Which array length lets the table hold every possible subset sum, and which direction keeps each element from counting twice?

Algorithmic Solution (attempt the problem first)

Approach. The table has one boolean for every sum from 0 to the total of all elements, and only reach[0] starts true for the empty subset. Each element x sets reach[s] for every sum s whose predecessor s - x was reachable before x was added. The loop visits sums from the total down to x, so the predecessor still describes the earlier elements and no element is counted twice.

At every step, reach[s] is true exactly for sums of subsets of the processed elements. The count of distinct subset sums is the number of true entries in the final table, and the empty array gives 1.

Complexity.

  • Time is O(n * total), because each element updates up to total entries.

import java.util.*;

public final class CapPartReachableSums {
    /**
     * Returns the number of distinct subset sums, including the empty sum 0.
     * Time: O(n * total). Space: O(total).
     * Invariant: reach[s] is true exactly for sums of subsets of the processed elements.
     */
    static int countSums(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        boolean[] reach = new boolean[total + 1];
        // The empty subset sums to 0.
        reach[0] = true;
        for (int x : nums) {
            // Descending sums keep reach[s - x] at the state before x.
            for (int s = total; s >= x; s--) {
                if (reach[s - x]) reach[s] = true;
            }
        }
        // Count the sums that some subset reaches.
        int count = 0;
        for (boolean flag : reach) if (flag) count++;
        return count;
    }

    /** Oracle: collects the sum of every subset in a set. */
    static int oracle(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            seen.add(sum);
        }
        return seen.size();
    }

        // The two examples of the exercise.
        if (countSums(new int[] {1, 2, 2}) != 6) throw new AssertionError("ex1");
        if (countSums(new int[] {5, 5}) != 3) throw new AssertionError("ex2");

        if (countSums(new int[] {}) != 1) throw new AssertionError("empty");

Smallest Equal Group

Problem Specification. The array nums holds positive integers. A split puts every index into one of two groups, and it is equal when both groups have the same sum. Return the smallest possible number of elements in a group that belongs to an equal split, or -1 if no equal split exists.

Hint

What can the table store for each sum in place of a boolean, so that a smaller group size replaces a larger one?

Algorithmic Solution (attempt the problem first)

Approach. An odd total has no equal split, so the method returns -1 at once. For an even total, each group of an equal split sums to the target total / 2, so the smallest group has the fewest elements among subsets that sum to the target. The table fewest[s] holds the fewest elements of a subset that sums to s, with the marker n + 1 for sums that no subset reaches and fewest[0] = 0.

Each element x triggers one pass over the sums from the target down to x, and the pass keeps the smaller of fewest[s] and fewest[s - x] + 1. The descending order makes fewest[s - x] describe the elements before x. The invariant is that fewest[s] is exact for the processed elements. The answer is fewest[target] or -1 when it holds the marker.

Complexity.

  • Time is O(n * target), because each element updates up to target entries.
  • Space is O(target) for the count array, and the input array stays unchanged.
import java.util.*;

public final class CapPartSmallestGroup {
    /**
     * Returns the fewest elements of a group in an equal split, or -1 when no equal split exists.
     * Time: O(n * target). Space: O(target).
     * Invariant: fewest[s] is the fewest elements of a subset of the processed elements that sums to s.
     */
    static int smallestGroup(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        // An odd total cannot be halved into integers.
        if (total % 2 != 0) return -1;
        int target = total / 2;
        int n = nums.length;
        // The marker n + 1 is larger than any real element count.
        int[] fewest = new int[target + 1];
        Arrays.fill(fewest, n + 1);
        // The empty subset has 0 elements and sums to 0.
        fewest[0] = 0;
        for (int x : nums) {
            // Descending sums keep fewest[s - x] at the state before x.
            for (int s = target; s >= x; s--) {
                // Adding x to the best subset for s - x gives a candidate with one more element.
                if (fewest[s - x] + 1 < fewest[s]) fewest[s] = fewest[s - x] + 1;
            }
        }
        // The marker means no subset reaches the target.
        return fewest[target] > n ? -1 : fewest[target];
    }

    /** Oracle: tests every subset and keeps the smallest one that sums to half. */
    static int oracle(int[] nums) {
        int total = 0;
        for (int x : nums) total += x;
        int best = -1;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            if (sum * 2 == total) {
                int size = Integer.bitCount(mask);
                if (best == -1 || size < best) best = size;
            }
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (smallestGroup(new int[] {4, 6, 5, 3, 2}) != 2) throw new AssertionError("ex1");
        if (smallestGroup(new int[] {3, 5, 9, 2}) != -1) throw new AssertionError("ex2");
        // One large element can form the smaller group alone.
        if (smallestGroup(new int[] {1, 1, 1, 1, 4}) != 1) throw new AssertionError("one big");
        // The input array stays unchanged.
        int[] nums = {4, 6, 5, 3, 2};
        int[] copy = nums.clone();
        smallestGroup(nums);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");
        // Random inputs against the subset oracle.
        Random rnd = new Random(2711);
        for (int t = 0; t < 3000; t++) {
            int[] a = new int[1 + rnd.nextInt(11)];
            for (int i = 0; i < a.length; i++) a[i] = 1 + rnd.nextInt(10);
            if (smallestGroup(a) != oracle(a)) throw new AssertionError("random " + t);
        }
    }

Odd Total And Large Target

Author exercise

Problem Specification. The inputs are positive integers nums and an integer cellBudget. The method may allocate at most cellBudget table entries. Return 0 if the total is odd. Otherwise return 3 if the target total / 2 needs more than cellBudget entries, which means target + 1 > cellBudget. Otherwise return 1 if an equal split exists and 2 if it does not.

Input Constraints. The limits are:

  • Length satisfies 1 <= nums.length <= 100.
  • Value satisfies 1 <= nums[i] <= 1000000000, so the total can exceed the int range.
  • Budget satisfies 1 <= cellBudget <= 1000000.
  • Order of checks is fixed: parity first, then the budget, then the table.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input nums = [1,2,4], cellBudget = 100, output 0.

Example 2. Input nums = [5,5,10], cellBudget = 5, output 3.

Prerequisites. The two exercises above.

What This Exercise Changes. The method returns a status code and skips the table when parity or the budget already decides. The total is a long, so the target and the budget comparison stay correct for large elements.

Hint

Which two quantities can be computed before the table exists, and what type must the total have so that the target stays correct for large elements?

Algorithmic Solution (attempt the problem first)

Approach. The method decides as much as it can before it allocates anything. It sums the elements into a long, because elements up to 10^9 can push the total past the int range. An odd total returns 0 immediately. For an even total, the target is total / 2, and the table would need target + 1 entries. If that number exceeds cellBudget, the method returns 3 without building the table.

Only then does the method allocate a boolean array of length target + 1, which is at most cellBudget and so fits in an int. It runs the descending subset-sum update and returns 1 when reach[target] is true and 2 otherwise. The flags keep their usual meaning, so each true entry names a sum that some subset of the processed elements reaches.

Complexity.

  • Time is O(n) for the checks and O(n * target) for the table, and the table runs only when the target fits the budget.
  • Space is O(min(target, cellBudget)) because the budget check precedes the allocation.
import java.util.*;

public final class CapPartOddAndLarge {
    /**
     * Returns 0 for an odd total, 3 when the table exceeds the budget, 1 for an equal split and 2 otherwise.
     * Time: O(n * target). Space: O(min(target, cellBudget)).
     * Invariant: reach[s] is true exactly for sums of subsets of the processed elements.
     */
    static int status(int[] nums, int cellBudget) {
        // A long total cannot overflow for 100 elements up to 10^9.
        long total = 0;
        for (int x : nums) total += x;
        // Parity decides first and costs no memory.
        if (total % 2 != 0) return 0;
        long target = total / 2;
        // The budget check comes before the allocation, so a huge target never allocates.
        if (target + 1 > cellBudget) return 3;
        boolean[] reach = new boolean[(int) target + 1];
        // The empty subset sums to 0.
        reach[0] = true;
        for (int x : nums) {
            // An element above the target cannot enter the loop.
            for (int s = (int) target; s >= x; s--) {
                if (reach[s - x]) reach[s] = true;
            }
        }
        // One group sums to the target exactly when the target is reachable.
        return reach[(int) target] ? 1 : 2;
    }

    /** Oracle: parity, budget, then subset enumeration. */
    static int oracle(int[] nums, int cellBudget) {
        long total = 0;
        for (int x : nums) total += x;
        if (total % 2 != 0) return 0;
        if (total / 2 + 1 > cellBudget) return 3;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            long sum = 0;
            for (int i = 0; i < nums.length; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            if (sum * 2 == total) return 1;
        }
        return 2;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (status(new int[] {1, 2, 4}, 100) != 0) throw new AssertionError("ex1");
        if (status(new int[] {5, 5, 10}, 5) != 3) throw new AssertionError("ex2");
        // Large elements: the long total is 3 * 10^9 and the budget check refuses the table.
        if (status(new int[] {1_000_000_000, 1_000_000_000, 1_000_000_000, 1_000_000_000}, 1_000_000) != 3) throw new AssertionError("large");
        // Java fact: the same sum in an int becomes negative, which would make the target negative.
        int wrapped = 1_000_000_000 + 1_000_000_000 + 1_000_000_000;
        if (wrapped >= 0) throw new AssertionError("int should overflow");
        // The input array stays unchanged.
        int[] nums = {3, 1, 4};
        int[] copy = nums.clone();
        status(nums, 50);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");
        // Random inputs against the oracle, with budgets that sometimes refuse the table.
        Random rnd = new Random(2712);
        for (int t = 0; t < 3000; t++) {
            int[] a = new int[1 + rnd.nextInt(10)];
            for (int i = 0; i < a.length; i++) a[i] = 1 + rnd.nextInt(10);
            int budget = 1 + rnd.nextInt(40);
            if (status(a, budget) != oracle(a, budget)) throw new AssertionError("random " + t);
        }
    }

Last Stone Weight II

Problem Specification. An array stones of positive integer weights is given. One move picks two stones with weights x <= y and smashes them. If x == y both are removed. Otherwise the stone y is replaced by a stone of weight y - x. Moves continue until at most one stone remains. Return the smallest possible weight of the remaining stone, or 0 if none remains.

  • Length satisfies 1 <= stones.length <= 30.
  • Weight satisfies 1 <= stones[i] <= 100.
  • Result is an int from 0 to the largest stone weight.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input stones = [10,4,3,1], output 2.

Example 2. Input stones = [6,11,4,9], output 0.

What This Exercise Changes. The method does not ask for an exact half. It finds the largest reachable sum that is at most total / 2, and it returns total minus twice that sum.

Hint

Each stone ends up with a plus sign or a minus sign in the final value. How does that relate to two groups, and what makes the difference between their sums small?

Algorithmic Solution (attempt the problem first)

Approach. Every sequence of smashes leaves one stone whose weight is a signed sum of the original weights, with a plus sign or a minus sign on each stone. The stones with plus signs form one group and the stones with minus signs form the other, so the final weight is the absolute difference of two group sums. Any split into two groups can also be reached by some order of smashes, so the answer is the smallest possible difference of two group sums.

If one group sums to s, the other sums to total - s, and the difference is total - 2s for s <= total / 2. The smallest difference comes from the largest reachable s that is at most total / 2. The method builds the one-use reachable-sum table up to total / 2, finds the largest true entry, and returns total - 2 * s. The flag table keeps the meaning from the earlier solutions in this lesson.

Complexity.

  • Time is O(n * total), because each stone updates up to total / 2 entries and the search scans the table once.
  • Space is O(total) for the boolean array, and the input array stays unchanged.
import java.util.*;

public final class CapPartLastStone {
    /**
     * Returns the smallest possible weight of the remaining stone, or 0 when none remains.
     * Time: O(n * total). Space: O(total).
     * Invariant: reach[s] is true exactly for sums of subsets of the processed stones.
     */
    static int lastStone(int[] stones) {
        int total = 0;
        for (int x : stones) total += x;
        int half = total / 2;
        boolean[] reach = new boolean[half + 1];
        // The empty subset sums to 0.
        reach[0] = true;
        for (int x : stones) {
            // Descending sums use each stone once.
            for (int s = half; s >= x; s--) {
                if (reach[s - x]) reach[s] = true;
            }
        }
        // The largest reachable sum at most half gives the smallest difference.
        int best = 0;
        for (int s = half; s >= 0; s--) {
            if (reach[s]) {
                best = s;
                break;
            }
        }
        return total - 2 * best;
    }

    /** Oracle: simulates the smashing game over every pair of stones. */
    static int oracle(List<Integer> stones) {
        if (stones.size() <= 1) return stones.isEmpty() ? 0 : stones.get(0);
        int best = Integer.MAX_VALUE;
        for (int i = 0; i < stones.size(); i++) {
            for (int j = i + 1; j < stones.size(); j++) {
                List<Integer> rest = new ArrayList<>();

            }
        }
        return best;

Problem

Marking Adjustments As Credits Or Debits

A reconciliation tool receives five ledger adjustments of 1 unit each. A reviewer must mark every adjustment as a credit or a debit, and the net change must equal 3 units. A credit counts +1 and a debit counts -1. Four credits and one debit give 4 - 1 = 3. The reviewer wants to know how many different markings reach the net change 3. The tool must also answer for lists of 20 adjustments with larger amounts, and the first version is too slow for them.

Formally, the input is an array nums of nonnegative integers and an integer target. A sign assignment puts a plus sign or a minus sign in front of every element, and its value is the signed sum. Two assignments differ when they differ at some index, even if the elements at those indexes are equal. The task is to count the assignments whose value equals target. The method never changes the array.

This lesson asks how to count sign assignments without listing all 2^n of them.

Simple approach

Tracking Every Signed Running Sum

The quick idea tracks the running sum directly. A map from running sum to the number of ways to reach it starts with sum 0 and one way. Each element replaces the map by a new one in which every sum moves up by the element and down by the element.

static long countBySignedSums(int[] nums, int target) {
    Map<Integer, Long> ways = new HashMap<>();
    ways.put(0, 1L);
    for (int x : nums) {
        Map<Integer, Long> next = new HashMap<>();
        for (Map.Entry<Integer, Long> e : ways.entrySet()) {
            next.merge(e.getKey() + x, e.getValue(), Long::sum);
            next.merge(e.getKey() - x, e.getValue(), Long::sum);
        }
        ways = next;
    }
    return ways.getOrDefault(target, 0L);
}

This method is correct. It merges the two moves of equal sums, so it does not enumerate assignments one by one. The open question is how large the map grows and what it spends on sums that can never reach the target.

Predict first: Run countBySignedSums on [1, 1, 1, 1, 1] with target 3. What does it return, and how many distinct sums does the map hold after the last element?

It returns 5, because four plus signs and one minus sign can be arranged in five places. The map holds 6 sums: -5, -3, -1, 1, 3 and 5. The map spans every value between minus the total and plus the total.

Bottleneck

The State Range Is Twice As Wide

The map must cover every signed sum from minus the total to plus the total. With total T, that is up to 2T + 1 keys, and each key is a boxed Integer with a boxed Long count. Every element rebuilds the whole map, so the work is O(n * T) hash operations and O(T) memory for boxed objects.

Most of that range is wasted. A target above T or below -T has no assignment, yet the method still builds the whole map before it answers 0. The method also hides a simpler structure. A sign assignment splits the elements into two groups by sign, and the values of the two groups are tied together by the total and the target.

A method that uses this tie needs only one number per sum between 0 and a derived goal. That is half the range or less, and it needs no boxed keys, only an array of counts. The time is O(n * goal), and the next section derives the goal.

Key idea

Turn Signs Into A Subset Question

A sign assignment sorts the elements into two groups. A small piece of algebra shows that the target fixes the sum of each group.

Two Groups From One Assignment

The plus group is the set of indexes that receive a plus sign, and the minus group is the set that receives a minus sign. Let P be the sum of the plus group and N the sum of the minus group. The value of the assignment is P - N, and the total of all elements is P + N. If the value equals target, then P - N = target and P + N = total. Adding the two equations gives 2P = total + target, so P = (total + target) / 2.

The Derived Goal Must Be Valid

The goal P must be a whole number, so total + target must be even. The goal must also lie between 0 and total, because P is a sum of nonnegative elements that are part of the total. That condition is the same as |target| <= total. When either condition fails, no assignment reaches the target, and the answer is 0 without any table.

Count Subsets With Sum P

An assignment is determined by its plus group, and every subset of indexes can be a plus group. So the number of assignments with value target equals the subset count for sum P, which is the number of subsets of indexes whose elements add up to P. Let ways[s] be the number of subsets of the processed elements with sum s. Only ways[0] is 1 at the start, for the empty subset. For each element x, the update ways[s] += ways[s - x] runs in descending order of s, so each element joins a subset at most once. The invariant is that after each element, ways[s] counts the subsets of the processed elements that sum to s. The answer is ways[P].

State

Counts For Sums Up To The Goal

The method leaves nums unchanged. It keeps these working values.

  • total is a long that holds the sum of all elements.
  • goal is (total + target) / 2, the sum that the plus group must reach.
  • ways is a long[] of length goal + 1; entry s counts the subsets of the processed elements that sum to s.
  • x is the element added in the current outer iteration.
  • s is the sum that the inner loop updates, from goal down to x.

The counts are long values because the number of assignments can be 2^n. The goal is computed only after the validity checks, so the array length is never negative or larger than the total plus 1.

Walkthrough

Counting Subsets That Reach The Goal

The first run uses nums = [1, 2, 3, 4] and target = 2. The total is 10 and the goal is 6. Each cell is a sum from 0 to 6, and the pointer s marks the entry that changes. The variable x is the element being added, add is the amount added to the entry, and ways is the entry after the update. The trace lists only the updates that change an entry, and the first step shows the starting state.

After the elements 1 and 2, sums 1, 2 and 3 are each reached once. The element 3 then adds to sums 6, 5, 4 and 3, so ways[6] is 1 and ways[3] becomes 2. The element 4 adds one more way to sums 6, 5 and 4. The final entry ways[6] is 2, from the subsets {2, 4} and {1, 2, 3}.

Zero Values Double The Count

The second run uses nums = [0, 0, 1] and target = 1. The total is 1 and the goal is 1. A zero joins any subset without changing its sum, so each zero doubles every entry. The first zero changes ways[0] from 1 to 2, and the second changes it to 4. The element 1 then adds ways[0] to ways[1], which gives 4. The four assignments are the four ways to sign the two zeros, with the plus sign on the 1.

Code

Check The Goal Then Count Subsets

The method returns the number of sign assignments. It rejects impossible targets first and then counts subsets in descending order.

static long countSigns(int[] nums, int target) {
    long total = 0;
    for (int x : nums) total += x;
    if (Math.abs((long) target) > total || (total + target) % 2 != 0) return 0;
    int goal = (int) ((total + target) / 2);
    long[] ways = new long[goal + 1];
    ways[0] = 1;
    for (int x : nums) {
        for (int s = goal; s >= x; s--) ways[s] += ways[s - x];
    }
    return ways[goal];
}

The range test runs first, so total + target is nonnegative when the parity test reads it, and % 2 cannot be negative. The method runs in O(n * goal) time and uses O(goal) memory. A zero element enters the inner loop for every s and doubles each entry.

When to use it

Recognizing Signed Sums With A Target

Reading The Cue

Use this method when every element must receive one of two opposite roles, such as plus or minus, and the question asks how many assignments reach a target value or whether any does. Words such as "add or subtract each number" and "number of expressions" point here. The two roles define two groups, and the target fixes the sum of one group.

Checking The Invariant

The invariant ties each entry to a count: ways[s] equals the number of subsets of the elements seen so far with sum s. Test a target larger than the total, which must return 0 before any allocation. Test a target whose parity differs from the total, which must also return 0. Test zeros, whose count doubles the answer, and test a negative target, which is symmetric to the positive one.

Avoiding The False Friend

The map over signed sums is correct and heavy, so it works as a cross-check and not as the recommended method. A loop that runs upward lets an element join a subset repeatedly and counts a different question. Checking parity with (total + target) % 2 == 1 accepts a wrong odd case when the sum is negative. An int count overflows when many zeros or equal elements make the answer large.

Algorithmic Solution (attempt the problem first)

Approach. Let P be the sum of the elements with a plus sign and N the sum of those with a minus sign. A target is reached when P - N = target, and the total satisfies P + N = total. import java.util.*;

public final class CapTgtDeriveEquation {
    /**
     * Returns the required plus-group sum, or -1 when no assignment can reach target.
     * Time: O(n). Space: O(1).
     * Invariant: P + N = total and P - N = target, so P = (total + target) / 2.
     */
    static long plusGroupSum(int[] nums, int target) {
        long total = 0;
        for (int x : nums) total += x;
        // Range test first: it also makes total + target nonnegative for the parity test.
        if (Math.abs((long) target) > total) return -1;
        // An odd total + target has no whole-number half.
        if ((total + target) % 2 != 0) return -1;
        return (total + target) / 2;
    }

    /** Oracle: tries every sign assignment and reports the plus-group sum of the first match. */
    static long oracle(int[] nums, int target) {
        int n = nums.length;
        for (int mask = 0; mask < (1 << n); mask++) {
            int signed = 0, plus = 0;
            for (int i = 0; i < n; i++) {
                if ((mask >> i & 1) == 1) { signed += nums[i]; plus += nums[i]; }
                else signed -= nums[i];
            }
            if (signed == target) return plus;
        }
        return -1;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (plusGroupSum(new int[] {1, 2, 3, 4}, 2) != 6) throw new AssertionError("ex1");
        if (plusGroupSum(new int[] {2, 3}, 2) != -1) throw new AssertionError("ex2");
        // A target beyond the total is rejected by the range test, in both signs.
        if (plusGroupSum(new int[] {1, 2}, 4) != -1 || plusGroupSum(new int[] {1, 2}, -4) != -1) throw new AssertionError("range");
        // The empty array has total 0, so only target 0 passes and its plus group is 0.
        if (plusGroupSum(new int[] {}, 0) != 0 || plusGroupSum(new int[] {}, 2) != -1) throw new AssertionError("empty");
        // Java fact: % keeps the sign of the left side, so a negative odd number gives -1.
        if ((-3) % 2 != -1) throw new AssertionError("negative remainder");
        // Random inputs: a valid derived sum exists exactly when some assignment reaches the target.
        Random rnd = new Random(2714);
        for (int t = 0; t < 3000; t++) {
            int[] a = new int[rnd.nextInt(9)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(8);
            int target = rnd.nextInt(41) - 20;
            boolean reachable = oracle(a, target) != -1;
            long got = plusGroupSum(a, target);
            // The derived sum is necessary, and when an assignment exists its plus group has that sum.
            if (reachable && got != oracle(a, target)) throw new AssertionError("sum " + t);
            if (!reachable && got != -1) {
                // A valid derived sum without an assignment is allowed: the derivation is necessary, not sufficient.
                if (got < 0) throw new AssertionError("negative " + t);
            }
        }
    }

import java.util.*;

public final class CapTgtCountSubsets {
    /**
     * Returns how many index subsets of nums sum to exactly goal.
     * Time: O(n * goal). Space: O(goal).
     * Invariant: ways[s] counts subsets of the processed elements that sum to s.
     */
    static long countSubsets(int[] nums, int goal) {
        long[] ways = new long[goal + 1];
        // The empty subset is one subset with sum 0.
        ways[0] = 1;
        for (int x : nums) {
            // Descending sums keep ways[s - x] at the state before x.
            for (int s = goal; s >= x; s--) {
                ways[s] += ways[s - x];
            }
        }
        return ways[goal];
    }

    /** Oracle: tests every subset. */
    static long oracle(int[] nums, int goal) {
        long count = 0;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            if (sum == goal) count++;
        }
        return count;
    }

        }

Hint

What does a zero do to the number of assignments, and can the zeros be set aside before the table is built?

Algorithmic Solution (attempt the problem first)

Approach. A zero can take either sign without changing the signed sum, so every zero doubles the number of assignments. The method counts the zeros, sets them aside, and solves the problem for the positive elements. It then multiplies the result by 2 for each zero, using 1L << zeros. For the positive elements, the method sums them into total and rejects the target if |target| > total or if total + target is odd. import java.util.*;

public final class CapTgtZerosAndParity {
    /**
     * Returns the number of sign assignments with signed sum target, with zeros allowed.
     * Time: O(n * goal). Space: O(goal).
     * Invariant: ways[s] counts subsets of the processed positive elements that sum to s.
     */
    static long countWithZeros(int[] nums, int target) {
        long total = 0;
        int zeros = 0;
        for (int x : nums) {
            total += x;
            if (x == 0) zeros++;
        }
        // Range test first, then parity, so the parity test never sees a negative number.
        if (Math.abs((long) target) > total || (total + target) % 2 != 0) return 0;
        int goal = (int) ((total + target) / 2);
        long[] ways = new long[goal + 1];
        ways[0] = 1;
        for (int x : nums) {
            // Zeros are set aside and counted by the multiplier below.
            if (x == 0) continue;
            for (int s = goal; s >= x; s--) ways[s] += ways[s - x];
        }
        // Each zero can take either sign, so the count doubles per zero.
        return ways[goal] * (1L << zeros);
    }

    /** Oracle: tries every sign assignment. */
    static long oracle(int[] nums, int target) {
        long count = 0;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) sum += (mask >> i & 1) == 1 ? nums[i] : -nums[i];
            if (sum == target) count++;
        }
        return count;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (countWithZeros(new int[] {0, 0, 1}, 1) != 4) throw new AssertionError("ex1");
        if (countWithZeros(new int[] {1, 2}, 0) != 0) throw new AssertionError("ex2");
        // An empty array with target 0 has one assignment, and the same array with target 1 has none.
        if (countWithZeros(new int[] {}, 0) != 1 || countWithZeros(new int[] {}, 1) != 0) throw new AssertionError("empty");
        // Sixty zeros give 2^60 assignments, which still fits in a long.
        int[] zeros = new int[60];
        if (countWithZeros(zeros, 0) != (1L << 60)) throw new AssertionError("sixty zeros");
        // The input array stays unchanged.
        int[] nums = {0, 3, 0, 1};
        int[] copy = nums.clone();
        countWithZeros(nums, 2);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");
        // Random inputs with many zeros against the assignment oracle.
        Random rnd = new Random(2716);
        for (int t = 0; t < 3000; t++) {
            int[] a = new int[rnd.nextInt(11)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(3) == 0 ? 0 : rnd.nextInt(8);
            int target = rnd.nextInt(31) - 15;
            if (countWithZeros(a, target) != oracle(a, target)) throw new AssertionError("random " + t);
        }
    }

Problem

Listing Change Breakdowns For A Cashier

A cashier app shows every distinct way to pay 5 units with coins of 1, 2 and 5. Cashiers read the list to pick a breakdown that matches the coins in the drawer. The correct list has four entries: 5, then 2 + 2 + 1, then 2 + 1 + 1 + 1, then five coins of 1. The app shows nine entries, because it lists 1 + 2 + 2, 2 + 1 + 2 and 2 + 2 + 1 as three different breakdowns. A cashier cannot tell which entries are duplicates.

The inputs are an array coins of distinct positive integers and a nonnegative integer amount. A combination is a choice of how many times each denomination is used, and the order of the coins does not matter. Two combinations are equal when every denomination is used the same number of times. The task is to count the combinations whose values add up to amount. A combination with no coins adds up to 0, so amount 0 has exactly one combination. The method never changes the array.

This lesson asks how to count each combination once without listing them.

Simple approach

Extending The Fewest-Coins Loop

The quick idea reuses the loop from the first lesson of this chapter. The outer loop walks the amounts upward, and the inner loop tries each denomination as the last coin. The table adds the counts instead of taking the minimum.

static long countByAmounts(int[] coins, int amount) {
    long[] ways = new long[amount + 1];
    ways[0] = 1;
    for (int a = 1; a <= amount; a++) {
        for (int coin : coins) {
            if (coin <= a) ways[a] += ways[a - coin];
        }
    }
    return ways[amount];
}

The method runs in O(amount * k) time for k denominations and uses O(amount) memory. The structure matches a correct table for the fewest coins. The open question is whether adding counts in this loop order counts each breakdown once.

Predict first: Run countByAmounts on the coins [1, 2, 5] with amount 5. What does it return, and how many distinct combinations exist?

It returns 9, and only 4 combinations exist. The method counts 1 + 2 + 2, 2 + 1 + 2 and 2 + 2 + 1 as three separate entries, because each order reaches amount 5 through a different last coin. A count that depends on the order of the coins is a count of sequences.

Bottleneck

The Last Coin Fixes The Order

The entry for amount a adds ways[a - coin] for every denomination. The breakdown with the coins 1, 2 and 2 can be laid down in three orders, and the table follows a separate path for each order, so it adds 3 to the count. The table does not remember which coins came before the last one, so it cannot merge those paths.

A correct but slow method lists the combinations by choosing a count for each denomination. With k denominations and amount A, the number of count vectors is about A^k divided by the product of the denominations, which is O(A^k) in the worst case. For the denominations 1 through 8 and amount 600, there are about 1.7 * 10^11 combinations, so listing them one by one is too slow.

The fix is to lay down the coins in a fixed order so that each combination has exactly one path through the table. If all uses of the first denomination come before all uses of the second, no reordering is possible. A table that processes one denomination at a time follows this rule and needs O(amount * k) time. The next section shows how.

Key idea

Count Coins In One Fixed Order

Every combination can be written down in many orders, and only one of them matters for counting. Choose a single writing order and count writings in that order only.

Write Each Combination In Canonical Order

Number the denominations by their position in the array. The canonical order of a combination lists all copies of denomination 0 first, then all copies of denomination 1, and so on. Every combination has exactly one canonical writing, and two different combinations have different writings. So the number of combinations equals the number of canonical writings, and a table that follows the canonical order counts each combination once.

Add One Coin At A Time

Let ways[a] be the number of combinations that add up to a using only the denominations processed so far. The method processes one coin at a time, in array order. When it adds denomination c, a combination for amount a either uses no copy of c, which the old ways[a] already counts, or uses at least one. Remove the last copy of c from the canonical writing. What remains is a combination for a - c that uses denominations up to and including c, so its count is ways[a - c] after c has already updated that smaller amount. So the update is ways[a] += ways[a - c], with a increasing from c to amount.

Seed The Table With The Empty Combination

The empty combination uses no coins and adds up to 0. It is the one combination for amount 0, so ways[0] is 1 before any denomination is processed. Every other combination grows from it by appending copies of a denomination. Without this seed, every entry stays 0. The invariant is that after denomination c finishes, ways[a] counts the combinations of a that use only the denominations processed so far. The answer is ways[amount].

State

Counts For Each Amount

The inputs coins and amount stay unchanged, and the method keeps four working values.

  • ways is a long[] of length amount + 1; entry a counts the combinations that add up to a.
  • coin is the denomination that the outer loop adds.
  • a is the amount that the inner loop updates, from coin up to amount.
  • ways[0] is the seed 1 for the empty combination.

The counts are long values, because the number of combinations grows quickly with the amount. For the denominations 1 through 8 and amount 600, the count passes the int range. The denominations must be distinct. A repeated value would act as two denominations and count its combinations twice.

Walkthrough

Two Runs With The Same Coins

Coins In The Outer Loop

The first run uses the coins 1, 2 and 5 and amount 5. Each cell is an amount from 0 to 5, and the pointer a marks the entry that changes. The variable coin is the denomination being added, add is the amount added to the entry, and ways is the entry after the update. The first step shows the seed.

The coin 1 gives every amount one combination. The coin 2 then raises the counts for amounts 2 to 5 to 2, 2, 3 and 3. The coin 5 adds one combination for amount 5, which makes the final count 4. The combinations are 5, 2 + 2 + 1, 2 + 1 + 1 + 1 and 1 + 1 + 1 + 1 + 1.

Amounts In The Outer Loop

The second run uses the same coins and the loop order of the naive section. For each amount it adds the entries one coin below, for every coin that fits. The entry for amount 3 becomes 3, because it adds the entries for amounts 2 and 1. The entry for amount 5 adds the entries for amounts 4, 3 and 0, which gives 5 + 3 + 1 = 9. That is the count of sequences, and it matches the nine entries in the cashier list.

Code

Coins Outside And Amounts Inside

The method returns the number of combinations. It processes one denomination per outer iteration and updates the table in increasing order of amount.

When to use it

Recognizing Counts That Ignore Order

Reading The Cue

Use this method when the question counts ways to reach an exact sum with reusable values and says that the order does not matter. Words such as "combinations", "number of ways to make change" and "distinct multisets" point here. The table indexes the sum, and the outer loop walks the values.

Checking The Invariant

The invariant says that after each denomination, every entry counts the combinations that use only the denominations seen so far. Test amount 0, which must return 1 even for an empty array. Test a positive amount with an empty array, which must return 0. Test a denomination above the amount, which must change nothing.

Avoiding The False Friend

The false friend is the fewest-coins loop with the order of the loops swapped, which counts sequences and returns 9 for the cashier example. A descending inner loop is another, and it counts selections that use each denomination at most once. Duplicate denominations in the array are a third, since they count the same combination twice. A final one is an int count, which overflows long before the amount gets large.

With one denomination, which single earlier entry feeds each entry, and what does the seed contribute?

Algorithmic Solution (attempt the problem first)

Approach. The table ways[a] counts the combinations that add up to a. The seed ways[0] = 1 stands for the empty combination. With one denomination, the loop runs a from coin to amount and adds ways[a - coin] to ways[a]. Each entry therefore copies the entry one coin below it, so the 1 from the seed travels along the multiples of the coin.

import java.util.*;

public final class CapCmbOneCoin {
    /**
     * Returns the number of combinations of one denomination that add up to amount.
     * Time: O(amount). Space: O(amount).
     * Invariant: ways[a] counts combinations of the coin that add up to a.

        long[] ways = new long[amount + 1];
        // The empty combination adds up to 0.
        ways[0] = 1;
        // Increasing amounts let the seed travel along the multiples of the coin.
        for (int a = coin; a <= amount; a++) ways[a] += ways[a - coin];
        return ways[amount];
    }

import java.util.*;

public final class CapCmbCoinChangeTwo {
    /**
     * Returns the number of combinations of the coins that add up to amount.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: after a coin is processed, ways[a] counts combinations that use only the coins seen so far.
     */
    static long change(int[] coins, int amount) {
        long[] ways = new long[amount + 1];
        // The empty combination adds up to 0.
        ways[0] = 1;
        // Coins outside: all copies of one coin come before the next coin in every combination.
        for (int coin : coins) {
            // Increasing amounts let the coin appear several times.
            for (int a = coin; a <= amount; a++) ways[a] += ways[a - coin];
        }
        return ways[amount];
    }

    /** The swapped loop order, kept to show that it counts sequences. */
    static long sequences(int[] coins, int amount) {
        long[] ways = new long[amount + 1];
        ways[0] = 1;
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) if (coin <= a) ways[a] += ways[a - coin];
        }
        return ways[amount];
    }

    /** Oracle: chooses a count for each denomination by recursion. */
    static long oracle(int[] coins, int i, int left) {
        if (i == coins.length) return left == 0 ? 1 : 0;
        long total = 0;
        for (int copies = 0; copies * coins[i] <= left; copies++) total += oracle(coins, i + 1, left - copies * coins[i]);
        return total;
    }

        // The two examples of the exercise.

Algorithmic Solution (attempt the problem first)

Approach. Both counts use the same update, ways[a] += ways[a - coin], and they differ only in which loop is outside. With the coins outside, every combination is built in one fixed order of denominations, so each combination has one path and the table counts combinations. With the amounts outside, the entry for a adds ways[a - coin] for every coin as the last coin, so a combination reached by several orders is added once per order, and the table counts sequences.

The method fills two arrays and returns the two final entries. The invariant for the first array is that after each coin, its entries count combinations over the coins seen so far. The invariant for the second array is that each entry a counts the sequences that add up to a, built from smaller entries that are already final. The test checks both against recursive counts.

import java.util.*;

public final class CapCmbExplainLoopOrder {
    /**
     * Returns {combinations, sequences} that add up to amount.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: the first array counts combinations over the coins seen so far; the second counts sequences.
     */
    static long[] bothCounts(int[] coins, int amount) {
        long[] combos = new long[amount + 1];
        long[] seqs = new long[amount + 1];
        // Both tables are seeded with the empty combination and the empty sequence.
        combos[0] = 1;
        seqs[0] = 1;
        // Coins outside: one fixed order of denominations per combination.
        for (int coin : coins) {
            for (int a = coin; a <= amount; a++) combos[a] += combos[a - coin];
        }
        // Amounts outside: every coin is tried as the last coin, so each order is a separate path.
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) if (coin <= a) seqs[a] += seqs[a - coin];
        }
        return new long[] {combos[amount], seqs[amount]};
    }

    /** Oracle: counts combinations by recursion over denominations. */
    static long comboOracle(int[] coins, int i, int left) {
        if (i == coins.length) return left == 0 ? 1 : 0;
        long total = 0;
        for (int copies = 0; copies * coins[i] <= left; copies++) total += comboOracle(coins, i + 1, left - copies * coins[i]);
        return total;
    }

    /** Oracle: counts sequences by recursion on the first coin. */
    static long seqOracle(int[] coins, int left) {
        if (left == 0) return 1;
        long total = 0;
        for (int coin : coins) if (coin <= left) total += seqOracle(coins, left - coin);
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(bothCounts(new int[] {1, 2}, 4), new long[] {3, 5})) throw new AssertionError("ex1");
        if (!Arrays.equals(bothCounts(new int[] {3, 4}, 7), new long[] {1, 2})) throw new AssertionError("ex2");
        // Amount 0 gives one combination and one empty sequence.
        if (!Arrays.equals(bothCounts(new int[] {2, 5}, 0), new long[] {1, 1})) throw new AssertionError("zero");
        // The two counts are equal when only one denomination exists.
        if (bothCounts(new int[] {3}, 9)[0] != bothCounts(new int[] {3}, 9)[1]) throw new AssertionError("single coin");
        // The input array stays unchanged.
        int[] coins = {2, 1};
        int[] copy = coins.clone();
        bothCounts(coins, 8);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs against the two recursive oracles.
        Random rnd = new Random(2720);
        for (int t = 0; t < 1500; t++) {
            int k = 1 + rnd.nextInt(4);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(7));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(16);
            long[] got = bothCounts(c, amount);
            if (got[0] != comboOracle(c, 0, amount) || got[1] != seqOracle(c, amount)) throw new AssertionError("random " + t);
        }
    }

The method runs in O(target * k) time for k values and uses O(target) memory. It is correct for the question that the previous lesson asked. The open question is whether it also answers a question where the order of the values counts.

Predict first: Run countByValues on nums [1, 2] with target 4. What does it return, and how many sequences add up to 4?

It returns 3, and 5 sequences add up to 4. The method writes every collection of values in one fixed order, with all the 1s before all the 2s. The sequences 1 + 2 + 1 and 2 + 1 + 1 never appear, so they are never counted.

Bottleneck

The Fixed Order Hides Reordered Sequences

The combination loop fixes the order in which values may appear. That rule is the reason it counts each multiset once, and it is also the reason it cannot see a reordering. The count of sequences needs the opposite rule: after any prefix, every value must be allowed to come next.

A correct but slow method builds sequences one value at a time and recurses on the remaining sum. With k values and a smallest value m, the recursion branches k ways at each level and has depth up to target / m, so it makes O(k^(target / m)) calls. For the values 1, 2 and 3 and target 40, that is far beyond 10^15.

Most of those calls repeat. After the prefixes 1 + 2 and 2 + 1, the remaining sum is the same, and the number of ways to finish depends only on that remaining sum. There are target + 1 possible remaining sums. A table with one entry per total does k reads per entry, which is O(target * k) time. The next section builds that table.

Key idea

Let Every Value Come Last

A sequence is a prefix followed by one final value. If the table knows how many sequences each smaller total has, the final value extends them.

One Entry For Each Total

Let ways[t] be the number of sequences whose values add up to t. The seed is ways[0] = 1, because the empty sequence adds up to 0. The answer is ways[target]. A total that no sequence reaches keeps the count 0.

The Last Element Splits Every Sequence

Take any nonempty sequence with sum t, and look at its last element, which is some value v from nums with v <= t. Removing it leaves a sequence with sum t - v. The reverse also works: appending v to any sequence with sum t - v gives a sequence with sum t whose last element is v. This pairing is one to one, so the sequences with last element v number exactly ways[t - v]. Different values for the last element give different sequences. So ways[t] is the sum of ways[t - v] over all values v with v <= t.

Totals Outside And Candidates Inside

Computing ways[t] needs the entries ways[t - v] to be final for every v. The loop therefore keeps the totals outside, in increasing order, and the candidates inside, where each value tries to be the last element. When the loop reaches t, all smaller totals are done. The invariant is that ways[s] is the exact number of sequences for every s the loop has passed. This is the loop that gave the wrong count in the previous lesson, and it answers the order-sensitive question here.

State

Counts For Each Total

The inputs nums and target stay unchanged, and the method keeps four working values.

  • ways is a long[] of length target + 1; entry t counts the sequences that add up to t.
  • t is the total that the outer loop computes, from 1 to target.
  • value is the candidate that the inner loop tries as the last element.
  • ways[0] is the seed 1 for the empty sequence.

The counts are long values, because sequences multiply quickly. For the values 1, 2 and 3 and target 40, the count is about 2.4 * 10^10, which exceeds the int range. Every value must be positive. A value of 0 or less would make t - value equal to t or larger, which reads an entry that is not final or lies outside the table.

Totals Outside And Values Inside

The method returns the number of sequences. It computes the totals in increasing order and tries every value as the last element.

static long countSequences(int[] nums, int target) {
    long[] ways = new long[target + 1];
    ways[0] = 1;
    for (int t = 1; t <= target; t++) {

The condition value <= t keeps the index t - value inside the table. The cost is O(target * k) time and O(target) memory. An empty nums array returns 1 for target 0 and 0 for every positive target.

When to use it

Recognizing Counts That Respect Order

Reading The Cue

Use this method when reusable values must add up to an exact total and the order of the values makes sequences different. Phrases such as "different sequences", "ordered ways" and "1 + 2 and 2 + 1 are different" point here. The table indexes the total, and every entry sums over the possible last elements.

Checking The Invariant

The invariant says that, for every total the loop has passed, the entry equals the number of sequences with that sum. Test target 0, which must return 1. Test a positive target with an empty array, which must return 0. Test a value larger than the target, which must contribute nothing. Test a long run of totals to see the counts outgrow an int.

Avoiding The False Friend

The false friend is the combination loop of the previous lesson, which returns 3 for the maintenance window. A second one is a table of int entries, which overflows silently. A third is a value of 0 or a negative value in the input, which breaks the order of evaluation because the entry would read itself or a later entry. A last one is a recursion without memoization, which repeats the same remaining total many times.

Hint

Which two earlier totals can precede the last element, and what does each last element contribute?

Algorithmic Solution (attempt the problem first)

Approach. The entry ways[t] counts the sequences of 1s and 2s that add up to t. The seed ways[0] = 1 is the empty sequence. Every nonempty sequence ends in a 1 or a 2. Removing a final 1 leaves a sequence for t - 1, and removing a final 2 leaves a sequence for t - 2. So ways[t] equals ways[t - 1] plus ways[t - 2], where the second term applies only for t >= 2.

The invariant is that every entry the loop has passed is exact. The totals run upward, so both earlier entries are final when t is computed. The values satisfy ways[t] = F(t + 1) for the Fibonacci numbers F(1) = F(2) = 1, and the test checks that fact for every total up to 60.

Complexity.

  • Time is O(total), because each total does at most two additions.
  • Space is O(total) for the table, and the input is a single integer.
import java.util.*;

public final class CapPrmOrderedSums {
    /**
     * Returns the number of ordered sequences of 1s and 2s that add up to total.
     * Time: O(total). Space: O(total).
     * Invariant: ways[s] is exact for every total s the loop has passed.
     */
    static long orderedSums(int total) {
        long[] ways = new long[total + 1];
        // The empty sequence adds up to 0.
        ways[0] = 1;
        // Increasing totals make both earlier entries final before they are read.
        for (int t = 1; t <= total; t++) {
            // A final 1 extends a sequence for t - 1.
            ways[t] += ways[t - 1];
            // A final 2 extends a sequence for t - 2, and it needs t >= 2.
            if (t >= 2) ways[t] += ways[t - 2];
        }
        return ways[total];
    }

    /** Oracle: recursion on the first element. */
    static long oracle(int left) {
        if (left == 0) return 1;
        long count = oracle(left - 1);
        if (left >= 2) count += oracle(left - 2);
        return count;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (orderedSums(4) != 5) throw new AssertionError("ex1");
        if (orderedSums(0) != 1) throw new AssertionError("ex2");
        // Total 1 has the single sequence 1.
        if (orderedSums(1) != 1) throw new AssertionError("one");
        // Every small total against the recursion, and every total up to 60 against the Fibonacci identity.
        for (int n = 0; n <= 20; n++) if (orderedSums(n) != oracle(n)) throw new AssertionError("n=" + n);
        long prev = 1, cur = 1;
        for (int n = 0; n <= 60; n++) {
            // prev and cur hold F(n + 1) and F(n + 2) at the start of each pass.
            if (orderedSums(n) != prev) throw new AssertionError("fib " + n);
            long next = prev + cur;
            prev = cur;
            cur = next;
        }
    }

import java.util.*;

public final class CapPrmCombinationSumFour {
    /**
     * Returns the number of ordered sequences of values from nums that add up to target.
     * Time: O(target * k). Space: O(target).
     * Invariant: ways[s] is the exact number of sequences with sum s for every total the loop has passed.
     */
    static long sequences(int[] nums, int target) {
        long[] ways = new long[target + 1];
        // The empty sequence adds up to 0.
        ways[0] = 1;
        // Totals outside: every smaller total is final when t is computed.
        for (int t = 1; t <= target; t++) {
            // Values inside: each value tries to be the last element.
            for (int value : nums) {
                // A value above t cannot be the last element.
                if (value <= t) ways[t] += ways[t - value];
            }
        }
        return ways[target];
    }

    /** The combination loop of the previous lesson, kept to show that it counts fewer. */
    static long combinations(int[] nums, int target) {
        long[] ways = new long[target + 1];
        ways[0] = 1;
        for (int value : nums) {
            for (int t = value; t <= target; t++) ways[t] += ways[t - value];
        }
        return ways[target];
    }

    /** Oracle: recursion on the first element. */
    static long oracle(int[] nums, int left) {
        if (left == 0) return 1;
        long count = 0;
        for (int value : nums) if (value <= left) count += oracle(nums, left - value);
        return count;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (sequences(new int[] {2, 3, 6}, 8) != 6) throw new AssertionError("ex1");
        if (sequences(new int[] {5}, 3) != 0) throw new AssertionError("ex2");

        if (sequences(new int[] {1, 2}, 4) != 5 || combinations(new int[] {1, 2}, 4) != 3) throw new AssertionError("window");

        if (sequences(new int[] {7}, 0) != 1) throw new AssertionError("zero");
        // The input array stays unchanged.
        int[] nums = {3, 1, 2};
        int[] copy = nums.clone();
        sequences(nums, 9);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");

            if (sequences(c, target) != oracle(c, target)) throw new AssertionError("random " + t);
        }

Algorithmic Solution (attempt the problem first)

Approach. A value of zero or less breaks the evaluation order. For a value v <= 0, the index t - v is at least t, so the update would read the entry being written or an entry that is not final, and for a negative v the index can also leave the table. The method therefore skips every value that is not positive. After that filter, every transition lowers the total by at least 1, and the totals-outside loop is valid.

The table type is long, because the number of sequences grows exponentially: the values 1, 2 and 3 with target 40 give about 2.4 * 10^10, which does not fit in an int. The test asserts that count. The seed ways[0] = 1 makes the empty sequence count for target 0, so an empty array still returns 1 there.

Complexity.

import java.util.*;

public final class CapPrmOverflowNonpositive {
    /**
     * Returns the number of ordered sequences of the positive values of nums that add up to target.
     * Time: O(target * k). Space: O(target).
     * Invariant: ways[s] is exact for every total the loop has passed, and every transition lowers the total.
     */
    static long sequences(int[] nums, int target) {
        long[] ways = new long[target + 1];
        // The empty sequence adds up to 0.
        ways[0] = 1;
        for (int t = 1; t <= target; t++) {
            for (int value : nums) {
                // A non-positive value would read an unfinished entry, and a large one does not fit.
                if (value <= 0 || value > t) continue;
                ways[t] += ways[t - value];
            }
        }
        return ways[target];
    }

    /** Oracle: recursion over the positive values only. */
    static long oracle(int[] nums, int left) {
        if (left == 0) return 1;
        long count = 0;
        for (int value : nums) if (value > 0 && value <= left) count += oracle(nums, left - value);
        return count;
    }

        // The two examples of the exercise.
        if (sequences(new int[] {0, -2, 3}, 6) != 1) throw new AssertionError("ex1");

Algorithmic Solution (attempt the problem first)

Approach. Both counts satisfy the same update, ways[a] += ways[a - coin], and they differ only in which loop owns the outside. With the coins outside, every combination is written in one fixed order of denominations, so the table counts combinations. With the amounts outside and the coins inside, every coin is tried as the last element, so the table counts sequences.

The method builds both tables up to amount and compares them entry by entry, counting the amounts a where the sequence count is strictly larger. A sequence count is never below the combination count, because every combination has at least one sequence. The invariant for each table is that every entry the loop has passed is exact for its question.

Complexity.

  • Time is O(amount * k) for each table and O(amount) for the comparison.
  • Space is O(amount) for the two tables, and the input array stays unchanged.
import java.util.*;

public final class CapPrmCompareCoinChange {
    /**
     * Returns how many amounts a in 0..amount have more sequences than combinations.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: combos[a] and seqs[a] are exact for every amount a the loops have passed.
     */
    static int differingAmounts(int[] coins, int amount) {
        long[] combos = new long[amount + 1];
        long[] seqs = new long[amount + 1];
        // Both tables start from the empty combination and the empty sequence.
        combos[0] = 1;
        seqs[0] = 1;
        // Coins outside: one fixed order of denominations per combination.
        for (int coin : coins) {
            for (int a = coin; a <= amount; a++) combos[a] += combos[a - coin];
        }
        // Amounts outside: every coin is tried as the last element.
        for (int a = 1; a <= amount; a++) {
            for (int coin : coins) if (coin <= a) seqs[a] += seqs[a - coin];
        }
        // Count the amounts where order creates extra sequences.
        int differing = 0;
        for (int a = 0; a <= amount; a++) if (seqs[a] > combos[a]) differing++;
        return differing;
    }

    /** Oracle: counts combinations and sequences by recursion for each amount. */
    static int oracle(int[] coins, int amount) {
        int differing = 0;
        for (int a = 0; a <= amount; a++) {
            if (seqOracle(coins, a) > comboOracle(coins, 0, a)) differing++;
        }
        return differing;
    }

    static long comboOracle(int[] coins, int i, int left) {
        if (i == coins.length) return left == 0 ? 1 : 0;
        long total = 0;
        for (int copies = 0; copies * coins[i] <= left; copies++) total += comboOracle(coins, i + 1, left - copies * coins[i]);
        return total;
    }

    static long seqOracle(int[] coins, int left) {
        if (left == 0) return 1;
        long total = 0;
        for (int coin : coins) if (coin <= left) total += seqOracle(coins, left - coin);
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (differingAmounts(new int[] {1, 2}, 4) != 2) throw new AssertionError("ex1");
        if (differingAmounts(new int[] {3}, 10) != 0) throw new AssertionError("ex2");
        // Amount 0 never differs, because both counts are 1.
        if (differingAmounts(new int[] {2, 5}, 0) != 0) throw new AssertionError("zero");
        // The input array stays unchanged.
        int[] coins = {2, 1};
        int[] copy = coins.clone();
        differingAmounts(coins, 12);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs against the recursive oracle.
        Random rnd = new Random(2723);
        for (int t = 0; t < 1000; t++) {
            int k = 1 + rnd.nextInt(4);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(7));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(14);
            if (differingAmounts(c, amount) != oracle(c, amount)) throw new AssertionError("random " + t);
        }
    }

        for (int total = pack; total <= target; total++) ways[total] += ways[total - pack];
    }
    return ways[target];
}

The routine runs in O(target * k) time for k pack sizes and uses O(target) memory. It gives the correct bundle count for repeatable packs. The open question is what it returns for the other two screens.

Bottleneck

Wrong Switches Give Plausible Numbers

The routine has the right cost for all three screens, since each valid structure runs in O(target * k). The defect is not speed. A wrong choice of loop direction or of loop owner keeps the code short and the output a plain integer, so nothing signals the mistake. A count of 4 for the voucher screen looks as believable as the correct 1.

Testing each variant against hand counts does not scale. The structure has two independent choices, and a third choice for the objective, so a team that copies code between screens can pair the wrong choices without noticing. Counting every pairing by exhaustive search is not an option for large targets, because the number of sequences grows exponentially.

A reliable method must tie the loop choices to the two questions in the problem statement. Asking whether an item can repeat fixes the inner direction, and asking whether order counts fixes the outer loop. The next section states that rule and the cases it excludes.

Key idea

Two Questions Fix The Loop Structure

Each question about the problem statement maps to one choice in the code. Ask them in order, and the structure follows.

Direction Decides Reuse

The loop direction is the order in which the inner loop visits totals. An upward loop reads ways[t - v] after the same item v has already updated it, so the item can appear again. A downward loop reads ways[t - v] before the item updates it, so the item contributes at most once. Reuse questions say "any number of times", and single-use questions say "each at most once".

Ownership Decides Order

The loop owner is the loop that stays on the outside. If the items own the outside, each combination is written once in the order of the item array, and the table counts combinations. If the totals own the outside, every item can be the last element of any prefix, and the table counts sequences. Order matters only when the statement says that different orders are different outcomes.

The Rule Decides The Question

The combine rule says how two entries merge: addition counts ways, taking the smaller value minimizes the item count, and a logical or tests reachability. The rule does not interact with the other two choices, so the same loop structure serves all three questions. The last row of the table below is excluded from this chapter. Sequences of single-use items need to know which items were used, which a table indexed by total cannot record, so this chapter excludes it.

State

Switches And One Count Table

The routine reads the item array and the target, and it changes neither. It keeps these values.

  • ways is a long[] of length target + 1; entry t counts the outcomes that add up to t.
  • reusable is a boolean that is true when an item may be used again.
  • ordered is a boolean that is true when different orders are different outcomes.
  • t is the total that a loop updates.
  • v is the item value that a loop adds or tries as the last element.

The routine rejects the pair ordered true and reusable false, because the table cannot count that case. The counts are long values. Every item value must be positive, since a value of 0 would read an entry that is not final.

Walkthrough

Two Runs On Three Pack Sizes

One Use Per Pack

The first run applies the downward loop to the packs 1, 2 and 3 with target 4. The cells are the totals 0 through 4, and the pointer t points at the entry that changes. The variable v is the pack being added, add is the amount it contributes, and ways is the entry after the contribution. The first step shows the seed.

Total 3 reads the entry for total 1, which holds only the pack 1, so the pack 2 is never counted twice. The pack 3 reaches total 4 from total 1 and total 3 from the seed. The final entry for total 4 is 1, from the packs 1 and 3.

The second run uses the same packs and target with the totals on the outside. Each total sums the entries one pack below it. Total 2 holds 2 and total 3 holds 4. Total 4 receives 4 from the last element 1, 2 from the last element 2, and 1 from the last element 3. The result is 7, which matches the purchase-order screen.

One Routine With Two Switches

static long countWays(int[] items, int target, boolean reusable, boolean ordered) {
    if (ordered && !reusable) throw new IllegalArgumentException("order with single use needs a set of used items");
    long[] ways = new long[target + 1];
    ways[0] = 1;
    if (ordered) {
        for (int t = 1; t <= target; t++)
            for (int v : items) if (v <= t) ways[t] += ways[t - v];
    } else if (reusable) {
        for (int v : items)
            for (int t = v; t <= target; t++) ways[t] += ways[t - v];
    } else {
        for (int v : items)
            for (int t = target; t >= v; t--) ways[t] += ways[t - v];
    }
    return ways[target];
}

All three branches cost O(target * k) time and O(target) memory. The first branch implements the totals-outside loop, the second the items-outside upward loop, and the third the items-outside downward loop. The packs 1, 2 and 3 with target 4 return 7, 4 and 1 in that order.

When to use it

Choosing The Loop Structure

Reading The Cue

Use this lesson when a statement mentions a limit or a sum, a pool of items, and a count or a best value. Read the statement for two phrases. "Any number of times" or "unlimited supply" sets the direction upward, and "each at most once" sets it downward. "Different orders are different" or "sequences" puts the totals outside, and "combinations" or "sets" puts the items outside.

Checking The Invariant

The invariant says that every entry is exact for the question defined by the two answers, once the outer step that finishes it is done. Test the same small input under all three structures and compare against the hand counts. Test target 0, which must return 1 in every structure. Test an item above the target, which must change nothing.

Avoiding The False Friend

The false friend is a copied loop that answers a neighboring question and returns a plausible number. A downward loop used for a reuse question undercounts, and an upward loop used for a single-use question overcounts. A totals-outside loop used for combinations overcounts, and an items-outside loop used for sequences undercounts. A fourth false friend is an int count, which overflows once sequences grow.

Problem Specification. An array coins of positive integers, a nonnegative integer amount and a boolean reusable are given. When reusable is true, each denomination may be used any number of times. Example 2. Input coins = [1,3,4], amount = 6, reusable = false, output -1.

What This Exercise Changes. The flag chooses the direction of the inner loop. The table, the marker and the minimum rule stay the same in both cases.

Hint

Which inner direction lets a coin be read after it has already updated a smaller amount, and which direction does not?

Algorithmic Solution (attempt the problem first)

Approach. The table dp[a] holds the fewest coins for amount a, with dp[0] = 0 and the marker amount + 1 for amounts not yet reached. Coins form the outer loop. For a reusable coin, the inner loop runs upward, so dp[a - coin] may already include the same coin. For a single-use coin, the inner loop runs downward, so dp[a - coin] still describes the earlier coins and each array position joins at most once.

The invariant is that after each coin, dp[a] is the fewest coins for a using the coins seen so far under the chosen reuse rule. Only the direction of the inner loop depends on the flag. The marker becomes -1 at the return.

Complexity.

  • Time is O(amount * k) for k coins, because each coin updates each amount at most once.
  • Space is O(amount) for the table, and the input array stays unchanged.
import java.util.*;

public final class CapDpcCoinChangeFlag {
    /**
     * Returns the fewest coins that add up to amount, with coins reusable or single-use, or -1.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: after each coin, dp[a] is the fewest coins for a using the coins seen so far.
     */
    static int fewest(int[] coins, int amount, boolean reusable) {
        int[] dp = new int[amount + 1];
        // The marker amount + 1 is larger than any real count.
        Arrays.fill(dp, amount + 1);
        dp[0] = 0;
        for (int coin : coins) {
            if (reusable) {
                // Upward amounts read dp[a - coin] after this coin updated it, so the coin repeats.
                for (int a = coin; a <= amount; a++) dp[a] = Math.min(dp[a], dp[a - coin] + 1);
            } else {
                // Downward amounts read dp[a - coin] before this coin updated it, so the coin joins once.
                for (int a = amount; a >= coin; a--) dp[a] = Math.min(dp[a], dp[a - coin] + 1);
            }
        }
        // The marker becomes -1 at the return.
        return dp[amount] > amount ? -1 : dp[amount];
    }

    /** Oracle: single-use by subset enumeration, reusable by breadth-first search. */
    static int oracle(int[] coins, int amount, boolean reusable) {
        if (!reusable) {
            int best = -1;
            for (int mask = 0; mask < (1 << coins.length); mask++) {
                int sum = 0;
                for (int i = 0; i < coins.length; i++) if ((mask >> i & 1) == 1) sum += coins[i];
                if (sum == amount) {
                    int size = Integer.bitCount(mask);
                    if (best == -1 || size < best) best = size;
                }
            }
            return best;
        }
        int[] dist = new int[amount + 1];
        Arrays.fill(dist, -1);
        Deque<Integer> queue = new ArrayDeque<>();
        dist[0] = 0;
        queue.add(0);
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            for (int coin : coins) {
                int next = cur + coin;
                if (next <= amount && dist[next] == -1) {
                    dist[next] = dist[cur] + 1;
                    queue.add(next);
                }
            }
        }
        return dist[amount];
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (fewest(new int[] {1, 3, 4}, 6, true) != 2) throw new AssertionError("ex1");
        if (fewest(new int[] {1, 3, 4}, 6, false) != -1) throw new AssertionError("ex2");
        // Amount 0 returns 0 in both modes, and equal values at two positions are two coins.
        if (fewest(new int[] {}, 0, false) != 0 || fewest(new int[] {5, 5}, 10, false) != 2) throw new AssertionError("edges");
        // The input array stays unchanged.
        int[] coins = {4, 1, 3};
        int[] copy = coins.clone();
        fewest(coins, 7, false);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs in both modes against the oracles.
        Random rnd = new Random(2724);
        for (int t = 0; t < 3000; t++) {
            int[] c = new int[rnd.nextInt(7)];
            for (int i = 0; i < c.length; i++) c[i] = 1 + rnd.nextInt(10);
            int amount = rnd.nextInt(40);
            boolean reusable = rnd.nextBoolean();
            if (reusable) {
                // The breadth-first oracle treats equal values as one denomination, which is the same for reuse.
                if (fewest(c, amount, true) != oracle(c, amount, true)) throw new AssertionError("reusable " + t);
            } else if (fewest(c, amount, false) != oracle(c, amount, false)) throw new AssertionError("single " + t);
        }
    }

Approach. Both answers share the seed ways[0] = 1 and the update that adds ways[t - v] to ways[t]. For combinations, the coins are the outer loop and the totals run upward, so each combination is written once in the order of the array. For sequences, the totals are the outer loop and every coin is tried as the last element, so each order is a separate path.

The flag selects the loop owner and nothing else. The invariant for the combination branch is that after each coin, ways[t] counts combinations over the coins seen so far. import java.util.*;

public final class CapDpcCoinChangeTwoOrdered {
    /**
     * Returns the number of combinations or, when ordered, the number of sequences that add up to amount.
     * Time: O(amount * k). Space: O(amount).
     * Invariant: every entry the loops have finished is exact for the chosen question.
     */
    static long ways(int[] coins, int amount, boolean ordered) {
        long[] ways = new long[amount + 1];
        // The empty combination and the empty sequence both add up to 0.
        ways[0] = 1;
        if (ordered) {
            // Totals outside: every coin may be the last element of a sequence.
            for (int t = 1; t <= amount; t++) {
                for (int coin : coins) if (coin <= t) ways[t] += ways[t - coin];
            }
        } else {
            // Coins outside: one fixed order of denominations per combination.
            for (int coin : coins) {
                for (int t = coin; t <= amount; t++) ways[t] += ways[t - coin];
            }
        }
        return ways[amount];
    }

    /** Oracle: combinations by choosing a count for each coin, sequences by recursion on the first coin. */
    static long oracle(int[] coins, int left, int i, boolean ordered) {
        if (ordered) {
            if (left == 0) return 1;
            long total = 0;
            for (int coin : coins) if (coin <= left) total += oracle(coins, left - coin, 0, true);
            return total;
        }
        if (i == coins.length) return left == 0 ? 1 : 0;
        long total = 0;
        for (int copies = 0; copies * coins[i] <= left; copies++) total += oracle(coins, left - copies * coins[i], i + 1, false);
        return total;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (ways(new int[] {2, 4, 5}, 9, false) != 2) throw new AssertionError("ex1");
        if (ways(new int[] {2, 4, 5}, 9, true) != 5) throw new AssertionError("ex2");
        // The billing example: 4 bundles and 7 purchase orders.
        if (ways(new int[] {1, 2, 3}, 4, false) != 4 || ways(new int[] {1, 2, 3}, 4, true) != 7) throw new AssertionError("billing");
        // Amount 0 has one outcome in both modes.
        if (ways(new int[] {3, 7}, 0, false) != 1 || ways(new int[] {3, 7}, 0, true) != 1) throw new AssertionError("zero");
        // The input array stays unchanged.
        int[] coins = {5, 2, 4};
        int[] copy = coins.clone();
        ways(coins, 30, true);
        if (!Arrays.equals(coins, copy)) throw new AssertionError("mutated");
        // Random inputs in both modes against the recursive oracle.
        Random rnd = new Random(2725);
        for (int t = 0; t < 2000; t++) {
            int k = 1 + rnd.nextInt(4);
            Set<Integer> chosen = new LinkedHashSet<>();
            while (chosen.size() < k) chosen.add(1 + rnd.nextInt(8));
            int[] c = chosen.stream().mapToInt(Integer::intValue).toArray();
            int amount = rnd.nextInt(16);
            boolean ordered = rnd.nextBoolean();
            if (ways(c, amount, ordered) != oracle(c, amount, 0, ordered)) throw new AssertionError("random " + t);
        }
    }

Partition Equal Subset Sum

LeetCode 416

Problem Specification. An array nums of nonnegative integers is given. Split the indexes into two groups so that both groups are nonempty and have the same sum. The answer is true when a legal split exists.

Input Constraints. The limits are:

  • Length satisfies 1 <= nums.length <= 40, and a single element cannot be split.
  • Value satisfies 0 <= nums[i] <= 100, and zeros may fill the array.
  • Groups must both be nonempty, and each index belongs to exactly one group.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input nums = [0,0], output true.

Example 2. Input nums = [0], output false.

Prerequisites. The two exercises above and the target-sum lesson.

What This Exercise Changes. The table counts subsets in place of testing reachability, with the descending loop. The method subtracts the empty subset and the full set when they reach half.

Hint

The empty subset and the full set may both sum to half. How can a count of subsets tell the legal splits from those two?

Algorithmic Solution (attempt the problem first)

Approach. A split needs a subset that sums to half of the total and leaves a nonempty complement. The method first checks that the total is even. It then counts subsets with sum half using the descending one-use table ways, where ways[0] = 1 for the empty subset. The count includes subsets that are empty or complete, which are not legal groups.

The empty subset sums to half only when half is 0, and the complete set sums to half only when the total is 0. So the method subtracts 1 for each of those two cases. A legal split exists exactly when the remaining count is positive. For an array of zeros, the count is 2^n, and the subtraction leaves 2^n - 2, which is positive only for n of at least 2. The counts are long values, which cover 2^40.

Complexity.

  • Time is O(n * half), because each element updates up to half entries.
  • Space is O(half) for the count array, and the input array stays unchanged.
import java.util.*;

public final class CapDpcPartitionNonempty {
    /**
     * Returns whether nums splits into two nonempty groups with equal sums.
     * Time: O(n * half). Space: O(half).
     * Invariant: after each element, ways[s] counts subsets of the processed elements with sum s.
     */
    static boolean canSplit(int[] nums) {
        long total = 0;
        for (int x : nums) total += x;
        // An odd total cannot be halved.
        if (total % 2 != 0) return false;
        int half = (int) (total / 2);
        long[] ways = new long[half + 1];
        // The empty subset is one subset with sum 0.
        ways[0] = 1;
        for (int x : nums) {
            // Descending sums keep ways[s - x] at the state before x, and x = 0 doubles every entry.
            for (int s = half; s >= x; s--) ways[s] += ways[s - x];
        }
        long legal = ways[half];
        // The empty subset reaches half only when half is 0.
        if (half == 0) legal--;
        // The complete set reaches half only when the total is 0.
        if (total == 0) legal--;
        return legal > 0;
    }

    /** Oracle: tests every proper nonempty subset. */
    static boolean oracle(int[] nums) {
        int n = nums.length;
        long total = 0;
        for (int x : nums) total += x;
        for (int mask = 1; mask < (1 << n) - 1; mask++) {
            long sum = 0;
            for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) sum += nums[i];
            if (sum * 2 == total) return true;
        }
        return false;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!canSplit(new int[] {0, 0})) throw new AssertionError("ex1");
        if (canSplit(new int[] {0})) throw new AssertionError("ex2");
        // A single positive element and an odd total cannot be split.
        if (canSplit(new int[] {6}) || canSplit(new int[] {1, 2, 4})) throw new AssertionError("no split");
        // A positive element beside a zero cannot be split, but two equal elements can.
        if (canSplit(new int[] {5, 0}) || !canSplit(new int[] {5, 5})) throw new AssertionError("pairs");
        // Forty zeros give 2^40 subsets, which a long holds exactly.
        if (!canSplit(new int[40])) throw new AssertionError("zeros");
        // The input array stays unchanged.
        int[] nums = {3, 0, 3};
        int[] copy = nums.clone();
        canSplit(nums);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");
        // Random inputs with many zeros against the subset oracle.
        Random rnd = new Random(2726);
        for (int t = 0; t < 4000; t++) {
            int[] a = new int[1 + rnd.nextInt(11)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(3) == 0 ? 0 : rnd.nextInt(9);
            if (canSplit(a) != oracle(a)) throw new AssertionError("random " + t + " " + Arrays.toString(a));
        }
    }

Target Sum

LeetCode 494

Problem Specification. An array nums of nonnegative integers and two integers lo and hi with lo <= hi are given. Every element receives a plus or a minus sign. Return the number of sign assignments whose signed sum s satisfies lo <= s <= hi.

Input Constraints. The limits are:

  • Length satisfies 1 <= nums.length <= 20.
  • Value satisfies 0 <= nums[i] <= 50, and the total is at most 1000.
  • Range satisfies -1000 <= lo <= hi <= 1000.
  • Result is a long.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input nums = [1,2,3], lo = 0, hi = 2, output 3.

Example 2. Input nums = [4,1,3,2], lo = -2, hi = 3, output 6.

Prerequisites. All three exercises above.

What This Exercise Changes. One table of subset counts answers the whole range. The method adds up the entries whose plus-group sum falls between the two bounds.

Hint

A signed sum of s means the plus group sums to (total + s) / 2. Which plus-group sums stay inside the range?

Algorithmic Solution (attempt the problem first)

Approach. For a sign assignment, let P be the sum of the plus group. The signed sum equals 2P - total, so the condition lo <= s <= hi is the same as (total + lo) / 2 <= P <= (total + hi) / 2. Because P is an integer, the lower bound rounds up and the upper bound rounds down. The method also clamps both bounds to the range 0 to total, since P is a sum of nonnegative elements within the total.

The method builds one table of subset counts with the descending loop, where ways[p] counts the subsets of the processed elements whose sum is p. It then adds the entries from the lower bound to the upper bound. An empty range gives 0. The floor division uses Math.floorDiv, so negative values round in the correct direction.

Complexity.

  • Time is O(n * total) for the table and O(total) for the range sum.
  • Space is O(total) for the count array, and the input array stays unchanged.
import java.util.*;

public final class CapDpcSignedRange {
    /**
     * Returns the number of sign assignments whose signed sum lies in [lo, hi].
     * Time: O(n * total). Space: O(total).
     * Invariant: after each element, ways[p] counts subsets of the processed elements with sum p.
     */
    static long countInRange(int[] nums, int lo, int hi) {
        int total = 0;
        for (int x : nums) total += x;
        long[] ways = new long[total + 1];
        // The empty subset is one subset with sum 0.
        ways[0] = 1;
        for (int x : nums) {
            // Descending sums keep ways[p - x] at the state before x.
            for (int p = total; p >= x; p--) ways[p] += ways[p - x];
        }
        // The signed sum is 2p - total, so p must lie between the rounded-up and rounded-down bounds.
        int low = Math.max(0, -Math.floorDiv(-(total + lo), 2));
        int high = Math.min(total, Math.floorDiv(total + hi, 2));
        long count = 0;
        // An empty range adds nothing.
        for (int p = low; p <= high; p++) count += ways[p];
        return count;
    }

    /** Oracle: tries every sign assignment. */
    static long oracle(int[] nums, int lo, int hi) {
        long count = 0;
        for (int mask = 0; mask < (1 << nums.length); mask++) {
            int sum = 0;
            for (int i = 0; i < nums.length; i++) sum += (mask >> i & 1) == 1 ? nums[i] : -nums[i];
            if (lo <= sum && sum <= hi) count++;
        }
        return count;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (countInRange(new int[] {1, 2, 3}, 0, 2) != 3) throw new AssertionError("ex1");
        if (countInRange(new int[] {4, 1, 3, 2}, -2, 3) != 6) throw new AssertionError("ex2");
        // A range that excludes every signed sum returns 0, and a point range equals the plain target count.
        if (countInRange(new int[] {1, 2}, 10, 20) != 0) throw new AssertionError("outside");
        if (countInRange(new int[] {1, 1, 1, 1, 1}, 3, 3) != 5) throw new AssertionError("point");
        // The input array stays unchanged.
        int[] nums = {2, 0, 5};
        int[] copy = nums.clone();
        countInRange(nums, -3, 3);
        if (!Arrays.equals(nums, copy)) throw new AssertionError("mutated");
        // Random inputs, including zeros and ranges beyond the total, against the assignment oracle.
        Random rnd = new Random(2727);
        for (int t = 0; t < 3000; t++) {
            int[] a = new int[1 + rnd.nextInt(10)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(9);
            int lo = rnd.nextInt(61) - 30;
            int hi = lo + rnd.nextInt(30);
            if (countInRange(a, lo, hi) != oracle(a, lo, hi)) throw new AssertionError("random " + t);
        }
    }
