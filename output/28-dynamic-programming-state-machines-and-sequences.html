Chapter 28

Dynamic Programming State Machines And Sequences

Orientation

A trading report sells a share on the day before it buys it. A diff tool lists three changes where one would turn "abc" into "bc". A spell checker rates a word as far from its correction because it counts only matching letters in the same positions. Each program leaves out one fact: what situation a table entry describes. This chapter labels every table entry with that situation, such as holding a share or having used one of two trades, and then fills tables over two strings or over the ends of one string.

Prerequisites

You should know the two previous dynamic programming chapters. They explained how to state in one sentence what a table entry means, how to seed the base entry, and how to read only entries that are already final. The code uses arrays of int and String, and it assumes import java.util.*; in samples.

The Six Lessons

Each lesson fixes one question about what an entry remembers.

  • Stock States keeps two values per day, the best cash while holding a share and the best cash while holding none. A mode is a named situation that limits the next move.
  • Transaction Variants adds a waiting day, a fee or a trade count to the mode, so the rule becomes part of the state.
  • Increasing Subsequences finds the longest strictly rising choice of elements, first with a quadratic table and then with a short array of smallest tails.
  • Common Subsequences compares two strings with a table indexed by two prefix lengths.
  • Edit Distance counts the fewest insertions, deletions and replacements that turn one string into another, using the same two-prefix table.
  • Palindromic Sequences moves to a table indexed by the two ends of one string and fills it by growing range length.

The Closing Lesson

  • DP State Machines joins the mode idea and the trade count into one table of labeled states and shows why one number per day loses the answer.

How To Work Through Each Lesson

A lesson opens with a small program that returns a wrong or slow answer on a realistic input. It shows a first version and asks you to predict its output. Later parts name the rule, list the variables, follow two traces, show the code and say when the rule stops fitting. Four exercises close each lesson, and they climb through Build, Vary, Boundary and Recognize. Read a hint only after a real attempt.

What You Can Do After This Chapter

You can list the legal moves of a problem and turn them into a table whose entries carry a label. You can choose between a prefix table, a range table and a tails array from the shape of the question. You can fill a two-index table in an order that finishes every needed entry first, and you can recover one optimal answer from it.

What Later Chapters Reuse

Chapter 29 reuses the range table from the last lesson and adds states such as ranges of positions, digits and bit masks. Every later table problem reuses the habit of writing the meaning of an entry before writing a loop.

Problem

A Profit Report That Sells Before Buying

The Wrong Subtraction

A reporting script receives the daily closing prices of one stock: 6, 9, 1, 3. The author reasons that the best profit is the largest price minus the smallest price. The script prints 9 - 1 = 8. No real trade earns 8, because the largest price (9) occurs on day 1 and the smallest price (1) occurs on day 2. A trade buys first and sells later, so buying at 6 and selling at 9 earns 3, and buying at 1 and selling at 3 earns 2. The correct answer for a single trade is 3.

The error comes from ignoring order. At the end of each day, the trader is in one of two situations: the trader owns a share or does not own one. What the trader may do next depends only on that situation and the next price.

The Exact Task

Formally, the input is an array prices, where prices[i] is the price on day i. A trade buys one share on a day and sells it on a later day, and the profit of a trade is the sell price minus the buy price. This lesson computes the best total profit while the trader owns at most one share at a time.

The lesson asks how to record the two situations so that every day updates them with a constant amount of work.

Simple approach

Trying Every Choice On Every Day

The direct idea is a recursion over the days. On each day, the trader rests, buys when no share is owned, or sells when a share is owned. The method explore(prices, day, owns) returns the best profit obtainable from day to the end of the array. The flag owns records whether the trader owns a share before that day. A share still owned after the last day never gets sold, so that ending is invalid and receives a very negative value.

static int explore(int[] prices, int day, boolean owns) {
    if (day == prices.length) return owns ? -1_000_000 : 0;
    int rest = explore(prices, day + 1, owns);
    if (owns) {
        return Math.max(rest, prices[day] + explore(prices, day + 1, false));
    }
    return Math.max(rest, -prices[day] + explore(prices, day + 1, true));
}

The call explore(prices, 0, false) returns the best profit for any number of trades. Every day offers two choices, so the recursion tree has one leaf for each combination of choices.

Predict first: How many calls does explore make for a prices array of length 3, counting the first call? Then estimate the number for length 30.

It makes 15 calls for length 3, because the tree has 1 + 2 + 4 + 8 calls on its four levels. For length 30 the tree has 2^31 - 1 calls, which is more than two billion. The method returns the right answer but takes exponential time.

Bottleneck

The Same Day Is Solved Many Times

The recursion has O(2^n) running time for n days, and n = 40 already needs about 2 * 10^12 calls. Most of that work repeats. Two different histories can reach day 5 with no share owned, for example after selling on day 2 or after never buying. The call explore(prices, 5, false) is identical in both histories and returns the same number.

A call depends on only two inputs: the day and the ownership flag. A prices array of length n has n + 1 values of day and 2 values of owns, so the recursion has at most 2n + 2 distinct calls. The exponential cost comes entirely from computing each distinct call again and again. A table with two entries per day removes the repetition, and a loop over the days fills it in O(n) time.

Key idea

Two Best Values Per Day

The profit before a day does not depend on the order of earlier trades, only on the ownership situation at the end of the day. So it is enough to remember the best profit for each situation.

Two Values For Two Situations

Let hold be the best profit over the processed days among all plans that end the last processed day while owning a share. The profit of such a plan already includes the price paid for that share, so hold is often negative. Let cash be the best profit among all plans that end the last processed day without owning a share. Before day 0, cash is 0, because doing nothing is a legal plan. The value of hold is impossible, because no share exists yet, so it starts at a very negative number.

Each Day Has Four Moves

On a new day with price p, exactly two moves reach each situation. Each move is a transition between the situation before the day and the situation after it.

Staying in cash means doing nothing, and the value is the old cash. Selling moves from hold to cash and earns the price, so the value is the old hold plus p. Staying in hold means doing nothing, and the value is the old hold. Buying moves from cash to hold and pays the price, so the value is the old cash minus p.

The new cash is the larger of the first two values, and the new hold is the larger of the last two. Both new values use only old values, so the day computes them from a snapshot of the previous day.

Why The Answer Is Cash

The best plan over all days must end without a share, since an owned share at the end earns nothing. The final cash therefore covers all plans, and the answer is the final cash. For a single allowed trade, the buy value changes to -p, because the one trade has no earlier profit to add to the price paid.

State

The Two Running Values

The method reads the array without changing it and keeps these values.

  • hold is the best profit so far among plans that own a share, started at Integer.MIN_VALUE / 2.
  • cash is the best profit so far among plans that own no share, started at 0.
  • p is the price of the current day.
  • nextHold is the new value of hold computed from the old hold and old cash.
  • nextCash is the new value of cash computed from the old hold and old cash.

The start value of hold is half of the smallest int. Adding a price of at most 10^4 to it cannot overflow, and the half value leaves a wide margin before the smallest int. The loop computes both next values before it overwrites either old value, so the second computation never reads an updated value.

Walkthrough

Two Runs Day By Day

Many Trades On Five Prices

The first run uses prices 3, 1, 4, 1, 5 with any number of trades. Each cell is a price, the pointer i marks the day, and the variables show hold and cash after that day. The impossible hold before the first day appears as -1073741824, which is half of the smallest int.

On day 0 the only useful move is a buy, so hold becomes -3. On day 1 a lower price improves hold to -1. Day 2 sells at 4, so cash becomes 3. Day 3 buys again with cash - 1, and hold becomes 2. Day 4 sells at 5 and cash becomes 7. Two trades each earn their own rise, 3 and 4.

One Trade On Six Prices

The second run uses prices 7, 1, 5, 3, 6, 4 and allows one trade. The buy move is -p, so hold always holds the negated lowest price seen so far. It reaches -1 on day 1 and stays there. The value of cash grows from 0 to 4 on day 2 and to 5 on day 4. Day 5 does not improve it, so the answer is 5, the profit of buying at 1 and selling at 6.

Code

Two Loops With Two Values

Both methods scan the array once and return cash. The first allows any number of trades. The second allows one trade, and only its buy line differs.

static int manyTrades(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;
    int cash = 0;
    for (int p : prices) {
        int nextHold = Math.max(hold, cash - p);
        int nextCash = Math.max(cash, hold + p);
        hold = nextHold;
        cash = nextCash;
    }
    return cash;
}

static int oneTrade(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;
    int cash = 0;
    for (int p : prices) {
        int nextHold = Math.max(hold, -p);
        int nextCash = Math.max(cash, hold + p);
        hold = nextHold;
        cash = nextCash;
    }
    return cash;
}

Each method runs in O(n) time and O(1) extra memory. An empty array returns 0, and a strictly falling array also returns 0, because cash never rises above its start value.

When to use it

Recognizing Daily Ownership Modes

Reading The Cue

Use this method when every step ends in one of a few named modes and the next step depends only on the current mode and the new input. Stock questions, on and off switches and borrow and return sequences all have this shape. Draw the modes as boxes and the legal moves as lines before writing any variable.

Checking The Invariant

The invariant says that after each day, hold and cash are the best profits over the processed prefix for their exact ownership situations. Check it on a one-day array, where cash must stay 0 and hold must equal the negated price. Check a strictly falling array, where cash must stay 0, and a flat array, where a trade earns nothing and cash also stays 0.

Avoiding The False Friend

The false friend is the largest price minus the smallest price from the opening, which ignores order. A second false friend is the sum of all positive day-to-day rises. That sum equals the many-trades answer. It has no ownership modes to extend, so it fails once a rule such as a waiting day after a sale or a fee appears.

Knowing When Two Values Are Not Enough

Do not use two scalars when a rule needs history beyond the current mode. A cooldown after a sale needs to know whether the last action was a sale. A limit on the number of trades needs a trade count. Each such fact adds a dimension to the state, and the next lesson adds them.

Best Time to Buy and Sell Stock

LeetCode 121

Problem Specification. Given an integer array prices, where prices[i] is the price on day i, a trader completes at most one trade. A trade buys on one day and sells on a strictly later day. Return an array best of the same length, where best[i] is the largest profit of at most one trade that is complete by the end of day i. A profit of 0 means no trade.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 1000, and empty input returns an empty array.
  • Price satisfies 0 <= prices[i] <= 10000.
  • Result is a new int[] of the same length as prices.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [7,1,5,3,6,4], output [0,0,4,4,5,5].

Example 2. Input prices = [5,4,3], output [0,0,0].

Prerequisites. The two best values hold and cash from this lesson.

What This Exercise Changes. The method records cash after every day, not only after the last day. The buy move is -p, because only one trade is allowed.

Hint

The value of cash after day i is exactly best[i]. Which line of the loop gives it, and when do you store it?

Algorithmic Solution (attempt the problem first)

Approach. The loop keeps hold, the best profit of plans that own a share, and cash, the best profit of plans that own none. For one trade, a buy always starts from profit 0, so the buy value on a day with price p is -p. The sell value is the old hold plus p. The loop computes both new values from the old pair before it stores either.

The invariant is that after day i, cash is the largest profit of at most one completed trade within days 0 to i. The method stores cash into best[i] at the end of each iteration. Because the start value of hold is half of the smallest int, adding a price to it cannot overflow.

Complexity.

  • Time is O(n), because each day does a constant number of comparisons.
  • Space is O(n) for the returned array, and the working values use O(1) extra memory.
import java.util.*;

public final class SsOneTradeStates {
    /**
     * Returns, for each day, the best profit of at most one completed trade so far.
     * Time: O(n). Space: O(n) for the result, O(1) for the working values.
     * Invariant: after day i, cash is the best profit of at most one trade within days 0..i.
     */
    static int[] bestByDay(int[] prices) {
        // The result has one entry per day.
        int[] best = new int[prices.length];
        // hold is impossible before any buy; half of MIN_VALUE leaves room for additions.
        int hold = Integer.MIN_VALUE / 2;
        // cash starts at 0 because doing nothing is a legal plan.
        int cash = 0;
        // One pass visits every day once, which costs O(n).
        for (int i = 0; i < prices.length; i++) {
            // Buying starts the only trade, so its value is the negated price.
            int nextHold = Math.max(hold, -prices[i]);
            // Selling adds today's price to the best owning plan.
            int nextCash = Math.max(cash, hold + prices[i]);
            // Both new values came from old values, so the order of these stores does not matter.
            hold = nextHold;
            cash = nextCash;
            // The day's cash is the answer for the prefix ending today.
            best[i] = cash;
        }
        // The caller receives a fresh array and the input stays unchanged.
        return best;
    }

    /** Oracle: tries every buy day and later sell day for each prefix. */
    static int[] oracle(int[] prices) {
        int[] best = new int[prices.length];
        for (int i = 0; i < prices.length; i++) {
            int b = 0;
            for (int a = 0; a < i; a++) {
                for (int s = a + 1; s <= i; s++) {
                    b = Math.max(b, prices[s] - prices[a]);
                }
            }
            best[i] = b;
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(bestByDay(new int[] {7, 1, 5, 3, 6, 4}), new int[] {0, 0, 4, 4, 5, 5})) throw new AssertionError("ex1");
        if (!Arrays.equals(bestByDay(new int[] {5, 4, 3}), new int[] {0, 0, 0})) throw new AssertionError("ex2");
        // An empty input returns an empty array.
        if (bestByDay(new int[] {}).length != 0) throw new AssertionError("empty");
        // The sentinel plus a price does not overflow, while the smallest int minus one wraps to the largest.
        if (Integer.MIN_VALUE / 2 + 10000 >= 0) throw new AssertionError("sentinel");
        if (Integer.MIN_VALUE - 1 != Integer.MAX_VALUE) throw new AssertionError("wrap");
        // The input stays unchanged.
        int[] p = {3, 1, 2};
        bestByDay(p);
        if (!Arrays.equals(p, new int[] {3, 1, 2})) throw new AssertionError("mutated");
        // Random inputs against the pair oracle.
        Random rnd = new Random(2801);
        for (int t = 0; t < 2000; t++) {
            int[] a = new int[rnd.nextInt(12)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(20);
            if (!Arrays.equals(bestByDay(a), oracle(a))) throw new AssertionError("random " + t);
        }
    }
}verified
Variation

Best Time to Buy and Sell Stock II

LeetCode 122

Problem Specification. Given an integer array prices, a trader may buy and sell any number of times while owning at most one share. Each day allows at most one action, and a buy and a sell cannot share a day. Return an array {profit, trades} where profit is the largest total profit and trades is the smallest number of buys that achieves that profit.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 1000.
  • Price satisfies 0 <= prices[i] <= 10000.
  • Result is an int[] of length 2, and {0,0} means no trade helps.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [3,1,4,1,5], output [7,2].

Example 2. Input prices = [2,2,2], output [0,0].

Prerequisites. The previous exercise and the buy and sell moves from this lesson.

What This Exercise Changes. Each situation keeps a profit and a trade count instead of one number, and equal profits keep the smaller count.

Hint

Store a pair for each situation and compare pairs by larger profit first, then by fewer trades. Where is a trade counted?

Algorithmic Solution (attempt the problem first)

Approach. Each situation keeps a pair: the best profit and, among plans with that profit, the fewest buys. A buy moves from cash to hold, subtracts the price and adds one to the buy count. A sell moves from hold to cash, adds the price and keeps the count. Doing nothing keeps the pair. The loop compares two candidate pairs by larger profit first, then by smaller count.

The invariant is that after each day, each pair describes the best plan for its exact situation under that order. Impossible plans carry the sentinel profit, and the first buy replaces it. The answer is the pair of cash. Fixing the count at the buy keeps the comparison correct, because a plan that is still owning a share has already paid for its trade.

Complexity.

  • Time is O(n), because each day compares a constant number of pairs.
  • Space is O(1) extra, since four integers carry the whole state.
import java.util.*;

public final class SsManyTrades {
    static final int NONE = Integer.MIN_VALUE / 2;

    /** Reports whether the pair (p1, t1) beats the pair (p2, t2): larger profit first, then fewer trades. */
    static boolean better(int p1, int t1, int p2, int t2) {
        return p1 > p2 || (p1 == p2 && t1 < t2);
    }

    /**
     * Returns {largest profit, fewest buys that reach it} for any number of trades.
     * Time: O(n). Space: O(1).
     * Invariant: each situation holds the best pair over the processed days, ordered by profit then trades.
     */
    static int[] profitAndTrades(int[] prices) {
        // hold is impossible at the start; cash is the empty plan with no buys.
        int holdP = NONE, holdT = 0, cashP = 0, cashT = 0;
        // One pass over the days costs O(n).
        for (int price : prices) {
            // Staying in hold is the first candidate for the new hold pair.
            int nhP = holdP, nhT = holdT;
            // Buying pays the price and adds one buy; it wins only when it is better.
            if (better(cashP - price, cashT + 1, nhP, nhT)) {
                nhP = cashP - price;
                nhT = cashT + 1;
            }
            // Staying in cash is the first candidate for the new cash pair.
            int ncP = cashP, ncT = cashT;
            // Selling earns the price and keeps the buy count; it wins only when it is better.
            if (better(holdP + price, holdT, ncP, ncT)) {
                ncP = holdP + price;
                ncT = holdT;
            }
            // Both new pairs were computed from the old pairs, so now the stores are safe.
            holdP = nhP;
            holdT = nhT;
            cashP = ncP;
            cashT = ncT;
        }
        // The answer is the cash pair, because a plan must end without a share.
        return new int[] {cashP, cashT};
    }

    /** Oracle: tries every sequence of Buy, Sell and Rest and keeps the best legal pair. */
    static int[] oracle(int[] prices) {
        int n = prices.length;
        int total = 1;
        for (int i = 0; i < n; i++) total *= 3;
        int bestP = 0, bestT = 0;
        for (int code = 0; code < total; code++) {
            int c = code;
            boolean own = false, ok = true;
            int profit = 0, trades = 0;
            for (int d = 0; d < n && ok; d++) {
                int a = c % 3;
                c /= 3;
                if (a == 0) {
                    if (own) ok = false;
                    else { own = true; profit -= prices[d]; trades++; }
                } else if (a == 1) {
                    if (!own) ok = false;
                    else { own = false; profit += prices[d]; }
                }
            }
            if (ok && !own && better(profit, trades, bestP, bestT)) {
                bestP = profit;
                bestT = trades;
            }
        }
        return new int[] {bestP, bestT};
    }

    static int calls;

    /** The recursion from the lesson, instrumented to count its calls. */
    static int explore(int[] prices, int day, boolean owns) {
        calls++;
        if (day == prices.length) return owns ? -1_000_000 : 0;
        int rest = explore(prices, day + 1, owns);
        if (owns) return Math.max(rest, prices[day] + explore(prices, day + 1, false));
        return Math.max(rest, -prices[day] + explore(prices, day + 1, true));
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(profitAndTrades(new int[] {3, 1, 4, 1, 5}), new int[] {7, 2})) throw new AssertionError("ex1");
        if (!Arrays.equals(profitAndTrades(new int[] {2, 2, 2}), new int[] {0, 0})) throw new AssertionError("ex2");
        // An empty input returns {0, 0}.
        if (!Arrays.equals(profitAndTrades(new int[] {}), new int[] {0, 0})) throw new AssertionError("empty");
        // The lesson's recursion makes 15 calls on 3 days, 2^(n+1) - 1 in general, and returns the same profit.
        calls = 0;
        int[] three = {1, 2, 3};
        if (explore(three, 0, false) != profitAndTrades(three)[0] || calls != 15) throw new AssertionError("calls");
        calls = 0;
        explore(new int[10], 0, false);
        if (calls != (1 << 11) - 1) throw new AssertionError("calls10");
        // The input stays unchanged.
        int[] p = {3, 1, 2};
        profitAndTrades(p);
        if (!Arrays.equals(p, new int[] {3, 1, 2})) throw new AssertionError("mutated");
        // Random inputs against the sequence oracle, with a small price range to force ties.
        Random rnd = new Random(2802);
        for (int t = 0; t < 1500; t++) {
            int[] a = new int[rnd.nextInt(9)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(7);
            if (!Arrays.equals(profitAndTrades(a), oracle(a))) throw new AssertionError("random " + t);
        }
    }
}verified

One Day And Falling Prices

Author exercise

Problem Specification. Given an integer array prices, a trader completes at most one trade, which pairs a buy day with a later sell day. Return the largest profit of a trade, or -1 if no trade earns a profit greater than 0.

Input Constraints. The limits are:

  • Length satisfies 1 <= prices.length <= 1000.
  • Price satisfies 0 <= prices[i] <= 10000.
  • Result is an int, and -1 is the only negative result.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [9], output -1.

Example 2. Input prices = [4,4,2,1,4], output 3.

Prerequisites. The two exercises above.

What This Exercise Changes. The method converts a final cash of 0 to the result -1, because a trade with zero profit does not count as a profitable trade.

Hint

What does cash equal when no trade ever earned more than 0, and which value of cash means that no trade happened?

Algorithmic Solution (attempt the problem first)

Approach. The method runs the one-trade loop with hold and cash and then reads the final cash. The value of cash starts at 0, so it equals 0 whenever no trade earned more than 0. A trade with profit 0 gives the same cash as no trade, and the contract treats both as unprofitable. The method therefore returns -1 for a final cash of 0 and returns cash otherwise.

The invariant is that cash is the largest profit of at most one trade over the processed prefix, so it is never negative. A one-day array never reaches the sell move with a real hold, a strictly falling array never beats the start value, and a flat array only ties it. All three end at 0 and return -1.

Complexity.

  • Time is O(n), because the loop visits each day once.
  • Space is O(1), since only hold and cash are stored.
import java.util.*;

public final class SsFallingPrices {
    /**
     * Returns the largest positive profit of one trade, or -1 when no trade earns more than 0.
     * Time: O(n). Space: O(1).
     * Invariant: cash is the best profit of at most one trade in the processed prefix and never drops below 0.
     */
    static int positiveProfitOrMinusOne(int[] prices) {
        // hold is impossible until the first buy.
        int hold = Integer.MIN_VALUE / 2;
        // cash 0 stands for no profitable trade yet.
        int cash = 0;
        // One pass over the days costs O(n).
        for (int p : prices) {
            // The one trade buys at the lowest price seen, so the buy value is -p.
            int nextHold = Math.max(hold, -p);
            // Selling adds today's price to the best owning plan.
            int nextCash = Math.max(cash, hold + p);
            // Stores happen after both values are computed.
            hold = nextHold;
            cash = nextCash;
        }
        // A final cash of 0 means no trade beat the start, so the contract returns -1.
        return cash == 0 ? -1 : cash;
    }

    /** Oracle: tries every buy day and later sell day. */
    static int oracle(int[] prices) {
        int best = -1;
        for (int a = 0; a < prices.length; a++) {
            for (int s = a + 1; s < prices.length; s++) {
                if (prices[s] - prices[a] > best && prices[s] - prices[a] > 0) best = prices[s] - prices[a];
            }
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (positiveProfitOrMinusOne(new int[] {9}) != -1) throw new AssertionError("ex1");
        if (positiveProfitOrMinusOne(new int[] {4, 4, 2, 1, 4}) != 3) throw new AssertionError("ex2");
        // Falling and flat arrays return -1.
        if (positiveProfitOrMinusOne(new int[] {5, 4, 3, 2}) != -1) throw new AssertionError("falling");
        if (positiveProfitOrMinusOne(new int[] {6, 6, 6}) != -1) throw new AssertionError("flat");
        // A rise after a fall is found, and the largest price may come before the smallest.
        if (positiveProfitOrMinusOne(new int[] {6, 9, 1, 3}) != 3) throw new AssertionError("order");
        // The input stays unchanged.
        int[] p = {3, 1, 2};
        positiveProfitOrMinusOne(p);
        if (!Arrays.equals(p, new int[] {3, 1, 2})) throw new AssertionError("mutated");

State Diagram

Author exercise

Problem Specification. Given an integer array prices, each day the trader performs exactly one action: Buy, Sell or Rest. Buy requires that the trader owns no share, and Sell requires that the trader owns one. The trader owns no share before the first day and after the last day. Return {profit, ways}, where profit is the largest total profit and ways is the number of legal action sequences that earn it.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 12.
  • Price satisfies 0 <= prices[i] <= 100.
  • Result is an int[] of length 2, and the empty array returns {0,1}.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [1,2,3], output [2,1].

Example 2. Input prices = [2,2,2], output [0,4].

Prerequisites. All three exercises above.

What This Exercise Changes. Each situation keeps a best profit and a count of sequences that reach it, and equal profits add their counts.

Hint

Draw the two situations and the actions on each line first. How many ways reach each situation, and what happens to the counts when two actions tie?

Algorithmic Solution (attempt the problem first)

Approach. The state diagram has two situations, cash and hold, and each day draws four lines. Rest keeps cash, rest keeps hold, Buy goes from cash to hold, and Sell goes from hold to cash. Each line is one action, so counting action sequences means counting paths through this diagram. The method derives these lines first and then keeps, for each situation, the best profit and the number of paths that reach it.

When two lines enter the same situation on a day, the larger profit wins and keeps its count. When the profits tie, the counts add. An impossible situation has count 0, so it never contributes to a sum. The invariant is that each pair holds the best profit over the processed days and the exact number of legal prefixes that reach it. The answer is the cash pair.

Complexity.

  • Time is O(n), because each day combines a constant number of lines.
  • Space is O(1) extra, since two profits and two counts carry the state.
import java.util.*;

public final class SsStateDiagram {
    static final int NONE = Integer.MIN_VALUE / 2;

    /**
     * Returns {largest profit, number of legal Buy/Sell/Rest sequences that earn it}.
     * Time: O(n). Space: O(1).
     * Invariant: each situation stores its best profit and the number of legal prefixes that reach it.
     */
    static int[] bestAndWays(int[] prices) {
        // Cash has the empty prefix as one way; hold has no way yet.
        int cashP = 0, cashW = 1, holdP = NONE, holdW = 0;
        // One pass over the days costs O(n).
        for (int price : prices) {
            // Two lines enter cash: Rest from cash and Sell from hold.
            int sellP = holdP + price;
            int ncP = Math.max(cashP, sellP);
            // Equal profits add their ways; a line with a smaller profit adds nothing.
            int ncW = (cashP == ncP ? cashW : 0) + (sellP == ncP ? holdW : 0);
            // Two lines enter hold: Rest from hold and Buy from cash.
            int buyP = cashP - price;
            int nhP = Math.max(holdP, buyP);
            int nhW = (holdP == nhP ? holdW : 0) + (buyP == nhP ? cashW : 0);
            // The stores wait until both pairs are ready, because each reads the old pair of the other.
            cashP = ncP;
            cashW = ncW;
            holdP = nhP;
            holdW = nhW;
        }
        // The sequence must end without a share, so the cash pair is the answer.
        return new int[] {cashP, cashW};
    }

    /** Oracle: enumerates all 3^n action strings and filters the legal ones. */
    static int[] oracle(int[] prices) {
        int n = prices.length;
        int total = 1;
        for (int i = 0; i < n; i++) total *= 3;
        int best = Integer.MIN_VALUE, ways = 0;
        for (int code = 0; code < total; code++) {
            int c = code;
            boolean own = false, ok = true;
            int profit = 0;
            for (int d = 0; d < n && ok; d++) {
                int a = c % 3;
                c /= 3;
                if (a == 0) {
                    if (own) ok = false;
                    else { own = true; profit -= prices[d]; }
                } else if (a == 1) {
                    if (!own) ok = false;
                    else { own = false; profit += prices[d]; }
                }
            }
            if (!ok || own) continue;
            if (profit > best) { best = profit; ways = 1; }
            else if (profit == best) ways++;
        }
        return new int[] {best, ways};
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(bestAndWays(new int[] {1, 2, 3}), new int[] {2, 1})) throw new AssertionError("ex1");
        if (!Arrays.equals(bestAndWays(new int[] {2, 2, 2}), new int[] {0, 4})) throw new AssertionError("ex2");
        // The empty array has exactly one legal sequence, the empty one.
        if (!Arrays.equals(bestAndWays(new int[] {}), new int[] {0, 1})) throw new AssertionError("empty");
        // The input stays unchanged.
        int[] p = {3, 1, 2};
        bestAndWays(p);
        if (!Arrays.equals(p, new int[] {3, 1, 2})) throw new AssertionError("mutated");
        // Random inputs against the enumeration oracle, with a small price range to force ties.
        Random rnd = new Random(2804);
        for (int t = 0; t < 1500; t++) {
            int[] a = new int[rnd.nextInt(9)];
            for (int i = 0; i < a.length; i++) a[i] = rnd.nextInt(5);
            if (!Arrays.equals(bestAndWays(a), oracle(a))) throw new AssertionError("random " + t);
        }
    }

A Profit Calculator That Ignores A Rule

A brokerage tool receives daily prices [2, 3, 4, 1, 3] and reports the largest profit from buying and selling one share at a time. The tool uses the hold and cash states from the previous lesson and prints 4. It buys at 2 and sells at 4, then buys at 1 and sells at 3. The exchange rejects the second purchase, because its rules forbid buying on the day after a sale. The achievable profit is 3.

The same calculator also misleads when every sale carries a flat fee, and when only two sales are allowed. In each case the two-state code accepts a sequence of actions that the rules forbid, or it prices the sequence wrongly.

Formally, prices[i] is the price on day i, and the trader holds at most one share. A transaction is one purchase followed by one later sale. The cooldown rule forbids a purchase on the day right after a sale. The task is to return the largest total profit that obeys the rule. The method never changes prices.

This lesson asks how the table can remember a rule that depends on what happened yesterday.

Simple approach

Reusing The Two-State Update

The quick idea is to run the hold and cash update from the previous lesson unchanged. Each day it keeps the better of two values for holding a share and for holding none.

static int twoStates(int[] prices) {
    int hold = -prices[0];
    int cash = 0;
    for (int i = 1; i < prices.length; i++) {
        int nextHold = Math.max(hold, cash - prices[i]);
        int nextCash = Math.max(cash, hold + prices[i]);
        hold = nextHold;
        cash = nextCash;
    }
    return cash;
}

The method runs in O(n) time and O(1) memory for n days. The open question is whether the value cash can tell a purchase that follows a sale from a purchase that follows a quiet day.

Predict first: Run twoStates on prices [2, 3, 4, 1, 3]. What does it return, and what is the largest profit when a purchase on the day after a sale is forbidden?

It returns 4. On day 3 the update reads cash, which already contains the sale made on day 2, and buys at price 1. The rule forbids that purchase, so the true largest profit is 3.

Bottleneck

One Cash Value Hides Yesterday

The variable cash stores a profit only. Two histories can give the same profit while one of them sold yesterday and the other did not. The next action is legal in the second history and illegal in the first, so a single value cannot decide the transition.

A correct but slow method tries every legal action for each day: skip, buy or sell. Each day offers at most two actions, so the search visits up to 2^n action sequences, which is O(2^n) time. For n = 40 days that is more than 10^12 sequences.

Another repair stores the day of the last sale next to each profit. Day i then keeps up to i pairs, and the whole scan costs O(n^2) time. That is better, but the extra information is wasteful. The next action depends only on whether the last sale happened yesterday, which is one yes-or-no fact. A table that keeps that fact as part of its state needs a constant number of values per day.

Key idea

Make The Rule Part Of The State

Each state must answer two questions at once: does the trader own a share, and which actions the rule allows next. Then the transition table is a small graph, and the best profit for each state follows from the best profits of the previous day.

Three States For A Cooldown

The cooldown splits the cash condition in two. The sold state means the trader sold today, so a purchase tomorrow is illegal. The rest state means the trader holds no share and may buy tomorrow. The hold state keeps its meaning. Each state stores the best profit of any history that ends the day in it.

Five transitions are legal. Hold stays hold, or comes from the rest state by paying today's price. The sold state comes only from hold by receiving today's price. The rest state comes from the rest state or from the sold state of the day before. A purchase never reads the sold state, so the rule holds by construction.

One Fee On One Transition

A fee changes the value of a transition and leaves the states alone. The two states hold and cash still describe the rule completely. Subtract the fee on exactly one transition of each transaction, here the sale. Charging it on both the purchase and the sale would count it twice.

A Count Becomes A State

A limit of two sales needs the number of completed sales in the state. Hold after zero sales, cash after one sale, hold after one sale and cash after two sales are four states, and cash after zero sales is the constant 0, which the table does not store. A purchase moves from a cash state to the next hold state, and a sale moves from a hold state to the next cash state.

Reading Only The Old Values

All new values of day i come from the old values of day i - 1. If the code overwrites one variable and then reads it for another state, the second state sees a mix of two days. The invariant is that after day i, each state holds the best profit of histories that end day i in that state. Compute every new value into a temporary before any assignment.

State

The Three Profit Values

The cooldown method leaves prices alone and keeps these working values.

  • hold is the best profit of a history that owns a share at the end of the day.
  • sold is the best profit of a history that sold a share today.
  • rest is the best profit of a history that owns no share and sold nothing today.
  • i is the current day, from 1 to n - 1.
  • nextHold, nextSold and nextRest are the values for day i, computed before any assignment.

Day 0 starts with hold = -prices[0], sold = 0 and rest = 0. The value sold = 0 is a placeholder that no purchase reads, because a purchase reads only rest. The answer is the larger of sold and rest after the last day, because a history that still owns a share has not realized its profit.

Walkthrough

Two Runs Over Short Price Lists

The Rule Blocks A Purchase

The first run uses prices [2, 3, 4, 1, 3] and the correct update. Each cell is a price, and the pointer i marks the current day. The variables hold, sold and rest show the three states after the day.

On day 1 the sale at 3 gives sold = 1. On day 2 that profit moves into rest, so a purchase becomes legal only on day 3. On day 3 the hold value rises to 0, which means the trader sold at 3 on day 1, skipped day 2 and bought at 1. On day 4 the sale at 3 gives sold = 3, which is the answer.

The Update That Reads A Fresh Value

The second run uses prices [2, 5, 1, 4] and an update in the wrong order. It computes sold first and then lets rest read that new sold in the same day. The correct answer is 3, because the sale at 5 on day 1 blocks the purchase at 1 on day 2.

The faulty rest already contains the sale of day 1, so hold buys at 1 on day 2 and the final sale at 4 reports 6. The profit of 6 comes from a history that the rule forbids.

Code

The Three-State Loop

The method returns the largest profit under the cooldown rule. It computes the three new values from the three old ones and then assigns them together.

static int cooldownProfit(int[] prices) {
    int hold = -prices[0];
    int sold = 0;
    int rest = 0;
    for (int i = 1; i < prices.length; i++) {
        int nextHold = Math.max(hold, rest - prices[i]);
        int nextSold = hold + prices[i];
        int nextRest = Math.max(rest, sold);
        hold = nextHold;
        sold = nextSold;
        rest = nextRest;
    }
    return Math.max(sold, rest);
}

The cost is O(n) time and O(1) memory. The fee version keeps two variables and subtracts the fee in the line that computes nextCash. The two-sale version keeps four variables and follows the same pattern of temporaries.

When to use it

Recognizing A Rule That Needs State

Reading The Cue

Use this method when a rule restricts which action may follow which, or when the number of completed actions has a limit. Phrases such as "after a sale you must wait", "each transaction costs", and "at most k transactions" point here. A flat cost or reward changes a transition value, a waiting rule adds a state, and a count limit multiplies the states.

Checking The Invariant

The invariant says that each state stores the best profit of histories that end the day in exactly that situation. Check it by listing the legal transitions and confirming that no transition leaves a state the rule forbids. Test a falling price list, where the answer is 0. Test a single day. Test a list where a sale on day i makes day i + 1 attractive, because only that case exposes a wrong update order.

Avoiding The False Friend

The first false friend is the two-state update, which passes every list in which the rule never binds. The second is a greedy rule that sells at every peak, which ignores both the fee and the waiting day. The third is an in-place update that overwrites a variable before another state reads it.

The method does not fit when legality depends on a history that no small label summarizes. A cooldown of n / 2 days needs about n / 2 states. A rule that compares the next purchase price with an earlier purchase price needs that price in the state. In those cases a table indexed by day and a larger parameter fits better.

import java.util.*;

public final class TvCooldownProfit {
    /**
     * Returns the largest profit when a purchase on the day after a sale is illegal.
     * Time: O(n). Space: O(1).
     * Invariant: after day i, hold, sold and rest are the best profits of histories ending day i in that situation.
     */
    static int cooldownProfit(int[] prices) {
        // Day 0 allows only a purchase, so hold pays the first price.
        int hold = -prices[0];
        // No sale is possible on day 0.
        int sold = 0;
        // Owning nothing with no sale today starts at profit 0.
        int rest = 0;
        // Each later day costs a constant number of steps.
        for (int i = 1; i < prices.length; i++) {
            // A purchase reads rest only, so it never follows a sale of the previous day.
            int nextHold = Math.max(hold, rest - prices[i]);
            // A sale turns the held share into profit today.
            int nextSold = hold + prices[i];
            // Yesterday's sale becomes free to act on after one waiting day.
            int nextRest = Math.max(rest, sold);
            // The three assignments happen after all three reads.
            hold = nextHold;
            sold = nextSold;
            rest = nextRest;
        }
        // An owned share has no realized profit, so hold is excluded.
        return Math.max(sold, rest);
    }

    /** Oracle: explores skip, buy and sell with the cooldown flag. */
    static int oracle(int[] p, int i, boolean holding, boolean cool) {
        if (i == p.length) return 0;
        int best = oracle(p, i + 1, holding, false);
        if (holding) best = Math.max(best, p[i] + oracle(p, i + 1, false, true));
        else if (!cool) best = Math.max(best, -p[i] + oracle(p, i + 1, true, false));
        return best;
    }

        // The two examples of the exercise.
        if (cooldownProfit(new int[] {6, 1, 3, 2, 4, 7}) != 6) throw new AssertionError("ex1");

        if (cooldownProfit(new int[] {2, 3, 4, 1, 3}) != 3) throw new AssertionError("opening");
        // A single day cannot realize any profit.
        if (cooldownProfit(new int[] {7}) != 0) throw new AssertionError("single");
        // The input array stays unchanged.
        int[] p = {2, 3, 4, 1, 3};
        cooldownProfit(p);
        if (!Arrays.equals(p, new int[] {2, 3, 4, 1, 3})) throw new AssertionError("mutated");

import java.util.*;

public final class TvFeeProfit {
    /**
     * Returns the largest profit when each sale pays a flat fee once.
     * Time: O(n). Space: O(1).
     * Invariant: after day i, cash and hold are the best profits without and with an open position.
     */
    static int feeProfit(int[] prices, int fee) {
        // Day 0 allows only a purchase, so hold pays the first price.
        int hold = -prices[0];
        // Cash starts at profit 0 with no position.
        int cash = 0;
        // Each later day costs a constant number of steps.
        for (int i = 1; i < prices.length; i++) {
            // Keep the share or buy with the previous day's cash.
            int nextHold = Math.max(hold, cash - prices[i]);
            // Keep the cash or sell the held share and pay the fee once.
            int nextCash = Math.max(cash, hold + prices[i] - fee);
            // Both assignments happen after both reads.
            hold = nextHold;
            cash = nextCash;
        }
        // Only a closed position has a realized profit.
        return cash;
    }

    /** Oracle: explores skip, buy and sell with the fee charged at each sale. */
    static int oracle(int[] p, int fee, int i, boolean holding) {
        if (i == p.length) return 0;
        int best = oracle(p, fee, i + 1, holding);
        if (holding) best = Math.max(best, p[i] - fee + oracle(p, fee, i + 1, false));
        else best = Math.max(best, -p[i] + oracle(p, fee, i + 1, true));
        return best;
    }

        // The two examples of the exercise.
        if (feeProfit(new int[] {3, 8, 5, 10, 4, 9}, 2) != 9) throw new AssertionError("ex1");

        if (feeProfit(new int[] {9}, 3) != 0) throw new AssertionError("single");

Update Aliasing

Author exercise

Problem Specification. Run two cooldown updates over prices. The correct update uses the three-state recurrence with all new values computed from the previous day. The faulty update runs sold = hold + p, then rest = max(rest, sold), then hold = max(hold, rest - p) in place, for price p. Both start with hold = -prices[0], sold = 0 and rest = 0. After each day i from 1, the profit is max(sold, rest). Return the smallest i where the two profits differ, or -1 if they never differ.

Input Constraints. The limits are:

  • Length satisfies 1 <= prices.length <= 2000.
  • Price satisfies 0 <= prices[i] <= 1000.
  • Result is -1 for a list of length 1.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [2,5,1,4], output 3.

Example 2. Input prices = [3,3,3], output -1.

Prerequisites. The exercises above.

What This Exercise Changes. The task compares two update orders on the same input. The correct one reads only values from the previous day, and the faulty one reads values that it has just written.

Hint

A wrong value first shows in the profit only after a purchase that the rule forbids can pay off. On which day does that profit appear?

Algorithmic Solution (attempt the problem first)

Approach. The method runs the two updates side by side from the same start. The correct update computes nextHold, nextSold and nextRest from the previous day and assigns them together. The faulty update assigns sold, then lets rest read the new sold, then lets hold read the new rest. Each assignment feeds the next, so the faulty rest contains a sale made on the current day, and a purchase on the following day reads it.

After each day the method compares the two values of max(sold, rest) and returns the first day with a difference. The invariant is that before day i, both runs have produced equal profits on every earlier day. The test compares the correct run with an exhaustive search on every prefix, and it computes the faulty run by a separate array-based simulation.

Complexity.

  • Time is O(n), because each day updates six values in constant time.
  • Space is O(1), because only six profits and three temporaries exist, and the input array stays unchanged.
import java.util.*;

public final class TvUpdateAliasing {
    /**
     * Returns the first day where the in-place update and the correct update differ, or -1.
     * Time: O(n). Space: O(1).
     * Invariant: before day i, the two runs agree on the profit of every earlier day.
     */
    static int firstDifference(int[] prices) {
        // Both runs share the same start values after day 0.
        int hold = -prices[0], sold = 0, rest = 0;
        int fHold = hold, fSold = 0, fRest = 0;
        // Each later day updates both runs in constant time.
        for (int i = 1; i < prices.length; i++) {
            int p = prices[i];
            // The correct update reads only the previous day.
            int nextHold = Math.max(hold, rest - p);
            int nextSold = hold + p;
            int nextRest = Math.max(rest, sold);
            hold = nextHold;
            sold = nextSold;
            rest = nextRest;
            // The faulty update lets each assignment feed the next one.
            fSold = fHold + p;
            fRest = Math.max(fRest, fSold);
            fHold = Math.max(fHold, fRest - p);
            // The first unequal profit ends the scan.
            if (Math.max(sold, rest) != Math.max(fSold, fRest)) return i;
        }
        // Equal profits on every day give -1.
        return -1;
    }

    /** Oracle: the correct profit of one prefix by exhaustive search. */
    static int exhaustive(int[] p, int i, int end, boolean holding, boolean cool) {
        if (i == end) return 0;
        int best = exhaustive(p, i + 1, end, holding, false);
        if (holding) best = Math.max(best, p[i] + exhaustive(p, i + 1, end, false, true));
        else if (!cool) best = Math.max(best, -p[i] + exhaustive(p, i + 1, end, true, false));
        return best;
    }

    /** Oracle: the faulty profit after each day, simulated with an array of three slots. */
    static int oracleFirst(int[] p) {
        int[] s = {-p[0], 0, 0};
        for (int i = 1; i < p.length; i++) {
            s[1] = s[0] + p[i];
            s[2] = Math.max(s[2], s[1]);
            s[0] = Math.max(s[0], s[2] - p[i]);
            // The faulty value at day i is compared with the exhaustive profit of the prefix.
            if (Math.max(s[1], s[2]) != exhaustive(p, 0, i + 1, false, false)) return i;
        }
        return -1;
    }

Problem Specification. The array prices lists one share price per day. A trader owns at most one share and sells it before the next purchase. Return the largest profit from at most two transactions, where a transaction is one purchase followed by one later sale.

  • Length satisfies 1 <= prices.length <= 100000.
  • Price satisfies 0 <= prices[i] <= 100000.
  • Count allows 0, 1 or 2 transactions.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [4,2,6,1,5,3,8], output 11.

Example 2. Input prices = [9,7,5], output 0.

Prerequisites. All three exercises above.

What This Exercise Changes. The state carries a count of completed sales together with the possession flag. This gives four values, and each reads the four values of the previous day.

Hint

How many completed sales does a history have so far, and does it own a share right now?

Algorithmic Solution (attempt the problem first)

Approach. The state needs the number of completed sales and the possession flag. The method keeps hold1 for owning the first share, done1 for one completed sale, hold2 for owning the second share, and done2 for two completed sales. A purchase moves from a done value to the next hold value, and a sale moves from a hold value to the next done value.

Each of the four new values reads only the four values of the previous day. The invariant is that after day i, each value is the best profit of histories with that count and that possession flag. A history with fewer sales stays inside done1 or done2, because each done value keeps its previous best. The answer is done2, since it is at least done1 and at least 0. The test compares the method with an exhaustive search that tracks the number of sales left.

Complexity.

  • Time is O(n), because each day updates four values in constant time.
  • Space is O(1), because four profits and four temporaries are the only extra memory, and the input array stays unchanged.
import java.util.*;

public final class TvTwoTransactions {
    /**
     * Returns the largest profit from at most two transactions.
     * Time: O(n). Space: O(1).
     * Invariant: after day i, each value is the best profit for its sale count and possession flag.
     */
    static int twoTransactions(int[] prices) {
        // Day 0 allows only a first purchase.
        int hold1 = -prices[0];
        // No sale is possible yet, so profit stays 0.
        int done1 = 0;
        // Selling and rebuying on day 0 gives the same price, so hold2 starts equal to hold1.
        int hold2 = -prices[0];
        // Two completed sales start at profit 0.
        int done2 = 0;
        // Each later day costs a constant number of steps.
        for (int i = 1; i < prices.length; i++) {
            int p = prices[i];
            // The first purchase starts from profit 0.
            int nextHold1 = Math.max(hold1, -p);
            // The first sale closes the first purchase.
            int nextDone1 = Math.max(done1, hold1 + p);
            // The second purchase starts from the first completed sale of the previous day.
            int nextHold2 = Math.max(hold2, done1 - p);
            // The second sale closes the second purchase.
            int nextDone2 = Math.max(done2, hold2 + p);
            // All four assignments happen after all four reads.
            hold1 = nextHold1;
            done1 = nextDone1;
            hold2 = nextHold2;
            done2 = nextDone2;
        }
        // Done2 keeps the best of zero, one and two completed transactions.
        return Math.max(done2, done1);
    }

    /** Oracle: explores skip, buy and sell with a count of sales left. */
    static int oracle(int[] p, int i, boolean holding, int left) {
        if (i == p.length) return 0;
        int best = oracle(p, i + 1, holding, left);
        if (holding) best = Math.max(best, p[i] + oracle(p, i + 1, false, left));
        else if (left > 0) best = Math.max(best, -p[i] + oracle(p, i + 1, true, left - 1));
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (twoTransactions(new int[] {4, 2, 6, 1, 5, 3, 8}) != 11) throw new AssertionError("ex1");
        if (twoTransactions(new int[] {9, 7, 5}) != 0) throw new AssertionError("ex2");
        // A single day returns 0.
        if (twoTransactions(new int[] {3}) != 0) throw new AssertionError("single");
        // One rising run uses one transaction only.
        if (twoTransactions(new int[] {1, 2, 3, 4}) != 3) throw new AssertionError("rising");
        // The input array stays unchanged.
        int[] p = {4, 2, 6};
        twoTransactions(p);
        if (!Arrays.equals(p, new int[] {4, 2, 6})) throw new AssertionError("mutated");
        // Random lists against the exhaustive search.
        Random rnd = new Random(2805);
        for (int t = 0; t < 3000; t++) {
            int n = 1 + rnd.nextInt(12);
            int[] q = new int[n];
            for (int i = 0; i < n; i++) q[i] = rnd.nextInt(10);
            if (twoTransactions(q) != oracle(q, 0, false, 2)) throw new AssertionError("random " + t);
        }
    }

Problem

Finding A Rising Trend In Noisy Readings

A monitoring service stores a sensor reading for each minute. The readings for seven minutes are 5, 1, 6, 2, 7, 3 and 8. An engineer wants the longest group of readings that rise from one chosen minute to the next, where the chosen minutes need not touch each other. The readings 1, 2, 3 and 8 form such a group of four, and so do 5, 6, 7 and 8.

A first version scans the data and counts the longest run of neighbouring minutes that rise. On these readings it reports 2, because every rise is cut off by a drop on the next minute. The report misses the trend because the noisy readings in between hide it.

Formally, the input is an int[] nums. A subsequence keeps some elements in their original order and may skip any elements between them. It is strictly increasing when each kept element is larger than the one before it. The method returns the length of the longest strictly increasing subsequence. The empty array has length 0, and the method never changes the array.

This lesson asks how to count such a subsequence when the chosen elements are scattered through the array.

Simple approach

Counting Runs Of Neighbouring Elements

The quick idea scans once and counts how many neighbouring elements in a row increase. It resets the count whenever an element does not exceed the one before it.

static int longestRun(int[] nums) {
    if (nums.length == 0) return 0;
    int best = 1;
    int run = 1;
    for (int i = 1; i < nums.length; i++) {
        run = nums[i] > nums[i - 1] ? run + 1 : 1;
        best = Math.max(best, run);
    }
    return best;
}

The method runs in O(n) time and uses O(1) memory. It answers a different question, which is the longest increasing block of adjacent elements. A subsequence may skip elements, so the block answer is never larger than the true answer and is often smaller.

Predict first: Run longestRun on 5, 1, 6, 2, 7, 3, 8. What does it return, and what is the true longest strictly increasing subsequence?

It returns 2, because the pairs 1 and 6, 2 and 7, and 3 and 8 are the longest adjacent rises. The true answer is 4, for example 1, 2, 3, 8. The elements 1, 2 and 3 are not adjacent, so the run counter cannot see them.

Bottleneck

Too Many Subsequences To List

A correct but slow method lists every subsequence. An array of n elements has 2^n subsequences, and checking one costs O(n), so the work is O(2^n * n). For n = 40 that is more than 4 * 10^13 operations.

A better method uses the structure of the problem. Every increasing subsequence ends at some index, and what comes before that last element is itself an increasing subsequence that ends at a smaller index. This allows a table with one entry per index. Filling the entry for index i compares nums[i] with every earlier element, so the total work is O(n^2). That is fast enough for n = 2,000, because it needs about four million comparisons.

The quadratic method fails when n reaches 200,000. It needs about 4 * 10^10 comparisons, which takes tens of seconds in Java. The extra cost comes from comparing each new element with all earlier elements, even though most of those comparisons cannot change the answer. The next section builds the table first and then removes the repeated comparisons.

Key idea

Keep The Best Ending For Each Length

The goal is to extend a subsequence one element at a time without remembering the subsequence itself. Two summaries are enough, and the second one is a faster version of the first.

One Length For Every Last Element

Let dp[i] be the length of the longest strictly increasing subsequence whose last element is nums[i]. Every such subsequence has length 1 when it holds only nums[i]. Otherwise its second-to-last element is some nums[j] with j < i and nums[j] < nums[i], and the part before nums[i] is a subsequence that ends at j. Therefore dp[i] is 1 plus the largest dp[j] over all earlier smaller values, or 1 if none exists. The answer is the largest dp[i], because the best subsequence ends at some index.

One Smallest Tail For Every Length

The tail of a subsequence is its last element. For each length L, keep the smallest tail among all increasing subsequences of length L that exist in the part of the array read so far. Store these values in an array tails, where tails[L - 1] belongs to length L. A smaller tail is always at least as good, because any later element that can extend a subsequence with a larger tail can also extend one with a smaller tail.

The array tails is strictly increasing. If a subsequence of length L + 1 ends at value v, then removing its last element leaves a subsequence of length L with a tail below v. So the smallest tail for length L is below the smallest tail for length L + 1.

Place Each Value With Binary Search

A new value x can extend the longest subsequence only if x is larger than every tail. Otherwise it belongs at the first position whose tail is at least x. That position is the lower bound of x in tails. Replacing the tail there with x keeps the array strictly increasing, and it keeps the smallest tail for that length. Because tails is sorted, binary search finds the lower bound in O(log n) steps.

Equal values must replace and not extend. If x equals a tail, the lower bound points at that tail, and the replacement changes nothing. The length of the answer stays the same, which is correct for a strict comparison.

The array tails is not an actual subsequence of the input. It mixes the best tails from different subsequences, and a later tail may come from an earlier position than a smaller one. Only its size is the answer. The invariant is that after each element, tails[L - 1] is the smallest possible last element of an increasing subsequence of length L in the prefix read so far.

State

The Length Table And The Tails Array

The quadratic method keeps these working values, and it leaves the input unchanged.

  • dp is an int[] where dp[i] is the longest increasing subsequence that ends at index i.
  • i is the index whose entry the outer loop computes.
  • j is an earlier index that the inner loop compares with i, from 0 up to i - 1.
  • best is the largest entry of dp seen so far.

The faster method keeps these values instead.

  • tails is an int[] of capacity n, and its first size entries are strictly increasing.
  • size is the number of used entries, which equals the longest length found so far.
  • x is the element nums[i] that the loop places.
  • pos is the lower bound of x among the first size entries.

If pos equals size, the value is larger than every tail, and size grows by one. Otherwise the entry at pos is overwritten and size stays.

Walkthrough

Two Runs Over Small Arrays

Quadratic Table On The Opening Readings

The first run fills the length table for the readings 5, 1, 6, 2, 7, 3 and 8. Each cell is one reading. The pointer i marks the reading whose entry is being computed, and the pointer j marks the earlier reading that it is compared with. The variable len is dp[j], and in this trace only, best is the current entry for i.

Index 2 holds 6 and extends both 5 and 1, so its length is 2. Index 4 holds 7 and extends 6 at length 2, so its length is 3. Index 6 holds 8, which is larger than everything, and it takes the best earlier length 3 plus one. The final length is 4, the same as the subsequence 5, 6, 7, 8 or 1, 2, 3, 8.

Tails On An Array With Equal Values

The second run uses the readings 4, 8, 4, 9, 2, 3, 5, 5 and 6. The pointer i marks the reading being placed. The variable x is that reading, pos is its lower bound among the tails, and size is the length found so far.

The first two readings grow the list to 4 and 8, and 9 grows it to length 3. The second 4 finds the tail 4 already at position 0, so it replaces that tail with an equal value and the length stays. The reading 2 then replaces 4, which makes the list 2, 8, 9. That list is not a subsequence of the input, since 2 comes after 8 and 9. The readings 3 and 5 replace 8 and 9, and the second 5 changes nothing. The reading 6 grows the list to length 4. The tails 2, 3, 5 and 6 happen to form a subsequence here, yet the method never relies on that.

Code

Two Methods For The Same Length

The first method fills the table of lengths. The second keeps the sorted tails and searches for each position.

static int lisQuadratic(int[] nums) {
    int n = nums.length;
    int[] dp = new int[n];
    int best = 0;
    for (int i = 0; i < n; i++) {
        dp[i] = 1;
        for (int j = 0; j < i; j++) {
            if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) dp[i] = dp[j] + 1;
        }
        best = Math.max(best, dp[i]);
    }
    return best;
}

static int lisTails(int[] nums) {
    int[] tails = new int[nums.length];
    int size = 0;
    for (int x : nums) {
        int lo = 0;
        int hi = size;
        while (lo < hi) {
            int mid = (lo + hi) >>> 1;
            if (tails[mid] < x) lo = mid + 1;
            else hi = mid;
        }
        tails[lo] = x;
        if (lo == size) size++;
    }
    return size;
}

The first method costs O(n^2) time and O(n) memory. The second costs O(n log n) time, because each element needs one binary search over at most n entries, and it uses O(n) memory. Both return 0 for an empty array, since the loops never run. The search keeps tails[mid] < x as the move-right test, which makes it a lower bound and handles equal values. The exercises below build the table first, then change the question, then the comparison, then the input size.

When to use it

Recognizing Rising Subsequences

Reading The Cue

Use this method when the answer is a longest chain of elements that keep their order, the elements need not be adjacent, and each chosen element must be larger than the previous one. Words such as "not necessarily contiguous" and "strictly increasing" point here. The quadratic table fits small inputs and also fits questions that need a value for each ending index. The sorted tails fit large inputs where only the length matters.

Checking The Invariant

The invariant of the table says that dp[i] is final before any later index reads it. The invariant of the tails says that the list is strictly increasing and holds the smallest possible tail for each length. Test an array in strictly decreasing order, which must give 1. Test an array of equal values, which must also give 1 for a strict rule. Test an empty array and a single element.

Avoiding The False Friend

The first false friend is the longest increasing block of adjacent elements, which passes sorted inputs and fails the opening readings. The second is reading the tails list as the answer subsequence, which fails whenever a small value arrives late. The third is an upper bound search, which lets equal values extend the list and so solves the non-decreasing question. This method does not apply when the chosen elements must be adjacent, or when the answer needs a weighted sum in place of a count, because the tails list stores no weights.

Hint

Which earlier entries may extend index i, and what does every entry start as?

Algorithmic Solution (attempt the problem first)

Approach. Entry dp[i] is the length of the longest strictly increasing subsequence whose last element is nums[i]. Each entry starts at 1, because the element alone is a valid subsequence. The inner loop then visits every earlier index j. When nums[j] is smaller than nums[i], any subsequence that ends at j can take nums[i] as its next element, so the candidate is dp[j] + 1. The entry keeps the largest candidate.

The invariant is that every entry below i is final when index i starts, so each candidate reads a finished value. Equal values give no candidate, which enforces the strict rule. The test compares every entry with a subset enumeration on random arrays.

Complexity.

  • Time is O(n^2), because index i compares with i earlier indexes and the sum of those counts is about n^2 / 2.
  • Space is O(n) for the result array, and the input array stays unchanged.
import java.util.*;

public final class IsEndingAtI {
    /**
     * Returns, for each index, the longest strictly increasing subsequence length that ends there.
     * Time: O(n^2). Space: O(n).
     * Invariant: dp[0..i-1] are final when index i is computed.
     */
    static int[] endingAt(int[] nums) {
        // One entry per index, so memory is O(n).
        int[] dp = new int[nums.length];
        for (int i = 0; i < nums.length; i++) {
            // The element alone is a subsequence of length 1.
            dp[i] = 1;
            // Every earlier index is a possible previous element, so this loop costs O(i).
            for (int j = 0; j < i; j++) {
                // Only a strictly smaller earlier value can extend, so equal values never count.
                if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) dp[i] = dp[j] + 1;
            }
        }
        // The finished table is the result.
        return dp;
    }

    /** Oracle: the longest strictly increasing subsequence ending at index i, by subset enumeration. */
    static int oracle(int[] a, int end) {
        int best = 0;
        // Each mask selects the earlier elements to keep, and the element at end is always last.
        for (int mask = 0; mask < (1 << end); mask++) {
            int prev = Integer.MIN_VALUE;
            boolean first = true;
            int len = 0;
            boolean ok = true;
            for (int k = 0; k < end && ok; k++) {
                if ((mask >> k & 1) == 0) continue;
                if (!first && a[k] <= prev) ok = false;
                prev = a[k];
                first = false;
                len++;
            }
            if (ok && (first || prev < a[end])) best = Math.max(best, len + 1);
        }
        return best;
    }

    public static void main(String[] args) {
        // The worked examples.
        if (!Arrays.equals(endingAt(new int[] {3, 1, 4, 1, 5, 9, 2, 6}), new int[] {1, 1, 2, 1, 3, 4, 2, 4})) throw new AssertionError("ex1");
        if (!Arrays.equals(endingAt(new int[] {4, 4, 4}), new int[] {1, 1, 1})) throw new AssertionError("ex2");
        // The empty array gives an empty result.
        if (endingAt(new int[0]).length != 0) throw new AssertionError("empty");
        // The input array stays unchanged.
        int[] in = {2, 1, 3};
        endingAt(in);
        if (!Arrays.equals(in, new int[] {2, 1, 3})) throw new AssertionError("mutated");
        // Random arrays against the subset oracle.
        Random rnd = new Random(2803);
        for (int t = 0; t < 2000; t++) {
            int n = rnd.nextInt(11);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(8) - 3;
            int[] got = endingAt(a);
            for (int i = 0; i < n; i++) {
                if (got[i] != oracle(a, i)) throw new AssertionError("random " + t + " index " + i);
            }
        }
    }

import java.util.*;

    /**
     * Returns the length of the longest strictly increasing subsequence.
     * Time: O(n^2). Space: O(n).
     * Invariant: best is the maximum of the finished entries dp[0..i-1].
     */
    static int lis(int[] nums) {
        // One entry per index.
        int[] dp = new int[nums.length];
        // An empty array keeps best at 0.
        int best = 0;
        for (int i = 0; i < nums.length; i++) {
            // The element alone has length 1.
            dp[i] = 1;
            // Compare with every earlier index, which costs O(i).
            for (int j = 0; j < i; j++) {
                // A strictly smaller earlier value can be extended by nums[i].
                if (nums[j] < nums[i] && dp[j] + 1 > dp[i]) dp[i] = dp[j] + 1;
            }
            // The best subsequence may end at any index, so keep the maximum.
            best = Math.max(best, dp[i]);
        }
        return best;

                if (len > 0 && a[k] <= prev) ok = false;
                prev = a[k];
                len++;
            }
            if (ok) best = Math.max(best, len);
        }
        return best;
    }

Example 1. Input nums = [2,2,3,3,1,3], output [2,5].

Example 2. Input nums = [5,4,3], output [1,1].

What This Exercise Changes. The strict count places each value at the lower bound, and the non-decreasing count places it at the first tail larger than the value. Only the comparison in the search differs.

Hint

Which search position, the first tail at least x or the first tail larger than x, lets an equal value extend the list?

Algorithmic Solution (attempt the problem first)

Approach. The method keeps two sorted arrays of tails, one for each rule. For the strict rule, each value x goes to the lower bound, which is the first position whose tail is at least x. An equal tail sits at that position, so the value replaces it and the size does not grow. For the non-decreasing rule, each value goes to the upper bound, which is the first position whose tail is larger than x. An equal tail stays, and the value lands after it, so the size grows.

The invariant is that each array is sorted and tails[L - 1] is the smallest possible last element for length L under its rule. The search is a binary search over the used part of the array. The test compares both lengths with subset enumeration, including arrays with many equal values.

Complexity.

  • Time is O(n log n), because each element costs two binary searches over at most n entries.
  • Space is O(n) for the two tail arrays, and the input array stays unchanged.
import java.util.*;

public final class IsDuplicates {
    /**
     * Returns {strict length, non-decreasing length} of the longest subsequences.
     * Time: O(n log n). Space: O(n).
     * Invariant: each tails array is sorted and holds the smallest last element for every length.
     */
    static int[] lengths(int[] nums) {
        // Two tail arrays, one for each comparison rule.
        int[] strict = new int[nums.length];
        int[] loose = new int[nums.length];
        int sizeStrict = 0;
        int sizeLoose = 0;
        for (int x : nums) {
            // Lower bound: first tail >= x, so an equal tail is replaced.
            int lo = 0;
            int hi = sizeStrict;
            // Each search halves the range, so it costs O(log n).
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (strict[mid] < x) lo = mid + 1;
                else hi = mid;
            }
            strict[lo] = x;
            // Appending at the end is the only way the strict length grows.
            if (lo == sizeStrict) sizeStrict++;
            // Upper bound: first tail > x, so an equal tail stays and the value lands after it.
            lo = 0;
            hi = sizeLoose;
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (loose[mid] <= x) lo = mid + 1;
                else hi = mid;
            }
            loose[lo] = x;
            if (lo == sizeLoose) sizeLoose++;
        }
        return new int[] {sizeStrict, sizeLoose};
    }

    /** Oracle: tries every subset, with a flag for the strict rule. */
    static int oracle(int[] a, boolean strict) {
        int n = a.length;
        int best = 0;
        for (int mask = 0; mask < (1 << n); mask++) {
            int prev = 0;
            int len = 0;
            boolean ok = true;
            for (int k = 0; k < n && ok; k++) {
                if ((mask >> k & 1) == 0) continue;
                if (len > 0 && (strict ? a[k] <= prev : a[k] < prev)) ok = false;
                prev = a[k];
                len++;
            }
            if (ok) best = Math.max(best, len);
        }
        return best;
    }

    public static void main(String[] args) {
        // The worked examples.
        if (!Arrays.equals(lengths(new int[] {2, 2, 3, 3, 1, 3}), new int[] {2, 5})) throw new AssertionError("ex1");
        if (!Arrays.equals(lengths(new int[] {5, 4, 3}), new int[] {1, 1})) throw new AssertionError("ex2");
        // Empty input and all-equal input.
        if (!Arrays.equals(lengths(new int[0]), new int[] {0, 0})) throw new AssertionError("empty");
        if (!Arrays.equals(lengths(new int[] {7, 7, 7}), new int[] {1, 3})) throw new AssertionError("equal");
        // The input array stays unchanged.
        int[] in = {2, 2, 1};
        lengths(in);
        if (!Arrays.equals(in, new int[] {2, 2, 1})) throw new AssertionError("mutated");
        // Random arrays with a small value range, so equal values are common.
        Random rnd = new Random(2805);
        for (int t = 0; t < 3000; t++) {
            int n = rnd.nextInt(13);
            int[] a = new int[n];
            for (int i = 0; i < n; i++) a[i] = rnd.nextInt(5) - 2;
            int[] got = lengths(a);
            if (got[0] != oracle(a, true) || got[1] != oracle(a, false)) throw new AssertionError("random " + t);
        }
    }

import java.util.*;

public final class IsPrefixLengths {
    /**
     * Returns the longest strictly increasing subsequence length for every prefix.
     * Time: O(n log n). Space: O(n).
     * Invariant: after element k, tails[L-1] is the smallest last element for length L in the prefix.
     */
    static int[] prefixLengths(int[] nums) {
        int[] tails = new int[nums.length];
        int[] result = new int[nums.length];
        int size = 0;
        for (int i = 0; i < nums.length; i++) {
            int x = nums[i];
            int lo = 0;
            int hi = size;
            // Binary search for the first tail >= x, which costs O(log n).
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (tails[mid] < x) lo = mid + 1;
                else hi = mid;
            }
            // Replace the tail, or extend when every tail is smaller.
            tails[lo] = x;
            if (lo == size) size++;
            // The size is the answer for this prefix.
            result[i] = size;
        }
        return result;
    }

    /** Oracle: tries every subset of the first k elements. */
    static int oracle(int[] a, int k) {
        int best = 0;
        for (int mask = 0; mask < (1 << k); mask++) {
            int prev = 0;
            int len = 0;
            boolean ok = true;
            for (int p = 0; p < k && ok; p++) {
                if ((mask >> p & 1) == 0) continue;
                if (len > 0 && a[p] <= prev) ok = false;
                prev = a[p];
                len++;
            }
            if (ok) best = Math.max(best, len);
        }
        return best;
    }

        // The empty array gives an empty result.
        if (prefixLengths(new int[0]).length != 0) throw new AssertionError("empty");
        // The input array stays unchanged.
        int[] in = {2, 1, 3};
        prefixLengths(in);
        if (!Arrays.equals(in, new int[] {2, 1, 3})) throw new AssertionError("mutated");
        // A large sorted input finishes quickly and ends at length n.
        int[] big = new int[200000];
        for (int i = 0; i < big.length; i++) big[i] = i - 100000;
        if (prefixLengths(big)[big.length - 1] != big.length) throw new AssertionError("large");

            }
        }

Problem

Comparing Two Versions Of A Line

A version-control tool compares an old line of text, bacd, with a new line, acdb. The tool wants the longest run of characters that both lines keep in the same order, because everything else counts as an edit. The characters a, c and d appear in both lines in that order, so the shared length is 3. Only b moved.

A developer writes a quick scan. It reads the old line from left to right and, for each character, jumps to the next copy in the new line. The scan reports 1. It sees b first, jumps to the end of the new line, and has nothing left to read there.

Formally, the input is two strings a and b. A subsequence of a string keeps some of its characters, possibly none, in their original order and may skip characters between them. A common subsequence is a subsequence of both strings. The task is to return the length of the longest one. Neither string changes.

This lesson asks how to find that length when a single wrong early choice ruins a left-to-right scan.

Simple approach

Scanning Left To Right With Early Choices

The quick idea is to take each character of a as soon as the new line can supply it. The scan keeps the position p in b after the last taken character.

static int quickScan(String a, String b) {
    int p = 0;
    int taken = 0;
    for (int i = 0; i < a.length(); i++) {
        int q = b.indexOf(a.charAt(i), p);
        if (q >= 0) {
            taken++;
            p = q + 1;
        }
    }
    return taken;
}

The scan runs in O(a.length() * b.length()) time in the worst case and uses O(1) memory. It is fast, but each decision is final. Taking a character can push p so far right that better characters of a have no room left.

Predict first: Run quickScan on a = "bacd" and b = "acdb". What does it return, and what is the true longest common subsequence length?

It returns 1. The scan takes b at the last position of the new line, so p moves past the end and a, c and d find nothing. The true length is 3, from the characters a, c and d.

Bottleneck

One Early Choice Blocks Later Choices

The failure has a clear cause. Taking a character of a is not independent of the characters after it, because it fixes where the next search in b starts. A single choice made without looking ahead can cost the whole answer.

A correct but slow method lists every subsequence of a and checks whether it is also a subsequence of b. A string of length m has 2^m subsequences, and each check scans b in O(n) time. The total is O(2^m * n). For m = 40 that exceeds 10^13 steps.

The work repeats. Two different choices that stop at the same positions in both strings leave the same remaining problem, and the slow method solves that problem again for each choice. The number of distinct positions is only (m + 1) * (n + 1). If each position is solved once and stored, O(m * n) work suffices. The next section defines what to store and how one answer follows from smaller ones.

Key idea

Answer Each Pair Of Prefixes Once

Compare the two strings from their ends and let the answers for shorter strings decide the answer for longer ones. The table needs one entry for every pair of prefix lengths.

One Entry For Each Prefix Pair

A prefix pair (i, j) is the first i characters of a together with the first j characters of b. Let dp[i][j] be the length of the longest common subsequence of that pair. The final answer is dp[m][n], where m and n are the string lengths.

Equal Last Characters Join The Subsequence

Look at the last characters of the pair, a[i - 1] and b[j - 1]. If they are equal, some longest common subsequence ends with that character, and the rest of it lies inside the shorter pair (i - 1, j - 1). The entry is therefore the diagonal entry dp[i - 1][j - 1] plus 1. Using the equal pair is never worse than skipping it, because skipping can only keep or shrink the remaining room.

Different Last Characters Drop One

If the last characters differ, they cannot both end the same common subsequence. At least one of them is unused. Dropping the last character of a gives the pair (i - 1, j), and dropping the last character of b gives (i, j - 1). The entry is the larger of dp[i - 1][j] and dp[i][j - 1].

Empty Prefixes Fill The Zero Row

A prefix of length 0 is the empty string, which shares only the empty subsequence with any text. Row 0 and column 0 are the zero row and the zero column, and every entry in them is 0. The invariant is that when the loop reaches (i, j), the three entries it reads are already final, because each has a smaller i, a smaller j, or both.

State

The Table And Its Two Indexes

Two strings come in unchanged, and these working values describe the table.

  • dp is an int[m + 1][n + 1]; entry dp[i][j] is the longest common subsequence length of the first i characters of a and the first j characters of b.
  • i counts the characters of a in the prefix, from 1 to m.
  • j counts the characters of b in the prefix, from 1 to n.
  • diag, up and left are dp[i - 1][j - 1], dp[i - 1][j] and dp[i][j - 1], the three entries that entry (i, j) can read.

The characters being compared are a.charAt(i - 1) and b.charAt(j - 1), because a prefix of length i ends at index i - 1. Java fills a new int array with zeros, so row 0 and column 0 need no extra code.

Walkthrough

Two Runs Of The Table

Moving One Letter Out Of Place

The first run uses the lines from the opening, a = "bacd" and b = "acdb". The table has 5 rows and 5 columns, and the cells below list them row by row, so cell 0 to 4 is row 0, cell 5 to 9 is row 1, and so on. The pointer cell marks the entry in progress. The variables diag, up and left are the three entries it may read, and dp is the value written.

Row 1 compares b with each character of the new line. Its entries stay 0 until the last column, where b meets b and writes 1. Row 2 compares a. It finds an equal pair at column 1 and writes the diagonal value 0 plus 1. Rows 3 and 4 extend that chain with c and d, which reaches 3 at cell 23. The last column then compares d with b, which differ, so the entry keeps the larger neighbour and the answer stays 3.

A Match That Builds On An Earlier Match

The second run uses a = "cab" and b = "abc". The best length is 2, and it comes from ab in both strings. The row for c finds one equal pair at the last column and writes 1. The row for a finds an equal pair at column 1 and then carries that 1 to the right through differing pairs. The row for b finds an equal pair at column 2, reads the diagonal value 1 from that earlier equal pair, and writes 2. The last column then differs and keeps the larger neighbour, so the answer is 2.

Code

Filling The Table Row By Row

The method returns the length of the longest common subsequence. It fills the table with a row for each prefix length of a.

static int commonLength(String a, String b) {
    int m = a.length();
    int n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (a.charAt(i - 1) == b.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1] + 1;
            } else {
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
    }
    return dp[m][n];
}

Time grows as O(m * n) and the table needs O(m * n) memory. When only the length matters, two rows suffice, which cuts memory to O(n) but removes the ability to rebuild the subsequence itself. If either string is empty, a loop runs zero times and the method returns 0. The exercises below build the table step by step.

When to use it

Recognizing Order-Preserving Matches

Reading The Cue

Use this method when two sequences may skip elements but must keep relative order. Phrases such as "in the same order, not necessarily next to each other" and "shared by both" point here. The state is a pair of prefix lengths, and each entry depends on three neighbours that have smaller indexes.

Checking The Invariant

The invariant says that each entry is final before any entry reads it, and that it describes exactly its own prefix pair. Test two equal strings, which must return their length. Test two strings with no shared character, which must return 0. Test one empty string. Test strings where the equal characters appear in reversed order, such as ab and ba, which must return 1.

Avoiding The False Friend

The first false friend is the quick left-to-right scan, which passes any test where the first available copy is also the best. The second is the longest common substring, which needs the characters to touch and resets an entry to 0 on a difference. The third is a table that sets the entry to the larger neighbour even when the characters are equal, which drops the matched character. The method does not apply when the pieces must be adjacent or when the order may change, because the prefix pair no longer captures the remaining problem.

import java.util.*;

public final class CsShortPrefixes {
    /**
     * Returns the longest common subsequence length of a[0..i) and b[0..j).
     * Time: O(i * j). Space: O(i * j).
     * Invariant: each entry is final before a later entry reads it.
     */
    static int prefixLength(String a, String b, int i, int j) {
        // Java fills the new array with zeros, which sets row 0 and column 0 for empty prefixes.
        int[][] dp = new int[i + 1][j + 1];
        // Row x covers the first x characters of a.
        for (int x = 1; x <= i; x++) {
            // Column y covers the first y characters of b.
            for (int y = 1; y <= j; y++) {
                // Equal last characters extend the best answer of the diagonal entry.
                if (a.charAt(x - 1) == b.charAt(y - 1)) {
                    dp[x][y] = dp[x - 1][y - 1] + 1;
                } else {
                    // Different last characters drop one of them and keep the larger result.
                    dp[x][y] = Math.max(dp[x - 1][y], dp[x][y - 1]);
                }
            }
        }
        // The corner entry describes the requested prefix pair.
        return dp[i][j];
    }

    /** Oracle: tries every subsequence of the prefix of a and checks it against the prefix of b. */
    static int oracle(String a, String b, int i, int j) {
        int best = 0;
        for (int mask = 0; mask < (1 << i); mask++) {
            StringBuilder s = new StringBuilder();
            for (int k = 0; k < i; k++) if ((mask >> k & 1) == 1) s.append(a.charAt(k));
            int p = 0;
            for (int k = 0; k < j && p < s.length(); k++) if (b.charAt(k) == s.charAt(p)) p++;
            if (p == s.length()) best = Math.max(best, s.length());
        }
        return best;
    }

import java.util.*;

public final class CsLongestCommonSubsequence {
    /**
     * Returns the length of the longest common subsequence of two strings.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: entry (i, j) is final once its row pass reaches column j.
     */
    static int lcs(String text1, String text2) {
        // m and n are the string lengths, so the table has (m + 1) * (n + 1) entries.
        int m = text1.length();
        int n = text2.length();
        int[][] dp = new int[m + 1][n + 1];
        // Rows run over the prefix lengths of text1, which costs m passes.
        for (int i = 1; i <= m; i++) {
            // Columns run over the prefix lengths of text2, which costs n steps per row.
            for (int j = 1; j <= n; j++) {
                // Equal last characters join the diagonal subsequence.
                if (text1.charAt(i - 1) == text2.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    // Otherwise one last character is unused, so the better neighbour wins.
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        // The corner entry covers both full strings.
        return dp[m][n];
    }

    /** Oracle: tries every subsequence of a and tests it as a subsequence of b. */
    static int oracle(String a, String b) {
        int best = 0;
        for (int mask = 0; mask < (1 << a.length()); mask++) {
            StringBuilder s = new StringBuilder();
            for (int k = 0; k < a.length(); k++) if ((mask >> k & 1) == 1) s.append(a.charAt(k));
            int p = 0;
            for (int k = 0; k < b.length() && p < s.length(); k++) if (b.charAt(k) == s.charAt(p)) p++;
            if (p == s.length()) best = Math.max(best, s.length());
        }
        return best;
    }

Example 2. Input a = "ab", b = "ba", output 6.

What This Exercise Changes. The method counts zeros in the whole table, including row 0 and column 0. With an empty string, every entry is one of those.

Hint

Which entries are 0 before any character is compared, and does the loop need to visit them?

Algorithmic Solution (attempt the problem first)

Approach. The table has a.length() + 1 rows and b.length() + 1 columns. Row 0 and column 0 describe an empty prefix, so each of those entries is 0 and the method counts them without any comparison. The loops then fill the remaining entries with the usual rule, and the method counts each entry that equals 0.

The invariant is that every entry is final before it is counted. With an empty string, the inner loops never run, so every entry is a zero-row or zero-column entry, and the count is the full table size. Counting only the interior would miss these entries.

Complexity.

  • Time is O(m * n) for lengths m and n, because the table has (m + 1) * (n + 1) entries and each costs constant work.
  • Space is O(m * n) for the table, and the strings stay unchanged.
import java.util.*;

public final class CsEmptyPrefix {
    /**
     * Counts prefix pairs whose longest common subsequence has length 0.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: every entry is final before the count reads it.
     */
    static int zeroPairs(String a, String b) {
        int m = a.length();
        int n = b.length();
        // The new table holds zeros, which is the correct value for row 0 and column 0.
        int[][] dp = new int[m + 1][n + 1];
        // Rows from 1 skip the zero row.
        for (int i = 1; i <= m; i++) {
            // Columns from 1 skip the zero column.
            for (int j = 1; j <= n; j++) {
                // Equal last characters extend the diagonal entry, others keep the better neighbour.
                dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                        ? dp[i - 1][j - 1] + 1
                        : Math.max(dp[i - 1][j], dp[i][j - 1]);
            }
        }
        int zeros = 0;
        // The count visits every entry, including row 0 and column 0.
        for (int i = 0; i <= m; i++) {
            for (int j = 0; j <= n; j++) {
                // An entry equal to 0 is a prefix pair with no shared character.
                if (dp[i][j] == 0) zeros++;
            }
        }
        // The total is returned as an int.
        return zeros;
    }

    /** Oracle: for each prefix pair, tries every subsequence of the a prefix and checks the b prefix. */
    static int oracle(String a, String b) {
        int zeros = 0;
        for (int i = 0; i <= a.length(); i++) {
            for (int j = 0; j <= b.length(); j++) {
                boolean shared = false;
                // A common subsequence of length 1 exists exactly when some character appears in both prefixes.
                for (int x = 0; x < i && !shared; x++) {
                    for (int y = 0; y < j; y++) if (a.charAt(x) == b.charAt(y)) shared = true;
                }
                if (!shared) zeros++;
            }
        }
        return zeros;
    }

        // The two examples of the exercise.
        if (zeroPairs("", "abc") != 4) throw new AssertionError("ex1");
        if (zeroPairs("ab", "ba") != 6) throw new AssertionError("ex2");
        // Both strings empty give one pair, and disjoint strings give every pair.
        if (zeroPairs("", "") != 1) throw new AssertionError("both empty");
        if (zeroPairs("ab", "cd") != 9) throw new AssertionError("disjoint");
        // Equal single characters leave only the zero row and column.
        if (zeroPairs("a", "a") != 3) throw new AssertionError("single");
        // Random inputs against the direct oracle.
        Random rnd = new Random(2824);
        for (int t = 0; t < 2000; t++) {
            String a = word(rnd, rnd.nextInt(8));
            String b = word(rnd, rnd.nextInt(8));
            if (zeroPairs(a, b) != oracle(a, b)) throw new AssertionError("random " + t);
        }
    }

        for (int k = 0; k < len; k++) s.append((char) ('a' + rnd.nextInt(4)));
        return s.toString();

Example 2. Input word1 = "kitten", word2 = "sitting", output 5.

What This Exercise Changes. The answer counts the removed characters, so the method returns the two lengths added together minus twice the common subsequence length.

Hint

The characters that survive form a common subsequence of both strings. How long can that survivor string be?

Algorithmic Solution (attempt the problem first)

Approach. After the deletions, both strings equal one shared string s. That string is a subsequence of each input, because deletions keep the order of the remaining characters. A longer s means fewer deletions, so the best s is a longest common subsequence. The deletions then remove word1.length() - L characters from the first string and word2.length() - L from the second, where L is the common subsequence length.

The method computes L with the prefix-pair table and returns the two lengths added together minus 2 * L. The invariant of the table is that each entry is final before a later entry reads it. The oracle in the test tries every pair of kept character sets and does not use this formula.

Complexity.

  • Time is O(m * n), because the table dominates and the final formula costs constant work.
  • Space is O(m * n) for the table, and the strings stay unchanged.
import java.util.*;

public final class CsDeleteOperation {
    /**
     * Returns the fewest single-character deletions that make two strings equal.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: each table entry is final before a later entry reads it.
     */
    static int minDeletions(String word1, String word2) {
        int m = word1.length();
        int n = word2.length();
        // Zeros in row 0 and column 0 stand for empty prefixes.
        int[][] dp = new int[m + 1][n + 1];
        // Rows cover prefixes of word1.
        for (int i = 1; i <= m; i++) {
            // Columns cover prefixes of word2.
            for (int j = 1; j <= n; j++) {
                // Equal last characters extend the diagonal entry, others keep the better neighbour.
                if (word1.charAt(i - 1) == word2.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1] + 1;
                } else {
                    dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        // Everything outside the common subsequence is deleted from one side or the other.
        return m + n - 2 * dp[m][n];
    }

    /** Oracle: tries every pair of kept character sets and keeps the equal pairs with the most characters. */
    static int oracle(String a, String b) {
        int best = Integer.MAX_VALUE;
        for (int ma = 0; ma < (1 << a.length()); ma++) {
            String sa = pick(a, ma);
            for (int mb = 0; mb < (1 << b.length()); mb++) {
                if (sa.equals(pick(b, mb))) {
                    best = Math.min(best, a.length() - sa.length() + b.length() - sa.length());
                }
            }
        }
        return best;
    }

    static String pick(String s, int mask) {
        StringBuilder r = new StringBuilder();
        for (int k = 0; k < s.length(); k++) if ((mask >> k & 1) == 1) r.append(s.charAt(k));
        return r.toString();
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minDeletions("bacd", "acdb") != 2) throw new AssertionError("ex1");
        if (minDeletions("kitten", "sitting") != 5) throw new AssertionError("ex2");
        // Equal strings need none, disjoint strings delete everything, and empty strings are allowed.
        if (minDeletions("abc", "abc") != 0) throw new AssertionError("equal");
        if (minDeletions("ab", "cd") != 4) throw new AssertionError("disjoint");
        if (minDeletions("x", "") != 1) throw new AssertionError("one empty");
        if (minDeletions("", "") != 0) throw new AssertionError("both empty");
        // Random inputs against the pair-of-subsets oracle.
        Random rnd = new Random(2834);
        for (int t = 0; t < 800; t++) {
            String a = word(rnd, rnd.nextInt(7));
            String b = word(rnd, rnd.nextInt(7));
            if (minDeletions(a, b) != oracle(a, b)) throw new AssertionError("random " + t);
        }
    }

    static String word(Random rnd, int len) {
        StringBuilder s = new StringBuilder();
        for (int k = 0; k < len; k++) s.append((char) ('a' + rnd.nextInt(3)));
        return s.toString();
    }

Problem

A Diff Tool Reporting Extra Changes

A text diff tool compares the old line abc with the new line bc. The tool walks both lines from the left and compares the characters at the same position. Position 0 differs, so it reports a change. Position 1 differs, so it reports a second change. The old line has one extra character, so it reports a third change. The honest answer is a single deletion of the first character.

The same failure appears in a spell checker that ranks suggestions by how many characters differ. A word that lost its first letter looks as different as an unrelated word, because every later character shifts by one position.

Formally, the input is two strings s and t, and either may be empty. One edit is an insertion of one character, a deletion of one character, or a replacement of one character with another. The task is to return the smallest number of edits that turns s into t. The method never changes the strings.

This lesson asks how to count the fewest edits when characters shift position.

Simple approach

Comparing Position By Position

The quick idea is to scan both strings at the same index. A mismatch costs one replacement, and any extra characters at the end cost one deletion or insertion each.

static int samePositionCount(String s, String t) {
    int common = Math.min(s.length(), t.length());
    int edits = Math.abs(s.length() - t.length());
    for (int i = 0; i < common; i++) {
        if (s.charAt(i) != t.charAt(i)) edits++;
    }
    return edits;
}

The method runs in O(min(m, n)) time for strings of length m and n. It gives a correct count only when no insertion or deletion happens before the end. The open question is what the count means when a character is removed near the front.

Predict first: Run samePositionCount on "abc" and "bc". What does it return, and what is the true minimum number of edits?

It returns 3. Positions 0 and 1 mismatch, and the length gap adds one more. The true minimum is 1, because deleting the first character of "abc" produces "bc". Position matching ignores that a deletion shifts every later character.

Bottleneck

Every Edit Shifts The Alignment

An insertion or a deletion moves all later characters by one position. A fixed pairing of index i in s with index i in t is therefore wrong as soon as one such edit occurs. The method must try each choice at the current position and compare the totals.

A correct but slow method does exactly that with recursion. At the front of both strings, it either skips two equal characters or tries the three edits. Each edit shortens s, t or both by one character, so the recursion has depth up to m + n and branches three ways. The work is O(3^(m + n)). For two strings of length 15 that is already above 10^14 calls.

Most of those calls repeat. The recursion asks again and again for the cost of the same pair of remaining suffixes, and there are only (m + 1) * (n + 1) distinct pairs. Storing each answer once reduces the work to O(m * n) time and memory. The next section defines the stored answer and proves that three neighbors suffice.

Key idea

Each Cell Reads Three Neighbors

Define the answer for every pair of prefixes and fill the pairs from short to long. The final pair is the whole task.

One Cell For Each Prefix Pair

A prefix pair is the first i characters of s together with the first j characters of t. Let dp[i][j] be the smallest number of edits that turns the first i characters of s into the first j characters of t. The table has m + 1 rows and n + 1 columns, and the answer is dp[m][n].

Compare The Last Characters

Look at the last characters of the two prefixes, which are s[i - 1] and t[j - 1]. If they are equal, an optimal script can leave them paired, so dp[i][j] equals dp[i - 1][j - 1], the diagonal neighbor. If they differ, the script must handle the last character of s in one of three ways. A replacement pairs the two characters and costs dp[i - 1][j - 1] + 1. A deletion removes s[i - 1] and costs dp[i - 1][j] + 1. An insertion appends t[j - 1] after the prefix of s and costs dp[i][j - 1] + 1. The cell holds the smallest of the three.

Edges Hold Plain Lengths

When j is 0, the target prefix is empty, so every character of the source prefix needs a deletion, and dp[i][0] equals i. When i is 0, every character of the target prefix needs an insertion, and dp[0][j] equals j. The invariant is that every cell is final before any cell that reads it, because each read points up, left or diagonally up-left. A row-by-row fill from the top row satisfies that order.

State

The Table And The Three Reads

The method leaves both strings alone and keeps these working values.

  • dp is an int[m + 1][n + 1]; entry dp[i][j] is the edit distance between the first i characters of s and the first j characters of t.
  • i is the row, which counts the characters taken from s.
  • j is the column, which counts the characters taken from t.
  • diag is dp[i - 1][j - 1], which the method reads for a match or a replacement.
  • up is dp[i - 1][j], which the method reads for a deletion.
  • left is dp[i][j - 1], which the method reads for an insertion.

Row 0 and column 0 are filled before the loops, so the loops start at 1 and no read goes outside the table. In the trace, the cell index is i * (n + 1) + j, which numbers the table row by row.

Code

Filling The Table Row By Row

The method returns the edit distance. It fills the edges first and then each interior cell from its three neighbors.

static int editDistance(String s, String t) {
    int m = s.length(), n = t.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;
    for (int j = 0; j <= n; j++) dp[0][j] = j;
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (s.charAt(i - 1) == t.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1];
            } else {
                dp[i][j] = 1 + Math.min(dp[i - 1][j - 1],
                        Math.min(dp[i - 1][j], dp[i][j - 1]));
            }
        }
    }
    return dp[m][n];
}

The cost is O(m * n) time and O(m * n) memory. Two empty strings give a 1 by 1 table with answer 0. Row i reads only row i - 1 and itself, so two arrays of length n + 1 are enough when no script is needed. The exercises below build the table in four forms.

When to use it

Recognizing Strings That Become Each Other

Reading The Cue

Use this method when one sequence must become another by local changes and the goal is the fewest changes or the cheapest total cost. Words such as "minimum number of operations to convert" and "insert, delete or replace a character" point here. Each prefix pair has one answer, and each answer depends on three smaller prefix pairs.

Checking The Invariant

The invariant says that dp[i][j] is the exact distance between two fixed prefixes, and each operation moves to the matching smaller pair. Check it with an empty string on each side, which must return the other length. Check two equal strings, which must return 0. Check strings of different lengths with no shared letter, which must return the longer length.

Avoiding The False Friend

The first false friend is position-by-position comparison, which breaks after one deletion. The second is the longest common subsequence length, which ignores replacement and counts a replacement as one deletion and one insertion. The third is a greedy rule that matches the first equal letters, which fails when an early match blocks a cheaper alignment.

The method does not apply when edit costs depend on the position or on a moved block of text. Moving a whole block is not one edit here, and the table cannot price it.

Approach. The table cell dp[i][j] holds the fewest insertions and deletions that turn the first i characters of s into the first j characters of t. Column 0 holds i deletions and row 0 holds j insertions. When the last characters are equal, the cell copies its diagonal neighbor. When they differ, no replacement exists, so the cell adds one to the smaller of the cell above, which stands for a deletion, and the cell on the left, which stands for an insertion.

import java.util.*;

public final class EdInsertDeleteOnly {
    /**
     * Returns the fewest insertions and deletions that turn s into t.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: dp[i][j] is exact for the prefixes of lengths i and j, and every read points to a finished cell.
     */
    static int insertDelete(String s, String t) {
        int m = s.length(), n = t.length();
        // One extra row and column hold the empty prefixes.
        int[][] dp = new int[m + 1][n + 1];
        // Turning i characters into nothing takes i deletions.
        for (int i = 0; i <= m; i++) dp[i][0] = i;
        // Building j characters from nothing takes j insertions.
        for (int j = 0; j <= n; j++) dp[0][j] = j;
        // Rows run from top to bottom, so the row above is final.
        for (int i = 1; i <= m; i++) {
            // Columns run left to right, so the left cell is final.
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    // Equal last characters stay paired at no cost.
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // Without replacement, only a deletion or an insertion remains.
                    dp[i][j] = 1 + Math.min(dp[i - 1][j], dp[i][j - 1]);
                }
            }
        }
        // The corner covers both whole strings.
        return dp[m][n];
    }

    /** Oracle: m + n minus twice the longest common subsequence, found by plain recursion. */
    static int oracle(String s, String t) {
        return s.length() + t.length() - 2 * lcs(s, t);
    }

    static int lcs(String a, String b) {
        if (a.isEmpty() || b.isEmpty()) return 0;
        if (a.charAt(0) == b.charAt(0)) return 1 + lcs(a.substring(1), b.substring(1));
        return Math.max(lcs(a.substring(1), b), lcs(a, b.substring(1)));
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (insertDelete("sea", "eat") != 2) throw new AssertionError("ex1");
        if (insertDelete("abc", "xyz") != 6) throw new AssertionError("ex2");
        // Empty strings give the other length, and two empty strings give 0.
        if (insertDelete("", "") != 0) throw new AssertionError("both empty");
        if (insertDelete("abc", "") != 3 || insertDelete("", "ab") != 2) throw new AssertionError("one empty");
        // Replacement is not allowed, so one changed letter costs 2.
        if (insertDelete("cat", "cut") != 2) throw new AssertionError("no replace");
        // Random strings against the oracle.
        Random rnd = new Random(2805);
        for (int tr = 0; tr < 2000; tr++) {
            StringBuilder a = new StringBuilder(), b = new StringBuilder();
            for (int i = rnd.nextInt(8); i > 0; i--) a.append((char) ('a' + rnd.nextInt(3)));
            for (int i = rnd.nextInt(8); i > 0; i--) b.append((char) ('a' + rnd.nextInt(3)));
            if (insertDelete(a.toString(), b.toString()) != oracle(a.toString(), b.toString())) throw new AssertionError("random " + tr);
        }
    }

import java.util.*;

public final class EdEditDistance {
    /**
     * Returns the edit distance with insert, delete and replace.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: dp[i][j] is the exact distance between the prefixes of lengths i and j.
     */
    static int editDistance(String s, String t) {
        int m = s.length(), n = t.length();
        // The extra row and column describe the empty prefixes.
        int[][] dp = new int[m + 1][n + 1];
        // A source prefix of length i needs i deletions to become empty.
        for (int i = 0; i <= m; i++) dp[i][0] = i;
        // An empty source needs j insertions to reach a target prefix of length j.
        for (int j = 0; j <= n; j++) dp[0][j] = j;
        // Rows increase, so the row above is final when it is read.
        for (int i = 1; i <= m; i++) {
            // Columns increase, so the left cell is final when it is read.
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    // A match keeps the diagonal value without an extra edit.
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    // Replace reads the diagonal, delete reads above, insert reads left.
                    dp[i][j] = 1 + Math.min(dp[i - 1][j - 1], Math.min(dp[i - 1][j], dp[i][j - 1]));
                }
            }
        }
        // The corner cell is the distance between the whole strings.
        return dp[m][n];
    }

    /**
     * Returns the same distance with two rows of length n + 1.
     * Time: O(m * n). Space: O(n).
     * Invariant: prev holds row i - 1 and cur holds row i up to column j.
     */
    static int rolling(String s, String t) {
        int m = s.length(), n = t.length();
        // prev starts as row 0, which holds the insertion counts.
        int[] prev = new int[n + 1];
        int[] cur = new int[n + 1];
        for (int j = 0; j <= n; j++) prev[j] = j;
        // Each source character produces one new row.
        for (int i = 1; i <= m; i++) {
            // Column 0 of row i is i deletions.
            cur[0] = i;
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    // The diagonal value sits at prev[j - 1].
                    cur[j] = prev[j - 1];
                } else {
                    // Above is prev[j], left is cur[j - 1], diagonal is prev[j - 1].
                    cur[j] = 1 + Math.min(prev[j - 1], Math.min(prev[j], cur[j - 1]));
                }
            }
            // Swap the arrays so the finished row becomes the previous row.
            int[] tmp = prev;
            prev = cur;
            cur = tmp;
        }
        // After the last swap, prev holds row m.
        return prev[n];
    }

    /** Oracle: plain recursion over the first characters of both strings. */
    static int oracle(String a, String b) {
        if (a.isEmpty()) return b.length();
        if (b.isEmpty()) return a.length();
        if (a.charAt(0) == b.charAt(0)) return oracle(a.substring(1), b.substring(1));
        return 1 + Math.min(oracle(a.substring(1), b.substring(1)),
                Math.min(oracle(a.substring(1), b), oracle(a, b.substring(1))));
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (editDistance("kitten", "sitting") != 3) throw new AssertionError("ex1");
        if (editDistance("monday", "mundane") != 3) throw new AssertionError("ex2");
        // Deleting the first character fixes the case that position matching gets wrong.
        if (editDistance("abc", "bc") != 1) throw new AssertionError("shift");
        // Equal strings cost 0, and two empty strings cost 0.
        if (editDistance("same", "same") != 0 || editDistance("", "") != 0) throw new AssertionError("zero");
        // Random strings against the oracle, and the rolling version against the table.
        Random rnd = new Random(2806);
        for (int tr = 0; tr < 2000; tr++) {
            StringBuilder a = new StringBuilder(), b = new StringBuilder();
            for (int i = rnd.nextInt(8); i > 0; i--) a.append((char) ('a' + rnd.nextInt(3)));
            for (int i = rnd.nextInt(8); i > 0; i--) b.append((char) ('a' + rnd.nextInt(3)));
            int expected = oracle(a.toString(), b.toString());
            if (editDistance(a.toString(), b.toString()) != expected) throw new AssertionError("table " + tr);
            if (rolling(a.toString(), b.toString()) != expected) throw new AssertionError("rolling " + tr);
        }
    }

Empty String

Author exercise

Problem Specification. Given strings s and t, either of which may be empty, return the smallest number of insertions, deletions and replacements that turns s into t.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length(), t.length() <= 300.
  • Alphabet is lowercase English letters.
  • Empty input is legal for either string or both.
  • Result is an int.

Example 1. Input s = "", t = "abc", output 3.

Example 2. Input s = "abcd", t = "", output 4.

Prerequisites. The two exercises above.

What This Exercise Changes. The first row and first column come from lengths and not from the three reads. When one string is empty, the loops never run and the table edge is the answer.

Hint

What does dp[i][0] mean when the target prefix has no characters?

Algorithmic Solution (attempt the problem first)

Approach. The edges of the table carry the whole answer when one string is empty. Cell dp[i][0] is i, because the only way to turn i characters into nothing is i deletions. Cell dp[0][j] is j, because the only way to build j characters from nothing is j insertions. The loops over interior cells never run when m or n is 0, so the corner is an edge cell, and the method returns the other length. Two empty strings give a 1 by 1 table with the value 0.

Setting the edges before the loops is what keeps the interior reads inside the table, since cell (1, 1) reads row 0 and column 0.

Complexity.

  • Time is O(m * n) for the interior and O(m + n) for the edges, which is O(max(m, n)) when a string is empty.
  • Space is O(m * n) for the table, which shrinks to O(max(m, n)) with an empty string.
import java.util.*;

public final class EdEmptyString {
    /**
     * Returns the edit distance, where either string may be empty.
     * Time: O(m * n + m + n). Space: O((m + 1) * (n + 1)).
     * Invariant: column 0 holds row indexes, row 0 holds column indexes, and the interior reads them.
     */
    static int distance(String s, String t) {
        int m = s.length(), n = t.length();
        // The table always has at least one row and one column.
        int[][] dp = new int[m + 1][n + 1];
        // Column 0 costs i deletions; the loop runs m + 1 times.
        for (int i = 0; i <= m; i++) dp[i][0] = i;
        // Row 0 costs j insertions; the loop runs n + 1 times.
        for (int j = 0; j <= n; j++) dp[0][j] = j;
        // The interior loops run zero times when m or n is 0.
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                // The cell either copies a match or adds one edit to the best neighbor.
                int best = Math.min(dp[i - 1][j - 1] + (s.charAt(i - 1) == t.charAt(j - 1) ? 0 : 1),
                        Math.min(dp[i - 1][j] + 1, dp[i][j - 1] + 1));
                dp[i][j] = best;
            }
        }
        // For an empty string, this corner is an edge cell.
        return dp[m][n];
    }

    /** Oracle: plain recursion over the first characters of both strings. */
    static int oracle(String a, String b) {
        if (a.isEmpty()) return b.length();
        if (b.isEmpty()) return a.length();
        if (a.charAt(0) == b.charAt(0)) return oracle(a.substring(1), b.substring(1));
        return 1 + Math.min(oracle(a.substring(1), b.substring(1)),
                Math.min(oracle(a.substring(1), b), oracle(a, b.substring(1))));
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (distance("", "abc") != 3) throw new AssertionError("ex1");
        if (distance("abcd", "") != 4) throw new AssertionError("ex2");
        // Two empty strings return 0 without an out-of-range read.
        if (distance("", "") != 0) throw new AssertionError("both empty");
        // An empty string equals the other length for many lengths.
        for (int k = 0; k <= 20; k++) {
            String x = "z".repeat(k);
            if (distance("", x) != k || distance(x, "") != k) throw new AssertionError("length " + k);
        }
        // Random strings, including empty ones, against the oracle.
        Random rnd = new Random(2807);
        for (int tr = 0; tr < 2000; tr++) {
            StringBuilder a = new StringBuilder(), b = new StringBuilder();
            for (int i = rnd.nextInt(7); i > 0; i--) a.append((char) ('a' + rnd.nextInt(3)));
            for (int i = rnd.nextInt(7); i > 0; i--) b.append((char) ('a' + rnd.nextInt(3)));
            if (distance(a.toString(), b.toString()) != oracle(a.toString(), b.toString())) throw new AssertionError("random " + tr);
        }
    }

Pattern Recognition

Reconstruct Operations

Author exercise

Problem Specification. Given strings s and t, return a script as a String with one letter for each aligned step, read from left to right. The letter M keeps a matching character, R replaces a character, D deletes a character of s, and I inserts a character of t. The script has the fewest letters other than M. When several moves are optimal at the end of a prefix pair, prefer the diagonal move, then D, then I.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length(), t.length() <= 300.
  • Alphabet is lowercase English letters.
  • Result has length at least max(s.length(), t.length()).
  • Mutation is not allowed, because strings are immutable.

Example 1. Input s = "cat", t = "cut", output "MRM".

Example 2. Input s = "ab", t = "b", output "DM".

Prerequisites. All three exercises above.

What This Exercise Changes. The same table is built, and then the method walks from the last cell back to cell (0, 0). Each step emits one letter, and the letters are reversed at the end.

Hint

Starting from dp[m][n], which neighbor cell explains the stored value?

Algorithmic Solution (attempt the problem first)

Approach. The method first builds the same table as the edit distance. The table stores counts only, so the method then walks from cell (m, n) back to (0, 0) and asks which neighbor explains the stored value. If the last characters are equal and the cell equals its diagonal neighbor, the step is M. Otherwise, if the cell equals the diagonal neighbor plus one, the step is R. Otherwise, if the cell equals the cell above plus one, the step is D, and the last remaining case is I. Each step moves to the neighbor that explains it, and the letters collect in reverse order.

The invariant is that the value of the current cell equals the number of non-M letters still to emit. Each step emits one letter and lowers that number by the cost of the letter, so the walk ends at (0, 0) with a script of exactly dp[m][n] edits. The fixed order of checks makes the answer unique.

Complexity.

  • Time is O(m * n) for the table and O(m + n) for the walk, because each step lowers i, j or both.
  • Space is O(m * n) for the table, because the walk needs interior cells, plus O(m + n) for the script.
import java.util.*;

public final class EdReconstructOperations {
    /**
     * Returns an optimal script of M, R, D and I letters read from left to right.
     * Time: O(m * n). Space: O(m * n).
     * Invariant: dp[i][j] equals the number of edit letters still needed for the prefixes of lengths i and j.
     */
    static String script(String s, String t) {
        int m = s.length(), n = t.length();
        // The extra row and column describe the empty prefixes.
        int[][] dp = new int[m + 1][n + 1];
        for (int i = 0; i <= m; i++) dp[i][0] = i;
        for (int j = 0; j <= n; j++) dp[0][j] = j;
        // Each interior cell copies a match or adds one to the best neighbor.
        for (int i = 1; i <= m; i++) {
            for (int j = 1; j <= n; j++) {
                if (s.charAt(i - 1) == t.charAt(j - 1)) {
                    dp[i][j] = dp[i - 1][j - 1];
                } else {
                    dp[i][j] = 1 + Math.min(dp[i - 1][j - 1], Math.min(dp[i - 1][j], dp[i][j - 1]));
                }
            }
        }
        // The walk collects letters from the end, so a builder is reversed later.
        StringBuilder out = new StringBuilder();
        int i = m, j = n;
        // Each pass lowers i, j or both, so the loop runs at most m + n times.
        while (i > 0 || j > 0) {
            if (i > 0 && j > 0 && s.charAt(i - 1) == t.charAt(j - 1) && dp[i][j] == dp[i - 1][j - 1]) {
                // The cell copied its diagonal neighbor, so the pair matches.
                out.append('M');
                i--;
                j--;
            } else if (i > 0 && j > 0 && dp[i][j] == dp[i - 1][j - 1] + 1) {
                // The diagonal neighbor explains the cell with one replacement.
                out.append('R');
                i--;
                j--;
            } else if (i > 0 && dp[i][j] == dp[i - 1][j] + 1) {
                // The cell above explains the cell with one deletion.
                out.append('D');
                i--;
            } else {
                // The last remaining explanation is the cell on the left, an insertion.
                out.append('I');
                j--;
            }
        }
        // The letters were collected from the end, so reverse them.
        return out.reverse().toString();
    }

    /** Oracle: plain recursion for the distance. */
    static int oracle(String a, String b) {
        if (a.isEmpty()) return b.length();
        if (b.isEmpty()) return a.length();
        if (a.charAt(0) == b.charAt(0)) return oracle(a.substring(1), b.substring(1));
        return 1 + Math.min(oracle(a.substring(1), b.substring(1)),
                Math.min(oracle(a.substring(1), b), oracle(a, b.substring(1))));
    }

    /** Applies the script to s and returns the string it produces, or null when a letter is invalid. */
    static String apply(String s, String t, String script) {
        StringBuilder res = new StringBuilder();
        int i = 0, j = 0;
        for (char c : script.toCharArray()) {
            if (c == 'M') {
                // A match needs equal characters at both cursors.
                if (i >= s.length() || j >= t.length() || s.charAt(i) != t.charAt(j)) return null;
                res.append(s.charAt(i));
                i++;
                j++;
            } else if (c == 'R') {
                if (i >= s.length() || j >= t.length()) return null;
                res.append(t.charAt(j));
                i++;
                j++;
            } else if (c == 'D') {
                if (i >= s.length()) return null;
                i++;
            } else {
                if (j >= t.length()) return null;
                res.append(t.charAt(j));
                j++;
            }
        }
        // Both strings must be fully consumed.
        return i == s.length() && j == t.length() ? res.toString() : null;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!script("cat", "cut").equals("MRM")) throw new AssertionError("ex1");
        if (!script("ab", "b").equals("DM")) throw new AssertionError("ex2");
        // Empty inputs give only insertions or only deletions.
        if (!script("", "").equals("") || !script("", "ab").equals("II") || !script("ab", "").equals("DD")) throw new AssertionError("empty");
        // Random strings: the script is valid, optimal, and at least as long as the longer input.
        Random rnd = new Random(2808);
        for (int tr = 0; tr < 2000; tr++) {
            StringBuilder a = new StringBuilder(), b = new StringBuilder();
            for (int i = rnd.nextInt(8); i > 0; i--) a.append((char) ('a' + rnd.nextInt(3)));
            for (int i = rnd.nextInt(8); i > 0; i--) b.append((char) ('a' + rnd.nextInt(3)));
            String s = a.toString(), t = b.toString();
            String sc = script(s, t);
            if (!t.equals(apply(s, t, sc))) throw new AssertionError("invalid " + tr);
            int edits = 0;
            for (char c : sc.toCharArray()) if (c != 'M') edits++;
            if (edits != oracle(s, t)) throw new AssertionError("not optimal " + tr);
            if (sc.length() < Math.max(s.length(), t.length())) throw new AssertionError("short " + tr);
        }
    }

Problem

Scoring How Symmetric A String Is

A text tool scores how close a string is to reading the same in both directions. Its first version finds the longest palindromic substring, which is a block of adjacent characters that reads the same backward. For bbbab that block is bbb, so the tool reports 3. A reviewer points out that the characters at positions 0, 1, 2 and 4 spell bbbb, which is symmetric and has length 4. The tool undercounts because it requires the kept characters to touch each other.

A subsequence keeps characters in their original order but may skip any of them. A palindromic subsequence is a subsequence that reads the same forward and backward.

Formally, the input is a string s of lowercase letters, possibly empty. The task is to return the length of the longest palindromic subsequence of s. The method does not change s.

This lesson asks how a table can decide which characters to keep and which to skip.

Simple approach

Trying Every Keep Or Skip Choice

The direct idea compares the first and last character and recurses on what remains. If the two characters match, both belong to the answer. If they differ, at least one of them must be skipped, and the code tries both.

static int slow(String s, int left, int right) {
    if (left > right) return 0;
    if (left == right) return 1;
    if (s.charAt(left) == s.charAt(right)) {
        return 2 + slow(s, left + 1, right - 1);
    }
    return Math.max(slow(s, left + 1, right), slow(s, left, right - 1));
}

The answer for the whole string is slow(s, 0, s.length() - 1). The code is correct, because every subsequence either uses the first character, uses the last one, or uses neither. The open question is how many calls it makes.

Predict first: How many calls does slow make for the string "abcd", where no two characters match, counting the first call?

It makes 15 calls. A call on a range of m characters makes two calls on ranges of m - 1 characters, so the count for length m is twice the count for length m - 1, plus one. The counts are 1, 3, 7 and 15 for lengths 1 to 4.

Bottleneck

The Same Ranges Appear Again And Again

When no characters match, each call on m characters makes two calls on m - 1 characters, so a string of n characters causes 2^n - 1 calls. The running time is O(2^n). A string of 40 characters needs more than 10^12 calls, which is far too slow.

The calls are not all different. The call slow(s, 1, 3) appears under both slow(s, 0, 3) and slow(s, 1, 4). Each call is fully described by the pair left and right, and a string of n characters has only n * (n + 1) / 2 such pairs. The same pair is solved over and over, and each solve reads only two smaller pairs.

Storing the answer for each pair once cuts the work to O(n^2) pairs with O(1) work each. The question is in which order to fill the pairs, because a pair can be computed only after the smaller pairs it reads.

Key idea

One Table Entry For Each Range

Treat the range left..right as the state. Every call of the recursion depends on nothing else, so one stored number per range replaces the repeated calls.

What One Entry Stores

A closed interval [left, right] contains the characters at positions left to right, including both ends. Let dp[left][right] be the length of the longest palindromic subsequence inside that closed interval. An interval with one character has dp[left][left] = 1. An empty range contributes 0.

Two Cases For Each Interval

Look at the characters s[left] and s[right]. When they are equal endpoints, some best subsequence uses both. Keeping both adds 2 to the best subsequence strictly inside, so dp[left][right] = dp[left + 1][right - 1] + 2. When left + 1 > right - 1, the inside is empty and its value is 0.

When the endpoints differ, no palindrome can use both of them as its outer pair. At least one endpoint is skipped, so dp[left][right] is the larger of dp[left + 1][right] and dp[left][right - 1]. Skipping an endpoint that a best subsequence does not use loses nothing, which is why trying both skips is enough.

Filling In Order Of Length

Every entry reads only intervals that are strictly shorter. The table is therefore filled by increasing length, from length 1 up to n, and by increasing left inside one length. The invariant is that when an interval of length L is computed, every interval of length less than L is already final. The answer is dp[0][n - 1], or 0 for the empty string.

State

The Table And The Two Ends

The method leaves s alone and keeps these working values.

  • dp is an int[n][n]; entry [left][right] is the longest palindromic subsequence inside that interval, and entries with left > right stay 0.
  • length is the number of characters in the interval that the outer loop fills, from 1 to n.
  • left is the first position of the interval, from 0 to n - length.
  • right is the last position, equal to left + length - 1.
  • inner is dp[left + 1][right - 1], which is 0 when the interval has length 2.

The cell dp[left + 1][right - 1] is read only when the endpoints match. For length 2 that index pair has left + 1 > right - 1, so the code reads it as 0 without touching the array.

Walkthrough

Two Strings Filled By Length

A Run With Many Matching Letters

The first run uses bbbab. The cells are the five characters. The pointers left and right mark the ends of the interval in progress, and the variable length is their span. The variable inner is the value strictly inside, skip is the better of the two skip cases, and dp is the stored entry.

The five intervals of length 1 each store 1. At length 2 the pairs bb match and store 2, while ba and ab differ and store 1. At length 3 the interval bbb has equal endpoints and an inner value of 1, so it stores 3. The final interval 0..4 has endpoints b and b, and the inner interval 1..3 holds 2, so the answer is 2 + 2, which is 4.

A Run With Few Matches

The second run uses abcda, where only the first and last characters match. Every shorter interval has distinct endpoints, so each entry copies the larger neighbor. The interval 0..4 has equal endpoints, and its inner interval 1..3 holds 1, so it stores 3. This is the only place in the run where the table adds 2.

Code

Filling The Table By Length

The method returns the length of the longest palindromic subsequence. It fills intervals from short to long.

static int longestPalindromicSubsequence(String s) {
    int n = s.length();
    int[][] dp = new int[n][n];
    for (int length = 1; length <= n; length++) {
        for (int left = 0; left + length - 1 < n; left++) {
            int right = left + length - 1;
            if (length == 1) {
                dp[left][right] = 1;
            } else if (s.charAt(left) == s.charAt(right)) {
                int inner = length == 2 ? 0 : dp[left + 1][right - 1];
                dp[left][right] = inner + 2;
            } else {
                dp[left][right] = Math.max(dp[left + 1][right], dp[left][right - 1]);
            }
        }
    }
    return n == 0 ? 0 : dp[0][n - 1];
}

The cost is O(n^2) time for the pairs and O(n^2) memory for the table. The empty string never enters the loops, so the final line returns 0 for it. The first exercise below fills only the entries of length 1 and 2.

When to use it

Recognizing Skippable Characters In A Range

Reading The Cue

Use this method when the state is a range of the input, the chosen characters keep their order, and some characters may be skipped. Words such as "subsequence", "delete characters" and "insert characters to make symmetric" point here. The table indexes two ends, and each entry depends on shorter ranges.

Checking The Invariant

The invariant says that every shorter interval is final before a longer one is read. Test a string of length 1, a string of length 2 with equal characters, and a string of length 2 with different characters, because those cases exercise the rule for empty inner ranges. Test a string of one repeated letter, where the answer equals the length.

Avoiding The False Friend

The first false friend is the longest palindromic substring, which requires adjacent characters and returns 3 for bbbab. The second is a loop over left from small to large with right from left to n - 1, which reads dp[left + 1][right] before it exists. The third is a greedy rule that drops a mismatched endpoint without trying the other one. Do not use this table when the input needs more than a few thousand characters, since O(n^2) memory then dominates.

Length One And Two

Author exercise

Problem Specification. Given a string s of length n, return an int[n][n] table. Entry [left][right] holds the length of the longest palindromic subsequence inside the interval from left to right when right - left + 1 is 1 or 2. Every other entry is 0.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 1000.
  • Characters are lowercase English letters.
  • Result is a new array, and an empty string returns an empty array.
  • Mutation is not allowed, because s is immutable.

Example 1. Input s = "aab", output [[1,2,0],[0,1,1],[0,0,1]].

Example 2. Input s = "z", output [[1]].

Prerequisites. The interval definition and the two cases from this lesson.

What This Exercise Changes. The method stops after length 2 and never reads an inner interval. These entries are the base cases that every longer interval relies on.

Hint

An interval of two characters stores 2 when its characters match. What does it store when they differ, and which two single-character entries explain that value?

Algorithmic Solution (attempt the problem first)

Approach. The table has n rows and n columns, and entry [left][right] describes the interval from left to right. An interval with one character is a palindrome by itself, so its entry is 1. An interval with two characters stores 2 when the characters match, because both form a palindrome. When they differ, only one of them can stay, so the entry is the larger of the two single-character entries, which is 1.

The method visits only intervals of length 1 and 2 and leaves every other entry at 0. The invariant is that each stored entry equals the true longest palindromic subsequence of its interval. These entries read no inner interval, so they are the base cases that every longer interval relies on.

Complexity.

  • Time is O(n) for the loop over start positions, plus O(n^2) to allocate the zero-filled table.
  • Space is O(n^2) for the returned table, and s stays unchanged.
import java.util.*;

public final class PsLengthOneAndTwo {
    /**
     * Returns a table whose length-1 and length-2 intervals hold their best palindromic subsequence.
     * Time: O(n^2) including allocation. Space: O(n^2).
     * Invariant: every nonzero entry equals the true answer for its interval.
     */
    static int[][] baseCases(String s) {
        int n = s.length();
        // Java allocates the table with every entry 0, which costs n * n.
        int[][] dp = new int[n][n];
        // One pass over the start positions fills both base lengths.
        for (int left = 0; left < n; left++) {
            // A single character is a palindrome of length 1.
            dp[left][left] = 1;
            // A pair exists only when a next character is present.
            if (left + 1 < n) {
                // Matching characters keep both, and different characters keep one.
                dp[left][left + 1] = s.charAt(left) == s.charAt(left + 1) ? 2 : 1;
            }
        }
        // The table is returned with every longer interval still 0.
        return dp;
    }

    /** Oracle: tests every subset of the interval for a palindrome. */
    static int oracle(String s, int left, int right) {
        int len = right - left + 1;
        int best = 0;
        for (int mask = 0; mask < (1 << len); mask++) {
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < len; i++) if ((mask >> i & 1) == 1) sb.append(s.charAt(left + i));
            String t = sb.toString();
            if (t.equals(sb.reverse().toString())) best = Math.max(best, t.length());
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.

Longest Palindromic Subsequence

LeetCode 516

Problem Specification. Given a string s, return the length of its longest palindromic subsequence. A subsequence keeps the original order and may skip any characters.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 1000.
  • Characters are lowercase English letters.
  • Result is an int.
  • Mutation is not allowed, because s is immutable.

Example 1. Input s = "bbbab", output 4.

Example 2. Input s = "cbbd", output 2.

Prerequisites. The exercise above.

What This Exercise Changes. Equal endpoints add 2 to the inner interval, and different endpoints skip one endpoint. The two cases replace the keep-or-skip choice of the capacity tables.

Hint

When the endpoints match, which inner interval gives the rest? When they differ, which two intervals does the larger value come from?

Algorithmic Solution (attempt the problem first)

Approach. Entry dp[left][right] is the longest palindromic subsequence inside the closed interval from left to right. A single character stores 1. When the two endpoints are equal, some best subsequence keeps both, so the entry is the inner entry plus 2, with an empty inner range counted as 0. When the endpoints differ, at least one is skipped, and the entry is the larger of the two entries that drop one endpoint.

Every entry reads only shorter intervals, so the loops run over increasing length and, inside one length, over increasing left. The invariant is that every interval shorter than the current length is final. The answer is the entry for the whole string. The recursion from the lesson makes 15 calls on abcd, and the test counts them.

Complexity.

  • Time is O(n^2), because the table has n * (n + 1) / 2 intervals and each takes at most two reads.
  • Space is O(n^2) for the table, and s stays unchanged.
import java.util.*;

public final class PsLongestPalindromicSubsequence {
    /**
     * Returns the length of the longest palindromic subsequence of s.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: all intervals shorter than the current length are final.
     */
    static int longest(String s) {
        int n = s.length();
        // The table has one entry for each pair of ends, which costs n * n memory.
        int[][] dp = new int[n][n];
        // Length is the outer loop so that shorter intervals finish first.
        for (int length = 1; length <= n; length++) {
            // Left runs over every start whose interval fits in the string.
            for (int left = 0; left + length - 1 < n; left++) {
                // Right is fixed by left and length.
                int right = left + length - 1;
                if (length == 1) {
                    // One character is a palindrome of length 1.
                    dp[left][right] = 1;
                } else if (s.charAt(left) == s.charAt(right)) {
                    // Equal endpoints add 2 to the inner interval, which is empty for length 2.
                    int inner = length == 2 ? 0 : dp[left + 1][right - 1];
                    dp[left][right] = inner + 2;
                } else {
                    // Different endpoints skip one end, and the better skip wins.
                    dp[left][right] = Math.max(dp[left + 1][right], dp[left][right - 1]);
                }
            }
        }
        // The whole string is the interval from 0 to n - 1, and the empty string returns 0.
        return n == 0 ? 0 : dp[0][n - 1];
    }

    static int calls;

    /** The lesson's recursion, with a call counter. */
    static int slow(String s, int left, int right) {
        calls++;
        if (left > right) return 0;
        if (left == right) return 1;
        if (s.charAt(left) == s.charAt(right)) return 2 + slow(s, left + 1, right - 1);
        return Math.max(slow(s, left + 1, right), slow(s, left, right - 1));
    }

    /** Oracle: tests every subset of characters for a palindrome. */
    static int oracle(String s) {
        int n = s.length();
        int best = 0;
        for (int mask = 0; mask < (1 << n); mask++) {
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) if ((mask >> i & 1) == 1) sb.append(s.charAt(i));
            String t = sb.toString();
            if (t.equals(sb.reverse().toString())) best = Math.max(best, t.length());
        }
        return best;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (longest("bbbab") != 4) throw new AssertionError("ex1");
        if (longest("cbbd") != 2) throw new AssertionError("ex2");
        // The longest palindromic substring of bbbab is bbb, shorter than the subsequence bbbb.
        if (longest("bbbab") <= 3) throw new AssertionError("substring false friend");
        // The recursion makes 15 calls on abcd and 2^n - 1 calls for n distinct letters.
        calls = 0;
        slow("abcd", 0, 3);
        if (calls != 15) throw new AssertionError("calls");
        // Small cases: one character, one repeated letter, and the empty string.
        if (longest("q") != 1) throw new AssertionError("one");
        if (longest("aaaa") != 4) throw new AssertionError("repeat");
        if (longest("") != 0) throw new AssertionError("empty");
        // Random strings against the subset oracle and the recursion.
        Random rnd = new Random(2816);
        for (int t = 0; t < 1500; t++) {
            int n = rnd.nextInt(13);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(3)));
            String s = sb.toString();
            if (longest(s) != oracle(s)) throw new AssertionError("random " + t);
            if (n > 0 && longest(s) != slow(s, 0, n - 1)) throw new AssertionError("slow " + t);
        }
    }

Fill By Increasing Length

Author exercise

Problem Specification. A string of length n has intervals (left, right) with 0 <= left <= right < n. List them by increasing length, and by increasing left among equal lengths. Given n, left and right, return the zero-based position of that interval in the list.

Input Constraints. The limits are:

  • Length satisfies 1 <= n <= 1000.
  • Interval satisfies 0 <= left <= right < n.
  • Result is an int, and the first interval has position 0.
  • Mutation is not allowed, because the inputs are plain integers.

Example 1. Input n = 5, left = 1, right = 2, output 6.

Example 2. Input n = 5, left = 0, right = 4, output 14.

Prerequisites. The two exercises above.

What This Exercise Changes. The method counts positions in the fill order. In that order, every interval that an entry reads has a smaller position, so inner intervals are always ready first.

Hint

How many intervals of each shorter length come before the first interval of the target length?

Algorithmic Solution (attempt the problem first)

Approach. In the fill order, every interval of length L comes after all intervals shorter than L. A string of length n has n - len + 1 intervals of length len, so the intervals shorter than the target length L occupy the first sum of n - len + 1 for len from 1 to L - 1 positions. Inside length L, the intervals are ordered by left, so the target sits left positions after that block.

The invariant is that the position of an interval is larger than the position of every interval it reads, because each read is a strictly shorter interval. The test builds the list explicitly and checks both the position formula and that property.

Complexity.

  • Time is O(L), because the loop adds one term for each shorter length.
  • Space is O(1), since the method keeps one running total.
import java.util.*;

public final class PsFillByIncreasingLength {
    /**
     * Returns the position of interval (left, right) in the increasing-length fill order.
     * Time: O(right - left). Space: O(1).
     * Invariant: the count skips exactly the intervals that are shorter than the target.
     */
    static int position(int n, int left, int right) {
        // Length of the target interval.
        int target = right - left + 1;
        int before = 0;
        // Each shorter length contributes all of its n - len + 1 intervals.
        for (int len = 1; len < target; len++) {
            before += n - len + 1;
        }
        // Inside the target length, the intervals are ordered by left.
        return before + left;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (position(5, 1, 2) != 6) throw new AssertionError("ex1");
        if (position(5, 0, 4) != 14) throw new AssertionError("ex2");
        // The first interval has position 0, and the last one has position n(n+1)/2 - 1.
        if (position(1, 0, 0) != 0) throw new AssertionError("single");
        if (position(1000, 0, 999) != 1000 * 1001 / 2 - 1) throw new AssertionError("last");
        // For every n up to 30, the formula matches an explicit list and every read comes earlier.
        for (int n = 1; n <= 30; n++) {
            List<int[]> order = new ArrayList<>();
            for (int len = 1; len <= n; len++) for (int l = 0; l + len - 1 < n; l++) order.add(new int[] {l, l + len - 1});
            for (int i = 0; i < order.size(); i++) {
                int l = order.get(i)[0];
                int r = order.get(i)[1];
                if (position(n, l, r) != i) throw new AssertionError("position " + n + " " + l + " " + r);
                // The three intervals that an entry reads must have smaller positions.
                if (r > l) {
                    if (position(n, l + 1, r) >= i || position(n, l, r - 1) >= i) throw new AssertionError("order");
                    if (r - l >= 2 && position(n, l + 1, r - 1) >= i) throw new AssertionError("inner");
                }
            }
        }
    }

Minimum Insertion Steps To Make A String Palindrome

LeetCode 1312

Problem Specification. Given a string s, an insertion adds one character at any position. Return the smallest number of insertions that turns s into a palindrome.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 500.
  • Characters are lowercase English letters.
  • Result is an int.
  • Mutation is not allowed, because s is immutable.

Example 1. Input s = "zzazz", output 0.

Example 2. Input s = "mbadm", output 2.

Prerequisites. All three exercises above.

What This Exercise Changes. The answer is n minus the longest palindromic subsequence, so the lesson table supplies the number. Each character outside that subsequence needs one inserted partner.

Hint

Characters that stay in place form a subsequence. Which subsequence must be a palindrome, and how many characters remain without a partner?

Algorithmic Solution (attempt the problem first)

Approach. Characters of s that are never moved keep their order, so they form a subsequence that must already be a palindrome in the result. Every other character needs one inserted partner on the opposite side. The cost is therefore n minus the length of the kept palindrome, and keeping the longest one gives the smallest cost.

The method computes that longest palindromic subsequence with the interval table from the lesson, filled by increasing length, and returns n minus its value. The invariant is that each entry is final before a longer interval reads it. The test compares the result with a separate recurrence that counts insertions directly.

Complexity.

  • Time is O(n^2), because the table has n * (n + 1) / 2 intervals with at most two reads each.
  • Space is O(n^2) for the table, and s stays unchanged.
import java.util.*;

public final class PsMinimumInsertionsPalindrome {
    /**
     * Returns the fewest insertions that make s a palindrome.
     * Time: O(n^2). Space: O(n^2).
     * Invariant: dp entries of shorter intervals are final before longer ones are read.
     */
    static int minInsertions(String s) {
        int n = s.length();
        // The table holds the longest palindromic subsequence of each interval.
        int[][] dp = new int[n][n];
        // Increasing length guarantees the inner intervals are ready.
        for (int length = 1; length <= n; length++) {
            for (int left = 0; left + length - 1 < n; left++) {
                int right = left + length - 1;
                if (length == 1) {
                    // A single character needs no partner.
                    dp[left][right] = 1;
                } else if (s.charAt(left) == s.charAt(right)) {
                    // Matching ends extend the inner palindrome by 2.
                    dp[left][right] = (length == 2 ? 0 : dp[left + 1][right - 1]) + 2;
                } else {
                    // Mismatched ends skip the better end.
                    dp[left][right] = Math.max(dp[left + 1][right], dp[left][right - 1]);
                }
            }
        }
        // Every character outside the kept palindrome needs one inserted partner.
        return n - dp[0][n - 1];
    }

    /** Oracle: a direct recurrence on insertions, memoised by interval. */
    static int direct(String s, int left, int right, int[][] memo) {
        if (left >= right) return 0;
        if (memo[left][right] >= 0) return memo[left][right];
        int result;
        if (s.charAt(left) == s.charAt(right)) {
            result = direct(s, left + 1, right - 1, memo);
        } else {
            result = 1 + Math.min(direct(s, left + 1, right, memo), direct(s, left, right - 1, memo));
        }
        memo[left][right] = result;
        return result;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (minInsertions("zzazz") != 0) throw new AssertionError("ex1");
        if (minInsertions("mbadm") != 2) throw new AssertionError("ex2");
        // One character needs no insertion, and two different characters need one.
        if (minInsertions("q") != 0) throw new AssertionError("one");
        if (minInsertions("qr") != 1) throw new AssertionError("two");
        // Random strings against the direct insertion recurrence.
        Random rnd = new Random(2826);
        for (int t = 0; t < 2000; t++) {
            int n = 1 + rnd.nextInt(14);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(4)));
            String s = sb.toString();
            int[][] memo = new int[n][n];
            for (int[] row : memo) Arrays.fill(row, -1);
            if (minInsertions(s) != direct(s, 0, n - 1, memo)) throw new AssertionError("random " + t);
        }
    }

Problem

A Backtest That Breaks The Settlement Rule

A brokerage backtester replays a price list such as 2, 6, 3, 7 and reports the best profit a strategy could have made. The venue enforces a settlement rule: after a sale on one day, the account cannot buy on the next day. The backtester reports 8, and the compliance team confirms that no legal plan on those four days earns more than 5.

The report is not random noise. It reports the largest profit with the rule ignored. Every printed number is too high whenever the rule binds. Traders who trust the report size their positions on profit that no account can collect.

This lesson asks how a table over days can respect rules about what the account holds and when it may act, and how to extend the same table with a trade limit or a fee.

What Each Technique Adds

What Two Earlier Skills Add

What Dynamic Programming Supplies

The foundations chapter gave every table entry a one-sentence meaning and a combine rule. Each entry reads smaller entries that are already final, so the loop order follows the dependencies. A day-indexed table answers how well the first d days can go. The final entry is the answer, and a base entry covers the empty prefix.

What State Modeling Supplies

The shortest-path chapters modeled a search over nodes that carry more than a position. A node holds a position plus a small piece of extra information, and the edges list the moves that the rules allow from that node. The extra information is exactly what separates a legal future from an illegal one. Listing the edges first also exposes every rule before any code exists.

What Both Add Together

A table over days alone gives each day one number. That number cannot say whether the account holds a share or may buy. A graph of situations alone has no order to evaluate. Together they give a table with one entry per day and per situation, where each entry takes the best of the entries that the legal edges lead from. The tables of days stay small, because the situations are few.

Simple approach

Adding Every Daily Rise

The quick idea keeps a single prefix table. Entry best[d] holds the profit for the first d + 1 days, and each day adds its price rise over the previous day when that rise is positive. The routine below does exactly that and ignores the settlement rule.

static int risesOnly(int[] prices) {
    int[] best = new int[prices.length];
    for (int d = 1; d < prices.length; d++) {
        best[d] = best[d - 1] + Math.max(0, prices[d] - prices[d - 1]);
    }
    return prices.length == 0 ? 0 : best[prices.length - 1];
}

The routine runs in O(n) time and uses O(n) memory for n prices. It is a correct answer when the account may trade freely, because it collects every upward step. The open question is what it returns when a sale blocks the next day's purchase.

Predict first: Run risesOnly on the prices [2, 6, 3, 7]. What does it return, and why can the settlement rule keep an account from earning that amount?

It returns 8, from the rise 4 on day 1 and the rise 4 on day 3. Collecting both needs a sale on day 1 and a purchase on day 2, and the rule forbids that purchase. The best legal plan buys on day 0 and sells on day 3 for 5.

Bottleneck

One Number Per Day Hides The Account

The routine is fast, and the defect lies in what one number per day can express. After day 1, a plan that sold the share and a plan that still holds it differ in what they may do on day 2. The prefix entry stores a single profit and drops that difference, so the next day cannot tell which actions are legal.

Patching the routine with special cases does not scale. A cooldown needs to know whether yesterday was a sale. A trade limit needs to know how many purchases happened, and a fee only changes the value of one move. Each rule adds a new fact to remember, and checking all plans one by one costs O(2^n) time for n days, because every day offers several actions.

A reliable method must keep the facts that the rules read, and keep nothing else. The next section states how to name those facts and how to list the actions that each one allows.

Key idea

One Entry For Every Situation

A prefix table answers "what is the best value after the first d days". A state machine table answers "what is the best value after d days, given that the account is in this exact situation". The second question matters because the legal future depends on the situation and not only on the value earned so far.

Name The Situations

A state label is a short name for one situation that the rules distinguish. The stock rules need three labels. free means the account holds no share and may buy. hold means the account holds one share. rest means the account sold a share today, so it cannot buy tomorrow. The second lesson names the no-share state rest and the sold-today state sold; this lesson uses free and rest for those same two situations. A trade limit adds the trade count, the number of purchases made so far, and the table then keeps one entry per pair of count and label.

List The Legal Moves

A legal move is one action from one label that the rules permit. The table below lists every move. The cost of a move is the change in cash. The column "To" shows where the entry for the next day takes its value, so each new entry is the best over all moves that end in it.

A purchase starts only from free, and that restriction enforces the cooldown. The same row sets the trade count and charges the fee exactly once. When the rule has no cooldown, the sell move ends in free instead of rest.

Why A Prefix Table Is Not Enough

A prefix table merges all plans that end on the same day into one number. A state machine table merges only plans that end on the same day in the same situation. Two plans in different situations never merge, because their futures differ. The invariant is that each entry equals the best cash over all legal plans that end the day in exactly its label and count. Day d reads only entries of day d - 1, so the table needs the previous day only.

State

Tables For Each Label And Count

The routine reads the price array and the rule values, and it never changes the array. It keeps these values.

  • prices is an int[] of daily prices, possibly empty.
  • maxTrades is the largest number of purchases allowed, which sets the size of each table to maxTrades + 1.
  • cooldown is a boolean that is true when a sale blocks the next day's purchase.
  • fee is an int charged once at each purchase.
  • free, hold and rest are long[] tables where entry c is the best cash with c purchases made.
  • NEG is a large negative long that marks a situation no legal plan reaches yet.

The method writes the new tables for a day into separate arrays, because a move reads yesterday's entries only. The first day starts with free[0] = 0 and every other entry at NEG.

Code

One Table Per Label And Count

The method builds the new tables from the old ones each day, using the moves of the table above. It switches the sale target by the cooldown flag.

static long bestCash(int[] prices, int maxTrades, boolean cooldown, int fee) {
    final long NEG = Long.MIN_VALUE / 4;
    long[] free = new long[maxTrades + 1], hold = new long[maxTrades + 1], rest = new long[maxTrades + 1];
    java.util.Arrays.fill(free, NEG);
    java.util.Arrays.fill(hold, NEG);
    java.util.Arrays.fill(rest, NEG);
    free[0] = 0;
    for (int price : prices) {
        long[] nFree = new long[maxTrades + 1], nHold = new long[maxTrades + 1], nRest = new long[maxTrades + 1];
        for (int c = 0; c <= maxTrades; c++) {
            nFree[c] = Math.max(free[c], rest[c]);
            if (!cooldown) nFree[c] = Math.max(nFree[c], hold[c] + price);
            nHold[c] = Math.max(hold[c], c > 0 ? free[c - 1] - price - fee : NEG);
            nRest[c] = cooldown ? hold[c] + price : NEG;
        }
        free = nFree; hold = nHold; rest = nRest;
    }
    long answer = 0;
    for (int c = 0; c <= maxTrades; c++) answer = Math.max(answer, Math.max(free[c], rest[c]));
    return answer;
}

The method runs in O(n * maxTrades) time and uses O(maxTrades) memory, since only the previous day's tables stay alive. The prices 3, 2, 6, 5, 0, 3 with a cooldown and a large limit return 7. The prices 3, 8, 1, 6, 2, 9 with limit 2 and no cooldown return 13.

When to use it

Choosing The Situations

Reading The Cue

Use this lesson when each step offers several actions and a rule restricts an action based on earlier actions. Phrases such as "cannot act the next day", "at most k times", "pay once per" and "holding at most one" name the facts to remember. Count the distinct facts the rules read, and give each combination its own label.

Checking The Invariant

The invariant says that every entry equals the best value over all legal plans that end the day in its exact label and count. Test it on an empty array, which must return 0. Test falling prices, which must return 0 without a purchase. Compare against a brute force that tries every action sequence on arrays of up to ten days.

Avoiding The False Friend

The false friend is a prefix table that adds the best gains day by day and looks like a state machine without labels. It returns a plausible profit that breaks a rule. A second false friend is updating hold and free in place on one day, which lets a purchase read the same day's sale. A third is charging the fee at both ends of a trade, which doubles the cost.

Best Time To Buy And Sell Stock

Return the array {b, s} of the trade with the largest profit, provided that profit is greater than 0. Among trades with equal profit, the smaller s wins, and then the smaller b. Example 2. Input prices = [7,5,4], output [-1,-1].

Prerequisites. The labels free and hold from this lesson and a running minimum from the prefix lessons.

What This Exercise Changes. The label stores the buy day next to its value. A strict comparison keeps the earliest day, which implements the tie rule.

Hint

The hold label keeps its best entry value and also the day that entry bought on. When does a later equal price replace that day?

Algorithmic Solution (attempt the problem first)

Approach. The free label before day j is the cheapest price seen on days 0..j-1, and the hold label keeps the day of that price next to it. Each day j first tests a sale against that held day and only then considers replacing the held day. The sale test uses a strict comparison, so the first day that reaches the largest profit wins, which is the smallest sale day. The held-day replacement uses a strict comparison too, so the earliest day among equal minimum prices stays, which is the smallest buy day.

The invariant is that at the start of day j, the held day is the earliest day with the minimum price among earlier days, and the best trade so far is the first one with the largest positive profit. A profit of 0 never replaces the sentinel {-1,-1}.

Complexity.

  • Time is O(n) for n prices, because each day makes one comparison against the held day.
  • Space is O(1), since the method keeps three integers and the result pair.
import java.util.*;

public final class SmBestTradeDays {
    /**
     * Returns {buyDay, sellDay} of the largest positive-profit trade, or {-1,-1}.
     * Time: O(n). Space: O(1).
     * Invariant: heldDay is the earliest minimum-price day before the current day.
     */
    static int[] bestTrade(int[] prices) {
        int heldDay = 0, bestProfit = 0, buy = -1, sell = -1;
        // Day 0 can only buy, so the scan starts at day 1.
        for (int j = 1; j < prices.length; j++) {
            // A strictly larger profit replaces the trade, which keeps the smallest sell day on ties.
            if (prices[j] - prices[heldDay] > bestProfit) {
                bestProfit = prices[j] - prices[heldDay];
                buy = heldDay;
                sell = j;
            }
            // A strictly smaller price replaces the held day, which keeps the earliest day on ties.
            if (prices[j] < prices[heldDay]) heldDay = j;
        }
        return new int[] {buy, sell};
    }

    /** Oracle: tries every pair of days and applies the tie rule directly. */
    static int[] oracle(int[] p) {
        long bestKey = Long.MIN_VALUE;
        int[] res = {-1, -1};
        for (int s = 0; s < p.length; s++) {
            for (int b = 0; b < s; b++) {
                long gain = p[s] - p[b];
                // The key orders by profit, then by smaller sell day, then by smaller buy day.
                long key = gain * 1_000_000L - s * 1000L - b;
                if (gain > 0 && key > bestKey) { bestKey = key; res = new int[] {b, s}; }
            }
        }
        return res;
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(bestTrade(new int[] {6, 2, 8, 2, 8, 1}), new int[] {1, 2})) throw new AssertionError("ex1");
        if (!Arrays.equals(bestTrade(new int[] {7, 5, 4}), new int[] {-1, -1})) throw new AssertionError("ex2");
        // Empty input, a single day and equal prices return the sentinel.
        if (!Arrays.equals(bestTrade(new int[] {}), new int[] {-1, -1})) throw new AssertionError("empty");
        if (!Arrays.equals(bestTrade(new int[] {5}), new int[] {-1, -1})) throw new AssertionError("single");
        if (!Arrays.equals(bestTrade(new int[] {3, 3, 3}), new int[] {-1, -1})) throw new AssertionError("flat");
        // The input array stays unchanged.
        int[] in = {4, 9, 4, 9};
        int[] copy = in.clone();
        bestTrade(in);
        if (!Arrays.equals(in, copy)) throw new AssertionError("mutated");
        // Random inputs against the pair-enumeration oracle.
        Random rnd = new Random(2801);
        for (int t = 0; t < 5000; t++) {
            int[] p = new int[rnd.nextInt(10)];
            for (int i = 0; i < p.length; i++) p[i] = rnd.nextInt(8);
            if (!Arrays.equals(bestTrade(p), oracle(p))) throw new AssertionError("random " + Arrays.toString(p));
        }
    }

Best Time To Buy And Sell Stock With Cooldown

LeetCode 309

Problem Specification. An array prices is given, and any number of trades may be made, holding at most one share. After a sale on day i, the account cannot buy on day i + 1. A plan ends with no share held. The profit is the total of sale prices minus purchase prices. A cooldown day is a day i + 1 < n that follows a sale on day i. Return {profit, cooldownDays} for the plan with the largest profit and, among those, the fewest cooldown days.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 1000, and an empty array returns {0, 0}.
  • Price satisfies 0 <= prices[i] <= 1000.
  • Result is a long[] of length 2.
  • Mutation is not allowed, because the input array stays unchanged.

Example 1. Input prices = [1,4,2,5], output [4,0].

Example 2. Input prices = [2,9,1,9,1,9], output [15,1].

Prerequisites. The exercise above and the table of legal moves from this lesson.

What This Exercise Changes. The rest label gains a penalty of one unit when the sale is not on the last day. The entry now orders plans by profit first and cooldown days second.

Hint

Both goals fit one comparison if the table stores profit times 1000 minus the cooldown days. Which move adds one cooldown day?

Algorithmic Solution (attempt the problem first)

Approach. The three labels free, hold and rest keep one score each. The score is the profit times 1000 minus the cooldown days, so a larger score means a larger profit and, on equal profit, fewer cooldown days. A purchase subtracts the price times 1000 and reads yesterday's free only, which enforces the cooldown. A sale adds the price times 1000 and subtracts 1 when a following day exists. The new rest value comes from yesterday's hold, and the new free value takes the larger of yesterday's free and rest.

The invariant is that each score is the best over all legal plans that end the day in that label. The final score is the larger of free and rest. Decoding takes the profit as the score divided by 1000 rounded up, and the cooldown days are what remains.

Complexity.

  • Time is O(n), because each day updates three scores.
  • Space is O(1), because the new scores are computed from the three old ones.
import java.util.*;

public final class SmCooldownDays {
    /**
     * Returns {profit, cooldownDays} of the best plan under the cooldown rule.
     * Time: O(n). Space: O(1).
     * Invariant: each score is the best packed score of the legal plans ending in its label.
     */
    static long[] cooldownPlan(int[] prices) {
        final long NEG = Long.MIN_VALUE / 4;
        long free = 0, hold = NEG, rest = NEG;
        // Each day builds all three new scores from yesterday's scores.
        for (int d = 0; d < prices.length; d++) {
            long price = prices[d] * 1000L;
            long nFree = Math.max(free, rest);
            // Buying reads yesterday's free score only, so a day after a sale cannot buy.
            long nHold = Math.max(hold, free - price);
            // A sale on a day with a following day costs one cooldown unit.
            long nRest = hold + price - (d < prices.length - 1 ? 1 : 0);
            free = nFree; hold = nHold; rest = nRest;
        }
        long score = Math.max(free, rest);
        // The score is profit * 1000 - cooldownDays, so rounding up recovers the profit.
        long profit = Math.floorDiv(score + 999, 1000);
        return new long[] {profit, profit * 1000 - score};
    }

    static long bestProfit, bestCool;

    /** Oracle: enumerates every action sequence and keeps the best pair. */
    static long[] oracle(int[] p) {
        bestProfit = Long.MIN_VALUE; bestCool = 0;
        walk(p, 0, false, false, 0, 0);
        return new long[] {bestProfit, bestCool};
    }

    static void walk(int[] p, int d, boolean holding, boolean blocked, long profit, long cool) {
        if (d == p.length) {
            // A plan counts only when it holds no share at the end.
            if (!holding && (profit > bestProfit || (profit == bestProfit && cool < bestCool))) { bestProfit = profit; bestCool = cool; }
            return;
        }
        walk(p, d + 1, holding, false, profit, cool);
        if (holding) walk(p, d + 1, false, true, profit + p[d], cool + (d < p.length - 1 ? 1 : 0));
        else if (!blocked) walk(p, d + 1, true, false, profit - p[d], cool);
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(cooldownPlan(new int[] {1, 4, 2, 5}), new long[] {4, 0})) throw new AssertionError("ex1");
        if (!Arrays.equals(cooldownPlan(new int[] {2, 9, 1, 9, 1, 9}), new long[] {15, 1})) throw new AssertionError("ex2");
        // Empty and single-day inputs return zeros.
        if (!Arrays.equals(cooldownPlan(new int[] {}), new long[] {0, 0})) throw new AssertionError("empty");
        if (!Arrays.equals(cooldownPlan(new int[] {5}), new long[] {0, 0})) throw new AssertionError("single");
        // The input array stays unchanged.
        int[] in = {3, 2, 6, 5, 0, 3};
        int[] copy = in.clone();
        cooldownPlan(in);
        if (!Arrays.equals(in, copy)) throw new AssertionError("mutated");
        // Random inputs against the enumeration oracle.
        Random rnd = new Random(2802);
        for (int t = 0; t < 3000; t++) {
            int[] p = new int[rnd.nextInt(10)];
            for (int i = 0; i < p.length; i++) p[i] = rnd.nextInt(9);
            if (!Arrays.equals(cooldownPlan(p), oracle(p))) throw new AssertionError("random " + Arrays.toString(p));
        }
    }

Best Time To Buy And Sell Stock With Transaction Fee

LeetCode 714

Problem Specification. An array prices, an integer fee and an integer minProfit are given. Any number of trades may be made, holding at most one share. Each purchase costs its price plus fee. A plan ends with no share held. Return the largest profit among all plans if it is at least minProfit; otherwise return 0.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 50000, and an empty array returns 0.
  • Price satisfies 0 <= prices[i] <= 50000.
  • Fee satisfies 0 <= fee <= 50000, and fee 0 is allowed.
  • Minimum satisfies 0 <= minProfit <= 1000000, and the result is a long.

Example 1. Input prices = [2,8,4,9], fee = 2, minProfit = 5, output 7.

Example 2. Input prices = [2,8,4,9], fee = 2, minProfit = 9, output 0.

Prerequisites. The two exercises above and the update-order warning from this lesson.

What This Exercise Changes. The fee is charged on the purchase, as in this lesson's move table, and the final answer passes through a threshold test. The update order stays the same as in the lesson.

Hint

Where does the fee enter the move table? Which day's free entry must a purchase read?

Algorithmic Solution (attempt the problem first)

Approach. Two labels suffice, free and hold, both holding the best cash. The purchase move subtracts the price and the fee once, so a trade pays the fee at its start only. The sale move adds the price. Both new values are computed from the old pair, so a purchase on day d never reads a sale of day d. A purchase and a sale on one day would otherwise cost the fee for no gain, and a fee of 0 would hide the error in tests.

The invariant is that free is the best cash with no share and hold is the best cash with one share, over all legal plans of the days so far. The method returns free after the last day when it reaches minProfit, and 0 otherwise.

Complexity.

  • Time is O(n) for n prices, because each day updates two values.
  • Space is O(1), since only the two values are kept.
import java.util.*;

public final class SmFeeMinProfit {
    /**
     * Returns the best profit with the fee charged on each purchase, or 0 below minProfit.
     * Time: O(n). Space: O(1).
     * Invariant: free and hold are the best cash in their label after the processed days.
     */
    static long feePlan(int[] prices, int fee, int minProfit) {
        final long NEG = Long.MIN_VALUE / 4;
        long free = 0, hold = NEG;
        for (int price : prices) {
            // Both new values read the old pair, so the day's sale cannot fund the day's purchase.
            long nHold = Math.max(hold, free - price - fee);
            long nFree = Math.max(free, hold + price);
            hold = nHold; free = nFree;
        }
        // The threshold is tested once, on the final cash with no share.
        return free >= minProfit ? free : 0;
    }

    static long best;

    /** Oracle: enumerates every action sequence. */
    static long oracle(int[] p, int fee, int minProfit) {
        best = 0;
        walk(p, 0, false, 0, fee);
        return best >= minProfit ? best : 0;
    }

    static void walk(int[] p, int d, boolean holding, long cash, int fee) {
        if (d == p.length) { if (!holding) best = Math.max(best, cash); return; }
        walk(p, d + 1, holding, cash, fee);
        if (holding) walk(p, d + 1, false, cash + p[d], fee);
        else walk(p, d + 1, true, cash - p[d] - fee, fee);
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (feePlan(new int[] {2, 8, 4, 9}, 2, 5) != 7) throw new AssertionError("ex1");
        if (feePlan(new int[] {2, 8, 4, 9}, 2, 9) != 0) throw new AssertionError("ex2");
        // Empty input, fee 0 and flat prices.
        if (feePlan(new int[] {}, 1, 0) != 0) throw new AssertionError("empty");
        if (feePlan(new int[] {1, 3}, 0, 0) != 2) throw new AssertionError("fee zero");
        if (feePlan(new int[] {3, 3, 3}, 0, 1) != 0) throw new AssertionError("flat");
        // A threshold of 0 returns the plain best profit.
        if (feePlan(new int[] {5, 1}, 3, 0) != 0) throw new AssertionError("falling");
        // Random inputs against the enumeration oracle.
        Random rnd = new Random(2803);
        for (int t = 0; t < 4000; t++) {
            int[] p = new int[rnd.nextInt(10)];
            for (int i = 0; i < p.length; i++) p[i] = rnd.nextInt(9);
            int fee = rnd.nextInt(5), min = rnd.nextInt(8);
            if (feePlan(p, fee, min) != oracle(p, fee, min)) throw new AssertionError("random " + Arrays.toString(p));
        }
    }

Best Time To Buy And Sell Stock III

LeetCode 123

Problem Specification. An array prices and an integer k are given. A plan makes at most k purchases, holds at most one share, and ends with no share held. Each purchase and its later sale form one trade, and the profit is the total of sale prices minus purchase prices. Return {profit, trades} for the plan with the largest profit and, among those, the fewest trades.

Input Constraints. The limits are:

  • Length satisfies 0 <= prices.length <= 1000, and an empty array returns {0, 0}.
  • Price satisfies 0 <= prices[i] <= 1000.
  • Limit satisfies 0 <= k <= 100, and k = 0 returns {0, 0}.
  • Result is a long[] of length 2.

Example 1. Input prices = [3,8,1,6,2,9], k = 2, output [13,2].

Example 2. Input prices = [1,5,2,6,1,5], k = 3, output [12,3].

Prerequisites. All three exercises above.

What This Exercise Changes. The tables get a second axis for the purchase count, and each entry packs profit and trade count into one comparison. The moves stay those of the lesson.

Hint

Besides the share, which second fact must each entry remember? How many entries does a day need?

Algorithmic Solution (attempt the problem first)

Approach. The table has one free entry and one hold entry for each purchase count c from 0 to k. A purchase moves from free at count c - 1 to hold at count c and adds one trade unit to the penalty. A sale moves from hold to free at the same count. The score packs profit times 1000 minus the number of purchases, so equal profit prefers fewer trades. The new tables are built from the old ones, which keeps a purchase from reading the same day's sale.

The invariant is that each entry is the best packed score over legal plans that end the day in its label and count. The answer is the largest free entry after the last day. The method runs fewer count levels than k when k exceeds the days, because a trade needs two days.

Complexity.

  • Time is O(n * k) for n prices, because each day updates 2(k + 1) entries.
  • Space is O(k) for the two tables, since only yesterday's entries stay alive.
import java.util.*;

public final class SmKTrades {
    /**
     * Returns {profit, trades} for the best plan with at most k purchases.
     * Time: O(n * k). Space: O(k).
     * Invariant: free[c] and hold[c] are the best packed scores with c purchases made.
     */
    static long[] limited(int[] prices, int k) {
        final long NEG = Long.MIN_VALUE / 4;
        // More purchases than half the days cannot be used, which bounds the table.
        int cap = Math.min(k, prices.length / 2);
        long[] free = new long[cap + 1], hold = new long[cap + 1];
        Arrays.fill(free, NEG);
        Arrays.fill(hold, NEG);
        free[0] = 0;
        for (int price : prices) {
            long[] nFree = new long[cap + 1], nHold = new long[cap + 1];
            for (int c = 0; c <= cap; c++) {
                // A sale returns to free at the same count; waiting keeps the old value.
                nFree[c] = Math.max(free[c], hold[c] + price * 1000L);
                // A purchase reads yesterday's free at the previous count and costs one trade unit.
                long buy = c > 0 ? free[c - 1] - price * 1000L - 1 : NEG;
                nHold[c] = Math.max(hold[c], buy);
            }
            free = nFree; hold = nHold;
        }
        long score = NEG;
        // The best final score over all counts, with no share held.
        for (long v : free) score = Math.max(score, v);
        long profit = Math.floorDiv(score + 999, 1000);
        return new long[] {profit, profit * 1000 - score};
    }

    static long bestProfit, bestTrades;

    /** Oracle: enumerates every action sequence. */
    static long[] oracle(int[] p, int k) {
        bestProfit = Long.MIN_VALUE; bestTrades = 0;
        walk(p, k, 0, false, 0, 0);
        return new long[] {bestProfit, bestTrades};
    }

    static void walk(int[] p, int k, int d, boolean holding, int used, long profit) {
        if (d == p.length) {
            if (!holding && (profit > bestProfit || (profit == bestProfit && used < bestTrades))) { bestProfit = profit; bestTrades = used; }
            return;
        }
        walk(p, k, d + 1, holding, used, profit);
        if (holding) walk(p, k, d + 1, false, used, profit + p[d]);
        else if (used < k) walk(p, k, d + 1, true, used + 1, profit - p[d]);
    }

    public static void main(String[] args) {
        // The two examples of the exercise.
        if (!Arrays.equals(limited(new int[] {3, 8, 1, 6, 2, 9}, 2), new long[] {13, 2})) throw new AssertionError("ex1");
        if (!Arrays.equals(limited(new int[] {1, 5, 2, 6, 1, 5}, 3), new long[] {12, 3})) throw new AssertionError("ex2");
        // Limit 0, empty input and falling prices return zeros.
        if (!Arrays.equals(limited(new int[] {1, 5}, 0), new long[] {0, 0})) throw new AssertionError("k zero");
        if (!Arrays.equals(limited(new int[] {}, 5), new long[] {0, 0})) throw new AssertionError("empty");
        if (!Arrays.equals(limited(new int[] {5, 4, 3}, 3), new long[] {0, 0})) throw new AssertionError("falling");
        // Random inputs, including limits above the day count, against the oracle.
        Random rnd = new Random(2804);
        for (int t = 0; t < 3000; t++) {
            int[] p = new int[rnd.nextInt(10)];
            for (int i = 0; i < p.length; i++) p[i] = rnd.nextInt(9);
            int k = rnd.nextInt(7);
            if (!Arrays.equals(limited(p, k), oracle(p, k))) throw new AssertionError("random " + Arrays.toString(p) + " " + k);
        }
    }
