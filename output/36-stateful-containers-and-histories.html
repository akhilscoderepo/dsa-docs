Chapter 36

Stateful Containers And Histories

Orientation

A queue class passes every test that adds three items and removes three items. In production it treats a full queue as empty, because head and tail meet after a wraparound and equal indices cannot separate the two states. Class-shaped problems fail at the seams between calls, not inside one method. This chapter teaches how to keep one stored state valid across any legal sequence of public calls.

Prerequisites

You should know arrays, lists, stacks, queues, deques, hash maps, linked lists, heaps and ordered sets, plus amortized cost. A public call is any method an outside caller may invoke. A logical state is what a caller can observe through those calls. The fields are the stored variables that together represent it.

What Each Lesson Protects

Each lesson names one fact that every public call must leave true.

  • Trace A Sequence Of Method Calls defines legal states and shows that a rejected call must leave every field unchanged.
  • Store Keys In Direct Slots gives each key one slot or bucket, so update and removal keep that ownership.
  • Circular Buffers reuse array positions with head, size and modular arithmetic, so no live slot is counted twice.
  • Split Containers keep two halves within one element of each other, so the boundary marks the middle.
  • Cut Forward History After A Write separates the stored pages from the cursor, so a new write drops the invalid future.
  • Reuse Freed Identifiers From A Pool keeps each identifier in exactly one of the free or allocated states.
  • Containers And API State joins a ring buffer with an index so every call restores both before it returns.
  • Multiple Collections Ownership keeps a heap or ordered set and a membership set in agreement about each resource.

Reading Order

Every lesson starts with a class that passes simple tests and then breaks on a longer call sequence. You predict the failure before the reasoning appears. Two traces follow the fields call by call, then Java code and the limits of the idea. The four exercises climb from a basic build to a variation, an edge case and a recognition problem. A LeetCode problem that appears twice carries a changed contract, and its text says what changed.

What You Can Do After This Chapter

You can write down the fields of a class and the one fact they must satisfy after every call. You can choose between a direct array, a ring buffer, two halves, a cursor over stored history and a pool that tracks the next never-issued id, and you can say what each call does when it must refuse. Problem

Why A Passing Class Still Fails

A web service caps simultaneous exports at three per account. A class named ExportLimiter counts the running exports. Its start() method returns false at the cap. Every unit test passes, because each test creates a fresh object and calls one method. In production the counter drifts. After a burst of five start requests, the two refused calls have each added one to the counter, so it reads 5 while only three exports run. When those three finish, the counter reads 2, the limiter believes two exports still run, and it permits only one new export.

No single method is wrong on a fresh object. The failure appears only in a sequence of calls on one object, because an earlier call changed a field that a later call reads. The lesson asks one question. How does a programmer specify and check a class so that every sequence of calls stays correct?

Simple approach

Testing Each Method On A Fresh Object

The direct method writes one small test per method. Each test creates a new object, calls the method once and compares the result with the expected value. For a counter with a limit, the class below looks natural, and increment counts first and then reports whether the count still fits.

final class NaiveCounter {
    private final int limit;
    private int count;

    NaiveCounter(int limit) { this.limit = limit; }

    boolean increment() {
        count++;                 // counts first
        return count <= limit;   // then reports whether it fit
    }
    void reset() { count = 0; }
    int value() { return count; }
}

With limit 2, the first increment on a fresh object returns true, value on a fresh object returns 0, and reset followed by value returns 0. All three tests pass, so the class looks finished.

Bottleneck

Counting The Call Sequences

Predict first: A counter has limit 2. A caller invokes increment three times and then value. What does the naive class return from value, and which call first leaves the object in a condition that no later call can describe correctly?

The value call returns 3, although the counter should stop at 2. The third increment correctly returns false, yet it also raised count from 2 to 3. The single-call tests never reach that third increment, so they cannot see the problem.

A fresh-object test reaches only the states that the constructor produces. A real caller reaches many more. With m methods and traces of length L, a caller can issue m^L different sequences, ignoring the arguments. A counter with three methods has 59 049 sequences of length 10 and about 3.5 billion of length 20. Checking every sequence costs O(m^L), which no test suite can afford.

The bug also does not live in any method body. The third increment returns the right answer and still damages a field. The damage matters only because later calls read that field. A check must therefore look at the fields left behind by each call, not only at the value that the call returns. The next section names the property to check and shows why a short check per method covers every long sequence.

Key idea

Keep The Object Legal After Each Call

What An Operation Trace Records

An operation trace is a constructor call followed by a chronological list of method calls, each paired with the value it must return. The trace new BoundedCounter(2), increment() = true, increment() = true, increment() = false, value() = 2 specifies the class on one history. A class is correct when it reproduces the expected return value of every call in every trace that its documentation allows.

Legal State And The Invariant

The fields of an object together hold its state. A legal state is an assignment of values to all fields that the class documentation permits. For the bounded counter, a legal state satisfies 0 <= count <= limit. The invariant of this lesson says that each completed call leaves a legal state for every possible next call. Any method may read any field, so one illegal field value can change the result of a call that comes much later.

A Rejected Call Changes Nothing

A rejected call is a call whose precondition fails, such as increment when count already equals limit. It returns the failure value, here false. It must also leave every field with the value it had before the call. The naive class breaks this rule, because it raises count before it decides to refuse. The repair tests the condition first and changes fields only on the accepting path.

Why One Check Per Method Suffices

The constructor must produce a legal state. Every other method must satisfy a second promise: when it starts in any legal state, it returns the right value and ends in a legal state. Then induction on the length of the trace proves that every trace is safe. The first call starts in the constructor's legal state, and each later call starts in the legal state that its predecessor left. The proof needs only m + 1 checks, one for the constructor and one per method, instead of m^L sequences. For a rejected call the check is even simpler, because the final state must equal the initial state.

State

Fields And The Trace Row

The bounded counter keeps two fields, limit and count. A trace table adds two columns, call and result, that the reader tracks after every call.

  • limit is the capacity, fixed by the constructor and never changed afterward.
  • count is the number of accepted increments since the last reset.
  • call is the index of the current entry in the operation trace, where entry 0 is the constructor.
  • result is the value the current call returns, written true, false, an integer, or null for a method that returns nothing.

The invariant is 0 <= count <= limit after the constructor and after every call, whether the call succeeds or fails.

Walkthrough

Tracing Calls On A Counter

A Correct Counter With Limit 2

The first trace follows a correct counter through the constructor and seven calls. The pointer call marks the call that just finished, and the variable count shows the field after that call.

The constructor sets count to 0. The first two increments succeed and raise count to 2. The third increment arrives when count equals limit, so the counter rejects it, returns false and keeps count at 2. The value call then returns 2, which matches the specification. A reset sets count to 0, and the next increment succeeds again. The rejected call is the only entry where the return value says false, and it is also the only increment after which count stays the same. The two facts always appear together in a correct class.

The Naive Counter On The First Calls

The second trace replays the first four calls on the naive class from the earlier stage. The first two increments behave exactly as before. The third increment returns false, so a test that checks only the return value still passes. The field tells a different story, because count now equals 3 while limit equals 2. That assignment violates 0 <= count <= limit, so the object has left every legal state. The following value call returns 3, and the trace expects 2. The error shows up one call after the damage, which is why a check of the return value alone cannot locate it.

Code

Writing The Counter As A Class

The Class

The correct class tests the limit first and changes count only when the call succeeds. The constructor, increment, reset and value each run in constant time. The fields are private, so these four members are the only code that can change count, and checking them covers every trace.

final class BoundedCounter {
    private final int limit;
    private int count;

    BoundedCounter(int limit) {
        this.limit = limit;   // a legal state needs limit >= 0
        this.count = 0;       // 0 <= 0 <= limit holds
    }

    boolean increment() {
        if (count == limit) return false;   // rejected: no field changes
        count++;                            // accepted: count stays <= limit
        return true;
    }

    void reset() { count = 0; }             // 0 is legal for every limit

    int value() { return count; }           // reads only, changes nothing
}

Cost

  • increment costs O(1) time and O(1) space.
  • reset and value cost O(1) time and O(1) space.
When to use it

When To Reason About Call Sequences

Recognizing The Pattern

Use this method when the input is a class name, a constructor with arguments and a chronological list of method calls with their expected outputs. Design problems on contest sites use exactly this shape. Before writing code, list the fields, state the invariant over those fields, and write down for each method which fields change on the accepting path. For every method that can refuse, write down that no field changes on the refusing path. The code then follows from the list.

A False Friend

Correct methods on a fresh object are a false friend of a correct API. A method can return the right value for every fresh object and still leave a field in a state that breaks the next call. The naive counter shows this. The question to ask is not whether the method returns the expected value. The question is whether the object is legal when the method returns.

When The Method Does Not Apply

A class with no fields, such as a set of pure helper functions, has no state to keep legal. A class that several threads call at once breaks the assumption of one chronological order, so this chapter always assumes a single caller. A call that must succeed partly and fail partly needs its documentation to say which fields change, because the rule that a rejected call changes nothing no longer describes it.

Bounded Counter API

Author exercise

Problem Specification. Design the class BoundedCounter with an integer limit fixed by the constructor. It supports three methods. increment() returns true and adds 1 to the count when the count is less than limit, and otherwise returns false. reset() sets the count to 0 and returns nothing. value() returns the current count. The count starts at 0 and never exceeds limit.

Input Constraints. The limits are:

  • Limit is an integer with 0 <= limit <= 10^9.
  • Calls number at most 1000 per object.
  • Rejected increment returns false and changes no field.
  • Mutation happens only inside the three methods.

Example 1. Input calls ["BoundedCounter","increment","increment","increment","value"] with arguments [[2],[],[],[],[]], output [null,true,true,false,2].

Example 2. Input calls ["BoundedCounter","increment","reset","increment","increment","value"] with arguments [[1],[],[],[],[],[]], output [null,true,null,true,false,1].

Prerequisites. The operation trace, legal state and rejected call definitions from this lesson.

What This Exercise Changes. Basic case: the method tests the precondition first and writes the field only on the accepting path.

Hint

Which comparison must run before count changes, and what does reset need to keep the invariant when limit is 0?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps two fields, the fixed limit and the mutable count. The invariant is 0 <= count <= limit. The constructor sets count to 0, which satisfies the invariant for every non-negative limit. The method increment compares count with limit before it writes anything. When they are equal, the method returns false and the state stays identical. Otherwise it adds 1, which keeps count at most limit, and returns true. The method reset writes 0, which is legal for every limit, and value only reads.

Because every method keeps the invariant when it starts from a legal state, induction over the trace length shows that every sequence of calls ends in a legal state. The program below checks the claim from two sides. It compares every return value with a model that stores the accepted increments in a list, and it checks the invariant after every call of every random trace.

Complexity.

  • Time is O(1) per call, because each method performs one comparison and at most one assignment.
  • Space is O(1) per object, because the class stores two ints regardless of the number of calls.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class BoundedCounterBuild {
    /** Counter that refuses increments at the limit and keeps 0 <= count <= limit. */
    static final class BoundedCounter {
        private final int limit;
        private int count;

        /**
         * Creates a counter with the given limit.
         * Time: O(1). Space: O(1).
         * Invariant: the constructor establishes count = 0, a legal state for every limit >= 0.
         */
        BoundedCounter(int limit) {
            // The limit never changes after construction.
            this.limit = limit;
            // The count starts at the smallest legal value.
            this.count = 0;
        }

        /**
         * Adds 1 when the count is below the limit and reports whether it did.
         * Time: O(1). Space: O(1).
         * Invariant: a refused call writes no field, so the state before and after are equal.
         */
        boolean increment() {
            // The precondition test runs before any write, so a refusal changes nothing.
            if (count == limit) return false;
            // Accepted path: count < limit, so count + 1 <= limit still holds.
            count++;
            // The caller learns that the increment happened.
            return true;
        }

        /**
         * Sets the count back to 0.
         * Time: O(1). Space: O(1).
         * Invariant: 0 is legal for every limit, so the state stays legal.
         */
        void reset() {
            // One assignment restores the smallest legal value.
            count = 0;
        }

        /**
         * Returns the current count.
         * Time: O(1). Space: O(1).
         * Invariant: the method only reads, so no field changes.
         */
        int value() {
            // The count is already within 0..limit by the invariant.
            return count;
        }
    }

    /** The naive class from the lesson: it counts first and reports afterward. */
    static final class NaiveCounter {
        private final int limit;
        private int count;
        NaiveCounter(int limit) { this.limit = limit; }
        boolean increment() { count++; return count <= limit; }
        int value() { return count; }
    }

    /** Model that remembers every accepted increment as a list entry. Time per call: O(limit). Space: O(limit). */
    static final class Model {
        private final int limit;
        private final List<Integer> accepted = new ArrayList<>();
        Model(int limit) { this.limit = limit; }
        boolean increment() {
            // A new entry fits only while the list is shorter than the limit.
            if (accepted.size() >= limit) return false;
            accepted.add(accepted.size());
            return true;
        }
        void reset() { accepted.clear(); }
        int value() { return accepted.size(); }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise: the third increment is refused and value stays 2.
        BoundedCounter c = new BoundedCounter(2);
        if (!c.increment() || !c.increment() || c.increment() || c.value() != 2) throw new AssertionError("example 1");
        // Example 2: reset makes room again for a limit of 1.
        BoundedCounter d = new BoundedCounter(1);
        if (!d.increment()) throw new AssertionError("example 2 first");
        d.reset();
        if (!d.increment() || d.increment() || d.value() != 1) throw new AssertionError("example 2");
        // A limit of 0 refuses every increment and keeps value at 0.
        BoundedCounter z = new BoundedCounter(0);
        if (z.increment() || z.value() != 0) throw new AssertionError("limit 0");
        // The naive class returns false on the third increment but its count passes the limit.
        NaiveCounter bad = new NaiveCounter(2);
        bad.increment();
        bad.increment();
        if (bad.increment() || bad.value() != 3) throw new AssertionError("naive drift");
        // Random traces compare every return value with the model and check the invariant after every call.
        Random rnd = new Random(3601L);
        for (int t = 0; t < 4000; t++) {
            int limit = rnd.nextInt(6);
            BoundedCounter real = new BoundedCounter(limit);
            Model model = new Model(limit);
            for (int step = rnd.nextInt(31); step > 0; step--) {
                int op = rnd.nextInt(3);
                if (op == 0 && real.increment() != model.increment()) throw new AssertionError("increment");
                if (op == 1) { real.reset(); model.reset(); }
                if (real.value() != model.value()) throw new AssertionError("value");
                if (real.value() < 0 || real.value() > limit) throw new AssertionError("invariant");
            }
        }
    }
}verified
Variation

Design Parking System

LeetCode 1603

Problem Specification. Design the class ParkingSystem with three car types, numbered 1 for big, 2 for medium and 3 for small. The constructor receives the number of free spaces for each type in that order. addCar(carType) returns true and uses one space of that type when a space is free, and otherwise returns false. A space is never freed.

Input Constraints. The limits are:

  • Spaces satisfy 0 <= big, medium, small <= 1000.
  • Car type is 1, 2 or 3.
  • Calls number at most 1000 per object.
  • Rejected call returns false and changes no field, including the counts of the other two types.

Example 1. Input calls ["ParkingSystem","addCar","addCar","addCar","addCar"] with arguments [[1,1,0],[1],[2],[3],[1]], output [null,true,true,false,false].

Example 2. Input calls ["ParkingSystem","addCar","addCar","addCar","addCar","addCar","addCar"] with arguments [[2,0,1],[3],[3],[2],[1],[1],[1]], output [null,true,false,false,true,true,false].

Prerequisites. The Bounded Counter API exercise above.

What This Exercise Changes. One counter becomes an array of independent counters, and the call argument selects which counter the invariant check applies to.

Hint

The single count of the previous exercise becomes several counts. Which argument selects the count, and may one type's refusal change another type's count?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps one array free with an entry for each car type. Entry t - 1 holds the number of free spaces of type t. The invariant is that each entry stays between 0 and the capacity given for that type. The call addCar(t) looks only at the entry of its own type. When the entry is 0, the call returns false and writes nothing. Otherwise it decreases that one entry and returns true.

The independence of the three types is the new decision compared with the single counter. A refusal for one type must not touch the other two entries, and the oracle checks this by comparing the full list of parked cars per type after each call.

Complexity.

  • Time is O(1) per call, because one array read and at most one array write run.
  • Space is O(1) per object, because the array always has exactly three entries.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class ParkingSystemVary {
    /** Parking lot with an independent number of free spaces for each of three car types. */
    static final class ParkingSystem {
        private final int[] free;

        /**
         * Stores the free spaces of each type in the order big, medium, small.
         * Time: O(1). Space: O(1).
         * Invariant: every entry is between 0 and its starting capacity.
         */
        ParkingSystem(int big, int medium, int small) {
            // Three entries, indexed by carType - 1.
            free = new int[] {big, medium, small};
        }

        /**
         * Parks one car of the given type when a space is free.
         * Time: O(1). Space: O(1).
         * Invariant: a refused call writes nothing; an accepted call lowers exactly one entry.
         */
        boolean addCar(int carType) {
            // Only the entry of this type takes part in the decision.
            if (free[carType - 1] == 0) return false;
            // Accepted: one space of this type is used, so the entry stays at least 0.
            free[carType - 1]--;
            return true;
        }
    }

    /** Oracle that stores every parked car in a list for its type. Time per call: O(1). Space: O(cars). */
    static final class Model {
        private final int[] cap;
        private final List<List<Integer>> parked = new ArrayList<>();
        private int nextId;
        Model(int big, int medium, int small) {
            cap = new int[] {big, medium, small};
            for (int i = 0; i < 3; i++) parked.add(new ArrayList<>());
        }
        boolean addCar(int type) {
            List<Integer> lot = parked.get(type - 1);
            // The lot accepts a car only while it holds fewer cars than its capacity.
            if (lot.size() >= cap[type - 1]) return false;
            lot.add(nextId++);
            return true;
        }
    }

    public static void main(String[] args) {
        // Example 1: the small lot has no space, and the big lot runs out after one car.
        ParkingSystem a = new ParkingSystem(1, 1, 0);
        if (!a.addCar(1) || !a.addCar(2) || a.addCar(3) || a.addCar(1)) throw new AssertionError("example 1");
        // Example 2: a refusal for medium cars does not use or free a space of another type.
        ParkingSystem b = new ParkingSystem(2, 0, 1);
        boolean[] want = {true, false, false, true, true, false};
        int[] types = {3, 3, 2, 1, 1, 1};
        for (int i = 0; i < types.length; i++) if (b.addCar(types[i]) != want[i]) throw new AssertionError("example 2 at " + i);
        // Random traces compare every answer with the oracle, including lots of size 0.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 4000; t++) {
            int big = rnd.nextInt(4), medium = rnd.nextInt(4), small = rnd.nextInt(4);
            ParkingSystem real = new ParkingSystem(big, medium, small);
            Model model = new Model(big, medium, small);
            for (int step = rnd.nextInt(16); step > 0; step--) {
                int type = 1 + rnd.nextInt(3);
                if (real.addCar(type) != model.addCar(type)) throw new AssertionError("mismatch");
            }
        }
    }
}verified
Edge Cases

Rejected Calls

Author exercise

Problem Specification. Design the class Quota with a capacity fixed by the constructor. reserve(n) returns true and adds n to the used amount when the used amount plus n does not exceed the capacity, and otherwise returns false. cancel(n) returns true and subtracts n from the used amount when n does not exceed the used amount, and otherwise returns false. used() returns the used amount. A call that returns false must leave every field exactly as it was.

Input Constraints. The limits are:

  • Capacity is an int with 0 <= capacity <= 2^31 - 1.
  • Amount n is an int with 1 <= n <= 2^31 - 1.
  • All or nothing means a reservation never takes part of n.
  • Overflow must not change an answer, even when the capacity equals 2^31 - 1.

Example 1. Input calls ["Quota","reserve","reserve","cancel","cancel","used"] with arguments [[5],[3],[3],[4],[2],[]], output [null,true,false,false,true,1].

Example 2. Input calls ["Quota","reserve","cancel","used"] with arguments [[0],[1],[1],[]], output [null,false,false,0].

Prerequisites. The Bounded Counter API and Design Parking System exercises above.

What This Exercise Changes. The focus moves from the accepting path to the refusing path: the precondition test must finish before the first field write, and it must not overflow.

Hint

Which comparison avoids computing the sum of two large int values?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps capacity and used, with the invariant 0 <= used <= capacity. Both methods that can refuse decide first and write second. The call reserve(n) accepts when n <= capacity - used. The subtraction form is deliberate. Because used <= capacity holds, the difference is a non-negative int, so no overflow occurs. The form used + n <= capacity would overflow when both values are near 2^31 - 1, and the wrapped negative sum would wrongly accept the call. The call cancel(n) accepts when n <= used, which keeps used at least 0.

The refusing path contains only a return false, so no field is written. The program proves this claim for every random trace. It reads every non-static field through reflection before each call and compares the values after each call that returns false. A field added to the class later is covered by the same comparison without any change to the checks.

Complexity.

  • Time is O(1) per call, because each method runs one comparison and at most one assignment.
  • Space is O(1) per object, because the class stores two ints.
import java.lang.reflect.Field;
import java.lang.reflect.Modifier;
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class RejectedCallsQuota {
    /** Quota that reserves and cancels whole amounts and refuses a call that would break 0 <= used <= capacity. */
    static final class Quota {
        private final int capacity;
        private int used;

        /**
         * Creates an empty quota.
         * Time: O(1). Space: O(1).
         * Invariant: used = 0 is legal for every capacity >= 0.
         */
        Quota(int capacity) {
            // The capacity stays fixed for the life of the object.
            this.capacity = capacity;
            // Nothing is reserved yet.
            this.used = 0;
        }

        /**
         * Reserves n units, all or nothing.
         * Time: O(1). Space: O(1).
         * Invariant: the test uses capacity - used, which cannot overflow because used <= capacity.
         */
        boolean reserve(int n) {
            // Refuse before any write; the subtraction form avoids int overflow.
            if (n > capacity - used) return false;
            // Accepted: n <= capacity - used, so used + n <= capacity.
            used += n;
            return true;
        }

        /**
         * Gives back n previously reserved units, all or nothing.
         * Time: O(1). Space: O(1).
         * Invariant: a refused call leaves used unchanged; an accepted call keeps used >= 0.
         */
        boolean cancel(int n) {
            // Refuse before any write when fewer than n units are reserved.
            if (n > used) return false;
            // Accepted: n <= used, so used - n >= 0.
            used -= n;
            return true;
        }

        /**
         * Returns the reserved amount.
         * Time: O(1). Space: O(1).
         * Invariant: the method reads only.
         */
        int used() {
            // The value is within 0..capacity by the invariant.
            return used;
        }
    }

    /**
     * Reads every non-static field of the quota, so main can compare states before and after a call.
     * Time: O(number of fields). Space: O(number of fields).
     */
    static List<Object> snapshot(Quota q) throws IllegalAccessException {
        List<Object> values = new ArrayList<>();
        // Every declared instance field takes part, including fields added later.
        for (Field f : Quota.class.getDeclaredFields()) {
            if (Modifier.isStatic(f.getModifiers())) continue;
            f.setAccessible(true);
            values.add(f.get(q));
        }
        return values;
    }

    public static void main(String[] args) throws Exception {
        // Example 1 from the exercise.
        Quota q = new Quota(5);
        if (!q.reserve(3) || q.reserve(3) || q.cancel(4) || !q.cancel(2) || q.used() != 1) throw new AssertionError("example 1");
        // Example 2: capacity 0 refuses every reservation and every cancellation.
        Quota z = new Quota(0);
        if (z.reserve(1) || z.cancel(1) || z.used() != 0) throw new AssertionError("example 2");
        // The addition form overflows in Java, so the class must not use it.
        if (Integer.MAX_VALUE + 1 >= 0) throw new AssertionError("expected wraparound");
        Quota big = new Quota(Integer.MAX_VALUE);
        if (!big.reserve(Integer.MAX_VALUE) || big.reserve(1) || big.used() != Integer.MAX_VALUE) throw new AssertionError("overflow");

Design an Ordered Stream

LeetCode 1656

Problem Specification. Design the class OrderedStream for keys 1 to n. The constructor receives n. The call insert(idKey, value) stores the value for the key. That key has no value yet. It then returns the list of values for the longest run of consecutive keys that starts at the smallest key not yet returned and whose values are all stored. The list is empty when that smallest key has no stored value. The call returns every value exactly once.

Input Constraints. The limits are:

  • Count n satisfies 1 <= n <= 1000.
  • Key satisfies 1 <= idKey <= n, and each key is inserted at most once.
  • Value is a string of 1 to 5 lowercase letters.
  • Order of the returned list is increasing key order.

Example 1. Input calls ["OrderedStream","insert","insert","insert","insert"] with arguments [[4],[2,"b"],[1,"a"],[4,"d"],[3,"c"]], output [null,[],["a","b"],[],["c","d"]].

Prerequisites. The Rejected Calls exercise above.

What This Exercise Changes. The state is no longer a count. It is a stored array plus a pointer, and one insertion releases a whole contiguous suffix, not a single value.

Hint

Which single index records the smallest key not yet returned, and where must it stop after one insertion?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps an array slots indexed by key and a pointer ptr. The invariant is that ptr is the smallest key whose value has not been returned, and every key below ptr has been stored and returned exactly once. An insertion writes the value into its slot. If the slot at ptr is still empty, nothing new becomes contiguous and the list is empty. Otherwise a loop collects the values at ptr, ptr + 1 and onward while slots are filled, and ptr stops at the first empty slot or at n + 1. The loop ends because each pass moves ptr forward and the array is finite.

The state is no longer one count. It is a stored array plus a pointer, and the returned list is exactly the contiguous run that the insertion completed. The oracle recomputes the whole contiguous prefix of stored keys from scratch after each insertion and returns the part that is new.

Complexity.

  • Time is O(n) in total over all insertions, because ptr only moves forward and each slot is read into a list at most once; one call costs O(1) plus its list length.
  • Space is O(n), because the array holds one string reference per key.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class OrderedStreamRecognize {
    /** Stream that releases values in key order as soon as they form a contiguous run. */
    static final class OrderedStream {
        private final String[] slots;
        private int ptr;

        /**
         * Creates a stream for keys 1 to n.
         * Time: O(n). Space: O(n).
         * Invariant: ptr = 1 and no value has been returned yet.
         */
        OrderedStream(int n) {
            // Index 0 stays unused, so key k lives at slots[k].
            slots = new String[n + 2];
            // Key 1 is the first value to release.
            ptr = 1;
        }

        /**
         * Stores one value and returns the newly contiguous values in key order.
         * Time: O(1) plus the length of the returned list. Space: O(1) beyond the returned list.
         * Invariant: ptr is the smallest key not yet returned; all smaller keys were returned once.
         */
        List<String> insert(int idKey, String value) {
            // Store the value; no other field changes yet.
            slots[idKey] = value;
            List<String> out = new ArrayList<>();
            // Release values while the slot at ptr is filled; the sentinel slot n + 1 stays null and stops the loop.
            while (slots[ptr] != null) {
                // Each returned value is read once, so the total work over all calls is O(n).
                out.add(slots[ptr]);
                // Move to the next key to release.
                ptr++;
            }
            return out;
        }
    }

    /** Oracle that recomputes the contiguous prefix of stored keys from scratch. Time per call: O(n). Space: O(n). */
    static final class Model {
        private final String[] stored;
        private int released;
        Model(int n) { stored = new String[n + 2]; }
        List<String> insert(int key, String value) {
            stored[key] = value;
            // k is the largest key such that keys 1..k are all stored.
            int k = 0;
            while (stored[k + 1] != null) k++;
            List<String> out = new ArrayList<>();
            // Return the keys between the old prefix and the new prefix.
            for (int i = released + 1; i <= k; i++) out.add(stored[i]);
            released = Math.max(released, k);
            return out;
        }
    }

    public static void main(String[] args) {
        // Example 1: keys 2 and 1 release together, then keys 3 and 4 release together.
        OrderedStream a = new OrderedStream(4);
        if (!a.insert(2, "b").equals(List.of())) throw new AssertionError("e1 step 1");
        if (!a.insert(1, "a").equals(List.of("a", "b"))) throw new AssertionError("e1 step 2");
        if (!a.insert(4, "d").equals(List.of())) throw new AssertionError("e1 step 3");
        if (!a.insert(3, "c").equals(List.of("c", "d"))) throw new AssertionError("e1 step 4");
        // Example 2: the last insertion completes a run that began at key 2.
        OrderedStream b = new OrderedStream(3);
        if (!b.insert(1, "x").equals(List.of("x"))) throw new AssertionError("e2 step 1");
        if (!b.insert(3, "z").equals(List.of())) throw new AssertionError("e2 step 2");
        if (!b.insert(2, "y").equals(List.of("y", "z"))) throw new AssertionError("e2 step 3");
        // Random permutations of the keys compare every returned list with the oracle.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 3000; t++) {
            int n = 1 + rnd.nextInt(10);
            List<Integer> keys = new ArrayList<>();
            for (int k = 1; k <= n; k++) keys.add(k);
            java.util.Collections.shuffle(keys, rnd);
            OrderedStream real = new OrderedStream(n);
            Model model = new Model(n);
            int returned = 0;
            for (int key : keys) {
                String v = "v" + key;
                List<String> got = real.insert(key, v);
                if (!got.equals(model.insert(key, v))) throw new AssertionError("mismatch at key " + key);
                returned += got.size();
            }
            // After all n insertions every value has been returned exactly once.
            if (returned != n) throw new AssertionError("returned " + returned + " of " + n);
        }
    }

Problem

Why Membership Checks Slow Down

A port scanner probes all 65 536 TCP ports of a host and records which ones answered. The first version keeps the answers in an ArrayList<Integer> and calls contains before every insert, to avoid duplicates. On a host that answers on 60 000 ports, the last probes each scan tens of thousands of stored numbers just to learn that the port is new. The scan that should take milliseconds takes seconds.

The same shape appears whenever a program must remember a set of small integers, a table from ids to values, or an ordered list that supports changes in the middle. Interview prompts often add a rule: no library HashSet or HashMap is allowed. This lesson asks one question. How can a class decide where a key belongs by looking at the key alone, so that every later call checks only that one place?

Simple approach

Searching A List For Each Key

The simple store keeps every key in one growing list. To add a key, the method searches the list and appends the key only when the search finds nothing. To test or remove a key, it searches the same list from the front.

final class ListSet {
    private final java.util.List<Integer> keys = new java.util.ArrayList<>();

    boolean add(int key) {
        if (keys.contains(key)) return false;
        keys.add(key);
        return true;
    }

    boolean contains(int key) { return keys.contains(key); }

    boolean remove(int key) { return keys.remove((Integer) key); }
}

The class is correct. After adding 40, 7 and 19, a call to contains(19) compares 19 with 40, then 7, then 19 and answers true. The cast in remove matters, because remove(int) on a list deletes by index while remove(Object) deletes by value.

Bottleneck

Counting The Searches

Predict first: A set holds 50 000 distinct keys in the list-based class. About how many comparisons does one more `add` of a new key make, and how many does `add` make for 50 000 new keys in total?

One add of a new key compares it with all 50 000 stored keys before it appends, so it costs about 50 000 comparisons. Adding 50 000 new keys in total costs about 1.25 billion comparisons, because the list length grows from 0 to 50 000 and the costs add up to roughly n squared over 2.

Each call searches the whole list, so one operation costs O(n) for a store holding n keys, and n operations cost O(n^2). The cost grows with the number of stored keys, although the answer to a single question depends on one key only.

The waste has a precise form. The search reads keys that cannot equal the query, such as 40 when the query is 19. Nothing in the store tells the search which stored keys are worth reading. The store keeps keys in arrival order, and arrival order carries no information about a key's value. A better store must place each key by its value. Then a later query computes the same place from the same value and reads only that place.

Key idea

Giving Every Key One Fixed Place

Direct Slots For A Small Domain

Suppose every key is an integer from 0 to D - 1 for a known D. The store allocates a boolean[D] array. Array position k is the direct slot of key k, because the key is its own index. The slot holds true when the set contains k and false otherwise.

An add writes true to slot k, a remove writes false, and a contains reads the slot. Each call touches one array position, so the cost is O(1). The store owns each key in exactly one place, and that place never changes. We call this the ownership rule: a call may change only the place that belongs to its key.

Buckets For A Large Domain

A domain of all int values, or of 10^6 keys with only a few hundred stored, makes the direct array too large or too empty. The store then uses a smaller array of B buckets. A bucket is one array position that owns a short chain of nodes, and each node holds one key. A hash function maps a key to a bucket index. For non-negative keys, the function key % B is enough.

Two different keys can share one bucket, such as 6 and 10 when B = 4. The chain in that bucket holds both nodes. A lookup computes the bucket index, then walks only that chain and compares keys by value. Because the hash function is deterministic, the key always returns to the same bucket, and no other bucket can contain it.

Updates And Removals Keep Ownership

A map stores a value next to each key. A put on a key that already has a node changes the value in that node and creates no second node. A get that finds no node returns an explicit absent result, which differs from a stored value such as 0. A remove unlinks the node from its own chain and touches no other bucket.

The same ownership rule governs an indexed list. Its head field owns the first node, its tail field owns the last node, and its size field counts the chain. Every insert and delete must update all three fields before the call returns. A chain bucket and a linked list therefore share one habit: each mutation changes exactly the fields that own the affected nodes.

With a good hash function and B close to the number of stored keys n, a chain holds O(1) nodes on average. The cost per call is O(1 + n / B) in expectation and O(n) in the worst case, when every key falls in one bucket.

State

Fields That Describe One Store

Each store keeps a few fields that together describe one logical state, and every public call must leave them in agreement.

  • present is the boolean[] array in the direct set, where present[k] is true exactly when key k is stored.
  • buckets is the array of chain heads, where buckets[b] is the first node of bucket b or null when the bucket is empty.
  • B is the number of buckets, and key % B is the bucket index of a non-negative key.
  • node is one chain element with a key, a value in the map, and a next reference.
  • head, tail and size are the linked list fields: the first node, the last node, and the number of nodes.

The invariant is that every stored key appears in exactly one place, which is the slot or the chain that its hash function selects, and that the counts and end references agree with the chains after every call.

Walkthrough

Tracing Slots And Chains

Direct Slots For Keys Up To 7

The first trace uses a direct set with domain 8, so the cells are the slot indexes 0 to 7. The pointer key marks the slot that the current call reads or writes. The calls run in order: add 3, add 5, add 3 again, remove 5, contains 5, contains 3.

The first add writes slot 3, and the second add writes slot 5. The repeated add of 3 finds the slot already true, so it changes nothing and reports that the key was present. The remove of 5 clears only slot 5, and the following contains of 5 reads that slot and finds false. The last call finds slot 3 still true. No call ever reads a slot other than the one numbered by its key, which is the reason each call costs one step.

Buckets For Four Chains

The second trace uses four buckets, so the cells are the bucket indexes 0 to 3. The pointer b marks the bucket chosen by key % 4. The calls run in order: add 6, add 10, add 3, add 10 again, remove 6, contains 10.

Keys 6 and 10 both map to bucket 2, so the second add walks the one-node chain, finds no equal key and links a new node at the chain head. The key 3 maps to bucket 3 and leaves bucket 2 untouched. The repeated add of 10 finds 10 at the head of bucket 2 and stops because the keys are equal. The remove of 6 walks past the head node 10 and unlinks the last node, and key 10 stays reachable from the bucket head. The final contains computes bucket 2 again and finds 10 after one comparison. Each step reads the one bucket that the key selects, and the other three buckets are never visited.

Code

Direct Set And Chained Set

Two Containers

The two classes below use the same three method names. The direct set indexes an array by the key. The chained set indexes an array of chain heads by key % buckets.length. Both assume non-negative keys.

final class Stores {
    static final class DirectSet {
        private final boolean[] present;

        DirectSet(int domain) { present = new boolean[domain]; }

        boolean add(int key) {
            if (present[key]) return false;
            present[key] = true;
            return true;
        }

        boolean contains(int key) { return present[key]; }

        boolean remove(int key) {
            if (!present[key]) return false;
            present[key] = false;
            return true;
        }
    }

    static final class ChainedSet {
        private static final class Node {
            final int key;
            Node next;
            Node(int key, Node next) { this.key = key; this.next = next; }
        }

        private final Node[] buckets;

        ChainedSet(int bucketCount) { buckets = new Node[bucketCount]; }

        private int bucketOf(int key) { return key % buckets.length; }

        boolean contains(int key) {
            for (Node n = buckets[bucketOf(key)]; n != null; n = n.next) if (n.key == key) return true;
            return false;
        }

        boolean add(int key) {
            if (contains(key)) return false;
            int b = bucketOf(key);
            buckets[b] = new Node(key, buckets[b]);
            return true;
        }

        boolean remove(int key) {
            int b = bucketOf(key);
            Node prev = null;
            for (Node n = buckets[b]; n != null; prev = n, n = n.next) {
                if (n.key != key) continue;
                if (prev == null) buckets[b] = n.next; else prev.next = n.next;
                return true;
            }
            return false;
        }
    }
}

Cost And Java Details

  • DirectSet costs O(1) time per call and O(D) space for the domain size D.
  • ChainedSet costs O(1 + n / B) expected time per call and O(B + n) space.

The remove method keeps a prev reference because a singly linked chain cannot step backward. When the removed node is the chain head, the bucket array entry itself changes. Java arrays of references start with null entries, which is why an empty bucket needs no setup. The expression key % buckets.length is non-negative only for non-negative keys, because the Java remainder keeps the sign of the dividend.

When to use it

When Direct Placement Applies

Recognizing The Shape

Reach for this design when the prompt forbids a library map or set, or when it states a small key range such as 0 to 10^6. A request to implement put, get and remove from scratch, or a list with head, tail and index operations, has the same shape. The invariant to state before coding is that each key has one deterministic place, and each update or removal changes only the fields that own that place.

Choosing Between The Layouts

Use a direct array when the whole domain fits in memory and the keys are dense enough to justify it. A domain of 10^6 booleans takes about one megabyte, which is acceptable. Use chains when the domain is huge or unknown, and choose B as a prime near the expected number of keys so that keys spread evenly. Use a head, tail and size triple when the order of elements matters and the key is a position, not a value.

Two False Friends

A false friend of the map is the sentinel return. A get that returns 0 for a missing key cannot be told apart from a stored 0, so the contract must name a separate absent result or check for the node. A second false friend is the list's tail reference. A delete that unlinks the last node but leaves tail pointing at it breaks the next append silently, because the fields no longer describe the same list.

Do not use a chained table when the problem needs keys in sorted order, since chains hold no order across buckets. A balanced tree or a sorted array serves that case.

Problem Specification. Design a class DirectSet with a constructor DirectSet(int domain) that creates an empty set of integer keys drawn from 0..domain-1. The method add(key) inserts the key and returns true when the key was absent, or false when it was already present. The method remove(key) deletes the key and returns true when the key was present, or false otherwise. The method contains(key) returns true exactly when the key is stored. A key outside 0..domain-1 makes any of the three methods throw IllegalArgumentException.

Input Constraints. The limits are:

  • Domain is 1 <= domain <= 10^6.
  • Keys are int values, and values outside the domain throw.
  • Calls number at most 10^5, and each call must cost O(1).
  • Library classes HashSet, HashMap and List are not allowed.

Example 1. Input domain = 10 and the calls add(4), add(4), contains(4), remove(4), remove(4), contains(4), output true, false, true, true, false, false.

Example 2. Input domain = 3 and the calls add(0), contains(2), add(2), remove(0), contains(0), output true, false, true, true, false. A later add(3) throws.

Prerequisites. The direct slot and the ownership rule from this lesson.

What This Exercise Changes. Basic case: the key is the array index, so no search and no collision exist.

Hint

Which array index can hold the answer for key k without any search, and what must a repeated add report?

Algorithmic Solution (attempt the problem first)

Approach. The class allocates one boolean per key of the domain, so key k owns array position k and no other position. An add reads the position first and writes true only when it was false, which gives the required report of a new key. A remove mirrors that rule. Every method first checks that the key lies inside the domain, because an unchecked index would either throw an unrelated array exception or, for a negative key, read the wrong position by accident.

The invariant is that present[k] is true exactly when key k is stored, and each call writes at most the single position that the key names. No call reads or writes a second position, so a repeated add or a removal of an absent key leaves the array unchanged.

Complexity.

  • Time is O(1) per call, because each method reads or writes one array position after one range check.
  • Space is O(D) for domain size D, because the array holds one boolean per possible key whether or not the key is stored.
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Random;
import java.util.Set;

public final class DirectSetBuild {
    /** Set over the keys 0..domain-1 with one boolean per key. Invariant: present[k] is true iff k is stored. */
    static final class DirectSet {
        // One entry per key of the domain; the key is its own index.
        private final boolean[] present;

        /**
         * Creates an empty set for the given domain size.
         * Time: O(D), because the array is zero-filled. Space: O(D).
         * Invariant: every entry starts false.
         */
        DirectSet(int domain) {
            // The allocation is the only linear-cost step of the class.
            present = new boolean[domain];
        }

        /**
         * Rejects keys outside the domain so that the array index is always valid.
         * Time: O(1). Space: O(1).
         * Invariant: afterwards 0 <= key < present.length.
         */
        private void check(int key) {
            // Both bounds are tested, because a negative key would otherwise raise an array exception with a different type.
            if (key < 0 || key >= present.length) throw new IllegalArgumentException("key " + key);
        }

        /**
         * Adds the key and reports whether it was absent.
         * Time: O(1). Space: O(1).
         * Invariant: only present[key] can change.
         */
        boolean add(int key) {
            // Validate before touching the array.
            check(key);
            // A stored key stays as it is, and the call reports that nothing was added.
            if (present[key]) return false;
            // The key owns this one position, so a single write stores it.
            present[key] = true;
            // The caller learns that the set grew.
            return true;
        }

        /**
         * Removes the key and reports whether it was present.
         * Time: O(1). Space: O(1).
         * Invariant: only present[key] can change.
         */
        boolean remove(int key) {
            // Validate before touching the array.
            check(key);
            // An absent key needs no write.
            if (!present[key]) return false;
            // Clearing the owned position removes the key.
            present[key] = false;
            // The caller learns that the set shrank.
            return true;
        }

        /**
         * Tests membership.
         * Time: O(1). Space: O(1).
         * Invariant: the call changes nothing.
         */
        boolean contains(int key) {
            // Validate, then read the single owned position.
            check(key);
            return present[key];
        }
    }

    /**
     * Applies one random call to both the direct set and the oracle and compares the results.
     * Time: O(1) per call. Space: O(1).
     * Invariant: after every call the two sets hold the same keys.
     */
    static void step(DirectSet s, Set<Integer> oracle, Random rnd, int domain) {
        // Keys range slightly past the domain so that the range check is exercised.
        int key = rnd.nextInt(domain + 3) - 1;
        int op = rnd.nextInt(3);
        boolean inside = key >= 0 && key < domain;
        try {
            // Each branch compares the answer of the direct set with the answer of java.util.HashSet.
            boolean got = op == 0 ? s.add(key) : op == 1 ? s.remove(key) : s.contains(key);
            if (!inside) throw new AssertionError("expected a throw for " + key);
            boolean want = op == 0 ? oracle.add(key) : op == 1 ? oracle.remove(key) : oracle.contains(key);
            if (got != want) throw new AssertionError("answer differs for op " + op + " key " + key);
        } catch (IllegalArgumentException e) {
            // Only out-of-domain keys may throw.
            if (inside) throw new AssertionError("unexpected throw for " + key);
        }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise: duplicate add and absent remove.
        DirectSet a = new DirectSet(10);
        boolean[] got = {a.add(4), a.add(4), a.contains(4), a.remove(4), a.remove(4), a.contains(4)};
        boolean[] want = {true, false, true, true, false, false};
        for (int i = 0; i < want.length; i++) if (got[i] != want[i]) throw new AssertionError("example 1 call " + i);
        // Example 2: domain edges and the first key outside the domain.
        DirectSet b = new DirectSet(3);
        if (!b.add(0) || b.contains(2) || !b.add(2) || !b.remove(0) || b.contains(0)) throw new AssertionError("example 2");
        boolean threw = false;
        try { b.add(3); } catch (IllegalArgumentException e) { threw = true; }
        if (!threw) throw new AssertionError("add(3) must throw");
        // A negative key also throws, which a bare array access would report as a different exception type.
        threw = false;
        try { b.contains(-1); } catch (IllegalArgumentException e) { threw = true; }
        if (!threw) throw new AssertionError("negative key must throw");
        // List.remove(int) deletes by index while remove(Object) deletes by value, which is why the list version casts.
        List<Integer> list = new ArrayList<>(List.of(40, 7, 19));
        list.remove(1);
        if (!list.equals(List.of(40, 19))) throw new AssertionError("remove by index");
        list.remove((Integer) 19);
        if (!list.equals(List.of(40))) throw new AssertionError("remove by value");
        // Random sequences compared with the library set, over several domain sizes.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 300; t++) {
            int domain = 1 + rnd.nextInt(12);
            DirectSet s = new DirectSet(domain);
            Set<Integer> oracle = new HashSet<>();
            for (int c = 0; c < 60; c++) step(s, oracle, rnd, domain);
        }
    }

Algorithmic Solution (attempt the problem first)

Approach. The set keeps an array of bucket heads and a hash function key % B. Every key belongs to the one chain that the function names, and the chain stores nodes in arrival order with new nodes at the head. The add method first searches only that chain, so a stored key is never inserted twice. The remove method walks the same chain with a prev reference. When the match is the head, the array entry moves to the next node. Otherwise the previous node skips the match.

The invariant is that every stored key appears in exactly one node, inside the chain of bucket key % B, and no chain holds a repeated key. Two keys that collide only share a chain, so removing one leaves the other reachable, which the tests below check with a tiny bucket count that forces many collisions. The memory depends on B and on the number of stored keys, not on the key range.

Complexity.

  • Time is O(1 + n / B) expected per call and O(n) in the worst case, because a call walks one chain whose length averages n / B.
  • Space is O(B + n), because the array has B entries and each stored key owns one node.
import java.util.HashSet;
import java.util.Random;
import java.util.Set;

public final class BucketSetVary {
    /** Chained set over non-negative int keys. Invariant: key k appears once, in the chain of bucket k % B. */
    static final class MyHashSet {
        // One chain node holds one key and the reference to the next node.
        private static final class Node {
            final int key;
            Node next;
            Node(int key, Node next) { this.key = key; this.next = next; }
        }

        // buckets[b] is the head of chain b, or null for an empty chain.
        private final Node[] buckets;

        /**
         * Creates an empty set with the given number of buckets.
         * Time: O(B). Space: O(B).
         * Invariant: every chain starts empty.
         */
        MyHashSet(int bucketCount) {
            buckets = new Node[bucketCount];
        }

        /**
         * Maps a key to its only bucket.
         * Time: O(1). Space: O(1).
         * Invariant: equal keys always return the same index, and the index is in 0..B-1 for non-negative keys.
         */
        private int bucketOf(int key) {
            // The remainder is deterministic, so the key always returns to this bucket.
            return key % buckets.length;
        }

        /**
         * Tests membership by walking one chain.
         * Time: O(1 + n / B) expected, O(n) worst case. Space: O(1).
         * Invariant: only the chain of bucketOf(key) is read.
         */
        boolean contains(int key) {
            // Start at the head of the owning chain and move node by node.
            for (Node n = buckets[bucketOf(key)]; n != null; n = n.next) {
                // Keys compare by value, because two different keys can share this chain.
                if (n.key == key) return true;
            }
            // The chain ended without a match, and no other bucket can hold the key.
            return false;
        }

        /**
         * Adds the key unless it is stored.
         * Time: O(1 + n / B) expected. Space: O(1) extra, one node when the key is new.
         * Invariant: no chain holds a repeated key afterwards.
         */
        void add(int key) {
            // The search also guards against duplicates.
            if (contains(key)) return;
            int b = bucketOf(key);
            // The new node points at the old head and then becomes the head, so the old chain stays intact.
            buckets[b] = new Node(key, buckets[b]);
        }

        /**
         * Removes the key if it is stored.
         * Time: O(1 + n / B) expected. Space: O(1).
         * Invariant: only the chain of bucketOf(key) can change, and only by dropping one node.
         */
        void remove(int key) {
            int b = bucketOf(key);
            // prev trails the current node so the walk can unlink it.
            Node prev = null;
            for (Node n = buckets[b]; n != null; prev = n, n = n.next) {
                // Skip nodes that hold other keys of this bucket.
                if (n.key != key) continue;
                // A head match moves the array entry; any other match is skipped by the previous node.
                if (prev == null) buckets[b] = n.next; else prev.next = n.next;
                // The key is unique in the chain, so the walk ends here.
                return;
            }
        }
    }

    public static void main(String[] args) {
        // Example 1: add, query, remove, query.
        MyHashSet s = new MyHashSet(769);
        s.add(5); s.add(9);
        if (!s.contains(5) || s.contains(6)) throw new AssertionError("example 1 before remove");
        s.remove(5);
        if (s.contains(5)) throw new AssertionError("example 1 after remove");
        // Example 2: 3 and 772 collide with 769 buckets, and removing the older one keeps the other reachable.
        if (3 % 769 != 772 % 769) throw new AssertionError("hash function");
        MyHashSet c = new MyHashSet(769);
        c.add(3); c.add(772); c.remove(3);
        if (!c.contains(772) || c.contains(3)) throw new AssertionError("example 2");
        // Removing a head, a middle and a tail node of one chain in turn, with a single bucket.
        MyHashSet one = new MyHashSet(1);
        for (int k = 1; k <= 4; k++) one.add(k);
        one.remove(4); one.remove(2); one.remove(1);
        if (one.contains(4) || one.contains(2) || one.contains(1) || !one.contains(3)) throw new AssertionError("chain positions");
        // Random comparison with the library set; tiny bucket counts force heavy collisions.
        Random rnd = new Random(3605L);
        for (int t = 0; t < 400; t++) {
            int buckets = 1 + rnd.nextInt(5);
            MyHashSet mine = new MyHashSet(buckets);
            Set<Integer> oracle = new HashSet<>();
            for (int c2 = 0; c2 < 80; c2++) {
                // Keys include the maximum value 10^6 and small values that share buckets.
                int key = rnd.nextInt(3) == 0 ? 1_000_000 - rnd.nextInt(3) : rnd.nextInt(12);
                int op = rnd.nextInt(3);
                if (op == 0) { mine.add(key); oracle.add(key); }
                else if (op == 1) { mine.remove(key); oracle.remove(key); }
                else if (mine.contains(key) != oracle.contains(key)) throw new AssertionError("contains " + key);
            }
        }
    }

Problem Specification. Design a class MyHashMap with put(key, value), get(key) and remove(key) over integer keys and non-negative integer values. The call put inserts the pair, or replaces the value when the key already exists. The call get returns the stored value, or -1 when the key is absent. The call remove deletes the pair when it exists. Use no built-in hash table.

Input Constraints. The limits are:

  • Keys satisfy 0 <= key <= 10^6.
  • Values satisfy 0 <= value <= 10^6, so 0 is a legal stored value and -1 is never stored.
  • Calls number at most 10^4 in total.
  • Update of an existing key must reuse its node and must not add a second pair.

Example 1. Input the calls put(2, 0), get(2), get(5), put(2, 7), get(2), remove(2), get(2), output 0, -1, 7, -1 for the four get calls.

Example 2. Input 769 buckets and the calls put(1, 1), put(770, 5), put(1, 9), get(770), get(1), remove(1), get(770), output 5, 9, 5. Keys 1 and 770 share a bucket.

Prerequisites. The Design HashSet exercise above.

What This Exercise Changes. The node now carries a value, so a lookup must separate "no node found" from "node found with value 0", and a repeated key must change the node in place.

Hint

What distinguishes a stored 0 from a missing key, and where must the second put of the same key write?

Algorithmic Solution (attempt the problem first)

Approach. The map uses the same array of chains as the set, but each node also stores a value. The private find method returns the node for a key or null, so the code separates "no node" from "a node whose value is 0". A put calls find first. When a node exists, the call overwrites that node's value and leaves the chain shape alone. When no node exists, the call links a new node at the head. A get returns -1 only when find returns null, and a stored 0 is returned as 0.

The invariant is that each key has at most one node and that node sits in the chain of its own bucket. A second put never creates a second node, so a later remove deletes the only copy and a later get cannot see an old value. The size field changes only when a node is created or unlinked, and the tests compare it with the library map after every call.

Complexity.

  • Time is O(1 + n / B) expected per call and O(n) in the worst case, because every call walks one chain.
  • Space is O(B + n), because the array has B entries and each stored pair owns one node.
import java.util.HashMap;
import java.util.Map;
import java.util.Random;

public final class HashMapBoundary {
    /** Chained map from non-negative int keys to non-negative int values. Invariant: one node per stored key, in bucket key % B. */
    static final class MyHashMap {
        // A node holds the key, its current value and the next node of the chain.
        private static final class Node {
            final int key;
            int value;
            Node next;
            Node(int key, int value, Node next) { this.key = key; this.value = value; this.next = next; }
        }

        // buckets[b] is the head of chain b.
        private final Node[] buckets;
        // size counts nodes and changes only when a node is created or unlinked.
        private int size;

        /**
         * Creates an empty map with the given number of buckets.
         * Time: O(B). Space: O(B).
         * Invariant: size is 0 and every chain is empty.
         */
        MyHashMap(int bucketCount) {
            buckets = new Node[bucketCount];
        }

        /**
         * Finds the node of a key.
         * Time: O(1 + n / B) expected. Space: O(1).
         * Invariant: returns null exactly when the key is absent, whatever values are stored.
         */
        private Node find(int key) {
            // Walk only the chain of the key's bucket.
            for (Node n = buckets[key % buckets.length]; n != null; n = n.next) {
                // Compare by key value; a node with value 0 is still a node.
                if (n.key == key) return n;
            }
            // The chain ended, so the key has no node.
            return null;
        }

        /**
         * Stores a pair, replacing the value of an existing key in place.
         * Time: O(1 + n / B) expected. Space: O(1) extra, one node when the key is new.
         * Invariant: the key has exactly one node afterwards.
         */
        void put(int key, int value) {
            Node n = find(key);
            // An existing node is updated in place, so size and chain shape stay the same.
            if (n != null) { n.value = value; return; }
            int b = key % buckets.length;
            // A new node becomes the chain head, and size grows with it.
            buckets[b] = new Node(key, value, buckets[b]);
            size++;
        }

        /**
         * Reads a value.
         * Time: O(1 + n / B) expected. Space: O(1).
         * Invariant: the result is -1 only when the key is absent, because stored values are never negative.
         */
        int get(int key) {
            Node n = find(key);
            // Only a missing node maps to -1; a stored 0 is returned as 0.
            return n == null ? -1 : n.value;
        }

        /**
         * Removes a pair if it exists.
         * Time: O(1 + n / B) expected. Space: O(1).
         * Invariant: size drops by one exactly when a node is unlinked.
         */
        void remove(int key) {
            int b = key % buckets.length;
            // prev trails the walk so the matching node can be skipped.
            Node prev = null;
            for (Node n = buckets[b]; n != null; prev = n, n = n.next) {
                // Ignore other keys that share this bucket.
                if (n.key != key) continue;
                // Unlink at the head or in the middle of the chain.
                if (prev == null) buckets[b] = n.next; else prev.next = n.next;
                size--;
                return;
            }
        }

        /** Returns the number of stored pairs. Time: O(1). Space: O(1). Invariant: equals the number of nodes in all chains. */
        int size() { return size; }
    }

    public static void main(String[] args) {
        // Example 1: a stored 0 differs from an absent key, and a second put changes the value.
        MyHashMap m = new MyHashMap(769);
        m.put(2, 0);
        if (m.get(2) != 0 || m.get(5) != -1) throw new AssertionError("absent versus zero");
        m.put(2, 7);
        if (m.get(2) != 7 || m.size() != 1) throw new AssertionError("update in place");
        m.remove(2);
        if (m.get(2) != -1 || m.size() != 0) throw new AssertionError("after remove");
        // Example 2: 1 and 770 share a bucket; updating 1 and removing 1 leave 770 intact.
        if (1 % 769 != 770 % 769) throw new AssertionError("hash function");
        MyHashMap c = new MyHashMap(769);
        c.put(1, 1); c.put(770, 5); c.put(1, 9);
        if (c.get(770) != 5 || c.get(1) != 9 || c.size() != 2) throw new AssertionError("example 2 before remove");
        c.remove(1);
        if (c.get(770) != 5 || c.get(1) != -1) throw new AssertionError("example 2 after remove");
        // Removing an absent key changes nothing.
        c.remove(1);
        if (c.size() != 1) throw new AssertionError("remove absent");
        // Random comparison with the library map; few buckets force collisions and many updates of one key.
        Random rnd = new Random(3606L);
        for (int t = 0; t < 400; t++) {
            MyHashMap mine = new MyHashMap(1 + rnd.nextInt(5));
            Map<Integer, Integer> oracle = new HashMap<>();
            for (int i = 0; i < 80; i++) {
                int key = rnd.nextInt(4) == 0 ? 1_000_000 - rnd.nextInt(2) : rnd.nextInt(10);
                int op = rnd.nextInt(3);
                // Values include 0 and the maximum 10^6.
                int value = rnd.nextInt(3) == 0 ? 0 : rnd.nextInt(1_000_001);
                if (op == 0) { mine.put(key, value); oracle.put(key, value); }
                else if (op == 1) { mine.remove(key); oracle.remove(key); }
                else if (mine.get(key) != oracle.getOrDefault(key, -1)) throw new AssertionError("get " + key);
                if (mine.size() != oracle.size()) throw new AssertionError("size");
            }
        }
    }

LeetCode 707

Problem Specification. Design a class MyLinkedList that stores integers in a singly linked chain with zero-based positions. The call get(index) returns the value at the position, or -1 when the position does not exist. The calls addAtHead(val) and addAtTail(val) insert at the ends. The call addAtIndex(index, val) inserts the value so that it occupies the position index, appends when index equals the current size, and does nothing when index is greater than the size or negative. The call deleteAtIndex(index) removes the node at the position and does nothing for an invalid position.

Input Constraints. The limits are:

  • Values satisfy 0 <= val <= 1000.
  • Indexes are int values, and invalid ones leave the list unchanged.
  • Calls number at most 2000 in total.
  • Library list classes are not allowed, so the class stores its own nodes.

Example 1. Input the calls addAtHead(4), addAtTail(8), addAtIndex(1, 6), get(1), deleteAtIndex(2), addAtTail(3), get(2), output 6, 3. The list is 4, 6, 8 after the third call and 4, 6, 3 at the end.

Example 2. Input on an empty list the calls addAtIndex(1, 5), get(0), addAtIndex(0, 5), deleteAtIndex(0), addAtTail(2), get(0), output -1, 2. The first call is ignored because 1 exceeds the size 0.

Prerequisites. The Design HashMap exercise above.

What This Exercise Changes. The key is now a position, so a chain walk replaces the hash function, and three fields must agree after every call.

Hint

After any delete, which of head, tail and size can still point at a node that no longer belongs to the chain?

Algorithmic Solution (attempt the problem first)

Approach. The list is a singly linked chain with three owning fields: head for the first node, tail for the last node and size for the node count. Positions replace hash keys, so a walk of index - 1 steps finds the node before the position. Insertion at index 0 changes head, insertion at index size changes tail, and a middle insertion changes neither. Deletion mirrors that table. Removing index 0 moves head, removing the last node moves tail back to its predecessor, and removing the only node sets both to null.

The invariant is that size equals the number of nodes reachable from head, tail is the last of them, and head and tail are both null exactly when size is 0. Every public call restores that statement before it returns, and the test calls a checker after every operation. Invalid indexes return before any field changes, so a rejected call leaves the list as it was.

Complexity.

  • Time is O(1) for addAtHead and addAtTail, and O(n) for get, addAtIndex and deleteAtIndex, because those three walk up to n nodes.
  • Space is O(n), because each stored value owns one node and the three fields add O(1).
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class ListOwnership {
    /** Singly linked list. Invariant: size counts the nodes after head, tail is the last node, and head is null iff size is 0. */
    static final class MyLinkedList {
        // A node holds one value and the reference to its successor.
        private static final class Node {
            final int val;
            Node next;
            Node(int val) { this.val = val; }
        }

        private Node head, tail;
        private int size;

        /**
         * Returns the node at a valid position.
         * Time: O(index). Space: O(1).
         * Invariant: the caller has checked 0 <= index < size.
         */
        private Node nodeAt(int index) {
            Node n = head;
            // Each step moves one node along the chain, which is the source of the linear cost.
            for (int i = 0; i < index; i++) n = n.next;
            return n;
        }

        /**
         * Reads the value at a position.
         * Time: O(index). Space: O(1).
         * Invariant: the call changes nothing.
         */
        int get(int index) {
            // An invalid position reports -1 before any walk.
            if (index < 0 || index >= size) return -1;
            return nodeAt(index).val;
        }

        /**
         * Inserts a value at the front.
         * Time: O(1). Space: O(1).
         * Invariant: head, tail and size agree again on return.
         */
        void addAtHead(int val) {
            Node n = new Node(val);
            // The new node points at the old first node, which is null for an empty list.
            n.next = head;
            head = n;
            // An empty list makes the new node the last node as well.
            if (size == 0) tail = n;
            size++;
        }

        /**
         * Inserts a value at the back.
         * Time: O(1). Space: O(1).
         * Invariant: head, tail and size agree again on return.
         */
        void addAtTail(int val) {
            Node n = new Node(val);
            // An empty list has no last node to link from, so the new node is both ends.
            if (size == 0) head = n; else tail.next = n;
            tail = n;
            size++;
        }

        /**
         * Inserts a value so that it occupies the given position.
         * Time: O(index). Space: O(1).
         * Invariant: an invalid index changes no field.
         */
        void addAtIndex(int index, int val) {
            // Positions after the end and negative positions are ignored.
            if (index < 0 || index > size) return;
            // The two ends have their own methods because they update head or tail.
            if (index == 0) { addAtHead(val); return; }
            if (index == size) { addAtTail(val); return; }
            // A middle insertion links after the predecessor and changes neither head nor tail.
            Node prev = nodeAt(index - 1);
            Node n = new Node(val);
            n.next = prev.next;
            prev.next = n;
            size++;
        }

        /**
         * Removes the node at a position.
         * Time: O(index). Space: O(1).
         * Invariant: an invalid index changes no field, and the last removal clears head and tail together.
         */
        void deleteAtIndex(int index) {
            // Invalid positions are ignored.
            if (index < 0 || index >= size) return;
            if (index == 0) {
                // The second node, or null, becomes the first.
                head = head.next;
                // Deleting the only node leaves no last node.
                if (size == 1) tail = null;
            } else {
                Node prev = nodeAt(index - 1);
                Node gone = prev.next;
                // The predecessor skips the removed node.
                prev.next = gone.next;
                // Deleting the last node moves tail back to the predecessor.
                if (gone == tail) tail = prev;
            }
            size--;
        }

        /**
         * Checks the ownership invariant by walking the whole chain.
         * Time: O(n). Space: O(1).
         * Invariant: it reports a mismatch of size, head or tail and changes nothing.
         */
        void checkOwnership() {
            int count = 0;
            Node last = null;
            // Count reachable nodes and remember the final one.
            for (Node n = head; n != null; n = n.next) { count++; last = n; }
            if (count != size) throw new AssertionError("size " + size + " but " + count + " nodes");
            if (last != tail) throw new AssertionError("tail does not point at the last node");
            if ((head == null) != (size == 0)) throw new AssertionError("head and size disagree");
        }
    }

    public static void main(String[] args) {
        // Example 1: ends and a middle insertion, then a delete and a new tail.
        MyLinkedList a = new MyLinkedList();
        a.addAtHead(4); a.addAtTail(8); a.addAtIndex(1, 6);
        if (a.get(0) != 4 || a.get(1) != 6 || a.get(2) != 8) throw new AssertionError("example 1 list");
        a.deleteAtIndex(2);
        a.addAtTail(3);
        if (a.get(2) != 3 || a.get(1) != 6) throw new AssertionError("example 1 tail after delete");
        a.checkOwnership();
        // Example 2: invalid insert on an empty list, then emptying the list and appending again.
        MyLinkedList b = new MyLinkedList();
        b.addAtIndex(1, 5);
        if (b.get(0) != -1) throw new AssertionError("ignored insert");
        b.addAtIndex(0, 5);
        b.deleteAtIndex(0);
        b.checkOwnership();
        b.addAtTail(2);
        if (b.get(0) != 2) throw new AssertionError("append after emptying");
        b.checkOwnership();
        // Negative indexes are ignored by every indexed method.
        b.addAtIndex(-1, 9); b.deleteAtIndex(-1);
        if (b.get(-1) != -1 || b.get(0) != 2) throw new AssertionError("negative index");
        // Random comparison with ArrayList, checking the three fields after every call.
        Random rnd = new Random(3607L);
        for (int t = 0; t < 600; t++) {
            MyLinkedList mine = new MyLinkedList();
            List<Integer> oracle = new ArrayList<>();
            for (int i = 0; i < 60; i++) {
                int op = rnd.nextInt(5);
                // Indexes run from -1 to size + 1 so that both invalid sides occur.
                int idx = rnd.nextInt(oracle.size() + 3) - 1;
                int val = rnd.nextInt(1001);
                if (op == 0) { mine.addAtHead(val); oracle.add(0, val); }
                else if (op == 1) { mine.addAtTail(val); oracle.add(val); }
                else if (op == 2) { mine.addAtIndex(idx, val); if (idx >= 0 && idx <= oracle.size()) oracle.add(idx, val); }
                else if (op == 3) { mine.deleteAtIndex(idx); if (idx >= 0 && idx < oracle.size()) oracle.remove(idx); }
                else {
                    int want = idx >= 0 && idx < oracle.size() ? oracle.get(idx) : -1;
                    if (mine.get(idx) != want) throw new AssertionError("get " + idx);
                }
                mine.checkOwnership();
                if (mine.size != oracle.size()) throw new AssertionError("size");
            }
        }
    }

Problem

Why Removing The Oldest Item Stalls

A network driver keeps the most recent 4096 incoming packets in one array and hands them to the application oldest first. Packets arrive thousands of times per second, and the application removes the oldest packet each time it is ready. The first version of the driver removes the oldest packet by moving every other packet one position to the left. Under load the driver spends most of its time copying packets instead of delivering them.

The same shape appears in a keyboard input queue, a log viewer that retains the last thousand lines, and a rate limiter that remembers recent requests. In each case the capacity is fixed, items leave in the order they arrived, and memory must not grow. This lesson asks one question. How can a fixed array behave as a first-in first-out queue so that adding and removing each cost constant time, with no copying?

Simple approach

Keeping The Oldest Item At Index 0

The direct design keeps the oldest item at index 0 and the newest at index count - 1. Adding an item writes at count. Removing an item returns index 0 and moves every later item one position to the left, so the invariant "oldest at index 0" holds again.

final class ShiftingQueue {
    private final int[] items;
    private int count;

    ShiftingQueue(int capacity) { items = new int[capacity]; }

    boolean offer(int v) {
        if (count == items.length) return false;
        items[count++] = v;
        return true;
    }

    int poll() {
        if (count == 0) return -1;
        int v = items[0];
        for (int i = 1; i < count; i++) items[i - 1] = items[i];
        count--;
        return v;
    }
}

A second idea avoids the copying. The queue keeps a start index that moves right after each removal. That version never copies, but it can no longer add items after capacity removals, even when the queue is nearly empty, because the free positions on the left are never reused.

Bottleneck

Counting The Copies And The Stranded Space

Predict first: A queue holds 100 000 items. A program removes one item and adds one item, and repeats this 1 000 000 times. About how many item copies does the shifting version make?

About 10^11 copies. Each removal moves the 99 999 remaining items, and 1 000 000 removals multiply that by 99 999. The adds cost one write each, so the removals decide the total.

For a queue holding n items, each removal in the shifting version costs O(n) time. A million removals on a full queue of 100 000 items therefore cost about 10^11 item moves, while the useful work is 2 000 000 reads and writes. Memory stays at O(n), so time is the only problem.

The start-index version fixes the time and breaks the space. Its removal costs O(1), but the used region slides to the right end of the array, and the positions it has already left stay empty and unreachable. The array behaves as if it were consumed once.

Both failures have the same cause. The design ties the oldest item to a fixed array position or ties free space to one end of the array. A correct design must let the used region start at any index and continue from the end of the array back to index 0.

Key idea

Letting The Used Region Wrap Around

Two Numbers Locate Every Item

Let cap be the array length. Store the array index of the oldest item in an int named head, and store the number of items currently held in an int named size. The queue contents are then the array positions head, head + 1, up to head + size - 1, where every position is taken modulo cap.

The modulo step is called wraparound. An index that would reach cap continues at index 0 instead. The next free position for an add is (head + size) % cap, and a removal advances head to (head + 1) % cap. Neither operation moves any item, so both cost O(1).

Why Size Replaces The End Index

A common alternative stores a tail index, the position of the next write, instead of size. That choice has a defect. When head equals tail, the queue could be empty or completely full, because both states make the two indices meet. Code then needs a spare unused slot or an extra flag to tell them apart.

The size field removes the ambiguity. The queue is empty exactly when size == 0 and full exactly when size == cap. The write position is computed from head and size and never stored, so it cannot disagree with them.

The Invariant

At every moment between public calls, 0 <= head < cap and 0 <= size <= cap. The live positions are (head + i) % cap for i from 0 to size - 1. Because size <= cap, these positions are all different, so each live item has exactly one position and no position holds two items.

A deque adds symmetric rules. Adding at the front first moves head to (head - 1 + cap) % cap, and the added cap keeps the value non-negative because Java's % returns a negative result for a negative left operand. The newest item sits at (head + size - 1) % cap.

State

Fields That Describe One Queue

A circular buffer is fully described by four values, and only three of them are stored.

  • slots is the fixed array that holds the items; its length is the capacity.
  • head is the array index of the oldest item, kept between 0 and cap - 1.
  • size is the number of live items, kept between 0 and cap.
  • next is the write position (head + size) % cap; it is computed on demand and never stored.

The state invariant is that the live items occupy exactly the positions (head + i) % cap for i from 0 to size - 1. Every public method reads these fields at its start and leaves them satisfying the invariant at its end, including when it rejects a call.

Code

Writing The Queue With Two Fields

The Class

The class below stores slots, head and size and nothing else. Both methods compute positions with the modulo rule, and neither method copies an item. The return value -1 marks a rejected removal because the stored values are non-negative.

final class IntRing {
    private final int[] slots;
    private int head;
    private int size;

    IntRing(int capacity) { slots = new int[capacity]; }

    // Adds v at the write position (head + size) % capacity; false when full.
    boolean offer(int v) {
        if (size == slots.length) return false;
        slots[(head + size) % slots.length] = v;
        size++;
        return true;
    }

    // Removes and returns the oldest value; -1 when empty.
    int poll() {
        if (size == 0) return -1;
        int v = slots[head];
        head = (head + 1) % slots.length;
        size--;
        return v;
    }
}

Cost And Java Details

  • offer costs O(1) time and no extra space, because it writes one slot.
  • poll costs O(1) time and no extra space, because it reads one slot and moves one index.
  • Memory is O(cap) for the whole life of the queue, and it never grows.

The contract requires a capacity of at least 1, because the remainder operator with a divisor of 0 throws an ArithmeticException for ints. When the stored values are objects, a removal should also clear its slot so the array does not keep a stale reference.

When to use it

When A Fixed Ring Fits

Recognizing The Pattern

Use a circular buffer when the capacity is fixed, items leave in arrival order, and the operations are add at the back and remove at the front, with a deque also allowing both ends. The statement often says "design a queue of size k", "keep only the last k items", or "drop the oldest when full". The state to name before coding is the invariant: the live positions are (head + i) % cap for i < size, and every method restores that statement before it returns.

Harder problems wrap more indexes around the same ring. A router that stores packets in arrival order and drops the oldest when memory is full still has this ring at its center, and it adds a set for duplicate checks and per-destination lists for counting.

Two False Friends

The pair of indices head and tail is a false friend. It looks like a complete description, yet equal values mean both empty and full, so correct code adds a spare slot or a flag and the bug returns when one branch forgets it.

The library class ArrayDeque is a second false friend. It uses the same wrapped array internally, yet it grows without limit and never rejects an add, so it cannot enforce a capacity by itself.

When Not To Use It

Do not use a fixed ring when the capacity is unknown, because growing it means copying live items into a new array in order. Do not use it when items leave from the middle, since the live positions would no longer form one run. Do not use it when removal order depends on priority and not on arrival.

import java.util.ArrayDeque;
import java.util.Random;

public final class RingBufferBuild {
    /** Fixed-capacity FIFO of ints. Time: O(1) per call. Space: O(capacity). Invariant: live values are at(0)..at(size - 1). */
    static final class RingBuffer {
        // Storage allocated once; its length never changes.
        private final int[] slots;
        // Array index of the oldest value, always in [0, capacity).
        private int head;
        // Number of live values, always in [0, capacity].
        private int count;

        RingBuffer(int capacity) { slots = new int[capacity]; }

        // The only place that applies wraparound: the array index of the i-th oldest live value.
        private int at(int i) { return (head + i) % slots.length; }

        /** Appends v, or returns false and changes nothing when full. Time: O(1). Space: O(1). */
        boolean offer(int v) {
            // A full buffer rejects before any field changes.
            if (count == slots.length) return false;
            // The write position is the index just after the newest value.
            slots[at(count)] = v;
            // The new value becomes live.
            count++;
            return true;
        }

        /** Removes and returns the oldest value, or -1 when empty. Time: O(1). Space: O(1). */
        int poll() {
            // An empty buffer has no oldest value.
            if (count == 0) return -1;
            // Read the oldest value before the index moves.
            int v = slots[head];
            // Advance head with wraparound; no value is copied.
            head = (head + 1) % slots.length;
            // One fewer live value.
            count--;
            return v;
        }

        /** Returns the oldest value without removing it, or -1 when empty. Time: O(1). Space: O(1). */
        int peek() { return count == 0 ? -1 : slots[head]; }

        /** Returns the number of live values. Time: O(1). Space: O(1). */
        int size() { return count; }
    }

    /** Oracle: a bounded FIFO on java.util.ArrayDeque. Time: O(1) per call. Space: O(capacity). Invariant: the deque holds the live values in order. */
    static final class Oracle {
        private final ArrayDeque<Integer> d = new ArrayDeque<>();
        private final int cap;
        Oracle(int cap) { this.cap = cap; }
        boolean offer(int v) { if (d.size() == cap) return false; d.addLast(v); return true; }
        int poll() { return d.isEmpty() ? -1 : d.pollFirst(); }
        int peek() { return d.isEmpty() ? -1 : d.peekFirst(); }
        int size() { return d.size(); }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise: capacity 2 with a wrapped write.
        RingBuffer r = new RingBuffer(2);
        boolean[] adds = {r.offer(5), r.offer(6), r.offer(7)};
        if (!adds[0] || !adds[1] || adds[2]) throw new AssertionError("e1 adds");
        if (r.poll() != 5 || !r.offer(7) || r.poll() != 6 || r.poll() != 7 || r.poll() != -1) throw new AssertionError("e1 rest");
        // Example 2: capacity 3, then peek and size after two removals and two adds.
        r = new RingBuffer(3);
        r.offer(1); r.offer(2); r.offer(3);
        if (r.poll() != 1 || r.poll() != 2 || !r.offer(4) || !r.offer(5) || r.peek() != 3 || r.size() != 3) throw new AssertionError("e2");
        // Capacity one: every index stays 0, and the buffer alternates between full and empty.
        r = new RingBuffer(1);
        if (!r.offer(9) || r.offer(8) || r.poll() != 9 || r.poll() != -1 || !r.offer(8) || r.peek() != 8) throw new AssertionError("cap 1");
        // The claim in the lesson: an int remainder with divisor 0 throws, so capacity 0 is outside the contract.
        int zero = args.length;
        try { int ignored = 5 % zero; throw new AssertionError("no exception " + ignored); } catch (ArithmeticException expected) { }
        // The claim in the lesson: ArrayDeque has no capacity limit and accepts every add.
        ArrayDeque<Integer> unbounded = new ArrayDeque<>();
        for (int i = 0; i < 10_000; i++) if (!unbounded.offerLast(i)) throw new AssertionError("ArrayDeque rejected");

Approach. The queue keeps data, head and size, and every query follows from them. Front reads data[head]. import java.util.LinkedList;
import java.util.Random;

public final class CircularQueue622 {
    /** Bounded queue answering six queries. Time: O(1) per call. Space: O(k). Invariant: live values sit at (head + i) % k for i < size. */
    static final class MyCircularQueue {
        private final int[] data;
        private int head;
        private int size;

        MyCircularQueue(int k) { data = new int[k]; }

        boolean enQueue(int value) {
            // Full queues reject without touching any field.
            if (isFull()) return false;
            // The slot after the newest value is free because size < k.
            data[(head + size) % data.length] = value;
            // The value is now live.
            size++;
            return true;
        }

        boolean deQueue() {
            // An empty queue has nothing to remove.
            if (isEmpty()) return false;
            // Moving head past the front value retires it; the stale number stays in the array but no live index reaches it.
            head = (head + 1) % data.length;
            // The count and the index change together in this one method.
            size--;
            return true;
        }

        // Front value, or -1 when empty.
        int Front() { return isEmpty() ? -1 : data[head]; }

        // Newest value, or -1 when empty; the position is computed from head and size.
        int Rear() { return isEmpty() ? -1 : data[(head + size - 1) % data.length]; }

        // Empty exactly when no value is live.
        boolean isEmpty() { return size == 0; }

        // Full exactly when every slot is live.
        boolean isFull() { return size == data.length; }
    }

    /** Oracle on a linked list with the same contract. Time: O(1) per call. Space: O(k). Invariant: the list holds live values in order. */
    static final class Oracle {
        private final LinkedList<Integer> l = new LinkedList<>();
        private final int k;
        Oracle(int k) { this.k = k; }
        boolean enQueue(int v) { if (l.size() == k) return false; l.addLast(v); return true; }
        boolean deQueue() { if (l.isEmpty()) return false; l.removeFirst(); return true; }
        int Front() { return l.isEmpty() ? -1 : l.getFirst(); }
        int Rear() { return l.isEmpty() ? -1 : l.getLast(); }
        boolean isEmpty() { return l.isEmpty(); }
        boolean isFull() { return l.size() == k; }
    }

Algorithmic Solution (attempt the problem first)

Approach. The deque uses the same three fields and adds one rule for each end. Insertion at the back writes (head + size) % k. Insertion at the front first moves head to (head - 1 + k) % k and then writes there. Deletion at the front moves head forward, and deletion at the back only lowers size, because the back position is derived from head and size. The reads return data[head] and data[(head + size - 1) % k].

The term + k is required because Java's remainder keeps the sign of the left operand, so -1 % 3 is -1 and would be an invalid index. With capacity one, every modular expression evaluates to 0, so the same code works with no special case: the front insertion moves head from 0 to (0 - 1 + 1) % 1 = 0. The invariant is the one for the queue, and each method restores it before it returns.

Complexity.

  • Time is O(1) per call, because every method is a fixed number of arithmetic steps.
  • Space is O(k) for the array, with three ints of extra state.
import java.util.ArrayDeque;
import java.util.Random;

public final class CircularDeque641 {
    /** Bounded deque. Time: O(1) per call. Space: O(k). Invariant: live values sit at (head + i) % k for i < size. */
    static final class MyCircularDeque {
        private final int[] data;
        private int head;
        private int size;

        MyCircularDeque(int k) { data = new int[k]; }

        boolean insertFront(int value) {
            // Full deques reject before head moves.
            if (isFull()) return false;
            // Step back one slot; adding the length keeps the left operand non-negative.
            head = (head - 1 + data.length) % data.length;
            // The new front value goes into the slot head now names.
            data[head] = value;
            size++;
            return true;
        }

        boolean insertLast(int value) {
            if (isFull()) return false;
            // The slot after the newest value is free because size < k.
            data[(head + size) % data.length] = value;
            size++;
            return true;
        }

        boolean deleteFront() {
            if (isEmpty()) return false;
            // Retire the front value by moving head forward.
            head = (head + 1) % data.length;
            size--;
            return true;
        }

        boolean deleteLast() {
            if (isEmpty()) return false;
            // The back position is derived from head and size, so lowering size retires it.
            size--;
            return true;
        }

        int getFront() { return isEmpty() ? -1 : data[head]; }

        int getRear() { return isEmpty() ? -1 : data[(head + size - 1) % data.length]; }

        boolean isEmpty() { return size == 0; }

        boolean isFull() { return size == data.length; }
    }

    /** Oracle on java.util.ArrayDeque with an explicit limit. Time: O(1) per call. Space: O(k). Invariant: the deque holds live values in order. */

        private final int k;
        Oracle(int k) { this.k = k; }
        boolean insertFront(int v) { if (d.size() == k) return false; d.addFirst(v); return true; }
        boolean insertLast(int v) { if (d.size() == k) return false; d.addLast(v); return true; }
        boolean deleteFront() { if (d.isEmpty()) return false; d.removeFirst(); return true; }
        boolean deleteLast() { if (d.isEmpty()) return false; d.removeLast(); return true; }
        int getFront() { return d.isEmpty() ? -1 : d.peekFirst(); }
        int getRear() { return d.isEmpty() ? -1 : d.peekLast(); }
        boolean isEmpty() { return d.isEmpty(); }
        boolean isFull() { return d.size() == k; }
    }

The method int[] forwardPacket() removes the oldest packet and returns [source, destination, timestamp], or returns an empty array when none is stored. The method int getCount(int destination, int startTime, int endTime) counts the stored packets with that destination and a timestamp in [startTime, endTime].

Input Constraints. The limits are:

  • Memory limit is 2 <= memoryLimit <= 10^5.
  • Fields satisfy 1 <= source, destination <= 2 * 10^5 and 1 <= timestamp <= 10^9.
  • Order requires that the timestamp of each addPacket call is at least that of the previous addPacket call.
  • Queries satisfy startTime <= endTime, and the calls number at most 10^5.

Example 1. Input: memory limit 3 and the calls addPacket(1,4,10), addPacket(2,4,11), addPacket(1,4,10), addPacket(3,5,12), addPacket(4,4,13), getCount(4,10,13), then four calls of forwardPacket(). Output: true, true, false, true, true, 2, [2,4,11], [3,5,12], [4,4,13], [].

Example 2. Input: memory limit 2 and the calls addPacket(1,1,5), addPacket(2,1,5), addPacket(3,2,5), addPacket(1,1,5), getCount(1,5,5). Output: true, true, true, true, 1. The packet (1,1,5) is accepted the second time because eviction removed it from the router.

Prerequisites. The Design Circular Deque exercise above.

What This Exercise Changes. Each stored item gains an identity and a destination, so every eviction or forward must update the identity set and the destination list in the same call.

Hint

The ring decides which packet leaves. Which two extra indexes must be updated at that same moment so that duplicate checks and counts stay correct?

Algorithmic Solution (attempt the problem first)

Approach. A ring of memoryLimit packets, stored as three parallel int arrays, decides order and eviction. Three indexes mirror it. A hash set of packet identity records answers the duplicate check. A map from destination to a timestamp list answers counts. A start offset in each list marks the entries that are still in the router. Timestamps never decrease across adds, and the oldest packet of one destination is also the oldest in the ring, so each list stays sorted and its evicted entries form a prefix.

One private method removeOldest owns every cross-field change. It reads the ring front, removes the key from the set, advances that destination's start offset and moves head. Both forwardPacket and a full addPacket call it, so the three structures cannot disagree. A count is two binary searches inside the live part of the list.

Complexity.

  • Time is O(1) expected for addPacket and forwardPacket, and O(log n) for getCount, where n counts packets ever added to one destination.
  • Space is O(memoryLimit) for the ring and the set, plus O(total adds) for the lists, which keep retired entries behind the start offset.
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Random;
import java.util.Set;

public final class RouterQueries {
    /** Bounded packet router. Invariant: ring, key set and destination lists describe the same packets. */
    static final class Router {
        private static final class Dest { final ArrayList<Integer> times = new ArrayList<>(); int from; }

        private final int[] src, dst, ts;
        private int head, size;
        private final Set<Key> keys = new HashSet<>();
        private final Map<Integer, Dest> byDest = new HashMap<>();

        Router(int memoryLimit) { src = new int[memoryLimit]; dst = new int[memoryLimit]; ts = new int[memoryLimit]; }

        // The identity of a packet; a record supplies equals and hashCode over all three fields.
        private record Key(int source, int destination, int timestamp) { }

        private static Key key(int s, int d, int t) { return new Key(s, d, t); }

        // Removes the oldest packet from the ring, the key set and the destination list together.
        private int[] removeOldest() {
            int[] p = {src[head], dst[head], ts[head]};
            keys.remove(key(p[0], p[1], p[2]));
            byDest.get(p[1]).from++;
            head = (head + 1) % src.length;
            size--;
            return p;
        }

        boolean addPacket(int source, int destination, int timestamp) {
            // A stored identical packet rejects the call before anything changes.
            if (!keys.add(key(source, destination, timestamp))) return false;
            // A full router drops its oldest packet first; the new key is already in the set but differs from it.
            if (size == src.length) removeOldest();
            int at = (head + size) % src.length;
            src[at] = source; dst[at] = destination; ts[at] = timestamp;
            size++;
            byDest.computeIfAbsent(destination, x -> new Dest()).times.add(timestamp);
            return true;
        }

        int[] forwardPacket() { return size == 0 ? new int[0] : removeOldest(); }

        int getCount(int destination, int startTime, int endTime) {
            Dest d = byDest.get(destination);
            if (d == null) return 0;
            // Live entries are d.times[from..end); both bounds are binary searches on the sorted part.
            return lowerBound(d.times, d.from, endTime + 1) - lowerBound(d.times, d.from, startTime);
        }

        // First index in [lo, list.size()) whose value is at least x.
        private static int lowerBound(List<Integer> list, int lo, int x) {
            int hi = list.size();
            while (lo < hi) { int mid = (lo + hi) >>> 1; if (list.get(mid) < x) lo = mid + 1; else hi = mid; }
            return lo;
        }
    }

    /** Oracle: a list of packets scanned linearly. Time: O(n) per call. Space: O(n). */
    static final class Oracle {
        private final ArrayList<int[]> l = new ArrayList<>();
        private final int limit;
        Oracle(int limit) { this.limit = limit; }
        boolean addPacket(int s, int d, int t) {
            for (int[] p : l) if (p[0] == s && p[1] == d && p[2] == t) return false;
            if (l.size() == limit) l.remove(0);
            l.add(new int[] {s, d, t});
            return true;
        }
        int[] forwardPacket() { return l.isEmpty() ? new int[0] : l.remove(0); }
        int getCount(int d, int a, int b) { int c = 0; for (int[] p : l) if (p[1] == d && p[2] >= a && p[2] <= b) c++; return c; }
    }

    public static void main(String[] args) {
        // Example 1: duplicate rejection, eviction at the limit, a count and four forwards.
        Router r = new Router(3);
        if (!r.addPacket(1, 4, 10) || !r.addPacket(2, 4, 11) || r.addPacket(1, 4, 10) || !r.addPacket(3, 5, 12) || !r.addPacket(4, 4, 13)) throw new AssertionError("e1 adds");
        if (r.getCount(4, 10, 13) != 2) throw new AssertionError("e1 count");
        if (!java.util.Arrays.equals(r.forwardPacket(), new int[] {2, 4, 11}) || !java.util.Arrays.equals(r.forwardPacket(), new int[] {3, 5, 12})
            || !java.util.Arrays.equals(r.forwardPacket(), new int[] {4, 4, 13}) || r.forwardPacket().length != 0) throw new AssertionError("e1 forwards");
        // Example 2: an evicted packet can be added again.
        r = new Router(2);
        if (!r.addPacket(1, 1, 5) || !r.addPacket(2, 1, 5) || !r.addPacket(3, 2, 5) || !r.addPacket(1, 1, 5) || r.getCount(1, 5, 5) != 1) throw new AssertionError("e2");
        // Largest legal field values: the identity must stay exact at the limits.
        r = new Router(2);
        if (!r.addPacket(200_000, 200_000, 1_000_000_000) || r.addPacket(200_000, 200_000, 1_000_000_000) || r.getCount(200_000, 1, 1_000_000_000) != 1) throw new AssertionError("large");
        // Random sequences with nondecreasing timestamps compared with the oracle.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 2000; t++) {
            int limit = 2 + rnd.nextInt(4);
            Router a = new Router(limit);
            Oracle b = new Oracle(limit);
            int time = 1;
            for (int op = 0; op < 50; op++) {
                int k = rnd.nextInt(5);
                if (k <= 2) {
                    time += rnd.nextInt(2);
                    int s = 1 + rnd.nextInt(3), d = 1 + rnd.nextInt(3);
                    if (a.addPacket(s, d, time) != b.addPacket(s, d, time)) throw new AssertionError("add");

                    if (a.getCount(d, lo, hi) != b.getCount(d, lo, hi)) throw new AssertionError("count");
                }
            }
        }
    }

Problem

Why Middle Inserts Slow A Queue

A music player keeps an up-next list. Listeners add a song to the front, add one in the middle, or append one at the back. The player also removes songs from all three places as the listener skips and reorders. With a few hundred songs this feels instant. A shared playlist of one hundred thousand songs with a stream of such edits makes every edit visibly slower than the last, even though each edit touches only one position.

Plain queues and deques serve the two ends well and cannot reach the middle without walking to it. A list reaches the middle by index and pays to shift everything behind it. The lesson asks one question. How can a structure serve the front, the middle and the back of a sequence, each in constant time?

Simple approach

Keeping Everything In One List

The direct design stores the sequence in one ArrayList. The middle of a list of size s sits at a computable index, so each call is one list operation. A push inserts at index 0, at index s / 2 or at the end. A pop removes the element at index 0, at index (s - 1) / 2 or at the last index.

static void pushFront(List<Integer> q, int v) { q.add(0, v); }
static void pushMiddle(List<Integer> q, int v) { q.add(q.size() / 2, v); }
static int popMiddle(List<Integer> q) { return q.isEmpty() ? -1 : q.remove((q.size() - 1) / 2); }

The code is short and always correct, and it needs no extra memory. The rule for an even size is part of the contract: the removed middle is the frontmost of the two middle elements, at index (s - 1) / 2.

Bottleneck

Counting The Shifted Elements

Predict first: A list receives 100 000 calls to `pushFront`, starting empty. About how many element moves does the list perform in total, and does `ArrayDeque` fix the middle calls?

About 5 billion moves, because the call that meets a list of size s shifts s elements, and the sizes run from 0 to 99 999. ArrayDeque makes pushFront constant time, but it has no insert or remove at an index, so a middle call would walk half of the elements.

Inserting at index i of an ArrayList of size s moves the s - i elements behind it. A front call moves all s elements, and a middle call moves about s / 2. Each call therefore costs O(s), and q calls cost O(q * s), which is quadratic when the list grows with the calls.

A linked list removes the shifting and adds a different cost, because reaching index s / 2 means walking s / 2 links. Both designs pay a linear price for the middle. The shifted elements are not the real waste. The real waste is that the structure forgets where the middle is after every call. A design that remembers the middle position and moves it by one place per call would avoid both prices.

Key idea

Two Containers Share The Sequence

Cut The Sequence At The Middle

Store the sequence as two deques placed end to end. The first deque holds the left half, and the second holds the right half. Read left to right, the left half followed by the right half is the logical sequence. The place where the two meet is the boundary, and it is the middle of the sequence.

For a sequence of size s, the left half holds exactly s / 2 elements (integer division) and the right half holds the rest. The two halves therefore differ in size by at most one, and the right half is the larger one when s is odd. With this rule, the front of the sequence is the first element of the left half, the back is the last element of the right half, and the middle sits at the boundary. Every end of interest is an end of a deque.

Move One Element To Rebalance

Each push or pop changes the size by one, so the rule left = s / 2 can break by one element only. A rebalance moves one element across the boundary. If the left half is longer than the right half, its last element moves to the front of the right half. If the right half has two more elements than the left half, its first element moves to the back of the left half. The order of the logical sequence does not change, because the element stays next to the boundary on both sides of the move.

A middle push inserts at index s / 2, which is the end of the left half. A middle pop removes index (s - 1) / 2. For an even s that is the last element of the left half, and for an odd s it is the first element of the right half. Each call is one deque operation plus at most one rebalance move, so each call costs O(1).

State

State Kept In The Two Halves

The structure keeps two fields, left and right, and no counters, because ArrayDeque.size() already reports each length in constant time.

  • left is the deque that holds the first s / 2 elements, in sequence order.
  • right is the deque that holds the last s - s / 2 elements, in sequence order.
  • s is a derived total size, equal to left.size() + right.size().
  • boundary is a derived index left.size(), the first index that belongs to the right half.

The state invariant is that right.size() - left.size() is 0 or 1 after every public call returns. During a call the difference can be off by one for a moment, and only the private rebalance method repairs it. No public method moves elements between the halves on its own, which keeps that repair in one place.

Code

Implementing The Six Calls

The Class With One Rebalance Method

The code below keeps the two halves in ArrayDeque fields. The private method shiftBoundary performs the rebalance from the insight, and every public method calls it last. The names leftHalf and rightHalf mean the left half and the right half.

final class SplitQueue {
    private final Deque<Integer> leftHalf = new ArrayDeque<>();
    private final Deque<Integer> rightHalf = new ArrayDeque<>();

    // The only method that moves an element between the halves.
    private void shiftBoundary() {
        if (leftHalf.size() > rightHalf.size()) rightHalf.addFirst(leftHalf.removeLast());
        else if (rightHalf.size() > leftHalf.size() + 1) leftHalf.addLast(rightHalf.removeFirst());
    }

    void pushFront(int v)  { leftHalf.addFirst(v); shiftBoundary(); }
    void pushMiddle(int v) { leftHalf.addLast(v);  shiftBoundary(); }
    void pushBack(int v)   { rightHalf.addLast(v); shiftBoundary(); }

    int popFront() {
        if (rightHalf.isEmpty()) return -1;
        int v = leftHalf.isEmpty() ? rightHalf.removeFirst() : leftHalf.removeFirst();
        shiftBoundary();
        return v;
    }

    int popMiddle() {
        if (rightHalf.isEmpty()) return -1;
        int v = leftHalf.size() == rightHalf.size() ? leftHalf.removeLast() : rightHalf.removeFirst();
        shiftBoundary();
        return v;
    }

    int popBack() {
        if (rightHalf.isEmpty()) return -1;
        int v = rightHalf.removeLast();
        shiftBoundary();
        return v;
    }
}

Cost And Java Details

  • Every call costs O(1) time, because it makes one or two deque operations and at most one move.
  • Memory is O(n) for the elements and O(1) beyond them.

The empty test in every pop reads only rightHalf. That is enough because the invariant keeps rightHalf at least as long as leftHalf, so it is empty only when the whole sequence is empty. The methods removeFirst and removeLast throw NoSuchElementException on an empty deque, so the guard must run before them.

When to use it

When To Split A Sequence

Recognizing The Pattern

Use two containers when the operations name several fixed logical positions, such as the front, the middle and the back, and each call changes the size by one. The cue is a statement that asks for a push or pop "in the middle" at constant cost. Before writing code, state the invariant in words: the left half holds s / 2 elements, the sequence is the left half followed by the right half, and one private method restores that after each call. Then decide which middle a pop removes when the size is even, and write that choice into a test.

The same idea covers a second family of problems that look different. A set of bounded stacks needs the leftmost stack with free space, and the rightmost stack with an element. Each of the two questions, which stack is writable and which stack holds an element, needs its own ordered index, and the two indexes must stay consistent after every call.

The False Friend

A single ArrayDeque looks sufficient, because it serves both ends in constant time. It is a false friend. The Deque interface has no access by index, so reaching the middle means iterating over half of the elements. A doubly linked list with a pointer to the middle node also works, but every end call must also move that pointer, and the even-size rule must be applied in each of six methods. Two deques keep that rule in one method.

When Not To Use It

Do not split when the operations insert at arbitrary indexes, because the boundary then needs to jump far, and an order-statistic tree or a rope serves that case. Do not split when only the two ends are used, since one ArrayDeque is simpler. Do not split when the calls must run from several threads, because a move between the halves is two operations that another thread could observe half-finished.

Balanced Two-Deque Sequence

Author exercise

Problem Specification. Implement a class BalancedSequence that stores a sequence of integers in two deques, left followed by right. It supports pushFront(v), which inserts v before every element, and pushBack(v), which inserts v after every element. The method sizes() returns the array {left.size(), right.size()}, and toArray() returns the whole sequence in order. After every call, right.size() - left.size() must be 0 or 1.

Input Constraints. The limits are:

  • Calls number at most 10^5, and v is any int.
  • Empty sequence returns {0, 0} from sizes() and an empty array from toArray().
  • Balance holds after each call, not only at the end.
  • Values v are stored as given, with duplicates allowed.

Example 1. Input calls pushBack(1), pushBack(2), pushFront(0), pushBack(3). Output toArray() is [0,1,2,3] and sizes() is [2,2].

Example 2. Input calls pushFront(7), pushFront(6), pushBack(8), pushBack(9), pushBack(10). Output toArray() is [6,7,8,9,10] and sizes() is [2,3]. The right half holds the extra element.

Prerequisites. The left half, the right half and the single rebalance move from this lesson.

What This Exercise Changes. Basic case: the sequence is split at the middle once, and each end insertion triggers at most one rebalance move.

Hint

After one insertion the sizes are off by one. Which end of which deque crosses the boundary to repair each of the two kinds of imbalance?

Algorithmic Solution (attempt the problem first)

Approach. The sequence is the left deque followed by the right deque. Each push touches one end of one deque: pushFront adds to the front of the left deque, and pushBack adds to the back of the right deque. That single insertion leaves the sizes off by one element in one direction only. A private method rebalance then repairs it. If the left deque is longer, its last element becomes the first element of the right deque. If the right deque is two elements longer, its first element becomes the last element of the left deque. A move across the boundary keeps the order of the whole sequence, because the moved element stays adjacent to the same neighbours.

The invariant is that right.size() - left.size() is 0 or 1 whenever a public method returns. Equivalently, the left deque holds exactly size / 2 elements. Only rebalance moves elements between the deques, so the repair lives in one place and the push methods cannot disagree about it.

Complexity.

  • Time is O(1) per push, because each call makes one deque insertion and at most one move.
  • Space is O(n) for the n stored elements, with O(1) extra per call; toArray allocates O(n) only when it is called.
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;
import java.util.Random;

public final class BalancedSequenceBuild {
    /** Sequence stored as the left deque followed by the right deque. */
    static final class BalancedSequence {
        // Left deque holds the first size() / 2 elements, in sequence order.
        private final Deque<Integer> left = new ArrayDeque<>();
        // Right deque holds the remaining elements, so it is never smaller than left.
        private final Deque<Integer> right = new ArrayDeque<>();

        /**
         * Restores the invariant right.size() - left.size() in {0, 1} after one insertion.
         * Time: O(1), because at most one element moves between the deques.
         * Space: O(1), because no new container is created.
         * Invariant: the sequence order left + right is unchanged by the move.
         */
        private void rebalance() {
            // The left deque is too long by one: its last element becomes the first of the right deque.
            if (left.size() > right.size()) right.offerFirst(left.pollLast());
            // The right deque is too long by two: its first element becomes the last of the left deque.
            else if (right.size() > left.size() + 1) left.offerLast(right.pollFirst());
        }

        /** Inserts v before every element. Time: O(1). Space: O(1). Invariant: rebalance runs before returning. */
        void pushFront(int v) {
            // The new element becomes the first element of the left deque.
            left.offerFirst(v);
            // Insertion can leave left one element too long.
            rebalance();
        }

        /** Inserts v after every element. Time: O(1). Space: O(1). Invariant: rebalance runs before returning. */
        void pushBack(int v) {
            // The new element becomes the last element of the right deque.
            right.offerLast(v);
            // Insertion can leave right two elements longer than left.
            rebalance();
        }

        /** Returns {left size, right size}. Time: O(1). Space: O(1). */
        int[] sizes() {
            // Deque.size() is constant time for ArrayDeque.
            return new int[] {left.size(), right.size()};
        }

        /** Returns the whole sequence in order. Time: O(n). Space: O(n). */
        int[] toArray() {
            // Copy left first, then right, which is the sequence order.
            List<Integer> all = new ArrayList<>(left);
            all.addAll(right);
            int[] res = new int[all.size()];
            // One pass unboxes each element.
            for (int i = 0; i < res.length; i++) res[i] = all.get(i);
            return res;
        }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise: four calls leave two elements in each deque.
        BalancedSequence s = new BalancedSequence();
        s.pushBack(1); s.pushBack(2); s.pushFront(0); s.pushBack(3);
        if (!Arrays.equals(s.toArray(), new int[] {0, 1, 2, 3}) || !Arrays.equals(s.sizes(), new int[] {2, 2})) throw new AssertionError("example 1");
        // Example 2: odd total size puts the extra element in the right deque.
        s = new BalancedSequence();
        s.pushFront(7); s.pushFront(6); s.pushBack(8); s.pushBack(9); s.pushBack(10);
        if (!Arrays.equals(s.toArray(), new int[] {6, 7, 8, 9, 10}) || !Arrays.equals(s.sizes(), new int[] {2, 3})) throw new AssertionError("example 2");
        // An empty sequence has two empty deques.
        if (!Arrays.equals(new BalancedSequence().sizes(), new int[] {0, 0})) throw new AssertionError("empty");
        // Random comparison with a plain list; the invariant is checked after every call.
        Random rnd = new Random(3601L);
        for (int t = 0; t < 2000; t++) {
            BalancedSequence b = new BalancedSequence();
            List<Integer> oracle = new ArrayList<>();
            for (int i = rnd.nextInt(30); i > 0; i--) {
                int v = rnd.nextInt(100);
                // The oracle inserts at index 0 or at the end, which is the definition of the two calls.
                if (rnd.nextBoolean()) { b.pushFront(v); oracle.add(0, v); } else { b.pushBack(v); oracle.add(v); }
                int[] sz = b.sizes();
                if (sz[1] - sz[0] != 0 && sz[1] - sz[0] != 1) throw new AssertionError("unbalanced");
                if (sz[0] != oracle.size() / 2) throw new AssertionError("boundary position");
            }
            int[] got = b.toArray();
            for (int i = 0; i < got.length; i++) if (got[i] != oracle.get(i)) throw new AssertionError("order");
            if (got.length != oracle.size()) throw new AssertionError("length");
        }
    }

Which half ends at index size / 2 before a middle push, and which half holds the element at index (size - 1) / 2 for each parity of the size?

Algorithmic Solution (attempt the problem first)

Approach. The same two deques now serve six calls. A middle push inserts at index size / 2, which equals the length of the left deque, so the value goes to the back of the left deque. A middle pop removes index (size - 1) / 2. When the sizes are equal, the size is even and that index is the last element of the left deque, which is the frontmost of the two middle elements. When the right deque is longer, the size is odd and the middle is the first element of the right deque. Front and back pops take the first element of the left deque (or of the right deque when the left deque is empty) and the last element of the right deque.

The invariant is that the left deque holds size / 2 elements after each call. The test for an empty queue reads the right deque only, because that deque is empty exactly when the whole queue is empty.

Complexity.

  • Time is O(1) per call, because each call does one deque operation and at most one move in rebalance.
  • Space is O(n) for n stored elements, with no extra memory per call.
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;
import java.util.Random;

public final class FrontMiddleBackQueue {
    // Left deque holds the first size() / 2 elements; right deque holds the rest.
    private final Deque<Integer> left = new ArrayDeque<>();
    private final Deque<Integer> right = new ArrayDeque<>();

    /**
     * Restores right.size() - left.size() in {0, 1}; the single owner of cross-deque moves.
     * Time: O(1), because at most one element moves. Space: O(1).
     * Invariant: the order left + right never changes.
     */
    private void rebalance() {
        // Left too long: its last element joins the front of right.
        if (left.size() > right.size()) right.offerFirst(left.pollLast());
        // Right too long: its first element joins the back of left.
        else if (right.size() > left.size() + 1) left.offerLast(right.pollFirst());
    }

    /** Inserts at index 0. Time: O(1). Space: O(1). */
    void pushFront(int v) { left.offerFirst(v); rebalance(); }

    /** Inserts at index size() / 2, which is the end of the left deque. Time: O(1). Space: O(1). */
    void pushMiddle(int v) { left.offerLast(v); rebalance(); }

    /** Appends at the end. Time: O(1). Space: O(1). */
    void pushBack(int v) { right.offerLast(v); rebalance(); }

    /** Removes index 0, or returns -1 when empty. Time: O(1). Space: O(1). */
    int popFront() {
        // Empty check first: the polls below would return null and unboxing would throw.
        if (left.isEmpty() && right.isEmpty()) return -1;
        // A single element lives in the right deque, so the left deque can be empty.
        int v = left.isEmpty() ? right.pollFirst() : left.pollFirst();
        rebalance();
        return v;
    }

    /**
     * Removes index (size - 1) / 2, the first of the two middle elements when size is even; -1 when empty.
     * Time: O(1). Space: O(1).
     */
    int popMiddle() {
        if (left.isEmpty() && right.isEmpty()) return -1;
        // Equal sizes: the frontmost middle is the last of left. Odd size: the middle is the first of right.
        int v = left.size() == right.size() ? left.pollLast() : right.pollFirst();
        rebalance();
        return v;
    }

    /** Removes the last element, or returns -1 when empty. Time: O(1). Space: O(1). */
    int popBack() {
        // The right deque holds the extra element, so it is empty only when the whole queue is empty.
        if (right.isEmpty()) return -1;
        int v = right.pollLast();
        rebalance();
        return v;
    }

    /** Reference queue: one list, with the middle indexes written out by their definitions. Time: O(n) per call. */
    static final class Oracle {
        final List<Integer> a = new ArrayList<>();
        void pushFront(int v) { a.add(0, v); }
        void pushMiddle(int v) { a.add(a.size() / 2, v); }
        void pushBack(int v) { a.add(v); }
        int popFront() { return a.isEmpty() ? -1 : a.remove(0); }
        int popMiddle() { return a.isEmpty() ? -1 : a.remove((a.size() - 1) / 2); }
        int popBack() { return a.isEmpty() ? -1 : a.remove(a.size() - 1); }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        FrontMiddleBackQueue q = new FrontMiddleBackQueue();
        q.pushFront(1); q.pushBack(2); q.pushBack(3); q.pushMiddle(4); q.pushMiddle(5);
        int[] got = {q.popMiddle(), q.popMiddle(), q.popFront(), q.popBack(), q.popMiddle(), q.popMiddle()};
        int[] want = {5, 4, 1, 3, 2, -1};
        for (int i = 0; i < want.length; i++) if (got[i] != want[i]) throw new AssertionError("example 1 at " + i);
        // Example 2: with two middle elements, popMiddle removes the frontmost one.
        q = new FrontMiddleBackQueue();
        q.pushFront(1); q.pushBack(2); q.pushMiddle(3); q.pushMiddle(4);
        if (q.popMiddle() != 4 || q.popBack() != 2 || q.popFront() != 1 || q.popMiddle() != 3) throw new AssertionError("example 2");
        // Java claim behind the empty guard: ArrayDeque.pollFirst returns null when empty.
        if (new ArrayDeque<Integer>().pollFirst() != null) throw new AssertionError("poll on empty");
        // Java claim behind the guard in the pop methods: removeFirst on an empty deque throws NoSuchElementException.
        try { new ArrayDeque<Integer>().removeFirst(); throw new AssertionError("no exception"); } catch (java.util.NoSuchElementException expected) { }
        // Random sequences of all six calls, checked against the oracle after every call.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 3000; t++) {
            FrontMiddleBackQueue f = new FrontMiddleBackQueue();
            Oracle o = new Oracle();
            for (int i = rnd.nextInt(40); i > 0; i--) {
                int op = rnd.nextInt(6), v = 1 + rnd.nextInt(1000);
                switch (op) {
                    case 0 -> { f.pushFront(v); o.pushFront(v); }
                    case 1 -> { f.pushMiddle(v); o.pushMiddle(v); }
                    case 2 -> { f.pushBack(v); o.pushBack(v); }
                    case 3 -> { if (f.popFront() != o.popFront()) throw new AssertionError("popFront"); }
                    case 4 -> { if (f.popMiddle() != o.popMiddle()) throw new AssertionError("popMiddle"); }
                    default -> { if (f.popBack() != o.popBack()) throw new AssertionError("popBack"); }
                }
                // Boundary check: the left deque always holds exactly size / 2 elements.
                if (f.left.size() != o.a.size() / 2 || f.right.size() != o.a.size() - o.a.size() / 2) throw new AssertionError("balance");
            }
        }
    }

Edge Cases

Oscillating Empty Halves

Author exercise

Problem Specification. A sequence starts empty. The array ops lists operations in order: a positive value v inserts v at index size / 2, and the value 0 removes the element at index (size - 1) / 2. Return an array of the removed values in the order of removal, using -1 for a removal from an empty sequence. Keep the sequence in two deques whose sizes differ by at most one after every operation, including when the sequence becomes empty and refills.

Input Constraints. The limits are:

  • Operations number at most 10^5, and 1 <= v <= 10^9.
  • Empty input returns an empty array.
  • Removal from empty appends -1 and changes no state.
  • Balance holds after each operation, including at size 0 and size 1.

Example 1. Input ops = [1,2,0,0,0,3,0], output [2,1,-1,3]. The sequence after the first two inserts is [2,1], and it empties and refills once.

Example 2. Input ops = [1,2,3,4,0,0,0,0,0], output [4,3,2,1,-1]. The sequence [2,4,3,1] shrinks one middle element at a time.

Prerequisites. The Design Front Middle Back Queue exercise above.

What This Exercise Changes. The workload shifts from growth to repeated removal at the boundary, so the empty and single-element states are visited many times.

Hint

At size 1 the left half is empty. Which half supplies the middle, and what does the next insertion see when both halves are empty?

Algorithmic Solution (attempt the problem first)

Approach. The risky states are size 0 and size 1. At size 1 the left deque is empty and the only element is the first of the right deque, so a middle removal must read the right deque and leave both deques empty. At size 0 the removal reports -1 and leaves the state alone. When the sizes are equal and non-zero, the middle is the last element of the left deque. After each operation the size changes by at most one, so one call to rebalance is always enough, including the first insertion into two empty deques: the new element goes to the left deque and crosses to the right deque at once.

The invariant is that the left deque holds size / 2 elements after every operation. The random test in main removes more often than it inserts, so the sequence visits the empty state many times, and it checks the balance after each run and compares the removed values with a single-list oracle.

Complexity.

  • Time is O(q) for q operations, because each operation does constant work and at most one move.
  • Space is O(n) for the live elements plus O(r) for the r returned values.
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Deque;
import java.util.List;
import java.util.Random;

public final class OscillatingHalves {
    // Left deque holds the first size / 2 elements, right deque the rest.
    static final Deque<Integer> left = new ArrayDeque<>();
    static final Deque<Integer> right = new ArrayDeque<>();

    /**
     * Moves at most one element so that right.size() - left.size() is 0 or 1.
     * Time: O(1). Space: O(1).
     * Invariant: the order left + right is unchanged.
     */
    static void rebalance() {
        // Left holds one element too many.
        if (left.size() > right.size()) right.offerFirst(left.pollLast());
        // Right holds two elements more than left.
        else if (right.size() > left.size() + 1) left.offerLast(right.pollFirst());
    }

    /**
     * Applies the operations: a positive value inserts at index size / 2, zero removes index (size - 1) / 2.
     * Returns the removed values in order, with -1 for a removal from an empty sequence.
     * Time: O(q) for q operations, because each operation does O(1) work and moves at most one element.
     * Space: O(n) for the sequence and O(r) for the r removed values.
     * Invariant: after every operation, left.size() equals size / 2.
     */
    static int[] run(int[] ops) {
        left.clear();
        right.clear();
        List<Integer> removed = new ArrayList<>();
        // One pass over the operations; each costs O(1).
        for (int op : ops) {
            if (op > 0) {
                // Insertion at index size / 2 is the end of the left deque.
                left.offerLast(op);
            } else if (left.isEmpty() && right.isEmpty()) {
                // Both deques empty: nothing to remove, report -1.
                removed.add(-1);
            } else if (left.size() == right.size()) {
                // Even size: the frontmost middle is the last element of left.
                removed.add(left.pollLast());
            } else {
                // Odd size: the middle is the first element of right, and left may be empty (size 1).
                removed.add(right.pollFirst());
            }
            // Every operation changes the size by one, so one move restores the invariant.
            rebalance();
        }
        int[] res = new int[removed.size()];
        for (int i = 0; i < res.length; i++) res[i] = removed.get(i);
        return res;
    }

    /** Reference: one list with the indexes from the definition. Time: O(q * n). Space: O(n). */
    static int[] oracle(int[] ops) {
        List<Integer> a = new ArrayList<>(), removed = new ArrayList<>();
        for (int op : ops) {
            if (op > 0) a.add(a.size() / 2, op);
            else removed.add(a.isEmpty() ? -1 : a.remove((a.size() - 1) / 2));
        }
        return removed.stream().mapToInt(Integer::intValue).toArray();
    }

    public static void main(String[] args) {
        // Example 1: the sequence empties twice and refills.
        if (!Arrays.equals(run(new int[] {1, 2, 0, 0, 0, 3, 0}), new int[] {2, 1, -1, 3})) throw new AssertionError("example 1");
        // Example 2: removals from a four-element sequence drain it to empty and past it.
        if (!Arrays.equals(run(new int[] {1, 2, 3, 4, 0, 0, 0, 0, 0}), new int[] {4, 3, 2, 1, -1})) throw new AssertionError("example 2");
        // After a drain both deques are empty, which is the state the next insertion must start from.
        if (!left.isEmpty() || !right.isEmpty()) throw new AssertionError("not empty after drain");
        // Random runs with many removals so the sequence hovers around empty.
        Random rnd = new Random(3603L);
        for (int t = 0; t < 5000; t++) {
            int[] ops = new int[rnd.nextInt(40)];
            for (int i = 0; i < ops.length; i++) ops[i] = rnd.nextInt(5) < 2 ? 1 + rnd.nextInt(50) : 0;
            if (!Arrays.equals(run(ops), oracle(ops))) throw new AssertionError("mismatch " + Arrays.toString(ops));
            // The final state must satisfy the balance invariant too.
            if (right.size() - left.size() < 0 || right.size() - left.size() > 1) throw new AssertionError("final balance");
        }
    }

Dinner Plate Stacks

LeetCode 1172

Problem Specification. Implement DinnerPlates(capacity), an unbounded row of stacks numbered from 0, each holding at most capacity values. The call push(val) places val on the stack with the smallest index that is not full. The call pop() removes and returns the top value of the stack with the largest index that is not empty, or -1 when all stacks are empty. The call popAtStack(index) removes and returns the top value of stack index, or -1 when that stack is empty or index is beyond every stack used so far.

Input Constraints. The limits are:

  • Capacity is 1 <= capacity <= 2 * 10^4.
  • Values satisfy 1 <= val <= 2 * 10^4.
  • Index satisfies 0 <= index <= 10^5.
  • Calls number at most 2 * 10^5.

Example 1. Input capacity = 2 and pushes of 1 to 5, which build [1,2], [3,4], [5]. The call popAtStack(0) returns 2, then push(20) and push(21) fill stack 0 and stack 2. The calls pop, popAtStack(1), pop, pop, pop, pop give the output 21, 4, 5, 3, 20, 1.

Example 2. Input capacity = 1 and pushes of 7 and 8, which build [7], [8]. The call popAtStack(0) returns 7, and push(9) refills stack 0. Then popAtStack(5), pop, pop, pop give the output -1, 8, 9, -1.

Prerequisites. The Oscillating Empty Halves exercise above.

What This Exercise Changes. There is no single middle. Two ordered positions, the leftmost writable stack and the rightmost non-empty stack, play the role of the boundary.

Hint

Which index must a push find, and which must a pop find? State the order of each index set and how an entry leaves it before choosing a TreeSet or a PriorityQueue.

Algorithmic Solution (attempt the problem first)

Approach. Two queries need two orders. A push needs the smallest index among stacks with room, so the structure keeps a TreeSet of those indexes, ordered ascending. A pop needs the largest index among non-empty stacks, which is the last stack in the list once empty stacks at the end are trimmed. The stale-entry policy is that the set is exact: an index is in the set if and only if its stack exists and is not full. A push removes the index when the stack becomes full, a pop at a stack adds the index back, and trimming a stack from the end also removes its index from the set. With no stale entries, first() is always a valid target and no lazy skipping is needed.

The invariant ties the list and the set together after every call. Trimming is safe because an empty trailing stack behaves the same as a missing one: a later push would create it again at the same index.

Complexity.

  • Time is O(log s) per call for s stacks, because the set operations are logarithmic and each stack is trimmed at most once after it is created.
  • Space is O(n + s) for n stored values and the set of at most s indexes.
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;
import java.util.Random;
import java.util.TreeSet;

public final class DinnerPlates {
    // Stack i is stacks.get(i); a stack is bounded by capacity.
    private final int capacity;
    private final List<Deque<Integer>> stacks = new ArrayList<>();
    // Ordering: ascending stack index. Policy: holds exactly the indexes of existing stacks that are not full, with no stale entries.
    private final TreeSet<Integer> writable = new TreeSet<>();

    DinnerPlates(int capacity) { this.capacity = capacity; }

    /**
     * Pushes onto the leftmost stack that is not full.
     * Time: O(log s) for s stacks, because TreeSet.first and remove are logarithmic. Space: O(1) extra.
     * Invariant: writable holds every non-full stack index and nothing else.
     */
    void push(int val) {
        // No writable stack: create the next stack and register it as writable.
        if (writable.isEmpty()) {
            stacks.add(new ArrayDeque<>());
            writable.add(stacks.size() - 1);
        }
        // The smallest writable index is the leftmost stack with room.
        int i = writable.first();
        stacks.get(i).push(val);
        // A stack that just became full leaves the set, which keeps the set exact.
        if (stacks.get(i).size() == capacity) writable.remove(i);
    }

    /**
     * Pops from the rightmost non-empty stack, or returns -1.
     * Time: amortized O(log s), because each stack is trimmed once after it was created. Space: O(1).
     */
    int pop() {
        // Trim trailing empty stacks, and drop them from the set so no entry refers to a removed stack.
        while (!stacks.isEmpty() && stacks.get(stacks.size() - 1).isEmpty()) {
            writable.remove(stacks.size() - 1);
            stacks.remove(stacks.size() - 1);
        }
        if (stacks.isEmpty()) return -1;
        return popAtStack(stacks.size() - 1);
    }

    /**
     * Pops from stack index, or returns -1 when the index is out of range or the stack is empty.
     * Time: O(log s). Space: O(1).
     * Invariant: after the pop the stack is not full, so its index is in writable.
     */
    int popAtStack(int index) {
        // Index beyond the list means the stack was never created or was trimmed, so it is empty.
        if (index >= stacks.size() || stacks.get(index).isEmpty()) return -1;
        int v = stacks.get(index).pop();
        // Add is idempotent for a TreeSet, so a stack that was already writable stays listed once.
        writable.add(index);
        return v;
    }

    /** Reference: unbounded list of lists scanned linearly. Time: O(s) per call. Space: O(total elements). */
    static final class Oracle {
        final int cap;
        final List<List<Integer>> st = new ArrayList<>();
        Oracle(int cap) { this.cap = cap; }
        void push(int v) {
            for (List<Integer> s : st) if (s.size() < cap) { s.add(v); return; }
            List<Integer> s = new ArrayList<>();
            s.add(v);
            st.add(s);
        }
        int pop() {
            for (int i = st.size() - 1; i >= 0; i--) if (!st.get(i).isEmpty()) return st.get(i).remove(st.get(i).size() - 1);
            return -1;
        }
        int popAtStack(int i) {
            if (i >= st.size() || st.get(i).isEmpty()) return -1;
            return st.get(i).remove(st.get(i).size() - 1);
        }
    }

    public static void main(String[] args) {
        // Example 1: capacity 2; a hole at stack 0 is refilled before a new stack is opened.
        DinnerPlates d;
        d = new DinnerPlates(2);
        for (int v = 1; v <= 5; v++) d.push(v);
        if (d.popAtStack(0) != 2) throw new AssertionError("ex1 a");
        d.push(20); d.push(21);
        int[] want = {21, 4, 5, 3, 20, 1};
        int[] seq = {d.pop(), d.popAtStack(1), d.pop(), d.pop(), d.pop(), d.pop()};
        for (int i = 0; i < want.length; i++) if (seq[i] != want[i]) throw new AssertionError("ex1 at " + i);
        // Example 2: capacity 1; an out-of-range index and an emptied structure both return -1.
        d = new DinnerPlates(1);
        d.push(7); d.push(8);
        if (d.popAtStack(0) != 7) throw new AssertionError("ex2 a");
        d.push(9);
        if (d.popAtStack(5) != -1 || d.pop() != 8 || d.pop() != 9 || d.pop() != -1) throw new AssertionError("ex2 b");
        // Random sequences against the oracle, with small capacities so stacks fill and empty often.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 3000; t++) {
            int cap = 1 + rnd.nextInt(3);
            DinnerPlates f = new DinnerPlates(cap);
            Oracle o = new Oracle(cap);
            for (int i = rnd.nextInt(60); i > 0; i--) {
                int op = rnd.nextInt(5), v = 1 + rnd.nextInt(100);
                if (op <= 1) { f.push(v); o.push(v); }
                else if (op == 2) { if (f.pop() != o.pop()) throw new AssertionError("pop"); }
                else { int idx = rnd.nextInt(5); if (f.popAtStack(idx) != o.popAtStack(idx)) throw new AssertionError("popAtStack"); }
                // The set must equal the non-full indexes exactly: no stale and no missing entries.
                TreeSet<Integer> expect = new TreeSet<>();
                for (int k = 0; k < f.stacks.size(); k++) if (f.stacks.get(k).size() < cap) expect.add(k);
                if (!expect.equals(f.writable)) throw new AssertionError("stale or missing entry");
            }
        }
    }

Problem

A Forward Button That Shows Deleted Pages

A user opens a browser on the homepage, visits pages A, B and C, and presses the back button twice. The browser now shows page A. The user then types the address of page D and opens it. The forward button must now be disabled, because the user left the old path. A buggy history still offers B, and pressing it jumps to a page that no longer belongs to the visible path.

The same failure appears in a text editor that offers undo and redo. After two undo steps, a new keystroke must erase the redo steps. Each of these classes receives a long sequence of calls, and every answer depends on the calls that came before it. The lesson asks one question. Which stored values must the class keep so that back, forward and a new visit stay correct and cheap?

Simple approach

Copying The Path On Every Visit

The direct method keeps a list of pages and an index of the current page. A visit that only appends to the end of the list is wrong, because the new page lands after C while the index still points at A. A correct version rebuilds the list from the pages up to the current one, adds the new page, and moves the index to it.

final class SnapshotHistory {
    private java.util.List<String> pages = new java.util.ArrayList<>();
    private int at; // index of the page on screen

    SnapshotHistory(String homepage) { pages.add(homepage); }

    void visit(String url) {
        java.util.List<String> next = new java.util.ArrayList<>(pages.subList(0, at + 1));
        next.add(url);
        pages = next;
        at++;
    }

    String back(int steps) { at = Math.max(0, at - steps); return pages.get(at); }

    String forward(int steps) { at = Math.min(pages.size() - 1, at + steps); return pages.get(at); }
}

For the visit sequence above, the list after the second back press is [home, A, B, C] with at = 1. The visit of D builds [home, A, D], so forward from D finds nothing. The method is correct and easy to read.

Bottleneck

Counting The Copied Entries

Predict first: A user visits 100 000 pages in a row and never presses back. About how many list entries does the copying visit method move in total, and are any of those copies ever read again?

About 5 billion entries, because the visit number i copies i entries and the sum of 1 to 100 000 is roughly 5 * 10^9. The old list is discarded after each copy, so none of the copied entries is read again.

A history with n pages makes every visit copy up to n entries, so n visits cost O(n^2) time. A text editor that stores a full snapshot of the text after each keystroke is worse. A document of length L costs O(L) per keystroke and O(L) extra memory per kept snapshot.

The work has a precise waste. The pages after the current index are the ones the visit discards, and nothing reads them again. The pages before the current index do not change at all, yet the method copies them. Removing the discarded pages one by one also costs time proportional to how many were discarded. The next section shows that the class needs neither the copy nor the removal.

Key idea

One Array And Two Numbers

Keep Elements And A Cursor

Store the pages in one array that never gets rebuilt. Keep one integer called the cursor, which is the index of the page on screen. The array and the cursor together define what the user sees, so back and forward only change the cursor and write nothing.

Hide The Dead Future With A Count

Keep a second integer called the live length, which is the number of array slots that belong to the current path. Slots at index live length and above are dead: they hold old pages that no call may return. A visit moves the cursor one slot to the right, writes the new page into that slot, and sets the live length to cursor plus 1. The write overwrites one old slot, and the new live length hides every slot after it. Nothing is deleted, so a visit costs O(1) time.

Clamp Every Move

A request to go back 100 steps from slot 2 cannot move past slot 0. The clamp limits a target index to the legal range. Back uses the larger of 0 and cursor minus steps. Forward uses the smaller of live length minus 1 and cursor plus steps. The clamp never touches the array, so an oversized request cannot corrupt the history. The stored array and the cursor keep describing one consistent path after every call.

State

State Kept Between Calls

The class keeps three fields and one rule that connects them.

  • items is the array of pages; slots from live length upward may hold stale pages.
  • cursor is the index of the page on screen, always between 0 and live length minus 1.
  • live length is the count of slots that belong to the current path, at least 1 after the constructor.

The state invariant is that the visible path is exactly items[0..live length), the page on screen is items[cursor], and no public call reads a slot at index live length or above. Visit, back and forward each end with this statement true again.

Tracing Back, Visit And Clamping

The step count here is small, and each call changes at most one slot and two integers.

Oversized Moves On The Same State

The second trace starts from the final state of the first one. A forward(5) request would target slot 7, so the clamp stops the cursor at slot 2, the last live slot. A back(9) request would target a negative slot, so the clamp stops the cursor at slot 0. A forward(1) then moves to slot 1, and a visit of E overwrites slot 2.

The trace shows the stale page C in slot 3 through every step. The clamp never lets the cursor reach it, and the visit never needs to erase it. Both facts follow from the same rule: the cursor stays below the live length.

Code

Browser History With A Cursor

The Class

The class stores the pages in a growable array. The field liveLength holds the live length from the trace, and cursor holds the cursor. Growing the array when it is full costs O(1) amortized per visit.

final class CursorHistory {
    private String[] items = new String[8];
    private int cursor;      // slot of the page on screen
    private int liveLength;  // slots 0..liveLength-1 form the current path

    CursorHistory(String homepage) { items[0] = homepage; liveLength = 1; }

    void visit(String url) {
        if (cursor + 1 == items.length) items = java.util.Arrays.copyOf(items, items.length * 2);
        items[++cursor] = url;   // overwrite one old slot
        liveLength = cursor + 1; // everything after it becomes dead
    }

    String back(int steps) { cursor = Math.max(0, cursor - steps); return items[cursor]; }

    String forward(int steps) { cursor = Math.min(liveLength - 1, cursor + steps); return items[cursor]; }
}

Cost And Java Details

  • visit costs O(1) amortized time, because a doubling copy happens after every doubling number of visits.
  • back and forward cost O(1) time and read one slot.

Stale references stay in memory until a later visit overwrites them, so a very long history that shrinks holds pages longer than needed. Setting dead slots to null would free them but costs time proportional to the number discarded, so the design keeps them. The expression cursor + steps can overflow when steps is near Integer.MAX_VALUE, which the Boundary exercise below addresses.

When to use it

When Cursor And Live Length Apply

Recognizing The Pattern

Use this design when a class supports moving through past states and a new write must discard part of the future. The statement usually says back, forward, undo or redo, and it says that a new action clears what lies ahead. The invariant to state before coding is that the stored elements and the cursor jointly define the visible state, with every slot at or above the live length unreadable.

Two False Friends

A stack looks like the natural tool for back, because back pops the latest page. It is a false friend here, since forward needs the popped pages, which forces a second stack that a visit must empty. The array with a cursor expresses the same behavior with two integers and no moving of elements.

A text editor with a movable caret is a second false friend. Its caret also sits inside stored elements, yet the caret divides the text into a part before it and a part after it, and an insert at the caret changes the middle of the sequence. No slot range plus one cursor describes that state, so the Recognize exercise below keeps the text in two parts.

When Not To Use It

Do not use it when the user can branch, because a version tree keeps both futures, and truncation would lose one of them. Do not use it when the history must stay bounded by memory, since the array never shrinks without a separate eviction rule. Do not use it for a concurrent class, because two threads can change the cursor and the live length between two reads.

Undoable String Cursor

Author exercise

Problem Specification. Design a class UndoString that stores a text built one character at a time. The constructor takes no arguments and starts with the empty text. append(char c) adds c to the end of the visible text and discards every character that undo had hidden. undo(int k) hides the last k visible characters. redo(int k) shows the k most recently hidden characters again, if no append happened after they were hidden. text() returns the visible text as a String.

Input Constraints. The limits are:

  • Calls number at most 10^5.
  • Undo receives 0 <= k <= the number of visible characters.
  • Redo receives 0 <= k <= the number of hidden characters that may be shown.
  • Characters are lowercase English letters and !.
  • Mutation does not occur outside the class.

Example 1. Input calls append('h'), append('i'), append('!'), undo(2), text(), append('o'), text(), undo(1), redo(1), text(). Output of the three text() calls is "h", "ho" and "ho".

Example 2. Input calls append('a'), append('b'), append('c'), append('d'), undo(3), redo(2), text(), append('e'), text(), undo(4), text(). Output of the three text() calls is "abc", "abce" and "".

Prerequisites. The cursor and live length fields from this lesson.

What This Exercise Changes. Basic case: the stored characters stay in place on undo, and an append overwrites one slot instead of building a new copy of the text.

Hint

Which slot does an append write after an undo, and which number hides the characters that were undone earlier?

Algorithmic Solution (attempt the problem first)

Approach. The class stores characters in one array and keeps two integers. The cursor counts the visible characters, and the liveLength counts the characters that undo may still bring back. Undo lowers the cursor and writes nothing. Redo raises the cursor and writes nothing. An append writes into the slot at the cursor, raises the cursor, and sets the live length equal to the cursor, which hides every character that undo had hidden.

The invariant is that 0 <= cursor <= liveLength <= size of the array, the visible text is items[0..cursor), and the redo candidates are items[cursor..liveLength). The input contract promises legal step counts, so no method needs a clamp here.

Complexity.

  • Time is O(1) amortized for append, undo and redo, and O(cursor) for text() because it copies the visible characters.
  • Space is O(n) for n appended characters, since stale characters stay in the array until a later append overwrites them.
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class UndoStringBuild {
    /** Stores characters once; the visible text is items[0..cursor) and redo candidates are items[cursor..liveLength). */
    static final class UndoString {
        private char[] items = new char[4];
        // Number of visible characters, also the next slot to write.
        private int cursor;
        // Number of slots that undo may still restore.
        private int liveLength;

        /** Time: O(1) amortized, because doubling happens after every doubling number of appends. Space: O(1) extra. Invariant: afterwards liveLength == cursor. */
        void append(char c) {
            // Grow only when the next slot does not exist; this is the only source of copying.
            if (cursor == items.length) items = java.util.Arrays.copyOf(items, items.length * 2);
            // Overwrite the slot at the cursor; a stale character there is lost on purpose.
            items[cursor++] = c;
            // Everything after the new character becomes dead, so redo has nothing to show.
            liveLength = cursor;
        }

        /** Time: O(1). Space: O(1). Invariant: the stored characters do not change. */
        void undo(int k) { cursor -= k; }

        /** Time: O(1). Space: O(1). Invariant: cursor never exceeds liveLength for legal k. */
        void redo(int k) { cursor += k; }

        /** Time: O(cursor) for the copy. Space: O(cursor) for the returned string. Invariant: reads only slots below cursor. */
        String text() { return new String(items, 0, cursor); }
    }

    /**
     * Brute-force oracle that stores a complete snapshot of the text after every append.
     * Time: O(L) per append for the copy. Space: O(n * L) for n snapshots.
     * Invariant: snapshots.get(pos) is the visible text, and snapshots after pos are the redo candidates.
     */
    static final class Oracle {
        // Snapshot 0 is the empty text.
        private List<String> snapshots = new ArrayList<>(List.of(""));
        private int pos;
        void append(char c) {
            // Drop the redo candidates, then add the new snapshot built by concatenation.
            snapshots = new ArrayList<>(snapshots.subList(0, pos + 1));
            snapshots.add(snapshots.get(pos) + c);
            pos++;
        }
        void undo(int k) { pos -= k; }
        void redo(int k) { pos += k; }
        String text() { return snapshots.get(pos); }
    }

    public static void main(String[] args) {
        // First worked example: append after undo drops the hidden characters.
        UndoString u = new UndoString();
        for (char c : "hi!".toCharArray()) u.append(c);
        u.undo(2);
        if (!u.text().equals("h")) throw new AssertionError("undo 2");
        u.append('o');
        if (!u.text().equals("ho")) throw new AssertionError("append after undo");
        u.undo(1);
        u.redo(1);
        if (!u.text().equals("ho")) throw new AssertionError("redo");
        // Second worked example: redo restores part of the hidden text, then an append hides the rest.
        u = new UndoString();
        for (char c : "abcd".toCharArray()) u.append(c);
        u.undo(3);
        u.redo(2);
        if (!u.text().equals("abc")) throw new AssertionError("partial redo");
        u.append('e');
        if (!u.text().equals("abce")) throw new AssertionError("append e");
        u.undo(4);
        if (!u.text().isEmpty()) throw new AssertionError("empty after full undo");
        // Random sequences with legal step counts compared against the snapshot oracle.
        Random rnd = new Random(3601L);
        for (int t = 0; t < 3000; t++) {
            UndoString fast = new UndoString();
            Oracle slow = new Oracle();
            // Shadow counters supply the legal ranges for undo and redo.
            int visible = 0, live = 0;
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(3);
                if (op == 0) {
                    char c = (char) ('a' + rnd.nextInt(3));
                    fast.append(c); slow.append(c);
                    visible++; live = visible;
                } else if (op == 1) {
                    int k = rnd.nextInt(visible + 1);
                    fast.undo(k); slow.undo(k);
                    visible -= k;
                } else {
                    int k = rnd.nextInt(live - visible + 1);
                    fast.redo(k); slow.redo(k);
                    visible += k;
                }
                if (!fast.text().equals(slow.text())) throw new AssertionError("mismatch at trial " + t);
            }
        }
    }

Design Browser History

LeetCode 1472

Problem Specification. Design a class BrowserHistory. The constructor takes a homepage string and shows it. visit(String url) opens url from the current page and removes every page that lay ahead of the current page. back(int steps) moves back by at most steps pages and returns the page now shown. forward(int steps) moves ahead by at most steps pages and returns the page now shown. Movement stops at the oldest or the newest page that is still part of the path.

Input Constraints. The limits are:

  • Homepage and urls have 1 <= length <= 20 lowercase letters, digits and dots.
  • Steps satisfy 1 <= steps <= 100.
  • Calls number at most 5000.
  • Return is the page shown after the call; visit returns nothing.

Example 1. Input: homepage "start.com", then visit("a.com"), visit("b.com"), visit("c.com"), back(1), back(1), visit("d.com"), forward(2), back(3), forward(1). Output of the five navigation calls is "b.com", "a.com", "d.com", "start.com" and "a.com", in that order, with d.com coming from forward(2).

Example 2. Input: homepage "x", then visit("y"), visit("z"), back(5), forward(1), visit("w"), forward(1), back(1), forward(9). Output of the five navigation calls is "x", "y", "w", "y" and "w".

Prerequisites. The Undoable String Cursor exercise above.

What This Exercise Changes. The class stores pages and must discard the forward path on a visit, so a live length joins the cursor.

Hint

After a visit from the middle of the path, which single integer makes the old forward pages unreachable without deleting them?

Algorithmic Solution (attempt the problem first)

Approach. The pages sit in one array. The cursor is the slot of the page on screen, and the liveLength is the number of slots that belong to the current path. Back lowers the cursor but not below 0, and forward raises it but not above liveLength - 1. A visit moves the cursor right by one, writes the url into that slot, and sets the live length to cursor + 1. The write replaces one old page, and the new live length hides every page after it, so the removed forward path needs no deletion.

The invariant is that the shown page is items[cursor], the path is items[0..liveLength), and 0 <= cursor < liveLength after every call. Back and forward cannot break it, because each result is clamped into that range. The visit restores it because the cursor and the live length both end on the same new slot. The array doubles when the next slot does not exist.

Complexity.

  • Time is O(1) amortized per call, because each call changes two integers and at most one slot, and doubling is paid by earlier visits.
  • Space is O(n) for n visited pages, since the array keeps stale pages until later visits overwrite them.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Random;

public final class BrowserHistoryAnchor {
    /** Array plus cursor plus live length; no call deletes or copies the path. */
    static final class BrowserHistory {
        private String[] items = new String[4];
        // Slot of the page on screen.
        private int cursor;
        // Slots 0..liveLength-1 form the current path.
        private int liveLength;

        BrowserHistory(String homepage) { items[0] = homepage; liveLength = 1; }

        /** Time: O(1) amortized. Space: O(1) extra. Invariant: afterwards cursor == liveLength - 1. */
        void visit(String url) {
            // Double the array when the next slot does not exist; this is the only copying.
            if (cursor + 1 == items.length) items = Arrays.copyOf(items, items.length * 2);
            // Move right and overwrite one old slot.
            items[++cursor] = url;
            // Pages that were ahead of the old cursor become unreachable.
            liveLength = cursor + 1;
        }

        /** Time: O(1). Space: O(1). Invariant: the result lies in [0, cursor]. */
        String back(int steps) {
            // Clamp at the oldest page.
            cursor = Math.max(0, cursor - steps);
            return items[cursor];
        }

        /** Time: O(1). Space: O(1). Invariant: the result lies in [cursor, liveLength - 1]. */
        String forward(int steps) {
            // Clamp at the newest live page, never at a stale slot.
            cursor = Math.min(liveLength - 1, cursor + steps);
            return items[cursor];
        }
    }

    /**
     * Brute-force oracle that deletes the forward pages from a list on every visit.
     * Time: O(n) per visit for the removal. Space: O(n).
     * Invariant: the list holds exactly the current path and index is the page on screen.
     */
    static final class Oracle {
        private final List<String> path = new ArrayList<>();
        private int index;
        Oracle(String home) { path.add(home); }
        void visit(String url) {
            // Remove every page after the current one, then append.
            while (path.size() > index + 1) path.remove(path.size() - 1);
            path.add(url);
            index++;
        }
        String back(int steps) { while (steps-- > 0 && index > 0) index--; return path.get(index); }
        String forward(int steps) { while (steps-- > 0 && index < path.size() - 1) index++; return path.get(index); }
    }

    public static void main(String[] args) {
        // First worked example: the visit of d.com removes the forward pages b.com and c.com.
        BrowserHistory h = new BrowserHistory("start.com");
        h.visit("a.com"); h.visit("b.com"); h.visit("c.com");
        if (!h.back(1).equals("b.com") || !h.back(1).equals("a.com")) throw new AssertionError("back twice");
        h.visit("d.com");
        if (!h.forward(2).equals("d.com")) throw new AssertionError("forward after visit");
        if (!h.back(3).equals("start.com")) throw new AssertionError("back clamp");
        if (!h.forward(1).equals("a.com")) throw new AssertionError("forward one");
        // Second worked example: oversized steps stop at the ends of the live path, not at stale slots.
        h = new BrowserHistory("x");
        h.visit("y"); h.visit("z");
        if (!h.back(5).equals("x") || !h.forward(1).equals("y")) throw new AssertionError("x then y");
        h.visit("w");
        if (!h.forward(1).equals("w") || !h.back(1).equals("y") || !h.forward(9).equals("w")) throw new AssertionError("w path");
        // Random sequences compared against the oracle; many visits after back calls exercise truncation.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 3000; t++) {
            BrowserHistory fast = new BrowserHistory("h");
            Oracle slow = new Oracle("h");
            for (int step = 0; step < 60; step++) {
                int op = rnd.nextInt(3);
                int steps = 1 + rnd.nextInt(6);
                if (op == 0) {
                    String url = "p" + rnd.nextInt(1000);
                    fast.visit(url); slow.visit(url);
                } else if (op == 1) {
                    if (!fast.back(steps).equals(slow.back(steps))) throw new AssertionError("back mismatch " + t);
                } else {
                    if (!fast.forward(steps).equals(slow.forward(steps))) throw new AssertionError("forward mismatch " + t);
                }
            }
        }
    }

Oversized Navigation

Author exercise

Problem Specification. Extend UndoString so that undo(int k) and redo(int k) accept any k from 0 to Integer.MAX_VALUE. Each method moves as far as the legal range allows and returns the number of characters it actually hid or showed. An oversized request must not change the stored characters and must not make a later redo or append behave differently from a request of the exact legal size.

Input Constraints. The limits are:

  • Calls number at most 10^5.
  • Steps satisfy 0 <= k <= 2147483647.
  • Return is an int between 0 and the legal range, inclusive.
  • Characters are lowercase English letters.
  • Empty text accepts undo with a return of 0.

Example 1. Input calls append('a'), append('b'), undo(2147483647), text(), redo(2147483647), text(), undo(1), append('c'), redo(5), text(). Output is 2, "", 2, "ab", 1, 0 and "ac" for the calls that return a value.

Example 2. Input calls undo(5) on the empty text, append('z'), redo(2147483647), text(), undo(0). Output is 0, 0, "z" and 0 for the calls that return a value.

Prerequisites. The Undoable String Cursor and Design Browser History exercises above.

What This Exercise Changes. The call returns the distance moved and the arithmetic compares k against the available distance, so no sum overflows.

Hint

What does cursor + k produce in int arithmetic when k is 2147483647, and how can the comparison avoid that sum?

Algorithmic Solution (attempt the problem first)

Approach. Each move computes the distance it can travel before it changes anything. Undo can travel at most cursor characters, and redo can travel at most liveLength - cursor. The moved distance is the smaller of k and that limit. Comparing k with the limit avoids the sum cursor + k, which wraps to a negative int when k is Integer.MAX_VALUE and the cursor is positive. The method then adds or subtracts the moved distance and returns it.

The invariant is the same as in the Build exercise: 0 <= cursor <= liveLength. A move touches only the cursor, so the stored characters and the live length keep their values, and a later append or redo behaves as after an exact request.

Complexity.

  • Time is O(1) per move and amortized O(1) per append.
  • Space is O(n) for n appended characters, because stale slots stay until overwritten.
import java.util.Random;

public final class OversizedNavigation {
    /** Same storage as the Build solution, but moves report the distance actually travelled. */
    static final class UndoString {
        private char[] items = new char[2];
        private int cursor;
        private int liveLength;

        void append(char c) {
            if (cursor == items.length) items = java.util.Arrays.copyOf(items, items.length * 2);
            items[cursor++] = c;
            liveLength = cursor;
        }

        /** Time: O(1). Space: O(1). Invariant: the result is min(k, cursor) and the array is untouched. */
        int undo(int k) {
            // Compare k with the limit instead of computing cursor - k, so no arithmetic can wrap.
            int moved = Math.min(k, cursor);
            cursor -= moved;
            return moved;
        }

        /** Time: O(1). Space: O(1). Invariant: the result is min(k, liveLength - cursor). */
        int redo(int k) {
            // The limit is a small non-negative int; comparing it with k never overflows.
            int moved = Math.min(k, liveLength - cursor);
            cursor += moved;
            return moved;
        }

        String text() { return new String(items, 0, cursor); }
    }

    /**
     * Brute-force oracle that moves one character at a time on a string snapshot list.
     * Time: O(min(k, n)) per move. Space: O(n * L) for the snapshots.
     * Invariant: the loop stops at the edge of the stored range, so the count equals the legal distance.
     */
    static final class Oracle {
        private java.util.List<String> snaps = new java.util.ArrayList<>(java.util.List.of(""));
        private int pos;
        void append(char c) {
            snaps = new java.util.ArrayList<>(snaps.subList(0, pos + 1));
            snaps.add(snaps.get(pos) + c);
            pos++;
        }
        int undo(int k) { int m = 0; while (m < k && pos > 0) { pos--; m++; } return m; }
        int redo(int k) { int m = 0; while (m < k && pos < snaps.size() - 1) { pos++; m++; } return m; }
        String text() { return snaps.get(pos); }
    }

    public static void main(String[] args) {
        // The overflow that the exercise warns about: a positive int plus Integer.MAX_VALUE wraps negative.
        int c = 2;
        if (c + Integer.MAX_VALUE >= 0) throw new AssertionError("expected wraparound");
        // First worked example.
        UndoString u = new UndoString();
        u.append('a'); u.append('b');
        if (u.undo(Integer.MAX_VALUE) != 2 || !u.text().isEmpty()) throw new AssertionError("undo max");
        if (u.redo(Integer.MAX_VALUE) != 2 || !u.text().equals("ab")) throw new AssertionError("redo max");
        if (u.undo(1) != 1) throw new AssertionError("undo 1");
        u.append('c');
        if (u.redo(5) != 0 || !u.text().equals("ac")) throw new AssertionError("redo after append");
        // Second worked example: empty text and zero steps.
        u = new UndoString();
        if (u.undo(5) != 0) throw new AssertionError("undo on empty");
        u.append('z');
        if (u.redo(Integer.MAX_VALUE) != 0 || !u.text().equals("z") || u.undo(0) != 0) throw new AssertionError("redo on live end");
        // Random sequences that mix oversized and small steps compared against the oracle.
        Random rnd = new Random(3603L);
        for (int t = 0; t < 3000; t++) {
            UndoString fast = new UndoString();
            Oracle slow = new Oracle();
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(3);
                // Oversized steps are common, and Integer.MAX_VALUE appears often enough to hit the wrap case.
                int k = rnd.nextInt(4) == 0 ? Integer.MAX_VALUE : rnd.nextInt(6);
                if (op == 0) {
                    char ch = (char) ('a' + rnd.nextInt(3));
                    fast.append(ch); slow.append(ch);
                } else if (op == 1) {
                    if (fast.undo(k) != slow.undo(k)) throw new AssertionError("undo count " + t);
                } else {
                    if (fast.redo(k) != slow.redo(k)) throw new AssertionError("redo count " + t);
                }
                if (!fast.text().equals(slow.text())) throw new AssertionError("text mismatch " + t);
            }
        }
    }

Design a Text Editor

LeetCode 2296

Problem Specification. Design a class TextEditor that holds a text and a caret between two characters. It starts empty with the caret at position 0. addText(String text) inserts text at the caret and leaves the caret after the inserted characters. deleteText(int k) removes up to k characters before the caret and returns the number removed. cursorLeft(int k) and cursorRight(int k) move the caret by up to k positions and return the last min(10, p) characters before the caret, where p is the number of characters before the caret after the move.

Input Constraints. The limits are:

  • Calls number at most 2 * 10^4.
  • Text per addText has 1 <= length <= 40 lowercase letters and digits.
  • Steps satisfy 1 <= k <= 40.
  • Return of the move methods is a String of length at most 10.

Example 1. Input calls addText("hello"), addText("world"), cursorLeft(3), deleteText(4), addText("xyz"), cursorRight(20), cursorLeft(2), deleteText(50), cursorLeft(5). Output is "hellowo", 4, "helxyzrld", "helxyzr", 7 and "" for the calls that return a value.

Example 2. Input calls addText("abcdefghijklmn"), cursorLeft(1), cursorLeft(12), cursorRight(100), deleteText(3), cursorLeft(2). Output is "defghijklm", "a", "efghijklmn", 3 and "abcdefghi" for the calls that return a value.

Prerequisites. The Design Browser History and Oversized Navigation exercises above.

What This Exercise Changes. The visible state is no longer a prefix of one array; the caret splits the text into two parts, and every call touches only the ends beside the caret.

Hint

If the caret splits the text into a left part and a right part, which end of each part does every operation touch?

Algorithmic Solution (attempt the problem first)

Approach. The editor keeps the text in two parts: left holds the characters before the caret in reading order, and right holds the characters after the caret in reverse order. Every operation touches only the end of one part or moves characters between the two ends. Insertion appends to left. Deletion shortens left. Moving the caret left pops characters from the end of left and pushes them onto right, and moving right does the reverse. After a move, the returned context is the last ten characters of left.

The invariant is that left + reverse(right) is the whole text and the caret sits where the two parts meet. Each call preserves it, because a move transfers a character without changing the order of the whole text. The cost of a call is proportional to the characters it moves, which the constraints bound by 40.

Complexity.

  • Time is O(k) for each move and delete, O(length of the added text) for insertion, and O(10) for the returned context.
  • Space is O(n) for the n characters currently held in the two parts.
import java.util.Random;

public final class TextEditorAnchor {
    /** Two StringBuilders; the caret sits between left and the reversed right. */
    static final class TextEditor {
        // Characters before the caret in reading order.
        private final StringBuilder left = new StringBuilder();
        // Characters after the caret, stored in reverse so the nearest one is last.
        private final StringBuilder right = new StringBuilder();

        /** Time: O(len(text)). Space: O(len(text)). Invariant: the caret ends after the new text. */
        void addText(String text) { left.append(text); }

        /** Time: O(1). Space: O(1). Invariant: only characters before the caret are removed. */
        int deleteText(int k) {
            // Cannot remove more than exist before the caret.
            int removed = Math.min(k, left.length());
            // setLength drops the last characters in constant time.
            left.setLength(left.length() - removed);
            return removed;
        }

        /** Time: O(k). Space: O(1) besides the answer. Invariant: left + reverse(right) is unchanged. */
        String cursorLeft(int k) {
            int moved = Math.min(k, left.length());
            // Move one character at a time from the end of left to the end of right.
            for (int i = 0; i < moved; i++) {
                right.append(left.charAt(left.length() - 1));
                left.setLength(left.length() - 1);
            }
            return context();
        }

        /** Time: O(k). Space: O(1) besides the answer. Invariant: left + reverse(right) is unchanged. */
        String cursorRight(int k) {
            int moved = Math.min(k, right.length());
            for (int i = 0; i < moved; i++) {
                left.append(right.charAt(right.length() - 1));
                right.setLength(right.length() - 1);
            }
            return context();
        }

        // The context is at most ten characters, so this copy costs O(10).
        private String context() { return left.substring(Math.max(0, left.length() - 10)); }
    }

    /**
     * Brute-force oracle with one string and an integer caret.
     * Time: O(n) per call for string rebuilding. Space: O(n).
     * Invariant: text.substring(0, caret) is the part before the caret.
     */
    static final class Oracle {
        private String text = "";
        private int caret;
        void addText(String s) { text = text.substring(0, caret) + s + text.substring(caret); caret += s.length(); }
        int deleteText(int k) {
            int m = Math.min(k, caret);
            text = text.substring(0, caret - m) + text.substring(caret);
            caret -= m;
            return m;
        }
        String cursorLeft(int k) { caret -= Math.min(k, caret); return ctx(); }
        String cursorRight(int k) { caret += Math.min(k, text.length() - caret); return ctx(); }
        private String ctx() { return text.substring(Math.max(0, caret - 10), caret); }
    }

    public static void main(String[] args) {
        // First worked example, including a delete larger than the text before the caret.
        TextEditor e = new TextEditor();
        e.addText("hello"); e.addText("world");
        if (!e.cursorLeft(3).equals("hellowo")) throw new AssertionError("left 3");
        if (e.deleteText(4) != 4) throw new AssertionError("delete 4");
        e.addText("xyz");
        if (!e.cursorRight(20).equals("helxyzrld")) throw new AssertionError("right 20");
        if (!e.cursorLeft(2).equals("helxyzr")) throw new AssertionError("left 2");
        if (e.deleteText(50) != 7 || !e.cursorLeft(5).isEmpty()) throw new AssertionError("delete 50");
        // Second worked example: the context shows only ten characters.
        e = new TextEditor();
        e.addText("abcdefghijklmn");
        if (!e.cursorLeft(1).equals("defghijklm")) throw new AssertionError("ten chars");
        if (!e.cursorLeft(12).equals("a")) throw new AssertionError("left 12");
        if (!e.cursorRight(100).equals("efghijklmn")) throw new AssertionError("right 100");
        if (e.deleteText(3) != 3 || !e.cursorLeft(2).equals("abcdefghi")) throw new AssertionError("delete 3");
        // Java behaviour: setLength truncates a StringBuilder in place.
        StringBuilder sb = new StringBuilder("abc");
        sb.setLength(1);
        if (!sb.toString().equals("a")) throw new AssertionError("setLength");
        // Random sequences compared against the oracle.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 3000; t++) {

            Oracle slow = new Oracle();
            for (int step = 0; step < 40; step++) {

                } else {
                    if (!fast.cursorRight(k).equals(slow.cursorRight(k))) throw new AssertionError("right " + t);
                }
            }
        }

Problem

Why Two Clients Share One Session Number

A chat server gives every connected client a session number between 0 and 9 999. When a client disconnects, its cleanup code hands the number back so that a later client can use it. One day a network error runs the cleanup code twice for the same client. Minutes later, two new clients both receive session number 4, and each one starts reading messages meant for the other.

The same failure appears in file descriptor tables, database connection slots, order numbers and block numbers in a memory manager. In each case a fixed set of numbers moves between two states, free and in use. The lesson asks one question. How must the pool store those states so that no number is ever free and in use at once, and so that the next number handed out follows a promised order?

Simple approach

Keeping A List Of Free Numbers

The direct design keeps a list of the free numbers. Allocation finds the smallest number in the list and removes it. Release appends the returned number to the list.

static final java.util.ArrayList<Integer> free = new java.util.ArrayList<>();

static void start(int n) {
    for (int id = 0; id < n; id++) free.add(id);
}

static int allocate() {
    if (free.isEmpty()) return -1;
    int best = 0;
    for (int i = 1; i < free.size(); i++) if (free.get(i) < free.get(best)) best = i;
    return free.remove(best);
}

static void release(int id) {
    free.add(id);
}

With ten numbers, the calls allocate, allocate, release(0), allocate return 0, 1 and then 0 again. The list design is short, it uses memory only for the free numbers, and it gives the right answer when every client releases a number exactly once.

Bottleneck

Counting Duplicates And Scans

Predict first: A client calls release(4) twice for the same session number, and then two new clients call allocate. What do the two clients receive, and what does the list look like?

Both clients receive 4 if 4 is the smallest number in the list. The second release appended a second copy of 4, and allocate removes only one copy per call. The list holds a number that is free twice, which contradicts the rule that each number has exactly one state.

The list cannot detect the second release, because the only way to learn whether a number is already present is to scan the whole list. Adding that scan makes release cost O(n) in the list length. The allocation scan also costs O(n) per call.

For a pool of 100 000 numbers, allocating every one of them reads 100 000, then 99 999, then 99 998 list entries, and so on. That sum is about 5 billion comparisons, which is O(n^2) over n calls. The cost comes from searching a list for two facts, whether a number is present and which number is smallest.

The deeper problem is that the list answers a question about states only by searching. A state lookup for one specific number should cost O(1). The next section stores the state of each number at the position that the number itself names.

Key idea

Storing One State Per Number

One Free Flag For Each Number

Store a boolean array free of length n. The entry free[id] is true exactly when id is available, so each number has one free flag and therefore exactly one state. A number cannot be free twice, because a flag holds a single value.

Release That Ignores A Second Call

A release is idempotent release when repeating the same call leaves the pool unchanged. The method reads free[id] first. When the flag is already true, or when id lies outside 0 to n - 1, the method changes nothing and returns false. Only a number whose flag is false becomes free, and the method returns true. The duplicate cleanup call from the opening therefore has no effect.

A Scan Start For The Smallest Free Number

Allocation must return the smallest free number. A field low stores the scan start: every number below low is known to be in use, so allocation begins its scan at low and never reads those entries. When allocation finds the free number id, it sets the flag to false and moves low to id + 1. When release frees a number smaller than low, it moves low back to that number, because a free number now exists below the old scan start.

The scan start keeps allocation fast when releases are rare, since the scan reads only entries that were not yet visited. The worst case stays O(n) per call, for example when a client repeatedly frees the last number and the first number. That cost is acceptable here, and the Vary exercise below removes it with an increasing frontier and a sorted set.

State

State Kept Between Calls

The pool stores three fields that together describe one logical state.

  • n is the number of identifiers, fixed by the constructor.
  • free is the boolean array where free[id] is true when id is available.
  • low is the scan start, the smallest index that may hold a true flag.

The invariant holds before and after every public call: for every id below low, free[id] is false. An allocation that returns id leaves free[id] false. A release that returns true leaves free[id] true and low <= id. A call that returns false changes none of the three fields. A call that returns -1 leaves every flag unchanged and only moves low to free.length, which the invariant allows because every flag is already false.

Walkthrough

Tracing Allocations And Releases

A Pool Of Five Numbers

The first trace uses a pool with n = 5. The pointer id marks the number a call returns or touches, and the pointer low marks the scan start. The variable free lists the numbers whose flag is true after the call.

Three allocations return 0, 1 and 2, and each one moves low just past the number it returns. The call release(1) sets the flag of 1 to true and moves low back from 3 to 1. The next allocation scans from 1, finds it free at once and returns 1. Two more allocations return 3 and 4. The final allocation scans from 5 and reads nothing, so it returns -1 and the pool is exhausted without any state change.

A Duplicate Release In A Pool Of Four

The second trace uses a pool with n = 4 and repeats the failure from the opening. After allocations of 0 and 1, the call release(1) returns true and moves low back to 1. The second release(1) finds the flag already true, so it returns false and changes nothing. The call release(7) names a number outside the pool and also returns false.

The following allocations return 1, 2 and 3, each exactly once, and the last allocation returns -1. In the list design two of those results would have been the same number. The flag array makes that outcome impossible, because every returned number needed a true flag at the moment of allocation.

Code

Allocating And Releasing With Flags

The Pool Class

The class below follows the three fields from the variables stage. The loop in allocate starts at low, and the guard in release implements the idempotent rule.

final class IdPool {
    private final boolean[] free;
    private int low;

    IdPool(int n) {
        free = new boolean[n];
        java.util.Arrays.fill(free, true);
        low = 0;
    }

    int allocate() {
        for (int id = low; id < free.length; id++) {
            if (free[id]) {
                free[id] = false;
                low = id + 1;
                return id;
            }
        }
        low = free.length;
        return -1;
    }

    boolean release(int id) {
        if (id < 0 || id >= free.length || free[id]) return false;
        free[id] = true;
        low = Math.min(low, id);
        return true;
    }
}

Cost And Java Details

  • allocate costs O(n) time in the worst case and O(1) when low points at a free number.
  • release costs O(1) time, because it reads and writes one array entry.
  • Memory is O(n), with one byte-sized flag per number in the usual JVM layout.

The bounds check comes before the array read, because free[-1] or free[7] on a pool of four would throw an ArrayIndexOutOfBoundsException. The || operator skips the right side once the left side is true, so the order of the three tests matters.

When to use it

When A Pool Of Flags Applies

Recognizing The Pattern

Use this design when a fixed set of identifiers moves between free and in use, when release can arrive twice or arrive for a number that was never issued, and when the statement names the order in which freed numbers return. Phrases such as the smallest available number, release a number only once or reject an unknown number point here.

State the invariant before coding: every identifier is in exactly one state, and every helper that changes one field changes the others in the same call. Check that each public method leaves the invariant true on its failure paths as well as its success path.

Two False Friends

A list or queue of free numbers is the first false friend. It supplies an order and a cheap removal, but it cannot reject a duplicate, because it holds no per-number state. A priority queue has the same gap: it returns the smallest entry, yet two equal entries are both legal inside it. A flag array supplies the state check, while the order structure supplies the choice, and a pool that needs fast ordered choice keeps both and keeps them consistent.

A counter that only counts how many numbers are free is the second false friend. It cannot tell which numbers are free, so a second release of the same number raises the count above the real total.

When Not To Use It

Do not allocate a flag array when the identifier range is huge and few numbers are ever issued, such as ranges up to 10^9. Store an increasing frontier plus a sorted set of returned values instead. Do not use it when the freed units must form contiguous runs, as in a memory allocator, because a single flag cannot tell whether a block of the needed length is free.

Reusable ID Pool

Author exercise

Problem Specification. Design a class IdPool for identifiers 0 to n - 1. The constructor IdPool(int n) marks every identifier free. The method allocate() marks the smallest free identifier in use and returns it, or returns -1 when none is free. The method release(int id) returns true and marks id free when id is in use. It returns false and changes nothing when id is free or outside 0 to n - 1.

Input Constraints. The limits are:

  • Pool size is 1 <= n <= 10^5.
  • Calls number at most 10^5 per pool.
  • Identifiers passed to release are any int value.
  • Return is -1 for an exhausted pool and a boolean for release.

Example 1. Input constructor argument n = 3 and the calls allocate, allocate, release(0), allocate, allocate, allocate, output 0, 1, true, 0, 2, -1.

Example 2. Input constructor argument n = 2 and the calls release(1), allocate, release(0), release(0), release(5), release(-1), allocate, output false, 0, true, false, false, false, 0.

Prerequisites. The free flag, the scan start and the idempotent release rule from this lesson.

What This Exercise Changes. Basic case: the pool stores one state per identifier in an array and rejects a release by reading that entry.

Hint

Which single array entry answers whether a release is a duplicate, and which field tells allocation where to start reading?

Algorithmic Solution (attempt the problem first)

Approach. The pool keeps one boolean per identifier, so every identifier has exactly one state. A second field low records a scan start: every index below it holds a false flag. Allocation reads flags from low upward, takes the first true flag, clears it and moves low past it. When the scan reaches the end, it sets low to n and returns -1, so the next failed call starts at the end and reads nothing.

Release first checks the range and then the flag. A number outside the pool or already free returns false before any write, which makes the call idempotent. A valid release sets the flag and lowers low to the released number when that number is smaller, which restores the invariant that no true flag sits below low.

Complexity.

  • Time is O(n) per allocate in the worst case, because a scan may cross many in-use entries, and O(1) per release, because it touches one entry.
  • Space is O(n), because the array holds one flag per identifier and the other fields are single ints.
import java.util.HashSet;
import java.util.Random;
import java.util.Set;

public final class ReusableIdPool {
    private final boolean[] free;
    private int low;

    /**
     * Creates a pool of identifiers 0 to n - 1, all free.
     * Time: O(n), because every flag is written once.
     * Space: O(n), because one flag exists per identifier.
     * Invariant: no flag below low is true.
     */
    ReusableIdPool(int n) {
        // One flag per identifier; the allocation of the array costs O(n) space.
        free = new boolean[n];
        // Every identifier starts free, written in one pass of n steps.
        java.util.Arrays.fill(free, true);
        // The scan start is 0 because index 0 may be free.
        low = 0;
    }

    /**
     * Returns the smallest free identifier and marks it in use, or -1 when none is free.
     * Time: O(n) worst case, because the scan can cross every in-use entry.
     * Space: O(1), because only an index is stored.
     * Invariant: after the call, no flag below low is true.
     */
    int allocate() {
        // The loop starts at low, so entries known to be in use are never read again.
        for (int id = low; id < free.length; id++) {
            // The first true flag is the smallest free identifier, because smaller entries are false.
            if (free[id]) {
                // Mark the identifier in use so that a later call cannot return it.
                free[id] = false;
                // Everything up to id is now in use, so the next scan begins just after it.
                low = id + 1;
                // The caller receives the identifier exactly once.
                return id;
            }
        }
        // The scan found nothing; moving low to n makes the next failure cost nothing.
        low = free.length;
        // The pool is exhausted and no field except low changed.
        return -1;
    }

    /**
     * Returns true and frees id when id is in use; returns false and changes nothing otherwise.
     * Time: O(1), because one entry is read and at most one is written.
     * Space: O(1), because no structure grows.
     * Invariant: a repeated call with the same id returns false the second time.
     */
    boolean release(int id) {
        // The range test runs first, so the array is never read at an invalid index; a free flag means a duplicate.
        if (id < 0 || id >= free.length || free[id]) return false;
        // The identifier becomes available again.
        free[id] = true;
        // A free entry now exists at id, so the scan start cannot stay above it.
        low = Math.min(low, id);
        // The caller learns that the release took effect.
        return true;
    }

    /**
     * Oracle with a set of identifiers in use and a full scan from 0.
     * Time: O(n) per allocate, because the scan always starts at 0.
     * Space: O(n), because the set can hold every identifier.
     * Invariant: an identifier is free exactly when the set does not contain it.
     */
    static final class Oracle {
        private final int n;
        private final Set<Integer> used = new HashSet<>();
        Oracle(int n) { this.n = n; }
        int allocate() {
            // Try every identifier in increasing order; the first one not in use is the smallest free.
            for (int id = 0; id < n; id++) if (used.add(id)) return id;
            return -1;
        }
        boolean release(int id) {
            // Removing from the set reports whether the identifier was in use; an invalid id was never added.
            return used.remove(id);
        }
    }

    public static void main(String[] args) {
        // The first worked example: reuse of 0 after release, then exhaustion.
        ReusableIdPool a = new ReusableIdPool(3);
        if (a.allocate() != 0 || a.allocate() != 1 || !a.release(0) || a.allocate() != 0 || a.allocate() != 2 || a.allocate() != -1)
            throw new AssertionError("example 1");
        // The second worked example: release before allocation, duplicate release and out-of-range release.
        ReusableIdPool b = new ReusableIdPool(2);
        if (b.release(1) || b.allocate() != 0 || !b.release(0) || b.release(0) || b.release(5) || b.release(-1) || b.allocate() != 0)
            throw new AssertionError("example 2");
        // Release order does not matter: the smallest free identifier always comes first.
        ReusableIdPool c = new ReusableIdPool(4);
        for (int i = 0; i < 4; i++) c.allocate();
        c.release(3);
        c.release(1);
        if (c.allocate() != 1 || c.allocate() != 3 || c.allocate() != -1) throw new AssertionError("order");
        // A failed allocation leaves the pool usable.
        c.release(2);
        if (c.allocate() != 2) throw new AssertionError("after exhaustion");
        // Random operation sequences compared with the oracle, including invalid and duplicate releases.
        Random rnd = new Random(3601L);
        for (int t = 0; t < 4000; t++) {
            int n = 1 + rnd.nextInt(8);
            ReusableIdPool p = new ReusableIdPool(n);
            Oracle o = new Oracle(n);
            for (int step = 0; step < 40; step++) {
                // Half of the calls allocate and half release a number that may be invalid.
                if (rnd.nextBoolean()) {
                    if (p.allocate() != o.allocate()) throw new AssertionError("allocate mismatch");
                } else {
                    int id = rnd.nextInt(n + 4) - 2;
                    if (p.release(id) != o.release(id)) throw new AssertionError("release mismatch");
                }
            }
        }
    }

Smallest Number in Infinite Set

Problem Specification. Design a class SmallestInfiniteSet that holds every positive integer at first. The method popSmallest() removes the smallest integer in the set and returns it. The method addBack(int num) inserts num into the set when the set does not hold it, and does nothing otherwise.

Input Constraints. The limits are:

  • Value num satisfies 1 <= num <= 1000.
  • Calls number at most 1000 per set.
  • Duplicates in addBack leave the set unchanged.
  • Return of popSmallest is always an existing positive integer.

Example 1. Input the calls popSmallest, popSmallest, popSmallest, addBack(1), popSmallest, popSmallest, output 1, 2, 3, null, 1, 4.

Example 2. Input the calls addBack(7), popSmallest, popSmallest, addBack(2), addBack(2), popSmallest, popSmallest, output null, 1, 2, null, null, 2, 3.

Prerequisites. The Reusable ID Pool exercise above.

What This Exercise Changes. The range changes from a fixed array to an unbounded frontier, so only values below the frontier need stored state.

Hint

Every integer at or above some frontier value was never removed. Which removed integers are smaller than that frontier, and which structure returns the smallest of them?

Algorithmic Solution (attempt the problem first)

Approach. Every integer at or above the integer frontier was never removed, so the set stores nothing for them. Every integer below frontier is either still removed or has been added back, and a TreeSet named returned holds exactly the added-back ones. The method popSmallest takes the smallest element of returned when that set is not empty, because every value in it is smaller than frontier. Otherwise it returns frontier and increments it.

The method addBack inserts num only when num < frontier, because a larger value is already in the set implicitly. The TreeSet ignores a second insertion of the same value, so a duplicate addBack changes nothing. The invariant is that the set equals the union of returned and all integers from frontier upward, with returned holding only values below frontier.

Complexity.

  • Time is O(log k) per call, where k is the size of returned, because the tree set orders its entries.
  • Space is O(k), because only the added-back values below the frontier are stored.
import java.util.Random;
import java.util.TreeSet;

public final class InfiniteSetFrontier {
    private int frontier = 1;
    private final TreeSet<Integer> returned = new TreeSet<>();

    /**
     * Removes and returns the smallest integer in the set.
     * Time: O(log k), because pollFirst on a tree set is logarithmic.
     * Space: O(1) extra, because at most one element leaves or the frontier moves by one.
     * Invariant: every element of returned is below frontier.
     */
    int popSmallest() {
        // A returned value is always smaller than the frontier, so it wins when one exists.
        if (!returned.isEmpty()) return returned.pollFirst();
        // Otherwise the frontier is the smallest present integer; the post-increment advances it past the removed one.
        return frontier++;
    }

    /**
     * Inserts num into the set when it is absent.
     * Time: O(log k), because a tree set insertion is logarithmic.
     * Space: O(1) extra, because at most one element is added.
     * Invariant: returned never holds a value at or above frontier, and never holds a value twice.
     */
    void addBack(int num) {
        // A value at or above the frontier is still in the set, so nothing needs storing.
        if (num < frontier) returned.add(num);
    }

    /** Oracle: a flag array that marks removed integers and scans from 1. Time: O(limit) per pop. Space: O(limit). */
    static final class Oracle {
        private final boolean[] removed = new boolean[5000];
        int popSmallest() {
            // The first integer not removed is the smallest present one.
            int x = 1;
            while (removed[x]) x++;
            removed[x] = true;
            return x;
        }
        void addBack(int num) { removed[num] = false; }
    }

    public static void main(String[] args) {
        // First worked example: pop three, add back 1, pop twice.
        InfiniteSetFrontier s = new InfiniteSetFrontier();
        if (s.popSmallest() != 1 || s.popSmallest() != 2 || s.popSmallest() != 3) throw new AssertionError("pops");
        s.addBack(1);
        if (s.popSmallest() != 1 || s.popSmallest() != 4) throw new AssertionError("after addBack");
        // Second worked example: addBack above the frontier does nothing, and a duplicate addBack stores one copy.
        InfiniteSetFrontier u = new InfiniteSetFrontier();
        u.addBack(7);
        if (u.popSmallest() != 1 || u.popSmallest() != 2) throw new AssertionError("ignored addBack");
        u.addBack(2);
        u.addBack(2);
        if (u.popSmallest() != 2 || u.popSmallest() != 3) throw new AssertionError("duplicate addBack");
        // Random sequences within the statement limits, compared with the oracle.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 3000; t++) {
            InfiniteSetFrontier f = new InfiniteSetFrontier();
            Oracle o = new Oracle();
            for (int step = 0; step < 60; step++) {
                if (rnd.nextInt(3) > 0) {
                    if (f.popSmallest() != o.popSmallest()) throw new AssertionError("pop mismatch");
                } else {
                    int num = 1 + rnd.nextInt(12);
                    f.addBack(num);
                    o.addBack(num);
                }
            }
        }
    }

Design Phone Directory

LeetCode 379

Problem Specification. Design a class PhoneDirectory for numbers 0 to maxNumbers - 1. The method get() returns the available number that has been available longest, assigns it, and returns -1 when none is available. The method check(int number) returns true when number is available. The method release(int number) makes an assigned number available again at the end of the waiting order, and does nothing when number is already available.

Input Constraints. The limits are:

  • Size is 1 <= maxNumbers <= 10^4.
  • Numbers passed to check and release satisfy 0 <= number < maxNumbers.
  • Calls number at most 2 * 10^4 per directory.
  • Initial order is increasing: 0 is available longest, then 1, and so on.

Example 1. Input constructor argument maxNumbers = 3 and the calls get, get, check(0), release(0), check(0), release(0), get, get, get, output 0, 1, false, null, true, null, 2, 0, -1.

Example 2. Input constructor argument maxNumbers = 2 and the calls get, release(1), get, release(1), release(0), get, get, output 0, null, 1, null, null, 1, 0.

Prerequisites. The Reusable ID Pool exercise above.

What This Exercise Changes. The order structure becomes a queue with first-in, first-out reuse, and release must read a separate state array before it touches the queue.

Hint

If release only appends to the waiting order, a second release of the same number appends it twice. What must release read first?

Algorithmic Solution (attempt the problem first)

Approach. The directory keeps two structures that must agree. A queue waiting holds the available numbers in the order in which they became available, and a boolean array assigned holds the state of each number. The method get polls the queue, marks the number assigned and returns it, or returns -1 on an empty queue. The method check reads the flag only.

The method release reads the flag first. When the number is not assigned, the call returns without touching the queue, because appending it again would put one number in the queue twice and a later pair of get calls would return it twice. When the number is assigned, the flag is cleared and the number joins the end of the queue. The invariant is that a number is in waiting exactly once when its flag is false, and not at all when its flag is true.

Complexity.

  • Time is O(1) per call, because the queue and the array both support constant-time operations at the points used.
  • Space is O(maxNumbers), because the queue and the array each hold at most one entry per number.
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;
import java.util.Random;

public final class PhoneDirectoryQueue {
    private final ArrayDeque<Integer> waiting = new ArrayDeque<>();
    private final boolean[] assigned;

    /**
     * Creates a directory in which every number is available, oldest first.
     * Time: O(maxNumbers), because every number is queued once.
     * Space: O(maxNumbers), because the queue and the array hold one entry per number.
     * Invariant: waiting holds the numbers whose assigned flag is false, each exactly once.
     */
    PhoneDirectoryQueue(int maxNumbers) {
        // One flag per number, all false at the start.
        assigned = new boolean[maxNumbers];
        // Queue the numbers in increasing order so that 0 has been available longest.
        for (int i = 0; i < maxNumbers; i++) waiting.add(i);
    }

    /**
     * Assigns and returns the number that has been available longest, or -1.
     * Time: O(1), because polling the head of an ArrayDeque is constant.
     * Space: O(1), because nothing grows.
     * Invariant: the returned number leaves the queue and its flag becomes true in the same call.
     */
    int get() {
        // An empty queue means the directory is exhausted.
        if (waiting.isEmpty()) return -1;
        // The head is the longest-waiting available number.
        int number = waiting.poll();
        // The flag and the queue change together, so the two structures agree.
        assigned[number] = true;
        return number;
    }

    /** Returns true when number is available. Time: O(1). Space: O(1). Invariant: reads the flag only. */
    boolean check(int number) {
        // Available means not assigned.
        return !assigned[number];
    }

    /**
     * Makes number available again unless it already is.
     * Time: O(1), because one flag is read and the queue gains at most one entry.
     * Space: O(1), because at most one entry is added.
     * Invariant: a number is queued only when its flag changes from true to false.
     */
    void release(int number) {
        // A number that is not assigned is already queued, so a second append would duplicate it.
        if (!assigned[number]) return;
        // The flag changes first so a repeated call finds it false.
        assigned[number] = false;
        // The number joins the end of the waiting order.
        waiting.add(number);
    }

    /**
     * Oracle with a plain list that searches for duplicates before adding.
     * Time: O(maxNumbers) per call, because contains scans the list.
     * Space: O(maxNumbers), because the list holds each available number once.
     * Invariant: the list order is the order in which numbers became available.
     */
    static final class Oracle {
        private final List<Integer> order = new ArrayList<>();
        private final int max;
        Oracle(int max) {
            this.max = max;
            for (int i = 0; i < max; i++) order.add(i);
        }
        int get() { return order.isEmpty() ? -1 : order.remove(0); }
        boolean check(int number) { return order.contains(number); }
        void release(int number) {
            // Append only when the number is absent from the available list.
            if (number >= 0 && number < max && !order.contains(number)) order.add(number);
        }
    }

    public static void main(String[] args) {
        // First worked example, including a repeated release that must be ignored.
        PhoneDirectoryQueue d = new PhoneDirectoryQueue(3);
        if (d.get() != 0 || d.get() != 1 || d.check(0)) throw new AssertionError("start");
        d.release(0);
        if (!d.check(0)) throw new AssertionError("check after release");
        d.release(0);
        if (d.get() != 2 || d.get() != 0 || d.get() != -1) throw new AssertionError("order after release");
        // Second worked example: releasing a number that was never assigned changes nothing.
        PhoneDirectoryQueue e = new PhoneDirectoryQueue(2);
        if (e.get() != 0) throw new AssertionError("e0");
        e.release(1);
        if (e.get() != 1) throw new AssertionError("e1");
        e.release(1);
        e.release(0);
        if (e.get() != 1 || e.get() != 0) throw new AssertionError("fifo");
        // Random sequences with many duplicate releases, compared with the oracle.
        Random rnd = new Random(3603L);
        for (int t = 0; t < 4000; t++) {
            int max = 1 + rnd.nextInt(6);
            PhoneDirectoryQueue p = new PhoneDirectoryQueue(max);
            Oracle o = new Oracle(max);
            for (int step = 0; step < 40; step++) {
                int kind = rnd.nextInt(3), number = rnd.nextInt(max);
                if (kind == 0) {
                    if (p.get() != o.get()) throw new AssertionError("get mismatch");
                } else if (kind == 1) {
                    if (p.check(number) != o.check(number)) throw new AssertionError("check mismatch");
                } else {
                    p.release(number);
                    o.release(number);
                }
            }
        }
    }

LeetCode 2502

Problem Specification. Design a class Allocator for a memory array of n units, all free at first. The method allocate(int size, int mID) finds the lowest start index of a run of size consecutive free units, marks the run as owned by mID, and returns the start, or returns -1 when no run exists. The method freeMemory(int mID) frees every unit owned by mID, including units from several allocations, and returns the number of units freed.

Input Constraints. The limits are:

  • Memory size is 1 <= n <= 1000.
  • Request size satisfies 1 <= size <= 1000.
  • Owner satisfies 1 <= mID <= 1000.
  • Calls number at most 1000 per allocator.

Example 1. Input constructor argument n = 10 and the calls allocate(1,1), allocate(1,2), allocate(1,3), freeMemory(2), allocate(3,4), allocate(1,1), allocate(1,1), freeMemory(1), allocate(4,2), allocate(8,5), output 0, 1, 2, 1, 3, 1, 6, 3, 6, -1.

Example 2. Input constructor argument n = 6 and the calls allocate(2,7), allocate(2,7), allocate(2,8), freeMemory(7), allocate(3,9), freeMemory(7), allocate(3,9), output 0, 2, 4, 4, 0, 0, -1.

Prerequisites. The three exercises above.

What This Exercise Changes. The state per unit changes from a boolean to an owner label, and allocation searches for a run of free units and not for a single one.

Hint

A single free flag per unit cannot name the owner. Which per-unit value records both the free state and the owner, and how does a scan count a run?

Algorithmic Solution (attempt the problem first)

Approach. This is a transfer problem. Each unit stores the owner id, with 0 meaning free, because ids start at 1. Allocation scans left to right and counts the current run of free units. When the count reaches size, the run ends at the current index, so the start is the index minus size - 1, and the method writes the owner into that run. Because the scan runs left to right, the first completed run has the lowest start. Freeing reads every unit once, clears those that match the owner and counts them. A single flag per unit would not work, because the free call must find all blocks of one owner.

The invariant is that every unit has exactly one value, which is free or one owner, and a run found by allocation is entirely free before the write.

Complexity.

  • Time is O(n) per call, because each call scans the array once and writes at most size units.
  • Space is O(n), because the owner array has one int per unit.
import java.util.HashMap;
import java.util.Map;
import java.util.Random;
import java.util.TreeSet;

public final class MemoryAllocatorRuns {
    private final int[] owner;

    /** Creates n free units. Time: O(n). Space: O(n). Invariant: owner[i] is 0 for a free unit. */
    MemoryAllocatorRuns(int n) { owner = new int[n]; }

    /**
     * Allocates the lowest run of size free units to mID, or returns -1.
     * Time: O(n), because one left-to-right scan counts runs.
     * Space: O(1), because only counters are stored.
     * Invariant: run counts consecutive free units ending at the current index.
     */
    int allocate(int size, int mID) {
        // run counts consecutive free units ending at i; it resets at every owned unit.
        int run = 0;
        for (int i = 0; i < owner.length; i++) {
            // A free unit extends the run; an owned unit breaks it.
            run = owner[i] == 0 ? run + 1 : 0;
            // The first index where the run reaches size gives the lowest start.
            if (run == size) {
                int start = i - size + 1;
                // Write the owner into the whole run; this is the only write path.
                for (int j = start; j <= i; j++) owner[j] = mID;
                return start;
            }
        }
        // No run was long enough, including a size larger than n.
        return -1;
    }

    /**
     * Frees every unit owned by mID and returns how many were freed.
     * Time: O(n), because every unit is read once.
     * Space: O(1), because only a counter is stored.
     * Invariant: no unit holds mID after the call.
     */
    int freeMemory(int mID) {
        int freed = 0;
        for (int i = 0; i < owner.length; i++) {
            // Clear only the units owned by mID and count them.
            if (owner[i] == mID) { owner[i] = 0; freed++; }
        }
        return freed;
    }

    /** Oracle: a set of units in use per owner, with a start-by-start test. Time: O(n * size) per allocate. Space: O(n). */
    static final class Oracle {
        private final int n;
        private final Map<Integer, TreeSet<Integer>> units = new HashMap<>();
        Oracle(int n) { this.n = n; }
        private boolean used(int u) {
            for (TreeSet<Integer> s : units.values()) if (s.contains(u)) return true;
            return false;
        }
        int allocate(int size, int mID) {
            for (int s = 0; s + size <= n; s++) {
                boolean ok = true;
                // Every unit of the candidate run must be unowned.
                for (int j = s; j < s + size && ok; j++) ok = !used(j);
                if (ok) {
                    TreeSet<Integer> set = units.computeIfAbsent(mID, k -> new TreeSet<>());
                    for (int j = s; j < s + size; j++) set.add(j);
                    return s;
                }
            }
            return -1;
        }
        int freeMemory(int mID) {
            TreeSet<Integer> set = units.remove(mID);
            return set == null ? 0 : set.size();
        }
    }

    public static void main(String[] args) {
        // First worked example: freed units are reused and a request larger than any run fails.
        MemoryAllocatorRuns a = new MemoryAllocatorRuns(10);
        int[] got = {a.allocate(1, 1), a.allocate(1, 2), a.allocate(1, 3), a.freeMemory(2), a.allocate(3, 4),
            a.allocate(1, 1), a.allocate(1, 1), a.freeMemory(1), a.allocate(4, 2), a.allocate(8, 5)};
        int[] want = {0, 1, 2, 1, 3, 1, 6, 3, 6, -1};
        if (!java.util.Arrays.equals(got, want)) throw new AssertionError("example 1");
        // Second worked example: an owner without units frees nothing.
        MemoryAllocatorRuns b = new MemoryAllocatorRuns(6);
        int[] got2 = {b.allocate(2, 7), b.allocate(2, 7), b.allocate(2, 8), b.freeMemory(7), b.allocate(3, 9),
            b.freeMemory(7), b.allocate(3, 9)};
        if (!java.util.Arrays.equals(got2, new int[] {0, 2, 4, 4, 0, 0, -1})) throw new AssertionError("example 2");
        // Random sequences compared with the oracle.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 3000; t++) {
            int n = 1 + rnd.nextInt(12);
            MemoryAllocatorRuns p = new MemoryAllocatorRuns(n);
            Oracle o = new Oracle(n);
            for (int step = 0; step < 30; step++) {
                int id = 1 + rnd.nextInt(4);
                if (rnd.nextBoolean()) {
                    int size = 1 + rnd.nextInt(n + 1);
                    if (p.allocate(size, id) != o.allocate(size, id)) throw new AssertionError("allocate mismatch");
                } else if (p.freeMemory(id) != o.freeMemory(id)) throw new AssertionError("free mismatch");
            }
        }
    }

Problem

Why A Fast Queue Refuses Good Requests

A notification service keeps at most 3 pending send requests in a fixed array. It refuses a request id that is already pending, so no user receives the same message twice. A reviewer writes a fast version that records the id in a hash set first and checks for a full array second. When the array is full, the call returns "full" but the id stays in the set. A slot frees up later, the caller retries the same id, and the service answers "duplicate" for an id that appears nowhere in the queue. The message is never sent.

Each method reads correctly when viewed alone. The defect appears only in a sequence of calls, and it comes from the order of two statements. The question of this lesson is how to choose the fields of a bounded queue with an index, and the order of writes inside each public method, so that both structures describe the same elements after every call, rejected calls included.

What Each Technique Adds

What The Earlier Lessons Contribute

Simple approach

Keeping The Queue In A List

The direct design stores the pending ids in an ArrayList. The call offer scans the list with contains to detect a duplicate, and poll removes the element at position 0.

final class NaiveJobQueue {
    private final java.util.ArrayList<Integer> pending = new java.util.ArrayList<>();
    private final int capacity;

    NaiveJobQueue(int capacity) { this.capacity = capacity; }

    // Returns 0 when accepted, 1 when the queue is full, 2 when the id is already pending.
    int offer(int id) {
        if (pending.contains(id)) return 2;           // linear scan of every pending id
        if (pending.size() == capacity) return 1;     // nothing was written yet, so rejection is safe
        pending.add(id);
        return 0;
    }

    // Returns the oldest id, or -1 when the queue is empty.
    int poll() {
        if (pending.isEmpty()) return -1;
        return pending.remove(0);                     // shifts every remaining element left by one
    }
}

With capacity 3, the calls offer(7), offer(9), offer(7), poll() return 0, 0, 2 and 7. The answers are correct, and a rejected call changes nothing because all checks run before the only write. The cost sits in the two linear operations.

Predict first: The queue has capacity 50,000 and is always full. A caller alternates `poll` and `offer` for 100,000 calls with ids that are never duplicates. About how many element moves or comparisons does the code above make?

Each offer scans all 50,000 pending ids with contains before it adds anything. Each poll shifts about 50,000 elements left by one position. So every call touches roughly 50,000 elements, and 100,000 calls cost about 5 * 10^9 operations. The correctness is fine, and the time is the problem.

Bottleneck

Linear Work And Drifting Indexes

For capacity c, each call of the list version costs O(c) time. With c = 5 * 10^4 and 10^5 calls, that is about 5 * 10^9 steps for a task that needs one decision per call. The cost is easy to place. The duplicate check re-reads every pending id, and the removal at position 0 moves every pending id, although only one id left.

The obvious repair replaces the list with a ring array for order and a hash set for membership. That repair is fast, and it creates a second danger. The array and the set are now two separate records of one fact, namely which ids are pending. Any call that updates one of them, then returns early before updating the other, leaves them disagreeing. The service in the opening example failed in exactly this way.

A correct fix must meet three requirements. First, offer and poll must run in O(1) expected time. Second, the array and the set must list the same ids after every call that returns. Third, a rejected call must leave every field as it found it, so the caller can retry safely.

Key idea

One Window And One Index

The Live Window

The ring array has capacity c, and two integers head and size describe the contents. The live window is the set of slots (head + i) % c for i from 0 to size - 1. A slot belongs to the queue exactly when it lies in the live window. Slots outside it hold stale values that no method reads.

Two rules define the whole representation. First, every queued id sits in exactly one slot of the live window. Second, the hash set holds one entry for each id in the live window and no other entry. The field size is necessary because head and the next write position are equal both for an empty queue and for a full one.

Public Calls Restore The Representation

Inside one call the array and the set change one after the other, so for a short moment they disagree. That moment is allowed only inside a method body. Every public method must end with both rules true again, on every return path, including early returns.

The practical consequence is an order of statements. A method first reads state and runs every check that can reject the call. Only after the last check passes does it write, and the writes contain no further return. The array write, the size update and the set update then happen together, and a later method never sees one without the others.

Rejected Calls Change Nothing

A method reports its outcome with a status code, an integer that the contract defines for each case. In this lesson 0 means accepted, 1 means full and 2 means duplicate. When two rejections apply to the same call, the contract names which one wins. In this lesson the duplicate check comes first.

A call has atomicity when it either completes all of its writes or makes none of them. A rejected call makes none. The next call therefore starts in the same state as if the rejected call had never happened. The observable behavior of the class is then fully described by the status codes and returned values of the call sequence, and the call sequence is the unit that a test checks.

State

Fields And Their Roles

The queue of pending ids uses these fields. Together they represent one logical state, and no method may change one of them without keeping the rest consistent.

  • slots is an int array of length capacity, and only the live window holds meaningful values.
  • head is the index of the oldest element, from 0 to capacity - 1.
  • size is the number of queued ids, from 0 to capacity.
  • queued is a hash set that contains exactly the ids in the live window.
  • tail is a local value (head + size) % capacity computed when needed, never stored, so that it cannot drift.

Ids are non-negative integers, and the value -1 means that poll found an empty queue.

Walkthrough

Following Calls Through Both Collections

A Correct Sequence With Wraparound

The queue has capacity 3. The pointer head marks the oldest slot, and the pointer next marks the slot that the next accepted offer writes. The first two offers fill slots 0 and 1. The third call repeats id 7, so the duplicate check rejects it before any write, and the fields stay as they were.

The offer of 4 fills slot 2, so size is 3 and next wraps back to slot 0. At that moment head and next are both 0, the same pair of values as in an empty queue, and only size tells the two cases apart. The offer of 5 returns status 1 and writes nothing. After poll returns 7, the offer of 5 succeeds and writes slot 0, which holds the stale value 7 until that moment. The last offer of 7 succeeds again, because poll removed 7 from the set.

The Same Calls With The Wrong Order

The second trace uses the version that adds the id to the set before it checks for a full array. After three offers the queue holds 5, 6 and 7. The offer of 8 returns status 1, yet the set now contains 8, so the set holds an entry for an id outside the live window. The poll returns 5 and frees a slot. The retry of 8 returns status 2, although 8 is not queued, and a correct queue would return 0. The disagreement began at one call and surfaced two calls later, which is why a call sequence is the right unit of checking.

Code

Ring Array With A Hash Index

The Queue Class

The constants name the status codes, so callers never compare against bare numbers. The method offer performs both checks before its first write. The method poll reads the oldest id first and then updates the three fields that depend on it.

final class JobQueue {
    static final int OK = 0, FULL = 1, DUPLICATE = 2;
    private final int[] slots;
    private int head, size;
    private final java.util.HashSet<Integer> queued = new java.util.HashSet<>();

    JobQueue(int capacity) { slots = new int[capacity]; }

    // Returns a status code; a non-zero code means no field changed.
    int offer(int id) {
        if (queued.contains(id)) return DUPLICATE;          // the duplicate check wins over the full check
        if (size == slots.length) return FULL;
        slots[(head + size) % slots.length] = id;           // tail slot, one past the live window
        size++;
        queued.add(id);                                     // the set gains exactly the id that the array gained
        return OK;
    }

    // Returns the oldest id, or -1 when the queue is empty.
    int poll() {
        if (size == 0) return -1;
        int id = slots[head];
        head = (head + 1) % slots.length;                   // the old slot leaves the live window
        size--;
        queued.remove(id);                                  // the set loses exactly the id that left
        return id;
    }
}

Cost And Java Details

  • offer costs O(1) expected time, because the hash lookup, the array write and the set insert are constant on average.
  • poll costs O(1) expected time, because the head moves by one and the set removes one entry.
  • Memory is O(c) for the array and the set, and it does not grow with the number of calls.

The expression (head + size) % slots.length never overflows for realistic capacities, because both operands are below the capacity. The set stores Integer objects, so queued.remove(id) with an int argument chooses the overload that removes an element. A List<Integer> would instead treat the same int as an index.

When to use it

When The Composed API Applies

Recognizing The Pattern

Look for a class with a fixed capacity, a front and back discipline, and a second question that the array alone cannot answer fast: is this id present, how many entries have this key, or what is the oldest entry. Look also for a phrase such as "return false and leave the state unchanged". The invariant to state is that every queued element sits in one live slot and one index entry, and every public method restores that pair before it returns.

The Nearest False Friend

The false friend is to know the queue API and to assume that the fields follow from it. A reader who can call a queue still has to decide whether tail is stored, which field separates full from empty, and which write comes first. A class with correct individual methods can fail on a sequence, as the opening example shows. A second false friend is to add a second collection without a rule for which method owns each write, because two owners drift apart.

When Not To Use It

Do not build the ring and the set by hand when the capacity is unbounded or when memory for removals does not matter. A LinkedHashSet already keeps insertion order and membership in one object, and iterator().next() reads the oldest element. The hand-built version earns its place when the capacity is fixed, when the array must not allocate per call, or when the contract needs an index by position as well as by value.

Author exercise

Problem Specification. Design a class BoundedQueue with a constructor BoundedQueue(int capacity). The method int offer(int v) appends v at the back. When the queue already holds capacity elements, it first removes the oldest element and returns that element, and otherwise it returns -1. The method int poll() removes and returns the oldest element, or returns -1 when the queue is empty. The method int size() returns the number of elements. The method int at(int i) returns the i-th oldest element, counting from 0, or -1 when i is outside 0..size-1. Store only slots, head and size.

Input Constraints. These limits apply:

  • Capacity satisfies 1 <= capacity <= 10^5.
  • Values are int values from 0 to 10^9, so -1 is never a stored value.
  • Calls number at most 10^5 in one sequence.
  • Mutation is limited to offer and poll; size and at change nothing.

Example 1. Input capacity 3 and the calls offer(4), offer(5), offer(6), offer(7), at(0), poll(), offer(8), offer(9), output -1, -1, -1, 4, 5, 5, -1, 6.

Example 2. Input capacity 1 and the calls offer(2), offer(3), poll(), poll(), size(), output -1, 2, 3, -1, 0.

Prerequisites. The lesson Circular Buffers. This exercise changes the policy for a full queue: a full offer evicts the oldest element and does not reject.

What This Exercise Changes. A full queue no longer rejects. The oldest slot is overwritten in place, head advances in the same call, and size stays at capacity.

Hint

When the queue is full, which slot holds the oldest element, and which slot receives the new one after head moves?

Algorithmic Solution (attempt the problem first)

Approach. The state is three fields: the array slots, the index head of the oldest element, and the count size. The live window is the size slots that start at head and wrap modulo the capacity. A private method slot(i) owns the arithmetic (head + i) % capacity, so no other method repeats it. A full offer has exactly one extra step compared with a rejecting queue: it reads the oldest value, overwrites that same slot with the new value, and advances head. The slot that held the oldest element is the slot one past the newest element when the window is full, so the write lands in the right place.

The invariant is that after every call, 0 <= size <= capacity and the live window lists the elements from oldest to newest. Each of offer, poll, size and at reads size before it writes, so no branch leaves the fields half updated.

Complexity.

  • Time is O(1) for every method, because each call performs a fixed number of array reads, one modulo operation and one or two integer updates.
  • Space is O(capacity) for the array, with no allocation inside any call.
import java.util.ArrayDeque;
import java.util.Random;

public final class BoundedQueueContract {
    static final class BoundedQueue {
        private final int[] slots;
        private int head, size;

        BoundedQueue(int capacity) { slots = new int[capacity]; }

        /**
         * Maps a position in the live window to an array index.
         * Time: O(1). Space: O(1).
         * Invariant: the result lies in 0..capacity-1 for 0 <= i <= size.
         */
        private int slot(int i) {
            // head + i is below twice the capacity, so one modulo wraps it.
            return (head + i) % slots.length;
        }

        /**
         * Appends v and evicts the oldest element when the queue is full.
         * Time: O(1), because there is no shifting. Space: O(1).
         * Invariant: size never exceeds the capacity after the call.
         */
        int offer(int v) {
            // A full queue evicts the oldest element, which sits in slot head.
            if (size == slots.length) {
                int evicted = slots[head];
                // The new value reuses the evicted slot, which is one past the newest element.
                slots[head] = v;
                // The oldest element is now the one after the evicted slot.
                head = (head + 1) % slots.length;
                return evicted;
            }
            // A non-full queue writes at the first slot past the live window.
            slots[slot(size)] = v;
            size++;
            // Nothing was evicted.
            return -1;
        }

        /**
         * Removes and returns the oldest element, or -1 when empty.
         * Time: O(1). Space: O(1).
         * Invariant: the removed slot leaves the live window, and size drops by one.
         */
        int poll() {
            // An empty queue has no element and changes nothing.
            if (size == 0) return -1;
            int v = slots[head];
            // The window starts one slot later.
            head = (head + 1) % slots.length;
            size--;
            return v;
        }

        // Number of stored elements.

Circular Queue With Status Codes

Problem Specification. Design a class StatusQueue with a constructor StatusQueue(int k) for capacity k. The method int enQueue(int v) returns 0 after appending v, or 1 when the queue is full. The method int deQueue() returns 0 after removing the front, or 1 when the queue is empty. The methods int front() and int rear() return the oldest and newest element, or -1 when the queue is empty. The methods boolean isEmpty() and boolean isFull() report the state. The method int[] snapshot() returns the elements from front to back. A call that returns 1 changes no field.

Input Constraints. These limits apply:

  • Capacity satisfies 1 <= k <= 1000.
  • Values satisfy 0 <= v <= 1000.
  • Calls number at most 3000 in one sequence.
  • Return value of snapshot is a new array of length size.

Example 1. Input capacity 3 and the calls enQueue(1), enQueue(2), enQueue(3), enQueue(4), rear(), isFull(), deQueue(), enQueue(4), snapshot(), output 0, 0, 0, 1, 3, true, 0, 0, [2, 3, 4].

What This Exercise Changes. Rejections become explicit status codes, and snapshot reads the live window so that a caller can compare the state with a model after every call.

Hint

If the class stores only head and size, how does it compute the slot of the newest element?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps slots, head and size, and it never stores a tail index. The newest element lives in slot (head + size - 1) % k, and the next write goes to (head + size) % k. Storing only size to separate full from empty means the two states differ even when head equals the write position. Each mutating method checks its rejection condition first and returns the code 1 before touching any field, so a rejected call has atomicity. An accepted call writes the slot and then updates size or head.

The invariant is that the live window of size slots from head contains the queue from front to back after every call. The method snapshot reads exactly that window into a new array, so a caller can compare the whole queue with a model after each step.

Complexity.

  • Time is O(1) for every method except snapshot, which takes O(size) because it copies each live slot once.
  • Space is O(k) for the array, and snapshot allocates O(size) for its result.
import java.util.ArrayDeque;
import java.util.Arrays;
import java.util.Random;

public final class CircularQueueStatus {
    static final class StatusQueue {
        private final int[] slots;
        private int head, size;

        StatusQueue(int k) { slots = new int[k]; }

        /**
         * Appends v, or returns 1 and changes nothing when full.
         * Time: O(1). Space: O(1).
         * Invariant: a return of 1 leaves head and size equal to their values on entry.
         */
        int enQueue(int v) {
            // Check first: the rejection path writes nothing.
            if (size == slots.length) return 1;
            // The first free slot is one past the live window.
            slots[(head + size) % slots.length] = v;
            size++;
            return 0;
        }

        /**
         * Removes the front, or returns 1 and changes nothing when empty.
         * Time: O(1). Space: O(1).
         * Invariant: the live window shrinks from the front only.
         */
        int deQueue() {
            // Check first: an empty queue has no front to remove.
            if (size == 0) return 1;
            head = (head + 1) % slots.length;
            size--;
            return 0;
        }

        // Oldest element or -1; the slot at head is read only when size is positive.
        int front() { return size == 0 ? -1 : slots[head]; }

        // Newest element or -1; its slot is computed from head and size, with no stored tail.
        int rear() { return size == 0 ? -1 : slots[(head + size - 1) % slots.length]; }

        boolean isEmpty() { return size == 0; }

        boolean isFull() { return size == slots.length; }

        /**
         * Copies the live window from front to back.
         * Time: O(size), one read per live slot. Space: O(size) for the new array.
         * Invariant: the result has length size and does not alias slots.
         */
        int[] snapshot() {
            int[] out = new int[size];
            // Walk the window in order; the index arithmetic wraps past the array end.
            for (int i = 0; i < size; i++) out[i] = slots[(head + i) % slots.length];
            return out;
        }
    }

    public static void main(String[] args) {
        // Example 1: the fourth enQueue is rejected, and the refill after deQueue wraps around.
        StatusQueue q = new StatusQueue(3);
        int[] codes = {q.enQueue(1), q.enQueue(2), q.enQueue(3), q.enQueue(4)};
        if (!Arrays.equals(codes, new int[] {0, 0, 0, 1})) throw new AssertionError("codes");
        if (q.rear() != 3 || !q.isFull() || q.deQueue() != 0 || q.enQueue(4) != 0) throw new AssertionError("example 1");
        if (!Arrays.equals(q.snapshot(), new int[] {2, 3, 4})) throw new AssertionError("snapshot");
        // Example 2: capacity one.
        StatusQueue one = new StatusQueue(1);
        if (one.deQueue() != 1 || one.enQueue(9) != 0 || one.front() != 9 || one.rear() != 9
                || one.deQueue() != 0 || !one.isEmpty() || one.front() != -1) throw new AssertionError("example 2");
        // Random sequences against an ArrayDeque; every step compares the full snapshot.
        Random rnd = new Random(3602L);
        for (int t = 0; t < 3000; t++) {
            int cap = 1 + rnd.nextInt(6);
            StatusQueue a = new StatusQueue(cap);
            ArrayDeque<Integer> model = new ArrayDeque<>();
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(3);
                if (op == 0) {
                    int v = rnd.nextInt(1001);
                    int expect = model.size() == cap ? 1 : 0;
                    if (expect == 0) model.addLast(v);
                    if (a.enQueue(v) != expect) throw new AssertionError("enQueue");
                } else if (op == 1) {
                    int expect = model.isEmpty() ? 1 : 0;
                    if (expect == 0) model.pollFirst();
                    if (a.deQueue() != expect) throw new AssertionError("deQueue");
                }
                // After any call, including rejected ones, the representation must match the model.
                int[] snap = a.snapshot();
                if (snap.length != model.size()) throw new AssertionError("length");
                int i = 0;
                for (int x : model) if (snap[i++] != x) throw new AssertionError("content");
                if (a.front() != (model.isEmpty() ? -1 : model.peekFirst())) throw new AssertionError("front");
                if (a.rear() != (model.isEmpty() ? -1 : model.peekLast())) throw new AssertionError("rear");
                if (a.isFull() != (model.size() == cap) || a.isEmpty() != model.isEmpty()) throw new AssertionError("flags");
            }
        }
    }

Deque Of Capacity One With A Call Log

LeetCode 641

Problem Specification. Design a class LoggedDeque with a constructor LoggedDeque(int k). The methods boolean insertFront(int v), boolean insertLast(int v), boolean deleteFront() and boolean deleteLast() return true when they change the deque and false otherwise. The methods int getFront() and int getRear() return -1 when the deque is empty. The method String log() returns one character for each mutating call so far, in call order: A for an accepted call and R for a rejected call. A rejected call changes the log and no other field.

Input Constraints. These limits apply:

  • Capacity satisfies 1 <= k <= 1000.
  • Values satisfy 0 <= v <= 1000.
  • Calls number at most 2000 in one sequence.
  • Read methods getFront, getRear and log add no character to the log.

Example 1. Input capacity 1 and the calls insertFront(5), insertLast(6), getRear(), deleteLast(), deleteFront(), log(), output true, false, 5, true, false, "ARAR".

Example 2. Input capacity 2 and the calls insertLast(1), insertFront(2), insertFront(3), getFront(), getRear(), deleteLast(), insertLast(4), getRear(), log(), output true, true, false, 2, 1, true, true, 4, "AARAA".

Prerequisites. The second exercise above. This exercise changes the contract of LeetCode 641: the class records one character per mutating call, and the capacity may be 1.

What This Exercise Changes. Both ends write, so insertFront moves head backward with wraparound and insertLast writes past the live window. The log makes each rejected call observable.

Hint

In a deque of capacity one, the front slot and the rear slot are the same slot. Which formula for each end still gives that slot?

Algorithmic Solution (attempt the problem first)

Approach. A deque needs both ends to move. The field head is the slot of the front element, insertLast writes slot (head + size) % k, and insertFront first moves head back to (head - 1 + k) % k and then writes there. The addition of k keeps the operand non-negative, because Java's % returns a negative result for a negative left operand. The rear element sits at (head + size - 1) % k. With capacity one, both formulas give slot 0, so the front and the rear are the same slot and no special case is needed.

Each mutating method decides accepted or rejected first, appends A or R to the log, and writes only on acceptance. The log is a separate field with its own single writer, the private method record. The invariant is that the live window is correct after every call and that the log length equals the number of mutating calls so far.

Complexity.

  • Time is O(1) per call for the deque operations, since each uses one modulo and a few updates, and appending to the log costs O(1) amortized.
  • Space is O(k) for the slots plus O(m) for the log of m mutating calls.
import java.util.ArrayDeque;
import java.util.Random;

public final class DequeCapacityOneLog {
    static final class LoggedDeque {
        private final int[] slots;
        private int head, size;
        private final StringBuilder log = new StringBuilder();

        LoggedDeque(int k) { slots = new int[k]; }

        // The only writer of the log: A for accepted, R for rejected.
        private boolean record(boolean accepted) {
            log.append(accepted ? 'A' : 'R');
            return accepted;
        }

        /**
         * Inserts v before the front, or rejects when full.
         * Time: O(1). Space: O(1).
         * Invariant: head moves back by one slot only when the call is accepted.
         */
        boolean insertFront(int v) {
            // Rejection check precedes every write.
            if (size == slots.length) return record(false);
            // Adding the length keeps the operand non-negative before the modulo.
            head = (head - 1 + slots.length) % slots.length;
            slots[head] = v;
            size++;
            return record(true);
        }

        /**
         * Inserts v after the rear, or rejects when full.
         * Time: O(1). Space: O(1).
         * Invariant: the write slot is the first slot past the live window.
         */
        boolean insertLast(int v) {
            if (size == slots.length) return record(false);
            slots[(head + size) % slots.length] = v;
            size++;
            return record(true);
        }

        /**
         * Removes the front, or rejects when empty.
         * Time: O(1). Space: O(1).
         * Invariant: head moves forward by one slot exactly when the call is accepted.
         */
        boolean deleteFront() {
            if (size == 0) return record(false);
            head = (head + 1) % slots.length;
            size--;
            return record(true);
        }

        /**
         * Removes the rear, or rejects when empty.
         * Time: O(1). Space: O(1).
         * Invariant: only size changes, so head still names the front.
         */
        boolean deleteLast() {
            if (size == 0) return record(false);
            size--;
            return record(true);
        }

        // Front element or -1 when empty.
        int getFront() { return size == 0 ? -1 : slots[head]; }

        // Rear element or -1 when empty.
        int getRear() { return size == 0 ? -1 : slots[(head + size - 1) % slots.length]; }

        // Copy of the log, so the caller cannot change it.
        String log() { return log.toString(); }
    }

    public static void main(String[] args) {
        // Example 1: with capacity one, every second mutating call is rejected.
        LoggedDeque d = new LoggedDeque(1);
        if (!d.insertFront(5) || d.insertLast(6) || d.getRear() != 5 || !d.deleteLast() || d.deleteFront()
                || !d.log().equals("ARAR")) throw new AssertionError("example 1");
        // Example 2: capacity two, inserts at both ends, then a wraparound at the rear.
        LoggedDeque e = new LoggedDeque(2);
        if (!e.insertLast(1) || !e.insertFront(2) || e.insertFront(3) || e.getFront() != 2 || e.getRear() != 1
                || !e.deleteLast() || !e.insertLast(4) || e.getRear() != 4 || !e.log().equals("AARAA"))
            throw new AssertionError("example 2");
        // Java's remainder is negative for a negative left operand, which is why the code adds the length.
        if (-1 % 3 != -1) throw new AssertionError("remainder sign");
        // Random sequences against ArrayDeque, with a model log built from the model's accept decisions.
        Random rnd = new Random(3603L);
        for (int t = 0; t < 3000; t++) {
            int cap = 1 + rnd.nextInt(4);
            LoggedDeque a = new LoggedDeque(cap);
            ArrayDeque<Integer> model = new ArrayDeque<>();
            StringBuilder modelLog = new StringBuilder();
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(6);
                int v = rnd.nextInt(1001);
                boolean expect, got;
                switch (op) {
                    case 0 -> { expect = model.size() < cap; if (expect) model.addFirst(v); got = a.insertFront(v); modelLog.append(expect ? 'A' : 'R'); }
                    case 1 -> { expect = model.size() < cap; if (expect) model.addLast(v); got = a.insertLast(v); modelLog.append(expect ? 'A' : 'R'); }
                    case 2 -> { expect = !model.isEmpty(); if (expect) model.pollFirst(); got = a.deleteFront(); modelLog.append(expect ? 'A' : 'R'); }
                    case 3 -> { expect = !model.isEmpty(); if (expect) model.pollLast(); got = a.deleteLast(); modelLog.append(expect ? 'A' : 'R'); }
                    default -> { expect = got = true; }
                }
                if (expect != got) throw new AssertionError("op " + op);
                // Reads must agree and must not change the log.
                if (a.getFront() != (model.isEmpty() ? -1 : model.peekFirst())) throw new AssertionError("front");
                if (a.getRear() != (model.isEmpty() ? -1 : model.peekLast())) throw new AssertionError("rear");
                if (!a.log().equals(modelLog.toString())) throw new AssertionError("log");
            }
        }
    }

Input Constraints. These limits apply:

  • Memory limit satisfies 2 <= memoryLimit <= 10^5.
  • Source and destination satisfy 1 <= value <= 2 * 10^5.
  • Timestamps satisfy 1 <= timestamp <= 10^9 and never decrease across addPacket calls.
  • Calls number at most 10^5, and startTime <= endTime.

Example 1. Input memory limit 3 and the calls addPacket(1,4,10), addPacket(2,4,10), addPacket(1,4,10), addPacket(3,5,12), addPacket(2,5,13), forwardPacket(), getCount(4,10,10), getCount(5,12,13), output true, true, false, true, true, [2,4,10], 0, 2.

Prerequisites. The first three exercises above and the lesson Store Keys In Direct Slots. This exercise adds a packet identity set and a destination index to a ring that evicts its oldest packet.

What This Exercise Changes. Three collections now describe one packet set. The duplicate check runs before the eviction, because a rejected call may not evict anything.

Hint

Which of the three structures must change when the oldest packet leaves, and in which order should addPacket check for a duplicate and evict?

Algorithmic Solution (attempt the problem first)

Approach. The router has three collections that must describe one packet set. A ring array of records keeps arrival order and evicts the oldest packet. A hash set of records answers the duplicate question. A map from destination to a list of timestamps, with a start offset per destination, answers getCount. Timestamps never decrease across additions, so each destination list is sorted, and two binary searches count the entries in a range. The oldest packet overall is also the oldest packet of its own destination, so removing it moves that destination's offset by one and never needs a deletion in the middle of a list.

Inside addPacket, the duplicate check runs before the eviction. A rejected duplicate then evicts nothing, and the three collections stay unchanged. Every removal goes through one private method drop, which updates the ring, the set and the offset together. The invariant is that the packets in the ring, the records in the set, and the entries from each offset onward in the lists are the same set.

Complexity.

  • Time is O(1) expected for addPacket and forwardPacket, and O(log n) for getCount, where n counts additions to one destination.
  • Space is O(memoryLimit) for the ring and the set, plus O(a) for the lists, because the lists keep consumed entries and hold every accepted addition a.
import java.util.*;

public final class RouterExpiryIndex {
    static final class Router {
        record P(int s, int d, int t) {}
        private final P[] ring;
        private int head, size;
        private final Set<P> seen = new HashSet<>();
        private final Map<Integer, List<Integer>> times = new HashMap<>();
        private final Map<Integer, Integer> lo = new HashMap<>();

        Router(int memoryLimit) { ring = new P[memoryLimit]; }

        /**
         * Adds a packet, evicting the oldest when full; rejects exact duplicates first.
         * Time: O(1) expected. Space: O(1) beyond the stored lists.
         * Invariant: a false return changes no collection.
         */
        boolean addPacket(int s, int d, int t) {
            P p = new P(s, d, t);
            // Reject before any eviction, so a rejected call cannot lose a packet.
            if (seen.contains(p)) return false;
            if (size == ring.length) drop();
            ring[(head + size) % ring.length] = p;
            size++;
            seen.add(p);
            times.computeIfAbsent(d, k -> new ArrayList<>()).add(t);
            return true;
        }

        // Removes the oldest packet from the ring, the set and its destination offset together.
        private P drop() {
            P p = ring[head];
            ring[head] = null;
            head = (head + 1) % ring.length;
            size--;
            seen.remove(p);
            lo.merge(p.d(), 1, Integer::sum);
            return p;
        }

        // Forwards the oldest packet, or returns an empty array when there is none.
        int[] forwardPacket() {
            if (size == 0) return new int[0];
            P p = drop();
            return new int[] {p.s(), p.d(), p.t()};
        }

        /**
         * Counts live packets for d with startTime <= timestamp <= endTime.
         * Time: O(log n) for two binary searches. Space: O(1).
         * Invariant: entries before lo[d] are removed packets and are never counted.
         */
        int getCount(int d, int a, int b) {
            List<Integer> l = times.get(d);
            if (l == null) return 0;
            int from = lo.getOrDefault(d, 0);
            return lower(l, b + 1, from) - lower(l, a, from);
        }

        // First index at or after from whose value is at least x.
        private static int lower(List<Integer> l, int x, int from) {
            int lo = from, hi = l.size();
            while (lo < hi) {
                int mid = (lo + hi) >>> 1;
                if (l.get(mid) < x) lo = mid + 1; else hi = mid;
            }
            return lo;
        }
    }

    // Brute force: a plain list of live packets scanned on every query.
    static final class Oracle {
        private final int limit;
        private final ArrayList<int[]> live = new ArrayList<>();
        Oracle(int limit) { this.limit = limit; }
        boolean add(int s, int d, int t) {
            for (int[] p : live) if (p[0] == s && p[1] == d && p[2] == t) return false;
            if (live.size() == limit) live.remove(0);
            live.add(new int[] {s, d, t});
            return true;
        }
        int[] forward() { return live.isEmpty() ? new int[0] : live.remove(0); }
        int count(int d, int a, int b) {
            int c = 0;
            for (int[] p : live) if (p[1] == d && p[2] >= a && p[2] <= b) c++;
            return c;
        }
    }

    public static void main(String[] args) {
        // Example 1: duplicate rejected, eviction on the fifth add, then forward and two queries.
        Router r = new Router(3);
        if (!r.addPacket(1, 4, 10) || !r.addPacket(2, 4, 10) || r.addPacket(1, 4, 10) || !r.addPacket(3, 5, 12)
                || !r.addPacket(2, 5, 13)) throw new AssertionError("example 1 adds");
        if (!Arrays.equals(r.forwardPacket(), new int[] {2, 4, 10}) || r.getCount(4, 10, 10) != 0
                || r.getCount(5, 12, 13) != 2) throw new AssertionError("example 1 reads");
        // Example 2: eviction moves the destination offset, so the old timestamp is no longer counted.
        Router q = new Router(2);
        if (!q.addPacket(7, 1, 5) || !q.addPacket(8, 1, 6) || q.getCount(1, 5, 6) != 2 || !q.addPacket(9, 1, 6)
                || q.getCount(1, 5, 6) != 2 || q.getCount(1, 5, 5) != 0) throw new AssertionError("example 2");
        // Random sequences with nondecreasing timestamps, compared with the brute force after every call.
        Random rnd = new Random(3604L);
        for (int t = 0; t < 3000; t++) {
            int limit = 2 + rnd.nextInt(4);
            Router a = new Router(limit);
            Oracle o = new Oracle(limit);
            int ts = 1;
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(3);
                if (op == 0) {
                    // Small value ranges force duplicates and many equal timestamps.
                    ts += rnd.nextInt(3);
                    int s = 1 + rnd.nextInt(3), d = 1 + rnd.nextInt(3);
                    if (a.addPacket(s, d, ts) != o.add(s, d, ts)) throw new AssertionError("add");
                } else if (op == 1) {
                    if (!Arrays.equals(a.forwardPacket(), o.forward())) throw new AssertionError("forward");
                } else {

                    if (a.getCount(d, x, y) != o.count(d, x, y)) throw new AssertionError("count");
                }
            }
        }
    }

Chapter 17 on heaps and priority queues supplied PriorityQueue, which removes its smallest element in O(log k) time for k stored elements. It cannot answer the question whether a given element is stored, except by scanning all k elements. Chapter 32 on ordered data supplied TreeSet, which keeps elements in sorted order and answers membership, insertion and removal of the smallest element in O(log k) time. Chapter 4 on hash maps and sets supplied HashSet, which answers membership in expected O(1) time but has no order.

The chapter on design problems supplied the habit of writing down which fields describe one logical state and which method owns each change. This lesson applies that habit to a new situation. Two collections store overlapping facts about the same ids, so one method must update both and never leave them disagreeing between calls.

Simple approach

Reusing Ids With One Queue

The direct design keeps a counter next for ids that were never handed out and a PriorityQueue of ids that callers gave back. Allocation takes the smallest queue entry when one exists and otherwise takes next and increases it. Release adds the id to the queue.

final class NaivePool {
    private final int capacity;
    private int next = 0;
    private final java.util.PriorityQueue<Integer> back = new java.util.PriorityQueue<>();

    NaivePool(int capacity) { this.capacity = capacity; }

    // Returns the smallest reusable id, a fresh id, or -1 when all ids are in use.
    int allocate() {
        if (!back.isEmpty()) return back.poll();           // the smallest given-back id comes out first
        if (next < capacity) return next++;                // otherwise take a never-used id
        return -1;
    }

    // Gives an id back to the pool; the code trusts the caller.
    void release(int id) { back.add(id); }
}

With capacity 4, the calls allocate, allocate, allocate, release(1), allocate return 0, 1, 2 and then 1. For callers that behave, the answers are correct and each call costs O(log k).

Predict first: With capacity 4, the calls are allocate, allocate, release(1), release(1), allocate, allocate. What do the last two calls return, and what does the pool believe about id 1?

Both of the last two calls return 1. The queue holds two copies of 1 after the repeated release, and each allocation removes one copy. Two callers now own id 1, yet the pool believes that it handed out id 1 once and has the id fully accounted for. The queue stores order but not a fact about which ids it already contains.

Bottleneck

Order Without Membership Costs O(k)

The queue gives the right order for allocation, but it gives no cheap answer to the question that release needs: is this id already waiting in the queue? Calling contains on a PriorityQueue scans its array, so each release costs O(k) for k waiting ids. A pool with 10^5 ids and 10^5 releases then performs about 10^10 element comparisons in the worst case.

The check has a second gap that no scan of the queue closes. A release of an id that was never handed out, such as id 3 when next is 2, passes the scan because the queue does not contain it. The pool then hands out id 3 twice, once from the queue and once when next reaches 3.

A correct design must therefore decide three things in about O(log k) time. It must tell whether an id is waiting for reuse. It must tell whether an id was ever handed out. It must keep both answers consistent with the order structure after every call, including calls that fail.

Key idea

Every Id Has One State

Three States For Every Id

Every id from 0 to capacity - 1 is in exactly one of three states. A never-issued id has not been handed out since the pool was created. An allocated id belongs to a caller. A returned id was handed out earlier, was given back, and waits for reuse. Each state needs a store that answers its own questions quickly.

The never-issued ids form a contiguous range, because allocation takes them in increasing order. One integer, the frontier, stores that whole range: every id at or above the frontier is never issued, and every id below it has been issued at least once. The returned ids are scattered below the frontier, so they need a real collection.

Order In One Collection, Membership In Another

A PriorityQueue of returned ids supplies the smallest one in O(log k) time. A hash-based returned set holds the same ids and answers the question whether a given id waits for reuse in expected O(1) time. The queue serves allocation, and the set serves validation.

An allocated id is defined by absence. An id below the frontier that is not in the returned set must be allocated. This definition means that the pool needs no third collection, and it means that the two stores plus the frontier decide the state of every id.

The Policy For A Stale Entry

A stale entry is an element that one collection still holds although the other collection has already dropped it. The queue cannot remove an arbitrary element cheaply, so a design must pick a policy and state it. The eager policy never creates a stale entry. Every method changes the queue and the set together, so both always hold the same ids. The lazy policy lets a stale entry stay and discards it when it reaches the front. The eager policy is correct here because allocation removes the smallest id from both stores, and release adds the id to both.

The invariant has three parts. The queue and the set contain identical ids. Every one of those ids is below the frontier. No id appears twice in either one. A release that would break a part is rejected before any field changes, so a rejected call leaves the pool unchanged.

State

Fields That Describe One Pool

The pool stores four fields, and every public method reads or changes them together. A fifth item, state(id), is derived from them.

  • capacity is the number of ids, fixed at construction, so valid ids run from 0 to capacity - 1.
  • frontier is the smallest never-issued id, from 0 to capacity.
  • returnedHeap is a PriorityQueue<Integer> that holds the returned ids in increasing order.
  • returnedSet is a HashSet<Integer> that holds the same ids and answers membership.
  • state(id) is a derived answer: never-issued when id >= frontier, returned when returnedSet contains it, allocated otherwise.

The state of an id is never stored as a field, because a stored copy could disagree with the stores above. Only the frontier and the two collections hold information, and the answer for one id is computed from them in expected O(1) time.

Code

Writing The Pool In Java

Allocate And Release With Two Owners

Two private helpers own every change to the stores, and the public methods call only those helpers. This keeps the heap and the set from drifting apart. The method state follows the definition of the three states from the insight stage.

final class IdPool {
    static final int NEVER_ISSUED = 0, ALLOCATED = 1, RETURNED = 2;
    private final int capacity;
    private int frontier = 0;
    private final java.util.PriorityQueue<Integer> returnedHeap = new java.util.PriorityQueue<>();
    private final java.util.Set<Integer> returnedSet = new java.util.HashSet<>();

    IdPool(int capacity) { this.capacity = capacity; }

    private void putReturned(int id) { returnedHeap.add(id); returnedSet.add(id); }   // the only way an id enters the stores

    private int takeReturned() {
        int id = returnedHeap.poll();                      // the smallest returned id, removed in O(log k)
        returnedSet.remove(id);                            // keeps the set equal to the heap
        return id;
    }

    // The state of an id, derived from the frontier and the returned set.
    int state(int id) {
        if (id < 0 || id >= capacity) throw new IllegalArgumentException("id out of range: " + id);
        if (id >= frontier) return NEVER_ISSUED;           // the frontier covers a whole range with one integer
        return returnedSet.contains(id) ? RETURNED : ALLOCATED;
    }

    // Returns the smallest available id, or -1 when every id is allocated.
    int allocate() {
        if (!returnedHeap.isEmpty()) return takeReturned();    // a returned id is always below the frontier
        if (frontier < capacity) return frontier++;            // otherwise issue the next never-issued id
        return -1;
    }

    // Gives an allocated id back; any other state is a caller error and changes nothing.
    void release(int id) {
        if (state(id) != ALLOCATED) throw new IllegalStateException("id is not allocated: " + id);
        putReturned(id);
    }
}

Cost And Java Details

  • allocate costs O(log k) time when a returned id exists and O(1) time otherwise, for k returned ids.
  • release costs O(log k) time for the heap insertion, plus expected O(1) time for the set.
  • Space is O(k) for the two stores, and k never exceeds frontier.

The set operation returnedSet.remove(id) takes an int that Java boxes to an Integer, which is the intended overload for a Set. The same call on a List<Integer> would remove by position, which is a different and silent behavior. The method poll returns an Integer, and unboxing it cannot fail because the code checks isEmpty first.

When to use it

When Two Collections Must Agree

Recognizing The Pattern

Look for a class that needs the next resource by an order, such as smallest id, lowest free slot or leftmost stack with room, and also needs to answer a question about a named resource, such as whether this id is free or whether this return is legal. One collection answers the first need, and a different one answers the second. The invariant is that each resource appears in exactly one state, and every collection that mentions it agrees about that state after each public call.

The Nearest False Friend

The false friend is the priority queue alone. It returns the right smallest element and passes every test with well-behaved callers, yet it accepts a repeated return and stores the id twice. A scan with contains repairs correctness and costs O(k) per call. A second false friend is a boolean array of capacity length. It rejects repeated returns, but it finds the smallest free id by scanning, which costs O(n) per allocation when the free ids lie far to the right.

Choosing Eager Or Lazy Cleanup

Choose eager removal when every removal happens at the front of the ordered collection, as in this pool. Choose lazy removal when an element can lose its meaning while it sits in the middle of the ordered collection, as with a stack index that becomes full. Lazy cleanup is safe only when every use of the front element first checks that it is still valid. Do not use either policy when ids are not integers from a bounded range, because the frontier then has no meaning, and a map from resource to state is simpler.

Reusable-ID Pool

Author exercise

Problem Specification. Design a class IdPool. Its constructor takes capacity, and the valid ids are the integers from 0 to capacity - 1. The method allocate() returns the smallest id that is not currently allocated, or -1 when all ids are allocated. The method release(id) makes an allocated id available again.   • Calls number at most 2 * 10^5.
  • Smallest is by numeric value of the id.
  • Return value of allocate is an int, and -1 means that no id is available.

Example 1. Input capacity = 3 and four calls of allocate(), output 0, 1, 2, -1.

Example 2. Input capacity = 5, three calls of allocate(), then release(1), release(0) and release(1), then three calls of allocate(). The output is 0, 1, 2, then no output for the first two releases, then IllegalStateException for the third, then 0, 1, 3.

Prerequisites. The lesson stages above. This exercise has no LeetCode counterpart.

What This Exercise Changes. A release now validates against a derived state before it touches any collection, so repeated and never-issued ids are rejected.

Hint

If the heap and the set must hold the same ids after every call, which two lines of code change them together?

Algorithmic Solution (attempt the problem first)

Approach. The pool stores three facts. The integer frontier says that every id at or above it is never issued. The PriorityQueue named returnedHeap gives the smallest returned id. The HashSet named returnedSet answers whether an id waits for reuse. Allocation prefers the heap, because every returned id lies below the frontier and is therefore smaller than the next fresh id. Release first derives the state of the id and rejects anything that is not allocated, so a repeated or never-issued id cannot enter the stores.

The invariant is that the heap and the set hold the same ids, each id once, all below the frontier. Two private helpers are the only code that touches the stores, so a public method cannot update one store and forget the other. The stale-entry policy is eager: no store ever holds an id that the other has dropped. The main method checks this equality after every random call.

Complexity.

  • Time is O(log k) per allocate and release, where k is the number of returned ids, because the heap dominates and the set costs expected O(1).
  • Space is O(k) for the two stores plus O(1) for the frontier, and k never exceeds the frontier.
import java.util.*;

public final class ReusableIdPool {
    static final class IdPool {
        static final int NEVER_ISSUED = 0, ALLOCATED = 1, RETURNED = 2;
        private final int capacity;
        private int frontier = 0;
        private final PriorityQueue<Integer> returnedHeap = new PriorityQueue<>();
        private final Set<Integer> returnedSet = new HashSet<>();

        IdPool(int capacity) { this.capacity = capacity; }

        /** Adds an id to both stores. Time: O(log k). Space: O(1). Invariant: heap and set stay equal. */
        private void putReturned(int id) { returnedHeap.add(id); returnedSet.add(id); }

        /** Removes the smallest returned id from both stores. Time: O(log k). Space: O(1). Invariant: heap and set stay equal. */
        private int takeReturned() {
            // The heap yields the smallest returned id.
            int id = returnedHeap.poll();
            // The set drops the same id so that the two stores agree.
            returnedSet.remove(id);
            return id;
        }

        /** Derives the state of an id. Time: expected O(1). Space: O(1). Invariant: states partition the valid ids. */
        int state(int id) {
            // Ids outside the valid range have no state.
            if (id < 0 || id >= capacity) throw new IllegalArgumentException("id out of range: " + id);
            // Every id at or above the frontier was never issued.
            if (id >= frontier) return NEVER_ISSUED;
            // Below the frontier, the set separates returned ids from allocated ones.
            return returnedSet.contains(id) ? RETURNED : ALLOCATED;
        }

        /** Returns the smallest available id or -1. Time: O(log k). Space: O(1). Invariant: returned ids are below the frontier. */
        int allocate() {
            // A returned id is smaller than any never-issued id.
            if (!returnedHeap.isEmpty()) return takeReturned();
            // Otherwise issue the frontier id and advance the frontier.
            if (frontier < capacity) return frontier++;
            // No id is available.
            return -1;
        }

        /** Returns an allocated id to the pool. Time: O(log k). Space: O(1). Invariant: a throwing call changes nothing. */
        void release(int id) {
            // Validation happens before any store changes.
            if (state(id) != ALLOCATED) throw new IllegalStateException("id is not allocated: " + id);
            putReturned(id);
        }

        /** Checks that both stores agree. Time: O(k log k). Space: O(k). Invariant: same ids, each below the frontier. */
        boolean consistent() {
            // Equal sizes and equal contents mean no duplicate in the heap.
            if (returnedHeap.size() != returnedSet.size()) return false;
            for (int id : returnedHeap) if (!returnedSet.contains(id) || id >= frontier) return false;
            return true;
        }
    }

    public static void main(String[] args) {
        // Example 1: capacity 3 exhausts after three ids.
        IdPool a = new IdPool(3);
        int[] first = {a.allocate(), a.allocate(), a.allocate(), a.allocate()};
        if (!Arrays.equals(first, new int[] {0, 1, 2, -1})) throw new AssertionError("example 1");
        // Example 2: reuse in numeric order, then a rejected repeat release.
        IdPool b = new IdPool(5);
        b.allocate(); b.allocate(); b.allocate();
        b.release(1); b.release(0);
        try { b.release(1); throw new AssertionError("repeat release accepted"); } catch (IllegalStateException expected) { }
        int[] next = {b.allocate(), b.allocate(), b.allocate()};
        if (!Arrays.equals(next, new int[] {0, 1, 3})) throw new AssertionError("example 2");
        // Never-issued and out-of-range ids are rejected with the documented exceptions.
        try { b.release(4); throw new AssertionError("never-issued accepted"); } catch (IllegalStateException expected) { }
        try { b.release(5); throw new AssertionError("range accepted"); } catch (IllegalArgumentException expected) { }
        // Random comparison with a boolean-array oracle.
        Random rnd = new Random(3692L);
        for (int t = 0; t < 3000; t++) {
            int cap = 1 + rnd.nextInt(6);
            IdPool pool = new IdPool(cap);
            boolean[] used = new boolean[cap];
            boolean[] ever = new boolean[cap];
            for (int step = 0; step < 40; step++) {
                if (rnd.nextBoolean()) {
                    // Oracle: scan for the smallest unused id.
                    int want = -1;
                    for (int i = 0; i < cap; i++) if (!used[i]) { want = i; break; }
                    int got = pool.allocate();
                    if (got != want) throw new AssertionError("allocate " + got + " vs " + want);
                    if (want >= 0) { used[want] = true; ever[want] = true; }
                } else {
                    int id = rnd.nextInt(cap + 2) - 1;
                    boolean valid = id >= 0 && id < cap;
                    if (valid && used[id]) { pool.release(id); used[id] = false; }
                    else {
                        // Every other release must throw the documented exception and change nothing.
                        try { pool.release(id); throw new AssertionError("accepted " + id); }
                        catch (IllegalArgumentException e) { if (valid) throw new AssertionError("wrong exception"); }
                        catch (IllegalStateException e) { if (!valid) throw new AssertionError("wrong exception"); }
                    }
                }
                // The state of every id agrees with the oracle and both stores agree.
                for (int i = 0; i < cap; i++) {
                    int want = !ever[i] ? 0 : used[i] ? 1 : 2;
                    if (pool.state(i) != want) throw new AssertionError("state of " + i);
                }
                if (!pool.consistent()) throw new AssertionError("stores disagree");
            }
        }
    }

Hint

Which comparison with the frontier tells whether num was ever removed, and which return value of TreeSet.add tells whether the removed count changes?

Algorithmic Solution (attempt the problem first)

Approach. The set has two regions. Every integer at or above frontier has never been popped, and the TreeSet named addedBack holds exactly the values below the frontier that were popped and then restored. Popping takes the first element of the TreeSet when it is not empty, because every such value is smaller than the frontier, and otherwise takes the frontier itself. The method addBack ignores values at or above the frontier, since they were never removed. For a value below the frontier, the result of TreeSet.add is true exactly when the value was removed, so the same call both ignores a duplicate and decides whether the removed count drops.

The invariant is removed == frontier - 1 - addedBack.size(), which counts the popped values minus the restored ones. The main method checks that equation after every operation, and it compares every pop with a boolean-array oracle.

Complexity.

  • Time is O(log k) per call for k restored values, because pollFirst and add on a TreeSet are logarithmic.
  • Space is O(k) for the restored values, and the infinite range costs one integer.
import java.util.*;

public final class InfiniteSetTree {
    static final class InfiniteSet {
        private int frontier = 1;
        private final TreeSet<Integer> addedBack = new TreeSet<>();
        private int removed = 0;

        /** Removes and returns the smallest value. Time: O(log k). Space: O(1). Invariant: removed == frontier - 1 - addedBack.size(). */
        int popSmallest() {
            int v;
            // Restored values are all below the frontier, so they come first.
            if (!addedBack.isEmpty()) v = addedBack.pollFirst();
            // Otherwise the frontier is the smallest present value.
            else v = frontier++;
            removed++;
            return v;
        }

        /** Restores a removed value. Time: O(log k). Space: O(1). Invariant: values at or above the frontier are never stored. */
        void addBack(int num) {
            // A value at or above the frontier was never removed.
            if (num >= frontier) return;
            // add returns true only when the value was absent, meaning it was removed.
            if (addedBack.add(num)) removed--;
        }

        /** Counts removed values. Time: O(1). Space: O(1). Invariant: equals popped values minus restored values. */
        int removedCount() { return removed; }

        boolean consistent() { return removed == frontier - 1 - addedBack.size(); }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        InfiniteSet s = new InfiniteSet();
        int[] p = {s.popSmallest(), s.popSmallest(), s.popSmallest()};
        if (!Arrays.equals(p, new int[] {1, 2, 3})) throw new AssertionError("pops");
        s.addBack(2); s.addBack(2); s.addBack(7);
        if (s.popSmallest() != 2 || s.popSmallest() != 4 || s.removedCount() != 4) throw new AssertionError("example 1");
        // Example 2: restoring the only popped value empties the removed count.
        InfiniteSet u = new InfiniteSet();
        if (u.popSmallest() != 1) throw new AssertionError("e2 pop");
        u.addBack(1);
        if (u.removedCount() != 0 || u.popSmallest() != 1 || u.removedCount() != 1) throw new AssertionError("example 2");
        // Random comparison with a boolean-array oracle over values 1..60.
        Random rnd = new Random(3693L);
        for (int t = 0; t < 3000; t++) {
            InfiniteSet set = new InfiniteSet();
            boolean[] gone = new boolean[100];
            for (int step = 0; step < 50; step++) {
                if (rnd.nextInt(3) > 0) {
                    // Oracle: scan for the smallest value not removed.
                    int want = 1;
                    while (gone[want]) want++;
                    if (set.popSmallest() != want) throw new AssertionError("pop");
                    gone[want] = true;
                } else {
                    int n = 1 + rnd.nextInt(60);
                    set.addBack(n);
                    gone[n] = false;
                }
                // The oracle count of removed values must equal the stored count.
                int c = 0;
                for (boolean g : gone) if (g) c++;
                if (set.removedCount() != c || !set.consistent()) throw new AssertionError("count");
            }
        }
    }

Design Phone Directory

LeetCode 379

Problem Specification. Design a class PhoneDirectory. Its constructor takes maxNumbers, and the valid numbers run from 0 to maxNumbers - 1, all free at the start. The method get() removes any free number and returns it, or returns -1 when none is free. The method check(number) returns true when the number is in range and free. The method release(number) returns true when it changed an allocated number to free, and false for a number that is out of range or already free. Store the free numbers as a linked list in one int[] next, where one reserved value marks an allocated number.

Input Constraints. The limits are:

  • maxNumbers satisfies 1 <= maxNumbers <= 10^4.
  • Calls number at most 2 * 10^4.
  • Number arguments are any int, including negative values and values at or above maxNumbers.
  • Order of the numbers returned by get is unspecified.

Example 1. Input maxNumbers = 3 and the calls get(), get(), release(0), release(0), get(), get(), get(). The output is 0, 1, true, false, 0, 2, -1.

Example 2. Input maxNumbers = 2 and the calls release(1), check(1), release(5), get(), check(0). The output is false, true, false, 0, false. Number 1 is already free, so its release returns false.

Prerequisites. The first exercise above. This exercise changes the contract of LeetCode 379: release reports whether it freed a number, and the free numbers form a linked list inside an int array.

What This Exercise Changes. The release result is now a boolean, so a repeated release is a normal answer and not an error. One array stores both ownership and the list order, so no second collection exists to disagree.

Hint

If next[n] holds one reserved value exactly when n is allocated, how does release reject a second return without any extra collection?

Algorithmic Solution (attempt the problem first)

Approach. One array next stores two things. For a free number n, next[n] is the following free number, or END for the last one, and a field head names the first free number. For an allocated number, next[n] holds the reserved value USED. A number is therefore in exactly one place: in the free chain, or marked used. Both get and release work at the head, so each is a constant number of array writes.

Release is idempotent because the test next[n] == USED is both the permission to free and the record of the change. A number out of range or already free fails the test and returns false without touching the list. The invariant is that following head visits every free number once and ends at END, and the used count plus the chain length equals maxNumbers. The main method walks the chain after every call.

Complexity.

  • Time is O(1) per call, because each call reads and writes a constant number of array cells.
  • Space is O(n) for the single int[] of length maxNumbers, and no other collection exists.
import java.util.*;

public final class PhoneDirectoryFreeList {
    static final class PhoneDirectory {
        private static final int END = -1, USED = -2;
        private final int[] next;
        private int head = 0;

        PhoneDirectory(int maxNumbers) {
            // Every number starts free, linked to the next larger number.
            next = new int[maxNumbers];
            for (int i = 0; i < maxNumbers; i++) next[i] = i + 1 < maxNumbers ? i + 1 : END;
        }

        /** Hands out a free number. Time: O(1). Space: O(1). Invariant: the chain from head holds exactly the free numbers. */
        int get() {
            // An empty chain means every number is used.
            if (head == END) return -1;
            int n = head;
            // Unlink the head and mark the number as used.
            head = next[n];
            next[n] = USED;
            return n;
        }

        /** Tells whether a number is free. Time: O(1). Space: O(1). Invariant: free means not marked USED. */
        boolean check(int n) { return n >= 0 && n < next.length && next[n] != USED; }

        /** Frees a used number and reports whether it changed. Time: O(1). Space: O(1). Invariant: a false result changes nothing. */
        boolean release(int n) {
            // Out of range or already free means there is nothing to undo.
            if (n < 0 || n >= next.length || next[n] != USED) return false;
            // Push the number onto the front of the chain.
            next[n] = head;
            head = n;
            return true;
        }

        /** Counts the chain length, failing on a cycle. Time: O(n). Space: O(1). Invariant: chain visits each free number once. */
        int freeCount() {
            int c = 0;
            for (int v = head; v != END; v = next[v]) {
                if (next[v] == USED || ++c > next.length) throw new AssertionError("broken chain");
            }
            return c;
        }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        PhoneDirectory d = new PhoneDirectory(3);
        if (d.get() != 0 || d.get() != 1) throw new AssertionError("gets");
        if (!d.release(0) || d.release(0)) throw new AssertionError("release");
        if (d.get() != 0 || d.get() != 2 || d.get() != -1) throw new AssertionError("example 1");
        // Example 2: a number that was never taken is already free.
        PhoneDirectory e = new PhoneDirectory(2);
        if (e.release(1) || !e.check(1) || e.release(5)) throw new AssertionError("example 2 a");
        if (e.get() != 0 || e.check(0)) throw new AssertionError("example 2 b");
        // Random comparison with a boolean-array oracle; get may return any free number.
        Random rnd = new Random(3694L);
        for (int t = 0; t < 4000; t++) {
            int max = 1 + rnd.nextInt(6);
            PhoneDirectory dir = new PhoneDirectory(max);
            boolean[] used = new boolean[max];
            for (int step = 0; step < 40; step++) {
                int op = rnd.nextInt(3);
                if (op == 0) {
                    int free = 0;
                    for (boolean b : used) if (!b) free++;
                    int got = dir.get();
                    // -1 exactly when nothing is free, otherwise a number that the oracle holds free.
                    if ((got == -1) != (free == 0)) throw new AssertionError("get -1");
                    if (got != -1) { if (used[got]) throw new AssertionError("duplicate " + got); used[got] = true; }
                } else if (op == 1) {
                    int n = rnd.nextInt(max + 4) - 2;
                    boolean want = n >= 0 && n < max && used[n];
                    if (dir.release(n) != want) throw new AssertionError("release " + n);
                    if (want) used[n] = false;
                } else {
                    int n = rnd.nextInt(max + 4) - 2;
                    boolean want = n >= 0 && n < max && !used[n];
                    if (dir.check(n) != want) throw new AssertionError("check " + n);
                }
                // The chain length must equal the oracle's free count.
                int free = 0;
                for (boolean b : used) if (!b) free++;
                if (dir.freeCount() != free) throw new AssertionError("chain length");
            }
        }
    }

Pattern Recognition

Dinner Plate Stacks

LeetCode 1172

Problem Specification. Design a class DinnerPlates. Its constructor takes capacity, the maximum number of values per stack, and there is an unbounded row of stacks numbered from 0. The method push(val) places val on the leftmost stack that is not full. The method pop() removes and returns the top value of the rightmost non-empty stack, or returns -1 when every stack is empty. The method popAtStack(index) removes and returns the top value of stack index, or returns -1 when that stack is empty or does not exist.

Input Constraints. The limits are:

  • capacity satisfies 1 <= capacity <= 2 * 10^4.
  • Values satisfy 1 <= val <= 2 * 10^4.
  • index satisfies 0 <= index <= 10^5.
  • Calls number at most 2 * 10^5.

Example 1. Input capacity = 2, pushes of 1, 2, 3, 4, 5, then popAtStack(0), push(6), pop(), pop(). The pushes build [1,2], [3,4] and [5]. The output of the last four calls is 2, nothing, 5, 4.

Example 2. Input capacity = 1, pushes of 7 and 8, then popAtStack(0), popAtStack(0), push(9), pop(). The pushes build [7] and [8]. The output of the last four calls is 7, -1, nothing, 8.

Prerequisites. The first exercise above and the lazy cleanup policy from the applicability stage. This exercise keeps the contract of LeetCode 1172.

What This Exercise Changes. The writable set may hold entries for full stacks and for removed stacks. Every use of its smallest entry first validates the stack and discards the entry when it is invalid.

Hint

If a set of stack indexes may contain a full stack, which check must push run on the smallest index before it uses it?

Algorithmic Solution (attempt the problem first)

Approach. The class keeps an ArrayList of stacks and a TreeSet<Integer> named writable of stack indexes. The policy for stale entries is lazy. The set may contain an index whose stack is full or whose index is at or above the list size, but it must contain every index of a non-full stack. Push reads the smallest index, discards it when the stack is full or missing, and repeats. When the set runs out, it opens a new stack at the end of the list. Pop removes empty stacks from the end of the list before it reads the last stack, and both pop methods add the touched index to the set, where a second add changes nothing.

Each push or pop adds at most one entry, and each cleanup removes one, so cleanup is paid for by earlier additions. The invariant is that every non-full stack below the list size appears in writable, which the main method checks after each call.

Complexity.

  • Time is amortized O(log n) per call for n stacks, because cleanup removes only entries that earlier calls added.
  • Space is O(n + v) for n stacks and v stored values, plus at most one set entry per call.
import java.util.*;

public final class DinnerPlatesWritable {
    static final class DinnerPlates {
        private final int cap;
        private final List<ArrayDeque<Integer>> stacks = new ArrayList<>();
        private final TreeSet<Integer> writable = new TreeSet<>();

        DinnerPlates(int capacity) { cap = capacity; }

        /** Places val on the leftmost non-full stack. Time: amortized O(log n). Space: O(1). Invariant: writable covers every non-full stack. */
        void push(int val) {
            int idx = -1;
            // Inspect the smallest entry; discard it when it is stale.
            while (!writable.isEmpty()) {
                int c = writable.first();
                if (c < stacks.size() && stacks.get(c).size() < cap) { idx = c; break; }
                writable.pollFirst();
            }
            // No valid entry means every stack is full, so open a new one.
            if (idx < 0) { idx = stacks.size(); stacks.add(new ArrayDeque<>()); writable.add(idx); }
            stacks.get(idx).push(val);
        }

        /** Pops from the rightmost non-empty stack. Time: amortized O(log n). Space: O(1). Invariant: the last stack is non-empty afterwards. */
        int pop() {
            // Trailing empty stacks are dropped; their set entries become stale and are cleaned by push.
            while (!stacks.isEmpty() && stacks.get(stacks.size() - 1).isEmpty()) stacks.remove(stacks.size() - 1);
            if (stacks.isEmpty()) return -1;
            return popAtStack(stacks.size() - 1);
        }

        /** Pops from a named stack. Time: O(log n). Space: O(1). Invariant: a touched stack is in writable. */
        int popAtStack(int index) {
            // A missing or empty stack gives -1 and changes nothing.
            if (index < 0 || index >= stacks.size() || stacks.get(index).isEmpty()) return -1;
            // The stack now has room, so it must be listed; add is idempotent.
            writable.add(index);
            return stacks.get(index).pop();
        }

        boolean covers() {
            for (int i = 0; i < stacks.size(); i++) if (stacks.get(i).size() < cap && !writable.contains(i)) return false;
            return true;
        }
    }

    /** Brute force: scans stacks from the left for push and from the right for pop. */
    static final class Oracle {
        final int cap; final List<ArrayDeque<Integer>> st = new ArrayList<>();
        Oracle(int cap) { this.cap = cap; }
        void push(int v) {
            for (ArrayDeque<Integer> s : st) if (s.size() < cap) { s.push(v); return; }
            ArrayDeque<Integer> s = new ArrayDeque<>(); s.push(v); st.add(s);
        }
        int pop() {
            for (int i = st.size() - 1; i >= 0; i--) if (!st.get(i).isEmpty()) return st.get(i).pop();
            return -1;
        }
        int popAt(int i) { return i < st.size() && !st.get(i).isEmpty() ? st.get(i).pop() : -1; }
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        DinnerPlates d = new DinnerPlates(2);
        for (int v = 1; v <= 5; v++) d.push(v);
        if (d.popAtStack(0) != 2) throw new AssertionError("popAt");
        d.push(6);
        if (d.pop() != 5 || d.pop() != 4) throw new AssertionError("example 1");
        // Example 2 from the exercise.
        DinnerPlates e = new DinnerPlates(1);
        e.push(7); e.push(8);
        if (e.popAtStack(0) != 7 || e.popAtStack(0) != -1) throw new AssertionError("example 2 a");
        e.push(9);
        if (e.pop() != 8) throw new AssertionError("example 2 b");
        // Random comparison with the brute force.
        Random rnd = new Random(3695L);
        for (int t = 0; t < 4000; t++) {
            int cap = 1 + rnd.nextInt(3);
            DinnerPlates x = new DinnerPlates(cap);
            Oracle o = new Oracle(cap);
            for (int step = 0; step < 60; step++) {
                int op = rnd.nextInt(3);
                if (op == 0) { int v = rnd.nextInt(100); x.push(v); o.push(v); }
                else if (op == 1) { if (x.pop() != o.pop()) throw new AssertionError("pop"); }
                else { int i = rnd.nextInt(6); if (x.popAtStack(i) != o.popAt(i)) throw new AssertionError("popAt " + i); }
                if (!x.covers()) throw new AssertionError("writable lost a non-full stack");
            }
        }
    }
