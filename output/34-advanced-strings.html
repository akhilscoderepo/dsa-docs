Chapter 34

Advanced Strings

Orientation

A moderation service watches a chat feed for 5,000 banned phrases. The first version tests every phrase at every position of every message, and the feed falls behind within minutes. A second version checks each position with a built-in substring search and still rereads the same characters again and again after each near miss. Advanced string algorithms remove that rereading by remembering what the text already proved.

Prerequisites

You should know arrays and strings, the two-pointer and sliding-window habits, hash maps, tries from the trie chapter, and sorting with a comparator. A prefix of a string is its first characters, and a suffix is its last characters. A border is a piece that is both a proper prefix and a suffix of the same string.

What Each Lesson Reuses

Each lesson answers one question about reusing work on text. The prefix-matching lesson also ends with an extension exercise on the Z array.

  • Rolling Hash gives every window of a fixed length a number that updates in constant time, and it compares characters whenever two numbers agree.
  • Match A Pattern Without Restarting stores the longest border of every pattern prefix, so a mismatch falls back instead of rewinding the text.
  • Find Palindromes Around Every Center pads the string, copies radii from a mirror position and expands only past the known edge.
  • Sort And Compare All Suffixes orders every suffix by doubling the compared length, then reads shared prefixes between neighbors.
  • Match Many Patterns In One Pass builds one trie of the patterns and adds failure links so a single scan finds all of them.
  • Stream Matching With Failure Links keeps one automaton state between arriving characters, so a late character is answered without rescanning old ones.

Reading Order

Every lesson begins with a text task that fails at scale. A direct method follows, and you predict where its cost comes from before the reasoning appears. The remaining parts name the reused fact, list the variables, follow two traces, give Java code and state where the idea stops fitting. The exercises climb from a basic build to a variation, an edge case and a recognition problem. A LeetCode problem that appears twice carries a changed contract, and its text says what changed.

What You Can Do After This Chapter

You can pick the tool whose stored fact fits a text task: a hash for equal windows, a border table for one pattern, radii for palindromes, a suffix order for many substring questions, and an automaton for many patterns or a stream. You can state what each one stores and when a hash match still needs a character check. Compositions of strings with dynamic programming or tries are left to the chapters that own those invariants.

Problem

Why Equal Checksums Are Not Equal Data

A backup tool splits each file into fixed-size blocks and stores a block only once. To find duplicates quickly, it keeps a 32-bit checksum for every stored block and treats a new block with a known checksum as a copy. The design works for months. Then two different blocks produce the same checksum, the tool skips the second block, and a restore returns the wrong bytes without any error message. A 32-bit value has about 4.3 billion possibilities, yet random blocks start to repeat a value after roughly 77,000 of them, so the failure is certain at scale and not a rare accident.

The same tension appears wherever software compares many pieces of equal length. A genome tool looks for 10-letter sequences that occur twice in a DNA string. A plagiarism checker looks for the longest passage shared by two halves of a document. Comparing every piece letter by letter is slow, and a short fingerprint is fast but can be wrong. The question of this lesson is how to compute a fingerprint for every window of a string almost for free, and how to keep the answer correct when two fingerprints agree by accident.

Simple approach

Copying Every Window Into A Set

The direct method cuts out each window of length k, puts the text into a HashSet<String>, and reports a repeat when the set already holds the text. Equality is exact here, because the set compares the actual characters.

static int firstRepeatStartNaive(String s, int k) {
    java.util.HashSet<String> seen = new java.util.HashSet<>();
    for (int start = 0; start + k <= s.length(); start++) {
        String window = s.substring(start, start + k);
        if (!seen.add(window)) return start;
    }
    return -1;
}

On "abcdabc" with k = 3 the method returns 4, the start of the second "abc". The answer is correct. The cost is in what the loop does for each start: it copies k characters into a new String, and the set then reads those k characters again to compute a hash code and, on a match, once more to compare.

Predict first: The loop above handles a string of length n with window length k. How many characters does it copy and read in total, and what changes when k grows to half of n?

Each of the n - k + 1 windows costs about k characters to copy and about k more to hash, so the copy costs (n - k + 1) * k characters and the hashing costs the same amount again. When k is n / 2, each of those two counts is about n^2 / 4, so the total is about n^2 / 2 character reads, and the set also holds the copied characters in memory at once.

Bottleneck

Counting The Characters Read Twice

Cost Of The Direct Method

For n windows of length k, the direct method touches about n * k characters, which is O(n * k) time, and the set stores the same amount, which is O(n * k) memory. With n = 1,000,000 and k = 10 that is ten million character copies and the cost is acceptable. With n = 30,000 and k = 15,000 it is hundreds of millions of character copies, and the set holds all of them.

The longest duplicate substring problem makes the cost worse, because the window length is unknown. A search over lengths calls the window check about log n times with lengths up to n, so the direct method costs O(n^2 log n) in total. For n = 30,000 that is roughly seven billion character reads.

The Repeated Work

Two neighbouring windows share all characters except one at each end. The window at start 4 of "abcdabc" is "abc" and the window at start 5 would be "bc?", so k - 1 of the k characters are the same. The direct method reads those shared characters again for every new window. That repeated reading is the named waste. A better method must produce the summary of the next window from the summary of the current window and the two characters that differ, in constant time.

Key idea

Updating The Summary Letter By Letter

What A Polynomial Hash Stores

A polynomial hash turns a window of characters into one number. Give each character a numeric code, pick a base B, and treat the window as the digits of a number written in base B. The window c0 c1 ... c(k-1) gets the value c0 * B^(k-1) + c1 * B^(k-2) + ... + c(k-1), reduced by a fixed modulus M so it stays small enough for a long. This lesson fixes a policy for lowercase text: the letters a to z map to the codes 1 to 26, never 0, and the base is 27, which is larger than every code. Two distinct windows of the same length would then have distinct values if no reduction took place. The reduction by M = 1,000,000,007 is what allows a collision.

How The Rolling Update Works

The rolling update moves the window one position to the right. Subtract the outgoing character times B^(k-1), multiply the remainder by B, and add the incoming character. Each of the three operations touches one character, so the new value costs O(1) instead of O(k). The value B^(k-1) mod M is computed once before the scan. In Java the subtraction can leave a negative number, because the % operator keeps the sign of the left operand, so the code adds M after the subtraction to return to the range 0 to M - 1.

Why A Collision Check Is Needed

Reducing by a modulus means that different windows can share a value. With n windows there are about n^2 / 2 pairs, and a single modulus near one billion gives each pair a chance of about one in a billion. For n = 30,000 the expected number of accidental matches in one pass is about 0.45, so a real run meets collisions regularly. The collision check is the rule that a hash match is only a candidate. The code compares the two windows character by character, using start indexes into the original string and no substring copy, and accepts the match only when every character agrees. The check costs O(k) but runs only on a match, so a pass over distinct windows pays almost nothing for it.

For DNA the policy is different and stronger. The four letters get the 2-bit codes A as 0, C as 1, G as 2 and T as 3, and the window is the 2-bit digits written in base 4. A window of 10 letters needs 20 bits, which fits in an int without any modulus, so the value is exact and a match needs no check.

State

Values The Scan Keeps

The scan keeps a small set of named values, and each one belongs to the policy stated above.

  • code is the number for one letter, 1 to 26 for a to z.
  • BASE is the constant 27, one larger than the biggest code.
  • MOD is the constant 1,000,000,007, a prime that keeps every product inside a long.
  • power is BASE^(k-1) mod MOD, the weight of the outgoing letter.
  • hash is the value of the current window, always in the range 0 to MOD - 1.
  • seen maps a hash value to the start indexes of the windows that produced it.
  • DNA code is the 2-bit number for one letter in the DNA policy: A is 0, C is 1, G is 2 and T is 3.
Walkthrough

Sliding Across Two Strings

First String Finds A Real Repeat

Take s = "abcdabc" with k = 3, base 27 and modulus 1,000,000,007. The weight power is 729. The pointer end marks the last index of the current window. At end = 2 the window "abc" has the value 1 * 729 + 2 * 27 + 3 = 786. Sliding to end = 3 subtracts a times 729, leaving 57, multiplies by 27 and adds 4 for d, which gives 1543 for "bcd". The next two slides give 2296 for "cda" and 2945 for "dab". At end = 6 the window "abc" has the value 786 again. The table lookup finds the earlier start 0, the collision check compares the three letters, and all of them agree, so the repeat is real.

Second String Meets A False Match

To make a collision visible by hand, the second trace uses the small modulus 101, so power is 22. The string is "abbcde" and k = 3. The first window "abb" has the value 78. The slide to "bbc" subtracts 22 and gives 0 after the multiplication. The slide to "bcd" subtracts 44 from 0, which gives -44. The code adds 101 and continues with -44 + 101 = 57, which is the reason for the normalization. Then 57 * 27 + 4 = 1543, which is 28 modulo 101, so the new hash is 28. The slide to "cde" also normalizes and ends at 78, the same value as "abb". The table reports start 0, the collision check compares c with a and rejects the match, and the scan correctly finds no repeat.

Scanning With Hashes And Index Checks

The Scan With Verification

The class below applies the policy from the insight. The method firstRepeatStart takes the modulus as a parameter so the same code can be tried with a tiny modulus, and the method sameWindow compares two windows by index.

final class RollingScan {
    static final long BASE = 27;

    // Compares two windows of length k in place; no substring is created.
    static boolean sameWindow(String s, int a, int b, int k) {
        for (int j = 0; j < k; j++) {
            if (s.charAt(a + j) != s.charAt(b + j)) return false;
        }
        return true;
    }

    // Returns the start of the first window equal to an earlier one, or -1.
    static int firstRepeatStart(String s, int k, long mod) {
        int n = s.length();
        if (k <= 0 || k > n) return -1;
        long power = 1;
        for (int j = 1; j < k; j++) power = power * BASE % mod;
        java.util.HashMap<Long, java.util.ArrayList<Integer>> seen = new java.util.HashMap<>();
        long hash = 0;
        for (int end = 0; end < n; end++) {
            int in = s.charAt(end) - 'a' + 1;
            if (end >= k) {
                int out = s.charAt(end - k) - 'a' + 1;
                hash = (hash - out * power % mod + mod) % mod;
            }
            hash = (hash * BASE + in) % mod;
            if (end < k - 1) continue;
            int start = end - k + 1;
            java.util.ArrayList<Integer> earlier = seen.computeIfAbsent(hash, h -> new java.util.ArrayList<>());
            for (int other : earlier) if (sameWindow(s, other, start, k)) return start;
            earlier.add(start);
        }
        return -1;
    }
}

Cost Of The Scan

The scan reads each character once for the update, which is O(n) time, plus O(k) for each collision check. With a large modulus the checks run almost only on true repeats, and the scan returns at the first one, so the expected cost is O(n + k). The table holds up to n - k + 1 start indexes, which is O(n) memory, and it holds no characters, in contrast to the O(n * k) memory of the direct method. If many windows share one hash value, the lists grow and the scan degrades, which is why the modulus must be large and the check must stay.

When to use it

Deciding When A Hash Fits

The Invariant To Keep

After each slide, hash must equal the polynomial value of exactly the current window under the fixed base, modulus and letter codes. That statement is the invariant of the method. It breaks if the base or the codes change midway, if the subtraction is left negative, or if the multiplication runs in int and overflows. In Java the product 1,000,000,006 * 27 already exceeds the int range, so every intermediate value lives in a long.

The False Friend Of Equal Hashes

Equal hash values are a false friend of equal windows. They prove a difference when they disagree, since equal windows always give equal values, but they prove nothing when they agree. A solution that returns the answer on a hash match alone passes small tests and fails on the one input where two windows collide. The collision check from the insight is the fix, and the check compares indexes without creating a substring.

When Another Method Fits Better

A hash needs equal-length windows, so a single comparison of two unrelated strings is better done with String.equals or regionMatches. When the alphabet is tiny and the window short, as with 10 DNA letters, an exact 2-bit code replaces the modulus and the check disappears. When a guarantee against adversarial input matters more than speed, because the cost of a long run of collisions is quadratic, the suffix structures covered later in this chapter give a worst-case bound without any randomness. Treat the hash as a fast filter whose output is verified, and do not use it where an unverified answer would corrupt data.

Fixed-Window Hash

Author exercise

Problem Specification. Let s be a string of lowercase letters a to z and let k be a window length. Map each letter to its code, a to 1 up to z to 26. The hash of a window w of length k is the sum over positions j from 0 to k - 1 of code(w[j]) * 27^(k-1-j), reduced modulo 1,000,000,007. Return the hash of the last window, the one that starts at index s.length() - k. Compute it by sliding from the first window, which means removing the outgoing letter and appending the incoming letter at each step.

Input Constraints. The limits are:

  • Length of s is between 1 and 100,000.
  • Window k satisfies 1 <= k <= s.length().
  • Alphabet is lowercase a to z only.
  • Answer is a long in the range 0 to 1,000,000,006.

Example 1. Input s = "abcab", k = 3, output 2216, the hash of "cab".

Example 2. Input s = "zzzzzzzzzz", k = 10, output 130653411. The window is the whole string, so no slide happens and the value is reduced several times.

Prerequisites. The rolling update and the letter policy from this lesson.

What This Exercise Changes. Basic case: one window summary replaces a rescan of k letters at each step.

Hint

Build the first window with the same multiply-and-add step that the slide uses. What value must you precompute for the outgoing letter?

Algorithmic Solution (attempt the problem first)

Approach. The method builds the hash of the first window with the multiply-and-add step, which is Horner evaluation of the polynomial. It also computes power, the weight 27^(k-1) mod 1,000,000,007 of the leading letter. For every later position it removes the outgoing letter times power, multiplies by 27 and adds the incoming letter. The invariant is that after processing index end, hash equals the polynomial value of the window that ends at end under the fixed base, modulus and letter codes. The update stays in long arithmetic, because the product of a value below the modulus and 27 exceeds the int range, and the code asserts that overflow.

The oracle recomputes the last window from its definition with BigInteger, which cannot overflow, and the random tests compare both results.

Complexity.

  • Time is O(n), because the first window costs k steps and each of the n - k later positions costs a constant number of operations; computing power adds k - 1 steps.
  • Space is O(1), because only hash, power and loop indexes are stored and no substring is created.
import java.math.BigInteger;
import java.util.Random;

public class FixedWindowHashSolution {
    static final long BASE = 27;
    static final long MOD = 1_000_000_007L;

    /**
     * Returns the hash of the last window of length k, found by sliding from the first window.
     * Time: O(n), because every position triggers one constant-time update.
     * Space: O(1), because only a few longs are kept.
     * Invariant: after index end, hash is the polynomial value of s[end-k+1..end] mod MOD.
     */
    static long lastWindowHash(String s, int k) {
        // power is the weight of the leading letter, BASE^(k-1) mod MOD, built with k-1 multiplications.
        long power = 1;
        for (int j = 1; j < k; j++) power = power * BASE % MOD;
        long hash = 0;
        // One pass over all letters; each iteration costs a constant number of operations.
        for (int end = 0; end < s.length(); end++) {
            // Windows only slide once the first k letters are in, so the outgoing letter exists from end = k.
            if (end >= k) {
                long out = s.charAt(end - k) - 'a' + 1;
                // Remove the leading letter; the reduced term keeps the difference above -MOD, so + MOD restores it.
                hash = (hash - out * power % MOD + MOD) % MOD;
            }
            // Append the incoming letter: shift one base position and add its code.
            hash = (hash * BASE + (s.charAt(end) - 'a' + 1)) % MOD;
        }
        // After the last index the hash describes the last window.
        return hash;
    }

    /** Oracle: sum of code * 27^(k-1-j) evaluated exactly with BigInteger, then reduced once. */
    static long oracle(String s, int k) {
        BigInteger sum = BigInteger.ZERO;
        int from = s.length() - k;
        // Exact evaluation: no overflow, no intermediate reduction.
        for (int j = 0; j < k; j++) {
            BigInteger term = BigInteger.valueOf(s.charAt(from + j) - 'a' + 1).multiply(BigInteger.valueOf(BASE).pow(k - 1 - j));
            sum = sum.add(term);
        }
        return sum.mod(BigInteger.valueOf(MOD)).longValue();
    }

    public static void main(String[] args) {
        // The statement examples.
        if (lastWindowHash("abcab", 3) != 2216) throw new AssertionError("example 1");
        if (lastWindowHash("zzzzzzzzzz", 10) != 130653411L) throw new AssertionError("example 2");
        // A window of one letter is the letter code itself.
        if (lastWindowHash("abcz", 1) != 26) throw new AssertionError("k = 1");
        // Java claim: 1,000,000,006 * 27 overflows int, so the code must multiply in long.
        int wrapped = 1_000_000_006 * 27;
        if ((long) wrapped == 1_000_000_006L * 27) throw new AssertionError("int product should overflow");
        // Random tests against the BigInteger oracle with a seeded generator.
        Random rnd = new Random(34_01);
        for (int t = 0; t < 3000; t++) {
            int n = 1 + rnd.nextInt(60);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(26)));
            int k = 1 + rnd.nextInt(n);
            if (lastWindowHash(sb.toString(), k) != oracle(sb.toString(), k)) throw new AssertionError("mismatch " + sb + " " + k);
        }
        System.out.println("ok");
    }
}verified
Variation

Repeated DNA Sequences

LeetCode 187

Problem Specification. Let s be a string over the letters A, C, G and T. A sequence is a substring of length exactly 10. Return every sequence that occurs at least twice in s, where occurrences may overlap, each sequence listed once, in ascending alphabetical order. This lesson uses the exact 2-bit code of each window as its key, so the contract here asks for sorted output and never relies on a modulus.

Input Constraints. The limits are:

  • Length of s is between 0 and 100,000.
  • Alphabet is A, C, G and T only.
  • Answer is a list of 10-letter strings, empty when no sequence repeats.
  • Order is ascending by the order A, C, G, T.

Example 1. Input s = "AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT", output ["AAAAACCCCC", "CCCCCAAAAA"].

Example 2. Input s = "AAAAAAAAAAAAA" with 13 letters, output ["AAAAAAAAAA"]. Four overlapping windows are equal, yet the sequence appears once in the answer. An input shorter than 10 letters gives an empty list.

Prerequisites. The fixed-window hash exercise and the 2-bit DNA codes from the insight.

What This Exercise Changes. The stored key changes from a modulus-reduced hash to an exact 2-bit code, so the collision check is removed.

Hint

Twenty bits hold ten letters. Which operation drops the oldest two bits when a new letter enters?

Algorithmic Solution (attempt the problem first)

Approach. The four letters get the 2-bit codes A as 0, C as 1, G as 2 and T as 3, so a window of 10 letters is a 20-bit integer. Appending a letter shifts the key left by 2 bits and adds the code. A mask of 20 one-bits then drops the oldest letter, which replaces the subtraction of the rolling update and removes any need for a modulus or a negative-value fix. The invariant is that after index end, key holds exactly the 20 bits of the last 10 letters, so two windows are equal exactly when their keys are equal and no collision check is required.

A byte array of size 2^20 counts each key up to 2. A key reaches the count 2 on its second occurrence and joins the answer once, so overlapping windows and triple repeats never duplicate an entry. Numeric order of equal-length keys matches alphabetical order under the code order A, C, G, T, so sorting the integer keys sorts the answer, and the strings are built only for the final answer.

Complexity.

  • Time is O(n + R log R), because the scan does constant work per letter and sorting sorts the R repeated keys; R is at most n.
  • Space is O(2^20 + R), because the count array has a fixed size of about one million bytes and the answer holds R keys.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Random;
import java.util.TreeMap;

public class RepeatedDnaSolution {
    static final int K = 10;
    static final int MASK = (1 << (2 * K)) - 1;

    /** Maps A, C, G, T to 0, 1, 2, 3; the alphabet is the stated assumption of the contract. */
    static int code(char c) {
        // The switch is exhaustive for the contract alphabet; anything else is a caller error.
        switch (c) {
            case 'A': return 0;
            case 'C': return 1;
            case 'G': return 2;
            case 'T': return 3;
            default: throw new IllegalArgumentException("bad letter " + c);
        }
    }

    /**
     * Returns every 10-letter sequence that occurs at least twice, once each, in ascending order.
     * Time: O(n + R log R), because the scan is linear and the R repeated keys are sorted.
     * Space: O(2^20 + R), because of the fixed count table and the answer keys.
     * Invariant: after index end, key equals the 2-bit digits of s[end-9..end] exactly.
     */
    static List<String> repeated(String s) {
        // The table stores 0, 1 or 2 per key; 2 means the key already joined the answer.
        byte[] seen = new byte[1 << (2 * K)];
        int[] keys = new int[Math.max(s.length(), 1)];
        int count = 0;
        int key = 0;
        // One pass; each iteration does a shift, a mask and a table lookup.
        for (int end = 0; end < s.length(); end++) {
            // Shift the old letters up by 2 bits, add the new code, and drop the oldest letter with the mask.
            key = ((key << 2) | code(s.charAt(end))) & MASK;
            // The first K - 1 iterations only fill the key, so no complete window exists yet.
            if (end < K - 1) continue;
            // The second sighting records the key once; later sightings change nothing.
            if (seen[key] == 1) { seen[key] = 2; keys[count++] = key; }
            else if (seen[key] == 0) seen[key] = 1;
        }
        // Numeric order of equal-length 2-bit keys equals alphabetical order for A < C < G < T.
        Arrays.sort(keys, 0, count);
        List<String> out = new ArrayList<>();
        // Strings are built only for answers, never inside the scan.
        for (int i = 0; i < count; i++) {
            char[] w = new char[K];
            int v = keys[i];
            for (int j = K - 1; j >= 0; j--) { w[j] = "ACGT".charAt(v & 3); v >>= 2; }
            out.add(new String(w));
        }
        return out;
    }

    /** Oracle: count every substring of length 10 in a TreeMap, which also sorts the keys. */
    static List<String> oracle(String s) {
        TreeMap<String, Integer> counts = new TreeMap<>();
        // Direct counting with substring copies; slow but obviously correct.
        for (int i = 0; i + K <= s.length(); i++) counts.merge(s.substring(i, i + K), 1, Integer::sum);
        List<String> out = new ArrayList<>();
        for (var e : counts.entrySet()) if (e.getValue() >= 2) out.add(e.getKey());
        return out;
    }

    public static void main(String[] args) {
        // The statement examples.
        if (!repeated("AAAAACCCCCAAAAACCCCCCAAAAAGGGTTT").equals(List.of("AAAAACCCCC", "CCCCCAAAAA"))) throw new AssertionError("example 1");
        if (!repeated("AAAAAAAAAAAAA").equals(List.of("AAAAAAAAAA"))) throw new AssertionError("overlapping repeats listed once");
        // Inputs shorter than 10 letters, and the empty input, give an empty list.
        if (!repeated("ACGTAC").isEmpty() || !repeated("").isEmpty()) throw new AssertionError("short input");
        // Exactly 10 letters is one window and cannot repeat.
        if (!repeated("ACGTACGTAC").isEmpty()) throw new AssertionError("single window");
        // Ten letters need 20 bits, so the key fits in an int with no modulus.
        if (MASK != 1_048_575) throw new AssertionError("mask size");
        // Random tests over a tiny alphabet slice so repeats are common, against the TreeMap oracle.
        Random rnd = new Random(34_02);
        for (int t = 0; t < 1500; t++) {
            int n = rnd.nextInt(60);
            int letters = 1 + rnd.nextInt(4);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append("ACGT".charAt(rnd.nextInt(letters)));
            if (!repeated(sb.toString()).equals(oracle(sb.toString()))) throw new AssertionError("mismatch " + sb);
        }
        System.out.println("ok");
    }
}verified
Edge Cases

Negative Modular Difference

Author exercise

Problem Specification. Let s be a string of lowercase letters with codes a to 1 up to z to 26, let k be a window length, use base 27 and modulus 101. Return the array of hashes of all windows of length k, from the leftmost to the rightmost, where the hash of a window w is the sum of code(w[j]) * 27^(k-1-j) for j from 0 to k - 1, reduced modulo 101. Compute each hash from the previous one by sliding. After the outgoing letter is removed, the intermediate value must be brought back into the range 0 to 100 before the multiplication.

Input Constraints. The limits are:

  • Length of s is between 0 and 1,000.
  • Window k is at least 1, and the answer is empty when k > s.length().
  • Alphabet is lowercase a to z only.
  • Answer has s.length() - k + 1 values, each between 0 and 100.

Example 1. Input s = "abcab", k = 3, output [79, 25, 95]. The second slide subtracts 44 from 25 and gets -19 before the fix.

Example 2. Input s = "zyxzy", k = 3, output [59, 12, 43]. The first slide subtracts 572 from 59, so the unreduced difference is -513 and a single addition of 101 would still leave it negative.

Prerequisites. The rolling update and the Java behavior of % for negative values.

What This Exercise Changes. The subtracted term is reduced before the difference is taken, so one addition of the modulus afterwards is enough and the order of those operations matters.

Hint

What range does % give for a negative left operand in Java? How many multiples of 101 can the subtracted term span?

Algorithmic Solution (attempt the problem first)

Approach. The method computes the first hash with the multiply-and-add step and then slides across the string. At each slide it subtracts the outgoing letter times power. The product is reduced by the modulus first, so it lies between 0 and 100, and the difference with the running hash lies between -100 and 100. Java % keeps the sign of the left operand, so a negative difference stays negative and would feed a negative number into the next multiplication. Adding the modulus once after the subtraction and reducing again returns the value to the range 0 to 100. The invariant is that hash is always in the range 0 to 100 and equals the polynomial value of the current window.

The tests also run the broken variant that skips the addition. It produces a negative value on the first statement example and, after the multiplication, a wrong hash, which shows that the repair is the part that matters. If the subtracted product is not reduced first, the difference can fall far below -101, and one addition of the modulus would not be enough.

Complexity.

  • Time is O(n) for a string of length n, because each slide is a constant number of operations and the first window costs k steps.
  • Space is O(n - k + 1), because the result holds one hash per window; the working state is O(1).
import java.util.Arrays;
import java.util.Random;

public class NegativeModularDifferenceSolution {
    static final long BASE = 27;
    static final long MOD = 101;

    /**
     * Returns the hash of every window of length k, each found by sliding from the previous one.
     * Time: O(n), because every slide is a constant number of operations.
     * Space: O(n - k + 1), because the answer array has one slot per window.
     * Invariant: hash is in [0, MOD - 1] and equals the polynomial value of the current window.
     */
    static int[] windowHashes(String s, int k, boolean normalize) {
        int n = s.length();
        // No window fits, so the answer is empty.
        if (k > n) return new int[0];
        int[] result = new int[n - k + 1];
        long power = 1;
        // power is BASE^(k-1) mod MOD, the weight of the leading letter.
        for (int j = 1; j < k; j++) power = power * BASE % MOD;
        long hash = 0;
        // One pass; every iteration is a constant number of arithmetic operations.
        for (int end = 0; end < n; end++) {
            if (end >= k) {
                long out = s.charAt(end - k) - 'a' + 1;
                // The reduced product lies in [0, 100], so the raw difference lies in [-100, 100].
                long raw = hash - out * power % MOD;
                // The repair adds MOD once and reduces again; skipping it leaves a negative value behind.
                hash = normalize ? (raw + MOD) % MOD : raw;
            }
            // Append the incoming letter; a negative hash from the broken variant propagates here.
            hash = (hash * BASE + (s.charAt(end) - 'a' + 1)) % MOD;
            if (end >= k - 1) result[end - k + 1] = (int) hash;
        }
        return result;
    }

    /** Oracle: Horner evaluation of every window from scratch, reduced at each step. */
    static int[] oracle(String s, int k) {
        if (k > s.length()) return new int[0];
        int[] result = new int[s.length() - k + 1];
        // Each window is evaluated independently, so there is no sliding state to get wrong.
        for (int i = 0; i < result.length; i++) {
            long h = 0;
            for (int j = 0; j < k; j++) h = (h * BASE + (s.charAt(i + j) - 'a' + 1)) % MOD;
            result[i] = (int) h;
        }
        return result;
    }

    public static void main(String[] args) {
        // The statement examples.
        if (!Arrays.equals(windowHashes("abcab", 3, true), new int[] {79, 25, 95})) throw new AssertionError("example 1");
        if (!Arrays.equals(windowHashes("zyxzy", 3, true), new int[] {59, 12, 43})) throw new AssertionError("example 2");
        // Empty input and a window longer than the string both give an empty answer.
        if (windowHashes("", 3, true).length != 0 || windowHashes("ab", 3, true).length != 0) throw new AssertionError("empty");
        // Java claims: % keeps the sign of the left operand, and floorMod does not.
        if (-19 % 101 != -19) throw new AssertionError("remainder keeps sign");
        if (Math.floorMod(-19, 101) != 82) throw new AssertionError("floorMod is non-negative");
        // The unreduced difference of example 2 is -513, and one addition of 101 stays negative.
        long power = 27L * 27 % MOD;
        if (59 - 26 * power != -513 || -513 + 101 >= 0) throw new AssertionError("raw difference");
        // The reduced product used by the method keeps the difference above -101.
        if (59 - 26 * power % MOD != -8) throw new AssertionError("reduced difference");
        // Without the repair the second slide of example 1 holds -19 and the hashes go wrong.
        if (Arrays.equals(windowHashes("abcab", 3, false), new int[] {79, 25, 95})) throw new AssertionError("broken variant should differ");
        // Random tests against the from-scratch oracle, including windows longer than the string.
        Random rnd = new Random(34_03);
        for (int t = 0; t < 3000; t++) {
            int n = rnd.nextInt(40);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(26)));
            int k = 1 + rnd.nextInt(n + 2);
            if (!Arrays.equals(windowHashes(sb.toString(), k, true), oracle(sb.toString(), k))) throw new AssertionError("mismatch " + sb + " " + k);
        }
        System.out.println("ok");
    }

Longest Duplicate Substring

LeetCode 1044

Problem Specification. Let s be a string of lowercase letters. A duplicate substring is a substring that occurs at least twice in s, where the occurrences may overlap. Return a duplicate substring of maximum length. When several duplicate substrings share the maximum length, return any one of them. When no duplicate exists, return the empty string. The lesson on suffix structures later in this chapter solves this problem with a suffix array. Here the contract requires a binary search on the length with a rolling hash, and a verified comparison for every hash match.

Input Constraints. The limits are:

  • Length of s is between 0 and 30,000.
  • Alphabet is lowercase a to z only.
  • Answer is a substring of s, or the empty string.
  • Ties allow any longest duplicate.
  • Verification is by index comparison, with no substring created inside the search loop.

Example 1. Input s = "banana", output "ana". The two occurrences start at indexes 1 and 3 and overlap on the letter a. This is the only duplicate of length 3.

Example 2. Input s = "aaaaa", output "aaaa", with occurrences at indexes 0 and 1. The input s = "abcd" gives the empty string.

Prerequisites. The collision check and the fixed-window scan from this lesson.

What This Exercise Changes. The window length is no longer given, so a binary search chooses it and the rolling hash answers one yes-or-no question per length.

Hint

If a duplicate of length L exists, does one of length L - 1 exist? What does that answer let you do with the lengths?

Algorithmic Solution (attempt the problem first)

Approach. A duplicate of length L implies a duplicate of every shorter length, because removing the last letter from both occurrences leaves two equal shorter substrings. The property is monotone, so a binary search over lengths from 1 to n - 1 finds the largest length for which a duplicate exists. Each probe slides a rolling hash across the string with base 27 and letter codes 1 to 26 and keeps a table from each hash value to the starts that produced it. When a window hash is already in the table, the code compares the new window with every stored start through regionMatches, which reads both windows in place and creates no substring. Only an exact match counts as a duplicate. The invariant of a probe is that hash equals the polynomial value of the current window and that the table holds every earlier start, so no true duplicate is missed and no false one is accepted.

Because every match is verified, a collision costs time but never changes the answer. The harness proves that by running the same code with a modulus of 13, which forces many collisions, and by counting that false matches did occur and were rejected. The result is the substring of the best start, which is copied once at the end.

Complexity.

  • Time is O(n log n) expected with a large modulus, because the binary search makes about log n probes and each probe is one linear pass with rare verification; a probe degrades toward O(n * L) if many windows collide.
  • Space is O(n), because one probe stores at most n - L + 1 starts in the table and no window text.
import java.util.ArrayList;
import java.util.HashMap;
import java.util.Random;

public class LongestDuplicateSubstringSolution {
    static final long BASE = 27;
    static final long BIG_MOD = 1_000_000_007L;
    /** Counts matches of equal hash with different text; used only by the harness. */
    static long falseMatches = 0;

    /**
     * Returns the start of a window of length len that equals an earlier window, or -1.
     * Time: O(n) expected per probe, because each window is hashed in constant time and verified only on a hash match.
     * Space: O(n), because the table holds up to n - len + 1 start indexes.
     * Invariant: hash is the polynomial value of s[end-len+1..end] mod mod, and the table holds all earlier starts.
     */
    static int findDuplicate(String s, int len, long mod) {
        int n = s.length();
        // power is BASE^(len-1) mod mod, the weight of the leading letter.
        long power = 1;
        for (int j = 1; j < len; j++) power = power * BASE % mod;
        HashMap<Long, ArrayList<Integer>> table = new HashMap<>();
        long hash = 0;
        // One pass over the string; every window costs a constant number of operations to hash.
        for (int end = 0; end < n; end++) {
            // The outgoing letter exists once the window has been full for a step.
            if (end >= len) {
                long out = s.charAt(end - len) - 'a' + 1;
                // Reduce the product first, then add mod once, so the value stays in [0, mod - 1].
                hash = (hash - out * power % mod + mod) % mod;
            }
            // Append the incoming letter.
            hash = (hash * BASE + (s.charAt(end) - 'a' + 1)) % mod;
            // Windows are complete only from index len - 1 onward.
            if (end < len - 1) continue;
            int start = end - len + 1;
            ArrayList<Integer> earlier = table.computeIfAbsent(hash, h -> new ArrayList<>());
            // Verified comparison: regionMatches reads both windows in place and allocates no substring.
            for (int other : earlier) {
                if (s.regionMatches(other, s, start, len)) return start;
                falseMatches++;
            }
            earlier.add(start);
        }
        return -1;
    }

    /**
     * Returns a longest substring that occurs at least twice, or the empty string.
     * Time: O(n log n) expected, because about log n probes each cost O(n) expected.
     * Space: O(n), because of the probe table.
     * Invariant: lo is a length with a known duplicate (or 0) and hi + 1 is a length with none.
     */
    static String longestDuplicate(String s, long mod) {
        int lo = 0, hi = s.length() - 1, bestStart = 0;
        // Binary search on the length; the search is valid because a duplicate of length L implies one of length L - 1.
        while (lo < hi) {
            int mid = (lo + hi + 1) >>> 1;
            int start = findDuplicate(s, mid, mod);
            // A duplicate of length mid exists, so the answer is at least mid; remember where it starts.
            if (start >= 0) { lo = mid; bestStart = start; }
            // No duplicate of length mid exists, so the answer is shorter.
            else hi = mid - 1;
        }
        // The only substring copy in the whole method happens here, once.
        return s.substring(bestStart, bestStart + lo);
    }

    /** Oracle: try lengths from longest down, using a HashSet of substring copies. */
    static int oracleLength(String s) {
        // Slow and exact: every length gets a full set of copied windows.
        for (int len = s.length() - 1; len >= 1; len--) {
            java.util.HashSet<String> seen = new java.util.HashSet<>();
            for (int i = 0; i + len <= s.length(); i++) if (!seen.add(s.substring(i, i + len))) return len;
        }
        return 0;
    }

    /** Counts occurrences of t in s, overlapping allowed. */
    static int occurrences(String s, String t) {
        int c = 0;
        for (int i = s.indexOf(t); i >= 0; i = s.indexOf(t, i + 1)) c++;
        return c;
    }

    public static void main(String[] args) {
        // The statement examples.
        if (!longestDuplicate("banana", BIG_MOD).equals("ana")) throw new AssertionError("example 1");
        if (!longestDuplicate("aaaaa", BIG_MOD).equals("aaaa")) throw new AssertionError("overlap");
        if (!longestDuplicate("abcd", BIG_MOD).isEmpty()) throw new AssertionError("no duplicate");
        // Empty and one-letter inputs have no duplicate.
        if (!longestDuplicate("", BIG_MOD).isEmpty() || !longestDuplicate("z", BIG_MOD).isEmpty()) throw new AssertionError("tiny");
        // Java claims: regionMatches compares in place with offsets, and a partial substring is a new object.
        String t = "banana";
        if (!t.regionMatches(1, t, 3, 3) || t.regionMatches(0, t, 2, 3)) throw new AssertionError("regionMatches");
        if (t.substring(1, 4) == t || t.substring(0, t.length()) != t) throw new AssertionError("substring identity");
        // Random tests with the large modulus and with a tiny modulus that forces collisions.
        Random rnd = new Random(34_04);
        for (int trial = 0; trial < 2500; trial++) {
            int n = rnd.nextInt(40);
            int letters = 1 + rnd.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(letters)));
            String s = sb.toString();
            int expected = oracleLength(s);
            for (long mod : new long[] {BIG_MOD, 13}) {
                String got = longestDuplicate(s, mod);
                // The length must equal the oracle length, and the text must really occur twice.
                if (got.length() != expected) throw new AssertionError("length " + s + " mod " + mod);
                if (expected > 0 && occurrences(s, got) < 2) throw new AssertionError("not a duplicate " + s);
            }
        }
        // The tiny modulus produced hash matches between different windows, and verification rejected each one.
        if (falseMatches == 0) throw new AssertionError("collisions should have occurred");
        System.out.println("ok");
    }

Match A Pattern Without Restarting

Problem

Why A Search Freezes On Repeated Text

A log viewer opens a two-megabyte export in which a faulty exporter padded every line with the letter a. An engineer searches for aaaaaaaaab, a pattern of nine letters a followed by one b. The search should finish at once, yet the viewer lags far behind what a single pass over the text would cost. The text holds about two million characters, and the viewer is comparing the pattern against almost every start position, nine characters deep each time, before the final b rejects it.

The same failure appears in any tool that scans text for a fixed pattern, such as a find command, a log filter or a file importer that looks for a marker line. The lesson asks one question. After a mismatch, what must the scan remember so that it never re-reads a text character it has already matched?

Simple approach

Trying Every Start Position

The direct method tries each start position in the text. At a start s it compares the pattern with the text one character at a time. When a character differs, the method discards the progress and tries start s + 1.

static int firstStart(String text, String pattern) {
    for (int s = 0; s + pattern.length() <= text.length(); s++) {
        int j = 0;
        while (j < pattern.length() && text.charAt(s + j) == pattern.charAt(j)) j++;
        if (j == pattern.length()) return s;
    }
    return -1;
}

On text aaaaaaaaaaab with pattern aaab the method matches three letters at the first start, fails on the fourth, and repeats that work at the next start. It is correct, and it uses no extra memory.

Bottleneck

Counting The Repeated Comparisons

Predict first: The text is 100 000 letters `a` and the pattern is 500 letters `a` followed by `b`. About how many character comparisons does the start-by-start method make, and which comparisons repeat?

About 50 million comparisons, because roughly 100 000 starts each match 500 letters before the b fails. Each text character is compared against up to 500 different pattern positions, and almost all of those comparisons were already implied by the previous start.

For a text of length n and a pattern of length m, the method makes up to (n - m + 1) * m comparisons, which is O(n * m). With n = 2 000 000 and m = 10 that is about 20 million comparisons, and with a 1 000-letter pattern it is about two billion.

The waste has a precise form. Suppose the scan matched the first five pattern characters at some start and then failed. Those five matched characters are the five text characters just read, so their content is known exactly. The restart reads them again, even though the pattern alone tells which shorter prefix of the pattern those same text characters already match.

The repeated work is therefore a re-comparison of text characters whose values the scan has already verified. A scan that moves the text index backward is the signal. The next section names the information that removes the backward move.

Key idea

Remembering The Longest Reusable Match

The Prefix Function

Take the prefix p[0..i], which holds the first i + 1 characters of the pattern. A border of p[0..i] is a non-empty string that is both a proper prefix of it and a suffix of it. A proper prefix is a prefix shorter than the whole string. The prefix function pi of the pattern stores, for each index i, the length of the longest border of p[0..i], and 0 when no border exists.

For the pattern ababaca, the prefix ababa has the borders a and aba, so pi[4] = 3.

Why A Mismatch Needs No Restart

Suppose k pattern characters currently match the end of the text read so far, and the next text character differs from p[k]. The matched characters equal p[0..k-1]. Any shorter match that could still be alive must be a prefix of the pattern that is also a suffix of p[0..k-1], which is exactly a border of it. The longest such border has length pi[k - 1].

The scan therefore sets k to pi[k - 1] and compares the same text character again. This step is a fallback. If the character still differs, another fallback uses the next shorter border, and the chain ends at k = 0. The text index never moves backward.

Why The Total Work Is Linear

Each text character raises k by at most 1, and each fallback lowers k by at least 1. The value of k never goes below 0, so the total number of fallbacks over the whole scan cannot exceed the total number of increases, which is at most n. The same argument builds pi itself in O(m) time, because building pi is a match of the pattern against itself.

State

State Kept During The Scan

The array construction and the search keep the same small state.

  • p is the pattern, read by index and never copied.
  • pi is the int array where pi[i] is the longest border length of p[0..i].
  • k is the matched length: the number of pattern characters that equal the end of the text read so far.
  • i is the text index (or the pattern index while building pi) and only moves forward.
  • n and m are the text length and the pattern length.

The state invariant is that k is the largest value less than m (or equal to m at a full match) for which p[0..k-1] is a suffix of the text read so far.

Walkthrough

Tracing The Fallbacks On ababaca

Building The Array For ababaca

The pattern ababaca is the case to study, because its mismatch at index 5 triggers two fallbacks in a row. In the trace below, the pointer i is the index being read and the pointer k is the matched length.

The scan reads b at index 1 and finds no match with p[0] = a, so pi[1] stays 0. Indexes 2, 3 and 4 match a, b, a against p[0], p[1], p[2], so k grows to 3. At index 5 the character c differs from p[3] = b. The first fallback sets k = pi[2] = 1, and c still differs from p[1] = b. The second fallback sets k = pi[0] = 0, and c differs from p[0] = a, so pi[5] = 0. At index 6 the character a matches p[0], so pi[6] = 1. The finished array is 0, 0, 1, 2, 3, 0, 1. The two consecutive fallbacks at index 5 are the reason the pattern is a good test: one fallback is not enough there. After the first fallback the length is 1 and c still fails against p[1]. The chain must continue to length 0 before the scan can give up on c.

Scanning A Text With The Array

Now the same array drives a scan of the text abababaca. The pointer i is the text index, and the pointer k is the number of pattern characters matched.

The first five letters match the pattern prefix ababa, so k reaches 5. The sixth letter is b, but p[5] is c. One fallback sets k = pi[4] = 3, which says that the last three text characters aba still match the pattern start. The letter b then equals p[3], so k grows to 4 without the text index moving. The scan continues, reaches k = 7 at index 8, and reports the start 2. A restart-based scan would have returned to index 1 after the mismatch and read five letters again. The saving is visible in the count of reads: the text has nine characters, and the trace performs one read for each of them plus one extra comparison after the fallback, ten comparisons in total, whereas the start-by-start method repeats the five-letter partial match.

Code

Building The Array And Searching

The Two Methods

Both methods use only index reads, so they allocate nothing except the array. The names border and matched in this code correspond to the border length and the matched length k of the trace.

// Longest border length for every prefix of the pattern.
static int[] borderLengths(String pat) {
    int[] pi = new int[pat.length()];
    int border = 0;
    for (int i = 1; i < pat.length(); i++) {
        while (border > 0 && pat.charAt(i) != pat.charAt(border)) border = pi[border - 1];
        if (pat.charAt(i) == pat.charAt(border)) border++;
        pi[i] = border;
    }
    return pi;
}

// First start of pat inside text, or -1. An empty pattern returns 0.
static int scanForPattern(String text, String pat) {
    if (pat.isEmpty()) return 0;
    int[] pi = borderLengths(pat);
    int matched = 0;
    for (int i = 0; i < text.length(); i++) {
        while (matched > 0 && text.charAt(i) != pat.charAt(matched)) matched = pi[matched - 1];
        if (text.charAt(i) == pat.charAt(matched)) matched++;
        if (matched == pat.length()) return i - pat.length() + 1;
    }
    return -1;
}

Cost And Java Details

  • borderLengths costs O(m) time and O(m) space for the array.
  • scanForPattern costs O(n + m) time in total, because the text index advances once per iteration and fallbacks are paid for by earlier growth.

The empty-pattern guard matters, because the first comparison would otherwise read pat.charAt(0) on an empty string and throw. The methods compare UTF-16 code units from charAt, so the lesson assumes text in which each character is one code unit, such as lowercase English letters.

When to use it

When The Prefix Function Applies

Recognizing The Pattern

Use this technique when one fixed pattern is matched against text that may contain long partial matches, or when a problem asks about the prefixes of a string that are also suffixes. The statement often reads as the longest prefix that is also a suffix, the period of a string, or a search that must run in linear time.

The invariant to state before coding is that k is the longest pattern prefix that is a suffix of the text read so far. Every fallback keeps that statement true, and every other move follows from it.

Two False Friends

The Z array looks like a close relative, because it is also an array of match lengths. It is a false friend of the prefix function. The Z array z stores, for each index i, the length of the longest common prefix of the whole string and the suffix that starts at i. The value z[i] looks forward from i. The value pi[i] looks backward and gives the longest border of p[0..i]. For aabxaab the Z array is 7,1,0,0,3,1,0 and the prefix function is 0,1,0,0,1,2,3. At index 4 the suffix aab matches the prefix for 3 characters, so z[4] = 3, while the longest border of aabxa is only a, so pi[4] = 1.

A second false friend is the rolling hash from the previous lesson. It also avoids restarting, yet an equal hash does not prove an equal string, while the prefix function compares characters and is exact.

When Not To Use It

Do not use it when the pattern is short and the text is small, because the library indexOf is clear enough. Do not use it for many patterns at once, since a trie with failure links serves that case. Do not use it when the match allows wildcards or edits, because a border no longer describes the reusable part.

Prefix Function

Author exercise

Problem Specification. A proper prefix of a string is a prefix whose length is less than the length of the string. A border of a string is a non-empty string that is both a proper prefix and a suffix of it. Given a string p, return an int array pi of the same length in which pi[i] is the length of the longest border of p[0..i], and 0 when p[0..i] has no border.

Input Constraints. The limits are:

  • Length is 0 <= p.length() <= 10^5.
  • Characters are lowercase English letters, each one UTF-16 code unit.
  • Empty input returns an empty array.
  • Mutation does not occur; p is immutable.

Example 1. Input p = "aabaaab", output [0,1,0,1,2,2,3].

Example 2. Input p = "abcabcabd", output [0,0,0,1,2,3,4,5,0]. The border grows to 5 and collapses to 0 at the last character.

Prerequisites. The border and prefix function definitions and the fallback step from this lesson.

What This Exercise Changes. Basic case: a mismatch replaces the current length by a stored shorter length and never restarts from 0.

Hint

When p[i] differs from p[k], which shorter border of the first k characters is the next to try, and where is its length stored?

Algorithmic Solution (attempt the problem first)

Approach. The array pi is filled left to right. Before position i is read, the variable k holds pi[i - 1], the length of the longest proper prefix of p[0..i-1] that is also a suffix of it. The character p[i] extends that border when it equals p[k]. When the two characters differ, no border of length k + 1 exists, so the loop replaces k with pi[k - 1], the next shorter border of the same text, and compares again. The loop stops when a character matches or when k reaches 0.

The invariant is that k is always the length of a border of the text read so far, and the borders are tried from longest to shortest. Every shorter border is reachable through pi, so no candidate is skipped. Each iteration of the outer loop raises k by at most 1, and each fallback lowers k by at least 1, so the total number of fallbacks never exceeds n - 1.

Complexity.

  • Time is O(n), because k rises at most n - 1 times in total and every fallback consumes one unit of that rise.
  • Space is O(n), because the answer array holds one int per position; the working state is the single int k.
import java.util.Arrays;
import java.util.Random;

public final class PrefixFunctionBuild {
    // Counts fallback iterations so that main can check the amortized bound.
    static int fallbacks;

    /**
     * Returns pi, where pi[i] is the length of the longest proper prefix of p[0..i] that is also a suffix of it.
     * Time: O(n), because the matched length k rises at most once per position and each fallback lowers it.
     * Space: O(n), because the result array has one entry per character.
     * Invariant: at the top of iteration i, k equals pi[i - 1].
     */
    static int[] prefixFunction(String p) {
        // One entry per character; pi[0] stays 0 because a one-character text has no proper prefix.
        int[] pi = new int[p.length()];
        // k is the current matched length; it is 0 before any character is read.
        int k = 0;
        // Position 0 needs no work, so the scan starts at 1 and costs n - 1 iterations.
        for (int i = 1; i < p.length(); i++) {
            // A mismatch moves k to the next shorter border; each pass lowers k, which pays for itself.
            while (k > 0 && p.charAt(i) != p.charAt(k)) {
                // Fall back to the longest border of the first k characters.
                k = pi[k - 1];
                // Instrumentation only: it counts fallbacks for the bound checked in main.
                fallbacks++;
            }
            // A match extends the border by one character; this is the only place k grows.
            if (p.charAt(i) == p.charAt(k)) k++;
            // Record the border length for position i.
            pi[i] = k;
        }
        // The caller reads fallback lengths from this array.
        return pi;
    }

    /**
     * Brute-force oracle that tests every proper prefix length against the suffix of the same length.
     * Time: O(n^3), because each position tries up to n lengths and each comparison costs up to n.
     * Space: O(n), because only the result array is stored.
     * Invariant: the first length that matches, tried from longest to shortest, is the maximum.
     */
    static int[] oracle(String p) {
        // Result array, one entry per position.
        int[] pi = new int[p.length()];
        // Every end position is handled independently.
        for (int i = 0; i < p.length(); i++) {
            // Lengths run from the longest proper candidate (i) down to 1.
            for (int len = i; len >= 1; len--) {
                // ok stays true while the prefix and the suffix agree character by character.
                boolean ok = true;
                // Compare p[j] with the character at the same offset inside the suffix ending at i.
                for (int j = 0; j < len && ok; j++) ok = p.charAt(j) == p.charAt(i + 1 - len + j);
                // The first agreeing length is the longest, so the search for this position ends.
                if (ok) { pi[i] = len; break; }
            }
        }
        // The oracle answer is compared with the fast answer in main.
        return pi;
    }

    public static void main(String[] args) {
        // Worked examples from the exercise, including the long match that collapses to 0.
        if (!Arrays.equals(prefixFunction("aabaaab"), new int[] {0, 1, 0, 1, 2, 2, 3})) throw new AssertionError("aabaaab");
        if (!Arrays.equals(prefixFunction("abcabcabd"), new int[] {0, 0, 0, 1, 2, 3, 4, 5, 0})) throw new AssertionError("abcabcabd");
        // A repeated letter makes every border as long as possible but never the whole text.
        if (!Arrays.equals(prefixFunction("aaaa"), new int[] {0, 1, 2, 3})) throw new AssertionError("aaaa");
        // The empty text yields an empty array.
        if (prefixFunction("").length != 0) throw new AssertionError("empty");
        // Random comparison with the oracle; the seed makes any failure reproducible.
        Random rnd = new Random(3402L);
        for (int t = 0; t < 3000; t++) {
            // Small alphabets create many borders and many fallbacks.
            int len = rnd.nextInt(14), alpha = 1 + rnd.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rnd.nextInt(alpha)));
            String p = sb.toString();
            // The amortized bound: the fallbacks of one call never exceed n - 1 (and are 0 for an empty text).
            fallbacks = 0;
            int[] got = prefixFunction(p);
            if (!Arrays.equals(got, oracle(p))) throw new AssertionError("mismatch on " + p);
            if (fallbacks > Math.max(0, len - 1)) throw new AssertionError("too many fallbacks on " + p);
        }

First Occurrence With KMP

LeetCode 28

Problem Specification. Given strings text and pattern, return the smallest index s such that text has pattern as a substring starting at s, or -1 when no such index exists. In this lesson the pattern may be empty, and an empty pattern occurs at index 0. The text index must not move backward during the scan.

Input Constraints. The limits are:

  • Text length is 0 <= text.length() <= 10^5.
  • Pattern length is 0 <= pattern.length() <= 10^5.
  • Characters are lowercase English letters, each one UTF-16 code unit.
  • Empty pattern returns 0, even when the text is empty.
  • Mutation does not occur; both strings are immutable.

Example 1. Input text = "abababaca", pattern = "ababaca", output 2.

Example 2. Input text = "aaaaab", pattern = "aab", output 3. The scan matches aa at several starts before the real occurrence.

Prerequisites. The Prefix Function exercise above.

What This Exercise Changes. The output changes from an array of lengths to the first start index, which is computed as i - m + 1 when k reaches m.

Hint

What does the matched length become when text[i] differs from pattern[k], and does the text index change?

Algorithmic Solution (attempt the problem first)

Approach. The pattern's prefix function is computed once. The text is then scanned with a single index i that never moves backward, and a state k that holds how many pattern characters currently match the text ending at i - 1. When text[i] differs from pattern[k], the state falls back to pi[k - 1], because the last pi[k - 1] matched characters are also the first characters of the pattern. When the characters agree, k grows. When k equals the pattern length, the match ends at i, so the start is i - m + 1, and the method returns it at once, which gives the first occurrence.

The empty pattern is handled before the scan, because the contract returns 0 for it and the loop would otherwise read pattern.charAt(0). The invariant is that k is the length of the longest pattern prefix that is a suffix of text[0..i-1], so no earlier start can have been missed.

Complexity.

  • Time is O(n + m), because the prefix function costs O(m) and the scan has the same amortized argument, with k rising at most n times.
  • Space is O(m), because the prefix function array has one entry per pattern character and the scan adds one int.
import java.util.Random;

public final class FirstOccurrenceKmp {
    /**
     * Returns the first index where pattern occurs in text, 0 for an empty pattern, or -1.
     * Time: O(n + m), because i only advances and k falls at most as often as it rose.
     * Space: O(m), because the prefix function array has one entry per pattern character.
     * Invariant: after reading text[i], k is the longest pattern prefix that is a suffix of text[0..i].
     */
    static int indexOf(String text, String pattern) {
        // m is the pattern length; reading it once avoids repeated calls.
        int m = pattern.length();
        // The contract returns 0 for an empty pattern, and the guard keeps the loop from reading pattern.charAt(0).
        if (m == 0) return 0;
        // Fallback lengths for the pattern, built once for O(m) time.
        int[] pi = new int[m];
        // k is reused first as the border length while building pi.
        for (int i = 1, k = 0; i < m; i++) {
            // A mismatch falls back to the next shorter border.
            while (k > 0 && pattern.charAt(i) != pattern.charAt(k)) k = pi[k - 1];
            // A match grows the border by one.
            if (pattern.charAt(i) == pattern.charAt(k)) k++;
            // Store the border length for position i.
            pi[i] = k;
        }
        // k now counts pattern characters matched against the text; i never moves backward.
        int k = 0;
        // One pass over the text costs n iterations plus the fallbacks that earlier growth paid for.
        for (int i = 0; i < text.length(); i++) {
            // Fall back while the next pattern character cannot extend the current match.
            while (k > 0 && text.charAt(i) != pattern.charAt(k)) k = pi[k - 1];
            // Extend the match when the characters agree.
            if (text.charAt(i) == pattern.charAt(k)) k++;
            // A full match ends at i, so the first start is i - m + 1; returning here makes it the first occurrence.
            if (k == m) return i - m + 1;
        }
        // No position completed the pattern.
        return -1;
    }

    /**
     * Brute-force oracle that tries every start and compares character by character.
     * Time: O(n * m), because each start compares up to m characters.
     * Space: O(1), because only indexes are stored.
     * Invariant: starts are tried in increasing order, so the first success is the first occurrence.
     */
    static int oracle(String text, String pattern) {
        // Every start that leaves room for the whole pattern.
        for (int s = 0; s + pattern.length() <= text.length(); s++) {
            // j counts agreeing characters from this start.
            int j = 0;
            while (j < pattern.length() && text.charAt(s + j) == pattern.charAt(j)) j++;
            // A full agreement is a match; an empty pattern matches at 0 here too.
            if (j == pattern.length()) return s;
        }
        // No start matched.
        return -1;
    }

    public static void main(String[] args) {
        // Plain match at the start and an absent pattern.
        if (indexOf("sadbutsad", "sad") != 0) throw new AssertionError("sad");
        if (indexOf("leetcode", "leeto") != -1) throw new AssertionError("leeto");
        // The hostile case: the match starts after a long partial match that must fall back.
        if (indexOf("aaaaab", "aab") != 3) throw new AssertionError("aaaaab");
        if (indexOf("abababaca", "ababaca") != 2) throw new AssertionError("ababaca");
        // The empty pattern returns 0, and this agrees with String.indexOf.
        if (indexOf("abc", "") != 0 || "abc".indexOf("") != 0) throw new AssertionError("empty pattern");
        // A pattern longer than the text cannot match.
        if (indexOf("ab", "abc") != -1) throw new AssertionError("long pattern");
        // Random comparison with the oracle and with String.indexOf.
        Random rnd = new Random(3403L);
        for (int t = 0; t < 5000; t++) {
            // Small alphabets force many partial matches.
            int alpha = 1 + rnd.nextInt(3);
            StringBuilder a = new StringBuilder(), b = new StringBuilder();
            for (int i = rnd.nextInt(16); i > 0; i--) a.append((char) ('a' + rnd.nextInt(alpha)));
            for (int i = rnd.nextInt(6); i > 0; i--) b.append((char) ('a' + rnd.nextInt(alpha)));
            String text = a.toString(), pat = b.toString();
            int want = oracle(text, pat);
            if (indexOf(text, pat) != want) throw new AssertionError("mismatch " + text + " / " + pat);
            if (text.indexOf(pat) != want) throw new AssertionError("library disagrees " + text + " / " + pat);
        }
        // A long repetitive input: a restarting scan would do about 10^8 comparisons here, this one does about 4 * 10^5.
        String big = "a".repeat(200_000), pat = "a".repeat(500) + "b";
        if (indexOf(big, pat) != -1) throw new AssertionError("big");
        if (indexOf(big + "b", pat) != 200_000 - 500) throw new AssertionError("big match");
    }

Repeated Prefixes

Author exercise

Problem Specification. Let p be a string and let k satisfy 1 <= k <= p.length(). A border length of the first k characters is an integer L with 0 < L < k such that p[0..L) equals p[k-L..k). Return all border lengths of the first k characters in decreasing order. The pattern ababaca with k = 5 needs two fallbacks to list all of them.

Input Constraints. The limits are:

  • Length is 1 <= p.length() <= 10^5.
  • Prefix length k satisfies 1 <= k <= p.length().
  • Characters are lowercase English letters.
  • Empty answer is an empty array, returned when no border exists.
  • Mutation does not occur; p is immutable.

Example 1. Input p = "ababaca", k = 5, output [3,1].

Example 2. Input p = "aaaa", k = 1, output [], because the whole prefix is excluded and no shorter length exists.

Prerequisites. The Prefix Function exercise above.

What This Exercise Changes. The output changes from one length to the full chain of lengths reached by repeated fallback.

Hint

Start from pi[k - 1]. Is every shorter border also a border of that longest border?

Algorithmic Solution (attempt the problem first)

Approach. The borders of the first k characters are exactly the values reached by starting at pi[k - 1] and repeatedly replacing a length L with pi[L - 1]. The longest border is pi[k - 1] by definition. Every shorter border of the full text is also a border of that longest border, because it is a prefix of it and a suffix of it, so pi[L - 1] names the next one. The walk stops when L reaches 0, and it never reports 0 or k itself because both are excluded by the word proper and by the requirement 0 < L.

For ababaca and k = 5, the text is ababa, pi[4] is 3, and pi[2] is 1, so the answer is 3 then 1. The invariant is that the list always holds the borders found so far in decreasing order, and L holds the longest border that is not yet listed.

Complexity.

  • Time is O(n) for the prefix function plus O(k) for the walk, because each step lowers L by at least 1.
  • Space is O(n), because the prefix function array has one entry per character; the answer holds at most k - 1 lengths.
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Random;

public final class RepeatedPrefixChain {
    /**
     * Returns every L with 0 < L < k such that p[0..L) equals p[k-L..k), in decreasing order.
     * Time: O(n + k), because the prefix function costs O(n) and each chain step lowers L.
     * Space: O(n), because the prefix function array has one entry per character.
     * Invariant: L is the longest border of p[0..k) that is shorter than every length already listed.
     */
    static int[] borderLengths(String p, int k) {
        // Standard prefix function; the borders of every prefix come from this one array.
        int[] pi = new int[p.length()];
        // The matched length while building pi.
        int m = 0;
        for (int i = 1; i < p.length(); i++) {
            // Falls back through shorter borders on a mismatch.
            while (m > 0 && p.charAt(i) != p.charAt(m)) m = pi[m - 1];
            // Extends the border on a match.
            if (p.charAt(i) == p.charAt(m)) m++;
            // Records the border length at position i.
            pi[i] = m;
        }
        // The list grows by one entry per chain step.
        List<Integer> out = new ArrayList<>();
        // Start at the longest proper border of the first k characters; the loop ends when L reaches 0.
        for (int len = pi[k - 1]; len > 0; len = pi[len - 1]) {
            // Each value visited is a border and is longer than every value visited later.
            out.add(len);
        }
        // Copy into a primitive array for the caller.
        int[] res = new int[out.size()];
        for (int i = 0; i < res.length; i++) res[i] = out.get(i);
        return res;
    }

    /**
     * Brute-force oracle that tests every length directly.
     * Time: O(k^2), because each of up to k lengths costs up to k comparisons.
     * Space: O(k), because the result list is bounded by k.
     * Invariant: lengths are tested from longest to shortest, which gives the decreasing order.
     */
    static int[] oracle(String p, int k) {
        // Result list in decreasing order of length.
        List<Integer> out = new ArrayList<>();
        // Only proper lengths 1..k-1 qualify.
        for (int len = k - 1; len >= 1; len--) {
            // ok stays true while prefix and suffix agree.
            boolean ok = true;
            for (int j = 0; j < len && ok; j++) ok = p.charAt(j) == p.charAt(k - len + j);
            // Keep the length when the whole comparison agreed.
            if (ok) out.add(len);
        }
        int[] res = new int[out.size()];
        for (int i = 0; i < res.length; i++) res[i] = out.get(i);
        return res;
    }

    public static void main(String[] args) {
        // The exercise example: two fallbacks from length 3 to 1 to nothing.
        if (!Arrays.equals(borderLengths("ababaca", 5), new int[] {3, 1})) throw new AssertionError("ababa");
        // The whole pattern has the single border "a".
        if (!Arrays.equals(borderLengths("ababaca", 7), new int[] {1})) throw new AssertionError("ababaca");
        // A repeated letter lists every shorter length, and k = 1 lists none because the whole text is excluded.
        if (!Arrays.equals(borderLengths("aaaa", 4), new int[] {3, 2, 1})) throw new AssertionError("aaaa");
        if (borderLengths("aaaa", 1).length != 0) throw new AssertionError("k = 1");
        // Random comparison with the oracle for every legal k.
        Random rnd = new Random(3404L);
        for (int t = 0; t < 3000; t++) {
            int len = 1 + rnd.nextInt(12), alpha = 1 + rnd.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rnd.nextInt(alpha)));
            String p = sb.toString();
            for (int k = 1; k <= len; k++) {
                if (!Arrays.equals(borderLengths(p, k), oracle(p, k))) throw new AssertionError("mismatch " + p + " k=" + k);
            }
        }
    }

Longest Happy Prefix

LeetCode 1392

Problem Specification. A happy prefix of a string s is a non-empty string that is a proper prefix of s and also a suffix of s. Return the longest happy prefix of s as a String, or the empty string when none exists. The prefix and the suffix may overlap inside s.

Input Constraints. The limits are:

  • Length is 1 <= s.length() <= 10^5.
  • Characters are lowercase English letters.
  • Empty answer is the empty string "", never null.
  • Mutation does not occur; s is immutable.

Example 1. Input s = "level", output "l".

Example 2. Input s = "ababab", output "abab". The prefix and the suffix overlap.

Prerequisites. The Prefix Function and Repeated Prefixes exercises above.

What This Exercise Changes. The array is no longer the output; only its last entry is read, and the answer is cut from the string at that length.

Hint

Which single entry of the prefix function already holds the length of the answer?

Algorithmic Solution (attempt the problem first)

Approach. A happy prefix is a non-empty proper prefix that is also a suffix, and the longest one is by definition the last value of the prefix function, pi[n - 1]. The answer is the first pi[n - 1] characters of the string, and the empty string when that value is 0. The prefix function never reports the whole string, so the proper requirement holds without a separate check. Overlap is allowed, so ababab returns abab.

The invariant is the one from the Build exercise: after the loop, k is the longest border of the entire string. Only one substring is created, at the end, because every comparison inside the loop uses indexes.

Complexity.

  • Time is O(n), because the prefix function is linear and the final copy costs at most n characters.
  • Space is O(n), because the array holds one entry per character and the returned string can be nearly as long.
import java.util.Random;

public final class HappyPrefixFinal {
    /**
     * Returns the longest proper prefix of s that is also a suffix, or the empty string.
     * Time: O(n), because the border length rises at most n times and falls no more often than it rose.
     * Space: O(n), because the fallback array has one entry per character.
     * Invariant: after reading s[i], k is the longest proper border of s[0..i].
     */
    static String longestHappyPrefix(String s) {
        // Fallback lengths; only the last entry is needed, but the others drive the loop.
        int[] pi = new int[s.length()];
        // k is the length of the current border.
        int k = 0;
        // Scan from position 1; a single character has no proper border.
        for (int i = 1; i < s.length(); i++) {
            // Mismatch: fall back to the next shorter border, using indexes and no substring.
            while (k > 0 && s.charAt(i) != s.charAt(k)) k = pi[k - 1];
            // Match: the border grows by one character.
            if (s.charAt(i) == s.charAt(k)) k++;
            // Record the border at position i.
            pi[i] = k;
        }
        // One substring at the end; k = 0 yields the empty string and k < n keeps the prefix proper.
        return s.substring(0, k);
    }

    /**
     * Brute-force oracle that tries lengths from longest to shortest.
     * Time: O(n^2), because each of up to n lengths costs up to n comparisons.
     * Space: O(n), because the answer is one substring.
     * Invariant: the first length that agrees is the longest.
     */
    static String oracle(String s) {
        // Proper lengths only: n - 1 down to 1.
        for (int len = s.length() - 1; len >= 1; len--) {
            // Compare the first len characters with the last len characters.
            boolean ok = true;
            for (int j = 0; j < len && ok; j++) ok = s.charAt(j) == s.charAt(s.length() - len + j);
            // The first agreeing length is the maximum.
            if (ok) return s.substring(0, len);
        }
        // No proper border.
        return "";
    }

    public static void main(String[] args) {
        // Overlapping border: the prefix and the suffix share characters.
        if (!longestHappyPrefix("ababab").equals("abab")) throw new AssertionError("ababab");
        // A single-letter border.
        if (!longestHappyPrefix("level").equals("l")) throw new AssertionError("level");
        // No border returns the empty string, and substring(0, 0) is empty.
        if (!longestHappyPrefix("abcd").isEmpty() || !"abcd".substring(0, 0).isEmpty()) throw new AssertionError("abcd");
        // The whole string is never returned, even when it is one repeated letter.
        if (!longestHappyPrefix("aaaa").equals("aaa")) throw new AssertionError("aaaa");
        // A one-character string has no proper border.
        if (!longestHappyPrefix("a").isEmpty()) throw new AssertionError("a");
        // Random comparison with the oracle.
        Random rnd = new Random(3405L);
        for (int t = 0; t < 5000; t++) {
            int len = 1 + rnd.nextInt(14), alpha = 1 + rnd.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rnd.nextInt(alpha)));
            String s = sb.toString();
            if (!longestHappyPrefix(s).equals(oracle(s))) throw new AssertionError("mismatch " + s);
        }
    }

Z Array

Author exercise

Problem Specification. For a string s of length n, define z[i] as the length of the longest common prefix of s and the suffix s[i..]. Define z[0] = n by convention. Return the array z. Then explain how the window [l, r) of the rightmost match found so far plays the role that the matched length k plays in the prefix function.

Input Constraints. The limits are:

  • Length is 0 <= s.length() <= 10^5.
  • Characters are lowercase English letters, each one UTF-16 code unit.
  • Empty input returns an empty array.
  • Convention z[0] = n for every non-empty string.
  • Mutation does not occur; s is immutable.

Example 1. Input s = "aabxaab", output [7,1,0,0,3,1,0].

Example 2. Input s = "aaaaa", output [5,4,3,2,1]. Each position reuses the entry to its left.

Prerequisites. All four exercises above.

What This Exercise Changes. The state changes from one length k of the text read so far to a window of text already compared with the prefix.

Hint

If position i lies inside the window that starts at l, which earlier entry already describes the same characters, and how far may it be trusted?

Algorithmic Solution (attempt the problem first)

Approach. The array z is filled left to right while the algorithm keeps one window [l, r), the segment that starts at l, ends before r, and equals the prefix s[0..r-l). For a new position i inside the window, the characters s[i..r) equal s[i-l..r-l), so z[i] starts at min(r - i, z[i - l]) without any comparison. For a position outside the window the start is 0. The loop then extends by direct comparison, and the window moves to [i, i + z[i]) when that reaches farther right.

The invariant is that every character of s before r has already been compared against the prefix, and r never decreases. The extension loop only runs past r, so it advances r by one on every successful comparison, and r is at most n. This gives O(n) in total.

The two methods keep different state. The window state is a segment of the text, and it answers how far each suffix matches the prefix. The fallback state is a single length, and it answers which prefix the text currently ends. The assertions below show they carry the same information, because the prefix function is recovered from z alone by a pass that writes each entry once.

Complexity.

  • Time is O(n), because r rises with every successful comparison, never falls, and is capped at n, while every other step is constant work.
  • Space is O(n), because the result array has one entry per position; the window needs only two ints.
import java.util.Arrays;
import java.util.Random;

public final class ZArrayWindow {
    /**
     * Returns z, where z[i] is the length of the longest common prefix of s and s[i..], with z[0] = n.
     * Time: O(n), because the right edge r never moves left and every direct comparison moves it right.
     * Space: O(n), because the result has one entry per position.
     * Invariant: s[l..r) equals s[0..r-l) and r is the farthest right edge found so far.
     */
    static int[] zArray(String s) {
        // One entry per position; z[0] is defined as n by this contract.
        int n = s.length();
        int[] z = new int[n];
        if (n == 0) return z;
        z[0] = n;
        // The window [l, r) starts empty.
        int l = 0, r = 0;
        // Position 0 is fixed, so the scan starts at 1.
        for (int i = 1; i < n; i++) {
            // len starts at the amount already known to match.
            int len = 0;
            // Inside the window the mirrored entry z[i - l] is reused, capped so it never claims text beyond r.
            if (i < r) len = Math.min(r - i, z[i - l]);
            // Direct comparison runs only past what is known; each success advances i + len, which cannot pass n.
            while (i + len < n && s.charAt(len) == s.charAt(i + len)) len++;
            // Record the answer for position i.
            z[i] = len;
            // Move the window when this match reaches farther right than any earlier one.
            if (i + len > r) { l = i; r = i + len; }
        }
        // The caller reads match lengths from this array.
        return z;
    }

    /**
     * Brute-force oracle that compares each suffix with the prefix.
     * Time: O(n^2), because each of n positions compares up to n characters.
     * Space: O(n), because the result has one entry per position.
     * Invariant: the loop stops at the first mismatch, so the count is the longest common prefix.
     */
    static int[] oracle(String s) {
        int[] z = new int[s.length()];
        // Position 0 is the whole string by definition.
        if (s.length() > 0) z[0] = s.length();
        for (int i = 1; i < s.length(); i++) {
            // Count agreeing characters from the start of the prefix and of the suffix.
            int len = 0;
            while (i + len < s.length() && s.charAt(len) == s.charAt(i + len)) len++;
            z[i] = len;
        }
        return z;
    }

    /**
     * Recovers the prefix function from z alone: each border end is written once, by the earliest window covering it.
     * Time: O(n), because every position is written at most once and each scan stops at a written entry.
     * Space: O(n), because the result has one entry per position.
     * Invariant: pi[j] holds the longest border ending at j once some window with start i + length - 1 >= j has been seen.
     */
    static int[] prefixFromZ(int[] z) {
        int[] pi = new int[z.length];
        // Each start i with z[i] > 0 claims the end positions i .. i + z[i] - 1 that are still unclaimed.
        for (int i = 1; i < z.length; i++) {
            // Walk from the farthest end down; a written entry means all nearer ones are already written.
            for (int j = z[i] - 1; j >= 0 && pi[i + j] == 0; j--) pi[i + j] = j + 1;
        }
        return pi;
    }

    /** Prefix function by fallback, used only to compare with prefixFromZ in main. Time: O(n). Space: O(n). */
    static int[] fallbackPrefix(String p) {
        int[] pi = new int[p.length()];
        int k = 0;
        for (int i = 1; i < p.length(); i++) {
            // Fall back on mismatch.
            while (k > 0 && p.charAt(i) != p.charAt(k)) k = pi[k - 1];
            // Extend on match.
            if (p.charAt(i) == p.charAt(k)) k++;
            pi[i] = k;
        }
        return pi;
    }

        if (!Arrays.equals(zArray("aabxaab"), new int[] {7, 1, 0, 0, 3, 1, 0})) throw new AssertionError("aabxaab");

Problem

A Padding Line Freezes The Viewer

A log viewer has a feature that highlights the longest palindromic run in each line, meaning the longest stretch of characters that reads the same forward and backward. The feature works well on ordinary lines. Then a customer opens a file in which one line holds 100,000 copies of the same padding character, and the viewer freezes for many seconds. The feature tests every position as the middle of a possible palindrome, and on this line each test walks almost as far as the line allows.

This lesson answers one question: how can a program find the palindromes around every center in time proportional to the line length, so the padding line costs no more than any other line of the same size? Centers come in two kinds. A character is the center of a palindrome with odd length, and the gap between two neighbouring characters is the center of a palindrome with even length. The answer must handle both kinds.

Simple approach

Expanding Outward From Each Center

The direct method treats every position as a possible center and grows a window outward while the two end characters are equal. It runs once for odd lengths, where the window starts as a single character, and once for even lengths, where the window starts as an empty gap between two characters. It remembers the longest window found, and it replaces the answer only when a window is strictly longer, so the leftmost window wins a tie.

static int[] longestByExpansion(String s) {
    int bestStart = 0, bestLen = 0;
    for (int center = 0; center < s.length(); center++) {
        for (int parity = 0; parity < 2; parity++) {
            // parity 0 starts a one-character window, parity 1 starts an empty gap window
            int lo = center, hi = center + parity;
            while (lo >= 0 && hi < s.length() && s.charAt(lo) == s.charAt(hi)) {
                lo--;
                hi++;
            }
            int len = hi - lo - 1; // number of characters between the failed ends
            if (len > bestLen) {
                bestLen = len;
                bestStart = lo + 1;
            }
        }
    }
    return new int[] {bestStart, bestLen};
}

On abaab the method finds aba around the first b and baab around the gap between the two a characters, and it returns start 1 with length 4. The method is correct, short, and fast on ordinary text, and it uses no memory beyond a few integers.

Bottleneck

Counting The Repeated Comparisons

Predict first: On a line of n identical characters, about how many character comparisons does the expansion method make, and which comparisons does it repeat?

Each center expands until it reaches the nearer end of the line, so the total is about n^2 / 2 comparisons, which is O(n^2). Center number k repeats the same equal pairs that center number k - 1 already compared, only shifted by one position.

Where The Cost Comes From

Every center scans on its own and forgets what earlier centers learned. On a line of n identical characters, the odd center at index i makes about min(i, n - 1 - i) successful comparisons, and the sum over all indexes is about n^2 / 4. The even centers add the same amount, so the total is about n^2 / 2, which is O(n^2). For n = 100,000 that is about 5 * 10^9 comparisons, which explains the frozen viewer. A line of n distinct characters costs only O(n), so the method hides its worst case until the input is repetitive.

The Repeated Work

Once the method has found a long palindrome, the characters inside it are known to be symmetric. A center that sits inside that palindrome sees a left half that is the reversed right half of another center it has already finished. The method still compares those pairs again. The repeated work is the re-comparison of characters that a finished center already compared, and the lesson removes it.

Key idea

Reusing Matches Inside A Known Palindrome

Three ideas remove the repeated comparisons: one array that covers both kinds of center, a copy of an earlier answer for a position inside a known palindrome, and a limit on how much of that copy is trustworthy.

One Array For Both Parities

A palindrome of odd length has a character at its center, and a palindrome of even length has a gap at its center. Two kinds of center normally need two loops and two result arrays. Insert one separator character, written # here, before the first letter, between every pair of letters and after the last letter. The string abab becomes #a#b#a#b#, and the separator must not occur in the original string. Every palindrome of the new string has odd length and a single character as its center, and the gap between two letters has become an ordinary separator position.

The radius of position i is the largest k such that the characters from index i - k through i + k form a palindrome. The code stores it in an array named rad. Because separators are added in matching pairs, the radius at i equals the length of the longest palindrome of the original string that is centered there, and that palindrome starts at index (i - radius) / 2 of the original string.

Copying From The Mirror Position

Suppose the scan has finished all positions before i. It remembers the finished palindrome whose right edge right = center + rad[center] lies farthest to the right. If i lies inside that palindrome, the mirror position of i is j = 2 * center - i, the position at the same distance from center on the other side. The big palindrome reads the same in both directions, so the text around i is the reversed text around j. A palindrome centered at j that fits entirely inside the big one therefore has a reflected twin centered at i, with the same radius. When rad[j] is smaller than right - i, the radius at i equals rad[j] exactly, and no comparison is needed.

Clamping At The Right Edge

The characters beyond right have not been compared with anything on the left side, so the reflection argument stops at that edge. When rad[j] is at least right - i, the code must clamp the copied value to right - i, which is the largest radius the big palindrome guarantees. Only after the clamp does it compare characters one pair at a time beyond right, and every successful comparison moves right farther to the right.

The invariant is that every position inside rad[i] of i is already known to match before an expansion starts. The value of right never decreases and never exceeds the last index, so successful comparisons happen at most once per index in total. Each position adds at most one failed comparison. The whole scan is therefore linear in the length of the separator string, which is 2n + 1 for an input of length n.

State

Values The Scan Keeps

The scan keeps five values next to the current index i, and all of them describe the separator string t of length m = 2n + 1.

  • t holds the input letters with one separator before, between and after them.
  • rad holds one radius per index of t, and rad[i] is final once the scan leaves i.
  • center is the index of the finished palindrome with the farthest right edge.
  • right equals center + rad[center], the last index known to match.
  • j equals 2 * center - i, the mirror of the current index i.

When i is greater than or equal to right, the scan copies nothing and starts with radius 0.

Walkthrough

Tracing Two Strings Step By Step

The pointer i marks the position being finished, the pointer c marks center, and the pointer r marks right. Each step shows the state after the scan finishes one position. The variable copied is the radius taken from the mirror before any comparison, and expanded is the number of extra matching pairs found by comparing. The final rad equals copied plus expanded.

Tracing abaab

The string abaab becomes #a#b#a#a#b#, which has 11 positions. Positions 0 to 3 start fresh, because right has not passed them. Position 3 is the letter b, and it expands to radius 3, so center moves to 3 and right moves to 6. Position 4 has mirror 2, whose radius is 0, so it copies 0. Position 5 has mirror 1 with radius 1, and that equals right - i, so the copy reaches the edge exactly and one more comparison is needed. That comparison fails, so the radius stays 1.

Position 6 is the gap between the two letters a. It is not inside any palindrome that extends past it, so it starts fresh and expands to radius 4, which is baab. Now center is 6 and right is 10. Positions 7 and 8 copy radii 1 and 0 from their mirrors. Position 9 has mirror 3 with radius 3, but right - i is only 1, so the clamp reduces the copy to 1. The scan keeps 1 because the comparison beyond the edge fails. Position 10 is at right, so it starts fresh with radius 0.

Tracing abab With A Clamp

The string abab becomes #a#b#a#b#, with 9 positions. Position 3 expands to radius 3 and moves right to 6. Position 5 expands to radius 3, so center is 5 and right is 8. Position 7 is the letter b, and its mirror is 3, whose radius is 3. The value right - i is 1, because index 8 is the last position. The clamp gives 1, and an unclamped copy would claim radius 3 for a position that has only one character to its right.

The final radii are 0 1 0 3 0 3 0 1 0. The largest value is 3, first reached at index 3, so the longest palindrome is aba and it starts at original index (3 - 3) / 2 = 0.

Code

Manacher's Scan In Java

Building The Padded Array

The first method builds the separator string as a char array, so later code reads characters by index and never allocates a substring.

static char[] withSeparators(String s) {
    char[] t = new char[2 * s.length() + 1];
    for (int i = 0; i < t.length; i++) t[i] = '#'; // every position starts as a separator
    for (int k = 0; k < s.length(); k++) t[2 * k + 1] = s.charAt(k); // letters sit at odd indexes
    return t;
}

Computing Every Radius

The second method is the scan. The condition i < right decides whether a mirror exists, and the while loop is the only place that moves right.

static int[] radii(char[] t) {
    int m = t.length;
    int[] rad = new int[m];
    int center = 0, right = 0;
    for (int i = 0; i < m; i++) {
        if (i < right) rad[i] = Math.min(right - i, rad[2 * center - i]); // copy, clamped at the edge
        while (i - rad[i] - 1 >= 0 && i + rad[i] + 1 < m
                && t[i - rad[i] - 1] == t[i + rad[i] + 1]) {
            rad[i]++; // one more matching pair around i
        }
        if (i + rad[i] > right) { // this palindrome reaches farther right than any before
            center = i;
            right = i + rad[i];
        }
    }
    return rad;
}

Reading Off The Longest Palindrome

The third method takes the finished radius array, scans it once and keeps the first maximum. The strict comparison keeps the leftmost center on a tie, and a smaller center index gives a smaller start index in the original string.

static int[] longestFromRadii(int[] rad) {
    int bestCenter = 0;
    for (int i = 1; i < rad.length; i++) {
        if (rad[i] > rad[bestCenter]) bestCenter = i; // strictly larger keeps the leftmost on ties
    }
    return new int[] {(bestCenter - rad[bestCenter]) / 2, rad[bestCenter]};
}

Checking Cost And Java Details

  • radii costs O(n) time, because right only moves forward and each position adds at most one failed comparison.
  • radii uses O(n) space, because rad and t each hold 2n + 1 values.
  • longestFromRadii costs one more O(n) pass and no extra array.

The separator # must be a character that cannot occur in the input, so the code assumes an alphabet of letters and digits. A Java char is one UTF-16 code unit, so a character outside the Basic Multilingual Plane occupies two units and the scan would treat its halves as separate characters. A caller with such text should first convert it to an array of code points.

When to use it

Deciding When Radii Fit

Reading The Recognition Cue

Use the technique when a problem asks about palindromic substrings at every center, such as the longest one, the count of all of them, or whether a given range is a palindrome after a lookup. A hint is a statement that needs both odd and even lengths and gives a length limit of tens of thousands or more, where a quadratic expansion would time out. The invariant to hold in mind is that the radii left of i are final and that right is the farthest known matching index.

Naming The False Friend

The nearest false friend is the longest palindromic subsequence, which allows skipped characters. It looks like the same question, but the position rule differs and the radii do not apply, because a subsequence has no center to expand around. That problem belongs to dynamic programming over two indexes. A second false friend is the prefix function from the previous lesson. It also reuses earlier work after a mismatch, but it measures prefixes that are suffixes, and a palindrome has no such relation to the start of the string.

Knowing When Not To Use It

Do not use radii when palindromes may contain mismatches, because the mirror argument needs exact equality. Do not use them for short inputs with limits near 1,000, where center expansion is simpler and fast enough. Do not forget the separator assumption: a string that already contains # breaks the transform, so choose a character outside the alphabet or compare original indexes without building the padded array.

Expand Odd Centers

Author exercise

Problem Specification. Let s be a string. For each index c of s, the odd radius of c is the largest integer k >= 0 such that c - k >= 0, c + k < s.length(), and the characters from index c - k through index c + k form a palindrome, meaning they equal their own reverse. Return an array odd of length s.length() where odd[c] is the odd radius of c. Compute each value by expanding outward from c one pair of characters at a time.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 1000.
  • Characters are lowercase English letters.
  • Answer is an int[] of the same length as s.
  • Mutation does not occur.

Example 1. Input s = "abaab", output [0, 1, 0, 0, 0].

Example 2. Input s = "aaaaa", output [0, 1, 2, 1, 0], because the radius at each index is limited by the nearer end of the string.

Prerequisites. The direct expansion method from this lesson.

What This Exercise Changes. Basic case: each center expands alone, and no result from a neighbouring center is reused.

Hint

Compare s[c - k - 1] with s[c + k + 1] before you increase k. What stops the loop at the ends of the string?

Algorithmic Solution (attempt the problem first)

Approach. For each index c, the code keeps a counter k that starts at 0 and grows while the characters at c - k - 1 and c + k + 1 are both inside the string and equal. The invariant is that the characters from c - k through c + k already form a palindrome before each comparison, so a successful comparison extends the palindrome by one character on each side. The loop ends at a mismatch or at an end of the string, and the final k is the odd radius of c. A brute-force oracle checks every k independently with an index-range palindrome test.

Complexity.

  • Time is O(n^2) in the worst case, because a string of identical letters lets each of the n centers expand about n / 4 times on average.
  • Space is O(1) beyond the result array, because the loop keeps only the counters c and k.
import java.util.Random;

public final class OddCenterRadii {
    /**
     * Returns the odd radius of every index of s by direct expansion.
     * Time: O(n^2) worst case, because each center may expand across the string.
     * Space: O(n) for the result array and O(1) extra.
     * Invariant: s[c - k .. c + k] is a palindrome before each comparison.
     */
    static int[] oddRadii(String s) {
        // One result slot per index of s.
        int n = s.length();
        int[] out = new int[n];
        // Each index is a center; this loop runs n times.
        for (int c = 0; c < n; c++) {
            int k = 0; // current radius, the palindrome s[c..c] has radius 0
            // Stay inside the string and extend only while the next outer pair is equal.
            while (c - k - 1 >= 0 && c + k + 1 < n && s.charAt(c - k - 1) == s.charAt(c + k + 1)) {
                k++; // one more matching pair, so the palindrome grows by two characters
            }
            out[c] = k; // the first mismatch or boundary ends the expansion
        }
        // The caller reads one radius per index.
        return out;
    }

    /**
     * Tests whether s[lo..hi] reads the same in both directions without allocating a substring.
     * Time: O(hi - lo), because one pass compares symmetric pairs.
     * Space: O(1), because only two indexes are kept.
     * Invariant: every pair outside the moving indexes has matched.
     */
    static boolean isPalindrome(String s, int lo, int hi) {
        // Move the two ends toward each other until they cross.
        while (lo < hi) {
            // A mismatch means the block is not a palindrome.
            if (s.charAt(lo++) != s.charAt(hi--)) return false;
        }
        // Every pair matched, or the block had at most one character.
        return true;
    }

    /**
     * Oracle: tries every k and keeps the largest one whose block is a palindrome.
     * Time: O(n^2) per center in the worst case, because each test is linear.
     * Space: O(1) beyond the result array.
     * Invariant: best holds the largest verified k so far.
     */
    static int[] oracle(String s) {
        // Result array, one entry per index.
        int[] out = new int[s.length()];
        // Check every center.
        for (int c = 0; c < s.length(); c++) {
            // Check every candidate k that fits inside the string.
            for (int k = 0; c - k >= 0 && c + k < s.length(); k++) {
                // Keep the largest k whose whole block is a palindrome.
                if (isPalindrome(s, c - k, c + k)) out[c] = k;
            }
        }
        // The caller compares this array with the fast result.
        return out;
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        if (!java.util.Arrays.equals(oddRadii("abaab"), new int[] {0, 1, 0, 0, 0})) throw new AssertionError("abaab");
        // Example 2: radius at each index is limited by the nearer end.
        if (!java.util.Arrays.equals(oddRadii("aaaaa"), new int[] {0, 1, 2, 1, 0})) throw new AssertionError("aaaaa");
        // A one-character string has radius 0.
        if (!java.util.Arrays.equals(oddRadii("z"), new int[] {0})) throw new AssertionError("single");
        // Random strings over a small alphabet produce many palindromes.
        Random rnd = new Random(34031);
        for (int iter = 0; iter < 2000; iter++) {
            // Length 1..14 over the letters a and b.
            int n = 1 + rnd.nextInt(14);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(2)));
            String s = sb.toString();
            // The fast result must equal the oracle on every index.
            if (!java.util.Arrays.equals(oddRadii(s), oracle(s))) throw new AssertionError("mismatch on " + s);
        }
    }

Unified Separators

Problem Specification. The radius of index i in t is the largest k >= 0 such that i - k >= 0, i + k < t.length(), and t[i - k .. i + k] is a palindrome. Return the array rad of length t.length() that holds the radius of every index of t.   • Characters are lowercase English letters, so # never occurs in s.
  • Answer is an int[] of length 2 * s.length() + 1.
  • Mutation does not occur.

Hint

Which index of t holds the gap between s[0] and s[1], and what is the radius there when both letters are equal?

Algorithmic Solution (attempt the problem first)

Approach. The code builds t with a # before, between and after the letters, so the length is 2n + 1 and letter k of s sits at index 2k + 1. Every palindrome of t has odd length, and the gap between two letters is a separator index, so one expansion loop covers both parities. The invariant is the same as in the previous exercise, applied to t: before each comparison, t[i - k .. i + k] is a palindrome. The oracle ignores t entirely and computes, for every center of s (a letter or a gap), the longest palindrome directly in s, and the two results must agree at index i of t.

Complexity.

  • Time is O(n^2) in the worst case, because each of the 2n + 1 centers can expand across the whole string.
  • Space is O(n), because t and rad each hold 2n + 1 values.
import java.util.Arrays;
import java.util.Random;

public final class SeparatorRadii {
    /**
     * Builds the separator string as a char array.
     * Time: O(n), because each letter is written once.
     * Space: O(n), because the array has 2n + 1 slots.
     * Invariant: letter k of s sits at index 2k + 1 and every other index is a separator.
     */
    static char[] withSeparators(String s) {
        // 2n + 1 slots: a separator before, between and after the letters.
        char[] t = new char[2 * s.length() + 1];
        // Fill every slot with a separator first.
        Arrays.fill(t, '#');
        // Then place each letter at its odd index.
        for (int k = 0; k < s.length(); k++) t[2 * k + 1] = s.charAt(k);
        // The caller expands around each index of t.
        return t;
    }

    /**
     * Returns the radius of every index of t by direct expansion.
     * Time: O(n^2) worst case.
     * Space: O(n) for the result.
     * Invariant: t[i - k .. i + k] is a palindrome before each comparison.
     */
    static int[] radii(String s) {
        char[] t = withSeparators(s);
        // One radius per index of t.
        int[] rad = new int[t.length];
        // Every index of t is a center, odd or even in the original string.
        for (int i = 0; i < t.length; i++) {
            int k = 0; // radius found so far
            // Extend while the next outer pair exists and is equal.
            while (i - k - 1 >= 0 && i + k + 1 < t.length && t[i - k - 1] == t[i + k + 1]) k++;
            rad[i] = k; // store the final radius
        }
        // The caller reads the array by index.
        return rad;
    }

    /**
     * Oracle: longest palindrome of s centered at t-index i, computed on s itself.
     * Time: O(n) per call, because one expansion crosses the string at most once.
     * Space: O(1).
     * Invariant: lo..hi is a palindrome whenever the loop test runs.
     */
    static int centeredLength(String s, int i) {
        // Odd i is a letter index 2k + 1, even i is the gap before letter i / 2.
        int lo, hi;
        if (i % 2 == 1) { lo = i / 2; hi = i / 2; } // start from the letter itself
        else { lo = i / 2 - 1; hi = i / 2; } // start from the empty gap between two letters
        // Grow the block while both ends exist and match.
        while (lo >= 0 && hi < s.length() && s.charAt(lo) == s.charAt(hi)) { lo--; hi++; }
        // Characters strictly between the failed ends.
        return hi - lo - 1;
    }

    public static void main(String[] args) {
        // Example 1: the even palindrome abba appears as radius 4 at index 4.
        if (!Arrays.equals(radii("abba"), new int[] {0, 1, 0, 1, 4, 1, 0, 1, 0})) throw new AssertionError("abba");
        // Example 2: the gap between two equal letters has radius 2.
        if (!Arrays.equals(radii("aa"), new int[] {0, 1, 2, 1, 0})) throw new AssertionError("aa");
        // The padded array has length 2n + 1 and starts and ends with separators.
        char[] t = withSeparators("abc");
        if (t.length != 7 || t[0] != '#' || t[6] != '#' || t[3] != 'b') throw new AssertionError("layout");
        // Random strings: the radius at i must equal the longest palindrome of s centered there.
        Random rnd = new Random(34032);
        for (int iter = 0; iter < 2000; iter++) {
            int n = 1 + rnd.nextInt(14);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(2)));
            String s = sb.toString();
            int[] rad = radii(s);
            // Length check first, then each index against the oracle.
            if (rad.length != 2 * n + 1) throw new AssertionError("length " + s);
            for (int i = 0; i < rad.length; i++) {
                if (rad[i] != centeredLength(s, i)) throw new AssertionError("index " + i + " of " + s);
            }
        }
    }

Edge Cases

Mirror Beyond Boundary

Author exercise

Problem Specification. Let s be a string of lowercase letters and let t and the radius of every index of t be defined as in the previous exercise. Return the radius array rad of t by scanning t once from left to right. The scan keeps the finished palindrome whose right edge right = center + rad[center] is farthest right. For an index i < right, it starts rad[i] at the smaller of right - i and rad[2 * center - i], and then it expands. For s = "abab" an unbounded copy of rad[2 * center - i] would give a wrong radius, so the bound right - i is the point of this exercise.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 100000.
  • Characters are lowercase English letters.
  • Answer is an int[] of length 2 * s.length() + 1.
  • Mutation does not occur.

Example 1. Input s = "abab", output [0, 1, 0, 3, 0, 3, 0, 1, 0], where index 7 holds 1 and not 3.

Example 2. Input s = "aaabaa", output [0, 1, 2, 3, 2, 1, 0, 5, 0, 1, 2, 1, 0], where an unbounded copy would leave 3 at index 11.

Prerequisites. The radius array of the previous exercise and the copy rule from this lesson.

What This Exercise Changes. The copied radius is limited by the distance to the known right edge before any further comparison.

Hint

At index 7 of abab, how many positions remain between i and the right edge of the palindrome centered at index 5?

Algorithmic Solution (attempt the problem first)

Approach. The scan keeps center and right, where right = center + rad[center] is the farthest right edge of any finished palindrome. For an index i < right, the mirror 2 * center - i has a finished radius, but that palindrome may extend left of the big palindrome, where the reflection argument gives no guarantee. The code therefore starts rad[i] at min(right - i, rad[mirror]) and expands from there. The invariant is that all characters within rad[i] of i match before the first comparison. The solution also contains an unbounded variant that skips the min. The assertions show that this variant returns a wrong radius on abab and on aaabaa, which is the reason for the clamp.

Complexity.

  • Time is O(n), because right never decreases and every successful comparison advances it, which allows at most 2n + 1 successful comparisons plus one failed comparison per index.
  • Space is O(n), because t and rad hold 2n + 1 values each.
import java.util.Arrays;
import java.util.Random;

public final class MirrorClamp {
    /**
     * Builds t with a separator before, between and after the letters.
     * Time: O(n). Space: O(n).
     * Invariant: letter k of s sits at index 2k + 1.
     */
    static char[] withSeparators(String s) {
        // 2n + 1 slots, all separators first.
        char[] t = new char[2 * s.length() + 1];
        Arrays.fill(t, '#');
        // Letters go to the odd indexes.
        for (int k = 0; k < s.length(); k++) t[2 * k + 1] = s.charAt(k);
        return t;
    }

    /**
     * Computes every radius of t with the copy limited by the right edge.
     * Time: O(n), because right only moves forward.
     * Space: O(n) for rad.
     * Invariant: all characters within rad[i] of i match before the first comparison at i.
     */
    static int[] radii(String s, boolean clamp) {
        char[] t = withSeparators(s);
        int m = t.length;
        // rad[i] is final once the scan leaves i.
        int[] rad = new int[m];
        // center is the finished palindrome with the farthest right edge.
        int center = 0, right = 0;
        // One pass over all indexes of t.
        for (int i = 0; i < m; i++) {
            // Only indexes strictly left of the right edge have a usable mirror.
            if (i < right) {
                int mirror = 2 * center - i; // same distance from center on the other side
                // The bounded copy stays inside the known palindrome; the unbounded copy does not.
                rad[i] = clamp ? Math.min(right - i, rad[mirror]) : rad[mirror];
            }
            // Expand while the next outer pair exists and matches.
            while (i - rad[i] - 1 >= 0 && i + rad[i] + 1 < m && t[i - rad[i] - 1] == t[i + rad[i] + 1]) {
                rad[i]++; // each success moves i + rad[i] one step right
            }
            // A palindrome reaching farther right becomes the new reference.
            if (i + rad[i] > right) { center = i; right = i + rad[i]; }
        }
        // The caller reads rad by index.
        return rad;
    }

    /**
     * Oracle: expands every index of t independently.
     * Time: O(n^2) worst case. Space: O(n).
     * Invariant: t[i - k .. i + k] is a palindrome before each comparison.
     */
    static int[] oracle(String s) {
        char[] t = withSeparators(s);
        int[] rad = new int[t.length];
        // Independent expansion at each index, with no reuse.
        for (int i = 0; i < t.length; i++) {
            int k = 0;
            while (i - k - 1 >= 0 && i + k + 1 < t.length && t[i - k - 1] == t[i + k + 1]) k++;
            rad[i] = k;
        }
        return rad;
    }

    public static void main(String[] args) {
        // Example 1: the bounded copy gives 1 at index 7.
        if (!Arrays.equals(radii("abab", true), new int[] {0, 1, 0, 3, 0, 3, 0, 1, 0})) throw new AssertionError("abab");
        // Example 2: the bounded copy gives 1 and 0 at the last two indexes.
        if (!Arrays.equals(radii("aaabaa", true), new int[] {0, 1, 2, 3, 2, 1, 0, 5, 0, 1, 2, 1, 0})) throw new AssertionError("aaabaa");
        // The unbounded copy is wrong on both inputs, so the bound is necessary.
        if (Arrays.equals(radii("abab", false), oracle("abab"))) throw new AssertionError("abab unbounded should differ");
        if (radii("abab", false)[7] != 3) throw new AssertionError("unbounded value at index 7");
        if (radii("aaabaa", false)[11] != 3) throw new AssertionError("unbounded value at index 11");
        // Random strings: the bounded scan must equal the independent expansion.
        Random rnd = new Random(34033);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(16);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(3)));
            String s = sb.toString();
            if (!Arrays.equals(radii(s, true), oracle(s))) throw new AssertionError("mismatch on " + s);
        }
        // A long repetitive string finishes and gives the expected maximum radius.
        char[] big = new char[100000];
        Arrays.fill(big, 'a');
        int[] r = radii(new String(big), true);
        if (r[100000] != 100000) throw new AssertionError("center of the long string");
    }

Longest Palindromic Substring

LeetCode 5

Problem Specification. Let s be a string. A palindromic substring is a contiguous block of s that equals its own reverse. Return an array {start, length} for a longest palindromic substring of s, where start is the 0-based index of its first character. When several have the longest length, return the one with the smallest start. This repeats LeetCode 5, which the strings chapter solved by center expansion, and the contract here differs in two ways: the length limit is 100,000, and the answer is a start index with a length and not the substring itself.

Input Constraints. The limits are:

  • Length satisfies 1 <= s.length() <= 100000.
  • Characters are English letters and digits.
  • Answer is an int[] of two values, and the length is at least 1.
  • Ties go to the smallest start index.
  • Mutation does not occur.

Example 1. Input s = "babad", output [0, 3], because bab and aba both have length 3 and bab starts first.

Example 2. Input s = "abcbaxdefed", output [0, 5], because abcba and defed both have length 5 and abcba starts first.

Prerequisites. All three exercises above.

What This Exercise Changes. The radii of every center are computed once, and the answer is read from them instead of being tracked during expansion.

Hint

Which center index of the separator string holds the largest radius, and how does the start index of the original string follow from that center and radius?

Algorithmic Solution (attempt the problem first)

Approach. The code computes all radii of the separator string with the bounded copy, then scans them once and keeps the first index with the maximum radius. A strict comparison keeps the leftmost center on a tie, and among equal radii a smaller center index gives a smaller start in s, so the tie rule holds. The radius at center i equals the palindrome length in s, and the start is (i - radius) / 2. The invariant of the scan is that all characters within rad[i] of i match before the first comparison, and the invariant of the final pass is that bestCenter holds the leftmost index of the largest radius seen so far. The oracle tries every substring start and length with an index-based palindrome test, and no substring is allocated. A last assertion records that a character outside the Basic Multilingual Plane is two Java char values, which is why the code treats text as UTF-16 code units.

Complexity.

  • Time is O(n), because the radius scan advances right at most 2n + 1 times and the final pass visits each index once.
  • Space is O(n), because the separator array and the radius array each hold 2n + 1 values.
import java.util.Arrays;
import java.util.Random;

public final class LongestPalindromeRadii {
    /**
     * Returns {start, length} of the leftmost longest palindromic substring.
     * Time: O(n), because right only moves forward.
     * Space: O(n) for the padded array and the radii.
     * Invariant: bestCenter is the leftmost index holding the largest radius so far.
     */
    static int[] longest(String s) {
        int n = s.length();
        // Padded array: separators before, between and after the letters.
        char[] t = new char[2 * n + 1];
        Arrays.fill(t, '#');
        for (int k = 0; k < n; k++) t[2 * k + 1] = s.charAt(k);
        int m = t.length;
        int[] rad = new int[m];
        int center = 0, right = 0;
        // Scan every index once, left to right.
        for (int i = 0; i < m; i++) {
            // Copy from the mirror, limited to the known right edge.
            if (i < right) rad[i] = Math.min(right - i, rad[2 * center - i]);
            // Expand beyond the known coverage only.
            while (i - rad[i] - 1 >= 0 && i + rad[i] + 1 < m && t[i - rad[i] - 1] == t[i + rad[i] + 1]) rad[i]++;
            // Update the reference palindrome when this one reaches farther right.
            if (i + rad[i] > right) { center = i; right = i + rad[i]; }
        }
        // Pick the first maximum so the leftmost palindrome wins ties.
        int bestCenter = 0;
        for (int i = 1; i < m; i++) if (rad[i] > rad[bestCenter]) bestCenter = i;
        // The radius is the palindrome length in s, and the start follows from the center.
        return new int[] {(bestCenter - rad[bestCenter]) / 2, rad[bestCenter]};
    }

    /**
     * Oracle: tries every start and length, keeping the longest and then leftmost.
     * Time: O(n^3) worst case. Space: O(1).
     * Invariant: bestLen is the longest palindrome length verified so far.
     */
    static int[] oracle(String s) {
        int bestStart = 0, bestLen = 0;
        // Every start index in order, so an earlier start wins on equal length.
        for (int start = 0; start < s.length(); start++) {
            // Every end index from the start.
            for (int end = start; end < s.length(); end++) {
                int len = end - start + 1;
                // Replace only when strictly longer, which keeps the leftmost on ties.
                if (len > bestLen && isPalindrome(s, start, end)) { bestLen = len; bestStart = start; }
            }
        }
        return new int[] {bestStart, bestLen};
    }

    /**
     * Index-based palindrome test with no substring allocation.
     * Time: O(hi - lo). Space: O(1).
     * Invariant: all pairs outside lo..hi have matched.
     */
    static boolean isPalindrome(String s, int lo, int hi) {
        while (lo < hi) if (s.charAt(lo++) != s.charAt(hi--)) return false;
        return true;
    }

    public static void main(String[] args) {
        // Example 1: bab and aba tie at length 3, and bab starts first.
        if (!Arrays.equals(longest("babad"), new int[] {0, 3})) throw new AssertionError("babad");
        // Example 2: abcba and defed tie at length 5, and abcba starts first.
        if (!Arrays.equals(longest("abcbaxdefed"), new int[] {0, 5})) throw new AssertionError("abcbaxdefed");
        // A single character is its own palindrome.
        if (!Arrays.equals(longest("q"), new int[] {0, 1})) throw new AssertionError("single");
        // An even palindrome is found through the gap center.
        if (!Arrays.equals(longest("cbbd"), new int[] {1, 2})) throw new AssertionError("cbbd");
        // Random strings over a small alphabet, compared with the brute-force oracle.
        Random rnd = new Random(34034);
        for (int iter = 0; iter < 3000; iter++) {
            int n = 1 + rnd.nextInt(20);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < n; i++) sb.append((char) ('a' + rnd.nextInt(3)));
            String s = sb.toString();
            if (!Arrays.equals(longest(s), oracle(s))) throw new AssertionError("mismatch on " + s);
        }
        // The long repetitive line from the lesson finishes and returns the whole string.
        char[] big = new char[100000];
        Arrays.fill(big, 'a');
        if (!Arrays.equals(longest(new String(big)), new int[] {0, 100000})) throw new AssertionError("long line");
        // A character outside the Basic Multilingual Plane is two UTF-16 units in a Java String.
        if ("\uD83D\uDE00".length() != 2) throw new AssertionError("surrogate pair length");
    }

Problem

Why Copying Every Suffix Fails

A code-review tool offers a feature that flags the longest passage repeated inside one generated source file. The first version lists every tail of the file as its own String and sorts the list, so that tails with a shared beginning sit side by side. It works on a 2,000-character test file. On a real 100,000-character file the JVM stops with OutOfMemoryError: Java heap space.

A suffix of a string s is the part from index i to the end, written s[i..], and a string of length n has exactly n of them. The failed version copied all of them. Their total length is n * (n + 1) / 2, which is 5,000,050,000 characters for n = 100,000, about 5 GB of character data. The question for this lesson is how to put all suffixes of one text in order and read repeated substrings from that order without ever copying a suffix.

Simple approach

Sorting Copied Suffixes

The direct method copies each suffix with substring, sorts the copies with the natural string order and recovers each start index from the copy length. Distinct suffixes of one string have distinct lengths, so the length identifies the start.

static int[] sortCopiedSuffixes(String s) {
    int n = s.length();
    java.util.List<String> suffixes = new java.util.ArrayList<>();
    for (int i = 0; i < n; i++) {
        suffixes.add(s.substring(i)); // copies n - i characters
    }
    java.util.Collections.sort(suffixes);
    int[] start = new int[n];
    for (int j = 0; j < n; j++) {
        start[j] = n - suffixes.get(j).length();
    }
    return start;
}

For banana the sorted copies are a, ana, anana, banana, na, nana, and the method returns the starts [5, 3, 1, 0, 4, 2]. The answer is correct, and the memory cost is the problem.

Bottleneck

Counting What The Sort Copies And Rescans

Predict first: A string holds 100,000 copies of the letter a. How many characters does the copying method allocate, and how many characters can one comparison scan inside the sort?

The copies hold 5,000,050,000 characters in total. Every pair of suffixes shares a prefix as long as the shorter one, so one comparison can scan up to 100,000 characters.

The method has two separate costs. The first is memory. The n copies hold n * (n + 1) / 2 characters, so space is O(n^2). The second is repeated scanning. A sort makes about n log n comparisons, and a comparison of two suffixes reads characters until they differ. On aaaa...a they never differ before the shorter suffix ends, so each comparison reads up to n characters and the total time is O(n^2 log n).

The named repeated work is rescanning shared beginnings. In banana the suffixes ana and anana share the beginning ana. Every comparison involving either of them reads those three characters again, although an earlier comparison already established that they match. Skipping the copies fixes the memory cost only, because a comparator that reads in place still rescans every shared beginning. The sort needs to reuse what earlier comparisons established.

Key idea

Ordering By Doubling Prefixes

The structure that fixes both costs is the suffix array: an int[] sa of length n holding the start indexes of all suffixes in increasing lexicographic order. It stores n integers and no characters.

Doubling The Compared Length

Give every suffix an integer rank that orders it by its first k characters only. Two suffixes get equal ranks when those k characters are equal, and a suffix shorter than k compares with its end treated as smaller than any character. If ranks for length k are known, ranks for length 2k follow from one pair. The first k characters of s[i..] have rank rank[i], and the next k characters are the first k of s[i+k..], which have rank rank[i+k]. Sorting by the pair (rank[i], rank[i+k]), with -1 when i + k is past the end, orders by 2k characters without reading a single character again.

Start from k = 1, where the rank is the character code itself. After at most ceil(log2 n) doublings, 2k reaches n, all suffixes differ within n characters and every rank is distinct. Each round sorts n pairs in O(n log n), so construction is O(n log^2 n) time and O(n) space.

Reading Repeats From Neighbours

Once the suffix array exists, the LCP array (longest common prefix array) records one number per sorted position r. The number lcp[r] is the length of the longest common prefix of the suffixes sa[r - 1] and sa[r], and lcp[0] = 0. The suffixes that share a given prefix form one contiguous block in sorted order, because any suffix sorted between two of them also begins with that prefix. A substring that occurs twice is therefore a common prefix of two suffixes in one block, and adjacent pairs inside the block share it too. The longest repeated substring has length max(lcp).

Computing each LCP value by comparing neighbours directly can cost O(n) per pair. Kasai's method processes suffixes in text order instead. If s[i..] shares h characters with its sorted predecessor, then s[i+1..] shares at least h - 1 characters with its own predecessor. The variable h never drops by more than 1 per step and never exceeds n, so all increments together are at most 2n and the whole LCP array costs O(n).

Counting Distinct Substrings

Every substring is a prefix of exactly one earliest suffix in sorted order. The suffix at sa[r] has n - sa[r] prefixes, and lcp[r] of them already belong to its predecessor. The number of distinct substrings is therefore n * (n + 1) / 2 - sum(lcp).

Equal End Positions In An Automaton

A suffix automaton answers the same questions from the other direction. For a substring t, its end-position set lists every index where an occurrence of t ends. Substrings with the same end-position set form one state. In banana the substrings na and ana both end at indexes 3 and 5, so they share one state with lengths 2 and 3. The substring a ends at 1, 3 and 5 and has its own state. The automaton has at most 2n - 1 states for n >= 2. This lesson builds the suffix array, and the automaton stays an idea, because its construction needs a separate lesson.

State

Arrays Kept During Construction

Construction and the LCP pass keep a short list of arrays and counters.

  • s is the text, read by charAt and never copied.
  • sa holds start indexes in sorted order, so sa[r] is the start of the suffix with sorted position r.
  • rank holds one integer per start index; rank[i] orders suffix i by its first k characters, and after the last round it equals the sorted position of suffix i.
  • order lists the start indexes sorted by the current ranks, and after the last round it equals sa.
  • k is the compared length, which starts at 1 and doubles each round.
  • lcp holds lcp[r], the common prefix length of the suffixes at sorted positions r - 1 and r.
  • h is the running match length in Kasai's loop, carried from one text position to the next.

Building The Order And LCP On banana

Doubling Rounds On banana

The text is banana. The pointers first and last mark the start index of the smallest and the largest suffix after each round. Before any round, the rank is the character code: b is 98, a is 97 and n is 110.

The round with k = 1 sorts by pairs of the first two characters and gives ranks [2, 1, 3, 1, 3, 0]. Two ties remain. The loop stops after two rounds.

Kasai Pass On banana

The pointer i marks the text position being compared, and j marks the start of its predecessor in sorted order, or -1 when none exists. The variable h carries over from one position to the next.

At i = 0 the suffix banana sits at sorted position 3, and its predecessor anana begins with a different letter, so the match is 0. Code

Building Suffix Array And LCP

Construction Without Substrings

The first method builds the suffix array by doubling. It sorts boxed indexes with a comparator that reads only the rank array, so no suffix is ever copied.

static int[] suffixArray(String s) {
    int n = s.length();
    Integer[] order = new Integer[n];
    int[] rank = new int[n];
    int[] next = new int[n];
    for (int i = 0; i < n; i++) {
        order[i] = i;
        rank[i] = s.charAt(i);
    }
    for (int k = 1; n > 0; k <<= 1) {
        final int step = k;
        java.util.Comparator<Integer> byPair = (a, b) -> {
            if (rank[a] != rank[b]) return Integer.compare(rank[a], rank[b]);
            int ra = a + step < n ? rank[a + step] : -1;
            int rb = b + step < n ? rank[b + step] : -1;
            return Integer.compare(ra, rb);
        };
        java.util.Arrays.sort(order, byPair);
        next[order[0]] = 0;
        for (int t = 1; t < n; t++) {
            int bump = byPair.compare(order[t - 1], order[t]) < 0 ? 1 : 0;
            next[order[t]] = next[order[t - 1]] + bump;
        }
        System.arraycopy(next, 0, rank, 0, n);
        if (rank[order[n - 1]] == n - 1) break; // all ranks distinct
    }
    int[] sa = new int[n];
    for (int r = 0; r < n; r++) sa[r] = order[r];
    return sa;
}

LCP, Repeats And Distinct Count

The remaining methods use sa and the Kasai pass. Characters are compared as UTF-16 code units, which is the order String.compareTo uses.

static int[] adjacentLcp(String s, int[] sa) {
    int n = s.length();
    int[] rank = new int[n];
    for (int r = 0; r < n; r++) rank[sa[r]] = r;
    int[] lcp = new int[n];
    int h = 0;
    for (int i = 0; i < n; i++) {
        if (rank[i] == 0) { h = 0; continue; }
        int j = sa[rank[i] - 1];
        while (i + h < n && j + h < n && s.charAt(i + h) == s.charAt(j + h)) h++;
        lcp[rank[i]] = h;
        if (h > 0) h--;
    }
    return lcp;
}

static long distinctSubstrings(int n, int[] lcp) {
    long total = (long) n * (n + 1) / 2;
    for (int v : lcp) total -= v;
    return total;
}

The count uses long, because n * (n + 1) / 2 exceeds the int range once n passes 65,535.

When to use it

When Suffix Order Answers The Question

Recognizing The Pattern

Reach for sorted suffixes when one fixed text is queried for repeated substrings, for the longest repeat, for distinct substring counts or for the order of its suffixes. The invariant to protect is that after every doubling round, equal ranks mean equal first k characters, and after the last round the ranks equal the sorted positions. A comparator that breaks this, for example by treating a missing character as equal to a real one, silently merges ana with anana.

False Friends And Limits

The rolling hash is a false friend of the suffix array. It also finds repeated substrings, but it answers one length per pass, relies on collision handling and needs a binary search over the length. The suffix array is deterministic and answers every length at once, at the price of O(n log^2 n) construction and O(n) integers of memory. A second false friend is String.indexOf in a loop, which finds one pattern per call and cannot order suffixes.

The method does not apply when the text changes between queries, because every edit invalidates the order. It also does not apply when only a single pattern is searched once, where a linear scan is cheaper. Characters are compared as UTF-16 code units, so supplementary characters sort by their surrogate halves and not by code point, which can differ from the order a person expects.

Sort Small Suffixes

Problem Specification. Given a string s of lowercase English letters, return the int array sa of length s.length() in which sa[r] is the start index of the suffix of rank r when all suffixes are sorted by character code. A suffix that is a proper prefix of another suffix sorts before it. The suffix starting at index i is the characters from i to the last index.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 100000.
  • Characters are the letters a to z only.
  • Empty input returns an empty array.
  • Ties do not occur, since distinct start indexes give distinct suffixes.
  • Mutation does not occur; s is read only.

Example 1. Input s = "banana", output [5, 3, 1, 0, 4, 2].

Example 2. Input s = "abab", output [2, 0, 3, 1], because ab is a proper prefix of abab and sorts first.

Prerequisites. The doubling rounds and the rank array from this lesson.

What This Exercise Changes. The sort key changes from a copied string to a pair of integers read from a rank array.

Hint

Sort the indexes, not the substrings. Which two numbers decide the order of two suffixes once the first k characters are ranked?

Algorithmic Solution (attempt the problem first)

Approach. The solution sorts the start indexes instead of copied suffixes. A rank array holds, for every start index, the order of its suffix by the first k characters, and the first rank is the character code. Each round sorts the indexes by the pair of rank[i] and rank[i + k]. The second value is -1 when i + k is past the end, so a suffix that ends early sorts first. The new ranks are assigned by walking the sorted order and adding 1 whenever the pair changes. The invariant is that after a round, equal ranks mean equal first 2k characters and a smaller rank means a smaller 2k-character prefix. Once all ranks are distinct, the sorted index order is the answer. The test compares every result with the copying method on random strings. It checks that the copied suffixes hold n * (n + 1) / 2 characters. It also shows that substring(1) returns a new object on every call.

Complexity.

  • Time is O(n log^2 n), because there are at most ceil(log2 n) + 1 rounds and each round sorts n indexes with O(1) comparisons.
  • Space is O(n), because the order, rank and next-rank arrays each hold n integers and no suffix is copied.
import java.util.*;

public final class SortSmallSuffixes {
    /**
     * Returns the start indexes of all suffixes in increasing lexicographic order.
     * Time: O(n log^2 n), because each doubling round sorts n indexes in O(n log n).
     * Space: O(n), because only integer arrays of length n are allocated.
     * Invariant: after the round with step k, equal rank means equal first 2k characters.
     */
    static int[] byDoubling(String s) {
        // n is read once; every loop below is bounded by it.
        int n = s.length();
        // order holds start indexes and is the array being sorted (boxed because the comparator needs Integer).
        Integer[] order = new Integer[n];
        // rank[i] orders suffix i by its first k characters; it starts as the character code.
        int[] rank = new int[n];
        // next receives the new ranks so the comparator keeps reading the old ones.
        int[] next = new int[n];
        // One pass seeds the identity order and the first-character ranks.
        for (int i = 0; i < n; i++) {
            // Every start index begins in its own slot.
            order[i] = i;
            // The character code orders suffixes by one character, matching String.compareTo.
            rank[i] = s.charAt(i);
        }
        // The step doubles each round; the break below ends the loop once all ranks differ.
        for (int k = 1; n > 0; k <<= 1) {
            // A lambda may capture only effectively final variables, so the step is copied.
            final int step = k;
            // The comparator reads two ranks per index and never touches a character.
            Comparator<Integer> byPair = (a, b) -> {
                // A different first half decides the order at once.
                if (rank[a] != rank[b]) return Integer.compare(rank[a], rank[b]);
                // A suffix with no second half uses -1, which sorts before every real rank.
                int ra = a + step < n ? rank[a + step] : -1;
                // The same rule applies to the other index.
                int rb = b + step < n ? rank[b + step] : -1;
                // Equal first halves are settled by the second halves.
                return Integer.compare(ra, rb);
            };
            // TimSort on n elements makes O(n log n) comparisons of O(1) each.
            Arrays.sort(order, byPair);
            // The smallest suffix gets rank 0.
            next[order[0]] = 0;
            // Walking the sorted order assigns ranks in a single pass.
            for (int t = 1; t < n; t++) {
                // The rank grows only when the pair differs from the previous pair.
                int bump = byPair.compare(order[t - 1], order[t]) < 0 ? 1 : 0;
                // Equal pairs share one rank, which is what keeps the invariant exact.
                next[order[t]] = next[order[t - 1]] + bump;
            }
            // Copying publishes the new ranks for the following round.
            System.arraycopy(next, 0, rank, 0, n);
            // Rank n - 1 at the end means no two suffixes tie, so the order is final.
            if (rank[order[n - 1]] == n - 1) break;
        }
        // The result unboxes the final order into the return array.
        int[] sa = new int[n];
        // One copy loop of n steps.
        for (int r = 0; r < n; r++) sa[r] = order[r];
        // Callers read the start of the r-th smallest suffix as sa[r].
        return sa;
    }

    /**
     * Brute-force oracle that copies and sorts every suffix.
     * Time: O(n^2 log n) comparisons of copied strings.
     * Space: O(n^2) characters.
     */
    static int[] oracle(String s) {
        // The list holds one copy per suffix, which is the cost the solution avoids.
        List<String> copies = new ArrayList<>();
        // Each substring call copies n - i characters.
        for (int i = 0; i < s.length(); i++) copies.add(s.substring(i));
        // Natural order of String is lexicographic by UTF-16 code unit.
        Collections.sort(copies);
        // The start of a suffix is the string length minus the copy length.
        int[] sa = new int[s.length()];
        // One recovery step per sorted copy.
        for (int r = 0; r < sa.length; r++) sa[r] = s.length() - copies.get(r).length();
        // The oracle answer is compared with the doubling answer in main.
        return sa;
    }

    public static void main(String[] args) {
        // Both examples from the problem text.
        if (!Arrays.equals(byDoubling("banana"), new int[] {5, 3, 1, 0, 4, 2})) throw new AssertionError("banana");
        if (!Arrays.equals(byDoubling("abab"), new int[] {2, 0, 3, 1})) throw new AssertionError("abab");
        // Empty and one-character inputs are the smallest boundaries.
        if (byDoubling("").length != 0) throw new AssertionError("empty");
        if (!Arrays.equals(byDoubling("q"), new int[] {0})) throw new AssertionError("single");
        // Seeded random strings over a tiny alphabet force long shared prefixes.
        Random rng = new Random(34_04_01L);
        for (int trial = 0; trial < 3000; trial++) {
            // Length 0 to 40 covers empty and repeated-letter shapes.
            int len = rng.nextInt(41);
            // The alphabet size varies from 1 to 3 letters.
            int alpha = 1 + rng.nextInt(3);
            StringBuilder sb = new StringBuilder();
            // Each position takes a random letter.
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rng.nextInt(alpha)));
            String s = sb.toString();
            // The doubling result must equal the copying result.
            if (!Arrays.equals(byDoubling(s), oracle(s))) throw new AssertionError("mismatch " + s);
        }
        // The copies hold n(n+1)/2 characters in total, the memory claim in the Approach.
        String text = "mississippi";
        long copied = 0;
        for (int i = 0; i < text.length(); i++) copied += text.substring(i).length();
        if (copied != (long) text.length() * (text.length() + 1) / 2) throw new AssertionError("copy total");
        // substring(1) allocates a fresh String on each call, so the copies cannot share one object.
        if (text.substring(1) == text.substring(1)) throw new AssertionError("substring reuse");

        String wide = "Ａ", half = "\uD83D";

        // The doubling sort uses the same order, so it ranks the surrogate half first.
        if (!Arrays.equals(byDoubling(wide + half), new int[] {1, 0})) throw new AssertionError("surrogate order");
    }

Longest Common Prefix Of Adjacent Suffixes

Author exercise

Problem Specification. Given a string s of lowercase English letters, let sa be its suffix array. Return the int array lcp of length s.length() where lcp[0] = 0 and, for r >= 1, lcp[r] is the length of the longest common prefix of the suffixes starting at sa[r - 1] and sa[r].

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 100000.
  • Characters are the letters a to z only.
  • Empty input returns an empty array.
  • Values in lcp are non-negative int values below s.length().
  • Mutation does not occur; s is read only.

Example 1. Input s = "banana", output [0, 1, 3, 0, 0, 2], so the longest repeat has length 3.

Example 2. Input s = "mississippi", output [0, 1, 1, 4, 0, 0, 1, 0, 2, 1, 3], where the value 4 is the repeat issi.

Prerequisites. The suffix array exercise above and the Kasai pass.

What This Exercise Changes. The question moves from the order of suffixes to the match length between neighbours, and the running value h replaces a fresh comparison for each pair.

Hint

If suffix i matches its predecessor for h characters, how many characters must suffix i + 1 match its own predecessor?

Algorithmic Solution (attempt the problem first)

Approach. The solution first sorts the start indexes with a comparator that reads characters in place, so no suffix is copied. It then fills the common prefix lengths in text order, which is Kasai's method. A rank array maps each start index to its sorted position. For text position i the predecessor is sa[rank[i] - 1]. The match length h starts from the previous value minus 1. Dropping the first character of two suffixes that matched for h characters leaves a match of at least h - 1. The invariant is that h at the start of position i is a proven lower bound on the true value, so the loop only extends it. Since h falls by at most 1 per step and never exceeds n, the extending loop runs at most 2n times in total. The test counts those steps to confirm it. The oracle compares every adjacent pair from scratch.

Complexity.

  • Time is O(n) for the Kasai pass, because the match counter rises at most 2n times in total. The comparator sort that obtains sa costs O(n^2 log n) on a run of one letter, and the doubling method replaces it.
  • Space is O(n), because the sorted indexes, the rank array and the result each hold n integers.
import java.util.*;

public final class AdjacentSuffixLcp {
    // Counts every successful character match in the Kasai loop for the 2n bound.
    static long matchSteps;

    /**
     * Sorts start indexes by comparing suffixes character by character in place.
     * Time: O(n^2 log n) worst case, because a comparison may scan up to n characters.
     * Space: O(n), because only the index array is allocated.
     * Invariant: the comparator is a total order, since a proper prefix sorts first.
     */
    static int[] sortInPlace(String s) {
        // The index array is the only allocation of this method.
        Integer[] idx = new Integer[s.length()];
        // Seed each slot with its own start index.
        for (int i = 0; i < idx.length; i++) idx[i] = i;
        // The comparator walks both suffixes with two cursors and allocates nothing.
        Arrays.sort(idx, (a, b) -> {
            // Cursors start at the two suffix starts.
            int x = a, y = b;
            // Advance while both suffixes continue and agree.
            while (x < s.length() && y < s.length() && s.charAt(x) == s.charAt(y)) { x++; y++; }
            // The suffix that ended first is a proper prefix and sorts first.
            if (x == s.length() || y == s.length()) return Integer.compare(s.length() - a, s.length() - b);
            // Otherwise the first differing characters decide.
            return Character.compare(s.charAt(x), s.charAt(y));
        });
        // Unbox into the return array.
        int[] sa = new int[idx.length];
        // One pass of n copies.
        for (int r = 0; r < sa.length; r++) sa[r] = idx[r];
        // sa[r] is the start of the r-th smallest suffix.
        return sa;
    }

    /**
     * Kasai's method: lcp[r] is the common prefix length of the suffixes at sa[r - 1] and sa[r].
     * Time: O(n), because h rises at most 2n times in total.
     * Space: O(n), because rank and lcp each hold n integers.
     * Invariant: at the start of position i, h is a lower bound for the true match length.
     */
    static int[] kasai(String s, int[] sa) {
        // n is the text length and the length of every array.
        int n = s.length();
        // rank is the inverse permutation of sa.
        int[] rank = new int[n];
        // One pass builds the inverse.
        for (int r = 0; r < n; r++) rank[sa[r]] = r;
        // The answer array starts at all zeros, so lcp[0] stays 0.
        int[] lcp = new int[n];
        // h carries over from one text position to the next.
        int h = 0;
        // Text order is what makes the lower bound h - 1 valid.
        for (int i = 0; i < n; i++) {
            // The smallest suffix has no predecessor, so the carried bound is reset.
            if (rank[i] == 0) { h = 0; continue; }
            // j is the start of the predecessor in sorted order.
            int j = sa[rank[i] - 1];
            // Extend the lower bound only while characters agree and both suffixes continue.
            while (i + h < n && j + h < n && s.charAt(i + h) == s.charAt(j + h)) { h++; matchSteps++; }
            // The settled match length goes to the slot of suffix i.
            lcp[rank[i]] = h;
            // Dropping the first character costs one, never more.
            if (h > 0) h--;
        }
        // The caller reads the maximum for the longest repeat.
        return lcp;
    }

    /**
     * Brute-force oracle that compares each adjacent pair from the start.
     * Time: O(n^2), because each of n pairs may compare n characters.
     * Space: O(n), because the result holds n integers.
     */
    static int[] oracle(String s, int[] sa) {
        // One slot per sorted position.
        int[] lcp = new int[s.length()];
        // The first slot stays 0 by definition.
        for (int r = 1; r < sa.length; r++) {
            // Cursor h counts equal leading characters of the pair.
            int h = 0;
            // Plain comparison with no carried state.
            while (sa[r - 1] + h < s.length() && sa[r] + h < s.length()
                    && s.charAt(sa[r - 1] + h) == s.charAt(sa[r] + h)) h++;
            // Record the pair result.
            lcp[r] = h;
        }
        // The oracle answer is compared with Kasai in main.
        return lcp;
    }

    public static void main(String[] args) {
        // Both examples from the problem text.
        int[] b = kasai("banana", sortInPlace("banana"));
        if (!Arrays.equals(b, new int[] {0, 1, 3, 0, 0, 2})) throw new AssertionError("banana");
        int[] m = kasai("mississippi", sortInPlace("mississippi"));
        if (!Arrays.equals(m, new int[] {0, 1, 1, 4, 0, 0, 1, 0, 2, 1, 3})) throw new AssertionError("mississippi");
        // Empty input returns an empty array.
        if (kasai("", sortInPlace("")).length != 0) throw new AssertionError("empty");
        // Seeded random strings compare Kasai with the pairwise oracle and check the 2n bound.
        Random rng = new Random(34_04_02L);
        for (int trial = 0; trial < 3000; trial++) {
            // Length 0 to 60 with 1 to 3 letters gives long shared prefixes.
            int len = rng.nextInt(61), alpha = 1 + rng.nextInt(3);
            StringBuilder sb = new StringBuilder();
            // Random letters.
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rng.nextInt(alpha)));
            String s = sb.toString();
            // Reset the counter before each run so the bound is per string.
            matchSteps = 0;
            int[] sa = sortInPlace(s);
            int[] fast = kasai(s, sa);
            // Kasai must equal the pairwise result.
            if (!Arrays.equals(fast, oracle(s, sa))) throw new AssertionError("mismatch " + s);
            // The total number of extensions is bounded by 2n.
            if (matchSteps > 2L * len) throw new AssertionError("steps " + s);
        }
    }

Edge Cases

Repeated Character String

Author exercise

Problem Specification. Given a string s of lowercase English letters, return the number of distinct non-empty substrings of s, where two substrings are equal when they have the same characters in the same order. Equal prefixes of different suffixes must not be counted twice, and the suffixes of a string made of one repeated letter all start at different indexes while sharing long prefixes.

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 100000.
  • Characters are the letters a to z only.
  • Return type is long, because the number of substrings can exceed the int range.
  • Empty input returns 0.
  • Mutation does not occur; s is read only.

Example 1. Input s = "abab", output 7: a, b, ab, ba, aba, bab, abab.

Example 2. Input s = "zzzzzzz", output 7, because only the lengths 1 to 7 of the repeated letter exist.

Prerequisites. The adjacent LCP exercise above and the distinct substring count.

What This Exercise Changes. The count subtracts shared prefix lengths, so equal prefixes of distinct suffix starts are counted once.

Hint

How many prefixes does the suffix at sa[r] contribute, and how many of those did its sorted predecessor already contribute?

Algorithmic Solution (attempt the problem first)

Approach. Every distinct substring is a prefix of exactly one suffix when suffixes are taken in sorted order and a prefix already shared with the predecessor is skipped. The suffix at sa[r] has n - sa[r] prefixes, and lcp[r] of them belong to the predecessor. The count is therefore the sum of n - sa[r] - lcp[r], which equals n * (n + 1) / 2 minus the sum of lcp. The boundary is a string of one repeated letter. All its suffixes start at different indexes yet share the longest possible prefixes, so the sum of lcp is n * (n - 1) / 2 and the answer is n. The arithmetic runs in long, because 100000 * 100001 / 2 overflows int. This version builds sa by packing the pair of ranks and the index into one long and sorting a primitive array, which avoids boxing. The invariant is that sorting the packed values orders by pair first and by index only on equal pairs.

Complexity.

  • Time is O(n log^2 n), because there are O(log n) rounds, each sorting n packed longs in O(n log n), plus an O(n) Kasai pass.
  • Space is O(n), because the packed array, the ranks and the lcp array hold n numbers each and no suffix is copied.
import java.util.*;

public final class RepeatedCharacterString {
    /**
     * Counts distinct non-empty substrings from the sorted suffixes and their adjacent prefix lengths.
     * Time: O(n log^2 n), because construction dominates the O(n) lcp pass.
     * Space: O(n), because all arrays hold n numbers.
     * Invariant: sa[r] contributes n - sa[r] - lcp[r] new substrings, each counted once.
     */
    static long distinct(String s) {
        // n is the text length.
        int n = s.length();
        // An empty text has no substrings.
        if (n == 0) return 0;
        // The sorted start indexes come from packed-key doubling.
        int[] sa = packedDoubling(s);
        // The adjacent prefix lengths come from the carried-match pass.
        int[] lcp = adjacent(s, sa);
        // The total is accumulated in long to survive n near 100000.
        long total = 0;
        // Each sorted position adds its new prefixes only.
        for (int r = 0; r < n; r++) total += n - sa[r] - lcp[r];
        // The count of distinct substrings.
        return total;
    }

    /**
     * Builds the suffix array by sorting packed long keys, with no boxing.
     * Time: O(n log^2 n), because each round sorts n primitives in O(n log n).
     * Space: O(n), because the packed array and two int arrays hold n values.
     * Invariant: key(i) = rank[i] * M + (rank[i + k] + 1) orders suffixes by 2k characters.
     */
    static int[] packedDoubling(String s) {
        // n is the text length, at least 1 here.
        int n = s.length();
        // M exceeds every rank value, including character codes up to 65535.
        long m = Math.max(n, 65536) + 1;
        // rank starts as the character code.
        int[] rank = new int[n];
        // Seed the first-character ranks.
        for (int i = 0; i < n; i++) rank[i] = s.charAt(i);
        // packed[t] holds key * n + index, so a numeric sort sorts by key then index.
        long[] packed = new long[n];
        // The sorted index list that each round leaves behind.
        int[] sa = new int[n];
        // The step doubles until all ranks differ.
        for (int k = 1; ; k <<= 1) {
            // Build one packed value per start index.
            for (int i = 0; i < n; i++) {
                // A suffix with no second half uses 0, below every real second rank + 1.
                long second = i + k < n ? rank[i + k] + 1 : 0;
                // The first rank is the more significant part.
                long key = rank[i] * m + second;
                // The index sits in the low part, so equal keys sort by index.
                packed[i] = key * n + i;
            }
            // A primitive sort needs no comparator and no boxing.
            Arrays.sort(packed);
            // The new rank of the smallest key is 0.
            int[] fresh = new int[n];
            // Previous key is tracked to detect ties.
            long prevKey = -1;
            // The running new rank value.
            int cur = -1;
            // Walk the sorted packed values.
            for (int t = 0; t < n; t++) {
                // Low part is the index, high part is the key.
                int idx = (int) (packed[t] % n);
                long key = packed[t] / n;
                // A new key means a new rank value.
                if (key != prevKey) { cur++; prevKey = key; }
                // Equal keys share one rank.
                fresh[idx] = cur;
                // The sorted order is stored for the final answer.
                sa[t] = idx;
            }
            // The new ranks replace the old ones for the following round.
            rank = fresh;
            // Rank n - 1 for the last suffix means all keys differ.
            if (cur == n - 1) return sa;
        }
    }

    /**
     * Computes adjacent common prefix lengths by carrying the match length across text positions.
     * Time: O(n), because the carried length rises at most 2n times.
     * Space: O(n), because the inverse array and result hold n integers.
     * Invariant: the carried length never exceeds the true match of the next text position.
     */
    static int[] adjacent(String s, int[] sa) {
        // n is the text length.
        int n = s.length();
        // where[i] is the sorted position of the suffix starting at i.
        int[] where = new int[n];
        // Invert the permutation.
        for (int r = 0; r < n; r++) where[sa[r]] = r;
        // Result array, zero at position 0.
        int[] lcp = new int[n];
        // Carried match length.
        int carried = 0;
        // Visit starts in text order.
        for (int i = 0; i < n; i++) {
            // The smallest suffix has no predecessor.
            if (where[i] == 0) { carried = 0; continue; }
            // Predecessor start.
            int j = sa[where[i] - 1];
            // Extend while both suffixes continue and agree.
            while (i + carried < n && j + carried < n && s.charAt(i + carried) == s.charAt(j + carried)) carried++;
            // Store for the sorted position of i.
            lcp[where[i]] = carried;
            // Moving to i + 1 loses at most one character of the match.
            if (carried > 0) carried--;
        }
        // Return the full array.
        return lcp;
    }

    /**
     * Oracle that stores every substring in a set.
     * Time: O(n^3) because each of O(n^2) substrings is built and hashed.
     * Space: O(n^3) characters in the worst case.
     */
    static long oracle(String s) {
        // The set removes duplicate substrings by value.
        Set<String> all = new HashSet<>();
        // Every start and every end gives one substring.
        for (int i = 0; i < s.length(); i++) for (int j = i + 1; j <= s.length(); j++) all.add(s.substring(i, j));
        // The set size is the count.
        return all.size();
    }

    public static void main(String[] args) {
        // Both examples from the problem text.
        if (distinct("abab") != 7) throw new AssertionError("abab");
        if (distinct("zzzzzzz") != 7) throw new AssertionError("zzzzzzz");
        // Empty and single-letter boundaries.
        if (distinct("") != 0 || distinct("a") != 1) throw new AssertionError("tiny");
        // Seeded random strings compare with the set oracle.
        Random rng = new Random(34_04_03L);
        for (int trial = 0; trial < 2000; trial++) {
            // Length 0 to 30 over 1 to 3 letters.
            int len = rng.nextInt(31), alpha = 1 + rng.nextInt(3);
            StringBuilder sb = new StringBuilder();
            // Random letters.
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rng.nextInt(alpha)));
            String s = sb.toString();
            // The suffix-based count must equal the set size.
            if (distinct(s) != oracle(s)) throw new AssertionError("mismatch " + s);
        }
        // A repeated letter of every length from 1 to 40 has exactly n distinct substrings.
        for (int n = 1; n <= 40; n++) if (distinct("c".repeat(n)) != n) throw new AssertionError("repeat " + n);
        // The largest allowed input runs the same code and returns n.
        String big = "a".repeat(100_000);
        if (distinct(big) != 100_000L) throw new AssertionError("big");
        // int arithmetic overflows for n = 100000, which is why the total uses long.
        int wrong = 100_000 * 100_001 / 2;
        if (wrong == 5_000_050_000L) throw new AssertionError("int did not overflow");
        if ((long) 100_000 * 100_001 / 2 != 5_000_050_000L) throw new AssertionError("long total");
    }

Longest Duplicate Substring

LeetCode 1044

Problem Specification. This lesson uses LeetCode 1044 with a different contract from the rolling-hash lesson, which asks for a duplicate found by hashing. Here, given a string s of lowercase English letters, return the pair (start, length) of the longest substring that occurs at two or more different start indexes. Occurrences may overlap. Among all substrings of the maximum length that occur twice, return the smallest start index of any occurrence. If no substring occurs twice, return (-1, 0).

Input Constraints. The limits are:

  • Length satisfies 0 <= s.length() <= 100000.
  • Characters are the letters a to z only.
  • Answer is an int[] of two values, start then length.
  • Ties between equal lengths resolve to the smallest start index.
  • Mutation does not occur; s is read only.

Example 1. Input s = "banana", output (1, 3), the substring ana.

Example 2. Input s = "xyxyxy", output (0, 4), because xyxy occurs at starts 0 and 2 and the occurrences overlap.

Prerequisites. The adjacent LCP exercise above and the rolling-hash lesson of this chapter.

What This Exercise Changes. The answer is read from neighbouring suffixes and ties are settled by the smallest start, in place of a binary search over the length.

Hint

Where must two occurrences of the longest repeat sit in sorted suffix order? Which neighbour pairs reach the maximum common prefix length?

Algorithmic Solution (attempt the problem first)

Approach. This contract returns the start index and length of the longest repeated substring, with the smallest start on ties, and it differs from the rolling-hash version of the same LeetCode number. The solution builds the suffix array, computes the adjacent common prefix lengths and reads the answer from them. Two occurrences of a repeated substring of length L are two suffixes sharing an L-character prefix. Every suffix between them in sorted order shares it too, so the maximum value of lcp is the longest repeat length. Every start index of a maximum-length repeat belongs to some adjacent pair with lcp equal to that maximum, so the smallest start is the minimum of min(sa[r - 1], sa[r]) over those pairs. The invariant is that no pair outside the maximum can name a longer repeat, and no maximum pair is skipped. The hashing approach binary searches on the length, hashes every window of that length and needs a collision check. The suffix method is deterministic, handles ties by construction and costs O(n log^2 n) with this construction. Rolling hash costs O(n log n) expected time and O(n) space, with a small chance of a wrong candidate unless every hit is verified. The test checks both against an indexOf oracle.

Complexity.

  • Time is O(n log^2 n), because construction sorts n indexes in each of O(log n) rounds, while the lcp pass and the final scan cost O(n) each.
  • Space is O(n), because the order, rank and lcp arrays hold n integers and the answer is two integers.
import java.util.*;

public final class DuplicateSubstringContract {
    /**
     * Returns {start, length} of the longest substring occurring at two or more starts, smallest start on ties.
     * Time: O(n log^2 n), because suffix array construction dominates.
     * Space: O(n), because every working array holds n integers.
     * Invariant: every start of a maximum-length repeat belongs to an adjacent pair whose lcp equals the maximum.
     */
    static int[] longestDuplicate(String s) {
        // n is the text length.
        int n = s.length();
        // Sorted starts and adjacent prefix lengths feed the scan.
        int[] sa = suffixArray(s);
        int[] lcp = phiLcp(s, sa);
        // best is the longest repeat length so far; -1 start means none yet.
        int bestLen = 0, bestStart = -1;
        // Pair r compares sorted positions r - 1 and r.
        for (int r = 1; r < n; r++) {
            // The earlier text position is the smaller start of the pair.
            int start = Math.min(sa[r - 1], sa[r]);
            // A strictly longer prefix replaces the answer.
            if (lcp[r] > bestLen) { bestLen = lcp[r]; bestStart = start; }
            // An equal length keeps the smaller start, which is the tie rule.
            else if (lcp[r] == bestLen && bestLen > 0 && start < bestStart) bestStart = start;
        }
        // No repeat leaves {-1, 0}, as the contract says.
        return new int[] {bestStart, bestLen};
    }

    /**
     * Builds the suffix array by doubling with a precomputed second-half array.
     * Time: O(n log^2 n), because each round sorts n indexes.
     * Space: O(n), because all arrays hold n integers.
     * Invariant: equal rank means equal first 2k characters after each round.
     */
    static int[] suffixArray(String s) {
        // n is the text length.
        int n = s.length();
        // Boxed indexes for the comparator sort.
        Integer[] order = new Integer[n];
        // Current ranks and the second-half ranks of the current round.
        final int[] rank = new int[n], second = new int[n];
        // Seed identity order and character-code ranks.
        for (int i = 0; i < n; i++) { order[i] = i; rank[i] = s.charAt(i); }
        // Doubling stops when all ranks differ.
        for (int k = 1; n > 1; k <<= 1) {
            // Precompute the second half so the comparator has two array reads.
            for (int i = 0; i < n; i++) second[i] = i + k < n ? rank[i + k] : -1;
            // Sort by the pair of first and second half.
            Arrays.sort(order, (a, b) -> rank[a] != rank[b] ? Integer.compare(rank[a], rank[b]) : Integer.compare(second[a], second[b]));
            // New ranks are built apart from the old ones.
            int[] fresh = new int[n];
            // Walk the sorted order and bump on each changed pair.
            for (int t = 1; t < n; t++) {
                int p = order[t - 1], q = order[t];
                boolean same = rank[p] == rank[q] && second[p] == second[q];
                fresh[q] = fresh[p] + (same ? 0 : 1);
            }
            // Publish the new ranks by copying, because the comparator holds the rank array.
            System.arraycopy(fresh, 0, rank, 0, n);
            // The last sorted suffix has rank n - 1 only when no ties remain.
            if (rank[order[n - 1]] == n - 1) break;
        }
        // Unbox the final order.
        int[] sa = new int[n];
        for (int r = 0; r < n; r++) sa[r] = order[r];
        // The array of sorted starts.
        return sa;
    }

    /**
     * Computes adjacent prefix lengths through the permuted array indexed by text position.
     * Time: O(n), because the match length rises at most 2n times.
     * Space: O(n), because two arrays of n integers are allocated.
     * Invariant: plcp[i] >= plcp[i - 1] - 1, so the match never restarts from zero.
     */
    static int[] phiLcp(String s, int[] sa) {
        // n is the text length.
        int n = s.length();
        // phi[i] is the start of the suffix just before suffix i in sorted order, or -1.
        int[] phi = new int[n];
        // Fill phi from consecutive sorted starts.
        for (int r = 0; r < n; r++) phi[sa[r]] = r == 0 ? -1 : sa[r - 1];
        // plcp[i] is the prefix length of suffix i and its predecessor.
        int[] plcp = new int[n];
        // Carried match length.
        int h = 0;
        // Text order.
        for (int i = 0; i < n; i++) {
            // No predecessor means no match and a reset.
            if (phi[i] < 0) { h = 0; continue; }
            // Extend while both suffixes continue and agree.
            while (i + h < n && phi[i] + h < n && s.charAt(i + h) == s.charAt(phi[i] + h)) h++;
            plcp[i] = h;
            // One character is lost when both suffixes advance.
            if (h > 0) h--;
        }
        // Convert to sorted order: lcp[r] belongs to the suffix at sa[r].
        int[] lcp = new int[n];
        for (int r = 0; r < n; r++) lcp[r] = plcp[sa[r]];
        // The array read by the scan.
        return lcp;
    }

    /**
     * Oracle that tests every length from longest to shortest with indexOf.
     * Time: O(n^3) worst case.
     * Space: O(n) per substring.
     */
    static int[] oracle(String s) {
        // Longest lengths first, so the first hit is maximal.
        for (int len = s.length() - 1; len >= 1; len--) {
            // Smallest start first, so the first hit is the tie winner.
            for (int p = 0; p + len <= s.length(); p++) {
                // A later occurrence of the same text at a different start proves a repeat.
                if (s.indexOf(s.substring(p, p + len), p + 1) >= 0) return new int[] {p, len};
            }
        }
        // No repeat.
        return new int[] {-1, 0};
    }

    public static void main(String[] args) {
        // Both examples from the problem text.
        if (!Arrays.equals(longestDuplicate("banana"), new int[] {1, 3})) throw new AssertionError("banana");
        if (!Arrays.equals(longestDuplicate("xyxyxy"), new int[] {0, 4})) throw new AssertionError("xyxyxy");
        // No repeat, empty and single-letter inputs return {-1, 0}.
        for (String t : new String[] {"abcd", "", "a"}) {
            if (!Arrays.equals(longestDuplicate(t), new int[] {-1, 0})) throw new AssertionError("none " + t);
        }
        // Two repeats of length 3 tie, and the smaller start 0 wins.
        if (!Arrays.equals(longestDuplicate("xyzabcabcxyz"), new int[] {0, 3})) throw new AssertionError("tie");
        // Seeded random strings compare with the indexOf oracle.
        Random rng = new Random(34_04_04L);
        for (int trial = 0; trial < 3000; trial++) {
            // Length 0 to 40 over 1 to 3 letters.
            int len = rng.nextInt(41), alpha = 1 + rng.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 0; i < len; i++) sb.append((char) ('a' + rng.nextInt(alpha)));
            String s = sb.toString();
            // Start and length must both match, including the tie rule.
            if (!Arrays.equals(longestDuplicate(s), oracle(s))) throw new AssertionError("mismatch " + s);
        }
    }

Problem

Why A Longer List Slows Every Scan

A moderation service checks each posted message against a blocklist. With 40 blocked words the check finishes instantly. Then the policy team imports a list of 20,000 entries, and the posting endpoint starts missing its latency budget. The code did not change. It still loops over the list and asks, for each entry, whether the message contains it. The work per message now grows with the size of the list, even when the message is a single short sentence.

The same shape appears in log scanners that look for known error signatures, in intrusion detection that checks packets against attack strings, and in editors that highlight many keywords at once. In every case the text arrives once, while the patterns are many and fixed. The question for this lesson is how to read each character of the text one time and still find every occurrence of every pattern, including occurrences that overlap or sit inside one another.

This lesson assumes you know the trie from chapter 18 and the level-order traversal with a queue from chapter 16. It adds one idea on top of them, a way to continue a match after a mismatch without rereading the text.

Simple approach

Searching For Each Pattern Alone

The direct approach treats the patterns one at a time. For each pattern, try every start position in the text and compare characters until the pattern matches or a character differs. The code below counts every occurrence of every pattern, overlapping ones included.

static int countAll(String text, String[] patterns) {
    int total = 0;
    // One full pass over the text for each pattern.
    for (String p : patterns) {
        for (int start = 0; start + p.length() <= text.length(); start++) {
            // startsWith compares in place and allocates no substring.
            if (text.startsWith(p, start)) total++;
        }
    }
    return total;
}

This code is correct, and for a handful of patterns it is fast enough. It also reports overlapping matches, because every start position is tested on its own.

Predict first: A text has n characters and the pattern list has k patterns of length m each. In the worst case, how many character comparisons does this method make, and what happens when k grows from 40 to 20,000 while the text stays the same?

The worst case is about n * k * m comparisons, because every pattern tries every start and may compare m characters before a mismatch. Raising k by a factor of 500 raises the work by the same factor, even though the text did not change.

Bottleneck

Counting The Repeated Reads

Let n be the text length, k the number of patterns and m the longest pattern. The method above makes up to n * k * m character comparisons, which is O(n * k * m). Take n = 100,000, k = 20,000 and m = 10. That is 2 * 10^10 comparisons for one message-sized scan, far beyond what a request can afford. Even with startsWith and no substring allocation, the count of comparisons is the problem.

Two Kinds Of Repeated Work

The first repeated work is the loop over patterns. The text character at position i is read again for every pattern, so the text is read k times in total. Patterns that share a beginning, such as she and shell, compare the same first three characters twice at the same start.

The second repeated work is the restart after a mismatch. Take the patterns hers and she on the text ushers. The attempt for she reads s, h, e and succeeds at position 1. The attempt for hers starts at position 2 and reads h, e, r, s. Those characters h and e were already read as part of the match for she. Each attempt forgets what the previous attempts learned, so the same characters are read again.

What A Fix Must Provide

A better method must satisfy two conditions at once. It must share the reading of common prefixes across patterns, and it must keep, after each text character, enough knowledge to continue without going back. The trie from chapter 18 supplies the first condition. The second condition needs one extra piece of information for every trie node, and the next stage defines it.

Key idea

Sharing One Trie Across Patterns

Build one trie over all patterns, then read the text once while keeping a single current node. The current node stands for the longest part of the text just read that is still a prefix of some pattern. Three additions to the plain trie make this work.

A Failure Link Keeps The Longest Useful Suffix

Let s be the string spelled by the path from the root to a node v. The failure link of v points to the node for the longest proper suffix of s that is also a node in the trie, which means it is a prefix of some pattern. The root points to itself. A suffix is proper when it is shorter than s.

The link is safe because of one fact. After the text ends with s, any partial match that is still alive must be a suffix of s that is also a trie prefix. The longest such suffix is the failure link target. The shorter live ones are found by following failure links again from there.

The Goto Transition Removes The Retry Loop

The goto transition go[v][c] is the node reached from v after reading the character c. If v has a child on c, that child is the answer. Otherwise the answer is go[fail[v]][c], which means the automaton falls back to the longest useful suffix and tries again there. At the root, a missing child leaves the state at the root.

Filling the full table in advance lets the scan do one array lookup per text character, with no retry loop. The fill runs in level order, the BFS from chapter 16. When the loop handles a node at depth d, the failure targets of all nodes at depth d - 1 and above are known, and their table rows are complete. The failure link of a child u of v on character c is then go[fail[v]][c], one lookup in a finished row.

An Output Link Reports Every Match

A node that ends a pattern is a terminal node. Reaching a terminal node means that pattern ends at the current text position. But shorter patterns that are suffixes of that node's string also end here. For the patterns he and she, reading she ends both of them.

The output link of v points to the nearest node on the failure chain of v that is terminal, or to the root when none exists. At each text position the scan reports v if it is terminal and then follows output links. The walk visits exactly the patterns that end at this position, so its length equals the number of matches reported.

The invariant ties these pieces together. After reading text[0..i], the current node is the node for the longest suffix of text[0..i] that is a prefix of some pattern.

State

Four Arrays And One State

The automaton keeps four arrays indexed by trie node, one current state, and the pattern list.

  • go is a table with one row per node and one column per letter, holding the next node for every letter.
  • fail holds, for each node, the node of its longest proper suffix that is also a trie prefix.
  • link holds, for each node, the nearest terminal node on its failure chain, or 0 when none exists.
  • id holds the index of the pattern that ends at a node, or -1 when no pattern ends there.
  • state is the node reached after the text read so far, and it starts at the root, node 0.

The alphabet is the 26 lowercase letters, and a letter c selects the column c - 'a'. Any other character needs a different table, as the applicability stage explains.

Node 4 (sh) points to node 1 (h), because h is the longest proper suffix of sh that is a trie prefix. Node 5 (she) points to node 2 (he), which is also a terminal node. That single pair is why the output link of node 5 is node 2.

Code

Building And Scanning In Java

Building The Tables

The class below stores the automaton for lowercase letters. It inserts each pattern into a trie, then fills fail, link and the full go table in one level-order pass.

final class Automaton {
    private static final int ALPHABET = 26;
    private final int[][] go;
    private final int[] fail, link, id;

    Automaton(String[] patterns) {
        int cap = 1;
        for (String p : patterns) cap += p.length();
        go = new int[cap][ALPHABET];
        for (int[] row : go) java.util.Arrays.fill(row, -1);
        fail = new int[cap];
        link = new int[cap];
        id = new int[cap];
        java.util.Arrays.fill(id, -1);
        int nodes = 1;
        for (int k = 0; k < patterns.length; k++) {
            int v = 0;
            for (int j = 0; j < patterns[k].length(); j++) {
                int c = patterns[k].charAt(j) - 'a';
                if (go[v][c] == -1) go[v][c] = nodes++;
                v = go[v][c];
            }
            id[v] = k;
        }
        int[] queue = new int[nodes];
        int head = 0, tail = 0;
        for (int c = 0; c < ALPHABET; c++) {
            int u = go[0][c];
            if (u == -1) go[0][c] = 0; else queue[tail++] = u;
        }
        while (head < tail) {
            int v = queue[head++];
            int f = fail[v];
            link[v] = id[f] >= 0 ? f : link[f];
            for (int c = 0; c < ALPHABET; c++) {
                int u = go[v][c];
                if (u == -1) go[v][c] = go[f][c];
                else { fail[u] = go[f][c]; queue[tail++] = u; }
            }
        }
    }

    // Calls handler(endIndex, patternIndex) for every occurrence.
    void scan(String text, java.util.function.BiConsumer<Integer, Integer> handler) {
        int v = 0;
        for (int i = 0; i < text.length(); i++) {
            int c = text.charAt(i) - 'a';
            if (c < 0 || c >= ALPHABET) throw new IllegalArgumentException("not a-z at " + i);
            v = go[v][c];
            for (int m = id[v] >= 0 ? v : link[v]; m != 0; m = link[m]) handler.accept(i, id[m]);
        }
    }
}

The array go has cap rows, which is the total pattern length plus one. That is an upper bound on the node count, because every inserted character creates at most one node.

Cost And Java Details

Building costs O(L * 26) time and space, where L is the total length of the patterns, because the table has L + 1 rows of 26 entries. The scan costs O(n + z) time, where z is the number of reported matches. Each text character performs one lookup, and each output link followed reports one match.

Two Java details matter. The expression charAt(j) - 'a' is an int, so it can be used directly as a column index and a stray character produces a value outside 0 to 25, which the scan rejects instead of reading a wrong column. The code never calls substring, because index arithmetic is enough for every step.

When to use it

When To Use The Automaton

Recognizing The Pattern

Reach for this method when a fixed set of patterns must be matched against one text or one stream, and the answer needs every occurrence, a count per pattern, or a yes or no after each character. The signal in a statement is the word "stream" or "any of these words", together with patterns that may overlap or contain one another. The invariant to state before coding is that the current node is the longest suffix of the text read so far that is a prefix of some pattern.

The Nearest False Friend

Running KMP once per pattern is the nearest false friend. KMP is the single-pattern case of the same idea, and it is correct, but k patterns need k passes and the cost returns to O(n * k). A second false friend is following only the failure link and testing only the current node for a terminal mark. That code finds she and misses he, because the nearest pattern end sits on the failure chain and not at the node itself. The output link or a precomputed count per node prevents the miss.

When Not To Use It

Do not use the table when the alphabet is large, such as arbitrary Unicode text. A table row per node then wastes memory, and a hash map per node is the better storage. Do not use it for a single pattern, where KMP needs less memory. Do not use it when patterns change between queries, because insertion invalidates the failure links and forces a rebuild. Patterns with wildcards or character classes also fall outside the method.

Hint

Process the nodes in order of depth. When you handle node v and its child u on letter c, which already finished row gives the link of u?

Algorithmic Solution (attempt the problem first)

Approach. The code inserts the patterns into a trie whose absent edges hold -1, so nodes receive numbers in creation order. A queue then visits nodes in level order, starting with the children of the root, whose failure link is the root. When the loop dequeues a node v, every shallower node already has a finished table row. For each letter c, a missing child of v copies the entry go[fail[v]][c]. A real child u gets the failure link go[fail[v]][c], which is the node reached by the longest proper suffix of u that is still a trie prefix.

The invariant is that a dequeued node has a correct failure link and that every row of a shallower node is complete. That is why each lookup in go[fail[v]] reads a finished row. The harness also asserts two Java facts used by the code: a new int array is filled with zeros, and 'c' - 'a' is the int 2.

Complexity.

  • Time is O(L * 26), because the fill touches every one of the L + 1 rows once per letter, where L is the total pattern length.
  • Space is O(L * 26), because the table has L + 1 rows of 26 entries, and the queue holds at most one entry per node.
import java.util.*;

public class AcFailLinks {
    /**
     * Returns the failure link of every trie node, with nodes numbered in creation order.
     * Time: O(L * 26), one table-row fill per node.
     * Space: O(L * 26), the dense table dominates.
     * Invariant: a dequeued node has a correct link, and all shallower rows are complete.
     */
    static int[] failLinks(String[] patterns) {
        // Upper bound on node count: one node per inserted character plus the root.
        int cap = 1;
        for (String p : patterns) cap += p.length();
        // Each row holds the 26 transitions; -1 marks an edge that does not exist yet.
        int[][] go = new int[cap][26];
        for (int[] row : go) Arrays.fill(row, -1);
        int nodes = 1;
        // Insert each pattern; a new node takes the next unused number.
        for (String p : patterns) {
            int v = 0;
            for (int k = 0; k < p.length(); k++) {
                // The letter offset is already an int, so it indexes the row directly.
                int c = p.charAt(k) - 'a';
                // Create the child only when the edge is absent; creation order fixes the numbering.
                if (go[v][c] == -1) go[v][c] = nodes++;
                v = go[v][c];
            }
        }
        // Zero-filled by Java, so every link starts at the root until the loop sets it.
        int[] fail = new int[nodes];
        int[] queue = new int[nodes];
        int head = 0, tail = 0;
        // Depth-1 nodes keep link 0 and enter the queue; missing root edges loop to the root.
        for (int c = 0; c < 26; c++) {
            int u = go[0][c];
            if (u == -1) go[0][c] = 0; else queue[tail++] = u;
        }
        // Level order: a node leaves the queue only after all shallower nodes did.
        while (head < tail) {
            int v = queue[head++];
            for (int c = 0; c < 26; c++) {
                int u = go[v][c];
                // Missing child: borrow the transition of the fallback node, whose row is complete.
                if (u == -1) go[v][c] = go[fail[v]][c];
                // Real child: its link is where the fallback node would go on the same letter.
                else { fail[u] = go[fail[v]][c]; queue[tail++] = u; }
            }
        }
        return fail;
    }

    /**
     * Oracle: finds each link by comparing node strings, using substring allocation freely.
     * Time: O(L^3) in the worst case, which is acceptable for tiny inputs.
     * Space: O(L^2) for the node strings.
     * Invariant: the link is the longest proper suffix of the node string that is a node string.
     */
    static int[] oracle(String[] patterns) {
        // Map every trie prefix to its creation number; the empty string is the root.
        LinkedHashMap<String, Integer> id = new LinkedHashMap<>();
        id.put("", 0);
        for (String p : patterns)
            for (int len = 1; len <= p.length(); len++)
                id.putIfAbsent(p.substring(0, len), id.size());
        int[] fail = new int[id.size()];
        // Try suffixes from longest to shortest and keep the first that is a node.
        for (Map.Entry<String, Integer> e : id.entrySet()) {
            String s = e.getKey();
            for (int from = 1; from < s.length(); from++) {
                Integer hit = id.get(s.substring(from));
                if (hit != null) { fail[e.getValue()] = hit; break; }
            }
        }
        return fail;
    }

    public static void main(String[] args) {
        // Java facts the method relies on: zero-filled arrays and int letter offsets.
        int[] zeros = new int[3];
        if (zeros[2] != 0 || ('c' - 'a') != 2) throw new AssertionError("java facts");
        // Fixed examples from the exercise.
        if (!Arrays.equals(failLinks(new String[] {"he", "she", "his", "hers"}), new int[] {0, 0, 0, 0, 1, 2, 0, 3, 0, 3}))
            throw new AssertionError("example 1");
        if (!Arrays.equals(failLinks(new String[] {"abab", "baba"}), new int[] {0, 0, 5, 6, 7, 0, 1, 2, 3}))
            throw new AssertionError("example 2");
        // Random patterns over a small alphabet create many suffix relations.
        Random rnd = new Random(34051);
        for (int t = 0; t < 3000; t++) {
            LinkedHashSet<String> set = new LinkedHashSet<>();
            int k = 1 + rnd.nextInt(5);
            for (int j = 0; j < k; j++) {
                StringBuilder sb = new StringBuilder();
                int len = 1 + rnd.nextInt(6);
                for (int x = 0; x < len; x++) sb.append((char) ('a' + rnd.nextInt(3)));
                set.add(sb.toString());
            }
            String[] pats = set.toArray(new String[0]);
            // The fast version must match the substring-based oracle.
            if (!Arrays.equals(failLinks(pats), oracle(pats))) throw new AssertionError("mismatch " + Arrays.toString(pats));
        }
    }

Return an int[] whose entry k is the number of occurrences of patterns[k]. This changes the previous task by consuming a text and reporting all terminal outputs at each position.

  • Text has length 0 <= text.length() <= 10^5.
  • Letters are lowercase a to z only, in patterns and text.
  • Answer is an int[] of length patterns.length, and every count fits in an int.

Prerequisites. The failure link exercise above and the output link in this lesson.

What This Exercise Changes. The automaton now walks a text, and every position can report several patterns instead of at most one.

Hint

After each text character, which patterns end here? Think of the current node and then of the nodes reachable from it by output links.

Algorithmic Solution (attempt the problem first)

Approach. This solution marks absent edges with 0, which is safe during insertion because no edge ever points back to the root. It records the pattern index at each terminal node, then fills the failure links and the output links in one level-order pass. The output link of a node v is the fallback node fail[v] when a pattern ends there, and otherwise the output link of fail[v]. The scan advances one table lookup per text character and then walks the output links from the current node, adding one to the count of each pattern it visits.

The invariant is that after reading text[0..i] the state is the node of the longest suffix that is a trie prefix, so every pattern ending at i lies on the chain formed by the state and its output links. Overlapping occurrences need no special handling, because the state never resets after a match.

Complexity.

  • Time is O(L * 26 + n + z), because the build fills the table, each text character costs one lookup, and each output link followed counts one occurrence, where z is the total number of occurrences.
  • Space is O(L * 26), because the table dominates, and the counts take one entry per pattern.
import java.util.*;

public class AcMultiScan {
    /**
     * Counts the occurrences of every pattern in the text, overlaps included.
     * Time: O(L * 26 + n + z) for total pattern length L, text length n and z occurrences.
     * Space: O(L * 26) for the table plus O(k) for the counts.
     * Invariant: the state is the longest suffix of the text read so far that is a trie prefix.
     */
    static int[] countMatches(String[] patterns, String text) {
        int cap = 1;
        for (String p : patterns) cap += p.length();
        // Zero means "no edge" during insertion, because no edge ever leads back to the root.
        int[][] go = new int[cap][26];
        int[] id = new int[cap];
        // -1 means no pattern ends at the node.
        Arrays.fill(id, -1);
        int nodes = 1;
        for (int k = 0; k < patterns.length; k++) {
            int v = 0;
            for (int j = 0; j < patterns[k].length(); j++) {
                int c = patterns[k].charAt(j) - 'a';
                // An absent edge reads 0; allocate the next node number for it.
                if (go[v][c] == 0) go[v][c] = nodes++;
                v = go[v][c];
            }
            // Remember which pattern ends at this node.
            id[v] = k;
        }
        int[] fail = new int[nodes];
        int[] link = new int[nodes];
        ArrayDeque<Integer> queue = new ArrayDeque<>();
        // Children of the root fall back to the root and start the level order.
        for (int c = 0; c < 26; c++) if (go[0][c] != 0) queue.add(go[0][c]);
        while (!queue.isEmpty()) {
            int v = queue.poll();
            int f = fail[v];
            // The nearest pattern end on the fallback chain: the fallback itself, or its own nearest.
            link[v] = id[f] >= 0 ? f : link[f];
            for (int c = 0; c < 26; c++) {
                int u = go[v][c];
                // Row v still holds only real children, so 0 here means the edge is absent.
                if (u == 0) go[v][c] = go[f][c];
                else { fail[u] = go[f][c]; queue.add(u); }
            }
        }
        int[] counts = new int[patterns.length];
        int state = 0;
        // One lookup per text character: the table already contains the fallback.
        for (int i = 0; i < text.length(); i++) {
            state = go[state][text.charAt(i) - 'a'];
            // Walk the node itself if it ends a pattern, then each output link; every step is one match.
            for (int m = id[state] >= 0 ? state : link[state]; m != 0; m = link[m]) counts[id[m]]++;
        }
        return counts;
    }

    /**
     * Oracle: tests every pattern at every start position with regionMatches.
     * Time: O(n * L). Space: O(k).
     * Invariant: counts[k] equals the number of starts where patterns[k] matches.
     */
    static int[] oracle(String[] patterns, String text) {
        int[] counts = new int[patterns.length];
        for (int k = 0; k < patterns.length; k++)
            for (int s = 0; s + patterns[k].length() <= text.length(); s++)
                if (text.regionMatches(s, patterns[k], 0, patterns[k].length())) counts[k]++;
        return counts;
    }

    public static void main(String[] args) {
        // Fixed examples from the exercise.
        if (!Arrays.equals(countMatches(new String[] {"he", "she", "his", "hers"}, "ushers"), new int[] {1, 1, 0, 1}))
            throw new AssertionError("example 1");
        if (!Arrays.equals(countMatches(new String[] {"a", "aa"}, "aaaa"), new int[] {4, 3}))
            throw new AssertionError("example 2");
        // An empty text reports nothing.
        if (!Arrays.equals(countMatches(new String[] {"a"}, ""), new int[] {0})) throw new AssertionError("empty text");
        // Random patterns and texts over {a, b, c} produce many overlaps and nested patterns.
        Random rnd = new Random(34052);
        for (int t = 0; t < 3000; t++) {
            LinkedHashSet<String> set = new LinkedHashSet<>();
            int k = 1 + rnd.nextInt(5);
            for (int j = 0; j < k; j++) {
                StringBuilder sb = new StringBuilder();
                int len = 1 + rnd.nextInt(4);
                for (int x = 0; x < len; x++) sb.append((char) ('a' + rnd.nextInt(3)));
                set.add(sb.toString());
            }
            String[] pats = set.toArray(new String[0]);
            StringBuilder tx = new StringBuilder();
            int n = rnd.nextInt(30);
            for (int x = 0; x < n; x++) tx.append((char) ('a' + rnd.nextInt(3)));
            // The automaton must agree with the per-pattern oracle.
            if (!Arrays.equals(countMatches(pats, tx.toString()), oracle(pats, tx.toString())))
                throw new AssertionError("mismatch " + Arrays.toString(pats) + " " + tx);
        }
    }

Suffix Pattern Matches

Author exercise

Problem Specification. Given distinct non-empty patterns over a to z and a text over a to z, return an int[] ends of length text.length(), where ends[i] is the number of patterns that occur in the text and finish at index i. A pattern finishes at i when it equals the text characters from i - length + 1 through i. Some patterns are suffixes of other patterns, so one text position can end several patterns, and a count that reads only the current node misses the shorter ones.

Input Constraints. The limits are:

  • Patterns satisfy 1 <= patterns.length <= 1000, all distinct, with total length at most 10^4.
  • Text has length 0 <= text.length() <= 10^5.
  • Letters are lowercase a to z only.
  • Answer is an int[] of length text.length(), and each entry is at most patterns.length.
  • Mutation does not occur; neither input changes.

Example 1. Input patterns ["he","she","hers"] and text "ushers", output [0,0,0,2,0,1].

Example 2. Input patterns ["a","aa","aaa"] and text "aaaa", output [1,2,3,3], where every shorter pattern is a suffix of the longer ones.

Prerequisites. The multi-pattern scan above.

What This Exercise Changes. A node carries the matches inherited from its failure chain as well as its own, so the count at a node includes its fallback's count.

Hint

If the current node is aaa, which other patterns end at the same position? Which link leads to each of them?

Algorithmic Solution (attempt the problem first)

Approach. When one pattern is a suffix of another, reaching the longer pattern's node also completes the shorter one, yet the shorter pattern's node is not the current state. The fix is to store at each node the number of patterns that end there or on its failure chain. The value of a node is one if a pattern ends exactly there, plus the value of its failure link. The level-order loop computes it when the node is dequeued, because the failure link is shallower and already has its value.

With that value the scan needs no chain walk. After each text character the answer for that position is the value of the current state. The invariant is that inherited[v] equals the number of patterns that are suffixes of the string of v, so the entry at index i counts exactly the patterns that finish at i. For a, aa and aaa the node aaa has value 3, because the two shorter patterns are suffixes of it.

Complexity.

  • Time is O(L * 26 + n), because the build fills the table once and the scan does one lookup and one read per text character.
  • Space is O(L * 26 + n), because of the table and the answer array of length n.
import java.util.*;

public class AcSuffixMatches {
    /**
     * For each text index, counts the patterns that finish at that index.
     * Time: O(L * 26 + n), one table lookup per text letter.
     * Space: O(L * 26 + n) for the table and the answer.
     * Invariant: inherited[v] counts the patterns that are suffixes of the string of node v.
     */
    static int[] endCounts(String[] patterns, String text) {
        int cap = 1;
        for (String p : patterns) cap += p.length();
        int[][] go = new int[cap][26];
        // own[v] is 1 when a pattern ends exactly at v.
        int[] own = new int[cap];
        int nodes = 1;
        for (String p : patterns) {
            int v = 0;
            for (int j = 0; j < p.length(); j++) {
                int c = p.charAt(j) - 'a';
                // Zero is the absent marker while inserting.
                if (go[v][c] == 0) go[v][c] = nodes++;
                v = go[v][c];
            }
            own[v] = 1;
        }
        int[] fail = new int[nodes];
        // inherited[v] = own[v] + inherited[fail[v]], filled in level order.
        int[] inherited = new int[nodes];
        int[] queue = new int[nodes];
        int head = 0, tail = 0;
        for (int c = 0; c < 26; c++) if (go[0][c] != 0) queue[tail++] = go[0][c];
        while (head < tail) {
            int v = queue[head++];
            int f = fail[v];
            // The failure link is shallower, so its inherited count is final already.
            inherited[v] = own[v] + inherited[f];
            for (int c = 0; c < 26; c++) {
                int u = go[v][c];
                if (u == 0) go[v][c] = go[f][c];
                else { fail[u] = go[f][c]; queue[tail++] = u; }
            }
        }
        int[] ends = new int[text.length()];
        int state = 0;
        // Scan once; the answer at index i is read from the state alone.
        for (int i = 0; i < text.length(); i++) {
            state = go[state][text.charAt(i) - 'a'];
            ends[i] = inherited[state];
        }
        return ends;
    }

    /**
     * Oracle: counts, for each index, the patterns whose last character lands there.
     * Time: O(n * L). Space: O(n).
     * Invariant: ends[i] counts patterns p with text[i - |p| + 1 .. i] equal to p.
     */
    static int[] oracle(String[] patterns, String text) {
        int[] ends = new int[text.length()];
        for (String p : patterns)
            for (int s = 0; s + p.length() <= text.length(); s++)
                if (text.regionMatches(s, p, 0, p.length())) ends[s + p.length() - 1]++;
        return ends;
    }

    public static void main(String[] args) {
        // Fixed examples from the exercise.
        if (!Arrays.equals(endCounts(new String[] {"he", "she", "hers"}, "ushers"), new int[] {0, 0, 0, 2, 0, 1}))
            throw new AssertionError("example 1");
        if (!Arrays.equals(endCounts(new String[] {"a", "aa", "aaa"}, "aaaa"), new int[] {1, 2, 3, 3}))
            throw new AssertionError("example 2");
        // Random patterns over {a, b} make suffix patterns common.
        Random rnd = new Random(34053);
        for (int t = 0; t < 3000; t++) {
            LinkedHashSet<String> set = new LinkedHashSet<>();
            int k = 1 + rnd.nextInt(6);
            for (int j = 0; j < k; j++) {
                StringBuilder sb = new StringBuilder();
                int len = 1 + rnd.nextInt(4);
                for (int x = 0; x < len; x++) sb.append((char) ('a' + rnd.nextInt(2)));
                set.add(sb.toString());
            }
            String[] pats = set.toArray(new String[0]);
            StringBuilder tx = new StringBuilder();
            int n = rnd.nextInt(25);
            for (int x = 0; x < n; x++) tx.append((char) ('a' + rnd.nextInt(2)));
            // The inherited counts must match the position-by-position oracle.
            if (!Arrays.equals(endCounts(pats, tx.toString()), oracle(pats, tx.toString())))
                throw new AssertionError("mismatch " + Arrays.toString(pats) + " " + tx);
        }
    }

LeetCode 1032

Problem Specification. Design a class StreamChecker. Its constructor takes an array words of distinct non-empty strings over a to z. Its method query(char letter) appends letter to the end of an internal stream, which starts empty and is never cleared. It returns true exactly when some word in words is a suffix of the whole stream so far, and false otherwise. The method returns one boolean and does not say which word matched or how many did. The automaton state must persist between calls to query.

Input Constraints. The limits are:

  • Words satisfy 1 <= words.length <= 2000, all distinct, with total length at most 10^4.
  • Calls to query number at most 4 * 10^4.
  • Letters are lowercase a to z only, in words and queries.
  • Answer of each call is a boolean.
  • Mutation does not occur on words; the stream is only appended to.

Example 1. Input words ["rat","at","tea"] and queries r,a,t,e,a, output false,false,true,false,true.

Example 2. Input words ["abcd","bc"] and queries a,b,c,d,c, output false,false,true,true,false; the third query is true only because bc is inherited through a failure link.

Prerequisites. The multi-pattern scan and suffix matches above.

What This Exercise Changes. The text is no longer a finished string, so the scan loop becomes a single step that keeps the node between calls.

Hint

The state must survive between calls. Can the answer for a node be decided once, when the automaton is built, so that each query is one lookup?

Algorithmic Solution (attempt the problem first)

Approach. The class builds the automaton once in its constructor and keeps one int field state between calls. A call to query moves the state by one table lookup and returns a precomputed boolean for the new node. The boolean for a node is true when a word ends at the node or when the boolean of its failure link is true. The level-order loop computes it when the node is dequeued, because the failure link is shallower. This single boolean per node is the compact form of the output links, since the problem asks only whether some word matches and not which one.

The invariant is that after each call state is the node of the longest suffix of the stream that is a prefix of some word. A word is a suffix of the stream exactly when its node lies on the failure chain of state, so the boolean answers the question. The stream itself is never stored, so memory does not grow with the number of calls.

Complexity.

  • Time is O(L * 26) for construction and O(1) per query, because a query is one table lookup and one array read.
  • Space is O(L * 26), because the table dominates, and the stream is not stored.
import java.util.*;

public class AcStreamRecognize {
    /** Answers whether some word is a suffix of the stream appended so far. */
    static final class StreamChecker {
        private final int[][] go;
        private final boolean[] hit;
        private int state;

        /**
         * Builds the automaton over the words.
         * Time: O(L * 26). Space: O(L * 26).
         * Invariant: hit[v] is true when some word is a suffix of the string of node v.
         */
        StreamChecker(String[] words) {
            int cap = 1;
            for (String w : words) cap += w.length();
            go = new int[cap][26];
            boolean[] ends = new boolean[cap];
            int nodes = 1;
            for (String w : words) {
                int v = 0;
                for (int j = 0; j < w.length(); j++) {
                    int c = w.charAt(j) - 'a';
                    // Zero marks an absent edge until the level-order fill.
                    if (go[v][c] == 0) go[v][c] = nodes++;
                    v = go[v][c];
                }
                ends[v] = true;
            }
            hit = new boolean[nodes];
            int[] fail = new int[nodes];
            int[] queue = new int[nodes];
            int head = 0, tail = 0;
            for (int c = 0; c < 26; c++) if (go[0][c] != 0) queue[tail++] = go[0][c];
            while (head < tail) {
                int v = queue[head++];
                int f = fail[v];
                // A word ends here, or one ends on the fallback chain.
                hit[v] = ends[v] || hit[f];
                for (int c = 0; c < 26; c++) {
                    int u = go[v][c];
                    if (u == 0) go[v][c] = go[f][c];
                    else { fail[u] = go[f][c]; queue[tail++] = u; }
                }
            }
        }

        /**
         * Appends one letter and reports whether some word is now a suffix of the stream.
         * Time: O(1), one lookup. Space: O(1).
         * Invariant: state is the longest suffix of the stream that is a prefix of some word.
         */
        boolean query(char letter) {
            // One lookup moves the state; the table already holds the fallback.
            state = go[state][letter - 'a'];
            // The precomputed flag covers the whole failure chain.
            return hit[state];
        }
    }

    /**
     * Oracle: keeps the whole stream and tests endsWith for every word.
     * Time: O(L) per call. Space: O(stream length).
     * Invariant: the answer is true exactly when some word is a suffix of the stream.
     */
    static boolean oracleQuery(StringBuilder stream, String[] words, char letter) {
        stream.append(letter);
        for (String w : words) if (stream.length() >= w.length() && stream.substring(stream.length() - w.length()).equals(w)) return true;
        return false;
    }

    public static void main(String[] args) {
        // Example 1 from the exercise.
        StreamChecker a = new StreamChecker(new String[] {"rat", "at", "tea"});
        boolean[] want1 = {false, false, true, false, true};
        String q1 = "ratea";
        for (int i = 0; i < 5; i++) if (a.query(q1.charAt(i)) != want1[i]) throw new AssertionError("example 1 at " + i);
        // Example 2: the third query is true only through the inherited word bc.
        StreamChecker b = new StreamChecker(new String[] {"abcd", "bc"});
        boolean[] want2 = {false, false, true, true, false};
        String q2 = "abcdc";
        for (int i = 0; i < 5; i++) if (b.query(q2.charAt(i)) != want2[i]) throw new AssertionError("example 2 at " + i);
        // Random words and streams over {a, b, c}; state must persist across many calls.
        Random rnd = new Random(34054);
        for (int t = 0; t < 2000; t++) {
            LinkedHashSet<String> set = new LinkedHashSet<>();
            int k = 1 + rnd.nextInt(5);
            for (int j = 0; j < k; j++) {
                StringBuilder sb = new StringBuilder();
                int len = 1 + rnd.nextInt(4);
                for (int x = 0; x < len; x++) sb.append((char) ('a' + rnd.nextInt(3)));
                set.add(sb.toString());
            }
            String[] words = set.toArray(new String[0]);
            StreamChecker sc = new StreamChecker(words);
            StringBuilder stream = new StringBuilder();
            for (int x = 0; x < 40; x++) {
                char ch = (char) ('a' + rnd.nextInt(3));
                // Each answer must equal the endsWith oracle on the full stream.
                if (sc.query(ch) != oracleQuery(stream, words, ch)) throw new AssertionError("mismatch " + Arrays.toString(words) + " at " + x);
            }
        }
    }

Problem

Why A Stream Scanner Leaks Secrets

A log forwarder masks secrets before log lines leave a server. It watches the byte stream for 2,000 forbidden tokens, such as API key prefixes. Bytes arrive in network chunks of any size, so a token can start in one chunk and end in the next. The first version keeps every received character and, after each new character, compares all 2,000 tokens with the end of that buffer. In a load test its memory grows with the stream, and each character costs time proportional to the total length of all tokens. A second version drops its partial progress whenever a character fails to extend a match. That version misses the token aab inside the input aaab, so the secret reaches the log.

The question of this lesson is how a scanner can keep a small state for each stream, never store the stream, and still report every token that ends at the current character.

What Each Technique Adds

What The Earlier Lessons Contribute

The lesson Match A Pattern Without Restarting supplied the prefix function, which that lesson stored in an array named pi. This lesson calls the same array fail, to match the failure links of the trie. For one pattern p, the entry fail[i] is the length of the longest proper prefix of p[0..i] that is also a suffix of it. After a mismatch, the matched length moves to fail[k - 1] and the text index stays where it is. The lesson Match Many Patterns In One Pass supplied the trie. Each trie node stands for one prefix of some word, a failure link points to the longest proper suffix of that prefix that is also a node, and an output link reaches the nearest word that ends on that chain.

This lesson reads both ideas as one machine whose only memory is one state. The new step is to keep the machine running after a full match, so that overlapping occurrences are reported, and to keep the state alive between calls, so that the input never has to be stored.

Simple approach

Comparing Every Word At Every Character

The direct design stores the stream in a StringBuilder. After each appended character, it compares every word with the end of the stream and counts the words that agree.

final class NaiveStream {
    private final String[] words;
    private final StringBuilder stream = new StringBuilder();

    NaiveStream(String[] words) { this.words = words; }

    // Returns how many words end at the newest character of the stream.
    int query(char c) {
        stream.append(c);
        int count = 0;
        for (String w : words) {
            int start = stream.length() - w.length();
            if (start < 0) continue;                       // the stream is still shorter than this word
            int j = 0;
            while (j < w.length() && stream.charAt(start + j) == w.charAt(j)) j++;
            if (j == w.length()) count++;                  // every character agreed
        }
        return count;
    }
}

With the words aab, ab and b, the queries a, a, b return 0, 0 and 3, because all three words end at the third character. The answers are correct. Each call still reads the whole word list and the whole buffer end again.

Predict first: A single word of 1,000 letters `a` followed by one `b` is stored, and the stream is 100,000 letters `a`. About how many character comparisons does the code above make, and how much memory does the stream take?

Every query compares the 1,000 letters a of the word against the end of the stream and fails only at the final letter b, so it makes about 1,001 comparisons. The run costs about 10^8 comparisons, which is O(n * m) for a stream of n characters and a word of m characters. The buffer holds all 100,000 characters, so memory grows with the stream and never shrinks.

Bottleneck

Two Costs That Grow Without Limit

For q queries and words of total length L, the code above costs O(q * L) time. With L = 10^4 and q = 4 * 10^4, that is 4 * 10^8 character reads for a task that only needs one decision per character. The buffer adds O(q) memory, which is unacceptable for a stream that never ends.

The repeated work is easy to name. After the stream aaaa, the word aaab has matched three characters. At the next query the code reads those same three characters again, from the start of the word, and the query after that reads them again. Information gained at one character is discarded and rebuilt at the next. Restarting from the first character of the word on every mismatch removes some reads but breaks correctness, because the suffix aa of aaa is already a valid partial match for aab. Running a separate single-pattern matcher for each word keeps the reads linear in the stream, but still costs one step per word for every character, which is O(k) per character for k words.

A fix must give four things. It must use constant extra memory per stream, apart from a structure built once from the words. It must do work that does not grow with the number of words. It must keep every partial match that can still succeed. It must report every word that ends at the current character, including words nested inside longer ones.

Key idea

One State Summarizes The Whole Stream

The Match State

Read the stream one character at a time and ask one question after each character. What is the longest suffix of the characters read so far that is also a prefix of some stored word? The answer is the match state. For one pattern it is a length k between 0 and m. For many words it is a trie node.

The match state is enough to predict everything that follows. Any word occurrence that is still alive, meaning its first characters are already in the stream, begins at some suffix of the stream. That suffix is a prefix of the word, so it is no longer than the longest one. It is also a suffix of the longest one, because both end at the same character. Therefore every alive partial match is a border of the match state string, and the failure links list those borders from longest to shortest. Nothing before the match state needs to be kept.

The Fallback Transition

When the next character c does not extend the current state, the machine follows a fallback transition. It moves to the failure target and tries c again at that shorter state, repeating until c extends a state or the root is reached. No text index moves, so no character is read twice. Each character raises the matched length by at most 1, and each fallback lowers it by at least 1, so all fallbacks together cost at most as much as all the growth. The work over a stream of n characters is O(n) in total.

A full match is not a stopping point. At state m there is no next pattern character, so the machine treats the state as a mismatch and falls back to fail[m - 1]. The longest border of a found word is exactly the longest overlap with the next occurrence. In a trie the same rule is carried by the failure link, and a count stored at each node adds the words that end along its failure chain.

One Array Answers Three Questions

The array fail of one string s of length n also answers questions about s alone. The value fail[n - 1] is the length of the longest proper prefix that is also a suffix. The smallest period of s is the smallest p such that s[i] == s[i + p] wherever both indexes exist, and it equals n - fail[n - 1]. When this p divides n and is less than n, the string is n / p copies of its first p characters. When it does not divide n, the whole string is the only repeating unit.

State

State Kept By The Machine

One pattern and a set of words use the same pieces with different shapes.

  • fail for one pattern is an int array where fail[i] is the longest proper border length of p[0..i].
  • k is the match state for one pattern, the number of pattern characters that end the stream read so far, from 0 to m.
  • go for many words is a table with one row per trie node and one column per letter, holding the next node for every letter.
  • fail for many words is indexed by node, and holds the node of the longest proper suffix that is also a node. Node k of a one-word trie has the target fail[k - 1] of the array above.
  • hits holds, for each node, how many stored words end at that node or along its failure chain.
  • state is the current trie node and starts at the root, node 0. It is the only value kept between calls.

Words and stream use only lowercase a to z, so the letter c selects column c - 'a'.

The first five characters extend the state from 0 to 5, which is a full match that starts at index 0. The machine does not stop. It falls back from state 5 to fail[4] = 2, because the last two characters aa already begin the next occurrence. At index 5 the character is a, but the pattern expects b after two matched characters. One fallback moves the state to fail[1] = 1, where a matches and the state becomes 2. Indexes 6, 7 and 8 raise the state to 5 again, so the second match starts at index 4. The text index moved forward on every step, and the result is the array 0, 4.

Three Words With Failure Links

The words are ab, bab and b. Their trie has nodes 1 and 2 for ab, nodes 3, 4 and 5 for bab, and the word b ends at node 3. The failure targets are fail[2] = 3, fail[4] = 1 and fail[5] = 2, and the others point to the root. The stored counts are hits[2] = 2, hits[3] = 1 and hits[5] = 3, because node 5 inherits ab through node 2 and b through node 3. The stream is ababbab, and the pointer v is the current node.

The first b reaches node 2 and reports two words, ab and b. The next a has no child under node 2, so the transition goes through the failure target, node 3, and lands on node 4. The second b reaches node 5 and reports three words in one lookup. The following b finds no child under node 5. The transitions follow the failure chain to node 3 and report only b. The counts for the whole stream are 0, 2, 0, 3, 1, 0, 3, and no query looked at an earlier character.

Code

Matching One Pattern And Many Words

One Pattern As A Machine

The method advance is the single transition. It is used while building fail and while scanning, and it never reads a character twice. The names fail and state here match the variables stage.

final class StreamMatching {
    // Longest proper border length for every prefix of pat; pat must not be null.
    static int[] failArray(String pat) {
        int[] fail = new int[pat.length()];
        int state = 0;
        for (int i = 1; i < pat.length(); i++) {
            state = advance(fail, pat, state, pat.charAt(i));
            fail[i] = state;
        }
        return fail;
    }

    // One transition: from a match state, read c and return the next match state.
    static int advance(int[] fail, String pat, int state, char c) {
        if (state == pat.length()) state = fail[state - 1];          // a full match falls back instead of stopping
        while (state > 0 && pat.charAt(state) != c) state = fail[state - 1];
        return pat.charAt(state) == c ? state + 1 : state;
    }

    // Every start index of pat in text, overlaps included, in increasing order. pat is non-empty.
    static int[] allStarts(String text, String pat) {
        int[] fail = failArray(pat);
        int[] starts = new int[text.length()];
        int found = 0, state = 0;
        for (int i = 0; i < text.length(); i++) {
            state = advance(fail, pat, state, text.charAt(i));
            if (state == pat.length()) starts[found++] = i - pat.length() + 1;
        }
        return java.util.Arrays.copyOf(starts, found);
    }

    // Smallest length u so that s is s[0..u-1] repeated; returns s.length() when no shorter unit exists.
    static int smallestUnit(String s) {
        int n = s.length();
        int p = n - failArray(s)[n - 1];
        return n % p == 0 ? p : n;
    }
}

The call failArray(pat) relies on advance reading fail[state - 1] only for indexes already filled. In failArray the state is always less than i, so the entry it reads has been written.

Many Words With A Persistent State

The class below builds the trie once, fills go, fail and hits in one level-order pass, and keeps one state between calls. The array made marks which go entries are real trie edges, because the fill later writes fallback results into the same table and a plain 0 cannot tell the two apart.

final class WordStream {
    private static final int ALPHABET = 26;
    private final int[][] go;
    private final int[] hits;
    private int state = 0;

    WordStream(String[] words) {
        int cap = 1;
        for (String w : words) cap += w.length();                  // each character adds at most one node
        go = new int[cap][ALPHABET];
        hits = new int[cap];
        int[] fail = new int[cap];
        boolean[] made = new boolean[cap * ALPHABET];              // marks real trie edges, node * 26 + letter
        int nodes = 1;
        for (String w : words) {
            int v = 0;
            for (int j = 0; j < w.length(); j++) {
                int c = w.charAt(j) - 'a';
                if (!made[v * ALPHABET + c]) { made[v * ALPHABET + c] = true; go[v][c] = nodes++; }
                v = go[v][c];
            }
            hits[v]++;                                             // one more word ends at this node
        }
        int[] queue = new int[nodes];
        int head = 0, tail = 0;
        for (int c = 0; c < ALPHABET; c++) if (made[c]) queue[tail++] = go[0][c];
        while (head < tail) {
            int v = queue[head++];
            hits[v] += hits[fail[v]];                              // the failure target is shallower, so its count is final
            for (int c = 0; c < ALPHABET; c++) {
                int u = go[v][c];
                if (made[v * ALPHABET + c]) { fail[u] = go[fail[v]][c]; queue[tail++] = u; }
                else go[v][c] = go[fail[v]][c];                    // missing edge becomes the fallback result
            }
        }
    }

    // Consumes one letter and returns how many words end at it.
    int query(char letter) {
        state = go[state][letter - 'a'];
        return hits[state];
    }
}

Cost And Java Details

  • failArray costs O(m) time and O(m) space, because the state rises at most once per character.
  • allStarts costs O(n + m) time and O(m + z) space for z matches, because the text index never moves back.
  • WordStream builds in O(L * 26) time and space for total word length L, and each query costs O(1) time with no growth in memory.

The expression letter - 'a' has type int, so it indexes the table directly, and a letter outside a to z would throw an ArrayIndexOutOfBoundsException instead of reading a wrong column. The code never calls substring, because every comparison uses an index.

When to use it

When The Machine Applies

Recognizing The Pattern

Look for input that arrives as a sequence and a question asked after each element about the end of what has arrived: does any stored word end here, how many, or where did a pattern start. A second cue is a question about a single string's own structure, such as the longest border or the shortest repeating unit. Both cue types are answered by the same state. The invariant is that the match state always names the longest suffix of the characters read that is a prefix of some stored word, so the whole stream collapses into one number or node.

The Nearest False Friend

The false friend is to restart matching from scratch on a mismatch. It looks natural, and it passes inputs such as abc in abxabc, yet it fails on aab in aaab, because the characters already matched may begin the next attempt. A second false friend is to run KMP on each word separately. It is correct for one pattern, and for k words it costs k steps for every character, so a pattern list of 2,000 words keeps the cost of the naive scan. The trie with failure links merges all words into one state.

When Not To Use It

Do not use the table version when the word list changes while the stream runs, because adding one word can change failure targets across the trie and forces a rebuild. Do not use it when the alphabet is large, such as full Unicode, because a table of L * |alphabet| ints is too big and a map per node is needed. A single search of a stored text with one pattern is better served by String.indexOf, which needs no preparation. Patterns with wildcards or character classes break the border argument and need a different method.

Every Start Of A Pattern

LeetCode 28

Problem Specification. Given strings text and pattern, return an int[] of every index s such that text has pattern as a substring starting at s. The occurrences may overlap. The indices are in increasing order, and the array is empty when there is no occurrence. Run the pattern as an automaton with states 0 to m, where state m is the match state and it falls back to fail[m - 1] instead of stopping the scan.

Input Constraints. The limits are:

  • Text length is 0 <= text.length() <= 10^5.
  • Pattern length is 1 <= pattern.length() <= 10^5.
  • Characters are lowercase English letters.
  • Return value is a new int[], which may have length 0.
  • Mutation does not occur; both strings are immutable.

Example 1. Input text = "abababa", pattern = "aba", output [0, 2, 4].

Example 2. Input text = "aaaaaa", pattern = "aaa", output [0, 1, 2, 3]. Every position after the third continues the previous match.

Prerequisites. The Prefix Function and First Occurrence With KMP exercises of the lesson Match A Pattern Without Restarting. This exercise changes the contract of LeetCode 28: it returns all start indices, not the first one.

What This Exercise Changes. The scan no longer returns at the first full match, and the match state falls back to fail[m - 1] so overlapping occurrences are found.

Hint

After the machine reaches state m, which earlier state describes the longest end of the text that still begins the pattern?

Algorithmic Solution (attempt the problem first)

Approach. The pattern defines states 0 to m, where state k means that the last k characters read equal pattern[0..k-1]. The array fail is built first. Each text character is then one transition: while the next pattern character pattern[k] differs from the text character, the state drops to fail[k - 1], and when the characters agree the state rises by one. State m has no next pattern character. The transition from it therefore starts with a fall to fail[m - 1], which keeps the longest end of the text that can still begin another occurrence. This fall is what lets overlapping occurrences appear, and a scan that returned at state m could report only the first.

The invariant is that after reading text[0..i] the state is the length of the longest prefix of the pattern that is a suffix of that text, except that a full match is reported before the fall. A match ending at i is reported as start i - m + 1, in increasing order because i only grows.

Complexity.

  • Time is O(n + m), because the state rises at most once per text character and every fallback lowers it, so fallbacks never exceed n.
  • Space is O(m + z), because fail has one entry per pattern character and the answer holds z start indices.
import java.util.Arrays;
import java.util.Random;

public final class AllStartsAutomaton {
    // Counts fallbacks so that main can check the amortized bound.
    static int fallbacks;

    /**
     * Returns the border length of every prefix of pat; pat is non-empty.
     * Time: O(m), because the state rises at most once per character.
     * Space: O(m), because the result has one entry per character.
     * Invariant: before iteration i, k equals fail[i - 1].
     */
    static int[] failArray(String pat) {
        // One entry per pattern character; entry 0 stays 0 because a single character has no proper prefix.
        int[] fail = new int[pat.length()];
        // k is the length of the border of the prefix read so far.
        int k = 0;
        // Position 0 needs no work, so the loop starts at 1.
        for (int i = 1; i < pat.length(); i++) {
            // A mismatch moves k to the next shorter border of the same prefix.
            while (k > 0 && pat.charAt(i) != pat.charAt(k)) k = fail[k - 1];
            // A match extends the border by one character.
            if (pat.charAt(i) == pat.charAt(k)) k++;
            // Record the border length for position i.
            fail[i] = k;
        }
        // The caller reads fallback targets from this array.
        return fail;
    }

    /**
     * Returns every start index of pat in text, overlaps included, in increasing order.
     * Time: O(n + m), because the text index never moves back and fallbacks are paid by earlier growth.
     * Space: O(m + z), because of the fail array and the z reported starts.
     * Invariant: after reading text[0..i], k is the longest pattern prefix that is a suffix of the text read.
     */
    static int[] allStarts(String text, String pat) {
        // Pattern table built once; its cost is O(m).
        int[] fail = failArray(pat);
        // Matches cannot exceed the number of text positions, so this buffer is large enough.
        int[] starts = new int[text.length()];
        // found counts reported starts; k is the match state.
        int found = 0, k = 0;
        // The text index only moves forward, which bounds the scan to n iterations.
        for (int i = 0; i < text.length(); i++) {
            // Fall back while the next pattern character rejects the text character.
            while (k > 0 && pat.charAt(k) != text.charAt(i)) { k = fail[k - 1]; fallbacks++; }
            // An agreeing character extends the match by one.
            if (pat.charAt(k) == text.charAt(i)) k++;
            // A full match ends at i, so it starts at i - m + 1.
            if (k == pat.length()) {
                starts[found++] = i - pat.length() + 1;
                // The match state has no next character; fall to the longest border so overlaps continue.
                k = fail[k - 1];
                fallbacks++;
            }
        }
        // Trim the buffer to the reported matches.
        return Arrays.copyOf(starts, found);
    }

    /**
     * Brute-force oracle that tests every start position.
     * Time: O(n * m), because each start compares up to m characters.
     * Space: O(z), because only the result is stored.
     * Invariant: start s is reported exactly when the m characters from s equal pat.
     */
    static int[] oracle(String text, String pat) {
        // Collect starts in a list because the count is unknown.
        java.util.List<Integer> out = new java.util.ArrayList<>();
        // Every start with enough room for the pattern is tested.
        for (int s = 0; s + pat.length() <= text.length(); s++) {
            // regionMatches compares in place without allocating a substring.
            if (text.regionMatches(s, pat, 0, pat.length())) out.add(s);
        }
        // Convert the list to the contract's int array.
        return out.stream().mapToInt(Integer::intValue).toArray();
    }

    public static void main(String[] args) {
        // Overlapping occurrences from the exercise.
        if (!Arrays.equals(allStarts("abababa", "aba"), new int[] {0, 2, 4})) throw new AssertionError("abababa");
        // The hostile all-equal case reports every position after the third.
        if (!Arrays.equals(allStarts("aaaaaa", "aaa"), new int[] {0, 1, 2, 3})) throw new AssertionError("aaaaaa");
        // A pattern longer than the text yields an empty array.
        if (allStarts("aab", "aabaab").length != 0) throw new AssertionError("longer pattern");
        // An empty text yields an empty array.
        if (allStarts("", "a").length != 0) throw new AssertionError("empty text");
        // A pattern of length one is its own match state with no fallback beyond the root.
        if (!Arrays.equals(allStarts("abca", "a"), new int[] {0, 3})) throw new AssertionError("length one");
        // Random comparison with the oracle; the seed makes any failure reproducible.
        Random rnd = new Random(3491L);
        for (int t = 0; t < 4000; t++) {
            // Small alphabets create many overlaps and fallbacks.
            int alpha = 1 + rnd.nextInt(3);
            StringBuilder tx = new StringBuilder(), pt = new StringBuilder();
            for (int i = rnd.nextInt(25); i > 0; i--) tx.append((char) ('a' + rnd.nextInt(alpha)));
            for (int i = 1 + rnd.nextInt(5); i > 0; i--) pt.append((char) ('a' + rnd.nextInt(alpha)));
            // Reset the counter so each case is bounded on its own.
            fallbacks = 0;
            int[] got = allStarts(tx.toString(), pt.toString());
            if (!Arrays.equals(got, oracle(tx.toString(), pt.toString()))) throw new AssertionError("mismatch " + tx + " / " + pt);
            // The amortized bound: fallbacks never exceed the text length.
            if (fallbacks > tx.length()) throw new AssertionError("too many fallbacks");
        }
    }

Smallest Repeating Unit

LeetCode 459

Problem Specification. Given a non-empty string s of length n, return the smallest positive integer u such that u divides n and s equals the first u characters repeated n / u times. Return n when no smaller u has this property. Compute the answer from n - fail[n - 1], where fail[n - 1] is the length of the longest proper prefix of s that is also a suffix.

Input Constraints. The limits are:

  • Length is 1 <= s.length() <= 10^5.
  • Characters are lowercase English letters.
  • Return value is an int from 1 to n.
  • Ties do not occur because the smallest valid u is unique.
  • Mutation does not occur; the string is immutable.

Example 1. Input s = "abcabcabc", output 3.

Example 2. Input s = "ababa", output 5. The border length is 3 and the gap 2 does not divide 5, so no proper unit exists.

Prerequisites. The first exercise above. This exercise changes the contract of LeetCode 459: it returns a length, not a boolean.

What This Exercise Changes. The output changes from a yes-or-no answer to the exact unit length. The test n % p == 0 still decides between p and n, where p = n - fail[n - 1].

Hint

If the gap n - fail[n - 1] does not divide n, can any other length work?

Algorithmic Solution (attempt the problem first)

Approach. The array fail gives b = fail[n - 1], the length of the longest proper prefix of s that is also a suffix. A border of length b means that s[i] == s[i + (n - b)] for every valid index, so p = n - b is the smallest shift under which the string agrees with itself, which is its smallest period. When p divides n, the string is the first p characters repeated n / p times, and no smaller length can work because a smaller valid unit would be a smaller period. When p does not divide n, no proper unit exists. A proper unit u that divides n is also a period with u <= n / 2, and then p + u <= n, so the periodicity lemma of Fine and Wilf makes p divide u, which would make p divide n.

When the border is 0, the formula gives p = n, and n divides n, so the same line returns n. The invariant is that p is the smallest period of the whole string, because the border chain lists all periods.

Complexity.

  • Time is O(n), because building fail is linear and the final test is one remainder.
  • Space is O(n), because fail has one entry per character.
import java.util.Random;

public final class SmallestRepeatingUnit {
    /**
     * Returns the border length of the whole string, using a running border value.
     * Time: O(n), because the border rises at most once per character.
     * Space: O(n), because the table of border lengths has n entries.
     * Invariant: before iteration i, k is the border length of s[0..i-1].
     */
    static int wholeBorder(String s) {
        // Table of border lengths per prefix.
        int[] fail = new int[s.length()];
        // k is the current border length.
        int k = 0;
        // Each position extends or shortens the border of the previous prefix.
        for (int i = 1; i < s.length(); i++) {
            // Shorten the border until the next character agrees or the border is empty.
            while (k > 0 && s.charAt(i) != s.charAt(k)) k = fail[k - 1];
            // Extend by one when the characters agree.
            if (s.charAt(i) == s.charAt(k)) k++;
            // Store the border for prefix i.
            fail[i] = k;
        }
        // The last entry is the border of the whole string.
        return fail[s.length() - 1];
    }

    /**
     * Returns the smallest u that divides n with s equal to u-character blocks repeated, or n if none is smaller.
     * Time: O(n), because of the border computation.
     * Space: O(n), because of the border table.
     * Invariant: p = n - border is the smallest period of s.
     */
    static int smallestUnit(String s) {
        // Length of the string.
        int n = s.length();
        // The gap between the string and its longest border is the smallest period.
        int p = n - wholeBorder(s);
        // A period that divides n tiles the string; otherwise the whole string is the only unit.
        return n % p == 0 ? p : n;
    }

    /**
     * Brute-force oracle that tests every divisor length.
     * Time: O(n^2), because each of up to n lengths checks n characters.
     * Space: O(1), because only counters are used.
     * Invariant: the first divisor u whose blocks all agree is the smallest valid one.
     */
    static int oracle(String s) {
        // Lengths are tried from 1 upward, so the first success is the smallest.
        for (int u = 1; u < s.length(); u++) {
            // Only divisors of n can tile the string exactly.
            if (s.length() % u != 0) continue;
            // ok stays true while every character equals the one u positions earlier.
            boolean ok = true;
            for (int i = u; i < s.length() && ok; i++) ok = s.charAt(i) == s.charAt(i - u);
            // The first tiling length is returned.
            if (ok) return u;
        }
        // No proper unit exists, so the whole string is the unit.
        return s.length();
    }

    public static void main(String[] args) {
        // Worked examples from the exercise.
        if (smallestUnit("abcabcabc") != 3) throw new AssertionError("abcabcabc");
        // The border 3 leaves gap 2, which does not divide 5, so the answer is the full length.
        if (smallestUnit("ababa") != 5) throw new AssertionError("ababa");
        // A single character is its own unit.
        if (smallestUnit("a") != 1) throw new AssertionError("a");
        // All-equal text has unit 1.
        if (smallestUnit("aaaaaa") != 1) throw new AssertionError("aaaaaa");
        // Random comparison with the oracle; the seed makes any failure reproducible.
        Random rnd = new Random(3492L);
        for (int t = 0; t < 5000; t++) {
            // Short blocks repeated a random number of times produce many true cases.
            int alpha = 1 + rnd.nextInt(2);
            StringBuilder block = new StringBuilder();
            for (int i = 1 + rnd.nextInt(4); i > 0; i--) block.append((char) ('a' + rnd.nextInt(alpha)));
            StringBuilder s = new StringBuilder();
            for (int r = 1 + rnd.nextInt(4); r > 0; r--) s.append(block);
            // Sometimes append one stray character to build near-miss cases.
            if (rnd.nextInt(3) == 0) s.append((char) ('a' + rnd.nextInt(alpha)));
            if (smallestUnit(s.toString()) != oracle(s.toString())) throw new AssertionError("mismatch " + s);
        }
    }

Borders And Repeats Of Every Prefix

LeetCode 1392

Problem Specification. Given a non-empty string s of length n, return an int[][] with two rows of length n. In row 0, entry i is the length of the longest proper prefix of s[0..i] that is also a suffix of s[0..i], or 0 when none exists. In row 1, entry i is 1 when s[0..i] consists of two or more equal copies of a shorter string, and 0 otherwise.

Input Constraints. The limits are:

  • Length is 1 <= s.length() <= 10^5.
  • Characters are lowercase English letters.
  • Return value is a new int[2][n], and row 1 holds only 0 and 1.
  • Length one gives [[0], [0]], because a single character has no shorter string to repeat.
  • Mutation does not occur; the string is immutable.

Example 1. Input s = "ababab", output [[0, 0, 1, 2, 3, 4], [0, 0, 0, 1, 0, 1]]. The prefixes abab and ababab are repeats.

Example 2. Input s = "abcab", output [[0, 0, 0, 1, 2], [0, 0, 0, 0, 0]]. The last prefix has a border of length 2, yet its gap 3 does not divide 5, so it is not a repeat.

Prerequisites. The second exercise above. This exercise changes the contract of LeetCode 1392: it reports every prefix, and it adds a repeat flag for each one.

What This Exercise Changes. The border row is the same as before. The repeat row applies the divisibility test to every prefix, so a border that exists is no longer enough to report a repeat.

Hint

For a prefix of length len with border b > 0, which length is the only candidate for the repeating unit, and what test confirms it?

Algorithmic Solution (attempt the problem first)

Approach. The string is matched against itself. The state k is the border of the prefix read so far, and each new character s[i] is one transition of the machine built from the earlier entries. While s[k] differs from s[i], the state falls to fail[k - 1]. When the characters agree, the state rises to k + 1. Row 0 stores that state for index i. The state is always at most i, because the transition reads s[i] against a position k that is still before i, so the border is strictly shorter than the prefix.

Row 1 reads only the finished border. A prefix of length len = i + 1 with border b has the period p = len - b. The prefix is a repeat exactly when b > 0 and len % p == 0. When b is 0 the period equals len, so there is no shorter unit. When p does not divide len, no other length can work, because every period of the prefix is at least p and a unit length must divide len. Index 0 has border 0, so both rows hold 0 there and the loop does not run for a string of length one. The invariant is that before iteration i, the value k equals fail[i - 1].

Complexity.

  • Time is O(n), because k rises by at most 1 per index, each fallback lowers it by at least 1, and the flag is one remainder test per index.
  • Space is O(n), because the two rows have one entry per index.
import java.util.Arrays;
import java.util.Random;

public final class PrefixBorderLengths {
    /**
     * Returns row 0 with the longest proper border of every prefix and row 1 with the repeat flag of every prefix.
     * Time: O(n), by the amortized rise and fall of k.
     * Space: O(n), because both rows have n entries.
     * Invariant: before iteration i, k equals out[0][i - 1].
     */
    static int[][] bordersAndRepeats(String s) {
        // Row 0 holds borders and row 1 holds repeat flags; entry 0 of both is 0.
        int[][] out = new int[2][s.length()];
        // k starts at the border of the first prefix.
        int k = 0;
        // The loop is skipped for a string of length one.
        for (int i = 1; i < s.length(); i++) {
            // Fall to shorter borders while the next character disagrees.
            while (k > 0 && s.charAt(k) != s.charAt(i)) k = out[0][k - 1];
            // Rise by one when the characters agree; k stays at most i because s.charAt(k) is read before i.
            if (s.charAt(k) == s.charAt(i)) k++;
            // Store the border for the prefix ending at i.
            out[0][i] = k;
            // The period is the prefix length minus the border; it divides the length only for a repeat.
            int len = i + 1;
            if (k > 0 && len % (len - k) == 0) out[1][i] = 1;
        }
        // The caller reads both rows from this array.
        return out;
    }

    /**
     * Brute-force oracle that tests every proper length and every unit length for every prefix.
     * Time: O(n^3), because of three nested loops.
     * Space: O(n), because of the result.
     * Invariant: the first matching border tried from the longest is the maximum.
     */
    static int[][] oracle(String s) {
        // Result rows.
        int[][] out = new int[2][s.length()];
        // Each prefix s[0..i] is handled alone.
        for (int i = 0; i < s.length(); i++) {
            // Proper border lengths run from i down to 1.
            for (int len = i; len >= 1; len--) {
                // The prefix and the suffix of this length must agree.
                if (s.regionMatches(0, s, i + 1 - len, len)) { out[0][i] = len; break; }
            }
            // A unit length u below the prefix length that divides it and rebuilds the prefix proves a repeat.
            for (int u = 1; u <= i; u++) {
                if ((i + 1) % u != 0) continue;
                boolean same = true;
                for (int j = u; j <= i; j++) if (s.charAt(j) != s.charAt(j - u)) { same = false; break; }
                if (same) { out[1][i] = 1; break; }
            }
        }
        // Compared with the fast answer in main.
        return out;
    }

    public static void main(String[] args) {
        // Worked examples from the exercise.
        if (!Arrays.deepEquals(bordersAndRepeats("ababab"), new int[][] {{0, 0, 1, 2, 3, 4}, {0, 0, 0, 1, 0, 1}})) throw new AssertionError("ababab");
        // A border that does not divide the length is not a repeat.
        if (!Arrays.deepEquals(bordersAndRepeats("abcab"), new int[][] {{0, 0, 0, 1, 2}, {0, 0, 0, 0, 0}})) throw new AssertionError("abcab");
        // All-equal text: every prefix after the first is a repeat of one letter.
        if (!Arrays.deepEquals(bordersAndRepeats("aaaa"), new int[][] {{0, 1, 2, 3}, {0, 1, 1, 1}})) throw new AssertionError("aaaa");
        // Length one gives a zero in both rows.
        if (!Arrays.deepEquals(bordersAndRepeats("a"), new int[][] {{0}, {0}})) throw new AssertionError("a");
        // Random comparison with the oracle; the seed makes any failure reproducible.
        Random rnd = new Random(3493L);
        for (int t = 0; t < 4000; t++) {
            // Small alphabets create many borders and repeats.
            int alpha = 1 + rnd.nextInt(3);
            StringBuilder sb = new StringBuilder();
            for (int i = 1 + rnd.nextInt(14); i > 0; i--) sb.append((char) ('a' + rnd.nextInt(alpha)));
            String s = sb.toString();
            int[][] got = bordersAndRepeats(s);
            if (!Arrays.deepEquals(got, oracle(s))) throw new AssertionError("mismatch " + s);
            // Every border is proper: strictly shorter than its prefix.
            for (int i = 0; i < s.length(); i++) if (got[0][i] > i) throw new AssertionError("not proper " + s);
        }
    }

Pattern Recognition

Count Words Ending Here

LeetCode 1032

Problem Specification. Design a class WordCounter. Its constructor takes an array words of distinct non-empty strings. Its method query(char letter) appends letter to an internal stream that starts empty and is never cleared. It returns the number of words in words that are a suffix of the whole stream so far. The state must persist between calls, and the class must not store the stream.

Input Constraints. The limits are:

  • Words satisfy 1 <= words.length <= 2000, all distinct.
  • Word length is at least 1, and the total length is at most 10^4.
  • Calls to query number at most 4 * 10^4.
  • Letters are lowercase a to z in words and queries.
  • Answer of each call is an int from 0 to words.length.

Example 1. Input words ["cd","abc","bc","c"] and queries a,b,c,d, output 0,0,3,1.

Example 2. Input words ["a","aa","aaa"] and queries a,a,a,a, output 1,2,3,3. Every shorter word is a suffix of a longer one.

Prerequisites. The multi-pattern scan and suffix matches of the lesson Match Many Patterns In One Pass. This exercise changes the contract of LeetCode 1032: each call returns a count and not a boolean.

What This Exercise Changes. The answer is a number of words and not a flag, so the count of the failure target is added to each node at build time and a query reads one value.

Hint

If the count at a node already includes the count at its failure target, how many nodes does one query have to look at?

Algorithmic Solution (attempt the problem first)

Approach. The words are inserted into a trie, so each node stands for one prefix of some word. A level-order pass computes, for every node, a failure target (the node of its longest proper suffix that is also a node), and fills every missing edge with the edge of the failure target. After this pass each node has a transition for all 26 letters. The pass also adds the count of the failure target to the count of the node itself. The target is shallower, so its count is already final when the node is processed, and each node then holds the number of words that end at it or at some node on its failure chain.

The class keeps one integer state, the current node. A call to query replaces state with go[state][letter] and returns hits[state]. The stream is never stored. The invariant is that after each call, state is the node of the longest suffix of the stream that is a prefix of some word, so the words ending at the newest letter are exactly the words on its failure chain.

Complexity.

  • Time is O(L * 26) to build for total word length L, and O(1) for each query, because a query is one table read and one array read.
  • Space is O(L * 26), because the table has up to L + 1 rows of 26 entries, and each query adds no memory.
import java.util.ArrayList;
import java.util.LinkedHashSet;
import java.util.List;
import java.util.Random;

public final class StreamWordCounter {
    /** Counts the words that end at each streamed letter. */
    static final class WordCounter {
        private static final int ALPHABET = 26;
        private final int[][] go;
        private final int[] hits;
        // state is the only value kept between calls.
        private int state = 0;

        /**
         * Builds the automaton from distinct non-empty words.
         * Time: O(L * 26), because each of up to L + 1 rows is filled once.
         * Space: O(L * 26), because of the transition table.
         * Invariant: after the level-order pass, hits[v] counts the words ending at v or on its failure chain.
         */
        WordCounter(String[] words) {
            // The node count is at most one plus the total word length.
            int cap = 1;
            for (String w : words) cap += w.length();
            // Each row holds the next node for every letter.
            go = new int[cap][ALPHABET];
            hits = new int[cap];
            // fail[v] is the node of the longest proper suffix of v that is also a node.
            int[] fail = new int[cap];
            // real[v * 26 + c] marks genuine trie edges, since 0 is also the root.
            boolean[] real = new boolean[cap * ALPHABET];
            // nodes is the next free node number; the root is node 0.
            int nodes = 1;
            // Insert each word by walking or creating one node per letter.
            for (String w : words) {
                int v = 0;
                for (int j = 0; j < w.length(); j++) {
                    int c = w.charAt(j) - 'a';
                    // A missing edge creates the next node.
                    if (!real[v * ALPHABET + c]) { real[v * ALPHABET + c] = true; go[v][c] = nodes++; }
                    v = go[v][c];
                }
                // One more word ends at this node.
                hits[v]++;
            }
            // The queue visits nodes by depth, so every failure target is finished before its dependents.
            int[] queue = new int[nodes];
            int head = 0, tail = 0;
            // Root children have the root as failure target and need no count change.
            for (int c = 0; c < ALPHABET; c++) if (real[c]) queue[tail++] = go[0][c];
            // Each dequeued node finalizes its count and completes its row.
            while (head < tail) {
                int v = queue[head++];
                // The target is shallower, so its count is final; add the words it ends.
                hits[v] += hits[fail[v]];
                for (int c = 0; c < ALPHABET; c++) {
                    int u = go[v][c];
                    if (real[v * ALPHABET + c]) {
                        // The child's failure target is reached by following the target of v on the same letter.
                        fail[u] = go[fail[v]][c];
                        queue[tail++] = u;
                    } else {
                        // A missing edge takes the result of the failure target, which is already complete.
                        go[v][c] = go[fail[v]][c];
                    }
                }
            }
        }

        /**
         * Consumes one letter and returns how many words end at it.
         * Time: O(1), because of one table read.
         * Space: O(1), because the stream is not stored.
         * Invariant: state is the longest suffix of the stream that is a prefix of some word.
         */
        int query(char letter) {
            // One transition replaces any search through earlier letters.
            state = go[state][letter - 'a'];
            // The stored count already includes words on the failure chain.
            return hits[state];
        }
    }

    /**
     * Brute-force oracle that keeps the whole stream and tests every word.
     * Time: O(q * L) over q queries, because each query tests all words.
     * Space: O(q), because the stream is stored.
     * Invariant: a word counts exactly when the stream ends with it.
     */
    static int[] oracle(String[] words, String stream) {
        // One answer per query.
        int[] out = new int[stream.length()];
        for (int i = 0; i < stream.length(); i++) {
            // Prefix of the stream up to and including letter i.
            String seen = stream.substring(0, i + 1);
            for (String w : words) if (seen.endsWith(w)) out[i]++;
        }
        // Compared with the automaton in main.
        return out;
    }

    static int[] run(String[] words, String stream) {
        // A fresh automaton per scenario.
        WordCounter wc = new WordCounter(words);
        int[] out = new int[stream.length()];
        // The state persists across the calls inside this loop.
        for (int i = 0; i < stream.length(); i++) out[i] = wc.query(stream.charAt(i));
        return out;
    }

    public static void main(String[] args) {
        // Character subtraction has type int, which is why it indexes the table directly.
        Object diff = 'd' - 'a';
        if (!(diff instanceof Integer) || (Integer) diff != 3) throw new AssertionError("char arithmetic");
        // First worked example: bc and c are inherited through failure links.
        if (!java.util.Arrays.equals(run(new String[] {"cd", "abc", "bc", "c"}, "abcd"), new int[] {0, 0, 3, 1})) throw new AssertionError("ex1");
        // Hostile example: nested suffixes give growing counts.
        if (!java.util.Arrays.equals(run(new String[] {"a", "aa", "aaa"}, "aaaa"), new int[] {1, 2, 3, 3})) throw new AssertionError("ex2");
        // A single one-letter word reports every matching letter and no other.
        if (!java.util.Arrays.equals(run(new String[] {"b"}, "abb"), new int[] {0, 1, 1})) throw new AssertionError("single");
        // Random comparison with the oracle; the seed makes any failure reproducible.
        Random rnd = new Random(3494L);
        for (int t = 0; t < 3000; t++) {
            int alpha = 1 + rnd.nextInt(3);
            // A set keeps the words distinct, as the contract requires.
            LinkedHashSet<String> set = new LinkedHashSet<>();
            for (int k = 1 + rnd.nextInt(5); k > 0; k--) {
                StringBuilder w = new StringBuilder();
                for (int i = 1 + rnd.nextInt(4); i > 0; i--) w.append((char) ('a' + rnd.nextInt(alpha)));
                set.add(w.toString());
            }
            String[] words = set.toArray(new String[0]);
            StringBuilder sb = new StringBuilder();
            for (int i = rnd.nextInt(30); i > 0; i--) sb.append((char) ('a' + rnd.nextInt(alpha)));
            if (!java.util.Arrays.equals(run(words, sb.toString()), oracle(words, sb.toString()))) throw new AssertionError("mismatch " + set + " / " + sb);
        }
    }
