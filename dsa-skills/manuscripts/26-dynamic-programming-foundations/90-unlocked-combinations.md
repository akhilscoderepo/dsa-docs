## Unlocked Combinations

A developer writes a clean recursive function for the number of routes across a board, and it takes minutes on a board of modest size. Her teammate adds a store keyed by the wrong values, and the program returns wrong numbers quickly. Both programs use the same recursion, and only the cache key separates them. This chapter releases one pairing, where a pairing is a lesson that joins earlier topics into one decision, and it leaves one pairing for later.

### Pairing Taught In This Chapter

The lesson Recursion And Memoization joins plain recursion with the cache from the second lesson, and it reuses the state sentences from the first. The recursion supplies the arguments of each call, the state definition says which arguments change the answer, and the store keeps one result for each distinct set of arguments. The lesson adds one idea: the call arguments are the cache key, so a key that leaves out a deciding value returns wrong answers and a key that adds a useless value repeats work. Its four exercises cover stairs with a hit counter, houses chosen by index, routes through a required tile, and the cheapest entry cost across a board.

### Pairing That Waits For A Later Chapter

Capacity problems need a state that records how much room is left, and a loop direction that decides whether an item can be chosen again. No lesson of this book teaches that rule yet, so this chapter assigns no exercises for it. Chapter 27 owns the topic, and it will build on the take-or-skip and table lessons from this chapter.
