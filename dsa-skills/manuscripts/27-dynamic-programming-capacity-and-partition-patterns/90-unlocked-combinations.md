## Unlocked Combinations

A pricing engine shows the same invoice three times and prints three different counts: 4, 7 and 1. All three counts are correct, because the screens ask three different questions about the same list of packs. A developer who merges them into one routine ships a bug that returns plausible numbers and that only a hand count catches. This chapter releases one pairing and leaves one for later, where a pairing is a lesson that joins earlier topics into one decision.

### Pairing Taught In This Chapter

The lesson DP And Capacity joins the table habits from the foundations chapter with the capacity rules from the seven lessons. The table supplies the meaning of an entry and the combine rule. The capacity rules supply the direction of the inner loop, which decides whether an item repeats, and the owner of the outer loop, which decides whether order counts. The lesson adds one idea: the two answers in the problem statement select the loop structure, and one pair of answers falls outside a table over totals. Its four exercises set the reuse flag for the fewest-coins table, set the order flag for the counting table, count subsets to split an array into two nonempty groups, and count signed sums inside a range.

### Pairing That Waits For A Later Chapter

Problems with buying and selling, cooldowns and holding states need an extra label on every table entry. This book has not taught labeled states yet, so this chapter assigns no exercises for them. Chapter 28 owns the topic, and it builds on the one-use and reuse tables from this chapter.
